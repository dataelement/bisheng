02

数据迁移：先冻结事实，再转换关系

PRD §1.6 · AC-55–AC-64、AC-85；停服期间执行迁移，停服/任务收尾/恢复由运维负责，脚本不检测停服。

Q-04-1 已确认：停服是运维前提，脚本不检测。升级文档要求正式迁移在停服期间执行。运维暂停新派发/启动，等待运行任务自然完成并确认无活跃写后停止旧服务；超维护预算仍未完成则保持维护交人工处置，不自动强杀或继续转换。排队任务保留，升级校验后再恢复。迁移脚本不探测服务/进程/心跳，不要求停服标记或停服确认参数，也不启停服务或等待任务退出；只检查数据和迁移合同。
同一空间在两端一致，各空间仍可保留各自策略。迁入空间继续使用原模型，不能强制改为工作台的新建默认模型；存量文件保留原 split_rule / 分段。旧库缺少空间级默认时按既有默认解释，不从最后上传文件或混合历史配置反推一份默认。只有新建空间才按新建入口规则预选默认模型。
责任方负责职责边界
升级运维停新派发/启动 → 运行任务自然收尾 → 停旧服务 → 备份 → 执行脚本 → 升级校验 → 恢复队列/入口超预算保持维护并人工处置；确认停服前提属于运维手册
迁移脚本数据与权限合同预检、冻结计划/账本、幂等转换、结果校验、检查点恢复和报告不检测是否停服、不探测健康/进程/心跳、不要求停服标记或确认参数、不等待任务或启停服务

上线后持续统一：任务、索引与引用

任务状态与资源可访问状态独立表达，重建不能让整个空间不可授权。

跨空间移动按原计划恢复

整版本链改归属，继承跟随目标父级、自定义授权保留；按目标模型迁移检索数据。记录源读取、目标替换写、目标校验、清源和清理验证。重投不重复 Chunk；旧归属残留不能被检索。移动后删除源空间仍要验证图片/附件可访问。

引用保护检查最终保存

空间/模型删除按业务绑定索引查引用，默认拦截普通删除；显式强删确认后保留失效关系。删除与新增业务配置引用的写端共用锁或版本协议，阻止预检后新增引用的竞态。共享模型受控跨租户检查，无权依赖只返回类型和数量。

Q-03 清空规则已确认：清空删除空间全部内容，保留空间本体、ID、配置和授权。存在有效空间级绑定或直接文件业务引用即拒绝，须先解除；历史对话与审计不阻止，但执行前须提示对应历史内容引用不可访问。取消不修改内容；最终写入前复核，管理员、新旧接口同规则。
Q-04-2 模型引用规则已确认：模型删除只检查有效业务资源、仍可执行/线上/待上线版本及默认配置。任务执行与重试从业务配置解析模型；配置已解除且无合法模型时明确失败，不能用历史任务参数继续调用。无需任务模型绑定表、占用跟踪或任务扫描删除拦截。文件解析/切分参数快照和任务幂等继续保留。
实现接线：现有空间/QA 重建任务显式携带模型 ID，须按业务配置校验与解析；当前仅标注技术改造要求，未修改代码。
三件事必须分开：默认策略修改影响后续上传；模型重建保留原分段重新生成向量；类型迁移保留原模型和索引位置。不能通过一次全量重处理混合完成。

关联引用：业务怎样维护绑定

复查修订：业务保存时同步维护结构化绑定；目标删除按索引反查，原配置重算用于回填和对账。

发布 / 版本退役 / 回滚每个有效版本独立建集合；失去执行资格才移除；回滚重新提取和校验修改草稿不删除线上关系；目标已删除则回滚失败，不恢复旧关系绕过

草稿原绑定空间 A、模型 M1，保存后改为 A/B、M2：仅在草稿集合增加 B/M2、删除 M1、保留 A。线上 V3 如果仍使用 M1，它自己的 M1 关系继续保留，普通删除 M1 仍被阻止；也可显式确认强删，保留线上 V3 的失效关系供手动修复。所有差异与草稿配置一次提交，关系写失败则整次保存回滚。

来源租户、业务类型/ID、稳定版本、配置槽位 → 目标类型/ID/拥有租户；文件绑定额外保存当前 target_space_id。唯一键覆盖来源/版本/槽位/目标；索引支持模型、空间和文件归属反查，不存名称、配置全文或凭据。

来源集合：business_reference_set

每个来源/版本保存配置修订、提取器版本、集合摘要及有效/就绪状态，区分“确实零引用”和“还没有提取”。集合与配置及明细同事务提交；不能通过单独删除关系来让目标可删除。

怎么防止漏维护：新旧 API、保存、导入/复制、发布/回滚、默认切换和文件移动统一接入维护协议，不依赖异步消息补关系。升级停服期间按业务相同提取器回填全部有效来源/版本（包含零引用）；按修订和摘要对账，覆盖未就绪时普通/强制删除都不放行；有合法强删标记的失效关系保留供修复。后续只读对账发现漂移则阻止受影响范围删除，修复按显式事务协议执行，不能静默复活已删目标。迁移脚本仍不检测或控制停服。
模式/状态空间与模型配置引用方业务
普通删除有有效引用则拦截引导先在业务中解除或改绑
强制删除显式确认完整影响；模型三类移除入口统一处理；空间记录持久清理计划原 ID/版本/入向关系保留，目标标记 deleting/deleted；无自动解绑定或模型回退
清空空间本轮不增加强制清空；仍需先解引用空间配置及出向模型关系保留
失效展示/执行resource_reference_tombstone 保存目标与操作标记，ID 不复用；直接文件可按所属空间标记失效显示“引用已失效”；执行/启用受影响配置明确报错，默认模型也不静默回退
手动修复/对账合法强删失效是预期状态，不作为普通数据漂移自动清除业务槽位解除/改绑按来源与版本同事务更新；原发布版本关系继续保留，直到修复/退役
Q-05 已确认：强删只越过已知引用阻断，不扩大既有操作权限，不跳过租户/共享只读、业务状态、任务冲突或完整性检查。服务端确认计划冻结目标和入向绑定摘要；影响变化需重新确认。保留失效槽位可用于逐项修复，新建/复制/导入及回滚激活不能新增已删目标关系。
