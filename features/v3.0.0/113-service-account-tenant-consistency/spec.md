**范围边界**：

- **纳入**：归属人/服务账号租户不一致时拒绝全部服务账号业务调用；关系变化和复用会话后仍生效；在途发布必要阶段复核；超管选择服务账号管理及创建租户；应用生命周期、元信息、日志/数据及配置等管理操作校验调用者与应用的租户；明确原资源不迁移、不可跨租户管理。
- **排除**：资源/账号/密钥迁租户、自动恢复人员原租户、自动移交owner或复制授权、自动重建旧应用、自动停用服务账号或停止在线应用、人员迁移拦截、通用迁移器及新发布幂等能力。用户已明确保留现有资源，以上均不作为修复手段。
- **排除**：修改PAT和独立托管应用运行凭据的生命周期或权限；新增轮换/吊销功能；全量Docker/K8s/arm64及故障升级回归。既有权限和运行隔离继续适用。

## 1. 用户故事

- 作为集成开发者，我希望账号归属关系不符合租户要求时收到明确拒绝，以免继续在错误租户创建或操作资源。
- 作为全局超管，我希望选择服务账号的管理和创建租户，以便为目标租户配置正确的账号、归属人及密钥。
- 作为租户用户，我希望迁租户后只按当前租户和已有授权访问资源，以免归属人字段成为跨租户权限例外。
- 作为应用负责人和审批人，我希望异步发布再次执行时检查原提交资格，以免人员关系变化后仍继续上线或误改历史审批。

## 2. 验收标准

### 2.1 服务账号业务调用

- **AC-01** — WHEN 服务账号及密钥符合原准入要求，且归属人当前唯一有效租户等于服务账号所属租户，THE SYSTEM SHALL 继续按既有权限位、身份模式、委托范围及业务资源权限决定是否允许；租户一致本身不得额外授予权限。
- **AC-02** — IF 服务账号归属人当前租户与服务账号所属租户不一致，THEN THE SYSTEM SHALL 拒绝使用该账号密钥的新业务调用，明确告知“归属人租户与服务账号租户不一致”及管理员处理指引；不能以成功空结果代替拒绝。该要求覆盖读写、创建、执行、模型和MCP等全部已开放业务，不因接口权限位或委托模式不同而豁免。
- **AC-03** — WHEN 当前有效租户关系变化完成后发起下一次业务调用，THE SYSTEM SHALL 根据变化后的关系判定；即使此前密钥已成功调用或现有连接仍在复用，也不得凭旧身份关系继续执行。HTTP、MCP及其他已支持的复用连接均适用；不要求中断已开始执行的单次流式业务。
- **AC-04** — WHEN 管理员按原规则更换服务账号归属人后发起新业务调用，THE SYSTEM SHALL 使用当前归属人进行校验和后续资源归属判定；不得继续使用旧归属人；此前资源和发布提交的归属不追溯改写。
- **AC-05** — IF 无法取得归属人的唯一有效租户，THEN THE SYSTEM SHALL 拒绝新业务调用并明确提示“无法确认归属人所属租户”；不得随意选择一条关系或默认为根租户。
- **AC-06** — IF 读取或确认归属关系的依赖发生故障，THEN THE SYSTEM SHALL 拒绝本次业务处理并返回依赖不可用类错误；不得误报租户不一致或放行业务。
- **AC-07** — WHEN 关系出现失配或恢复一致，THE SYSTEM SHALL 不因此自动改写服务账号/密钥租户、撤销密钥、改账号启停状态或复制权限；关系恢复后，未过期、未撤销且符合其余条件的密钥可恢复正常调用。
- **AC-08** — IF 归属人仅被标记禁用或删除但仍可确定其唯一有效租户，THEN THE SYSTEM SHALL 不将该标记本身视为租户失配或本次新增的业务拒绝条件；IF 已无法确认有效租户，THEN THE SYSTEM SHALL 按AC-05拒绝，且不将密钥自动撤销。人员停用、资源权限变化和租户关系变化须可区分。
- **AC-09** — WHEN 管理员通过正常登录会话管理失配服务账号，THE SYSTEM SHALL 仍允许其在既有管理权限与租户范围内查看、修改归属人、停用或处理密钥；失配账号不得因此获得管理权。个人PAT与独立托管应用运行凭据不适用本次服务账号归属人闸门。

### 2.2 在途应用发布

- **AC-10** — IF 新发布或迭代发布在接收时已存在AC-02或AC-05所述关系问题，THEN THE SYSTEM SHALL 拒绝提交并给出相应原因，不创建应用、保存平台源码快照、投递发布任务或创建版本/审批；允许临时接收文件按原机制清理。
- **AC-11** — WHEN 平台已接收发布后归属人或账号归属关系变化，THE SYSTEM SHALL 保留本次提交时固定的资源归属人和租户，不将已接收发布自动改成新归属人或新租户的提交。
- **AC-12** — WHEN 已接收发布实际开始预检，THE SYSTEM SHALL 重新确认该提交原归属人的当前租户与提交租户一致；IF 不一致、无法确定或依赖不可用，THEN THE SYSTEM SHALL 记录可区分的失败原因并停止后续准备，不影响已有在线版本。
- **AC-13** — WHEN 发布准备完成且即将生成版本及审批，THE SYSTEM SHALL 再确认AC-12所述关系；IF 此时不再符合，THEN THE SYSTEM SHALL 不生成该次新版本/审批，保留失败原因并继续清理本次临时产物。
- **AC-14** — WHEN 已审批发布即将登记待生效版本、正式上线或上线重试，包括应用已停用而本次只登记下次恢复使用版本的场景，THE SYSTEM SHALL 在这些动作前再次确认本次固定归属人与租户符合要求；IF 不符合，THEN THE SYSTEM SHALL 拒绝本次执行，不得因该拒绝执行改变当前运行版本、待生效版本或路由，不执行本次数据库迁移、停止旧实例或启动新正式实例，也不自动转到新租户上线。
- **AC-15** — IF 审批已通过而上线因关系问题拒绝，THEN THE SYSTEM SHALL 保留审批决定和历史内容，将业务执行反映为失败并向有权查看者提供原因；不得伪装执行成功、自动改为驳回或无止境自动重试；必要清理不因业务拒绝而被跳过；归属关系恢复后不自动恢复本次失败发布，沿用现有有权用户主动重试或重新提交发布的流程。
- **AC-16** — WHEN 为已接收版本新增审批预览执行，THE SYSTEM SHALL 对原提交归属人和租户采用相同资格要求；IF 不符合，THEN THE SYSTEM SHALL 不启动新预览。已存在预览仍按既有到期、终态及回收规则处理，不借此改写审批历史。

### 2.3 超管管理和创建租户

- **AC-17** — WHERE 多租户模式启用，WHEN 全局超管进入服务账号管理页，THE SYSTEM SHALL 提供“管理租户”选择并明确显示当前管理租户；租户管理员及其他非全局超管不得看到或使用跨租户切换能力。
- **AC-18** — WHEN 全局超管选择某个具体可用租户，THE SYSTEM SHALL 使服务账号列表、详情、归属人候选、密钥及资源授权管理使用同一租户范围；旧租户私有账号不得因根租户共享规则混入其他租户列表。
- **AC-19** — WHEN 全局超管选择根租户管理并创建账号，THE SYSTEM SHALL 明确在根租户创建；选择某子租户时在该子租户创建，不得因归属人候选或上一次选择而静默改变创建租户。无具体创建租户时，须要求先选择，不能猜测。
- **AC-20** — WHEN 在所选租户创建服务账号，THE SYSTEM SHALL 仅允许选择该租户符合原要求的自然人作为归属人；创建的账号及其新密钥归属该租户，后续资源按既有规则在该租户归属对应自然人。直接请求不能绕过同租户校验。
- **AC-21** — WHEN 切换管理租户，THE SYSTEM SHALL 不修改已有服务账号、密钥、资源或人员的所属租户，不复制原账号权限，也不把查看范围切换描述为账号迁移。
- **AC-22** — WHEN 页面切换到另一管理租户，THE SYSTEM SHALL 返回该租户列表并清除旧详情、搜索结果、已选归属人及未提交表单；切换尚未完成时不能提交§3.1列明的任何服务账号管理写操作，旧响应不能覆盖新租户页面。
- **AC-23** — IF 另一标签页或管理操作改变了共享管理租户，使表单/操作发起时的租户与提交时实际范围不同，THEN THE SYSTEM SHALL 拒绝§3.1列明的任何服务账号管理写提交并提示刷新，不能将旧表单应用到新租户；页面须提示该选择为共享管理范围，会影响已有适用的管理页面；已被服务端接受且范围校验通过的操作不因随后切换而撤销，不把本要求扩为跨请求全局锁定。
- **AC-24** — IF 非超管伪造目标租户或试图跨租户管理账号、签发密钥、增删授权，THEN THE SYSTEM SHALL 拒绝且不产生变更；隐藏选择器不能替代服务端权限检查。超管也须按其所选范围操作，不得借过期详情处理另一租户账号。
- **AC-25** — IF 所选租户不存在、已禁用或在提交前变为不可用，THEN THE SYSTEM SHALL 拒绝相应切换或变更并提示原因，不得静默回退根租户或创建到其他租户。
- **AC-26** — WHERE 单租户模式，THE SYSTEM SHALL 隐藏跨租户切换，沿用单租户的账号管理和创建行为；非超管管理员在多租户下仍可按原权限管理本租户账号。
- **AC-27** — WHEN 展示本功能新增提示、管理范围、空态和拒绝原因，THE SYSTEM SHALL 支持中文、英文和日文；租户不一致、无法确定关系、依赖不可用及管理范围已变化须可区分，不展示密钥明文或其他租户私有资源内容。

### 2.4 历史资源与116现状

- **AC-28** — WHEN 升级启用本功能或归属人切换租户，THE SYSTEM SHALL 保持既有资源的租户、owner、权限、版本、数据库/附件、访问地址及审批历史不变，不自动迁移、补授权、清理或重建资源。
- **AC-29** — WHEN 归属人以新租户身份查看原租户资源，THE SYSTEM SHALL 继续按现有租户隔离与授权处理，不因owner字段相同而新增跨租户可见或管理例外；超管和原租户有权主体仍按原权限管理。
- **AC-30** — WHEN 本功能部署到116，THE SYSTEM SHALL 不为修复可见性而改变三个存量应用“今日待办”“知识库读写验证”“知识库读写验证（无能力声明）”、服务账号24及审批414/415的归属或当前状态；后续真实业务操作按正常流程和本次资格检查处理，待审批415不能绕过检查启动正式实例。
- **AC-31** — WHEN 服务账号因关系失配被拒绝业务调用，THE SYSTEM SHALL 不自动停止已有在线应用或使其独立运行凭据失效；应用内部若使用该失配服务账号密钥调用平台，仍须按AC-02拒绝，不影响独立凭据既有权限规则。
- **AC-32** — WHEN 管理员在归属人当前租户创建新账号并发布新应用，THE SYSTEM SHALL 保持其为独立账号、密钥与新应用，不自动承接原账号授权、旧应用ID或旧版本历史；已被旧应用占用的slug不得重复使用或被静默抢占。

### 2.5 应用管理操作租户校验

- **AC-33** — WHEN 已登录用户发起应用上线、手动上线、停用、恢复、删除或编辑名称/描述/图标，THE SYSTEM SHALL 校验调用者所属租户与应用所属租户，并执行该动作原有owner/管理员及应用状态规则；除AC-35限定的原有超管管理例外外，跨租户必须拒绝，不能仅凭知道应用ID或owner ID相同执行操作。
- **AC-34** — IF 调用者迁租户后仍是原应用记录的owner，但不满足AC-33的租户条件，THEN THE SYSTEM SHALL 在本次管理操作产生业务副作用前拒绝；不因该次请求改变应用状态、当前/待生效版本、元信息或路由，不启动/停止/删除执行实例、不发起数据迁移或删除资产。允许记录拒绝审计或安全日志，不把拒绝伪装为成功。
- **AC-35** — WHEN 调用者租户与应用租户一致，THE SYSTEM SHALL 继续采用原动作权限，不能让普通非owner、无权租户管理员或其他同租户用户仅凭租户一致获得操作权；全局超管仅保留各入口本来允许的跨租户管理动作，不因本次修复扩大超管权限。原本owner-only的应用数据、配置或其他受限入口不得新增管理员绕过。
- **AC-36** — WHEN 用户直接请求应用详情、实例状态、版本、运行日志、数据表/行的查看编辑及导出，或环境变量配置的查看修改/删除及确认重建，THE SYSTEM SHALL 对每个入口执行与该应用一致的调用者租户约束及原操作权限；跨租户请求不得因owner ID相同或持有历史页面/导出任务引用而返回数据、取得导出文件或产生修改。拒绝沿用无权/不可见语义，不额外泄露其他租户应用的存在和内容。
- **AC-37** — WHEN 判断应用管理请求的调用者租户，THE SYSTEM SHALL 使用该请求已认证且有权采用的调用者身份和管理范围；加载目标应用或后续执行时进入应用租户，不能反过来视为调用者已属于该租户。此要求覆盖平台管理请求和现有开放API/MCP应用操作入口，且不改变服务账号、委托用户或个人令牌的既有权限来源。
- **AC-38** — WHEN 审批执行、预览准备及平台后台任务代表应用处理业务，THE SYSTEM SHALL 校验其可信任务归属与目标应用租户一致，不得把没有自然人调用者当作任意跨租户通行条件；发布和新增预览仍须满足AC-11至AC-16。已有应用的正常对账、受权清理及维持原租户原批准版本的运行恢复不作为用户跨租户操作，不因人员迁租户而自动停止旧应用，也不得借后台任务将应用迁到其他租户或发布新的代码版本。

## 3. 边界与既有契约适用关系

### 3.1 业务边界

**服务账号管理写操作的完整范围（AC-22、AC-23）：** 创建账号；编辑名称/描述；改绑归属人；启用、停用、删除账号；签发密钥；编辑密钥配置（含权限位、有效期、委托范围等既有可编辑项）；单把及全部吊销密钥；新增、修改、单项及全部撤销资源授权。组合/批量提交中的每项写动作同样适用。此处按业务效果判定，不以请求使用何种HTTP方法区分；候选查询、列表和详情等纯读取继续按当前管理范围处理。

**“待生效版本”**是已批准、被选定在下一次启动/恢复使用而尚未实际运行的版本。AC-14要求失配拒绝不能改变该选择；资格通过时仍保留“停用应用不自动启动”的原产品规则。

- 一次业务调用的准入与已在执行的调用区分：关系变化后新调用拒绝，已开始流式业务不要求主动中断；本次不承诺撤销已执行副作用（AC-03）。
- 在途发布以提交时固定归属人与租户为准，而新业务调用采用服务账号当前归属人。人员迁移和账号改绑都不能改写旧提交（AC-04、AC-11）。
- 每个发布阶段开始前确认资格；不新增人员迁移锁定、跨阶段全局事务或通用发布幂等保证（AC-12、AC-13、AC-14、AC-15、AC-16）。失配拒绝不能改待生效版本；必要预览/临时产物清理仍独立完成。
- 管理页租户选择是管理范围，账号租户是创建后固定事实；二者不能相互替代（AC-17至AC-26）。
- 缺失/重复有效成员关系、人员删除标记、权限变化及依赖故障分别处理，不能混报租户失配（AC-05、AC-06、AC-08）。
- 应用操作补校验同时覆盖写操作与原有读取/导出入口；对自然人请求与可信后台作业分别按已认证来源校验，不把应用执行租户当作调用者身份（AC-33、AC-34、AC-35、AC-36、AC-37、AC-38）。
- 116确切应用ID及只读证据见已确认方案§5；本功能不包含对它们的维护写入。其他主体正常操作导致的业务状态变化不属于升级自动改写（AC-28至AC-31）。

### 3.2 对旧规格的明确增量

| 原条款/对象 | 本规格适用关系 |
|---|---|
| F049 AC-23“租户取当前管理员所在租户、不提供选择” | 由AC-17、AC-19、AC-20补充全局超管选择管理/创建租户；普通管理员不变，“创建后不可更换”仍保留 |
| F049 AC-24“归属人可见可管理、如同本人所建” | 由AC-28、AC-29明确受当前租户隔离约束；迁租户不迁历史资源，也不产生跨租户例外 |
| F049 AC-26“归属人权限变化不改变服务账号范围” | 原资源权限不继承继续成立；新增租户资格不等于借用owner权限，同租户仍受原scope/资源授权限制（AC-01、AC-02） |
| F049 AC-27“改绑仅影响未来资源” | 不变；已接收发布同样不追溯换owner（AC-04、AC-11） |
| F049 AC-28“禁用/删除不自动使账号及密钥失效” | 不新增凭据级联撤销；仅人员标记不触发新闸门。若已不能确认唯一有效租户，按本次新业务资格拒绝，不能凭仍未撤销密钥放行（AC-05、AC-07、AC-08） |

| F054应用操作/查询及F055配置入口 | 原Owner不变，补调用者与应用的租户前置条件；修复owner相同直接放行的缺口，不扩大同租户或超管权限（AC-33、AC-34、AC-35、AC-36、AC-37、AC-38） |

| INV-27至INV-35及现有PAT合同 | 不修改不变量；本次只增服务账号业务资格，不改变凭据类型、权限来源、必审、资产删除及双形态产品语义 |

## 4. 设计与验证安排

规格确认后再编写design.md，确定公共准入接线、缓存和MCP处理、规范成员查询、发布复核、超管管理范围及并发表单处理、应用操作与可信后台作业的租户判定；不在本规格预先决定接口、字段、数据库变更或文件清单。设计须单独确认后才能拆任务和编码。

仅做本功能定向验证：同租户允许/拒绝配对、关系变化后调用、在途发布阶段及待生效版本不变、管理页完整写操作清单与越权、应用状态/元信息/日志/数据/配置租户校验、可信后台作业不回归、历史不变及本功能E2E。E2E采用专用临时对象，不修改116三个存量应用；不跑全量测试。DM8仅静态兼容核对，真实部署结果须单独留证，不能以规格自审或模拟测试替代。
