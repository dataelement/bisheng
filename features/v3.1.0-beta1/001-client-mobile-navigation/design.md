# Design: 工作台窄屏新版完整侧栏

**关联**：[spec.md](./spec.md) · [tasks.md](./tasks.md)
**版本**：v3.1.0-beta1
**最后更新**：2026-10-30
**状态**：2026-10-30 用户在设计确认中明确修正交互为主屏右推、露出底层侧栏；按修正后的设计实施。实施后覆盖 §4 的基线说明为实际交付状态。

## 1. 目标与非目标

将浏览器小于 768px 时的全局菜单替换为新版完整工作台侧栏：默认收起，打开时主屏向右推出 240px，露出其下方的侧栏，模块、项目、会话和账号入口保持可用。修复菜单收起时工具与技能首页对应的重复标题和横向越界。

范围按 spec 的边界执行：保持既有桌面、独立分享与应用、DSH 宿主职责；不调整业务授权、项目数据来源或其他页面内部的完整布局。

## 2. 关键约束

- 遵循 [constitution](../../../docs/constitution.md) 和 [版本契约](../release-contract.md)；本特性不新增后端接口、存储对象、错误码或授权规则。菜单及资源权限依旧由原有能力决定。
- 布局边界严格为 `<768px`，继续使用 `usePrefersMobileLayout`。触屏行为由 pointer/hover 判断，不把窄窗口视为触屏，不全局修改 Tailwind 的 sm/lg 断点。
- 项目与会话的查询和交互状态必须能跨菜单开关保存。项目当前是 localStorage 中的 mock 数据，不因本特性描述为已接入后端项目能力。
- 采用现有 UI 组件与语义 token；Drawer 组件尚未正式落地时沿用 client 已有 Radix/Sheet 能力。左侧导航的侧滑方向来自本轮用户确认；组件文档中的业务抽屉手机底部形态不用于替代这项确认。
- 沿用已有 Recoil 菜单开关，不增加 atom/selector，不在新文件引入 Recoil。局部展示状态使用 React state/ref，服务端列表沿用 react-query。
- 保持页面 Outlet 和 KeepAlive 的位置与 key，不因断点或菜单开关包入新的条件树；否则可能丢失草稿或重建页面。

## 3. 方案对比与选定

### 决策 1：复用新版侧栏内容，窄屏只切换外壳

- **备选**：A. 继续为旧图标栏补入口；B. 新做一份移动侧栏；C. 复用 `WorkbenchSidebar` 内容，桌面常驻、窄屏置于主屏下方，由主屏右推露出。
- **选定**：C。
- **原因**：`MainLayout.Sidebar` 仍从旧模块列表生成入口，而 `WorkbenchSidebar/useSidebarEntries` 已包含工具与技能、统一广场及更多菜单；复制一份列表会继续产生入口漂移。复用现有行、项目和会话组件也保留业务动作。
- **何时重新考虑**：产品明确批准手机采用不同导航结构，且为分歧建立明确契约时。

### 决策 2：保持侧栏控制层挂载，浮层内容正常卸载

- **备选**：A. 每次打开重新挂载整个侧栏；B. 强制挂载并隐藏模态内容；C. 持续挂载侧栏控制层，保存项目展开和滚动状态、持有会话查询，浮层按组件标准生命周期开关。
- **选定**：C。
- **原因**：现有 `SidebarProjects.openIds` 和列表滚动位置都属于组件实例。A 会丢失它们；B 若未同步关闭模态副作用，可能让隐藏内容继续锁住背景或焦点。C 把业务与展示状态留在稳定层，由 Radix 只管理活动浮层。
- **实现边界**：`WorkbenchSidebar` 在 `MainLayout` 中保持同一个实例；项目展开 id 和列表滚动位置保存在其稳定控制层，作为受控值/ref 传给内容组件。会话查询在这一层保持有效订阅，列表和项目只消费同一份查询结果，避免关闭超过缓存时间后丢失已加载页。
- **何时重新考虑**：菜单数据规模产生可测量的常驻开销，或项目/会话组件已有公共的持久状态机制时。

### 决策 3：保留既有菜单开关，显式处理导航和关闭原因

- **备选**：A. 为新版菜单新增全局状态；B. 继续消费 `mobileSystemMenuOpenState`，统一在 `MainLayout` 接入新版侧栏。
- **选定**：B。
- **原因**：聊天、频道、知识空间和设置已经通过这一开关打开系统菜单。沿用它无需逐页替换业务导航，也不会增加冻结中的 Recoil 状态。
- **关闭规则**：模块、更多菜单、项目会话、历史会话、新建对话和账号入口显式调用关闭回调；当前路径／当前会话点击也关闭，但保留已有同路径导航保护。路由变更、退出窄屏和宿主隐藏网页导航时同时清理开关。
- **焦点规则**：在触发菜单的点击事件发生、Radix 自动聚焦之前记录触发按钮。关闭按钮／遮罩／Escape 关闭时只向仍连接且可见的触发器归还焦点；路由或断点切换关闭时不强制聚焦已离开的按钮。
- **何时重新考虑**：项目正式启动 Recoil 迁移，或全局导航已有统一的开关协议时。

### 决策 4：保留主屏右推与底层侧栏，复用 Radix 管理交互

- **备选**：A. 新版侧栏覆盖主屏；B. 保留原有右推主屏的结构，侧栏宽度从 64px 扩为 240px；C. 手写全部焦点与滚动管理。
- **选定**：B，依用户设计确认中的明确修正；交互管理复用已有 Radix Dialog 原语。
- **原因**：用户要求沿用原有前后层级；右推本身不是缺陷。现有 Radix 能处理 Escape、焦点循环、背景屏蔽、嵌套 Portal 和滚动恢复，不需要把导航视觉改成上层抽屉。
- **几何**：侧栏保持现有 240px 内容宽度，贴左、通高，处于主屏下方。主屏保持窗口宽度，打开时平移 240px；根容器裁切窗口以外部分。主屏露出的左侧边沿保留原有圆角与阴影。点击右移后的主屏透明拦截层收回，不增加黑色遮罩或模糊。
- **结构**：非 Portal 的 Radix Content 绝对定位在布局底层，主屏保持同一实例且位于其上；Overlay 只覆盖主屏右移后仍可见的区域，用于阻止操作并关闭菜单。底层内容关闭时保留至主屏收回动画结束，控制层持续挂载。
- **层级**：项目命名、会话操作打开的子弹窗必须位于主屏拦截层之上；仅为相关调用透传/配置层级，不修改全部业务弹窗的默认层级。更多菜单继续使用已有 Portal。
- **热区**：菜单开关使用至少 44px 的按钮范围或已有透明热区能力；触屏更多操作保持可见，细小项目动作采用已有按钮的较大尺寸或不重叠的点击区域。
- **何时重新考虑**：现有浮层能力在浏览器实测中无法可靠处理嵌套交互时；先修复最小底座问题，不引入第二套 UI 库。

### 决策 5：工具与技能首页只调整排版，保留页面实例

- **备选**：A. 整页复制成移动版；B. 用全局 CSS 改所有模块页头；C. 对共享页头增加显式可选的窄屏模式，仅工具与技能首页启用。
- **选定**：C。
- **原因**：`MainLayout` 已提供窄屏页标题；`ModuleHomeHeader` 固定单行 32px，高度和右侧不可缩宽容器仍适用于桌面。将同一页面的第二处标题在窄屏做视觉隐藏、保留语义标题，搜索变成可收缩的整行，即可消除该页重复与越界，不影响其他模块。
- **排版**：搜索独占窄屏页内首行；分类行允许换行。小于 576px 时，上传按钮在需要显示的分类下占独立一行；576–767px 允许在足够空间时与分类同行。列表容器补齐 `min-w-0`，长名称／描述截断，开关保留宽度。
- **状态**：搜索仍由 `CapabilityCenterPage` 本地状态持有，分类和详情沿用查询参数；不增加页面 key，不在断点切换时重置状态。
- **何时重新考虑**：其他模块提出相同页头布局需求且完成设计确认时，可扩展相同可选模式。

### 决策 6：移除旧聊天侧栏，保留现有快捷下拉与应用专属历史

- **备选**：A. 同时保留旧 `<Nav>`、新版全局侧栏和标题下拉；B. 取消所有聊天标题下拉；C. 移除主站旧 `<Nav>` 挂载，全局菜单统一使用新版侧栏，保留现有聊天标题快捷下拉和应用专属历史选择。
- **选定**：C。
- **原因**：`Root` 是旧 `<Nav>` 唯一生产挂载点；它与新版全局会话区重复。标题下拉属于既有快捷选择行为，删除并非本次需求；应用侧历史依赖 AppRoot 的独立路由上下文，应继续保留。
- **清理范围**：删除旧挂载与确认为无调用的组件/导出；共享 SearchContext、导航工具与独立页面仍有调用时保留。同步消除旧图标栏、其应用抽屉及右推布局的失效状态和样式条件。
- **何时重新考虑**：用户另行确认聊天标题交互变更时。

## 4. 系统现状与实施接线

### 4.1 已核对的实施前现状

- `usePrefersMobileLayout` 在浏览器使用 `(max-width: 767px)`，`isDesktopEmbedded()` 时强制返回 false。
- `MainLayout` 的桌面分支挂载新版 `WorkbenchSidebar`；窄屏分支挂载内联旧 `Sidebar`，菜单打开时给主内容添加 `translate-x-16`。
- `WorkbenchSidebar/useSidebarEntries` 汇总新版模块、工具与技能、广场及更多入口；项目和会话区使用既有组件。
- `Root` 仍挂载旧聊天 `<Nav>`；`MobileNav` 的全局菜单按钮实际已经使用系统菜单开关，标题则打开快捷历史下拉。
- `CapabilityCenterPage` 同时渲染 `ModuleHomeHeader`；其父布局又提供窄屏顶栏标题，形成可见重复。

### 4.2 目标数据流

页面菜单入口 → 原有 `mobileSystemMenuOpenState` → `MainLayout` 判定浏览器窄屏 → 主屏向右平移 240px → 露出底层 `WorkbenchSidebar` 的共用模块、项目和会话内容；Radix 管理活动侧栏焦点和主屏拦截。

导航动作 → 原有业务导航处理 + 关闭回调 → 主屏收回；纯关闭动作 → Radix 清理模态副作用 + 恢复原触发器焦点。仅跨断点 → 切换侧栏外壳，页面 Outlet 保持原位置与 key。

### 4.3 关键模块职责

| 模块／文件 | 本轮职责 | 边界 |
| --- | --- | --- |
| `layouts/MainLayout.tsx` | 唯一全局菜单接线、触发器记录、路由与断点清理、原宽度主屏右推 | 不复制菜单数据或会话业务 |
| `layouts/WorkbenchSidebar/WorkbenchSidebar.tsx` | 稳定控制层、现有菜单内容、桌面／窄屏外壳接线 | 不新增 Recoil 状态，不复制权限判断 |
| `layouts/WorkbenchSidebar/` 的展示辅助组件 | 复用现有模态能力、持有式项目展开与列表滚动恢复 | 不维护另一份移动菜单清单 |
| `SidebarConversationList`、`SidebarProjects` | 消费共享会话查询、受控展示状态及导航后关闭回调 | 项目仍沿用原有数据来源 |
| `components/Conversations/Convo.tsx` | 保持原有会话导航，同会话点击也可收起导航 | 更多操作或改名时不触发导航关闭 |
| `layouts/UserPopMenu.tsx` | 账号导航成功触发关闭回调 | 保留原有设置返回历史 |
| `routes/Root.tsx`、`components/Nav/` | 清理旧全局会话侧栏，保留快捷下拉及应用专属历史 | 不修改聊天生成及独立应用协议 |
| `components/ModuleHome/ModuleHome.tsx`、`pages/capabilities/CapabilityCenterPage.tsx` | 显式启用窄屏页头与工具列表排版 | 其他调用方默认外观不变 |

## 5. 已知坑与验证边界

| 事实／风险 | 如果忽略 | 处理位置／验证方式 |
| --- | --- | --- |
| 旧图标栏和新版侧栏的数据入口不同（已由调用链核对） | 窄屏继续缺少新版入口 | MainLayout 删除旧分支，复用 useSidebarEntries |
| 会话查询 key 不包含分页参数，分页数据共用一个 infinite query（已核对 queries.ts） | 为移动端另建查询可能重置页或与共享数据不同步 | 稳定侧栏层使用原 hook，列表／项目消费同一结果 |
| Convo 当前同会话点击会在 toggleNav 之前返回（已核对 clickHandler） | 点当前会话不会收起菜单 | 显式处理同会话关闭且不重复导航，行为测试 |
| Project 的 openIds 当前在组件局部状态中（已核对 SidebarProjects） | 浮层卸载后已展开项目关闭 | 稳定控制层受控保存展开 id；菜单开关／断点测试 |
| 网页菜单按钮不是统一的 Radix Trigger（已核对各页面 setSystemMenuOpen 调用） | 关闭后焦点可能回不到打开位置 | 在打开事件前记录真实触发器，测试点击／键盘及导航关闭 |
| usePrefersMobileLayout 在 DSH 中忽略窄宽（已有测试覆盖） | 直接按 CSS 宽度显示网页菜单会抢占宿主职责 | 沿用 hook 与 showPlatformNavigation 双门禁 |
| 模态强制挂载与嵌套 Portal 的焦点／层级行为需要浏览器验证 | 可能出现隐藏浮层锁页或子弹窗在菜单后方 | 不强制挂载关闭的模态；浏览器测背景滚动与嵌套操作，未实测前不宣称通过 |
