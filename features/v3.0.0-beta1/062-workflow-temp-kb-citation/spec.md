# Feature: 工作流临时知识库溯源（F062）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
> spec 只回答 **做什么 / 验收标准 / 不做什么**；所有 How 在 [design.md](./design.md)。
>
> **前置**：产品已裁定方向 B（要能点开，而不是关掉角标），并纠正口径：用户可见名称是「临时知识库」，不是内部对象名「临时文件」。F054 discovery §4.4 / §4.5 把该能力标为下一版；本 Feature 承接其中**工作流输入节点「解析并存入临时知识库」**这一条。

**关联需求**: 承接 F054 discovery §4.4 / §4.5 的下一版需求 + 产品裁定「工作流临时知识库问答要能溯源到原文」。无独立 PRD 文件。
**优先级**: P1
**所属版本**: v3.0.0-beta1
**依赖**: F054（文章来源类型、失效/无权限分态、匿名收紧）· F043（会话附件从临时存储提升为永久对象）· F029 / F041（正式知识库 `view_file` 与 INV-7 两档，本 Feature **不改**）

> **范围边界**
> - **本次纳入**：
>   - 工作流输入节点选择「解析并存入临时知识库」后，RAG / 知识检索 / Agent 从该临时知识库召回的内容，在答案里出可点击溯源角标。
>   - 悬浮看到来源类型「临时知识库」、文件名与引用片段；点击用**现有文件预览**打开原文；解析已给出页内位置时才高亮。
>   - 被答案实际引用的原件，在会话仍在时，历史回看仍能打开（不因临时上传过期而整批失效）。
>   - 未登录 / 读不到该会话 → 「暂无权限」；原件没了 → 「来源已失效」；两端（工作台与平台调试会话）文案与点击行为一致。
>   - **取代** F054 AC-16 / AC-17 中「工作流 Agent 检索临时文件不得出角标」——仅针对本范围。
> - **本次明确排除**：
>   - **日常模式上传附件溯源** —— 整段塞进提示词，无切片可发号；须先改成检索，单独立项（F054 discovery §4.5）。
>   - **灵思上传附件溯源** —— 不走检索工具，归 F047 后续。
>   - **「解析（不入库）」与「不解析（原始文件）」** —— 没有可检索的临时知识库切片，本期仍不出临时知识库角标。
>   - 不把临时知识库升级为可在知识空间里管理的正式库；不改 INV-7；不把临时来源纳入知识空间权限模型。
>   - 不保证所有格式都有页内高亮；不新增角标颜色；不做两端角标组件合并；不做导出件烘焙。

## 1. 用户故事

作为 **在工作流里上传文件并提问的业务用户**，
我希望 **答案引用我上传内容的地方带可点击角标，点开能看到原文和引用段**，
以便 **确认这句话来自哪一份上传文件，而不是模型自己的发挥**。

作为 **对数据可见性敏感的管理员 / 合规角色**，
我希望 **未登录的分享页不能打开这些会话上传文件**，
以便 **不会因为一条分享链接把用户上传的原件泄漏出去**。

作为 **回看历史答案的用户**，
我希望 **当时真正引用过的文件过几天仍能打开；文件没了时明确告诉我「来源已失效」，而不是「暂无权限」**，
以便 **区分「我没权限」「文件没了」和「系统坏了」**。

## 2. 验收标准

> AC-ID 在本特性内唯一。字段名 / 存储键 / 函数名等实现细节见 design.md。
> 本 Feature **取代** F054 的 AC-16、AC-17（仅工作流「解析并存入临时知识库」召回）。日常附件与灵思上传仍按 F054 排除。

### 2.1 临时知识库召回可溯源

- **AC-01** — WHEN 工作流 RAG、知识检索或 Agent 从输入节点「解析并存入临时知识库」的结果中召回内容, THE SYSTEM SHALL 为被召回的文件登记可溯源来源，并使模型在读到该内容时能获得对应来源标识。
- **AC-02** — THE SYSTEM SHALL 为这类来源使用**真实稳定的原件定位**（能打开用户上传的那份文件），**不得**伪造正式知识库的文件标识，也不得把它展示成知识库文档。
- **AC-03** — WHEN 模型撰写答案并使用了已登记的临时知识库来源, THE SYSTEM SHALL 使答案正文在对应句 / 段位置内联携带该来源的溯源标记；未使用时不产生标记。
- **AC-04** — WHEN 用户悬浮该角标, THE SYSTEM SHALL 展示来源类型「临时知识库」、文件名与引用片段。
- **AC-05** — WHEN 用户点击该角标或来源文件名, THE SYSTEM SHALL 用现有文件预览打开原文，并展示引用段；**不得**走进正式知识库文件预览。
- **AC-06** — WHERE 解析已给出页内位置, THE SYSTEM SHALL 在预览中定位到该引用段。WHERE 解析未给出页内位置, THE SYSTEM SHALL 仍打开原文并展示片段，只是不在页内高亮。
- **AC-07** — WHEN 一轮回答结束, THE SYSTEM SHALL 仅把答案中**实际引用到**的临时知识库来源持久化并绑定到该回答；重复处理同一条回答不产生重复来源记录。
- **AC-08** — WHERE 某来源在答案中被实际引用且该会话仍存在, WHEN 用户在临时上传保留期之后回看该历史答案, THE SYSTEM SHALL 仍能打开对应原文。
- **AC-09** — WHERE 用户上传了文件但本轮答案并未引用它, THE SYSTEM SHALL NOT 要求该原件在临时上传保留期之后仍然可打开。
- **AC-10** — WHEN 同一输入里上传了多份文件且答案分别引用了它们, THE SYSTEM SHALL 把每一份被引用的文件作为独立来源展示，不得把多份文件合成一条来源。

### 2.2 混用、入口与回归

- **AC-11** — WHEN 同一轮答案同时引用正式知识库与临时知识库, THE SYSTEM SHALL 让两类角标并存：正式知识库来源仍按既有知识库预览跳转，临时知识库来源按 AC-05 打开上传原件。
- **AC-12** — THE SYSTEM SHALL 保持正式知识库、知识空间、频道文章、网页、日常模式附件、灵思上传的既有溯源行为不变。
- **AC-13** — WHEN 输入节点策略是「解析（不入库）」或「不解析（原始文件）」, THE SYSTEM SHALL NOT 为这些文件产生临时知识库角标（它们没有可检索切片）。

### 2.3 权限与失效

> **口径**：临时知识库不是知识空间资源，不走正式知识库的两档可见性。解析时的闸门是「当前查看者是谁、能不能读这条会话」。
> 未登录一律不返回详情，与 F054 AC-14 对知识库 / 文章的收紧同向，避免分享页泄漏会话上传物。
>
> **已裁定（2026-09-09）**：免登录独立工作流里，上传者点自己刚传的文件 **仍按无登录处理，不可点**。访客页没有稳定的访客主体；放开等于谁拿到答案里的来源标识谁就能换原件签名。若后续要「当场能点开」，须另做按会话绑定的访客票，不在本 Feature。

- **AC-14** — WHEN 已登录且有权阅读该会话的用户请求临时知识库来源详情, THE SYSTEM SHALL 返回足以展示与打开原文的信息。
- **AC-15** — WHERE 请求不携带已登录用户身份（含免登录分享页、免登录独立工作流，以及该次运行中上传者点击自己刚上传的文件）, THE SYSTEM SHALL 不返回临时知识库来源详情，并按「暂无权限查看该来源」呈现。
- **AC-16** — WHERE 已登录用户无权阅读该会话, THE SYSTEM SHALL 不返回临时知识库来源详情，并按「暂无权限查看该来源」呈现。
- **AC-17** — WHERE 查看者有权阅读该会话，但对应原件已不可打开, THE SYSTEM SHALL 把该角标呈现为「来源已失效」，且与「暂无权限」文案可区分。
- **AC-18** — WHERE 无权限与已失效同时成立, THE SYSTEM SHALL 一律呈现为「暂无权限查看该来源」（不向无权限者暴露该来源是否曾经存在）。
- **AC-19** — WHERE 分享页或免登录独立工作流中的临时知识库角标因 AC-15 无法解析, THE SYSTEM SHALL 按不可点状态呈现并保留答案正文，不得报错、不得使页面渲染失败。

### 2.4 文案与两端一致

- **AC-20** — THE SYSTEM SHALL 使用户可见的来源类型名为「临时知识库」，具备 zh-Hans / en / ja 三语，且不在源码中硬编码中文；内部对象名不得出现在界面上。
- **AC-21** — THE SYSTEM SHALL 在任何用户可见状态下只展示角标序号与可读来源信息；内部引用键、片段标识与协议标记始终不可见。
- **AC-22** — THE SYSTEM SHALL 使工作台会话与平台调试会话对临时知识库角标使用同一套类型识别、预览跳转，以及「暂无权限 / 来源已失效」区分。

### 2.5 非侵入

- **AC-23** — IF 来源登记 / 标注 / 原件保留过程发生任何异常, THEN THE SYSTEM SHALL 回退到不带该条溯源的结果并继续作答；溯源失败不得使问答报错或中断。
- **AC-24** — IF 历史消息缺少本 Feature 的结构化溯源数据, THEN THE SYSTEM SHALL 原样保留答案，不补造角标、不报错。
- **AC-25** — WHEN 同一答案在流式生成、生成完成、历史回看、分享等状态下展示, THE SYSTEM SHALL 使用同一份溯源数据，角标序号与来源归组保持一致。

## 3. 边界情况

- **模型未引用临时知识库内容** → 答案无对应角标，不持久化该来源（正常）。
- **同一句引用多个来源** → 相邻多个角标；同一来源重复引用复用同一序号。
- **模型漏发或错发标记** → 已注册的正常渲染；未注册的标记在保存前清除。
- **解析未给出页内位置** → 仍可打开原文并看片段，只是不高亮（AC-06，不是缺陷）。
- **多文件同一输入** → 各文件独立来源（AC-10）；未引用的文件不要求长期保留（AC-09）。
- **正式库与临时库混用** → 两类角标并存、跳转各走各的（AC-11）；答案正文不因此断裂。
- **无会话的调试运行** → 允许本轮作答出角标；不要求跨天历史回看仍能打开原文。
- **分享页 / 免登录独立工作流未登录** → 临时知识库角标不可点（含上传者点自己刚传的文件），正文不受影响（AC-15 / AC-19）。不把发布链接上的 share-token / 默认操作人当成「已登录的上传者」。
