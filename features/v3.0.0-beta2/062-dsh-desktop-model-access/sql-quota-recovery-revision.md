# SQL 自动恢复额度账本（2026-09-11）

用户已确认：取消 MinIO 证据与人工确认；Redis 丢失账本后从 SQL 已落库数据自动恢复，接受无法找回的异步尾部用量丢失，不推算、不补扣。此修订替代旧版 quota-operations 中外部证据、run_id 人工批准与确认文件的要求。

## 行为与验收

- 移除 quota_evidence_bucket、quota_approval_object、quota_approval_sha256，DSH 不再访问 MinIO。取消依赖证据的人工恢复/补录命令。
- Redis 连接恢复后可自动继续。完整账本原样保留，不能因应用或 Redis 重启重置用量。
- 缺失/不完整账本按用户恢复：合并 SQL 明细及尚存 Redis 请求的最新版本；SQL 月度汇总与明细核对，不能将读取失败当作零。类型损坏、身份冲突等无法确认的数据拒绝恢复，不自动猜测修正。
- 尚存 Redis 用量优先保留；只在 SQL 存在的 RUNNING 请求恢复成 USAGE_UNKNOWN，不伪造 Token 数。各用户/模型/月独立。
- 多进程恢复由共享租约及写入所有权保护，恢复期间该用户暂停新调用/额度变更；SQL 策略变化后重试，不覆盖新配置。
- 保留 SQL 先提交后 ACK、事件版本幂等以及模型独立额度的既有语义。公共客户端 API、License、部门、席位不变。
- 落库仍为 5 秒定时扫描加队列和数据库耗时；30 秒积压保护不是延迟承诺，不改为同步扣费。

## 验证计划

空实例首次授权；Redis 完全丢失、部分月份丢失、重启但数据完整；两恢复者竞争及租约过期；已有实时用量保留；重放不重复累计；未落库用量损失边界；策略更新中恢复；不依赖 MinIO；MySQL/DM 通用 ORM；DSH 模型/API 回归。

部署时移除三个旧配置，保留 SQL 和 Redis 数据。历史 MinIO 对象不由应用删除。此变更不包含 109 部署。
