# 个人授权保存与历史用量恢复修复

## 根因与修复

线上 SQL 的 `started_at` 使用秒精度 DATETIME，Redis 请求保留微秒。例如同一请求 SQL 为 `05:42:15`，Redis 为 `05:42:14.662861`。恢复使用完整请求身份哈希比较，两者因此冲突，个人策略停留在 REGISTERED/PROCESSING，后台每 5 秒重试，最终授权仍显示旧状态。

恢复首次合并 SQL 记录与 Redis 记录时，只允许 SQL 时间等于 Redis 时间的秒级截断值或四舍五入值，采用存活记录的精确时间。其余身份字段继续严格比较；后续 Redis 记录之间继续完整精度比较。保留事件版本、Token 一致性校验和累计用量，沿用原操作 ID 继续提交。

前端个人授权保存采用最大 3 个并发任务，一个用户等待恢复时其他用户继续提交。完成项及时回读最终权限；失败草稿及未决操作 ID 保留，原有查询后重试流程继续适用。
