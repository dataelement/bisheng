# Feature: 沙箱接入参数页面配置

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。How 的唯一真相在 [design.md](./design.md) 与 [tasks.md](./tasks.md)。

**关联 PRD**: 无独立 PRD。需求来源：2026-10-20 需求「沙箱的地址在页面上配置，实时生效」，Spec Discovery 已与需求方确认三项决策（见 §5）
**优先级**: P1
**所属版本**: v3.0.0-beta1
**依赖**: F068-code-execution-sandbox（沙箱执行模式、服务地址列表 `endpoints`、管理端「代码执行方式」弹窗）

> **范围边界**
> - **本次纳入**：
>   - 在管理端代码执行器的配置弹窗里选「沙箱运行」后，在弹窗中填写沙箱服务地址与访问令牌
>   - 保存后 60 秒内，backend、Celery worker、Linsight 三类进程上新发起的执行使用新参数，不重启任何进程
>   - 页面配置与部署配置（环境变量 / `config.yaml`）并存：页面填了的字段优先，留空的字段沿用部署配置
>   - 「测试连接」：保存前验证地址可达、令牌被接受
> - **本次明确排除**：
>   - **按主机名自动找副本**——产品里不再有这套扫描和对应配置（主机名模式、起始序号、端口、刷新间隔）。副本只来自页面或部署配置里的服务地址列表
>   - **超时、副本池大小、发现刷新间隔、copy-in 上限、本机隔离等参数的页面化**——运维调优参数，误改代价高，继续只走部署配置
>   - **runner 自身的参数**（会话数、租约 TTL、会话 uid 隔离）——属于 runner 容器，平台改不到
>   - **按租户分别配置沙箱**——沙箱副本池是部署级基础设施，没有按租户隔离的需求
>   - **废弃环境变量配置**——保留为兜底，存量 Compose / Helm 部署靠它
>   - **网络可达性**——页面改得了地址，改不了网络。新地址能否被三类进程访问（Compose 的 `sandbox_net`、Helm 的 NetworkPolicy）仍是部署侧责任
>   - **E2B 模式与本机模式的配置**——不改

---

## 1. 用户故事

作为 **平台超级管理员**，
我希望 **在管理端直接改沙箱的接入地址和令牌，保存后 60 秒内生效**，
以便 **换沙箱集群、扩缩副本或轮换令牌时，不必改环境变量再重启 backend、worker、Linsight**。

作为 **私有化交付的实施人员**，
我希望 **不在页面上填写时，沙箱只用部署配置里的服务地址列表；需要时再在页面上覆盖**，
以便 **清空页面配置就退回这份列表**。列表为空时沙箱执行按不可达失败，不再按主机名去找副本。

## 2. 验收标准

### 2.1 配置入口与权限

- **AC-01** — WHERE 管理端代码执行器配置弹窗中「代码执行方式」选中「沙箱运行」, THE SYSTEM SHALL 在同一弹窗中展示两项输入：沙箱服务地址（可填一个或多个，每个地址对应一台沙箱副本）与访问令牌，并随弹窗的「保存」一起保存。
- **AC-19** — THE SYSTEM SHALL 在沙箱服务地址的提示中写明：多台副本要逐个填写各自的地址，不要只填一个负载均衡地址，否则任务模式同一任务的多次执行可能落到不同副本、读不到上一步的文件。
- **AC-02** — THE SYSTEM SHALL 仅允许全局超级管理员读取与保存沙箱接入参数；其他身份调用读取或保存一律被拒绝。
- **AC-03** — THE SYSTEM SHALL 使沙箱接入参数在整个部署中只有一份：在任一租户下保存后，对全部租户的执行生效。
- **AC-04** — THE SYSTEM SHALL 在读取时只回显访问令牌的掩码；保存时提交掩码视为不修改令牌。令牌不得以明文存入数据库或缓存，明文也不得出现在任何读取接口响应、日志与审计记录中。
- **AC-05** — WHERE 执行方式切换为「本地隔离运行」或「E2B沙箱运行」, THE SYSTEM SHALL 保留已保存的沙箱接入参数，切回「沙箱运行」时原值仍在。

### 2.2 生效与优先级

- **AC-06** — WHEN 管理员保存沙箱接入参数, THE SYSTEM SHALL 使 backend、Celery worker、Linsight 三类进程上此后新发起的沙箱执行在 60 秒内改用新参数，不重启任何进程。日常会话的每条消息、助手的每一轮对话、工作流的每一次运行都算新发起的执行。任务模式中已经绑定副本的任务不在此列，仍按 AC-11。保存时把新值写入缓存；写入失败不让保存失败。当时还没写完的旧读取不得盖掉这份新值。写失败后若缓存里仍是旧值，该缓存在 60 秒后过期，仍落在此时限内。
- **AC-07** — THE SYSTEM SHALL 对沙箱服务地址与访问令牌两项分别判定：页面上填写了的项优先于部署配置；留空的项使用部署配置（环境变量 `BS_SANDBOX_CONF__*`，其次 `config.yaml`，再次代码默认值）。地址只来自这两处的服务地址列表，不按主机名查找副本。
- **AC-08** — THE SYSTEM SHALL 在弹窗中为沙箱服务地址与访问令牌分别标明当前生效值的来源（页面配置 / 部署配置 / 默认值）。某一项的来源只看这一项：页面上该项有值为页面配置，否则部署配置里该项有值为部署配置，否则为默认值。地址输入回显的是页面保存的列表，可以为空；部署地址不写入该输入。令牌只显示来源和掩码，不显示值。
- **AC-09** — WHEN 管理员清空全部页面配置并保存, THE SYSTEM SHALL 使执行行为恢复为仅由部署配置决定，与本 Feature 上线前一致。
- **AC-10** — WHERE 部署从未在页面上保存过沙箱接入参数, THE SYSTEM SHALL 只用部署配置中的服务地址列表。列表为空时，沙箱执行按不可达失败，不按主机名查找副本。
- **AC-11** — WHILE 保存发生时已有沙箱执行在进行, THE SYSTEM SHALL 让其在已占用的副本上完成，不因保存而中断；任务模式中已绑定副本的任务在本轮结束前继续使用该副本，新任务与新一轮使用新参数。

### 2.3 校验与测试连接

- **AC-12** — IF 提交的沙箱服务地址不合法（不是 `http` / `https` 地址、缺少主机名、端口越界、含空地址、去掉末尾 `/` 后同一地址重复、或超过 32 个）, THEN THE SYSTEM SHALL 拒绝保存并返回 28009，已保存的配置保持不变。比较与落库前先去掉每个地址末尾的 `/`。
- **AC-13** — THE SYSTEM SHALL 允许保存未通过测试连接的接入参数（例如副本尚未启动），保存不以测试通过为前提。
- **AC-14** — WHEN 管理员点击「测试连接」, THE SYSTEM SHALL 使用页面当前填写值（未保存也可，令牌为掩码时用已保存的令牌）从平台服务进程逐个探测（页面未填地址时探测部署配置里的服务地址；部署也没有地址则没有可探测的目标）。探测前按 AC-12 校验地址，不合法则返回 28009 且不发请求；合法地址先去掉末尾的 `/`。每个地址的连通与建会话各等待 5 秒，超时视为不可达。返回每个地址的结果；结果区分「不可达」「令牌不被接受」「副本繁忙、令牌未能验证」与「可用」。
- **AC-15** — THE SYSTEM SHALL 在测试结果旁明示：结果只代表平台服务进程的网络可达性，Celery worker 与 Linsight 进程能否访问需按部署说明另行验收。
- **AC-16** — THE SYSTEM SHALL 使测试连接在结束后不残留占用的副本会话。

### 2.4 审计与文档

- **AC-17** — WHEN 管理员保存沙箱接入参数, THE SYSTEM SHALL 写一条审计记录，包含操作人、时间、来源 IP 与变更的字段名；令牌只记录「已修改」，不记录值。
- **AC-18** — THE SYSTEM SHALL 在《沙箱部署说明》与《沙箱使用说明》中写明页面配置入口、字段优先级、生效时限，以及「页面改不了网络可达性」。

## 3. 边界情况

- 缓存里的内容不是约定结构，或缓存不可用时，改读数据库，本次使用库里的值。这条读取不写缓存，坏缓存留到它自己过期；保存仍会覆盖缓存。库里的内容也不是约定结构、密文无法解密，或数据库也不可用时，退回部署配置并记录错误日志。已经读到合法库值之后，写缓存失败仍使用这份库值。不得因此改走本机执行，也不得因此让沙箱执行中断。弹窗读取遇到坏结构时按没有页面配置展示，以便重新保存。日志与缓存不得出现令牌明文。
- 两位管理员先后保存时，以后保存者为准，不做合并。
- 页面填写服务地址后，沙箱执行只使用这些地址。清空页面地址后，改用部署配置里的服务地址列表；该列表为空则没有副本。
- 新地址不可达时，沙箱执行按既有沙箱不可用的失败语义返回（F068 AC-05），不回落到本机执行。
- 令牌被修改后，已在进行中的执行使用旧令牌完成；新执行使用新令牌。
