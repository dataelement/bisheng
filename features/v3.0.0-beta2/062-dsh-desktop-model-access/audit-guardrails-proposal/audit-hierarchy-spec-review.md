# 父子会话嵌套展示：规格增量检查

日期：2026-10-19。阶段：spec 0.23确认前；没有代码实施、测试通过或部署声明。

## 来源与现状

- 用户要求子Agent会话放在父会话历史中，并确认“父会话内折叠、子会话原始审计独立、父关系不可用或冲突时单独提示”的调整方向。
- 前轮只读核对109租户1：截图子会话38条请求均声明subagent、指向同一父会话；该父会话已有62条审计请求。该证据仅说明这组已有元数据可支持关系组织，不证明其他历史会话均有合法父关系，也不把真实记录内容带入测试。
- 当前`model_audit_conversations.py:project_request/group_page`按各自会话归组；`ModelAuditPanel.tsx`平铺渲染组。`parent_conversation`只定位父会话，没有层级查询或跨页嵌套。客户端无需为截图这组数据再补报；服务端/管理页尚需设计和实现。

## 本次规格变更

| 范围 | 规格依据 | 检查结论 |
|---|---|---|
| 原始归属与浏览层级分离 | §4.2.1、AC-H01 | 不改请求编号、会话编号、用量或正文去重范围 |
| 跨页、多子节点、多层 | AC-H02 | 目录/子集合/请求分别分页，不允许仅拼当前前端页；深层到边界给继续查看入口 |
| 缺失、冲突、循环与Fork | AC-H03 | 不擅选父声明，不猜未知来源，不丢独立入口；不建立权威任务因果树 |
| 筛选和精确定位 | AC-H04 | 子请求命中保留父路径；所有条件必须同一请求满足 |
| 数量与异常范围 | AC-H05 | 明示本会话与含子汇总，父正常不能掩盖子异常；未知不冒充正常 |
| 授权和原文 | AC-H06、AC-H09 | 仅同租户同历史用户关联，节点展开无正文读取，逐请求授权/留痕保持 |
| 旧数据与资料准备 | AC-H07 | 复用已存字段，缺字段不猜；准备中不隐藏入口，迟到和冲突刷新可见 |
| 可用性与资源 | AC-H08 | 不无限读树、不阻塞模型或用量，不把关系故障标作正文/模型故障 |

本次未变更客户端线协议、模型入出参、审计模式、加密格式、席位或配额真相。参照release-contract的F062领域归属及B2-INV-7、constitution C1至C8，没有新增跨Feature归属变化；实际架构合规仍需下一步设计审查。

## 检查边界与结论

按仓库sdd-review的spec增量清单检查：本次新增AC唯一、可测试，有需求来源、异常边界、非目标及测试样本；AC-H01至AC-H09没有冻结技术栈、数据库结构或数值SLA。原spec中既有接口/预算等How描述未在本次全面清理，不能据本次增量检查声称全篇规格已重新评审通过。

本次增量未发现需要阻断规格确认的high/medium问题；不是设计评审或功能验收。下一阶段必须明确：关系事实如何有索引且有界地维护、顶层分页去重、只命中子分支时的筛选、跨层统计、循环/冲突与迟到关系收敛、历史准备和回滚。不能在这些设计未明确时直接实现页面缩进。

**当前停在规格用户确认点。** `docs/SDD-Guide.md` §2、§3及仓库sdd-review流程要求确认后才继续设计；本轮没有生成新数据库模型、迁移、接口或页面代码，也没有执行应用测试或操作109。
