# Feature: 标准 Helm 交付与可选环境诊断

**状态**：规格已由用户于 2026-11-10 确认；跨 Vibe 合同审查修订后通过，按最新设计实施，源码与定向验证完成，真实集群待验。原 F007 因发版线占号顺延 F009，验收标准正文不变。
**关联需求**：[discovery.md](./discovery.md) 中记录的用户部署要求及最后确认的简化方案。
**优先级**：P0
**所属版本**：v3.1.0-beta1
**依赖**：F054/F055/F056 托管应用、发布与治理，F086 运行交付、F059 Kubernetes runtime、F114 全操作权限与协议统一、F119 清单/启动兼容、F115 审批展示及 F048 权限；已合入发版线的 R1–R10 通用修复。

**用户后续范围决定（2026-11-10）**：不考虑旧部署接入标准 Helm 的兼容迁移；已启用内置沙箱后再关闭时，已保存端点/执行器的联动缺陷延期，不作为本期阻塞。本期默认开启并持续使用。此项仅缩小 AC-12 对该切换场景的验收，其他开关和升级保留要求不变；具体边界见 [复评澄清 §2、§5](./design-clarifications.md)。

## 1. 用户故事与范围

作为部署运维人员，我希望从毕昇 GitHub 获取标准 Chart，通过部署参数选择基础组件、网络、资源和存储，以便在满足运行前提的新集群安装，不再复制 122 的主机操作或容器启动补丁。

作为应用开发者，我希望无需等待人工环境验收或定期更新验收报告即可提交 Vibe 应用，同时在镜像、依赖构建、应用启动出错时获得实际错误，并保持应用权限和持久化数据保护。

作为平台管理员，我希望官方运行环境自动可用，并沿用首次注册成为超管的流程，不额外导入模板或注册内置管理员。

本次纳入：标准公开 Chart、基础组件与 Gateway 选装、Vibe/代码沙箱默认开启、通用配置参数化、运行环境诊断与业务准入解耦、官方模板初始化、部署教程及代码验证。

本次排除：镜像构建/发布、线上部署、122 既有数据或 release 迁移、宿主磁盘格式化、存储驱动安装、新增模板管理页面、预建管理员、未经测试的跨架构/离线/高可用可用性承诺。

取消强制诊断及报告时效的范围仅为 Kubernetes 执行域。Docker/legacy systemd 的宿主隔离及其有效性要求保持不变。本轮不发行镜像，不削减 F086 对未来正式发行的双架构及真实验收要求。

## 2. 验收标准

### 2.1 环境诊断与应用执行

- **AC-01** — WHERE Kubernetes 执行域配置有效且运行服务正常，THE SYSTEM SHALL 允许应用正常准入，不要求用户先执行集群环境诊断或提供诊断报告。
- **AC-02** — WHERE 使用 Kubernetes 执行域，WHEN 未执行手动环境诊断、诊断报告超过 24 小时或仅报告时间发生变化，THE SYSTEM SHALL 不因此阻断应用构建、部署、恢复或已运行应用的入口访问。
- **AC-03** — WHEN 运维显式运行手动诊断，THE SYSTEM SHALL 执行真实检查，输出逐项结果和失败原因；未执行的检查 SHALL 标为未检测，不伪造通过证据。
- **AC-04** — WHERE 使用 Kubernetes 执行域，THE SYSTEM SHALL 不默认安装环境验收 Job、环境巡检 CronJob 或要求外部定期刷新诊断报告；手动诊断结果 SHALL 不单独改变业务运行准入，也不得覆盖 AC-06/AC-07 的实际配置、执行或安全错误。
- **AC-05** — WHEN 用户提交应用，THE SYSTEM SHALL 按所选交付方式保留其适用的镜像检查、依赖解析/下载/构建、应用启动及健康检查，并在实际失败时中止该次发布并报告对应错误；完整镜像方式不强制重复执行源码依赖安装。
- **AC-06** — THE SYSTEM SHALL 保留实际执行时的身份与业务鉴权、入口/出站网络隔离、最小 RBAC 与禁止 exec/attach/portforward、受控 Pod 模板/准入、资源预算、单活动写入者、精确 Pod UID 停止证明和未知状态下的数据保护；不得将“取消诊断门槛”解释为取消上述控制。旧 UID 已为 false 或未知的保护历史 SHALL 不因配置声明、模式升级、新心跳或诊断恢复而被追认为已持续受保护。
- **AC-07** — WHEN 集群 API、实际镜像、材料链路、挂载存储或应用运行出现错误，THE SYSTEM SHALL 按实际失败处理；不能用未检测或历史通过的诊断报告覆盖错误。

### 2.2 标准安装与组件选择

- **AC-08** — THE SYSTEM SHALL 在毕昇 GitHub 项目中维护唯一标准安装入口及对应发行打包方式；发行物包含固定版本的安装依赖，安装不依赖 122 私有部署仓库。
- **AC-09** — THE SYSTEM SHALL 支持 MySQL、Redis、MinIO、Elasticsearch、Milvus、OpenFGA 独立选择随安装部署或连接外部服务，并支持内置与外部混用。
- **AC-10** — WHERE 某基础组件使用外部服务，THE SYSTEM SHALL 不创建该组件的服务实例或接管客户既有 release；外部数据库的建库、账号和授权前提 SHALL 明确说明，应用仅操作其授权范围内的数据。
- **AC-11** — WHERE Gateway 未启用，THE SYSTEM SHALL 不创建其工作负载、数据库初始化或必需引用；WHERE Gateway 启用，THE SYSTEM SHALL 提供对应版本的配置和必要初始化说明。当前原生 DSH 基本登录 SHALL 不因 Gateway 关闭而被强制关闭。
- **AC-12** — WHEN 通过标准 Chart 全新安装且用户未覆盖默认值，THE SYSTEM SHALL 默认启用 Vibe 和代码沙箱，并提供分别关闭的配置及说明；升级 SHALL 保留用户显式关闭的部署配置及已保存的功能设置，不将 false 当作缺失值，也不自动改变既有代码执行模式、端点、凭据或会话绑定。关闭后 SHALL 移除悬空上游依赖，同时保留既有未启用引导页、前端隐藏及角色权限点不变的语义。
- **AC-13** — WHEN 用户在全新环境首次注册，THE SYSTEM SHALL 沿用首个注册用户成为超管的既有流程，不预建管理员、伪造用户或写入固定管理员密码。
- **AC-14** — WHEN 首次安装 Vibe，THE SYSTEM SHALL 仅从受信发行物自动初始化官方运行环境及缺失的语言默认项，记录系统初始化来源，无需管理员首次登录或手工导入；全局环境的人工登记、替换和默认选择 SHALL 仍仅允许平台超管，不向 Manager、普通用户或服务账号开放该管理权。升级 SHALL 保留用户已选择的默认项，拒绝同一不可变版本的内容冲突，且不改变已冻结、审批中或正在运行版本的环境组合。
- **AC-15** — THE SYSTEM SHALL 沿用各服务正常初始化入口，补齐全新环境缺失的必要初始化；升级不得无条件覆盖既有授权模型或业务数据。关闭 Gateway/Vibe 时不执行其专属初始化。

### 2.3 参数、存储、凭据及升级

- **AC-16** — THE SYSTEM SHALL 提供组件资源、启动/健康检查、调用/阶段超时、调度、命名空间、网络和存储参数，并对非法值或不一致的组合给出明确校验错误。
- **AC-17** — WHEN 调整托管应用系统 Helper 的资源、镜像检查期限或调度参数，THE SYSTEM SHALL 在生产请求、执行及准入验证中使用一致策略；重试或进程重启不得重置已开始操作的总期限，也不得改写已冻结操作。资源档位可按既有合同提供部署期初始规格，但已有管理员修改及运行实例的冻结规格 SHALL 不被升级或新默认值覆盖，应用继续经档位及容量预约准入。
- **AC-18** — THE SYSTEM SHALL 不在标准安装路径硬编码 122 IP、主机名、节点名或主机目录；不通过 ConfigMap 注入或替换业务 Python 代码来启动服务。
- **AC-19** — THE SYSTEM SHALL 按存储用途支持容量、StorageClass、已有 PVC 和合法访问模式配置；默认 StorageClass 与显式无 class 静态卷语义 SHALL 区分，不统一要求平台提供 RWX，不自动格式化客户磁盘。
- **AC-20** — WHERE 应用使用持久化数据，THE SYSTEM SHALL 保留已声明的文件系统、容量、文件锁和持久化兼容要求，并明确发布当前支持范围；未确认的 CSI 不得被描述为已验证兼容。
- **AC-21** — THE SYSTEM SHALL 支持已有凭据 Secret；新建示例数据库密码可提供公开默认值和修改提醒。内部签名根、服务身份密钥和内部 TLS 私钥 SHALL 为每次安装独立生成或由用户提供，升级 SHALL 保持其稳定。
- **AC-22** — WHEN 同一集群安装不同 release 或共享平台命名空间，THE SYSTEM SHALL 隔离资源名称、选择器和管理范围，不修改其他 release 的命名空间安全标签或业务资源。
- **AC-23** — WHERE 全新安装选择在线模式，THE SYSTEM SHALL 仅在既有受控材料下载阶段支持配置允许的依赖源访问；安装、编译及正式运行阶段 SHALL 保留各自既有出站限制。升级 SHALL 保留环境已选择的离线、镜像拉取及运行出网策略，不自动回退公网。THE SYSTEM SHALL 提供企业镜像源及离线模式说明；可写 OCI 仓库仅作为需要推送镜像的执行方式的前提，不阻断其他合法交付方式。
- **AC-24** — THE SYSTEM SHALL 提供安装、外部依赖、关闭功能、参数调整、手动诊断、升级/卸载保留数据和常见故障处理教程，并明确声明 CNI/CSI 等运维前提及镜像兼容范围。
- **AC-25** — THE SYSTEM SHALL 覆盖默认/外部/混合依赖、功能开关、双 release 隔离、升级保留密钥与默认项、无诊断报告及超过 24 小时的业务回归验证；模板检查 SHALL 不被记作真实集群安装成功。
- **AC-26** — WHILE 本轮交付仅限源代码和部署文件，THE SYSTEM SHALL 不构建或发布镜像，不更新线上服务；发行打包 SHALL 拒绝缺少兼容镜像锁定清单，不捏造 digest 或宣称旧 v3.0.0 镜像含本次新代码。

## 3. 边界情况

- 配置非法、外部服务不可达、镜像或许可证缺失，应定位到相应组件与字段，保留真实错误。
- 诊断未执行、结果失败、报告过时是诊断状态，不等同于应用故障；实际运行失败仍阻止相应操作。
- 取消诊断门槛不清除历史未知写入者记录，不绕过业务授权，不自动释放可能仍被使用的持久卷。
- 动态卷、静态预置卷、已有 PVC 的供应与回收条件需要分别说明；已有数据不能因失败重试被删除。
- 多副本与 RWO 挂载拓扑不兼容时，应拒绝错误配置或要求选择明确支持的存储布局。
- 用户提供的默认项、Secret 和外部组件归属在升级时保持，不由新默认值覆盖。
