# Feature: F083-expert-qa-enhancement（专家问答：定向/公开与转公开）

> **前置**：Spec Discovery 已通过 grilling（2026-08-12）完成，结论已回写 [`prd.md`](./prd.md)。

**关联 PRD**: [`prd.md`](./prd.md) §3.2.6（权威；不回写 Word）  
**技术方案（权威）**: [`design.md`](./design.md)（DB / OpenAPI 契约 / 流程图；旧 impl-plan 作废）  
**优先级**: P0  
**所属版本**: v2.6.0  
**模块编码**: **183**（新建 `common/errcode/qa_expert.py`；已在 `release-contract.md` 登记）  
**依赖**: 现有 `qa_expert` + F012 多租户 + message（`inbox_message`）+ knowledge/permission（文档鉴权）+ F070 采纳挂钩（只调用、不夺写）+ Portal 会话角色（`isPortalAdmin`）

> **范围边界**
> - **纳入**：定向/公开类型与可见性；三态展示（未回答/待采纳/已解决）；首答锁定；公开题首次采纳资格快照；匿名稳定别名与定向预存公开姓名；转公开审批；专家软停用；账号停用联动；专家库管理员服务端鉴权与破匿名；通知统一 inbox；存量题默认公开。
> - **明确排除**：问题关闭/隐藏下架态；账号硬删匿名化；投票规则重写；积分账本/幂等键改写；Portal 自建问答表；将门户「管理员」升格为 `is_global_super`。
> - **端侧**：用户端与专家库管理 → **Portal**；领域写模型 → **BiSheng `qa_expert`**。

## 1. 概述与用户故事

**故事 A（提问者）**：  
作为 **一线业务用户**，  
我希望 **发起定向或公开提问、邀请专家、采纳回答，并在定向题解决后申请转公开**，  
以便 **获得可信解答并在合适时共享给更多同事**。

**故事 B（认证专家）**：  
作为 **有效专家**，  
我希望 **在资格范围内回答、互动，并参与转公开审批**，  
以便 **贡献专业能力且控制内容是否公开**。

**故事 C（专家库管理员）**：  
作为 **门户管理员（专家库管理员）**，  
我希望 **维护专家有效/停用、查看定向题与匿名真实身份**，  
以便 **运营专家池并处理敏感内容治理**。

**故事 D（平台超管）**：  
作为 **平台超管**，  
我希望 **对违规问答内容执行删除（±积分扣减）**，  
以便 **内容合规且激励可追溯**。

| AC-12 | 定向题 | 非受邀有效专家尝试回答 | 拒绝 |

## 3. 边界情况

- 定向阶段展示实名；转公开后才按预存选项匿名/实名。  
- 转公开审批中禁止删除回答；结束后未采纳答可删。  
- 关联文档无权限：正文仍可见，文档入口不可用；文案不得写成「文档不存在」。  
- 关联文档有权限：选择器与详情打开同一 `space_id`+`file_id`（门户 durable entry）；打开成功并显示标题。  
- 「文档不存在」仅真删除 / 知识库无有效 entry。  
- 并发转公开末人同意 vs 新答人加入：申请行锁/版本号，保证审批人集合与通过判定一致。  
- 列表筛参与业务态混用：以附录/AC-03 为准，单测锁定。  
- 定向评论门槛：仅「本问题已有有效回答」的专家可评；提问者追问不受该门槛限制。  
- 转公开延期：单次 +1 天、累计封顶 +3 天后不再因新增审批人延期。

**不支持**：见 AC-37～40 与 PRD §3.2.6.9。

## 7. Service 层逻辑

> 位置：`bisheng/qa_expert/domain/services*.py`（可拆 `publish_request_service` 等）。  
> **禁止** Endpoint 直接 ORM；**禁止**新 DAO 入口绕过 Repository（沿现网仓库模式收敛）。

### 核心方法

| 方法 | 职责 |
|------|------|
| `create_question` | 校验类型/邀请数；写匿名预选项；初始未锁定 |
| `submit_answer` | 资格校验；事务写回答；原子锁；通知 |
| `adopt_answer` | 槽位条件更新；首次采纳改已解决+快照；调 F070；通知 |
| `delete_answer` | 未采纳&无进行中转公开；级联评论 |
| `add_comment` | 定向评论门槛（须已有效回答）；匿名选项；通知 |
| `create_publish_request` / `decide_publish` | 审批人集合、1/3/7 有效期、+1/+3 延期、通过转换、审计 |
| `on_expert_disabled` / `on_user_disabled` | 资格与审批人重算 |
| `disable_expert` / `enable_expert` | 软停用；管理员鉴权 |
| `mask_identity` | 非专家库管理员统一脱敏 |
| `hydrate_related_docs` | 解析 `{spaceId}-{fileId}`；按访问者 knowledge 权限填 `RelatedDocView`；forbidden ≠ not_found |

### 权限检查

- 专家库管理员：对齐 Portal `isPortalAdmin`（`UserPayload.is_admin()` + 角色名兼容集）。  
- 平台超管：保持 `require_platform_admin`。  
- 知识文档：现有 PermissionService / knowledge 校验；选择与打开同一 entry id。  
- 不查 `role_access` 做资源授权。

## 8. 前端设计

### 8.1 Platform

不适用（本 Feature 不改 Platform）。

### 8.2 Portal（主端）

> 仓：`shougang-group-knowledge-portal`  
> 页面：`ExpertQAPage` / `ExpertQAAskPage` / `ExpertQADetailPage` / `ExpertManagePage`

**要点**：

- 状态文案：未回答 / 待采纳 / 已解决（与 `display_status` 对齐）。

- 详情：按 `capabilities` 展示回答/采纳/转公开/审批。  
- 关联文档：`eqa-related-doc` / `eqa-related-doc-blocked`；`forbidden` 文案不得为「文档不存在」。  
- 专家管理：删除→停用/恢复；入口仍 `isPortalAdmin`，与后端一致。  
- 破匿名：仅专家库管理员展示真名。  
- 违规删除：仅 `canModerateExpertQaPoints`（平台超管）。

**API**：`frontend/src/api/expertQa.ts` → `/workspace/api/v1/qa_experts/...`
