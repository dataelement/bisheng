# 失败任务进度、放弃与整体回退（待确认）

关联 PRD：本聊天 2026-11-17 的新增要求及追问；此前 F023 的“不恢复现场任务”保持。优先级 P0；版本 v3.1.0-beta1。本文为需求发现后的候选规格，尚未获准实施任务状态/回退新契约。

## 用户目标

管理知识空间的人能看清复制/移动实际完成到哪一步、为什么失败、为什么阻止删除，并选择停止后续处理或在无冲突时整体撤销这次操作。用户不应从“索引成功 0 个”误判文件归属没有变化。

相似文档界面按前台交互对齐是独立 UI 修复，使用已有接口先交付，不依赖本规格。

## 候选验收标准

| AC | 要求 |
| --- | --- |
| AC-01 | WHEN 查看复制/移动任务，THE SYSTEM SHALL 分别展示文件记录/归属变更、权限确认、内容/索引处理、源侧清理的完成数、总数和当前阶段，不把索引成功数作为全部业务进度。无法核实的阶段显示未知，不伪装为 0 或已完成。 |
| AC-02 | WHEN 任务失败，THE SYSTEM SHALL 显示具体失败阶段、可读原因及下一步处理建议；保留错误码作为辅助。历史仅存包装错误的任务不得声称知道底层原因，补充诊断必须标明证据来源及时间。 |
| AC-03 | WHEN 失败或未完成任务仍依赖源空间，THE SYSTEM SHALL 在删除预检中明确说明阻断原因，展示获准查看的任务摘要、实际进度及查看任务入口；无权任务仅显示受限依赖提示，不暴露目标空间、文件名或用户信息。 |
| AC-04 | WHEN 用户选择“放弃后续处理”，THE SYSTEM SHALL 先预览保留的完整结果、未完成内容、残留清理及检索不可用影响，二次确认后停止后续执行；保留完整已完成结果，不承诺恢复执行前状态。 |
| AC-05 | WHEN 放弃复制任务，THE SYSTEM SHALL 保留完整已完成的副本，清理本任务未完成的占位文件/关联和索引残留；仅创建数据库记录不得算完整副本。WHEN 放弃已变更归属的移动，THE SYSTEM SHALL 保留现有归属，保证原始文件仍可读取，明确标识未完成索引的文件需要重新解析。 |
| AC-06 | WHEN 用户选择“整体回退”，THE SYSTEM SHALL 预览本任务将撤销的全部变更；只有源/目标/文件/权限/索引等受影响事实仍可安全恢复时才允许确认。复制回退清除本任务创建的副本及新空间；移动回退恢复任务影响文件的原位置、关联和权限并处理目标残留，不回滚空间内其他操作。 |
| AC-07 | IF 任务结果被后续编辑、移动、删除、引用，或恢复输入缺失、权限变更、当前索引代次不兼容，THEN THE SYSTEM SHALL 列出有权查看的冲突并拒绝自动整体回退，不覆盖后续操作；不得通过强制改状态绕过。 |
| AC-08 | WHILE 放弃/回退未完成，THE SYSTEM SHALL 继续保护源输入并阻止重试和旧执行者提交。只有确认无需源输入且善后完成，才允许自然释放对应保护；不得将放弃/回退伪装为成功，不删除任务记录。 |
| AC-09 | WHEN 重复确认、超时重试、旧 worker 返回或服务重启，THE SYSTEM SHALL 恢复同一操作进度，不重复清理、复制、回退或释放保护；失败显示可恢复的处理状态。 |
| AC-10 | THE SYSTEM SHALL 按当前租户和任务/源/目标权限执行，记录操作者、方式、影响、冲突及处理结果，普通用户与超管管理子租户的范围边界保持。 |

## 本轮边界

- 第一版限定 SPACE 的失败/部分失败复制和移动任务。正在运行的任务先检查执行占用；不做通用强杀 Celery 或所有知识加工任务的撤销。
- 对 116 的两条任务，本轮只读交付证据与候选处置预览，不自动放弃、回退、重试、删除空间或改历史状态。
- “整体回退”是新增、需确认的能力；如果本期只选放弃，AC-06/07 单列延期，不能用放弃冒充回退。
