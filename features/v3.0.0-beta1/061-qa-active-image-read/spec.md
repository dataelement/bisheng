# Feature: 问答场景主动读图

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How（决策、数据流、字段、API、Service、前端、文件清单、性能指标）一律不写在这里。**
> How 的唯一真相在 [design.md](./design.md)（接手必读）与 [tasks.md](./tasks.md)（执行流水；本轮尚未拆解）。

**关联 PRD**: 工作台问答「频道问答、知识库问答场景能够主动读取图片」（用户确认的 ①–⑦ 流程）
**优先级**: P1
**所属版本**: v3.0.0-beta1
**依赖**: 既有工作台模型「视觉」开关；日常模式、知识空间、频道订阅既有问答入口。无前置未交付 Feature。

> **范围边界**
> - **本次纳入**：
>   - 三个问答场景：**首页日常模式对话**、**知识空间问答**（单文件 / 文件夹 / 整空间）、**频道订阅文章问答**。
>   - 当检索结果或文章正文含 markdown 图片（`![...](url)`），且当前问答模型开启视觉能力时：系统给图片编号，模型可按需「查看图片」，再基于真实画面作答。
>   - 第一次请求只让模型知道「这儿有张图」；只有模型主动查看后，第二次请求才带上图片内容。
>   - 取图失败、模型无视觉、正文无图：问答不中断，行为与今天一致或明确降级，不得编造图中内容。
> - **本次明确排除**：
>   - **不改入库 / OCR / 切片**：图片仍按现有解析链路写入 markdown 引用；本期只在问答运行时按需读像素。
>   - **不预把全部图片塞进第一次模型请求**：多数问题不需要读图，预塞贵且易超上下文。
>   - **灵思任务模式、工作流 RAG、助手 RAG**：本期只接上述三个问答入口。
>   - **不新做前端读图 UI**：日常模式复用已有工具调用展示；知识空间 / 频道不把首轮工具调用内容当成答案刷给用户。
>   - **不解析 HTML `<img>`**：只认 markdown `![...](url)`。
>   - **不新增表 / Alembic / 错误码段**：无新领域对象；取图失败不另开对外错误码，只在本轮对话内降级。
>   - **不高清档 / 多档画质**：本期只提供标准档（长边缩放）。高清档另起迭代。

## 1. 用户故事

作为 **在首页日常模式提问的用户**，
我希望 **模型能按需看懂知识库检索结果里的图表，而不是说「看不到图」或按周围文字编一段**，
以便 **问走势、对比、图内数字时得到与画面一致的答案**。

作为 **在知识空间对文件 / 文件夹 / 整库提问的用户**，
我希望 **模型能主动查看命中段落中的图片后再作答**，
以便 **文档里的图、表、截图成为可用依据，而不是一段失效的 markdown 标签**。

作为 **在频道订阅文章下提问的用户**，
我希望 **模型能看懂文章正文里的配图后再讨论**，
以便 **围绕文章图表提问时，答案来自图本身而不是标题猜测**。

## 2. 验收标准

> AC-ID 在本特性内唯一。P1 且跨模块，采用 EARS 句型。实现细节见 design.md。

### 2.1 编号与可见性

- **AC-01** — WHERE 当前问答模型已开启视觉能力, WHEN 本轮送给模型的检索结果或文章正文含 markdown 图片引用, THE SYSTEM SHALL 为每张不重复图片分配稳定编号，并在原引用旁留下模型可识别的锚点；原图片 URL 保持不变，前端仍按原 markdown 渲染。
- **AC-02** — WHERE 当前问答模型未开启视觉能力, WHEN 正文含 markdown 图片引用, THE SYSTEM SHALL 保持今天的行为：原文引用不变，不提供「查看图片」能力。
- **AC-03** — WHERE 正文不含 markdown 图片引用, THE SYSTEM SHALL NOT 向模型提供「查看图片」能力，问答路径与今天一致。

### 2.2 按需查看（①–⑦）

- **AC-04** — WHEN 系统第一次把带图上下文送给模型, THE SYSTEM SHALL NOT 在该次请求中附带任何图片像素；模型此时只能从锚点知道「这儿有张图」。
- **AC-05** — WHEN 回答依赖图 / 表 / 走势等画面信息, THE SYSTEM SHALL 允许模型调用「查看图片」，并只接受本轮已编号的图片；THE SYSTEM SHALL NOT 接受模型传入的任意 URL。
- **AC-06** — WHEN 模型请求查看一张或多张已编号图片, THE SYSTEM SHALL 取回这些图片、按标准档缩到长边 512，并在下一次模型请求中附带这些图片内容；该次请求仍包含原问题与检索 / 文章上下文。
- **AC-07** — WHEN 模型请求查看的图片已取回并按标准档处理成功, THE SYSTEM SHALL 在下一次模型请求中附带这些图片的像素内容；THE SYSTEM SHALL NOT 在已成功查看后仍只提供文字锚点。
- **AC-08** — THE SYSTEM SHALL 在单轮对话中最多查看 3 张图片；同一图片 URL 只对应一个编号。
- **AC-09** — THE SYSTEM SHALL 只提供标准档查看；不提供其他画质档位。

### 2.3 三场景覆盖

- **AC-10** — WHEN 用户在首页日常模式选了知识库并提问，且检索命中含图段落, THE SYSTEM SHALL 按 AC-01～AC-07 使模型能按需查看这些图后再作答。
- **AC-11** — WHEN 用户在知识空间对单文件、文件夹或整空间提问，且检索命中含图段落, THE SYSTEM SHALL 按 AC-01～AC-07 使模型能按需查看这些图后再作答。
- **AC-12** — WHEN 用户在频道订阅文章下提问，且文章正文含 markdown 图片, THE SYSTEM SHALL 按 AC-01～AC-07 使模型能按需查看这些图后再作答。

### 2.4 回答呈现与权限

- **AC-13** — WHEN 模型作答且需要引用资料中的图片, THE SYSTEM SHALL 让回答继续输出原始 markdown 图片格式，不得改写、转义或删除该引用（前端仍能渲染原图）。
- **AC-14** — THE SYSTEM SHALL 只允许查看本轮已经过现有权限过滤的检索结果或文章正文中出现的图片；不新开越权取图入口（知识空间继续遵守 `view_file`；频道继续遵守敏感文可见性）。

### 2.5 降级与稳健

- **AC-15** — IF 某张已编号图片取回或缩放失败, THEN THE SYSTEM SHALL 告知模型该图不可用，并继续完成本轮问答，不得因此中断会话或返回整请求失败。
- **AC-16** — IF 模型在无需读图的问题上调用「查看图片」, THEN THE SYSTEM SHALL 仍按编号校验与取图规则处理，不得把工具调用内容当作最终答案展示给用户。
- **AC-17** — WHEN 知识空间或频道问答的第一次模型响应是「查看图片」而不是最终答案, THE SYSTEM SHALL NOT 把该次工具调用内容作为用户可见答案流式输出。
- **AC-18** — WHEN 日常模式模型调用「查看图片」, THE SYSTEM SHALL 复用已有工具调用展示，不新增一种前端读图界面。
- **AC-19** — IF 模型请求查看本轮未编号或不存在的图片编号, THEN THE SYSTEM SHALL 不取该图，向模型说明该编号不可用，继续完成本轮问答，且不把该次失败作为用户可见答案。
- **AC-20** — IF 模型一次请求查看超过 3 张图片, THEN THE SYSTEM SHALL 最多查看其中 3 张，对其余编号不取图并向模型说明已达上限；用户侧问答不中断。

## 3. 边界情况

- **同一段落多张图** → 分别编号；模型可一次查看多张，但单轮不超过 3 张。
- **相同 URL 出现多次** → 只占一个编号，避免重复查看。
- **模型传入未编号或不存在的图片编号** → 不取图，告知模型该编号不可用，会话不中断（AC-19）。
- **一次请求超过 3 张** → 只查看 3 张，其余不取图并告知已达上限，会话不中断（AC-20）。
- **文章或 chunk 被截断后图引用被切掉** → 未进入本轮上下文的图不可查看（正常，非缺陷）。
- **模型无视觉但用户问「图里是什么」** → 不提供查看能力；不得假装看见。
- **正文只有 HTML `<img>`、没有 markdown 图片** → 本期不识别、不编号。
- **图片是外链且主机不在允许范围** → 按取图失败降级（AC-15），不把任意外链当成功来源。
- **用户上传的对话附件图片** → 不在本 feature 范围（日常模式已有视觉附件路径）。
