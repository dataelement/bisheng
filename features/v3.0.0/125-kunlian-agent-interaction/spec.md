# Feature 毕昇 Workflow 调用昆联 Agent 的人工输入与恢复

- **Feature ID**: F125（拟用，合入前复核）
- **Version**: v3.0.0
- **Status**: CONFIRMED，用户确认进入设计
- **Mode**: SPEC_ONLY，Mock 优先
- **关联**: 总设计《2026-10-23-kunlian-bisheng-workflow-integration.html》S07，[开发规划 4C](../../../docs/architecture/proposals/kunlian-workflow-development-plan.md#下一批需求发现--4c-昆联-agent-等待人工输入)、[F123 原生输入与恢复](../123-kunlian-workflow-interaction/spec.md)、[F124 Agent 长任务与取消](../124-kunlian-agent-long-task/spec.md)、[版本契约](../release-contract.md)。

## 1. 目标与范围

用户在毕昇的有会话运行页执行已发布的 Workflow。固定版本的昆联 Agent 请求人工输入时，Workflow 暂停在该 Agent 节点。原运行用户可以在原会话查看表单并提交。Agent 继续原 Run，毕昇获取有效结果后恢复原 Workflow，下游只消费一次结果。

首轮在「开始 → 平台 Agent → 输出 → 结束」线性流程验收，包含一个平台 Agent 节点、一次人工等待和一个必填纯文本字段。用户可断线后回到原会话操作。原 Worker 释放执行任务后，另一 Worker 能接续该等待点。运行仍采用 4B 的状态与结果轮询，停止沿用既有 Workflow 入口。

多轮或多节点交互、文件和复杂表单、审批与转交、回调、事件订阅、通用图跨 Worker 恢复，以及昆联反向调用毕昇 Workflow 的交互扩展，分别留待后续场景评估。

## 2. 用户故事

- 作为 Workflow 运行者，我希望 Agent 需要补充信息时能在当前会话看到并填写表单，刷新页面后仍能继续。
- 作为 Workflow 运行者，我希望重复提交只生效一次。若我停止运行或表单已超时，迟到的答案或结果不能让工作流继续。
- 作为 Workflow 发布者，我希望发布新版本时，已经等待输入的运行继续使用原 Workflow 版本、Agent 版本和表单修订。

## 3. 业务需求

| ID | 需求 |
| --- | --- |
| REQ-01 | **显式启用与版本固定。** 交互只对已显式启用且固定 Agent 版本支持人工输入的发布配置开放。Workflow、Agent 版本及输入输出约定在该次运行内保持原绑定。 |
| REQ-02 | **等待与重连。** 收到与原 Agent Run 匹配的有效等待状态后，在原会话展示该次交互的必填文本字段、修订和等待截止时间。原请求断开或 Worker 退出后仍能查询，等待期间不执行下游。重复查询和重连不增加待办或延长截止时间。 |
| REQ-03 | **提交校验与幂等。** 答案必须匹配原运行、当前交互和表单修订。无效文本或过期修订不消耗当前交互。同一提交标识及答案重试返回原受理事实或最新已确认的进度。同键异参，或用新标识重复消费已接受的交互，须拒绝。 |
| REQ-04 | **同次运行恢复。** 已接受的答案提交给原远端交互。另一 Worker 能沿用原会话、节点执行、固定版本和暂停前上下文继续。恢复不重新启动 Agent 或重复运行已完成节点。只有核验原 Run、版本和输出结构后，才允许下游消费一次结果。 |
| REQ-05 | **实际用户与数据范围。** 查看表单、提交、重试、恢复与取得结果遵守原执行归属、可信租户、接入方及当前权限。外部受保护操作沿用原实际运行用户。撤权、停用或无法确认权限时，不继续相应操作。状态和日志不暴露凭据、未授权的表单或答案、内部恢复材料及原始异常。 |
| REQ-06 | **受理、失败与终态。** 区分本地收到答案、昆联已受理、送达未知、明确拒绝和结果不可用。送达未知时按原交互和原提交关联有限核对。只有确认重放安全时才可使用同一提交标识和答案重试。重复提交不延长等待或核对期限。首次答案被接受后再出现新的远端交互，按首轮不支持处理。 |
| REQ-07 | **停止与超时。** 区分人工等待到期、提交核对到期和提交后的结果等待到期。有效答案在人工截止前被接受后，按后续阶段时限处理。停止或超时生效后拒绝新的本地提交、阻止尚未发出的远端提交及尚未写入的输出，按 4B 规则处理原 Run 的取消或核对。已发出的提交可能被昆联受理，迟到回执只用于核对，不能恢复本地运行。 |
| REQ-08 | **Mock 与兼容。** 隔离 Mock 可模拟等待、接受、拒绝、回执丢失、超时和取消。F119 同步路径、未启用交互的 4B 路径和 4A 原生表单保持原行为。正式替换点保留关联待确认项的 `# TODO`，正式调用失败不回落到模拟结果。 |

## 4. 验收标准

| ID | Requirements | 可观察结果 | Verification |
| --- | --- | --- | --- |
| AC-01 | REQ-01、REQ-02 | 当有权用户运行启用交互的固定 V1 且 Agent 等待输入时，毕昇在原会话展示同一交互、必填文本字段和截止时间。断线重连、重复查询后仍是原 Workflow 执行和原 Agent Run，等待期间下游执行次数为零。 | V-01、V-04 |
| AC-02 | REQ-01、REQ-04 | 当 Worker A 退出、用户提交有效答案且等待期间发布 V2 时，Worker B 从 V1 的原等待点继续。核对 Workflow 执行、Agent Run 和交互关联相同，暂停前的节点和 Agent 启动均只发生一次。结果保留暂停前上下文，下游只消费一次核验后的输出。 | V-02、V-04 |
| AC-03 | REQ-03、REQ-06 | 当相同答案被并发提交或响应丢失后重试时，只产生一次有效远端受理。改答案重试和另起标识重复消费均拒绝。无效文本、旧修订或错配交互被拒后，当前有效表单仍可提交。 | V-03、V-04 |
| AC-04 | REQ-05 | 如果请求来自其他用户、租户或接入方，或原用户已撤权或停用，则无法查看受保护的表单或提交。若答案已被接受但恢复前撤权，则不继续受保护的远端操作或下游执行。 | V-03、V-04 |
| AC-05 | REQ-04、REQ-06 | 如果昆联的受理响应丢失，则先显示送达未知，查回后只处理原交互的事实。明确拒绝、无法核对及远端成功但结果不可用分别可辨。第二次人工等待或错配的 Run、版本、输出不会被当作本次成功。 | V-03、V-04 |
| AC-06 | REQ-07 | 当停止先于发送远端提交时，昆联未收到答案，即使毕昇已经收到该答案。当人工等待到期先于本地受理时，答案无法触发继续。当停止发生在远端提交在途或已受理后时，迟到的受理及成功结果无法恢复下游。取消受理与已取消可区分，交互、提交核对和结果等待超时可区分。 | V-01、V-03、V-04 |
| AC-07 | REQ-07 | 当有效答案在人工等待截止前被接受时，后续阶段按自身期限收敛。模拟回执和输出跨过各自截止时间，重复查询、提交和迟到响应均不能续期或覆盖本地终态。 | V-03 |
| AC-08 | REQ-01、REQ-08 | 当交互未启用或固定版本不支持时，不进入 4C 等待。同步 Agent、普通异步 Agent、4A 原生交互均按既有行为通过回归。正式来源不可用时有明确失败，Mock 有可辨识的来源。 | V-03 |

| ID | 验证方式 | 当前状态 |
| --- | --- | --- |
| V-01 | 隔离 Mock 浏览器验收。通过毕昇有会话运行页运行最小图，检查表单、重连、输出和原停止入口。 | 已通过，见[验证记录](./verification.md) |

| V-03 | 可控时钟和故障注入集成验证。覆盖权限、幂等、回执丢失、阶段竞争、输出校验及相邻特性回归。 | 隔离 Mock 已验证，见[验证记录](./verification.md) |

## 5. 双方待确认

| ID | 待确认能力 |

| EXT-01 | 固定 Agent 版本的交互能力标识、等待状态、交互标识及修订语义。确认状态查询能否同时返回表单，或由既有详情能力取得。 |

| EXT-05 | 正式 OpenAPI 或 Schema、测试环境、固定版本和测试账号，以及等待输入、重试、取消、超时与无权的可核对样例。 |
