## 部署后人工检查

### AC-12：模型失败原因

- [ ] 管理员为专用测试模型设置无效 API Key，使用客户端分别触发流式和非流式调用。
- [ ] 在模型审计中按请求编号找到记录，展开“请求详情”，确认有“模型失败原因”；供应商返回 401 时显示身份验证失败和上游 HTTP 401。业务 HTTP 与上游 HTTP 不混淆。
- [ ] 模拟超时、无法连接、429、5xx，确认分类来自实际异常；429 仅有状态码时提示限流或额度不足，不断言单一原因。
- [ ] 用原生 Responses 协议触发 `response.failed`，确认模型结果失败、接口完整传输状态可为完成，两个状态不互相覆盖。
- [ ] 查看升级前失败记录：没有原因时展示“未留存具体原因”，不从正文或历史记录猜测。
- [ ] 检查页面、查询响应及新增诊断字段，不含密钥、认证头、完整供应商异常消息或 traceback。

### AC-13：响应失败原因

- [ ] 调用中断开连接，检查实际观测到的连接断开、取消或传输中断分类；未观测到根因时保持未知。
- [ ] 模型已经完成后模拟发送失败，确认模型成功、实际用量结算保持原值，只有接口响应中断。
- [ ] 仅元数据模式可查看原因；关闭审计不新增原因记录；普通用户不能读取审计，租户管理员不能跨租户读取。

### AC-14：完整原文倒序

- [ ] 打开“查看原文”，本次输出在上，历史输入倒序排列；正文、思考内容、工具参数内部文字顺序不变。
- [ ] 覆盖 Chat Completions 与 Responses 的流式、非流式结果；工具调用、工具结果、图片占位和来源标签仍关联原消息。
- [ ] 触发会话压缩后，压缩摘要、系统提示、工具结果和历史正文完整保留，不标记或猜测“本次新增”。
- [ ] 超过 100 条消息逐页检查，最新页在前，最早历史和系统提示仍可访问；翻页不重复申请原文读取。
- [ ] 正文有缺口、传输被中断时仍提示不完整；倒序不会把缺口标记删除。
- [ ] 切换请求、切换租户和收起后重新展开时回到首段，不混入上一请求内容。
