# 中粮机器人问答调试客户端

用途：在我们自己的环境复现机器人知识问答，观察原助手的模型、执行模式、工具调用、模型实际收到的结果和检索来源。它不是 E+ 通信模拟器，也不修正模型答案。

## 入口与边界

助手编辑 →「E+ 机器人」配置区 →「机器人调试」。请先保存配置并上线助手；编辑页未保存的改动不参与测试。

第一版只测试文字和机器人知识工具；其他工具不执行，页面列出差异。当前租户所有已登录用户都能调试，不要求助手编辑权限；普通用户固定自己身份，管理员可切换有效测试用户。不能自定义空间、模型或系统提示词。

知识检索仍只认机器人绑定空间，绑定部门空间走原检索逻辑；不按测试用户的个人空间权限扩大范围。每轮重读绑定，本轮用快照完成，历史不按空间版本过滤，与本次已确认的正式机器人规则一致。

不启动正式 Worker、不建客户连接、不发客户消息、不申请机器人单活租约、不写正式会话/消息/轮次。测试历史只在页面内存，刷新、清空或切换用户会清除；只将成功完整回答带入下一轮，最多20轮/64000字。模型及数据库、索引共用，仍产生正常费用、配额、既有调用审计/遥测和资源竞争。

## 启用

需要包含 F075 代码的前后端，不能只启动旧镜像。没有新增表或迁移；不需要降级数据库，也不要复制生产密钥到本地文件。

1. 前端入口默认开启，不再需要设置 `VITE_EPLUS_DEBUG_ENABLED=true`；如需隐藏，构建时显式设置 `VITE_EPLUS_DEBUG_ENABLED=false`。该变量是**构建时**开关，改容器运行环境不能改变已构建页面。入口仍要求独立调试服务的 status 检查成功及已保存机器人配置；后端独立服务仍需显式启用，不影响正式 API/Worker。
2. 使用既有环境的 backend 配置启动独立服务，不替换正式 API/Worker，不使用 `bisheng.main:app`：

   ```bash
   EPLUS_DEBUG_ENABLED=true uv run uvicorn bisheng.eplus.debug_app:create_app --factory --host 127.0.0.1 --port 7871 --workers 1 --no-access-log
   ```

   沿用部署的 `config` 配置路径及安全凭证注入。必须 unset `BISHENG_RECORD_HISTORY`，否则拒绝启动。权限 Store、模型和目录必须已由正式部署准备完成；调试进程强制只读发现，缺失或不兼容时拒绝运行，不自动创建权限 Store/模型、不播种目录、不执行迁移或默认业务数据回填。
3. 在**已登录前端的同源入口**增加代理；只代理 API，页面仍由 Platform SPA 提供。示例适用于无路径前缀的 Nginx（容器独立服务需改为可达的内部服务地址，不能把容器 localhost 当宿主机）：

   ```nginx
   location /robot-debug/api/ {
       proxy_pass http://127.0.0.1:7871;
       proxy_http_version 1.1;
       proxy_set_header Host $http_host;
       proxy_set_header X-Forwarded-Proto $scheme;
       proxy_set_header Authorization $http_authorization;
       proxy_set_header Cookie $http_cookie;
       proxy_buffering off;
       proxy_cache off;
       proxy_read_timeout 240s;
   }
   ```

   保留真实登录身份与租户，不设置固定管理员，不绕过商业网关认证。若前端有部署路径前缀，代理应剥离该前缀后转到 `/robot-debug/api/`。仅信任内部代理的 forwarded headers，确保 HTTP/HTTPS origin 一致。不要把7871暴露公网；未能安全转发认证时不启用入口。
4. 任意已登录用户访问 `/robot-debug/api/status` 应返回成功信封、`data.enabled=true`；匿名应拒绝。调试不要求管理员或助手编辑权限，但助手、机器人及空间必须属于当前租户且有效。该检查证明准入可用，不代表模型或全部检索资源已就绪。
5. 保存上线的助手配置后，在机器人配置区打开调试页；没有助手编辑权限的用户可使用 `/robot-debug?assistantId=<助手ID>` 直接进入。默认当前登录用户为测试用户；普通用户固定使用自己身份，只有超级管理员/当前租户管理员可切换同租户有效用户，后端对 context 和 run 均校验。无外部 ID 的测试用户可测试后端问答，但不代表客户 IAM 入站已验证。

## 怎样定位来源问题

机器人与调试入口共用的知识工具现在把返回值分成 `sources`（文件ID、真实文件名、空间ID及名称）和 `chunks`（按文件ID关联的正文片段），并标记 `is_complete_file_list=false`。来源由当前租户、机器人绑定空间内的成功文件记录核实，不使用索引中的旧名称或从正文猜归属。同名文件按文件ID分别保留，同一文件的多个片段不会重复列来源。

用户明确指定完整文件名时，工具可传 `file_name` 做精确匹配，并在索引检索前后限制文件范围；没有匹配时不拿其他文件替代。若文件记录有效但没有正文命中，只返回来源，不生成内容。`verified_source_summary` 是后端按真实字段生成的文字说明，供模型回答归属时使用，**不代表对最终模型正文做了强制纠错**。没有增加完整目录能力、额外生成式模型调用、表或迁移。助手系统提示词仍来自页面配置，本次不需要修改页面提示词。

主题找文件（如「深圳市医学研究相关的文件有哪些」）可由工具参数 `file_name_query` 传主题关键词，多词用空格分隔。后台在本轮绑定空间内查询解析成功文件的真实文件名，大小写不敏感、各词均需包含，`%`/`_` 不作为通配符；最多返回50条真实来源。无论文件名是否命中，都有界并行执行全绑定空间正文召回，不因标题不匹配漏掉正文候选。文件名命中但尚无有效正文的文件，按空间批量补查（每个空间最多追加一次索引查询，使用文件ID过滤）；已有正文的不重复查。补查后再次核验当前成功文件归属。两部分正文合并去重、统一排序和裁剪，并保留有效文件名命中的来源。这不是完整目录能力；真正无正文命中或正文被预算裁剪时仅保留来源，不按文件名编造内容。补查会增加常规检索及向量查询成本，不增加单独的总结模型调用。

内容问答检索所有绑定空间，2026-10-14 起由串行改为有界并行：每轮同一执行器最多同时检索6个空间，正文召回与按文件ID补查使用同一限额；同一工具实例的异步并行调用也共享限额，旧同步执行器顺序调用时允许复用不同事件循环。初始召回收齐后才核验来源、选择补查文件；补查收齐后再核验来源。空间内部两路索引仍沿用原顺序，不新增嵌入或生成式模型调用；不同会话各自最多6个，不是环境全局限流。并行会提高瞬时资源压力，具体提速需现场测量，模型生成耗时不由本次改变。任一空间异常向上报告（异步任务组的 ExceptionGroup），取消并等待同组其他本地任务，不把部分结果伪装成完整结果；已发出的远程请求不保证停止或取消计费。

保留两路索引的 top-k 候选，按文件身份去重并融合关键词/向量的召回排名，再对全部有效候选统一计算正文及真实文件名的 BM25 排名并融合，最后按15000字符正文预算裁剪。全部结果按稳定空间顺序合并，不按完成先后截断，也不直接比较不同检索器的原始分数。索引片段原本包含标题；统一排序去掉旧入库包装，使用数据库真实文件名。同文件同索引且正文相同的片段不因入库包装不同而重复计入预算；不同文件的相同正文保留各自来源。超预算片段可被截断。没有 rerank 模型调用；排序仅作用于已召回候选，不能保证任何问题都召回所有相关文件。

- 本轮调用次数为0：模型没有用知识工具；不要把它的空间/文件描述当检索结果。
- 「实际交给模型的工具结果」：原包装器返回的完整文本，包含哪些来源字段就显示哪些，没有则不补。
- 「检索原始元数据」：格式化前命中 Document 的空间 ID、文件 ID、文件名等安全字段；不代表这些字段都已传给模型。
- 两个空间同名文件：按实际空间 ID、文件 ID 对照原始结果，不能只比较文件名。
- 工具错误和最终回复分开：旧 ReAct 会把工具错误转成观察结果后继续回答，所以“有回复”不代表检索成功。调试工具异常只把错误类型交给执行器，不把供应商异常正文交给模型；这是脱敏差异，成功工具结果仍与正式链路原样一致。ReAct 整段返回，不伪造逐字流。

## 运行限制和退出

全环境同时只允许一轮调试，专用 Redis 键 `eplus:debug:active-run`（210秒TTL，按所有者 token 释放）。180秒总超时覆盖准备与推理；忙碌、失败或超时通过 `failed` 事件结束，错误只显示类型。请求512KiB、问题4096字、答案16000字、整轮追踪2MiB上限；越界明确失败，不截断后宣称完整。

每轮按 `run_id/seq` 顺序展示，不自动重发请求。停止、关闭、清空会取消本地执行并释放名额；断开清理屏蔽外层重复取消，最多等待5秒，清理超时后名额由TTL恢复。供应商已经开始的计算和计费不能保证撤销。临时来源文本包含业务数据，按用户确认的口径向当前租户已登录用户开放机器人绑定空间的检索结果；不要随意对外分享截图。

### 服务端诊断日志

2026-10-12 按用户确认增加独立调试服务日志，前提是包含本次代码的新镜像已部署；正式机器人和普通助手不变。日志输出到进程标准错误，由容器日志系统保存，不新增业务表或共享文件。检索参数与结果、历史问答和最终回复均按原文记录，包含业务数据，仅供内部诊断，不对外分享；保存期限与容量按部署的容器日志轮转策略管理。

用 `EPLUS_DEBUG_DIAG` 搜索，再按同一个 `run_id` 对照：`request` 是本轮问题、实际传入的历史问答及轮数和租户/助手/用户ID；`context` 是模型、执行模式和绑定空间；`tool_start` 的 `arguments` 包含 `query`、`file_name`、`file_name_query`，`tool_end` 是原样模型工具结果及来源元数据，两者以 `call_id` 关联；`answer` 是合并后的回复及 `execution_completed`，中断时标记为 false；`completed/failed/tool_error` 记录结束状态与调用次数或错误类型。零次调用也有 request/answer/结束记录，可识别模型没有重新检索。不逐字打印 `answer_delta`，不改变页面事件类型、检索行为或模型输入。准备阶段失败可能只有 request 与 failed，没有 answer。

系统密钥、Bot Secret、模型凭证、认证头、完整配置和供应商异常正文不从对象中提取或写入日志；标准 Python/Uvicorn 日志仍关闭，异常仍仅保留类型及无局部变量的堆栈位置。用户主动写进问题/历史、知识正文或模型回复中的敏感内容不会自动打码。

测试结束：停止独立调试进程、移除调试代理即可回收后端；后续前端构建关闭开关。无需回滚业务表；正式机器人按原方式运行。
