# Feature: 知识空间文件与文件夹变更审核

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> 本文档只回答做什么、验收标准与范围边界。实现方案、数据模型、接口、服务拆分和文件清单在后续 `design.md` 中确定。

**关联 PRD**: [0811 中粮需求响应 §1.4 新增文件变更审核（新方案）](https://dataelem.feishu.cn/wiki/MWHZwS0mbihH7NkbBvpckvSRnwc)
**优先级**: P0
**所属版本**: v2.6.0
**依赖**: F025-approval-center-unification（统一审批中心）、F034-knowledge-space-file-move（文件/文件夹移动能力）、现有知识空间上传、重命名与删除能力

> **范围边界**
> - **本次纳入**：
>   - 按租户独立保存和生效的知识空间文件变更审核总控及按知识空间配置。
>   - 编辑者上传文件的审核、待审批文件管理、审批通过后的正式入库。
>   - 编辑者对正式文件和文件夹执行重命名、移动、删除时的审核，以及审批通过后的正式执行。
>   - 正式文件或文件夹审批期间的状态展示、审批动作详情与重复操作拦截。
>   - 私密知识空间免审，以及部门知识空间禁止设置为私密的业务约束。
>   - 文件与文件夹页面和审批中心对同一审批申请的状态联动、单条及批量通过。
> - **本次明确排除**：
>   - PRD 1.1 的知识空间和频道统一权限设置入口。
>   - PRD 1.2 的个人用户邀请确认。
>   - PRD 1.3 已弃用的旧文件审核方案及其存量审批能力扩展。
>   - 频道内容发布、上传、重命名、移动或删除审核。
>   - 除“部门知识空间禁止设置为私密”外，改变知识空间既有成员权限规则或其他可见性语义。
>   - 未完成上传审批文件的删除审核；此类文件尚未正式入库，清理时不得创建删除审批。

---

## 1. 用户故事

### 1.1 平台管理员

作为 **平台管理员**，
我希望 **统一控制租户内知识空间是否需要文件变更审核，并可按知识空间分别配置**，
以便 **按集团运营规则管理文件发布、组织结构调整和删除风险**。

### 1.2 知识空间编辑者

作为 **具备上传、重命名、移动或删除能力的知识空间编辑者**，
我希望 **提交文件变更申请并查看处理状态和结果**，
以便 **在不越过知识空间管理规则的前提下完成文件维护**。

### 1.3 知识空间所有者和管理者

作为 **知识空间所有者或管理者**，
我希望 **直接执行自己的文件变更，并审核编辑者提交的文件变更申请**，
以便 **控制空间内内容的正式发布、名称、位置和删除**。

### 1.4 知识空间成员

作为 **知识空间普通成员**，
我希望 **只看到已经正式入库的文件，并在删除审核期间继续正常使用原文件**，
以便 **未完成的变更不会影响正常检索、问答和引用**。

## 2. 验收标准

### 2.1 审核策略与准入

- **AC-01** — THE SYSTEM SHALL 允许平台管理员为当前租户关闭文件变更审核，或在开启后选择“全部知识空间需要审核”与“按知识空间配置”两种审核范围。
- **AC-02** — WHERE 审核范围为“全部知识空间需要审核”，THE SYSTEM SHALL 对当前及后续新建的非私密个人知识空间、集团知识空间和部门知识空间统一启用文件变更审核；私密知识空间始终免审。
- **AC-03** — WHERE 审核范围为“按知识空间配置”，THE SYSTEM SHALL 允许平台管理员对非私密知识空间逐空间选择“无需审核”或“需要审核”，且未单独配置的非私密知识空间默认为“需要审核”；私密知识空间不得因单空间配置进入审核。
- **AC-04** — WHEN 平台管理员修改总开关或审核范围但尚未成功保存，THE SYSTEM SHALL 保持当前生效策略不变，且不得提示配置已经保存。
- **AC-05** — WHEN 平台管理员关闭总开关后再次开启，THE SYSTEM SHALL 保留并恢复此前各知识空间的独立配置。
- **AC-06** — IF 租户尚无文件变更审核总控配置，THEN THE SYSTEM SHALL 按“总开关开启、按知识空间配置、各空间默认需要审核”处理。
- **AC-07** — WHEN 审核策略发生变化，THE SYSTEM SHALL 仅对之后发起的文件变更操作应用新策略，已发起审批继续按申请发起时的规则处理。
- **AC-08** — WHEN 操作者不具备目标资源操作所需的既有上传、重命名、移动或删除能力，THE SYSTEM SHALL 拒绝该操作且不得创建审批申请。
- **AC-09** — WHEN 知识空间所有者或当前有效管理者上传文件，或重命名、移动、删除正式文件或文件夹，THE SYSTEM SHALL 直接执行操作且不得创建文件变更审批。
- **AC-10** — WHEN 具备对应操作能力的编辑者在私密知识空间或其他无需审核的知识空间上传文件，或重命名、移动、删除正式文件或文件夹，THE SYSTEM SHALL 沿用现有直接执行行为且不得创建审批。
- **AC-11** — WHEN 具备对应操作能力的编辑者在需要审核的知识空间上传文件，或重命名、移动、删除正式文件或文件夹，THE SYSTEM SHALL 按资源、按操作分别创建审批申请。

### 2.2 上传文件审核

- **AC-12** — WHEN 编辑者提交需要审核的文件上传，THE SYSTEM SHALL 保存待审批原文件并将其展示在独立的待审批文件列表中，但不得将其作为正式文件加入知识空间文件列表。
- **AC-13** — WHILE 上传审批未完成，THE SYSTEM SHALL 不启动内容解析、切分、Embedding、全文索引或向量入库，且该文件的文件名与内容不得出现在搜索、RAG、问答引用、知识广场或 OpenAPI 的正式文件结果中。
- **AC-14** — WHILE 上传审批未完成，THE SYSTEM SHALL 仅允许申请人和当前有效审核人查看待审批状态、审批信息并预览原文件；其他用户不得看到该文件、文件名或内容。
- **AC-15** — WHEN 任一当前有效审核人同意上传申请，THE SYSTEM SHALL 结束同节点其他待办并启动正式文件入库流程；只有解析及入库全部完成后，文件才按既有权限进入知识空间文件列表并可被检索和使用。
- **AC-16** — WHILE 已通过上传审批的文件正在正式入库，THE SYSTEM SHALL 向申请人和审核人展示“解析中”，且完成前不得被其他用户检索或使用。
- **AC-17** — IF 上传审批通过后解析或入库失败，THEN THE SYSTEM SHALL 展示“解析失败”及可用的失败原因，并保持文件不可检索、不可用于问答。
- **AC-18** — WHEN 编辑者对同一份已通过审批且内容未变化的文件重试解析或入库，THE SYSTEM SHALL 复用原审批结果且不得重复创建上传审批。
- **AC-19** — WHEN 编辑者变更文件内容后重新上传，THE SYSTEM SHALL 将其视为新的上传并重新执行适用的审核规则。
- **AC-20** — WHEN 上传审批被拒绝、撤回或取消，THE SYSTEM SHALL 不启动正式入库，且该文件不得进入知识空间文件列表。
- **AC-21** — WHEN 申请人清理被拒绝、已撤回、已取消或仍未完成审批的上传文件，THE SYSTEM SHALL 清理对应待审批文件且不得创建删除审批任务。

### 2.3 删除文件与文件夹审核

- **AC-22** — WHEN 编辑者对需要审核的知识空间正式文件或文件夹发起删除，THE SYSTEM SHALL 在删除审批执行成功前继续保留该资源；文件及文件夹下既有内容的目录展示、搜索、问答和引用保持可用。
- **AC-23** — WHILE 正式文件或文件夹处于“审批中”，THE SYSTEM SHALL 在资源列表中保留并展示该资源；申请人和当前有效审核人可以查看审批详情及动作“删除”，其他有权访问该资源的用户不得看到申请人、审核状态或原因。
- **AC-24** — WHEN 任一当前有效审核人同意删除申请且正式删除执行成功，THE SYSTEM SHALL 按既有删除语义清理目标文件或文件夹及其既有关联内容、版本、索引、向量和存储对象。
- **AC-25** — WHEN 删除审批被拒绝、撤回或取消，THE SYSTEM SHALL 保持目标文件或文件夹及其内容的位置、名称、发布和可用状态不变。
- **AC-26** — WHEN 用户批量删除多个文件或文件夹，THE SYSTEM SHALL 按资源分别判断并返回“已删除”或“审批中”，客户端仅移除已经删除成功的资源。
- **AC-27** — WHEN 操作者清理尚未正式入库的待审批上传文件，THE SYSTEM SHALL 不适用正式文件删除审核规则。

### 2.4 审批人与重复申请

- **AC-28** — THE SYSTEM SHALL 将当前知识空间的有效所有者和管理者作为文件变更审核人，并采用单节点或签规则。
- **AC-29** — WHEN 任一当前有效审核人同意申请，THE SYSTEM SHALL 通过该申请并结束其余同节点待办。
- **AC-30** — IF 审核人在处理前已失去该知识空间的所有者或管理者身份，THEN THE SYSTEM SHALL 禁止其继续处理该审批任务。
- **AC-31** — WHILE 正式文件或文件夹存在任一未结束的变更审批，THE SYSTEM SHALL 禁止对该资源再次发起重命名、移动或删除审批，不得因操作类型不同而创建新的并行审批；目标为文件夹时，该限制同时覆盖其全部子资源。
- **AC-32** — WHEN 审批通过后的正式上传、重命名、移动或删除执行失败，THE SYSTEM SHALL 明确展示执行失败，且不得把业务未生效的申请展示为执行成功。

### 2.5 文件页与审批中心联动

- **AC-33** — THE SYSTEM SHALL 在独立待审批文件列表中展示和筛选“上传待审核”，并在正式资源列表中将存在未结束重命名、移动或删除审批的文件和文件夹展示为“审批中”；多选状态时按并集返回，不为正常资源展示“成功”状态。
- **AC-34** — THE SYSTEM SHALL 使文件页面与审批中心处理同一审批申请；任一入口处理后，另一入口应刷新为同一最终状态。
- **AC-35** — WHEN 审核人在审批中心通过当前待办，THE SYSTEM SHALL 提示审批已通过、移除当前任务并停留在待处理列表；有下一条任务时自动选中下一条，否则展示空状态，不自动切换到已处理列表。
- **AC-36** — WHEN 当前用户在文件页面选择一条或多条仍可处理的待审核记录并执行批量通过，THE SYSTEM SHALL 仅处理所选记录中该用户当前有权处理的原审批任务。
- **AC-37** — WHEN 批量通过全部成功，THE SYSTEM SHALL 提示成功数量；WHEN 部分任务失败或状态已变化，THE SYSTEM SHALL 分别反馈成功数与失败数、保留成功结果不回滚，并展示失败记录的最新状态以供刷新后重试。
- **AC-38** — WHEN 用户在文件页面完成审批处理，THE SYSTEM SHALL 保持用户停留在当前页面且不得自动跳转到审批中心的已处理列表。

### 2.6 空间与频道边界

- **AC-39** — WHILE 知识空间为私密状态，THE SYSTEM SHALL 对具备既有操作权限的用户直接执行上传、重命名、移动和删除，不得创建文件变更审批；文件变更审核配置不得改变该空间的私密状态或成员权限。
- **AC-40** — WHEN 个人知识空间所有者本人上传文件，或重命名、移动、删除文件或文件夹，THE SYSTEM SHALL 直接执行；WHEN 获得编辑能力的非管理者操作，THE SYSTEM SHALL 按该空间当前审核策略处理。
- **AC-41** — THE SYSTEM SHALL 保持集团和部门知识空间的分享语义，并禁止将部门知识空间设置或变更为私密；其文件变更是否审核由租户总控和单空间配置决定。
- **AC-42** — THE SYSTEM SHALL 不把本功能应用到频道内容发布、上传、重命名、移动或删除；频道现有分享、订阅审批和个人用户邀请确认流程保持不变。

### 2.7 重命名与移动审核

- **AC-43** — WHEN 编辑者对需要审核的知识空间正式文件或文件夹发起重命名，THE SYSTEM SHALL 创建审批并在执行成功前保留原名称；资源在列表中继续可见并展示为“审批中”。
- **AC-44** — WHEN 重命名审批通过且正式执行成功，THE SYSTEM SHALL 将目标文件或文件夹更新为申请的新名称；WHEN 审批被拒绝、撤回或取消，THE SYSTEM SHALL 保持原名称不变。
- **AC-45** — WHEN 编辑者对需要审核的知识空间正式文件或文件夹发起移动，THE SYSTEM SHALL 创建审批并在执行成功前保留原位置；资源在原位置继续可见并展示为“审批中”。
- **AC-46** — WHEN 移动审批通过且正式执行成功，THE SYSTEM SHALL 按既有移动规则将目标文件或文件夹移动到申请的目标位置；WHEN 审批被拒绝、撤回或取消，THE SYSTEM SHALL 保持原位置不变。
- **AC-47** — WHILE 重命名或移动审批未结束，THE SYSTEM SHALL 继续按资源当前正式名称、当前位置及既有权限提供目录展示、搜索、问答、引用、预览和下载能力。
- **AC-48** — WHEN 正式执行重命名或移动前目标位置、目标名称、资源权限或结构约束已经变化，THE SYSTEM SHALL 重新执行现有业务校验；校验失败时不得部分执行，并应展示明确的执行失败结果。
- **AC-49** — WHEN 用户批量重命名、移动或删除多个资源，THE SYSTEM SHALL 按资源分别返回直接执行、审批中或失败结果，单个资源失败不得回滚其他资源已经完成的结果。
- **AC-50** — WHILE 文件夹处于变更审批中，THE SYSTEM SHALL 阻止对该文件夹及其全部子文件、子文件夹再次发起重命名、移动或删除审批。
- **AC-51** — WHEN 用户查看“审批中”文件或文件夹的审批详情，THE SYSTEM SHALL 明确展示本次审批由“重命名”“移动”或“删除”中的哪一种动作触发，并展示该动作对应的待生效变更信息。
- **AC-52** — WHEN 文件夹的重命名、移动或删除进入审批，THE SYSTEM SHALL 以该文件夹的一条审批覆盖整个子树，其内部文件和子文件夹不得分别创建审批任务；审批通过后的正式执行应将同一动作完整应用于该文件夹及其子树。
- **AC-53** — WHERE 系统存在多个租户，THE SYSTEM SHALL 按租户独立保存、读取和应用文件变更审核总开关、审核范围及单空间配置；任一租户的查询和修改不得读取、覆盖或影响其他租户的配置与审核判断。

## 3. 边界情况

- 同一批上传包含多个文件时，每个文件拥有独立结果；单个文件的拒绝或执行失败不得回滚其他文件已经完成的结果。
- 同一批变更同时包含直接执行与需要审核的文件或文件夹时，应逐资源返回真实状态，客户端不得把审批中资源误判为已执行。
- 审批等待期间审核人关系发生变化时，仅当前仍有效的所有者和管理者可以处理；失效审核人的历史操作记录仍应保留。
- 审批等待期间平台管理员修改租户或空间策略时，既有申请不得被自动放行、取消或重新计算。
- 租户尚无配置时，仅对该租户应用默认审核规则，不得复用其他租户的配置。
- 知识空间在审批等待期间变更为私密时，既有审批不得被自动放行或取消；私密免审仅适用于状态变更后新发起的操作。
- 待审批上传文件不是正式知识空间文件；其预览、清理和审批状态展示不得使其进入正式文件列表、检索链路或正式文件删除审核。
- 正式删除执行失败时，原文件应保持或恢复为可用状态，不得出现审批显示执行成功但文件处于部分删除状态的假成功。
- 用户对同一正式文件或文件夹连续提交相同或不同变更时，只要已有未结束审批，就不得产生新的并行待办。
- 文件夹审批覆盖整个子树；子资源不得重复创建审批，但其既有正式展示和使用能力在审批执行成功前保持不变。
