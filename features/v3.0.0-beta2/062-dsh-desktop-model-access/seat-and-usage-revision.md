# DSH Desktop 用户授权、席位与使用统计修订

日期：2026-09-15

## 授权合同

- 模型权限支持用户、部门、角色三个授权来源。
- 用户授权分别保存开关和每月 Token 额度。开关开启且额度大于 0 时，该用户直接授权生效；关闭开关保留已配置额度。空额度保存为 0，开关状态保持用户设置。
- 部门授权包含当前全部下级部门，成员与部门或角色关系变化后，下一次请求立即按最新关系计算。
- 用户命中多条有效授权时，模型额度取最高值，不叠加。额度继续按用户、模型、北京时间月份独立结算。
- 新增正额度授权前，服务端在租户事务锁内计算授权后的去重用户数。人数超过商业授权席位上限时，整条授权写入失败并返回 `seat_limit_reached`。
- 直接用户授权的在途操作计入席位预留，避免并发授权同时通过相同剩余席位。
- 部门后续新增成员不提前写入席位。成员登录时由 Gateway 按剩余席位分配；无剩余席位时登录不分配席位。
- 商业授权无效、过期或 DSH 停用时，新增正额度授权使用对应业务错误拒绝。

## 管理界面

- 模型权限弹窗按用户、部门、角色分区。用户页展示用户名与 ID、授权状态、用户月额度、用户授权开关和保存操作；授权状态完整单行显示。部门、角色、来源列和逐行说明已从用户页移除。
- 开关切换直接提交当前有效额度；保存期间锁定，失败恢复已保存开关。单独修改额度通过保存按钮提交。最终授权状态根据用户、部门和角色的全部有效来源计算。
- 部门页使用可展开的树形结构，选择上级部门后下级部门显示继承状态；展开节点可查看直属成员。
- 部门与角色的搜索框和统一保存按钮位于弹窗右上区域。
- 席位超限提示提供进入【授权与席位】的操作入口。

## 使用统计合同

- `GET /api/v1/dsh/admin/usage-overview` 按时间范围、部门树、用户名和游标返回当前租户用户页及完整筛选范围汇总。
- 一个 `request_id` 计一条消息；成功请求计问答次数；失败、取消、执行中和用量未知分别统计。
- Token 汇总分别返回输入、输出与总量。存在请求但全部缺少用量时，Token 保持未知，不显示为零。
- 管理界面使用右上角统一筛选栏，依次选择部门或用户、具体对象、时间范围并刷新。部门使用树形下拉；用户输入关键词后在下拉框内选择，选择结果替换同一区域。
- 部门和用户均先展示指标与热力图。部门成员明细默认收起，展开后分页加载；点击成员切换为该用户用量，保留时间范围。
- 部门聚合接口通过 `include_summary=true` 返回完整筛选范围的连续时间桶，与用户列表分页独立，并继续执行租户隔离和成员去重。
- 用户明细复用当前选择的时间范围，避免列表与明细采用不同统计区间。
- 用户明细使用 Token 热力瓷砖图：今天按小时，7 天和 30 天按天，自定义范围超过 31 天时使用七行日历布局。每格按该时间桶 Token 总量映射五档颜色，并在悬浮或键盘聚焦时展示北京时间、Token 与消息数。
- Token 用量缺失且存在消息的时间格保留独立警示状态，避免与真实零用量混淆。
- 今天显示 00 至 23 时的 24 个瓷砖，未来小时标记为未到时间。最近 7 天和 30 天包含今天，按北京时间自然日计算；切换日期保留已选对象。
