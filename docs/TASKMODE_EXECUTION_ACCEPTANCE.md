# 任务模式执行链路修复与验收

## 范围

最终共同开发分支为 `dataelement/bisheng:feat/bisheng-work-120-main`。本轮修复从 `codex/work120-main-integration@480fc2972` 开始，并于 2026-10-22 按用户要求合入共同分支，保留该分支的 `cb4b18018` 前端修改。本轮同步 3006 已发布的 `a01d35a3c` Cookie 配置修复。平台 Chat 的任务模式在服务端隔离容器执行；桌面 Work 保持本地执行边界。日常聊天的技能使用规则沿用现有实现。

## 根因及修改

1. 空工具选择导致任务工具装配提前返回，代码执行器依赖前端显式选择；改为在任务初始化、恢复时按当前用户的 `tool/use` 权限装配基础执行能力，显式选择去重。权限拒绝时保留其他可用工具，权限系统异常按原规则中止。
2. 3006 已配置 `type=container` 并运行隔离 runner，新基线缺少对应后端传输实现；恢复后端容器执行适配，地址与凭据仅由服务配置控制，任务元数据只传工作目录、存储前缀及执行选项。
3. 工具配置写在分类层，而旧装配只读工具层；统一按工具配置优先、分类配置兜底解析，使用独立 ORM 对象保存本次工作区绑定，数据库配置保持原值。
4. 执行产物只有临时下载地址；任务文件同步到 `workspace/<session_version>/` 后返回稳定路径，保存失败报告工具错误，恢复执行带回原件、产物、中间文件和大工具结果；后续新一轮任务继承原件与产物。
5. 重复调用检测只识别相邻一致调用；增加周期 2–4 的重复后缀检测，保留用户输入、交互工具和正常内容变化的边界。

6. 统一积分迁移后，Chat 结算调用了依赖 Work 审计执行对象的私有方法，出现 `SimpleNamespace has no attribute audit`。将共享账本结算提取为明确的数据接口；Work 保留自己的审计回调，Chat 使用统一计量和结算接口。
