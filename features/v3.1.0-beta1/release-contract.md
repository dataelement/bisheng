### 2. 本轮已确认口径及待决事项

- 用户于 2026-11-03 确认 Q-01 为 A，并明确：**所有权限模型移除独立使用（use）动作，原使用准入由可见性承担，不仅限知识空间**。标准、自定义、预设与系统模型及各资源调用均适用，QA 数据保持独立但权限一并收敛；其他动作与业务/身份/租户/scope 限制保持。图23及 §1.7 的旧说法不作为目标。
- 存量文档库迁移、旧调用兼容至整个 3.x、同 ID、既有索引位置和原始文件保留、一次性维护窗口、不双写，是本轮 PRD 的硬边界。
- Q-01 已闭合：保留原主体、可见范围及其他动作。原已可见但无 use 的使用资格变化作为预期差异记录，不再作为待裁定阻断；仅 use 模型去掉动作后仍保持有效可见授权与撤销能力。禁止通过补其他动作或扩大主体范围完成迁移。
- 用户已确认 Q-02-1：仅平台超管与相应租户管理员可进入“知识空间管理”页签及全量管理清单。部门管理员和资源 owner/manager 继续按普通资源授权访问；Q-02-2 已确认超管默认所属租户、可切换其他具体租户，租户管理员仅所属租户；每次单一具体租户，不提供跨租户汇总。Q-02-3 已确认支持当前具体租户内完整管理（详情/内容、授权/配置、上传/移动/下载/删除），保留配额、安全、部门审批、引用及任务冲突检查，空间复制仍仅创建者。Q-02 全部闭合，清空保护见 Q-03。
- Q-03 已确认：清空删除全部内容、保留空间本身；有效空间绑定和直接文件引用均阻止，须先解除引用；历史对话和审计不阻止，但执行前提示对应引用不可访问。管理员、新旧入口执行同一规则。Q-04-1 已确认：任务自然收尾、超预算人工处置、排队保留及升级校验后恢复由运维执行；升级文档要求停服期间运行迁移脚本，脚本不检测或控制停服状态。Q-04-2 已确认仅按有效业务资源/版本/默认配置检查模型引用，不维护任务独立模型绑定，配置解除后任务不独立阻止删除。
- Q-01–Q-07 业务决策均已闭合，完整 94 条 AC 的 spec 已于 2026-11-05 获用户确认。技术设计独立复查已闭合，用户授权进入任务拆分；八列 QA 参考用例与多 agent 任务已生成，尚未编码或环境迁移。

当前源码 Catalog 中 use 适用于 knowledge_library、workflow、assistant、tool、app、linsight_skill；此枚举是本次源码扫描事实，不把用户“所有模型”范围限制在这六类。正式实施前继续盘点其他遗留模型及别名。

### 7. Q-04-2 模型引用范围修订（2026-11-03，已确认）

模型删除仅检查业务配置及默认配置绑定；2026-11-04 已细化为 Spec §3.15.1 的已保存资源、未删工作流版本及可管理预览的应用历史版本等实际来源，不计运行/排队/失败/可重试任务的独立引用，不新增任务绑定或占用系统。这项用户确认替代原 PRD §1.8 和早期设计中的任务引用要求。LLM 与各业务 Owner 保持原归属，任务按所属业务配置解析模型，无合法配置则不能继续执行；历史模型标识只作审计，文件处理策略快照与任务幂等不变。当前显式携带模型 ID 的重建任务需在实现时收敛，不宣称现有源码已符合。

### 8. 关联引用维护方案复查（2026-11-03，技术方案已纳入整体评审）

### 9. Q-05 强制删除与失效引用（已确认）

有引用关系时，空间删除及模型单删/服务清单移除/服务整删支持显式强制模式，默认仍拦截普通删除；清空保持 Q-03。用户明确选择保留业务原 ID/版本/绑定，由目标删除标记识别失效，执行报错并手动修复，不自动清除配置/关系或切换模型。强制仅越过已知引用阻断，权限、租户、共享只读、状态/任务冲突及完整性检查仍生效。引用影响变化重新确认；目标 ID 不复用，修复按业务事务维护原来源/版本。补充 AC-90–AC-92，替代前稿禁止强删条款；技术方案仍待整体评审，未实际删除资源。

### 10. 2026-11-04 Spec 评审决策（已确认）

- 相关模型配置/索引被替换后旧任务过期，不用新模型重试旧任务剩余项；无关名称/说明修改不使过期，不形成任务模型绑定。

- 失效引用可按原可编辑来源/版本逐项保存修复，但剩余失效配置不能执行/发布。托管应用旧快照不可变，新版本修复不清旧版本失效关系，整应用删除才解除对应来源。
