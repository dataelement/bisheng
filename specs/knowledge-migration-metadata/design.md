# 实施设计

根因：普通迁移复制物理行后增加内容代次，保留链接路径也增加代次，随后使用从原文件加载的投影器重建。

1. 普通迁移改为原位归属变更；复用现有控制表、检查点、目标目录和覆盖校验。新控制记录的来源与目标文件 ID 相同；旧批次已有不同目标 ID 时保留恢复兼容。
2. 在迁移资源清单保存来源规范文档/版本/代次。迁移专用共享投影复用已存向量、只改标识和归属，覆盖合并先写目标再删除已废弃来源。
3. 迁移持有投影处理责任期间延后普通投影领取；只有外部存储写入和核验成功才更新 applied 代次。缺失内容直接失败，不自动解析。
4. 发布命令增加内部迁移选项，仅迁移调用启用，普通自动发布行为保持原样。
5. 执行器默认每页领取 20 个单元（构造参数允许 1～100）；仓储批量读取执行记录、文件、空间、所有者及迁移模式，批量提交检查点和结束结果。外部副作用之间保留检查点，数据库切换仍按文档保持原子性。ES Bulk / Milvus 每批写 500 个分块。
6. 迁移通过 `projection_next_retry_at=9999-01-01` 将后台自动投影延后，成功后恢复正常时间；对账任务已有 `projection_busy` 排除逻辑。迁移失败由批次重试/中断恢复接管，不能把投影代次未变误当作元数据已经就绪。
7. 旧批次已准备的目标记录可接续处理；若已经切换且缺少可靠来源内容身份，则明确失败并要求单独恢复，不猜测历史代次，也不触发解析。来源身份存入 `source_resource_manifest.shared_content`，不随目标补偿清空。

主要落点：迁移 runtime/repository/executor/shared_projection、preserve_link_operations、distribution_service 内部命令、共享存储 writer 契约与适配器及对应测试。

风险：数据库与 ES/Milvus/权限非原子，失败必须保留检查点；部署时不得混用旧、新迁移 Worker。无 schema 变化，代码可回退，但新批次应先完成或停止后再回退；不把数据库 rollback 当成外部回滚。
