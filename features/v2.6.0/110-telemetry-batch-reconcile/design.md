# 设计

复用当前 ContentStatReconciler 的批量读取校验与 ES seq_no/primary_term 条件写入，增加通用字符串 ID 支持及合并函数。人员对账保持登录字段/事件时部门；历史名单和登录按相同 ID 合成，人员名单每批复用于多个日期。清理从轮次标记改为仅扫描 participation 范围并核对有效人员，避免未写入记录被误删。

问答定时修复保留 event_time 部门，批量对账；内容增量文件与空间批次复用差异写入。同一批 ES 成功项无需在下次重试重新写入。

任务级有界执行状态存于 Redis，按任务逻辑名隔离，不按随机 Celery ID。记录 owner、租约、attempt、next_at、last_error、dead。原子领取、续期、完成；连续失败和崩溃共用预算。已 dead 不自动重置；成功归零，新的正常周期可继续。互斥竞争不算业务失败。

内容工作队列额外按工作项记录领取次数，成功 ACK 清除次数；到期/失败回收达到上限进入 dead，payload 保留。pending/dead 去重，普通重新入队不复活 dead。任务级保护覆盖领取前基础设施异常。恢复工具只读默认，显式 --apply 才重置指定任务或重放指定条目，不批量清空状态。

名单/问答批次默认 1000；内容队列保留现有 500 的领取限制以控制租约时长。正常工作批量处理，失败重投拆成单条以隔离坏记录。进度按实际处理数量记录。

内容行为事件：HMGET 批量读取 payload，Repository 批量加载用户/用户组/角色/部门，原始事件使用 create bulk（已有 ID 的 409 视为已持久化），刷新成功后按 event_type＋daily_id 分组，用一次 msearch 获取各组精确计数，最后 bulk 单调更新日统计、批量 ACK。部分失败只保留相应工作项。重复原始事件不覆盖原始快照；计数相同时使用 noop。

失败窗口和调用参数保存在任务预算中，跨天和人工重放均保持原窗口。分钟级恢复器补偿未投递成功的重试消息和崩溃任务，重投保留原预算。全量内容对账跳过 dead 文件，不能绕过工作项上限。Redis 原子 ACK 仅清理确实仍处于 processing 的记录，迟到 ACK 不得清除回收后的次数或 payload。

上线风险：新旧 Worker 混跑可能绕过新预算；发布应同时更新统计 Worker。Redis 状态依赖现有持久化，清空 Redis 会丢失预算。回退代码保留 Redis 状态供排查。需实环境验证 ES CAS、Redis Cluster 和 MySQL/DM8；本地测试不能代替部署验证。
