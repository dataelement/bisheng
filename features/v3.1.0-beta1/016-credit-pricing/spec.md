# Feature: 积分按模型真实价格扣除

**关联 PRD**：[确认的需求来源](./request.md)（《积分体系升级-需求文档 v1.0》，产品负责人 2026-11-11 确认）。
**优先级**：P0。
**所属版本**：v3.1.0-beta1，F015-credit-pricing。
**依赖**：发版线既有的统一额度账本与积分规则（F062）、模型可见范围、工作台模型配置；桌面客户端企业连接。
**流程**：Full SDD。本规格待用户确认；标「待澄清」的条目待产品确认，不影响其余条目的实现。

> **范围边界**
> - **本次纳入**：
>   - 单次调用的积分扣除改为按该模型四类 token 的真实单价计价，再按积分单价换算。
>   - 模型价格：添加模型时自动带出、可修改、可恢复原价；用户可选模型表中查看与修改价格。
>   - 积分设置：计价币种、积分单价、汇率、基准模型。
>   - 积分倍率展示：后台用户可选模型表、网页工作台、桌面 Chat 与 Work 下拉框、桌面账号页。
>   - 计费范围补齐：知识空间问答（主对话与看图）、频道问答看图、日常对话回答溯源。
>   - 删除旧的「积分倍率」输入与旧算法；升级时为已有模型补价。
> - **本次明确排除**：
>   - 额度分配、积分规则、积分用完后的拦截方式（沿用现有能力）。
>   - 应用广场、工作流、助手、知识库入库、开放 API、非聊天模型（Embedding、Rerank、语音等）的计费——产品决定本期不扩大范围。
>   - 桌面员工自带 Key 与生图插件——直连厂商，服务端无法计费。
>   - 首钢定制的知识库文件自动编码——按产品决定保持现状。
>   - 分时段 / 分档计价、价格表联网更新、与厂商账单对账、用量未知时估算扣费——下一版或后续。
>   - 「拉取厂商模型列表」结果自动对应价格表——下一版。
>   - 历史调用记录重算——产品决定历史数据不处理。

## 1. 用户故事

作为**企业管理员**，我希望每个模型按它的真实价格消耗积分，并能在添加模型时直接看到官方价格、必要时修改，以便积分额度真实反映模型花费，贵的模型多扣、便宜和自部署的模型少扣或不扣。

作为**企业管理员**，我希望设定计价币种、积分单价和汇率，以便用人民币或美元做预算，并在切换币种时自行选择保持预算还是保持数字。

作为**员工**，我希望在选模型时看到每个模型相对基准模型的积分倍率，以便按任务选择合适的模型、控制积分消耗。

作为**员工**，我希望免费模型在积分用完后仍然可用，回答溯源不会因为积分刚好用完而报错，以便日常工作不被打断。

## 2. 验收标准

### 2.1 扣费计算

- **AC-01** — WHEN 一次计费范围内的模型调用结束并返回用量, THE SYSTEM SHALL 按「未命中缓存的输入、缓存命中、缓存写入、输出」四类 token 分别乘以该模型单价求和得到花费，再除以积分单价得到扣除积分，向上取整到 0.000001 积分。例：DeepSeek V4 Pro（每百万 token：输入 9 元、命中 0.3 元、输出 27 元），未命中 6,000、命中 24,000、输出 1,000，积分单价 0.01 元，扣 8.82 积分。
- **AC-02** — THE SYSTEM SHALL 对缓存命中按命中价、缓存写入按写入价（模型没有写入价时按输入价）、输出按输出价分别计算。
- **AC-03** — IF 厂商没有返回缓存命中数, THEN THE SYSTEM SHALL 将全部输入按未命中价计算。
- **AC-04** — IF 整次调用没有返回用量, THEN THE SYSTEM SHALL 不扣积分，并将该次调用记为「用量未知」。
- **AC-05** — WHEN 模型价格币种与计价币种不同, THE SYSTEM SHALL 按积分设置中的汇率换算后计价（美元价模型在人民币计价下、人民币价模型在美元计价下均适用）。
- **AC-06** — WHEN 管理员修改模型价格、积分单价、计价币种或汇率, THE SYSTEM SHALL 对修改前已开始的调用按开始时的价格结算，对之后开始的调用按新价格结算。
- **AC-07** — THE SYSTEM SHALL 为每次计费调用记录当时的四个单价、计价币种、积分单价和花费金额。

### 2.2 模型价格

- **AC-08** — WHEN 管理员添加模型并输入能匹配内置价格表的服务提供方与模型名, THE SYSTEM SHALL 自动填入官方价格并提示来源；管理员修改后显示「已修改」，并可恢复原价。
- **AC-09** — WHEN 管理员添加模型并输入匹配不上价格表的模型名, THE SYSTEM SHALL 将四个价格默认填 0，并提示按免费处理。
- **AC-10** — WHEN 管理员在用户可选模型的价格弹框中修改价格, THE SYSTEM SHALL 与模型配置中显示同一份价格，保存后从下一次调用开始生效。
- **AC-11** — WHILE 某模型的四个价格均为 0, THE SYSTEM SHALL 对该模型的调用扣 0 积分，且员工积分用完后仍允许调用；对收费模型，积分用完后拦截并提示「本月积分已用完」。

### 2.3 积分倍率与积分设置

- **AC-12** — THE SYSTEM SHALL 按「(3 × 输入价 + 输出价)」相对基准模型计算并展示积分倍率；更换基准模型后倍率随之变化，同一调用的实际扣除不变。
- **AC-13** — WHERE 企业客户端开启, THE SYSTEM SHALL 在网页工作台模型下拉框、桌面 Chat 与 Work 模型下拉框、桌面账号页模型列表、后台用户可选模型表中显示积分倍率。
- **AC-16** — WHEN 管理员切换计价币种, THE SYSTEM SHALL 弹出二选一确认：选「保持预算不变」时积分单价按汇率换算，选「保持数字不变」时积分单价数字不变。

### 2.4 计费范围

- **AC-14** — WHEN 员工在工作台使用知识空间问答（主对话与看图）、频道问答看图、日常对话回答溯源, THE SYSTEM SHALL 对这些模型调用扣除积分。
- **AC-15** — IF 员工积分已用完时触发回答溯源, THEN THE SYSTEM SHALL 不因额度不足让回答或溯源失败，并照常记账。
- **AC-21** — THE SYSTEM SHALL 保持不在范围的场景（工作流、助手、知识库入库、开放 API 等）的扣费行为与改造前一致。

### 2.5 旧算法、升级与兼容

- **AC-17** — THE SYSTEM SHALL 不再在后台提供「积分倍率」输入，所有计费调用按新算法扣除。
- **AC-18** — WHEN 系统完成升级, THE SYSTEM SHALL 使所有已有的大语言模型都有价格：能匹配价格表的为官方价，匹配不上的为 0。
- **AC-19** — WHEN 旧版本桌面客户端连接新版本服务端, THE SYSTEM SHALL 保持原有功能可用，仅不显示积分倍率。
- **AC-20** — THE SYSTEM SHALL 在 MySQL 与达梦上均正常运行；多租户下各企业的积分设置互不影响。
- **AC-22**【待澄清】 — IF 某个大语言模型没有价格记录（只可能因为升级时未完成补价）, THEN THE SYSTEM SHALL 拒绝该模型在计费范围内的调用并返回错误码 26176，提示联系管理员，而不按免费处理；管理员在用户可选模型表中可见「价格缺失」标记。

> AC 编号沿用需求文档；AC-14/15/21 归入 2.4、AC-16 归入 2.3 只为按能力分组，编号不变。AC-22 为技术评审后新增，待产品确认。

## 3. 边界情况

- 基准模型被删除、下线或价格改为 0 时，不显示积分倍率，后台提示重新选择。
- 同一个模型名挂在两个服务提供方下时，各自单独定价。
- 单次调用很贵、超过剩余额度时，本次照常完成，可能用超，下一次才会被拦（与现在一致）。
- 【待澄清】厂商返回的缓存数大于输入总数时（个别接口口径不同）：需求文档原写「未命中输入按 0 计并记录告警」；技术评审指出这样会少扣，建议改为「判定该来源的输入不含缓存，把缓存数加回输入再计价，并记录告警」。待产品确认采用哪一种。
- 匹配不上价格表的收费云模型（如火山方舟接入点、中转站的新模型名）默认 0 即免费，管理员不改价就一直不扣；后台以「默认 0」标签提醒核对。
- 月中修改积分单价或切换币种时，本月已用积分数字不变；精确金额以每次调用的记录为准。
- 【待澄清】总公司共享给子公司的模型：价格由总公司设定，子公司只读（需求文档写「技术方案待确认」，待产品确认）。若产品要求子公司各自定价，需调整设计。
- 两名管理员同时修改同一模型价格时，后保存的一方得到冲突提示，不静默覆盖前者的修改。
- 升级必须停服完成；升级完成并开放使用后，不支持回退到旧版本（如发现问题以补丁版本修复）。是否必须支持开放后回退，待拍板。
