# Design 毕昇 Workflow 调用昆联 Agent 长任务与取消

- **Feature ID**: F124（拟用，合入前复核）
- **Version**: v3.0.0
- **Status**: DRAFT，规格已确认，设计待确认
- **Mode**: SPEC_ONLY，首轮 Mock 优先
- **关联**: [已确认规格](./spec.md)、[F119 设计](../119-kunlian-platform-agent/design.md)、[F119 验证记录](../119-kunlian-platform-agent/verification.md)、[版本契约](../release-contract.md)、[架构约束](../../../docs/constitution.md)。

## 1. 目标与现有基础

复用 F119 的平台 Agent 节点、固定版本、发布绑定、运行人、输出变量和停止入口，增加显式选择的长任务路径。首轮在有会话的「开始 → 平台 Agent → 输出 → 结束」流程验证启动、轮询、取消及超时。远端人工输入归 4C；本期不引入回调、独立 Agent 取消 API 或通用跨 Worker 图恢复。

| 已核对的代码 | 现状及复用边界 |
| --- | --- |

## 2. 约束与方案选择

| 决策 | 采用与原因 | 何时重新考虑 |
| --- | --- | --- |
| D-01 模式 | 在原节点配置及发布绑定中增加 `execution_mode: sync / async`，省略为 `sync`；发布和调试校验固定版本声明的异步能力。复用节点和映射，避免新增第二种节点或从返回状态猜模式。旧发布图的摘要算法及缺省读取行为保持兼容。 | 双方需要同一版本按不同执行合同独立授权时，再评估能力描述。 |
| D-02 执行 | 原图执行者有界等待，同一个节点拿到结果后继续原图。远端取消与补偿可由独立短任务执行。拒绝在 Worker 丢失后从图头重跑，也不把 F123 文本等待检查点套用到 Agent 节点。 | 原图执行槽占用不能满足并发目标，或需要 Worker 退出后继续原图时，另行设计图挂起与恢复。 |
| D-03 记录 | 在现有 F119 执行行的 `calls[node_id:ordinal]` 增加版本化 `long_task`。本地结果、远端事实和取消进度分别保存，同一行裁决竞争。Redis 和队列只用于通知及提速。无需新表、现有列变更或历史数据迁移。 | 如果实际量级使同一执行行争用或补偿扫描超预算，再单独评估索引或独立任务表。 |
| D-04 停止 | 先在 F119 的 `request_stop` 路径写本地停止及取消意图，再尽力投递补偿。旧停止路由不等待昆联 HTTP。相比从接口直接取消，这能覆盖本地已停止但投递失败的窗口，也能处理尚无 Run ID 的情况。 | 昆联提供可验证的回调或可靠推送后，可替换确认方式，仍保留本地截止和输出门禁。 |

首轮的异步指昆联受理与结果分离，不占住浏览器请求。轮询间隔让出事件循环，不持有数据库事务或 HTTP 连接；F119 的图执行线程仍占一个执行槽。独立补偿使用短任务，不依赖这条线程存活。Mock 明确限制活动长任务数，超过能力时按既有排队或拒绝策略反馈，不作生产并发承诺。

## 3. 状态与执行记录

`long_task` 仅用于显式启用的执行，原同步 `calls` 项继续由 F119 处理。外层执行状态沿用 F119；等待远端时仍是本地运行中，不能写成表示用户输入的 `WAITING`。以下是毕昇内部状态名，非昆联接口枚举。

| 记录 | 状态或字段 | 约束 |
| --- | --- | --- |
| 本地节点 | `PREPARED → WAITING_RESULT → SUCCEEDED`；允许按原因结束为 `STOPPED / TIMED_OUT / FAILED` | 只有原图领取者可提交输出。终态不可重开，停止与输出共用运行行的原子判定。 |
| 启动与远端 | `NOT_SENT → START_IN_FLIGHT → START_UNKNOWN`；受理后为 `QUEUED / RUNNING`，可观测到 `WAITING_INPUT`，最终为 `SUCCEEDED / FAILED / CANCELLED`。明确拒绝用 `START_REJECTED`。 | 先核对关联，再接受 Run ID。只允许一次绑定，已有 Run ID 不被替换；终态不被旧状态覆盖。远端成功与本地结果可用分开保存。 |
| 取消 | `NONE → INTENT → SENT → ACCEPTED → CONFIRMED`；另有 `REJECTED / UNCONFIRMED / NO_ACTION` | `INTENT` 只表示待发；`SENT` 表示已发或发送结果不明；`ACCEPTED` 不能显示为已取消；`CONFIRMED` 必须有该 Run 的远端取消终态。终态已知或确定未发送时，无需发取消；如远端先以成功或失败结束，保留其终态并说明取消未生效。 |
| 关联与时钟 | 固定 `execution_id`、节点 ID、序号、Agent 版本、请求摘要和启动键；另有远端 ID、取消键、阶段期限、下次核对时间、阶段领取标识及安全错误分类。 | 关联绑定原租户、接入方、实际用户、来源及策略修订。时钟在锁内判定，轮询、重投和重连不续期。请求正文不为补偿另存副本；保留摘要和非敏感状态。 |

启动键沿用 F119 的逻辑调用关联（执行 ID、节点 ID、序号），按昆联契约映射格式与作用域。请求摘要包含固定版本、有效输入、主体和来源。同键同参重读已知事实；异参拒绝。取消键在同一调用内固定，独立于启动键；任务重投不生成新键。不同节点执行或新的 Workflow 运行使用新的逻辑关联。

## 4. 执行与补偿流程

现有 Workflow 运行 → 平台 Agent 节点登记并启动 → 按原 Run ID 轮询 → 校验并提交一次输出；停止与到期走同一执行记录，关闭本地输出后由补偿处理远端。

### 4.1 启动、轮询和输出

1. **受理。** 沿用 F119 的发布绑定与运行快照。已授权的原图执行者解析输入，校验固定版本、异步能力及映射，登记逻辑调用和绝对截止。启动发送前，在短事务中再次核对当前执行、领取标识、停止状态和截止，只给一个发送者许可。停止先取得判定权或能确认请求未交给传输层时，不发送。发送许可交接后若无法证明有没有发出，按在途或未知处理。数据库锁不跨网络调用。
2. **确认启动。** 受理回执须匹配原版本和调用关联；锁内记录可信 Agent Run ID。明确拒绝结束本地节点。发送后超时、响应丢失或受理报文不足时先按原关联查回。仅当契约明确支持安全幂等重放，且本地仍允许启动、原执行者仍持有原参数、原窗口仍有效时，才用同一键及参数重放。停止或超时后只允许不会创建任务的核对。
3. **轮询。** 原执行者按已绑定 Run ID 查询。只展示来源可信的状态和有限进度摘要。每次请求有超时，临时失败或限流按有界退避重试，间隔不超原截止；权限拒绝不重试。每次只接受当前阶段领取者的响应，旧响应不能使状态从运行回到排队，也不能覆盖已确认终态。远端等待人工输入时以明确的本地不支持结束，保留远端等待事实，不发输入。
4. **结果提交。** 远端成功但结果暂不可读时，继续在原期限内查询结果。验证原 Run、固定版本、来源及冻结输出 Schema；校验不通过不写部分输出。提交前重新核验本地和远端操作资格，行锁内核对原领取者、调用状态、环境及截止，再复用 `output_commit_scope` 发布一次 `result`。结果与停止同锁判定：停止或到期先发生时，晚到结果只更新可确认的远端摘要；输出先提交则保留，停止仍阻断其后尚未开始的节点。
5. **下游开始门禁。** F119 的输出门禁只保护当前节点变量，4B 在现有图执行链对已绑定长任务的执行加一次下游开始许可。进入后续节点前以同一运行行核对当前领取者和本地停止状态，在节点开始回调和业务执行前判定；已经获准开始的步骤不作回滚承诺。同步和其他图不走此附加门禁。

### 4.2 停止与超时

| 触发 | 锁内裁定 | 锁外动作 |
| --- | --- | --- |
| 通过现有 Workflow 停止入口主动停止 | 由现有会话主体与 Workflow 权限定位本次 `execution_id`，设本地停止标记，并为在途长任务记录一个取消意图。已经结束的调用保留。 | 使用现有停止信号通知图执行；本地停止响应不等远端或图任务轮询结束。补偿负责发送与确认。 |
| 到达启动或总等待截止 | 明确未发送时记本地启动超时；无法确认是否已受理时保留未知；已知远端状态但未提交输出时关闭本地输出，区分远端成功而结果未取得和远端仍未结束。 | 已知未终态的 Run 尽力取消。未知 Run 只按原关联做有限核对，找到且仍未终态再取消。 |
| 取消送达、响应丢失或拒绝 | 使用原取消键和领取标识处理回执；接受、拒绝、未确认分别记录，不改写本地停止或超时。 | 优先查询原 Run。只有正式契约证明安全且仍未终态时才以原取消键重试；确认远端已取消才结束为 `CONFIRMED`。 |
| 取消核对截止或失去授权 | 停止本轮外部动作，保留最后可信的远端事实和安全原因；无终态证据时为未确认。 | 不换凭据、不换 Run ID、不重发启动，也不恢复已结束的图。 |

状态更新用短事务按执行、阶段、当前领取标识条件写入。旧阶段响应不能提交结果。为处理「停止发生在请求在途」的窗口，在补偿期限内仅允许原启动关联的迟到回执补录经过核对的 Run ID 或远端事实，不会恢复本地输出资格。查到任务已终态时跳过新取消；若收到可核验的取消终态，可直接确认，无须先补一个受理状态。

`request_stop` 同时被清理旧执行引用、写入失败状态和主动停止调用。只有经过授权的主动停止或 4B 自身的超时裁定可建立远端取消意图。内部清理保持原有本地行为，不发远端请求，也不清除已有取消意图。浏览器停止先落本地事实，再处理原有事件流，避免等待运行消息的锁拖住停止。

### 4.3 补偿调度与状态读取

- **先记录，后投递。** 停止、超时或待核对事实先与执行状态同事务写入。提交后唤醒候选补偿任务；投递失败记录安全原因，由扫描补投，不把已经生效的本地停止报成失败。消息只带执行和调用标识，租户由可信消息头提供，不携带输入、结果或凭据。Mock 只在隔离环境装配定时触发，不修改生产 Beat 或 Worker 启动配置。
- **漏投和进程退出。** 按可信租户对现有执行行做有限批次、主键游标轮转；按归属和 `long_task` 的到期事实选取候选，覆盖已停止、已失败但仍待确认的执行，不依赖 Redis 指针或数据库 JSON 方言。取到候选后短事务领取操作；失联领取可在租约到期后接管查询，写回核对领取标识。是否允许重发启动或取消仍由幂等合同决定，租约过期不证明旧请求没有发出。没有原图执行者时只收敛本地超时和远端事实，不重新执行节点。
- **预算。** 启动受理时限、节点总等待时限、单请求时限及取消核对窗口分开；前两者基于该逻辑执行首次受理设定。所有请求受所在阶段剩余预算限制。Mock 使用可控时钟和有限退避；正式数值、并发容量及扫描时限待 EXT-01～03 确认和验证。
- **读取。** 在已有会话状态入口提供长任务摘要，使用原执行关联和当前权限读取执行行，避免 Redis 终态被消费后误认为需要重开任务。会话重连时可沿用原执行 ID；未提供时只解析当前可信执行引用，不能用同会话的最新执行冒充已指定的运行。显式新运行才产生新的执行 ID。既有节点事件可提供即时提示，成功的业务输出继续使用现有 Workflow 输出及会话历史。取消摘要在本地结束后仍可查询，保留窗口到期清理非必要进度与回执；仍保留能阻止旧调用被重新启动的事实。非会话预览仍遵守既有断线规则。

## 5. 授权、契约与模块落点

启动、轮询、读结果、取消和对外查询均按 F119 的当前实际用户与租户核对，发布运行用 Workflow `use`，调试沿用现有 `edit`，外部适配另按昆联动作权限裁定。接入方、来源、策略修订和当前身份版本须匹配原执行；读本地摘要还须核验会话归属，本身不触发昆联调用。自动超时可关闭本地输出，但无法确认原用户仍有权限时不代发远端请求。运行记录、队列和日志不保存访问令牌或委托凭据。

### 5.1 内部候选契约

| 能力 | Mock 归一后的业务结果 | 契约边界 |
| --- | --- | --- |
| `start`／`lookup_start` | 受理、明确拒绝、查回原 Run 或未知 | 关联原启动键、版本和主体；查询未命中不等于未创建，不能据此新发一次。 |
| `get_status`／`get_result` | 远端状态、可选进度、结果就绪或不可用 | 可以由同一昆联接口实现；适配层核对关联、身份和版本。只保留安全进度及错误分类。 |
| `cancel` | 已受理、已拒绝、已终态、送达未知 | 使用原 Run ID 和取消键；结果以可信终态为准，不以 HTTP 成功推断已经取消。 |
| 毕昇现有 Workflow 状态／停止 | 既有状态消息可附加 `agent_long_task` 对象：`execution_id`、`local_state`、`remote_state`、`cancel_state` 为字符串，`agent_run_id`、安全原因和进度摘要按已知事实提供。 | 在已有入口扩充长任务摘要，不新增独立取消入口。已有停止响应含义仍是本地受理；此候选视图不定义昆联字段。 |

## 6. 已知坑与宪法检查

| 易错点 | 影响 | 处理位置 |
| --- | --- | --- |
| F119 会把在途同步调用标为放弃；内部清理也调用停止。 | 容易把本地放弃误报成远端终态，或误发取消。 | `PlatformAgentRepository.request_stop` 区分调用模式和停止原因，`RedisCallback` 传递对应原因。 |
| Redis 终态会被消费，停止消息可能漏投，Worker 内存对象也可能丢失。 | 重连误开任务，或取消意图无法执行。 | `WorkflowClient.check_status` 补查执行记录，补偿任务不依赖原执行进程和 Redis 指针。 |
| 只在节点返回时判断停止。 | 写变量或下游开始仍可能晚于停止。 | `output_commit_scope` 和图执行前的开始许可共用执行行。 |
| 发送许可提交与请求送达不是同一件事。 | 把未知当未启动，重试时可能创建第二次任务。 | 平台 Agent 服务记录发送边界，Provider 区分未发送、已受理和送达未知。 |

**Constitution Check**：C1 由入口、领域服务、仓储与 Provider 分层；C2 复用双库 `JsonType`，扫描不依赖 JSON 方言；C3 用现有租户上下文和可信任务头，核对原用户与接入方；C4 沿用 F048 与 F118，不新增权限动作；C5 沿用 Workflow 错误域，不在本设计预占错误码；C6 凭据只在授权后的请求期使用；C7 前端沿用既有运行 API／事件客户端；C8 SQL 保存共享运行事实，Redis 和消息只作为通道。当前为设计审查，实际架构检查和真实双库验证留给实施阶段。
