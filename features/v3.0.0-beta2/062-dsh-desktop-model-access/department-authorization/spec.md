# 部门树统一授权
状态：2026-09-17 用户确认简化版并授权开发部署。

- AC-01：一个部门树，根默认展开，子部门有连接线，直属成员按需分页加载。
- AC-02：成员展示名称、ID、个人额度、生效额度和席位资格。同人多部门编辑一致。
- AC-03：统一搜索部门、用户名或 ID，显示所属路径；无部门成员可查看编辑。
- AC-04：右上角保存生效，空值为 0，校验非负安全整数，离开草稿需确认。
- AC-05：保存部分失败保留草稿与幂等操作 ID，回读确认完成，网络等待有界。
- AC-06：生效额度取个人与各所属部门、祖先部门最大值。部门 100000 + 个人 6000/1000000/0/空分别为 100000/1000000/100000/100000。
- AC-07：新成员按当前部门获得额度，全部来源零为未授权；修改额度保留累计月用量。
- AC-08：保存额度保持现有席位；登录时 Gateway 分配。正额度+有效许可+已分配为已授权；容量充足为待登录分配，满额为席位不足。
- AC-09：撤销、许可失效、查询异常各自展示原因，异常保留额度。
- AC-10：当前有效角色成员迁移为个人额度，max(原个人,角色)，核对每人最终额度后关闭旧角色策略，保留历史。
- AC-11：租户隔离、管理鉴权、并发版本、审计保持；迁移可重入。
- AC-12：3006 增量部署保留并行改动，分别记录自动化、健康及端到端验收。
- AC-13：部门和个人设置额度、最终额度统一以“万 Token/月”展示，输入支持 4 位小数，1 Token 精度；空值保存为 0，后台继续存储整数 Token。
- AC-14：部门行展示已保存的自身与祖先部门最大额度及授权状态，成员行展示实际席位状态；编辑后点击保存生效。
- AC-15：树正文采用紧凑字号和行距，空部门展开时直接展示子部门，空成员占位省略。

本轮席位继续登录分配。排队、自动补发和提前占席属于后续范围。
