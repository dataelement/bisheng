## 本分支修复

1. `SpaceCopyOwner._initialize` 对新目标的空 Milvus 集合复用原 `KnowledgeUtils.ensure_milvus_schema_ready`，先以标准元数据种子建立 schema 并删除种子，再 load，随后创建 ES 索引。失败继续抛错，不把任务标成功。现有集合直接 load；原 session 仍传给模型引用准入，避免重新引入自身锁等待。
2. 移动的批次读取、跨空间范围读取及执行复核统一要求源和目标 `state == PUBLISHED(1)`。state=0 的未初始化空间在逻辑迁移/授权投影之前拒绝，不再先迁入文件再因索引不存在失败。复制中、重建中及 model_transition 的保护保持。
3. 未自动修改旧任务的冻结权限计划。4394 的源权限版本已变化，不能通过放宽比较或直接重写 version 恢复。部署修复不等于现有失败任务已经恢复；若后续要求恢复，需要单独核对旧任务、源权限及已经迁入的两份文件后选择原任务可安全恢复或重新建复制流程。
