## 4. 首轮边界与分期

首轮 Feature 交付对象是 Docker 开源托管闭环，包含平台存储、共享控制状态、数据安全、应用包/完整镜像、离线补包及正式镜像安装。优先完成前置可靠性再开放目标默认发布方式，不把“可以启动容器”当作整个 Feature 完成。

K8s 执行实现保留在 F059 后续阶段；当前不取消 INV-33 的双形态产品语义一致要求。整个应用工场是否达到双形态交付，仍需 F059 真正实现和验证。

本轮不增加平台管理界面和用户一键回滚。运行环境及离线材料通过管理接口/安装工具完成；数据库恢复属于明确授权的运维操作。历史代码恢复为一次新的正常发布，继续必审。

F086 拥有新增的运行产物、运行环境目录、运行操作及事实/投影合同；不接管既有 App、AppVersion、ResourceTier、ApiCredential 或审批对象的业务写入归属。F054/F055 使用相应服务完成组合行为。

| 原规格/设计 | 当前约束或事实 | 本轮需同步的边界 |
| --- | --- | --- |
| F054 AC-15 | 源码构建可运行镜像 | 为旧构建方式保留；新应用包/完整镜像交付使用扩展后的准备与运行语义 |
| F054 AC-21 | 默认先启动新实例再退休旧实例 | 无持久写入或数据兼容时保留；SQLite 结构变更增加单活动维护分支 |

| F055 AC-07、AC-42、AC-43 | 预检、迁移快照、冻结材料 | 增加复合交付、离线预检、持久确认和响应丢失查询 |

## 6. 明确保留的约束与已知坑

1. 发布仍必审；预检失败不生成审批或正式版本，已审批版本容量不足不重复创建审批。
2. 当前版本能力切换与外部权限撤销是不同动作。不得用“保留旧服务”绕过已经失效的外部授权。
3. 普通运行检索使用应用声明与访问者可见范围；F055 AC-27/INV-36 的审批预览 owner 能力例外仍保留，不能误写为所有预览按审批人能力判定。
4. 应用专属 SQLite 持久卷不是平台共享控制状态；容器重建无损不等于单机物理盘损坏后零损迁移。
5. 修改 Compose manager.image 不会修改应用运行镜像；当前也不存在可直接使用的新运行档位配置项。
6. 纯离线缺少新包时必须补齐材料，不能从“镜像已导入”推断依赖闭包和业务接口都可用。
7. 现有 release-contract 的 INV-27 至 INV-36 和继承版本约束继续生效；F086 不引入第二套授权、审批或平台主数据所有者。
