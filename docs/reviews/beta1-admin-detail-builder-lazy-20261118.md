# 子租户详情权限与构建按需查询修复

日期：2026-11-18（Asia/Taipei）。分支：`codex/3.1.0-beta1/bugfixes-20261118`。本轮基线：同步发布线后的 `83da476446`。当前聊天继续在托管修复 worktree 工作，原主工作区不变。

## 问题及处理

1. 子租户管理员从知识空间管理进入详情，目录报“只有创建者或管理员”错误。管理清单允许同租户管理员，但目录调用业务 `visible` 后进入个人可见关系判断；没有个人 Grant 的租户管理员被拒绝。
2. 构建清单以管理/编辑资格列出工作流等应用，详情也因为相同的业务 `visible` 与个人关系混用而返回 403。
3. 构建页首次加载按每张卡片查询资源权限；工作流版本由后端清单额外查询，托管版本又在每张卡片 mount 时独立读取，造成请求放大。

本轮按既有管理员访问、个人可见及版本操作合同修复，采用 hotfix/performance track，不增加 API、数据库字段或权限模型。

- 权限业务入口在管理边界和创建就绪检查后解析真实业务目标，只有完整数据范围的本租户管理员可以快捷通过业务访问。普通用户、外国目标、收窄凭证和业务目标失效仍保留原检查；raw `check_visible`、个人可见列表及加入状态不变。单项和批量业务入口保持一致。
- 构建清单仍进行必要的列表准入；前端不再逐卡片预取具体权限。点击设置、进入编辑、查看版本或操作状态时，只请求当前资源，区分 workflow / assistant / app，设置菜单显示查询中或失败状态。
- 工作流管理清单 `version_list` 保持字段但不执行版本查询。打开版本选择器再读原版本接口；仅离线且已证明 edit 权限才切换版本，线上只读。其他非 managed 清单保持原版本返回。
- 托管应用初始展示版本入口，点击后查询。继续区分最新上传与当前运行版本，失败可重试，替换卡片时旧响应不能覆盖新资源；版本不提供切换写入。
- 权限请求缓存加入所属/管理租户维度，保持类型隔离、请求合并及原 TTL；范围变更后的旧结果不用于操作。未知权限不会提交发布、删除或版本切换写入，后端仍做最终授权。
