# 树形结构 Tree

> 设计系统 · 树形结构 v1 草案 · 2026-11-16
> 适用范围为有明确父子关系的内容。当前覆盖知识空间和组织部门的浏览用法，见[组件演示](/components/tree-navigation)。

## 1. 什么时候用

用树形结构展示有父子关系的数据，例如知识空间和文件夹、部门和子部门。用户可以同时展开多个分支，了解它们各自有哪些下级。

BISHENG 目前用树形结构浏览和打开内容。点击节点名称后，在相邻区域显示相应的文件、成员或详情。导航是树形结构在这些页面中的用法。

| ✅ 推荐 | ❌ 不推荐 |
| --- | --- |
| 同时展开几个知识空间，在文件夹之间来回切换 | 把同级入口都画成树。没有父子关系时，普通导航列表更清楚 |
| 在组织结构里展开部门，点击部门查看成员 | 用页面的部门树直接回填「所属部门」。平铺选项用 [组件-Select选择器.md](组件-Select选择器.md)，沿父子路径逐级选值用 [组件-Cascader级联选择.md](组件-Cascader级联选择.md) |

## 2. 类型

按根节点是否需要归类，选用基础树或分组树。两种组合共享节点尺寸和状态。

| 组合 | 什么时候用 | 示例 |
| --- | --- | --- |
| 基础树 | 所有根节点属于同一类内容 | 组织部门树 |
| 分组树 | 先按来源归类，再看组内的层级 | 知识空间按「部门知识空间」「我创建的」「我加入的」分组 |

用分组标题展开或收起该组，把排序、新建等组内操作放在标题行。节点层级从组内根节点起算，当前态只应用于节点。

基础树和分组树都可用 `showLine` 显示层级竖线，默认关闭。知识空间的多层目录开启竖线，方便在多个展开分支之间追踪父子层级。竖线位于展开分支的子节点左侧，沿用深浅色主题的 `border-base`。

## 3. 尺寸

桌面提供两档尺寸。同一棵树使用同一档，知识空间沿用紧凑档 `small`。

| 尺寸 | 节点行、分组标题行高度 | 节点名称字号／行高 | 分组标题字号／行高 | 适用场景 |
| --- | --- | --- | --- | --- |
| 紧凑 `small`（默认） | 28 px | 12 / 20 px | 12 / 18 px | 知识空间等需要同时看见更多节点的侧栏 |
| 常规 `medium` | 32 px | 14 / 22 px | 14 / 22 px | 组织部门等需要更大字号的面板 |

两档共用以下尺寸。层级越深，节点内容向右移动，整行的选中底色仍从同一位置起画。

| 项目 | 共用尺寸 |
| --- | --- |
| 相邻节点间距 | 2 px |
| 节点层级 | 根节点缩进 0 px，每深入一级加 20 px |
| 展开箭头、节点图标 | 图标 16 × 16 px，各占 20 × 20 px 槽位 |
| 图标到名称 | 节点图标槽后留 4 px |
| 行背景圆角 | 6 px |
| 分组间距 | 标题后留 8 px，每组末尾留 16 px |
| 分组操作 | 图标 16 × 16 px，按钮 20 × 20 px；触屏点击区 44 × 44 px |
| 列表内距 | 分组树两侧各 12 px，基础树与面板边缘对齐 |
| 行尾操作 | 按钮距列表右边缘 4 px，与名称之间留 8 px。分组树的按钮距视口右边缘 16 px |
| 置顶标记 | 图标 12 × 12 px，紧跟节点名称 |

尺寸按默认字号计算。放大文字后要能读到完整文字并看到焦点，行高随文字增高。

## 4. 内容与滚动

- 从左到右放缩进、展开箭头、类型图标、节点名称、可选状态标记和行尾操作。已知没有子项的节点留出箭头槽位，保持同级名称对齐。子项情况未知时可以先保留箭头，确认无子项且没有后续数据后隐藏。
- 节点名称保持单行。超出时在树的可视边缘显示省略号，横向滚动可以读到名称末尾。辅助技术可以读取完整名称。
- 在树内部横向滚动时，分组标题及其操作固定在可视区，行尾菜单贴右侧。菜单显示时给它预留空间，让省略号落在按钮前面。
- 纵向滚动时，让分组标题贴住滚动区顶部。离开该组时，标题随组滚走。滚动条显隐见 [基础-滚动条规范.md](基础-滚动条规范.md)。
- 用行尾「更多」集中节点操作。置顶是节点状态，排序是分组操作。菜单沿用 [组件-Dropdown下拉菜单.md](组件-Dropdown下拉菜单.md)。

| ✅ 推荐 | ❌ 不推荐 |
| --- | --- |
| 用触控板横滑、Shift 加滚轮或同等键盘操作查看标签尾部 | 用永久截断显示所有长名称，名称前半段相同就无法辨认 |
| 用箭头展开分支，用名称打开对应内容 | 点击同一个区域同时切换内容并折叠分支，用户会失去正在浏览的位置 |

## 5. 状态与交互

| 状态 | 规则 |
| --- | --- |
| 默认、悬停 | 默认透明底。鼠标悬停时整行显示浅底，支持操作的节点显示行尾菜单。键盘聚焦到菜单触发器时同样显示 |
| 当前 | 两档均用整行底色、500 字重和主要文字色的图标标识当前节点。再次点击当前节点时保留当前态，直到打开另一个节点 |
| 键盘焦点 | 显示清晰的焦点轮廓。焦点可以移动到未打开的节点，只有激活节点才切换内容 |
| 展开、收起 | 从左向右阅读时，箭头朝右表示收起，朝下表示展开。点击箭头只切换该分支，点击名称打开内容。切换当前节点，或收起再打开父级和分组时，保留内部已有的展开状态 |
| 加载、重试 | 在正在展开的分支内显示进度。读取失败时在同一处提供重试，保留之前已加载的节点。后续页在该分支末尾继续加载 |
| 空、禁用 | 整棵树或整组无内容时显示空状态。已确认无子项的节点下方不加空行。明确不可用的操作展示禁用态 |

用 Tab 和 Shift + Tab 在可操作项之间移动。按 Enter 激活聚焦的入口，按钮也可以用空格激活。展开按钮和更多菜单要有带节点名称的可读标签。从外部打开深层节点时，展开它的上级分支并将当前节点带到可视区。

## 6. 移动端适配

窄屏页面需要在树和内容区之间切换时，用独立页或抽屉承载树，打开节点后回到内容区。触屏上的行尾操作保持可见。给展开、节点名称和行尾操作独立的点击区，触屏点击范围按 [基础-多端适配原则.md](基础-多端适配原则.md) 执行。字号随系统字体设置。

## 7. 深浅色

浅色和深色共用位置、字号、图标和状态。用语义色区分背景、悬停、当前节点和键盘焦点，随主题切换。当前节点通过底色和字重共同识别。两档可操作文字与背景的对比度均至少达到 4.5:1。色阶见 [基础-色彩规范.mdx](基础-色彩规范.mdx)，对比度依据见 [WCAG 2.2 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

## 8. 组件能做什么

当前组件提供基础树和分组树，支持独立展开、标记一个当前节点、长名称滚动和行尾菜单。页面负责节点数据、加载与重试、打开后的内容和操作权限，也决定面板的宽度、标题和收起方式。

批量勾选、拖拽调整层级及表单回填需要各自的交互设计。根据任务明确勾选的范围、拖拽后的父子关系，或回填的字段值，再评审相应的用法。

## 给实现窗口

1. **组件边界**。当前浏览用法由 `TreeNavigation` 提供视口，`TreeNavigationGroup` 接收分组标题和操作，操作按钮使用 `TreeNavigationGroupAction`。`TreeNavigationNode` 接收名称、层级、图标、当前态和可选 `disclosure`。调用方使用稳定的节点标识记录展开状态，并负责请求、游标、权限、租户隔离、排序、置顶和路由。深层定位时，调用方逐级展开并加载上级分支，共享组件负责将已渲染的当前节点滚入视口。需要再次定位同一个节点时更新 `revealKey`。
2. **语义与焦点**。结构使用有标签的 `nav`、分层 `ul/li`、独立的展开按钮和导航入口。展开按钮用 `aria-expanded` 和 `aria-controls` 关联子列表，当前导航入口用 `aria-current`。传入 `href` 时使用链接。折叠或刷新移除焦点所在节点后，焦点回到仍存在的祖先操作、组标题或树视口。行尾菜单沿用 Dropdown 的焦点行为。
3. **视口**。长名称保留自然宽度生成横向滚动范围，可见名称按视口重新计算裁切边缘，测宽副本对辅助技术隐藏。横滚可用触控板、Shift 加滚轮，或在视口聚焦时按左右方向键。滚动条显隐沿用[滚动条规范](基础-滚动条规范.md)的原生行为。
4. **尺寸和字重**。`small` 用于知识空间，`medium` 用于组织部门。两档选中统一用 500 字重。粗指针且无法悬停时，展开、菜单和分组操作使用独立的 44 px 热区。
5. **主题**。节点和组标题使用 `text-1`、`text-2`，悬停和选中使用 `fill-1`、`fill-2`。
