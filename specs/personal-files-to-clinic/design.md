# 设计

新增独立脚本 `src/backend/scripts/move_personal_files_to_clinic.py`；不改已有迁移引擎或已有维护脚本。参考 `move_clinic_knowhow_to_public.py` 的共享索引元数据写入、内容指纹校验及恢复机制，脚本可单文件部署。

## 处理过程

显式来源范围（2026-10-20）：`--source-space-id` 自动启用接口同步模式，允许当前租户有效已发布且非收藏的个人/科室/部门等知识库；不传时仍仅个人库。查询和按文件 ID 复核同时限制来源库，完整目录名称路径及后代仍由 `--folder-path` 筛选。`source_filter` 保存来源 ID、目录及 scope 的 level/owner_type/owner_id，随迁移单元写入恢复报告；创建目标目录前比较完整筛选快照，锁内再次验证并锁定来源 scope 行。恢复允许文件处于报告中的源或目标位置，仍检查原来源范围，不重新按组织选目标，也不能通过恢复参数改范围。完整版本链及接口标记检查复用原实现，已在路由目标库的文件直接跳过。

1. 使用严格租户上下文。分页查询个人库文件及目录，读取原始上传人/当前上传人的组织关联；目录由 ID 路径逐层还原并校验。
2. 生成逐文件路由，依次查原始上传人科室库、当前上传人科室库、原始上传人部门库、当前上传人部门库，全部失败保留首次错误码并记录不同失败原因。同人不重复匹配同类库；从唯一主组织向上取最近 office 或 dept，检测循环/缺失/停用节点。科室库为有效绑定且 scope 为 `team_ks` 或兼容 `team`、owner_type 为 `user`；部门库为有效绑定且 scope 为 `department`、owner_type 为 `department`、owner_id 等于绑定部门。每阶段按库 ID 升序选首个，不越过未绑定库的最近同类组织。预览及锁内复核批量加载两人的用户和主组织关联，复核匹配来源及目标，不改写已有上传人字段。部门路由新增 department_id、office_id 为空；锁内执行及恢复根据报告记录的路由类型校验目标范围和部门绑定，旧科室库报告仍只接受科室库类型；恢复不重新选目标。
3. 规范文档作为事务单元，版本链必须完整在扫描范围且目标及目录一致。重读并复核路由后创建目录。保留源空目录。
4. 文档行锁与文件锁内再次检查来源、目录、组织路由、版本、投影和审批。保存 before 后原地改归属；文件权限改为目标库所有者和目标目录/库父关系，其他发布/共享入口保留。
5. 更新共享索引 `knowledge_ids`，读回验证内容指纹和归属；数据库提交后刷新全文及推荐元数据。成功后记录统计。
6. 非原子外部写失败保留报告；`--recover-report` 根据数据库当前在源或目标修复对应索引和权限，不撤销已完成迁移。报告落盘失败立即停止。

## 风险和边界

相同内容覆盖（2026-10-14）：通过默认关闭的 `--overwrite-same-content` 仅放行同目录唯一、非空 MD5 相同的目标。源文件仍保留全部 ID 和内容；旧目标独立单版本文档或未解析原始文件被软删除并写现有回收快照，原对象和版本行保留，回收保留期沿用系统配置。目标有历史版本、共享/发布/前序引用、审批、任务租约、异常图谱或索引归属漂移时拒绝；同内容与不同内容冲突同时存在时，回收相同内容目标，源文件按原改名开关避让另一个不同内容目标。

回收和源归属修改共用事务。写前恢复单元持久化旧目标完整文件/文档身份和 ES/Milvus 原分块、向量、索引标识；只有写前落盘后才软删。旧目标最后一个入口退出后不能写空 knowledge_ids，改为按已读取 ES ID 和序列号/主分片条件清理、按 Milvus 已读取主键清理，随后确认两侧无旧投影；不删除源内容或调用解析/嵌入。提交前异常回滚两侧数据库状态，恢复只补回原缺失行及向量，不覆盖现存内容；ES 用 create 防止覆盖并发写入，Milvus 分批保留原字段且重新生成主键，稀疏向量键经 JSON 报告往返后转回整数。提交后恢复继续保持旧目标回收，补齐源元数据与旧目标全文/推荐清理。目标身份、回收快照或分块元数据外部变化均拒绝恢复。必要原分块仅出现在未完成单元的 0600 恢复报告中，主报告口径不变；成功后回收站恢复沿用系统原文件/版本及投影恢复流程。

同名不同内容改名（2026-10-14）：增加默认关闭的 `--rename-conflicts`，规划参数传入迁移单元；规范文档与无版本链文件复用锁内冲突查询，任何同 MD5 目标仍阻挡改名，缺少 MD5 不猜内容是否相同。主版本文件生成 `原名_迁移_文件ID.扩展名`，名称已占用时依次加 `_2` 等序号，最多尝试 100 个；限制总长为模型的 200 字符并保留扩展名。目标库/文档/文件保持已有锁及维护窗口要求，不覆盖目标、历史版本名称或其他共享入口名称，不使用普通改名服务以免增加内容代次及重建投影。写前将 `rename={file_id,old_name,new_name}` 连同完整 before 原状态落盘；同一事务改归属和主文件名。恢复先核对数据库源/目标位置对应的原名/新名，只对这一个已核对名称作指纹归一化，不全局忽略 file_name；旧报告仍核对原指纹。提交后全文刷新额外更新改名文件的 file_name，推荐刷新沿用数据库快照；正文、原对象及共享内容保持原值。预览仍只做路由/范围筛选，不承诺最终改名清单，即时冲突与名称在执行锁内确定。

静止的失败投影：增加默认关闭的 `--allow-failed-projection`。只有唯一管理入口且没有其他引用入口、主文件解析状态 2 且投影 failed 时，允许跳过 applied 代次未完成要求；仍验证 desired 内容代次、租户、版本、租约、解析状态、现有分块和权限。保留失败状态和 applied 进度，不重新解析。原成功文件校验与有其他发布/共享入口的图谱不放宽。恢复单元持久化该选项。

本次后台执行采用独立任务控制器和固定清单，不改变普通命令的筛选规则。清单仅含已核对的 1239 个文件，原 869 个暂缓项保持报告记录。控制器在租户写入未冻结、路由变化或目标目录未准备时拒绝 apply；全局文件锁防同容器重复执行，事件日志落盘失败停止后续项。完成后按数据库实际归属、目录、上传人核验清单，核验通过才恢复租户写入。Web 终端断开由 nohup/setsid 隔离；Pod 重建仍可能中断，需保留恢复记录。

接口同步模式的直接目录映射（2026-10-12 用户修正）：文件条目 `folder_parts` 继续保存完整来源目录，另存 `target_folder_parts` 为最后一个目录名（根文件为空列表）；目标目录检查及分组使用目标路径，源范围筛选和版本链一致性仍校验完整来源。不同来源祖先下的同名直接目录复用目标库根下同一目录，不覆盖重名文件。事务单元 `folder_parts` 保存实际目标，锁内分别校验文件在源库时的完整来源路径和已提交后在目标库的目标路径。恢复按已记录的单元目标处理，不因新映射改动旧报告的目标路径。普通模式保留完整层级。

接口同步筛选（2026-10-12）：复用当前独立脚本，通过默认关闭的 `--api-sync-only` 启用。元数据 `filelib_sync_endpoint` 或 `external_file_id` 非空即命中，与现有审计/科室技术诀窍维护脚本一致，不从文件名或 `file_source` 猜测。不命中文件在规划前排除；完整版本链若含其他来源，记录命中的接口文件，整链不迁移。初次规划及创建目标目录前复核都应用该过滤。迁移单元保存 `api_sync_only`，锁内路由校验在恢复分支返回前检查各文件来源；恢复无需依赖新命令的筛选开关。沿用已有原始上传人组织路由、目录、权限、解析状态及恢复，不使用按当前上传人复制/删除的旧脚本。

未激活管理入口的版本链（2026-10-12）：先验证唯一主版本及主版本文件，再区分有效管理入口和未建立入口两种情况。无管理入口时，用主版本文件校验文档位置；全部版本必须未解析成功、入口类型/状态为空且引用为空或当前文档，不允许链外入口。保留原文件与投影字段，不写 desired/applied 代次、不创建管理入口。ES/Milvus 首次读取必须均为空，迁移只改文档/文件位置及权限，提交前再次读回确认没有新增内容；无管理入口但已有共享内容时拒绝，避免在缺少有效成员关系时改写检索访问范围。复用完整版本锁、路由、审批、冲突、写前恢复报告和提交后刷新。恢复仍按内容/入口指纹及数据库实际位置进行，入口已激活或内容变化时拒绝覆盖。

未解析文件（2026-09-30）：移除成功状态作为候选前提，允许状态 3/5/6/7/NULL，1/4 暂缓并给出具体原因。锁内复核解析状态、所有版本/入口的投影执行状态及租约。成功主版本仍走原有严格投影/双侧分块检查；未成功主版本允许未成功入口处于 pending/failed/ready，保留 applied 代次及错误状态，只增加管理入口 desired 代次。已有分块仍校验规范标识、代次、有效向量及两侧共有分块文本一致性，允许两侧集合不同或为空；只对非空侧调用修复，随后两侧都读回，新增/丢失/变化的分块均视为失败。恢复按原内容指纹及数据库归属处理。

无版本链、无规范文档引用/入口的未解析物理文件独立成单元；负文件 ID 仅作报告内部的单元键，不写数据库文档 ID。锁内复核仍无版本链，复用目录、路由、目标库、所有者、审批检查。写前保存完整文件快照和原权限，更新归属和权限后提交，刷新目录元数据。不调用共享分块接口、不创建文档/版本/分块。失败恢复固定原文件内容/解析状态、权限所有者与数据库实际归属；拒绝覆盖外部变更。

`--use-operator-as-file-owner` 默认关闭，正式执行先验证 operator 为有效全局超级管理员。仅目标库所有者失效时采用该账号写入文件 owner 权限，不改 Knowledge.user_id 或文件 user_id/user_name。未完成单元持久化原库所有者 ID 与实际采用的操作人 ID；恢复使用记录的账号，不随本次操作人或开关变化。原库所有者 ID 已变化、接管账号失效时拒绝恢复，其他版本/租户/内容/审批校验保持不变。

报告精简：主 JSON 为文件列表，仅包含文件 ID、文件名、来源库 ID、原目录和未迁移原因。失败、中断未处理、恢复回源的文件列出，成功文件排除；预览不把候选文件记成失败。`recovery/` 子目录只保存尚未完成且已产生 before 状态的迁移单元及必要上下文，不保存成功单元、全量计划或堆栈。先保存恢复状态再保存主报告，任一写入失败停止执行；兼容读取原格式恢复报告。

真实 apply 需要停止相关写入的维护窗口；数据库、ES、Milvus、OpenFGA 无分布式事务。默认不覆盖历史索引漂移，显式 `--force-rewrite` 才按数据库重写。目标重名/同内容默认跳过；改名开关只放行已核对的同名不同内容，不删除数据。新增目录失败可能留空目录，需要人工核对。
