**关联 PRD / 增量需求**：[需求发现与用户确认](./discovery.md) §1、§3；[应用工场 PRD-1](../../../docs/PRD/3.0-release/3.0%20应用工场%20PRD-1%20专业开发者通道与应用运行时.md) DEV-04、RT-03、RT-05；本次发布文案为用户新增需求，不宣称上游 PRD 已有完整定义。

**优先级**：P1
**所属版本**：v3.0.0，发版线 `feat/3.0.0`
**依赖**：F053 CLI 提交与安装件分发、F055 发布管线及审批场景、F054 正式版本与版本记录；既有审批详情及版本记录访问权限。

**范围边界**：

- **本次纳入**：开发者通过 CLI 为首次或迭代发布填写说明；说明与该次发布绑定；审批详情和应用版本记录展示同一份说明；历史数据、旧 CLI 和无说明提交兼容。
- **本次排除**：界面上传或编辑发布说明、提交后补写与修改历史说明、Markdown/HTML 富文本、自动生成更新内容、公开发布日志、消息推送、广场更新提醒、运行应用内弹窗及回滚入口。这些不是本次确认的提交和审读场景。
- 发布说明说明“本次改了什么”，不代替应用介绍、审批意见、驳回理由或结构变更提示。

## 1. 用户故事

- 作为应用开发者，我希望在提交应用时写明新增功能、改进和修复，以便审批人了解本次发布目的。
- 作为审批人，我希望在本次审批详情中阅读提交时的说明，以便结合代码和声明作出决定。
- 作为有权查看应用版本记录的用户，我希望查看每个正式版本自己的说明，以便追溯版本变化。

## 2. 验收标准

### 2.1 CLI 提交与内容校验

- **AC-01** — WHEN 开发者提交首次或迭代发布，THE SYSTEM SHALL 允许为本次发布提供一份可选的发布说明；不提供说明时继续采用原发布流程，不弹出新的必答交互。
- **AC-02** — WHEN 开发者提供发布说明，THE SYSTEM SHALL 支持直接填写文本或读取本地 UTF-8 文本文件；IF 两种来源同时指定，THEN THE SYSTEM SHALL 拒绝命令并提示二者只能选一种，且不上传应用包。
- **AC-03** — WHEN 接收发布说明，THE SYSTEM SHALL 将 CRLF 和 CR 换行为 LF、去掉首尾空白并保留正文内部换行与缩进；处理后为空的说明按未填写处理。CLI 预校验与平台校验须得到相同结果。
- **AC-04** — IF 处理后的说明超过 2,000 个 Unicode 码点，THEN THE SYSTEM SHALL 拒绝本次输入并明确提示上限，不能截断后提交；2,000 个码点须被接受，2,001 个须被拒绝。
- **AC-05** — IF 说明文件不存在、不是普通文件、不可读或不能解码为 UTF-8，THEN THE SYSTEM SHALL 提示说明文件错误，且不上传应用包。
- **AC-06** — WHEN 开发者执行仅检查而不上传的发布命令，THE SYSTEM SHALL 同样校验说明；校验失败须返回失败结果，且不创建发布、版本或审批记录。
- **AC-07** — IF 调用者绕过 CLI 直接提交不合要求的发布说明，THEN THE SYSTEM SHALL 在进入构建和审批前拒绝，不产生该次正式版本或审批记录；不能仅依赖 CLI 校验。

### 2.2 绑定、冻结与失败行为

- **AC-08** — WHEN 平台成功接收一份带说明的发布提交，THE SYSTEM SHALL 将说明绑定到该次发布；后续异步处理、任务重试及服务重启后继续处理时，仍使用这份说明。
- **AC-09** — WHEN 发布产生正式版本，THE SYSTEM SHALL 为该版本保留提交时的说明；后续发布的说明、应用介绍变更或说明源文件变更不得覆盖先前版本的说明。提交后不提供修改该次说明的入口。
- **AC-10** — WHEN 发布被驳回、撤回或审批通过但等待上线，THE SYSTEM SHALL 在已有正式版本记录和可访问审批详情中保留原说明；对同一已审批版本的上线重试不得改写说明。
- **AC-11** — IF 发布在正式版本产生前失败，THEN THE SYSTEM SHALL 保持原有“不进入正式版本列表”的行为；不得为展示发布说明单独创建一个正式版本。

### 2.3 审批与版本记录展示

- **AC-12** — WHEN 有权访问应用发布审批详情的用户查看该次申请，THE SYSTEM SHALL 在标明“发布说明”的独立区域展示本次提交的全文；申请人和审批人查看同一申请时内容一致，不把它混入审批意见或结构变更。
- **AC-13** — WHEN 有权查看应用版本记录的用户查看版本历史，THE SYSTEM SHALL 能查看每个版本对应的发布说明全文，并保持其与版本号、提交时间和审批/上线结果的对应关系；分页和刷新不得串到其他版本。
- **AC-14** — WHEN 发布没有填写说明或查看升级前的历史记录，THE SYSTEM SHALL 显示“未填写发布说明”，不得借用应用介绍或其他版本的说明，也不补造历史内容。
- **AC-15** — WHEN 展示发布说明，THE SYSTEM SHALL 将其作为纯文本保留正文换行并允许长行换行；HTML、脚本和 Markdown 标记不得执行或被解释成富文本；窄屏下全文可读且不挤出操作区。新增标题、空态和校验提示须支持中文、英文和日文。

### 2.4 权限、兼容与交付

- **AC-16** — WHEN 提交或读取发布说明，THE SYSTEM SHALL 继续执行所在发布、审批或版本记录的既有权限与租户约束；无权提交、无权查看详情、非授权应用访问和跨租户访问不得因说明功能取得额外权限或说明内容。
- **AC-17** — WHEN 旧 CLI 或既有调用不提供发布说明，THE SYSTEM SHALL 允许其继续发布；升级前的正式版本和审批记录仍可读取，不要求补填说明。
- **AC-18** — IF 新 CLI 带发布说明连接尚不支持说明的平台，THEN THE SYSTEM SHALL 在上传应用包前明确提示平台不支持本功能，不能静默丢弃说明后报告提交成功；不带说明时保持既有兼容行为。
- **AC-19** — WHEN 平台选择 Docker 或 K8s 托管模式，以及选择当前已支持的应用交付类型，THE SYSTEM SHALL 提供一致的提交、保存和展示行为；发布说明不改变构建、审批决策、资源档位、运行启动及应用环境变量语义。
- **AC-20** — WHEN 用户从更新后的平台下载并安装所分发的 CLI，THE SYSTEM SHALL 提供本规格定义的说明输入和校验能力；不能仅在开发源码运行时可用。

## 3. 边界情况

- 只含空格或换行的说明与未填写等价；正文可以包含中英文、emoji、换行和代码样式文本，均受相同长度和纯文本展示约束（AC-03、AC-04、AC-15）。
- 同一次发布的自动重试和同一已审批版本的手动上线继续使用原说明；另一次获准提交的新版本可以有新的说明（AC-08、AC-09、AC-10）。
- 预检失败不改变原正式版本列表；审批被驳回并不删除已经形成的版本说明（AC-10、AC-11）。
- 历史记录缺少说明时显示空态，不回写推测的发布内容（AC-14、AC-17）。
- 本次不新增发布说明专属的匿名读取入口；查看应用页面不自动获得审批详情或版本记录权限（AC-16）。
- 新 CLI 与旧平台的能力不匹配时须在上传前明确报错；新平台须兼容不带说明的旧 CLI（AC-17、AC-18）。
