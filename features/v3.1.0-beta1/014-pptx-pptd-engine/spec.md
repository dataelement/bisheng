# Feature: 深度研究 PPT 制作改用 PPTD 页面设计引擎

> 本文档只写做什么、验收标准、不做什么。实现方案见 [design.md](./design.md)，执行流水见 [tasks.md](./tasks.md)。

**关联材料**：2026-11-11 三方对比与 114 验证（会话记录；材料在 114 `/opt/taskmode-eval/pptcmp/`）。法务已确认引入 dsh-desktop PPT 引擎无合规风险（用户告知）。
**优先级**：P1
**所属版本**：v3.1.0-beta1
**依赖**：发版线既有代码执行器与本地隔离、内置技能种子（按内容哈希更新内置技能）、技能全挂载与勾选标注；F006 html-report（主题配色校验引用 bisheng-pptx 的模板目录，需要随本特性调整）。

> **范围边界**
> - **本次纳入**：
>   - 后端镜像与沙箱镜像（`bisheng-sandbox`，代码执行器 container 模式使用）都内置 PPTD 引擎（dsh-desktop `packages/ppt-runtime/core` 的 CLI 与公开 npm 依赖、Node 运行时），amd64 与 arm64 都可用。
>   - 原地替换内置技能 `bisheng-pptx` 的内容：技能名和显示名「PPT 制作」不变，正文、脚本、模板整体换成 PPTD 版本（逐页设计版面，经引擎检查后导出可编辑 .pptx）；包含 16 套参考模板和 1 套新做的政企红色模板。
>   - 用 PPTD 转换能力改写已有 .pptx、参照用户上传的 .pptx 模板制作。
>   - 源码部署（非镜像）环境的引擎安装脚本。
> - **本次明确排除**：
>   - 新增技能或退役机制。原因：同名替换后种子程序在升级时自动覆盖内容，只存在一个 PPT 技能。
>   - 桌面端的 PPT 模式界面、个人模板库、图片槽位生成。原因：深度研究只需要引擎和技能，界面另议。
>   - 看图质检（渲染截图给模型看）。原因：验证中 PPTD 的几何检查已经足够；截图会显著增加耗时。
>   - 保留用户模板的母版与版式结构。转换后的页面是平铺元素，导出的 .pptx 不再带原母版（见 §3）。
>   - 替换租户自己修改过的 bisheng-pptx（来源已变为自定义）。种子程序本来就不覆盖这类技能。
>   - 技能「默认勾选」。2026-11-11 已拍板不恢复；新版本 SKILL.md 不加 `default-checked`，已部署环境中该列的值由管理员掌握，升级不改。

## 1. 用户故事

作为**深度研究的使用者**，我希望让系统做 PPT 时，得到版式多样、信息密度够、在 Windows 投影上字号可读的可编辑 .pptx，并在 10 分钟内拿到，以便直接拿去汇报或稍作修改。

作为**央国企客户的使用者**，我希望党委会、年度总结这类材料使用庄重的红色政企版式，以便材料符合内部汇报习惯。

作为**平台运维与租户管理员**，我希望升级镜像后「PPT 制作」技能自动换成新版本，原有的启用状态和权限设置保持不变，不需要手工改库或重新配置，以便升级只是一次常规发布。

## 2. 验收标准

### 2.1 引擎运行环境

- **AC-01** — THE SYSTEM SHALL 在后端镜像和沙箱镜像中提供 PPTD 引擎，使代码执行器在 local 与 container 两种模式下都能完成 `check` 与 `render`；amd64 与 arm64 两种架构都可用；导出的 .pptx 只含原生对象（文本、形状、图表、表格），没有整页图片。
- **AC-02** — WHEN 代码执行器以本地隔离方式运行技能脚本（非特权 uid、2GB 地址空间上限、受限环境变量），THE SYSTEM SHALL 能完成一个 12 页工程的检查和导出，且各自耗时不超过 10 秒。
- **AC-03** — THE SYSTEM SHALL 在运行时不访问网络、不在任务中安装任何依赖；引擎及其依赖的版本在仓库中固定，随仓库附带上游许可证与第三方声明。
- **AC-04** — WHERE 部署环境不是官方镜像（源码部署），THE SYSTEM SHALL 提供一个安装脚本，在该机器上装好与镜像相同版本的引擎；IF 引擎没有安装, THEN 技能 SHALL 告诉用户「当前环境未安装 PPT 引擎，请联系管理员」并停止，不改用其他方式生成 PPT。

### 2.2 制作流程

- **AC-05** — WHEN 用户要求制作 PPT、幻灯片、汇报材料或课件（.pptx），THE SYSTEM SHALL 触发「PPT 制作」技能（`bisheng-pptx`）；WHEN 用户要的是网页幻灯片，THE SYSTEM SHALL 交给 html-report。两个技能的触发描述互相写明这条分界。
- **AC-06** — WHEN 开始制作，THE SYSTEM SHALL 引导模型先写逐页大纲（每页一句结论式标题和主图形式），再从模板目录选一套模板，读该模板的设计说明和 3–6 个参考页，然后写 PPTD 工程。
- **AC-07** — WHEN 工程写完，THE SYSTEM SHALL 引导模型执行「检查 → 一次改完全部问题 → 再检查」，最多 4 轮；只有检查结论为「通过」才导出；第 4 轮后仍有 error 时拆页或删减内容，不跳过检查。
- **AC-08** — WHEN 导出完成，THE SYSTEM SHALL 在 `output/` 只放最终 .pptx，并如实告诉用户文件名、页数、所用模板，以及「只做了引擎检查，没有在 PowerPoint/WPS 中打开验证」。

### 2.3 可读性与字体

- **AC-09** — THE SYSTEM SHALL 拒绝导出存在以下字号的工程，并在检查结果中列出页码与元素：超过 24 字的正文或表格正文小于 11pt，短标签、注释、来源、页脚小于 9pt。页标题不小于 24pt 作为技能规则写入，不作为阻断项。
- **AC-10** — THE SYSTEM SHALL 使导出的 .pptx 中文字体为 Microsoft YaHei、西文字体为 Arial，不残留 PingFang SC、Noto Sans CJK SC 等 Windows 上缺失的字体名。
- **AC-11** — WHEN 用 4 道对比题（2026-11-11 题集）各运行一次，THE SYSTEM SHALL 使每份 .pptx 中按字数加权的字号中位数不小于 11pt，小于 10pt 的文字占比不超过 25%。

### 2.4 模板

- **AC-12** — THE SYSTEM SHALL 提供 17 套参考模板：16 套来自桌面端，1 套新做的政企红色模板。模板目录写明每套的风格和适用场景，政企汇报、年度总结、党委会材料首选政企红色模板。
- **AC-13** — THE SYSTEM SHALL 使模板 ID、模板说明、技能正文与脚本输出中不出现产品品牌名（如 DSH、BiSheng），以满足贴牌部署要求；技能名 `bisheng-pptx` 与技能包内路径属于既有技术标识，保持不变。
- **AC-14** — WHEN 用 2026-11-11 题集的 P1（央国企年度总结、党委会场景）运行，THE SYSTEM SHALL 选用政企红色模板，主色为深红，并通过检查后导出。

### 2.5 已有 PPT 与用户模板

- **AC-15** — WHEN 用户上传 .pptx 并要求改写、续写或翻新，THE SYSTEM SHALL 先把它转换成 PPTD 工程，在工程上修改后检查并导出新文件；转换中被简化的效果（阴影、发光、三维）在交付说明里如实列出。
- **AC-16** — WHEN 用户上传 .pptx 模板并要求「按这个模板做」，THE SYSTEM SHALL 转换该模板，沿用它的配色、字体、网格和装饰元素制作新页面，并在交付说明中写明导出文件不带原母版。

### 2.6 升级替换

- **AC-17** — WHEN 已部署环境升级到本版本，THE SYSTEM SHALL 在每个租户中把来源仍为内置的 `bisheng-pptx` 内容替换为新版本，并保留该技能的启用状态、默认勾选设置和权限授予。
- **AC-18** — IF 租户修改过 `bisheng-pptx`（来源已变为自定义）, THEN THE SYSTEM SHALL 保留租户的版本不变。
- **AC-19** — WHEN 升级后发起新的深度研究任务，THE SYSTEM SHALL 只挂载一个制作 .pptx 的技能；升级前已开始的任务和已交付的文件不受影响。
- **AC-20** — THE SYSTEM SHALL 使 html-report 的主题配色校验对照新的模板目录，两个技能的政企红色主题配色保持一致。

### 2.7 效果

- **AC-21** — WHEN 用 2026-11-11 题集 4 道题在 x86 测试环境各运行一次（同一模型 DeepSeek-V4.1-Flash），THE SYSTEM SHALL 使每题墙钟时间不超过 10 分钟，并输出三方对比报告（bisheng-pptx 基线、桌面端、本特性），注明样本量。
- **AC-22** — WHEN 在 arm64 环境运行 1 道题，THE SYSTEM SHALL 完成导出，用来证明 arm64 引擎可用。

## 3. 边界情况

- 模型写出 YAML 语法错误的页面时，检查结果应指出文件名和行号，模型按提示修改；技能不提供 python-pptx 兜底。
- 用户模板转换后得到的是平铺元素：导出文件不再有母版和版式，用户在 PowerPoint 中「新建幻灯片」时拿不到原版式。这是本期接受的限制。
- 单份 PPT 超过 40 页时，检查和导出的耗时按页数线性增长；技能建议超过 30 页时分章节分批检查。
- 源码部署环境升级后若没有安装引擎，「PPT 制作」技能按 AC-04 提示后停止；这期间该环境不能制作 .pptx。
- 同一会话多次导出时，`output/` 中以最终文件为准，模型不重复导出同名文件。
- 引擎检查只看几何（溢出、遮挡、越界、重复版式），不看配色是否得体、图表数据是否正确；这类问题仍靠技能规则约束模型。
