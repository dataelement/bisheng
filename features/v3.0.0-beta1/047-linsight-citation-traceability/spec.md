# Feature: 灵思任务模式引用溯源（角标溯源）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
> spec 只回答 **做什么 / 验收标准 / 不做什么**；所有 How 在 [design.md](./design.md)。

**关联 PRD**: [`docs/PRD/2.6 灵思 deepagents 迁移 PRD/灵思 Linsight 迁移 deepagents 框架 PRD.md` §4.3.3「引用溯源」(L692) · FR-2.13 (L571)]
**优先级**: P2
**所属版本**: v3.0.0-beta1（原登记为 v2.6.0 F040；v2.6.0 该编号已被 F040-rebac-read-path-perf-rollout 占用，随版本线一并改编为 **F047**）
**依赖**: F035（灵思任务模式，deepagents 内核）· F029（知识库检索权限过滤 / INV-7）—— 两者均为 v2.6.0 存量 Feature，已上线；现有 citation 子系统（`bisheng/citation/`，日常模式已在用）

> **范围边界**
> - **本次纳入（Phase 1）**：
>   - 任务模式报告（Markdown 产物）在**应用内预览**时，正文内联**可点击角标溯源**——覆盖知识库检索（KB 文档）与联网检索（Web 网页）两类来源。
>   - 角标悬浮预览卡（标题 / 摘要 / 来源名）。
>   - 点击 KB 角标 → 预览原文件，PDF 按 bbox 高亮定位到被引 chunk；点击 Web 角标 → 新标签打开原网页。
>   - 角标解析（`/api/v1/citations/resolve`）复用 F029 的 `view_file` 权限过滤（满足 INV-7）。
>   - 任务完成时，仅持久化**报告中实际被引用**的来源到 `message_citation`（以任务轮 `ChatMessage.id` 为 `message_id`）。
> - **本次明确排除**：
>   - **Phase 2**（延后，本 spec 只登记不验收）：下载的 **Word/PDF** 文件内把隐藏溯源标记烘焙成可见 `[1]` 编号 + 文末「参考资料」列表。原因：内联溯源标记在 Office 文档中不可见/乱码，需独立的导出预处理，且下载件内 KB 文件只能显示名称+页码（无法点击预览）。
>   - **用户上传附件的溯源**（PRD FR-2.13 提及「附件」）：本期只覆盖**检索类来源**（知识库 / 联网）。上传附件在灵思中经 `read_file` 按需翻阅、不走检索工具，需另一套「读文件即登记来源」机制，复杂度更高，**延后**（记为候选 Phase 1.5）。
>   - **独立「参考资料」汇总列表面板**（日常模式右侧那种）。用户选择先只做行内角标；后续可复用日常模式的汇总面板组件。
>   - **引用修复 / 二次校验 pass**：模型漏发标记时**优雅降级**（少若干角标），不做补救性重跑。
>   - **改动灵思底层检索的文件级可见性**：检索级 `view_file` 归属 F029 / F035；本 feature 只在**角标呈现面**复用其过滤，不新引入越权，也不负责收敛既有检索级缺口。
>   - **日常对话模式的任何改动**：本 feature 只接线任务模式进既有 citation 子系统。

## 1. 用户故事

作为 **使用灵思任务模式的业务用户**，
我希望 **在任务产出的报告里，看到引用内容旁的可点击角标，并能一键回看到原始知识库文件（定位到具体页/段）或原始网页**，
以便 **核实结论出处、建立对长报告的信任，而不必人工翻找来源**。

作为 **对数据可见性敏感的管理员 / 合规角色**，
我希望 **报告里的溯源角标严格遵守知识库文件的查看权限**，
以便 **无权查看某文件的用户，既看不到该文件的角标来源信息，也无法借角标越权预览该文件**。

## 2. 验收标准

> AC-ID 在本特性内唯一。错误码/字段等实现细节见 design.md。P2 但跨模块，采用 EARS 句型。

### 2.1 来源捕获（检索侧）

- **AC-01** — WHERE 任务开启了知识库检索, WHEN 知识库检索返回结果, THE SYSTEM SHALL 为每个命中片段登记一条带**稳定来源标识**的溯源来源，携带足以定位与展示的信息（文档名、知识库名、页码、页内定位坐标），并使模型在读到该结果时能获得对应来源标识。
- **AC-02** — WHERE 任务开启了联网检索, WHEN 联网检索返回结果, THE SYSTEM SHALL 为每条网页结果登记一条带稳定来源标识的溯源来源（携带 URL、标题、摘要、站点）。
- **AC-03** — WHEN 模型撰写报告并使用了某条已登记来源的内容, THE SYSTEM SHALL 使报告正文在对应句/段位置内联携带该来源的溯源标记；未使用任何已登记来源时不产生标记。
- **AC-04** — WHEN 检索发生在子任务（researcher 子代理）而报告由主流程撰写, THE SYSTEM SHALL 使来源标记可越过子任务边界传递到最终报告正文。

### 2.2 持久化与解析（服务侧）

- **AC-05** — WHEN 任务完成, THE SYSTEM SHALL 解析主产物报告中**实际引用**到的来源，仅将被引用的来源持久化并绑定到该任务轮的结果消息（供后续预览解析与权限过滤）。
- **AC-06** — WHEN 同一份报告被重复完成处理（resume / 续轮）, THE SYSTEM SHALL 保持幂等，不产生重复的溯源来源记录。
- **AC-07** — WHERE 查看者对某知识库文件无 `view_file` 权限, WHEN 解析该报告角标, THE SYSTEM SHALL NOT 在角标溯源接口（`/api/v1/citations/resolve`）响应的任何结构化字段中返回该文件的来源信息（复用 F029 过滤，满足 INV-7）。

### 2.3 前端呈现（预览侧）

- **AC-08** — WHEN 用户在应用内预览任务报告, THE SYSTEM SHALL 把正文内联溯源标记渲染为**顺序编号（[1][2]…）的上标角标**。
- **AC-09** — WHEN 用户悬浮某角标, THE SYSTEM SHALL 展示该来源的标题 / 摘要 / 来源名（知识库来源显示文档名+页码，网页来源显示站点+日期）。
- **AC-10** — WHEN 用户点击知识库角标, THE SYSTEM SHALL 打开该原文件预览；WHERE 文件为 PDF, THE SYSTEM SHALL 高亮并滚动定位到被引片段。
- **AC-11** — WHEN 用户点击网页角标, THE SYSTEM SHALL 在新标签打开原网页 URL。
- **AC-12** — WHERE 查看者对某知识库角标对应文件无权限（AC-07 过滤后无法解析）, THE SYSTEM SHALL 将该角标呈现为「无权限」态而非报错。

### 2.4 健壮性与非侵入

- **AC-13** — IF 来源登记 / 注解过程发生任何异常, THEN THE SYSTEM SHALL 回退到不带溯源的检索结果并继续任务（溯源失败**绝不**使工具报错或任务中断）。
- **AC-14** — IF 模型在长报告中漏发部分标记, THEN THE SYSTEM SHALL 优雅降级（对应来源不出现角标），不得产生悬空 / 损坏的角标或解析报错。
- **AC-15** — THE SYSTEM SHALL 以**非侵入**方式接入：保持既有任务执行流的对外事件协议与执行记录结构不变（不新增流式事件类型、不改执行步骤持久化结构；具体约束见 design §2）。

## 3. 边界情况

- **检索命中但模型未引用任一来源** → 报告无角标，不持久化任何来源（正常，非缺陷）。
- **同一句多来源** → 前端渲染为相邻的多个角标。
- **子代理检索、主流程撰写** → 标记须随子任务结果回传；若主流程转述丢失，按 AC-14 优雅降级。
- **老报告预览时来源运行时缓存已过期** → 角标解析回退到完成时持久化的记录（AC-05）。
- **某些知识库检索返回缺少知识库标识** → 登记前补齐（实现坑见 design §5）。
- **报告产物不是可渲染文本 / 无主产物** → 无可解析标记，跳过持久化，不影响任务完成。
