# F084 问答失败分类与恢复提示

状态：需求镜像草稿；设计待确认；未进入开发。

需求来源：[飞书需求第4项](https://dataelem.feishu.cn/wiki/YQWdw2BIbiBufYk19ZAcTCsGnWb#doxcnXFEPVihshP7XFzMF05i9Jb)，读取版本344，2026-11-05；本期范围以用户随后明确的“日常和任务模式”为准。本文将其整理为本地验收依据，不将设计草案视为已批准。

## 1. 目标与范围

问答失败时，让用户识别实际失败服务、知道下一步如何处理，并能提供定位信息。

本期仅覆盖工作台的日常模式和任务模式，包括两种模式执行中的检索、附件解析、工具调用、任务提交、实时反馈、重连和历史记录。服务源头、包装、队列和保存过程中保持同一失败来源。

已有权限、额度、文件校验、用户停止、正常无结果和正在恢复等结果保留各自语义。独立助手页、知识问答页、工作流、后台管理和platform调试入口不在本期范围；仅两种模式执行时实际使用的依赖纳入来源判断。全局HTTP错误拦截和登录流程不变。

## 2. 五类固定主提示

| 分类 | 固定主提示 |
|---|---|
| 数据库 | 【数据库】数据服务访问异常，请联系对应的数据服务维护人员排查。 |
| 网络 | 【网络】网络连接异常，请检查网络连接；持续异常时，请联系网络维护人员排查。 |
| 模型服务 | 【模型服务】模型调用异常，请联系模型服务维护人员排查。 |
| 单点登录 | 【单点登录】登录认证异常，请重新登录；持续异常时，请联系单点登录维护人员排查。 |
| 对象存储 | 【对象存储】文件存储服务访问异常，请联系对象存储维护人员排查。 |

## 3. 验收标准

| 编号 | 条件与预期结果 |
|---|---|
| AC-01 | 当实际服务对象已确认时，每次失败显示一个主分类及上表原文；具体组件、模型展示名、时间和已有定位信息紧邻展示。 |
| AC-02 | 当模型连接、认证、超时、限流、余额或供应方内部组件报错时，归模型服务；业务数据库、Redis、ES、Milvus故障归数据库；MinIO故障归对象存储。 |
| AC-03 | 仅当证据确认设备、入口或传输链路失败时归网络；企业单点登录及其会话认证失败归单点登录。模型凭据和开放API凭据不因此归单点登录。 |
| AC-04 | 当发生输入、权限、平台配额、许可证、资源缺失等明确业务结果时，保留原业务提示；原因不足或平台自身逻辑错误使用通用失败反馈，不猜测五类。 |
| AC-05 | 当两种模式内的错误经过工具、任务、队列和响应包装时，保留实际失败来源；相同数值错误码不得作为唯一归类依据。 |
| AC-06 | 同一失败的实时、重连和刷新历史展示保持分类、服务和发生时间一致；旧记录只有可靠来源时才映射，其他保留通用反馈。 |
| AC-07 | 当已有部分答案、成功资料或成功文件时保留；检索无命中、部分依赖失败、工具软失败和整轮失败分别表达，继续执行策略不变。 |
| AC-08 | 现有模型重试、降级、恢复和停止逻辑不变；连接中断先确认已有任务结果，不自动重提任务。登录恢复使用现有入口。 |
| AC-09 | 日常SSE、任务提交SSE、任务执行WebSocket及历史读取保持现有协议兼容；生成失败在对应回答或步骤显示。本期不修改全局HTTP错误拦截。 |
| AC-10 | 主提示和辅助信息不显示凭据、内部地址、SQL、堆栈或无权查看的名称；原始原因进入受控日志。各语言文案同步交付。 |
| AC-11 | 代码定义盘点、来源映射、传播接线和真实环境验证分别记录；不能用错误定义数量代表运行覆盖。 |
