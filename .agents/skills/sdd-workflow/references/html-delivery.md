# HTML 文档交付约定

## 适用产物

| 文档 | 默认文件名 | 内容规则 |
|---|---|---|
| 需求／PRD | requirements.html | 使用[PRD 写作与完成标准](../../sdd-requirement-validation/references/prd-writing-standard.md) |
| 技术设计 | design.html | 使用[设计文档写作与完成标准](../../sdd-design/references/design-writing-standard.md) 与[HTML 模板](../../sdd-design/assets/design-template.html)，分层解释方案并保留精确契约、追溯和验证安排 |
| 测试用例 | test-cases.html | 使用[测试用例写作与完成标准](../../sdd-test-cases/references/case-writing-standard.md)，包含覆盖矩阵、九列用例表、异常边界清单及自动化标注；不同岗位的用例按实际工程分开存放 |

正式交付必须为实际可打开的 HTML 文件，不能只在对话贴 HTML 代码，也不能把 Markdown 改扩展名或原样放进 pre 元素交差。原始输入仍可为对话、Markdown、Word、PDF 等。需求评审草稿进入正式确认时也使用 HTML；未解决事项清晰标注，不能因页面完整就称已闭环。

实际位置由[产物存放与维护约定](artifact-storage.md) 统一解析。表中名称是默认名称，用户指定、项目既有约定及有效登记确定本次位置；各阶段引用同一来源，不因目录分类复制一份正文。研发用例与独立验收用例分别归各自工程。

计划、状态、提测索引和执行报告目前没有统一改为 HTML 的要求。测试代码仍使用项目实际语言／框架；机器可读的用例或运行结果可以作为配套文件，但不能替代 HTML 用例交付。简单 Bug 不因此增加全套文档。

## 结构与可用性

- 默认提供可单独打开的 UTF-8 HTML，含文档标题、版本／日期、当前状态和目录锚点；样式内嵌，表格可横向滚动，支持打印。已有视觉规范时在满足本约定前提下复用，不自动调用其他文档 skills。
- 规则、字段和映射使用语义化表格；各类图解用可直接显示的内联 SVG 或 HTML/CSS，附标题、必要图例与文字解读。默认不依赖 CDN、在线字体或打开后才下载的图表库；仅有 Mermaid 源码并不算已交付可见图形。
- 相关术语与技术映射关联同一来源、修订和确认状态；正文、图示及表格共同核对，摘录不独立定义另一套规则。
- 保留稳定的需求、验收条件、设计决策和用例标识，推荐作为 HTML id；名称和编号调整后核对站内与跨文档链接。共享需求规则通过来源版本和标识关联，不复制成另一套可独立修改的业务定义。
- 文档记录来源、适用范围和确认状态；用户决定、事实、建议和未知明确区分。待确认、已确认、用例定义就绪和测试执行通过各自记录，不用颜色或一句“完成”混淆。
- 需求定稿、设计和用例分别维护一个有效来源。已有非 HTML 正式稿转为 HTML 时保留来源／版本关系，旧稿标为被替代或指向当前稿；纯格式转换不凭空使原确认或有效测试失效。内容改变时按影响范围重新确认及更新下游。

## 交付前检查

检查 HTML 可解析、中文编码正确、目录／表格／流程图具备实际内容、标识无冲突、链接能定位目标，长文本和宽表可阅读。使用当前获准工具核对，不为文档检查启动业务系统、执行产品 UI 或真实 E2E 测试。
内容自检以各专业 skill 为准；结构检查或页面可打开不能证明业务需求闭环、设计已获确认或测试已执行。交付实际文件位置与真实状态；跨岗位使用可访问的版本化来源。
