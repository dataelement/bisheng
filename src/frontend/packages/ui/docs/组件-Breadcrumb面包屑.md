> 与 [00-总纲.md](00-总纲.md)、[基础-多端适配原则.md](基础-多端适配原则.md)、[基础-圆角与阴影规范.mdx](基础-圆角与阴影规范.mdx) 配套。

## 1. 什么时候用

- 页面处在**两级以上**的层级结构里、且用户需要往上跳时，才放面包屑（知识空间的多级文件夹、应用分组等）。
- **只有一级时不显示面包屑，页面整体上移**——空面包屑占着一行却不给任何信息。
- 面包屑是**辅助导航**，不替代侧栏和顶栏；它也不是浏览历史，只回答「我在结构的哪一层」。
- 表达「第几步」用步骤条，不用面包屑——两者长得像，含义完全不同。

---

## 2. 组成与层级

从左到右按 根级 → 中间各级 → 当前页 排列，分隔符统一用**右向箭头图标**（不是文本 `>`，理由见 §3）。

| 位置 | 可点击 | 说明 |
|---|---|---|
| 根级（第 1 项） | ✅ | 知识空间名等结构入口，**永不折叠** |
| 中间各级 | ✅ | 层级多时按 §5 折叠 |
| 当前页（最后 1 项） | ❌ 不可点、无 hover | 已经在这一页，点击没有去处 |

- 不设「首页」项，根级直接从知识空间这类结构入口起——回首页的职能由侧栏承担。
- 每一项都要对应一个**真实能打开的页面**；只是个分类名、点进去没有页面的层级不进面包屑。
- 一个页面有多个上级时只展示**一条主路径**，不做分叉——两条路径会让用户怀疑自己走错了地方。

---

## 3. 尺寸与状态

| 项 | 值 |
|---|---|
| 字号 / 行高 | 12/24（`text-caption` 字号，行高 24px） |
| 字重 | 400，父级与当前页一致 |
| 项与分隔符的间距 | 左右各 2px |
| 分隔符 | bisheng-icons 右向箭头，**16px**，色 `#c9cdd4`（`text-disabled`），不参与 hover、不可点 |

**分隔符用图标，不用文本 `>`。** `>` 是数学符号：它按西文基线对齐，跟中文字排一起会偏低、大小也压不住，换个字体形状粗细就变了。图标的线宽和圆头圆角跟全站一套（见 [基础-图标规范.mdx](基础-图标规范.mdx)），尺寸和颜色走 token，读屏器也天然读不到它。

| 状态 | 父级 | 当前页 |
|---|---|---|
| 常态 | `#86909c`（`text-hint`） | `#1d2129`（深一档，标明「你在这」） |
| hover | 文字转品牌色 | 无 hover |
| focus | `focus-visible` 才出外环 | 不可聚焦 |

## 4. 名称长度与省略

- 父级名称**最大宽度 96px**，超出截断为「前面若干字 + …」，hover 出 Tooltip 显示完整名称。96px 在 12px 字号下约合 8 个中文字、16 个英文字符——**按宽度卡而不是按字数卡**，中文、英文、中英混排都不用换算。
- **当前页名称不受 96px 限制**，只受页面宽度限制；超宽同样截断 + Tooltip。
- 面包屑**任何情况下不换行**。换行会把分隔符断在行尾，顺序就读不出来了，还会把页面标题往下顶。

## 5. 层级过多时的折叠

### 5.1 折叠规则

- 层级**超过 4 级**时折叠：保留**根级 + 末两级**（末位就是当前页），中间各级收进 `…`。
- `…` 固定在**第 2 个位置**（紧跟根级）。位置固定，用户不必每次去找它在哪。
- 折叠后可见项恒为 4 个：`根级 · … · 上一级 · 当前页`。页面再窄也不改这个结构，只按 §6 换阈值。
- 4 级及以内全部展开。

### 5.2 触发器 `…` 的样子

`…` 是按钮，不是一段被省略的文字；但容器**不常驻**，hover 才出现（设计师 2026-08-05 拍板：常驻底色破坏面包屑行的轻量感）。Carbon / Fluent 的触发器也是这个做法：静态裸 `…`，hover 出容器。

- 常态：裸 `…`，无底色；`cursor: pointer`。
- hover：出 24×24、圆角 4px、底色 `#f2f3f5` 的容器；菜单打开期间容器保持同色常驻（不再加深——`#e5e6eb` 视觉过重），让用户知道浮层是从这里出来的。
- 挂 Tooltip「点击展开省略的 N 层」（N = 被折叠的层级数），把「点了会得到什么」说清楚——常驻容器去掉后，这条是首次发现的主要线索，不可省。
- 触屏热区扩到 44×44，视觉尺寸不变。

| ✅ 推荐 | ❌ 不推荐 |
|---|---|
| hover 出容器 + `cursor: pointer` + Tooltip，三条反馈齐全 | `…` 与相邻层级名完全同样，hover 无任何反应——没人知道它能点 |

### 5.3 展开形态：单列纵向菜单

点 `…` 打开一个**竖排菜单**，一行一级，从上到下＝从上级到下级。

- **不做横排、不分列、不折行。** 面包屑的全部信息量就是「顺序」；一旦折行或分列，分隔符会断在行尾，九个层级看起来像三条互不相干的路径。
- 菜单里**不加分隔符、不加逐级缩进**：纵向排列本身已经表达顺序，而缩进到第九级会把右边挤没。
- 每行**纯文字，不带图标**，把宽度留给名称。
- 菜单里显示**完整名称**，不套 §4 的 96px 限制——用户点开 `…` 就是为了看清名字，在这里再省一次等于信息丢两遍。宽度上限 240px，只有超出才截断 + Tooltip。
- 一行高 32px、左右内边距 12px、字号 12px、**整行可点**；文字色与外层父级一致：默认 `#86909c`（`text-hint`），hover 文字转品牌色 + 整行浅灰底 `#f7f8fa`。只让那几个字可点会大幅降低命中率。
- 菜单与 `…` **水平居中对齐**，在其下方 4px 弹出；宽度 min 120px / max 240px；圆角与投影取 [基础-圆角与阴影规范.mdx](基础-圆角与阴影规范.mdx) 的 popup 档。
- 超过 8 行时菜单内滚动，最大高度 320px。
- 当前页不进菜单——它永远在外面可见。
- **点击**打开，不用悬停打开：菜单里装的是九个会跳走的链接，是操作面不是说明；`…` 又嵌在一行文字中间，鼠标扫过去就会误弹。悬停菜单在触屏上也根本打不开，鼠标斜着移过去还容易半路关掉。点菜单外或按 Esc 关闭。

| ✅ 推荐 | ❌ 不推荐 |
|---|---|
| 竖排单列、一行一级、整行可点 | 横排折成多行多列的小面包屑，分隔符断在行尾，读不出谁是谁的上级 |
| 菜单里给完整名称 | 菜单里再省略一次，用户点开了还是看不到全名 |
| 菜单与 `…` 居中对齐、宽度 ≤240px | 面板宽到接近整行，浮起来盖住页面标题 |

## 6. 移动端适配

> 通用原则见 [基础-多端适配原则.md](基础-多端适配原则.md)，此处只写面包屑的细则。

| 项 | 触屏 / 窄屏规则 |
|---|---|
| 折叠阈值 | 窄屏（< 576px）降到**超过 3 级即折叠**，可见项为 `根级 · … · 当前页` |
| 触达 | `…` 与各层级链接热区扩到 ≥ 44×44，视觉尺寸不变 |
| hover | 触屏不出 hover 高亮，按下时整行浅灰底作为唯一反馈 |
| 长名称 | 触屏没有 hover，Tooltip 不可达；看完整名称一律走 `…` 菜单 |
| 换行 | 同桌面：永不换行 |

---

## 7. 无障碍

- 整体包在 `<nav aria-label="面包屑">` 里。
- 当前页标 `aria-current="page"`，且不渲染成链接。
- `…` 是按钮，带 `aria-label="展开省略的层级"` 与 `aria-expanded`；菜单支持上下键移动、Enter 跳转、Esc 关闭。
- 分隔符图标标 `aria-hidden`，别让读屏器逐个念出来。

---

## 8. 给实现窗口

1. 组件落 `packages/ui/src/components/Breadcrumb/`，对外 API：`items`（含 `title` / `href` / `onClick`）、`maxItems`（默认 4）、`itemsAfterCollapse`（默认 2）。折叠逻辑写在组件内，业务页只传完整层级数组。
2. `…` 菜单复用现有 Dropdown 基座（Dropdown 组件期定基准前先直接用 popup 档样式），**不新写一个浮层**。
3. 截断走 CSS：`max-width: 96px` + `overflow: hidden` + `text-overflow: ellipsis` + `white-space: nowrap`，**不在 JS 里数字符**——数字符必然要为中英文各写一套换算，而且拿不到真实字宽。Tooltip 只在实际发生截断时挂（比对 `scrollWidth > clientWidth`）。
4. 分隔符用 bisheng-icons 的右向箭头，16px；小尺寸档的 `strokeWidth` 补偿由图标组件统一处理（图标规范 §2.2.1），业务页不自调。
5. 窄屏阈值切换用 `useMediaQuery`(576px)，与适配原则同一套断点，不自造。
6. 颜色全走 token，不留裸 hex：灰系复用 Button 已建的 `--btn-*` 系，品牌色走 `--primary`。

## 附录 A：调研存档（2026-08-04）

| 体系 | 折叠阈值 | 保留哪几项 | 中间级去哪 |
|---|---|---|---|
| Carbon（IBM） | 空间不足时 | 首 + 末两级 | overflow **菜单** |
| Fluent 2（微软） | 宽度超出时 | 首、末**永远**可见 | 从第 2 项起进 overflow 菜单；链接 30 字截断、Tooltip 80 字 |
| Spectrum（Adobe） | ≥ 5 级 | root slot + 当前级 | action **菜单**，菜单内按 root→当前 顺序排；默认可见 4 项 |
| SG GovTech | ≥ 5 项 | 首 + 末 | 折进菜单，**挂在第 2 个位置** |
| MUI | `maxItems=8` | 首 1 + 末 1 | 点省略号展开 |
| NN/g | — | — | 面包屑不表达历史；当前页不可点；移动端不许折行 |
| W3C APG | — | — | `nav` + `aria-label`；当前页 `aria-current="page"` |

四条共识：① 折叠触发点在 4～5 级；② 折叠位固定在第 2 个位置；③ 首级与当前级永不折叠；④ 面包屑绝不换行。本规范的差异点：折叠阈值取 4 级（落在共识区间 4～5 的下沿，初版曾取 5，2026-08-05 拍板收紧）、菜单内不做二次省略（业内多数只截 30 字，我们的层级名多为中文短名，240px 足够）。

### A.1 现状诊断（截图，2026-08-04）

结构规则本身没问题——「根级 + `…` + 末两级」与 Carbon / Fluent 完全一致。问题全在展开后的面板形态：

1. 九个层级排成 3 列 × 3 行，还带着 `>`，分隔符断在行尾，看起来像三条独立路径。
2. 面板不像菜单：没有整行 hover 底、没有行高，要精准点到几个小字上。
3. 面板里仍是「一级文件夹一级…」，二次省略，信息丢两遍。
4. 面板宽到接近整行，浮起来盖住当前页标题。

对应改法即 §5.2/§5.3，规则不动，只换触发器与展开形态。

### A.2 中间省略层级的交互方式专项（2026-08-05）

市面上对「点 `…` 之后发生什么」共三派：

| 交互派系 | 代表 | 展开后形态 |
|---|---|---|
| **点击 → 纵向菜单**（主流） | Carbon、Fluent 2、Spectrum、SG GovTech、GitLab Pajamas、shadcn/ui、Primer（overflow='menu'）、MUI（备选） | 折叠项竖排成 dropdown，点某项直接跳转；GitLab 明确写作「selecting the ellipsis button 后以平铺层级展示在 disclosure dropdown 里」 |
| **点击 → 原地展开全部** | MUI（默认）、Semi Design（默认，超 4 项折叠、点 `…` 铺开全部层级） | 面包屑在原行里铺开所有层级，不出浮层 |
| **悬停 → popover** | Semi Design（`moreType='popover'`，仅作可选档）；即我们的现状形态 | 悬停省略号浮出面板 |

取舍：

- **原地展开**在浅层级、短名称下体验最顺（零浮层），但深层级 × 长中文名会把行撞爆——要么折行要么横向滚动，正是现状多行面板问题的根源，排除。
- **悬停 popover** 只有 Semi 一家且仅作可选档；误弹（触发器嵌在文字行里）、触屏打不开、WCAG 1.4.13 对 hover 内容的硬约束三条都不好解，NN/g 对 hover 暴露内容的时序问题也有专文。
- 故取主流派：**点击 → 纵向菜单**（§5.3）。
