## 七项结论

| 用户问题 | 结论与本次处理 |
| --- | --- |
| 分段调整布局 | 页面内容区限制最大宽度并居中，步骤条与底部操作栏居中。使用既有解析/切分组件，保留类型适配。 |
| 有效项、不可用项、预检 | 这原本是服务端对目标归属、版本、权限、配置及执行冲突的计划检查，不是新分段质量检查。文件界面隐藏技术计数与预检措辞，改为“预览新分段 → 确认覆盖”；预览成功前禁止覆盖。后台校验与原计划确认协议保留。 |
| 权限菜单、文件排序 | 菜单改用三语言均存在的 `permission:actionName.manage_permission`。默认请求采用 `file_type asc`，文件夹（0）在文件（1）前，由服务端分页前排序；用户主动选择其他排序继续生效。 |
| 元数据部分失败 | 现场任务遇到文件元数据与冻结快照不一致，随后又因模型配置变化而过期。不是部门权限失败。元数据还需同步 ES/Milvus 中的索引字段，数据库更新不能替代此过程。保留冲突保护，补充可读原因。 |
| 状态筛选无效 | Axios 默认数组序列化产生 `file_status[]`，FastAPI 接收的是重复 `file_status`。children 请求设置 `paramsSerializer.indexes=null`，并验证实际生成的 URL。 |
| 复制提示与项目编号 | 文案改为可切换页面、返回空间查看进度；任务项使用可见文件名称，缺失时显示文件 ID，不再显示项目序号。新失败记录安全原因，旧任务缺少细节时如实提示并展示任务编号。另修复复制权限来源规范化后的误判。 |
| 模型重建与 PRD/spec | 对照用户截图中的 PRD 摘录，AC-48/53/54 要求一致，缺陷在实现顺序及全失败后的最终切换。补齐已知不可用模型拒绝、清理前真实模型探测，以及全部文件失败时禁止模型切换。 |

## 重建的实际边界

1. 显式重建/切换模型准备阶段，已知模型错误状态拒绝，正常同模型元数据保存不受影响；共享模型状态查询复用已验证的目标/租户范围。
2. 普通文档旧任务及原生空间任务在任何集合清理前调用目标 Embedding 并检查非空有限数值向量；探测失败不清理原集合。
3. 全部文件失败保留原模型和待完成操作，不进行 SQL/R2 模型最终切换，记录任务/文件失败。原任务重试成功后可以完成切换；部分成功仍按 AC-53 发布成功文件并保留失败项重试。
4. 原物理流程仍是原地重建。探测通过后，若供应商或索引在运行中途故障，已清理向量不能自动回滚；需修复后重试，原文件、ES 分段、版本及权限保留。这不同于原子索引代际切换，不能宣传为旧向量自动恢复。截图未给出具体 P0 空间/任务 ID，未将其他成功任务当作该事件的复现或现场验收。
