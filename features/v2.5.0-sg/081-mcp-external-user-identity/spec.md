# F081：MCP 指定业务账号身份规格

- Feature ID: `081-mcp-external-user-identity`
- Status: `IMPLEMENTED_LOCAL`
- Version: `v2.5.0-sg`
- Created: `2026-10-22`
- 关联需求来源：[用户已确认的发现范围](spec-discovery.md)，无独立 PRD。
- 需求追溯：[requirements.md](requirements.md)；实现设计：[design.md](design.md)；评审：[spec-review.md](spec-review.md)。

## 1. 概述与用户故事

作为可信业务后端，我希望用有效开发者 Token 接入 MCP，并在每次工具调用中传入真实登录用户的 `external_id`，由该用户决定资源读写权限及业务归属，不再受 Token 绑定用户资源权限的影响。

Token 仍负责接入校验和审计。指定账号不是本人身份证明：可信后端须验证真实用户，并从已验证会话导出账号，不能直接转发终端或模型任意指定的账号。

本特性覆盖当前十个工具，不修改 REST 身份代理行为、现有权限模型、Token 管理界面或真实数据。原 F070/F078 禁止 MCP 身份参数、仅用 Token 用户执行的约定在本特性规格获确认后由本文件覆盖；其他契约保持。

| AC-01 | 接入方 | 列工具、握手及调用十工具；缺少 external_id 或传非字符串 | 握手/列工具仍只需有效 Token；十工具均声明必填严格字符串账号，缺参/非法类型拒绝且不执行业务；没有 Token 用户回退 |
| AC-02 | 接入方 | Token 无效/禁用/归属失效、IP/非空路由不符、触发限流 | 保留现有 HTTP 401/403/429/503；账号解析和业务访问均未执行；空路由白名单仍不启用路由过滤 |
| AC-03 | 业务用户 | 传唯一有效、空/超长、禁用、不存在、跨来源重复账号 | 唯一有效用户可解析；其余安全拒绝；保留前导零及归一化后精确值，不按工号/名称或首条候选回退 |
| AC-04 | 业务用户 | Token 用户无权而目标用户有权，及 Token 用户有权而目标用户无权 | 前者按目标权限成功，后者明确拒绝；不复制 Token 角色或取两者权限交集；目标管理员也通过正常权限入口构造身份 |

| AC-08 | 并发接入方 | 两个目标账号/租户并发，含异常、身份加载超时和取消；继承污染上下文 | 目标用户、角色、租户和 session 不串用；解析阶段后 bypass 关闭；业务装配前建立目标上下文；成功/拒绝/超时/取消均恢复，不产生因解析而来的业务写入 |
| AC-09 | 审计人员 | 查看成功/拒绝/异常调用与客户端错误 | 记录 Token ID、Token 绑定用户/租户和执行用户/租户（解析失败可为空）、工具/trace/结果；客户端固定安全错误，无 Token 明文、候选明细、账号字符串、正文或签名泄漏 |
| AC-10 | 既有接入方 | 升级 MCP 客户端，复跑 REST、folder_id、预览/下载与现有 Token/CORS | MCP 客户端增加账号并刷新工具清单；其他既有业务契约保留；文档明确任意有效接入 Token 的账号代理能力、可信后端责任及代码回退不撤销已写文件 |

## 3. 账号与租户契约

### 3.1 公共参数

所有工具新增顶层参数：

| 参数 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `external_id` | string | 是 | 严格字符串，去除前后空白后长度 1～255；按归一化值精确匹配，保留内部字符、大小写与前导零；不接受 null、数字或布尔 |

数据库字符串排序规则可能忽略大小写或尾空格，候选还必须作字符串精确值核对，不以模糊 SQL 结果推断身份。只在未禁用用户中判断唯一性，不能通过筛选其“有租户/有权限”来猜选跨来源重复账号。

目标用户选择完全独立于 Token 用户。Token 的启用、绑定用户/归属租户有效性等既有凭证检查保留，但 Token 的资源权限不参与目标业务授权。

### 3.2 租户规则

- 多租户开启：目标用户恰有一条 `is_active=1` 的当前关系，该关系须 `status=active`，对应 Tenant 须存在且 `status=active`。先判断全部当前关系是否唯一，再检查状态；不能过滤掉失效关系后悄悄选择另一条。
- 历史 `is_active=NULL`、`is_default` 和 Token 所属租户均不能代替当前关系。零条、多条、失效均拒绝，不修复数据、不调用登录同步流程。
- 多租户关闭（单租户模式）：使用 `DEFAULT_TENANT_ID=1`；仍校验账号及默认租户有效性，忽略历史/当前租户关系选择。
- 不新增 `tenant_id`、`user_id`、`source` 或管理员 scope 参数，未知字段仍拒绝。配置读取失败不能解释为“多租户关闭”。
- 每调用重新解析有效身份，不跨调用缓存代理结果；调用内身份固定，权限由既有业务入口继续校验，不承诺对进行中的写入提供即时撤权或跨系统事务。

## 4. API 契约

### 4.1 HTTP 与协议

| Method | Path | 行为 | 鉴权 |
|---|---|---|---|
| POST | `/mcp`、`/mcp/` | initialize、通知、tools/list、tools/call；路径统一按 `/mcp` 匹配 Token 规则 | X-Developer-Token；业务账号仅在 tools/call 必填 |
| GET / DELETE | 同上 | 先校验 Token，再保持 405，不执行账号解析或工具 | 现有 Token 校验 |
| OPTIONS | 同上 | 现有 MCP CORS 预检 | 不返回业务信息 |

继续使用 MCP JSON-RPC / `CallToolResult`，不增加 REST endpoint、Cookie/JWT 接入或 `UnifiedResponseModel` 包装。非 MCP 路由和跨域政策不变。

### 4.2 十工具覆盖

| 工具 | 新增身份参数 | 原业务行为来源 |
|---|---|---|
| `search_knowledge` | external_id 必填 | F070 原检索，原参数/检索范围及响应保持 |
| `list_knowledge` | external_id 必填 | F078 有权空间发现 |
| `list_folders` | external_id 必填 | F078 目录浏览 |
| `list_files` | external_id 必填 | F078 文件浏览 |
| `search_files` | external_id 必填 | F078 文件搜索 |
| `get_file_detail` | external_id 必填 | F078 当前入口与正文 |
| `get_file_source` | external_id 必填 | F078 现有有权预览 Owner |
| `retrieve_chunks` | external_id 必填 | F078 空间校验及共享检索 |
| `create_document` | external_id 必填 | F078 文本/Markdown 新文件 |
| `upload_file` | external_id 必填 | F078 Base64 新文件 |

其他参数/输出见 [F070](../070-mcp-server/spec.md)、[F078](../078-mcp-knowledge-tools/spec.md) 及 [MCP 使用说明](../../../docs/api/mcp-usage.md)。`folder_id` 的整数/数字字符串兼容、分页、内容限制、50/10/80 MiB 上限、版本与下载策略均保留；仅缺少新身份参数的调用不再兼容。

工具请求 params 示例（账号为占位示例，必须由可信后端根据登录身份提供）：

```json
{"name":"list_knowledge","arguments":{"external_id":"00012345"}}
```

```json
{"name":"search_knowledge","arguments":{"external_id":"00012345","query":"安全要求","knowledge_base_ids":[118]}}
```

```json
{"name":"upload_file","arguments":{"external_id":"00012345","knowledge_id":118,"folder_id":"305","file_name":"hello.txt","content_base64":"aGVsbG8="}}
```

响应字段不增加身份回显。读写动作的业务归属变化通过原业务结果和审计核验，不在错误中暴露候选身份。

例如 list_knowledge 无可见空间时，沿用原响应模型，以下为工具结构化业务结果（外层仍由 SDK 生成 CallToolResult，不另包 REST 响应）：

```json
{"data":[],"page_size":20,"has_more":false,"next_cursor":null}
```

账号/当前租户不可用或不唯一时，CallToolResult 返回 `isError=true`，固定提示“指定账号或当前租户不可用”；不区分账号不存在、重复、关系失效或租户停用。参数错误继续由 SDK 按参数契约拒绝。

### 4.3 失败契约

| 边界 | 状态 / 原错误类型 | 客户端结果 | AC |
|---|---|---|---|
| HTTP 凭证缺失、无效/禁用 | 401 / 19801、19802、19803 | 原有 HTTP 鉴权响应，无账号查询 | AC-02 |
| HTTP IP 或非空路由不匹配 | 403 / 19804、19812 | 原有 HTTP 鉴权响应 | AC-02 |
| HTTP 限流 / 限流不可用 | 429 / 19805、503 / 19806 | 原有 HTTP 鉴权响应 | AC-02 |
| 工具参数缺失/类型/长度非法 | SDK 参数错误 | 原生参数拒绝；不打开账号或业务服务 | AC-01、AC-03 |
| 账号/当前关系/租户不可用或不唯一 | 既有 `UnAuthorizedError`（403，历史通用错误类） | HTTP 协议成功时 MCP `isError=true`，固定安全提示；拒绝原因仅内部枚举，无候选明细 | AC-03、AC-05、AC-06、AC-09 |
| 角色、配置、数据库或权限设施异常 | 原始异常或既有业务错误 | 安全工具失败，不当作无结果、不降级为 Token 用户 | AC-04、AC-08 |
| 业务权限拒绝、超时及上传不确定 | 既有领域错误和工具安全映射 | 保留原错误/受理不确定语义，必要时保留合法已知 file_id | AC-07、AC-08 |

不新增业务错误模块编号或复用数字冒充新错误码。`UnAuthorizedError` 是当前已存在的通用类；新增专属错误码若确有必要，须先更新版本契约并记录范围偏差。

## 5. 架构决策

| ID | 决策 | 结论与理由 |
|---|---|---|
| AD-01 | 接入身份与执行身份分离 | 保留原 Token principal 作校验/审计，新增只读执行身份 DTO，不能覆盖或伪造原 Token principal |
| AD-02 | 十工具共享账号语义 | 九工具 runtime 与旧检索都调用同一身份上下文服务；不把旧检索外部账号再传入 Filelib 的 REST 代理入口 |
| AD-03 | 租户关系查询归属 | 新增 tenant 模块 Repository 读取现有 UserTenant/Tenant；复用 user Repository 查询账号；Service 无 SQL、无新 DAO |
| AD-04 | 身份读取与业务作用域分离 | 身份阶段可有限跨范围读取，关闭其 session/bypass 后才建目标业务会话；业务维持现有 MCP 的目标租户可见集，不额外扩大到 Root 或管理员全局范围 |
| AD-05 | 不复用 REST 代理执行作用域 | 原代理固定默认租户且执行期保留 bypass，不符合本次跨租户与正常过滤目标；REST 保持原样 |
| AD-06 | 无旧调用隐藏回退 | 新参数必填，避免同一客户端因漏参而用 Token 用户写入不同位置；以发布说明明确升级要求 |
| AD-07 | 目标用户完整身份 | 复用 UserPayload 正常构造入口加载目标角色/管理员身份，而非复用 Token 的权限快照；资源授权及创建 Owner 仍归既有领域服务 |

## 6. 数据、Owner 与非功能边界

无新表、新字段、迁移、新权限实体、运行配置或第三方依赖。User、UserTenant、Tenant、PermissionTuple、知识文件和队列的 Owner 不变；只新增只读仓储接口，不创建或修复身份数据。

保持版本 INV-1/2/3/4/6/8/9/11/13：业务租户由目标身份建立，ORM 自动注入过滤；资源归属与目标租户仍须匹配；统一权限入口、创建授权及失败补偿、队列 tenant headers、配额和存储前缀保留。Token 租户不参与目标用户租户判定，不等于绕过资源本身租户约束。

身份解析最多 30 秒；九个新工具的该阶段纳入原读 30 秒/写 120 秒总预算。旧 search_knowledge 增加独立的最多 30 秒身份阶段，原检索及来源超时配置保留，故最坏调用时长可增加一个身份阶段；不新增无界等待。异常/取消不能泄漏数据库会话或 ContextVar，不在每个 SDK 静态工具对象上共享可变用户状态。

具体模块、文件范围、预算与验证分组见 design。本阶段无前端页面或 Worker 实现变更；Worker 的目标租户由已有上传投递流程携带。

## 7. 发布与回退

这是接口与权限身份变化：有效 MCP Token 的持有方可指定包括管理员在内的账号并跨 Token 租户执行。只有可信业务后端应持有该 Token；后端须固定/覆盖传给 MCP 的账号，不能信任终端、模型或检索内容要求切换账号。

发布前升级调用方、补齐 external_id 并刷新工具清单。无需修改已有 Token 白名单或迁移数据。回退代码恢复 Token 用户执行方式，不能撤销新方式已创建的文件、Owner、授权或配额记录；这些仍按现有业务生命周期管理，禁止自动清理。
