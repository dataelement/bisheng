# 后台知识空间展示适配

基线：`origin/feat/3.1.0-beta1` / `c9918ba14e`。旧 UI 参考：`3d4e167db1^` 的 client 知识空间侧栏、`FileListRow`、`FileCard`、`FileListToolbar`。

沿用旧前台的分组树、双行文件列表和卡片布局；展示适配在 platform 内完成。旧 client 的 Recoil、Auth、路由和上传/删除实现不跨应用移植，避免覆盖 F118 的 scope、权限、游标分页和确认生命周期。遵守 [constitution](../../../docs/constitution.md) C3、C4、C6、C7；无后端契约变更。

## 数据流与职责

- `/filelib` 与 `/filelib/:id?parent_id=...` 共用 `KnowledgePage`，普通页签挂载 `KnowledgeSpaceWorkspace`；目录切换保留侧栏。主页右侧自动进入第一个空间的文件目录，空间全量列表保留在独立管理页签。
- `sidebar/` 通过已有 `/department`、`/mine`、`/joined` 取三组，按组排序；置顶使用现有 `set-pin`。查询 key 包含完整 `knowledgeQueryKeys.scope(scope)`。
- 文件夹树调用 `children(file_type=0)` 并消费游标，按需加载；深链通过已有 parent 路径接口展开。不能照搬旧实现固定取第一页的写法。
- `SpaceDetail` 复用当前服务端标题、父路径和 `Files` 数据/权限/生命周期。`Files` 的 workspace 呈现参考旧 UI，其他调用默认保持原表格模式。
- 列表/卡片偏好沿用旧版持久化行为，存储按身份、租户、管理域隔离；已解析文档优先显示缩略图，加载失败回到类型图标。目录与面包屑导航保留状态筛选等无关 query；切换目录清除 `file_id`，侧栏选择同时清除配置页签 query，回到文件管理。
- 问答库及管理员全量清单维持原独立页签。分组接口不能替代 F118 普通可见清单，可见清单用于个人分组为空时选择首个入口，右侧不再展示该清单；管理员列表继续使用可信管理域。
- 广场沿用工作台 `/knowledge?square=1` 入口，不在后台重做订阅和加入审批。

## 已知约束

| 约束 | 处理 |
| --- | --- |
| 旧侧栏返回整页目录，现接口是游标分页 | 新树保留继续加载和错误重试，不能丢弃下一页。 |
| 只获文件/文件夹授权时根空间可能不可见 | 以普通可见清单选择首条作为分组为空时的兼容入口；深链目录不以 getSpaceInfo 成功作为文件浏览前置。 |
| 超管分组接口与管理员全量清单语义不同 | 保留独立管理清单；分组只是个人导航，不作为全量管理数据源。 |

## Client 空间入口收敛

2026-11-12 用户明确要求移除前台四个独立按钮，引用来源在删除过程中按需展示。

- 移除 toolbar 的移动任务历史入口、主文件列表下的引用/清空按钮，删除无消费者的对应回调。无新增菜单入口。
- 删除普通处理任务管理面板及其专用查询 hook；以 `SpaceProcessingStatus` 保留 Root state=3/4 的重建中/失败提示。文件行状态与批量处理回执保持现有逻辑。
- 保留实际移动提交后自动打开的 `MoveJobProgress`、当前任务轮询、失败重试和丢失确认 ACK 的恢复；删除不再有入口的全空间移动历史查询和选择路径。无当前任务时不得手工 refetch 空 operation。
- 空间删除继续使用 `useSpaceActions → useKnowledgeDeletion`；文件/文件夹删除继续使用 `useKnowledgeFileActions → useKnowledgeDeletion`。不改只读范围捕获、服务端预检、不可变计划、二次确认、强制空间删除和批量跳过规则。
- `KnowledgeDeletionDialog` 只有预检返回引用计数、受限计数或来源页时展示引用区块；无引用不展示空来源/受限来源标题。来源名称/入口仍由服务端 disclosure 决定，检查失败保持原阻断。
- 原处理面板和专用 hook 的测试随退役功能删除，以状态反馈、四入口缺席、真实删除 hook 与弹窗的按需引用展示测试替代。

## 后台详情页签与回显

2026-11-13 按用户追加口径展示五个页签，处理任务并入模型与索引；文件管理保留双行列表/卡片展示。

- `SpaceManagementView` 负责空间标题、成员权限入口、页签及文件操作挂载点。配置页签依赖当前 scope 的 SPACE `edit`，成员按钮依赖 `manage_permission`，不通过管理员身份推测业务授权。子项浏览不等待根权限或根信息成功；有根编辑权限的目录用户另读根标题，避免将文件夹名称误作被配置空间名称。
- `tab` query 记录详情页签；切换页签保留 `parent_id`、`fileStatus` 和其他 query。点击侧栏空间或目录清除 `tab` 回到文件管理。页签内容按需挂载，文件新增/批量操作复用现有回调和权限，借 portal 显示于标题右侧。
- 默认解析及基本信息表单复用现有服务器有效配置读取和保存实现，通过业务 `SpacePanelFrame` 在页内呈现。默认解析连续保存更新本地 `config_version`，不重用旧版本号。新建空间、文件处理及复制仍使用现有弹窗。
- 模型页原先仅初始化空字符串，未读取空间已保存模型。现在按 scope、空间及本次挂载读取 `getSpaceInfo.model`，初次成功后仅初始化一次；用户主动选择后不再被迟到读取覆盖。读取失败禁用预检并提供重试；候选目录之外的旧模型通过已有 ModelSelect 回退展示，旧名称重建使用当前绑定，不发送 NaN/非法数值。
- 模型、元数据、任务及文件处理仅启用当前模式所需的读取。预检计划、二次确认、幂等键、未知 ACK 恢复和状态轮询继续复用原实现。
- 侧栏通过宽度和 hidden 收起导航内容，保留已挂载树和目录展开状态；只移除可见重复标题，保留辅助技术标签及明确的展开/收起按钮。
- 本次仅修改 platform，不变更 client、后端契约和数据库。
- 2026-11-13 入口收敛：共享文件行不再挂载 SpaceFileTools，列表、卡片和表格均移除常驻“处理版本”按钮及其专用编辑权限读取；通过文件详情中的元数据和分段策略入口管理。SpaceFileTools 仍被独立历史版本面板使用，不属于无消费者组件。

## 默认落点与文件详情

- `useInitialSpace` 与左树共用三组查询 key，全部组就绪后按顺序选择首个有效空间，避免较快返回的“我创建的”抢先覆盖部门空间。个人分组为空才读取可见空间，消费空游标页；不在右侧绘制空间列表。
- 自动导航仅在知识空间页签实际激活且 URL 没有空间 ID 时生效。Radix 页签退场有一个内容保留周期，必须显式传入 active，避免 QA/管理切换被自动导航拉回。
- `SpaceModelIndexPanel` 组合模型表单和 kind=embedding_rebuild 的任务列表，保留原预检/幂等/轮询。旧任务页签 query 自动替换为 embedding；文件重处理能力继续沿用现有入口。
- 文件详情通过 file_id query 保留目录/筛选上下文，以当前 SPACE 文件预览接口成功作为展示前置，随后读取已有 file info、chunk、bbox 接口。复用旧 `PreviewFile` 与 `PreviewParagraph` 的左右布局、PDF/表格/媒体预览和编辑器；不重新接入旧固定读取前 1000 文件的列表。
- `useSpaceFileDetail` 以完整 scope、空间、物理文件及挂载实例隔离查询和提交，后台加工目标校验成功且当前 SPACE 有 edit 才展示写入能力；只读原文不依赖编辑资格。编辑/删除请求固定使用当前物理文件 ID，保留 chunk_index=0 和原 bbox；切换分块清空框选，迟到编辑不会借用另一分块的框选。保存失败保留文本并提供原目标重试；组件退役后不触发后续写入/刷新。
- 新容器保留当前 API 和权限语义，旧图片/表格/chunk UI 组件继续复用；不会复活旧的无范围缓存和文件列表查询。三种语言补充文件详情标题，其他文案复用已有键。

## 管理详情统一

- `view=admin` 显式记录管理页签上下文，只有 `useKnowledgePageScope.canManage` 为真时生效；普通和 QA 页签切换同步 URL。保留旧 QA 详情返回时的 LibPage 初始页签兼容，空间导航不再使用该全局标记传递管理模式。
- 管理根入口继续展示可信当前租户的分页空间清单；空间行和高级配置进入带管理上下文的详情。详情与普通页签复用 `KnowledgeSpaceWorkspace → SpaceDetail → SpaceManagementView`，管理模式不挂载个人三组树或首空间自动选择；不引入额外管理版详情实现。
- 管理列表行来自管理员可信租户清单，点击行在当前生命周期有效时直接路由到对应 admin 详情，不以 SPACE visible 查询作为导航前置。普通列表仍走原可见动作校验；三点菜单阻断事件冒泡并按需查询有效动作，业务 API 校验不变。
- 完整 scope 继续隔离普通/管理目录、配置、文件编辑及上传查询；现有 URLSearchParams 保留目录、文件、筛选与 view。新建/新建并导入带回管理上下文，上传入口按角色和 view 选择 scope，上传返回保留原参数，详情返回进入管理清单。
- Radix 页签退场期间，未激活 Workspace 不渲染目录/文件内容，防止切换页签时以过渡路由触发另一视图的详情读取。个人首空间选择仅在激活的 ordinary 根入口运行。
- 所有业务动作继续读取服务端有效权限，不依据 URL 构造授权；管理员免逐空间授权沿用现有服务端角色/租户短路。本轮无后端、client、browser-config 或 user/info 刷新实现改动。
