## 用户要求

桌面窗口宽度变化时保持图标、控件、字号和内部间距稳定；用户确认卡片宽度可以随内容区伸缩，并补充默认一行三张、参考订阅的内容断点。

## 根因与处理

- 原局部 `--vnext-layout-unit=max(.8px,.0657894736842vw)` 根据视口宽度缩放几何尺寸；最小卡宽也参与缩放。因此内容列已经达到 1000px 上限时，窗口缩窄仍会缩小最小卡宽，从两列反向变为三列。
- 真实页面修复前：1440px 视口下两列各 488px，主图标 34px、排序 120×30px、Gap 22px；1366px 下三列各 320px，主图标 32px、排序 114×28px、Gap 20px。1920px 下主图标增至 44px、排序 160×40px、卡片自然高度增至 144px。
- 上述宽度实测页面标题 / 卡片标题 / 正文一直为 24 / 16 / 14px。变化包括图标槽位及卡片标题行高；用户两张附件原始宽度不同，按相同展示宽度缩放也会改变文字观感。
- 固定原 1440px 下的局部几何值，页面与显式加入 geometry 作用域的弹层共用。只保留卡片列宽随容器伸缩。
- 订阅桌面端采用原生 `auto-fill + 固定最小卡宽 320px`。知识空间使用同样方式，但保留 22px 间距，最小卡宽为 300px；照搬 320px 会使默认三列需要 1004px，超过 1000px 内容列。
- 移除手工除法取整列数与偶数列宽：边界实测中，原算式在内容区 622px、最小卡宽 300px 时错误向下取到一列。原生 Grid 正确给出两列各 300px。内部配置几何仍为偶数像素，弹性列宽可以含小数。
