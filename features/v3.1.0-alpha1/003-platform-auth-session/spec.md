# Feature: 平台统一认证与会话

**关联 PRD**：[需求确认记录](./discovery.md) U-01～U-10；无独立 PRD。
**优先级**：P0。**所属版本**：v3.1.0-alpha1。
**状态**：规格 S1 已由用户于 2026-11-27 确认；用户随后授权按tasks实现与测试，开发及本地单元验证完成；真实集成由用户自行处理，结果见validation.md。
**依赖**：既有用户认证与权限、DSH 本地会话、F026 OAuth2／OIDC Provider；遵循[版本契约](../release-contract.md)。

## 1. 用户故事与范围

作为网页或手机用户，我希望在各端按同一规则保持登录、续期和退出，避免正常使用时反复登录或因后台刷新被错误踢出。

作为管理员，我希望账号停用、密码重置、会话撤销及单点登录策略在网页和手机上有相同效果，且升级不会破坏现有 DSH 和第三方 SSO。

作为后续 DSH 接入维护者，我希望桌面能够迁入平台统一认证，不继续维护一套永久独立的凭证体系。

本期纳入：网页与手机认证和凭证生命周期统一、网关认证结果的后端签发接入、现有网页身份消费者适配、DSH 过渡边界及发布方案。

本期不做：保留普通旧网页登录态；修改网关程序；迁移旧 DSH 设备会话；改造第三方 SSO 协议与凭证策略；改变 PAT／服务账号或匿名访问；修改资源权限与业务数据；承诺旧手机无感迁移。

## 2. 验收标准

### 2.1 登录及身份

- **AC-01** — WHEN 网页或手机完成受支持的身份认证，THE SYSTEM SHALL 为其建立统一管理的登录会话，并提供同一种平台访问凭证和相同的续期、撤销规则。
- **AC-02** — WHEN 用户登录，THE SYSTEM SHALL 保留现有验证码、密码错误限制、密码过期、账号停用、所属组织状态和可用权限检查；IF 检查失败，THEN THE SYSTEM SHALL 不建立可使用的登录会话。
- **AC-03** — WHEN 网关完成认证并向毕昇请求登录凭证，THE SYSTEM SHALL 由毕昇后端完成平台会话和凭证交付，且不要求更改网关的请求、响应或程序。
- **AC-04** — WHEN 已认证用户访问业务，THE SYSTEM SHALL 按其当前有效身份、所属组织和权限处理；客户端名称、登录方式和续期均不得增加用户权限。

### 2.2 默认期限与续期

Access Token 30 天、Session／Refresh Token 默认 90 天闲置期限、活动口径及默认无额外绝对上限，已随规格和设计于 2026-11-27 获用户确认。

- **AC-05** — WHEN 新会话签发访问凭证，THE SYSTEM SHALL 默认使其自签发时起有效 30 天，且不超过所属会话的剩余有效期；该默认期限可由服务端配置。
- **AC-06** — WHEN 建立新平台会话，THE SYSTEM SHALL 默认给予 90 天闲置期限，并使当前刷新凭证在同一时刻到期；缺省不设置额外的绝对总寿命限制。
- **AC-07** — WHEN 未过期会话发生符合活动口径的真实业务活动，THE SYSTEM SHALL 将其闲置到期时间和当前刷新凭证到期时间顺延至该活动发生后 90 天；后台刷新、心跳、身份读取和状态轮询不属于该活动。
- **AC-08** — WHEN 用户提交有效刷新凭证且会话仍有效，THE SYSTEM SHALL 提供新的访问凭证并轮换刷新凭证；刷新本身不顺延会话闲置期限。
- **AC-09** — IF 访问凭证已经过期但刷新凭证和会话仍有效，THEN THE SYSTEM SHALL 允许用户续期而不要求重新输入密码。
- **AC-10** — IF 会话或刷新凭证已过期、被撤销、所属用户或组织不可用、身份版本不再匹配，THEN THE SYSTEM SHALL 拒绝续期，不恢复失效会话，并向客户端提供可区分的结束原因。
- **AC-11** — WHEN 刷新响应丢失后在允许的重试条件内再次提交原凭证，THE SYSTEM SHALL 安全恢复已经产生且尚未继续使用的后继凭证；IF 已超出恢复条件，THEN THE SYSTEM SHALL 识别异常重用并撤销对应会话。
- **AC-12** — WHEN 并发刷新、撤销和业务活动相互竞争，THE SYSTEM SHALL 保证被撤销或过期的会话不能被迟到请求恢复，且不能出现并行有效的刷新分支。

### 2.3 多端与退出

- **AC-13** — WHERE 允许多点登录，THE SYSTEM SHALL 允许网页和手机拥有独立有效会话；WHERE 禁止多点登录，THE SYSTEM SHALL 使后完成的成功登录替换已有统一会话；同一会话续期不算新登录。
- **AC-14** — WHEN 同一浏览器使用管理端、工作台或多个标签页，THE SYSTEM SHALL 共用该浏览器登录会话，并避免标签页之间因正常刷新发生互踢或凭证重用错误。
- **AC-15** — WHEN 用户退出当前端，THE SYSTEM SHALL 撤销当前统一会话；WHEN 用户执行统一会话全部退出，THE SYSTEM SHALL 撤销其全部新平台会话，且明确该操作不等于退出上游身份平台或旧 DSH 设备。
- **AC-16** — WHEN 用户主动退出、管理员撤销、账号停用或密码重置触发失效，THE SYSTEM SHALL 拒绝其后到达的新业务请求，并在正常服务条件下 5 秒内停止现有连接上的新业务准入和认证输出，不等待 30 天访问凭证自然到期。
- **AC-17** — IF 网络中断、请求超时或认证服务暂不可用，THEN THE SYSTEM SHALL 保留客户端已保存的凭证并允许重试；IF 明确收到不可恢复的会话失效结果，THEN THE SYSTEM SHALL 结束本地登录。
- **AC-18** — WHEN 刷新响应在退出或账号切换后才返回，THE SYSTEM SHALL 丢弃该过期响应，不恢复此前登录或覆盖新账号凭证。

### 2.4 旧网页、DSH 与 SSO 边界

- **AC-19** — WHEN 切换至新平台认证，THE SYSTEM SHALL 允许普通旧网页登录态失效并引导一次重新登录；不得借此清空业务数据或无关用户偏好，也不得仅靠修改全局签名秘密使全部凭证失效。
- **AC-20** — WHILE 旧 DSH 客户端仍受支持，THE SYSTEM SHALL 保持其授权、换证、刷新、模型访问、手机桥接及内嵌网页流程可用，且不擅自改变这些历史会话的有效期。
- **AC-21** — WHEN 新网页普通旧凭证被拒绝，THE SYSTEM SHALL 继续接受经既有 DSH 会话验证的定向网页桥接凭证，不使旧 DSH 因此失效。
- **AC-22** — WHEN 第三方应用使用现有 OAuth2／OIDC SSO，THE SYSTEM SHALL 保持客户端配置、授权同意、授权码、用户信息、刷新及撤销行为，不因本次迁移额外作废符合原策略的已签发凭证；网页登录变更不得绕过授权范围或改变第三方凭证用途。
- **AC-23** — WHEN 网关登录成功的用户进入新网页，THE SYSTEM SHALL 在不改网关的条件下建立可续期的网页登录；重复或丢失响应不得产生多个刷新分支，也不得凭任意旧网页凭证获得新长期会话。
- **AC-24** — WHEN 用户通过 Desktop 现有浏览器授权、回调及一次性票据/PKCE 流程登录，THE SYSTEM SHALL 保留交接体验，并在票据兑换成功后签发 client_id=bisheng-desktop 的统一平台会话；保留既有旧 DSH 凭据校验，不自动转换历史 Token。客户端须接受新平台凭据及刷新/退出协议，严格依赖旧 Token 格式的版本仍需适配。第一方平台会话向目标应用静默换证不需要 OAuth 用户同意，普通第三方 OAuth 授权规则不变。
- **AC-25** — WHEN 旧手机未满足新认证协议要求，THE SYSTEM SHALL 明确提示升级或重新登录；发布说明必须列出最低支持版本，不承诺不可区分的历史网页／手机凭证无感保留。

### 2.5 完整性与发布

- **AC-26** — WHEN 身份被用于普通请求、长连接、文件访问或延后执行，THE SYSTEM SHALL 持续检查所属会话及身份有效性，不因只校验凭证签名、缓存身份或排队延迟绕过撤销。
- **AC-27** — WHEN 不同 API 认证体系同时存在，THE SYSTEM SHALL 保持平台登录、第三方 SSO、开放 API 密钥和匿名分享的使用边界，不接受用途不匹配的凭证。
- **AC-28** — WHEN 认证数据服务故障，THE SYSTEM SHALL 显式报告暂不可用且不执行未经确认的业务；客户端不得把服务故障误判为账号错误或立即删除凭证。
- **AC-29** — WHEN 发布或回滚新认证，THE SYSTEM SHALL 保证所有服务副本使用一致的凭证协议，并保留对已签发新平台会话的校验和撤销能力；不得恢复不认识新会话的旧验证路径。
- **AC-30** — THE SYSTEM SHALL 使凭证生命周期在支持的数据库和多实例运行条件下保持一致，且不会在普通日志或审计记录中输出完整密码及登录凭证。

## 3. 边界情况

- 30 天访问凭证过期与 90 天会话过期不同：前者可以在后者仍有效时续期；后者必须重新认证。
- 恰好到期的会话不可被业务活动、刷新、重试或延迟任务复活。
- 打开页面、心跳、轮询和成功换证不是业务活动；无法读取活动策略时不能猜测为可保活活动。
- 多租户用户的所属组织由服务端解析；管理目标切换不能改写认证所属组织或冒充新登录。
- 更换服务器地址必须隔离凭证和待处理请求，不能把一个部署的刷新凭证发送到另一个部署。
- 本期只强制普通旧网页登录态重登；旧 DSH 定向兼容与历史手机的发布安排分别验收。
- 旧网页可以重登不意味着可以让商业网关重写协议、让第三方 SSO 丢失授权或让旧桌面无法打开网页。
