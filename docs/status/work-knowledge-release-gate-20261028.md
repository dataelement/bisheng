# Work 知识检索发布流程修复 · 2026-10-28

## 原因与行为

PR #2546 提供完整的数据升级命令。原 `docker/deploy.sh update` 只拉镜像和
启动容器，随后输出更新完成，部署操作与知识工具的数据升级仍然分开。

本次把现有升级命令接入部署入口。包含 backend 的更新先校验 Store 确认值和
操作人参数，再拉取镜像、等待 backend 就绪、执行知识工具登记与权限校准，
成功后继续更新其余服务并报告完成。失败状态向调用方传递，后续阶段停止。
backend 已更新而维护失败时，错误信息明确说明当前状态和重试方式。

预览采用目标镜像的一次性容器，并继承 backend 的配置、挂载及网络。
权限维护沿用 F048 统一入口；API 启动沿用已有结构迁移职责。
worker/frontend 单独更新及现有版本重启继续保持指定范围。

## 发布边界

使用与目标镜像配套的部署目录，执行步骤见 `docker/README.md`。
每个环境在维护窗口运行一个发布作业。其他流水线及直接 Compose 更新需要显式
调用同一维护命令并检查成功结果。维护失败时，环境可能已经完成 backend 和数据库
结构更新，运维按发布流程保留维护窗口并处理错误。

本轮验证覆盖源码与命令编排。13001 的实际部署方式、镜像发布、真实数据库及
OpenFGA 校准、dsh-sara5 的 K1/K2 引用验收继续单独记录。
