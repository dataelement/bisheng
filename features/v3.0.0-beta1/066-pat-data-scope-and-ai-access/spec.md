## 1. 范围裁定

**本次纳入：**

- **数据范围收窄（D21）**：租户策略新增「AI 助手可检索的范围」单选（全部可见知识 / 仅员工自己创建的知识库），**仅租户级、无部署级**；调用期强制、不写凭据行，对存量已签发令牌 5 秒内生效、可逆；**对含管理员在内的全体持有人一致生效，判定先于管理员短路**；覆盖 `knowledge:read` 位下全部端点；越界返回 `26044`（防枚举）。「本人创建」口径与界面「我创建的」同源，按库 / 空间归属粒度判定、不下探文件创建者。
- **租户策略变更审计**：能力开关 / 默认有效期 / 数据范围任一变更写操作审计（含变更人与前后值）——现状策略更新为审计空白，随本条一并偿清。
- **员工侧与管理端界面重构（D22）**：功能统一更名「AI 助手接入」；入口 = 知识库页常驻主入口 + 设置页一级分区 + 深链直达弹窗；租户关停态在设置分区保留解释；风险提示分层（员工只在密钥展示时警示、管理员默认档签发前二次确认 + 加重警示、收窄档降级）；「这把密钥能查到什么」静态四态文案；**既有警示「此令牌不会继承管理员特权」按 D17 事实改写**（beta1 上该文案与已合入的管理员短路实现相反）。
- **技能包 P0 修缮**（后端打包逻辑零改动，只改包内静态文件）：SKILL.md 教「先调清单端点拿知识库标识再检索」并补中文触发词；`search.py` 读取并透出 HTTP 错误响应体中的业务码与信息；新增 `references/api.md`（端点表、请求 / 响应结构、错误码表含 `26044` 处置指引、分页游标、检索结果引用回链——即 PRD §4.10.8 点名「至少要写清」的三件）。
- **文案与台账顺带修**：「最后使用」空值显「从未使用」（与「过期时间」拆键）；删除成功提示明示动作后果；权限位内部码（`knowledge:read`）两端翻译为人话；platform 台账吊销加确认、「按持有人吊销」与「吊销」合并、补分页。

**本次明确排除：**

- **部署级数据范围配置**——D21 已否决两层方案：能力开关默认关已承担「升级不静默开出口」，数据范围属租户自治；不要再提回。
- **动态范围清单**——只做静态四态文案；可见清单与可检索范围存在口径差（QA 库可见但检索面拒收、v2 空间清单不含部门空间），动态展示反而误导。
- **文件创建者下探过滤**（personal_strict 档）——残余风险（本人库 / 空间内他人添加的内容仍可检索）已确认接受，且**界面不做提示**；更严档位待真实客户诉求另立 feature。
- **技能包打包期动态渲染租户配置**——分发端点匿名、打包时不知租户，且配置运行期可变；范围事实源只有运行期清单端点与 `26044`。
- **技能包 P1/P2 余件**——`meta.json`、版本自检、凭据配置文件回落、`--tag`/`--max-content` 参数化，另批偿还。
- **存量令牌 TTL 回溯、一人多把令牌、按 Agent 独立吊销**——维持 PRD 既有裁定。

## 3. 验收标准

**PRD 侧（唯一真相在 PRD v2.9 §五 R10，本 feature 全部承接）**：**AC-P23～AC-P31** 共九条——默认档行为不变 / 收窄语义与 5 秒生效 / 归属粒度边界 / 管理员同收窄且签发确认降级 / `knowledge:read` 全端点覆盖 / 策略变更审计 / 命名与警示改写 / 双入口与关停态 / 展示弹窗四态。另：AC-P17 的「默认数据范围下验收」限定随本 feature 生效。

**工程侧补充验收：**

- **AC-R1 滚动升级与回滚兼容**——WHILE 新旧版本进程混跑（滚动升级或回滚窗口），THE SYSTEM SHALL 对升级前已存在、且升级后未重新保存过的租户策略按默认「全部可见」生效：不得出现整租户被误收窄或误拒绝；旧版本进程读写租户策略不得因新增配置而出错。
- **AC-R2 26044 呈现与防枚举**——IF 收窄档下令牌访问范围外资源, THEN THE SYSTEM SHALL 返回 HTTP 403 + 业务码 `26044`，响应不携带被拒资源的标识或存在性信息；多库检索请求任一越界即整单失败（沿用既有语义，不静默剔除）；清单类端点静默收窄、不报 `26044`。
- **AC-R3 覆盖矩阵防回归**——THE SYSTEM SHALL 保证 `knowledge:read` 位下每个已登记端点在（普通员工 / 租户管理员 / 全局超管持有的令牌）×（全部可见 / 仅限自建）全部组合下的行为均有自动化验收；IF 该权限位下新增端点而未纳入上述覆盖, THEN 相关测试套件 SHALL 失败（防新端点静默绕过收窄）。
- **AC-R4 技能包端到端**——WHEN 从匿名分发端点下载技能包, THE SYSTEM SHALL 产出含更新后 `SKILL.md`（中文触发词 + 先清单后检索流程）与 `references/api.md` 的 zip；`search.py` 收到非 2xx 响应时向调用方输出响应体中的业务码与 `status_message`（不再只有一句 `HTTP Error 403`）；打包服务除既有占位符渲染外零逻辑变更。
- **AC-R5 i18n 三语与键族收敛**——THE SYSTEM SHALL 以新键族交付全部新界面文案（三语同 PR、`check-i18n` 通过）；旧「个人 API 令牌」键族随组件改造下线，不残留双轨文案；`26040` 文案按新命名口径更新、`26044` 三语新增（api_errors 域，产物文件不手改）。
- **AC-R6 策略审计可查**——WHEN 管理端保存租户策略, THE SYSTEM SHALL 在操作审计中留一条含操作人、变更前后三字段值的记录；仅当值实际变化时记录；不新增任何逐调用表。
- **AC-R7 深链连续性**——WHEN 用户经深链访问「AI 助手接入」分区并携带连接参数, THE SYSTEM SHALL 直接拉起签发弹窗；更名迁移后，此前已复制分发的安装提示词中的密钥获取地址 SHALL 保持可达（旧参数继续生效或跳转到新参数，不得断链）。

## 4. 非目标

- 不改服务账号密钥的任何行为——数据范围只作用于自然人令牌主体；关 PAT / 收窄 PAT 不得影响 `bs-sak-`（INV-34 既有半边继续成立）。
- 不引入密钥级资源白名单（PRD D3 维持）；不做部署级数据范围；不改 `knowledge:read` 之外权限位的行为。
- 不新增 UI / 状态管理库；client 与 platform 两端组件不得互相 import；不使用 `backdrop-filter`。
- 不改技能包打包 / 分发的后端逻辑与端点路径；不做 MCP 面。
- 不回溯改写存量令牌的过期时间（AC-P2a 维持）。

## 5. 验证要求

- 后端单元 / 契约测试覆盖 AC-P23～P28 与 AC-R1～R3、R6、R7；收窄覆盖矩阵用权限位注册表驱动生成用例集（注册表新增端点即用例缺口、测试失败）；新增测试放 `test/open_api/`；MySQL + Redis + OpenFGA 集成用例进 CI 既有分组；Alembic 新迁移遵守单头纪律（`alembic heads` 实跑为准）。
- client 与 platform 分别通过 `pnpm lint`、`pnpm typecheck` 与相关组件测试；三语 key parity（`pnpm check-i18n`）通过。
- 执行 `/e2e-test features/v3.0.0-beta1/066-pat-data-scope-and-ai-access`：API 侧输出覆盖矩阵结果；浏览器侧输出双入口、弹窗四态、管理端收紧确认的手动验证清单。
