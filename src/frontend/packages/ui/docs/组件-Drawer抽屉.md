# 抽屉 Drawer

> 设计系统 · v1 · 2026-08-04
> 适用：从窗口右侧滑入的面板，响应式 Web 三档（手机 / 平板 / 桌面）。
> 通用规则见 [基础-多端适配原则.md](基础-多端适配原则.md)、[基础-阴影与圆角规范.mdx](基础-阴影与圆角规范.mdx)；本文只写抽屉自己的细则。

抽屉从窗口右边缘滑入，盖住一部分页面。它和弹窗的区别只有一个：**抽屉留着页面的边，弹窗不留**。用户始终看得见自己刚才在哪，关掉就回去。

## 1. 什么时候用抽屉

用抽屉：**这件事是当前页面的一个子任务，做完要回到原处**。创建知识空间、编辑频道、查看版本历史，都是。

不用抽屉，改用别的：

| 情况 | 用什么 | 为什么 |
|---|---|---|
| 只需要用户答一句「是 / 否」 | 二次确认弹窗 | 一句话的事不值得开一整块面板 |
| 内容是一段独立的信息，有自己的地址、要能分享 | 独立页面 | 抽屉没有网址，也接不住浏览器的返回键 |
| 只有几行文字或两三个操作 | 气泡卡片 Popover | 抽屉的开合动作比内容还重 |
| 需要用户立刻处理完才能继续 | 弹窗 Modal | 弹窗居中夺焦，抽屉的语气太轻 |

**一次只开一个抽屉。** 抽屉里不能再开抽屉——两层面板叠着，用户数不清关几次才回得去。抽屉里可以开二次确认弹窗，那是一问一答，不算一层。

## 2. 两种类型

| 类型 | 有遮罩 | 主内容区 | 用在哪 |
|---|---|---|---|
| **模态抽屉**（默认） | 有 | 被盖住，不能操作 | 绝大多数场景。创建、编辑、填表 |
| **非模态抽屉** | 无 | 被推窄，仍可操作 | 需要一边看主内容一边改的场景。如属性面板、筛选面板 |

**非模态抽屉推开主内容，不盖在上面。** 既然允许用户继续操作，就不能有一半是看不见的。

**非模态抽屉只有 small 一档（400px）**，因为它会长时间占着屏幕。窗口窄于 1024px 时，非模态自动变成模态——空间不够并排，硬并排两边都不好用。

## 3. 宽度三档

| 档位 | 宽度 | 装什么 |
|---|---|---|
| small | **400px** | 单列表单、筛选项、列表（版本历史、成员列表） |
| medium | **600px** | 分组表单、带表格的内容 |
| large | **800px** | 多列表单、需要预览区的内容 |

**按内容的横向复杂度选档，不按内容长短选档。** 内容长的解法是滚动，不是加宽——加宽只会让每行文字变长、更难读。

单列表单一律用 small：一行输入框超过 400px 宽，用户的视线要横扫很远才找得到下一个字段。

> 抽屉不设全屏档。真出现「需要并排两栏 + 完整表格」的场景，那件事本身应该是一个独立页面。

## 4. 窗口变窄时逐级降档

抽屉宽度**不随大屏变宽**，只随小屏降档。桌面档内部按窗口宽度降一档：

| 窗口宽度 | small | medium | large |
|---|---|---|---|
| ≥ 1280px | 400 | 600 | 800 |
| 1024–1280px | 400 | 600 | **600** |
| 768–1024px | 400 | **400** | **400** |
| 576–768px（平板） | 400 | 400 | 400 |
| < 576px（手机） | 见 §7 移动端适配 | | |

另有一条兜底，任何情况都生效：**抽屉最宽不超过 `窗口宽度 - 96px`**。这 96px 是留给主内容的最后一条边——看得见它，用户才知道自己没有跳走。

大屏不加宽的原因：抽屉占屏幕多少，应该由用户拖窗口来决定，而不是由屏幕尺寸替他决定。24 寸显示器上把 800px 的表单拉成 1400px，只会让每行更难读。

## 5. 结构与间距

抽屉贴住窗口右边缘和上下边缘，**四角直角、通高**（圆角规则见 [基础-阴影与圆角规范.mdx](基础-阴影与圆角规范.mdx) §1.4）。

从上到下三段：

| 区域 | 内边距 | 说明 |
|---|---|---|
| 头部 Header | 高 56px，左右 20px | 标题 16px / 字重 500，左对齐；关闭按钮 24px，靠右 |
| 主体 Body | 20px | 内容装不下时**只有这里滚动** |
| 底部 Footer | 上下 12px，左右 20px | 上方一条分隔线；没有操作按钮时整段不出现 |

**头部和底部始终固定，只有主体滚动。** 用户滚到哪里都能看见标题和「保存」，不用滚回去找。

底部按钮的对齐方式见 [基础-多端适配原则.md](基础-多端适配原则.md) 布局惯例表。

## 6. 打开与关闭

滑入 **240ms**，滑出 **200ms**。出场比入场快一点——用户关闭时已经做完决定了，等待是纯粹的浪费。

模态抽屉给三条关闭路径，**一条都不能少**：

1. 头部的关闭按钮
2. 点击遮罩
3. 按 Esc 键

**抽屉里有没保存的内容时，三条路径都要先弹二次确认。** 填了十分钟的表单，不能因为手滑点到遮罩就没了。

非模态抽屉只保留关闭按钮：它没有遮罩可点，也不该抢走 Esc——用户此刻可能正在操作主内容区。

焦点：模态抽屉打开时焦点移入抽屉、Tab 在抽屉内循环，关闭后焦点回到打开它的那个按钮。非模态抽屉不做这些，Tab 照常走完整个页面。

## 7. 移动端适配

**手机档（< 576px）抽屉改为从底部上滑。** 手机没有「侧边」可言，从右侧滑进来只会铺满整屏；而且抽屉的关闭按钮在右上角，正是单手最够不着的位置。改从底部上滑，也和 BISHENG 弹窗在手机上的做法一致（见 [基础-多端适配原则.md](基础-多端适配原则.md) 布局惯例表）。

| 项 | 值 |
|---|---|
| 高度 | 默认 60% 屏高，最高 90%；内容不足时按内容高 |
| 圆角 | 仅顶部两角 16px |
| 拖拽条 | 32×4px，居中，距顶 8px |
| 底部按钮 | 等宽平铺占满一行，并避开手机底部安全区 |

**顶部必须露出一条主内容**，别让高度顶到 100%。那条缝就是「你还在原来的页面上」的全部凭据——铺满了，用户会以为自己跳到了新页面，然后去按返回键。

**拖拽条现在只是视觉提示，不能拖。** 它告诉用户这是一块浮层，真正的关闭走关闭按钮和点击遮罩。手势关闭在手机上很容易和系统的上滑返回、下拉通知栏打架，先不做；等做了，也必须保留可见的关闭按钮。

其余通用规则（触屏不显示 hover、可点范围 ≥ 44×44px、控件文字不放大）见 [基础-多端适配原则.md](基础-多端适配原则.md)。

## 给实现窗口（技术细节，设计师可跳过）

- **降档断点用 1024 / 1280**，即 Tailwind 的 `lg:` / `xl:`。二者属桌面档（>768）内部的细分排版，不是新增档位断点，符合[基础-多端适配原则.md](基础-多端适配原则.md)「不自造断点」。档位断点仍只有 576 / 768 两个。
- 宽度实现：`width: min(<档位>, calc(100vw - 96px))`，降档表用 `lg:` / `xl:` 前缀覆盖，不写 JS 计算。
- 非模态推开主内容：主内容容器加 `margin-inline-end` 或改 grid 列宽，**不要用 `transform`**——`transform` 会让内部的 `position: fixed` 子元素（下拉、气泡）定位错乱。
- 非模态 <1024px 转模态：用 `useMediaQuery` 判断后切换渲染分支，不要两套都挂载。
- 滚动：body 区 `overflow-y: auto` + `overscroll-behavior: contain`，防止滚到底后把页面一起带滚。
- 移动端底部形态与 AlertDialog 底座现有做法一致（贴底、仅顶部圆角），可直接复用其位移动画；安全区用 `padding-bottom: calc(12px + env(safe-area-inset-bottom))`，需 `viewport-fit=cover`。
- 无障碍：模态 `role="dialog"` + `aria-modal="true"` + `aria-labelledby` 指向标题；非模态不加 `aria-modal`。焦点归还触发元素。
- 动效曲线：进出统一 `cubic-bezier(0.2, 0, 0, 1)`；240ms / 200ms。
- 遮罩与层级**不在本文定义**，随[组件-Modal弹窗.md](组件-Modal弹窗.md)统一（当前 z 有 50 / 100 / 110 三档并存，抽屉接入时一并收敛）。
- 现有抽屉类实现（待盘点确认）：`CreateKnowledgeSpaceDrawer`、`CreateChannelDrawer`、`VersionHistorySheet`、`RelateDocumentPanel`。
- 新页上线：本文需在 `src/frontend/client/rspress.config.ts` 的 `themeConfig.sidebar` 注册入口，改完重启 dev 服务。
