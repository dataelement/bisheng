# F062 部门与角色模型授权修订

日期：2026-09-14。

## 已实现规则

- 租户管理员在“模型管理 → 工作台模型授权”查看当前租户的完整有效部门树，以及当前租户可用的租户角色和全局角色。
- 每个模型分别给部门或角色配置“可调用”状态和成员每月 Token 额度。选择上级部门时包含全部下级部门；当前成员及后续加入的成员都按实时组织关系继承。
- 用户命中任意部门、角色或兼容保留的直接用户授权即可使用模型。多条授权同时命中时，选择其中最高的月度 Token 额度，不叠加。
- 额度继续按“租户 + 用户 + 模型 + 北京时间自然月”独立计算。部门与角色只提供授权来源，不形成共享 Token 池。
- 部门成员关系、角色成员关系和授权策略在新请求中即时解析。历史请求、历史用量和正在执行的请求继续保留。
- 模型授权不分配席位；用户实际完成桌面工作台登录时才按既有固定席位规则占用席位。
- 每次部门或角色策略变更保存操作者、目标、前后值、版本和时间。版本冲突要求管理界面刷新后再提交。

## 数据与接口

- `dsh_subject_policy`：每个“租户 + 主体类型 + 主体 + 模型”一行，保存额度、启用状态、版本和更新人。
- `dsh_subject_policy_audit`：逐次保存不可覆盖的前后值与操作者证据。
- `GET /api/v1/dsh/admin/models/{model_id}/subjects`：返回按父子顺序排列的部门树和角色列表，以及各主体在当前模型上的策略状态。
- `PUT /api/v1/dsh/admin/models/{model_id}/subjects/{subject_type}/{subject_id}/policy`：按 `expected_version` 更新单个部门或角色策略。
- 运行时模型列表、模型调用准入、SQL 投影、持久化用量读取和 Redis 账本恢复统一读取同一个有效策略解析结果。

## 额度一致性

部门或角色授权不会为每位成员预先生成用户策略行。模型请求将当前有效最高额度传入 Redis 原子准入脚本；脚本继续使用已经持久化的“用户 + 模型 + 月份”计数，并在新授权模型第一次使用时安全初始化独立计数。Redis 自动恢复模式先读取当前账本代次，准入返回的事件作为后续结算的唯一事件，保持授权来源切换前后的账本一致。

兼容保留原用户级授权接口和历史记录。直接用户授权与部门、角色授权同时存在时也执行最高额度规则，便于已有测试数据和未发布环境平滑衔接。

## 本地验证与边界

- 部门/角色策略、父部门继承、后加入成员、角色重合、直接授权重合、最高额度、审计、版本冲突和仅主体授权用量投影专项通过。
- 不依赖外部数据库的 DSH 后端回归 347 项通过、30 项按 Redis 重启或隔离 MySQL 等条件跳过、65 项外部数据库变体按筛选未运行；其中专用真实 Redis 覆盖动态有效额度、新模型计数初始化、账本代次切换、模型调用结算和自动恢复。
- Platform DSH 相关 17 个测试文件共 89 项通过；三语言一致性检查和生产构建通过。本轮新增 TypeScript 错误为 0；全项目严格类型检查仍保留两个目标分支既有测试错误。
- 本记录证明源码实现和本地自动验证。真实租户组织数据、真实 Desktop 登录与模型调用、DM8 真库、部署环境和原生交互验收分别保持 `NOT_RUN`。
