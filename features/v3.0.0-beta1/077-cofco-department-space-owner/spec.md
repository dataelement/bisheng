# Feature: 中粮部门知识空间负责人使用所有者权限

**状态**：用户已确认负责人交接口径并于 2026-10-21 要求直接开发；代码已实现，后端定向回归通过，镜像及环境验收待执行。
**需求依据**：用户于 2026-10-21 明确要求部门知识空间负责人具有所有者权限，并确认“转给新负责人，原负责人恢复原有成员权限”。
**优先级**：P1。
**所属版本**：v3.0.0-beta1，中粮定制分支 `feat/cofco-1021-3.0.0-beta1`。
**依赖**：部门空间唯一负责人、F048 资源权限、F050 权限设置。

## 1. 用户故事与范围

作为部门知识空间负责人，我需要拥有系统定义的完整所有者权限，页面显示与实际权限一致；更换负责人时，该负责人身份对应的所有者权限交给新负责人。

纳入新建、补配、更换、失效处理和存量部门空间负责人校准。该规则只适用于中粮部门知识空间；普通知识空间、频道及其他资源沿用现有规则，定制功能不回流主版本。

实际创建操作人的身份和创建事实继续保留用于审计，不能因负责人更换而改写。此处不新增通用所有者转移功能，也不移除其他来源的独立有效授权。

## 2. 验收标准

- **AC-01** — WHEN 创建部门知识空间或为待配置空间补配有效负责人, THE SYSTEM SHALL 使该负责人获得系统既有所有者权限，而非仅管理员权限。
- **AC-02** — WHEN 查看部门空间权限设置或成员权限, THE SYSTEM SHALL 将负责人权限展示为“所有者”，不将其负责人身份标记为“创建者”；展示与实际授权结果一致。
- **AC-03** — WHEN 超管将负责人由 A 更换为 B, THE SYSTEM SHALL 将负责人身份对应的所有者权限从 A 转给 B；A 原先已有成员权限时恢复原权限，否则移除其负责人带来的访问权限。
- **AC-04** — WHEN 更换负责人, THE SYSTEM SHALL 保留 A、B 通过其他独立来源获得的有效权限，并保持实际创建操作人的审计事实不变。
- **AC-05** — IF 新负责人无效、跨企业或并发更换发生冲突, THEN THE SYSTEM SHALL 明确拒绝该请求，保持既有有效负责人和权限不变，不留下新旧负责人均持有负责人身份的结果。
- **AC-06** — WHEN 负责人因停用、删除或移出企业而失效, THE SYSTEM SHALL 撤销负责人身份带来的所有者权限并进入待配置状态，保留既有待配置期间的访问和审批限制。
- **AC-07** — WHEN 对存量部门空间执行负责人权限校准, THE SYSTEM SHALL 依据当前有效负责人恢复所有者权限并清除历史负责人身份遗留的权限；重复执行不改变既有正确结果。
- **AC-08** — IF 权限变更失败或超时, THEN THE SYSTEM SHALL 保留可核对、可重试的状态，不以页面显示成功代替实际授权成功；重试后负责人、权限和审批人保持一致。
- **AC-09** — THE SYSTEM SHALL 继续保留超管隐式治理身份隐藏、唯一配置负责人、企业隔离及负责人更换后的审批人更新规则。
- **AC-10** — THE SYSTEM SHALL 保持普通空间、频道及其他资源的创建者保护和所有者规则不变，既有列表性能优化不受影响。

## 3. 边界

- 对同一负责人重复保存或重复校准，不产生重复所有者授权，不丢失其原有成员权限。
- 新负责人原先已是成员、拥有独立授权或曾担任该空间负责人时，仍按实际原有权限处理。
- 待配置空间没有负责人时，不凭空指定创建操作人或超管为负责人。
- 存量校准应保留历史创建审计；执行方式、试运行和核对方法在设计中明确，本次本地开发不直接操作 105 数据。

## 4. 与现有规格的关系

本规格仅覆盖中粮部门空间的负责人权限口径，替代旧部门空间规格中“负责人按管理员处理”和“不涉及所有者转移”对本场景的约束。F048 通用资源的创建者保护规则保持原状；部门负责人变更属于此定制场景的专用业务规则。
