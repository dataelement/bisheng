# Feature: 预置 Skill 前端隐藏（隐藏但强制下发）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
> spec 只回答 **做什么 / 验收标准 / 不做什么**;How 在 [design.md](./design.md) 与 [tasks.md](./tasks.md)。

**关联 PRD**: 中粮 cofco 需求(2026-08-17 会话:需求文本 + 管理后台截图 + 三态行为矩阵)
**优先级**: P0
**所属版本**: v2.6.0(cofco 分支)
**依赖**: F035-linsight-task-mode(`LinsightSkill` 领域对象归其所有,本 feature 在其上加字段,属协同改动)

> **范围边界**
> - **本次纳入**：
>   - 管理后台技能管理为每个 Skill 增加【前端隐藏】开关(独立于【启用状态】)
>   - 开启【前端隐藏】时,同一次保存自动开启【启用状态】
>   - 隐藏的 Skill 在业务前台不可发现、不可查看、不可手动选择/取消
>   - 任务模式:隐藏且启用的 Skill 由**服务端强制加入本次运行的已选 Skill** 并随模型请求下发(用户未选任何技能时同样强制加入)
>   - 配置按租户/部署范围生效(中粮专版自行配置,不影响标品及其他租户)
> - **本次明确排除**：
>   - 不做代码级预置种子——docx/pptx/xlsx 三个 Skill 的隐藏配置由超管在中粮环境的管理后台操作(交付时可代为点上)
>   - 不改变【停用】语义:停用优先于隐藏,停用即禁止下发
>   - 日常对话模式无技能链路,不涉及

---

## 1. 用户故事

A. 作为**中粮专版超级管理员**,我希望把 Office 文档处理等内部能力型 Skill 设为前端隐藏,以便业务用户看不到、也不用理解这些实现细节。

B. 作为**业务用户**,我在任务模式提交任务时无须(也无法)选择这些内部 Skill,但文档处理能力始终可用——隐藏对我完全透明。

C. 作为**标品/其他租户的管理员**,我的技能可见性规则不因中粮的配置发生任何变化。

---

## 2. 验收标准

### 2.1 配置(管理后台)

- **AC-01** — THE SYSTEM SHALL 在技能管理列表为每个 Skill 提供【前端隐藏】开关,与【启用状态】并列独立展示,超管(租户管理员)可随时开关。
- **AC-02** — WHEN 超管开启【前端隐藏】, THE SYSTEM SHALL 在同一次保存中自动将该 Skill 的【启用状态】置为开启。
- **AC-03** — THE SYSTEM SHALL 允许对已隐藏的 Skill 执行停用;停用后按【停用】行为矩阵处理(前台后台均按停用规则,禁止下发)。
- **AC-04** — WHEN 超管关闭【前端隐藏】, THE SYSTEM SHALL 恢复该 Skill 的既有可见与手动选择规则,不改变其启用状态。

### 2.2 业务前台隐藏

- **AC-05** — WHILE 某 Skill 处于【前端隐藏】, THE SYSTEM SHALL 使其不出现在业务前台的技能选择器、搜索与任何详情/状态入口中;用户不可手动选择或取消。
- **AC-06** — THE SYSTEM SHALL 保证隐藏 Skill 不在任何面向业务用户的回显中出现(会话中的已选技能展示、历史回放等)。
- **AC-07** — 管理后台不受隐藏影响:隐藏 Skill 在技能管理列表中照常可见、可编辑、可开关。

### 2.3 任务模式强制下发

- **AC-08** — WHEN 用户在任务模式发起运行, THE SYSTEM SHALL 由服务端把全部【前端隐藏且启用】的 Skill 自动并入本次运行的已选 Skill 并随模型请求下发——包括用户未选择任何技能的运行。
- **AC-09** — WHILE 某 Skill 同时处于【前端隐藏】与【停用】, THE SYSTEM SHALL 禁止其下发(停用优先)。
- **AC-10** — THE SYSTEM SHALL 保证隐藏不改变 Skill 的执行能力与行为——隐藏前后,该 Skill 对模型可用的内容一致。

### 2.4 范围

- **AC-11** — THE SYSTEM SHALL 使【前端隐藏】配置按租户(部署)生效:一个租户的配置不影响其他租户与标品默认行为。

---

## 3. 边界情况

1. **用户显式传入隐藏 Skill 名称**(构造请求):不视为错误——该 Skill 本就会被强制加入;但不得因此绕过其他 Skill 的启用校验。
2. **隐藏 Skill 被删除**:照常删除,強制下发集合随之收缩,不留悬挂。
3. **隐藏与启用的并发切换**:以最后一次保存为准,任一落库状态都必须符合行为矩阵(不存在"隐藏且未启用却仍下发"的状态)。
4. **运行进行中修改配置**:对已开始的运行不追溯,下一次运行生效。
