## 1. 什么时候用

下拉菜单把**一组相关的动作**收进一个按钮里，点开再选。点完就执行，触发器本身不变。

- 卡片、列表行、表格行上的次要操作（重命名、复制、移动、删除），收进「⋯」菜单。
- 一个按钮有几种做法（「新建」→ 新建文档 / 新建文件夹），用带下箭头的按钮。
- **要选一个值、选完回显在框里，用选择器**，不用下拉菜单（判别见 [组件-Select选择器.md](组件-Select选择器.md) §1）。
- **少于 3 项不做菜单**：一两个动作直接放成按钮，点开菜单就为看两项不值得。
- **主要操作不藏进菜单**：页面最常用的动作要一眼看得见，菜单只放次要的。

| ✅ 推荐 | ❌ 不推荐 | 原因 |
|---|---|---|
| 「编辑」放成按钮，重命名、复制、删除收进「⋯」 | 编辑、重命名、复制、删除全收进「⋯」 | 最常用的编辑被藏起来，用户要先猜它在哪 |
| 只有「删除」一个动作时直接放删除按钮 | 「⋯」点开只有一项「删除」 | 多点一次只换来一个选项 |
| 切换排序方式用选择器 | 「排序 ▾」点完框里还是「排序」 | 当前排序是状态，用户要看得见 |

## 2. 结构 Anatomy

| 部分 | 是什么 |
|---|---|
| 触发器 | 打开菜单的元素：带下箭头的按钮、「⋯」图标按钮、文字链 |
| 面板 | 浮层，外壳同选择器面板 |
| 菜单项 | 一行一个动作，可带前缀图标、快捷键 |
| 分组标题 / 分隔线 | 给动作归类 |
| 子菜单 | 某一项展开出的第二层面板 |

## 3. 触发器

| 形态 | 什么时候用 | 画法 |
|---|---|---|
| **「⋯」更多按钮** | 卡片、行内的次要操作 | 图标按钮，`Outlined.More`，尺寸跟所在位置的按钮档 |
| **按钮 + 下箭头** | 一个动作有几种做法（新建、导出） | 任意按钮类型，文字后跟 `Outlined.Down`，间距同按钮图标间距 |
| **文字链 + 下箭头** | 工具栏、标题旁的轻量入口 | 文字按钮 + 下箭头 |
| **只有下拉箭头** | 贴在主按钮或标题旁，放「同一件事的其他做法」（「发送 ▾」里的定时发送） | `Outlined.Down` 图标按钮，与主按钮拼成组合按钮，或紧贴标题 |

- **只有箭头的触发器不单独出现**，必须贴着它所补充的主按钮或标题；读屏标签写清楚，如「更多发送方式」。
- **与主按钮拼成组合按钮时，两半画成一个按钮**：共用一圈描边、中间 1px 分隔线（描边款就是那条共用的描边，实底款是一条 30% 白线）、圆角只留外侧四角；两半尺寸与颜色一致，各自悬停、各自按下。只做描边与实底两种画法。菜单默认与箭头右边对齐。
- **选完之后旁边的文字跟着变（如 GitHub 合并按钮选完合并方式，主按钮文字随之改变）就不是下拉菜单，是选择器**——值显示在了旁边元素上，见 [组件-Select选择器.md](组件-Select选择器.md) §3.1。
- 触发器用的都是现成的按钮，尺寸、颜色、状态照 [组件-Button按钮.md](组件-Button按钮.md)，本文不另定义。
- **菜单开着时，触发器保持悬停态**，让用户知道面板是从哪里出来的；下箭头旋转 180°。
- 「⋯」按钮在行内可以只在悬停该行时出现，但**菜单开着时必须常驻**，否则面板像是凭空浮着。

## 4. 面板与菜单项

外壳（底色、投影、12px 圆角、6px 内边距、层级 1100）、32px 选项行、分组标题、分隔线全部照 [组件-Select选择器.md](组件-Select选择器.md) §5。下拉菜单的差异只有这几条：

| 项 | 规则 |
|---|---|
| 宽度 | 随内容，**最小 120px、最大 280px**；不与触发器等宽——「⋯」只有 24px 宽 |
| 最大高度 | 同选择器 296px（8 行）；动作菜单本该很短，滚动出现说明该拆了 |
| 前缀图标 | 16px，与文字间距 8px；**同一组要么都有、要么都没有** |
| 快捷键 | 可选，放最右，12 / 20 `text-3`；与文字间距 ≥ 24px |
| 分组 | 不超过 3 组，组间用分隔线 |
| 圆角 | 面板默认 `xl`，可换 `sm`–`4xl` 任一档圆角 token，选项行自动同心；规则同 [组件-Select选择器.md](组件-Select选择器.md) §5.4，不写样式覆盖。触发器是按钮，圆角归 [组件-Button按钮.md](组件-Button按钮.md) |

### 4.1 菜单项文案

- **用动词开头**：「重命名」「移动到…」「导出为 PDF」，说清点了会发生什么。
- **点了还需要用户再输入或再选择的，文案后加「…」**：「移动到…」「另存为…」。直接执行的不加。
- 文案细则照 [基础-文案规范.md](基础-文案规范.md)。

### 4.2 排序

- **常用的放上面**——用户从上往下扫。
- 相关的放一组：编辑类一组、移动类一组。
- **危险项放最后，单独一组**（§5）。

## 5. 危险项

删除、移除、清空这类不可逆的动作：

- **文字用危险红**，前缀图标同色；悬停底色换成危险色浅底。
- **放在菜单最后，与上面用分隔线隔开**——离常用项最远，最不容易误点。
- **点了先弹二次确认**，确认弹窗用 useConfirm（见 [组件-Confirm二次确认.md](组件-Confirm二次确认.md)）；菜单先关闭，再弹确认。不做气泡式确认。

| ✅ 推荐 | ❌ 不推荐 | 原因 |
|---|---|---|
| 「删除」红字，放最后一组 | 「删除」夹在「重命名」和「复制」中间 | 手一滑就点到，且和普通动作长得一样 |
| 点「删除」→ 关菜单 → 弹确认 | 点「删除」直接删掉 | 菜单项离得太近，误点概率高，不可逆的动作必须确认 |

## 6. 状态 State

| 状态 | 样式 |
|---|---|
| 常态 | 透明底，`text-1` |
| 悬停 / 键盘高亮 | 浅灰底 `fill-2`，同选择器 |
| 禁用 | 文字与图标 `text-4`，无悬停，「禁止」光标；**置灰，不隐藏**——让用户知道有这个动作，只是现在用不了 |
| 危险项悬停 | 危险色浅底，文字保持危险红 |
| 开关项 | 少数「开 / 关某个设置」的项（如「显示已归档」）：开着时右侧 16px 品牌色 ✓，画法同选择器选中项 |

- 禁用项最好在悬停时用文字提示说明原因（「无编辑权限」），否则用户不知道怎样才能用。
- 开关项只是菜单里的点缀；一整个菜单都在挑同一个值时，那是选择器。

## 7. 触发与交互

- **默认点击触发**：点触发器打开，点外部、按 ESC、再点一次触发器关闭；ESC 关闭后焦点回到触发器。
- **可选悬停触发**，只给导航栏、工具栏里「扫一眼有什么」的菜单：指针进入 100ms 后打开，可以移进面板操作，移出触发器与面板后关闭。时长与文字提示共用一套（见 [组件-Tooltip文字提示.md](组件-Tooltip文字提示.md) §6）。
- **点了菜单项：先关菜单，再执行**。要开弹窗的，菜单关掉再开，不让两层浮层叠着。
- 位置：默认在触发器下方、左边对齐；**触发器靠右（如卡片右上角「⋯」）时右边对齐**；空间不够自动翻转，不盖住触发器。
- 键盘：上下键移动高亮，回车执行，右键进入子菜单、左键退出；敲字母跳到首字匹配的项。
- 动效与选择器同一组：淡入 150ms + 4px 位移，淡出 100ms。

### 7.1 子菜单

- **最多一层**，子菜单里不再有子菜单。
- 父项右侧放 16px `Outlined.Right`（`text-3`）；悬停或键盘右键 100ms 后打开，父项保持高亮。
- 子面板外壳同主面板，在父项右侧，与主面板间距 4px，首项与父项顶边对齐；右侧放不下翻到左侧。
- **子菜单项控制在 5 个左右**；更多说明该单独做一个菜单或换成弹窗。
- 父项的文案要能让人猜到里面是什么：「移动到…」「导出为」。

## 8. 移动端适配

通用原则见 [基础-多端适配原则.md](基础-多端适配原则.md)，这里只写下拉菜单自己的：

| 项 | 规则 |
|---|---|
| 悬停触发 | 触屏没有悬停，一律降级为轻点触发 |
| 「⋯」按钮 | 触屏上常驻显示，不依赖悬停出现；热区 ≥ 44×44px |
| 面板（手机档 < 576px） | 改为从底部滑入的面板，宽度铺满，顶部两角 12px、底部直角；菜单项高 44px |
| 子菜单（手机档） | 点父项进入下一页，顶部带返回，不在旁边再弹一层 |
| 平板 / 桌面 | 与桌面一致，挨着触发器弹出 |

## 9. 深浅色

与选择器面板同一套，见 [组件-Select选择器.md](组件-Select选择器.md) §10：颜色走 token 自动翻转，深色下面板加 1px `border-base` 描边。危险红与危险浅底随功能色深色阶翻转，不单独取值。

## 落地（给实现窗口）

1. **组件位置**：`packages/ui/src/components/Dropdown/`，基座 `@radix-ui/react-dropdown-menu`（menu 语义、焦点管理、子菜单内置）。对外 `Dropdown` + `DropdownItem` / `DropdownGroup`（带 `label`）/ `DropdownSeparator` / `DropdownSub`；`trigger="click" | "hover"`，默认 `click`；`DropdownItem` 的 `danger` / `disabled` / `icon` / `shortcut` / `checked`（开关项）。
2. **面板与菜单项样式与 Select 共用**（含 `panelRadius` 与选项行圆角派生映射，见 Select 落地 7a）：把 Select 落地第 3 条的外壳与选项行 class 抽成 `packages/ui/src/components/shared/menuSurface.ts`（或同等位置），Select 与 Dropdown 同引一份，禁止两边各写。差异：宽 `min-w-[120px] max-w-[280px]`、不设 trigger 宽度；`align` 由调用方传 `start | end`，`sideOffset=4`；`collisionPadding=8`。
3. **危险项**：`text-danger`，`data-[highlighted]:bg-danger-tint`（token 名以 `design-token.cjs` FUNCTIONAL 的 danger / danger-tint 为准）。组件不内置确认弹窗——由调用方在 `onSelect` 里调 `useConfirm`；但 `danger` 项在 dev 下若 `onSelect` 同步返回且未调 confirm 不做检测，靠评审。
4. **子菜单**：`SubContent` `sideOffset=4`、`alignOffset=-6`（抵掉面板 6px 内边距，首项与父项顶边对齐）；SubTrigger 右侧 `Outlined.Right` 16px `text-text-3`，`data-[state=open]:bg-fill-2`。Radix 子菜单开启延时默认即约 100ms，不另调。
5. **悬停触发**：Radix DropdownMenu 不内置 hover，用受控 `open` + 触发器 / 面板的 pointerenter/leave 封装，时序常量与 Tooltip 共用（进入 100ms、离开宽限 100ms）；`(hover: none)` 下忽略 `trigger="hover"`。
6. **移动端**：`< 576px` 面板改走底部面板形态（与 Select 落地第 6 条同一实现），子菜单改为面板内二级页。
