# 前台租户隔离与应用广场修复记录

用户变更所属租户后，旧租户资源仍归原租户，不能因创建人相同而继续出现在当前租户的前台。此次修复统一收窄业务请求范围，修复应用广场失败后的循环加载，并补齐标签相关读写的租户边界。修复保存在独立分支，本次不部署，也不修改 116 的业务数据或权限投影。

## 根因与修复

| 范围 | 原因 | 修复后的行为 |
| --- | --- | --- |
| 我创建的空间、知识广场、频道发现与公开详情、应用和标签查询 | 普通用户的请求边界重新加入 Root，实际查询范围变成当前租户与 Root 的并集 | `bind_admitted_scope` 保持已确认的单一租户；创建者记录不会绕过资源归属。用户从 Root 转到 Child 或在两个 Child 之间变动时，旧资源不迁移、不展示 |
| 应用权限候选 | 单条候选的业务证明读取到异常投影，在正式批量权限检查前抛出 25008，阻断整页 | 对无法证明的单条候选拒绝授予任何动作并记录告警，正常候选继续检查；单资源访问仍拒绝，意外的数据库或运行时失败仍传播 |
| 应用广场加载 | 失败后 `hasMore` 仍为真，观察器持续重试；过期请求还可能清掉新筛选条件下的加载状态 | 失败后停止自动翻页并展示重试；保留已加载卡片和失败页游标；游标缺失、重复或空页仍宣称可继续时停止；旧请求不能修改当前筛选条件的加载状态 |
| 首页应用分类选择 | 所有租户改写全局 `config.home_tags` | 使用已有 `tenant_workstation_config` 的 `home_tags` 键保存本租户选择；没有覆盖记录时保留旧全局排序，但只读取本租户标签；外租户标签 ID 写入返回 10701 |
| 标签删除与关联 | 批量 DELETE 不经过 SELECT 租户事件；关联创建未确认标签所属租户 | 标签和关联表的批量删除附带严格租户条件；删除及创建关联先确认标签存在于当前租户 |

模型提供方的显式 Root 共享继续由原有领域授权及受控 bypass 读取。没有将跨租户默认可见作为共享授权的替代。历史助手的资源归属与权限投影不一致仍需单独的数据治理；本次不自动修补此类记录。
