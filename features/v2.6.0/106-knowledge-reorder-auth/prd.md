# F106 库与文件夹排序权限调整 · 已确认 PRD

**状态**: Discovery 已确认（2026-09-01）  
**版本**: v2.6.0  
**写模型仓**: 毕昇 `knowledge`；门户 iframe 只消费，不自建规则

---

## 1. 目标

在**不收回系统管理员现网能力**的前提下，按角色开放知识库 / 文件夹的拖拽排序。

## 2. 角色 × 能力（权威）

| 拖什么 | 系统管理员 | 运营岗（角色名精确「平台管理员」） | 部门管理员 | 库所有者/管理员 | 文件夹所有者/管理员 |
|---|---|---|---|---|---|
| 公共库、部门库顺序 | 能（现网） | **新开放** | 不能 | 不能 | 不能 |
| 团队库、科室库顺序 | 能（现网） | 不能 | **新开放**：管辖部门（含下级）∩ `department_knowledge_space` 已绑定，且当前可见 | 不能 | 不能 |
| 库根目录下文件夹顺序 | 能（现网） | 不能（除非同时还是该库管理员） | 不能（除非同时还是该库管理员） | **新开放** | 不能 |
| 某文件夹内子文件夹顺序 | 能（现网） | 不能（除非同时还是该文件夹管理员） | 不能（除非同时还是该文件夹管理员） | 能（库管继承） | **新开放** |
| 个人库顺序 | 不能（现网） | 不能 | 不能 | 不能 | 不能 |

## 3. 钉死的规则

1. 系统管理员现网能拖的全部继续能拖。
2. 运营岗 = 门户运营岗，不是 `is_admin()`；只新开放公共库、部门库排序。
3. 部门管理员按组织属性 + **部门绑定表**，不按「侧栏看见的都能拖」。
4. 「含下级」= 现网 `_admin_department_ids()`：本部门 + 子树。
5. 团队库与科室库按侧栏一组一起拖，允许互为邻居。
6. 文件夹按**当前所在目录**鉴权：根看库 `can_manage`，进入文件夹 F 看 F 的 `can_manage`。
7. 失败：接口拒绝、目标表 `sort_weight` 不变、前端不显示拖拽。并发沿用现网后写覆盖。

## 4. 明确不做

- 门户 BFF 再做一套鉴权
- 给未绑定部门的团队库按「下级员工创建」推断归属
- 改置顶语义、改个人库顺序
- 给运营岗额外开文件夹拖拽
- 新表 / 改字段 / 迁移

## 5. 涉及数据表

| 表 | 角色 | 结构 |
|---|---|---|
| `knowledge` | 写 `sort_weight` | 无 DDL |
| `knowledgefile` | 写 `sort_weight` | 无 DDL |
| `knowledge_space_scope` | 读 `level` | 无 DDL |
| `department_knowledge_space` | 读 `department_id`, `space_id` | 无 DDL |
| `department` / `department_admin_grant` | 读管辖范围 | 无 DDL |
| `space_channel_member` + OpenFGA | 读库/文件夹管理员 | 不新写授权 |
