# 深度研究：幻灯片逐页溢出测量与局部修改

**版本**：v3.1.0-beta1。**优先级**：P1。**流程**：小功能（SDD-Guide §1），只写本 spec，决策记在 PR。**状态**：2026-11-05 用户同意开发，规格待确认。

**关联问题**：cofco 场内慢会话 svid `f59e076c`（2026-11-05 报告 `linsight-slow-session-f59e076c-20261105.md`）。墙钟 116 分钟中 98.8% 是模型生成；模型累计输出 28.7 万 token，其中约 14.8 万是作为 write_file / edit_file 参数的整页 HTML。模型在思考里逐页估算像素高度（「第 24 页仍偏高…把字号再降一点」），改一处、重读一遍、再估一次，82 次调用没有收敛。check_html 只测横向溢出，给不出「哪一页超出了多少」。

## 1 目标与范围

作为深度研究的使用者，我希望模型改幻灯片类 HTML 时按测量结果只修溢出的页，并用小范围修改完成，使同类任务的输出量和耗时下降。

本期做两件事：check_html 增加分页版式的逐页溢出测量；主图提示词要求以测量为准、做局部修改。不做：新的交付格式、截图读图、编辑次数上限（按「不用兜底掩盖模型缺陷」原则）、cofco 分支回移（另行决定）。

## 2 验收标准

- **AC-01** — WHEN check_html 渲染的页面含 2 个以上同级分页容器（class 以 `slide` 或 `page` 结尾，或带 `data-slide` 属性），THE SYSTEM SHALL 在桌面宽度下逐个测量容器内容是否超出容器的高度或宽度。
- **AC-02** — WHEN 分页容器内容超出容器 2px 以上，THE SYSTEM SHALL 报告一条 ERROR，按页列出页序号、该页标题（取首个 h1–h3，截断到 20 字）和超出像素，并写明未列出的页已经装得下、不要再改。
- **AC-03** — WHEN 页面的分页容器全部装得下，THE SYSTEM SHALL 在报告里写明「共 N 页，逐页测量均未溢出」，不产生分页相关的 ERROR 或 WARN。
- **AC-04** — WHEN 分页容器设置了 `overflow: auto` 或 `scroll`（本身可滚动），或处于不显示状态，THE SYSTEM SHALL 不把它判为溢出；不显示的页计数并在报告里说明未测量。
- **AC-05** — WHEN 页面没有分页容器（普通长页报告），THE SYSTEM SHALL 保持现有检查结果不变。
- **AC-06** — WHEN 浏览器不可用，THE SYSTEM SHALL 沿用现有「仅静态检查」退化说明，不伪造逐页结论。
- **AC-07** — WHEN 主图生成 HTML 交付物或修改已写好的文件，THE SYSTEM SHALL 在系统提示词中要求：分页版式是否装得下以 check_html 的逐页测量为准，不在思考里估算像素；只修报告列出的页；统一调整字号、间距等样式时改 `<style>` 中的 CSS 规则；edit_file 的 old_string 取能唯一定位的最短片段，不把整页、整节作为参数重写。
- **AC-08** — WHEN 同类改版任务（37 页 HTML 幻灯片，要求调大字号且每页不溢出）在同一模型上执行，THE SYSTEM SHALL 使累计输出 token 和墙钟时间低于改动前的基线（105 环境对比，样本量与波动在报告中注明）。

## 3 明确接受的边界

- 识别分页容器靠 class 命名与同级数量的启发式；命名不符合的自定义分页（如只用 `section` 无 class）测不到，按 AC-05 走现有检查。
- 用 JS 只显示当前页的翻页式 deck，非当前页不显示，按 AC-04 只计数不测量。
- 逐页溢出是 ERROR，提示词沿用「最多修 2 轮」的上限；2 轮后仍溢出时模型按现有规则收尾并说明。
- 依赖镜像里的 Chromium；精简镜像只做静态检查。
