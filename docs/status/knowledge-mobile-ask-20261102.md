# 知识空间移动端统一提问入口

日期：2026-11-02（北京时间）。

## 当前行为

- 桌面和移动端的知识空间统一通过 `KnowledgeAiBottomDock` 渲染 `KnowledgeAskBar`。
- 空间内只保留提问输入框，不再出现本地历史对话、新建会话、展开或收起会话面板。
- 发送问题时，将问题、当前空间 ID/名称和所选模型交给主对话，进入 `/c/new`；后续会话从全局侧栏访问。
- 与已有桌面行为一致，知识来源是整个空间，不继承当前目录和旧的标签过滤条件。移动端仍在文件批量选择和搜索模式下隐藏输入框。
- 已移除旧的 `KnowledgeAiInPlaceDock`、`ConversationHistory` 和无运行时消费者的 `useFolderChat`，输入框的标签类型改为组件内声明。服务端既有会话 API 和数据保持兼容。

## 发送时欢迎页闪现修复

- 根因：`/c/new` 首次渲染时，问题尚未由 effect 接收，也可能还在等待模型配置、知识选择或发送租约；此时没有消息和 streaming 标记，`ChatView` 会先渲染欢迎页。原先外层布局判断包括 streaming，正文分支却未使用同一判断。
- `useChatAskHandoff` 在渲染阶段即暴露文本问题待交接状态，覆盖全局暂存和已接收的局部状态；`ChatView` 据此直接使用底部输入框的对话布局，直到真实消息接管。没有新增跨页状态、虚构消息、固定延时或加载遮罩。
- 普通新建对话仍显示欢迎页；模型不可用仍返回可编辑的问题；附件问题仍挂载原先负责上传的首页输入框。Desktop 的首页状态上报也使用相同的交接判定。
- 使用真实 `ChatView` 和交接 Hook 的回归覆盖首次渲染、配置延迟、异步发送、普通新建与失效模型；换成原交接模块后，欢迎组件在第一阶段被调用两次，回归明确失败。修复后 4 组、29 项相关测试通过。
- 改动文件 ESLint、全工作区类型检查、架构检查和 diff 空白检查通过。扩展运行 `useAiChat.test.ts` 套件存在失败；其中首个 streaming 断言在原交接模块上同样失败，本轮未改动该发送实现及套件。
