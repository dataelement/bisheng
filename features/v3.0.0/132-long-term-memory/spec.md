# Feature: 长期记忆

**关联 PRD**: [长期记忆 PRD v0.2](<../../../docs/PRD/memory 长期记忆/长期记忆 PRD.md>)（§4 需求、§5 验收、§7 决策）；需求发现见 [discovery.md](./discovery.md)
**优先级**: P0
**所属版本**: v3.0.0（开发基线；目标版本号待定，见 discovery.md）
**依赖**: F048（权限与租户隔离）、F053（开放 API 身份）、F072（日常模式引用角标）。无阻塞性前置 Feature
**状态**: 规格草稿，待用户确认

> **范围边界**
> - **本次纳入**：
>   - 日常模式、深度研究、助手、工作流四类场景的跨会话长期记忆
>   - 两条写入途径：模型调用的记忆写入工具、会话安静后的自动整理
>   - 两条读取途径：常驻记忆每轮带入、按需检索（模型工具与工作流记忆检索节点）
>   - 租户级、用户级、助手级、工作流级四处开关
>   - "已记住"提示、回答归因、记忆管理页
>   - 效果指标与评测集
> - **本次明确排除**：
>   - 按应用隔离的记忆：一个用户只有一份记忆，不存在只属于某个应用的记忆
>   - 组织级、多人共享的记忆：延后，本期只预留作用域
>   - 回查对话原文：它是另一个能力，不属于长期记忆
>   - 系统自己推断的、带置信度的信念
>   - 自动遗忘：系统不因时间久或很久没用到而删除记忆
>   - 实体关系抽取：本期只建结构，不写入数据
>   - "上个月系统以为的情况是什么"这类时间回溯查询
>   - 工作流的记忆写入节点：工作流的记忆只来自自动整理
>   - 外部用户标识下的记忆、免登录访问下的记忆
>   - 管理员或应用作者对用户记忆的任何操作，包括查看、清除、统计页面
>   - 记忆管理页的搜索与筛选、记忆的导入导出
>   - 事件时间过去之后把表述改写成过去时（PRD 列为 P1，不在本规格验收）
>   - 深度研究从任务过程中自动整理经验类记忆（PRD 列为 P1，不在本规格验收；经验类条目的读取规则在本规格内）

## 1. 用户故事

**A. 日常模式的用户**
作为 **日常模式的用户**，
我希望 **系统记住我说过的身份、偏好和安排，并在我明确要求时当场记下**，
以便 **新开会话时不必把同样的话再说一遍**。

**B. 深度研究的用户**
作为 **深度研究的用户**，
我希望 **我对产出的固定要求在后续任务里自动生效**，
以便 **不必在每个任务里重复同一批要求**。

**C. 助手的使用者**
作为 **某个助手的使用者**，
我希望 **这个助手用得上我在别处说过的情况，并且别的使用者看不到我的记忆**，
以便 **多人共用同一个助手时，它对每个人都是连贯的**。

**D. 工作流的作者**
作为 **工作流的作者**，
我希望 **在流程里用一个节点取回当前使用者的相关记忆**，
以便 **把记忆当作一个可编排的输入交给后续节点**。

**E. 助手与工作流的作者**
作为 **助手或工作流的作者**，
我希望 **由我决定这个应用是否使用记忆，默认不使用**，
以便 **应用的行为不会在我不知情时改变**。

**F. 任何有记忆的用户**
作为 **用户**，
我希望 **看得到系统记了什么、每次回答用了哪些记忆，并且能改、能删、能关掉**，
以便 **记错的内容可以改正，不想被记住时可以停止**。

**G. 租户管理员**
作为 **租户管理员**，
我希望 **能在租户范围内关闭记忆功能**，
以便 **组织不需要这项能力时可以整体停用**。

## 2. 验收标准

术语按 PRD §2：记忆条目、详情、记忆空间、来源标记、常驻记忆、显式写入、自动整理、归因。下文"启用记忆"指 §2.6 的启用条件成立。

### 2.1 记忆空间与隔离

- **AC-01** — THE SYSTEM SHALL 让每个用户在一个租户内只有一个记忆空间，任何场景下读写的都只是当前用户本人的记忆空间。
- **AC-02** — WHEN 两个用户使用同一个启用记忆的助手或工作流, THE SYSTEM SHALL 使一方产生的记忆对另一方不可读、不可检索、不影响其回答。
- **AC-03** — WHEN 用户在任一启用记忆的场景或应用里产生一条记忆, THE SYSTEM SHALL 使该记忆在该用户的日常模式、深度研究以及其他启用记忆的助手和工作流里可读。
- **AC-04** — THE SYSTEM SHALL 为每条记忆保留来源标记，标明它产生于哪个场景、哪个应用、哪个会话，并在向用户展示该记忆时显示来源。
- **AC-05** — THE SYSTEM SHALL 使一个租户内的记忆对其他租户不可读；WHEN 用户换到另一个租户, THE SYSTEM SHALL 使其读不到原租户里的记忆。
- **AC-06** — THE SYSTEM SHALL 不向租户管理员、应用作者或其他任何非本人角色提供查看、修改、清除或统计某个用户记忆的入口。
- **AC-07** — IF 当前调用识别不出一个确定的平台用户（免登录链接访问，或开放 API 调用只带外部用户标识）, THEN THE SYSTEM SHALL 不读取也不写入任何记忆，并使该应用照常运行、不返回与记忆有关的错误。
- **AC-08** — WHEN 开放 API 以代表某个平台用户的方式调用, THE SYSTEM SHALL 读写被代表的那个用户的记忆空间。

### 2.2 记忆条目

- **AC-09** — THE SYSTEM SHALL 使每条记忆条目只表达一个结论，内容不超过 200 字，并归为事实、偏好、经验三种类型之一。
- **AC-10** — WHEN 待写入的内容含有相对时间表述（如"明天""下周二"）, THE SYSTEM SHALL 按用户所在时区换算成具体日期后再写入，使记忆条目中不出现相对时间。
- **AC-11** — WHERE 一条记忆描述一件有具体时间的事, THE SYSTEM SHALL 为该条目记录事件时间。
- **AC-12** — IF 待写入的内容是密码、密钥、令牌、证件号或银行卡号, THEN THE SYSTEM SHALL 不写入，即使用户明确要求；显式写入时并向用户说明原因。
- **AC-13** — THE SYSTEM SHALL 只把用户本人说的话、以及用户与系统在对话里明确达成的结论作为记忆的来源；文档、网页、知识库、工具返回里的内容不得成为记忆。
- **AC-14** — WHEN 一段结论需要连贯说明、无法在一条条目的长度内表达, THE SYSTEM SHALL 把完整正文保存为该条目的详情，并使条目内容为详情的一句概括。

### 2.3 显式写入

- **AC-15** — WHEN 用户在当前这句话里明确要求记下某件事, THE SYSTEM SHALL 立即新增一条记忆条目，使其在同一会话的后续轮次和任何新会话里可读。
- **AC-16** — WHEN 显式写入成功, THE SYSTEM SHALL 在回答中说明记下了什么；时间被换算成具体日期的，回答中给出换算后的日期。
- **AC-17** — WHEN 显式写入成功, THE SYSTEM SHALL 在该回答旁显示"已记住"提示，提示可展开看到写下的条目原文，并提供撤销。
- **AC-18** — WHEN 用户在"已记住"提示上撤销, THE SYSTEM SHALL 使该条记忆不可再读。
- **AC-19** — WHEN 用户明确要求更正一条已有记忆, THE SYSTEM SHALL 新增一条有效条目，并把被更正的条目标为已被取代。
- **AC-20** — WHEN 用户明确要求忘掉一条已有记忆, THE SYSTEM SHALL 把对应条目标为已删除。
- **AC-21** — IF 更正或忘掉时找不到对应的条目, THEN THE SYSTEM SHALL 在回答中说明没有找到，不新建条目。
- **AC-22** — IF 显式写入失败, THEN THE SYSTEM SHALL 在回答中说明没有记下，并且不显示"已记住"提示。
- **AC-23** — THE SYSTEM SHALL 只在一次写入真实成功后才显示"已记住"提示；回答声称已记下而没有成功写入时，系统不代为补写，并把这次情况计入"声称未写入"指标。
- **AC-24** — WHILE 记忆未启用, THE SYSTEM SHALL 不向模型提供记忆的写入与检索能力；WHEN 此时用户要求记下某件事, THE SYSTEM SHALL 在回答中说明记忆功能未开启。
- **AC-25** — THE SYSTEM SHALL 在日常模式、深度研究、助手三类场景提供显式写入；工作流不提供显式写入。

### 2.4 自动整理

- **AC-26** — WHEN 一个启用记忆的会话自最后一次交互起经过了安静期, THE SYSTEM SHALL 从该会话中整理出符合 §2.2 的记忆条目。
- **AC-27** — WHILE 会话仍在安静期内且用户继续对话, THE SYSTEM SHALL 不启动对该会话的整理，并重新计算安静期。
- **AC-28** — THE SYSTEM SHALL 每次只整理上次整理之后新增的对话，同一段对话不被整理两次、不产生重复条目。
- **AC-29** — WHEN 整理出的结论与一条已有的有效条目表达同一件事, THE SYSTEM SHALL 不新增重复条目；WHEN 它与已有的有效条目矛盾, THE SYSTEM SHALL 新增条目并把旧条目标为已被取代。
- **AC-30** — THE SYSTEM SHALL 对四类场景的会话都执行自动整理；工作流的整理范围是使用者的输入，以及工作流输出给使用者且经其确认的结论。
- **AC-31** — THE SYSTEM SHALL 允许部署方调整安静期与整理频率，并允许整体关闭自动整理；安静期初值为 30 分钟。
- **AC-32** — WHEN 同一个用户同时在两个服务节点上进行两个会话, THE SYSTEM SHALL 保留两边写下的全部记忆，任何一方的写入都不被另一方覆盖。

### 2.5 读取

- **AC-33** — WHILE 记忆已启用, THE SYSTEM SHALL 在日常模式和助手的每轮对话开始时、在深度研究的任务开始时，把当前用户的常驻记忆整份带入。
- **AC-34** — THE SYSTEM SHALL 使带入的常驻记忆不超过条数上限和总字数上限中先到达的一个；初值为 60 条、6000 字，部署方可调整。
- **AC-35** — WHEN 常驻记忆到达上限后又有新条目应当常驻, THE SYSTEM SHALL 通过合并相近条目或把较少用到的条目移出常驻来满足上限，不截断内容；被移出常驻的条目保持有效并可被检索到。
- **AC-36** — THE SYSTEM SHALL 不把经验类条目放入日常模式和助手的常驻记忆；WHEN 深度研究任务开始, THE SYSTEM SHALL 额外带入经验类条目。
- **AC-37** — THE SYSTEM SHALL 把带入的记忆标注为背景信息并注明记录时间，不作为必须执行的指令提供给模型。
- **AC-38** — WHILE 记忆已启用, THE SYSTEM SHALL 在日常模式、深度研究、助手三类场景向模型提供记忆检索能力，检索范围是当前用户的记忆空间，只返回有效条目，并可取回条目的详情全文。
- **AC-39** — IF 记忆中没有与问题相关的内容, THEN THE SYSTEM SHALL 据实回答，不编造记忆。
- **AC-40** — WHEN 用户当前这句话与记忆矛盾, THE SYSTEM SHALL 以当前这句话为准；当前会话的上文优先于长期记忆。
- **AC-41** — THE SYSTEM SHALL 不在工作流中自动带入常驻记忆；工作流只通过记忆检索节点读取记忆。

### 2.6 保持正确与数据生命周期

- **AC-42** — THE SYSTEM SHALL 使已被取代和已删除的条目不出现在常驻记忆、检索结果、记忆检索节点的输出和记忆管理页中。
- **AC-43** — WHEN 一条记忆被取代, THE SYSTEM SHALL 保留旧条目并记录取代它的是哪一条，不物理删除旧条目。
- **AC-44** — WHEN 用户删除一条记忆或清空全部记忆, THE SYSTEM SHALL 使对应条目及其详情不可再读。
- **AC-45** — WHEN 一条带事件时间的条目的事件时间已过, THE SYSTEM SHALL 不再把它放入常驻记忆，并保持它可被检索到。
- **AC-46** — THE SYSTEM SHALL 不因一条记忆存在时间长或长期未被读取而自动删除它。
- **AC-47** — WHEN 用户删除一个会话, THE SYSTEM SHALL 保留由该会话产生的记忆，并且不改变删除会话的交互。
- **AC-48** — WHEN 一个应用被删除, THE SYSTEM SHALL 保留用户在该应用里产生的记忆，其来源标记仍显示原应用的名称。
- **AC-49** — WHEN 一个用户被删除或停用, THE SYSTEM SHALL 删除该用户的全部记忆。
- **AC-50** — WHEN 用户删除或清空记忆, THE SYSTEM SHALL 写入审计记录，记录操作人、时间和动作，不包含记忆内容。

### 2.7 开关

- **AC-51** — THE SYSTEM SHALL 在管理端的工作台配置中提供租户记忆开关，默认开，仅租户管理员可改，作用于本租户全部用户的全部场景。
- **AC-52** — WHERE 租户记忆为开, THE SYSTEM SHALL 在用户个人设置中提供"我的记忆"开关，默认开，作用于该用户在全部场景和全部应用里的记忆。
- **AC-53** — WHILE 租户记忆为关, THE SYSTEM SHALL 不显示"我的记忆"开关和记忆管理页，并使四类场景都不读不写记忆。
- **AC-54** — WHEN 用户关闭"我的记忆", THE SYSTEM SHALL 使其在日常模式、深度研究以及任何启用记忆的助手和工作流里都不读不写记忆，其他用户不受影响。
- **AC-55** — THE SYSTEM SHALL 在助手的设置页提供助手记忆开关，在工作流的开始节点提供工作流记忆开关，两者默认关，随应用版本保存和发布。
- **AC-56** — THE SYSTEM SHALL 按以下条件启用记忆：日常模式与深度研究要求租户记忆开且"我的记忆"开；助手另要求该助手的记忆开关开；工作流另要求该工作流的记忆开关开。
- **AC-57** — WHEN 任一开关被关闭, THE SYSTEM SHALL 保留已有记忆并停止读写；WHEN 该开关重新开启, THE SYSTEM SHALL 使关闭之前的记忆继续可读。
- **AC-58** — THE SYSTEM SHALL 在助手记忆与工作流记忆的开关旁说明开启的含义：本应用会读取并写入每个使用者自己的记忆；使用者的记忆可能出现在本应用的回答里；不同使用者之间互不可见。
- **AC-59** — WHEN 部署升级到带有本功能的版本, THE SYSTEM SHALL 使租户记忆为开，并使所有已有的助手和工作流的记忆开关为关。
- **AC-60** — WHEN 助手记忆开启, THE SYSTEM SHALL 使该助手具备常驻记忆带入、记忆检索、显式写入和自动整理，作者无须另行配置工具。

### 2.8 工作流记忆检索节点

- **AC-61** — THE SYSTEM SHALL 在工作流的节点面板中提供"记忆检索"节点，同一个工作流中可放置多个。
- **AC-62** — THE SYSTEM SHALL 使该节点的"检索内容"参数可以直接输入文字、引用其他节点的变量，或两者混写，并且为必填。
- **AC-63** — THE SYSTEM SHALL 使该节点的"最大检索数量"参数默认为 20，只接受 1 到 100 的整数。
- **AC-64** — WHEN 该节点执行, THE SYSTEM SHALL 在当前使用者本人的记忆空间内检索有效条目（不限于在本工作流里产生的记忆），按与检索内容的相关程度从高到低输出不超过最大检索数量的列表，列表可被后续节点作为变量引用。
- **AC-65** — THE SYSTEM SHALL 使输出列表的每一项包含记忆内容、类型、记录时间、来源标记，有事件时间的带事件时间；条目带详情时，内容为详情全文。
- **AC-66** — IF 检索没有命中、运行时检索内容为空、识别不出确定的平台用户，或当前使用者关闭了"我的记忆", THEN THE SYSTEM SHALL 输出空列表并使节点正常结束，不中断工作流。
- **AC-67** — IF 工作流含有记忆检索节点而工作流记忆开关为关, THEN THE SYSTEM SHALL 在上线校验时拒绝并提示作者先开启工作流记忆。
- **AC-68** — THE SYSTEM SHALL 在该节点的运行日志中记录本次检索内容和返回条数。

### 2.9 用户可见与可控

- **AC-69** — WHEN 一次回答用到了记忆, THE SYSTEM SHALL 在日常模式、深度研究和助手的该回答旁显示本次用到的记忆条目，并允许就地删除其中任意一条。
- **AC-70** — WHERE 租户记忆为开, THE SYSTEM SHALL 在用户个人设置中提供记忆管理页，列出本人全部有效条目，每条显示内容、类型、记录时间、事件时间、来源标记和是否常驻。
- **AC-71** — WHEN 用户在记忆管理页编辑一条记忆, THE SYSTEM SHALL 把原条目标为已被取代并使新内容成为有效条目。
- **AC-72** — WHEN 用户在记忆管理页手动新增一条记忆, THE SYSTEM SHALL 按 §2.2 的规则接受或拒绝它，接受后使其在新会话里可读。
- **AC-73** — WHEN 用户在记忆管理页清空全部记忆, THE SYSTEM SHALL 先要求二次确认。

### 2.10 效果度量

- **AC-74** — THE SYSTEM SHALL 记录五类指标并支持按租户、场景、应用拆分：写入量（显式写入、自动整理、被取代、被删除）；读取情况（被带入、被检索命中、从未被读到）；详情取回比例；用户纠正（删除条数、撤销次数）；声称未写入次数。
- **AC-75** — THE SYSTEM SHALL 使上述指标只含数量，不含记忆内容。
- **AC-76** — THE SYSTEM SHALL 随本功能交付一个基于真实对话的评测集，并产出同一批题目在"带记忆"与"不带记忆"两种条件下的得分对比。

## 3. 边界情况

- 当用户在同一句话里既要求记下、内容又属于不记的类别时，系统应拒绝写入并说明原因，不做部分写入。
- 当用户要求更正而有多条条目都可能是被更正的对象时，系统应向用户确认是哪一条，不得猜测后取代。
- 当条目的详情暂时读不出来时，系统应以条目自身的内容继续回答，不向用户报错，也不表现为没有这条记忆。
- 当记忆的内容与用户意图的关系不明确、而按记忆行事会明显影响结果时，系统应先向用户确认，不按记忆直接行事。
- 当一个会话在安静期内被删除时，尚未整理的对话不再被整理；已整理出的记忆按 AC-47 保留。
- 当用户在安静期结束前关闭了"我的记忆"或某个应用的记忆开关时，这段尚未整理的对话不再被整理。
- 当开关在一次回答的生成过程中被改变时，以该轮开始时的状态为准，下一轮起按新状态。
- 当工作流的历史版本未包含记忆开关时，系统应把它当作关闭。
- 当记忆检索节点引用的变量取值不是文字时，系统应把它转成文字后检索；转换后为空的按 AC-66 处理。
- 当用户换租户时，原租户内的记忆按"用户被删除"处理（同 AC-49）；之后再换回原租户，这些记忆不恢复。
- 当助手记忆开启、而作者在该助手里另外配置了同名或同用途的工具时，以平台提供的记忆能力为准，具体处理方式见 design.md。
- 模型在用户没有明确要求时调用写入能力、或在应当调用时没有调用，属于模型行为偏差。期望的对外行为由 AC-23 与 AC-76 约束，系统不以兜底方式掩盖。
