# 组织父链与路径一致性修复

- Feature ID: `069-department-parent-path-consistency`
- Mode: `bugfix`
- Created: `2026-09-30`
- Status: `implementing`

## 已确认问题与范围
生产只读核查发现 330 条存储路径与父链不一致。现有同步与手工移动按旧 path 前缀查找后代：缺失前缀的真实后代会遗漏，具有伪前缀的无关组织可能被误改；根节点路径未改变时也不会修复损坏后代。上游传入或缓存的父路径还可能继续传播错误。
用户在原因分析后要求“修复代码”，授权本地实现和回归验证。本轮不部署，不迁移历史数据，不重建 ES，不变更组织权限或租户挂载规则。

## 需求与验收
- REQ-001：同步新增/更新、延迟父级重新挂接、后台创建/移动，写入路径以当前父关系为准。
  - AC-001：子孙路径缺失、错前缀或空值时仍更新真实后代；无关同前缀组织不受影响。正常路径与父级不变的重复同步也满足此规则。V-001。
- REQ-002：路径与父关系在同一事务内变更，拒绝损坏父链。
  - AC-002：父节点缺失、跨租户关联、自环/移入后代均拒绝；失败不残留半更新或半创建的记录。V-001。
  - AC-003：保留挂载状态、归档后代状态、原有权限检查和提交后事件；兼容 MySQL/DM8 的普通 ORM 查询。V-001、V-002。
- REQ-003：修复边界可验证。
  - AC-004：先观察旧实现回归失败；最终相关测试和静态检查通过，生产修复及真实双数据库验证边界明确。V-001、V-002。
