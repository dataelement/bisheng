## 1. 用户故事

### 1.1 租户管理员

作为租户管理员，我希望统一管理本租户 DSH 模型调用的输入与输出敏感词规则，以便所有受保护的模型请求遵守同一套内容要求。

### 1.2 Desktop 使用者

作为 Desktop 使用者，我希望命中敏感词时立即得到清楚的阻断提示，并停止当前轮次和未经检查的工具执行，以便理解请求未完成的原因。

### 1.3 审计人员

作为有审计权限的人员，我希望在请求、会话和目录层级发现命中记录，查看检查方向和依据，并区分模型执行结果与内容拦截结果，以便准确追溯。

### 1.4 平台运维人员

作为平台运维人员，我希望检查能力可按租户启停，身份查询开销受控，回传故障可发现并恢复，以便在多实例和持续请求下保持可用并识别审计缺口。

### 1.5 无 Gateway 部署的使用者

作为无 Gateway 部署的使用者，我希望仍能使用 F110 提供的本地登录、模型授权、额度和审计能力，以便内容安全增量不改变现有接入条件。

## 2. 验收标准

### 2.1 保护范围与独立运行

- **AC-01** — WHERE DSH 敏感词检查已接入，THE SYSTEM SHALL 覆盖 Chat Completions 和 Responses 的流式与非流式模型请求，且不因客户端声明的请求用途、会话类型或审计元数据而跳过检查。
- **AC-02** — WHEN 部署级检查能力未开启，THE SYSTEM SHALL 保持原有 DSH 透传行为；WHEN 能力已开启但可信租户的策略未配置或关闭，THE SYSTEM SHALL 不对该租户执行敏感词阻断。首次安装和首次使用的默认状态均为关闭。
- **AC-03** — WHERE Gateway 未部署，THE SYSTEM SHALL 继续允许符合 F110 规则的本地登录与模型使用；backend 的模型鉴权、模型权限、额度及计量不得新增 Gateway 运行时依赖，也不得恢复 License 或席位准入。
- **AC-04** — WHERE 部署宣称 DSH 模型请求受本功能保护，THE SYSTEM SHALL 覆盖客户端实际可达的全部 DSH 模型调用入口，使客户端不能通过直连 backend 或其他公开入口绕过检查；登录、刷新、profile、模型目录和用量查询不作为内容检查对象。

- **AC-05** — WHEN 适用检查全部通过且请求正常转发，THE SYSTEM SHALL 保持 backend 原有正文、工具调用、协议顺序、错误及用量语义，不改写模型内容或另行生成模型调用。

### 2.2 租户策略与管理权限

- **AC-06** — WHEN 管理员配置本租户策略，THE SYSTEM SHALL 允许统一配置启停、输入检查、输出检查、内置词库、自定义词及阻断提示，支持内置词与自定义词同时生效，并将同一策略应用于该租户全部 DSH 模型。
- **AC-07** — WHEN 普通用户或无目标租户管理权限的人员读写策略，THE SYSTEM SHALL 拒绝操作；WHEN 租户管理员管理策略，THE SYSTEM SHALL 限于本租户；WHEN 超级管理员指定目标租户，THE SYSTEM SHALL 验证该租户存在且处于其可管理范围。
- **AC-08** — WHEN 保存策略，THE SYSTEM SHALL 按当前有效的平台管理身份与权限判定是否允许保存，不把 DSH profile 的身份定位结果或其缓存当作租户管理授权。
- **AC-09** — IF 某方向启用检查但没有有效词，或词库、词条、阻断提示不满足已公布的校验要求，THEN THE SYSTEM SHALL 拒绝保存并指出原因；不得出现界面显示已启用但实际上没有检查规则的状态。
- **AC-10** — WHEN 多个管理员基于同一旧版本先后保存策略，THE SYSTEM SHALL 明确拒绝冲突保存，避免静默覆盖已生效的更新。
- **AC-11** — WHEN 策略保存成功，THE SYSTEM SHALL 使新请求在最多 5 秒内使用新策略，并向管理员说明该生效范围；正在处理的请求继续使用进入检查时的策略，包含后续的关闭或词库变更。
- **AC-12** — WHERE 多个 Gateway 实例同时服务同一租户，THE SYSTEM SHALL 对相同策略及内置词库版本使用一致的词条和匹配语义；若无法取得有效策略或词库，不得将其视为策略关闭并透传。

### 2.3 profile 定位与结果复用

- **AC-13** — WHEN Gateway 选择租户策略，THE SYSTEM SHALL 以 backend 成功验证原始 DSH 凭据后返回的用户和租户为准，不采信客户端自报的租户；不同 backend 部署或不同完整凭据的身份复用结果不得互相串用。
- **AC-14** — WHEN 复用已验证身份，THE SYSTEM SHALL 使其距最近成功验证最多 30 秒，且不得超过凭据有效期；访问或转存该结果不得延长其绝对有效期，失败的验证不得成为成功身份记录。身份复用结果不保存原始凭据，相关诊断日志不输出凭据。
- **AC-15** — WHILE 同一有效凭据的身份结果仍有效且未发生失效或缓存故障，THE SYSTEM SHALL 供后续模型请求复用，并允许多个 Gateway 实例复用同一 backend 部署、同一完整凭据的成功验证结果；身份验证次数不得随输出分片或 Token 数量增长。
- **AC-59** — WHEN 同一 Gateway 实例内，多个请求使用同一 backend 部署的相同完整凭据并发访问，且没有有效身份结果（包括首次访问和缓存过期），THE SYSTEM SHALL 将同一轮身份验证合并为一次 profile 调用，并向等待请求共享验证结果；单个等待请求取消不得取消其他请求仍依赖的验证，等待超限时按 AC-18 报告检查不可用，不自动重试模型请求。
- **AC-16** — WHEN 模型请求转发 backend，THE SYSTEM SHALL 保留原始 DSH 凭据，由 backend 按当前身份、会话、租户、模型权限和额度重新执行原有准入；身份结果复用不得提供额外模型权限或绕过已失效的会话。
- **AC-17** — WHEN backend 明确返回凭据、会话、用户或租户失效，THE SYSTEM SHALL 使对应身份复用结果失效，并保留该错误；模型权限不足和额度不足不得被误判为身份失效，模型请求不得因此自动重试。
- **AC-18** — IF 必须取得身份或策略时发生超时、服务错误、异常响应或容量耗尽，THEN THE SYSTEM SHALL 明确终止本次请求并报告检查不可用，不默认为无效账号、策略关闭或检查通过。
- **AC-19** — IF 身份结果复用设施不可用，THEN THE SYSTEM SHALL 仅使用仍在有效期内的已验证结果或在有界验证能力内重新验证；不得延长旧结果寿命、无限等待或无限重试，也不得保存或输出原始凭据到身份缓存及诊断日志。

### 2.4 文本与协议覆盖

本小节适用于已启用的检查方向；未开启的方向保持原有交付语义。

- **AC-20** — WHEN 某方向启用检查，THE SYSTEM SHALL 检查该方向完整上下文中的可读消息、可读推理、工具描述、工具参数和工具结果，按 JSON 解码后的字符串语义匹配；图片编码、加密推理、鉴权材料、协议标识和审计元数据不作为可读文本扫描。
- **AC-21** — WHEN 文本属于同一消息的连续文本块，THE SYSTEM SHALL 保持其连续语义以识别跨块命中；不同消息、不同工具调用的独立文本不得相互拼接形成不存在的命中。匹配沿用既有 Gateway 字面子串及大小写语义。
- **AC-22** — WHEN 命中词跨越网络分片、SSE 事件、UTF-8 字节、转义序列或最后剩余文本，THE SYSTEM SHALL 在完整命中词交付客户端前识别并阻断，不因传输切分而漏检。
- **AC-23** — WHEN Responses 在增量、完成消息或最终完整结果中提供可读内容，THE SYSTEM SHALL 对所有可交付的内容执行相同检查，并保持原协议事件顺序；最终结果新增的内容不得绕过检查。
- **AC-24** — WHERE 输出检查开启且输出包含工具调用，THE SYSTEM SHALL 在工具参数完整且检查通过后才允许客户端取得可执行参数；参数命中、解析失败或检查未完成时，不得执行该工具调用。
- **AC-25** — IF 正文、事件或工具参数无法安全解析，THEN THE SYSTEM SHALL 返回可识别的错误并停止交付，不跳过检查透传，不将解析失败误记为敏感词命中。
- **AC-26** — IF 请求、响应、词库或并发检查超过已公布的支持限制，THEN THE SYSTEM SHALL 拒绝或终止相应处理并说明原因，不以无限缓存、无限排队或未经检查的透传继续请求。

### 2.5 阻断、客户端与用量

- **AC-27** — WHEN 输入命中，THE SYSTEM SHALL 在 backend 模型请求发生前阻断，告知输入被拦截，且不产生模型调用次数、额度扣减或 Token 用量事实。
- **AC-28** — WHEN 非流式输出交付客户端，THE SYSTEM SHALL 先完成该响应的全部适用检查；输出命中时不得交付被拦截的模型正文。
- **AC-29** — WHEN 流式输出命中，THE SYSTEM SHALL 停止交付后续模型内容，且在约定检查范围内不交付完整命中词；此前已交付的安全前缀可以保留，不再发送表示该轮正常成功的结束结果。
- **AC-30** — WHEN 输入或非流式输出命中，THE SYSTEM SHALL 返回可识别为内容阻断的 HTTP 403、content_blocked 结果及租户配置的阻断提示；WHEN 流式输出命中，THE SYSTEM SHALL 分别以 Chat 的 content_filter 终止语义和 Responses 的明确内容阻断错误通知客户端。Desktop 显示阻断原因并停止当前轮次，不自动重试。
- **AC-31** — WHEN 检查本身不可用，THE SYSTEM SHALL 将其与内容命中及 backend 原有鉴权、额度、供应商错误区分：响应尚未开始时返回检查不可用的 HTTP 503，已开始时明确报错并终止；不得伪装为成功或自动重试模型调用。
- **AC-32** — WHEN 输出命中且模型已开始执行，THE SYSTEM SHALL 保留 backend 能确认的实际执行和用量事实；阻断后仍产生的 Token 依原有规则结算，无法确认的用量保持未知。客户端停止交付不代表模型已停止、未消耗额度或已完成结算。
- **AC-57** — WHEN 输出已判定命中且 backend 响应尚未结束，THE SYSTEM SHALL 立即停止向客户端交付模型内容，并最迟在判定命中后 30 秒停止后台续读；字节预算耗尽、无法取得续读容量或上游连接异常时提前结束，释放对应连接和缓冲。实际执行和用量仍按 AC-32 处理，续读结束不作为供应商已停止执行或停止计费的证据。

### 2.6 检查事实与审计回传

- **AC-60** — WHEN 租户敏感词策略关闭，THE SYSTEM SHALL 不为新请求生成内容安全事件；WHEN 审计采集同时关闭，THE SYSTEM SHALL 不新增审计请求摘要或输入、输出正文。模型鉴权、额度、计量和既有记录查询保持原有行为；关闭前已记录的安全事件仍按既有补报与保留规则处理。
- **AC-61** — WHEN 用户查看审计采集状态，THE SYSTEM SHALL 常驻说明：敏感词检查开启时，即使审计采集关闭，仍记录请求摘要和检查结果，但不保存输入、输出正文；两项均关闭时不新增请求摘要，既有记录仍可查看。说明对可配置和只读用户均可见，无需展开采集设置。
- **AC-62** — WHEN Gateway 转发 DSH Chat Completions 或 Responses 模型请求，THE SYSTEM SHALL 在转发前生成独立 UUID，覆盖客户端 X-Request-ID 并透传给 backend；backend 按通用 HTTP 约定复用唯一、规范且非空 UUID，缺失、非法或多值时自行生成编号，响应、错误、审计和计量使用同一编号。该编号不替代鉴权、租户隔离、额度或重复准入检查；backend 不新增 Gateway 配置或运行时依赖。
- **AC-63** — WHEN 转发后未取得响应头或客户端提前断开，THE SYSTEM SHALL 保留已分配的模型请求编号用于安全事件和请求摘要关联；有会话的摘要进入会话记录，无会话的摘要进入未关联请求。仅凭分配编号或转发尝试不得认定模型已执行、模型结果成功或用量为零；历史缺少编号、可信身份不匹配或唯一约束冲突等事件保留数据库供debug排查，不再提供未关联检查界面。
- **AC-64** — WHEN 用户查看审计界面，THE SYSTEM SHALL 不再提供独立“未关联检查”入口、页面或专属筛选，也不从前端发起独立未关联检查事件查询；保留会话记录、未关联请求及请求内的检查详情。未能关联请求摘要的检查事件继续按既有规则入库和保留，仅供debug排查，不删除历史事件，也不为隐藏界面而强制关联或丢弃事实。
- **AC-65** — WHEN 用户查看审计，THE SYSTEM SHALL 仅提供会话记录与未关联请求两种主视图，移除独立请求明细页签及其跳转、返回入口；会话内请求列表、单条请求的信息展开、原文及检查详情继续可用。达到会话树展示深度上限时说明限制，不提供指向已移除视图的链接。
- **AC-66** — WHEN 内容检查命中，THE SYSTEM SHALL 保存本次冻结词库中实际命中的词值快照，按输入、输出保存，并在经授权的请求检查详情中合并去重展示；词值合计最多20个、每词最多256个Unicode字符，不保存周边正文、不写入普通日志或客户端阻断提示。历史未保存词值的记录明确显示无法还原，不按当前词库推测；快照继续遵守既有租户权限、幂等、事件体积及保留规则。

- **AC-67** — WHEN 敏感词检查开启而审计采集关闭，THE SYSTEM SHALL 在请求摘要中保存可取得的模型名称，并为同租户、同用户已保存的检查摘要同步会话标题；输入拦截与检查通过均适用，不新增输入、输出正文、正文块或原文manifest。标题先于摘要到达时允许有界重试，标题自身不得创建请求摘要或跨用户、跨租户绑定。仅有保留检查摘要的标题补齐不重新采集历史正文；模型已删除或元数据读取失败时保留模型编号和检查结果，不编造名称或丢弃事件。
- **AC-68** — WHEN 用户查看审计，THE SYSTEM SHALL 移除配置审计旁的“刷新状态”按钮以及“范围与查询说明”入口和说明面板；高级筛选全部保留，包括模型名称、审计状态、是否命中、命中方向、检查结果、请求编号和会话编号，既有用户、时间、查询、重置及分页语义不变。检查详情仅显示已保存的命中词及检查时间；命中词按文本渲染并去重，旧记录缺失明确提示无法还原，异常或未知时不宣称检查通过。
- **AC-69** — WHEN 请求汇总、输入和输出检查均为通过且没有任何已知命中标记，THE SYSTEM SHALL 隐藏检查详情入口且不查询检查明细；已展开记录更新为全部通过时卸载明细并取消未完成请求。历史命中、异常、未检查、未上报等情况仍保留详情入口，不隐藏仍可用于定位的已知事实。


- **AC-33** — WHEN 已接入检查的请求形成检查终态，THE SYSTEM SHALL 记录并向 backend 审计提供输入、输出各阶段的真实结果；输入阻断或 backend 准入失败而没有模型输出时，输出检查标为不适用，不编造通过。
- **AC-34** — WHEN 展示检查结果，THE SYSTEM SHALL 分别显示输入、输出的阶段结果与请求汇总结果；阶段结果区分通过、命中、检查失败、已关闭、不适用和未收到完整结果，请求汇总按下表由上到下第一个满足的条件确定。没有事件或没有已知命中均不得被解释为已通过，后到结果不得清除已确认的命中。

| 优先序 | 请求汇总条件 | 请求汇总结果 |
|---|---|---|
| 1 | 任一阶段已经确认命中，包含此前已确认的命中 | 命中 |
| 2 | 没有命中，但任一阶段检查失败 | 检查失败 |
| 3 | 没有上报，或任一阶段缺少可确认的终态 | 未收到完整结果 |
| 4 | 输入、输出均有明确关闭事实 | 已关闭 |
| 5 | 至少一个阶段明确通过，其他阶段均为通过、关闭或不适用 | 通过 |
| 6 | 全部阶段终态已明确，没有执行任何适用检查，且不满足两阶段均关闭 | 不适用 |

只有输入、输出均有明确关闭事实才能汇总为“已关闭”。例如，输入关闭、输出通过时汇总为通过；输入关闭、输出检查失败时汇总为检查失败；输入关闭、backend 准入失败导致输出不适用时汇总为不适用。该汇总仅描述内容检查，不替代模型执行、交付和用量状态。

- **AC-35** — WHERE 模型内容审计关闭或仅保存元数据，THE SYSTEM SHALL 仍能保存最小内容安全事实；安全回传与其诊断日志不得额外保存请求正文、完整回复、匹配原文或凭据，既有模型原文审计仍受原有规则约束。
- **AC-36** — WHEN 输入命中且未向 backend 发起模型请求，THE SYSTEM SHALL 生成可查询的独立安全审计条目，明确显示“输入命中，未调用模型”；模型结果、交付、用量及模型审计完整性为不适用，不伪造运行中、执行失败、正常完成或零消耗的模型记录。
- **AC-37** — WHEN 输出检查结果包含可信的本次 backend 模型请求标识，THE SYSTEM SHALL 关联该模型审计记录，不使用 profile 请求标识关联；无法确定模型请求标识时保留未关联事实，不猜测归属。
- **AC-38** — WHEN 外部安全事实与模型审计先后或并发到达，THE SYSTEM SHALL 将可确认属于同一请求的事实呈现为一条审计记录，补齐可以确认的事实并保留命中结果；身份以毕昇成功验证结果为准，接受可信身份变化，不新增跨事件身份冻结或因该变化拒收事实。关联沿用模型记录自身的归属和既有权限边界，无法确认关联时保留未关联事实，不重写既有模型执行或用量事实，也不得因此阻塞无关记录的正常查询。尚无模型执行事实的输出安全条目保持未观测状态，不因收到外部事实就认定模型已执行或未执行。
- **AC-39** — WHEN backend 确认接收外部安全事实成功，THE SYSTEM SHALL 保证该事件及对应审计摘要在相应保留范围内，接收端重启后仍可查询；仅进入易失队列不得作为成功确认。
- **AC-58** — WHEN Gateway 已成功记录检查事实但尚未收到 backend 成功确认，THE SYSTEM SHALL 在允许补报的保留范围内，保证该事实不因 Gateway 进程或实例重启而丢失，并在恢复后继续投递；重复投递不得重复计数，未确认的事件不得标记为交付完成。超过补报保留范围或收到明确拒绝时不得视为交付成功，应按 AC-43 暴露缺口，并遵守 AC-51 的删除与保留边界。
- **AC-40** — WHEN 检查发现命中，THE SYSTEM SHALL 立即形成可回传的命中事实，不等待模型后续读取或用量结算完成才报告命中；结算或后续读取状态变化可以补充，不能推迟或撤销命中事实。
- **AC-41** — WHEN 事件重复、乱序或后到通过，THE SYSTEM SHALL 保留已经确认的输入、输出命中，按请求去重计算命中次数；相同事件身份对应不同事实时明确报告冲突，不按普通重复成功处理，原模型审计后到也不得重置安全结果。
- **AC-42** — WHEN 来源提交外部安全事实，THE SYSTEM SHALL 验证来源可信，按毕昇成功验证返回的租户和用户身份及本次模型请求信息保存事实，接受可信身份变化；拒绝伪造、篡改、超出服务来源允许租户范围及用浏览器或 DSH 用户凭据冒充的上报，但不因真实事件发生后的用户退出、凭据失效或租户归属变更拒绝历史补报。
- **AC-43** — IF 安全事实记录或回传失败，THEN THE SYSTEM SHALL 继续阻断已命中的内容，显式暴露记录失败、积压或缺口，不宣称已完整回传；恢复后可补报仍保留的事实。审计写入故障不得替代 backend 的模型或用量事实。

### 2.7 审计展示、筛选与汇总

- **AC-44** — WHEN 有权限的人员查看请求列表，THE SYSTEM SHALL 显示是否命中、输入或输出命中及检查状态，并允许“模型执行成功”与“输出命中，已拦截”同时成立；请求汇总为未收到完整结果时显示为尚未收到完整检查结果，不将未知结果显示为安全或已通过。
- **AC-45** — WHEN 有权限的人员筛选审计，THE SYSTEM SHALL 支持按是否命中、命中方向、检查结果，并与现有用户、模型和时间条件组合查询；请求、详情、会话和目录中的结果均受既有审计权限及租户范围约束。
- **AC-46** — WHEN 查看检查详情，THE SYSTEM SHALL 仅展示受限的命中词和检查时间；来源、规则、版本和关联编号等诊断字段继续按既有权限保存在后端，不在检查详情展示。请求开始和模型实际执行开始时间继续由原请求信息区分。仅有外部安全事实的条目不提供不存在的模型原文入口，已有原文继续按既有权限访问。
- **AC-47** — WHEN 查看会话、轮次或树形目录，THE SYSTEM SHALL 汇总其自身及子级的命中情况，按命中请求去重，独立于模型审计异常数；安全条目可以计入审计条目数，但不得据此增加模型调用次数或用量。
- **AC-48** — WHEN 命中事实变化而模型执行状态未变，THE SYSTEM SHALL 仍更新相关会话及目录的命中汇总，并提供汇总更新时间；汇总尚未就绪或组合查询未完成扫描时明确提示，不返回貌似完整的无命中结果。仅有外部安全事实的条目不得因缺少模型执行证据被误报为停滞调用，或导致全租户汇总永久无法就绪。
- **AC-49** — WHEN 继续翻页或刷新命中结果，THE SYSTEM SHALL 保持已有请求的稳定排序位置，不因模型审计晚于安全事实到达而移动该请求；拒绝将其他租户或用户显式选择的另一组筛选条件的续页凭据用于当前查询。分页沿用既有行为，不要求默认相对时间范围跨页固定。补报导致旧请求新满足条件时，用户可刷新获得新结果，不承诺跨页为不可变快照。
- **AC-50** — WHEN 打开在线审计筛选，THE SYSTEM SHALL 默认查询最近 7 天，并允许每次查询最多 31 天的时间跨度；超过跨度时明确提示分段查询，不静默截断或尝试无限历史查询。单次请求的多条安全事件不得增加列表行数或命中请求数。
- **AC-51** — WHEN 安全事件明细因保留期清理，THE SYSTEM SHALL 保留仍在有效保留期内的主审计命中结论，明确区分明细已清理与没有发生检查；补报不得复活已按保留规则删除的审计记录，也不得承诺在事实已不可回放后完整重建明细。

### 2.8 历史、兼容与启停

- **AC-52** — WHEN 升级已有审计记录，THE SYSTEM SHALL 保留历史用量、未知结算、模型审计及原有证据，将无检查事实的历史记录视为未收到结果，不批量标记为检查通过。
- **AC-53** — WHERE 使用项目支持的 MySQL 或 DM8 部署，THE SYSTEM SHALL 提供一致的租户策略适用、审计关联、幂等、筛选、汇总和保留期业务结果。
- **AC-54** — WHEN 使用原有 Gateway 应用或非 DSH 的敏感词功能，THE SYSTEM SHALL 保持其原有路由、策略和响应语义，不将 DSH 租户策略错误应用到其他场景。
- **AC-55** — WHEN 停用租户检查、部署级检查或回滚本功能，THE SYSTEM SHALL 停止对新请求启用相应检查，并保留已有审计事实、用量和待补报事实；已产生事实的补报继续进行，在途请求遵守进入检查时的策略。
- **AC-56** — WHEN 平台或 Desktop 展示本功能新增的配置、阻断、检查不可用、未调用模型及未收到结果等文案，THE SYSTEM SHALL 在简体中文、英文和日文下提供对应内容，且各语言对同一检查事实的含义一致。

## 3. 边界情况

本节只说明期望行为；对应 AC 是验收依据。

| 场景 | 期望行为 | 验收依据 |
|---|---|---|
| 请求携带伪造租户，或管理员试图修改其他租户策略 | 以可信身份选策略，拒绝越权管理及越租户查询 | AC-07、AC-08、AC-13、AC-45 |
| 同一凭据缓存期间用户退出或租户归属改变 | 转发后的模型准入检查最新事实；输入已被提前阻断时，可以先显示内容阻断，不承诺先显示注销错误 | AC-14、AC-16、AC-17、AC-27 |
| profile 或策略不可用，与策略明确关闭 | 分别呈现检查不可用及不启用检查，不把查询失败当作关闭 | AC-02、AC-12、AC-18、AC-31 |
| 身份缓存中断或凭据刷新 | 不串用身份，不续命过期结果，验证量不随响应分片增长 | AC-13、AC-14、AC-15、AC-19 |
| 同一实例内首次访问或缓存过期时并发使用相同凭据 | 同一轮仅一次 profile 验证，共享结果；取消单个等待请求不影响其他等待者，超限明确报错 | AC-13、AC-18、AC-59 |
| 空词库、内置词不一致、旧版本覆盖新策略 | 拒绝无效或冲突配置，不以无规则状态启用检查 | AC-09、AC-10、AC-12 |
| 流中切换词库或关闭策略 | 当前请求保持原规则，新请求在约定窗口内使用新规则 | AC-11、AC-55 |
| 命中词跨字节、跨文本块、跨事件，或只在最终快照出现 | 在完整命中词交付前识别；不把不同消息和工具拼成命中 | AC-21、AC-22、AC-23 |
| 工具参数转义、分片或无法解析 | 检查完整可执行参数；未通过不执行；解析失败与命中区别显示 | AC-20、AC-24、AC-25 |
| 输入命中且模型审计关闭 | 仍有最小安全条目，显示未调用模型和不适用，不制造模型调用、用量或原文 | AC-27、AC-35、AC-36、AC-46 |
| 输出命中后客户端停止，backend 仍在执行或结算 | 内容交付停止，命中先上报，实际用量后补；不能证明的状态保持未知 | AC-29、AC-32、AC-40、AC-57 |
| 输出命中后续读达到 30 秒、字节预算耗尽、无可用续读容量或上游异常 | 最迟在命中后 30 秒结束续读，其他限制先触发则提前结束并释放资源；不据此认定模型已停止或用量为零 | AC-32、AC-57 |
| 外部安全条目先到、原模型审计后到 | 合并为同一条目，保留安全结果，不制造正文入口或无关索引故障 | AC-36、AC-38、AC-41、AC-46、AC-48 |
| 已分配编号但未取得响应头，或历史无编号、可信身份结果发生变化 | 新转发尝试按预分配编号建摘要，模型执行及用量保持未知；无法安全关联的历史或冲突事件保留未关联事件，接受可信身份变化 | AC-37、AC-38、AC-42、AC-62、AC-63 |
| 重复、乱序、重启补报、关闭功能后仍有积压 | 不重复计数，不撤销命中，继续补报可保留的事实 | AC-39、AC-41、AC-43、AC-55、AC-58 |
| Gateway 已记录但 backend 不可用期间 Gateway 重启，或 backend 确认在途中丢失 | 未确认事实在补报保留范围内恢复后续报；已提交事件重复投递不重复计数，不能把未确认当成交付完成 | AC-39、AC-41、AC-58 |
| 没有事件或部分阶段缺少结果 | 按优先序确定汇总；没有命中或检查失败事实时显示未收到完整结果，不把未知当作通过或关闭 | AC-33、AC-34、AC-44 |
| 输入关闭而输出通过、检查失败或因 backend 准入失败而不适用 | 分别汇总为通过、检查失败或不适用；只有输入、输出都明确关闭才汇总为已关闭 | AC-33、AC-34 |
| 使用默认最近 7 天连续翻页，或显式更改过滤条件 | 沿用既有分页，不固定默认相对时间窗口；更改显式过滤条件时清游标 | AC-49、AC-50 |
| 请求量和明细量持续增长、组合筛选触及支持范围 | 有界分页，明确提示超范围或未扫描完成，不伪装为完整空结果 | AC-26、AC-48、AC-50 |
| 事件明细已清理或审计记录已删除 | 不重置仍有效的命中摘要，不因迟到补报重新创建已删除记录 | AC-51 |
