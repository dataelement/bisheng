# Feature: F068 知识空间问答与目录解耦、历史对话按空间保留

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> 本文只定义业务范围与验收标准；实现方案、数据迁移、事务边界、接口与文件清单在设计确认后记录于
> [design.md](./design.md)。

**关联 PRD**: [《0923 中粮需求响应》§10「知识空间问答与目录解耦，历史对话按空间保留」](https://dataelem.feishu.cn/wiki/YPnUwk9ZjiNYPdkmh1DcmiRnnac#doxcnRszbttZbgrh4uKeJExEcSf)
**原始需求**: 0902-01
**优先级**: P1
**所属版本**: v3.0.0-beta1
**依赖**: v2.6.0 F034 文件/文件夹移动、F048 资源权限模型、既有知识空间问答
**状态**: ✅ Spec、会话时间语义、best-effort 异步收敛及 `clear_space` 范围修订已于 2026-09-18 确认；`tasks.md` 已生成

> **范围边界**
> - **本次纳入**：
>   - 文件、文件夹及文件夹子树被删除后，其关联历史对话在原知识空间根目录继续可见。
>   - 清空知识空间内容（`clear_space`，保留空间本身）后，被清空文件和文件夹的关联历史对话在该空间根目录继续可见。
>   - 文件、文件夹及文件夹子树跨知识空间移动后，其源空间历史对话在原知识空间根目录继续可见，且不进入目标空间。
>   - 同时覆盖文件夹问答与单文件问答、单项与批量操作、页面与直接业务调用。
>   - 回收后的会话可按原知识空间根目录的全空间范围继续问答。
>   - 恢复上线前已经失去目录入口、但会话历史仍存在的数据。
>   - 在线删除、清空空间内容或跨空间移动后的入口回收采用 best-effort 异步收敛，允许定向任务完成前短暂不可见，也接受派发/执行故障造成的持续失联残余。
> - **本次明确排除**：
>   - 完整删除知识空间不主动派发回收，也不提供可访问的历史入口；既有旧会话和此前已排队任务可能留下的不可访问入口元数据允许保留。仅保留空间本身的 `clear_space` 属于本期范围。
>   - 同一知识空间内的移动和资源重命名不触发根目录回收。
>   - 不恢复用户主动删除的会话、用户主动清空的消息或已删除知识空间的会话入口。
>   - 不改变普通工作台、助手、工作流、灵思或频道文章会话。
>   - 不新增跨用户共享会话、会话导出或全局历史中心。
>   - 跨空间移动因版本链联动搬迁、但不在 valid item 直接 move rows 内的 sibling file 会话不纳入本期在线回收；当前可见主版本文件及其会话仍在范围内。

---

## 1. 用户故事

作为 **在知识空间文件夹或单个文件中发起过问答的用户**，
我希望 **关联文件或文件夹被删除或移出原知识空间后，仍能在原空间找到完整历史对话**，
以便 **目录整理不会让已经形成的工作记录失去入口**。

作为 **需要继续利用历史上下文的用户**，
我希望 **从原空间根目录打开回收会话后仍可继续提问**，
以便 **在原目录已失效时按整个原知识空间继续工作**。

作为 **知识空间管理员**，
我希望 **历史保留不改变空间权限、会话所有者和目标空间数据边界**，
以便 **修复可见性问题时不产生跨用户或跨空间泄漏**。

## 2. 验收标准

> AC-01～AC-18（含 AC-04A）描述定向任务成功执行后的目标态；在线派发和执行失败以 AC-19 的 best-effort 边界为准，不构成资源操作回滚条件。

### 2.1 删除后的历史保留

- **AC-01** — WHEN 用户成功删除一个文件, THE SYSTEM SHALL 将该文件关联且未被用户主动删除的知识空间问答会话保留在原知识空间根目录。
- **AC-02** — WHEN 用户成功删除一个文件夹, THE SYSTEM SHALL 将该文件夹以及其全部后代文件夹和文件关联且未被用户主动删除的问答会话保留在原知识空间根目录。
- **AC-03** — WHEN 用户通过批量操作成功删除文件、文件夹或混合选中项, THE SYSTEM SHALL 对每个被删除项及其后代应用与单项删除相同的历史保留规则。
- **AC-04** — WHEN 一个资源删除单元的硬删除已经提交, THE SYSTEM SHALL 立即 best-effort 尝试派发仅面向该单元影响范围的会话入口回收；已成功执行的任务应使匹配会话从原知识空间根目录找到，派发/执行故障不得改变删除结果。
- **AC-04A** — WHEN 用户成功清空一个知识空间但保留空间本身, THE SYSTEM SHALL 在清空数据提交后 best-effort 尝试回收清空前全部文件和文件夹的活动会话，使任务成功处理的会话从该空间根目录找到；完整删除知识空间自身不得新派发该回收，但不要求取消此前已经排队的任务。

### 2.2 跨空间移动后的历史保留

- **AC-05** — WHEN 用户成功将一个文件移出原知识空间, THE SYSTEM SHALL 将该文件在源空间产生且未被用户主动删除的问答会话保留在源空间根目录。
- **AC-06** — WHEN 用户成功将一个文件夹移出原知识空间, THE SYSTEM SHALL 对该文件夹以及本次直接 move rows 中的后代文件夹和文件 best-effort 回收源空间问答会话；版本链额外扩展、但不在直接 move rows 内的 sibling file 不在本期在线保证范围。
- **AC-07** — THE SYSTEM SHALL 不在目标知识空间展示、复制或继承上述源空间历史会话。
- **AC-08** — WHEN 文件或文件夹只在同一知识空间内移动, THE SYSTEM SHALL 保持其现有会话归属，不将会话回收到根目录。
- **AC-09** — WHEN 文件或文件夹仅发生重命名, THE SYSTEM SHALL 保持其现有会话归属。

### 2.3 回收会话的可用性与完整性

- **AC-10** — WHEN 有权用户在原知识空间根目录查看历史列表, THE SYSTEM SHALL 将回收会话与原有根目录会话一并按既有排序规则展示，且同一会话只出现一次。
- **AC-11** — WHEN 用户打开回收会话, THE SYSTEM SHALL 展示该会话的完整现存消息，并保持会话标题、消息顺序、引用、反馈状态、创建人、会话创建时间及消息创建/更新时间不变；会话元数据更新时间可因入口归属变化按既有机制刷新，且不作为知识空间会话排序或最后消息时间。
- **AC-12** — WHEN 用户对回收会话执行既有的打开、切换、重命名或删除操作, THE SYSTEM SHALL 提供与普通根目录会话一致的用户可见行为。
- **AC-13** — WHEN 用户从回收会话继续提问, THE SYSTEM SHALL 保留可用的历史上下文，并按原知识空间根目录的全空间范围处理后续知识检索，不再依赖已删除或已移出的文件/文件夹范围。
- **AC-14** — WHEN 会话已因删除、清空空间内容或跨空间移动被回收到原空间根目录, THE SYSTEM SHALL 保持该归属；即使同一资源标识随后重新出现或资源被移回原空间，也不得自动把会话重新绑定到该资源。
- **AC-15** — WHEN 同一删除、清空、移动或历史恢复动作被重复执行, THE SYSTEM SHALL 保持结果幂等，不复制会话或消息，也不在根目录生成重复入口。

### 2.4 权限、失败与历史数据

- **AC-16** — THE SYSTEM SHALL 只向会话所有者展示其本人可访问的回收会话，不得因回收扩大到同空间其他用户。
- **AC-17** — WHEN 用户查看、打开或继续使用回收会话, THE SYSTEM SHALL 继续校验其对原知识空间的现行访问权限；无权访问原空间的用户不得通过历史入口读取会话或空间内容。
- **AC-18** — THE SYSTEM SHALL 只改变历史会话在原空间内的可见范围，不改变会话所有者，也不把源空间权限、内容或会话授予目标空间用户。
- **AC-19** — IF 异步入口回收派发或执行失败, THEN THE SYSTEM SHALL 不回滚或阻断已经提交的删除、清空空间内容或跨空间移动；在进程能够捕获失败时记录影响范围和失败阶段，并允许人工重试或维护期迁移修复。本期不承诺资源提交与任务入队原子，也不保证提交后进程退出或任务终态失败一定自动恢复。
- **AC-20** — WHILE 会话创建与删除、清空空间内容或跨空间移动并发发生, THE SYSTEM SHALL 不删除会话或消息；定向回收任务成功执行时，对扫描前已经提交的受影响会话写入原空间根入口。任务扫描后才提交的极低概率会话允许保留既有竞态，不要求为此阻塞或复查正常会话创建。
- **AC-21** — WHEN 本 Feature 上线, THE SYSTEM SHALL 使上线前因关联文件/文件夹已删除或已移出原空间而失去入口、但会话仍存在的历史按相同规则恢复到原空间根目录。
- **AC-22** — THE SYSTEM SHALL 不恢复用户主动删除的会话、用户主动清空的消息，也不为已经删除的知识空间提供可访问的历史入口；完整删除空间不要求物理删除旧会话、清空既有 `entry_flow_id` 或取消此前已排队的回收任务。
- **AC-23** — WHEN 相同目录操作分别通过页面或直接业务调用完成, THE SYSTEM SHALL 产生一致的历史保留、原空间归属和权限结果。
- **AC-24** — THE SYSTEM SHALL 保持本 Feature 范围外的普通工作台、助手、工作流、灵思和频道文章会话行为不变。

## 3. 边界情况

- 一个文件夹包含多层子目录、单文件问答和文件夹问答时，所有受影响会话都应保留，未受影响的兄弟目录会话不得改变。
- 清空知识空间时应使用清空前已经取得的完整子资源集合回收会话；空空间清空为 no-op。完整删除空间不主动派发且不可访问，但允许保留旧会话及排队任务写入的失效入口元数据。
- 一次批量操作同时包含父文件夹和其后代时，服务端必须在执行删除前移除已被祖先覆盖的顶层后代输入；同一资源只删除一次，同一会话只回收一次。
- 源空间与目标空间中存在相似名称或相同资源标识时，源空间历史仍不得出现在目标空间，也不得自动回绑。
- 回收会话与原根目录会话标题相同不构成合并条件；两者都应保留且不能互相覆盖。
- 根目录请求携带的 `chat_id` 若尚未回收到该根入口、属于其他空间/用户或已删除，必须拒绝且不得读取或写入消息；只有当前入口已是原空间根目录的会话才能按全空间范围继续问答。
- 用户在资源操作后失去原空间权限时，历史仍归原空间，但在重新获得合法权限前不可见、不可继续使用。
- 存量历史无法可靠证明其原空间、会话所有者或未被用户主动删除时，必须失败关闭，不得猜测归属或扩大可见范围。
- 在线回收只检查本次删除、清空或移动冻结的影响范围；不得为消除并发、派发或执行故障窗口而周期性扫描全部知识空间会话。允许在明确维护窗口受控运行存量迁移脚本。
