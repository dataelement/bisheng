# 需求与验收

## 问题和边界

知识库编辑者在文件夹被单独授权为查看者后，门户仍允许打开上传操作。
本地已复现：`permissions/check` 返回 allowed=true，而 add_file 在读文件前抛出 SpacePermissionDeniedError。
根因是页面查询累加上级权限、业务接口采用最近一级授权；前端异步布尔状态还会沿用上一目录。

修复仅覆盖知识库文件夹/文件细粒度操作查询、两处列表写权限状态和实际使用的门户 PortalHeaderActions。
不改 Schema、授权记录、OpenFGA 模型、管理员隐式权限或其他资源类型。未使用的 FilePane 不扩展改动。

## Requirements

- REQ-1：文件夹/文件操作查询采用最近一级匹配授权。没有子级授权时继承上级；有子级空模型时不恢复上级写权限。保留现有隐式管理员/所有者特殊权限。
- REQ-2：切换知识库、目录、账号时，在新权限返回前禁止写操作；失败默认拒绝；迟到结果不得恢复旧权限。
- REQ-3：无上传权限时隐藏上传和网页链接，无创建权限时隐藏新建文件夹。拖放、文件选择和空列表上传也服从当前目录权限。

## Acceptance Criteria

| ID | 可观察结果 | Verification |
|---|---|---|
| AC-1 | 库编辑者+目录查看者查询拒绝上传/创建，子文件拒绝编辑；真实上传校验保持拒绝 | 真实权限路由和细粒度解析回归、add_file 拒绝回归 |
| AC-2 | 未独立授权继承、内层编辑授权恢复、空模型拒绝、FGA 读取故障绑定降级和现有特殊权限保持 | 参数化后端回归和既有权限集 |
| AC-3 | 导航/账号变化立即禁止写操作，迟到允许响应与失败均不恢复操作 | 共享 hook 状态测试及列表接入验证 |
| AC-4 | 查看者无三个写入口，有权限时保留操作及筛选 | HeaderActions DOM 测试、真实浏览器观察、前端构建 |
