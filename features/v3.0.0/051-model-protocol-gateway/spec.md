> **范围边界**
>
> 本 Feature 是 PRD-1 DEV-02 的**模型协议直连面**：讲 OpenAI 协议的客户端凭一把服务账号密钥（托管应用则凭其运行期凭据）直连租户已启用的平台托管模型并流式返回，每次调用逐条留痕。它站在 F049 的凭据地基上，是 F053（接入信息与本地 dev）与 F055（能力总线「模型」项）的运行期通道。**MCP 工具面归 F052，本 Feature 与其只共享「可用模型范围」这一判定。**
>
> - **本次纳入**：
>   - **OpenAI 兼容模型协议直连面**：对外只承诺 **OpenAI 兼容子集**——**对话补全（含流式）** 与 **模型列表** 两类端点为承诺面；讲 OpenAI 协议的客户端按官方 OpenAI 兼容客户端默认用法（base URL + 密钥 + 模型名）即可直连并流式返回，无需平台专有 SDK 或本地插件；承诺面之外的 OpenAI 协议路径本版不暴露、以明确响应拒绝（§4 决议-1）；鉴权 = 服务账号密钥 + `model:invoke` 位（缺位 403 指明缺哪一位）；仅模式 S（以服务账号自身身份执行）
>   - **可用模型范围**：服务账号密钥 = 密钥所属租户在模型管理页**可见且已启用**的对话类模型（GOV-05 模型项：租户管理员配置一次、租户内共享，含 Root 共享给该租户的模型；租户级、非 per-key）；托管应用运行期凭据 = 该应用**当前生效能力声明**中的模型 ∩ 上述租户已启用集合（未声明 → 「能力未声明」可区分错误，GOV-05 验收 3 / F055 AC-51 在模型面的执行点，§4 决议-8）；模型名 = 模型管理页原名、无逻辑档位转换；**租户内跨服务商同名的歧义规则**（§4 决议-2：拒绝裸名 + 提供限定名，不取默认）；不可用 / 已下线 / 已删除模型的明确错误（GOV-05 能力收回错误态在模型面的表现）；本面「哪些模型可用、某名字解析为谁」的判定与 F052 模型清单工具、F055 能力声明预检**三处同源**
>   - **逐条模型调用审计带维度**（release-contract 表 1 **ModelCallRecord**，本 Feature 写入、F056 只读）：每次调用记录密钥 / 服务账号（可追溯资源归属人）、模型（含所属服务商）、时间、token 数、结果；托管应用运行期经本面调用时带出应用维度（actor = 应用、subject = 由 F054 AC-34 短时访问凭据确立的当前访问用户，与 F055 AC-55 对齐——本 Feature 负责在调用记录上带出这些维度并可按 key / 对象应用 / 时间筛选）；被拒调用计审计事件、不入用量；记录不含消息正文与密钥明文；用量计入平台既有 token 用量口径（同一账本）；**聚合账单本版不做**（§5.2 顺延）；token 用量只计量、不设上限
>   - **`delegate` 入口拒绝**（INV-31 的模型面）：持 `delegate` 的密钥在本面入口按权限位直接拒绝，错误指向「委托专用、本地开发另签一把」，不得静默落回模式 S、不得只回参数错误码；任何委托类身份传递头一律拒绝
>   - **与 `chat:invoke` 互不蕴含**：本面是裸协议透传——不建会话、不持久化历史、不注入平台提示词、不挂平台工具与知识库；持 `chat:invoke` 而无 `model:invoke` 的密钥调用本面被拒，反之亦然（反向由 F049 / F058 承接）
>   - **开放能力层开关（F049 拥有）**未开时本面不可达；已开时不依赖工场运行时层即可用；对外提供**单一稳定的 base URL** 供 F053 接入信息区展示与 F054 / F055 运行期注入
>   - **本地引擎适配的对外承诺**：讲 OpenAI 对话补全协议的本地引擎（Qwen Code / Codex CLI / Kimi Code 等）可直连并流式返回；只讲 Anthropic 协议的工具（如客户自装的 Claude Code）连接被拒并给出明确提示；托管应用运行期与本地 `bisheng dev` 期对本面的接法完全一致
> - **本次明确排除**：
>   - **Anthropic 兼容面**——本版**只承诺、只测试、只对外暴露 OpenAI 兼容子集**（PRD-1 DEV-02 / 产品方案 §3.4 决议）；design 若采用的现成代理自带 Anthropic 端点，那是附赠、**不在承诺、测试与对外宣传范围内**、且不暴露到本面承诺面（§4 决议-1）；只讲 Anthropic 协议的引擎走其自带订阅（产品方案 §4.3 路径 B）
>   - **模型清单查询的 MCP 工具**——F052；本 Feature 只保证「可用模型范围」的判定与 F052 一致（AC-10）
>   - **`chat:invoke` 日常模式会话 Responses 契约**（伴生 §4.6.3）——F058；OpenAI Responses 协议路径在本面不承诺、不暴露（它属另一数据面而非本面缺件，§3）
>   - **按 key / 按应用的聚合用量账单与用量可视**（PRD-1 §5.2 顺延 v3.1）——本版只逐条计量与留痕（AC-25）；将来补做的注意事项（用量表加维度而非反查遥测）作为 design 约束登记（§4 决议-6）
>   - **token 用量上限、per-key / per-app 调用频率限流**（PRD-1 §5.1「token 用量限制不做」/ §5.2「限流顺延」）——本面沿用模型管理页对服务商的既有上限配置，不新增任何上限
>   - **模型管理页本身**（服务商 / 模型配置、上下线、Root 共享）——既有能力，本 Feature 只读其结果作为可用范围
>   - **引擎凭据档案与强 / 中 / 快三档映射**（PRD-2 GOV-06，且已随 Anthropic 面一并搁置）——本面无任何逻辑档位转换（AC-11）
>   - **SDK chat 模块**——PRD-1 DEV-07 刻意不进 SDK：用官方 OpenAI 兼容客户端 + 平台注入的 base URL 与凭据即可（F053 技能包教用法）
>   - **应用运行期凭据的签发 / 重签 / 撤销**（F055 AC-57 编排、F049 底座）与**「当前生效能力声明」的定义与生效时机**（F055）——本面只读该声明并据此收窄托管应用凭据的可用模型范围（AC-34）、在记录上带出应用维度；短时访问凭据的签发与验签能力归 F054 AC-34，本面只消费其验签结果确立 subject
>   - **接入信息区与一键复制界面**（F053 AC-44）——本 Feature 只提供 base URL 这一稳定值
>   - **`delegate` 与三扩展位的签发侧互斥硬阻断**（伴生 AC-48）——F050；本 Feature 是运行期入口拒绝（伴生 AC-49 的模型面）
>   - **平台既有模型消费方（助手 / 工作流 / 工作台 / 灵思）的计量补齐**——它们不经本面；本 Feature 只保证本面的每次调用留痕、且 token 口径与平台既有计量一致（AC-23）

## 1. 用户故事

作为 **开发者的本地 coding agent（Qwen Code / Codex CLI / Kimi Code 等讲 OpenAI 协议的引擎）**，
我希望 **只配一个 base URL、一把密钥、一个模型名就能流式调到企业托管的模型**，
以便 **不改工具、不装插件就在企业模型上工作，报错时能自己看懂并纠正**。

作为 **专业开发者（同时是托管应用 owner）**，
我希望 **本地开发期与线上运行期用同一套官方 OpenAI 客户端写法、同一个模型名调平台模型**，
以便 **代码零差异，不为平台学一套私有 SDK，也不担心线上悄悄换了模型或档位**。

作为 **租户管理员**，
我希望 **在模型管理页配置一次模型，开发者与托管应用即可使用；同名模型不会被悄悄接到错的服务商；下线一个模型后调用会明确失败而不是继续消耗**，
以便 **能力的供给与收回都可控、可预期，不需要为工场再配一遍**。

作为 **租户管理员 / 平台超管（审计视角）**，
我希望 **每一次模型调用都能追溯到密钥、服务账号（及其资源归属人）或应用与访问用户，含模型与 token 数**，
以便 **出问题时定位到人、了解谁在用什么模型用了多少——即便本版没有账单**。

作为 **安全与合规负责人**，
我希望 **模型面不建会话、不留正文、不承载委托、缺位即拒**，
以便 **一把密钥泄漏的爆炸半径限制在该租户模型的使用权本身，任何业务数据都不会经模型面流出**。

## 2. 验收标准

> AC 编号在本特性内唯一。与 PRD-1 / 伴生 PRD 的对应关系在括号中标注（如 `↔DEV-02 验收 4`、`↔伴生 AC-49`），便于双向追溯。
> 错误码在此仅作为可观测的对外行为引用，其定义与归属写在 design.md。「OpenAI 兼容错误体」指讲 OpenAI 协议的客户端能按其错误约定解析并呈现的响应，其字段形状属 design。

### 2.1 协议面与鉴权

- **AC-01** — THE SYSTEM SHALL 提供一个 OpenAI 兼容的模型协议直连面，承诺面为两类端点：**对话补全**（含流式）与**模型列表**；讲 OpenAI 协议的客户端只需配置平台给出的 base URL、一把服务账号密钥与模型名，按官方 OpenAI 兼容客户端的默认用法即可调用，不需要平台专有 SDK 或本地端插件。（↔DEV-02 模型协议直连面表·协议 / 验收 4；DEV-07「chat 不进 SDK」/ 验收 2；伴生 B.2 模型协议面行）
- **AC-02** — THE SYSTEM SHALL 使本面只承诺、只测试、只对外暴露上述 OpenAI 兼容子集；OpenAI 协议族中承诺面之外的路径（如 embeddings、旧式 completions、responses、images / audio / files / fine-tuning / assistants 等）本版不暴露——请求得到明确的「本版不提供该端点」可读响应，不静默转发到任何上游、不以未定义错误或 5xx 收场。（§4 决议-1；DEV-02 表·协议）
- **AC-03** — IF 客户端按 Anthropic 协议路径请求本面（只讲 Anthropic 协议的工具接入）, THEN THE SYSTEM SHALL 返回可读的明确提示「本版仅提供 OpenAI 兼容面」并拒绝，不做协议错译或静默转发；本 Feature 交付的任何文档、接入信息与对外材料只讲 OpenAI 兼容面。（↔DEV-02 表·协议 / 验收 4；产品方案 §3.4；§4 决议-1）
- **AC-04** — WHEN 请求携带有效服务账号密钥且该密钥持 `model:invoke`, THE SYSTEM SHALL 以该服务账号自身身份（模式 S）执行，租户上下文取密钥所属租户；本面不存在任何按他人身份执行的路径。（↔DEV-02 ④；伴生 §4.2.4「三个扩展位只走模式 S」/ B.2；INV-31）
- **AC-05** — IF 请求未携带凭据、凭据无效、已撤销、已过期，或其服务账号已停用 / 删除, THEN THE SYSTEM SHALL 返回 401 且不执行调用、不返回任何模型信息（含模型列表）；撤销 / 停用 / 删除的生效上界与 F049 一致（5 秒），无任何回落身份。（↔DEV-01 ④ / 验收 2 / 验收 7；F049 AC-01 / AC-03 / AC-21；INV-27 / INV-28）
- **AC-06** — IF 凭据有效但缺少 `model:invoke`（含仅持 `chat:invoke` 或未勾任何位的密钥）, THEN THE SYSTEM SHALL 对对话补全与模型列表两类端点均返回 403 并指明缺少 `model:invoke`；`chat:invoke` 与 `model:invoke` **互不蕴含**——持 `model:invoke` 而无 `chat:invoke` 的密钥同样不能调用日常模式会话端点（该侧由 F049 / F058 承接）。（↔DEV-01 ① 映射表 / 验收 5；伴生 §4.2.4 扩展位表 `model:invoke` 行；F049 AC-04）
- **AC-07** — WHEN 管理员编辑密钥权限位（授予或移除 `model:invoke`）, THE SYSTEM SHALL 使本面自下一次调用起**立即**按新配置放行或拒绝，无需重签密钥（同 F049 AC-08）。（↔DEV-01 ② / 验收 5；F049 AC-08）
- **AC-08** — THE SYSTEM SHALL 使本面的一切错误响应对 OpenAI 兼容客户端可解析（HTTP 状态语义正确、错误体含可读原因与平台错误标识），使本地 agent 能自行区分以下类别并纠正：「凭据错」/「缺位」/「委托专用密钥被拒」/「模型不存在或已收回」/「能力未声明」（托管应用凭据，AC-34）/「超出上游 / 平台上限」/「端点不支持」/「上游失败」；不出现裸 5xx 字符串或平台内部堆栈。（↔DEV-03「调错了平台报错明确（404 / 401），agent 自己就能纠正」；产品方案 §4.6 现存端点反面教材）

### 2.2 可用模型范围与名称解析

- **AC-09** — THE SYSTEM SHALL 使本面的可用模型范围按凭据主体分两档：**服务账号密钥** = 密钥所属租户在模型管理页**可见且已启用**的对话类模型（含 Root 共享给该租户的模型），租户级、非 per-key；**托管应用运行期凭据** = 该应用当前生效能力声明中的模型 ∩ 上述租户已启用集合（AC-34）。租户管理员在模型管理页配置一次即对本面生效，无需任何额外配置或重签密钥。（↔DEV-02 表·可用模型范围；GOV-05 界面表·模型 / 验收 1；伴生 B.2 模型清单行「非 per-user」）
- **AC-10** — WHEN 持 `model:invoke` 的凭据请求模型列表, THE SYSTEM SHALL 返回该凭据可用范围（AC-09 / AC-34）内每个模型**可直接用于调用的名称**（唯一时为原名，歧义时为限定名，AC-12）与是否对话类，不返回服务商凭据、端点等任何配置；本面的名称解析规则是唯一出处——F052 AC-13（模型清单工具返回可直接调用的唯一名称与对话类标注）与 F055 AC-07（预检要求所引模型按本规则可唯一解析、裸名歧义拒绝）均按本面规则执行，三处对「哪些模型可用、某个名字解析为谁」得到同一结论（**三处同源**）。（↔DEV-02 工具表「模型清单查询」；F052 AC-13；F055 AC-07 / AC-49）
- **AC-11** — THE SYSTEM SHALL 以模型管理页「模型名称」原文作为本面的模型名：精确匹配、无逻辑档位转换（不存在强 / 中 / 快之类映射）、无别名与模糊匹配。（↔GOV-05 模型项「模型管理页原名，无逻辑档位转换」；DEV-03 表·平台能力接线；DEV-07；§4 决议-3）
- **AC-12** — IF 租户内存在跨服务商同名的多个可用模型（歧义）, THEN THE SYSTEM SHALL 拒绝以裸名发起的调用并在错误中列出可用的限定名（服务商名 + 模型名的组合形式）；以限定名调用可唯一解析（限定名在名称唯一时同样可用）；模型列表对歧义模型只给出限定名。THE SYSTEM SHALL NOT 在歧义时按任何默认规则（最早创建 / 首个服务商等）静默择一。（§4 决议-2；Discovery §2.5 / §4.2 次级决策「模型名歧义规则」）
- **AC-13** — IF 请求的模型名在该租户可见范围内不存在（含属于其它租户、非对话类、名称不匹配）、已下线（未启用）或其服务商已删除, THEN THE SYSTEM SHALL 返回 4xx 的 OpenAI 兼容错误体并指明模型名与原因（不存在 / 已下线 / 已收回）——可与普通调用失败区分；对其它租户的模型一律按「不存在」处理，不透露存在性。（↔GOV-05 规则「能力收回后行为」/ 验收 4；F055 AC-53 在模型面的表现；DEV-02 表·可用模型范围）
- **AC-14** — WHEN 租户管理员在模型管理页下线或删除某模型 / 服务商, THE SYSTEM SHALL 使本面对该模型的**新**调用自变更起最多 60 秒内开始返回 AC-13 的错误（生效上界）；已在途的响应（含流式）不被强行切断。（§4 决议-4）
- **AC-15** — THE SYSTEM SHALL 使本面对某模型「能否调用」的判定与平台内助手 / 工作流消费同一模型时一致（启用状态、模型管理页对服务商的既有调用上限等既有配置一体沿用），超出既有上限时返回 AC-08「超出上游 / 平台上限」类别的明确错误；THE SYSTEM SHALL NOT 为本面新增 per-key / per-app 的调用频率限制或 token 用量上限。（↔DEV-01 ②「token 用量只计量、不设上限」；§5.1「token 用量限制不做」；§5.2 限流顺延）

### 2.3 流式与透传

- **AC-16** — WHEN 对话补全请求要求流式, THE SYSTEM SHALL 以 OpenAI 流式事件形状边生成边转发（不缓冲整段后一次性返回）；IF 上游在流式过程中失败或中断, THEN THE SYSTEM SHALL 以可读的错误收尾并关闭连接、不挂起。（↔DEV-02 表·协议「支持流式」/ 验收 4）
- **AC-17** — THE SYSTEM SHALL 使本面为裸协议透传：不创建平台会话、不持久化任何消息正文、不注入平台提示词、不改写调用方消息与采样参数、不挂载知识库与平台工具；除模型名解析、鉴权与计量所需的元数据外，请求与响应语义与调用方直连该服务商等价。（↔伴生 §4.2.4 `model:invoke` 行「裸协议透传，不建会话、不持久化历史」；DEV-01 ① 映射表）
- **AC-18** — THE SYSTEM SHALL 使对话补全对以下对话要素透传可用：system / user / assistant 消息（多轮）、流式、temperature / top_p / max_tokens / stop、**工具调用（tools / tool_choice 与 tool 角色消息的结果回传）**——本地 coding agent 依赖工具调用，必须透传——以及按协议约定返回的用量；超出该枚举的请求字段原样透传但不作承诺；IF 上游模型不支持调用方使用的某要素, THEN THE SYSTEM SHALL 把上游错误以可读形式返回，不静默丢弃该要素。（↔DEV-02 验收 4；DEV-07 验收 2）
- **AC-19** — THE SYSTEM SHALL 使经本面的调用不产生平台会话记录：不出现在任何用户或服务账号的会话列表、不可经 V2 会话 / Responses 类接口取回、不留历史——与 `chat:invoke` 的数据面完全不同。（↔伴生 §4.2.4「二者数据面不同，需要哪个给哪个」）

### 2.4 逐条调用审计维度

- **AC-20** — WHEN 一次经鉴权的调用到达模型解析阶段（无论成功、上游失败或模型不可用）, THE SYSTEM SHALL 记录一条模型调用记录：密钥（掩码或标识）、服务账号（据此可追溯其资源归属人）、模型（解析后的模型与所属服务商）、时间、输入 / 输出 / 合计 token 数、结果（成功 / 失败及原因类别）；记录不含消息正文、不含密钥明文。IF 调用在到达模型解析阶段前被拒（无凭据 / 凭据无效 / 缺位 / 委托专用密钥, AC-05 / AC-06 / AC-26）, THEN THE SYSTEM SHALL 记录一条**被拒调用的审计事件**（凭据可识别时归属到该凭据与其主体，不可识别时只记事件与拒绝原因；时间；不入用量、token 为空），使每次调用（含被拒）可归属。（↔DEV-01 验收 1「每次调用可归属」；GOV-04 事件清单「模型调用记录」/ 验收 2；NFR-2；§4 决议-7）
- **AC-21** — WHEN 调用凭据的主体为托管应用（F055 AC-57 签发的应用运行期凭据）, THE SYSTEM SHALL 在调用记录上带出应用维度（actor = 应用）；WHEN 该调用随运行期凭据一同呈现 F054 AC-34 由 app-proxy 签发、平台可验签的**短时访问凭据**且验签有效, THE SYSTEM SHALL 记录 subject = 该访问凭据所绑定的用户；无访问凭据的调用（如应用后台任务）subject 记为「应用自身」并显式标注，**不得**记为任意用户。subject 只用于审计归属，不改变可用模型范围（由凭据主体决定，AC-09 / AC-34）与任何权限判定；subject 的确立不经任何请求头字段。（↔GOV-04 事件清单「应用运行期能力调用」双归属；F054 AC-34；F055 AC-49 / AC-55；§4 决议-5）
- **AC-22** — IF 服务账号密钥发起的调用附带任何访问凭据、或以任何方式试图指定他人为 subject, THEN THE SYSTEM SHALL 拒绝该调用（本地开发三面无第三方在场）；服务账号密钥的调用 subject 恒为该服务账号自身。（↔INV-31；DEV-02 ④；§4 决议-5）
- **AC-23** — THE SYSTEM SHALL 使 token 数计量不依赖调用方是否在请求中要求返回用量；IF 上游未提供用量, THEN THE SYSTEM SHALL 把 token 数记为「未知」（区别于 0）、不估算伪造；本面调用**计入平台既有 token 用量统计（同一账本，不另立一套）**，同一次调用在本面记录的 token 数与既有口径一致，不出现两套口径。（↔DEV-01 ②；GOV-04 验收 3；release-contract 表 1 ModelCallRecord）
- **AC-24** — WHEN 租户管理员按密钥 / 对象应用 / 时间范围筛选查询, THE SYSTEM SHALL 返回逐条模型调用记录，每条含服务账号（及其资源归属人）、模型（含服务商）、时间、token 数、结果、subject 等记录列并可导出；服务账号 / 模型 / token 数为**记录列**而非筛选器（本版不承诺按其筛选，与 F056 一致）；租户管理员限本租户，平台超管可跨租户；管理面审计查询面的接线与可查性由 F056 保证。（↔GOV-04 验收 3 / 验收 4；F056 AC-25）
- **AC-25** — THE SYSTEM SHALL NOT 提供按 key / 按应用的聚合用量账单、用量可视化或用量上限；本版只逐条计量与留痕。（↔GOV-04 事件清单「逐条留痕，本版不做聚合账单」；§5.2 顺延）

### 2.5 `delegate` 与模式 S

- **AC-26** — IF 密钥持有 `delegate`, THEN THE SYSTEM SHALL 在本面入口按权限位直接拒绝，错误信息指向「这把密钥配置为委托专用，本地开发请另签一把」；THE SYSTEM SHALL NOT 表现为按服务账号身份正常执行（静默落回模式 S），也不得只返回参数缺失类错误码。（↔伴生 AC-49；DEV-02 ④ / 验收 10；INV-31）
- **AC-27** — IF 请求携带任何委托类身份传递头（代表平台用户 / 外部用户标识）, THEN THE SYSTEM SHALL 拒绝并提示本面不承载委托，不得静默忽略该头继续执行。（↔F049 AC-33 同形；伴生 §4.2.4「三面只走模式 S」；INV-31）

### 2.6 开放能力层开关与接入信息

- **AC-28** — WHERE 开放能力层未部署, THE SYSTEM SHALL 使本面不可达（得到「端点不存在」类响应、不透露本面存在与否）；服务账号模块与 V2 开放 API 不受影响。（↔GOV-10 规则 / 验收 4；F049 AC-49）
- **AC-29** — WHERE 开放能力层已部署而工场运行时层未部署, THE SYSTEM SHALL 使本面对服务账号密钥完整可用（不依赖任何工场运行时能力）。（↔GOV-10 验收 3）
- **AC-30** — THE SYSTEM SHALL 对外提供**单一、稳定**的 OpenAI 兼容 base URL——不因租户或密钥而异、不随平台升级变化——供 F053 接入信息区展示与一键复制、`bisheng dev` 同名环境变量注入，以及 F054 / F055 托管运行期注入使用；本 Feature 不拥有任何展示界面。（↔DEV-01 界面表「接入信息区」/ ⑤；F053 AC-27 / AC-44；F055 AC-49）

### 2.7 引擎适配承诺

- **AC-31** — WHEN 讲 OpenAI 对话补全协议的本地引擎（如 Qwen Code、Codex CLI 的对话补全接线模式、Kimi Code 等）配置本面 base URL、服务账号密钥与模型名, THE SYSTEM SHALL 使其可直连平台托管模型并流式返回，无需任何本地端专有插件或平台改造。（↔DEV-02 表·适用对象 / 验收 4；§5.1「本地端专有插件不做」；产品方案 §4.2）
- **AC-32** — IF 本地引擎只讲 Anthropic 协议（如客户自装的 Claude Code）, THEN THE SYSTEM SHALL 使其连接本面被拒并得到 AC-03 的明确提示；此类引擎的模型走其自带订阅，本面与接入信息不宣传对其的支持。（↔DEV-02 表·协议 / 适用对象 / 验收 4；产品方案 §3.4 / §4.3 路径 B）
- **AC-33** — THE SYSTEM SHALL 使托管应用运行期与本地 `bisheng dev` 期对本面的接法完全一致——同一 base URL、同一模型名（无档位转换）、同一 OpenAI 兼容客户端用法，代码零差异；两者仅凭据不同（应用运行期凭据 vs 开发者服务账号密钥），可用模型范围随之不同：`dev` 期 = 该租户已启用模型（服务账号密钥，AC-09），运行期 = 当前生效能力声明 ∩ 租户已启用（AC-34）——本地能调的模型可能多于线上声明的，发布前须把用到的模型写进能力声明（F055 AC-07 预检把关）。（↔DEV-05；DEV-07 验收 2；F053 AC-27；F055 AC-07 / AC-49 / AC-51）

### 2.8 追加（2026-08-17 审查补齐，末尾追加不重排）

- **AC-34** — WHEN 调用凭据是托管应用运行期凭据（F055 AC-57 签发、主体类型「托管应用」）, THE SYSTEM SHALL 把可用模型范围收窄为该应用**当前生效能力声明**中的模型 ∩ 租户已启用集合（模型列表同样只返回该范围）；IF 请求的模型未在生效声明中, THEN THE SYSTEM SHALL 拒绝并返回「能力未声明」的可区分错误（与 AC-13「不存在 / 已下线 / 已收回」及 AC-06 缺位可区分）；声明变更随发布生效（F055 AC-57 重签）；该收窄不是 per-user、不构成模式 D。服务账号密钥维持 AC-09 的租户级范围。（↔GOV-05 验收 3；F055 AC-51 / AC-53；§4 决议-8）

## 3. 边界情况

> 只写期望的对外行为；实现层的落点、缓存与数据访问细节见 design.md §5。

- **同名模型歧义是产品级风险，不是实现细节**：租户内跨服务商同名的「模型名称」在模型管理页是合法配置（Discovery §2.5），静默择一等于把调用绑到错误的服务商凭据上、且不报错只错。因此裸名歧义一律拒绝、限定名恒可解析（AC-12）；歧义只在「租户内可见且已启用」的集合上判定——同名模型之一下线后裸名恢复唯一即可直接用；F055 能力声明预检与 F052 清单工具用同一规则（AC-10），不会出现「本地能跑、发布被拒」或「清单里有、调不通」。
- **模型下线中途的流式响应**：下线 / 删除是能力配置变更而非安全事件——已在途的响应允许完成，新调用自变更起最多 60 秒内开始被拒（AC-14）；密钥撤销 / 服务账号停用属安全事件——后续调用 5 秒内被拒（AC-05），在途响应不作切断承诺（凭据面以「下一次调用」为界，与 F049 一致）。
- **密钥权限位编辑即时生效**（AC-07）：agent 无需重新 `login` 或换密钥；缺位错误告知缺的是 `model:invoke`（AC-06），而不是笼统 403——本地 agent 才知道该找管理员补哪一位。
- **跨租户模型不可见**：其它租户的模型按「不存在」处理（AC-13），不区分「没有」与「不属于你」；Root 共享给本租户的模型属可见范围（模型管理页既有语义，AC-09）。资源归属人对可用范围零影响（伴生定义 6 边界 c）——归属人只在审计追溯时出现。
- **WHERE 未部署开放能力层**：本面「端点不存在」（AC-28）；同时 F049 AC-13 使 `model:invoke` 位不出现在签发表单，不存在「有位无面」的状态；反向「有面无位」= 403 缺位（AC-06）。仅部署开放能力层（无工场运行时层）本面完整可用（AC-29）。
- **与 `chat:invoke` 数据面不同**（AC-06 / AC-17 / AC-19）：需要会话留痕、知识库、平台工具或在平台 UI 可见的对话，走 `chat:invoke`（F058）；本面不是会话 API，也不是「便宜版 chat」——两位互不顶替，需要哪个给哪个。
- **承诺面之外的路径一律不暴露**（AC-02 / AC-03）：本地引擎若默认走 OpenAI 的其它协议（如 Codex CLI 默认的 Responses 接线）须切到其对话补全模式接入；OpenAI Responses 端点在本面不承诺——它属 F058 日常模式会话契约（`chat:invoke`，另一数据面），不是本面缺件。无论 design 采用现成代理还是自研薄层，对开发者可达的只有承诺面；代理自带的管理面、UI 与其它协议端点一概不对外。
- **审计写放大**：本面暴露给本地 agent 是高频场景。对外行为只要求两点——逐条模型调用记录可按 key / 对象应用 / 时间查到（AC-24），且逐条记录的写入**不拖慢既有审计页**与其它审计事件的查询；被拒调用（无凭据 / 缺位 / 委托专用）计审计事件、不入用量（AC-20 / 决议-7）；上游失败与模型不可用仍逐条记录（结果 = 失败）。记录对象是表 1 ModelCallRecord（决议-6），落点见 design。
- **token 数「未知」不是 0**（AC-23）：上游未返回用量时不估算；客户端未请求返回用量也不影响记账；同一调用不得在本面与平台既有计量之间出现两套 token 口径。
- **既有服务商上限沿用、无新增限流**（AC-15）：模型管理页对服务商的既有调用上限是可用范围配置的一部分，超限得到明确错误；per-key 限流与 token 上限属 §5.1 / §5.2 明确不做——本面不因「暴露给外部工具」而单方面加闸。
- **非对话类模型不经本面**：embedding / rerank / asr / tts 类模型不出现在模型列表、按名请求按「不存在」处理（AC-13；§4 决议-3）。
- **默认拒绝语义与 INV-27 等价**：伴生 B.2 把本面与 V2 端点分表登记，但「无凭据即拒、无回落身份、无兼容窗口」对本面同样成立（AC-05）；商业版前置网关部署形态下本面须可达（design 落点，与 F053 同一约束）。
- **托管应用实例的网络可达**：应用实例经出站策略可达本面由 F054 保证；本 Feature 只保证 base URL 单一稳定（AC-30），运行期注入的环境变量名与 F053 `dev` 同名（F053 AC-27 / F054 / F057 对齐）。
- **凭据校验与模型解析是两道门，都 fail-closed**：凭据校验与 F049 一致（缓存 / 存储不可用即拒）；模型信息的读取延迟（AC-14 的 60 秒）不得让已撤销 / 缺位的密钥通过——第一道门失败不进第二道门；第二道门（模型配置读取 / 名称解析 / 范围确立）失败同样拒绝、不落回更宽集合（AC-35）。
- **托管应用凭据的两类拒绝可区分**：声明中的模型被管理员下线 → 「已收回」（AC-13，F055 AC-53 据此在发布面标「已失效」）；模型未写进能力声明 → 「能力未声明」（AC-34）——owner 与本地 agent 据此分辨是「忘了声明」还是「被收回」；本地 `dev` 期用服务账号密钥不受声明收窄，故「本地能跑、线上未声明」由 F055 预检在发布前拦下（AC-33）。
- **上游错误可读透传**：上游 4xx（内容拦截、上下文超长、参数不支持等）以可读错误体原样返回（AC-08 / AC-18），不包装成 5xx，也不改写成平台内部错误。

## 4. 待澄清决议

> 2026-08-17 用户授权全自动模式：以下各项按建议直接定案，记录理由与备选供追溯；spec 评审（`/sdd-review`）后如有 high 级发现再增补。Discovery §4.2 次级决策清单中「模型名歧义规则（跨服务商同名 model_name，F051）」在此定案（决议-2）。

- **[决议-1] 对外只承诺 OpenAI 兼容子集（对话补全 + 模型列表）；承诺面之外的路径一律不暴露并以明确响应拒绝；Anthropic 协议路径给「本版仅提供 OpenAI 兼容面」提示。协议面用现成代理还是自研薄层归 design。** 理由：PRD-1 DEV-02 与产品方案 §3.4 已定「仅 OpenAI 兼容、Anthropic 面本版不承诺」；三个候选引擎全讲 OpenAI 协议，主路径不依赖 Anthropic 面；DEV-02 验收 4 明写「仅讲 Anthropic 协议的工具连接被拒并给出明确提示」，因此即便 design 采用的现成代理自带 Anthropic 端点，也**不暴露到本面承诺面**——这与产品方案「附赠不在承诺、测试与宣传范围」一致（不暴露即无需宣传），且避免形成开发者会依赖的隐性契约（升级时可无痛开放，反向收回会破坏调用方）。承诺面之外的 OpenAI 端点（embeddings / Responses 等）同理：本版无真实消费者（应用内 RAG 走 F052 / F057 检索面，不用裸 embeddings），不暴露、明确拒绝。**措辞红线**：对外不说「不实现 Anthropic」，说「本版只承诺 / 只测试 / 只暴露 OpenAI 兼容面」。**何时重新考虑**：v3.1 出现讲 Anthropic 协议的真实客户诉求，或托管应用出现 embeddings / Responses 的真实诉求时，在同一 base URL 下扩承诺面，不改既有契约。
- **[决议-2] 同名歧义规则 = 拒绝裸名 + 提供限定名（服务商名 + 模型名），不取默认。** 理由：静默择一等于把调用绑到错误的服务商凭据（Discovery §2.5 风险「应用声明绑定到错误凭据」），是「不报错只错」的静默失败形状——与全册「不静默降级」取向相悖；限定名给 agent 一个恒可用的稳定写法（唯一时也接受），模型列表对歧义模型只返回限定名，agent 从列表拿到的名字都能直接调通；F055 预检与 F052 清单用同一规则避免三处漂移。备选 ① 给模型管理页加租户内唯一名约束——改动既有模型管理、破坏存量合法配置，否决；备选 ② 按最早创建 / 首个服务商取默认——静默错绑，否决。**何时重新考虑**：模型管理页将来引入租户内唯一名后裸名恒唯一，本规则退化为空转但契约不需改。
- **[决议-3] 模型名基准 = 模型管理页「模型名称」字段原文（用户在页面看到并输入的调用名，非显示别名）；仅对话类模型经本面暴露；精确匹配、无别名 / 模糊匹配 / 档位转换。** 理由：PRD-1 DEV-03 / GOV-05 / DEV-07 三处一致要求「模型名即平台模型管理原名、无逻辑档位转换」，强 / 中 / 快三档映射已随 Anthropic 面一并搁置（产品方案 §4.3）；对话补全端点只对对话类模型有意义，embedding / rerank / asr / tts 走各自协议、本版无诉求（决议-1）；精确匹配是让「模型管理页看到什么名字、代码里就写什么」成立的最简规则，模糊匹配会重新引入歧义。
- **[决议-4] 模型下线 / 删除对本面新调用的生效上界 60 秒；已在途的响应（含流式）不切断；密钥撤销 / 停用沿用 F049 的 5 秒。** 理由：模型下线是能力配置变更而非安全事件，平台内助手 / 工作流对同一变更本就存在同量级的生效延迟（Discovery §2.5 风险「收回生效延迟」），不对开放面许下比平台自身更严的承诺；切断在途响应只会产生半截输出与不可诊断错误，下线的目的（停止新用量）由「新调用起拒绝」达成；凭据撤销属安全事件、维持 INV-28 的 5 秒上界。备选：即时生效——需对全部模型消费方做缓存主动失效改造，本版不做。**何时重新考虑**：平台内消费方对模型下线的生效延迟收敛得更快时，本面同步收敛，不需改契约。
- **[决议-5] 应用运行期调用的 subject 采信对象 = F054 AC-34 由 app-proxy 签发、与访问用户绑定、平台可验签的短时访问凭据（随托管应用运行期凭据一同呈现），不是任何请求头字段；验签有效 → 记 subject；无访问凭据（应用后台任务）→ subject 记「应用自身」并显式标注、不拒绝、不得记为任意用户；服务账号密钥 → subject 恒为自身，附带访问凭据或试图指定他人则拒绝；委托类身份头一律拒绝（AC-27）。** 理由：请求头可由应用代码任意填写，采信它等于允许伪造审计归属；短时访问凭据由 app-proxy 在验平台会话后签发、与访问用户绑定且不可由客户端伪造（F054 AC-34），是唯一可信的 subject 来源，与 F055 AC-55 的口径一字不差。本面的可用范围由凭据主体决定（服务账号 = 租户级，托管应用 = 生效声明）、不 per-user，subject 只承担审计归属，缺失时没有越权面、fail-closed 没有对象；应用内确实存在无用户上下文的模型调用（后台任务、定时汇总），拒绝会误伤——检索面的 fail-closed（无法取得访问用户即拒绝）归 F052 / F055（INV-36），两面取向不同是刻意的。服务账号侧拒绝是为防止本地开发密钥伪造归属，与 INV-31「本地开发三面无第三方在场」一致；`bisheng dev` 期不存在 app-proxy 也不签发访问凭据，合法流程不会触发拒绝。**访问凭据随请求的呈现形式（与运行期凭据的组合）属 design，须与 F054 AC-34 / F055 / F057 SDK 一致；F057 SDK 与 F053 技能包负责让应用侧带出，本 Feature 负责验签、采信与落记。**
- **[决议-6] 审计落点：逐条模型调用记录的对象 = release-contract 表 1 新登记的 ModelCallRecord（本 Feature 写入、F056 查询面只读）；spec 只要求「可按 key / 对象应用 / 时间查到逐条、可导出」（AC-24）与「不拖慢既有审计页」（§3）；PRD-1 §5.2「将来补账单须在用量表加 key / app 维度并打通调用链上下文，而不是从遥测侧反查」作为 design 约束登记，不作 spec 契约。** 理由：本面是高频写入面，与低频人为操作的审计事件在查询体验上必须分离，否则审计页被淹没；F056 只需保证审计查询面能按 key / 应用追溯到逐条记录（F056 AC-25），记录落在哪、怎么写是 How；把「加维度而非反查」写进 design 是为了 v3.1 聚合账单能在同一份记录上直接出账、不返工；用量同时计入平台既有 token 口径（AC-23）避免两套账本。
- **[决议-7] 计量边界：缺位 / 凭据失败 / 委托专用密钥的被拒调用计审计事件、不入用量（凭据可识别时归属到该凭据，不可识别时只记事件与原因）；上游失败与模型不可用逐条记录（结果 = 失败、token 未知）；模型管理页对服务商的既有调用上限沿用、超限明确报错；不新增 per-key / per-app 限流或 token 上限。** 理由：DEV-01 验收 1 要求「key 的每次调用可在审计中归属」，被拒的调用同样是「调用」——只记成功会让「谁在拿哪把 key 反复试」不可追溯；不入用量是因为被拒调用没有 token、也不该污染账本；失败调用留痕是排障与「谁在试图用什么模型」追溯的需要（GOV-04 逐条留痕不区分成败）；既有服务商上限是租户模型配置的一部分，本面若绕开会与平台内消费方行为不一致；限流与 token 上限是 PRD-1 §5.1 / §5.2 明确不做的项，本面不单方面加闸。**何时重新考虑**：v3.1 「精细成本控制 / 开发者 key 调用频率限流」立项时，在本面入口加闸、错误按 OpenAI 429 语义返回，不改既有契约。
- **[决议-8] 托管应用运行期凭据的可用模型范围在本面收窄为「当前生效能力声明 ∩ 租户已启用」；声明的语义与生效时机归 F055，执行点在本面。** 理由：模型面是运行期凭据调模型的唯一咽喉，F055 AC-51「未声明的能力不可调用」若不在此执行就是空文；GOV-05 验收 3「生产实例实际可用能力 = 其声明且经审批的能力集合」需要一个可判定的拒绝点；「能力未声明」与「已收回」分列两类错误（AC-13 / AC-34），owner 与本地 agent 才能分辨是忘了声明还是被管理员收回。该收窄按凭据主体判定、与访问用户无关，不构成 per-user 过滤或模式 D（INV-31 不受影响）；`dev` 期服务账号密钥不受声明收窄，「本地能跑、线上未声明」由 F055 AC-07 预检在发布前拦下。备选：本面不收窄、由 F055 在注入侧限制——F055 无法在协议面之外拦截一次具体的模型调用，否决。
