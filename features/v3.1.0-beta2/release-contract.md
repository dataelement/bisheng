## 表 1：领域对象归属

每个领域对象只能有一个 Owner Feature，负责定义该对象的写入行为
（创建、更新、删除）。其他 Feature 只能"读取"或"引用"该对象。

| 领域对象 | Owner Feature | 说明 |
|---------|--------------|------|
| 企业插件、企业工作台的可见授权（按用户 / 部门 / 用户组）及员工侧可见过滤 | F022-dsh-market-permission（本版本） | 只负责授权与员工侧（列表、详情、下载、同步）的可见过滤；企业插件、企业工作台对象本身的导入、更新、删除仍归 [F055](../v3.0.0-beta1/055-enterprise-plugin-market/spec.md) / [F019](../v3.1.0-beta1/019-dsh-market-workbench/spec.md)；授权数据只经 F048 统一权限写入与判定 |

**规则**：
- 非 Owner Feature 的 AC 中不得出现其他对象的"创建/修改/删除"行为，只能"读取"或"调用" Owner 的 Service
- 新增领域对象时必须先更新本表

## 表 2：跨 Feature 不变量（INV-N）

全局业务约束，任何 spec 的 AC **不得与之矛盾**。

| ID | 不变量描述 | 涉及领域对象 | 来源 spec |
|----|-----------|------------|---------|
| INV-B2-1 | 员工侧的企业插件、企业工作台列表、详情、下载与客户端同步，只返回或放行该员工有可见权限的项；管理后台向有管理资格的管理员显示全部。 | 企业插件、企业工作台 | F022 AC-06 / AC-07 / AC-08 |
| INV-B2-2 | 新上传的企业插件、企业工作台默认全企业可见；删除后重新导入恢复时沿用删除前的授权。 | 企业插件、企业工作台 | F022 AC-03 / AC-18 |
| INV-B2-3 | 「允许安装第三方插件 / 工作台」开关只控制公开市场的第三方内容，与企业插件、企业工作台的授权互不影响。 | 第三方安装策略、企业插件、企业工作台 | F022 AC-15 |

**规则**：
- 新增不变量：先在此表追加，再写 AC
- 修改不变量：必须列出 Impacted Specs 清单，逐一回写并重新评审
- 冲突检测：若 AC 与不变量矛盾，spec 评审不通过

## 部署注意（本版本）

- **F022 改变 F048 授权模型**：全新安装无需操作；已部署环境升级到本版本时需要一个停服维护窗口：停止全部后端进程（API / Celery / Beat / Linsight worker）→ 一致备份业务库与 OpenFGA 存储库 → 发布授权模型（先预览、再执行）→ 补登记存量企业插件与企业工作台 → 校验 → 启动全部进程；失败时恢复备份并回退镜像。只更新程序、不执行升级，会使该环境**全部**权限判定不可用。不能使用 §10.1 的 `upgrade_f048_authorization_model.py`（原因与具体命令见 F022 design.md 决策 7、§7）。
