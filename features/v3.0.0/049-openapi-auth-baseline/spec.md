>
> - **本次纳入**：
>   - **统一凭据底座**：密码学随机生成、服务端仅存单向哈希、恒时比较校验、软撤销、掩码展示（前缀 + 末四位）、明文仅签发时一次性展示、按主体批量撤销、撤销生效上界 5 秒
>   - **服务账号主体**：不可登录的一等主体（新增主体类型标识）、租户归属与可授权状态、用户列表分叉（授权选人可见 / 其余消费点不可见）、登录守卫、不占租户用户席位
>   - **服务账号密钥（`bs-sak-`）**：权限位（模块 + 动作级）、可选过期、资源白名单建表预留（本期不启用，PRD D3）
>   - **全部开放 API 端点接入鉴权**：44 个端点（含 2 个 WebSocket）无死角；默认身份模式 = 密钥主体本身（PRD 模式 S）
>   - **三条铁律**：无凭据即拒绝、缺身份 ≠ 放行全部、权限评估失败即报错（绝不返回未过滤或部分过滤的结果集）
>   - **管理界面**：密钥管理与服务账号管理（管理员）
>   - **存量迁移**：兼容窗口开关、默认操作员转型为服务账号并强制降权、迁移告警、对外文档中错误引导表述的修订
>   - **顺带修复的既有缺陷**（PRD §4.5.4 / §4.6.2 列明 + 本次基线核实新增，均在同一改造面上）：代用户解析不校验账号状态、工作流调用不校验上线状态、工作流停止不校验会话归属、助手 WebSocket 身份解析异常导致握手裸崩；**6 个完全无身份的端点**（5 个会话反馈类 + 1 个统计文件下载）补主体归属校验——其中统计下载端点当前可由调用方以任意路径参数取走服务器上任意 `.log` 文件，属越权读取，本期一并收口
> - **本次明确排除**：
>   - **三种身份模式与受限委托六道准入**（PRD R2/R3 的 P1 部分）——随 F050 交付；本期传入身份头一律拒绝，不静默忽略
>   - **个人访问令牌（绑定自然人、继承其权限的密钥）**——伴生 PRD 终版已**整条否决**（§1.4、§4.2.2、§6 非目标）：开放 API 的三类场景全是系统对系统集成，无一需要；密钥只签发给服务账号。故 F049 与 F050 **均不从伴生 PRD 继承此项**。⚠️《PRD-1》DEV-01 的个人 API key 是另一个面（MCP / 模型双协议 / CLI）的需求、且其权限模型正是「继承持有人权限」，与本条不是同一件事——两册口径的对齐见 §4 待澄清-4
>   - **裸 `user_id` 参数的收口与移除**——本期保持行为兼容（不移除、不改语义），收口随 F050 的委托准入一并做
>   - **限流、配额、IP 白名单、幂等性**（PRD R8，P2）——平台无任何 HTTP 层限流基建，不在本期
>   - **审计双归属**（PRD R7）——双归属的价值随模式 D 才成立，随 F050；本期只要求单归属（记录到密钥与其主体）
>   - **完整 OAuth 2.0 授权服务器、最终用户令牌透传、即时建号、`/api/v1` 前端接口鉴权改造、按单个端点的细粒度权限、Webhook 回调方向鉴权**（PRD §六 非目标，原样继承）
>   - **MCP / 模型双协议面复用本凭据体系**——底座在此建，接入分别随 F051 / F052

## 1. 用户故事

作为 **平台管理员 / 租户管理员**，
我希望 **每个调用开放 API 的外部系统都持有独立、可单独撤销、权限最小的凭据**，
以便 **出事时能定位到具体调用方并即时止血，而不是"谁都能调、也查不出是谁调的"**。

作为 **客户侧的集成开发者**，
我希望 **拿到一把密钥就能按既有方式调用开放 API，且升级期间存量调用不被打断**，
以便 **在不停机、不改造全部调用方的前提下完成迁移**。

作为 **安全与合规负责人**，
我希望 **平台不存在无凭据即可访问业务数据的接口，凭据本身即使数据库泄漏也无法还原**，
以便 **通过等保测评中「内部接口鉴权」这一明确失分项，并把凭据泄漏的爆炸半径限制在单把密钥**。

作为 **服务账号的使用方（自建业务系统）**，
我希望 **集成的权限锚定在一个不可登录的服务主体上**，
以便 **生产集成不因某位员工离职或调岗而中断**。

## 2. 验收标准

> AC 编号在本特性内唯一。与伴生 PRD §五验收标准的对应关系在括号中标注（如 `↔AC-1`），便于双向追溯。
> 错误码在此仅作为可观测的对外行为引用，其定义与归属写在 design.md。

### 2.1 凭据校验与生命周期

- **AC-01** — WHERE 开放 API 鉴权开关已开启, WHEN 请求未携带有效密钥, THE SYSTEM SHALL 返回 401 且不执行任何业务逻辑、不返回任何业务数据。（↔AC-1）
- **AC-02** — THE SYSTEM SHALL 使密钥明文仅在创建响应中出现一次；此后任何接口与界面对该密钥只返回掩码（前缀 + 末四位）。（↔AC-2）
- **AC-03** — WHEN 密钥被撤销, THE SYSTEM SHALL 使其后续调用在 5 秒内被拒绝。（↔AC-3）
- **AC-04** — IF 密钥缺少目标端点所需的权限位, THEN THE SYSTEM SHALL 返回 403，且错误信息指明缺少哪一位。（↔AC-4）
- **AC-05** — WHEN 密钥的过期时间到达, THE SYSTEM SHALL 拒绝其后续调用，无需任何人工干预。
- **AC-06** — THE SYSTEM SHALL 在创建密钥时默认不勾选任何权限位；未显式授予的权限位一律视为未授予。
- **AC-07** — WHEN 租户管理员查询密钥列表, THE SYSTEM SHALL 只返回本租户的密钥，跨租户查询返回空。（↔AC-5）
- **AC-08** — WHEN 管理员修改密钥的权限位或过期时间, THE SYSTEM SHALL 使原密钥立即按新配置生效，不要求轮换密钥。（↔AC-21）
- **AC-09** — WHEN 管理员对某一主体执行批量撤销, THE SYSTEM SHALL 使该主体名下全部密钥在 5 秒内失效。（↔AC-22）
- **AC-10** — WHEN 密钥被成功用于一次调用, THE SYSTEM SHALL 更新其最后使用时间（允许 60 秒内的写合并）。
- **AC-11** — WHEN 密钥被撤销, THE SYSTEM SHALL 保留该密钥记录及其历史归属，供审计追溯；撤销不等于删除。

### 2.2 服务账号主体

- **AC-12** — THE SYSTEM SHALL 使服务账号无法通过任何登录入口获得会话（覆盖平台全部登录入口，含本地登录、SSO、网关登录同步、租户选择）。（↔AC-14）
- **AC-13** — THE SYSTEM SHALL 使服务账号出现在资源授权选人列表中，且不出现在用户管理、审批人选择、部门成员、创建租户选管理员等其余用户列表消费点中。（↔AC-15）
- **AC-14** — WHEN 租户对账任务执行, THE SYSTEM SHALL 保持服务账号的租户归属不被改写。（↔AC-16）
- **AC-15** — THE SYSTEM SHALL 不把服务账号计入租户用户数配额。（↔AC-17）
- **AC-16** — WHEN 管理员创建服务账号, THE SYSTEM SHALL 使其立即处于「可被授权」状态（可作为授权主体被授予资源权限）。
- **AC-17** — IF 对服务账号调用面向自然人的用户更新操作（如改密、启用登录）, THEN THE SYSTEM SHALL 拒绝。
- **AC-18** — WHEN 服务账号被禁用或删除, THE SYSTEM SHALL 使其名下全部密钥在 5 秒内失效。

### 2.3 端点接入与三条铁律

- **AC-19** — THE SYSTEM SHALL 使全部开放 API 端点（含两个 WebSocket 端点）经过同一条凭据校验路径；不存在绕过该路径的端点。
- **AC-20** — WHEN WebSocket 握手携带无效密钥, THE SYSTEM SHALL 拒绝握手并优雅关闭连接（不产生未捕获异常）。（↔AC-18）
- **AC-21** — WHEN 使用有效密钥且未传任何身份头, THE SYSTEM SHALL 以密钥主体身份执行，返回结果的可见范围等于该主体的权限边界。
- **AC-22** — IF 请求携带身份传递类请求头（代表平台用户 / 外部用户标识）, THEN THE SYSTEM SHALL 返回 403 并提示该能力尚未启用——不得静默忽略该头而按密钥主体身份继续执行。
- **AC-23** — IF 权限引擎不可用或权限评估失败, THEN THE SYSTEM SHALL 返回 5xx 且不返回任何业务结果；绝不返回未过滤或部分过滤的结果集。（↔AC-13、铁律 F3）
- **AC-24** — WHERE 某端点被配置为必须携带最终用户身份, WHEN 请求未携带身份头, THE SYSTEM SHALL 只返回对所有人公开的资源，不返回全量（对无「公开」概念的资源类型等价于返回空集）。（铁律 F2）
- **AC-25** — WHEN 调用未上线的工作流, THE SYSTEM SHALL 返回业务错误而非执行该工作流。（↔AC-19）
- **AC-26** — WHEN 请求停止一个不属于当前密钥主体的会话, THE SYSTEM SHALL 返回 403。（↔AC-20）
- **AC-27** — IF 代用户解析的目标账号已被禁用或不存在, THEN THE SYSTEM SHALL 拒绝该请求，不构造出可用身份。
- **AC-28** — WHEN 调用会话反馈类端点（生成标题、查历史、点赞、标记解决、评论）, THE SYSTEM SHALL 校验目标会话/消息属于当前密钥主体的可见范围，不属于则返回 403——当前这些端点无任何身份，任何调用方可改任意会话的数据。
- **AC-29** — WHEN 调用统计文件下载端点, THE SYSTEM SHALL 只返回当前密钥主体有权获取的统计数据；THE SYSTEM SHALL NOT 接受由调用方指定的服务器文件路径作为取数依据。

### 2.4 管理界面

- **AC-28** — WHEN 管理员进入密钥管理界面, THE SYSTEM SHALL 支持创建、列表、编辑（名称 / 权限位 / 过期时间）、撤销、按主体批量撤销；非管理员无该入口。
- **AC-29** — THE SYSTEM SHALL 在密钥列表中展示名称、掩码、所属主体、权限位、最后使用时间、过期时间与状态。
- **AC-30** — WHEN 管理员创建服务账号, THE SYSTEM SHALL 提供独立于自然人用户管理的入口，支持创建、列表、启停、删除与授权跳转。
- **AC-31** — WHEN 密钥创建成功, THE SYSTEM SHALL 在一次性展示界面同时提供复制操作与「关闭后不可再查看」的明确提示。

### 2.5 存量迁移

- **AC-32** — WHERE 鉴权开关关闭（兼容窗口内）, WHEN 存量调用方不带密钥调用, THE SYSTEM SHALL 正常执行并记录迁移告警日志。（↔AC-26）
- **AC-33** — WHEN 默认操作员完成向服务账号的转型, THE SYSTEM SHALL 保持其名下存量资源的归属与可见性不变。（↔AC-27）
- **AC-34** — IF 部署自检发现默认操作员具备超级管理员身份, THEN THE SYSTEM SHALL 产生显式告警。
- **AC-35** — THE SYSTEM SHALL 使对外接口文档中不再出现「由网络层负责访问控制」与「建议将默认操作员配置为超级管理员」这两处表述。

## 3. 边界情况

- **凭据校验发生在租户上下文建立之前**：校验查询必须能在无租户上下文时执行，且校验通过后立即建立租户上下文；此后所有业务查询按该租户过滤。跨租户的密钥与主体组合一律拒绝。
- **撤销与缓存的 5 秒窗口**：撤销后允许最多 5 秒的旧结果窗口；主动失效是常态路径，TTL 到期只是兜底。批量撤销与主体禁用同此上界。
- **兼容窗口下的双路径**：窗口内「带密钥」与「不带密钥」两条路径并存，二者的业务行为必须一致（除身份与审计归属外），不得因带密钥而出现能力缩水。
- **密钥有效性的单一判据**：有效 = 未撤销且未过期。不引入可独立漂移的状态枚举列（平台已有「枚举存在但无写入端点」的负资产先例）。
- **服务账号的租户归属是声明式写入**，不由部门树派生；任何以部门树为真相的对账任务都必须结构性跳过服务账号，而不是"恰好没扫到"。
- **WebSocket 与 HTTP 的凭据传递方式一致**（请求头），不使用查询参数——密钥会进入访问日志。浏览器直连场景不在本期范围。
- **服务账号出现在授权选人列表**是必需项：若不可见则无法对其授权，模式 S 的全部能力将失效；但它必须默认从其余用户列表消费点中排除，且排除的失败方向应是"看不到"而非"泄漏"。
- **并发与写放大**：最后使用时间的更新不得成为热路径上的每请求写；密钥表禁止批量更新 / 删除与原生 SQL 写入（多租户自动过滤只拦 SELECT）。
- **凭据校验取 fail-closed，与平台既有会话校验的取向相反**：现有 HTTP 中间件的 token_version 校验在缓存/DB 抖动时刻意 fail-open（"不因缓存抖动把用户锁在门外"）。凭据校验属于鉴权而非会话续期，缓存或存储不可用时**必须拒绝**。这一差异是刻意的，不是不一致。

## 4. 待澄清（★ 需产品确认后方可进入 design）

以下三项在伴生 PRD 中没有覆盖，但都直接改变本 Feature 的交付内容，均为基线代码核实所得：

- **[待澄清-1] 两个 WebSocket 端点同时是平台自身「免登录分享页」的通道。**
  核实：平台前端的分享页（工作流分享、助手分享两个路由）直接连这两个开放 API 的 WebSocket 端点，其登录校验当初就是为此被注释掉的（代码注释写着"免登录链接"）。若按 PRD 对它们强制密钥鉴权，**已发布的分享链接会全部失效**——且浏览器原生 WebSocket 无法设置请求头，分享页无法改为携带密钥。
  三个方向：① 分享页改走平台已有的分享链接凭据（share link）通道，开放 API 的 WS 只服务服务端集成（推荐，但需确认分享链接凭据自身的有效期与撤销现状）；② 为浏览器场景提供短票据换取机制（本期范围膨胀）；③ 本期暂不对这两个端点强制鉴权（与 AC-19「无死角」冲突，需显式豁免登记）。
  **未定前，AC-19 / AC-20 对这两个端点的适用性悬置。**

- **[待澄清-2] 统一身份构造会放宽部分端点的现有权限。**
  核实：平台有同步与异步两个身份构造入口，同步入口**不计算「是否全局超管」标记**，而权限引擎正是从该标记判定超管短路。后果是同一个默认操作员账号，经同步入口构造时在权限引擎眼里永远不是超管，经异步入口构造时是。当前多数开放 API 端点走同步入口。
  凭据鉴权统一到异步构造后，这些端点的实际权限**会变宽**（若默认操作员恰是超管——而 PRD §2.2 记载现有文档正是这样建议客户配置的）。需要确认：本期是否同时把默认操作员强制降权作为**前置条件**（PRD §4.9 已要求降权，此处只是把它从"迁移动作"提升为"上线闸口"）。

- **[待澄清-3] 6 个无身份端点的归属校验基准。**
  核实：5 个会话反馈类端点与 1 个统计下载端点当前完全没有身份，函数体内没有可用的调用者信息。补校验时的基准有两种取法：以密钥主体的可见范围为准（本 spec AC-28 的写法），或以会话创建者为准。前者与模式 S 一致但会让存量集成"改了会话就报错"，后者更宽松。选择影响存量调用方的兼容性。

- **[待澄清-4] 两册对「绑定自然人的密钥」给出了相反口径，需要统一措辞。**
  伴生 PRD 终版（`9bb8e89cc` 修订）：❌ 不实现个人访问令牌，**密钥只签发给服务账号**，「本模块无面向普通用户的自助入口」；理由是三类场景全为系统对系统集成、引入第二类主体会带来第二套权限来源与生命周期联动。
  《PRD-1》DEV-01 同时规定：租户管理员为**开发者本人**签发个人 API key（前缀 `bs-pat-`、个人主体轨、权限 = **动态继承持有人当前权限** ∩ scope、账号禁用即失效），并在工作台账户菜单提供「我的 API key」**自助吊销**入口。
  我的判断是**二者其实不矛盾、但措辞会打架**：开放 API（`/api/v2`）面向系统集成，那里确实不该有自然人密钥；而 DEV-01 面向开发者本地接入 MCP / 模型 / CLI，其权限**必须**继承开发者本人，否则 NFR-1「检索范围 ⊆ 该开发者自身权限」无从实现——换成服务账号反而制造越权面。需要产品确认三点：① DEV-01 个人 key 保留（我判断必须保留）；② 它与本 Feature 的凭据底座是「同底座、不同主体轨」还是各自独立；③ PRD-1 §6 开放问题 3「个人 key 与开放 API 个人访问令牌是否合并为同一凭据实例」——既然开放 API 侧已不签发个人凭据，该问题应改判为**不合并**，建议直接在 PRD-1 收口。
