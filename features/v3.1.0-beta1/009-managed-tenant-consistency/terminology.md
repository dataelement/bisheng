# 租户修复文档术语与缩写说明

面向业务和测试的说明优先使用中文全称。技术设计中的公式、代码字段、状态值和接口名称可以保留，但应按本表理解；这些符号不表示系统存在多套可自由切换的用户身份。

## 租户与人员符号

| 符号 | 中文含义 | 在本次修复中的准确用法 |
| --- | --- | --- |
| H（Home Tenant） | 用户当前主属租户 | 普通角色绑定、菜单和个人配额按此租户生效；跨租户兼属不会改变它 |
| M（Management Tenant） | 当前管理目标租户 | 管理员已获授权、当前选中管理的租户；切换管理目标不改变本人的主属租户 |
| B | 部门业务归属租户 | 按部门挂载关系确定的实际业务归属，用于部门角色候选及成员政策判断 |
| S（Storage Tenant） | 部门记录存储租户 | 数据库部门行的tenant_id；挂载场景可能存于Root，但业务归属是子租户，不能将二者混同 |
| T | 本次操作的资源目标租户 | 经服务端核实后固定的创建、写入或执行范围；子对象、后台任务及资源计量使用该范围，不直接相信客户端参数 |
| O（Owner Tenant） | 资源或角色定义所属租户 | 例如全局角色定义及其菜单关联属于Root；共享定义不等于在各租户自动授予角色 |
| E（Effective Roles） | 当前有效普通角色集合 | 按人员主属、绑定和部门作用域计算的结果；平台、租户、部门管理员身份独立判断 |
| q | 配额责任人 | 计量所依据的人员，频道场景仍是原创建者；当前编辑者或权限系统中的owner不自动替代该责任人 |
| A、B（租户A、租户B） | 示例中的两个不同租户 | 这是示例名称；“租户B”不要与公式中表示部门业务归属的单独符号B混淆 |
| U | 示例中的普通用户 | 不是某一种管理身份 |
| Root | 系统根租户 | 子租户部门记录可能仍存于根租户；这不代表其业务、角色和预算也归根租户 |

示例：管理员主属租户A，切换管理目标为租户B，则H=A、M=B。在租户B新建资源时，资源目标租户为B；管理员本人的主属、菜单和个人配额仍按租户A判断。

## 常见技术缩写和编号

| 写法 | 含义及阅读方式 |
| --- | --- |
| SSO（Single Sign-On） | 单点登录；本项目也涉及其用户、部门和成员同步 |
| DSH | 本项目桌面端接入、设备会话和模型调用策略/额度相关模块的代码名称；本文保留模块名，不另行猜测英文展开 |
| FGA / OpenFGA | 细粒度授权及本项目使用的资源权限系统；角色菜单不能代替其资源动作授权 |
| PDP（Policy Decision Point） | 权限决策入口 |
| API（Application Programming Interface） | 服务接口；API工具指通过服务接口接入的工具 |
| MCP（Model Context Protocol） | 模型上下文协议，用于工具接入 |
| SQL（Structured Query Language） | 数据库查询语言；“同SQL事务”指相关数据库变更一起提交或回滚 |
| ORM（Object-Relational Mapping） | 对象关系映射，即通过模型操作数据库的机制 |
| DDL（Data Definition Language） | 数据库结构变更，例如新增列；不等于业务数据修复 |
| CAS（Compare-And-Swap） | 比较并更新：仅当记录仍处于预期旧状态时才更新，用于复制任务唯一领取等并发控制 |
| UoW（Unit of Work） | 同一工作单元；此处通常指由同一数据库事务统一提交的一组变更 |
| UUID（Universally Unique Identifier） | 通用唯一标识；本批没有要求复制接口新增必填UUID |
| DTO（Data Transfer Object） | 数据传输对象，例如接口请求或响应结构 |
| HTTP | 服务接口采用的通信协议 |
| E2E（End-to-End） | 端到端测试；局部替身或SQLite回归不代表真实系统端到端验收 |
| TSC | TypeScript类型检查器；语法转换通过不代表完整类型检查或构建通过 |
| i18n | 国际化，即多语言文案及其一致性检查 |
| QA | “QA知识库”指问答（Question and Answer）知识库；“QA用例/验收”指质量保证与测试（Quality Assurance），二者按上下文区分 |
| P0 / P1 | 测试优先级：本文P0为发布前必须覆盖的关键场景，P1为后续重要回归 |
| AC-NN（Acceptance Criteria） | 验收标准编号，例如AC-33；不是已通过测试的标记 |
| F009 / F048 / F118 | 特性编号，分别指本次租户修复、既有资源权限能力、知识库与知识空间统一；不是运行状态 |
| MAX / MIN / OR | 分别为取最大值、取最小值、逻辑或；具体配额中的0、-1等边界仍按设计规则解释 |

## 状态值与其他英文表达

- `PENDING`：创建尚未完成，不能按正常可用资源使用；`READY`：创建已就绪。
- `UNPUBLISHED`、`COPYING`、`PUBLISHED`、`FAILED`：分别为未发布、复制中、已发布、失败；是知识资源原有状态值。
- `CURRENT`：权限投影已处于当前确认状态；它本身不证明复制内容已经完成。`FAILED_CLOSED`：权限流程已封闭失败，不能盲目重放。
- `UNKNOWN` / `NOT_RUN` / `skipped`：分别为事实未知、未执行、测试跳过，均不等于验收通过。
- `scope`：角色或管理权限的作用范围；`actor` / `subject`：分别为操作者、被操作人员或授权主体。
- `creator` / `owner`：分别为原创建者、资源权限所有者；两者可能不同，权限所有权变更不自动改变配额责任。
- `worker` / `Broker`：分别为后台任务执行进程、消息队列服务；`v0`为工作流初始版本。
- `head` / `revision`：分别为数据库迁移图的末端版本、某个迁移版本；“单head”表示升级入口没有分叉。
