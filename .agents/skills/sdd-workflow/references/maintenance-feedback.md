# 按真实使用改进技能与环境

用户要求复盘，或反复／高代价失败需要修正方法时使用。完成常规任务不会自动启动额外治理流程。

先读取相关会话、需求、实际改动与执行证据，记录预期、实际、规则版本和影响。区分事实不足、规则表达、资料难找、工具未接通、项目约束或执行偏差；既有检查存在但未运行时，先修接入，避免再造同一检查器。
机械错误优先复用 lint、类型、构建、hook 或 CI；需要语义判断的部分才补专业审核标准。新增守卫在隔离样例中观察通过 → 故意违规失败 → 恢复通过，防止规则只写在纸上。配置变更遵守项目范围和测试阶段，不加入研发期 UI／真实 E2E。
资料读取按当前分支披露，共用规则一处维护，指针说明何时读取。移除重复或疑似无效提示前核对其使用方及保护目的；“模型应该默认懂”不是删除关键约束的唯一依据，必要时用实际场景比较。
建议按实际影响排序，写清最小改动、成本和如何观察收益；不从单个偶然失败扩张为每次必需步骤，也不擅自扩大当前任务。记录宿主可取得的实际 token、耗时、确认和返工；无法取得则记未知，不以一轮结果宣称普遍提升比例。
