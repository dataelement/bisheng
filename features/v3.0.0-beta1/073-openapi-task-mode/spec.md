# Feature: 任务模式开放 API

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
> spec 只回答 **做什么 / 验收标准 / 不做什么**；所有 How 在 [design.md](./design.md)。
>
> **前置步骤**：Spec Discovery 已完成（2026-09-30）。用户确认：需求口径以 PRD v1.4 为准；执行身份在任务执行期间失效时，已受理任务继续执行至终态；PRD 未写明的两处按现有能力取默认——代表他人时可选被代表用户的个人知识库、自身身份下选个人知识库即拒绝；使用统计沿用埋点的 `source` 字段区分来源，不新增统计界面。

**关联 PRD**: [`docs/PRD/3.0-beta2/3.0 任务模式开放 API PRD.md`](../../../docs/PRD/3.0-beta2/3.0%20任务模式开放%20API%20PRD.md) v1.4（下称「PRD」）；父文档《3.0 开放 API 鉴权与身份传递 PRD》v2.11
**优先级**: P0
**所属版本**: v3.0.0-beta1（发版线 `feat/3.0.0-beta2`）
**依赖**: F053（开放 API 密钥、身份模式、会话主体标记、会话附件上传、`/api/v2/workstation/config`）· F063（任务模式输入内容安全审查）· 灵思任务模式既有执行内核（worker、队列、产物、失败分类）

> **范围边界**
> - **本次纳入**：
>   - 在开放 API 已有的会话能力上点亮「任务 × 异步」：提交任务、查询状态、取回结果、下载产物、终止任务。
>   - 扩展已有的可用配置查询：按运行模式返回任务模式可用的模型、技能、平台工具、知识库与知识空间。
>   - 附件沿用开放 API 会话附件上传。
>   - 对外文档新增「任务模式」章节与升级说明。
> - **修订的既有契约**：
>   - **`26017`** 含义由「任务模式未开放」收窄为「指定了枚举外的运行模式」（父 PRD 附录 C、AC-50 已改）。
>   - **F053 §1 范围裁定**「不开放任务模式」不再成立（已改）；日常模式异步执行仍不开放，继续返回 `26015`。
>   - **开放 API 可用配置查询**新增任务模式分支；日常模式或未指定运行模式时返回内容不变。
> - **本次明确排除**（原因见 PRD §三）：
>   - 实时事件流、执行步骤明细；中途提问（等待人工输入）；在已有会话上续接或追问。
>   - 任务模式同步（流式）执行；日常模式异步执行。
>   - 托管应用经能力总线接入。
>   - 在途任务数上限、限流、配额；幂等键、Webhook 回调。
>   - 引用溯源对外开放；个人访问令牌调用；任务总时长上限；平台侧任务模板；附件目录层级。
>   - 资源归属人凭会话标识直接读取服务账号会话消息（日常模式既有问题，另行处理）。
>   - workflow 代码节点执行环境的配置调整（网络连通、执行时长），由交付按部署调整。
>   - 新增统计界面。

## 1. 用户故事

作为 **客户应用的开发者**，
我希望 **用一把服务账号密钥，把内置的任务描述、附件、技能和模型一次提交给平台，之后凭任务标识查状态、取结果、下载产物**，
以便 **员工只需上传文件、点一次确认，就能用上任务模式，不必自己写长提示词、选技能**。

作为 **客户应用的开发者**，
我希望 **在提交前查到当前执行身份能用哪些模型、技能、工具和知识**，
以便 **写进应用的配置不会因名字抄错或权限不足而在提交时被拒**。

作为 **被代表的员工**，
我希望 **应用替我发起的任务出现在我的工作台里**，
以便 **回到平台查看执行过程和产物**。

作为 **租户管理员**，
我希望 **API 发起的任务在审计里能同时看到调用密钥与执行身份，在统计里能与工作台发起的任务区分开**，
以便 **追溯调用来源、评估集成对任务队列的占用**。

## 2. 验收标准

> P0、跨模块，采用 EARS 句型。AC-ID 在本特性内唯一；括号内为对应的 PRD 验收条目，便于双向追溯。
> **执行身份**：自身身份下为服务账号，代表他人时为被代表用户。下文权限判定均以执行身份为准。

### 2.1 开通与权限

- **AC-01** — WHEN 持 `chat:invoke` 的服务账号密钥以任务模式提交, THE SYSTEM SHALL 受理该任务；IF 密钥缺少 `chat:invoke`, THEN THE SYSTEM SHALL 返回 403（`26003`）且不创建任务。（PRD AC-T1）
- **AC-02** — WHEN 以代表他人模式提交, THE SYSTEM SHALL 沿用父 PRD 的五道准入；IF 被代表用户不具备任务模式使用权限, THEN THE SYSTEM SHALL 返回 403 与新增错误码，且不创建任务。WHILE 以自身身份提交, THE SYSTEM SHALL 不判定任务模式使用权限。（PRD AC-T2）
- **AC-03** — IF 以个人访问令牌调用任务模式的任一能力, THEN THE SYSTEM SHALL 拒绝且不创建任务。（PRD AC-T3）

### 2.2 可用配置查询

- **AC-04** — WHEN 以「任务」运行模式查询可用配置, THE SYSTEM SHALL 返回可用模型（标出任务模式默认模型）、平台工具、已启用技能（含技能名、显示名称、说明）、执行身份可读的知识库与知识空间；每项含提交时使用的标识与显示名称。WHEN 以日常模式或不指定运行模式查询, THE SYSTEM SHALL 返回与现有契约一致的内容。（PRD AC-T29）
- **AC-05** — THE SYSTEM SHALL 使查询结果与提交校验同一口径：用查询结果中任意一组模型、技能、工具、知识库、知识空间提交，不因「不存在」或「无权限」被拒；代表不同员工、自身身份分别查询，结果各按执行身份过滤。IF 权限评估不可用或失败, THEN THE SYSTEM SHALL 返回错误，不返回未过滤或部分过滤的列表（INV-32）。（PRD AC-T30）
- **AC-06** — THE SYSTEM SHALL 不在查询结果中列出已停用的技能、未上线的模型、执行身份无权限的工具与知识；IF 查询后某技能被停用再提交, THEN THE SYSTEM SHALL 按 AC-12 拒绝。（PRD AC-T31）
- **AC-07** — THE SYSTEM SHALL 支持知识库、知识空间按名称搜索与分页；IF 代表他人且被代表用户不具备任务模式使用权限, THEN THE SYSTEM SHALL 对查询返回与 AC-02 相同的 403。（PRD AC-T32）

### 2.3 提交

- **AC-08** — WHEN 以任务模式 + 异步提交且入参全部合法, THE SYSTEM SHALL 返回任务标识，状态为「排队中」；调用方此后不再发送任何请求，任务仍执行至终态。（PRD AC-T4）
- **AC-09** — IF 任务模式要求同步执行, THEN THE SYSTEM SHALL 返回 400 与新增错误码；日常模式要求异步执行仍返回 `26015`；指定枚举外的运行模式仍返回 `26017`；三者响应可区分。WHEN 未指定运行模式, THE SYSTEM SHALL 按日常模式执行。（PRD AC-T5）
- **AC-10** — THE SYSTEM SHALL 要求任务描述非空且不超过长度上限；业务上下文指令只叠加在平台提示词之上，不替换、不关闭平台提示词。
- **AC-11** — IF 请求中任一入参不合法, THEN THE SYSTEM SHALL 拒绝整次提交且不创建任务，不得丢弃不合法项后继续执行。
- **AC-12** — IF 所选技能中任一项不存在或未在本租户启用, THEN THE SYSTEM SHALL 拒绝提交，响应列出全部不可用的技能名；不传技能时不加载任何技能。（PRD AC-T6）
- **AC-13** — IF 所选模型不在执行身份的工作台可用列表中或未上线, THEN THE SYSTEM SHALL 拒绝提交并返回平台错误码；日常模式同一场景一并返回该错误码。（PRD AC-T7）
- **AC-14** — IF 所选知识库、知识空间、平台工具中任一项执行身份无权限或不存在, THEN THE SYSTEM SHALL 拒绝提交并指明出错项；WHILE 以自身身份提交, THE SYSTEM SHALL 只允许使用授权给该服务账号的资源。（PRD AC-T8）
- **AC-15** — WHEN 以代表他人模式提交并选择个人知识库, THE SYSTEM SHALL 使用被代表用户的个人知识库；IF 以自身身份提交并选择个人知识库, THEN THE SYSTEM SHALL 拒绝提交。
- **AC-16** — IF 附件引用属于其他调用主体、为内联文件数据或外链地址, THEN THE SYSTEM SHALL 拒绝提交。（PRD AC-T9）
- **AC-17** — IF 请求传入会话标识, THEN THE SYSTEM SHALL 返回 400 与新增错误码，不创建任务、不续接任何会话。（PRD AC-T10）
- **AC-18** — WHERE 部署启用了内容安全策略, IF 任务描述或业务上下文指令命中, THEN THE SYSTEM SHALL 拒绝提交并返回处置文案，不创建任务。（PRD AC-T11）
- **AC-19** — IF 提交后、执行前所选技能被停用或所选模型下线, THEN THE SYSTEM SHALL 以「失败」结束该任务，失败说明指明该技能或模型；不得以缺少该项的方式继续执行。（PRD AC-T12）

### 2.4 附件

- **AC-20** — THE SYSTEM SHALL 对附件采用与工作台一致的类型与单文件大小上限；WHEN 同时提交一个类型不支持的附件和一个正常附件, THE SYSTEM SHALL 正常执行至终态，并在结果中逐个列出不可用附件及原因（类型不支持 / 解析失败 / 已过期）。（PRD AC-T13）

### 2.5 执行与状态

- **AC-21** — THE SYSTEM SHALL 使 API 发起的任务全程不出现「等待输入」状态；WHEN 任务描述信息不足, THE SYSTEM SHALL 按合理的默认假设产出结果，并在答复中写明所做假设。（PRD AC-T14）
- **AC-22** — THE SYSTEM SHALL 使 API 与工作台发起的任务共用一个队列、先到先执行，不设在途任务数上限；沿用任务模式的执行轮次上限，超限时能整理出结果的记为「部分完成」，否则记为「失败」。
- **AC-23** — WHEN 终止排队中或执行中的任务, THE SYSTEM SHALL 将状态置为「已终止」且不产出结果，终止后不可恢复；IF 终止已结束的任务, THEN THE SYSTEM SHALL 返回 409 与新增错误码。（PRD AC-T15）
- **AC-24** — WHILE 任务执行中, THE SYSTEM SHALL 使连续多次查询的进度只增不丢；WHEN 任务已到终态, THE SYSTEM SHALL 使连续多次查询的结果完全一致；查询不影响被代表用户在工作台对同一任务的实时展示。（PRD AC-T16）
- **AC-25** — WHILE 任务排队中, THE SYSTEM SHALL 返回排队位置；WHILE 任务执行中, THE SYSTEM SHALL 返回待办进度（已完成数 / 总数），尚未生成待办时为空。（PRD AC-T17）
- **AC-26** — WHEN 任务失败, THE SYSTEM SHALL 返回失败类别与说明，类别沿用平台现有分类；WHEN 任务部分完成, THE SYSTEM SHALL 带「部分完成」标记。（PRD AC-T18）
- **AC-27** — THE SYSTEM SHALL 使状态枚举能在日后加入「等待输入」而不需要调用方改已有代码。
- **AC-28** — IF 换一个调用主体（另一服务账号、另一被代表用户，或自身身份下另一 `X-End-User`）查询、取回结果、下载或终止同一任务, THEN THE SYSTEM SHALL 一律返回 404。（PRD AC-T19）

### 2.6 结果与产物

- **AC-29** — THE SYSTEM SHALL 使答复正文不含内部引用标记，产物清单每项含文件名、类型、大小、是否主交付物，且不含任何存储路径或服务器本地路径。（PRD AC-T20）
- **AC-30** — IF 模型声称生成的交付物实际不存在, THEN THE SYSTEM SHALL 在结果中单独列出，不混入产物清单。（PRD AC-T21）
- **AC-31** — THE SYSTEM SHALL 要求产物凭密钥按「任务 + 文件」下载并通过归属校验，下载内容与工作台下载的文件一致；结果中不返回长期有效的直链。产物保留期与工作台任务一致。（PRD AC-T22）

### 2.7 归属、可见性与审计

- **AC-32** — WHEN 以代表他人模式发起任务, THE SYSTEM SHALL 使任务出现在被代表用户的工作台会话记录中，可查看执行过程与产物。（PRD AC-T23）
- **AC-33** — WHEN 以自身身份发起任务, THE SYSTEM SHALL 使任务不出现在任何自然人的工作台会话记录中，包括该服务账号的资源归属人；处理方式与开放 API 日常模式会话一致。（PRD AC-T24）
- **AC-34** — THE SYSTEM SHALL 使审计记录可同时查到调用密钥与执行身份，模型用量计入执行身份；API 发起的任务在使用统计埋点中来源记为开放 API，与工作台发起的任务可区分。（PRD AC-T25）

### 2.8 交付

- **AC-35** — WHEN 按最小表单流程（查询可用配置 → 上传 2 个附件 → 以预置任务描述和 1 个技能提交 → 轮询至完成 → 下载主交付物）执行, THE SYSTEM SHALL 在代表他人、自身身份两种模式下各走通一遍。（PRD AC-T26）
- **AC-36** — THE SYSTEM SHALL 在对外文档中新增「任务模式」章节，逐项列出可用配置查询、入参、状态、结果内容、错误码及处置、失败类别及处置建议、附件引用的有效期、执行身份在任务执行期间失效时的行为、完整调用示例，以及本期不支持的能力和对应报错。（PRD AC-T27）
- **AC-37** — THE SYSTEM SHALL 在对外文档的升级说明中写明：持 `chat:invoke` 的存量密钥升级后即可发起任务模式，管理员应复核持有该权限位的密钥。（PRD AC-T28）
- **AC-38** — WHEN workflow 代码节点持服务账号密钥调用本 API, THE SYSTEM SHALL 按与外部应用相同的规则处理，两种执行身份均可用。

## 3. 边界情况

- 当附件引用在提交时已过有效期，系统应拒绝提交；当附件在排队期间过期，系统应在结果中把该附件列为「已过期」，任务不因此失败。
- 当同一调用方在极短时间内重复提交相同内容，系统应视为两个独立任务各自执行（本期不做幂等）。
- 当执行身份在任务排队或执行期间被停用、委托被撤销，已受理的任务继续执行至终态（准入在提交时判定，与 INV-33「判定在调用期」一致）；此后的查询、取回、下载、终止仍按每次调用时的准入判定，因此密钥被吊销或委托被撤销后调用方取不到结果。该行为写入对外文档（2026-09-30 用户确认）。
- 当任务在执行中因 worker 重启中断，系统应以「失败」或平台现有的中断处理结束该任务，状态查询不得长期停在「执行中」。
- 当自身身份下未传 `X-End-User`，系统应沿用父 PRD §4.3.4：记录告警、不阻断，任务按服务账号粒度分区。
- 当查询到的配置在提交前发生变化（技能停用、模型下线、权限撤销），系统应以提交时的校验为准，按对应 AC 拒绝，不得按查询时的结果放行。
