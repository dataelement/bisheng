# Design: 全问答入口统一溯源角标（F054）

> **本文档定位 — 现状快照（Why this How）**。spec 回答做什么；本文回答为什么这么实现 + 反直觉事实 + 对外契约。
> **关联**: [spec.md](./spec.md) · [discovery.md](./discovery.md)（现状基线与三个已裁定口径）
> **版本**: v3.0.0-beta1
> **最后更新**: 2026-09-07（实现前初版）

---

## 1. 目标与非目标

- **目标**：把**频道文章 AI 问答**接进既有 citation 溯源子系统；把「来源已失效」从「暂无权限」里拆出来；按 discovery §4.1 收紧匿名解析；按 discovery §4.4 关掉工作流临时文件的角标。**最大化复用既有链路，不新建第二套溯源机制。**
- **非目标**：
  - 不改灵思任务模式（归 **F047**）。
  - **不做导出件烘焙**——用户裁定会话导出维持现状（继续剥离角标）；烘焙能力整体归 F047 Phase 2。
  - 不做临时来源的溯源能力（下一版）。
  - 不改已上线四个入口（工作流 / 日常模式 / 助手 / 知识空间）的溯源行为。
  - 不动 platform 前端；不做两端角标组件合并。
  - 不给「提示词被改写」加兜底（discovery §4.2）。
  - 不新增表、不加 Alembic 迁移、不新增对外错误码段。

---

## 2. 关键约束

全局铁律遵循 `docs/constitution.md` C1–C7，本节只列本功能特有：

- **INV-7 及其 F041 例外不得改动**（release-contract v2.6.0 表 2）。本 Feature 的「收紧」**只作用于「无已登录用户」的调用分支**；已登录用户的 `per_user` / `shared` 两档语义原样保留。这是评审对齐结论，也是本设计的硬边界。
- **`citation_type` 是既有 `varchar(32)` 列**，新增来源类型只是该列的新取值 + `source_payload` 这个 schema-less JSON 的新形状 → **无 DDL、无 Alembic**。
- **组件视觉归设计师所有**（根 AGENTS.md）。共享徽标组件的溯源角标目前只有两种来源色（`document` / `web`），**本期不新增第三种颜色**——文章角标复用 `document` 形态，新增来源色须设计师签字。
- **不得新增对外 API**：文章溯源复用既有 `/api/v1/citations/resolve` 与单条详情端点；批量解析响应只做**向后兼容的字段追加**。
- **频道文章问答有敏感内容准入校验**（`ensure_article_sensitive_view_allowed`），溯源登记必须发生在该校验之后，不得绕过。
- **i18n**：新增用户可见文案（「来源已失效」等）三语齐发，不得硬编码中文；顺带把现存硬编码的「暂无权限」一并抽出。

## 3. 方案对比与选定

### 决策 1：文章来源的粒度 = 整篇文章一条来源，不做切片检索

- **备选**：
  - A. **整篇文章登记为一条来源**（来源内条目固定一条），来源标识 = 文章文档标识。
  - B. 把文章切片入库，改成检索式问答，按片段发号（对齐知识库来源的粒度）。
- **选定**：A。
- **原因**：频道文章问答**根本不检索**——服务端取到整篇文章后，把全文截断到配置上限，直接拼进用户提示词的「参考资料」块（`channel_chat.py` 的 `chat_completions`）。B 等于把这个入口重做成一条 RAG 链路，改动面和风险远超溯源本身；而文章问答的产品语义就是「就这一篇」，片段级溯源的边际价值很低。需求原文也明确写「频道文章使用文章文档 ID 或原文链接」= **文档级**。
- **何时该重新考虑**：若频道问答改为跨文章检索（多篇候选），那时片段级溯源才有意义。

### 决策 2：新增第三种来源类型，而不是把文章当网页复用

- **备选**：
  - A. 新增来源类型 `article` + 专属来源载荷（携带文章文档标识、标题、摘录、原文链接、来源站点类型）。
  - B. 复用 `web` 类型，把原文链接当作网页 URL 塞进去。
- **选定**：A。
- **原因**：B 会让「频道文章」和「联网搜索结果」在角标图标、来源归组、以及**未来的可见性判定**（文章有独立的敏感内容准入，网页没有）上彻底不可区分；需求把「来源类型」列为必须展示的字段之一，B 直接抹掉它。更关键的是 B 会丢掉文章文档标识 → 无法做应用内跳转、无法与频道侧的文章权限对齐。
- **代价**（必须一并解决，否则功能是坏的）：前端判定来源类型的函数当前是「是 web 就 web，**其余一律当知识库来源**」，新前缀不扩展就会被当成知识库来源走文件预览抽屉 → 点开一片空白。见 §5 坑 2。
- **何时该重新考虑**：若未来来源类型继续膨胀（第四、第五种），应把「类型 → 载荷 → 图标 → 点击行为」抽成注册表式的扩展点，而不是继续加分支。

### 决策 3：引用规则追加到频道问答的系统提示词尾部

- **选定**：无论管理员是否配置了自定义系统提示词，都在其尾部追加引用规则；用既有的 `prompt_has_citation_rules()` 做幂等判断（这是该函数**第一次被真正调用**，见 §5 坑 1）。
- **原因**：频道问答的默认系统提示词是一句英文通用语，**完全不含引用规则**；不注入则模型永远不会发标记，功能等于没做。这与 discovery §4.2「提示词被改写不做兜底」不冲突——§4.2 说的是**不改已上线入口的既有行为**；频道问答是新接入的入口，没有存量行为要保。
- **何时该重新考虑**：若产品要求「频道问答也允许管理员关掉溯源」，则改为按配置开关注入。

### 决策 4：文章来源的持久化用严格过滤，不用「无标记则全存」的兜底

- **备选**：
  - A. 严格：只持久化答案里**实际出现**的来源标识。
  - B. 沿用日常链路的 `select_registry_items_for_persistence`——它在「答案里一个标记都没有」时**回退保存全部**。
- **选定**：A。
- **原因**：B 的兜底对知识库检索是合理的（检索命中了就大概率被用了，宁可多存）；但文章问答**每一轮必然登记一条**文章来源，用 B 会导致「模型没引用也照存一条」，而前端此时无标记可渲染 → 库里有来源、页面上没角标，与 AC-06「仅持久化实际引用到的」直接冲突，且污染统计。
- **何时该重新考虑**：若产品希望「问了这篇文章就记一条来源」作为阅读行为记录——那是另一个需求，不该借溯源表实现。

### 决策 5：「已失效」与「无权限」在服务端判定，批量解析响应追加未解析原因

- **备选**：
  - A. 批量解析响应在既有 `items` 之外**追加**一个「未解析清单」，每条给出标识 + 原因（无权限 / 已失效）。
  - B. 维持现状，前端凭「请求了但没返回」自行推断——今天就是这样，因此**无法区分**两种情形。
  - C. 用错误码区分：单条详情端点对两种情形返不同码。
- **选定**：A（C 作为单条端点的配套）。
- **原因**：B 做不到需求要求的区分。A 是纯追加字段，老前端忽略新字段即可，向后兼容；且判定逻辑留在服务端，避免前端二次猜测导致两端漂移。
- **判定顺序（安全序，满足 AC-10「无权限优先」）**：
  1. **无已登录用户** → 一律「无权限」。不泄漏任何存在性。
  2. **来源记录在缓存和库里都查不到** → 「已失效」。此时连这条来源是什么都无从得知，不构成泄漏。
  3. **记录存在但被 `view_file` 过滤掉** → 「无权限」。
  4. **记录存在、权限通过，但底层文件 / 文章已被删除** → 「已失效」。已经过了权限闸门，安全。
- **何时该重新考虑**：若将来要区分「文件被删」与「知识库被删」等更细的失效原因。

### 决策 6：临时文件停发角标 = 在工具包装处显式跳过 + 注册表侧防御性护栏

- **备选**：
  - A. 在**创建临时文件检索工具**时打标，工作流 Agent 节点包装工具时跳过打标记的工具。
  - B. 在来源登记环节判断「文档标识不是整数就跳过」。
- **选定**：**A 为主 + B 为护栏**。
- **原因**：A 在「这是临时文件」这个事实最清楚的地方一刀切断，意图明确、不误伤真实知识库来源。B 单独用则是隐式嗅探，但作为护栏有价值——今天这个缺陷正是因为**没有任何一层拦住非整数标识的来源**才漏出去的（见 §5 坑 5），补上它能防住后续别的路径重蹈覆辙。
- **何时该重新考虑**：若下一版真要做临时文件溯源，A 的标记位就是天然的开关点，B 的护栏需要同步放开。

## 4. 系统现状（接手必读）

### 4.1 数据流（本 Feature 新增部分）

```
[频道文章问答]
  chat_completions
    → 取文章（ArticleEsService）→ 敏感内容准入校验
    → 【新】登记一条 article 来源（标识 / 标题 / 摘录 / 原文链接）→ 写运行时缓存
    → 【新】系统提示词尾部追加引用规则（幂等判断）
    → 【新】「参考资料」块内携带该来源标识，模型据此内联发标记
    → 流式作答 → 答案落库前：严格过滤（只留答案里出现的）+ 清除未注册标记
    → 【新】save_message_citations(message_id = 答案消息 id)

[解析 / resolve]
  POST /api/v1/citations/resolve
    → 缓存优先、库兜底取来源
    → 【改】无已登录用户：知识库与文章来源一律不返回（含 shared 档，见 §5 坑 4）
    → 已登录：INV-7 两档语义不变（per_user 整条剔除 / shared 留元数据不给完整文件入口）
    → 【新】响应追加「未解析清单」：{标识, 原因: 无权限 | 已失效}
    → 文章来源的补全：校验文章是否仍存在 → 不存在则记为已失效

[工作流临时文件]
  Agent 节点包装工具时
    → 【改】临时文件检索工具不再包装打标 → 不登记来源 → 答案里不出现其角标
    → 【护栏】来源登记环节跳过「文档标识非整数」的文档
```

### 4.2 关键数据结构（新增 / 变更）

| 结构 | 变更 | 形状 / 取值 | 谁消费 |
|---|---|---|---|
| `CitationType` | 新增 `ARTICLE = "article"` | 既有 `rag` / `web` 不变 | 注册、解析、前端类型分派 |
| 来源标识前缀 | 新增 `articlesearch_` + 8 位随机 | 对齐既有 `knowledgesearch_` / `websearch_` | 前端按**第一个下划线前**的片段判类型（§5 坑 2） |
| `ArticleCitationPayloadSchema` | **新增** | `{articleDocId: str, title: str \| None, snippet: str \| None, sourceUrl: str \| None, sourceType: int \| None, items: [{itemId: str, snippet: str \| None, title: str \| None}]}` | 前端角标悬浮卡 + 点击跳转 |
| `ResolveCitationResponse` | **追加** `unresolved` | `{items: [...], unresolved: [{citationId: str, reason: "forbidden" \| "expired"}]}`；`items` 语义与顺序不变，老客户端忽略新字段即可 | client 区分「暂无权限」/「来源已失效」 |
| 单条详情端点 | 语义细化 | 无权限与已失效均返 404（不泄漏存在性），但响应体携带同一个 `reason` 字段供前端呈现 | client 单条兜底路径 |
| `message_citation` 表 | **无 schema 变更** | `citation_type` 多一个取值（列已是 `varchar(32)`）、`source_payload` 多一种 JSON 形状 | — |

**匿名分支的类型口径**（对齐 spec AC-14）：无已登录用户时 —— **知识库来源与文章来源一律不返回**（含 `shared` 档）；**网页来源仍放行**。理由：网页来源是公开 URL、不含租户数据，收紧它只会让分享页的网页角标一并失效，与本次「防知识库文件经分享链接外泄」的意图无关；文章则受频道可见性与敏感内容准入约束，属内部内容，必须拒。

### 4.3 关键模块职责（改动点）

| 模块 | 本 Feature 的职责 | 不做什么 |
|---|---|---|
| `channel/domain/services/channel_chat_service.py` | **编排全部落在这里**：登记文章来源、注入引用规则、答案落库前过滤与清洗、绑定来源到答案消息 | 不改文章获取与敏感内容准入；不引入检索 |
| `channel/api/endpoints/channel_chat.py` | 只做入参、流式封装与调用 Service | **不新增编排逻辑**——该端点今天已直接持有 DAO 调用与提示词拼装（既有 C1 偏离），本 Feature 不再往上叠加，新增逻辑一律下沉 Service |
| citation 注册服务 | 新增文章来源的构建与载荷序列化 | 不改既有两类来源的构建逻辑 |
| citation 解析服务 | 匿名分支收紧；未解析原因判定；文章来源的存在性校验与补全 | **不动** INV-7 已登记的两档语义 |
| 工作流 Agent 节点 | 临时文件检索工具不再打标登记 | 不改临时文件的召回与答案内容 |
| client 前端 | 文章来源类型识别、图标与点击行为；「来源已失效」状态；文案三语 | 不动 platform；不新增徽标来源色 |

| 7 | 共享徽标组件的溯源角标只有 `document` / `web` 两种来源色，且**颜色归设计师** | 自行加第三种颜色违反组件所有权规则 | `packages/ui/src/components/Badge/Badge.tsx` 的 `CITATION` 映射；文章复用 `document` 形态，新色需签字（§2 约束） |
| 8 | 存量 `message_citation` 行没有文章类型 | 回放老消息不受影响，但任何「按类型分派」的逻辑要能容忍未知取值 | `citation_resolve_service.py::_enrich_item` 对未知类型走保守分支（不补全、不报错） |

## 6. 对外契约与依赖

### 6.1 我提供给别人的（Outgoing）

| 契约 | 形式 | 谁在用 |
|---|---|---|
| `article` 来源类型与其载荷形状 | 数据契约：`citation_type = "article"` + `source_payload` 为 §4.2 的 `ArticleCitationPayloadSchema` | 前端角标渲染；未来其他文档型来源可参照 |
| `POST /api/v1/citations/resolve` 响应新增 `unresolved` | HTTP 响应**追加**字段：`{items: [...], unresolved: [{citationId, reason}]}`，`reason ∈ {"forbidden", "expired"}`；`items` 语义与顺序不变 | client 前端区分「无权限 / 已失效」；老客户端忽略即可 |
| `GET /api/v1/citations/{citation_id}` 的 404 响应体携带 `reason` | HTTP 响应**追加**字段 | client 单条兜底路径 |
| 「无已登录用户即不返回来源详情」 | 行为契约 | 所有免登录访问路径（分享页等） |

### 6.2 我依赖别人的（Incoming）

| 依赖 | 形式 | 风险点 |
|---|---|---|
| F029 的文件可见性服务 | 内部 Service | INV-7 执行点，回归即越权 |
| F041 的 `accessScope` 两档语义 | 既有行为 | 本 Feature 明确不改；改动会破坏 INV-7 例外 |
| 频道文章检索服务与敏感内容准入 | 内部 Service | 文章字段（标识 / 标题 / 原文链接）形状变化会漏登记 |
| 共享徽标组件的溯源角标形态 | 组件契约 | 视觉归设计师，来源色不可自行扩展 |

## 7. 测试与可观测

- **后端单测**（`test/citation/`、`test/channel/`，`asyncio_mode=auto`）：
  - 文章来源登记：给定文章 → 断言登记一条 `article` 来源、载荷字段齐、提示词含引用规则且不重复注入。
  - 严格持久化：答案无标记 → 断言**不写**任何来源（决策 4 的回归点）。
  - 未解析原因：四种判定顺序各一例（无登录 / 记录缺失 / 权限过滤 / 底层已删）。
  - **匿名收紧回归**：匿名调用批量解析，`per_user` 与 **`shared`** 两档都不得返回（§5 坑 4）。
  - **INV-7 不回归**：已登录用户的两档语义与改造前逐字段一致。
  - 临时文件：工作流 Agent 检索临时文件 → 断言不产生来源；同轮的真实知识库来源仍正常。
- **前端**：文章来源类型识别与点击行为；「来源已失效」与「暂无权限」两态可区分；三语文案齐。
- **手动验证一遍**（本地起前后端 + 连 test 环境中间件，不改 test 部署）：
  1. 后端：`cd src/backend && export config=config.yaml && uv run uvicorn bisheng.main:app --port 7860`
  2. 前端：`cd src/frontend && pnpm dev:client`（`:4001`，base 路径 `/workspace`）
  3. 打开 `http://localhost:4001/workspace/channel/<channelId>/article/<articleId>`，在文章页侧边问答里提一个能命中文章内容的问题 → 答案出角标 → 悬浮看标题 / 摘录 → 点击开原文链接（新标签）。
  4. 追问一个与文章无关的问题 → 答案**无角标**，且 `message_citation` 不新增行（决策 4 的回归点）。
  5. 在日常模式会话里产生带角标的答案 → `/export` 导出 docx 与 pdf → 确认**导出件里没有角标、也没有隐藏字符**（维持现状的回归点）。
  6. 退出登录（或用无痕窗口）打开同一会话的分享页 → 知识库与文章角标全部为「暂无权限」、网页角标仍可点，页面不报错。
  7. 工作流里用输入节点上传一个文件、让 Agent 检索它 → 答案里**不出现**指向临时文件的角标；同轮真实知识库来源的角标仍正常。
- **可观测**：来源登记的降级分支打点（确认异常回退发生率）；未解析原因按类型计数（区分「无权限」与「已失效」的真实占比，验证判定顺序是否符合预期）。
