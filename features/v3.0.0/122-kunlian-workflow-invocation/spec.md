# Feature 昆联 Agent 反向调用毕昇 Workflow

- **Feature ID**: F122（当前分支拟用，合入前复核）
- **Status**: 本地 Mock 实施基线，正式对接待确认
- **Mode**: Mock 优先
- **Version**: v3.0.0
- **关联需求**: 原对接方案 S08、A10 中的反向工具调用，以及运行状态和结果查询。见[开发规划第 3 批](../../../docs/architecture/proposals/kunlian-workflow-development-plan.md#开发批次与验收)。
- **依赖**: [F121 发布与登记](../121-kunlian-workflow-management/spec.md)、[F118 身份与租户](../118-kunlian-sso-user-sync/spec.md)、F048 统一业务授权及[版本契约](../release-contract.md)。

## 1. 目标与范围

昆联 Agent 把毕昇已发布并登记的 Workflow 作为工具使用。昆联提交业务输入并取得运行会话标识，之后可独立查询运行状态和最终结果。毕昇按昆联指定且当前可用的发布版本、以实际用户权限执行。同一次逻辑调用因超时或断线重试时，昆联能拿回原会话。

首轮只覆盖**提交运行、查询状态、取得最终结果**。用一条无交互、无需真实昆联资源的 Workflow 验收，沿用 F121 本地登记支持的输入输出形态。人工输入与恢复、取消、事件流与续取、回调、跨平台嵌套和防环属于后续工作包。首轮开放范围限于可独立完成的工作流。

| 角色 | 用户故事 |
| --- | --- |
| 昆联 Agent 调用方 | 我希望调用指定的工具版本，提交后能在连接中断或请求超时的情况下恢复同一次调用，并查询最终结果。 |
| 实际运行用户 | 我希望毕昇按本人在对应租户的权限执行和提供结果，其他人拿到会话标识也无法读取我的输出。 |
| 毕昇发布者 | 我希望修改草稿不影响已登记版本，替换或下线生效后旧绑定无法发起新运行。 |

## 2. 业务需求

| ID | 需求 |
| --- | --- |
| REQ-01 | 调用必须明确指定工作流及其已登记的发布版本。毕昇校验工作流、版本、租户和昆联接入方的归属，以毕昇当前发布与登记可用状态为准。昆联目录缓存和登记回执均不构成调用授权。版本缺失、归属不符、未发布、登记资料不完整、被替换、已下线或状态无法确认时，拒绝发起新运行。 |
| REQ-02 | 成功受理后，以该发布版本的图和业务输入输出约定执行，并在会话中保留实际执行版本。保存草稿或之后发布新版本均不得改动该次执行。首轮以已受理为界，替换或下线阻止新受理，不取消已受理的运行，也不单独撤销其结果查询权。 |
| REQ-03 | 提交和查询都须核验受信昆联调用方、可信实际用户及租户，并检查用户当前的 Workflow 使用权限。运行按该实际用户身份执行。服务凭据、请求自报的用户或租户、创建者身份及登记权限均不能代替实际用户授权。查询还须匹配原会话的租户、接入方和实际用户。身份失效、用户停用、撤权或权限无法确认时，拒绝提交、幂等回查及结果查询。 |
| REQ-04 | 每次逻辑调用必须提供稳定的幂等标识。在约定的有效期内，同一接入方、租户和实际用户用同一标识提交相同工作流、版本及等价业务输入，返回同一会话，包含并发提交和受理后响应丢失的重试。原请求仍在受理时可返回可重试的处理中结果，不得产生第二个会话或重复执行。同一范围内复用标识但更改目标、版本或输入时，返回冲突。已受理请求的重试仍须通过当前身份和权限校验，版本后来不可用于新调用时，仍可取回原会话。 |
| REQ-05 | 受理成功应返回可查询的会话标识和固定版本。查询独立于最初请求连接，区分已受理待执行、运行中、成功和失败。成功时返回符合发布版本约定的最终输出，失败时返回可辨认的失败原因。终态在约定保留期内可重复读取，读取不消耗结果，临时查询异常不得被当作执行失败。 |
| REQ-06 | 受理前对业务输入按发布版本校验。身份或权限拒绝、目标版本不可用、输入错误和幂等冲突应可区分，且不产生新运行。无权访问会话时不得泄露会话状态、输入输出或其他租户信息。受理后的失败应能按会话定位，响应不得暴露凭据或内部堆栈。 |
| REQ-07 | Mock 阶段模拟昆联服务身份及用户上下文，通过实际提交、执行和查询路径验证闭环。至少准备有权用户、同租户其他用户和跨租户用户，以及同一工作流的两个可区分发布版本。正式协议替换点保留 `TODO`，真实环境验收标记为 `NOT_RUN`。 |

## 3. 首轮行为口径

| 场景 | 昆联可观察的结果 |
| --- | --- |
| 首次提交成功 | 获得会话标识和实际绑定的发布版本，可据此查询。受理成功和执行成功是两个状态。 |
| 重试原请求 | 当前身份和权限校验通过后，可恢复原会话。即使 V1 已被替换或下线，也不会把原会话改指 V2。 |
| 旧绑定提交新请求 | 毕昇拒绝已被替换或下线的版本。昆联拿到可用的 V2 绑定后可发起一次新的逻辑调用。 |
| 查询会话 | 只有原接入方下的原实际用户在对应租户中，且仍具备使用权限时，可以查询状态和最终结果。 |

## 4. 验收标准

以下为预期验收行为。V-01 为 Mock 接口和实际 Workflow 执行闭环，V-02 为权限、版本边界与并发重试集成验证，V-03 为双方真实环境验收，当前 `NOT_RUN`。

| ID | Requirements | 可观察验收结果 | Verification |
| --- | --- | --- | --- |
| AC-01 | REQ-01、REQ-02、REQ-05、REQ-07 | 当有权的 B 提交已登记的 V1 时，能取得会话标识与 V1，并在原请求断开后独立查询直至成功。返回值符合 V1 的输出约定，在保留期内多次查询得到相同终态及输出。 | V-01、V-03 |
| AC-02 | REQ-01、REQ-02 | 当 V1 已受理后，发布者保存草稿并以 V2 替换 V1，原会话仍按 V1 返回可区分的结果。使用新调用标识发起 V1 被拒，发起当前可用的 V2 得到 V2 结果。V2 下线后，即使昆联仍持有旧目录，也不得新受理 V2。 | V-02 |
| AC-03 | REQ-01、REQ-06 | 若版本缺失、属于其他工作流或租户、未发布、资料不完整或状态不可确认，提交被拒绝，不进入执行。 | V-02 |
| AC-04 | REQ-03、REQ-06 | A 发布、B 调用时，以 B 的可信身份执行。缺少实际用户、伪造身份、用户停用、无使用权或跨租户时提交被拒。拿到 B 的会话标识后，同租户其他用户或其他接入方也无法查询。B 被撤权后，旧会话查询和原请求重试均被拒。 | V-02、V-03 |
| AC-05 | REQ-02、REQ-03、REQ-04 | 相同请求并发提交，或受理成功后响应丢失再提交，最终拿到同一会话，执行只发生一次。V1 下线后，有权的原用户重试仍可拿回原会话。同一标识更改输入、目标或版本返回冲突，且无第二次执行。 | V-02、V-03 |
| AC-06 | REQ-05、REQ-06 | 输入与发布版本约定不符时拒绝受理。对故意执行失败的合法请求，可独立查到稳定失败终态及安全的原因。待执行或运行中的会话不返回最终成功输出。 | V-01 |

| EXT-04 | 专用测试地址、授权与拒绝账号、可调用版本和联调数据，验证真实身份、发布登记与运行闭环。 |
