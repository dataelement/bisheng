# 知识空间删除与异步处理并发修复

用户于 2026-11-17 确认在当前修复分支实现，并补充“移动和复制的保护保留，重建的删除，因为空间都要删除了就不需要重建了”。目标分支为 `codex/3.1.0-beta1/knowledge-processing-bugfix-20261117`，前置提交 `35ba199c9f`；本记录对应其后的实现。未部署或修改 116。

## 行为与验收

- DEL-01：普通排队、解析中的文件不再单独使文件、文件夹或整空间的删除预检不可执行。
- DEL-02：整空间删除可覆盖正在进行的模型重建；取消原处理任务，旧消息和旧租约不得继续发布结果。清空空间、单独删文件仍保留空间重建互斥。
- DEL-03：移动、复制的源空间输入保护和目标空间保护保留，包含未完成或失败后仍待恢复的任务；权限、租户、引用、版本和原确认计划检查保留。
- DEL-04：取消、写入与物理清理之间有明确的先后关系；旧成功/失败结果不能重新插入已删除文件。
- DEL-05：生成物在上传之前记录，Worker 崩溃、存储响应丢失也能恢复清理。完成后复核迟到的外部写入，清空空间的复核不能删除后来上传的新文件。

## 实现

删除确认在原事务内写入删除墓碑及 `KnowledgeSpaceDeleteJob`，并使非移动/复制处理任务失效。单文件删除仅取消其对应任务项，其他项通过原派发机制继续执行；整空间删除/清空使整个处理任务 obsolete。排队、解析、重建或其他活跃处理任务存在时返回 accepted，由现有 Celery 与 Beat 恢复；旧兼容删除入口也接受后台清理状态。

新增 `KnowledgeProcessingFence` 与 `KnowledgeProcessingArtifact` 两个独立表。按租户、空间、物理文件持久化互斥行；零号文件行用于空间级索引初始化/旧重建。锁只由物理写入或后台删除持有，删除确认不等待这些锁。后台取得原写入者使用的所有互斥行后，按既有 FGA → SQL cutover → MinIO/ES/Milvus 链路清理。进程崩溃会释放数据库锁；单纯任务租约过期不视为写入者已经停止。

解析/LLM阶段使用合作式检查点，存储上传、向量写入、索引初始化、重建及元数据索引更新使用写入互斥。已进入外部调用的线程不强杀。MinIO 对象键在外部上传前单独提交，避免仅存在于尚未保存的文件 patch 中。最终文件状态先锁原文件行再校验删除任务，仅更新现存行；模型配置 CAS 增加空间删除墓碑排除条件。

解析的 status、update_time 和派生对象键不再属于新删除计划的结构摘要；资源身份、路径、版本、引用仍被冻结。旧计划继续使用旧摘要算法。后台清理同时读取原清单与生成物台账，不依赖 Worker finally。

外部 IO 超时或进程死亡不等于存储端立即停止处理，因此完成的正式删除任务也参与原 Beat 扫描。复核保持 SUCCEEDED，不重放业务删除或 FGA 投影，只使用已完成清理回执和有效租约检查物理输出。首次完成后约一分钟可复核，之后一小时起退避至每天；失败一分钟后重试，未完成删除优先。整空间删除复核独占索引/集合；文件删除及清空复核只操作原 file_ids。后台不会修改 ES 集群全局配置。

使用 SQLAlchemy 与 dialect_helpers，不新增现有表字段；两个新模型按项目模型发现与升级 create_all 建表规则交付。部署需执行原升级流程并更新 API、Worker、Beat；混用旧 Worker 不能获得新写入检查。写入期间增加数据库连接与互斥事务，真实 MySQL/DM8 并发、连接池占用和大空间耗时仍需集成环境验证。

## 参考

[Celery revoke](https://docs.celeryq.dev/en/stable/userguide/workers.html#revoke-revoking-tasks) 说明 revoke 不会终止已经执行的任务；当前 threads 池不采用任务强杀。[Elasticsearch Index API](https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-index) 允许按配置自动创建索引，因此“索引不存在就报错”不能代替应用取消校验与后台复核。

## 本地验证与限制

真实 SQLModel/SQLAlchemy 仓储、删除计划/墓碑/租约以及解析流水线均执行；ASGI 测试覆盖实际删除预检入口。身份、FGA、Broker、模型与存储运输层使用现有测试边界。SQLite 不证明 MySQL/DM8 行锁和真实远端 IO 的时序；Redis 实机测试在不可连接时跳过。完整实机 E2E 和浏览器交互尚未执行。

最终测试数量与质量检查见同目录审查报告本次增量。人工验收见 [测试用例](knowledge-delete-processing-test-cases-20261117.md)。
