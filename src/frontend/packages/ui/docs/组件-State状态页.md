# 状态页规范 State

> 设计系统 · 状态页 v1 · 2026-08-14
> 由《组件-Empty空状态.md》（2026-08-14 建档）整份重写而来：空状态与结果反馈合成一份文档。**场景决定写什么字、配哪张图；插画尺寸只看容器有多大；排版只有一套。**
> 调研 antd Empty / Result、Arco Empty / Result、TDesign Empty、Semi Empty、Polaris EmptyState、Atlassian EmptyState 后制定；设计师 2026-08-14 拍板：全用插画不引图标、结果反馈只做成功与 404 / 500、无权限归「没有内容」那组、标题 16/24 字重 500、区域内 flex 居中（特殊容器由业务侧自行偏移）。

## 1. 什么时候用

状态页是**一块区域没有正常内容可显示**时，用来替代那片空白的一组图文。它要回答两个问题：这里为什么没有内容、接下来该做什么。

没有内容只有两种原因，本文把它们放在一起管：

- **还没有内容**——一条数据都没有、筛选没命中、你没权限看。
- **刚发生了一件事**——你做完了一整个流程，或者这个页面根本打不开。

**空白本身不是状态。** 什么都不画的空白会让用户以为页面没加载完、或者自己点错了地方。只要一块区域可能出现「什么都没有」，就要为它准备状态页。

| 情况 | 用什么 |
|---|---|
| 数据还在路上 | 骨架屏 / 加载态，**不是状态页** |
| 数据回来了，就是零条 | **状态页**（本文） |
| 有内容，只是某一格没值 | 单元格占位符 `-`，不用状态页 |
| 操作成了没成，用户知道一下就行 | 轻提示，见 [组件-Toast轻提示.md](组件-Toast轻提示.md) |

**状态页占的是整块区域，所以它只留给「这块区域没别的可看了」的时刻。** 保存成功、上传失败这种，用户手边还有一整页内容要接着用，弹一块状态页等于把他赶走。

| ✅ 推荐 | ❌ 不推荐 |
|---|---|
| 请求还没回来时先显示骨架屏，回来是零条再换状态页 | 请求期间就显示「暂无数据」，数据到了再闪回来 |
| 表格零条时在表格体内显示状态页，表头和筛选器都还在 | 表格零条时整个表格连表头一起消失 |
| 保存成功用轻提示 | 保存成功用一整块状态页 |

## 2. 场景分类

七类，分两组。**用哪张插画由场景定，全站同一场景必须用同一张图**；插画的选用速查见 [基础-插画规范.md](基础-插画规范.md) §5.1。

### 2.1 没有内容

| 场景 | 用户处境 | 用哪张插画 | 给不给按钮 |
|---|---|---|---|
| **从来没有过** | 功能刚开始用，一条都还没建 | EmptyState | 给，且是主按钮（「新建」「导入」） |
| **筛选 / 搜索无结果** | 有数据，只是这次条件没命中 | EmptyState / ListWebLink | **不给「新建」**，给「清空筛选」或靠文案引导改条件 |
| **无权限** | 内容存在，但不该他看 | NoPermission | 一般不给，或给「申请权限」 |
| **已完成 / 已清空** | 他自己把东西清空了，这是好事 | EmptyState | 一般不给——事情已经办完了 |

- **搜索无结果不要给「新建」当出路。** 用户想要的是改条件再搜一次，弹一个「新建」等于答非所问，还容易让他误以为搜索功能坏了。
- **无权限不分整页和区域内**，同一类场景、同一张图，差别只在插画多大（见 §3）。

### 2.2 有结果要报

| 场景 | 用户处境 | 用哪张插画 | 给不给按钮 |
|---|---|---|---|
| **成功** | 刚走完一整个流程 | Success | 给（「查看」「继续新建」） |
| **页面不存在 404** | 链接失效，或地址打错了 | SystemError | 给（「回首页」） |
| **服务异常 500** | 后端挂了，或这块区域加载失败 | SystemMaintenance | 给（「刷新」「重试」） |

- **只有终结了一整个流程的成功才占整块区域**，比如知识库创建完成。「已保存」「已复制」这种顺手的成功用轻提示。
- **失败不做整块区域的反馈。** 保存失败、上传失败用轻提示，关键失败用弹窗——判据见 [组件-Toast轻提示.md](组件-Toast轻提示.md) §1。只有整个页面或整块区域打不开，才用服务异常这一类。
- **服务异常这一类同时管区域内的加载失败**，比如网页爬取失败。它跟 500 是同一件事的两个体量，不另开类型。
- **不要说得像用户的错。** 写「暂时加载不出来，请稍后重试」，不写「您的操作有误」。

## 3. 插画尺寸

三档，**看容器有多大，不看是哪个场景**。

| 档位 | 插画 | 用在哪 |
|---|---|---|
| **页面级** | 120px | 整块内容区、页面主体、抽屉与弹窗的主体区域 |
| **面板级** | 80px | 卡片内、侧栏、AI dock 等矮容器 |
| **内联** | **不放插画** | 表格空行、下拉与选择器无选项、行内小区域 |

- **插画只有 120 / 80 两档，不为状态页新开尺寸**（档位定义见 [基础-插画规范.md](基础-插画规范.md) §5.2）。放不下就不放，不缩小。
- **容器可用高度不足 200px、或可用宽度不足 320px 时，一张插画都不放**，只留文字。80px 的图加一行字再加上下呼吸就要 200px，硬塞进去会挤成一团、上下贴边。
- **不放插画的状态页只给一行文字**，居中显示，也不给按钮——那种小格子里的按钮点不准，出路请放到容器外的工具栏上。
- **内联档只服务 §2.1**。表格行里不报「创建成功」，结果反馈至少要有一张图才立得住。
- 彩色还是灰稿见插画规范 §5.3；页面级一律彩色。

| ✅ 推荐 | ❌ 不推荐 |
|---|---|
| 40px 高的下拉列表无选项时只写「无匹配结果」 | 下拉列表里塞一张缩到 32px 的插画 |
| 卡片内空态用 80px 档 | 卡片内空态用 120px，图顶到卡片边缘 |
| 抽屉里的创建成功用 80px 档 | 抽屉里的创建成功照搬整页的 120px |

## 4. 文字与间距

**只有一套排版**，七个场景通用——不分场景组，也不分容器大小（设计师 2026-08-14 定）。

整组内容水平居中，文字也居中对齐；**内容块最大宽度 400px**，超出换行。再宽的一行字读起来要来回扫视，看着也不像一个整体。

### 4.1 排版

自上而下：插画 → 主提示（必需）→ 辅助说明（可选）→ 按钮（可选）。

主提示的样式不看场景，只问一句「这行字算不算标题」：

| 情况 | 层 | 字号 | 字重 | 颜色 |
|---|---|---|---|---|
| **下面还有辅助说明** | 主提示 = 标题 | 桌面 16/24（`text-h4`） | 500 | 主文字色 `text-1` |
| | 辅助说明 | `text-body`（桌面 14/22） | 400 | 第三档文字色 `text-3` |
| **只有一行、没有辅助说明** | 那行就是一句描述 | `text-body`（桌面 14/22） | 400 | 第三档文字色 `text-3` |

- **只有一行时它本来就不是标题**（「还没有知识库」），16/24 加粗会让一条本来只是「这里暂时空着」的信息喊得比周围正文还响。这一行按描述排，不按标题排。
- **要它显示成标题，就给它一句辅助说明。** 结果反馈尤其如此——「知识库创建完成」后面本来就该跟一句「现在可以上传文档」，光一句结论既撑不起整块区域，也没告诉用户下一步。

间距三个数，同样通用：

| 相邻层级 | 间距 |
|---|---|
| 插画 ↔ 主提示 | 16px |
| 主提示 ↔ 辅助说明 | 4px |
| 主提示（或辅助说明）↔ 按钮 | 16px |

- **16 是块与块之间，4 是一块之内。** 主提示和辅助说明是一句话拆成两段——先说是什么状态，再说下一步怎么办——中间一拉开就散成两块，标题反而像在单独喊一声。
- **不分插画档，也不分场景组。** 历史上排过三套：整页结果 16/32/40、容器内结果 16/8/20、紧凑档 16/4/20。实际渲染下来，大间距把四个元素拉成四块散件，而它们说的是同一件事；三套数值之间的差又都只有一档，读起来不像层级，像没对齐。2026-08-14 全部收成这一套。

### 4.2 文案

正文遵循 [基础-文案规范.md](基础-文案规范.md)，以下是状态页自己的细则。

- **主提示 / 标题说「是什么状态」，不说废话**：「还没有知识库」「知识库创建完成」，不写「暂无数据」「操作成功」——这类话用户看一百遍也不知道该干什么。
- **辅助说明说「为什么」或「怎么办」，不重复标题**，最多两行。
- **第三条出路做成辅助说明里的文字链接**，比如「没有权限？联系管理员」这句里的「联系管理员」。链接不占按钮位（见 §5）。
- **句末不加句号**，标题不加感叹号。
- **出错类要给可执行的下一步**：「加载失败，请刷新重试」，不是干甩一句「加载失败」。

| ✅ 推荐 | ❌ 不推荐 |
|---|---|
| 还没有知识库 | 暂无数据 |
| 没有找到匹配的内容，换个关键词试试 | 查询结果为空。 |
| 知识库创建完成 | 操作成功！ |
| 加载失败，请刷新重试 | 系统异常！ |
| 你没有权限查看这个空间 | 403 Forbidden |

## 5. 操作按钮

- **最多一个主按钮加一个次要按钮。** 主按钮承担唯一出路，次要按钮只放「了解更多」「刷新」这类退路。
- 两个按钮时**横排居中、间距 8px，主按钮在右**（设计师 2026-08-14 定）。与弹窗 footer 同一个道理：视线从左读到右，在最右侧收束于要做的那个动作。[组件-Button按钮.md](组件-Button按钮.md) §4 把「页面级操作区」定为主按钮领在最前，状态页不按那条走——状态页的按钮是居中的一小组收尾动作，不是页面的入口动作。
- **再多的出路做成辅助说明里的文字链接**（见 §4.2），不占按钮位。三个平级按钮会让用户先挑选、再行动，而状态页本该是「一眼看到该点哪儿」。
- **按钮取 medium（32px）档**，主按钮用 Primary、次要按钮用 Default，类型与尺寸定义见 [组件-Button按钮.md](组件-Button按钮.md) §2、§3。
- **按钮文案用「动词 + 名词」**：「新建知识库」，不写「点击这里」「去创建」。
- **没有真出路就别放按钮。** 已完成、已清空、无权限这些场景强行加按钮，等于逼用户回到他刚离开的地方。

| ✅ 推荐 | ❌ 不推荐 |
|---|---|
| 空列表：主按钮「新建应用」+ 次要按钮「导入」 | 空列表：「新建」「导入」「模板」三个平级按钮 |
| 无权限：文案里放「联系管理员」文字链接 | 无权限：放一个主按钮「联系管理员」 |
| 已清空回收站：不放按钮 | 已清空回收站：放一个「返回」按钮 |

## 6. 在区域内的位置

- **状态页替换的是内容，不替换容器的框架。** 表头、工具栏、筛选器、标签页、分页器一律保留——尤其筛选无结果时，筛选器被一起藏掉，用户就没法把条件改回来了。
- **水平垂直都居中，就这一种机制**（flex 居中，设计师 2026-08-14 定）。不做「顶距封顶」「按 40% 定位」这类特殊算法——多一套规则，就多一处要解释、要对齐、会跑偏的地方。
- **少数容器需要往上挪，由业务侧自己偏移**：给状态页加一个不对称的下内边距（`pb-16`、`pb-[112px]`），居中在剩下的框里重新解算，内容自然上移一半的量。两种情况才需要：容器比内容高出太多、图掉到首屏以下；或者容器底部压着悬浮元素（AI dock、批量操作条）。既有成例见 §10。
- **容器不因状态页塌陷或撑高。** 状态页占满它所替代的那块区域，最小高度：页面级 320px、面板级 200px。列表从 10 条变 0 条时页面高度剧烈跳动，用户会以为跳到了别的页面。
- **不要让状态页把页面撑出滚动条。** 撑出来说明该降档了（见 §3）。
- 表格内的状态页**横跨所有列**，占据表格体，表头留在原处。

## 7. 移动端适配

> 跨组件通用原则见 [基础-多端适配原则.md](基础-多端适配原则.md)，此处只写状态页自己的细则。

| 项 | 窄屏 / 触屏规则 |
|---|---|
| 插画 | 手机档页面级由 120px 降到 80px，面板级不变；内联档仍不放图 |
| 排版 | 与桌面同一套（16 / 4 / 16 本来就不分档，手机端不必再降） |
| 内容宽度 | 最大宽度改为左右各留 16px 后的剩余宽度 |
| 文字 | 正文随 token 抬到 16/24；**结果反馈的标题不跟着抬**，仍是 16/24，靠字重与间距拉层级 |
| 按钮 | 手机档 block 占满整行；两个按钮改为纵向堆叠、**主按钮在上**、间距 12px。桌面主按钮在右、手机在上，堆叠方向反过来（组件内用 `flex-col-reverse`，业务侧照桌面顺序写就行） |
| 触达 | 文字链接热区扩到 ≥44×44px，视觉尺寸不变 |
| 位置 | 同桌面：flex 居中，不另设移动端规则 |

## 8. 无障碍

- **插画是装饰，加 `aria-hidden`**（呼应插画规范 §4）。屏幕阅读器读不到图，所有信息必须由文字承担。
- **筛选与搜索的结果数量变化要播报**：结果由有变无时用 live region 念出主提示，别只换一张图。
- **操作按钮和文字链接必须能用 Tab 到达**，焦点样式不被状态页容器裁掉。
- **关键信息放主提示或标题，别只写在辅助说明里。** 辅助说明取的第三档文字色在白底上对比度约 2.8:1，低于 WCAG AA 的 4.5:1，弱视用户可能整行读不到。
- **404 / 500 这类整页状态要能被焦点找到**：页面加载后把焦点移到标题上，别让键盘用户在空页面里 Tab 半天。
- 状态页不抢焦点——它是内容，不是需要用户理会的提示。

## 9. 落地要求（给实现窗口）

1. 组件形态：`<StateView />` 声明式组件，props 收敛为 `size`（`page` / `panel` / `inline`）、`image`（传插画组件，`inline` 档不接受）、`title`、`description`、`action`。不做命令式 API。**文档与设计语言里叫「状态页 / State」，代码导出名是 `StateView`**——`State` 在 React 代码里会被读成状态变量，且是个过于通用的名字（2026-08-14 定）。
2. **只有 `size` 一根轴**（§3 看容器）。场景组（§2.1 / §2.2）决定你写什么字、配哪张图，不决定怎么排——排版只有一套（§4），所以不做 `variant` 这类 prop。抽屉里的创建成功就是 `size="panel"`。
3. `inline` 档不渲染插画与按钮（§3）。约束由**类型**兜住而非运行时警告：`size="inline"` 时 `image` / `action` 声明为 `never`，写错即编译错误（§3 末条）——组件库是 strict TS 且没有 node types，编译期报错比 `console.warn` 更早也更硬。
4. 间距只有两个常量：块间 `mb-4`（16px）、块内 `mb-1`（4px），`page` / `panel` / 所有场景同值。插画 `mb-4`、主提示 `mb-1`、辅助说明 `mb-4`；没有辅助说明时，主提示直接吃块间的 `mb-4`。
5. 垂直定位实现：`flex` + `items-center` + `justify-center`，仅此而已（§6）。不写占位盒、不写 `min()`、不按断点改规则。上移由业务侧通过 `className` 传不对称的 `pb-*` 达成，所以 `className` 必须透传到最外层容器，且组件自身的定位类要能被 twMerge 覆盖。
6. 最小高度写在组件上（page 320px / panel 200px），不由业务侧各自撑（§6）。
7. 文字色取 `text-1` / `text-3` token，禁止裸 hex；标题取 `text-h4`（字体规范 §2 Semantic 表里 16/24 那一档，桌面移动同值，正好符合「结果反馈标题不跟着抬」），辅助说明与「单行描述」取 `text-body`。判定写成 `description ? 标题 : 描述`——有没有说明是唯一依据。
8. 表格 / 下拉 / 选择器的内置空态统一接 `inline` 档，业务不再各写一行「暂无数据」。
9. 上线前照元规范 §5 清单：在 `src/frontend/client/rspress.config.ts` 的 `themeConfig.sidebar` 注册本文入口，`components/` 下建 ASCII 命名的 demo 页（`components/state.mdx`）。**✅ 2026-08-14 已完成**：组件落在 `packages/ui/src/components/StateView/`，demo 页归「组件 → 反馈 Feedback」组。
