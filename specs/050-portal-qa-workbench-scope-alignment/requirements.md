# 需求说明 Requirements: 门户智能问答与知识库工作台查看范围对齐

## 元信息 Metadata
- Feature ID: `050-portal-qa-workbench-scope-alignment`
- Status: `implemented`
- Mode: `bug-fix`
- Created: `2026-07-30`
- Updated: `2026-07-30`
- Source: 用户确认“智能问答选择器与门户知识库工作台使用相同查看范围，仅展示 SUCCESS 文件并保留懒加载”
- Bug source: 用户反馈智能问答选择器的个人知识库分组出现两个同名“gzx001的知识库”，并要求代码修复

## 背景 Background

当前登录用户的智能问答选择器采用门户广域发现范围：公共知识库、全部有效部门知识库，以及用户原有可见的团队和个人知识库。
知识库工作台则使用当前用户的标准读取权限列出知识库，并在目录和文件层继续执行 `view_space`、`view_folder`
和 `view_file` 校验。两者范围不一致，导致用户可能在智能问答中发现工作台不可读的部门知识库或文件。

本需求将智能问答的选择、搜索和最终检索范围统一到知识库工作台的标准读取权限，同时保留智能问答仅使用解析成功文件的约束。
本规格取代既有规格中“智能问答继续采用公共库与全部有效部门库广域发现”的相关约定。

## 范围 Scope

### 包含 Includes
- 登录用户的智能问答知识库列表与知识库工作台当前用户可读知识库集合一致。
- 目录、文件、文件名搜索和分类选择均受工作台标准读取权限约束。
- 智能问答选择器只展示 `SUCCESS` 文件。
- 保留树节点按需展开、游标分页和继续加载机制。
- 问答提交时在服务端重新校验知识库、目录和文件权限，拒绝构造 ID 绕过选择器。
- 保留未登录用户现有的公共知识库智能问答范围。
- 个人知识库分组不得重复返回当前用户的同名个人空间。

### 不包含 Excludes
- 除过滤同名无效个人空间外，不修改知识库工作台自身的可见范围、状态展示和懒加载行为。
- 不修改门户首页搜索、文件浏览、发布、分享、收藏和推荐等其他知识发现范围。
- 不修改数据库结构、权限数据、知识库成员关系或审批授权数据。
- 不改变智能问答的 1 个整库、20 个文件上限。
- 不删除、合并或迁移数据库中已经存在的同名个人空间记录。
- 不新增数据库唯一约束；并发创建的数据库级防重另行评估。

## 需求列表 Requirements

### REQ-001: 登录用户知识库范围对齐
系统 SHALL 对登录用户使用知识库工作台的标准可读知识库集合生成智能问答知识库列表。

#### 验收标准 Acceptance Criteria
- `AC-REQ-001-01`: 公共、部门、团队和个人知识库仅在当前用户能于工作台读取时出现在智能问答选择器。
- `AC-REQ-001-02`: 有效但当前用户无工作台读取权限的部门知识库不再出现在选择器。
- `AC-REQ-001-03`: 未登录用户仍只能看到公共知识库。

### REQ-002: 资源范围与状态过滤
系统 SHALL 使用工作台标准资源读取权限返回目录和文件，并只展示状态为 `SUCCESS` 的文件。

#### 验收标准 Acceptance Criteria
- `AC-REQ-002-01`: 根目录及子目录加载均校验 `view_space`、`view_folder` 和 `view_file`。
- `AC-REQ-002-02`: 无权限目录或文件不返回，不再以“可见但不可选”形式暴露。
- `AC-REQ-002-03`: `PROCESSING`、失败、超时及其他非 `SUCCESS` 文件不返回。
- `AC-REQ-002-04`: 文件名搜索只返回工作台可见且为 `SUCCESS` 的文件。
- `AC-REQ-002-05`: 分类选择只检索当前选择器已加载的可读知识库集合。

### REQ-003: 懒加载兼容
系统 SHALL 保留现有智能问答树的按需加载和游标分页契约。

#### 验收标准 Acceptance Criteria
- `AC-REQ-003-01`: 打开选择器仅加载知识库列表，不预加载所有目录和文件。
- `AC-REQ-003-02`: 展开知识库或目录时继续传递 `parent_id`、`page_size` 和可选 `cursor`。
- `AC-REQ-003-03`: `has_more`、`next_cursor` 和 `page_size` 按现有前端契约返回。
- `AC-REQ-003-04`: 目录深层可选文件数只统计用户可见的 `SUCCESS` 文件。

### REQ-004: 服务端失败关闭
系统 SHALL 在问答提交和最终 RAG 文件范围解析时重新执行工作台权限校验，不信任前端传入 ID。

#### 验收标准 Acceptance Criteria
- `AC-REQ-004-01`: 请求包含不可读知识库时，门户 BFF 拒绝请求。
- `AC-REQ-004-02`: 绕过 BFF 直接提交不可读知识库、目录或文件时，BiSheng 不将其加入检索范围。
- `AC-REQ-004-03`: 整库模式只解析当前用户可见的 `SUCCESS` 文件。
- `AC-REQ-004-04`: 文件模式继续执行 20 个文件上限，并对持久文件引用解析后的实际入口执行权限校验。
- `AC-REQ-004-05`: 空授权范围继续以空引用上下文运行，不自动扩大到其他知识库。

### REQ-005: 兼容性与范围隔离
系统 SHALL 保持智能问答以外的门户知识发现行为和 API 契约不变。

#### 验收标准 Acceptance Criteria
- `AC-REQ-005-01`: 现有智能问答 API 路径、请求参数和前端选择器数据结构不变。
- `AC-REQ-005-02`: 门户通用 `/files/browse` 的默认广域发现语义不被全局收紧。
- `AC-REQ-005-03`: 无数据库迁移、依赖变更或权限关系写入。

### REQ-006: 个人知识库分组同名防重
系统 SHALL 在工作台分组接口中仅返回当前用户每个规范化名称的第一条个人空间，避免历史或并发产生的同名记录在智能问答选择器中重复展示。

#### 验收标准 Acceptance Criteria
- `AC-REQ-006-01`: 当前用户存在两个不同 ID、名称去除首尾空格后相同的个人空间时，`personal_spaces` 只返回现有排序中的第一条。
- `AC-REQ-006-02`: 当前用户名称不同的个人空间继续返回，他人的个人空间继续不可见。
- `AC-REQ-006-03`: 公共、部门、团队分组及接口结构保持不变。
