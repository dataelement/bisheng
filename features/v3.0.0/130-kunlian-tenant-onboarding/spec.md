## 1. 目标与范围

昆联可信目录中的有效租户自动获得独立的毕昇工作流空间，其有效成员自动获得登录工作流管理入口和新建工作流所需的最小基础资格。用户使用自己的身份访问和管理有权操作的工作流；租户之间保持隔离。

本批纳入：有效租户自动开通、成员自动开通、最小基础资格、状态与本地阻断、重复处理与失败恢复、多租户登录准入及原入口兼容。

本批排除：跨租户 Workflow 资产消费、其他人的资源自动共享、模型平台接入、自动合并历史账号、资源迁移、空租户发现的新接口、秒级身份推送、全局或租户管理员自动任命。正式接口缺口先保留待确认，首轮用隔离 Mock。

### 已确认调整

| ID | 决策 |
| --- | --- |
| C-01 | 为可信目录中的有效租户自动创建独立本地租户。 |
| C-02 | 为有效成员自动配置“工作流管理入口＋新建工作流”最小基础角色；不授予管理员身份，不自动授予其他人的 Workflow 权限。 |
| C-03 | 用户确认继续收窄创建能力：自动资格只允许创建 Workflow，不自动获得创建助手、托管应用或通用模板管理能力；保留已有独立人工授权。 |

C-02 取代 F118 C-03 在本批启用范围内的“基础菜单由管理员提前配置”决定。F118 关于实际用户、在线身份有效性、停用、人工授权保留及具体资源权限的规则继续适用。未启用本批自动开通的连接保留原行为。

## 2. 用户故事与需求

- 作为昆联租户成员，我希望同步完成后可以进入自己的工作流管理页并新建工作流，无需逐个请求管理员开通基础入口。
- 作为管理员，我希望自动开通可追踪、可阻断，不改变历史授权或将外部角色变成管理员身份。
- 作为运维人员，我希望能区分目录未就绪、开通处理中、明确不可用和处理失败，并能安全重试。

| ID | 业务需求 |
| --- | --- |
| REQ-01 | 对可信目录中已确认有效且未被本地阻断的租户自动开通；同一外部租户稳定关联同一本地独立租户。 |
| REQ-02 | 有效成员自动成为对应租户的用户；稳定识别身份，不因重名、更名、重复同步或多实例执行产生误合并与重复账号。 |
| REQ-03 | 自动配置工作流管理入口与工作流专属创建资格，不因此获得其他类型应用创建或通用模板管理能力；用户对自己新建工作流的操作沿用既有创建者规则，其他资源动作继续独立鉴权。 |
| REQ-04 | 登录范围与可信租户、Workspace、成员及本地资格共同匹配；页面参数和目录读取范围不能代替登录授权。 |
| REQ-05 | 成员／租户停用、本地明确阻断及基础资格撤销能够阻止新访问；自动同步不得抵消管理员明确作出的阻断与撤销。 |
| REQ-06 | 开通过程可重试、可接续、可诊断，部分失败不导致重复创建、错误准入、半批次目录生效或误删既有对象。 |
| REQ-07 | 原单租户连接、人工映射、历史账号与授权、其他登录方式及工作流功能保持兼容；Mock 与真实验收分开记录。 |

## 4. 边界情况

- “可信目录”指已登记来源、认证及内容校验通过的目录。浏览器传入的租户、用户名或外部角色不是开通依据。
- 目录未包含无成员租户时，不推测或虚构这些租户；新用户未被目录覆盖时，继续执行补同步后重新登录规则。
- 角色和菜单就绪不等于 Workflow 对象权限就绪；不得为实现基础入口而默认开放所有 Workflow。
- 工作流专属创建资格不等于通用应用创建资格；复制工作流也必须核对源 Workflow 的当前权限，不能借复制入口创建其他类型或读取未获授权的来源。
- 用户恢复不能覆盖本地管理员阻断、手工撤销或已经失效的来源关联；同名其他身份仍独立处理。
- 昆联客户端只允许试点租户时，本地可验证其他租户的开通，但必须拒绝其超出上游范围的真实登录。
- 新建工作流配额不足时拒绝该次创建，不通过自动开通授予无限配额。
- 自动开通不是实时身份事件推送。同步生效时效应在设计及真实联调中明确，不将现有周期轮询宣传为秒级同步。

## 6. 待昆联完成的真实接入条件

- 扩展现有客户端的允许登录租户，或交付可复用的多租户客户端接入方式；明确租户与 Workspace 的对应关系。
- 提供至少两个租户的有效测试身份，以及可进行新增、停用／恢复验证的测试成员。
- 若要求无成员租户预开通或更短的新用户生效时效，确认已有租户目录、通知或增量能力；不默认要求新增接口。

现有客户端凭据、全租户目录 Key 及已登记回调不重复索取。真实范围尚未交付时不更改服务器范围或宣称多租户登录已通过。
