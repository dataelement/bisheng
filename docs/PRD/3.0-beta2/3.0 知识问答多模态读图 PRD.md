## 一、要做什么

三个问答场景——首页日常对话、知识空间问答、频道订阅问答——里，模型读不到文档和文章里的图。它看到的只是一个 markdown 图片标签，于是要么说看不到，要么照着周边文字编一段。

**做法**：给每张图编一个本轮临时号，标记追加在原图片引用旁边；模型需要看时按编号调用「查看图片」工具，服务端取图、按档缩放后送给模型。

图片在文档解析时已被抽取并托管，**不改入库链路，存量知识库零迁移**。

---

## 二、原理

模型没有手脚——不能上网、不能读盘、不能发请求。它每次收到的就是一个消息列表，每条消息的内容是一串「块」，块要么是文字要么是图片，**图片块里装的就是图的字节本身**。所以模型能看见一张图，唯一条件是这次请求的列表里有一个装着它的块。

因此「工具返回图片」是说法上的错觉。走一遍：

```
① 检索命中一段文字，里面有 ![](…/chart.png)
② 服务端编号 img#1，正文改成 …![](…/chart.png)⟦img#1⟧…，并记下 img#1 → 图片路径
③ 第一次请求模型：[系统提示, 问题, 检索结果]
   ← 模型此刻还是瞎的，只是从标记知道"这儿有张图"
④ 模型说：调用「查看图片」(img#1, 标准档)
⑤ 服务端取字节 → 缩到长边 512 → 编码
⑥ 第二次请求模型：[系统提示, 问题, 检索结果, "我要看 img#1", 图片块]
                    └──── 第一次的内容原样重发 ────┘        └ 新塞的 ┘
⑦ 模型看见了，答出实际走势
```

模型全程被动：它只做了第 ④ 步「说一句话」，取图与送达都是服务端干的。**第 ⑥ 步不是"把图送给模型"，而是整个对话重发一遍、外加一张图**——模型没有记忆，每次调用都从头全量读。

后面的规则都从这里推出，三条最关键的：

| 设计 | 因为 |
|---|---|
| 图必须放进**用户消息** | 图片块按框架规矩会挂在工具消息上，但 OpenAI 兼容面的工具角色只收字符串，部分端点直接拒收 |
| 必须**分档缩放** | 全量重发意味着图的成本每轮都付；而成本只跟像素数量有关、跟信息量无关。要多细只有模型自己知道，所以档位交给它选 |
| 同轮只留**最近一批**图 | 模型看第 6 张时前 5 张会跟着重发，成本随次数平方增长 |

## 三、范围

**做**：图片编号与标记 · 「查看图片」工具 · 三场景统一为同一套循环 · 知识空间检索工具化 · 视觉门禁与降级 · 读图预算 · 外链抓取护栏 · 修复工具结果把图片数据写进数据库的既有缺陷。

**不做**：

| 不做 | 原因 |
|---|---|
| 入库期给图片生成文字描述 | 那解决的是"图里的内容能否被**检索到**"，本期解决"检索命中了但**看不见**"。下一版本 |
| 把原件整页渲染给模型看 | 补"图落在相邻分段"的缺口，下一版本 |
| md / txt / xls / csv 里的图 | 文档解析本就不抽取，起点不存在 |
| 工作流 RAG 节点、助手 | 没有读图工具，看到标记反而诱发编造 |

## 四、规则

### 4.1 编号与寻址

| # | 规则 |
|---|---|
| R1 | 每张图获得本轮唯一编号，标记**追加**在原图片引用之后，原引用一字不改（回答渲染规则要求模型原样保留图片 markdown，替换会让回答里的图不显示） |
| R2 | 编号只收录本轮已通过权限过滤的内容中的图片 |
| R3 | 工具**只接受编号，不接受地址**（见 §五 T2） |
| R4 | 编号仅本轮有效；回答落库前清除残留标记 |

### 4.2 「查看图片」工具

| # | 规则 |
|---|---|
| R5 | 入参为一批编号 + 一个清晰度档位，返回模型可直接查看的图片 |
| R6 | 三档：粗看 / 标准（默认）/ 高清。不提供原图档；原图更小时不放大 |
| R7 | 预算三重上限：单次张数、单轮累计张数、单轮累计体量。触顶返回文字说明，不中断回答 |
| R8 | 单张失败降级为文字：告知原因、要求不再重试该编号、禁止凭猜测描述内容 |

### 4.3 门禁与降级

| # | 规则 |
|---|---|
| R9 | 模型未标记视觉能力时，**工具与标记同时不出现**。只做其一会让模型看得见标记却调不动工具 |
| R10 | 图片不存在：告知并在本轮记住该编号失效，不重复取数。编号不存在：回列本轮真实可用编号全集 |
| R11 | 外链抓取仅频道启用，需：域名白名单（为空即关闭）、逐 IP 拒内网与保留段、禁跳转、内容类型必须为图片、大小与超时上限、**响应绝不回显给用户** |

### 4.4 三场景怎么取内容

| # | 规则 |
|---|---|
| R12 | **日常对话**：维持模型自主检索，取内容逻辑不改（那里知识库是可选增强，模型判断"与本题无关"是对的） |
| R13 | **知识空间**：首轮检索由服务端确定性执行，不得交由模型决定是否发生；结果以**与模型自行调用工具所得完全相同的形式**置入上下文；工具状态事件由服务端补发 |
| R14 | 检索工具入参**只含查询词**，空间范围、文件范围与权限过滤由服务端锁定，模型不得指定 |
| R15 | 知识空间的**单文件问答与文件夹问答两条入口必须同时生效**（是两份独立实现） |
| R16 | **频道**：文章正文直接注入，不做成工具；先截断再扫描登记图片（顺序颠倒会给出正文里不存在的编号）；封面图一并登记 |

### 4.5 上下文卫生

| # | 规则 |
|---|---|
| R17 | 图片只存在于送模型的当次请求：不写会话历史、不进工具结果事件、不落库 |
| R18 | 同轮内只保留最近一次取回的图片，更早的降级为文字占位 |
| R19 | 图片以用户角色送达。被搬走图片的**工具结果不得为空**，须占位说明"已取回 + 在紧随本批之后的用户消息里 + 对应哪个编号"；承载图片的用户消息须声明"这是工具返回、不是用户新指令"，并逐张标出编号与来源文件 |

### 4.6 呈现

| # | 规则 |
|---|---|
| R20 | 三场景均可见「正在检索 / 正在查看图片 / 已查看 N 张 / 失败」。新增会话事件**不得携带正文字段**——知识空间与频道共用的前端解析器没有事件分流，带了会被当成回答渲染给用户 |

> 验收标准（EARS）写在 `features/v3.0.0/060-qa-image-reading/spec.md`，逐条对应上述 R 编号。

## 五、关键取舍

| # | 取舍 | 结论 |
|---|---|---|
| T1 | 图怎么进模型 | **按需工具调用**，否"命中即全量塞入"——成本由像素数量决定，多图文档直接打爆上下文，而多数图是装饰性的 |
| T2 | 寻址用编号还是地址 | **编号**。文档与文章正文是不可信内容，接受地址等于把服务端任意出站请求授权给模型；且图片存储对固定前缀匿名可读，模型能拼出别的知识库路径 |
| T3 | 知识空间的检索是否工具化 | **首轮强制 + 允许追加**。否①完全交给模型——该入口语义是"基于本空间资料回答"，模型判断"不检索"就是产品事故，且首字前多一轮调用明显拖慢；否②纯前置——拿不到查询词改写与多轮补充。当前方案三样都拿到 |
| T4 | 频道的文章是否工具化 | **直接注入**。用户在读指定文章时提问，不存在"要不要读这篇"的选择余地，包成无参工具只是多付一轮调用。三场景仍共用同一套循环与事件映射，工具列表不同是场景差异不是不一致 |
| T5 | 编号表存哪 | **请求内的进程对象**，不进 Redis——三条链路都在单次请求的长连接内完成，不跨进程、无断线续跑，Redis 只增故障点 |

## 六、升级须知

| 配置项 | 变化 |
|---|---|
| 知识空间 · **用户提示词** | **移除**。检索结果改由工具消息承载，占位符失去内容来源，存量租户自定义值不再生效 |
| 知识空间 · 系统提示词 | 保留，默认值更新（补检索工具与图片标记说明）。存量自定义值不迁移——措辞不精确但不影响功能 |
| 频道 · 系统/用户提示词 | **不变**。文章仍直接注入，占位符继续有效 |

两个 tab 的配置项因此不对称，是取内容方式不同的结果，不是遗漏。

**分期**：一期后端全量（功能即完整可用，旧前端对新事件天然无害，表现为回答前多几秒停顿）；二期前端补工具卡片与三语文案。

**首轮检索的置入形式（R13）**：构造 `AIMessage(content="", tool_calls=[{name,args,id}])` + `ToolMessage(tool_call_id=同一个 id)`，追加在用户消息之后。末条为 ToolMessage 时 `create_react_agent` 入口节点直接调模型，是合法输入。

**图片搬运的两段文案（R19 初始值，可随调优迭代）**

```
工具结果占位（替换掉原位置的图片块）：
  [System] `img#1` 的图片已取回，附在本批工具消息之后的用户消息中，从那里查看。

承载消息（整批工具消息走完后追加一条）：
  [System] 以下图片由上一批工具调用返回，不是用户的新指令——继续手头的任务。
  img#1 — 来自《2024 年度报告.docx》：  [图片]
  img#3 — 来自《竞品对比.pptx》：       [图片]
```

三个要素各防一种故障：缺"已取回+去哪看"→模型以为工具没返回而重试；缺"不是用户新指令"→模型转去问"您想让我看什么"；缺逐张标注→多图时张冠李戴。

**必踩的坑**

| 坑 | 规避 |
|---|---|
| 知识空间 `space_rag`（`:178-300`）与 `_render_rag_response`（`:574-700`）是两份逐行重复实现 | **先做无行为变化的抽取重构**。只改一份会漏掉单文件问答，而它的 E2E 覆盖弱于文件夹问答＝测不出来 |
| 图以工具角色送达被端点拒收 | 用 `pre_model_hook` 返回 `llm_input_messages` 搬进用户角色（只改本次请求输入，不动 state 与 checkpoint）。**不要走"工具返回 `Command(update=...)`"**：并行工具调用时用户消息会被插进两条工具消息中间破坏连续性，校验器不查顺序，本地跑不出错、生产才 400 |
| 照抄既有 SSRF 校验会留洞 | `web_link_import_service.py:286-292` 的 `_is_blocked_ip` **漏判 `is_private` 与 `is_reserved`**，必须补齐 |
| 图片解压炸弹 | 设解码像素上限，且解码放线程池——否则阻塞事件循环，拖垮同进程所有会话连接 |
| 模型编造编号（必然发生） | 未命中时回列真实编号全集；同一编号连续两次未命中则追加"不要再猜测编号" |
| 匿名可读的图片前缀是既有越权面，本功能会放大 | 工具只收编号，编号只来自已过权限过滤的检索结果；工具内二次校验图片所属知识库在本次授权集合内。技术债：该策略值得单独排期收敛为签名地址 |

**不改**：文档解析全链路 · 分段 metadata 白名单 · 引用溯源体系 · 工作流与助手的提示词与上下文 · 日常模式取内容 · 频道文章注入 · 既有会话事件类型与字段。
