## §1 画面清单

`.dc.html` 是 Claude Design 单文件交互稿：`<x-dc>` 内为模板（`sc-if` / `sc-for` 条件与循环），`<script data-dc-script>` 内 `class Component extends DCLogic` 的 `state` + `renderVals()` 驱动全部画面切换与假数据。v2 一共 1 个壳 + 6 个一级导航 + 4 个详情 tab + 6 个弹层，Tweaks 面板暴露两个开关：`runtimeForm`（compose 单机 / k8s 集群）、`singleTenant`。

### 2.0 全局壳与假数据

- 顶栏：logo「BISHENG」+ 灰标签「应用工场 PRD-1 · v1.9 交互 demo」；在构建列表页时居中显示构建三 tab「应用 / 工具 / 工作台配置」（后两者点击只 toast「既有构建区 tab，本 demo 只演示「应用」」）；右侧铃铛（带红点）→ 消息提醒 popover；「视角」切换 `personas`：开发者 / 租户管理员 / 审批人 / 平台超管（**demo 脚手架**，切换同时重置 nav：审批人→审批中心、超管→系统管理·资源档位、其余→构建）；用户头像 + 姓名 + 角色 pill（「开发者 · owner」/「租户管理员」/「审批人」/「平台超管」）。
- 左侧导航 `navDefs`（按视角与部署层过滤）：构建（需 `roles[role].build && layers.runtime`）· 审批中心（管理员或审批人 && runtime）· 审计（管理员）· 系统管理（管理员）· API key 管理（管理员 && `layers.open`）· 应用广场（runtime）。导航底部灰字：「承载面 = platform「构建 → 应用」，与工作流 / 助手同一列表。本册零新增一级菜单、零新增权限点（GOV-07）。」
- 模块内二级 tab（`hasTabs`，胶囊样式）：审批中心 = 待办 / 场景配置（非管理员只有待办）；系统管理 = 角色与权限 / 能力总线 / 部署形态 / 资源档位（runtime 层已装才出现）；API key 管理 = 服务账号与密钥。
- 假数据：5 个应用（合同台账助手·已上线·标准档·可见 法务部+王敏；报销单核对·待上线（资源不足）·轻量；客服知识速查·已上线·性能·在途迭代审批；供应商比价·已停运·上次驳回；出差申请小工具·草稿），2 张审批单（客服知识速查 v4 迭代·待审；报销单核对 v1 首发·已通过·待上线），3 档位，3 模型，10 个授权候选（5 用户 / 3 部门 / 2 用户组），10 条审计。
- 状态枚举 `STATUS`：`draft`「草稿」/ `online`「已上线」/ `pending_res`「待上线（资源不足）」/ `stopped`「已停运」（与 PRD §3.0.2 应用态一致，缺「已删除」终态——demo 删除即从列表移除）。版本终态 `VSTATE`：已上线 / 曾上线 / 被驳回 / 待审 / 已通过 · 待上线 / 已撤回。
- 视觉：主色 `#024DE3`，成功 `#00873D/#E8F6EE`，警示 `#B54708/#FFF4E5/#FFDCA8`，危险 `#ef4444/#FEF6F5/#FBD7D3`，卡片圆角 10–12px，pill 5px。

### 2.2 应用详情页（壳 + 发布 tab）

- 头部：「‹ 返回构建 · 应用」；logo 首字 + 应用名（19px）+ 状态 pill + 灰字「owner {owner} · {来源} · {档位}档 · {运行时形态}」（形态是 demo 脚手架）；描述；四个下划线 tab「发布 / 数据 / 运行日志 / 版本」，右侧灰注「本册形态：无左侧对话区、无管家」。
- **可见范围引导条**（`app.needVis` = 已上线且 vis 为空）：黄底卡「已上线，但目前仅 owner 可见」/「上线 ≠ 可用。设置可见范围是首发后的必经一步——不设，同事在广场里看不到它。」+ 主按钮「设置可见范围」→ 授权弹窗（PRD GOV-01 验收 3）。
- **发布管线**卡（边框随状态：在途/待上线黄、驳回红）：标题「发布管线」+ 右侧按钮组：「提交发布」（`canSubmit` = 非在途且 草稿/已上线/已停运）·「撤回审批单」（在途）·「手动上线」（待上线）；四步进度轨「提交发布 → 密钥扫描 → 审批 → 上线托管」（完成 ✓ 蓝实心、当前空心蓝边、未到灰）；说明段 `approvalText`（在途：「在途：{首发/迭代}审批单 · 待审（提交于 …）。同一应用同时至多一个在途审批单，在途期间再次 deploy 会被拒绝。审批人 = owner 所属部门的部门管理员 ∪ 租户管理员，或签。」/ 待上线：「审批已通过，上线终检遇运行环境容量不足（…）→ 应用处于「待上线（资源不足）」态。资源释放后由 owner 手动上线，无需重新审批。」/ 驳回：「上一次发布被驳回。迭代驳回不改变应用已上线态——当前版本继续运行，仅待上线版本被弃。」/ 草稿：「尚未发布。首发与迭代每次发布均需审批，不存在免审路径。」/ 其他：「无在途审批单。每次发布（首发 / 迭代）都生成审批单，走平台预置审批流——部署即生效，管理员无需先配置。」）；驳回时红框「驳回理由全文：{reject}」。
  - 提交发布动作：应用 `inflight=true`，版本表头插「v{n+1} · 首发/迭代 · 待审」，审批单进待办；toast「已提交发布 · 冻结待上线版本快照 → 密钥扫描 → 审批单进入审批中心（与本地 bisheng deploy 等价）」。撤回：在途版本置「已撤回」，审批单移除，toast「审批单已撤回 · 已收到待办的审批人收到站内消息；修改后重新提交将生成新审批单」。手动上线：容量仍不足则 toast 拒绝，否则置 online。
