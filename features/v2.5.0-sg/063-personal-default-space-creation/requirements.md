# 默认个人库创建修复需求

Status: `confirmed`

当前行为: 同一用户的并发请求均查不到默认库, 通过应用层重名检查后分别创建。已有查询无固定顺序。
用户结果样本: 297 个用户拥有 687 个默认库, 每组重复库在 3 秒内创建。样本支持并发判断, 未读取生产请求日志。

- REQ-001 / AC-01: 默认库不存在时, 同租户同用户的并发入口只执行一次创建, 所有成功请求返回同一 ID。使用并发屏障复现并回归。
- REQ-002 / AC-02: 不同用户/租户锁相互隔离; 已有库直接复用; 重复已有库固定按 ID 升序选择。通过隔离及查询测试验证。
- REQ-003 / AC-03: 锁等待有界, 获取失败不允许无锁创建; 长时间创建持续续期; 丢锁/续期失败停止当前创建; 取消和异常释放自有锁, 不释放其他持有者的锁。用 Redis 替身及故障注入验证。
- REQ-004 / AC-04: 门户、文件同步、指定用户入口共用保护, 创建参数和身份恢复保持不变。运行既有个人库及受影响同步测试。

不包含: 数据库唯一绑定/事务重构、既有孤立记录修复、用户名变化规则、收藏库创建规则、存量合并/覆盖/删除。Redis 锁不是数据库唯一约束, 主从切换丢锁或进程暂停等极端情形仍需后续数据库兜底。
