# F118 历史频道目录占位 ID 兼容

用户于2026-11-12确认：历史频道同步中的前端目录占位ID按旧版本bug处理，迁移跳过该场景，由用户在频道配置中重新绑定。本变更基于已合并main的 `feat/3.1.0-beta1`，基线 `efe698d0d4995c166182cb5286f2306bd43d6605`；不操作114/116/109环境。

## 问题与结果

旧目录选择器先显示 `new-folder-时间戳`，保存名称后才请求创建真实文件夹。创建响应返回前直接确认，可将占位值误存进 `channel_knowledge_sync.folder_id`；真实文件夹可能随后已成功创建。旧迁移在构造数字TargetKey时直接失败，导致整个M2无法冻结。

只对完整匹配 `new-folder-[0-9]{1,20}` 的原配置兼容：

- SQL配置和路径原样保留，原payload、配置摘要和业务修订摘要继续覆盖该值。
- M2及M4跳过错误的目录引用；原空间和其他真实引用继续登记及保护删除，不按名称猜ID，不替换成根目录。
- M2 warning记录 `channel_id`、`sync_id`、原 `folder_id` 和 `manual rebind required`，供运维列出用户待处理项。
- 已保存配置可读，错误目录返回 `invalid_legacy` / `is_valid=false`；用户可删除该关联或换成真实目录。
- 对应同步项投递报 `channel_legacy_folder_rebind_required`，在目标加载和上传前拒绝；正常同步项继续经过原完整集合、执行身份、空间及上传权限准入。
- 新建/显式保存配置仍严格拒绝占位ID；其他畸形ID及冻结后配置漂移继续阻断。纯属性修改保留原关联，不新增权限。

原提取协议 `channel-sync-v1` 对正常配置的结果不变；仅已保存快照读取显式启用兼容。此前含此占位值的新M2本来无法成功冻结，既有正常冻结Run仍按完整原摘要重验。无数据库DDL、索引绑定或存储变更。
