此前的 API E2E 绕过编辑器，未经过运行前的变量检查（`isVarInFlow`）；PR #2509 修的就是这里。

- [x] 父工作流中【输出】节点（消息内容）、【大模型】节点（用户提示词）、【代码】节点（入参引用）、【结束】节点（返回结果）各引用一次子工作流的返回结果 `answer`，点「运行」不被拦截，全部运行成功，各处取到的值都是子工作流返回的「会议纪要」。
- [x] 把子工作流的返回结果改名为 `summary` 后重新打开父工作流点「运行」：被拦截，提示「输出节点错误：子工作流/answer已失效」「大模型节点错误：子工作流/answer已失效」，两个节点标红。
- [ ] 同一场景下【代码】节点入参和【结束】节点返回结果也引用了已失效的 `子工作流/answer`，运行前没有被标出。发现于补验，未修。【代码】节点入参不做引用有效性检查是既有行为；【结束】节点返回结果复用同一组件（`CodeInputItem`），继承了这个缺口。若只有这两处引用失效，编辑器会放行，运行时由后端以 10562（缺少返回结果）报错，提示清楚，不会静默得到空值。
  - 已修，待 119 重建后复验：`CodeInputItem` 的「引用」行注册了与其它引用字段相同的运行前检查（`findInvalidRefItems` → `isVarInFlow`），失效时拦截运行、提示「…已失效」、该行标红。【代码】节点部分先修在发版线（3d71c0a94）；【结束】节点返回结果与【子工作流】节点输入参数的接线在本分支。
