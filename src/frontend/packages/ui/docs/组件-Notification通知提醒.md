## 1. 什么时候用

通知提醒是**从页面右上角滑出的一张小卡片**，用来告诉用户「有件事发生了，而且不是你刚才点出来的」：后台任务跑完了、别人把你拉进了一个空间、系统有消息要你跟进。它不挡页面，可以带一两个按钮，停留几秒后自己走，也可以等用户处理。

**用户自己刚做的操作，结果用轻提示；不是用户当下动作引起的事，才用通知提醒。** 这是两者唯一的分界线：

| 这件事是谁引起的 | 用什么 | 例子 |
|---|---|---|
| 用户刚才点的那一下 | 轻提示 Toast | 已保存、链接已复制、删除失败 |
| 后台任务、系统、别的用户 | **通知提醒**（本文） | 知识库解析完成、工作流运行失败、被加入了新空间 |
| 关键失败、必须当场决定 | 弹窗 | 导入中断 12 份文件未入库、登录已过期 |
| 需要对照着修的问题 | 页面内提示条 / 表单项报错 | 名称已存在，请换一个 |

- **同一件事只发一条。** 任务有 10 个步骤，报最终结果，不要每一步都弹一张。
- **会让用户干不下去的错误不要用通知提醒。** 它停几秒就走、也不进历史，错过就找不回来；阻断性的事用弹窗说。
- **不要把它当广播。** 营销、引导、「试试新功能」一律不走通知提醒——用户对它的期待是「有件和我有关的事」，掺一次无关的，以后每一条都会被忽略。

| ✅ 推荐 | ❌ 不推荐 | ❌ 错在哪 |
|---|---|---|
| 知识库「产品手册」解析完成 → 通知 + 「查看」 | 点保存成功 → 通知「已保存」 | 用户自己点的，该用轻提示 |
| 工作流「发票识别」运行失败，3 个节点未执行 → 通知 + 「查看日志」 | 用户自己点删除失败 → 通知「删除失败」 | 同上 |
| 管理员把你加入了「数据组」 → 通知 | 账号已在别处登录，当前会话失效 → 通知 | 用户已经干不下去了，该用弹窗 |

## 2. 类型 Type

四种类型，靠**左上角的图标**区分语义，卡片底色不变（见 §4）：

| 类型 | 什么时候用 | 图标取色 |
|---|---|---|
| **成功 Success** | 后台的事做成了 | 成功色 |
| **失败 Error** | 后台的事没做成 | 危险色 |
| **警告 Warning** | 做成了但有副作用，或需要用户留意 | 警告色 |
| **信息 Info**（默认） | 单纯告知，没有成败之分 | 品牌色 |

- **每种类型必须带图标**，不做无图标的「普通通知」——颜色分不清的用户靠图标读语义，少了图标就只剩一张白卡。
- 拿不准用哪种就用 **Info**。
- 不做「加载中」类型。任务进行中的状态由任务自己的页面展示，通知只报结果。
- 图标与轻提示同一套语义图标；色值取功能色 token，不写裸色值，取色规则见 [基础-色彩规范.mdx](基础-色彩规范.mdx) §3。

## 3. 位置与堆叠

- **固定在页面右上角，距顶部 24px、距右侧 24px**，随页面滚动停在原处。位置不可配置——右上角离主内容和左侧导航都远，弹出不挡事；顶部居中留给轻提示，两者不抢位置。
- **最多同时显示 3 条**，纵向排列、间距 16px，新的一条追加在最下方。
- **第 4 条来时，最上面那条（最旧的）立即消失**，给新的让位。
- **同一条通知重复触发时，更新已有的那条并重新计时，不新增。**
- **盖住弹窗与抽屉**，层级与轻提示同取 `1200`，不单开一档——两者位置不重叠，用不着分先后；四档层级表见 [组件-Modal弹窗.md](组件-Modal弹窗.md) §5。

## 4. 尺寸与样式

| 项 | 规格 |
|---|---|
| 宽度 | **固定 360px**，不随内容伸缩 |
| 高度 | 随内容自适应；最矮（只有一行描述）为 16 + 22 + 16 = 54px |
| 内边距 | 四边 16px |
| 圆角 | 12px（容器档 `xl`） |
| 投影 | `shadow-popup` 浮层投影 |
| 底色 | 页面底色 `bg-page`：浅色模式为白，暗色模式随主题变深 |
| 边框 | 浅色模式无；**暗色模式加 1px 中性描边 `border-base`** |
| 图标 | 16px，左上角，取对应类型的功能色主色，与轻提示同尺寸；与标题（无标题时与描述）首行居中对齐；与文字间距 12px |
| 标题 | `text-body`（14/22），字重 500，主文字色 `text-1` |
| 描述 | `text-body`（14/22），字重 400；有标题时取次要文字色 `text-2`，无标题时取主文字色 `text-1` |
| 标题与描述间距 | 4px |
| 关闭按钮 | 16px 图标，右上角，与标题首行居中对齐；颜色 `text-4`，悬停转 `text-2` |

- **用白底，不用浅语义色底。** 轻提示是浅色底的一句话，通知提醒是白底的一张卡——用户扫一眼就知道「这是我点出来的」还是「有事找我」。
- **宽度固定，内容再少也不收窄。** 卡片宽窄不一，叠在一起像一堆碎片。
- **暗色模式靠描边勾轮廓。** 投影两种模式同一组值（见 [基础-圆角与阴影规范.mdx](基础-圆角与阴影规范.mdx) §2.2），在深底上几乎看不见；描边在浅色下多余，所以只给暗色。底色、文字、图标全走 token，两种模式自动成立。

## 5. 内容形态

卡片从上到下：图标 + 标题 + 关闭按钮 → 描述 → 操作行。标题和操作行都可以没有，描述不能没有。

### 5.1 标题（可选）

- **一句话说发生了什么，不加句号**：「知识库解析完成」「工作流运行失败」。
- **最多显示 1 行**，超出截断加省略号。标题本来就该短，长了说明把描述写进了标题。
- 只有一句话要说时不要硬凑标题，直接写描述。

### 5.2 描述（必填）

正文遵循 [基础-文案规范.md](基础-文案规范.md)，以下是通知自己的细则：

- **用完整的句子，说清「发生了什么」和「用户能做什么」**：「『产品手册』已解析完成，共 128 个分段，可以开始提问了」。
- **长度不做人为限制，但默认最多显示 3 行**；超出的部分截断加省略号，同时操作行左侧自动出现「展开」链接按钮。
- **点「展开」后在原地展开全文**，卡片变高，最高不超过视口高度减 48px，再长的部分在卡片内部滚动。展开后不再收起。
- **展开即视为用户在读，停止自动关闭**，改为等用户手动关闭（见 §6）。
- 只放纯文字，不放富文本、不放图片、不放链接——要跳转，用操作按钮。

| ✅ 推荐 | ❌ 不推荐 | ❌ 错在哪 |
|---|---|---|
| 「产品手册」已解析完成，共 128 个分段，可以开始提问了 | 解析成功 | 没说是什么解析完了、接下来能干什么 |
| 「发票识别」运行失败，3 个节点未执行，请检查输入参数后重试 | 工作流运行失败！ | 没说哪个工作流、怎么办；感叹号在吓人 |
| 管理员将你加入了「数据组」，现在可以访问该组的知识库 | 您已被管理员成功添加至数据组，请注意查收 | 「成功添加」「请注意查收」都是废话 |

### 5.3 操作按钮

- **最多两个**，右对齐放在操作行，与上方文字间距 12px，按钮之间间距 8px；都用 `small`（24px）尺寸（见 [组件-Button按钮.md](组件-Button按钮.md) §3）——卡片只有 360px 宽，medium 的按钮会显得笨重。
- **主动作用次强调（`primary × filled`），次动作用文字按钮（`default × text`）。** 不放实心主按钮——通知不是当前页面的主行动点，不该抢页面的视线。
- **按钮必须是跟进这件事的实际动作**：「查看」「重试」「前往」。**不许是「关闭」「知道了」**——那是关闭按钮的事，白占位置。
- **带操作按钮时停留时长翻倍**（见 §6）。
- **点了操作按钮，通知随即关闭。**
- **不做整张卡片可点击。** 可点的只有按钮和关闭，用户才不会误触。

### 5.4 关闭按钮

- **常驻，每条通知都有。** 它停得久、可能等用户处理，必须随时给用户一个出口——这一点和轻提示相反。
- 规格见 §4。

## 6. 停留与关闭

- **默认停留 5 秒**，从完整出现的那一刻开始算。比轻提示长 2 秒：这里有标题、有描述，读完要多花一点时间。
- **带操作按钮时 10 秒**，留出看见并点中它的时间。
- **不按字数动态延长。** 读不完的交给「展开」（§5.2）——展开后停止计时，改手动关闭。
- **鼠标悬停或键盘焦点落在通知上时暂停计时，移开后从头重新计时**——用户正在读或正要点按钮，这时候消失最挖苦。
- **按 ESC 关闭最新的那一条。**
- **设为不自动关闭（时长为 0）只用于「必须等用户处理」的少数场景。** 拿不准就用默认值——一屏常驻的通知多了，用户只会整片关掉。

## 7. 动效

| 环节 | 规格 |
|---|---|
| 进场 | 从右侧 16px 处滑入并淡入，240ms |
| 出场 | 向右移 16px 并淡出，200ms |
| 其余条目补位 | 240ms |
| 展开全文 | 高度过渡 240ms |
| 缓动曲线 | `cubic-bezier(0.2, 0, 0, 1)` |

卡片比轻提示大、比抽屉小，动效取两者之间：比轻提示慢一档不显慌张，比抽屉快一档不拖沓。从右边来，和它贴着的右边缘方向一致。

## 8. 移动端适配

**v1 不做移动端适配**——后台任务与系统消息都发生在桌面端，移动端暂无通知提醒的场景。

窄屏只做一条兜底：视口宽度不足 408px（360 + 两侧 24）时，卡片宽度收为视口宽度减 32px、左右各留 16px，其余规则不变。等移动端出现真实场景再补，见待决策清单。

## 9. 无障碍

- 通知的容器**常驻在页面里**，内容变化时才播报。
- **成功与信息用 `role="status"`（礼貌播报）**，读完用户当前这句再念。
- **失败与警告用 `role="alert"`（打断播报）**，立刻念。
- **出现时不抢焦点**，用户正在填的表单不能被打断。
- **操作按钮、「展开」和关闭按钮都必须能用 Tab 到达**，焦点落上去时暂停计时（见 §6）。
- 关闭按钮加 `aria-label`「关闭通知」；语义图标和关闭图标都是装饰，加 `aria-hidden`。类型靠播报级别和文案本身传达。

## 10. 落地要求（给实现窗口）

1. 组件形态：命令式 API。`notification.open({ type?, title?, description, actions?, duration?, id?, onClose? })`，快捷方法 `notification.success / error / warning / info(description, options?)`，另有 `notification.close(id)` 与 `notification.closeAll()`。不做 JSX 挂载式用法，理由同 Toast（由事件触发，业务不该为它维护 state）。
2. 容器：单例，`createPortal` 到 `<body>`，常驻 DOM（§9 live region），`position: fixed; top: 24px; right: 24px`。z-index 取层级表 `1200`，与 Toaster 同档——两者都走预设 `z-toast`（`--z-toast: 1200`），Toaster 已不再是 `9999`，无需回填。
3. 队列：上限 3，超出 `shift()` 移除最旧；去重按 `id`，未传 `id` 时以「类型 + 标题 + 描述」作默认 id。队列逻辑已从 Toast 抽成通用 `packages/ui/src/utils/noticeQueue.ts`（`createNoticeQueue`），Toast 与本组件各自实例化。
4. 时长：`duration` 缺省 `5000`，`actions` 非空时缺省 `10000`，`0` 为不自动关闭；展开全文后强制转为 `0`。`mouseenter` / `focusin` 清计时器，`mouseleave` / `focusout` 以完整时长重新起算。
5. 描述截断：`-webkit-line-clamp: 3`；挂载后比较 `scrollHeight > clientHeight` 判断是否溢出，溢出才渲染「展开」按钮。展开后去掉 line-clamp，卡片 `max-height: calc(100vh - 48px)`，描述区 `overflow-y: auto`，滚动条样式见 [基础-滚动条规范.md](基础-滚动条规范.md)。
6. 标题截断：单行 `text-overflow: ellipsis`，右侧为关闭按钮预留 16 + 12 = 28px。
7. 样式 token：`w-[360px] p-4 rounded-xl shadow-popup bg-page`；暗色 `dark:border dark:border-border-base`；标题 `text-body font-medium text-text-1`；描述 `text-body text-text-2`（无标题时 `text-text-1`）；图标 16px 取功能色主色（成功 / 危险 / 警告）与品牌色（信息），类名以 `packages/ui/design-token.cjs` 的 FUNCTIONAL / BRAND 导出为准；关闭按钮 `text-text-4 hover:text-text-2`。禁止裸 hex、禁止 Tailwind 预设投影。
8. 操作行：`flex items-center gap-2 mt-3`；「展开」用 `primary × link` small 放最左并 `mr-auto`；主动作 `primary × filled` small，次动作 `default × text` small（Button 规范 §2.2 / §3）。点击任一 action 后调用其 `onClick` 并关闭。
9. 动效：进场 `translateX(16px) → 0` + opacity，240ms；出场反向 200ms；补位与展开高度过渡 240ms；曲线 `cubic-bezier(0.2, 0, 0, 1)`。进场起始态用读一次布局强制刷新，不用 rAF（Toast 落地踩过后台标签页冻结的坑，见 Toast §11.1）。时长与曲线写成预设的具名值 `duration-240` / `duration-160` / `ease-notice`（`tailwind-preset.cjs`），不写 `duration-[240ms]` 这类任意值——client 同时装了 tailwindcss-animate，它也注册 `duration-*` / `ease-*`，任意值会同时命中两个工具类而被 Tailwind 整条丢弃，动效悄悄退回 150ms 默认曲线（Toast 原先的 `ease-[…]` / `duration-[160ms]` 就是这样失效的，本次一并改掉）。
10. 无障碍按 §9，`role` 按类型放在每条通知的根节点上。
11. 窄屏兜底：`max-width: calc(100vw - 32px)`，`right: 16px`（§8）。
12. 上线前照元规范 §5 清单：`src/frontend/client/rspress.config.ts` 侧栏「组件规范」注册本文入口；建 `docs/components/notification.mdx` demo 页（front matter `component: Notification`）。
