1. 开始前准备

适用范围：使用项目原安装脚本的标准单机 Docker 部署。Docker 是运行项目服务的工具；本机必须已安装并启动 Docker 和 Docker Compose（负责一起启动多个服务）。

请使用包含本次凭据功能的配套后端镜像和部署文件。当前本地脚本与加密回归已验证；客户私有镜像、真实中间件及 MySQL/DM 的完整部署验收仍待执行，尚不能据此宣称生产验收通过。

1.1 打开部署服务器的终端。

完成标志：看到可输入命令的提示符。

如果连接失败，请先恢复服务器登录权限，再继续。

1.2 进入项目根目录。

执行 cd /实际存放毕昇代码的目录，请把示例路径替换为服务器上的真实目录。

完成标志：当前目录下同时有 docker 和 scripts 文件夹；路径不确定时执行 pwd 核对。

1.3 准备本公司批准使用的中间件密码。

准备 MySQL、Redis、MinIO、Elasticsearch 和 Milvus 五项密码；每项建议至少 16 位，包含字母、数字和符号，并按公司的密码制度保管。

完成标志：五项密码均可供下一节输入；若另外配置了统计 Elasticsearch，还需准备它的密码。

如果尚未取得密码，请先向本公司密码负责人领取；不要使用组件出厂密码。

2. 首次部署：执行命令，按提示输入

本节适用于没有历史中间件数据的新环境。无需事先创建密钥文件或手动生成加密配置。

2.1 执行原来的部署命令。

bash docker/install.sh

完成标志：镜像准备后出现“首次部署，将引导设置本公司的密码”。

如果出现“检测到旧部署”，请转到第 4 节；如果下载失败，请按第 5 节处理后重试原命令。

2.2 在每个“请输入…密码”提示后输入该组件的密码。

按回车提交；屏幕不会显示字符或星号，这是正常现象。

完成标志：出现“请再次输入确认”。

2.3 在确认提示后再次输入同一个密码。

按回车提交；脚本将依次询问 MySQL、Redis、MinIO、Elasticsearch、Milvus，已配置的统计 Elasticsearch 也会单独询问。

完成标志：出现下一项密码提示，最后一项通过后开始准备配置。

如果提示两次输入不一致或密码不符合要求，请在当前提示下重新输入这一项，无需退出重来。

脚本自动完成：在部署目录内建立私有外置密钥，生成加密业务配置及组件所需文件，保存路径，检查权限，启动中间件并验证新连接，最后启动后端和页面。.env 保存部署参数及生成文件的位置；后端加载的是生成后的 config.yaml，两者不是同一个文件。

2.4 等待脚本显示“已执行启动”。

完成标志：命令结束并返回终端提示符。

如果显示“部署停止”，请按第 5 节处理；不要删除数据或生成替代密钥。

2.5 查看服务状态。

docker compose --env-file docker/.env -f docker/docker-compose.yml ps

完成标志：常驻服务正常运行，定义了健康检查的服务显示 healthy；初始化服务成功退出属于正常情况。

如果持续重启或 unhealthy，请保留现场并提交脱敏错误，容器运行状态不能替代下一步业务验证。

2.6 在浏览器打开平台。

访问 http://服务器IP:3001，把“服务器IP”替换为部署服务器地址；使用了自定义入口时打开公司配置的地址。

完成标志：平台页面可以打开。

2.7 按现有交付流程验证业务。

逐项验证用户登录、知识上传与检索、工作流任务；启用组织同步、沙箱或 Gateway 的部署，还需逐项验证这些功能。

完成标志：全部启用功能符合公司验收要求；首次部署的注册用户和模型配置继续按原流程完成。

3. 再次部署：仍执行同一条命令

3.1 执行原来的部署命令。

bash docker/install.sh

完成标志：显示“检测到已有部署配置，将复用现有密码和密钥”；无需再次输入五项密码。

如果要求恢复密钥或配置包，请提供当前部署匹配的备份，不要当作新装。

3.2 按第 2.5～2.7 步验证本次部署。

完成标志：服务与业务验证均通过；原数据和密码继续可用。

重复部署不会自动修改中间件账号密码。只修改基础模板或自动化输入文件，不会覆盖已经保存的现用配置；更换真实账号密码属于单独维护变更，见附录。

4. 旧版本升级：在原命令中引导迁移

仅外置密钥不会消除旧弱密码或自动打开组件认证。本流程保留中间件现用密码和认证状态，先迁移密文；待治理项仍需安排账号改密维护。

4.1 按公司现有恢复制度完成升级前备份。

备份数据库、原业务配置、原容器环境快照和旧密钥；备份必须存入受限备份系统。

完成标志：升级工单中记录了备份位置与可用的恢复点；无法确认备份可恢复时请暂停升级。

4.2 执行原来的部署命令。

bash docker/install.sh

完成标志：脚本识别到已有中间件数据，并显示迁移及维护窗口说明。

4.3 在确认其他节点已停止写入后输入 yes。

只有全部部署节点、任务处理进程和外部写入已按维护计划停写时，才确认维护提示；脚本只能暂停本机标准名称的应用容器。

完成标志：脚本自动读取现用配置及旧密钥，准备过渡密钥并执行迁移。

如果条件尚未满足，请取消本次输入；不要确认后继续让其他节点写入。

4.4 在出现恢复提示时提供指定备份的完整路径。

仅当脚本无法从原容器自动读取时，才需要按提示提供配置、环境快照或旧密钥 JSON 备份文件。

完成标志：备份通过检查，迁移继续；密码和密钥内容不会显示在终端。

如果没有匹配备份，请保留旧容器、数据库和部署目录，由交付负责人处理；新密钥无法解开旧密文。

4.5 等待密文迁移及应用启动结束。

完成标志：显示“密钥外置迁移与应用启动已执行”；原生中间件没有被重新初始化或自动改密。

如果迁移中断，业务会保持停止；修正提示原因后重新执行原命令，脚本会读取保存的计划继续，不重新开始改密。

4.6 按第 2.5～2.7 步验证升级结果。

完成标志：组织同步、沙箱及其他启用业务均使用现有身份成功运行，之后由维护负责人统一恢复其他节点写入。

6. 部署后的备份

加密不增加日常部署命令，但密钥必须进入公司现有备份制度；只备份数据库不足以恢复加密配置。

6.1 将凭据文件纳入现有受限备份任务。

默认包括 docker/.env、docker/.generated/credential-security 及公司指定的外部凭据文件；若使用了外部备份路径，也要覆盖该路径。

完成标志：备份系统已覆盖现用密钥、匹配配置和迁移备份，访问权限限指定维护人员。

6.2 在隔离恢复环境验证备份。

使用同一恢复点的数据库、配置和密钥完成恢复，不在生产环境试删文件。

完成标志：可以解密配置并完成公司规定的业务恢复验证，工单留有恢复记录。

7. 附录：只在需要时查看

7.1 原有 Gateway 参数

Gateway 是商业版网关，参数与原部署方式相同。

bash docker/install.sh --gateway \
  --license-file /实际路径/license.txt \
  --public-url http://服务器IP:3001

完成标志：授权及网关业务验证通过；首次所需中间件密码仍在同一安装过程输入。

7.2 只准备部署参数，不启动服务
bash docker/install.sh --prepare-only

首次只复制部署参数并校验 Compose 结构，不要求密码、本地工具镜像或联网；它不代表真实连接检查已通过。存在完整凭据的环境会校验并保存现用路径，但仍不拉取、不启动服务。

7.3 自动化平台无人值守

仅在无法使用交互终端的自动化部署中，按公司秘密管理方式准备密码文件及输入清单，在 .env 的 BISHENG_CREDENTIAL_INPUTS_FILE 填写清单绝对路径。随后仍执行原安装命令；不要把密码本身放入命令参数。

清单格式由工具 credential_inputs.py 定义，密码文件须与清单位于同一个受限目录内。旧部署自动迁移还须由维护流程显式设置 BISHENG_ALLOW_CREDENTIAL_MIGRATION=yes，仅可在已经完成停写的维护作业中使用。

7.4 实际改密、密钥轮换和特殊部署

重新部署不会自动修改已有账号密码。真实改密须由组件管理员执行，并同时更新全部消费者、验证新连接和准备回退；底层 docker/credentials.sh 与 scripts/rewrap_credentials.py 是维护工具，不是正常部署的必做步骤。

外部 MySQL/DM、Redis Sentinel/集群、定制 ACL、ES TLS、多节点、源码/systemd 与 Helm 部署由交付负责人使用配套设计和专项维护流程。标准单机安装不能代替这些部署的配置与验收。

如果迁移后需回退旧版本，不能只回退镜像；应由交付负责人按同一恢复点恢复数据库、配置及密钥，并核对维护期新增数据和在途任务。

文件说明：config.yaml 是后端业务配置；.env 是安装参数；外置密钥文件用于解密密码，必须与匹配配置一同保留。密钥不写入源码，组件读取的原生凭据文件按受限秘密文件管理。
