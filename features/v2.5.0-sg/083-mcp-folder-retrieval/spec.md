# F083：MCP 文件夹正文片段检索规格

- Feature ID: `083-mcp-folder-retrieval`
- Status: `IMPLEMENTED_LOCAL`
- Version: `v2.5.0-sg`
- Created: `2026-10-26`
- 关联需求来源（关联 PRD）：[已确认的发现范围](spec-discovery.md)，无独立 PRD。
- 需求追溯：[requirements.md](requirements.md)；实现设计：[design.md](design.md)；规格评审：[spec-review.md](spec-review.md)。

## 1. 概述与用户故事

作为通过可信业务后端调用 MCP 的用户，我希望针对指定知识空间内的一个文件夹检索正文片段，默认覆盖子目录，并可以只检索当前层，以便缩小内容检索范围。

新增只读工具 `retrieve_folder_chunks`，保留原十个工具及其契约。继续使用目标 `external_id` 的用户、当前租户和业务权限；不生成模型答案，不授予额外资源权限，不产生业务写入。新增工具后共十一个工具。

## 2. 验收标准

| ID | 角色 | 操作 | 预期结果 |
|---|---|---|---|
| AC-01 | 接入方 | 列工具，调用新工具；传缺失、未知或非法类型参数 | 十一个工具可发现；新工具具备严格 schema，非法参数不进入范围查询或检索；原十工具参数和返回保持兼容 |
| AC-02 | 业务用户 | 对一个目录默认检索，再传 `recursive=false` | 默认包含直接文件和全部子目录中的文件；false 仅包含直接文件；兄弟目录、相似 ID 前缀及空间外文件不进入范围 |
| AC-03 | 业务用户 | 检索超过单批的目录、合法空目录、全部无权文件目录，或超出容量预算的目录 | 不漏掉后续批次；完整有权范围为空时返回空成功且不执行无范围召回；超过 1000 个成功候选文件时返回明确工具错误，不能截断或扩大范围 |
| AC-04 | 业务用户 | 使用目标账号调用；指定无权、不存在、跨空间、跨目标租户或已删除目录；目录内包含自定义权限文件 | 账号/租户沿用 F081；空间和目录不合法则拒绝；后代文件独立按现有权限判断，不借用 Token 用户或目录权限；权限设施异常为工具错误 |
| AC-05 | 业务用户 | 设置标签条件；召回 canonical 文档，其目录内入口无权或目录外入口有权 | 标签和目录范围取交集后进入召回；返回的入口必须在显式文件集合内，不回退目录外入口；当前版本、内容代次与现有最终授权规则保持 |
| AC-06 | 接入方 | 获取命中、无命中结果，或遇到总超时/范围解析/检索失败 | 返回原 `{chunks,total}`；无命中为空成功；主链路失败 `isError=true`；来源链接超时保持已授权片段和空链接的原语义，不将主链路错误伪装成空结果 |
| AC-07 | 既有接入方 | 阅读使用文档并复跑旧 MCP、REST 检索、身份及权限相关回归 | 文档提供参数、递归/当前层/标签示例及上限说明；旧接口及 Token/CORS/身份规则保持，无配置、依赖、Schema 或业务数据变化 |

每条 AC 的验证方式、分组与计划落点见 requirements。完整规格已获用户确认；本地实现和 400 项相关测试通过，实际设施与部署边界见 [verification.md](verification.md)。

## 3. 工具与参数契约

### 3.1 协议入口

| Method | Path / Tool | 请求与鉴权 | 响应 |
|---|---|---|---|
| POST | `/mcp`、`/mcp/`；`tools/call` 的 `name=retrieve_folder_chunks` | 既有 `X-Developer-Token` 校验；工具调用必填目标账号 | MCP 原生 `CallToolResult`，结构化业务结果为 `RetrieveResp` |

不增加 REST endpoint，不改 Filelib 对外请求 schema，不使用 REST 成功响应包装。初始化和工具发现继续只需有效 Token；目标账号在实际调用时解析。

### 3.2 输入

| 字段 | 类型 | 默认值 | 约束 |
|---|---|---|---|
| `external_id` | string | 必填 | 复用 `ExternalAccount`：严格字符串，首尾去空白后 1～255 字符，保留大小写和前导零 |
| `query` | string | 必填 | 首尾去空白后 1～2000 字符 |
| `knowledge_id` | integer | 必填 | 严格正整数；仅知识空间 |
| `folder_id` | integer / string | 必填 | 正整数或 ASCII 正数字符串，如 `305`、`"305"`、`"000305"`；归一化为整数；不能为 null、0、布尔、空白、小数或带符号字符串 |
| `recursive` | boolean | `true` | 严格布尔，false 只检索直接包含的文件 |
| `top_k` | integer | `5` | 严格整数，1～50；为最终返回片段数量上限，不是必定返回的数量 |
| `max_content` | integer | `15000` | 严格整数，1～15000；沿用现有检索字符预算语义 |
| `filters` | object / null | `null` | 复用现有标签结构；只可引用本次 knowledge_id，最多一项；tag_match_mode 仅支持 ANY |

`filters.knowledge_base_filters` 为 `[{knowledge_base_id, tags, tag_match_mode}]`。空列表或 tags 为空表示无额外标签限制。指定其他空间、重复项、ALL 或未知字段均拒绝，不允许客户端传入 file_ids、canonical ID、存储过滤表达式或身份覆盖字段。旧工具的过滤兼容行为不随此新契约改变。

folder_id 必填，不提供根目录替代值；检索整空间仍使用原 retrieve_chunks。

### 3.3 请求示例

默认递归：

```json
{"name":"retrieve_folder_chunks","arguments":{"external_id":"00012345","query":"检修前需要完成哪些检查？","knowledge_id":118,"folder_id":"305","top_k":5}}
```

仅当前层，并与标签取交集：

```json
{"name":"retrieve_folder_chunks","arguments":{"external_id":"00012345","query":"检修前需要完成哪些检查？","knowledge_id":118,"folder_id":305,"recursive":false,"filters":{"knowledge_base_filters":[{"knowledge_base_id":118,"tags":["操作规程"],"tag_match_mode":"ANY"}]}}}
```

### 3.4 响应示例

下例为工具结构化业务结果，外层仍由 SDK 生成 CallToolResult：

```json
{"chunks":[{"content":"检修前确认设备停机并完成能源隔离。","knowledge_id":118,"document_id":901,"document_name":"操作规程.txt","chunk_index":0,"source_url":"","source_full_url":""}],"total":1}
```

`document_id` 为指定目录范围内的授权入口，可继续用于 get_file_detail；不得回显原始索引元数据、无权文件 ID、路径或 canonical 内部事实。total 只是本次片段数。合法空范围或无内容命中返回 `{"chunks":[],"total":0}`，不是目录文件数或全量命中数。

## 4. 范围、权限与预算

1. 使用 F081 的目标身份和每调用上下文；原 Token 归属有效性、IP、路由、限流仍保留。可信业务后端负责从已认证会话提供账号，新工具不证明账号字符串属于调用者。
2. 先通过现有知识领域服务校验空间、目录及其归属和 `view_folder`，再分批获取所选路径内的成功文件候选（file_type=1、status=2、未删除且满足现有活跃库存规则）。逐文件沿用 `visible` 及最终检索授权；目录可读不授予 view_file，子目录也不因递归新增授权。
3. 文件范围在召回前传入现有共享检索；标签与文件 ID 取交集。空集合与未传范围严格区分，任何空交集直接返回空成功，不能转换为整库范围。
4. canonical 命中回映射使用严格显式入口范围；目录内入口不合格或无权时不能选择目录外的同文档入口。现有 canonical 当前主版本、内容代次、撤销/失效入口及最终权限检查保持，不新增投影就绪放行规则或旧索引回退。
5. 单次最多解析 **1000 个成功候选文件**，在逐文件权限和标签过滤前计数，包括递归子目录；只有成功候选计入，文件夹、未完成/失败/违规文件不计入。该值是本次已确认的实现预算，不能从 top_k 推导目录截断。
6. 达到 1000 时继续探测是否还有候选；恰好 1000 可继续，出现第 1001 个则整次拒绝，提示缩小目录范围或关闭递归，不返回部分结果或原始候选总数。任何后续底层数据库/检索参数限制仍按真实失败处理，不能宣称 1000 文件一定可在时限内成功。
7. 沿用只读 MCP **30 秒总超时**，包含身份、会话/服务装配、目录范围解析、检索和来源处理；不新增运行配置、自动重试或超时后台继续执行。超过时间或取消时释放会话并恢复上下文，结果不伪装成功。
8. 本功能基于调用内枚举得到的目录范围与现有实时授权，不提供 SQL、OpenFGA 和检索系统之间的原子快照。调用期间移动目录/文件或变更 ACL 的强一致实时语义不在范围内；下一次调用重新解析，最终授权仍执行。

## 5. 失败契约

| 边界 | 既有错误码 / 类型 | 客户端行为 | AC |
|---|---|---|---|
| Token 缺失、无效或禁用 | 19801/19802/19803 | HTTP 401，不进入工具 | AC-04、AC-07 |
| IP/非空路由不符；限流或限流不可用 | 19804/19812；19805/19806 | HTTP 403/429/503，原行为不变 | AC-04、AC-07 |
| 参数/过滤不合法 | SDK 参数校验 | 参数拒绝，不进入范围服务 | AC-01、AC-05 |
| 目标账号或当前租户不可用 | 既有 UnAuthorizedError（历史码 403） | isError=true，固定“指定账号或当前租户不可用” | AC-04 |
| 空间/目录无权、归属不符或不可用 | 既有 SpacePermissionDeniedError（18040） | isError=true，沿用安全资源错误，不暴露存在性细节 | AC-04 |
| 成功候选范围超过 1000 | 新增 McpFolderRetrievalScopeLimitError（18007） | isError=true，固定提示“目录检索范围过大，请选择更小的目录或设置 recursive=false”；无文件明细 | AC-03、AC-06 |
| 数据库、权限或主检索链路异常 | 原异常/既有领域错误及共享存储错误 | 安全工具错误，不当作空目录，不更换范围或身份 | AC-04、AC-06 |
| 30 秒超时、客户端取消 | 既有超时映射 / 取消 | 超时为工具错误，取消保留取消语义；会话/上下文清理 | AC-06 |
| 仅来源链接处理超时 | 原来源服务超时处理 | 已授权片段可返回，来源字段为空；其他异常按现有规则传播 | AC-06 |

范围预算错误在既有 knowledge_space 模块分配 18007，继承 BaseErrorCode；已检查该模块定义中未占用此码。不新增错误模块，不复用其他语义的错误码。MCP 仅将这个错误映射为固定安全提示，不透传任意异常文本，也不向客户端增加 REST 错误包装。

## 6. 架构决策与数据归属

| ID | 决策 | 理由 |
|---|---|---|
| AD-01 | 新增独立工具而非扩展旧工具的对外参数 | 符合新增工具诉求，保留既有客户端契约 |
| AD-02 | knowledge 领域解析目录范围，MCP 仅做装配 | 复用目录归属、细粒度权限和活跃入口规则；不在 API 编写 ORM 或索引表达式 |
| AD-03 | 共享服务增加仅内部可用的文件范围参数 | REST 请求模型不开放 file_ids；避免复制检索和来源链接逻辑 |
| AD-04 | 新工具显式启用严格入口范围 | 现有回映射的默认优先策略不足以保证不回退目录外入口；沿用 resolver 已有 strict_explicit 能力，默认行为不改 |
| AD-05 | 分批完整枚举，1000 候选和 30 秒双预算 | 控制内存、SQL 参数和权限请求规模，超过预算明确拒绝，避免静默漏检 |

Knowledge/KnowledgeFile/KnowledgeDocument/版本及 PermissionTuple 的 Owner 不变；无新表、字段、迁移、索引、依赖或运行配置。继承双版本契约的自动租户过滤、存储隔离、统一权限及 canonical 去重不变量；不直接查询 role_access 或自行拼接向量/ES 过滤表达式。

## 7. 范围与兼容、回退

包含新工具、知识领域目录范围解析、共享检索内部透传/严格回映射、测试和 MCP 使用文档。明确不包含多目录/跨空间查询、按名称找目录、LLM 答案生成、REST 新参数、原工具重构、权限模型变化、数据迁移或真实环境部署。

旧客户端继续使用原工具，新工具需刷新工具清单。新增内部参数默认省略，不能改变旧检索的空范围、排序、过滤或映射策略。可回退新工具和内部适配代码，无新增业务数据需要回滚。审计继续区分 Token 与实际用户/租户，不打印账号、问题、候选列表、正文或签名地址。

完整规格已确认并完成 tasks、测试先行实现、相关回归及受控 SDK 端到端验证；真实 MySQL/DM8、FGA、MinIO、Milvus/ES 和部署环境验证单独记录在 verification.md。
