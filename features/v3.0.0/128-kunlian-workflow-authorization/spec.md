## 1. 目标与范围

昆联后端代表当前实际用户查看、授予或撤销毕昇 Workflow 权限。毕昇负责判断当前用户能否执行对应动作，保存授权事实，并为后续访问提供权威判定。首轮使用同一租户下的工作流管理者 A、被授权用户 B 和越权样例，验证授权生效、撤权收敛及失败结果。

授权清单与当前有效权限分开验证。首轮新增或撤销的授权以同租户自然人为主，使用毕昇现有可授予模型。测试可预置用户组授权，用来验证直接撤权后仍有独立有效来源的情形。用户组作为昆联授权请求的目标需先确认映射。所有者转移、权限镜像及增量同步、昆联资源撤权与停用入站、额外创建配额和已受理运行的取消策略分别进入后续工作包。

## 2. 用户故事

- 作为 Workflow 管理者，我希望从昆联查看并调整当前工作流的直接授权，以便让同租户的用户获得所需权限，并按需撤销。
- 作为获授权的用户，我希望知道自己当前能查看或执行哪些动作，以便在权限发生变化后继续按毕昇的最新判定操作。
- 作为昆联调用方，我希望区分已生效、修订冲突和结果未确认，以便在重复请求或响应丢失后准确反馈操作结果。

## 3. 业务需求

| ID | 需求 |
| --- | --- |
| REQ-01 | **实际操作者与租户。** 每次请求均按受信接入方、实际用户、当前租户和目标 Workflow 核验。查看授权清单、授予及撤销要求当前具备授权管理权限。目标主体须是该租户内有资格的用户，操作者只能授予本人有权管理的权限。 |
| REQ-02 | **直接授权与有效权限。** 有权管理者可查询该 Workflow 的直接授权。当前用户可查询自己的有效动作，包括经其他独立来源取得的动作，结果以毕昇当前判定为准。仅具备查看 Workflow 权限的用户不因此取得授权清单或管理权。 |
| REQ-03 | **授予和撤销。** 成功授予后，目标用户的新请求按当前有效授权得到对应动作，其他动作仍分别校验。撤销只移除本次指明的直接授权。撤掉最后一个有效来源后，旧链接、缓存清单和直接请求均不能延续原权限；仍有独立授权时继续按其有效范围裁决。 |
| REQ-04 | **修订与重试。** 变更须基于当前权限修订。同一有效请求的重试只生效一次，原响应丢失后可查回已确认的处理结果。同一重试标识对应不同内容，或新的变更基于过期修订时，应明确拒绝。变更结果与当前权限查询须分别反映各自语义。 |
| REQ-05 | **拒绝与结果未知。** 操作者、目标、租户或权限无法确认时，拒绝相应访问或变更。权限变更尚未确认生效时，调用方可识别其未确认状态。错误与审计只提供定位所需的范围、操作和结果，不包含凭据或未获授权的授权明细。 |
| REQ-06 | **权威与兼容。** 毕昇现有授权体系继续决定权限结果，昆联获得的展示信息或旧回执不构成新的访问许可。毕昇原有授权入口和 Workflow 操作继续使用同一权限判定，首轮通过隔离 Mock 验证，正式契约及真实环境独立验收。 |

## 4. 验收标准

| ID | Requirements | 可观察结果 | Verification |
| --- | --- | --- | --- |
| AC-01 | REQ-01、REQ-02 | **当** A 具备授权管理权限并查看同租户 Workflow 的授权，**系统应** 返回该对象的直接授权及当前权限修订。仅有 Workflow 查看权限的 B 能查询自己的查看动作，查询授权清单时被拒绝。 | V-01、V-02 |
| AC-02 | REQ-01、REQ-03、REQ-06 | **当** A 授予 B 一个包含查看权限的可授予模型，**系统应** 确认授权后允许 B 从现有列表和详情访问该 Workflow。B 尝试未被授予的编辑、执行或权限管理动作时，应按各自权限拒绝。 | V-02、V-04 |
| AC-03 | REQ-02、REQ-03、REQ-06 | **当** A 撤销 B 的直接授权，**系统应** 从直接授权清单移除该条记录。若该条是 B 唯一有效来源，B 的下一次相关请求应被拒绝；若 B 仍通过已有用户组获得查看权限，B 仍可查看。验证其他主体的授权保持原值。 | V-02、V-03、V-04 |
| AC-04 | REQ-01、REQ-05 | **如果** 接入方或实际用户无法核验，操作者已撤权或停用，Workflow 或目标用户跨租户，或请求的权限超出可授予范围，**系统应** 拒绝该请求，不泄露受保护的授权明细，原授权保持原值。 | V-01、V-02、V-04 |
| AC-05 | REQ-04、REQ-05 | **当** 授予或撤销已生效但响应丢失，且实际操作者仍有权按原请求重试时，**系统应** 查回同一已确认结果，授权事实只变更一次。相同重试标识被用于不同内容，或新的请求使用过期修订时，应拒绝本次变更并保留当前状态。 | V-01、V-03 |
| AC-06 | REQ-04、REQ-05 | **如果** 两次不同的变更基于同一权限修订并发提交，**系统应** 至多接受一次并让冲突方能重新查询。权限判定不可用或授权生效尚未确认时，应给出相应的拒绝或未确认状态。审计可关联工作流、操作与结果，且不含凭据。 | V-01、V-03 |
| AC-07 | REQ-02、REQ-03、REQ-06 | **当** 管理者通过毕昇现有入口变更 Workflow 授权，**系统应** 让昆联后续的授权查询反映毕昇当前结果。重试早先已确认的操作时可以查回原结果，但后续访问仍按当前有效授权判断。 | V-02、V-04 |

| ID | 验证方式 | 当前状态 |
| --- | --- | --- |
| V-01 | 隔离 Mock 验证可信操作者、授权边界、同请求重试、修订冲突及权限不可确认。 | `PASS`，隔离 Mock |
| V-02 | 隔离端到端验证「A 查看 → 授予 B → B 访问 → A 撤销 → B 再访问」，对照直接授权、有效动作及现有 Workflow 入口行为。 | `PASS`，隔离 Mock |
| V-03 | 受控权限与存储环境验证并发变更、结果未知后的查回及已确认撤权的访问阻断。 | `NOT_RUN`，待环境 |
| V-04 | 双方联调验证实际用户委托、同租户授权、撤权和越权拒绝。 | `NOT_RUN`，待契约及测试环境 |
