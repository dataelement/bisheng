## 1. 判断

切换租户本身合理；问题是当前“部分查询改变范围、部分创建和执行仍沿用账号主属”的混合语义。推荐继续采用真实账号不变、租户业务统一采用经验证的操作目标、身份/平台/独立凭据入口明确例外的规则。

但统一入口只解决范围准入，不会自动修复下游显式读取 `LoginUser.tenant_id`、按创建者构建执行身份、批量写入、异步恢复及非 HTTP 通道。**所有路由有声明，不等于所有功能已隔离；零新增表，也不等于改动小或历史无影响。**

可在现有架构内渐进落地，不需要更换登录令牌、复制账号、新建身份系统或操作中心。应收窄第一批机制变化，再以业务链验证决定是否完成，不能承诺只修改中间件即可修复全平台。

## 2. 必须补齐的遗漏

### 2.1 创建者还是执行依据，不能只处理姓名和授权展示

源码调用链：

1. [工作流任务](../../src/backend/bisheng/worker/workflow/tasks.py#L63) 将 `Flow.user_id` 传为 `flow_user_id`，资源租户单独取自流程。
2. [知识节点](../../src/backend/bisheng/workflow/common/knowledge.py#L463) 在知识权限开关关闭时采用创建者，开启时采用实际运行人。
3. [身份构建](../../src/backend/bisheng/knowledge/domain/services/space_flow_retrieval.py#L38) 把流程租户传入创建者登录身份。
4. [用户身份服务](../../src/backend/bisheng/user/domain/services/auth.py#L552) 将该值当作预期主属租户；[角色策略](../../src/backend/bisheng/role/application/effective_roles.py#L54) 在与真实主属不符时拒绝。

因此，Root 超管在 A 创建流程后，A 普通获权用户运行该流程，在对应知识节点配置下存在 `24006` 拒绝路径。相同身份构建函数还有助手及工具调用方，需要沿实际调用者核对。**这是静态调用链确认，未在现场复现；实际触发依赖节点配置和数据。**

最小修正应保留真实创建者，分别表达执行身份的真实主属与资源执行目标，并通过既有权限端口校验目标和动作。不能伪造创建者主属、关闭角色校验，或统一改用运行人而改变知识权限开关语义。创建者被撤销超管、停用或迁出后的行为也必须明确，不能仅凭历史创建者记录继续跨租户执行。

新增验收：**A 普通用户执行超管在 A 创建的流程**；分别覆盖知识权限开关开/关、助手/工具等共享消费者、创建者资格变化。只检查创建成功和名称展示不够。

### 2.2 写入约束不完整，全局收紧也可能伤及合法路径

[数据库隔离钩子](../../src/backend/bisheng/core/database/tenant_filter.py#L230) 当前过滤 SELECT，`before_flush` 只检查 `session.new`。把新增对象的错租户警告改为拒绝，无法覆盖已有对象修改、批量 UPDATE/DELETE 及原始 SQL。例如[标注任务更新](../../src/backend/bisheng/database/models/mark_task.py#L108) 的语句按 ID 更新；其上游是否已有充分校验仍需逐链验证，不能仅凭此语句认定已经发生越权。

首批应在实际仓储写入口验证父资源及目标，并给更新/删除语句加必要范围约束。Root 共享定义、部门存储归属和后台投影等合法跨范围路径先单独核对，暂不直接全局收紧钩子，也不扩建通用 SQL 安全框架。

管理准入的权威主属应由用户领域的唯一事实来源提供。现有管理仓储自行查询活跃 `UserTenant`，角色策略另有主部门业务归属一致性校验；不能再复制一套近似规则，导致准入成功后身份计算失败。

### 2.3 异步目标不能只靠浏览器请求或消息头

[Celery 上下文](../../src/backend/bisheng/worker/tenant_context.py#L81) 发布时从当前 ContextVar 写租户头；普通任务缺少头时会回退 Root。权限及复制任务已有更严格检查，不能把现状描述成所有任务均有同一保护。

应按工作流、复制、导出、回调等逐类列出：提交入口、已有持久字段、消息参数、执行/重试入口、缺失目标及冲突处理。明确持久目标与头不一致时的拒绝规则，且在首次租户查询前完成恢复。已有任务记录足够则复用；只有缺少必要持久事实时才补最小字段，不能预先保证零字段。

旧队列不能一律清空、重投或按最新 Redis 选择执行。有可靠资源/任务事实的按事实恢复；无法证明目标的租户任务隔离待处理；真正平台级 Beat 任务保留平台语义，不能将所有缺头任务统一禁用。

### 2.4 Redis 格式、切换部分失败及页面自举需形成具体契约

当前[选择服务](../../src/backend/bisheng/admin/domain/services/tenant_scope.py#L34) 只识别正整数及十进制字符串；[清理任务](../../src/backend/bisheng/worker/admin_scope/tasks.py#L69) 使用 `int(raw)`。若改成包含目标及视图标识的 JSON，旧服务会视为无选择，旧清理任务在存在停用租户并进入扫描时会将该值当作损坏数据删除。

方案已提醒解析者兼容，但还需要点名这些消费者及发布顺序。**建议最小批次保留整数 Redis 值和现有 `X-Management-Tenant`，暂缓新增每次切换的视图标识。** 这仍需请求目标核验、准入后固定范围、前端切换清理及旧响应丢弃，不能保留过期后静默回 Root。

暂缓视图标识意味着首批不保证拒绝 A→B→A 后的同租户旧表单，必须同步调整原稿对应验收；资源自身版本校验仍保留。若该保证是本批硬要求，则视图标识和全部解析/清理兼容必须一起交付，不能只上线一端。

当前切换先写 Redis、再写 SQL 审计。审计失败或响应丢失时，服务端可能已经切换，前端却收到失败。需要定义提交点、失败后的重新读取及重试规则；不要求新增分布式事务，但不能假定“接口报错即未切换”。

前端现有初始化会较早请求工作台配置。强制所有租户业务带目标前，必须设置统一的范围就绪状态，延后业务请求；本人资料及范围自举不能反过来依赖已选定的业务范围。旧静态页面与新后端的兼容也应纳入发布，而非仅测试手工切换后刷新。

### 2.5 WebSocket、流式响应和直接下载不能遗漏

[工作流 WebSocket](../../src/backend/bisheng/api/v1/workflow.py#L380) 是独立入口，不能由 HTTP 路由机制自然覆盖。流式响应也需验证上下文生命周期：若在处理函数返回时立即清理上下文，后续流生成阶段可能已失去范围。此处是待实现机制必须验证的风险，不能当作已复现的现网故障。

优先复用现有资源/任务归属与既有鉴权能力；确有需要才增加用途受限的短期票据，不另建通用票据平台。原生连接建立、重连、断开、流消费结束和直接下载均应测试。若宣称工作流完整闭环，这些通道不能留作无说明的后续事项。

## 3. 最小落地范围建议

### 第一批必须做

- **统一范围准入及路由策略来源。** 租户业务默认继承，身份/平台/凭据入口明确例外；实际路由生成覆盖清单，避免继续维护 URL 白名单。保留现有真实身份、ContextVar、Redis 选择和统一权限服务。
- **沿实际业务链修目标错位。** 已复现的访客链接配置、工作台配置/个人角色混用、错误响应导致整页 404，以及创建、初始版本、授权、执行中的显式错目标都纳入。前端整页跳转修正只能消除错误表现，不能替代后端归属修正。
- **补创建者执行身份、必要写入口和异步恢复。** 以资源目标为准校验范围，再经既有动作权限；超管放行不能跳过目标验证。保留知识权限开关语义，保留现有资源配额超管例外及普通用户规则。
- **完成初始化及切换一致性。** 使用既有目标头核验，固定单次请求范围，清理/区分旧缓存和旧响应；失效明确拒绝。覆盖两套前端中实际参与浏览器选择的调用方，并逐入口验证网关转发契约，独立凭据不继承浏览器选择。
- **以链路覆盖决定完成。** 每个实际后台菜单核对查询、候选、详情、创建、保存、删除、附属配置、分页、导出和执行。先完成存量分类及必要修复，再开启全入口强制门禁；过渡期明确标为尚未完整闭合。

### 建议暂缓或保持现状

| 原稿事项 | 最小范围建议 | 代价或前提 |
| --- | --- | --- |
| 新视图标识及 Redis 值格式变化 | 暂缓，先复用已有目标值 | 首批不承诺 A→B→A 同租户旧表单失效 |
| 新的受信管理调试入口及完整计量改造 | 与缺陷修复拆开；保持既有已支持通道并修身份/目标混用，未支持通道明确拒绝 | 不能宣称所有调试功能已可用；若用户要求全可用，应计入本批明确工作量 |
| 全局错租户写入警告立即改拒绝 | 暂缓全局开关，先修具体写入口 | 仍需逐模块验证写入完整性，不能据此宣称全局写入已受保护 |
| 普通人员姓名和授权列表重写 | 保留已正确的按用户 ID 展示及资源授权查询 | 只修把候选/当前有效人员筛选误用于历史记录的路径 |
| 会话独立选择、账号复制、新业务表、新操作中心 | 不做 | 保留一个账号一个选择的现有产品语义 |
| 角色规则、积分计费、资源配额政策重设计 | 不做 | 如需变化单列决策，不借统一范围改变规则 |

这是一条降低机制变化的实施路线，并非将未修模块排除后仍称“整个平台已完成”。若验收要求所有租户功能切换后均可操作，全量入口盘点及各业务链修复不可省略。

## 4. 现有功能及历史数据影响

| 对象 | 应保留的行为 | 可能影响及处理 |
| --- | --- | --- |
| 单租户、普通用户、子租户管理员 | 身份、主属、角色及既有动作权限不变 | 仍需回归默认范围；普通用户伪造异租户目标应明确拒绝 |
| 超管在 A 创建、创建者属于 Root 的资源 | 资源留在 A，创建者仍为真实账号；已有授权记录不丢失 | 这是合法状态，不做“创建者与资源租户一致化”；补运行身份处理 |
| 创建人名称及授权名单 | 已获资源权限后可解析必要姓名；完整名单仍要求管理权限 | 当前已有多处全局用户 ID 解析，不应普遍重写；当前有效使用者摘要须与历史记录区分 |
| Root 共享模型、全局角色、部门挂载、默认继承 | 保留经领域验证的共享、存储/业务归属区别及覆盖规则 | 不得用全局租户相等校验误杀，不得把共享读取变成子租户可编辑 |
| 历史父子记录、版本、授权及配置引用 | 不自动搬迁、不清空、不替换默认值 | 新约束可能使既有异常操作失败；预检后分类处理，不能承诺零影响 |
| 历史授权与权限投影 | 保留资源 ID、真实创建者、授权来源和审计 | 授权稳定键包含租户；仅改一列可能破坏授权和权限系统对应关系，不能随手修数 |
| 已入队任务、导出与下载 | 始终绑定原资源/任务目标 | 新消费者与旧消息须兼容；无法证实目标的任务不能猜 Root 或最新选择 |
| 旧浏览器页、网关、Worker | 匹配版本及范围传递契约 | 分批部署可能造成拒绝或误判；明确版本组合、缓存更新和回退步骤 |

### 上线前只读预检

1. 以资源权威归属核对父子记录、初始版本、授权/来源及引用关系；姓名解析异常单列，不能将缺姓名当作资源归属错误。
2. 分为：**合法跨范围引用、可证明错归属、无法判断原意**。Root 共享、异租户创建者、全局定义和部门存储差异属于合法候选，不能只凭租户不相等判坏。
3. 列出涉及记录 ID、当前关系、证据和新校验后的读写影响；优先比较可见性、可编辑性、可执行性，不只统计行数。
4. 不得根据创建者主属批量反推资源目标。历史 Root 行可能原本就属于 Root，也可能曾错误落库，单凭创建者不能判断。
5. 实际修数另行确认、备份并逐类执行；本批不附带批量迁移，不改已发布迁移脚本，不重置授权或历史配额。版本回退保留已产生业务数据，临时选择缓存的受控重置不等于业务回滚。

**未连接历史数据库，本轮没有异常数量或“全部历史数据透明兼容”的证明。无需整体迁移是实施目标，不是已经验证的事实。** 修复错误可见性可能使原来能误读的数据不再可读，这应作为正确行为变化明确告知，而非为了兼容继续暴露。

## 5. 进入实现前应写进方案的验收与发布条件

- 真实创建者与资源目标不一致时，普通获权用户可查看、执行；知识权限开关语义保留，创建者停用或失去超管后的行为明确。
- INSERT、已有对象修改、批量 UPDATE/DELETE 各有真实入口验证；选 A 提交 B 的资源 ID 不能因超管身份放行。
- 工作流、复制、导出、回调、旧任务重试与平台周期任务分别验证目标恢复；明确缺失及冲突处理。
- 首次加载、切换失败后重读、多标签页、旧响应、过期、Redis 故障及旧静态页面均验证；同步调整是否交付视图标识的验收。
- WebSocket、流式响应及直接下载覆盖上下文生命周期；独立凭据按其自身身份和目标运行。
- 完成只读历史预检，说明可见性及操作行为变化；前端、Python、网关、Worker、清理任务按实际契约安排发布与回退。
- MySQL/DM8 及外部存储按项目既有验证层级验收。路由清单、HTTP 200、单一页面成功或仅本地单元测试都不能替代完整业务链证明。

未运行整套测试、现场端到端测试、数据库预检或部署验证。本评审发现的确定性源码路径与待验证影响已分开说明，不将风险推断写成现场已发生事实。
