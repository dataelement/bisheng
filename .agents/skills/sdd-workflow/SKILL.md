# Sdd Workflow

先读 [阶段交接规则](references/stage-contract.md)，之后只加载当前阶段需要的 skill。
首次落盘或接续时按[产物存放与维护约定](references/artifact-storage.md) 确定一次项目、特性标识和有效路径，各专业阶段共用登记。新项目默认按版本／主业务模块／特性包分层，已有项目沿用其适用约定。

## 任务分流

先用 [sdd-triage](../sdd-triage/SKILL.md) 检查任务和必要项目上下文：
- 新功能或已有功能扩展：完整 SDD。
- 满足全部简单 Bug 准入条件：直接修复和针对性开发验证，再按范围交接独立验收。
- 信息不足：先做有界诊断，不因未知就立即要求人工决定。
- 复杂、影响广或需要重大取舍：报告证据、影响和待决事项，与用户决定切入点。

用户明确指定的范围和已有授权持续生效。按顺序完成研发交付范围内所有已确认要求，不能自行缩小为某一个阶段。完整 SDD 生命周期包含测试工程师负责的独立验收，但本入口不自动执行该岗位流程。

## 研发交付流程

1. [需求验证](../sdd-requirement-validation/SKILL.md)：合理、闭环、边界、可验收四维检查；必要时引用 grilling 澄清。
2. 用户确认需求闭环。没有确认时保留待确认状态。
3. [技术设计](../sdd-design/SKILL.md) 和 [测试用例](../sdd-test-cases/SKILL.md)：都以已确认需求为依据。业务用例可先于技术设计完成；接口等用例在契约确定后补充。
4. 用户确认设计。实施依赖这一确认；需求范围内的业务用例准备可以独立开展。
5. [实施计划](../sdd-plan/SKILL.md)：安排可验证的任务和依赖。
6. [编码与自查](../sdd-implement/SKILL.md)：优先在 mock／隔离环境完成需要的单元、接口、功能和契约测试，并做适用静态检查。
7. [代码审核](../sdd-review-code/SKILL.md)：核对真实被测行为、模拟边界和本阶段应有证据，处理代码问题，记录真实环境缺口。
8. 按[岗位协作与提测规则](references/qa-handoff.md) 关联同一特性登记，交付需求与设计依据、可对应的代码／构建、开发验证证据和待验收项；按本次实际变化更新必要模块知识及索引，保留交付基线。标记“研发完成，待独立验收”，在这里结束。

研发入口不自动调用 sdd-acceptance、不触发或等待 UI／真实环境验收任务，不因已有环境就继续执行测试工程师的工作。验收用例和脚本由测试工程师在独立验收工程准备。
需求定稿、设计和测试用例文档均交付 HTML，参见 [HTML 交付约定](references/html-delivery.md)。需求稿遵循其专业 skill 中的 PRD 写作标准，在既定确认点供用户评审，不以格式齐全代替内容闭环。
开发阶段在各前后端项目的 test/ 下维护所需单元、接口和功能测试。接口与业务代码真实执行，昂贵外部边界可隔离；不要求本机复刻线上整套环境。

领域概念在需求／设计中按需澄清，后续阶段沿同一基线使用并核对。简单问题只消费必要已有定义；新概念或冲突按[领域语言约定](references/domain-language.md) 接入建模，不另加串行审批阶段。

## 独立验收入口

测试工程师可以需求闭环后提前设计验收场景和脚本；研发交付后，由其在指定的独立验收工程显式使用 [sdd-acceptance](../sdd-acceptance/SKILL.md) 组织执行。
两岗位共享需求、契约和代码／构建版本依据，测试代码和运行入口分离。用户明确要求以测试岗位执行验收时，按独立验收任务处理；不能把笼统的“完整开发交付”视为自动进入验收的指令。

## Bug 路径与接续

简单 Bug：sdd-implement → 必要代码复核和开发交付，用适当 mock／隔离测试证明修复。需要的 UI／真实环境验证交接测试工程师，不自动发起验收。
复杂 Bug：人工决定从需求、设计、计划或实施中的合适位置进入，只复用仍然有效的结果。
任何路径中出现影响扩散或推翻已确认需求、设计的情况，重新评估并对齐。

接续时核对阶段产物、用户确认、代码与验证记录。文件存在、任务勾选或旧报告都不能单独证明已经完成。
按受影响范围使旧证据失效并重跑；保留有效结论，控制重复成本。

## 输出

简述当前研发路径、已完成阶段、确认依据、开发验证、交接材料和待独立验收项。分别报告研发状态和测试岗位验收状态，不能代写测试工程师已确认通过。
用户询问状态或补充信息时，回答并继续已授权任务。
需求、设计的确认点及重大偏差决策之外，正常推进已授权工作。提交、合并和部署按用户实际授权处理。
