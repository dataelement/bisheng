## 1. 用户故事

作为 **平台管理员 / 租户管理员**，
我希望 **每个调用开放 API 的外部系统都持有独立、可单独撤销、权限最小的凭据**，
以便 **出事时能定位到具体调用方并即时止血，而不是"谁都能调、也查不出是谁调的"**。

作为 **客户侧的集成开发者**，
我希望 **升级前就能按发布说明建好服务账号、拿到密钥并完成加请求头这一处改造，升级后立即按既有方式继续调用**，
以便 **迁移是一次可预先排期、可预先验证的改造，而不是升级后才发现调用被拒**。（无兼容窗口——PRD D1；升级前三步指引与接入空窗见 §4.9）

作为 **安全与合规负责人**，
我希望 **平台不存在无凭据即可访问业务数据的接口，凭据本身即使数据库泄漏也无法还原**，
以便 **通过等保测评中「内部接口鉴权」这一明确失分项，并把凭据泄漏的爆炸半径限制在单把密钥**。

作为 **服务账号的使用方（自建业务系统）**，
我希望 **集成的权限锚定在一个不可登录的服务主体上**，
以便 **生产集成不因某位员工离职或调岗而中断**。

作为 **资源归属人（负责某个集成的自然人）**，
我希望 **集成经 API 创建出的知识库等资源在我的平台界面里像自己建的一样可见可管**，
以便 **集成产出的资产始终有人认领，而不是只有管理员靠权限短路才看得见的孤儿**。

## 2. 验收标准

> AC 编号在本特性内唯一。与伴生 PRD §五验收标准的对应关系在括号中标注（如 `↔AC-1`），便于双向追溯；伴生 PRD 未单列 AC 的需求以章节号标注（如 `↔§4.7.1`）。
> 错误码在此仅作为可观测的对外行为引用，其定义与归属写在 design.md。

### 2.1 凭据校验与生命周期

- **AC-01** — WHEN 请求未携带有效密钥, THE SYSTEM SHALL 返回 401 且不执行任何业务逻辑、不返回任何业务数据；**不存在任何回落路径**（无鉴权开关、无兼容窗口，PRD D1）。唯一例外是两个 WebSocket 端点上的 share-token（AC-55–58），它同样是平台签发的凭据、不构成回落。（↔AC-1）
- **AC-02** — THE SYSTEM SHALL 使密钥明文仅在创建响应中出现一次；此后任何接口与界面对该密钥只返回掩码（前缀 + 末四位）。（↔AC-2 / AC-40）
- **AC-03** — WHEN 密钥被撤销, THE SYSTEM SHALL 使其后续调用在 5 秒内被拒绝。（↔AC-3）
- **AC-04** — IF 密钥缺少目标端点所需的权限位, THEN THE SYSTEM SHALL 返回 403，且错误信息指明缺少哪一位。（↔AC-4）
- **AC-05** — WHEN 密钥的过期时间到达, THE SYSTEM SHALL 拒绝其后续调用，无需任何人工干预。
- **AC-06** — THE SYSTEM SHALL 在创建密钥时默认不勾选任何权限位；未显式授予的权限位一律视为未授予。
- **AC-07** — WHEN 租户管理员查询密钥列表, THE SYSTEM SHALL 只返回本租户的密钥，跨租户查询返回空。（↔AC-5）
- **AC-08** — WHEN 管理员修改密钥的名称 / 权限位 / 过期时间, THE SYSTEM SHALL 使原密钥立即按新配置生效，不要求轮换密钥。（↔AC-21）
- **AC-09** — WHEN 管理员对某一服务账号执行「撤销该账号全部密钥」, THE SYSTEM SHALL 使其名下全部密钥在 5 秒内失效。（↔AC-22）
- **AC-10** — WHEN 密钥被成功用于一次调用, THE SYSTEM SHALL 更新其最后使用时间（允许 60 秒内的写合并）。
- **AC-11** — WHEN 密钥被撤销, THE SYSTEM SHALL 保留该密钥记录及其历史归属，供审计追溯；撤销不等于删除。
- **AC-12** — WHEN 密钥发生签发、名称 / 权限位 / 过期时间变更、撤销（含批量）、到期自动失效、因主体停用或删除而失效, THE SYSTEM SHALL 记录审计事件（操作者或触发原因、密钥掩码、所属服务账号、动作、时间）；审计记录中不出现密钥明文。（↔PRD-1 GOV-08 承诺 4 / 验收 3；DEV-01 ② ④）
- **AC-13** — WHERE 开放能力层已部署, THE SYSTEM SHALL 在权限位清单及签发 / 编辑表单中提供「本地开发工具包」分组的三个扩展位（`model:invoke` / `identity:read` / `app:manage`）——与既有权限位同一张清单、同一个表单、同样默认全不勾；每位附白话用途说明；`identity:read` 旁以区别于普通说明的醒目样式常驻展示「勾选即本租户组织架构全量可读、无法收窄到部分部门」；`app:manage` 附「部署应用需勾选」；勾选开放 API 端点权限位时给出不阻断的软提示「转交个人使用的 key 建议仅配本地开发工具包权限位」。WHERE 开放能力层未部署, THE SYSTEM SHALL 不展示三位，且以三位入参的签发 / 编辑请求被拒绝。（↔§4.2.4 扩展位表；PRD-1 DEV-01 ①）
- **AC-14** — THE SYSTEM SHALL 在本 Feature 交付形态下不提供 `delegate` 位：签发 / 编辑表单不出现该位与委托配置区；任何以 `delegate` 入参的签发 / 编辑请求被拒绝并提示「委托能力尚未启用」。（§4 决议-6 f；委托随 F050，届时 `delegate` 与三扩展位互斥硬阻断 ↔AC-48 随之交付）

### 2.2 服务账号主体

- **AC-15** — THE SYSTEM SHALL 使服务账号无法通过任何登录入口获得会话（覆盖平台全部登录入口，含本地登录、SSO、网关登录同步、租户选择）。（↔AC-14）
- **AC-16** — THE SYSTEM SHALL 使服务账号**不出现在任何面向人的选人场景**——用户管理、审批人选择、部门加成员、用户组加成员、创建租户选管理员、**资源侧授权选人框**一概不可见；任何消费点即使未显式请求排除也不得看到服务账号（失败方向是"看不到"而非"泄漏"）；资源侧「已授权对象列表」仍能正确**显示**已获授权的服务账号——可显示、不可选择。（↔AC-15）
- **AC-17** — WHEN 租户对账任务执行, THE SYSTEM SHALL 保持服务账号的租户归属不被改写。（↔AC-16）
- **AC-18** — THE SYSTEM SHALL 不把服务账号计入租户用户数配额。（↔AC-17）
- **AC-19** — WHEN 管理员创建服务账号, THE SYSTEM SHALL 使其立即处于「可被授权」状态（可作为授权主体在其详情页被授予资源权限）。
- **AC-20** — IF 对服务账号调用面向自然人的用户更新操作（如改密、启用登录、修改类型）, THEN THE SYSTEM SHALL 拒绝。
- **AC-21** — WHEN 服务账号被停用或删除, THE SYSTEM SHALL 使其名下全部密钥在 5 秒内失效。
- **AC-22** — IF 试图为服务账号授予任何角色（含管理员角色）、租户管理员身份，或经管理接口把它加入用户组 / 部门, THEN THE SYSTEM SHALL 拒绝（承接原决议-2「不让一把密钥背后站着超管」的目的；组织侧自动兜底路径的处置见 §3）。
- **AC-23** — WHEN 管理员创建服务账号, THE SYSTEM SHALL 要求填写名称、描述与**资源归属人**（必填、必须为本租户的自然人；该选人框同样不出现服务账号）；缺失或非自然人时拒绝创建。租户取当前管理员所在租户、不提供选择、创建后不可更换。表单须一句话说明「该集成创建出的知识库等资源将归属此人、由其在平台内管理」；WHERE 开放能力层已部署, 归属人选择处另附提示「该账号首发部署的应用以此人为 owner；删除 / 撤回审批单仅 owner 可为、管理员不可代行；归属创建时固化、改归属人不追溯已有应用」。（↔§4.7.1 / §4.5 定义 3；PRD-1 DEV-01 界面表）
- **AC-24** — WHEN 服务账号经开放 API（模式 S）创建资源, THE SYSTEM SHALL 把创建关系落到其资源归属人名下——该资源在归属人的平台界面中可见可管理、如同其本人所建；同时服务账号自动获得对该资源的可编辑档位（「创建时自动回授」）并可继续写入。（↔AC-42；定义 6 边界 b）
- **AC-25** — THE SYSTEM SHALL 使模式 S 下经开放 API 产生的会话仍归属服务账号、**不出现在资源归属人的会话列表**中。（↔AC-43；定义 6 边界 a）
- **AC-26** — THE SYSTEM SHALL 使资源归属人本人对某资源的权限变化（被加入 / 移出某知识库授权）不改变该服务账号经开放 API 的可见范围。（↔AC-44；定义 6 边界 c）
- **AC-27** — WHEN 管理员更换服务账号的资源归属人, THE SYSTEM SHALL 保持此前已创建资源的归属不变，此后创建的资源归新归属人。（↔AC-45；定义 6 边界 d）
- **AC-28** — IF 服务账号的资源归属人被禁用或删除, THEN THE SYSTEM SHALL 不使该服务账号及其密钥自动失效（回收由管理员停用 / 删除该服务账号完成，AC-21）；列表页对该账号高亮提示（AC-42）。（↔PRD-1 DEV-01 ④ / GOV-08 验收 5）

### 2.3 端点接入与三条铁律

- **AC-29** — THE SYSTEM SHALL 使全部开放 API 端点（36 个 HTTP + 2 个 WebSocket）经过同一条凭据校验路径；不存在绕过该路径的端点。两个 WebSocket 端点在该校验点上额外接受 share-token（AC-55–58，§4 决议-1），不构成绕过。（↔附录 B.1）
- **AC-30** — THE SYSTEM SHALL 不再提供以下 6 个 `/chat/*` 端点（`GET /chat/history`、`POST /chat/gen_title`、`/chat/liked`、`/chat/solved`、`/chat/comment`、`POST /chat/sync/messages`）：调用得到「端点不存在」类响应、不执行任何业务逻辑。（↔§4.6；旧「宽松档」口径作废；发布说明要求见 AC-50）
- **AC-31** — WHEN WebSocket 握手携带无效密钥, THE SYSTEM SHALL 拒绝握手并优雅关闭连接（不产生未捕获异常）。（↔AC-18）
- **AC-32** — WHEN 使用有效密钥且未传任何身份头, THE SYSTEM SHALL 以密钥主体（服务账号）身份执行，返回结果的可见范围等于该主体的权限边界。
- **AC-33** — IF 请求携带身份传递类请求头（代表平台用户 / 外部用户标识）, THEN THE SYSTEM SHALL 返回 403 并提示该能力尚未启用——不得静默忽略该头而按密钥主体身份继续执行。
- **AC-34** — IF 权限引擎不可用或权限评估失败, THEN THE SYSTEM SHALL 返回 5xx 且不返回任何业务结果；绝不返回未过滤或部分过滤的结果集。（↔AC-13、铁律 3）
- **AC-35** — THE SYSTEM SHALL NOT 存在任何"缺身份即降级返回某个子集"的路径：本期不存在"必须携带最终用户身份"的端点级配置，未传身份头 = 模式 S（AC-32），传了 = 拒绝（AC-33）；两者之外没有第三种"返回公开资源 / 空集"的静默降级行为。（铁律 2 的 P0 形态；持 `delegate` 密钥漏传身份头 → 400/`26016` 随 F050。**已知残余**：开发期内 7 个端点的裸 `user_id` 参数仍按既有语义解析，它随 F050 移除、F049 不单独发版——见范围边界）
- **AC-36** — IF 密钥持有目标端点所需权限位、但其主体对具体资源无授权, THEN THE SYSTEM SHALL 返回业务模块既有的资源权限错误——**与缺权限位的 403（AC-04）可区分**，不得合并成同一个笼统 403。（↔§4.4.1 两层判定）
- **AC-37** — WHEN 调用未上线的工作流, THE SYSTEM SHALL 返回业务错误而非执行该工作流。（↔AC-19）
- **AC-38** — WHEN 请求停止一个不属于当前密钥主体的会话, THE SYSTEM SHALL 返回 403。（↔AC-20）
- **AC-39** — IF 代用户解析（F049 期仍存在的裸 `user_id` 路径）的目标账号已被禁用或不存在, THEN THE SYSTEM SHALL 拒绝该请求，不构造出可用身份。
- **AC-40** — WHEN 调用统计文件下载端点, THE SYSTEM SHALL 要求有效密钥与对应权限位，且只返回平台自身生成的统计数据文件；THE SYSTEM SHALL NOT 接受由调用方指定的任意服务器文件路径作为取数依据。（↔§4.6.2）

### 2.4 管理界面

- **AC-41** — WHEN 管理员进入服务账号管理入口, THE SYSTEM SHALL 提供列表、新建、详情页三 tab（概览：名称 / 描述 / 租户 / 创建信息 + 停用启用 + 删除；API 密钥；资源授权）；全模块仅租户管理员及以上可见可操作，不存在面向普通用户的自助入口。（↔§4.7 / §4.7.2）
- **AC-42** — THE SYSTEM SHALL 在服务账号列表中展示名称、状态（启用 / 停用）、有效密钥数（为 0 时高亮提示）、资源归属人（该人被禁用时高亮提示）、最后调用时间（为空或距今超过阈值时提示可考虑停用，阈值为部署配置项、默认 90 天）、创建人 / 创建时间。（↔§4.7.1；「委托」列随 F050 出现）
- **AC-43** — WHEN 服务账号创建成功, THE SYSTEM SHALL 直接给出签发第一把密钥的入口，而不是把管理员送回列表。（↔§4.7.1）
- **AC-44** — THE SYSTEM SHALL 在「API 密钥」tab 的密钥列表中展示名称、掩码、权限位、最后使用时间、过期时间与状态；签发表单含名称（必填）、过期时间（可空 = 长期有效）、按能力分组展示的权限位（默认全不勾，悬停显示该位覆盖哪些接口）。（↔§4.7.3；委托范围摘要与委托配置区随 F050）
- **AC-45** — WHEN 密钥创建成功, THE SYSTEM SHALL 在一次性展示界面同时提供复制操作与「关闭后不可再查看」的明确提示，且关闭前需勾选「我已保存」。（↔AC-40 / §4.7.3）
- **AC-46** — WHEN 管理员撤销单把密钥, THE SYSTEM SHALL 要求二次确认（WHERE 开放能力层已部署, 确认文案补「MCP / 模型协议 / CLI 三面同时被拒绝」）；「API 密钥」tab 顶部提供「撤销该账号全部密钥」快捷操作（AC-09）。（↔§4.7.3；PRD-1 DEV-01 界面表）
- **AC-47** — WHEN 管理员在概览 tab 停用服务账号, THE SYSTEM SHALL 在 5 秒内拒绝其名下密钥的调用（AC-21），但保留全部授权与配置；重新启用后原样恢复。（↔AC-31 停用部分；§4.7.2）
- **AC-48** — WHEN 管理员删除服务账号, THE SYSTEM SHALL 弹出二次确认并列出该账号当前持有的全部资源授权（含创建时自动回授项）、明示删除后这些授权一并失效、依赖它的集成将立即失败；**确认即可删除、不阻断**。删除后这些授权失效，被授权的资源本身及其归属人不受任何影响。（↔AC-31；旧硬阻断口径作废）
- **AC-49** — THE SYSTEM SHALL 使服务账号模块（列表 / 详情 / 密钥 / 授权）不受开放能力层部署开关影响而恒在；WHERE 开放能力层未部署, 仅「本地开发工具包」三扩展位（AC-13）与接入信息区（F053）不出现。（§4 决议-6 g）

### 2.5 存量升级

- **AC-50** — WHEN 存量调用方在升级后不带密钥调用, THE SYSTEM SHALL 返回 401、无回落路径（同 AC-01）；THE SYSTEM SHALL NOT 提供任何"兼容窗口 / 鉴权开关 / 迁移期放行"配置项。发布说明的升级前必读章节 SHALL 包含：升级前三步（创建服务账号并指定归属人、授权 → 签发密钥 → 调用方加 `Authorization` 头）、「升级完成到配好密钥之间存在接入空窗」、存量裸分享链接升级后失效须重新分享、本次不再提供的 6 个 `/chat/*` 端点清单（AC-30）。（↔§4.9 / D1）
- **AC-51** — THE SYSTEM SHALL 在升级过程中不做任何平台侧迁移：不写转型脚本、不改动任何存量用户与资源；原 `default_operator` 配置项指向的用户及其名下资源的归属与可见性**零变化**。（↔AC-27）
- **AC-52** — WHEN 升级部署执行, THE SYSTEM SHALL 移除 `default_operator` 配置项；升级后该配置项的任何取值对开放 API 行为无影响。（↔§4.9）
- **AC-53** — WHEN 升级部署执行, THE SYSTEM SHALL 移除 `enable_guest_access` 配置项；升级后该配置项的任何取值对开放 API 行为无影响。（↔§4.9 / 附录 B.1）
- **AC-54** — THE SYSTEM SHALL 使对外接口文档中不再出现「由网络层负责访问控制」与「建议将默认操作员配置为超级管理员」这两处表述，并公开 `bs-sak-` 密钥的前缀模式（供代码托管平台 secret scanning 规则与 F055 发布前密钥扫描规则集引用）。（↔§4.9 / §4.2.6；PRD-1 GOV-08 承诺 3）

### 2.6 分享链接通道

- **AC-55** — WHEN 分享页持有效 share-token 建立 WebSocket 连接, THE SYSTEM SHALL 允许会话，且其可访问范围仅限该分享所指向的单一资源。
- **AC-56** — WHEN share link 被撤销或到期, THE SYSTEM SHALL 使其后续访问与新建连接在 5 秒内被拒绝。
- **AC-57** — THE SYSTEM SHALL 提供 share link 的撤销入口，并强制执行其有效期（到期即拒）——二者当前均不存在（§4 决议-1）。
- **AC-58** — WHEN 以 share-token 建立的 WebSocket 会话执行, THE SYSTEM SHALL 以该分享的创建者为执行主体、租户上下文取该资源所属租户、可访问范围仅限该分享指向的单一资源（AC-55）；审计记录该 share-token 标识与分享创建者。share-token 是平台签发的凭据，不构成 INV-27 意义上的回落身份。（§4 决议-6 i）

### 2.7 主体侧授权（服务账号详情页「资源授权」）

> PRD §4.7.4：服务账号被排除出全部选人场景后（AC-16），这是它获得资源权限的**唯一**通道，缺了它模式 S 的全部能力失效。

- **AC-59** — THE SYSTEM SHALL 把对服务账号的资源授权收口在其详情页「资源授权」这一个入口，查看与变更**仅管理员**（租户管理员及以上）；非管理员访问该页的读写端点返回 403。（↔AC-30）
- **AC-60** — WHEN 管理员在该页授予某资源, THE SYSTEM SHALL 允许选择资源与由平台既有权限模型提供的权限档位（本页不自行定义档位）；授予后该主体名下持对应权限位的密钥即可按该档位访问该资源，条目来源标为「管理员授予」。（↔§4.7 / §4.7.4）
- **AC-61** — THE SYSTEM SHALL 在该页以**单一列表**展示该服务账号当前持有的全部资源授权，每条带「来源」列（管理员授予 / 创建时自动回授）；页面列出的集合与该主体的有效授权记录**一一对应**，且该主体不存在任何「创建者」类型的授权记录（创建关系落在资源归属人身上，出现即为缺陷）。（↔AC-28；旧「名下资源 / 被授予资源」分组作废）
- **AC-62** — WHEN 管理员在该页撤销某资源, THE SYSTEM SHALL 使该主体名下密钥对该资源的开放 API 调用返回资源权限错误（AC-36）；重新授予后恢复。（↔AC-29）
- **AC-63** — WHEN 管理员点击「全部撤销」, THE SYSTEM SHALL 只撤销「管理员授予」来源的条目、**不撤销「创建时自动回授」条目**；对回授条目单条撤销时给出二次确认并明示「撤销后该集成将无法再写入这个资源」；撤销后该服务账号对应的写入调用失败，重新授予后恢复。（↔AC-47）
- **AC-64** — THE SYSTEM SHALL 在该页顶部呈现该主体名下密钥数与各自的权限位，并对"本页已授权、但名下没有任何密钥持有对应权限位"的资源给出提示——两层判定（AC-04 ∧ AC-36）缺一不可，不呈现另一层管理员必然遇到"授了权仍失败"的困惑。（↔§4.7.4）
- **AC-65** — WHEN 该页发生授予 / 变更 / 撤销, THE SYSTEM SHALL 记录审计：操作管理员、目标服务账号、资源类型与 ID、权限档位的变更前后值、时间。（↔§4.7.4 审计）

## 3. 边界情况

> 只写期望的对外行为；实现层的落点、缓存与数据访问细节见 design.md §5。

- **凭据校验先于租户上下文**：密钥校验本身不依赖任何已建立的租户上下文；校验通过后一切业务查询按该密钥所属租户过滤。跨租户的密钥与主体组合一律拒绝。
- **撤销与缓存的 5 秒窗口**：撤销后允许最多 5 秒的旧结果窗口；主动失效是常态路径，不得依赖被动过期兜底。批量撤销、主体停用与删除同此上界。
- **只有一条路径**：升级后开放 API 只存在「带密钥」一条路径，不存在无密钥回落（PRD D1）；存量集成从固定超管身份切到最小授权的服务账号后能力**会**收窄——这是改造目的而非事故，靠升级前的授权配置与发布说明承接（AC-50）。平台侧不替客户做任何转型（AC-51）。
- **密钥有效性的单一判据**：有效 = 未撤销且未过期。不引入可独立漂移的状态枚举列（平台已有「枚举存在但无写入端点」的负资产先例）。
- **服务账号的租户归属是声明式写入**，不由部门树派生；任何以部门树为真相的对账任务都必须结构性跳过服务账号，而不是"恰好没扫到"。
- **服务账号"没有部门"不是代码保证的不变量**：组织侧存在把无部门用户兜底进访客部门的自动路径（PRD 附录 E.2）。本 Feature **不修改这些真人场景的兜底逻辑**，要求服务账号结构性不命中并以测试断言固化；管理接口层面主动加入部门 / 用户组 / 角色一律拒绝（AC-22）。委托侧的自然人判定随 F050 在调用期兜底。
- **资源归属人是"归属"不是"权限"**（定义 6 边界 c）：它只决定服务账号创建出的资源在界面上归谁认领；服务账号能创建什么、能读写什么，仍只由密钥权限位 ∧ 它自身被授予的资源决定，与归属人本人的权限完全无关。归属人也不因此获得对服务账号或密钥的任何管理能力；归属人被禁用不联动服务账号（AC-28）。
- **创建时自动回授不受「全部撤销」影响**（AC-63）：这是资源归属人机制引入的唯一新增操作风险——界面上这条授权看起来与管理员手动授予的毫无区别，一次点击就会切断集成对自己维护的知识库的写入。
- **密钥（`bs-sak-`）的传递方式 WebSocket 与 HTTP 一致**（请求头），不使用查询参数——密钥会进入访问日志。share-token 例外：允许经查询参数传给 WS——它本就承载于分享 URL 中，不构成新增泄漏面。
- **服务账号不出现在任何选人列表，授权走主体侧**：排除无例外（失败方向是"看不到"而非"泄漏"），资源侧授权弹窗的选人也在覆盖面内（AC-16）；模式 S 的能力靠服务账号详情页的「资源授权」（§2.7）获得，而非靠在资源侧选人框里被选中——否则任何资源所有者都能单方面扩大某把密钥的数据边界而管理员无从感知（PRD §4.7.4）。
- **托管应用凭据不是服务账号密钥**：F055 为每个应用签发的运行期凭据以「托管应用」为主体、不出现在服务账号列表、不需要资源归属人（应用 owner 即归属）；它复用本底座的生成 / 哈希 / 校验 / 撤销 / 审计能力，管理面对它零可见（PRD-1 GOV-08）。
- **服务账号模块恒在，开放能力层开关只 gate 增量**：v2 开放 API 发布即带鉴权，服务账号与密钥是它唯一的接入方式，因此不能被任何部署开关隐藏；开关只决定三扩展位（AC-13）与接入信息区（F053）是否出现（§4 决议-6 g）。
- **本期 `POST /filelib/retrieve` 的过滤强度维持现状**（知识资源级一次校验 + fail-closed），文件级双层过滤随 F052 收敛到同一条路径。模式 S 下服务账号的授权由管理员集中收敛（§2.7），过渡期风险可控；这不是"已经做过文件级过滤"，调用方注释的相反宣称与实现不符（PRD 附录 B.1）。
- **写放大与租户过滤**：最后使用时间的更新不得成为热路径上的每请求写；密钥表的写路径必须与多租户隔离兼容（细节 design §5）。
- **凭据校验取 fail-closed，与平台既有会话续期校验的取向相反**：会话续期在缓存 / 存储抖动时刻意宽松（"不因抖动把用户锁在门外"）；凭据校验属于鉴权而非会话续期，缓存或存储不可用时**必须拒绝**。这一差异是刻意的，不是不一致。

## 4. 待澄清决议

> ★ 决议 1–4 已于 2026-08-06 与产品逐项确认；决议-5 为 2026-08-15 与伴生 PRD v2.0 的同步记录；**决议-6 为 2026-08-17 与伴生 PRD v2.1 + PRD-1 v2.0 的同步记录，其中 f / g / h / i 四项于 2026-08-17 由用户授权「全部按建议拍板」定案，本 spec 第二次 ★ 已过**。历史决议中被后续 PRD 修订推翻的部分以各条末尾的「状态」为准，原文保留供追溯。

- **[决议-1] 两个 WebSocket 端点 × 免登录分享页 → ① share-token 全量方案。**
  核实基础：两个分享页 URL 仅含资源 id、零凭据；平台已有 share_link 通道（`share-token` 请求头、高熵 token、资源类型已含工作流 / 助手，client 端工作台 / 灵思分享在用），但**无撤销写入端点、有效期刻意不生效**；实际受影响面只有工作流 + 助手两个 WS；这两个 WS 同时写在 platform 的 API 接入文档页中，服务端集成方也在用——两类凭据必须并存。
  决议：分享页改走 share_link 通道并补齐撤销 + 有效期强制（AC-55–57）；WS 端点密钥（请求头）与 share-token（查询参数）双凭据并存。**状态（2026-08-17）：仍有效**。存量裸分享链接升级后即失效、需重新分享，列入发布说明（AC-50）；share-token 会话的执行主体见决议-6 i。

- **[决议-2] 统一身份构造放宽权限 → 默认操作员转型降权提升为上线闸口。**
  原决议（2026-08-06）：升级部署强制完成默认操作员 → 服务账号的转型与降权，闸口拦开放 API 鉴权启用、不拦全站；2026-08-15 修订为主体级 fail-closed。
  **状态（2026-08-17）：整条作废。** 伴生 PRD §4.9 已定「平台侧不做任何迁移」——不写转型脚本、不动存量用户与资源、`default_operator` 配置移除、其指向的用户保持普通用户身份（AC-51/52）。原决议的**目的**（不让一把密钥背后站着超管）由两处结构性约束承接：密钥只签发给服务账号（自然人无凭据），且服务账号不得被授予任何角色或管理员身份（AC-22）。「存量集成收窄」的承接=升级前授权配置 + 发布说明（AC-50）。

- **[决议-3] 5 个会话反馈端点的归属校验基准 → 宽松档：有效密钥即可。**
  **状态（2026-08-17）：作废。** 伴生 PRD §4.6（2026-08-16 决议）把 `history` / `gen_title` / `liked` / `solved` / `comment` 与 `sync/messages` 共 6 个 `/chat/*` 端点**整体移出本次范围、不暴露**（`session:*` 三位随之取消），归属校验问题不复存在（AC-30）。这 6 个端点从未出现在对外接口文档中，不构成已承诺能力的回收，但目前匿名可达、须在发布说明逐个列出（AC-50）。统计下载端点不受影响，仍按最严收口（AC-40）。

- **[决议-4] 两册「绑定自然人的密钥」口径冲突 → 统一成服务账号，不做个人 key。**
  决议：**全平台只存在服务账号一类密钥主体、`bs-sak-` 一类凭据**；PRD-1 DEV-01 改判为服务账号密钥、`bs-pat-` 作废；已确认接受代价（权限不随人走、离职需手动回收）。**状态（2026-08-17）：仍有效，且已被两 PRD 正文吸收**——PRD-1 v2.0 DEV-01「开发者 key 只是服务账号密钥的一种用途称呼」；原「绑定使用人」概念升格为伴生 PRD §4.5 定义 6「资源归属人」（必填、承接归属不出借权限），本 spec 按定义 6 落 AC-23–28。

- **[决议-5] 2026-08-15 与伴生 PRD v2.0（深度 Review 版）同步——5 处硬冲突逐项裁决。**
  ① 兼容窗口 / 鉴权开关 → 废止（D1）；② 裸 `user_id` 收口随 F050，但 F049 不得脱离 F050 单独发版；③ 铁律 2 形态改为「不存在任何缺身份即降级的路径」，`delegate` 即强制、无独立开关；④ 服务账号不出现在任何选人场景、授权走主体侧唯一入口（新增 §2.7）；⑤ Responses 契约无特性承接、待版本层归属。另同步：两层可区分错误、密钥级白名单不做不预留、`enable_guest_access` 随升级移除。**状态（2026-08-17）：①–④ 仍有效并已并入正文；⑤ 已由 release-contract 登记为 F058。**

- **[决议-6] 2026-08-17 与伴生 PRD v2.1 + PRD-1 v2.0 同步——逐项裁决如下。**
  1. **升级零迁移**（伴生 §4.9 / AC-27 新义）：转型降权闸口整条作废（见决议-2 状态）；新增 `default_operator` 移除（AC-52）。
  2. **6 个 `/chat/*` 端点不暴露**（伴生 §4.6）：宽松档作废（见决议-3 状态）；端点数由 44 改为 36 HTTP + 2 WS（AC-29/30）。
  3. **主体侧授权页 v2.1 形态**（伴生 §4.7.4）：删「名下资源」分组（资源归属人机制下结构性恒空），改单列表 + 来源列 + 「全部撤销」排除回授项 + 一一对应且无创建者记录（AC-61/63）。
  4. **删除服务账号不阻断**（伴生 §4.7.4 / AC-31）：`26013` 硬阻断降为「二次确认列清单即可删」（AC-48）——资源归属人机制下服务账号不拥有资源，删除不产生孤儿。
  5. **资源归属人**（伴生 §4.5 定义 6）：创建必填自然人 + 四条边界落 AC-23–27，归属人禁用不联动 AC-28；AC-46（模式 D 优先级）随 F050。
  6. **三扩展位登记与 `delegate` 位归属 [已定 f]**：三扩展位（`model:invoke` / `identity:read` / `app:manage`）在本 Feature 登记入权限位清单并随开放能力层开关出现（AC-13）；**本 Feature 表单不提供 `delegate` 位**（AC-14）——委托能力整体属 P1，`delegate` 位、委托配置区、伴生 AC-48 互斥硬阻断随 F050，运行期入口拒绝（伴生 AC-49）随 F051 / F052 / F053。备选=F049 就把 `delegate` 位做进表单并持久化（只存不生效），代价是 P0 期管理员能勾一个什么都不做的位。**已定：前者。** 无论哪种，"三扩展位仅模式 S 且与 `delegate` 互斥"登记为版本级不变量 INV-31。
  7. **服务账号模块恒在 vs GOV-10 措辞 [已定 g]**：PRD-1 GOV-10 规则与验收 4、GOV-08 界面表写「未部署开放能力层：管理后台『API key 管理页』不展示」，而 DEV-01 ⑥ 写「服务账号模块本身随该 PRD 交付」、伴生 §4.7 写「仅部署标准版（无应用工场）时按本节原样交付」。两者矛盾。本 spec 按后者（AC-49）：v2 开放 API 发布即带鉴权，服务账号与密钥是唯一接入方式，不能被部署开关隐藏；开关只 gate 三扩展位与接入信息区。**已定并执行：2026-08-17 已回修 PRD-1 GOV-10 规则表 / 验收 4 与 GOV-08 界面表措辞。**

  9. **share-token 会话的执行主体 [已定 i]**（2026-08-17 `/sdd-review` 独立审查指出决议-1 未定义此项）：两个免登录分享页的访问者是匿名的，其 WS 会话必须有一个执行主体来确定租户上下文、权限基准与审计归属。本 spec 定为**以分享创建者为执行主体、范围仅限该单一资源、审计记 share-token 与分享创建者**（AC-58）——这与「已发布分享链接 = 分享者把自己的应用开放给匿名访客使用」的产品语义一致，且比现状（两个 WS 以固定配置身份执行）收窄。备选=为每个分享派生一次性受限主体（体量更大，本期不推荐）。**已定：以分享创建者为执行主体。**
  另同步：AC 全表重编号（原 24a / 37a 消除；旧→新映射见文末附表）；用户故事新增「资源归属人」视角；范围边界补「已废止的旧范围」清单防回流；开放能力层部署开关的定义归本 Feature（F051–F053 复用）；`/sdd-review` 独立审查（2026-08-17）24 条发现的处置：新增 AC-12（密钥生命周期审计）/ AC-28（归属人禁用不联动）/ AC-58（share-token 主体）/ AC-60（授予动作），AC-13 / 23 / 41 / 42 / 46 / 47 / 50 / 54 补齐 DEV-01 表单层增量、租户不可换、概览内容、阈值、5 秒口径、发布说明清单、前缀模式；AC-01 / 35 补 share-token 例外与裸 `user_id` 残余说明；AC-22 扩到任何角色；AC-16 / 40 / 52 / 57 与 §3 去实现措辞；排除项补浏览器直连；ShareLink 对象在 release-contract 表 1 补登记。
