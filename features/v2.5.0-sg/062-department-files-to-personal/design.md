# F062 设计

Status: `confirmed`

个人默认库匹配追加规则：对匹配候选按 ID 升序稳定排序，固定使用第一个；不因第一个库模型不一致等原因改选后面的库，原目标校验仍适用。预览记录 `personal_space_candidate_ids` 与既有 `target_space_id`。

覆盖追加设计：预检不再排除批次同名候选，记录后续单元将覆盖的前序单元；执行每次重新解析实际同名目标及完整版本链。通过名字匹配集合关联版本，不复用旧脚本的全库 MD5 覆盖范围；可覆盖多个同名逻辑文档，但每条版本链必须完整位于目标目录且无共享/审批保护。使用既有 revalidate/snapshot/delete_overwrite_target 处理具体旧目标。首次旧目标删除前将 GuardedOperations/GuardedGraphStore 设置为保留目标副本，若后续任一步失败不得再清理新副本。旧目标删除失败或日志失败即停止，不宣称已删除旧文档可由普通来源补偿恢复。

完整设计以 [spec.md](./spec.md) 第 3 至 6 节为准。新增单个脚本与定向测试，局部补充 README；不修改旧迁移脚本和在线服务。

组件：只读快照加载、纯迁移候选规划、按用户创建默认个人库、目标路径准备、带持久记录的逐单元执行。默认库和目录未创建时使用逻辑路径描述，不伪造数据库 ID。apply 每个单元重新获取源快照并对比，再读取目标冲突。

只读阶段仅初始化数据库连接；全量应用基础设施初始化只允许在 apply。读取全租户文件关系用于识别候选的外部引用，不能只读取指定目录后就判断没有引用。UserTenant 不受自动租户过滤，读取候选用户关联后在内存中按所选租户和 active 状态校验。

目录通过现有 `KnowledgeSpaceService.add_folder()` 创建；该服务负责 ORM、权限检查和 owner/parent 授权。复用迁移底座处理物理数据。失败恢复不完整时保留目标副本，避免恢复失败后再清理唯一剩余数据。每个单元写入并 fsync 操作记录后才开始来源删除。

版本表没有独立 tenant_id：按本租户文档 ID 或文件 ID 分批查询，随后核对完整版本图；不能查询一个并不存在的租户字段，也不扫描其他租户的完整版本表。参考脚本的底座只读复用，在新脚本中用 GuardedOperations/GuardedGraphStore 补强恢复失败后保留目标副本的保护。

REQ/AC 映射：只读规划覆盖 001/002/004/005/006/009/010；资源创建与迁移覆盖 003/007/008；全部由对应 T001/T002 测试和 T003 验证记录追溯。

权限/迁移测试先行，测试使用隔离内存数据和外部服务替身。真实 MinIO/Milvus/ES/FGA 端到端及 DM8 实测必须单列证据，不把 mock 结果等同于生产验证。


## 2026-09-10 原记录迁移修复

用户要求修复审查发现的覆盖部分删除、索引异常中断、全租户反复加载和跨脚本依赖问题。本次已获授权的修复取代旧复制补偿设计：单脚本内置必要逻辑，保留文件/文档/版本 ID 和原对象地址；同名旧链删除与来源归属变化在同一事务。索引异常、失败/超时状态和模型不同可迁入后标记解析失败。部门转个人权限切换必须成功，权限/数据库/审计失败仍停止；提交异常须查询实际归属后才决定恢复旧权限。分部门加载命中子树、执行定向复查，保留外部引用与审批保护。新建目录及旧目标对象保留审计，不清理部门库。仅本地修复与验证，不包含真实 apply 或容器更新。
