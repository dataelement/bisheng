## 写在前面：为什么以「复制提示词给 AI」为主路径

参考飞书 CLI 的落地页：页面不让用户自己执行 `curl` 和 `pip`，而是给一段提示词，用户复制给 AI 编程工具，由 AI 执行全部命令。

我们的安装、登录、部署三步都能交给 AI 执行，所以开发者的操作收敛成「对 AI 说三句话，再在界面上操作两步」：

| 动作 | 谁做 | 怎么做 |
|---|---|---|
| 安装并登录 | 你 → AI | 复制安装提示词给 AI，填入密钥。AI 安装命令行并登录，登录时命令行把技能包放进 AI 编程工具 |
| 做出应用 | 你 → AI | 描述你要的应用。AI 编写代码，在本地运行给你看 |
| 部署 | 你 → AI | 让 AI 部署。平台构建应用并生成发布审批单 |
| 审批 | 管理员 | 在审批中心点「通过」，应用自动上线 |
| 授权 | 你 | 在「构建 → 应用」里把「查看者」授权给部门 |
| 使用 | 同事 | 在应用中心打开应用 |

为此后端加了 `install-guide` 端点，和 `cli/download`、`skills/{pack}` 使用同一套匿名分发机制。它把安装和登录步骤写成一份 AI 能读的指引，提示词只需指向它。手动安装保留为备选。

当时拍板的 5 点：

| # | 决策点 | 结论 |
|---|---|---|
| A | 主路径 | 「复制提示词给 AI」为主，手动安装为备选 |
| B | install-guide 端点 | 加。提示词保持简短，各操作系统的差异由指引处理 |
| C | 密钥进提示词 | 用户把 `bs-sak-…` 粘贴到本机的 AI 会话里；教程提醒不要发到共享位置 |
| D | AI 编程工具 | 列出 Claude Code、Codex、Cursor、Trae、Copilot、Windsurf；如实说明只有 Claude Code 和 Codex 会自动接入技能包，其他工具读取部署时写入的 `AGENTS.md` |
| E | 本地预览 | 保留。先在本地看效果，再部署 |

# 说三句话，把想法变成全公司能用的应用

AI 负责写代码和部署，平台负责构建和运行。你只需对 AI 说三句话，再在界面上操作两步。

## 开始前，准备两样东西

**一个 AI 编程工具**：Claude Code、Codex、Cursor、Trae、Copilot、Windsurf 都可以。

登录 bisheng 命令行时，它会把平台的技能包放进 Claude Code 和 Codex 的技能目录。技能包是一组写给 AI 看的开发和部署规则。

使用 Cursor、Trae 等其他工具时，第一次部署会在项目里写入 `AGENTS.md`，告诉 AI 技能包在哪里。

**一个平台密钥**：向平台管理员申请一个密钥，格式是 `bs-sak-` 开头的一串字符。第 1 句话里要用到它。

密钥只粘贴到你本机的 AI 编程工具里。不要发到群聊、文档或代码仓库。

## 对 AI 说三句话

按顺序把下面三条消息发给 AI。每发一条，等 AI 做完再发下一条。

### 1. 安装并登录

你发给 AI：

```text
帮我安装并登录 bisheng 命令行。安装与登录指引见：
http://你的平台地址/api/v1/dev-toolkit/install-guide.md
登录地址用 http://你的平台地址，我的密钥是 bs-sak-把这里换成你的密钥
装好后确认 bisheng --help 能运行，并告诉我接入了哪些 AI 编程工具。
```

平台地址已按本页地址填好。你只需把密钥部分换成自己的密钥。

AI 会做：AI 从平台下载并安装 bisheng 命令行，再用你的密钥登录。登录时，命令行会把技能包放进你的 AI 编程工具。最后 AI 会告诉你接入了哪些工具。

> **安装完成后，重启 AI 编程工具，新开一个会话。**已经打开的会话读不到新安装的技能包。

**不用 AI，自己在终端安装**：

```bash
# 下载安装包。-OJ 让 curl 使用平台返回的文件名，pip 只认这个文件名
curl -OJ http://你的平台地址/api/v1/dev-toolkit/cli/download
# 用 pipx 安装到用户目录。新开的终端也能运行 bisheng
python3 -m pip install --user pipx
python3 -m pipx ensurepath
python3 -m pipx install ./bisheng_cli-*.whl --force
# 用管理员给的密钥登录。凭据保存在本机，以后不用再输入
bisheng login http://你的平台地址 --api-key bs-sak-…
```

以上是 macOS 和 Linux 的命令。Windows 用户在 PowerShell 里执行，把 `curl` 换成 `curl.exe`，把 `python3` 换成 `py`。

安装包从你们的 BISHENG 平台下载，不需要访问公网。安装后新开一个终端，运行 `bisheng --help`。能看到 login 和 deploy 两个命令，就说明安装成功。

### 2. 描述你的应用

你发给 AI（示例，换成你要做的应用）：

```text
帮我做一个部门费用报销小工具：填写人、金额、事由、日期，提交后存下来，我能看到一张汇总表。先在本地运行给我看。
```

```text
帮我做一个满意度问卷：5 道单选题，提交后按选项统计比例，给我一个结果页。先在本地运行给我看。
```

AI 会做：AI 按技能包里的规则编写应用代码和配置文件 `bisheng-app.yaml`，然后在你的电脑上运行应用。你可以先在本地查看效果。

需要修改时，继续对 AI 说，比如「按钮改成蓝色」「加一列备注」。在本地修改不占用平台资源。

### 3. 部署

你发给 AI：

```text
帮我把这个应用部署到 BISHENG 平台。
```

平台会做：打包上传 → 敏感信息扫描 → 构建镜像 → 启动检查 → 生成发布审批单。

> **部署成功不等于上线。**管理员审批通过后，应用才会上线。

## 在界面上操作两步

下面两步在平台界面上完成，不需要再给 AI 发消息。

### 4. 等管理员审批（管理员操作，你等结果）

管理员在审批中心点「通过」后，你的应用会自动上线。审批由人工处理，可能需要一天以上。

部署后，AI 会等待审批结果，最多等 30 分钟。超过 30 分钟还没有结果，不代表审批失败。之后让 AI 再查一次部署状态即可。

管理员的操作路径：审批中心 → 我的审批 → 通过。

| 情况 | 做法 |
|---|---|
| 怎么确认已上线 | 打开「构建 → 应用」，应用卡片显示「已上线」 |
| 被驳回了 | AI 会告诉你驳回理由。让 AI 按理由修改，然后重新部署 |
| 你自己就是管理员 | 你可以审批自己提交的应用。平台会在审计日志里记录这次操作 |

### 5. 授权给部门（你操作）

**刚上线的应用只有你自己能打开。**要让同事使用，你需要给他们授权。

操作路径：构建 → 应用 → 卡片上的齿轮 → 管理权限 → 添加权限。

选择「查看者」，再选部门或用户组。要给全公司使用，选择顶层部门并勾选「包含子部门」。

## 之后，同事在应用中心打开它

被授权的同事打开**应用中心**，在「探索更多应用」里找到你的应用，点「进入应用」在新标签页打开。

同事用过一次后，应用会出现在他们最近使用过的应用里。

**以后要修改应用，**让 AI 修改后重新部署。应用里已有的数据会保留。

## 遇到问题

遇到报错时，先把报错原文发给 AI。大多数问题 AI 能自己解决。

**本地运行正常，部署到平台后起不来**

这类问题通常是应用不符合平台的托管要求，例如把端口写死在代码里，没有读取平台分配的端口。

技能包里写明了这些要求和常见错误。把报错原文发给 AI，让它对照技能包排查。

**实时推送的连接用一段时间后断开**

平台给每条 WebSocket 连接设了最长时长，默认 8 小时。同事的访问权限被收回时，平台也会断开这个同事的连接。

让 AI 给页面加上断线自动重连，然后重新部署。

**登录时提示「未接入任何 AI 编程工具」**

本机没有检测到 Claude Code 或 Codex。

如果你用的是这两个工具，让 AI 运行一次 `bisheng skills sync`。如果你用的是 Cursor、Trae 等其他工具，可以忽略这条提示。第一次部署时，命令行会在项目里写入 `AGENTS.md`，AI 读取它就能找到技能包。

**平台升级后，更新技能包**

让 AI 运行一次 `bisheng skills sync`。这个命令会下载新版技能包。输出的最后一行列出接入了哪些 AI 编程工具。
