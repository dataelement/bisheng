# 企业技能：统一管理与分别执行

2026-10-19 用户确认：毕昇统一管理技能和权限，Chat 在平台执行，Work 在桌面本地执行；两边读取同一份已授权技能。

## 当前事实

- 平台 `/api/v1/linsight/skill/selectable` 提供已启用技能的 name、display_name、description 和 default_checked。现有 Chat 选择技能后进入平台任务模式，任务提交携带所选技能。
- Work 使用本地 Harness 技能能力。桌面企业集成包目前提供身份、模型和市场桥接；企业技能目录同步和运行时注册需要实现。
- 技能中心中的个人技能预览使用本地浏览器存储。企业统一管理需要以服务端目录及授权作为正式来源。

## 接口与执行约定（待实现）

1. 目录包含稳定 skill_id、租户、来源、展示名称、描述、版本、content_hash 和可执行位置。名称用于展示；选择、缓存和执行使用稳定 ID 与版本。个人、企业以及内置同名技能分别保留身份。
2. 平台按当前企业身份返回授权目录，技能下载和任务执行各自再次校验授权。客户端选中状态只表达用户意图。
3. Chat 发送所选 ID/版本，平台解析授权技能并执行。普通聊天与任务模式分别实现明确的技能消费入口；当前已接通的路径为任务模式。
4. Work 由宿主通过既有企业认证获取授权技能包，校验版本和内容摘要，限制解包路径与资源大小，按租户/技能/版本缓存；通过 Harness 支持的技能注册入口提供给当前任务。
5. 凭证保存在宿主认证层。技能脚本及文件操作沿用本地策略、沙箱和审计链路；企业授权与本地执行权限分别校验。
6. 退出、切换企业、撤销授权与更新版本触发目录刷新和运行时可用性更新。已有任务保留可审计的技能版本快照，下一次调用按最新授权校验。
7. 两端选择器展示同一企业目录，使用 DSH 外观和交互。执行位置、加载失败、权限失效和版本更新提供明确状态。知识空间继续作为上下文资源独立选择。

## 验收顺序

- 同一账号两端看到一致的授权企业技能；同名跨来源技能可区分。
- 平台 Chat 任务执行选中版本；Work 本地任务执行同一版本；各自记录工具与技能事件。
- 验证撤销授权、切换企业、更新版本、断网缓存、包校验失败和路径越界。
- 最后验证 3006 与桌面安装包的实际目录、选择、执行和结果。界面预览、构建通过及目录可见分别记录证据。
