## 1. 什么时候用

气泡卡片（Popover）是挨着触发元素弹出的白底小卡片，装得下结构化内容——标题、多行文字、链接、按钮、轻量表单。当一个元素需要「进一步的信息或一两步轻操作」、又不值得开一个弹窗打断全局时，用它。

- **信息卡**：悬停头像出用户信息卡、悬停条目出详情预览。
- **轻量操作面板**：列筛选、字段显隐、颜色选择这类一两步就完成的小操作。
- **先过判定再动手**：与 Tooltip 的分界（两问判定 + 浮层家族速查）统一写在 [组件-Tooltip文字提示.md](组件-Tooltip文字提示.md) §2。一句话版——**一句纯文本用 Tooltip，可操作的富内容用 Popover**。

### 1.1 什么不该装进 Popover

- **警告和报错**。悬浮卡片容易错过、容易误关，警告用弹窗或全局提示。
- **二次确认**。删除等不可逆操作的确认一律用 useConfirm 居中弹窗（见 [组件-Modal弹窗.md](组件-Modal弹窗.md)）。**不做气泡式二次确认（Popconfirm）**——确认弹窗只有一套长相，用户才形成条件反射。
- **多步任务和复杂表单**。超过一两步的流程用弹窗或抽屉；Popover 一旦误关，用户填了一半的东西就丢了。
- **页面必需的内容**。Popover 里的信息错过了也不能误事；任务必经的内容放页面或弹窗里。

| ✅ 推荐 | ❌ 不推荐 | 原因 |
|---|---|---|
| 表头筛选用 Popover 装几个复选框 | 五步配置向导塞进 Popover | 超过一两步就该换弹窗 / 抽屉，误关一次前功尽弃 |
| 「保存失败」用全局提示或弹窗 | 「保存失败」从按钮旁弹个气泡 | 气泡容易错过也容易误关，警告必须确保被看到 |
| 删除确认用 useConfirm 弹窗 | 删除按钮旁弹气泡问「确认删除？」 | 确认只保留一套形态，气泡确认与之并存会分裂用户的肌肉记忆 |

## 2. 结构 Anatomy

从上到下三段，各自可选、按需取用：

| 区块 | 规格 |
|---|---|
| 标题 | 14 / 22，字重取加粗档，一级文字色；与正文间距 8px |
| 正文 | 14 / 22 常规，二级文字色；可含链接、图文 |
| 操作区 | 按钮用 small 档（24px）、间距 8px、右对齐，主按钮在最右（footer 通则见 [组件-Button按钮.md](组件-Button按钮.md) §5） |

- 字号与字重档见 [基础-字体规范.mdx](基础-字体规范.mdx)，文字色见 [基础-色彩规范.mdx](基础-色彩规范.mdx)。
- 内容只剩一句纯文本时——那是 Tooltip，回判定表。

## 3. 尺寸与样式

| 项 | 值 | 说明 |
|---|---|---|
| 底色 | 白底，跟随暗色主题 | 与页面同底，靠描边和投影分层 |
| 描边 / 投影 | 1px 描边 + 浮层投影档 | 与下拉同档，见 [基础-阴影与圆角规范.mdx](基础-阴影与圆角规范.mdx) |
| 圆角 | 12px | 容器档最小档；弹窗 16px，Popover 小一号 |
| 内边距 | 16px | 弹窗 20px，Popover 轻一档 |
| 宽度 | 随内容，最大 320px | 超过 320px 说明内容太多，该换弹窗或抽屉 |
| 高度 | 内容一屏放完，不出现内部滚动 | 要滚动就是装多了 |
| 箭头 | 默认带，指向触发元素 | 与 Tooltip 一致 |
| 与触发元素间距 | 4px | 带箭头时以箭头尖计 |

## 4. 位置

定位规则与 Tooltip 同一套：12 方位、默认上方居中、空间不足自动翻转、不许被视口裁掉（见 [组件-Tooltip文字提示.md](组件-Tooltip文字提示.md) §5）。Popover 自己多一条：

- **不遮住触发元素，也不遮住操作时需要参照的内容**。卡片是元素的延伸，盖住本体用户就丢了上下文。

## 5. 触发与关闭

- **默认悬停触发**：与 Tooltip 同一手感——指针进入 100ms 后出现；**指针可以移进卡片操作**，移出触发元素与卡片后关闭。
- **含输入框或多选操作的内容，改点击触发**：悬停型移出即关，输入一半手一滑内容就丢；点击型要点外部、按 ESC、或再点一次触发元素才关。
- **点击型的焦点进卡片**：Tab 在卡片内的可点元素间移动，ESC 关闭后焦点回到触发元素——这也是它和 Tooltip 的本质区别（Tooltip 焦点永远不进浮层）。
- **一次只开一个 Popover**，打开新的先关旧的；**禁止从 Popover 里再弹 Popover**——级联浮层没人知道自己在哪一层。卡片内的操作要开弹窗时，先关掉卡片再开。
- 悬停型同样**不自动超时消失**：保持可见直到指针移出或用户主动关闭（WCAG 1.4.13）。

| ✅ 推荐 | ❌ 不推荐 | 原因 |
|---|---|---|
| 带输入框的筛选面板用点击触发 | 带输入框的面板用悬停触发 | 输入中指针一滑出边界面板就关，内容全丢 |
| 卡片里点「编辑」→ 关卡片、开弹窗 | 卡片里再弹一层卡片继续操作 | 浮层叠浮层，关一层还剩几层没人说得清 |
| 点外部空白关闭点击型 Popover | 只能点卡片里的「×」才能关 | 点外部关闭是所有浮层的通用肌肉记忆，别单独发明 |

## 6. 层级

- Popover 可以出现在弹窗、抽屉之上——弹窗里同样会有筛选、信息卡。
- Tooltip 永远压在 Popover 之上，提示是最贴近指针的一层。
- 具体 z-index 阶梯归 [01-设计规范.md](01-设计规范.md) §5 统一定稿，本文不定数值。

## 7. 移动端适配

通用原则见 [基础-多端适配原则.md](基础-多端适配原则.md)，这里只写 Popover 自己的细则：

| 项 | 触屏 / 窄屏规则 |
|---|---|
| 触发 | 触屏没有悬停，悬停型一律降级为**轻点触发**，点外部关闭；内容不变 |
| 容器 | 窄屏上内容超过约半屏、或含表单输入的，不用 Popover，改抽屉或弹窗——窄屏放不下「挨着元素的小卡片」，全宽容器才好操作 |
| 触达 | 卡片内可点元素照多端适配原则扩热区（≥44×44px 底线） |

窄屏改全宽容器有权威依据：Apple HIG 明确建议紧凑视图里用全屏模态视图替代 popover。

## 落地（给实现窗口）

1. 基座用 Radix Popover 原语（点击语义、焦点圈定、ESC 归还焦点均内置）；悬停型用 HoverCard 原语或 Popover + hover 控制封装。对外只暴露一个组件，`trigger="hover" | "click"` 两档，默认 `hover`。
2. 样式 token：`bg-background`（跟暗色）、1px 描边（中性描边色，色彩规范接线）、圆角 12px、`p-4`（16px）、`max-w-[320px]`、浮层投影档；箭头同底色带描边。组件内不留裸 hex。
3. hover 档时序与 Tooltip 共用同一组常量（进入延时 100ms、移入保持、150ms 淡入）；封装处统一，禁止业务页自调 delay。
4. 触屏降级：`coarse-pointer` 媒体查询下 hover 档自动走 click 行为，处理惯例参照 Button 落地 §6。
5. z-index 待 [01-设计规范.md](01-设计规范.md) §5 阶梯定稿后接线；过渡期保证 Popover ≥ 弹窗层、< Tooltip 层。
6. 现状扫描待做：口径 `src/frontend/client/src`，排除 `ui/` 与 `_gallery/`，盘 Popover / HoverCard / 自造 hover 卡片（手写 absolute 浮层）的实现与用量，作迁移排批参考；Dropdown 菜单不算在内（另有规范待建）。
