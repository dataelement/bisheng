# 昆联反向调用毕昇 Workflow 的运行控制设计

- **Feature ID** `F127`（拟用，合入前复核）
- **版本** `v3.0.0`
- **状态** 规格与设计已确认，首轮隔离 Mock 已通过。正式契约待双方确认。 [任务清单](./tasks.md) · [验证记录](./verification.md)
- **关联** [已确认规格](./spec.md) · [开发规划](../../../docs/architecture/proposals/kunlian-workflow-development-plan.md#workflow-run-control) · [版本契约](../release-contract.md) · [架构约束](../../../docs/constitution.md)

## 1. 目标与范围

在昆联反向调用的原 `session_id` 上提供取消、终态查询和按序续读。复用 F122 的固定版本、幂等受理和运行记录，复用 F123 的原生文本等待点、答复回执与跨 Worker 恢复。参考 F126 的停止先裁决和迟到结果隔离语义。 [固定版本设计](../122-kunlian-workflow-invocation/design.md) · [原生交互设计](../123-kunlian-workflow-interaction/design.md) · [普通长任务设计](../126-kunlian-agent-long-task-resume/design.md)

首轮验收固定版本纯文本与单次原生文本表单，用可控节点复现执行中取消。推送式事件、回调、完整追踪明细、管理员代管、跨平台权限配置和嵌套 Agent 的远端取消分别进入后续范围。

## 2. 关键约束与架构核对

- 运行控制仍归 Workflow 领域。现有 `workflow_kl_run` 保持会话和终态权威，同一事务提交状态及事件。Mock 采用现有 `material` JSON 的版本化子记录，首轮无需新表、字段、索引或存量迁移。
- 隔离应用与 Worker 显式装配首轮能力。新受理会话按服务端装配写入运行控制标记，旧会话保留原合同和版本。原启动幂等键、摘要及回执语义继续生效，重放不改变既有会话的控制能力。已受理的会话沿用原固定版本及各阶段期限。
- 遵循 C1–C8、INV-27 和 INV-30。入口、应用服务、仓储分工保持现状。双库采用现有 `JsonType`、租户作用域、行锁与条件更新，事件在应用侧裁剪。授权调用复用 F048，Mock 操作级权限只在测试装配中验证。候选错误暂沿用安全分类，正式错误码按 C5 登记。凭据只通过受信适配器注入，跨进程权威状态来自数据库。本期为后端链路。 [架构约束](../../../docs/constitution.md) · [版本契约](../release-contract.md)

## 3. 关键设计决策

| 决策 | 备选及取舍 | 采用方案与复核条件 |
| --- | --- | --- |
| D-01 · 取消与结果的裁决 | 原浏览器的进程内停止能通知活跃实例，跨 Worker 时需要额外路由和持久状态。Redis 停止标记可以唤醒执行者，单独使用时无法与 SQL 结果原子裁决。 | 复用运行行的行锁和条件更新。F122/F123 已用同一行仲裁领取、答案、超时和结果。将来接入嵌套 Agent 时，远端取消增加独立对账，Workflow 终态仍由该运行行裁决。 |
| D-02 · 执行中取消与补偿 | 强制终止 Celery 任务会牵涉共享执行进程，且无法证明业务副作用状态。立即显示已取消则会掩盖仍在执行的节点。 | 保存取消受理，Worker 在节点入口和结果提交处复核运行资格。原 Worker 失联时沿用原执行截止，由其他 Worker 补记本地取消终态。若正式场景需要更短的失联感知，另评估心跳和租约。 |
| D-03 · 事件存储和消费 | 独立事件表支持更长历史与索引，需要增加表结构和清理。现有 Redis 事件流可低延迟通知，消费及过期后无法提供稳定重读。 | 首轮事件只记录会话生命周期，按序保存在运行行的有界日志中，与状态一起提交。用 HTTP 分页查询。节点级高频事件、长时间追溯或行大小压测超预算时，重评独立日志与推送。 |
| D-04 · 权限与响应投影 | 全部信息共用一个摘要会把结果及追踪权限绑到状态读取上。新增正式 RBAC 动作依赖双方授权矩阵与版本约束。 | 复用已核验自然人、接入方和当前 Workflow `use`，在应用层分别裁决取消和各读操作。Mock 测试可独立允许或拒绝操作。正式委托和动作映射确认后再接线。 |

## 4. 当前链路与拟接入点

现有候选入口受理固定版本并持久化 `QUEUED`，提交后向 Celery 投递。Worker 用可信租户头读取原会话、核验原用户并按阶段领取。图到达文本表单时保存快照和 `WAITING_INPUT`。答案与回执同事务进入 `RESUME_QUEUED`，随后由 Worker 以同一版本恢复。现有查询在会话归属及 Workflow `use` 复核后返回状态，按阶段提供表单或最终结果。

### 4.1 取消裁决与期限

| 行锁内读到的状态 | 裁决和写入 |
| --- | --- |
| `QUEUED`、`WAITING_INPUT`、`RESUME_QUEUED`，期限有效 | 直接提交 `CANCELLED`。同一事务依次记录 `CANCEL_ACCEPTED`、`CANCELLED`。旧派发不可领取，新答案不再受理。已受理答案允许按原键、原内容查询原回执，回执重放无派发。 |
| `RUNNING`、`RESUMING`，期限有效 | 提交 `CANCEL_REQUESTED` 与 `CANCEL_ACCEPTED`，保留原 `claim_id` 和执行截止供确认。关闭新节点准入、等待点提交、答案推进及成功／失败结果写入。 |
| `CANCEL_REQUESTED` | 返回当前受理事实。原领取者退出图时可用同一领取标识确认。原截止已到时，补偿 Worker 可以确认，无需重新领取执行。确认只追加一次 `CANCELLED`。 |
| 未取消的活跃状态已到当前阶段截止 | 用锁内当前时间按原阶段超时收敛，返回同一超时终态。到期判定为 `now >= deadline_at`。已提交的取消受理优先完成取消确认。 |
| 已提交 `SUCCEEDED`、`FAILED` 或 `CANCELLED` | 返回原终态。成功结果、完成时间、保留期与已有回执均保持原值。重复取消不写新事件。 |

取消、领取、等待点保存、答复受理、成功／失败和超时都通过同一运行行裁决。仓储在锁内重查状态、可信归属、期限及必要的领取标识，将新状态和相应事件放入同一次条件 `UPDATE`。条件更新成功后两者一并提交，发生冲突时重读已提交的结果。SQLite Mock 用独立连接和条件更新验证竞争，数据库锁行为由受控双库验证。

节点准入以 `_node_runner` 调用检查时的运行状态为界。检查通过的节点可以完成当前安全边界内的操作，之后的节点必须再次核验。恢复时在装载等待点与答案前检查一次，进入恢复后的第一个节点和输出适配节点时仍要复核。回调只暂存文本。最终完成方法在同一事务检查原领取，遇到 `CANCEL_REQUESTED` 时按取消确认处理。成功结果只在原领取有效、运行未取消且未到期时提交。等待点保存被拒绝的 Worker 也走该确认路径，覆盖旧 `pause_graph` 分支提前返回的情形。

### 4.2 跨 Worker 补偿

沿用 `WorkflowInvocationService.reconcile` 的连接范围与 `RunRepository.reconcile` 的有界扫描。在处理阶段超时前独立扫描已达原执行截止的 `CANCEL_REQUESTED`，按截止与会话排序，锁内核对状态和接入方后确认取消。该补偿只提交终态，使用同一会话和原固定版本。独立批限保证取消确认与原排队补投都能推进。

| 故障窗口 | 恢复结果 |
| --- | --- |
| 取消事务提交后响应丢失 | 重试或查询原会话读取同一取消记录。取消受理和终态各保留一个事件。 |
| Worker 收到取消后退出，或未观察到取消 | 到原执行截止后由其他 Worker 收敛。补偿使用可信租户、接入方和会话范围，未取得新的执行资格。 |
| 取消前的队列消息迟到或重复送达 | 领取重查阶段和交互标识，已取消或正在取消的记录直接退出。常规排队、恢复待领取的补投继续沿用原流程。 |
| 等待点或输出与取消竞争 | 等待点、答复或输出只有在对应状态仍有效时才提交。若答复先受理，随后取消能阻止尚未启动的恢复。若已领取恢复，按执行中取消收敛。 |

队列继续使用会话、阶段、必要的交互标识及可信租户头。身份、版本和执行材料从原记录读取。首轮取消确认无额外消息投递依赖，原 Worker 边界观察加持久扫描即可覆盖漏唤醒。权限服务异常时，面向调用者的取消与读取关闭。补偿 Worker 只依据已授权且已落库的取消事实完成本地收尾。

### 4.3 事件日志与保留期

新会话在 `material.run_control` 写入 `format=1`、服务端生成的 `trace_id`、`last_seq`、`pruned_through`、事件列表及最小取消回执。`QUEUED` 受理和首事件同事务写入。随后只有成功的状态迁移才生成事件。事件字段为 `seq`、`kind`、`status`、`occurred_at`，其中序号为正整数、时间为 Unix 秒。各会话从 1 递增，事件时间沿用仓储时钟并保持不回退。会话 ID 和固定版本由响应外层提供。

| 事务 | 事件种类 |
| --- | --- |
| 受理和领取 | `ACCEPTED`、`STARTED` |
| 文本等待和恢复 | `WAITING_INPUT`、`RESUME_QUEUED`、`RESUMED` |
| 取消和结束 | `CANCEL_ACCEPTED`、`CANCELLED`、`SUCCEEDED`、`FAILED`；超时沿用 `FAILED` 及状态接口的原安全原因 |

按时间与条数保留连续后缀。Mock 默认保留 32 条事件及 900 秒可读窗口，测试用可控时钟和更小页长覆盖过期与跨页。写入阶段随状态更新裁剪超量前缀，记录最后移除的序号。读取阶段按一次仓储时钟过滤已过期前缀，取较大的裁剪位置作为有效下界。查询和重读均不消费日志。到终态时沿用 F122/F123 对图、输入、答案和快照的清理，仅保留结果、最小答复回执及 `run_control`。原 `expires_at` 到期后，现有清理流程一并移除结果和控制材料，幂等摘要仍按原约定处理。

## 6. 候选契约与权限

候选路径以隔离应用的 `/api/v2/kunlian/workflow-runs/{session_id}` 为基准。沿用统一响应封装和 `Cache-Control: no-store`。会话、版本及身份来自原记录和可信依赖，业务请求只提交接口允许的查询参数。

| 接口 | Mock 请求和响应 |
| --- | --- |
| `POST …/{session_id}/cancel` | 空请求体。取消幂等范围为原会话及原归属，重复请求无需另建键。`202` 表示已受理、待确认，`200` 表示已终结，包括即时取消或原有终态。返回 `session_id`、`workflow_version_id`、`status`、`cancel_state`。取消标记为 `ACCEPTED`、`CONFIRMED` 或 `ALREADY_TERMINAL`。查询已有成功结果继续走结果视图。 |
| `GET …/{session_id}` | 默认保留 F122/F123 合同。已有表单或结果只在通过相应授权时返回。候选 `view=status` 返回会话、版本、状态、安全失败分类及适用的取消状态。状态与事件均获准时附 `resume_after`，它来自同一次快照的最新序号。 |
| `GET …/{session_id}?view=result` | 成功时返回会话、版本和冻结 Schema 校验后的 `output`。尚无成功输出时返回候选 `409 RESULT_NOT_AVAILABLE`。 |
| `GET …/{session_id}?view=trace` | 仅返回会话标识和已授权、可信记录的 `trace_id`。首轮样例没有绑定远端 Agent，因而没有远端 Run 或 Tool Call 标识。 |
| `GET …/{session_id}/events?after=0&limit=20` | `after` 为最后确认序号，初次为 0，`limit` 默认为 20 且最多 32。按 `seq > after` 升序取页，返回会话、版本、`events`、`next_after`、`has_more`。空页沿用原 `after`。起点低于保留下界时返回 `409 EVENT_CURSOR_EXPIRED`。超过本会话最新序号时返回 `422 INVALID_INPUT`。 |

客户端按 `session_id` 和 `seq` 去重，业务处理成功后推进 `after`。遇到过期游标，通过授权状态视图读取当前快照和 `resume_after` 后重建位置。恢复请求可见范围以每次请求的权限为准。分页状态和事件取自同一会话快照，后续追加事件由下一次查询读取。

授权分两步。先核验可信租户、接入方、自然人和当前 Workflow `use`，复用既有真实用户解析及对上游权限上下文的隔离。再核验本次操作需要的 `cancel`、`status`、`result`、`events`、`trace` 或 `interaction` 能力。首轮操作粒度由隔离测试策略裁决，默认装配只面向原实际用户，正式授权映射待确认。默认旧查询需要当前响应涉及的全部访问能力，仅获状态权限的调用方可显式读取 `view=status`。本次查询所需的权限结果未知时，整次查询失败。取消回执只含操作需要的摘要。Worker 执行前复核原用户和 Workflow 权限，补偿确认仅收敛已受理取消。

未认证返回 `401`，归属或权限拒绝统一按 `404 SESSION_NOT_FOUND`，权限或存储不可用返回 `503 UNAVAILABLE`。在完成授权后检查会话及事件期限。授权后访问未带运行控制标记的旧会话时，旧合同照常，新增操作返回候选 `409 CONTROL_UNAVAILABLE`。错误、日志和事件仅使用安全枚举和必要关联，表单答案、执行材料和结果正文通过各自已授权路径处理。

| 内部依赖 | 复用与变更影响 |
| --- | --- |
| F122/F123 `submit`、`query`、`answer` 和 `RunRepository` | 新增候选运行控制方法，原启动摘要、会话归属、答复回执和已受理固定版本保持兼容。既有仓储调用方依赖提交后才投递。 |
