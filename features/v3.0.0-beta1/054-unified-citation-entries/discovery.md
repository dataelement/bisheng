## 1. 结论先行

需求描述的能力**约 70% 已经在线上跑**。真正的新增工作只有四块，且彼此独立、可并行：

| # | 工作项 | 规模判断 |
|---|---|---|
| 1 | **频道文章 AI 问答接入溯源** | 主要工作量。零基础，且引入**第三种来源类型**（现只有知识片段 / 网页），要扩来源类型枚举 + 新增文章来源载荷 + 解析服务加分支 + 前端图标与「打开原文」入口 |
| 2 | **灵思任务模式接入** | 设计已定稿（F047），代码未落。按设计前端零改动 |
| 3 | **导出件烘焙可见引用** | 独立一块。导出的 Word / PDF 里现在是**不可见控制字符**，不处理即丢失或乱码；需在导出转换前把标记烘焙成可见 `[n]` + 文末参考资料 |
| 4 | **「来源已失效」态** | 小。现在只有「暂无权限」和一个笼统的加载失败，二者未区分 |

需求原文中「本期补齐**知识空间的空间、文件夹和单文件问答**」一句**已过期** —— 该三个入口后端前端均已打通（见 §2）。

## 2. 代码基线事实（2026-09-07 核实）

### 2.1 已打通的入口

| 入口 | 后端登记来源 | 提示词带引用规则 | 前端渲染角标 |
|---|---|---|---|
| 日常模式（工作台 Agent） | ✅ | ✅ 前端默认系统提示词自带 | ✅ |
| 助手 Assistant | ✅ | ✅ | ✅ |
| 工作流 RAG / Agent / 知识库检索 / 工具节点 | ✅ | ✅ 节点默认提示词模板自带 | ✅ |
| **知识空间：空间 / 文件夹 / 单文件问答** | ✅ | ✅ 后端 `knowledge_space.yaml` 自带 | ✅ 三个入口共用同一渲染组件 |
| **频道文章 AI 问答** | ❌ 完全没有 | ❌ | ❌ |
| **灵思任务模式** | ❌（F047 未实现） | ❌ | 组件已具备，无标记可渲染 |

### 2.2 已有的通用机制（需求要点已满足）

- **统一引用项 / citation_key**：来源登记、Redis 运行时缓存（TTL 30 天）、完成时落库三段链路已存在，各入口共用同一批 helper。
- **消息关联幂等**：`message_citation`（`citation_id` 唯一）+ `message_citation_relation`（`message_id` × `citation_id` 唯一），写入走 `ensure_*` 语义，重复保存不产生重复行。
- **编号规则**：前端按答案中**首次出现顺序**编号，同一 citation_key 复用同一编号 —— 与需求一致。
- **历史消息恢复**：前端不依赖任何推送，直接从答案正文里的隐藏标记惰性解析编号再批量换详情；因此历史消息、分享页天然带角标。缓存过期后回落数据库。
- **幻觉角标防护**：落库前会把「注册表里查无此号」的标记从正文擦除，避免渲染出点开即 404 的角标。
- **权限过滤**：解析来源详情时按查看者逐文件跑 `view_file`（INV-7 执行点），`per_user` 档无权即整条不返回，`shared` 档保留元信息但不发预览 / 下载链接。

### 2.3 反直觉事实 / 已知缺口

| # | 事实 | 影响 |
|---|---|---|
| 1 | **引用规则文本不在后端代码里**，住在前端默认提示词模板（工作流节点模板、日常模式默认系统提示词）与后端 `knowledge_space.yaml` 里 | 管理员改写提示词、或存量应用建于模板更新之前 → 角标**静默消失**。不是知识空间独有，所有模式同病 |
| 2 | 后端有兜底函数 `prompt_has_citation_rules`（检测提示词缺规则则自动补），**三处 import 了但一次都没调用，是死代码** | 「自动兜底」实际不存在 |
| 3 | **匿名 / 分享场景完全跳过权限过滤** | 分享出去的会话，任何人都能点开角标看来源详情，并拿到临时签名的预览 / 下载链接。属越权口径 —— 已裁定收紧，见 §4.1 |
| 4 | 来源类型枚举当前只有「知识片段」「网页」两种 | 频道文章需要扩枚举 + 新载荷 + 解析分支 + 前端图标 |
| 5 | 前端「暂无权限」为硬编码中文 | 违反 i18n 规则，需补三语 |
| 6 | 无「来源已失效」状态 | 需求要求区分，需新增 |
| 7 | **平台端与用户端各有一套约 2000 行的角标实现**，已在漂移 | 例：用户端修过「复制消息时剥离隐藏标记」，平台端没有 → 从平台端复制答案会带出控制字符 |
| 8 | **工作流输入节点的临时文件已经在出角标，但点不开**（详见 §2.5） | 临时文件的 documentId / knowledgeId 是字符串（UUID / 工作流 id），来源载荷要求整数的知识库文件 id → 转换落空 → 无预览链接、无下载链接、无页面定位。角标显示得出文件名和摘要，一点开是空的 —— 比没有角标更糟 |

### 2.5 临时文件 / 临时上下文的溯源现状

需求范围边界写明「**临时上下文**保持无角标」。核实三条临时来源链路：

| 链路 | 现状 | 能否支持溯源 |
|---|---|---|
| **日常模式上传附件** | 文件解析成文本后**整段拼接塞进提示词**（`<uploaded_file_content>`）。中途虽切片，但立即 `"".join()` 拼回，元信息只剩文件名 | **不能**。模型手里没有片段颗粒，无号可发。要支持须改为「临时文件也走检索」，属机制变更 |
| **工作流输入节点临时文件** | 进临时向量库，Agent 节点检索它时**走的是同一套打标链路** → 已经在发角标、落库、渲染 | **半残**。见 §2.4 缺口 8：能显示、点不开 |
| **灵思上传附件** | 按需翻阅工作区文件，不走检索工具 | **不能**。F047 设计已列为「候选 Phase 1.5」明确延后 |

### 2.4 两个前端的组件库现状（回答「后面都用 packages 公共库」）

| 维度 | platform | client |
|---|---|---|
| 公共组件库 `@bisheng/ui` | **未接入**（`packages/ui/AGENTS.md` 明载 "platform has not adopted it yet"） | 已接入；**溯源角标就是共享 Badge 的 `citation` 形态**，设计规范已落地 |
| Tailwind 主题 | 自有完整 theme，**且 `important: true`（全局 !important）** | `presets: [@bisheng/ui/tailwind-preset]` |
| 设计变量 `tokens.css` | 未引入 | 已引入 |
| 图标包 `bisheng-icons` | 未安装（公共组件依赖它） | 已安装 |
| Markdown 渲染器 | react-markdown **10** | react-markdown **9** |
| 状态 / 请求 / 别名 | Zustand · react-query v3 · `@/` | Recoil · @tanstack/react-query v4 · `~/` |

两条硬约束：

- **`@bisheng/ui` 有明文契约：不得包含状态管理、HTTP、i18n key、路由。** 因此角标的「拿编号换详情」逻辑放不进该包 —— 若要共享须另开包，或只共享纯解析函数。
- **平台端接入公共主题是影响全站的基建**（要处理 `important: true` 与现有 theme 去重），不属于本 Feature 范围。

## 4. 已裁定的口径（2026-09-07，用户确认）

### 4.1 分享页权限：收紧

**裁定**：来源详情一律按**当前登录用户**判断权限，无权限即置灰。匿名访问等同无权限。

**连带影响**：分享出去的会话，角标显示为不可点的灰色 + 「暂无权限查看该来源」。该文案需补三语。
若后续产品希望分享页仍可查看来源，需另行设计「按分享者权限解析」的方案，不在本期。

### 4.2 提示词被覆盖导致无角标：维持现状

**裁定**：不做自动兜底。管理员改写提示词后该入口不再出角标，属预期行为。

**配套建议**：在提示词编辑入口加一行说明，否则会被当作缺陷反馈回来。

### 4.3 平台端角标：维持现有拷贝

**裁定**：本期不做组件合并，平台端继续使用自己那份实现。

**理由**：用户端已在公共组件库上，平台端追平需先完成公共主题接入（影响全站、含 `important: true` 冲突处理），属独立基建，不纳入本 Feature。

### 4.4 工作流临时文件角标：关掉

**裁定**：在工作流临时文件这条检索链路上**停止登记来源**，不再产生角标。

**理由**：临时文件本就是一次性的、无稳定定位 ID，与需求「临时上下文保持无角标」的口径一致；渲染一个点不开的角标比不渲染更糟。

### 4.5 临时文件溯源：下一版需求

**裁定**：日常模式附件、工作流临时文件、灵思上传附件的溯源能力**本期全部不做**，留待下一版单独立需求。本期只做 §4.4 的「关掉」。
