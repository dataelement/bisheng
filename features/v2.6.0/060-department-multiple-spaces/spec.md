# Feature: F060 一个部门绑定多个知识空间

**Feature ID**: `060-department-multiple-spaces`  
**Status**: Implemented — 定向验证通过

## 1. 概述

当前 `department_knowledge_space` 同时对 `department_id` 和 `space_id` 设置唯一约束，导致一个部门只能绑定一个知识空间。部门 3 与其子部门 18 已存在旧团队知识库绑定，因此新的部门知识库无法调整到这些部门。

本特性把关系调整为“一个部门可绑定多个知识空间，一个知识空间仍只绑定一个部门”。同时将管理员同步、自由库迁移和外部文件同步从单值读取改为完整集合或确定性解析，避免多绑定后随机选择目标。

## 2. 已确认业务规则

| ID | 规则 |
|---|---|
| BR-001 | 一个部门可以绑定多个部门知识库，旧团队知识库绑定可同时保留。 |
| BR-002 | 一个知识空间仍只能绑定一个部门，`space_id` 唯一约束保留。 |
| BR-003 | 部门管理员变化同步该部门全部绑定知识空间。 |
| BR-004 | 自动选库优先当前部门，再沿父部门回退；同一部门优先部门层级空间。 |
| BR-005 | 同一优先级多候选时明确失败，不按数据库顺序、ID 或时间随机选择。 |
| BR-006 | 自由库迁移与外部文件同步使用同一选择规则。 |
| BR-007 | 现有绑定数据不解绑、不转换、不删除。 |
| BR-008 | 本特性不自动执行真实数据库 migration。 |

## 3. 用户可见行为

### 3.1 编辑部门知识库

系统管理员选择一个已经绑定其他空间的部门并保存时：

- 当前知识库成功切换到目标部门。
- 目标部门原有知识空间保持不变。
- 当前知识库的层级仍为“部门知识库”。
- 新旧部门默认 viewer 和管理员 manager 权限继续按 F058 规则迁移。

### 3.2 部门管理员变化

新增或移除部门管理员时，该部门全部绑定知识空间执行既有管理员成员同步。手工成员、creator 保护及角色恢复规则不变。

### 3.3 自动迁移与文件同步

```text
当前部门候选
  ├─ 1 个部门层级空间 → 选择
  ├─ 多个部门层级空间 → 冲突
  ├─ 无部门层级、1 个旧绑定 → 选择
  ├─ 无部门层级、多个旧绑定 → 冲突
  └─ 无任何候选 → 查找父部门
```

冲突时：

- 自由知识库删除迁移被阻止。
- 外部文件同步在文件落库前失败。
- 返回明确提示，不伪报成功。

## 4. 数据库契约

变更后约束：

| 对象 | 约束 |
|---|---|
| `department_knowledge_space.department_id` | 非唯一普通索引，可重复 |
| `department_knowledge_space.space_id` | 唯一，不可重复 |
| 现有数据 | 原样保留，不做 DML |

upgrade 删除 `uk_dks_department_id`。downgrade 只有在不存在重复部门绑定时恢复该约束；存在重复时明确终止并要求先进行业务清理。

## 5. API 与错误契约

- 现有知识库创建、绑定、编辑和列表 API 路径及成功响应不变。
- `DepartmentKnowledgeSpaceExistsError(18002)` 仅继续用于知识空间本身重复绑定等真实冲突，不再用于“部门已有其他知识库”。
- 新增 `DepartmentKnowledgeSpaceAmbiguousError(18004)` 表达自动目标空间不唯一。
- Open Endpoints 将该错误转换为既有 `FilelibSyncConflictError(19904)`。

## 6. 验收摘要

- 部门 3 在保留 `space_id=175` 的同时可绑定 `space_id=204`。
- 部门 18 在保留 `space_id=185` 的同时可绑定其他空间。
- 一个 `space_id` 仍不能存在两个绑定行。
- 管理员变化覆盖同一部门所有空间。
- 自由库迁移与文件同步不再调用单值 `.first()` 选择空间。
- 唯一候选正常执行，多候选明确失败且无写入副作用。
- MySQL/DM8 迁移实现不使用方言专有元数据 SQL。

## 7. 范围外

- 多部门共享同一知识空间。
- 主知识库配置、排序或选择 UI。
- 自动数据清理或生产库升级。
- 修改知识库内容、层级、审批配置和手工成员。
