# Feature: 企业微信单点登录（WeCom SSO，无网关）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。How 一律不写在这里，见 [design.md](./design.md) 与 [tasks.md](./tasks.md)。
>
> **前置步骤**：Spec Discovery 已于 2026-11-16 完成（代码调研 + 三轮范围确认），本文件据其编写。

**关联 PRD**: 无新增 PRD（v3.0.1 为补丁线）；链路背景见 `docs/architecture/11-gateway.md` §5（商业网关同类流程）
**优先级**: P0
**所属版本**: v3.0.1
**依赖**: F009 / F021（企微组织同步配置与 provider）、F014（SSO login-sync 语义）、F048（部门权限投影）

> **Spec Discovery 决议（2026-11-16，用户逐项确认，供后续核对偏离）**
>
> | 决议 | 内容 |
> |---|---|
> | D1 | 部署形态：**无网关**，由 BiSheng 后端自建 OAuth（不依赖商业版 Java 网关） |
> | D2 | 登录场景：企微内置浏览器静默登录 **+** PC 浏览器扫码登录 |
> | D3 | 前端入口：platform 登录页 **+** client 用户端（从 client 发起、登录后回跳 client 原页面） |
> | D4 | 凭据来源：**复用**组织同步的企业微信配置，不新增凭据管理面 |
> | D5 | 准入：企微成员首登**自动建号**（默认角色）；平台空库时首登者成为超管 |
> | D6 | 部门：登录时带企微部门；部门未同步时**降级**到临时访客部门并告警，不阻断登录 |
>
> **范围边界**
> - **本次纳入**：
>   - 无商业网关部署下，由 BiSheng 后端自行完成企业微信 OAuth 授权与回调
>   - 两种登录场景：企业微信内置浏览器静默登录、PC 浏览器扫码登录
>   - 两个前端入口：platform（管理/搭建台）登录页与 client（用户端）登录流程；client 不自建独立登录页，入口由统一登录页承载并在登录后回跳 client
>   - 复用组织同步中的企微凭据；复用既有 SSO 用户/部门/租户/JWT 语义
>   - 登录审计、失败提示、一次性 state 防重放
> - **本次明确排除**：
>   - 自定义 OAuth2 / LDAP / 钉钉 / 飞书 登录（各自另起 feature）
>   - 企业微信「服务商代开发」第三方应用扫码（本期只支持企业自建应用 agentId）
>   - 单点退出（企微侧登出联动、IdP 全局登出）
>   - 新增企微凭据管理页或新的配置文件项（凭据唯一来源是组织同步配置，见 INV-45）
>   - 移动端原生 App / 企微 JS-SDK 内嵌，只覆盖浏览器场景
>   - 刷新令牌、会话续期机制改造（沿用现有登录态过期策略）

## 1. 用户故事

**A. 企业微信内的终端用户**
作为 **通过企业微信工作台进入 BiSheng 的员工**，
我希望 **打开即已登录，不用再输一次账号密码**，
以便 **在企微里直接开始使用，不中断工作流**。

**B. PC 浏览器的终端用户**
作为 **在 PC 浏览器访问 BiSheng 的员工**，
我希望 **点一下「企业微信登录」用企微扫码就进来**，
以便 **不必记 BiSheng 的独立密码，账号与本人员工身份天然对应**。

**C. 平台管理员**
作为 **平台管理员**，
我希望 **只在我已配置好企微组织同步之后，登录入口才出现，且凭据只维护一处**，
以便 **不用为登录再配一套密钥，也不会因为配置不一致产生两套用户。**

## 2. 验收标准

> P0 feature，使用 EARS 句型。AC-ID 在本特性内唯一，`tasks.md` 通过 `覆盖 AC: AC-NN` 追溯。

### 2.1 入口可用性与凭据来源

- **AC-01** — WHEN 管理员已在「组织同步」中维护了**唯一一条启用中的**企业微信配置, THE SYSTEM SHALL 在 platform 登录页与 client 登录流程中显示「企业微信登录」入口。
- **AC-02** — IF 不存在启用中的企业微信配置, THEN THE SYSTEM SHALL 隐藏所有企微登录入口；对直接访问登录地址的请求返回错误码 19330（企微登录未配置），不得返回 500 或静默跳转。
- **AC-03** — WHERE 组织同步存在**多条**启用中的企业微信配置, THE SYSTEM SHALL 视为不可判定并关闭企微登录入口（错误码 19331），不得任选一条使用。
- **AC-04** — THE SYSTEM SHALL 只从组织同步中的企业微信配置读取企业标识、应用密钥与应用 AgentId 三项凭据，登录链路不提供、也不接受第二套凭据配置。

### 2.2 企业微信内置浏览器静默登录

- **AC-05** — WHEN 未登录用户在企业微信内置浏览器中通过企微侧入口打开 BiSheng, THE SYSTEM SHALL 静默完成企微授权，无需用户输入任何账号密码即建立登录态。
- **AC-06** — WHEN 静默授权得到的企微 userid 在平台尚不存在, THE SYSTEM SHALL 自动创建账号并授予默认角色，然后完成登录。
- **AC-07** — WHEN 静默授权得到的企微部门已同步到平台, THE SYSTEM SHALL 把用户绑定到该部门（主部门语义不变）并派生其 leaf 租户。
- **AC-08** — IF 静默授权得到的企微部门尚未同步到平台, THEN THE SYSTEM SHALL 仍然允许登录，把该用户落到临时访客部门，并写一条 WARNING 级日志（内容包含企微 userid 与未同步的部门标识），不阻断登录结果。

### 2.3 PC 浏览器扫码登录

- **AC-09** — WHEN 用户点击「企业微信登录」入口, THE SYSTEM SHALL 展示企业微信扫码登录页；用户扫码确认后回到 BiSheng 并处于登录态。
- **AC-10** — WHEN 扫码得到的企微 userid 在平台尚不存在, THE SYSTEM SHALL 按 AC-06 的同一规则自动建号并登录。
- **AC-11** — IF 平台当前不存在任何用户, THEN THE SYSTEM SHALL 把第一个成功登录的企微用户设为超管；此后任何企微首登用户只获得默认角色（该引导规则只生效一次）。

### 2.4 账号准入与并发

- **AC-12** — IF 企微用户已被停用或删除, THEN THE SYSTEM SHALL 拒绝登录并返回可读提示（沿用既有禁用用户错误码），不得创建新账号绕过停用。
- **AC-13** — IF 同一企微用户并发发起多次登录, THEN THE SYSTEM SHALL 只完成一次账号/部门写入，其余请求返回「登录进行中」（错误码 19311）。
- **AC-14** — IF 企微 userid 与平台已有的其他来源账号存在绑定冲突, THEN THE SYSTEM SHALL 按既有跨来源冲突规则处理并拒绝含糊合并（错误码 19304）。

### 2.5 登录态与安全

- **AC-15** — WHEN 企微授权成功, THE SYSTEM SHALL 由服务端下发登录态并让后续请求携带；最终跳转 URL 的 query / hash / path 中不得出现可复用的访问令牌。
- **AC-16** — THE SYSTEM SHALL 为每次授权发起生成一次性 state，并在回调时校验；state 缺失、过期或不匹配时拒绝登录（错误码 19332）。
- **AC-17** — IF 回调携带的授权码已被使用、已过期或无效, THEN THE SYSTEM SHALL 拒绝登录并提示用户重新发起（错误码 19333）。
- **AC-18** — IF 登录在任一环节失败, THEN THE SYSTEM SHALL 把用户送回登录页并显示可读原因，不得停在回调地址或空白页。

### 2.6 回跳与可观测

- **AC-19** — WHEN 未登录用户访问 client 的页面, THE SYSTEM SHALL 引导其到统一登录页（沿现有跨应用契约），并在企微登录完成后把用户送回其原本访问的 client 页面；client 不自建独立的线上登录页。
- **AC-20** — WHEN 一次企微登录成功, THE SYSTEM SHALL 记录一条登录审计（含企微 userid、来源=wecom 与来源 IP）以及一条触发类型为「SSO 实时登录」的组织同步日志。
- **AC-21** — IF 企微接口返回错误（凭据错误、通讯录权限不足、超时等）, THEN THE SYSTEM SHALL 记录企微 errcode 与描述，并以错误码 19334 告知用户「企业微信授权失败」，不得静默失败。

### 2.7 兼容与既有行为不变

- **AC-22** — THE SYSTEM SHALL 保持账号密码登录、既有 SSO login-sync 链路与商业网关链路的现有行为不变；新增链路不得改变它们在无配置时的表现。
- **AC-23** — WHERE 多租户开启, THE SYSTEM SHALL 按既有规则把登录后的用户限定在其 leaf 租户上下文内。
- **AC-24** — WHERE 前端请求由商业版 Java 网关接管, THE SYSTEM SHALL 仍然由网关提供企微登录（不显示后端自建入口、不改写网关链路）；后端自建企微登录只在网关不存在的独立部署中生效，两条链路不并存。
- **AC-25** — THE SYSTEM SHALL 保持既有「管理员用户名」配置的语义不变：该配置只参与账号密码登录与旧 SSO 入口的超管判定，不参与企微首登的超管判定（企微首登只按 AC-11 的「平台空库」规则）。

## 3. 边界情况

- 用户在企业微信授权页点「取消」：按 AC-18 回到登录页并提示已取消，不记为登录失败告警。
- 回调地址被用户收藏后重复访问（code 已消费）：按 AC-17 拒绝并引导重新登录，不得复用上一次登录态。
- 登录过程中管理员停用了企微组织同步配置：本次登录按 AC-02 失败；已登录用户的既有会话不受影响。
- 企业微信返回的 userid 大小写/前后空格差异：视为同一企微用户，不得产生两个平台账号。
- 用户在扫码页停留超过授权码有效期：按 AC-17 处理。
- 平台处于「密码已过期需改密」状态的企微用户：沿用既有改密强制流程，不因走企微登录而跳过。
