# Feature: 个人技能上传与技能中心

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答做什么、验收标准、不做什么。实现决策在 [design.md](./design.md)。

**关联 PRD**: 《0930 中粮需求响应》「个人 Skill 上传与技能中心」
**优先级**: P1
**所属版本**: v3.0.0-beta3
**依赖**: 无（本版本内）。运行时仍走既有灵思技能的启用与物化。每次任务把每个候选的整包拷进会话；勾选只在提示词里标明「用户选中了这个技能」

> **范围边界**
> - **本次纳入**：
>   - 用户导入已有技能文件（`.md` / `.zip` / `.skill`），服务端保存，换设备仍在
>   - 个人技能的列表、搜索、启用/停用、删除
>   - 技能中心把「平台分配给该用户的技能」和「该用户自己的技能」放在同一候选目录
>   - 每次任务把每个候选的整包拷进会话；勾选只在提示词里标明「用户选中了这个技能」
> - **本次明确排除**：
>   - 用 Kimi 创建技能、把 Office 文件转成技能（产品明确不做）
>   - 个人技能分享、公开到技能市场（产品明确不做）
>   - 只存在浏览器本地、不落服务端的预览存法。那是前端试验，不是本需求的交付形态

---

## 1. 用户故事

作为 **使用灵思任务的业务用户**，
我希望 **把自己已有的技能文件传到平台，并在技能中心里和平台分配给我的技能一起看到**，
以便 **换一台电脑还能用，任务也能从这些技能里自动选用**。

作为 **同一租户里的其他用户**，
我希望 **看不到、也调不到别人上传的个人技能**，
以便 **个人技能不会变成未经授权的共享能力**。

## 2. 验收标准

### 2.1 上传与保存

- **AC-01** — WHEN 用户上传一份通过校验的 `.md`、`.zip` 或 `.skill`，且该文件内含合法的 `SKILL.md`，THE SYSTEM SHALL 把技能保存到当前用户名下，并在技能中心「我的技能」中列出。
- **AC-02** — WHEN 同一用户在另一台浏览器再次打开技能中心，THE SYSTEM SHALL 列出 AC-01 已保存的技能，不依赖本机缓存。
- **AC-03** — IF 扩展名不是 `.md`、`.zip`、`.skill`，或压缩包内没有合法 `SKILL.md`，THEN THE SYSTEM SHALL 拒绝保存，技能中心不出现新条目。
- **AC-04** — IF `SKILL.md` 超过 1 MiB（1048576 字节），或压缩包内条目超过 1000 个，或上传体超过 50 MiB（52428800 字节），或解压后总大小超过 200 MiB（209715200 字节），THEN THE SYSTEM SHALL 拒绝保存并说明超出的是哪一条限制。四条限制各用一个错误码，前台显示对应的那一句，并写出这条限制的具体数值。
- **AC-05** — WHERE 多租户开启，THE SYSTEM SHALL 只在当前租户内保存和列出该用户的个人技能。

### 2.2 技能中心与隔离

- **AC-06** — WHEN 用户打开技能中心，THE SYSTEM SHALL 提供「我的技能」和「技能广场」两个页签。「我的技能」是一个列表，分成「我创建的」和「企业提供」两组：个人技能可以启停，更新和删除在详情里；企业技能始终启用。每一行展示名称、来源和一行用途说明，点击整行打开详情。「技能广场」只展示本租户已启用的企业技能，为只读卡片，点击卡片打开详情。页签数量分别为个人技能个数和企业技能个数。
- **AC-07** — WHEN 用户在当前页签搜索，THE SYSTEM SHALL 只筛选该页签中的名称、技能标识和用途说明，不把其他用户的个人技能算进来。切换页签时清空搜索词。
- **AC-08** — IF 用户请求另一用户的个人技能内容、下载或选用，THEN THE SYSTEM SHALL 按不存在拒绝（11053），不调用统一授权。响应中不出现名称、正文或对象地址，也不表明这条技能是否存在。归属是本人的详情、读取文件、更新、启停和删除，在返回内容前调用 `require_business_action`，资源类型为 `linsight_skill`。
- **AC-09** — WHEN 用户停用自己的个人技能，THE SYSTEM SHALL 使该技能不再进入新任务、运行恢复和重新规划的候选。已经返回给模型的文件内容留在当前步骤。会话目录里的副本留到该任务结束，不靠删除这些文件来停用。下一步 `read_file` 读到 `/skills/{名字}/`，或代码执行器再执行前，发现该技能已停用则拒绝这次读取或执行。同一次会话的 “Available Skills” 名单写在检查点里，恢复和继续提问不重读磁盘来改这份名单。
- **AC-10** — WHEN 用户删除自己的个人技能，且没有任务正在使用它，THE SYSTEM SHALL 从技能中心移除该技能，其他用户的列表不变。

### 2.3 自动选用

- **AC-11** — WHEN 用户发起灵思任务，THE SYSTEM SHALL 把「本租户已启用的平台技能 ∪ 该用户已启用的个人技能」中每个候选的整包拷进会话的 `/skills/{名字}/`，名称和用途说明进入同一次任务的提示词。用户勾中的技能（含默认勾选且未摘掉的）标明「用户选中了这个技能」。未勾选的候选同样拷入整包，但不加这句。这句由平台加在提示词里，不改写 `SKILL.md`。停用的个人技能仍在技能中心列出，但不进入候选。不另调模型生成名单。
- **AC-12** — IF 个人技能与平台技能的技能标识相同，THEN THE SYSTEM SHALL 在「我的技能」的两个分组里都列出，并标来源；「技能广场」只保留企业技能那一张卡片。同名去重只在任务候选里做：个人技能已启用时，该用户的任务只装载个人技能，不把同标识的企业技能文件放进这次任务。个人技能停用或删除后，新任务改为装载同名的企业技能。展示名相同而技能标识不同时，按新技能保存。

### 2.4 个人配额

- **AC-13** — IF 当前用户在当前租户的个人技能已有 20 个，或这些技能的上传文件合计已达 200 MiB（209715200 字节），再上传会使个数或合计容量超出，THEN THE SYSTEM SHALL 拒绝本次新增，已保存的技能保持不变。停用的个人技能仍占用个数和容量。企业技能不计入。上传前界面展示已用个数和已用容量。

### 2.5 同名再次上传

- **AC-14** — IF 当前用户上传的个人技能与自己已有的个人技能标识相同，THEN THE SYSTEM SHALL 先提示该技能已存在，不写入。用户确认覆盖后，用新文件替换原技能，保留原技能 ID 和启停状态。未确认时保留旧文件。个数不变；合计容量按新文件重新计算，替换后超出 200 MiB 则拒绝覆盖。与企业技能同名不走这条，「我的技能」的两个分组里仍然都列出。

### 2.6 删除与临时文件

- **AC-15** — WHEN 用户删除自己的个人技能，且已有任务正在使用它，THE SYSTEM SHALL 立即从技能中心和之后的候选中移除该技能。新任务、运行恢复和重新规划不再装载它。已经返回给模型的文件内容留在当前步骤。会话目录里的副本保留到该任务结束，不靠删除这些文件来停用。下一步 `read_file` 读到 `/skills/{名字}/`，或代码执行器再执行前，发现该技能已删除则拒绝这次读取或执行。装载时在该次会话版本上记下每个目录对应的技能 ID 和归属用户，读取和执行前按这一行判断，不按目录名判断。同一次会话恢复时，已有的技能目录不写入同名的另一份技能。正在跑的任务读的是会话自己的副本，所以本次删除请求中直接删除该技能的对象。
- **AC-16** — WHEN 用户取消上传，或校验失败，或同名时未确认覆盖，THE SYSTEM SHALL 不把技能包写入对象存储。请求结束时删除本次解压用的临时目录。不按天数保留临时文件。

### 2.7 管理操作、校验与任务提示

- **AC-17** — WHEN 个人技能新增、覆盖更新、启停状态发生实际变化或删除成功，THE SYSTEM SHALL 在现有审计日志中记录操作者、租户、技能 ID、来源、版本和结果。日志不包含技能正文、用途说明、文件字节或凭据。启停状态没有变化时不另记一条。
- **AC-18** — IF 覆盖请求携带的内容哈希与当前技能不一致，THEN THE SYSTEM SHALL 不写入新文件，并提示「该 Skill 已更新，请刷新后重试」。哈希一致时，保存成功后保留原技能 ID 和启停状态。
- **AC-19** — WHEN 启停请求的目标状态与当前状态相同，THE SYSTEM SHALL 返回当前技能且不报错。WHEN 删除请求对应的技能已不在当前用户名下，THE SYSTEM SHALL 返回与删除成功相同的结果，响应中不出现名称或正文。
- **AC-20** — WHEN 用户删除个人技能，THE SYSTEM SHALL 使用确认文案「删除‘{名称}’后，后续任务将无法使用该 Skill，已有对话和生成结果保留。」按钮为【取消】【删除】。删除请求失败时保留卡片，并提示「删除失败，请重试」。
- **AC-21** — IF 个人技能的记录还在、技能包已无法读取，THEN THE SYSTEM SHALL 在详情中说明原因并提供【更新技能】。该更新沿用 AC-14 的覆盖，保留原技能 ID 和启停状态。
- **AC-22** — IF 当前打开的技能已被删除，或平台技能已被停用或删除，THEN THE SYSTEM SHALL 提示原因并返回列表，其他技能保持显示。用户停用自己的个人技能时留在详情中，只更新开关。
- **AC-23** — IF 压缩包内有加密条目，THEN THE SYSTEM SHALL 拒绝导入并说明压缩包已加密。IF 扩展名与 MIME 不在需求允许的组合内，或文件内容与扩展名不一致，THEN THE SYSTEM SHALL 拒绝导入。`.md` 接受 `text/markdown`、`text/plain`、`application/octet-stream` 或空值；`.zip` 和 `.skill` 接受 `application/zip`、`application/x-zip-compressed`、`application/octet-stream` 或空值。压缩包损坏、缺少 `SKILL.md`、路径越界、文件为 0 字节、压缩包内含多份技能，各自用独立错误码说明原因，文件区展示该原因并提供【重新选择】。缺少 `SKILL.md` 的文案为「压缩包中缺少 SKILL.md，请检查后重新上传。」
- **AC-24** — WHEN 保存响应中断后用户重试，THE SYSTEM SHALL 用同一次导入标识先查询服务端。已经保存成功则不再创建第二条；尚未保存才再次提交。同一导入标识配上不同文件时拒绝写入。
- **AC-25** — IF 技能声明的工具不在本次任务的可用工具中，THEN THE SYSTEM SHALL 在任务中说明「该技能需要的工具当前不可用」，并且不因此拒绝整个任务。
- **AC-26** — WHEN 同一用户的个人技能与企业技能标识相同且两份都已启用，THE SYSTEM SHALL 在输入框菜单里分两行展示并标出来源，装入任务目录时只保留个人技能。个人技能停用或删除后，输入框只显示企业技能那一行，新任务装载企业技能。

## 3. 边界情况

- 当压缩包解压路径试图逃出技能目录时，系统应拒绝该包，不落任何文件
- 当两个请求同时为同一用户写入同一技能标识时，系统应只保留一次成功写入，另一次得到明确失败，不得写出半份包
- 当管理员停用某平台技能时，该技能立即退出本租户所有用户的候选目录；用户自己的个人技能不受影响
- 当技能已停用时，技能中心仍能看到它并允许重新启用。新任务、运行恢复和重新规划不再装载它。已经返回的内容留在当前步骤；会话目录里的副本留到该任务结束。下一步读取或代码执行前再查一次，已停用则拒绝
