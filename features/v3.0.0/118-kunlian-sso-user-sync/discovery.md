## 1. 目标与来源

目标：昆联用户进入毕昇独立工作流编辑器时，以昆联可信身份建立毕昇会话；毕昇完整同步获准范围内的外部租户、成员及状态，通过稳定映射进入现有租户和权限体系。昆联控制身份有效性，毕昇继续负责工作流与运行数据的业务授权。

用户先要求分析两份对接文档、对照现有实现，再要求按总体设计规划 SSO 和用户同步，随后询问商业网关复用能力并要求“SDD 规划一下”。2026-11-03 用户进一步确认：“确认，按这个职责分工继续编写 spec.md，先不要改代码。”本轮只进入正式规格编写及评审，不实施、部署或同步真实目录。

## 4. 推荐职责划分与关键决策

### D01：接入承接方（已确认）

**已选择 A：商业网关承接 OIDC，BiSheng 后端负责目录同步、身份映射及会话准入。**

- 网关复用 SSO 发起、回调和内部签名传输，增加昆联专用 OIDC 验证及浏览器退出；向后端提交受验证且与本次事务绑定的身份结果。
- 后端维护本地映射、外部会话引用、受保护访问有效性检查和业务授权。通过服务端受保护存储／受信内部协议关联外部凭据，不让浏览器成为凭据传递中介。
- 目录拉取统一交给后端定时任务；不在网关和 Python 各建一套同步器。便于与身份映射、停用及权限投影使用同一编排入口。
- 具体内部报文、会话存储和内省调用位置在 design 阶段论证；必须确保 HTTP、WebSocket 等昆联会话入口无法绕过，不能仅凭入口身份头放行。

**备选 B：Python 直接承接完整 OIDC。** 不依赖商业网关，但需要新建登录协议入口。若目标环境不部署网关、协议适配维护成本明显更高或无法保证网关回调可信交接，再选 B。

用户已确认 A。B 仅保留为备选依据，不同时规划或实现两条登录链；推翻已确认职责需重新确认。

### D02：首次登录尚无目录映射（已确认）

用户选择“采用：补同步后由用户重新登录”。若登录身份没有唯一映射，结束当前登录并提示目录未就绪，触发受控补同步后让用户重新登录。不按显示名建号，不把 `sub` 当成员 `id` 查询详情。未来若昆联提供按 `sub` 查成员能力，再评估即时建号。

### D03：外部租户及权限来源

全量保存外部租户／成员事实，建立明确本地映射；未完成映射或状态不可判定时不回退 Root。同步不自动开通所有租户的登录或默认工作流权限。正式设计需确定外部目录与本地租户的投影方式，保持既有自然人和租户对象的领域归属。

用户已确认基础菜单“不自动授予，由管理员提前配置”；停用时“保留人工授权记录；恢复后按当前有效授权判断”。停用期间仍须阻断新访问并失效旧会话，恢复不复活旧会话或补回已撤销授权。此确认限定了补充文档中“撤销本地授权”的人工授权部分。外部目录投影及其与原 Owner 的接线在后续设计明确，不在本轮选定表结构或新增管理权限。

### D04：缺口与时效

五分钟全量同步仅作为接收方初始配置建议，不冒充撤权上界。需要双方分别确认成员停用、租户停用和角色变化的生效上界，以及内省的 active 是否覆盖最新成员状态和租户到期。若不能支持业务要求的时效，应补事件／查询契约，不能凭空缩短承诺。

## 7. 外部依赖与发布风险

| 依赖／风险 | 影响及闭环方式 |
| --- | --- |
| 专属 client、secret、登录／退出回调、同步 Key、出口 IP | 未交付只能做离线契约验证，不能宣称真实联调通过 |
| 固定租户 SSO 与全租户目录不同范围 | 配置和准入分别验收，不把目录权限当用户业务权限 |
| 目录不完整／不是一致性快照 | 不虚构组织树、组成员或空租户数据；按批次恢复和补充契约处理 |
| 五分钟令牌与逐请求内省 | 登录重定向、内省容量／延迟、故障拒绝和退出体验需共同验收；不缓存允许来绕过要求 |
| 跨仓改动 | 后续分别建立网关与后端特性分支，固定内部契约；不修改公共旧接口来伪装兼容 |
| 新映射及状态投影 | 可能涉及 schema、权限及存量身份；实施前单独说明影响、兼容、回退并按已确认设计执行；不自动认领或迁移历史账号 |
| 回退 | 必须在 design 给出网关／后端版本配对及禁用昆联入口方案；回退不得使失效的外部会话重新获得访问，也不得靠宽松登录兜底 |
