## 第三轮（本会话复核第二版）

日期：2026-10-15。用户要求暂停编码并复核其改动；本轮仅更新评审记录，不修改用户的 spec/design 决策，不编写产品代码。

- ISSUE: D6 仅在 mutate 返回 19003 后执行 check，但同一节确认隐藏状态或部门范围变化并不会使 mutate 失败。对象在选择后移出候选范围时，写入可能直接成功，check 永远不执行，无法满足 AC-19“超出范围时标记并让用户调整”。应在设计中明确提交前只读检查，以及检查与实际写入间竞态继续遵守既有写入合同的边界；不能宣称事后检查已覆盖这个场景。 | SEVERITY: high | LOC: design.md:100
- ISSUE: D2 只有一个缺省 true 的全局开关，而 D5/AC-25 要求逐入口、经目标数据库性能验收后才能启用。不达标的入口缺少独立关闭/批准机制；首次安装缺配置会先启用未验收入口。需将已实现入口与经性能验收获准启用入口取交集，且能力声明和实际请求路由使用同一门禁。全局开关可继续作为总止损开关。 | SEVERITY: high | LOC: design.md:38
- ISSUE: D3 表中 /user/list 的新模式被安排为 endpoint 直接调用 Repository，跳过 Service；这是新增路径，不能借旧 endpoint 已有复杂编排豁免 C1。应明确由用户业务 Service 承接新查询，endpoint 只负责参数和响应，Service 再调用 Repository。 | SEVERITY: high | LOC: design.md:57
- ISSUE: D4 的窗口总数只存在于返回行中，零匹配或翻到越界页时无法取到 total；D5 又禁止额外 COUNT，并要求每次搜索只有一条 SQL。现有 global-members 恰好在空页执行额外 COUNT，且在命中后还查询部门信息，不能将它作为“完整请求一条 SQL”的证据。需明确空页计数方案，并将单条 SQL 预算限定为候选扫描，区分原范围推导、祖先/部门补全与参数检测查询；仍按完整服务端请求耗时验收性能。 | SEVERITY: medium | LOC: design.md:73

源码依据：

- `tenant/domain/services/f048_permission_subject.py:canonical_source` 校验用户的活动租户关系，不检查隐藏状态和候选部门范围；部门校验 active 与 tenant_id。
- `department/domain/services/department_service.py:aget_global_members_search` 使用窗口计数，但空页独立 COUNT，非空页另取部门记录。
- `docs/constitution.md` C1 要求 Endpoint → Service → Repository，新路径不得跳层。

结论：尚有上述阻断项，不能维持第二轮“等待整体确认即可实现”的结论。旧分支保持与 external_id 口径没有新增异议；先修订这些矛盾，再推进任务与编码。

## 第四轮（第三版收敛稿）

依据：用户最新要求“不做混合版本兼容、核心满足 ID 搜索、不影响之前性能优化”，及异步问题回复“接受完整 ID＋前缀，优先性能”。前版结论只作历史记录，当前实施依据为 design 第三版。

- 第三轮问题 1：关闭。删除新增 check 与逐项失效定位承诺，恢复原写入/错误合同；不再声称事后检查能拦住成功写入。
- 第三轮问题 2：关闭。删除能力声明、运行时开关和逐入口门禁；性能作为正常发布前验证，不合格先修正再发布。
- 第三轮问题 3：关闭。新查询明确经业务 Service/Repository，不允许 endpoint 跳层；仅迁移本次触及查询，不建立新目录子系统。
- 第三轮问题 4：关闭。保留窗口计数和空页 COUNT 兜底，删除“整个请求只发一条 SQL”的限制；全部范围推导与补充查询均计入性能验收。
- 核心功能：ID 完整/前缀、原名称规则、稳定身份去重、数据库分页、精确优先、候选/已选 ID 展示与全入口覆盖一致。
- 性能：保留既有前缀匹配、主属部门 JOIN、去 GROUP BY、窗口计数、懒加载与防抖；ID 独立可索引分支，目标库执行计划及前后基线回归列为发布证据。仅凭 SQL 形状不宣称性能保证。
- 索引：模型已知唯一索引以 source 开头，不能当作 external_id 单列前缀索引；必要查询索引及双库 DDL 是明确允许的最小增量，不添加业务字段或数据迁移。

结论：收敛稿未发现前轮阻断矛盾；尚未实现，尚未进行双库性能验证。实际执行计划、双库比较语义和相应测试是实施验证项，不能当作已经通过。
