# 旧会话知识空间访问状态 — 2026-11-03

## 缺陷与根因

关联 TC-120-KSP-038，从 reczz28SlUbxQhuS 拆分。用户提供的 macOS Chrome 无痕实测：dsh-sara6 退出仅通过审批加入的 space/14 后，旧会话标签、选择器计数与权限说明继续沿用退出前状态。

`useConversationKnowledge` 按账号与会话恢复本地选择；输入区与发送范围直接消费该记录。知识空间选择器另行查询当前列表并保留初始草稿。两条路径缺少服务端权限核验，造成已退出空间的标签、计数和空检索回复继续呈现有效选择的语义。

## 实现

- `useKnowledgeSpaceAccess` 使用现有 `/api/v1/permissions/check` 对已选空间核验 `visible`；与知识空间问答的权限动作一致。按账号、会话和已选 ID 隔离结果，挂载、窗口恢复焦点与网络恢复时重新查询。
- 权限返回 `allowed: false` 的空间移出有效标签和已选计数，输入区持续展示失效空间名称与重新选择引导。原选择记录保留为失效原因，刷新后仍能解释状态；用户重新选择或在选择器确认清空后更新记录。
- 核验中、接口失败和权限失效分别呈现说明；上述状态下发送及重新生成在建立流之前停止，保留问题草稿与历史消息。权限接口失败保留原选择，并引导刷新重试。
- 选择器独立核验草稿，确认时提交有效空间；选择上限按有效数量计算。搜索仅过滤展示列表，权限判断依据服务端结果；直接、部门、用户组等仍有效授权由服务端统一裁定。
- 中、英、日三语言文案同步。输入区既有回归断言同步采用当前图标标签的语义文本，jsdom 服务端渲染使用 Node 入口。
