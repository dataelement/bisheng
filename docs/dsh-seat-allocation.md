# DSH 授权即占席位

## 行为

毕昇将部门作为当前人员的批量选择器，保存正额度时冻结本次成员名单。Gateway 成功分配即持久占用席位，登录只使用已有席位。后续组织成员变动保持已分配席位，新成员需要管理员再次授权。

席位按用户去重，多个模型共享同一席位。容量检查、新席位和操作回执在一个数据库事务提交。余额不足时整批返回 `seat_limit_reached`。已撤销人员需要管理员通过现有重新授权流程恢复。模型额度和席位分别存储，修改额度为零保持席位，释放席位使用管理员撤销操作。

## 内部接口

`POST /api/internal/dsh/seats/assign-batch` 使用现有内部服务签名认证和管理员 actor/target 校验。

请求字段：`operation_id`（UUID）、`actor`、`target.tenant_id`、`user_ids`（1–1000 个正整数的字符串）。成员由可信毕昇后端在租户范围内选取，Gateway 对已有席位进一步核对租户归属。去重排序后的成员、租户、操作者构成幂等摘要。

响应字段：`operation_id`、`status`（SUCCEEDED/FAILED）、`result_code`、`selected`、`newly_assigned`。同一操作号及相同摘要返回原回执；相同操作号配不同摘要返回冲突。已明确失败后重试业务操作使用新操作号。

毕昇先持久化成员快照，再调用 Gateway。网络结果不确定时保留 PENDING，后台 worker 按原操作号和原名单恢复；Gateway 回执成功后提交额度策略。个人额度写入使用既有持久操作恢复流程。界面收到席位不足时保留草稿并提示扩充或释放席位。

## 数据库与发布

Gateway 全新数据库执行 `docker/db/update_dsh_mysql.sql` 或 DM 对应脚本，已包含回执表。已有 DSH 数据库仅执行 `docker/db/update_dsh_seat_batch_mysql.sql` 或 DM 对应增量脚本一次。

毕昇新增 SQLModel 表 `dsh_subject_grant`，由项目既有模型发现与 create_all(checkfirst=True) 创建；已有表结构保持。3006 发布预检使用同一模型显式创建该表，保留该环境现有 Alembic 历史。先完成两端数据库升级，再协调发布 Gateway、毕昇后端及 worker，最后更新前端。发布期间暂停 DSH 授权写入，避免混用旧登录自动分配行为。

已有 ASSIGNED 席位保留。历史只有额度、尚无席位的用户，由管理员明确重新保存授权后分配；上线前需要核对这批用户和剩余容量。首次登录没有席位返回 `seat_not_assigned`。数据库回执和人员快照在回滚时保留；应用回滚需协调两端版本，旧 Gateway 会恢复登录时自动占位语义。

## 验证边界

Gateway DSH 专项测试 78 项：60 通过、18 外部依赖项跳过，Java 打包成功。此前隔离真实 MySQL 验证包含并发整批分配、容量不足、重试去重及写入异常全事务回滚。毕昇相关后端 140 项通过；DSH 前端 216 项通过，另有 11 项 CI 测试用例修复验证通过，严格类型检查通过。

真实 DM 和完整原生登录联调为 NOT_RUN。单次部门选择上限 1000 人，多部门分别保存属于独立批次。3006 部署证据由本次发布目录保存。
