# 桌面嵌入页与独立网页的语言隔离

用户要求：桌面以桌面语言为准，独立网页以网页语言为准；2026-10-19 确认基于 `feat/bisheng-work-120` 完成同步。

## 验收范围

- 桌面首次打开及中英文切换后，嵌入聊天、知识空间、频道、应用和默认导航文案采用当前 Harness 语言。
- 路由切换、新页面挂载、完整重载及设置中隐藏的嵌入页继续采用桌面语言；切换语言不重新加载会话。
- 独立网页继续使用自身保存的语言，网页语言切换、持久化及日语配置沿用已有机制。
- 宿主覆盖不写网页的 `lang` cookie、`localStorage.lang` 或 `i18nextLng`；导航的管理员自定义名称和用户内容保留原文。
- 拒绝不支持的宿主 locale；订阅在卸载后释放。没有原生展示桥的普通网页忽略桌面样式的参数及事件。

## 实现契约

桌面宿主插件从 `ctx.locale.getSnapshot().active` 读取语言并订阅变更，复用现有 presentation IPC 的可选 `locale: zh | en` 字段。主进程校验该字段，在 entry URL 传 `dshLocale`，并向当前隔离文档写入 `data-dsh-host-locale`、派发 `dsh:locale`。该字段只影响呈现，不改变认证、权限、插件解析或后端启动阶段；旧调用方未传 locale 时保留既有行为。传送失败记录 `locale_delivery_failed`，保留会话及原有重连入口。

网页同时要求桌面嵌入状态与原生 `dshChatPresentation` 展示桥。将 `zh` 映射到既有 `zh-Hans` 词典，在初始化 i18next 前读取宿主语言；嵌入状态禁用语言检测器的偏好缓存。运行中只更新当前 i18next 实例和文档语言，不修改持久化 Recoil lang atom。`useLocalize` 挂载时优先采用当前宿主覆盖，避免原网页偏好覆盖刚送达的语言。会话级宿主 locale 保存在 sessionStorage，以支持路由去掉 entry 参数后的硬刷新；它随原生隔离 session 一起释放。

宿主初次 entry 参数仍存在时，语言变更同步更新该参数并保留 `history.state`，避免硬刷新采用旧值。已有 `defaultLang` 会把 atom 保存的 JSON 字符串当作不合法语言清理；原生覆盖存在时跳过这段网页偏好修复，保留有效保存值。禁用日语时的 i18next 历史值清理也限定到独立网页。普通网页继续使用原机制。

Shell 持有唯一语言事件监听器，卸载时解绑；导航继续消费原有本地化函数并按现有上报机制更新宿主，无需复制菜单或增加状态库。宪法 C1–C8 的后端、权限、数据与存储边界保持不变；不新增网络请求。
