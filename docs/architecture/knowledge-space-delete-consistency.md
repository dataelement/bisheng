# 知识空间删除一致性：3.0.0 分支适配

本修复适配自 COFCO 提交 `a03a31bf1e2d43d90aaabaa4be09d38f616bb923`。
目标基线为 `feat/3.0.0` 的 `2f216a464b46d418839ba06fbeb35055b94cfd68`。
保留主版本现有接口、版本链规则、频道绑定清理和聊天记录归档行为。

## 分支差异与范围

COFCO 已有 F046 的删除清单、任务表、执行步骤及恢复扫描器，可以直接复用。
3.0.0 没有这些组件，因此本次提供知识领域自己的最小删除任务，不引入 F046 或审批状态机。
对应持久化表为 `knowledge_space_delete_job`，仅服务正式文件、文件夹及批量删除。

3.0.0 的共享文件可见性服务在结果层始终查询正式文件记录，管理员也经过这一步；
业务记录提交删除后，该路径不再返回文件。因此不复制 COFCO 的 F046 footprint 过滤机制。
本修复不承诺所有历史检索入口均经过共享可见性服务，也不修改任务模式检索工具、
通用对象签名接口、网页 HTML 快照字段或已签发链接的有效期。

## 数据库事务边界

1. 校验明确的当前租户，锁定空间、根资源、子树和相关版本链。
2. 按现有规则展开版本：删除主版本时删除整个文档链，删除历史版本时只删除对应版本。
3. 对全部展开资源重新检查 `delete`，包括子树之外的历史版本文件；冻结权限快照。
4. 同一事务写入清理任务，同时删除文件、文件夹、版本行和相应文档锚点。
5. 事务提交后才尝试投递 Celery，API 的成功表示正式业务记录已删除。

在步骤 4 或提交失败时，业务记录和任务一起回滚，OpenFGA、MinIO、ES 和 Milvus
尚未发生写入。提交已成功但回执丢失时，持久化任务仍可由扫描器发现；不恢复业务行。
文件夹之间及批量条目之间延续原有逐项执行语义，不提供整个批量请求的总事务。

## 多进程协作与恢复

- API 进程只向数据库提交删除事实及冻结清单，然后发送任务 ID。
- Celery 消息显式携带 `tenant_id` 和权限任务标记；Worker 恢复该租户后读取任务。
- Worker 通过行锁领取 15 分钟租约；领取时生成独立 token，重复消息不重复领取活动任务。
- 每个清理阶段及 FGA/MinIO 循环续租。步骤完成和错误记录均校验 token，过期持有者
  不能覆盖另一 Worker 的进度。进程崩溃后，租约到期即可重新领取。
- Beat 每 60 秒扫描所有租户的到期任务，仅跨租户读取路由用的任务 ID 和租户 ID；
  实际清理仍在单租户上下文中执行。消息丢失、Broker 不可用、进程退出均不丢失清理意图。

清理顺序为 `FGA → MinIO → ES → Milvus`。每个阶段完成后提交 checkpoint。
FGA 使用删除前的业务权限快照及原始幂等操作账本；重试已完成资源不会创建第二次删除。
MinIO 删除后检查对象不存在，ES 删除后 refresh 并检查剩余分片数，Milvus 删除后 flush
并检查剩余数。只有四个阶段都成功才将任务标记为 `SUCCEEDED`。

阶段失败时保留已完成 checkpoint、记录错误，60 秒后可重试。下次执行跳过已确认阶段。
外部写入成功而 checkpoint 提交失败时，阶段可能重放；依靠幂等删除和 FGA 原始账本恢复，
不要求消息恰好投递一次。租约无法撤回已经发出的外部请求，安全性也依赖该重放性质。

## 部署与验证

新表通过仓库已有的模型发现和建表流程创建；没有变更已有表，也没有数据迁移脚本。
部署时按既有流程执行数据库升级，随后更新 API、知识队列 Worker 和 Beat。
Worker 必须消费 `knowledge_celery`，Beat 必须运行，否则正式删除成功后外部清理会等待。
任务及完成清单保留在数据库中，排查可查看 `state`、`attempts`、`completed_steps`、
`last_error`、`lease_until` 和 `next_attempt_at`。

验证覆盖数据库回滚、提交回执丢失、投递失败、版本链权限拒绝、租户隔离、重复领取、
过期 token、部分清理后跨实例恢复、清理残留拒绝完成，以及 F048 删除账本重放。
MySQL/DM8 的真实行锁竞争及外部中间件一致性仍需在集成环境验证。
本次代码修复不自动修复此前已经损坏的生产文件夹权限。

本地专项验证 34 项通过；权限回归 934 项通过、15 项既有失败、10 项跳过，
知识模块回归 853 项通过、22 项既有失败、23 项跳过。两组既有失败集合均与修改前一致。
权限回归排除了修改前同样无法收集的 MCP 依赖兼容测试模块。
