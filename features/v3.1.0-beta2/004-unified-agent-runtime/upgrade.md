# F004 统一运行时升级说明

本文给执行升级的人看。F004 把日常对话和深度研究放到同一个 agent 内核上运行。升级后所有用户自动走新链路，不需要在管理界面做任何操作（design 决策 13）。

## 一、变更一览

| 对象 | 变更 |
| --- | --- |
| 数据库 | 没有表结构变更，没有 Alembic 迁移，没有数据迁移。工作台配置里的「系统提示词」改为「自定义系统提示词」，旧值不再生效（见第八节，**升级前必读**）。 |
| Python 依赖 | `deepagents` 0.6.12 → 0.7.39；`langchain` ≥ 1.5；`langchain-core` ≥ 1.8.1。锁文件 `uv.lock` 已更新。 |
| Redis | 新用到 Stream 和 Lua 脚本。最低版本 5.0。随产品交付的 7.0.4 满足要求。 |
| 开关 | 没有开关。所有租户升级后都走新链路。 |
| 前端 | client 前端改用新的发送协议和事件订阅。必须与后端同一批发布。`/linsight/new` 不再能提交任务，打开时跳到新对话并打开「深度研究」。 |
| 开放 API | `/api/v2/workstation/chat/completions` 的日常对话改由统一运行时执行。请求、响应格式和状态含义不变，变化见第七节。 |
| 进程 | API 进程和深度研究 worker 都有改动，两者都要重启。 |

## 二、升级前检查

| # | 检查项 | 方法 | 不满足时 |
| --- | --- | --- | --- |
| 1 | Redis 版本 ≥ 5.0 | `redis-cli INFO server` 看 `redis_version` | 先升级 Redis。低于 5.0 时对话无法收到任何回答。 |
| 2 | 使用 Redis Cluster 时，客户端允许 Lua 脚本 | 确认没有禁用 `EVAL` / `EVALSHA` | 放开这两个命令。 |
| 3 | 各节点时钟已同步 | 各节点执行 `date -u` 对比，偏差应在 1 秒内 | 配置 NTP。运行租约按时间判断，偏差过大时运行会被误判为失效。 |
| 4 | 是否有客户端仍使用旧协议 | 盘点桌面端、未随本次升级的前端静态资源、直接调用 `/api/v1/workstation/chat/completions` 的集成方 | 见第五节。 |

## 三、升级步骤

1. 部署新版本后端代码。
2. 在后端目录执行 `uv sync --frozen`。镜像部署则使用新镜像，不需要这一步。
3. 重启 API 进程。
4. 重启深度研究 worker（`bisheng/linsight/worker.py`）。重启会终止正在执行的深度研究任务，请选在空闲时段。
5. 发布 client 前端的新构建。使用了 CDN 或浏览器缓存时，清掉旧的静态资源。
6. 按第四节验证。

第 3、4、5 步要在同一个维护窗口内完成。只升级其中一部分时，新旧协议会混用，表现见第五节。

## 四、升级后验证

| # | 操作 | 预期 |
| --- | --- | --- |
| 2 | 在对话页发一条普通问题 | 正常流式回答。API 日志出现 `direct run=… ended status=finished`。 |
| 3 | 回答过程中再发一条消息 | 新消息显示为排队，当前回答读到它之后继续。 |
| 4 | 回答过程中点停止 | 回答停住，已生成的文字保留。 |
| 5 | 发一条深度研究任务 | 3 秒内出现执行反馈，任务正常完成并给出文件。 |
| 6 | 刷新正在回答的页面 | 回答内容补全并继续流式输出。 |
| 7 | 用开放 API 调一次日常对话 | 流式返回回答，最后一帧是 `final`。API 日志出现 `direct run=… ended status=finished`。 |
| 8 | 在工作台配置里填写「自定义系统提示词」（例如「你是 XX 公司的智能助手」），分别发一条日常对话和一条深度研究，问“你是谁” | 两种模式都按新设定自我介绍。 |

## 五、仍使用旧协议的客户端

后端升级后默认走新链路。仍按旧协议发送的客户端会遇到两种情形：

- 回答进行中再发一条消息，客户端只收到结束帧，看不到这条消息被处理。
- 直接回答里 agent 向用户提问时，客户端看不到提问卡片。

处理办法：把这些客户端升级到支持新协议的版本。本版本没有回退到旧通道的配置（见第六节）。

## 六、没有配置回退

本版本不提供新旧链路的切换开关。升级后出现必须绕开的问题时，只能回退到上一个版本的后端和前端。

工作台配置里如果残留了 `unified_runtime_enabled` 这个键，它不起任何作用，下次保存工作台配置时自动消失。此前存了 `false` 的租户，升级后直接走新链路。

## 七、已知限制

| 限制 | 说明 |
| --- | --- |
| 未在两节点环境实测 | AC-33 的多节点场景只有设计和单元测试，没有在两台机器上执行过。 |
| 未在 DM8 环境实测 | AC-42 未执行。 |
| Redis 长时间不可用 | Redis 不可用超过约 30 秒时，正在执行的运行会被判为租约失效并结束。 |
| 开放 API 同一会话串行 | 开放 API 往一个正在回答的会话发消息时，请求最多等 60 秒；会话仍未空闲时返回错误码 12048。升级前同一会话的请求可以并行。 |
| 开放 API 的回答内容 | 开放 API 日常对话与网页端用同一个内核：历史从会话线程读取，附件内联上限为单文件 4000 字、总计 15000 字，可能出现 `read_attachments` 等新的工具帧，运行失败时的错误码按模型错误分类给出（如 11090/11091）。帧的格式和字段名不变。 |

## 八、「系统提示词」改为「自定义系统提示词」（升级前必读）

**升级后，所有租户原来保存的「系统提示词」都不再生效，统一使用新的默认设定。** 原因和设计见 design 决策 15。

| 项目 | 升级前 | 升级后 |
| --- | --- | --- |
| 配置项名称 | 构建 → 工作台 → 日常对话配置 → 系统提示词 | 同一位置，改名为「自定义系统提示词」 |
| 作用范围 | 只对日常对话生效 | 日常对话和深度研究都生效 |
| 应该写什么 | 默认模板里混有语言、引用、时间、图表等平台规则 | 只写助手的名称、身份、语气和业务要求 |
| 为空时 | 管理页自动填入当时的默认模板 | 使用内置默认设定「你是{品牌名}智能助手……」 |

平台已经内置下面这些能力，不需要再写进自定义系统提示词：使用用户的语言回答、标注来源编号、当前时间、检索结果不足时不强答、ECharts 图表渲染、知识库图片的引用。

### 升级前

1. 用管理员账号打开每个租户的「构建 → 工作台 → 日常对话配置」。
2. 如果系统提示词是客户自己改写过的（不是安装时的默认模板），把全文复制保存下来。

### 升级后

1. 打开同一页面。输入框显示新的默认设定。
2. 如果客户需要自己的身份或业务要求，按「只写身份、语气和业务要求」的口径，从升级前保存的文字里挑出这些内容，填入「自定义系统提示词」并保存。不要把旧模板整段贴回去。
3. 按第四节第 8 项验证。

### 说明

- 旧值仍留在数据库里（配置 JSON 的 `systemPrompt` 键），后端不再读取。管理员下一次保存日常对话配置时，这个键自动消失。
- 自定义系统提示词和平台规则冲突时，以平台规则为准。例如写了「回答不超过 50 字」，深度研究仍会按流程产出交付物。
- 订阅页 AI 助手的「系统提示词」是另一个配置项，不受影响。
