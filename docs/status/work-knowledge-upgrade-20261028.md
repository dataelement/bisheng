# Work 知识检索升级修复 · 2026-10-28

## 问题与证据

TC-120-KSP-042 的已有执行记录显示：macOS test3 中可选 K1/K2，两次知识检索均返回通用错误，同一资料在云端 Chat 可检索。本轮通过测试环境的已登录管理员只读核对目录，内置工具接口返回 17 类 / 38 个工具，知识检索键 `bisheng_knowledge_search` 缺失。本机 test2 通过原有宿主接口执行两次单选和一次多选，均复现通用错误。

Work 在检索前检查知识工具的可用权限。目录缺项会在这一阶段产生 403；桌面适配器将业务错误转为通用提示。实际报错账号及 test3 仍以部署后的原用例验收为准。

原有旧库维护流程把工具登记和权限校准分为两个操作，登记命令完成只代表数据库记录已创建。修复将两步纳入同一升级操作，并以权限投影 CURRENT 作为完成条件。项目的数据维护约束要求该操作在发布维护窗口执行。

## 改动

- 默认预览同时返回工具登记计划、权限状态及当前权限 Store/model 标识。
- Apply 明确绑定预览得到的 Store 和审计操作人，先核验权限运行时，再创建缺失记录，随后通过统一权限入口校准该知识工具分类。
- 数据库自动分配 ID；管理员配置、当前权限模式、个人启用开关和其他工具保持原值。
- 权限失败保留已提交的工具记录，命令返回失败；重复执行继续校准权限。现有非 CURRENT 状态按现有权限修复流程处理。
- 源码与 Docker 两个入口统一提供 `upgrade-work-knowledge`，部署命令见 `src/backend/scripts/README.md`。
