# 点赞 / 点踩反馈 Feedback

`MessageFeedbackButtons` —— 全部 6 类 AI 回答界面共用的反馈控件（首页对话 / 知源 / 订阅 3 面板 / 灵思 / appChat）。点踩为**延迟提交**：弹窗（共享壳 `CommentDialog`）点「提交」才落库并高亮，原因选填；「取消」= 彻底放弃点踩。每次落库成功的评价由组件自己弹一条成功轻提示，取消评价则保持安静。

## 三种初始状态

demo 只把回调打到旁边的文本上，不落库，可任意点；轻提示是组件真发的，落在页面顶部。

```tsx
import { useState } from 'react';
import { RecoilRoot } from 'recoil';
import { Toaster } from '@bisheng/ui';
import '~/locales/i18n';
import { ToastProvider } from '~/Providers';
import store from '~/store';
import { MessageFeedbackButtons } from '~/components/Chat/MessageFeedbackButtons';

function Demo({ label, hint, liked }: { label: string; hint: string; liked?: number }) {
  const [last, setLast] = useState('—');
  return (
    <div style={{ display: 'flex', alignItems: 'center', gap: 12 }}>
      <div style={{ width: 300, flexShrink: 0, fontSize: 13, color: 'rgb(var(--text-2))' }}>
        {label}
        <div style={{ fontSize: 12, color: 'rgb(var(--text-3))' }}>{hint}</div>
      </div>
      <MessageFeedbackButtons
        liked={liked}
        onLike={(l) => setLast(`onLike(${l})`)}
        onDislikeComment={(c) => setLast(`onDislikeComment("${c}")`)}
      />
      <span style={{ fontSize: 12, color: 'rgb(var(--text-3))' }}>最近调用：{last}</span>
    </div>
  );
}

export default () => (
  <RecoilRoot initializeState={({ set }) => set(store.lang, 'zh-Hans')}>
    <ToastProvider>
      <div style={{ display: 'flex', flexDirection: 'column', gap: 20 }}>
        <Toaster />
        <Demo label="初始未评价" hint="点踩先弹窗，提交后才高亮；取消不留痕" />
        <Demo label="已点赞态（liked=1）" hint="点踩弹窗取消后应保持点赞高亮" liked={1} />
        <Demo label="已点踩态（liked=2）" hint="再点踩 = 直接取消，不弹窗" liked={2} />
      </div>
    </ToastProvider>
  </RecoilRoot>
);
```

## 规则

### 状态与落库

- 点赞与取消评价**立即落库**；点踩只有弹窗提交后才落库并高亮。
- 已点踩态再点踩 = 直接取消，不再弹窗。
- 弹窗每次打开都清空草稿，取消 / ESC / 点遮罩一律视为**彻底放弃这次点踩**；原因选填，留空提交只落点踩、不发原因。

### 轻提示反馈

- **只有落库成功的评价才弹提示**：点赞、以及弹窗提交的点踩，各弹一条**成功**轻提示「感谢你的反馈，我们会用它来改进问答效果」。
- **取消评价不弹提示。** 图标掉高亮已经把结果说清楚了；此时再弹「感谢反馈」，用户会以为「取消」这个动作本身也被记了一笔。
- **赞和踩共用同一句文案**，不给点踩单写一版。差异化措辞（「已收到你的意见」之类）会暗示两种评价分量不同，也容易让用户以为点踩还要走额外流程。
- **提示由组件自己弹，调用方不要再弹一次**——`onLike` / `onDislikeComment` 里只管落库。调用方另写一句（如「已提交」）不会被去重，两条一起叠出来。
- **`onLike` 返回 Promise 时，提示等它 resolve 才弹**：请求失败就只剩响应拦截器那条错误提示，不会「感谢反馈」和「保存失败」一起出现。同步返回（调用方不关心成败）则立即弹。
- 连点无需自己防抖：同一条文案重复触发由轻提示层去重（刷新已有那条并重新计时），快速切换赞 → 取消 → 赞也只会看到一条。见 [组件-Toast轻提示.md](../组件-Toast轻提示.md) §3。

### 视觉

- 按钮视觉与 AI 消息操作行一致：`size-6` 热区、14px bisheng-icons Outlined 字形、`#818181` 常态 / 品牌色激活。
- 弹窗规格（CommentDialog）：圆角 12 / 边距 20 / 按钮 32 高 · 14px · 字重 400 · 圆角 6。

> demo 里的 `RecoilRoot` + `import '~/locales/i18n'` + `ToastProvider` + `<Toaster />` 只是文档站的挂载脚手架；业务页在 App 全局已具备。缺 `ToastProvider` 时 `useToastContext()` 拿到的是空实现，按钮照常工作但**静默不弹提示**——排查「提示没出来」先看这一层。
