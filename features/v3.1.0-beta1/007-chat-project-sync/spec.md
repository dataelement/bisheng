# Feature: Web 与 Desktop 项目数据实时同步

**关联 PRD**：[用户确认的需求来源](./request.md)。
**优先级**：P1。
**所属版本**：v3.1.0-beta1，F007-chat-project-sync。
**依赖**：现有企业身份、租户隔离、普通对话及项目界面；F002-project-new-chat 的既有交互。
**流程**：Full SDD。需求发现及本规格均已由用户于 2026-11-06 确认；三端实现与本地回归已完成，目标环境联合验收继续记录。

**本次纳入**：Web 与 Desktop 共用的账号私有项目及对话归属、双向实时更新、并发与重连恢复、旧本机数据合并迁移、三端联调。

**本次排除**：团队共享项目和项目成员管理；Work 本地工作区与文件上云；对话正文或模型流式协议重构。项目只组织现有对话，不创建另一份对话正文。

## 1. 用户故事

作为同时使用 Bisheng Web 和 Desktop 的用户，我希望两端项目与对话归属始终一致，以便在任意入口继续组织和使用同一批对话，不需要手动复制或刷新列表。

作为已有本机项目的用户，我希望保留原有分组并合并到我的账号中，以便升级不会导致项目消失或重复。

## 2. 验收标准

### 2.1 双端数据与交互

- **AC-01** — WHEN 用户在同一平台、租户和账号登录 Web 与 Desktop, THE SYSTEM SHALL 在两端展示同一批项目及对话归属；退出应用再登录后仍可恢复。
- **AC-02** — WHEN 用户在任一端成功新建、重命名或删除项目，或将对话移入、移出项目, THE SYSTEM SHALL 在本端立即展示结果；另一端在窗口重新获得焦点、重新进入页面或刷新时展示最新结果。系统不提供后台实时推送，与普通对话列表的同步方式一致。
- **AC-03** — WHEN 用户在项目中发送首条消息并成功创建正式对话, THE SYSTEM SHALL 将该对话归入发起它的项目；连续选择项目、快速发送、延迟到达的创建结果和任务模式不使它串入其他项目，全局新建或打开已有对话不继承旧项目意图。
- **AC-04** — WHEN 对话属于项目, THE SYSTEM SHALL 在默认分组视图中只将其列在所属项目一次；搜索和全部对话视图仍可找到它；较早对话不因普通列表尚未加载对应历史页而永久缺失。
- **AC-05** — WHEN 用户删除项目, THE SYSTEM SHALL 保留其中全部对话及聊天记录，并将它们移回普通对话列表；删除对话后不在项目中继续展示可打开的残留记录。

### 2.2 一致性、失败与恢复

- **AC-06** — WHEN 两端并发修改不同项目或不同对话的归属, THE SYSTEM SHALL 保留各自已成功提交的变更；同一名称或同一对话归属被并发修改时，两端最终展示一致的结果，同一对话至多属于一个项目，不因旧响应恢复旧状态。
- **AC-07** — IF 网络中断或应用从休眠中恢复, THEN THE SYSTEM SHALL 在下次获得焦点或网络恢复时重新读取最新项目与归属；中断期间另一端的成功修改不得永久遗漏；重试新建项目不得产生副本，重试归属不得产生重复归属。
- **AC-08** — IF 保存未成功，或由于网络、权限、服务版本等原因无法完成同步, THEN THE SYSTEM SHALL 明确展示失败或未同步状态并保留可重试的输入；不得只修改本机数据就展示为同步成功。

### 2.3 身份和旧数据

- **AC-09** — WHEN 用户退出或切换平台、账号、租户, THE SYSTEM SHALL 立即移除旧身份的项目展示并停止接收其更新；旧身份的延迟读写结果不得改变新身份的界面或数据。
- **AC-10** — IF 用户尝试读取或修改其他账号、其他租户的项目或对话归属, THEN THE SYSTEM SHALL 拒绝该操作；个人项目不因对方拥有平台管理身份或知道项目标识而自动向其开放。
- **AC-11** — WHEN 用户登录且项目服务可用, THE SYSTEM SHALL 自动导入旧版本机项目，无需点击迁移，并按对话归属判定项目主人：旧项目中至少有一条有效对话属于当前账号时，才为当前账号导入该项目，并只带入属于当前账号的对话；不含当前账号对话的旧项目（包括空项目）不导入。保留本机原记录；重复导入和断线重试不产生副本，不按同名合并，不覆盖云端修改，不迁入外来会话。
- **AC-12** — IF 同一浏览器先后登录多个账号, THEN THE SYSTEM SHALL 让每个账号按 AC-11 各自导入属于自己的旧项目，不把整份旧数据交给首个登录的账号；切换账号后忽略旧账号的迟到结果；界面不提供手动迁移入口或确认弹窗。
- **AC-13** — WHEN 项目同步能力启用, THE SYSTEM SHALL 保持“工作区 → 项目 → 对话”的桌面分类，以及已有项目命名、展开、新建对话、搜索、菜单和窄屏导航交互；Work 工作区、会话及文件继续保留原有本机归属。

## 3. 边界情况

- 项目名称继续采用现有 1–30 字符要求，保留重复名称的能力；同名不代表同一项目。
- 对话已被另一端删除、移走或目标项目已删除时，旧窗口的操作必须得到明确结果，并恢复一致的列表。
- 项目读写超时后重试不能制造副本；成功提交但响应丢失时同样适用。
- 旧本机数据无效、部分会话不属于当前账号或已删除时，导入应说明哪些内容未导入，保留原始数据，不静默丢弃。
- 不支持项目同步的旧服务应呈现能力不可用状态，不能回退为另一套本机项目并冒充互通。
- Web 与 Desktop 的项目数据、归属和重连均需联合验收；本地构建成功不能代替目标服务已部署、双端已加载并完成验证。

## 4. 设计与实现指针

规格仅定义可观察的行为。数据模型、接口、通知机制、并发版本、错误码、迁移标识、性能目标与执行顺序在设计阶段确定，不在本文提前认定为已实现。
