# 知识广场撤销查看授权后的加入状态 — 2026-11-02

## 问题与边界

关联 TC-120-DSQ-014。用户报告在 Windows BISHENG 1.2.0-test6 / Harness 0.2.1-rc.2，合成空间 KS1030T46（74）撤销 dsh-sara5 的直接查看者后，广场、抽屉显示已加入，正文按当前权限拒绝读取。用户已将空间配置恢复，文件 KSP_VIEW_1031R.txt 保留。

本次仅修改源码并使用本地夹具验证。用户记录证明实际读取被拦截，问题按状态一致性与重新申请入口处理。服务器、真实账号、空间配置和数据本轮保持用户恢复后的状态。

## 根因

- 成员表的 ACTIVE 记录与当前有效权限可以在撤权后分离。`_resolve_effective_subscription_status` 原来只会把具备权限的未加入状态提升为已加入，ACTIVE 记录始终保留已加入。
- 详情接口还会使用 ACTIVE 成员的旧角色；重新申请接口对 ACTIVE / 管理角色记录直接返回 subscribed，申请被旧记录短路。
- 抽屉已有独立 visible 检查，它拒绝内容后只更新正文可读标记，卡片和按钮仍使用原加入状态。

## 修复

- 广场与详情对 subscribed / not_subscribed 使用当前有效 visible 判定；pending / rejected 沿用已有申请状态。撤权后的成员旧角色参与详情展示前先满足内容权限。
- 重新加入仅在当前有效权限成立时沿用已加入。权限已撤销时重新进入既有审核门禁，按结果持久化 pending 或 subscribed。申请存储使用 MEMBER 角色，已撤销的旧管理角色保持撤销；创建者沿用所有权。
- 抽屉收到明确 allowed=false 时同步清除已加入信号，并通知广场显示可加入；权限服务异常保持原成员状态。提取原有状态、按钮与文件过滤规则以遵循文件行数约束，保留原有视觉。
- “用户数”继续按现有 ACTIVE 成员记录统计。本次修复加入状态及申请流程；撤权历史记录的全量清理、把成员人数改为有效访问人数属于独立统计变更。重新申请进入 pending 后，当前用户按原规则退出 ACTIVE 统计。
