# 报告页版块用法

底座 `assets/report-base.html` 里每个版块都有一段示例。本文说明**什么时候用、什么时候不用**。
一页报告通常只需要其中 4～6 种。

## 按报告类型选版块

| 报告类型 | 推荐顺序 |
|---|---|
| 审核、核查、合规检查 | 标题区 → 结论区 → 发现项（按严重程度）→ 对照表 → 依据材料 |
| 对比分析（方案、产品、供应商） | 标题区 → 结论区（推荐哪个、为什么）→ 对照表 → 分项说明 → 依据材料 |
| 调研、分析结论 | 标题区 → 结论区 → 各论点一节（每节：结论句 + 证据 + 图表）→ 来源 |
| 工作汇报、周报月报 | 标题区 → 结论区（进展和风险）→ 指标块 → 分项进展 → 下一步 → 时间线 |
| 数据看板 | 标题区 → 指标块 → 条形图或表格 → 明细（折叠）→ 数据口径说明 |

## 各版块

**标题区 `.masthead`**：每页都要。h1 写「对象 + 报告类型」，不写口号；`.meta` 写依据的材料、日期、编制方。

**结论区 `.verdict`**：每页都要，紧跟标题区。`.lead` 一句话给出总判断（要有判断，不能只是主题），
下面最多 4 条要点。读者只看这里就能知道要不要往下读。

**目录 `.toc`**：保留空的 `<ol>` 即可，脚本按 h2 自动生成；少于 3 个 h2 时脚本会自动移除它。

**指标块 `.metrics`**：只有数字本身就是结论时才用（例如「25 项一致、3 项需更正」）。
最多 4 个；数字要有对比对象或口径才有意义，没有就不用。

**发现项 `.finding`**：审核和核查类报告的主体。严重程度用 `high` / `mid` / `low` 三档，高的排前面。
每条固定写「现象、依据、建议」三栏；依据要能让读者回到原文核对（文件名、章节、页码、条款号）。

**状态标记 `.tag`**：`ok` 一致或正常，`warn` 有差异或需关注，`risk` 冲突或需更正，`info` 中性说明。
全页同一种状态始终用同一个词和同一种颜色。

**对照表**：外层必须包 `.table-wrap`。一致的行不加类，`tr.diff` 表示有差异，`tr.conflict` 表示相互矛盾；
最后一列放状态标记。需要排序的列在 `<th>` 上加 `data-sort`。
超过 30 行时，正文只放有差异的行，完整比对表放进 `<details>`。

**条形图 `.bars`**：适合 3～10 项的比例或排名。`--v` 填 0-100 的相对长度，`.val` 写原始数值和单位。
项目多于 10 个时改用表格。

**提示块 `.note`**：口径说明、前提假设、数据缺失说明。`.note.warn` 用于需要读者注意的限制条件。
一页不超过 2 个。

**时间线 `.timeline`**：有明确日期且先后顺序重要的事件（审批节点、项目里程碑）。

**折叠 `<details>`**：原文摘录、完整明细、计算过程。默认收起，打印时会自动展开。

**依据材料 `.sources`**：列出用到的文件和资料，写文件名和日期；引用了网页时写标题加链接。

## 不要做的事

- 不要为了「完整」把每种版块都用上。
- 不要在同一页里混用两种以上的强调方式（例如同时用色条、底色和图标表示严重程度）。
- 不要用表格做排版（把文字塞进表格只是为了对齐）。
