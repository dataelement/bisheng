# 沙箱使用说明

本文写**页面上怎么选执行方式、任务里文件该写到哪、提示词怎么约束**。Runner、token、DNS、环境变量见 [沙箱部署说明.md](./沙箱部署说明.md)。

选「沙箱运行」之前，部署侧要先把 `code-runner` 和 token 配好。存量升级不会自动改成沙箱。

---

## 1. 选择执行方式

只有全局超级管理员能改。打开管理端的**构建 → 工具**，左侧停在**内置工具**，找到**代码执行器**，点这一行右侧的设置图标。弹出的对话框标题是「编辑内置工具」。

对话框里「代码执行方式」有三个单选：

| 选项 | 选它的时候 |
|------|------------|
| 本地隔离运行 | 代码在 backend / worker 本机执行。`sandbox_conf.local_isolation`（或 `BS_SANDBOX_CONF__LOCAL_ISOLATION`）为 `uid` 时，子进程使用临时 uid；为 `off` 时仍以服务进程自己的用户跑。弹窗里不填地址。开启条件和目录权限见部署说明「本机执行的 uid 隔离」 |
| 沙箱运行 | 代码进入自建 `code-runner`。选项旁的提示写明：接入参数在系统配置里管理，这里不用填 token 或地址 |
| E2B沙箱运行 | 走云端 E2B。选中后才出现服务提供方、Domain、API Key，与自建副本池无关 |

点**保存**。写入的是 `t_gpts_tools_type.extra` 的 `type`（`local` / `container` / `e2b`）。任务模式、日常会话、助手、工作流里的代码执行器，以及代码节点，都按这一份来。已经打开的会话要重新发起一次，才会用到新选项。

---

## 2. 任务模式（灵思）

1. 打开工作台客户端（Helm 默认另开 `:4001`，路径 `/workspace`）。
2. 切到**任务模式**，工具里勾选**代码执行器**；要用知识库就一并勾选。
3. 执行方式选的是「沙箱运行」时，token / DNS 还要能打到 runner。Compose 的 `entrypoint.sh worker` 已经在后台拉起灵思，不要再起一份。Helm 使用 chart 里的灵思 Deployment。见部署说明「Linsight 进程」。

任务工作区（MinIO `workspace/{session_version_id}/`）会在 exec 前 copy-in：

| 路径 | 用途 |
|------|------|
| `output/` | **交付区**。只有这里会被收获给用户下载 |
| `scratch/` | 中间稿，跨轮不播种 |
| `uploads/` | 用户上传原件与解析出的 `.md` |
| `skills/` | 本轮技能包，只读 |
| `large_tool_results/` | 工具结果太大时的落盘，给模型稍后读取，**不是交付物** |

文件工具带前导斜杠（`/output/x`），沙箱 cwd 是工作区根，代码里必须写成相对路径 `output/x`。

---

## 3. 工作流代码节点

两件事分开，不要合成一个开关：

1. **能不能跑。** 系统配置 `workflow.code_node_enabled` 设为字面量 `true`（配置键是 `workflow`，种子在 `initdb_config.yaml`）。默认关闭。不是 `true` 时节点直接拒绝执行，跟选了哪种执行方式无关。
2. **在哪里跑。** 按「选择执行方式」。「沙箱运行」进入 `code-runner`，「本地隔离运行」在本机执行。页面写入的是 `extra.type`。
3. 编辑器「运行一次」在 backend 进程里执行，异步运行在 Celery worker。仓库默认的 Compose / Helm 已让这两个进程访问 runner。
4. 节点里写的是模块顶层的 `def main`。语法检查仍在本地 `ast.parse`，只有真正执行才进入所选的执行方式。

`BS_SANDBOX_CONF__CODE_NODE_ENABLED` 是遗留环境变量，既不是第 1 步的总开关，也不决定第 2 步。不用为了进沙箱去设置它。

---

## 4. 日常会话 / 助手

同样勾选代码执行器。本期**不把用户上传原件**送进沙箱，附件只抽文本进 prompt。一次 `run` 结束即 `DELETE` 租约。

---

## 5. 写提示词时要约束的路径

模型经常「口头说已生成」或写错路径。任务描述里建议写死下面几条：

```text
1. 先用知识库检索；若提示结果已存到 large_tool_results/<call_id>，不要重跑检索。
2. 代码执行器里只写纯 Python，不要调用 search_knowledge_base / read_file。
3. 用 open('large_tool_results/本轮返回的那个文件名') 读数据（相对路径，不要前导 /）。
   文件名以工具回显为准（call_xxxx），不要自己起 search_result.json。
4. 写文件前先：os.makedirs('output', exist_ok=True)
5. Excel 必须用 pandas + ExcelWriter / to_excel 写出真正的 xlsx，
   不要 open(..., 'w') 写一段中文再命名为 .xlsx。
6. 交付路径用 output/xxx.xlsx，不要 /output/...。
7. 只有代码 exitcode=0 且文件落在 output/ 才算完成，不要口头宣布已生成。
```

原因简记：

- `/output/x` 写到容器根，收获不到，用户侧「暂无产物文件」。
- 空目录 `output/` **不会**被 copy-in（只打文件），不 `makedirs` 会 `Cannot save file into a non-existent directory`。
- 文本冒充 `.xlsx` 会被收获逻辑丢掉（真实 Excel 以 `PK` 开头）。
- `large_tool_results/` 默认不跨轮带进新工作区（代码侧已补播种，旧镜像没有）。

沙箱里已装：pandas、numpy、matplotlib、openpyxl / XlsxWriter、python-docx、python-pptx、Pillow、reportlab、PyMuPDF（`import fitz`）。不要 `pip install`。

## 6. 产物对不上时

| 现象 | 原因 | 处理 |
|------|------|------|
| 工作区「暂无产物文件」 | 文件没写到相对 `output/`，或后缀与内容不符 | 看 `output_result.invalid_deliverables` / `phantom_deliverables` |
| `FileNotFoundError: large_tool_results/...` | 用了上一轮或自造的文件名 | 用本轮工具回显的 `call_id`；必要时本轮重新检索 |
| `Cannot save … directory: 'output'` | 沙箱里没有空目录 | 代码里 `os.makedirs('output', exist_ok=True)` |

勾了代码执行器仍在本机跑、编辑器代码节点不进沙箱、DNS 失败、下载 403，属于部署问题，见 [沙箱部署说明](./沙箱部署说明.md)「部署侧常见现象」。
