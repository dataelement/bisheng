# Feature: 多模型多模态微调闭环

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> 本文只定义业务范围与可测试验收标准。实现方案、接口、数据结构和文件清单写入同目录的 `design.md` 与 `tasks.md`。

**关联 PRD**: [文本图文视频微调改版需求](../../../docs/PRD/multimodal-finetune/毕昇文本与多模态模型微调改版需求分析.md) §3–§8
**优先级**: P0
**所属版本**: v3.1.0-beta1（F025；原在 v3.0.0 线以 111 编号开发，2026-11-18 迁入并改号）
**依赖**: 现有模型管理、微调任务、对象存储与训练服务能力
**本轮需求依据**: [数据集迭代范围梳理](./dataset-iteration-discovery.md) D1—D5（2026-11-25 用户确认范围，2026-11-26 用户确认本轮规格）。

> **范围边界**
> - **本次纳入**：
>   - 以可扩展能力目录展示和筛选多个基础模型，明确每个模型可用的数据类型、训练方式和验证状态。
>   - 文本、图文与视频数据集使用不同模板、上传提示、样本检测和预览，并兼容现有文本数据。
>   - 在数据集管理中展示历史旧格式及文本、图文、视频四类数据；新导入仅支持文本、图文、视频，来源为本地 JSON/JSONL/ZIP、FTP/显式 FTPS、SFTP、S3/MinIO 和 QA 知识库；支持远端清单及本地清单加远端媒体。
>   - 保留旧格式及旧数据；显式转换另生成新版文本数据集。仅保留一个“导入数据集”按钮，QA 知识库导入在同一弹窗中生成文本数据；不再接受旧格式新导入。
>   - 在单页创建任务中按数据类型选择已保存数据集，或临时上传一份本地数据；临时上传不新增可复用数据集或版本记录。
>   - 训练数据和验证媒体送达训练服务时，训练服务能下载平台存储链接就由它下载（拉取），下载不到就由平台把文件推给它（直传）；只要求平台能访问训练服务（2026-11-18 用户确认）。
>   - 从 FTP/FTPS、SFTP、S3/MinIO 导入的数据不经过平台：平台只读取清单、核对每个引用文件存在并记录大小、保存 3 条样本预览；开始训练时由训练服务用本次输入的账号密码直接从数据源下载（2026-11-19 用户确认）。
>   - 本地上传单个数据包最大 2 GiB（JSON/JSONL 文件最大 200 MiB），不做断点续传（2026-11-19 用户确认）。
>   - 创建任务前执行模型、数据、训练方式与训练资源的组合预检；不兼容或未验证组合不得提交。
>   - 从毕昇页面提交真实文本、图文或视频 LoRA 任务，展示真实阶段、日志、失败原因和产物状态。
>   - 训练方式恢复三种：文本模型 LoRA / Freeze / 全量，图文与视频模型 LoRA / Freeze（全量单张 24 GB 显卡放不下）；只做小样本真机验证（2026-11-20 用户确认）。
>   - 训练产物可在干净进程中重新加载，并用未参与训练的新文本、新图片或新视频执行推理验证。
> - **本次明确排除**：
>   - 长期保存的数据源凭据（每次训练重新输入）、SFTP 密钥登录、定时同步、后台批量导入和断点续传（SFTP 于 2026-11-18 按用户要求纳入，只支持账号密码登录）。
>   - 训练完成后自动清理训练服务器上的数据副本（直传包、远程下载的数据）：平台不管，由训练服务器运维自行处理（2026-11-20 用户确认）。
>   - 阿里云 OSS 等云对象存储的实测；S3 导入只实测 MinIO，界面只写「S3 / MinIO」（2026-11-20 用户确认）。
>   - 音频输入和视频音轨处理；页面和新接口均不开放。
>   - QLoRA、DPO、图像生成、语音生成和视频生成；这些组合尚未完成目标环境验证。
>   - 大规模训练效果、吞吐、并发和容量承诺；本次只验证产品与技术链路。
>   - 自动从原始材料生成业务标注；用户仍需提供监督答案，系统只做格式规范化和校验。
>   - 未经确认向远程仓库推送、合并或部署正式环境。

## 1. 用户故事

### 1.1 训练任务创建者

作为训练任务创建者，
我希望先选择文本、图文或视频任务，再看到兼容的基础模型、数据模板和训练方式，
以便在提交前知道当前组合是否真实可用，而不是通过模型名称猜测能力。

### 1.2 模型与训练服务管理员

作为模型与训练服务管理员，
我希望能够持续增加模型及其能力状态，而不需要为每个新模型重新改写创建页面，
以便逐步扩展经过验证的模型范围并阻止未验证组合进入训练。

### 1.3 任务验收者

作为任务验收者，
我希望在任务完成后看到可追溯的基础模型、数据版本、训练配置、产物检查和独立样本推理结果，
以便区分“进程执行结束”和“训练产物确实可以使用”。

### 1.4 数据准备者

作为数据准备者，
我希望在数据集管理中导入、分类和复用本地或企业文件服务中的样本，或在创建任务时临时上传一份数据，
以便区分需要长期管理的数据与仅用于本次任务的数据，避免临时文件进入已有数据列表。

## 2. 验收标准

### 2.1 模型能力与任务选择

- **AC-01** — THE SYSTEM SHALL 为每个可选基础模型显示其支持的数据类型、训练方式和验证状态。
- **AC-02** — WHEN 管理员增加一个符合平台规则的模型能力记录, THE SYSTEM SHALL 在创建任务时按该记录展示模型，且无需新增该模型专属的页面逻辑。
- **AC-03** — WHEN 用户选择文本、图文或视频数据类型, THE SYSTEM SHALL 只允许选择同时支持该数据类型、训练方式和当前训练服务的模型组合。
- **AC-04** — IF 模型能力缺失、组合未验证或训练服务不可用, THEN THE SYSTEM SHALL 禁止提交任务并显示可定位的原因。
- **AC-05** — WHEN 用户尝试音频输入, THE SYSTEM SHALL 拒绝任务；视频画面训练按已验证的模型组合开放，视频音轨不参与训练。

### 2.2 数据模板、检测与预览

- **AC-06** — WHEN 用户选择文本数据, THE SYSTEM SHALL 展示文本样本模板、文本上传要求、文本检测结果和文本样本预览。
- **AC-07** — WHEN 用户选择图文数据, THE SYSTEM SHALL 展示包含媒体引用的图文模板、图片上传要求、图片检测结果以及问题、图片和标准答案预览。
- **AC-08** — IF 样本字段错误、媒体缺失、引用越界、文件损坏或数据类型与实际内容不一致, THEN THE SYSTEM SHALL 阻止该数据版本用于训练并逐项报告错误位置和原因。
- **AC-09** — THE SYSTEM SHALL 保留历史文本训练任务的查询、取消及结果查看；新版任务可选择文本分类数据，旧格式数据先转换为新版文本后供新版任务选择。

### 2.3 预检与训练执行

- **AC-10** — WHEN 用户完成数据、模型、训练方式和训练资源选择, THE SYSTEM SHALL 在正式提交前返回该组合的预检结论。
- **AC-11** — IF 处理器、模板、运行依赖、GPU 资源、上下文预算、媒体约束或 LoRA 目标不满足, THEN THE SYSTEM SHALL 拒绝任务提交并返回对应检查项的失败原因。
- **AC-12** — WHEN 已验证的文本 LoRA 组合通过预检并提交, THE SYSTEM SHALL 执行真实训练并展示来自训练服务的状态、日志和结束原因。
- **AC-13** — WHEN 已验证的图文 LoRA 组合通过预检并提交, THE SYSTEM SHALL 使用样本关联的真实图片执行训练并展示来自训练服务的状态、日志和结束原因。
- **AC-14** — WHEN 用户取消尚未结束的任务, THE SYSTEM SHALL 停止后续训练流程并将任务显示为已取消，不得显示为训练成功。
- **AC-15** — IF 训练或产物检查失败, THEN THE SYSTEM SHALL 将任务显示为失败并保留可定位的阶段和原因，不得仅以进程退出作为成功依据。

### 2.4 产物与独立样本验证

- **AC-16** — WHEN 训练执行正常结束, THE SYSTEM SHALL 检查该训练方式要求的模型、适配器、分词器或处理器产物并记录检查结论。
- **AC-17** — WHEN 文本 LoRA 产物检查通过, THE SYSTEM SHALL 能在干净进程中重新加载基础模型和适配器，并对未参与训练的新文本执行推理。
- **AC-18** — WHEN 图文 LoRA 产物检查通过, THE SYSTEM SHALL 能在干净进程中重新加载基础模型、处理器和适配器，并对未参与训练的新图片执行推理。
- **AC-19** — WHEN 用户查看验证结果, THE SYSTEM SHALL 显示基础模型身份、适配器身份、数据版本、生成配置、输入摘要和真实输出，并明确区分基础模型与微调模型结果。
- **AC-20** — IF 真实推理未执行或执行失败, THEN THE SYSTEM SHALL 显示未验证或失败，不得使用预设答案或模拟结果替代。

### 2.5 隔离与真实性

- **AC-21** — THE SYSTEM SHALL 只向当前租户有权访问的用户展示其训练数据、任务、日志、产物和验证记录。
- **AC-22** — THE SYSTEM SHALL 在界面和任务记录中区分已验证、待验证、模拟和失败状态，且模拟结果不得满足真实训练或真实推理验收标准。
---

- **AC-23** — WHEN 已验证的视频 LoRA 组合通过预检并提交, THE SYSTEM SHALL 解码样本关联的视频画面并完成训练、产物检查和新视频独立重载推理，保留实际配置与输出。

### 2.6 数据集复用与任务临时数据（2026-11-25 修订）

- **AC-24** — WHEN 用户在创建任务中准备数据, THE SYSTEM SHALL 提供分类匹配的已有数据集选择和一份本地数据的临时上传入口；需要长期复用的本地或远程数据在数据集管理中导入和保存。
- **AC-25** — WHEN 用户导入远程数据, THE SYSTEM SHALL 允许一次填写连接与媒体根目录，并选择远端清单/完整 ZIP 或本地清单；每条样本只使用相对媒体路径。
- **AC-26** — WHEN 用户在数据集管理中导入数据且通过校验, THE SYSTEM SHALL 保存可复用的数据版本，供后续任务按分类选择；同一任务只使用一份已保存数据或临时上传数据，更换数据替换当前选择。
- **AC-27** — THE SYSTEM SHALL 展示所用数据的实际样本数、媒体数、内容哈希及可用样本预览，已保存数据同时展示版本标识，临时数据明确标为仅本次任务使用；IF 连接失败、清单错误或媒体缺失, THEN THE SYSTEM SHALL 显示可定位的错误并阻止失败数据用于训练。
- **AC-28** — THE SYSTEM SHALL 仅在本次导入或本次训练提交中使用连接凭据，不把凭据保存到平台数据记录、浏览器存储、URL、错误日志或训练服务的任务目录与日志；格式校验失败也不得回显凭据。
- **AC-29** — THE SYSTEM SHALL 只列出和预览当前租户有权访问的数据；提交训练时复核已保存数据或当前用户本次临时上传的数据及服务端校验结论，不接受浏览器伪造的文件归属、分类、样本数或校验报告。
- **AC-30** — WHEN 用户导入视频数据, THE SYSTEM SHALL 区分平台的结构校验与训练服务的真实解码；连接器读取成功或网页预览成功不能代替训练和独立推理验收。

### 2.7 数据送达训练服务与 SFTP（2026-11-18 用户确认）

- **AC-31** — WHEN 训练服务无法下载平台存储链接, THE SYSTEM SHALL 由平台把训练数据或验证媒体推送给训练服务，并在任务记录中注明本次是拉取还是直传；只需平台能访问训练服务即可完成训练与验证。
- **AC-32** — IF 直传失败（训练服务不可达、内容哈希不符或超过大小上限）, THEN THE SYSTEM SHALL 在创建任务前拒绝提交并给出可定位的原因，不得留下无数据的远端任务。
- **AC-33** — WHEN 用户从 SFTP 导入, THE SYSTEM SHALL 要求账号和密码；IF 填写了主机指纹且与服务器不符, THEN THE SYSTEM SHALL 在发送密码前中止导入。

### 2.8 远程数据直达训练服务与 2 GB 本地上传（2026-11-19 用户确认）

- **AC-34** — WHEN 用户从 FTP/FTPS、SFTP 或 S3/MinIO 导入, THE SYSTEM SHALL 只读取清单和前 3 条样本引用的媒体，核对其余每个引用文件存在且非空并记录大小，图片和视频本体不写入平台存储；IF 有文件缺失, THEN THE SYSTEM SHALL 指出样本序号和文件名并不生成版本。
- **AC-35** — WHEN 用户用远程数据版本提交训练, THE SYSTEM SHALL 要求再次输入数据源密码或密钥，并在创建任务前由训练服务登录数据源、读取一个计划文件；IF 失败, THEN THE SYSTEM SHALL 拒绝提交、不创建任务，并给出原因。
- **AC-36** — WHEN 训练服务下载远程数据, THE SYSTEM SHALL 检查文件数、总大小和磁盘空间上限，并核对每个文件大小与导入时一致；IF 不一致, THEN THE SYSTEM SHALL 让任务失败并提示重新导入，而不是用变化后的数据训练。
- **AC-38** — WHEN 用户选择基础模型, THE SYSTEM SHALL 列出 LoRA、Freeze、全量三种训练方式，只允许选择训练服务为该模型提供的方式，其余置灰并说明原因；提交时只发送所选方式的参数，任务详情显示训练方式。
- **AC-39** — IF 登记的训练服务没有能力目录接口（多模态版本之前的训练服务）, THEN THE SYSTEM SHALL 提示训练服务版本过旧、需要升级，而不是笼统地报模型列表获取失败。
- **AC-37** — WHEN 用户从本地上传数据包, THE SYSTEM SHALL 接受最大 2 GiB 的包（JSON/JSONL 最大 200 MiB）并显示上传进度；超过上限时在上传前提示改用远程数据源。

### 2.9 数据集分类、历史转换与统一导入（2026-11-26 用户调整）

- **AC-40** — THE SYSTEM SHALL 在数据集管理中展示旧格式、文本、图文、视频四类标识，支持按分类筛选；数据来源与数据分类分别展示，不能用本地或远程来源替代格式分类。
- **AC-41** — THE SYSTEM SHALL 通过统一“导入数据集”功能支持本地、FTP/显式 FTPS、SFTP、S3/MinIO 导入文本、图文、视频数据；文本文件须为 messages 格式，分类不符或旧格式文件拒绝保存。
- **AC-42** — THE SYSTEM SHALL 保留已有数据集的内容、归属及可查询性，旧格式数据保持旧格式标识，不自动视为已转换的新版文本；已保存的新版文本、图文、视频数据能在统一列表中按所属分类找到，不因原入口不同而重复或消失。
- **AC-43** — WHEN 用户对旧格式数据执行转换, THE SYSTEM SHALL 保留原数据及原记录，另生成一份经过校验的新版文本数据集并标为文本；转换保留问题、补充输入和标准答案，不能静默丢弃原有会话内容。
- **AC-44** — IF 旧格式样本无法完整转换或校验失败, THEN THE SYSTEM SHALL 报告对应样本及原因，不覆盖原数据，也不生成可用于训练的成功结果。
- **AC-45** — WHEN 用户在创建任务中选择文本、图文或视频类型, THE SYSTEM SHALL 仅列出数据集管理中当前租户有权使用、已校验且分类一致的数据；旧格式数据不直接进入新版任务选项，转换后的文本数据进入文本选项。
- **AC-46** — WHEN 用户在任务内临时上传一份本地数据且校验通过, THE SYSTEM SHALL 允许预览并作为当前任务数据使用，不新增可复用数据集或版本记录，不出现在数据集管理页及其他任务的已有数据列表中。
- **AC-47** — WHEN 用户取消创建任务、上传失败或任务创建失败, THE SYSTEM SHALL 不把本次临时数据转为已保存数据集；提交失败后仍可在数据有效且归属不变时修改任务配置并重试。
- **AC-48** — WHEN 用户使用临时数据成功创建任务, THE SYSTEM SHALL 在该任务中保留所用数据的引用与校验快照，供后续执行、查看和追溯，不因此将其加入可复用数据集列表。
- **AC-49** — THE SYSTEM SHALL 仅展示一个“导入数据集”按钮，将 QA 知识库选择合并进同一导入弹窗，不另设“加入文本数据”入口。
- **AC-50** — WHEN 用户在统一导入弹窗选择 QA 知识库来源, THE SYSTEM SHALL 复用原有知识库选择范围、分页搜索及问答生成规则，校验访问权限后直接生成文本类型数据集；QA 不生成图文或视频数据。
- **AC-51** — IF 用户切换任务数据类型, THEN THE SYSTEM SHALL 清除不兼容的已有选择和临时数据；提交时再次校验数据归属、分类及可用性，不因前端仍保留旧值而创建错误任务。
- **AC-52** — THE SYSTEM SHALL 沿用数据集管理、微调任务及 QA 知识库各自的权限边界；仅具有任务权限的用户可临时上传训练数据，不因此获得保存、修改或删除可复用数据集的权限。

## 3. 边界情况

- 同一个模型在不同训练服务上的可用状态可能不同；不可把一个环境的成功自动推广到所有环境。
- 同一模型名称对应不同版本或权重时，必须能够区分其验证状态；名称相似不代表能力相同。
- 数据类型切换后，先前选择的不兼容模型、训练方式、数据版本或参数不得被静默保留并提交。
- 在数据集管理中保存的本地上传和文本远程导入版本保存在平台，不随来源变更；远端服务不可达时仍能复用。任务内临时上传不生成可复用版本。图文/视频远程版本每次训练都从来源下载：来源不可达时无法训练；文件大小变化会被发现并要求重新导入，但同样大小的内容替换发现不了（导入时不逐个读取文件做哈希）。
- 清单中的绝对 URL、目录越界、缺失媒体或超过本轮导入边界的数据应被拒绝；远端 ZIP 自带媒体时不再从根目录重复取媒体。
- 图文样本存在多图、无图、重复媒体或媒体不可解码时，应按当前模型约束给出明确结论。
- 训练服务短暂不可达、预检结果过期或 GPU 状态发生变化时，提交阶段应重新确认可用性。
- 任务训练完成但产物缺失、处理器不完整或干净进程重载失败时，最终结果应为失败或未验证。
- 页面轮询中断、浏览器刷新或平台进程重启后，任务真实状态不得由前端本地状态替代。
- 旧文本任务缺少新增字段时仍应可查看；系统不得把历史缺失信息伪造成已验证结论。
- 旧格式转换失败、重复点击或重试均不得覆盖原数据；无法识别的原内容应报错，不能静默丢弃后显示成功。
- 数据集在任务选择后被删除、分类不再匹配或权限变化时，应在提交阶段拒绝使用，而不是继续信任页面旧选项。
- 临时上传与已有数据相互替换时，同一任务只保留当前选择；临时上传不提供任务内自动保存为数据集的行为。
