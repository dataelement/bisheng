# 运输方案与费用查询

## 先检查实际可用工具

本技能只使用平台“API工具”中配置的运输业务接口。查找当前可用工具中描述包含“运输唯一业务入口”、参数为request_json和context_id的工具；OpenAPI operationId为transport_execute，实际工具名称由平台生成，不固定工具ID或前缀。

如果本轮实际工具列表中没有该工具：立即输出“运输查询工具未绑定，本轮已结束，未执行查询。请在工具中选择‘运输方案与费用查询 API’后重新发送。”然后结束。不得等待、调用ask_user、规划子任务、猜造transport_history工具、用代码执行器或其他场景工具绕过。检查不到工具即失败，不先承诺正在查询。

## 调用合同

每轮最多调用该工具一次；模型只提取用户条件，不写Python，不访问源文件，不自行取数、计算费用或编造推荐。

原生工具有两个字符串参数：
- request_json：业务request对象的严格JSON字符串，不再套request。只传动作、业务条件、筛选、排序或费用引用。
- context_id：首次查询传空字符串。若本轮详情问法附有 \`<transport_detail_v1>\` 块，这是运输入口从当前 Chat 的原生工具回执提取的完整入参。逐字传递其中的 \`request_json\` 和 \`context_id\`，包括原查询编号。无需查看上一条回答或从上一轮回答提取链接。没有该块时，只在同一 Chat 可见原工具回执或其 F 引用链接时才沿用对应的 \`context_id\`，缺少可靠引用就结束，禁止传空、猜测或跨 Chat 沿用。

历史调用示例：
```json
{"request_json":"{\"action\":\"history\",\"query\":{\"master_numbers\":[\"MBL-DEMO-01\"],\"house_numbers\":[\"HBL-DEMO-01\"]}}","context_id":""}
```
详情业务对象为 {"action":"detail","reference":"F01"}，转成request_json字符串并传当前context_id。运输入口传入的 query_id 必须保留，由业务服务校验当前查询。兼容旧对话时省略 query_id 仍可由业务服务绑定该上下文的当前查询。\`<transport_detail_v1>\`、context_id 和 query_id 只供工具入参定位，不在答复中展示。

工具返回JSON字符串，解析后完整展示answer字段，保留费用表、共享范围、推荐依据和必要限制；不要展示外层JSON或context_id。不重新计算或删改业务内容，不增加第二次调用。保留 F01 等费用编号，保留 Markdown 链接可供点击；运输入口会直接从原生工具回执定位续问，用户要求用纯文本显示费用编号时也可直接续问。answer开头的business-process块是业务回顾元数据，原样保留交给界面渲染。

返回terminal=true且next_action=none时立即结束，包括澄清、空记录、busy、参数/状态/取数错误。遇到HTTP错误、鉴权失败、连接失败、超时或工具报错，明确说“运输工具调用失败，本轮已结束；这不表示没有历史费用。请联系管理员检查工具配置或服务状态后重试。”不得继续等待、自动重试、换工具或生成正常费用结果。只有用户下一轮明确补充、纠正或重试才可再次调用。

## 业务规则

history 按主单、分单、费用单或明确条件查历史。用户同时给出主单号和分单号时，分别传 master_numbers 和 house_numbers。主单号定位候选，分单号定位同一主单下的具体记录。只有主单号时列候选费用单并保留“分单未确认”。用户后来补分单号时，用原主单和新分单发起组合查询，保留已明确的取数条件。组合无匹配时保留未核实状态。分单或费用单单独查询仍可使用。

历史查询只返回历史费用与覆盖。用户明确请求新货运输方案推荐时走 inquiry，同时返回历史参考。规格型号为物料识别字段。首问同时明确的日期、方式、危化属性、筛选和排序须完整传递。

历史追溯示例：

```json
{"request":{"action":"history","query":{"house_numbers":["ELC24018561","NYCSHA24015477"]},"set":{"date_from":"2024-01-01","date_to":"2024-12-31","date_field":"etd"},"sort":"source","page_size":5}}
```

询价示例：

```json
{"request":{"action":"inquiry","target":{"origin":"JFK","destination":"TFU","model":"683-3-2/X-310A","gross_weight_kg":100,"length_cm":107,"width_cm":61,"height_cm":61,"mode":"空运","dangerous_goods":"危化品"}}}
```

inquiry 需要起运地、目的地、型号、毛重、包装长宽高及危化属性。未知值省略，呈现工具返回的澄清。重量仅使用明确毛重，包装数量暂不参与匹配或筛选。已归一重量用 gross_weight_kg、尺寸用 length_cm、width_cm、height_cm。原始值用 gross_weight={value,unit}、packaging={length,width,height,unit} 交代码换算。同一量只传一种形式。地点使用用户确认的代码或名称。

用户明确说“危险品”与“危化品”时，dangerous_goods传“危化品”；明确“非危险品”与“非危化品”传“非危化品”。不能因用词不同重复询问；未知、可能、待确认或相互冲突仍需澄清，不把“普货”自动推断为非危化品。

推荐由工具按服务商和运输方式固定计算，优先看经验层级、该层级票数、累计票数和最近 ETD。明确方式、服务商、币种、日期始终传入。历史费用按原币分组。没有同路线历史时可返回相近经验并明确提示。直接展示工具推荐表。

历史参考明细先取同路线及保护条件下的完整候选，再比较同一明细的全匹配或按物料、毛重、尺寸有相同才收窄。统一 KG/CM 后精确比较，长宽高按同一顺序。历史毛重未知时保留未知。未给方式时历史明细按方式分组，已明确的危化、方式、服务商、币种、日期保持。直接展示代码给出的匹配步骤和差异。

续问通过同一原生 API 工具处理，沿用当前 context_id：

- `show`：page/page_size/sort；默认每页5张，最多20张。排序仅source（来源顺序），F编号不随排序/翻页改变。
- `filter`：set追加/替换附加条件，unset撤销指定条件，其他筛选保留。撤销原API范围需要新查询，不能用旧子集冒充更大范围。
- `reset`：用户明确清除附加筛选时使用，保留原始取数范围。
- `detail`：reference为当前F编号，query_id可省略，由业务服务绑定当前上下文；可用page翻关联成员。旧查询引用不能混用。
- `inquiry`：改变型号/毛重/包装时重新匹配。同保护范围由工具复用完整路线池；改变路线或保护条件时工具重新取数。不能只filter旧的最终候选。

直接展示工具 answer 并结束。费用金额按费用单去重，同主单下不同费用单分别展示。整单覆盖只计该费用单的实际关联明细，与本次命中分开。共享费用保留账单原币整单金额。用户回复中省略人民币开票金额、货值及运费占比。

主结果只保留费用引用（如F01）与关联运输分单号。分单号在运输明细中定位一次，型号、毛重、包装尺寸及匹配差异跟随同一行；完整共享覆盖和未分摊提示必须保留。费用单号、主单号、合同号、订单号及来源行号放到detail返回，按费用账单、运输单据、业务关联、数据来源分组。用户说“查看F01详情”时走detail，不重复新查历史；不能在主结果自行补回这些原始编号。

用户要求自动分摊、每公斤运价、本次正式报价，或要求判断账单作废/差额承担方时，调用`{"request":{"action":"explain_limits"}}`，直接显示固定返回并结束。不能自由扩写账单已作废、价格已失效、合同责任或风险承担等未给事实，也不因用户要求“假设后写成事实”而推断。此动作不取数、不改变当前查询。查询历史费用走history，新货运输推荐走inquiry，不能误当成要求生成当前报价。

当前数据修订4为联调合成扩充。当前业务不展示或使用历史报价时间、运费开票日；不提供开票日筛选或排序。用户询问这些日期时说明当前范围不支持，不取日期、不用ETD/ETA替代。历史查询只返回费用及完整覆盖，不自动附运输方案推荐。仅用户明确请求新货运输推荐时走inquiry。推荐排序不使用人民币金额、货值、运费占比或包装数量；金额按原币分组展示，不跨币种比较。
