## 依赖、风险与验证

复用现有登录、全局超管身份及工具权限体系，不新增领域对象、数据库字段或权限体系。临时准入的恢复需独立评估。

正常执行保留已知同族 SSRF/出站风险，非本补丁覆盖；不提供同步安全传输或全局工具出站保护。历史 195 passed 属于已撤销的扩大范围阶段；当前最终回归待主实施者补实际结果，不作为已通过发版门禁。

## 中间件凭据治理增量（F003）

> 归档依据：当前工作分支 `feat/3.1-beta2`，沿用仓库 `v3.1.0-beta1` 的版本目录命名惯例。本文件仅登记当前已讨论特性的增量，不推断本版本其他交付内容。
>
> 既有领域归属、不变量和错误码占用继续遵循 [v3.1.0-beta1](../v3.1.0-beta1/release-contract.md)、[v3.0.0](../v3.0.0/release-contract.md) 及其引用的版本契约。架构约束以 [constitution.md](../../docs/constitution.md) 为准。

### 表 1：领域对象归属

| 增量范围 | Owner Feature | 边界 |
| --- | --- | --- |
| 中间件凭据交付、配置密码加密、外置密钥及其维护流程 | F003-middleware-credential-security（本版本） | 覆盖 MySQL、Redis、MinIO、Elasticsearch、Milvus 及其现有消费者；不新增业务领域对象，不改变业务账号权限或数据归属 |
| 共用加密工具关联的存量凭据重加密 | 原业务 Owner 保持不变；F003 仅协调受控加密维护 | 组织同步凭据、沙箱配置令牌及对应缓存只允许变更加密表示；不得修改逻辑凭据、业务内容、租户归属或权限，不新增业务写入 API |

### 表 2：跨 Feature 不变量

沿用继承版本的既有不变量，不新增或修改全局业务不变量。外置密钥、凭据同步、失败恢复等特性验收要求在 F003 spec 中维护；静态部署秘密由运维向每个节点显式分发，不依赖某个 API 节点的本地文件自动共享。

### 表 3：Feature 依赖图

| Feature | 依赖 | 说明 |
| --- | --- | --- |

### 已分配模块编码（MMMEE）

本次规格不新增业务 HTTP API 或分配错误码；沿用现有占用。设计阶段如确需增加可观测业务错误码，必须先核对继承契约及代码占用并更新登记，不在本文件预留猜测编号。
