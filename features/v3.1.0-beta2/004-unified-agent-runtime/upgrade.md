# F004 统一运行时升级说明

本文给执行升级的人看。F004 把日常对话和深度研究放到同一个 agent 内核上运行。升级后所有用户自动走新链路，不需要在管理界面做任何操作（design 决策 13）。

## 一、变更一览

| 对象 | 变更 |
| --- | --- |
| 数据库 | 没有表结构变更，没有 Alembic 迁移，没有数据迁移。 |
| Python 依赖 | `deepagents` 0.6.12 → 0.7.39；`langchain` ≥ 1.5；`langchain-core` ≥ 1.8.1。锁文件 `uv.lock` 已更新。 |
| Redis | 新用到 Stream 和 Lua 脚本。最低版本 5.0。随产品交付的 7.0.4 满足要求。 |
| 开关 | `unified_runtime_enabled` 缺省为开启。配置里没有这个键也按开启处理。 |
| 前端 | client 前端改用新的发送协议和事件订阅。必须与后端同一批发布。 |
| 进程 | API 进程和深度研究 worker 都有改动，两者都要重启。 |

## 二、升级前检查

| # | 检查项 | 方法 | 不满足时 |
| --- | --- | --- | --- |
| 1 | Redis 版本 ≥ 5.0 | `redis-cli INFO server` 看 `redis_version` | 先升级 Redis。低于 5.0 时对话无法收到任何回答。 |
| 2 | 使用 Redis Cluster 时，客户端允许 Lua 脚本 | 确认没有禁用 `EVAL` / `EVALSHA` | 放开这两个命令。 |
| 3 | 各节点时钟已同步 | 各节点执行 `date -u` 对比，偏差应在 1 秒内 | 配置 NTP。运行租约按时间判断，偏差过大时运行会被误判为失效。 |
| 4 | 是否有客户端仍使用旧协议 | 盘点桌面端、未随本次升级的前端静态资源、直接调用 `/api/v1/workstation/chat/completions` 的集成方 | 见第五节。 |

## 三、升级步骤

1. 部署新版本后端代码。
2. 在后端目录执行 `uv sync --frozen`。镜像部署则使用新镜像，不需要这一步。
3. 重启 API 进程。
4. 重启深度研究 worker（`bisheng/linsight/worker.py`）。重启会终止正在执行的深度研究任务，请选在空闲时段。
5. 发布 client 前端的新构建。使用了 CDN 或浏览器缓存时，清掉旧的静态资源。
6. 按第四节验证。

第 3、4、5 步要在同一个维护窗口内完成。只升级其中一部分时，新旧协议会混用，表现见第五节。

## 四、升级后验证

| # | 操作 | 预期 |
| --- | --- | --- |
| 1 | 调用 `GET /api/v1/workstation/config` | 返回里有 `unified_runtime_enabled: true`。 |
| 2 | 在对话页发一条普通问题 | 正常流式回答。API 日志出现 `direct run=… ended status=finished`。 |
| 3 | 回答过程中再发一条消息 | 新消息显示为排队，当前回答读到它之后继续。 |
| 4 | 回答过程中点停止 | 回答停住，已生成的文字保留。 |
| 5 | 发一条深度研究任务 | 3 秒内出现执行反馈，任务正常完成并给出文件。 |
| 6 | 刷新正在回答的页面 | 回答内容补全并继续流式输出。 |

## 五、仍使用旧协议的客户端

后端升级后默认走新链路。仍按旧协议发送的客户端会遇到两种情形：

- 回答进行中再发一条消息，客户端只收到结束帧，看不到这条消息被处理。
- 直接回答里 agent 向用户提问时，客户端看不到提问卡片。

处理办法二选一：把这些客户端升级到支持新协议的版本；或者按第六节把所在租户临时回退到旧通道。

## 六、应急回退

回退只用于线上出现必须立即绕开的问题。它没有界面入口，需要直接改库。

1. 确定记录位置。启用了多租户时，记录在 `tenant_workstation_config` 表，条件是 `tenant_id = <租户 id>` 且 `key = 'workstation'`。未启用多租户时，记录在 `config` 表，条件是 `key = 'workstation'`。
2. 备份这条记录的 `value` 字段。
3. 在 `value` 的 JSON 顶层加入 `"unified_runtime_enabled": false`。如果记录不存在，先在管理界面保存一次工作台配置，再修改。
4. 让用户刷新对话页。前端在加载配置时读取这个值。
5. 确认 `GET /api/v1/workstation/config` 返回 `unified_runtime_enabled: false`。

恢复新链路时，把这个键删掉或改为 `true`。

回退期间的限制：回退前由新链路开始、尚未结束的运行不会迁移到旧通道，请等它们结束或手动停止后再回退。

## 七、已知限制

| 限制 | 说明 |
| --- | --- |
| 未在两节点环境实测 | AC-33 的多节点场景只有设计和单元测试，没有在两台机器上执行过。 |
| 未在 DM8 环境实测 | AC-42 未执行。 |
| 排队位置不显示 | 深度研究排队时，后端有位置数据，界面目前不显示具体位置（AC-36）。 |
| Redis 长时间不可用 | Redis 不可用超过约 30 秒时，正在执行的运行会被判为租约失效并结束。 |
