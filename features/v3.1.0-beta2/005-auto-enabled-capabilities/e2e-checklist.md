**测试环境**：114，平台端 http://192.168.106.114:13000/ ，用户端 http://192.168.106.114:13000/workspace （13000 是 deploy.sh 重建的静态包；4001 的 vite 未运行）
**账号**：ADM = admin；U1 = 根租户普通用户（114 上的 `f005_noperm`）；子租户用户 `shuiwu`（租户 36）。密码见 `.claude/docs/dev-environments.md` 和 `/opt/bisheng-ops/.env`。
**自动化部分**：`src/backend/test/e2e/test_e2e_f005_auto_enabled_capabilities.py` 已覆盖 AC-01/02/06/07/10/11/13/14/24（2026-11-20 在 114 上 7/7 通过）。本清单只列界面交互和环境相关的用例。
**收尾**：每项做完把设置改回：代码执行器「默认勾选」，PPT 制作的「自动启用」关闭。

## 平台端

### AC-01、AC-02：已选工具的使用方式（TC-AE-001）
- [ ] ADM 登录，进入「构建 → 工作台 → 日常模式」，滚到「已选工具」。
- [ ] 每行右侧有「使用方式」下拉框，三个选项各带一行说明：用户自选、默认勾选、自动启用。
- [ ] 点击下拉框时，左侧工具列表不滚动（点击不冒泡）。
- [ ] 把代码执行器改为「自动启用」，点保存。预期：出现保存成功提示。
- [ ] 刷新页面。预期：代码执行器仍是「自动启用」，其他工具不变。

### AC-06：技能管理「自动启用」列（TC-AE-009）
- [ ] 进入「工具与技能 → 技能」。表头有「自动启用」列，鼠标悬停表头出现说明。
- [ ] 打开 PPT 制作这一行的开关。预期：开关立即变为开，刷新后仍为开。
- [ ] 断网或停后端后再切换开关。预期：开关回到原状态，并出现错误提示。

### AC-07：停用的技能不能设置（TC-AE-010）
- [ ] 关掉一个自定义技能的状态开关。
- [ ] 预期：它的「自动启用」开关变灰、不可点击；悬停时提示需要先启用技能。

### AC-08：内置技能同步不覆盖设置（TC-AE-014）
- [ ] 打开 PPT 制作的自动启用，然后在 114 执行 `systemctl restart bisheng-api`。
- [ ] 刷新技能管理。预期：PPT 制作的「自动启用」仍为开。

## 用户端

### AC-10、AC-11：选择入口不展示（TC-AE-003、TC-AE-011）
- [ ] U1 登录用户端，打开输入框的工具菜单。预期：没有代码执行器，输入框里也没有它的标签。
- [ ] 打开侧边栏「工具与技能」，分别切到工具和技能。预期：没有代码执行器，也没有 PPT 制作。
- [ ] 打开技能选择器（直接回答一次、深度研究一次）。预期：没有 PPT 制作。

### AC-12：旧选择不残留（TC-AE-008）
- [ ] 设置前，U1 勾选代码执行器并发送一条消息。
- [ ] ADM 把代码执行器设为自动启用。U1 刷新页面。
- [ ] 预期：输入框没有代码执行器标签；再发一条需要运行代码的消息，执行过程里只有一次代码执行器调用，没有报错。

### AC-23：个人停用不影响（TC-AE-007）
- [ ] 设置前，U1 在「工具与技能」里停用代码执行器。
- [ ] ADM 把它设为自动启用。U1 发送「运行一段 python 代码打印 sys.version」。
- [ ] 预期：执行过程里出现代码执行器调用，没有「已对此账号关闭」之类的报错。

### AC-20：执行过程照常显示
- [ ] 上面任一条会调用代码执行器的消息，展开执行过程。预期：能看到代码执行器的调用步骤；PPT 任务能看到读取技能说明的步骤。

## 开放 API

- [ ] 调用开放 API 读取日常配置。预期：返回的工具列表里有代码执行器。
