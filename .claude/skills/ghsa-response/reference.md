# 安全公告记录模板

这里只规定任何一条公告都使用的字段。某一批的编号、提交、版本和条数写在 `security-response-private/advisories/` 对应目录里，不写进本技能。

## index.json

每条一个对象：

```json
{
  "id": "公告编号",
  "seq": 1,
  "verdict": "是",
  "status": "搁置-已修复待验收",
  "path": "security-response-private/advisories/02-搁置-已修复待验收/公告编号",
  "parked": true,
  "park_reason": "公告所述问题已有修复，测试验收尚未通过",
  "park_location": "security-response-private/advisories/02-搁置-已修复待验收/公告编号"
}
```

`verdict` 只使用「是」「否」「证据待补充」。`status` 使用目录名去掉数字前缀后的文字。未搁置时 `parked` 为 false，两个 park 字段为 null。

## 最终处理报告.md

```markdown
# 公告编号

- 序号：
- 名称：
- 链接：
- 判定：
- 当前状态：
- 搁置原因：不适用，或一句原因
- 搁置位置：不适用，或当前目录路径

## 结论

只写这条公告的结论。
```

## 处理证据.md

写基线提交、核对过的路径、最早证据提交，以及复测的角色和业务结果。不写利用步骤，不写内网地址、账号、口令、token、用户 id。

## 处理方法.md

写已完成的处理。若判定为「是」且已处理完，写明先礼貌回复，真实环境验证通过前不关闭、不发布。验证通过后把本目录整份移到 `05-待继续-验收已通过/`，追加进度并更新 `index.json`，然后再关闭。

## 需要回复的内容.md

正文放在这个文件里，语言跟报告者。判定为「是」且处理完成时，正文是礼貌回复：问题已处理、修复所在的产品版本、修复提交的完整哈希、仍在测试则尚未发布、真实环境验证通过前不关闭。证据不足时写「当前不回复」和原因。已有评论时，在 `处理进度.md` 记下这次是修改原评论还是新增评论。

## 处理进度.md

```markdown
# 处理进度

- 当前状态：
- 搁置原因：
- 搁置位置：

## 记录

- YYYY-MM-DD：状态、原因、位置。
```

新记录只追加在「记录」下面。移动目录后，文件顶部的当前状态、搁置原因和搁置位置改成移动后的值。
