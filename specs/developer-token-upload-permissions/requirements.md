# 开发者 Token 目标上传权限修复

- Feature ID: `developer-token-upload-permissions`
- Mode: `bugfix`
- Updated: `2026-10-14`
- Authorization: 用户明确要求本地修复并验证，禁止直接修改生产。

## 问题与范围

候选列表和最终目标校验把 `upload_file_to_space` / `upload_file_to_folder` 传入 OpenFGA 的关系查询，但关系模型只有 `can_edit` 等关系，导致 `relation_not_found` 后列表为空或保存被拒绝。应由既有细粒度权限服务解释业务上传权限。

本次不扩展公共/部门空间范围，不改组织、租户、业务域绑定、权限授予、数据库结构、前端配置方式或部署。保护现有目录独立权限改动。

## 需求与验收

| Requirement | Acceptance | 行为 | Verification |
|---|---|---|---|
| REQ-1 | AC-1 | 绑定用户具备上传权限的已发布公共/部门空间进入候选；无上传权限的空间隐藏；先权限过滤再分页/搜索 | 定向服务回归和仓储验证 |
| REQ-2 | AC-2 | 目录上传按细粒度权限及最近目录授权覆盖计算；仅展示授权目录和必要祖先，祖先不因导航获得上传权限 | 真实细粒度计算配合可控关系模型的集成回归 |
| REQ-3 | AC-3 | 保存与共享运行时校验使用同一上传判断；已知固定目录 ID 校验目录，拒绝无权限、错配和失效目标 | 根/目录允许及拒绝参数化回归 |
| REQ-4 | AC-4 | 始终以 Token 绑定用户为主体，保持租户/类型/状态/业务域限制；不修改生产及用户已有改动 | 相关回归、diff 检查 |

路径目录尚未解析成目录 ID 时，保持现有空间根目录预检；本次不新增目录解析或创建行为。
