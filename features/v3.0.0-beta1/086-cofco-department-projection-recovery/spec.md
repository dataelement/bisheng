规格修订：R1，2026-11-16。状态：Discovery范围及规格R1已由用户于2026-11-16确认；Design R1已确认；进入实现与本地验证，部署验收另列。

## 1. 目标与范围

作为普通用户，希望组织同步的一次短暂失败不会使合法部门永久失去鉴权能力；作为运维，希望默认只读地知道哪些部门可修、哪些存在业务冲突，并对明确计划执行可续跑修复。

纳入：新同步/部门变更的缺陷修正、现有投影的有界自动恢复、按当前业务状态与当前生效模型手动对账、必要的IAM定点证明、失败留痕与状态收口。不新增表/列/索引/schema迁移，不新增用户授权规则或组织业务对象。

不纳入：自动改变组织树/生命周期/挂载、自动跨模型或Store修复、全Store覆盖、自动补偿逆转/整库还原、自动停服务、按名字猜映射或复活部门。人工确认的叶子重挂和源端已不存在的归档通过原业务Owner执行，既有资源Grant不扩大。

## 2. 验收标准

### 新写入与同步

- **AC-01** — WHEN 部门业务提交而权限投影失败后重试同一同步消息，THE SYSTEM SHALL 在时间戳短路前核对原绑定恢复义务，不因消息已处理而永久跳过权限修复；业务时间戳不倒退，消息幂等不变。
- **AC-02** — WHEN 合法父级变更或同步修正部门路径，THE SYSTEM SHALL 保持部门及其后代路径与真实parent链一致；事务失败不留下部分路径更新，既有挂载/租户边界保持。
- **AC-03** — IF 关系已写入但操作或部门状态未完成，THEN THE SYSTEM SHALL 核实后幂等收口，不重复增加版本、不盲写关系、不以普通CURRENT字段单独判断整个操作成功。

### 自动恢复

- **AC-04** — WHEN 自动恢复运行，THE SYSTEM SHALL 仅处理业务树合法、当前绑定/版本归属一致、当前授权环境与原操作一致且原目标仍符合当前事实的异常投影；不得以等待时间单独证明可接管。
- **AC-05** — WHEN 原绑定仍可安全恢复的处理中或失败操作被发现，THE SYSTEM SHALL 处理其完整应有关系和状态义务，包括成员及父子镜像，不因局部拓扑正确就解除门禁。
- **AC-06** — IF 父级失效、路径/挂载冲突、模型/Store变化、未知副作用或当前目标无法证明，THEN THE SYSTEM SHALL 保持失败关闭，输出准确阻塞原因及手动处理入口，不自动归档、重挂或复活。
- **AC-07** — WHEN 自动恢复首次部署及周期运行，THE SYSTEM SHALL 实际注册并触发恢复任务；按租户、有界分页/限速执行，避免跨进程重复接管；基础设施故障停止该轮，失败不得快速无限重试或让后续候选长期饥饿。
- **AC-08** — WHEN 自动恢复与正常变更、其他恢复进程或重投递重叠，THE SYSTEM SHALL 校验归属、绑定、版本和执行权；只允许有效操作收口，旧目标不得覆盖后续合法变更。

### 手动校对与修复

- **AC-09** — WHEN 未指定apply，THE SYSTEM SHALL 只读取并报告；按明确租户/部门范围动态发现异常，列出可修、依赖后可修、处理中、已完成、阻塞及失败，报告扫描完整度，不硬编码历史部门名单。
- **AC-10** — WHEN 手动生成计划，THE SYSTEM SHALL 以当前合法业务状态和当前已生效模型确定目标，不回放已失效的MOVE历史，不把旧pin不同作为永久阻塞，不自动发布模型或跨Store迁移。
- **AC-11** — WHEN 业务库不能证明候选的父级/路径或删除事实且已配置IAM，THE SYSTEM SHALL 只对该候选及必要父级定点查询，按source/external_id精确匹配；其他部门不全量问IAM，不按名称猜目标。
- **AC-12** — WHEN IAM证明合法叶子当前父级且本地目标有效，或精确证明本部门已不存在，THE SYSTEM SHALL 在手动计划列出重挂或归档的业务、关系及关联清理范围；无完整证明、非叶子、挂载/根或无法确定的关联只报告，不误删除仍在场的子部门。
- **AC-13** — WHEN 执行人工确认计划，THE SYSTEM SHALL 核实当前环境、影响范围、备份覆盖确认及相应写入静默要求，按依赖顺序执行；未知变化拒绝旧计划，不能扩大目标或覆盖未确认关联。
- **AC-14** — WHEN 进程中断、结果丢失或同计划重跑，THE SYSTEM SHALL 依据共享执行证据识别已完成/未完成，先验证再续跑；已完成项不重写、不增加版本，FGA已达目标的项只做剩余收口，失败保留门禁。
- **AC-15** — WHEN 明确停服修复且相关写入者均静默，THE SYSTEM SHALL 支持有界加速与轻量完成项复核；在线自动恢复保留低负载约束。提高速度不得省略未完成项的真实写前/写后验证或对不明写入结果的核查。

### 范围、安全和运维

- **AC-16** — WHILE 核查或恢复部门，THE SYSTEM SHALL 仅访问所选候选及必要依赖的关系，不遍历全FGA Store，不导出全租户成员或自动展开受祖先门禁影响的正常子树；分页、差异和事务都有上限。
- **AC-17** — WHEN 发现活跃操作、读取祖先及执行收口，THE SYSTEM SHALL 避免已复现的高成本查询形态和无关重复读取；保留跨状态累计上限、租户过滤、真实parent链及并发校验，输出阶段、当前部门、请求数和耗时，不承诺未经实测的完成时限。
- **AC-18** — WHEN 使用手动CLI，THE SYSTEM SHALL 直接使用同版服务配置和现有依赖；不以pyproject文件逐字一致作为额外门禁，不要求重复备份或虚构恢复演练证明。确认信息和备份引用保留审计，程序不声称验证备份可恢复。
- **AC-19** — WHILE 正常鉴权、恢复或失败，THE SYSTEM SHALL 保留原权限拒绝逻辑、租户隔离及资源授权边界；不删除用户，不自动迁人，不修改无关管理员/部门/资源Grant。
- **AC-20** — WHEN 汇报结果，THE SYSTEM SHALL 区分扫描完整、冻结范围修复完成、真实用户权限验收和未核查范围；提供执行、续跑、失败处理、证据保留及清理文档，清理源码不等于数据回滚。

- **AC-21** — WHEN 投影失败、对账不一致或请求因部门投影门禁拒绝，THE SYSTEM SHALL 输出稳定结构的告警日志，包含作用域、原因码、操作/恢复身份及有界差异摘要；不增加鉴权查询，不记录凭据或完整人员清单，区分处理中、失败与SQL提交读回后恢复成功。

## 3. 关键边界

- 默认自动恢复不跨模型、不从IAM推断新业务状态；这些情况由手动计划明确确认。
- 已物理删除且无可信删除证据的部门只报告，不从旧操作或备份重建。
- 历史旧包operation及审计不能被普通消费者误当已完成原请求；不兼容的恢复类型必须明确拒绝并引导专用入口。
- 数据库/FGA锁、网络响应不明、进程重启及双库差异属于必须覆盖的故障路径；本地模拟不等于生产证明。
