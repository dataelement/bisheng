# Feature: 助手节点与助手应用调用技能

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> 所有 How（执行器选型、middleware、存储路径、字段、API、前端组件）一律写在 [design.md](./design.md)。

**关联 PRD**: 无独立 PRD。需求来自项目交付，同时作为通用能力进入主线；本 spec 是需求口径的唯一来源。
**优先级**: P0
**所属版本**: v3.0.0（开发分支 `feat/SEC-3.0.0-1016`，择期合回 `feat/3.0.0`）
**依赖**: F035 技能库（任务模式技能的存储、启用开关与管理界面）；平台已有的代码执行器

> **范围边界**
> - **本次纳入**：
>   - workflow 助手节点可以配置并调用技能，包括带脚本、模板的完整技能。
>   - 独立助手应用可以配置并调用技能，能力与助手节点一致。
>   - 配置了技能的助手节点和助手应用获得会话级工作区，技能可以在其中读取文件、执行脚本、生成交付文件。
>   - 交付文件以文件卡片展示给用户，并通过助手节点的输出变量传给下游节点。
>   - 助手节点可以把上游的输入文件放进工作区，供技能处理原件。
> - **本次明确排除**：
>   - **工作台日常对话调用技能**：本期只覆盖 workflow 助手节点和助手应用，日常对话另起 feature。
>   - **ReAct 执行方式的模型调用技能**：只支持 function call 执行方式；改造 ReAct 分支的工作量和风险都超出本期。
>   - **新增 workflow「文件」类型变量**：交付文件通过文本变量（文件名加下载链接）传给下游，不改 workflow 变量体系。
>   - **助手应用会话上传文件**：助手应用会话目前没有上传入口，本期不新增，所以助手应用没有输入文件。
>   - **技能版本固定**：运行时始终使用技能的当前版本，不在发布时记录版本。
>   - **技能级授权**：技能可用范围仍只由管理员的启用开关决定，不新增按用户或按应用的授权。
>   - **技能「默认勾选」**：该标记只作用于任务模式的技能选择器，助手节点和助手应用的配置面板不预选任何技能。
>   - **AI 自动生成助手配置时推荐技能**：自动配置只处理提示词和工具，不选择技能。
>   - **技能库本身的变更**：不改技能的上传、编辑、启停和管理界面，也不新增停用、删除操作人的记录。技能只能由系统管理员和租户管理员管理，错误信息统称「管理员」即可定位处理人。
>   - **助手应用开放 API 返回交付文件**：该接口兼容 OpenAI 格式且没有会话，返回文件需要新增非标准字段和按调用身份归属文件的规则，超出本期范围；本期 API 只返回文字结果。
>   - **工作区容量上限**：工作区不设容量上限，也不计入租户存储配额，空间由会话删除时的清理回收（AC-23）。任务模式的工作区同样没有上限；如需设上限，应与任务模式一并处理，避免两套规则。
>   - **把交付文件交给外部系统**：下载需要登录并有权查看会话（AC-28），下游节点把链接发给外部系统时，外部系统无法下载；本期不提供免登录的分享链接。

## 0. 术语

| 术语 | 定义 |
|---|---|
| 技能 | 技能库中的一个技能包，由 SKILL.md 说明文件和可选的脚本、模板等文件组成。技能库按租户隔离，由管理员维护。 |
| 管理员 | 有权管理技能库的用户，即系统管理员和租户管理员。 |
| 已启用技能 | 管理员在技能库中设为启用状态的技能。 |
| 助手节点 | workflow 中的「助手」节点（Agent 节点）。 |
| 助手应用 | 平台中单独创建的助手（assistant）。 |
| 执行方式 | 模型配置里为助手推理模型设定的调用方式，取值为 function call 或 ReAct。 |
| 会话 | 用户与一个 workflow 或一个助手应用的一次对话，对应一个会话 ID。 |
| 工作区 | 系统为「一个会话中的一个助手节点或一个助手应用」分配的文件空间。技能文件、输入文件和交付文件都放在工作区中。 |
| 代码执行器 | 平台已配置的代码解释器，技能脚本在其中运行。 |
| 输入文件 | 用户在 workflow 中上传、并被助手节点选为工作区输入的文件。 |
| 本次运行 | 助手节点的一次执行，或助手应用的一轮回复。批量模式下每个批次各算一次运行。 |
| 输出区 | 工作区中专门存放交付结果的位置。系统引导模型把交付结果写到这里。 |
| 交付文件 | 本次运行结束时，输出区中本次运行新建、或内容被本次运行修改的文件。若输出区中没有这样的文件，则改取本次运行在工作区其它位置新建的文件。两种情况都不包括：技能文件、输入文件原件、模型标为临时的中间文件、系统自动转存的工具结果和历史对话。判定规则与任务模式一致。 |

## 1. 用户故事

**A. workflow 搭建者**
作为 **workflow 搭建者**，
我希望 **在助手节点里选择技能**，
以便 **流程中的一步可以按技能规范生成 Word、Excel、PPT 等文件，或者按技能要求加工用户上传的原件**。

**B. 助手应用创建者**
作为 **助手应用创建者**，
我希望 **为助手应用选择技能**，
以便 **助手在对话中按技能规范完成任务并交付文件**。

**C. 最终用户**
作为 **使用 workflow 或助手应用的用户**，
我希望 **在对话中直接下载生成的文件，并能在下一轮要求修改这份文件**，
以便 **不用离开对话就能拿到可用的交付物**。

**D. 管理员**
作为 **管理员**，
我希望 **在技能库里停用一个技能后，所有助手节点和助手应用立即不能再使用它**，
以便 **用同一个开关治理任务模式、助手节点和助手应用中的技能**。

**E. workflow 搭建者与助手应用创建者**
作为 **搭建者或创建者**，
我希望 **技能不可用导致运行失败时，错误信息直接写明是哪个技能、是被停用还是被删除**，
以便 **直接联系管理员处理，不用逐个排查**。

## 2. 验收标准

### 2.1 配置

- **AC-01** — WHERE 助手节点所选模型的执行方式为 function call, THE SYSTEM SHALL 在助手节点配置面板中提供技能多选，候选项为当前租户的全部已启用技能。
- **AC-02** — WHERE 助手应用所选模型的执行方式为 function call, THE SYSTEM SHALL 在助手应用配置页中提供技能多选，候选项与 AC-01 相同。
- **AC-03** — WHERE 所选模型的执行方式为 ReAct, THE SYSTEM SHALL 禁用技能多选，并提示「当前模型的执行方式不支持技能」。
- **AC-04** — THE SYSTEM SHALL 让助手节点配置面板可以从上游节点的文件变量中选择输入文件。
- **AC-05** — THE SYSTEM SHALL 在配置面板和配置页中不预选任何技能，与技能的「默认勾选」标记无关。

### 2.2 运行

- **AC-06** — WHEN 配置了技能的助手节点或助手应用开始运行, THE SYSTEM SHALL 只向模型提供所配置的技能，不提供租户技能库中的其它技能（所配置技能不可用时按 AC-12、AC-30 处理）。
- **AC-07** — WHEN 配置了技能的助手节点或助手应用开始运行, THE SYSTEM SHALL 让模型可以读取所配置技能的 SKILL.md 和技能包中的其它文件。
- **AC-08** — WHERE 平台已配置代码执行器, THE SYSTEM SHALL 在配置了技能时自动为助手节点或助手应用绑定代码执行器，代码执行器可以读写该工作区，搭建者不需要另外在工具列表中添加。
- **AC-09** — IF 平台未配置代码执行器, THEN THE SYSTEM SHALL 照常运行，技能按说明生成文字结果；同时在运行日志中标注「代码执行器未配置，技能脚本未执行」，并在本次回复处向用户展示一条提示，说明技能脚本未执行、结果可能不完整。
- **AC-10** — WHEN 配置了输入文件的助手节点开始运行, THE SYSTEM SHALL 把输入文件的原件放入工作区，供技能读取和修改。
- **AC-11** — THE SYSTEM SHALL 在运行时使用技能的当前版本；WHEN 管理员修改技能后再次运行, THE SYSTEM SHALL 使用修改后的内容，搭建者不需要重新发布。
- **AC-12** — IF 所配置的某个技能在运行时已被停用, THEN THE SYSTEM SHALL 终止该助手节点或该轮助手回复，并返回错误，错误信息为「<技能名称> 技能已被管理员停用」。
- **AC-30** — IF 所配置的某个技能在运行时已被删除, THEN THE SYSTEM SHALL 终止该助手节点或该轮助手回复，并返回错误，错误信息为「<技能名称> 技能已被管理员删除」。
- **AC-13** — IF 所配置的模型在配置技能之后被改为 ReAct 执行方式, THEN THE SYSTEM SHALL 在运行时终止并返回错误，错误信息写明「当前模型的执行方式不支持技能」。

### 2.3 交付文件

- **AC-14** — WHERE 助手节点勾选了「输出给用户」, WHEN 技能生成交付文件, THE SYSTEM SHALL 在节点回复后以文件卡片展示每个交付文件，用户可以下载。
- **AC-15** — WHEN 助手应用的技能生成交付文件, THE SYSTEM SHALL 在该轮回复后以文件卡片展示每个交付文件，用户可以下载。
- **AC-16** — THE SYSTEM SHALL 为配置了技能的助手节点提供一个输出变量，内容是本次运行全部交付文件的文件名和下载链接；未勾选「输出给用户」时该变量同样有值。下游节点可以引用该变量。
- **AC-17** — WHERE 助手节点使用批量模式, THE SYSTEM SHALL 让每个批次的交付文件只出现在该批次对应的输出中。
- **AC-18** — WHEN 用户在会话历史中重新查看带文件卡片的消息, THE SYSTEM SHALL 仍然可以下载对应的交付文件，只要该会话未被删除。
- **AC-19** — WHEN 技能运行结束但没有生成任何交付文件, THE SYSTEM SHALL 不展示文件卡片，第 AC-16 条的输出变量为空。
- **AC-31** — WHEN 同一会话的再次运行结束, THE SYSTEM SHALL 只把本次运行新建或修改的文件作为交付文件；上一次运行留在输出区、本次未改动的文件不再展示为文件卡片，也不写进 AC-16 的输出变量。
- **AC-32** — WHEN 技能在本次运行中修改了输入文件原件, THE SYSTEM SHALL 不把被修改的原件作为交付文件；只有写入输出区的结果文件才是交付文件。
- **AC-33** — IF 交付文件是 Office 文档、PDF 或常见图片格式，且文件内容与扩展名不符, THEN THE SYSTEM SHALL 照常展示其文件卡片，并在卡片上标注「文件内容与格式不符，可能无法打开」，同时在运行日志中记录。
- **AC-34** — WHEN 通过开放 API 调用 workflow、且助手节点本次运行产生交付文件, THE SYSTEM SHALL 在该助手节点的输出事件中，用已有的 `files` 字段返回每个交付文件的文件名和下载链接，格式与输出节点返回文件时一致；未产生交付文件时不返回该字段，已有字段不变。
- **AC-35** — WHEN 通过开放 API 调用配置了技能的助手应用, THE SYSTEM SHALL 在系统追加给模型的技能说明中不引导模型把结果写成文件，并告知模型本次调用只能以文字形式交付结果；创建者自己编写的提示词保持原样。
- **AC-28** — THE SYSTEM SHALL 只允许已登录、且有权查看该会话的用户下载交付文件；下载入口（文件卡片和 AC-16 输出变量中的链接）在会话存续期间一直有效。
- **AC-29** — IF 未登录用户或无权查看该会话的用户访问交付文件的下载链接, THEN THE SYSTEM SHALL 拒绝下载。

### 2.4 工作区

- **AC-20** — THE SYSTEM SHALL 为每个会话中的每个助手节点、每个助手应用会话分别分配工作区；不同会话、同一 workflow 中不同助手节点之间的工作区互不可见。
- **AC-21** — WHEN 同一会话中的同一助手节点或同一助手应用再次运行, THE SYSTEM SHALL 让技能可以读取并修改该工作区中之前生成的文件。
- **AC-22** — WHEN 同一会话的后续运行被调度到另一个服务节点, THE SYSTEM SHALL 仍然可以读取该工作区中之前生成的文件。
- **AC-23** — WHEN 会话被删除, THE SYSTEM SHALL 清理该会话的全部工作区和交付文件。
- **AC-24** — WHERE 运行来自应用评测或助手应用开放 API, THE SYSTEM SHALL 为该次运行使用一次性工作区，运行结束后不保留，也不展示交付文件。
- **AC-36** — WHEN 创建者或搭建者打开助手应用或 workflow 的调试窗口, THE SYSTEM SHALL 为该调试窗口分配临时会话：调试中生成的交付文件以文件卡片展示并可下载，同一调试窗口内可以多轮修改文件，行为与正式会话一致。
- **AC-37** — THE SYSTEM SHALL 只允许发起调试的用户下载临时会话中的交付文件；WHEN 调试窗口被关闭或刷新, THE SYSTEM SHALL 清理该临时会话的工作区和交付文件。

### 2.5 兼容与可观测

- **AC-25** — THE SYSTEM SHALL 让未配置技能的助手节点和助手应用（包括升级前保存的全部配置）与改动前行为一致：不加载技能、不绑定代码执行器、不分配工作区。
- **AC-26** — THE SYSTEM SHALL 在 workflow 运行日志和助手应用的工具调用记录中展示本次加载的技能名称，以及读取技能文件、执行代码的每一次工具调用。
- **AC-27** — THE SYSTEM SHALL 只从助手节点或助手应用所属租户的技能库中取技能。

## 3. 边界情况

- 搭建者既配置了技能，又在工具列表中手动添加了代码解释器时，系统只绑定一个代码执行器，模型看到的代码执行工具只有一个。
- 工作区中的技能文件对模型只读；模型修改技能文件不应改变技能库中的技能。
- 技能脚本执行失败时，失败信息作为工具调用结果返回给模型，节点不因单次脚本失败而终止；最终是否生成交付文件以工作区中的实际文件为准。
- 模型在回复中声称生成了某个文件、但工作区中没有该文件时，系统不为它补造文件卡片，也不把它写进 AC-16 的输出变量。
- 同一会话中两次运行生成同名文件时，后一次覆盖前一次；文件卡片展示的是该次运行结束时的文件。
- 调试窗口异常断开（如浏览器崩溃、网络中断）时没有关闭事件，临时会话也要被清理，不能永久残留；清理时机见 design.md。
- 通过开放 API 调用 workflow 时，API 调用方的身份就是会话当事人，可以用自己的凭据下载交付文件（AC-28、AC-34）。
- 通过开放 API 调用助手应用时，技能照常运行，响应只含文字结果，不含交付文件（见「本次明确排除」、AC-35）。
