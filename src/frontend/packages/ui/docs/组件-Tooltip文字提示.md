## 1. 什么时候用

文字提示（Tooltip）是悬停或键盘聚焦在一个控件上时，弹出的一句纯文字说明——告诉你「这个东西是干什么的」。它是锦上添花的辅助信息：有它更好懂，没有它任务照样能完成。

- **给没有文字的图标按钮配说明**。单 icon 按钮必须配 Tooltip，这条规则的家在按钮规范（[组件-Button按钮.md](组件-Button按钮.md) §4.2）。
- **补全被截断的文字**。表格单元格、侧栏标题因空间限制显示不全时，悬停给出完整内容。
- **解释禁用原因**。控件不可用时，说明满足什么条件才能用（如「勾选至少一项后可删除」）。
- **不放任务必需的信息**。说明、警告、报错一律不进 tooltip——悬停才出现的东西，用户可能永远看不到；触屏上它从不出现（见 §8）。

## 2. 是 Tooltip 还是 Popover

两个都是挨着触发元素弹出的小浮层，分不清就问两个问题：

1. **它怎么出现？** 悬停 / 聚焦就出现的，是 Tooltip；要点击才出现的，是 Popover。
2. **里面有没有能点的东西？** 内容里只要出现链接、按钮、输入框中的任何一个——**它一定不是 Tooltip**，用 Popover。

第二问是硬判据，依据是 WAI-ARIA 无障碍标准：Tooltip 不接收焦点，键盘用户永远进不去它的内容，里面的可点元素对他们等于不存在；可交互的浮层必须按可聚焦的卡片（Popover）来做。因此也**不做「带标题和按钮的加强版 tooltip」**——那就是 Popover，直接用 Popover。

一句话总结：**Tooltip 是一句话的说明书，Popover 是一块可以操作的小卡片。**

### 2.1 浮层家族速查

| 浮层 | 怎么出现 | 装什么 | 焦点去哪 | 典型场景 |
|---|---|---|---|---|
| **Tooltip 文字提示**（本文） | 悬停 / 聚焦 | 一句纯文本 | 留在触发元素上 | 图标按钮说明、截断补全 |
| **Popover 气泡卡片** | 悬停或点击 | 富内容，可含链接 / 按钮 / 轻表单 | 进入浮层 | 信息卡、轻量筛选、字段配置，见 [组件-Popover气泡卡片.md](组件-Popover气泡卡片.md) |
| **Dropdown 下拉菜单** | 点击 | 一组命令 | 方向键在菜单项间移动 | 「更多操作」菜单（规范待建，见总纲看板） |
| **二次确认** | 点击危险操作 | 确认文案 + 按钮 | 进入弹窗 | 一律用 useConfirm 居中弹窗（见 [组件-Modal弹窗.md](组件-Modal弹窗.md)），不做气泡式确认 |

新手引导的气泡（coach mark）是产品主动推送的一次性教学标注，既不是 Tooltip 也不是 Popover，需要时另行立项。

| ✅ 推荐 | ❌ 不推荐 | 原因 |
|---|---|---|
| 图标按钮悬停出「重命名」 | 悬停出一张带「查看详情」链接的卡片，却叫它 tooltip | 内容里有链接就该按 Popover 做：键盘焦点进不去 tooltip，链接等于不存在 |
| 危险操作点击后用 useConfirm 弹窗确认 | 悬停在删除按钮上就弹「确认删除？」的按钮 | 悬停是浏览动作不是决定动作，确认必须由点击发起 |
| 报错用表单内联提示或全局提示 | 报错原因只放在输入框的 tooltip 里 | 悬停才出现的信息用户可能永远看不到，触屏上更是从不出现 |

## 3. 长相与尺寸

深灰实色底 + 白字——与页面反差最大，一眼认出「这是提示，不是页面内容」。两种品牌主题（蓝 ⇄ 绿）下长相相同，不换肤；深色模式下仍是深底白字，只把底色换亮一档与页面拉开（见表）。

| 项 | 值 | 说明 |
|---|---|---|
| 底色 / 文字 | 浅色模式 `gray-10` 实色；深色模式**暗色灰阶第 2 档 `gray-2`**（`#2E2E30`）；文字两种模式都是纯白 | `gray-10` 即《色彩规范》灰阶最深档，见 [基础-色彩规范.mdx](基础-色彩规范.mdx)。**实色、不带透明度**——半透明会造成箭头叠加缝、文字反锯齿降级、对比度不可判定（决策依据见改动记录）。深色模式**不取翻转后的 `gray-10`**（灰阶暗色翻转后它会变浅，和白字冲突），tooltip 两种模式恒为深底白字；初值 `#373739` 已按暗色灰阶归档到最接近的 `gray-2`（ΔL\* 4.1，次近的 gray-3 为 7.5），组件与 token 均不再留暗色专用裸值。不随蓝 ⇄ 绿换肤 |
| 字号 / 行高 | 14 / 22（正文档） | 跟《字体规范》正文档，见 [基础-字体规范.mdx](基础-字体规范.mdx) |
| 内边距 | 上下 6px、左右 12px | 单行总高 34px，与 32px 控件近似同高，挨着控件出现不突兀 |
| 圆角 | 6px | 与同高度的控件档一致，见 [基础-圆角与阴影规范.mdx](基础-圆角与阴影规范.mdx) |
| 最大宽度 | 250px | 约一行 17 个汉字，超过自动换行 |
| 箭头 | **恒定带**，指向触发元素 | 一排图标挤在一起时，箭头说明提示属于谁；不设无箭头档——tooltip 只有一种长相，哪里都认得出；图表中跟随鼠标的数值浮层不属于本组件，归图表库自管 |
| 与触发元素间距 | 4px | 带箭头时以箭头尖计 |
| 投影 / 描边 | 浮层投影档；不描边 | 投影档见《圆角与阴影规范》；1px 描边是给白底浮层与页面拉开用的，深底自身反差已足够，免除 |

## 4. 内容怎么写

一句话说明用途，像给控件贴一张小标签。文案通则见 [基础-文案规范.md](基础-文案规范.md)，下面是 tooltip 自己的细则：

- **短**：一般不超过 20 个字、最多两行。要两行以上才说得清，说明该换 Popover，或界面本身要改。
- **按钮的提示用动词开头**，说清点了会发生什么：写「恢复默认设置」，不写「设置」。纯陈述（截断补全、数值全文）用原文即可。
- **不加句末标点**。一句话提示不加句号；确需两个短句时用中文逗号分隔。
- **不重复控件已有的文字**。带文字的按钮一般不需要 tooltip，「保存」按钮再配个「保存」提示是噪音。
- **随状态换文案**。收藏 ⇄ 取消收藏、展开 ⇄ 收起——提示跟着当前状态走，不写死一个。

| ✅ 推荐 | ❌ 不推荐 | 原因 |
|---|---|---|
| 「恢复默认设置」 | 「设置」 | 名词看不出点了会发生什么，动词短语才是说明书 |
| 已收藏状态下提示「取消收藏」 | 任何状态都提示「收藏」 | 提示与实际动作相反，用户点完才发现错了 |
| 「保存」按钮不配 tooltip | 「保存」按钮配「保存」tooltip | 重复信息是噪音，读屏软件还会念两遍 |

## 5. 位置

- 12 个方位（上 / 下 / 左 / 右 × 居中 / 首端 / 尾端对齐），**默认在触发元素上方居中**。
- 空间不够时自动翻到对面，任何情况下不许被视口裁掉。
- 同一排控件用同一个方位，提示位置跳来跳去会打断视线。

## 6. 触发与时序

- **悬停触发**：指针进入 100ms 后出现，响应近乎即时。同一组控件间快速移动时（间隔 300ms 内），下一个提示立即出现，不再各等一次。
- **聚焦触发**：键盘 Tab 聚焦立即出现，不延时——键盘导航本身就是逐个停留，没有「扫过」一说。
- **消失**：指针移出触发元素与浮层后消失；**指针可以移进浮层**（读长内容、复制文字），移入期间不消失。
- **ESC 立即关闭**，焦点留在原处。
- **不自动超时消失**：只要还悬停 / 聚焦着就一直显示。「显示几秒后自动消失」违反 WCAG 1.4.13（悬停内容必须保持可见），禁止。
- **一次只显示一个 tooltip**。

## 7. 挂在什么元素上

- **只挂在可交互（可聚焦）的元素上**：按钮、链接、输入框。挂在纯文本或普通容器上，键盘用户永远触发不了它。
- 纯文本旁要给解释，用一个「?」图标按钮承载 tooltip，或直接把解释写在界面上。
- **禁用控件也要能出提示**（说明禁用原因）。禁用元素不派发鼠标事件，实现上要包一层热区（见文末落地），业务页不用自己处理。
- **单 icon 按钮必须同时设无障碍标签**，tooltip 不能替代它——读屏用户不悬停。标签与提示文案同源，不写两份。

## 8. 移动端适配

通用原则见 [基础-多端适配原则.md](基础-多端适配原则.md)，tooltip 的态度只有一条：

**触屏上不显示 tooltip，也不做长按替代**。触屏没有悬停，长按又和选择文本、系统菜单等手势冲突。由此反推出桌面端也必须遵守的铁律——**tooltip 只装「没看到也不误事」的信息**：

- 图标按钮要么图形自明，要么在触屏场景配文字（如底部菜单带标签）。
- 截断文字在触屏上用「点击展开」或详情页兜底。
- 禁用原因在触屏上用界面文字、或点击后的全局提示说明。

## 落地（给实现窗口）

1. 基座用 Radix Tooltip 原语（client 依赖里已有 @radix-ui/react-tooltip，具体封装路径开工时核实）：`delayDuration=100`、`skipDelayDuration=300`、`disableHoverableContent` 保持 `false`（关掉即违反 WCAG 1.4.13 Hoverable）。ESC 关闭、focus 即时出现为 Radix 内置行为，核实即可。
2. 样式 token（2026-08-25 定稿，组件已于同日回改到位：`--tooltip-bg` 建在 `packages/ui/src/styles/tokens.css`，暗色档已归到 `gray-2`，气泡类名 `bg-tooltip text-white`）：底色**实色无 alpha**——建 `--tooltip-bg` 语义变量：浅色 = `rgb(var(--gray-10))`，`.dark` 下覆写为 `var(--arco-gray-2)`（= 暗色 `#2E2E30`，由初值 `#373739` 按 L\* 归到最近档，全链路无裸值）。**底色不要直接引用会翻转的 `--gray-10`**（暗色下变浅）；**文字写死白（`#fff`），不再取会翻转的 `rgb(var(--arco-gray-1))`**——深色模式定为恒深底后，翻转文字色会变成深字压深底。其余不变：无 backdrop-blur、圆角 6px、内边距 `6px 12px`、`text-sm`（14/22）、`max-w-[250px]`、浮层投影档（阴影规范落 token 后接线）、无边框。**箭头沿用 Radix 的 `Tooltip.Arrow`（SVG，11×6）**，贴在气泡外侧不与之重叠；`sideOffset` 记为 `4 + 箭头高`，让 4px 落在箭头尖而不是气泡边。组件内除 token 定义外不留裸 hex。
3. 触屏不显示：Radix Tooltip 原生不响应 touch，保持默认；**禁止业务页用 onTouchStart 自造长按提示**。
4. 禁用控件的提示：封装组件属性，内部对 disabled 触发元素包一层可聚焦热区（`span` + `tabIndex=0`）；禁止业务页各自手包。
5. 单 icon 按钮的 `aria-label` 与 tooltip 文案同源：IconButton 封装用同一个 `label` 属性同时喂给两者。
6. z-index 取 `1300`，即层级表的**最高浮层档**——tooltip 必须能出现在弹窗、抽屉、Popover 之上（弹窗里的图标钮也要有提示）。四档层级表见 [组件-Modal弹窗.md](组件-Modal弹窗.md) §5，本文不另立。
7. 动效暂定 150ms 淡入 / 100ms 淡出（无动效规范，先用此值，建档后归并）。
8. 现状扫描待做：口径 `src/frontend/client/src`，排除 `ui/` 与 `_gallery/`，盘现有 tooltip 实现（Radix 封装 / 原生 `title` 属性 / 自造 hover 层）与用量，作迁移排批参考。
