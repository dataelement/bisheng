# 工作台 TGZ 多选导入

## 范围与确认

用户确认：“好，那就直接支持多选吧。先不支持 zip”。这是工作台管理页面内的小功能：复用现有单包预览/导入接口、业务校验、租户鉴权与存储，不新增或改变其他模块依赖的接口合同。按 SDD Guide §1 Small feature 记录轻量验收清单、实现、E2E 回归与代码审查。此前 config 静态校验修复保留；alpha3 运行适配仍按原记录待目标环境，本次不扩大验收结论。

## 验收标准

- **AC-MULTI-01**：管理员一次可以选择多个 `.tgz`，也可继续只选一个。ZIP 明确不支持。单包最多 100 MiB；界面每次最多 50 包，无独立批次字节总量上限，超出数量时给出明确提示且不启动预览。单项格式/大小不合格时仅该项不可导入，不阻止同批其他合格项。
- **AC-MULTI-02**：选择后逐包串行调用现有预览接口，展示文件名、包名/身份、待导入版本及允许/拒绝原因。预览结束前不能提交；全部拒绝时不能提交。保留后端结构化校验原因，区分网络/超时与内容失败。
- **AC-MULTI-03**：用户补充确认“能通过的都导入，不能通过的告知用户”。已有工作台的有效升级包必须正常导入；按后续更新允许同版本不同内容覆盖，保留 SemVer 禁止降级、身份校验与相同内容安全重复规则，不在前端新增同身份整组拒绝。按选择顺序执行，正式导入时后端重新校验；同一批内较早导入或其他客户端改变版本后，后续包若不再满足规则，逐项显示实际失败原因并继续下一项。
- **AC-MULTI-04**：管理员明确确认后，只将预览通过项逐包串行导入；每个包独立显示排队/导入中/成功/失败及原因。一包失败不阻断其他通过项。完成后刷新工作台列表并保留多包结果；失败不显示为成功。原始 TGZ 内容不得改写。
- **AC-MULTI-05**：取消/关闭对话框、组件卸载或租户变化时，停止当前及后续请求；重新选择文件时清除旧状态。旧请求即使稍后返回也不能覆盖新批次结果或跨租户展示。取消不能承诺撤销服务端已完成的导入。
- **AC-MULTI-06**：保留单包显示名编辑与导入习惯；多包使用各自预览建议名称，避免将一个编辑值应用给所有包。重复点击提交不重复启动队列；已完成项不自动重导入。
- **AC-MULTI-07**：新提示同时提供中/英/日文，复用现有上传对话框组件及设计样式。测试覆盖旧单包、多包成功、部分失败、全失败、重选/关闭中止、新版本升级与实际导入冲突、ZIP/大小/数量拒绝，以及请求串行/重复提交保护。

## 实现决策

只在平台工作台管理端维护一组 File 与逐项状态，复用 wrapped request 中的 previewWorkbenchBundle/importWorkbenchBundle；不新增批次服务端对象、数据库表、ZIP 解析器或批量 HTTP 接口。每个请求沿用当前租户头和 AbortSignal。预览与导入均串行，避免同时上传大量包。批次不是跨包事务，后端在实际导入时重新校验版本并独立提交，其他客户端导致的预览后状态变化应显示该包实际失败原因。

批次编号/AbortController 隔离异步返回；禁止依赖 FileList 或对象引用作为持久身份。列表刷新不应重置正在显示的多包结果。为让组件仍可维护，可提取工作台导入对话框/队列 hook，不引入 UI/状态管理依赖。

### 页面手动验收清单（待真实服务环境）

- [ ] 以租户管理员打开工作台上传，文件选择器允许多选 TGZ，不接受 ZIP；选择单包时仍可编辑显示名。
- [ ] 选择新工作台、有效升级包、无效配置包，逐包预览结束后，仅有效项可导入，失败项显示文件名和原因。
- [ ] 确认导入通过项，观察逐个进度与最终成功/失败统计；期间某包失败不阻断下一项，多包结果保留。
- [ ] 同一批中两个同工作台升级包按选择顺序处理，后端实际版本冲突显示在对应行，不伪装成功。
- [ ] 导入中关闭对话框，已成功包保留并刷新列表，未启动文件停止；换租户或卸载后旧结果不能显示到新租户。
- [ ] 重新选择文件清除旧诊断；全部无效或超数量时不能提交；连续点击不重复启动导入。

组件与请求适配测试不能替代真实登录、数据库/MinIO 部署或 alpha3 安装运行验收；本次不启动替代服务，也不宣称已部署。
