## 0. 范围界定

### IN

- 以 `knowledge_space_scope.level='public'` 空间的当前成功文件为公共见证。
- 对 `level='department'` 空间的当前成功文件执行非空 MD5 精确去重。
- 删除命中的部门逻辑文档及全部历史物理版本。
- 清理部门目标拥有的 MySQL、Milvus、Elasticsearch、MinIO 和 OpenFGA 数据。
- 默认 dry-run、JSON 报告、apply 前重校验、失败停止、幂等重试和受限的提交后恢复。

### OUT

- 不删除或修改公共数据。
- 不清理空文件夹。
- 不使用文件名、SimHash 或模糊相似度判重。
- 不让公共/部门历史版本独立参与匹配。
- 不新增 API、页面、定时任务、数据库迁移或依赖。
- 不删除收藏引用、审批或审计历史。
- 不在本功能开发过程中执行真实环境 `--apply`。

## 1. 用户故事

作为平台运维人员，我希望先预览公共空间与部门空间的重复文档及完整影响范围，再通过显式参数安全删除部门侧重复文档，以减少重复存储和索引，同时保证公共文档、历史审计和未命中数据不受影响。

## 2. 验收标准

| ID | 角色 | 操作 | 预期结果 |
|----|------|------|----------|
| AC-01 | 运维人员 | 不带 `--apply` 运行 | 生成报告且所有系统零写入 |

| AC-03 | 系统 | 比较当前成功文件 | 仅非空 MD5 保存值完全相等时判重 |
| AC-04 | 系统 | 检查版本 | 只使用关系一致的主版本；无版本旧文件兼容；脏版本图安全跳过 |

| AC-06 | 运维人员 | 使用范围参数 | 只收窄部门目标，不缩减公共见证，也不能选中公共文件 |
| AC-07 | 系统 | apply 前发现状态、MD5、scope 或版本图变化 | 跳过过期单元，不沿用旧计划删除 |
| AC-08 | 运维人员 | 显式执行有效目标 | 部门完整版本链及其规定的跨存储资源被清理 |
| AC-09 | 系统 | 删除活动关系 | 标签、审核标签、分享链接、相似度候选和推荐投影被删除 |
| AC-10 | 系统 | 发现收藏引用和审计历史 | 保留记录并报告收藏影响数量 |
| AC-11 | 系统 | 任一步删除失败 | 停止后续单元，保存 completed/failed/pending，返回非零状态 |
| AC-12 | 运维人员 | 对部分失败结果重跑或恢复原 apply 报告 | 已不存在资源幂等处理；主记录已删除时只重试提交后步骤，报告不能授权新删除 |
| AC-13 | 系统 | apply 后验证 | 目标无规定残留且公共见证仍完整，否则返回失败 |
| AC-14 | 系统 | 检测到多租户启用 | 拒绝扫描和删除，以安全前置错误退出 |

## 3. 核心架构决策

| ID | 决策 | 结论 | 理由 |
|----|------|------|------|
| AD-01 | 空间分类 | 只使用 `knowledge_space_scope.level` | 对齐业务定义，不混入发布状态 |
| AD-02 | 重复判据 | 非空 MD5 原值精确相等 | 对齐已确认口径，行为确定且可审计 |
| AD-03 | 当前版本 | 关系一致的唯一主版本；无版本记录按旧文件兼容 | 避免历史版本误判，并兼容存量数据 |
| AD-04 | 删除粒度 | 部门完整逻辑文档或单个兼容旧文件 | 防止只删当前版本后历史版本继续占用资源 |
| AD-05 | 执行入口 | 默认 dry-run，显式 `--apply` | 删除不可逆，安全预览优先 |
| AD-06 | 删除编排 | 脚本同步编排，不仅依赖异步 Celery | 提供逐资源结果、退出码和可重试报告 |
| AD-07 | 失败策略 | 单元串行、失败停止、幂等重跑 | 缩小部分失败范围并保留可恢复证据 |
| AD-08 | 收藏与历史 | 保留非目标所有记录 | 避免越权删除用户数据和不可变历史 |
| AD-09 | 多租户 | 仅支持多租户关闭的当前部署 | 对齐本次系统边界，防止跨租户误扫 |

## 4. 数据与接口

- 不新增或修改数据库模型。
- 不新增 HTTP API、错误码或前端界面。
- 使用现有 Knowledge、KnowledgeFile、KnowledgeSpaceScope、KnowledgeDocument 和 KnowledgeDocumentVersion 模型。
- 跨存储删除使用现有 Milvus、Elasticsearch、MinIO 和 OpenFGA 接入能力。

## 6. 非功能要求

- **安全**：公共数据不可进入删除集合；dry-run 零写入；apply 前重校验。
- **可恢复**：跨存储单元串行、失败停止、报告先落盘、幂等重跑。
- **兼容性**：MySQL 与 DM8；无数据库迁移；兼容未进入版本模型的旧文件。
- **确定性**：稳定排序、精确 ID 删除、同快照同参数得到同顺序计划。
- **可观测性**：运行 ID、分步状态、退出码和无敏感信息 JSON 报告。

## 7. 风险

- `--apply` 是不可逆删除，必须由运维人员另行批准并在维护窗口执行。
- 多存储系统没有全局事务，可能出现部分资源已删除；通过数据库元数据后删、失败停止和幂等重跑收敛。
- MD5 存在理论碰撞，本功能按已确认业务判据执行，不额外读取正文比对。
- 收藏引用会按现有行为变为失效引用，但不会被脚本越权删除。
