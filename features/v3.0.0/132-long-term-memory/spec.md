# Feature: 长期记忆

**关联 PRD**: [长期记忆 PRD v0.3](<../../../docs/PRD/memory 长期记忆/长期记忆 PRD.md>)（§4 需求、§5 验收、§7 决策）；需求发现见 [discovery.md](./discovery.md)
**优先级**: P0（标注 P1 的验收标准排在 P0 之后实现，同一个版本交付）
**所属版本**: v3.0.0（开发基线；目标版本号待定，见 discovery.md）
**依赖**: v3.0.0-beta1 F048（权限与租户隔离）、v3.0.0-beta1 F053（开放 API 鉴权与身份）、v3.0.0-beta1 F075（日常模式引用角标，归因的呈现沿用它）。无阻塞性前置 Feature
**状态**: 第 2 稿已于 2026-11-13 由用户确认；同日在设计阶段经用户确认修订 AC-87、移出 AC-100

> **范围边界**
> - **本次纳入**：
>   - 日常模式、深度研究、助手、工作流四类场景的跨会话长期记忆
>   - 两条写入途径：模型调用的记忆写入能力、会话安静后的自动整理
>   - 两条读取途径：常驻记忆每轮带入、按需检索（模型检索能力与工作流记忆检索节点）
>   - 租户级、用户级、助手级、工作流级四处开关
>   - 操作提示、回答归因、记忆管理页
>   - 效果指标与评测集
> - **本次明确排除**：
>   - 按应用隔离的记忆：一个用户只有一份记忆，不存在只属于某个应用的记忆
>   - 托管应用（应用工场发布的应用）读写记忆：本文的"应用"只指助手与工作流
>   - 组织级、多人共享的记忆
>   - 回查对话原文：它是另一个能力，不属于长期记忆
>   - 系统自己推断的、带置信度的信念
>   - 自动遗忘：系统不因时间久或很久没用到而删除记忆
>   - 实体关系抽取
>   - "上个月系统以为的情况是什么"这类时间回溯查询
>   - 工作流的记忆写入节点：工作流的记忆只来自自动整理
>   - 外部用户标识下的记忆、免登录访问下的记忆、服务账号以自身身份调用时的记忆
>   - 专门供管理员或应用作者查看、修改、清除、统计他人记忆的入口
>   - 升级前或开关开启前的历史对话的整理
>   - 记忆生效时对用户的一次性告知
>   - 记忆随知识库权限回收而自动失效（见 §3）
>   - 账号被删除时清除记忆：平台目前没有删除账号的功能，等它出现时再做
>   - 记忆管理页的搜索与筛选、记忆的导入导出

## 0. 术语与验证方式

**术语。** 按 PRD §2：记忆条目、详情、记忆空间、来源标记、常驻记忆、显式写入、自动整理、归因。本文另外固定下列用词。

| 用词 | 含义 |
|---|---|
| 用户 | 一个确定的平台用户（自然人账号）。以个人访问令牌调用时指令牌持有人；开放 API 代表某个平台用户调用时指被代表的人 |
| 应用 | 助手与工作流。不含托管应用 |
| 记忆已启用 | AC-66 的启用条件对当前用户、当前场景成立 |
| 有效条目 | 状态为有效的记忆条目，即未被取代、未被删除 |
| 删除 | 使一条记忆及其详情对任何读取途径都不可读。除 AC-22 的撤销外不可恢复 |
| 部署配置 | 由部署方在系统配置中设定、对全部租户生效的参数 |

**验证方式。** 每条验收标准末尾标注验证方式。

| 标注 | 含义 | 能否作为自动化开发的完成条件 |
|---|---|---|
| 〔测〕 | 由确定性的自动化测试验证，不依赖模型的自由发挥 | 能 |
| 〔评〕 | 结果取决于模型行为，由 AC-104 的评测集验证 | 不能。通过线在评测集定稿时与用户确认，定稿前不得宣称这些条目通过 |

## 1. 用户故事

**A. 日常模式的用户**
作为 **日常模式的用户**，
我希望 **系统记住我说过的身份、偏好和安排，并在我明确要求时当场记下**，
以便 **新开会话时不必把同样的话再说一遍**。

**B. 深度研究的用户**
作为 **深度研究的用户**，
我希望 **我对产出的固定要求和已验证的做法在后续任务里自动生效**，
以便 **不必在每个任务里重复同一批要求**。

**C. 助手的使用者**
作为 **某个助手的使用者**，
我希望 **这个助手用得上我在别处说过的情况，并且别的使用者看不到我的记忆**，
以便 **多人共用同一个助手时，它对每个人都是连贯的**。

**D. 工作流的作者**
作为 **工作流的作者**，
我希望 **在流程里用一个节点取回当前使用者的相关记忆**，
以便 **把记忆当作一个可编排的输入交给后续节点**。

**E. 助手与工作流的作者**
作为 **助手或工作流的作者**，
我希望 **由我决定这个应用是否使用记忆，默认不使用**，
以便 **应用的行为不会在我不知情时改变**。

**F. 任何有记忆的用户**
作为 **用户**，
我希望 **看得到系统记了什么、每次回答依据了哪些记忆，并且能改、能删、能关掉**，
以便 **记错的内容可以改正，不想被记住时可以停止**。

**G. 租户管理员**
作为 **租户管理员**，
我希望 **能在租户范围内关闭记忆功能**，
以便 **组织不需要这项能力时可以整体停用**。

## 2. 验收标准

### 2.1 记忆空间与隔离

- **AC-01** — THE SYSTEM SHALL 让每个用户在一个租户内只有一个记忆空间，任何场景下读写的都只是当前用户本人在当前租户的记忆空间。〔测〕
- **AC-02** — WHEN 两个用户使用同一个记忆已启用的助手或工作流, THE SYSTEM SHALL 使一方产生的记忆对另一方不可读、不可检索。〔测〕
- **AC-03** — WHEN 用户在任一记忆已启用的场景或应用里产生一条记忆, THE SYSTEM SHALL 使该记忆在该用户其余记忆已启用的场景和应用里可读。〔测〕
- **AC-04** — THE SYSTEM SHALL 为每条记忆保留来源标记，标明它产生于哪个场景、哪个应用、哪个会话，以及它是显式写入、自动整理还是用户手动新增。〔测〕
- **AC-05** — THE SYSTEM SHALL 使一个租户内的记忆对其他租户不可读。〔测〕
- **AC-06** — WHEN 用户的租户归属发生变化, THE SYSTEM SHALL 保留其在原租户内的记忆、不迁移到新租户，并使其在归属不属于原租户期间读不到这些记忆。〔测〕
- **AC-07** — WHEN 用户的租户归属回到原租户, THE SYSTEM SHALL 使其原有记忆继续可读。〔测〕
- **AC-08** — THE SYSTEM SHALL 不提供专门用于查看、修改、清除或统计他人记忆的入口，对租户管理员和应用作者同样如此。〔测〕
- **AC-09** — WHEN 非本人在管理端查看一个会话, THE SYSTEM SHALL 只呈现回答正文，不呈现操作提示中的条目原文和归因列表。〔测〕
- **AC-10** — IF 当前调用识别不出一个确定的用户（免登录链接访问、开放 API 调用只带外部用户标识、服务账号以自身身份调用）, THEN THE SYSTEM SHALL 不读取也不写入任何记忆，并使该应用照常运行、不返回与记忆有关的错误。〔测〕
- **AC-11** — WHEN 开放 API 以代表某个平台用户的方式调用，或以个人访问令牌调用, THE SYSTEM SHALL 读写被代表的用户或令牌持有人的记忆空间。〔测〕

### 2.2 记忆条目

- **AC-12** — THE SYSTEM SHALL 把每条记忆条目的内容限制在 200 字以内，并归为事实、偏好、经验三种类型之一。〔测〕
- **AC-13** — THE SYSTEM SHALL 使每条记忆条目只表达一个结论，并且脱离原对话也能读懂，不含"他""那个项目"这类离开原对话就无法确定所指的指代。〔评〕
- **AC-14** — WHEN 待写入的内容含有相对时间表述（如"明天""下周二"）, THE SYSTEM SHALL 按该用户的时区换算成具体日期后再写入；取不到用户时区时按部署配置的默认时区。〔测〕
- **AC-15** — WHEN 一条记忆描述一件有具体时间的事, THE SYSTEM SHALL 为该条目记录事件时间。〔评〕
- **AC-16** — IF 待写入的内容含有密码、密钥、令牌、证件号或银行卡号, THEN THE SYSTEM SHALL 拒绝写入，对显式写入、自动整理和手动新增同样如此。〔测〕
- **AC-17** — THE SYSTEM SHALL 不把一次性的任务内容、当前对话里随时可见且很快变化的状态记为记忆。〔评〕
- **AC-18** — THE SYSTEM SHALL 只把用户本人说的话、以及用户在对话里明确表示认可的结论作为记忆的来源；文档、网页、知识库、工具返回里的内容本身不得成为记忆。〔评〕
- **AC-19** — THE SYSTEM SHALL 不把要求系统今后执行某种动作的指令性内容记为记忆，除非它是用户本人表达的偏好。〔评〕
- **AC-20** — WHEN 一段结论需要连贯说明、无法在一条条目的长度内表达, THE SYSTEM SHALL 把完整正文保存为该条目的详情，并使条目内容为详情的一句概括。〔评〕

### 2.3 显式写入

- **AC-21** — WHEN 一次显式写入成功, THE SYSTEM SHALL 在该回答旁显示操作提示，提示可展开看到本次操作涉及的条目原文，并提供撤销；记下、更正、忘掉三种操作都适用。〔测〕
- **AC-22** — WHEN 用户撤销一次"记下", THE SYSTEM SHALL 删除该条目；WHEN 撤销一次"更正", THE SYSTEM SHALL 删除新条目并使被取代的条目恢复为有效；WHEN 撤销一次"忘掉", THE SYSTEM SHALL 使该条目恢复为有效。〔测〕
- **AC-23** — THE SYSTEM SHALL 只在一次写入真实成功后显示操作提示；回答声称已记下而没有成功写入时，系统不代为补写。〔测〕
- **AC-24** — WHEN 一次"记下"成功, THE SYSTEM SHALL 使新条目在同一会话的后续轮次和该用户的任何新会话里可读。〔测〕
- **AC-25** — WHEN 一次"更正"成功, THE SYSTEM SHALL 新增一条有效条目，并把被更正的条目标为已被取代、记录取代它的是哪一条。〔测〕
- **AC-26** — WHEN 一次"忘掉"成功, THE SYSTEM SHALL 删除对应条目。〔测〕
- **AC-27** — WHILE 记忆未启用, THE SYSTEM SHALL 不向模型提供记忆的写入与检索能力。〔测〕
- **AC-28** — THE SYSTEM SHALL 在日常模式、深度研究、助手三类场景向模型提供显式写入能力；工作流不提供。〔测〕
- **AC-29** — WHEN 用户在当前这句话里明确要求记下、更正或忘掉某件事, THE SYSTEM SHALL 执行对应的写入操作。〔评〕
- **AC-30** — WHEN 用户在当前这句话里没有提出记下、更正或忘掉, THE SYSTEM SHALL 不执行显式写入。〔评〕
- **AC-31** — WHEN 显式写入成功, THE SYSTEM SHALL 在回答中说明记下了什么；时间被换算成具体日期的，回答中给出换算后的日期。〔评〕
- **AC-32** — IF 显式写入失败或被 AC-16 拒绝, THEN THE SYSTEM SHALL 在回答中说明没有记下及原因。〔评〕
- **AC-33** — IF 更正或忘掉时找不到对应的条目, THEN THE SYSTEM SHALL 在回答中说明没有找到，不新建条目。〔评〕
- **AC-34** — IF 更正或忘掉时有多条条目都可能是对象, THEN THE SYSTEM SHALL 先向用户确认是哪一条。〔评〕
- **AC-35** — WHEN 记忆未启用而用户要求记下某件事, THE SYSTEM SHALL 在回答中说明记忆功能未开启。〔评〕
- **AC-36** — IF 用户明确要求记下的内容属于 AC-17 或 AC-19 所述的类别, THEN THE SYSTEM SHALL 不写入并说明原因。〔评〕

### 2.4 自动整理

- **AC-37** — WHEN 一个记忆已启用的会话自最后一次交互起经过了安静期, THE SYSTEM SHALL 对该会话启动一次自动整理。〔测〕
- **AC-38** — WHILE 会话仍在安静期内且用户继续对话, THE SYSTEM SHALL 不启动对该会话的整理，并重新计算安静期。〔测〕
- **AC-39** — THE SYSTEM SHALL 每次只整理上次整理之后新增的对话，同一段对话不被整理两次。〔测〕
- **AC-40** — THE SYSTEM SHALL 只整理记忆对该用户、该场景启用之后产生的对话；升级前的历史对话、开关开启之前的对话不被整理。〔测〕
- **AC-41** — IF 一段对话在被整理之前，其所在会话被删除，或对应的记忆开关被关闭, THEN THE SYSTEM SHALL 不再整理这段对话。〔测〕
- **AC-42** — THE SYSTEM SHALL 对四类场景中记忆已启用的会话执行自动整理。〔测〕
- **AC-43** — THE SYSTEM SHALL 允许通过部署配置调整安静期与整理频率，并允许整体关闭自动整理。〔测〕
- **AC-44** — WHEN 同一个用户同时在两个服务节点上进行两个会话, THE SYSTEM SHALL 保留两边写下的全部条目与详情，任何一方的写入都不被另一方覆盖。〔测〕
- **AC-45** — IF 一次自动整理失败, THEN THE SYSTEM SHALL 记录失败事件，并在之后重新整理同一段对话，不丢弃它。〔测〕
- **AC-46** — WHEN 自动整理一段对话, THE SYSTEM SHALL 整理出符合 §2.2 的条目，覆盖用户陈述的身份与工作情况、称呼、表达与格式偏好、用户认可的结论。〔评〕
- **AC-47** — WHEN 整理出的结论与一条有效条目表达同一件事, THE SYSTEM SHALL 不新增重复条目。〔评〕
- **AC-48** — WHEN 整理出的结论与一条有效条目矛盾, THE SYSTEM SHALL 新增条目并把旧条目标为已被取代。〔评〕
- **AC-49** — WHEN 自动整理一个工作流的会话, THE SYSTEM SHALL 只以使用者的输入和使用者明确认可的工作流输出为来源。〔评〕
- **AC-50**（P1）— WHEN 自动整理一个深度研究任务, THE SYSTEM SHALL 把用户对产出的固定要求、以及任务中已验证有效或无效的做法整理为经验类条目。〔评〕

### 2.5 读取

- **AC-51** — WHILE 记忆已启用, THE SYSTEM SHALL 在日常模式和助手的每轮对话开始时、在深度研究的任务开始时，把当前用户的常驻记忆整份带入。〔测〕
- **AC-52** — THE SYSTEM SHALL 使带入的常驻记忆不超过条数上限和总字数上限中先到达的一个，两个上限可通过部署配置调整。〔测〕
- **AC-53** — WHEN 常驻记忆到达上限, THE SYSTEM SHALL 不截断任何条目的内容，并使未被带入的条目保持有效、可被检索到。〔测〕
- **AC-54** — THE SYSTEM SHALL 不把经验类条目放入日常模式和助手的常驻记忆。〔测〕
- **AC-55** — WHEN 深度研究任务开始, THE SYSTEM SHALL 在常驻记忆之外带入经验类条目，带入量受独立的上限约束。〔测〕
- **AC-56** — WHEN 一条带详情的条目属于常驻记忆, THE SYSTEM SHALL 只带入条目内容，不带入详情全文。〔测〕
- **AC-57** — THE SYSTEM SHALL 把带入模型的记忆（常驻带入、检索返回、检索节点输出被大模型节点引用时）标注为背景信息并注明记录时间。〔测〕
- **AC-58** — WHILE 记忆已启用, THE SYSTEM SHALL 在日常模式、深度研究、助手三类场景向模型提供记忆检索能力，检索范围是当前用户的记忆空间，只返回有效条目。〔测〕
- **AC-59** — THE SYSTEM SHALL 使记忆检索返回每条的内容、类型、记录时间、事件时间，并可取回条目的详情全文。〔测〕
- **AC-60** — THE SYSTEM SHALL 不在工作流中自动带入常驻记忆；工作流只通过记忆检索节点读取记忆。〔测〕
- **AC-61** — IF 常驻记忆带入失败或记忆检索失败, THEN THE SYSTEM SHALL 继续完成本轮回答，记录失败事件并计入指标，不得不留记录地继续。〔测〕
- **AC-62** — IF 条目的详情读取失败, THEN THE SYSTEM SHALL 以条目自身的内容继续，记录失败事件并计入指标。〔测〕
- **AC-63** — THE SYSTEM SHALL 由自动整理决定哪些有效条目属于常驻记忆：经常被读到的提为常驻，到达上限时合并相近条目或移出较少被读到的条目。〔评〕
- **AC-64** — IF 记忆中没有与问题相关的内容, THEN THE SYSTEM SHALL 据实回答，不编造记忆。〔评〕
- **AC-65** — WHEN 用户当前这句话或当前会话的上文与长期记忆矛盾, THE SYSTEM SHALL 以前者为准；记忆与用户意图的关系不明确、而按记忆行事会明显影响结果时，先向用户确认。〔评〕

### 2.6 开关

- **AC-66** — THE SYSTEM SHALL 按以下条件判定记忆已启用：日常模式与深度研究要求租户记忆开且该用户的"我的记忆"开；助手另要求该助手的记忆开关开；工作流另要求该工作流的记忆开关开。〔测〕
- **AC-67** — THE SYSTEM SHALL 在管理端的工作台配置中提供租户记忆开关，默认开，只有租户管理员可改；未开启多租户的部署中由系统管理员改。〔测〕
- **AC-68** — WHILE 租户记忆为开, THE SYSTEM SHALL 在用户个人设置中提供"我的记忆"开关，默认开，只有用户本人可改。〔测〕
- **AC-69** — THE SYSTEM SHALL 在助手的设置页提供助手记忆开关，默认关，只有对该助手有编辑权限的用户可改。〔测〕
- **AC-70** — THE SYSTEM SHALL 在工作流的开始节点提供工作流记忆开关，默认关，只有对该工作流有编辑权限的用户可改。〔测〕
- **AC-71** — THE SYSTEM SHALL 使工作流记忆开关随工作流版本保存和发布，不含该开关的历史版本按关闭处理；助手没有版本，助手记忆开关保存后即生效。〔测〕
- **AC-72** — WHEN 任一开关被关闭, THE SYSTEM SHALL 保留已有记忆，并使对应范围内不再带入、检索、显式写入和自动整理。〔测〕
- **AC-73** — WHEN 一个被关闭的开关重新开启, THE SYSTEM SHALL 使关闭之前的记忆继续可读。〔测〕
- **AC-74** — WHEN 开关在一次回答的生成过程中被改变, THE SYSTEM SHALL 对该轮按开始时的状态处理，下一轮起按新状态。〔测〕
- **AC-75** — THE SYSTEM SHALL 在助手记忆与工作流记忆的开关旁说明：本应用会读取并写入每个使用者自己的记忆；使用者的记忆可能出现在本应用的回答与输出里；不同使用者之间互不可见。〔测〕
- **AC-76** — WHEN 部署升级到带有本功能的版本, THE SYSTEM SHALL 使租户记忆为开，并使所有已有的助手和工作流的记忆开关为关。〔测〕
- **AC-77** — WHEN 助手记忆开启, THE SYSTEM SHALL 使该助手具备常驻记忆带入、记忆检索、显式写入和自动整理，作者无须另行配置工具。〔测〕

### 2.7 工作流记忆检索节点

- **AC-78** — THE SYSTEM SHALL 在工作流的节点面板中提供"记忆检索"节点，同一个工作流中可放置多个。〔测〕
- **AC-79** — THE SYSTEM SHALL 使该节点的"检索内容"参数为必填，可以直接输入文字、引用其他节点的变量，或两者混写；引用的变量取值不是文字时转成文字后使用。〔测〕
- **AC-80** — THE SYSTEM SHALL 使该节点的"最大检索数量"参数默认为 20，只接受 1 到 100 的整数，其余取值在保存时被拒绝并提示合法范围。〔测〕
- **AC-81** — WHEN 该节点执行, THE SYSTEM SHALL 在当前使用者本人的记忆空间内检索有效条目，不限于在本工作流里产生的记忆，按与检索内容的相关程度从高到低输出不超过最大检索数量的列表。〔测〕
- **AC-82** — THE SYSTEM SHALL 使输出列表可被后续节点作为变量引用，每一项包含记忆内容、类型、记录时间、来源标记，有事件时间的带事件时间；条目带详情时内容为详情全文。〔测〕
- **AC-83** — IF 检索没有命中、运行时检索内容为空，或记忆对当前使用者未启用（含识别不出确定的用户、租户记忆为关、"我的记忆"为关）, THEN THE SYSTEM SHALL 输出空列表并使节点正常结束。〔测〕
- **AC-84** — IF 记忆检索因故障无法完成, THEN THE SYSTEM SHALL 使该节点以失败结束并给出原因，不得以空列表冒充检索成功。〔测〕
- **AC-85** — IF 工作流含有记忆检索节点而工作流记忆开关为关, THEN THE SYSTEM SHALL 在上线校验时拒绝，并提示作者先开启工作流记忆。〔测〕
- **AC-86** — THE SYSTEM SHALL 在该节点的运行日志中记录本次检索内容和返回条数。〔测〕

### 2.8 用户可见与可控

- **AC-87** — WHEN 一次回答依据了记忆, THE SYSTEM SHALL 在日常模式、深度研究和助手的该回答旁向本人显示所依据的条目，并允许就地删除其中任意一条。显示分两部分：本轮检索取回的条目逐条列出；本轮带入的常驻记忆通过一个入口整份查看，不区分其中哪条被用到。〔测〕
- **AC-88** — WHILE 租户记忆为开, THE SYSTEM SHALL 在用户个人设置中提供记忆管理页，列出本人在当前租户的全部有效条目，每条显示内容、类型、记录时间、事件时间、来源标记和是否常驻；手动新增的条目来源显示为手动添加。〔测〕
- **AC-89** — THE SYSTEM SHALL 在记忆管理页支持：编辑一条（原条目标为已被取代，新内容成为有效条目）、手动新增一条、删除单条、清空全部（需二次确认）；新增与编辑的内容超过 200 字或被 AC-16 拒绝时不保存并提示原因。〔测〕
- **AC-90** — THE SYSTEM SHALL 使记忆管理页的查看、编辑、新增、删除、清空不受"我的记忆"开关影响；WHILE 租户记忆为关, THE SYSTEM SHALL 仍让用户查看、删除和清空本人已有的记忆，但不提供新增与编辑，也不显示"我的记忆"开关。〔测〕

### 2.9 保持正确与数据生命周期

- **AC-91** — THE SYSTEM SHALL 使已被取代和已删除的条目不出现在常驻记忆、检索结果、记忆检索节点的输出和记忆管理页中。〔测〕
- **AC-92** — WHEN 一条记忆被取代, THE SYSTEM SHALL 保留旧条目并记录取代关系，直到用户清空记忆。〔测〕
- **AC-93** — WHEN 用户清空全部记忆, THE SYSTEM SHALL 删除其在当前租户的全部条目及详情，包括已被取代的条目。〔测〕
- **AC-94** — WHEN 一条带事件时间的条目的事件时间已过（按 AC-14 的时区判定）, THE SYSTEM SHALL 不再把它放入常驻记忆，并保持它可被检索到。〔测〕
- **AC-95**（P1）— WHEN 一条条目的事件时间已过, THE SYSTEM SHALL 在之后的自动整理中把其表述改写为过去时并保留日期。〔评〕
- **AC-96** — THE SYSTEM SHALL 不因一条记忆存在时间长或长期未被读取而自动删除它。〔测〕
- **AC-97** — WHEN 用户删除一个会话, THE SYSTEM SHALL 保留由该会话已经产生的记忆。〔测〕
- **AC-98** — WHEN 一个应用被删除, THE SYSTEM SHALL 保留用户在该应用里产生的记忆，其来源标记仍显示原应用的名称。〔测〕
- **AC-99** — WHILE 一个用户处于停用状态, THE SYSTEM SHALL 保留其记忆且不读不写；WHEN 该用户被重新启用, THE SYSTEM SHALL 使其记忆继续可读。〔测〕
- **AC-100** — （已移出本期，编号保留不复用。原为"账号被删除时删除该用户的全部记忆"，平台目前没有删除账号的功能。）
- **AC-101** — WHEN 记忆被删除或恢复（管理页删除与清空、归因处删除、对话中的忘掉、操作提示上的撤销）或在管理页被编辑、新增, THE SYSTEM SHALL 写入审计记录，记录操作人、时间和动作，不包含记忆内容。〔测〕

### 2.10 效果度量

- **AC-102** — THE SYSTEM SHALL 记录下列指标并支持按租户、场景、应用拆分：显式写入、自动整理、手动新增各自的新增条数；被取代与被删除的条数；被带入、被检索返回的条目数；自写下起从未被带入也未被检索返回的条目数；带详情条目中详情被取回过的比例；用户撤销次数；AC-61、AC-62、AC-45 的失败次数。〔测〕
- **AC-103** — THE SYSTEM SHALL 使上述指标只含数量，不含记忆内容，并且不提供管理端的统计页面。〔测〕
- **AC-104** — THE SYSTEM SHALL 随本功能交付一个取自 bisheng 真实使用场景的评测集，覆盖全部标注〔评〕的验收标准，并包含"回答声称已记下而没有成功写入"与"未经要求而写入"两类情况的计数。〔测〕
- **AC-105** — THE SYSTEM SHALL 产出同一批题目在"带记忆"与"不带记忆"两种条件下的得分对比。〔测〕

## 3. 边界情况与已知限制

- 应用作者能取到使用者的记忆。记忆会被带入记忆已启用的助手，并作为记忆检索节点的输出交给工作流的后续节点，作者可以通过提示词或流程编排让它出现在回答与输出里。这是"一个用户一份记忆、应用可读"的直接后果，由开关默认关和 AC-75 的说明承担告知；AC-08 约束的是专门入口，不约束这条途径。
- 记忆不随知识库权限回收而失效。用户在对话里认可的结论可能源自某份知识库文件；之后他失去该文件的权限，这条记忆仍然有效。AC-18 把来源限定为用户本人的话和他明确认可的结论，文件内容本身不会被记下。
- 撤销在三种情况下会失败并说明原因，不做部分恢复：涉及的条目已被"清空"；撤销"更正"时新条目已经被再次取代或删除；同一次操作已经撤销过。
- 被删除的条目对任何读取途径都不可读，但其数据保留到用户"清空"为止，以支持撤销。"清空"是唯一会彻底移除数据的操作。
- 管理端回放会话时，记忆相关的工具调用显示为"记忆操作"占位，不显示记下或取回的内容。
- 当用户在同一句话里要求记下多件事、其中一部分属于不记的类别时，系统只写入可记的部分，并说明哪些没有记下及原因。
- 当助手记忆开启、而作者在该助手里另外配置了同名或同用途的工具时，以平台提供的记忆能力为准，具体处理方式见 design.md。
- 当一个用户在多个租户内都有记忆时，记忆管理页和各读取途径只涉及当前租户。
- 租户记忆关闭期间，用户仍能在管理页查看、删除和清空已有记忆（AC-90），但不能新增和编辑。
- 用户的租户归属变化后，其在原租户内的记忆一直保留。调走且不再回来的用户，记忆不会被自动清理；用户被停用后记忆同样一直保留。本期没有任何由系统发起的清除。
- 模型在不该写入时写入、该写入时没有写入、或声称已写入而没有写入，属于模型行为偏差。系统不以兜底方式掩盖，由 AC-23、AC-30 和 AC-104 暴露与计数。
