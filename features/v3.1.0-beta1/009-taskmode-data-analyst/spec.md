# 深度研究：数据分析子代理（NL2SQL）与按需澄清

**版本**：v3.1.0-beta1。**优先级**：P1。**流程**：小功能（SDD-Guide §1），只写本 spec；设计依据是已确认的方案文档 [`docs/PRD/2.6 灵思 deepagents 迁移 PRD/灵思任务模式 NL2SQL 数据分析子代理方案.md`](../../../docs/PRD/2.6%20灵思%20deepagents%20迁移%20PRD/灵思任务模式%20NL2SQL%20数据分析子代理方案.md)（v2，commit `0d0251666c`），实现中的决策记在 PR。**状态**：2026-11-11 规格已确认（sdd-review 两项 medium 已按建议修订），开始实现。

## 1 目标与范围

作为深度研究的使用者，我希望用自然语言问业务数据库，得到带数据、图表和 SQL 的报告；遇到只有我知道的口径问题时，系统再来问我，其余情况不打扰我。

本期做三件事：

1. 新增只读的 data-analyst 子代理。主图从已挂载的技能中选出数据库技能，把技能路径写进委派说明；子代理读技能拿到连接信息，在代码执行器里执行 SELECT，返回数据、图表路径、SQL 和结论；主图拼装交付物。
2. 去掉主提示词里"整个会话最多澄清一轮"的上限，改为按必要性判断是否提问。子代理遇到无法自解的歧义时返回 `NEED_CLARIFICATION:`，由主图决定是否问用户。
3. 代码执行器的执行边界规则增加例外：技能明确提供的外部业务库可以连接，平台自身服务仍禁止连接。

不做：数据源模块、凭据加密与按人隔离、前端改动（含子代理中文名显示）、复用工作流的 `sql_agent` 工具、DM8 等多方言适配。

## 2 验收标准

- **AC-01** — WHEN 会话绑定了代码执行器，且租户内有一个写明只读 MySQL 连接的数据库技能，用户提出需要查库的问题，THE SYSTEM SHALL 由主图委派 data-analyst；子代理读取该技能的 SKILL.md、在代码执行器中执行 SELECT，最后一条消息返回结论、关键数字、执行过的 SQL、文件路径和所做假设；主图亲自拼装最终交付物。
- **AC-02** — WHEN 主图委派 data-analyst，THE SYSTEM SHALL 在委派说明中包含问题、技能路径 `/skills/<name>/SKILL.md`、已知口径、允许范围和该子任务的 `scratch/<短名>/` 目录。
- **AC-03** — WHEN 会话没有绑定代码执行器，THE SYSTEM SHALL 不装配 data-analyst，主提示词中不出现它的委派指引。
- **AC-04** — WHEN 装配 data-analyst，THE SYSTEM SHALL 只给它代码执行器这一个业务工具（另有框架自带的文件工具），不给知识库检索、联网、ask_user、写文件类导出工具和 check_html。
- **AC-05** — WHEN data-analyst 运行，THE SYSTEM SHALL 使用与 researcher 相同顺序的中间件栈（压缩、容错、防循环、二进制守卫、结果预算、语言尾注、调用修复），不挂引用相关中间件。
- **AC-06** — WHEN data-analyst 遇到靠查库和技能都无法消除、且只有用户知道的歧义，THE SYSTEM SHALL 让子代理返回以 `NEED_CLARIFICATION:` 开头的问题列表；主图判断确有必要时调用 ask_user，拿到答案后写进新的委派说明重新委派；主图不把 `NEED_CLARIFICATION` 当作最终结果。
  - **验证状态（2026-11-11）**：E2E 中 3 次均未触发（主图总在委派前确定口径），用户决定接受现状，不作为阻断门槛；见 e2e-report.md。
- **AC-07** — WHEN 主图系统提示词生成（任意深度研究任务），THE SYSTEM SHALL 不含任何澄清次数上限（如"整个会话最多澄清一轮""绝不第二次调用 ask_user"），并写明提问判断原则：只有用户知道、且按默认假设大概率做错或返工代价大时才问；能补默认值的采用假设并在交付物写明；同一时刻的多个缺口合并为一次提问；用户已回答过的问题不再问。
- **AC-07b**（行为观察，不作为阻断门槛）— WHEN 在端到端中运行一组会话（含明确请求与含糊请求），THE SYSTEM SHOULD 对明确请求不弹澄清卡，对同一问题不重复提问；结果按会话数和人工判定记录在验证报告中。
- **AC-08** — WHEN 任务以无人值守方式运行（Open API），THE SYSTEM SHALL 不出现 ask_user 相关指引；主图收到 `NEED_CLARIFICATION` 时选择最合理的候选项作为假设，重新委派，并在交付物中写明假设。
- **AC-09** — WHEN data-analyst 产生中间文件，THE SYSTEM SHALL 写在 `scratch/` 下，不出现在交付物列表中；只有进入交付物的最终图表写在 `output/`。
- **AC-10** — WHEN 模型阅读代码执行器的执行边界规则，THE SYSTEM SHALL 在主提示词和执行器工具描述两处给出一致的例外：技能明确提供的外部业务数据库可以连接；平台自身的数据库、缓存、对象存储仍不得连接。
- **AC-11** — WHEN data-analyst 生成写操作 SQL，THE SYSTEM SHALL 依靠技能中的只读账号让数据库拒绝写入；子代理提示词要求只执行 SELECT。

## 3 明确接受的边界

- 企业技能对租户内全员可见且全部挂载，写在企业技能里的连接串任何用户都能读到。2026-11-10 用户拍板接受，缓解手段是只读账号和数据库侧 IP 白名单。
- 去掉澄清次数上限后，提问是否克制依赖模型遵循度，不加代码兜底；实测过度提问再提议软上限。
- 9 月"沙箱可直连业务库"的验证早于 uid 隔离默认化，端到端验证前需在当前默认隔离模式下复验连通性。
- 子代理步骤名在前端按 `data-analyst` 原样显示，与现有 `general-purpose` 一致。

## 4 验证

- 单测（`src/backend/test/linsight/`）：AC-03 / 04 / 05 的装配断言；AC-07 / 08 的提示词断言（含无人值守版本）；AC-10 两处措辞一致。
- 端到端（114 或本地连 test 中间件）：准备只读账号的测试 MySQL 和一个企业数据库技能，覆盖 AC-01 / 02 / 06 / 09 / 11；Open API 覆盖 AC-08；AC-07b 抽样 ≥6 个会话（明确 / 含糊各半），人工判定后记录。
