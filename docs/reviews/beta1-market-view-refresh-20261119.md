# 客户端管理「插件 > 工作台」管理视图刷新修复

日期：2026-11-19。修复分支：`codex/3.1.0-beta1/bugfixes-20261118`；目标：`feat/3.1.0-beta1`。

## 定位与修复

实际入口是平台 `/dsh?tab=plugins` 的 `PluginMarketPage`，工作台由 `WorkbenchMarketSection` 展示，并非 `/workspace` 的员工应用列表。

最新 beta1 已将两个市场管理列表 GET 接入管理请求准入，后端在分页与总数查询前使用已确认的管理租户。浏览器请求层为列表发送 `X-Management-Tenant`；`GET /admin/context` 返回的登录租户与 `X-DSH-Market-Tenant` 仍用于原有操作身份校验。它们含义不同，不能把后者统一替换成管理租户，否则会改变或破坏操作边界。

本次发现的页面缺口：市场只按 `user_id:tenant_id` 重建，而切管理视图不改变登录租户；面板内部的查询仅依赖登录租户、页码、手动刷新。因此页面保持挂载时，确认事件不会重新查询，旧列表、分页、详情等状态会保留。既有全局整页重载可以清理状态，但市场面板没有自己的视图切换处理。组件回归已复现旧记录残留及旧请求不退休。

修复在市场页订阅既有 `bisheng:management-scope-changed` 事件，用本地刷新序号重建活动面板：

- 插件/工作台当前页签保持不变；活动列表从第 1 页查询，旧数据立即清空。
- 复用原卸载清理：取消旧列表请求、失效删除确认，关闭详情与导入弹窗；迟到结果不写入新面板。
- 两张市场列表共用此处理。新请求仍使用原请求层确认的管理租户，不新增全局租户状态或查询租户参数。
- 外租户列表继续只读；详情、导入、删除与桌面员工目录的权限合同不变。全局重载机制保留。

本次未读取或变更 116 的部署版本、现场数据或管理视图，不能据本地验证断言现场已经生效。部署应同时包含 beta1 已有的列表租户准入修复与本次面板刷新修复。
