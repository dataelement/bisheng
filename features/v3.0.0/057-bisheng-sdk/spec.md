> **范围边界**
>
> 本 Feature 是专业开发者通道的**代码面**：把「平台特有 ∧ 写错了会出安全事故」的三件事——读平台注入身份（auth）、以当前访问者身份检索（retrieve）、按应用收窄的附件存取（storage）——各封成一行到位的默认做法，并随包发布开发者指南。它不拥有任何服务端能力：身份注入与短时凭据归 F054（线上）/ F053（本地）、检索门面归 F052、白名单与能力收回归 F055、附件存储句柄归 F054；SDK 只**读注入、调门面、消费句柄**。模型调用与应用数据库**刻意不进 SDK**（PRD-1 DEV-07 表「刻意不进 SDK 的两样」），用行业标准库 + 平台注入的环境变量。
>
> - **本次纳入**：
>   - **Python 首发 `bisheng-sdk` 安装件与分发**：公开面恰为 auth / retrieve / storage 三模块；由平台自身分发（与 CLI 安装件同一分发机制与规则：匿名可达、纯内网零公网依赖、随开放能力层开关存在；端点由 F053 拥有、承载本发布件），公开包索引为可选补充；托管构建期自平台自身分发端点安装（F054 AC-16 构建期白名单）；SDK 与平台版本的**兼容承诺**（独立版本、平台声明 SDK 最低兼容版本，不兼容时首次交互明确报错）
>   - **auth**：一次调用返回当前访问者身份（用户标识 / 姓名 / 主部门等平台约定字段 + 主体类型）；托管运行期 = 当前访问用户（F054 注入）、`bisheng dev` 期 = 开发者服务账号（F053 注入）、应用代码零差异；**无注入身份即抛错**（不返回 None / 匿名 / 缺省身份）；只读注入——不提供登录、签发 / 解析 / 校验凭据、覆盖身份（无 `as_user`）的任何 API；请求作用域、不跨请求缓存
>   - **retrieve**：以**当前访问者**为执行身份经 F052 门面检索；执行身份取自请求上下文中平台注入的访问者凭据句柄（线上 F054 AC-34 / 本地 F053 AC-23），**绝不以应用运行期凭据或任何固定身份检索**；托管期可及范围 = 平台侧按当前生效能力声明确定的白名单 ∩ 访问用户可见范围（文件级、集合相等，F055 AC-50 / F052 AC-21）、本地期 = 服务账号被显式授予范围（无白名单）；fail-closed（无身份 / 引擎不可用 / 目标不可及 → 明确错误、不降级、不缩水）；能力收回错误原样呈现；不新增数据面
>   - **storage**：在当前应用的附件空间内上传 / 下载 / 列举 / 删除；按应用隔离；不暴露 bucket / 对象键 / 端点 / 存储凭据；不进公共可读存储、无匿名直链；不计租户存储配额；本地 `dev` 期以 F053 AC-27 注入的本地附件目录句柄同一 API 工作、不进 deploy 上传包（F053 AC-32）
>   - **开发者指南**（随 SDK 发布）：安装、三件套用法（auth 章按 F053 AC-17 可判定形式显著标注静默失败点）、模型与应用数据库两条标准库接法（引用 F053 同源内容）、与技能包 / CLI 的配合、`login → dev → deploy` 完整流程；**「平台能力接线」包的 SDK 三件套章节、样例与自检脚本 SDK 部分**（承接 F053 AC-17 / AC-18 / AC-22 ②）；指南与技能包 SDK 章同源一份
>   - **调用范式全平台唯一**：本地手写引入的 SDK 与平台内模板（PRD-2 WB-01）预接线的是同一套 SDK（验收随 PRD-2）；SDK 是平台推荐且指南 / 技能包唯一教授的写法（直读注入头亦合法）、不提供第二套 helper；**模块准入门槛**（平台特有 ∧ 写错了会出安全事故）作为流程规则登记于 §3 / §4，chat / appdb 不得按惯性加回
> - **本次明确排除**：
>   - **chat（模型调用）**——用官方 OpenAI 兼容客户端 + 平台注入的 base URL 与凭据（**F051** AC-01 / AC-33；用法在 F053「平台能力接线」包模型章）；SDK 不含任何模型调用封装或便捷函数
>   - **appdb（应用数据库读写）**——标准数据库库 + 平台注入的连接环境变量（**F054** AC-45 线上 / **F053** AC-26 本地）；建表改表由 `bisheng-app.yaml` 声明、平台建表（**F055** RT-05）；SDK 不含连接工厂、ORM 封装或迁移工具
>   - **非 Python SDK**（TypeScript / Java 等）——v3.1 视 `runtime` 矩阵与客户反馈；本版 `node20` / `static` 运行时的应用只用「不经 SDK 的两条路径」+ 直读注入头
>   - **MCP 六类工具与统一检索门面本身**（F052）；**CLI 五命令、技能包结构、`dev` 注入、安装件分发端点**（F053）；**app-proxy 注入 / 剥离伪造头 / 短时凭据签发 / 附件存储服务端 / 每应用数据库**（F054）；**能力总线注入通道与凭据、白名单语义、能力收回、应用运行期凭据**（F055）
>   - **SDK 内部的重试 / 连接池 / 超时 / 序列化 / 框架适配层形态**（design）；**错误码定义**（design §6）
>   - **PRD-2 模板预接线（WB-01）与工作台侧任何界面**——随 PRD-2；DEV-07 验收 3 随之
>   - **storage 的绕过应用的下载直链 / 分享链接 / 附件级权限 / 附件配额与统计**（§4 决议-9；v3.1 视需求）；**审批期临时预览实例的附件空间隔离策略**（F055「试用数据不带入生产」同口径，SDK 对句柄透明）
>   - **以应用自身身份（非访问者）检索的 API**——PRD-1 全册无此场景、F055 AC-55 明定检索无访问用户一律拒绝；后台任务无访问者 → retrieve 报错（线上本地一致，§3）；模型调用的后台任务规则归 F051 / F055
>   - **SDK 侧的身份头验签、本地权限判定或本地白名单模拟**（§4 决议-3 / 决议-8）；**SDK 模块准入评审本身**（流程规则，见 §3 / §4 决议-10，不作 AC）——信任根在入口拓扑与服务端门面，SDK 不复制第二份判定

## 1. 用户故事

作为 **开发者（owner）**，
我希望 **写应用时 `auth` 一行拿到当前访问者、`retrieve` 不用自己想「以谁的身份查」、`storage` 不用碰 bucket 和对象键，且这三行在 `bisheng dev` 本地和上线后一字不改**，
以便 **把精力放在业务上；不会因为读错头、选错身份、拼错路径而做出「本地能跑、线上越权」的应用**。

作为 **开发者的本地 coding agent**，
我希望 **`login` 后技能包里就有 SDK 三件套章节与自检脚本，读了就知道「不写登录页、读平台注入身份」，SDK 报错时能拿到「缺什么、怎么改」而不是堆栈**，
以便 **凭技能包 + SDK + CLI 自主完成接线 → 本地跑通 → deploy 的闭环，不把安全决定留给自己猜**。

作为 **安全负责人**，
我希望 **唯一「写错了应用照样跑」的静默失败点（auth）被 SDK 的默认行为堵死——无注入即抛错；retrieve 在代码层面就不可能以应用身份越权；storage 不把对象存储的任何实现细节交给应用；模型与数据库不引入非标准封装**，
以便 **审计一个托管应用的接线时只需确认「用了 SDK 三件套 + 两条标准库接法」，攻击面与审查面都最小**。

## 2. 验收标准

> AC 编号在本特性内唯一。括号内标注对应 PRD-1 条目与验收序号（如 `↔DEV-07 验收 1`）及跨 Feature 不变量。属于服务端门面 / 注入 / 句柄的行为用「经 F052」「经 F054」「经 F055」措辞——本 Feature 只验收 SDK 侧的调用行为、错误呈现与文档。错误码仅作可观测行为引用，定义在 design.md。2026-08-17 审查修订后编号保持稳定：新增末尾追加（§2.8）、无删除。

### 2.1 安装、分发与兼容

- **AC-01** — THE SYSTEM SHALL 提供 Python 版 `bisheng-sdk` 安装件（首发只 Python），其公开面**恰为** auth / retrieve / storage 三个模块；安装件由平台自身分发——经 F053 AC-01 的安装件分发端点承载（同一端点亦承载平台声明的 SDK 最低兼容版本；下载不要求密钥或登录态、纯内网零公网依赖、随开放能力层开关存在）；发布到公开包索引为可选补充，不作为任何环境的前提。（↔DEV-07 需求描述「Python 首发」；DEV-03 规则「无公网依赖」；F053 AC-01；§4 决议-5 / 决议-10）
- **AC-02** — THE SYSTEM SHALL 使 SDK 可在**托管构建期**安装：应用依赖清单中声明 `bisheng-sdk` 即可——SDK 自平台自身分发端点安装（该端点在构建期出站白名单内，经 F054 AC-16）、其第三方依赖自平台配置的包源安装，无需公网、不要求把 SDK 放进客户自有镜像源；SDK 支持平台托管 `runtime` 矩阵内的全部 Python 版本（首发 python3.11）并可在开发者本地同版本运行。（↔DEV-04 托管运行契约「依赖包经平台内网镜像安装」；F054 AC-16；§4 决议-5）
- **AC-03** — THE SYSTEM SHALL 使 SDK 具有**独立于平台版本号**的版本，并对外承诺兼容关系：平台声明其支持的 SDK 最低兼容版本（随 F053 AC-01 分发端点的版本信息一并给出）；IF SDK 与目标平台不兼容, THEN THE SYSTEM SHALL 在 SDK 与该平台的首次交互即抛出明确错误（含双方版本与处置方式：从当前平台重新获取 SDK / 平台需升级），不静默降级、不部分工作；兼容的 SDK 在平台升级后无需重发应用。校验时机与判据属 design。（↔DEV-03 规则「版本对齐」外推；F053 AC-01；§4 决议-6）
- **AC-04** — THE SYSTEM SHALL 使 SDK 在任何输出、异常信息与本地日志中不回显访问凭据、服务账号密钥或应用运行期凭据的明文（至多掩码），不把任何凭据持久化到磁盘（本地 `dev` 期 storage 落盘的是附件、不是凭据），也不把凭据写进 storage 附件元信息。（↔NFR-2；INV-28）
- **AC-05** — WHERE 开放能力层未部署, THE SYSTEM SHALL 使 SDK 安装件分发端点不可达（呈不存在，同 F053 AC-05）；本地 `dev` 与托管运行各以对应层已部署为前提（F053 AC-05 / AC-29、F054 AC-30），SDK 不另设「层未部署」分支；auth 只读注入、与部署开关无关。（↔GOV-10；F049 AC-49）

### 2.2 auth（读平台注入身份）

- **AC-06** — WHEN 应用在处理一次经平台入口转发的请求时调用 auth, THE SYSTEM SHALL **一次调用**返回当前访问者身份：用户标识、姓名、主部门、主体类型（自然人 / 服务账号）等平台约定字段（字段清单 = F054 AC-31 与 F053 AC-23 注入的同一结构，SDK 原样暴露、不自行推导或补全）；托管运行期返回当前访问用户（经 F054 AC-31）、`bisheng dev` 期返回当前 `login` 密钥对应的开发者服务账号（经 F053 AC-23）；应用代码零差异。（↔DEV-07 表 auth / 验收 1；DEV-05 需求表「应用怎么拿：完全相同」/ 验收 1 / 5；INV-32 auth 半边承接（本 Feature 为来源 spec 之一））
- **AC-07** — IF 调用 auth 的上下文中不存在平台注入身份（如绕过入口直连应用进程、运行时健康探活请求、未经 `bisheng dev` 迷你代理直接运行应用、单元测试裸调用、后台任务无请求上下文）, THEN THE SYSTEM SHALL 抛出明确的「未取得平台注入身份」错误；THE SYSTEM SHALL NOT 返回 None / 空对象 / 匿名或任何缺省身份，也不得静默以进程内任何配置身份代替。（↔DEV-07 表 auth「唯一的静默失败点」；NFR-1.3；§4 决议-1）
- **AC-08** — THE SYSTEM SHALL 使 auth **只读注入**：不提供任何登录页 / 登录流程、签发凭据、解析或校验用户凭据、构造平台会话的 API；不提供以显式用户标识替代或覆盖注入身份的参数（无 `as_user` 及任何等价物）；伪造注入头无效由 F054 AC-32（线上）/ F053 AC-25（本地）在入口保证——SDK 不试图自行鉴别注入头真伪、也不持有任何用于验签的密钥材料。（↔DEV-05 ① / 验收 2 / 验收 4；PRD-1 §5.1；§4 决议-2 / 决议-8）
- **AC-09** — THE SYSTEM SHALL 使 auth 的结果作用域为**当前请求**：不跨请求复用；同一进程并发处理不同用户的请求时各自取得各自的身份；WebSocket 连接取握手时注入的身份，连接的授权有效期与到期断开由 F054 AC-35 承接、SDK 不续期。
- **AC-10** — THE SYSTEM SHALL 使 auth 在 `bisheng dev` 期返回的服务账号身份中组织类字段（主部门等）可为空、但结构与线上一致（服务账号不属任何部门，INV-29）；开发者指南与技能包 auth 章 SHALL 写明该差异，以及「本地看不到 per-user 差异、验证路径 = 发布后用真实账号访问」。（↔DEV-05 ②；F053 §3「dev 注入的是服务账号」）

### 2.3 retrieve（以当前访问者身份检索）

- **AC-11** — WHEN 应用调用 retrieve, THE SYSTEM SHALL 以**当前访问者**为执行身份、经 F052 统一检索门面执行检索（门面归 F052 AC-19，SDK 只调用）：入参与出参即门面的入参与出参（查询、可选目标知识库范围、条数上限；经文件级过滤、可引用溯源的片段结果——以 F052 AC-19 为准），SDK 不增删字段、不二次过滤。（↔DEV-07 表 retrieve / 验收 1；GOV-05；INV-36 retrieve 半边承接（本 Feature 为来源 spec 之一））
- **AC-12** — THE SYSTEM SHALL 使 retrieve 的执行身份**取自请求上下文中平台注入的访问者凭据**：托管运行期 = app-proxy 每请求注入的短时访问凭据句柄（F054 AC-34）；`bisheng dev` 期 = 迷你代理以同一结构每请求注入的服务账号访问凭据句柄（F053 AC-23；`login` 密钥不进应用进程、访问者凭据不以进程级环境变量提供，F053 AC-27）；THE SYSTEM SHALL NOT 以应用运行期凭据（应用自身身份，F055 AC-57）、进程级环境中的任何密钥或任何固定 / 配置身份执行检索，也不提供指定他人身份检索的参数。（↔DEV-07 表 retrieve「必须以当前访问者身份、选错即越权」；DEV-05 需求表「平台能力按谁的权限放行」；§4 决议-2）
- **AC-13** — WHILE 托管运行期, THE SYSTEM SHALL 使 retrieve 的可及范围 = 该应用当前生效能力声明的知识库白名单 ∩ 当前访问用户可见范围（文件级）——访问用户由注入的短时访问凭据确立、白名单由平台侧按应用当前生效能力声明确定、应用与 SDK 不可自报白名单（经 F055 AC-50 / AC-51；门面执行 F052 AC-21）：用户本人有权限但应用未声明的知识库经 SDK 不可检索；应用已声明但该用户无权限的库或文件不出现；声明范围内的结果与该用户在平台内自行检索的结果**集合相等**（不多给不少给）。（↔GOV-05 验收 5 / 6；NFR-1.1；INV-36）
- **AC-14** — WHILE `bisheng dev` 期, THE SYSTEM SHALL 使 retrieve 以 F053 AC-23 注入的服务账号访问凭据为执行身份，可及范围 = 该开发者服务账号被**显式授予**的知识库范围（无白名单，经 F052 AC-22），过滤强度与 fail-closed 行为与线上一致；SDK 不在本地模拟能力声明白名单（§4 决议-3）；IF 该密钥未持 `knowledge:read`, THEN THE SYSTEM SHALL 把 F052 面「指明缺该位」的拒绝原样抛出。（↔DEV-05 ③ / 验收 3；F053 AC-28；NFR-1.1）
- **AC-15** — IF 调用 retrieve 时请求上下文中无访问者凭据、或凭据无效 / 过期 / 因应用停运被拒（含 AC-07 各情形、后台任务等无访问用户上下文）, THEN THE SYSTEM SHALL 抛出明确错误、不发起检索——检索无访问用户**一律拒绝**（同 F055 AC-52 / AC-55），SDK 不提供以应用自身身份检索的路径；绝不回退为按白名单全量放行、按任何固定身份放行，或返回空集当作成功。（模型调用在无访问用户上下文以应用自身发起的规则归 F051 / F055 AC-55，不在本 SDK。）（↔GOV-05 fail-closed / 验收 7；F052 AC-23；F055 AC-52 / AC-55；NFR-1.4；INV-30）
- **AC-16** — IF 权限引擎不可用、评估失败或结果不可判定, THEN THE SYSTEM SHALL 把门面返回的带错误码的明确错误**原样**抛给应用（可与「检索成功但无结果」区分），不返回未过滤、部分过滤或缩水的结果集，不本地重试成「更小的范围」。（↔GOV-05 验收 7；DEV-05 验收 3；F052 AC-24；INV-30）
- **AC-17** — IF 显式指定的目标知识库中任一**不可及**——托管期：白名单外的库整体不可及（F052 AC-21；未声明的库经该应用不可检索，F055 AC-50 / AC-51）；本地期：不存在 / 未授予 / 类型不支持（F052 AC-11 / AC-27）——, THEN THE SYSTEM SHALL 按门面语义拒绝整个请求并指出不可及的标识、不静默剔除后返回缩水结果（存在性不泄露）；IF 应用声明的知识库能力被收回, THEN THE SYSTEM SHALL 把 F055 AC-53 定义的「带能力名与已收回原因」的错误原样暴露、可与普通失败区分，不回退旧结果。（↔GOV-05 规则「能力收回后行为」/ 验收 4 / 5）
- **AC-18** — THE SYSTEM SHALL 使 SDK retrieve **不新增数据面**：不跨请求 / 跨用户缓存或复用检索结果、不本地二次过滤或补召回、不绕过门面直连索引或知识库存储（F052 AC-26「唯一路径」）；同一查询由不同用户发起各得其过滤后的结果；运行期能力调用的审计双归属（actor = 应用、subject = 当前访问用户）由服务端从注入凭据取得（F055 AC-55），SDK 不自报也不能改写 subject。（↔DEV-02「不新增数据面」同判据；GOV-04）
- **AC-19** — THE SYSTEM SHALL 使 retrieve 的各类失败对应用**可区分**并各附可读原因：未取得访问者凭据 / 凭据无效或过期 / 缺权限位（本地期）/ 目标不可及 / 能力已收回 / 权限评估失败 / 版本不兼容 / 平台不可达；错误码与异常形态定义在 design。（↔DEV-04 验收 7「缺什么怎么改」同标准；NFR-1.4）

### 2.4 storage（按应用收窄的附件存取）

- **AC-20** — THE SYSTEM SHALL 提供 storage：在**当前应用**的附件空间内上传、下载、列举、删除附件（含附件元信息读取）——四操作、按应用隔离、越界拒绝、单文件上限的语义由 F054 AC-45 的按应用收窄附件存储句柄定义，SDK 以同名句柄同一 API 使用；句柄经运行期注入取得（F054 AC-17）；SDK 只消费句柄、不创建或销毁附件空间。（↔DEV-07 表 storage / 验收 1；DEV-04 契约「平台托管提供附件 / 文件存储」；F054 AC-45）
- **AC-21** — THE SYSTEM SHALL 使 storage 按应用隔离：应用 A 经 SDK 无法读取、列举、覆盖或删除应用 B 的附件；应用无法经 SDK 访问附件空间之外的任何对象；SDK 对外**不暴露底层对象存储的任何实现细节**（bucket、对象键前缀、端点地址、存储凭据、签名机制）——应用只见附件的应用内路径 / 名称与元信息；路径穿越等越界写法得到明确拒绝。（↔DEV-07 表 storage「不把底层对象存储实现暴露给应用」；NFR-1）
- **AC-22** — THE SYSTEM SHALL 使经 storage 上传的附件不进入公共可读存储、不计入租户存储配额，单文件超过部署配置上限得到明确错误而非截断写入（均为 F054 AC-45 句柄承诺，SDK 原样呈现）；SDK 不产生匿名可达的直链，本版不提供绕过应用的下载直链或分享链接，应用经自身接口向用户吐文件（§4 决议-9）。（↔GOV-03 规则；NFR-2；F054 AC-45）
- **AC-23** — WHILE `bisheng dev` 期, THE SYSTEM SHALL 使 storage 以**完全相同的 API** 工作：句柄即 F053 AC-27 注入的本地附件目录句柄（指向项目本地附件目录），附件在 `dev` 重启间保留、不进入 `deploy` 上传包（F053 AC-32 忽略规则含本地附件目录）；应用代码零差异；本地期同样只见附件的应用内路径、不依赖真实落盘位置。（↔DEV-05 需求「本地与线上零差异」；F053 AC-27 / AC-32；§4 决议-4）
- **AC-24** — THE SYSTEM SHALL 使托管期附件真身恒在平台存储：实例回收 / 崩溃 / 重建后附件完整（经 F054 AC-39），owner 显式删除应用时随资产一并删除（经 F054 AC-43）；SDK 不提供清空整个附件空间的操作，附件的删除只能逐个 / 按显式清单进行。（↔RT-07；INV-35）
- **AC-25** — IF storage 调用时无法取得应用的存储句柄（托管期未注入 / 已失效 / 应用已停运 / 平台不可达；本地期未经 `bisheng dev` 启动故无 F053 AC-27 句柄）、或目标附件不存在, THEN THE SYSTEM SHALL 抛出彼此可区分的明确错误；不静默改写到本地临时目录、不返回空列表或空内容当作成功。（↔NFR-1.4 同向；F055 AC-58 停运语义；F053 AC-27）

## 3. 边界情况

> 只写期望的对外行为；SDK 内部的上下文传递、错误分类实现、本地落盘布局见 design.md §5。

- **auth 是唯一「写错了应用照样跑」的静默失败点——SDK 让正确做法成为默认**：无注入身份即抛错（AC-07），而不是返回 None / 匿名让应用「看起来能跑」。由此健康探活请求、后台任务、单元测试裸调用会遇到该错误——这是**刻意的**：指南教健康端点不调 auth、后台任务不假设有访问者；不为这些场景提供「宽松模式」或缺省身份开关，否则静默失败点又回来了（§4 决议-1）。
- **retrieve 必须用访问者身份而非应用身份，选错即越权**：托管期同一容器内同时存在两种凭据——应用运行期凭据（应用自身身份，服务能力总线的模型调用等，F055 AC-57 / F051）与每请求注入的访问者短时凭据（F054 AC-34）；SDK retrieve 只认后者、结构上不接受前者（AC-12）。**后台任务无访问者 → retrieve 报错，线上本地一致**（AC-15；F055 AC-55 明定「仅模型调用允许后台任务以应用自身发起、检索一律拒绝」）；PRD-1 全册没有「以应用身份检索」的场景，本版不提供该 API（范围边界）。
- **本地 dev 与线上同构 → 应用代码零差异，但有四处可预期的「数据差异」**（指南必须写明）：① auth 取到的是服务账号、组织字段可为空（AC-10）；② 本地 retrieve 无能力声明白名单、范围 = 服务账号被授予范围——本地能查到但线上未声明的库上线后被拒、本地查不到但线上用户有权且已声明的库上线后能查到（AC-13 / AC-14）；③ 访问者凭据句柄的来源不同（本地 = 迷你代理每请求注入的服务账号访问凭据句柄，F053 AC-23；线上 = app-proxy 注入的访问用户短时凭据句柄，F054 AC-34）但对应用不可见；④ storage 本地落盘、线上落平台存储（AC-23）。开发期只会「本地看得少」，不会「本地能跑、线上越权」（PRD-1 DEV-05 ③）。
- **retrieve 不本地模拟白名单**：白名单的语义是「审批通过 = 应用侧授权」（F055），本地无经审批的声明可依；SDK 若按 `bisheng-app.yaml` 草稿本地收窄，等于复制一份白名单判定（与 F052 AC-26「唯一路径」/ INV-36 相悖），且草稿与线上生效声明会漂移。代价 = 上一条差异 ②，靠指南与 F055 预检（声明所引知识库存在与可用）兜住。
- **storage 不暴露 bucket / 路径 / 端点 / 凭据**：应用只见应用内路径与元信息（AC-21）；越界（跨应用、路径穿越、附件空间之外）一律明确拒绝而非静默映射（F054 AC-45 句柄语义）；不提供匿名直链——附件不进公共可读存储是 F054 承诺、SDK 不提供任何绕开它的句柄（AC-22）。需要让用户下载时应用自己吐流。单文件上限是部署配置项，超出报错不截断。
- **审批期临时预览实例**（F055）注入的是审批人身份、平台能力按 owner 权限放行且计审计（INV-36 唯一例外）：SDK 对此**透明**——auth 返回审批人、retrieve 以注入的凭据为准、storage 以注入的句柄为准；预览实例的附件空间是否与生产隔离由 F055「试用数据不带入生产」口径决定，SDK 不判断自己身处何种实例。
- **版本不兼容**：平台声明其支持的 SDK 最低兼容版本（F053 AC-01 版本信息），不兼容即在首次交互抛错（AC-03）。**auth 不需平台交互**，因此不兼容可能到 retrieve / storage 首次调用才暴露——指南建议应用启动时执行一次连通自检（AC-28 的自检脚本即为此）；同机多平台 `dev` 时以当前 `login` 的平台为准。平台升级后 SDK 版本仍在支持区间内的存量应用不需重发；低于区间的应用在下一次调用得到明确错误、由 owner 升级依赖后重新 `deploy`（重发必审，INV-34）。
- **不进 SDK 的两样**：SDK 内没有 chat / appdb，也没有「顺手包一层」的便捷函数（AC-30）；模型走官方 OpenAI 兼容客户端（F051 AC-33 已保证本地线上接法一致）、数据库走标准库 + 同名连接环境变量（F054 AC-45 / F053 AC-26）；**模块准入门槛（流程规则，spec 评审项，不作 AC）**：新增模块须同时满足「平台特有」∧「写错了会出安全事故」，chat / appdb 被否决的理由记录在 PRD-1 DEV-07 两表与 design（§4 决议-10；AC-33 只验收公开面恰三模块）——例如「密钥引用」若在 PRD-2 进入能力总线，须先过该门槛再讨论是否进 SDK。
- **凭据生命周期对 SDK 的影响**：访问者短时凭据到期 / 用户会话失效 → 该请求内的 retrieve 报「凭据无效或过期」（AC-15），SDK 不缓存、不续期；应用停运 → 运行期凭据与句柄拒绝（F055 AC-58）→ storage / retrieve 报可区分错误（AC-25）；服务账号密钥被撤销 → 本地 `dev` 期后续调用被拒（F053 AC-11 / AC-29），SDK 原样呈现。
- **部署开关**：SDK 安装件分发端点随开放能力层开关存在（AC-05）；本地 `dev` 以开放能力层已部署为前提（F053 AC-05 / AC-29）、托管运行以工场运行时层已部署为前提（F054 AC-30）——两个前提由 CLI 与运行时在入口把住，SDK 不为「层未部署」另设分支；auth 与部署开关无关。
- **多租户对 SDK 不可见**：租户由注入的凭据 / 句柄承载；SDK 不接触租户标识、不提供指定租户的参数；跨租户共享的知识库可见性由门面处理（F052 AC-20 四类来源）。
- **请求作用域与并发**：auth / retrieve / storage 的身份与句柄均取自当前请求上下文（AC-09）；同一进程内多用户并发互不串扰；WebSocket 取握手身份、到期由 F054 断开。SDK 不绑定特定 Web 框架——把当前请求上下文交给 SDK 的接法在指南给出、形态属 design。
- **审计归属由服务端决定**：运行期能力调用的 actor / subject 由服务端从注入凭据取得（F055 AC-55 / F051 AC-21），SDK 不自报 subject、也无法改写（AC-18）——否则应用可伪造「以谁的名义」。
- **托管期出站可达**：应用实例默认封禁出站、只放行平台 API 与声明域名（F054）；SDK 只访问平台 API，不引入需要额外出站白名单的第三方地址（design 约束）。

## 4. 待澄清决议

> 2026-08-17 用户授权全自动模式：以下各项按建议直接定案，记录理由与备选供追溯；spec 评审（`/sdd-review`）后如有 high 级发现再增补。

- **[决议-1] auth 无注入身份时抛出明确错误，不返回 None / 匿名 / 缺省身份，也不提供「宽松模式」开关。** 理由：DEV-07 把 auth 定为唯一静默失败点——「写错了应用照样跑起来、只是身份是错的」；返回 None 会让应用写出 `if user is None: 匿名处理` 这类分支，把静默失败点从「自建登录页」挪到「匿名兜底」，性质不变；抛错让错误在开发期第一次调用就暴露。备选 = 返回 Optional：对健康端点 / 后台任务更「方便」，但方便的代价正是安全事故的温床。**何时重新考虑**：无。
- **[决议-2] retrieve 的执行身份取自请求上下文中平台注入的访问者凭据（线上 = F054 AC-34 短时访问凭据句柄、本地 = F053 AC-23 迷你代理以同一结构每请求注入的服务账号访问凭据句柄）；SDK 不从进程级环境变量取密钥做检索、不读应用运行期凭据、不提供 `as_user` 等指定他人身份的参数；后台任务无访问者即报错。** 理由：DEV-07 表明写「必须以当前访问者身份检索、而非应用自身的身份，选错即越权——SDK 把这个选择固定下来」；托管容器内同时存在应用运行期凭据与访问者凭据，若 SDK 允许任一「兜底」，越权路径就在一个默认参数之外；`as_user` 是 `--as` 的代码翻版（PRD-1 §5.1 / DEV-05 ①）。本地期迷你代理以同一结构每请求注入服务账号访问凭据句柄、`login` 密钥不进应用进程（F053 AC-23 / AC-27），使 SDK 内部也不需要「本地读环境变量、线上读请求」两条路径。备选 = 线上无访问者时以应用身份检索：PRD-1 全册无此场景、F055 AC-55 明定检索无访问用户一律拒绝、且与 GOV-05 fail-closed 直接冲突，否决。**何时重新考虑**：PRD-2 若引入应用级后台检索需求，须先在 F055 定义其权限基准并补 INV，再议 SDK 面。
- **[决议-3] 本地 `dev` 期 SDK 不模拟能力声明白名单，retrieve 范围 = 服务账号被显式授予范围。** 理由：白名单语义 = 「审批通过 = 应用侧授权」（F055 AC-50），本地没有经审批的声明可依；本地按 `bisheng-app.yaml` 草稿收窄等于在 SDK 复制一份白名单判定（与 F052 AC-26 唯一路径 / INV-36 相悖），且草稿与线上生效声明会漂移造成「本地过、线上拒」的反向错觉；PRD-1 DEV-05 ③ 与 F052 AC-22 已明写本地期无白名单。代价 = §3「数据差异 ②」，由指南与 F055 预检（声明所引知识库存在与可用）兜住。**何时重新考虑**：F055 若提供「按草稿声明预演」的服务端能力（预检返回可及性），SDK 可在自检脚本里调用它提示差异，仍不在 retrieve 路径上收窄。
- **[决议-4] 本地 `dev` 期 storage 以 F053 AC-27 注入的本地附件目录句柄工作、API 与线上完全相同、在 `dev` 重启间保留、不进 `deploy` 上传包（F053 AC-32）；本地期同样不把真实落盘位置暴露给应用逻辑。** 理由：DEV-05「本地与线上零差异」对三件套整体成立才有意义；本地起一个对象存储服务成本高且与「零公网 / 零额外中间件」相悖；与 F053 AC-26 本地 SQLite 的形态一致、忽略规则一并覆盖。备选 = 本地直接调平台存储（走服务账号）：会让开发期附件混入平台、且服务账号没有「应用附件空间」的归属，否决。**何时重新考虑**：无。
- **[决议-5] SDK 发布形态 = 可安装的 Python 包，经平台自身分发（F053 AC-01 的安装件分发端点承载，同「匿名可达、随开放能力层开关」规则）+ 公开包索引可选；托管构建期自平台自身分发端点安装（F054 AC-16 构建期白名单）；首发支持 python3.11（托管 `runtime` 矩阵）并随矩阵扩展。** 理由：与 CLI 同渠道（F053 决议-1 / 决议-11）——纯内网零公网依赖是信创硬要求、版本对齐靠「从自家平台拉」天然成立；托管构建期出站只放行平台包源与平台分发端点（F054 AC-16），SDK 若只发公网即在内网构建期断裂、若要求进客户镜像源则每个客户多一步运维。备选 = 只发公网 PyPI：内网不可达，否决；备选 = 随 CLI 打进同一个包：CLI 是开发者本机工具、SDK 是应用运行期依赖，生命周期与安装位置不同，合包会让应用容器背上 CLI 依赖，否决。**何时重新考虑**：无。
- **[决议-6] SDK 版本策略：独立于平台版本号；对外承诺 = 平台声明其支持的 SDK 最低兼容版本（随 F053 AC-01 分发端点的版本信息给出）、不兼容时 SDK 在与该平台首次交互即明确报错并给出处置方式、兼容的存量应用在平台升级后无需重发。校验时机、判据（主 / 次 / 补丁）与探测方式属 design。** 理由：与 F053 决议-7「CLI 与平台同号」刻意不同——CLI 是开发者本机工具、随时可重装，SDK 被应用依赖清单锁定、跟着版本快照走（RT-05 只增不改），若要求同号则平台每次升级都会让全部存量应用不兼容、必须重发且重发必审（INV-34），不可接受；区间兼容 + 明确报错优于「看起来能跑、行为悄悄不对」。auth 不需平台交互、不兼容在首次 retrieve / storage 暴露——指南建议启动自检（AC-28）。**何时重新考虑**：F055 若在托管预检加入「应用锁定的 SDK 版本 ∈ 平台支持区间」校验（可选增强、归 F055），本条不变、只是暴露更早。
- **[决议-7] 开发者指南的三件套章节与「平台能力接线」包的 SDK 章节同源一份（本 Feature 拥有）；指南的模型 / 应用数据库两章引用 F053 AC-17 交付的同源内容、不另写第二份。** 理由：DEV-03「内外同源、不维护两套」的判据外推——指南（面向人）与技能包（面向 agent）教的是同一件事，两份必漂移；F053 已拥有两条标准库接法与包结构，F057 只补 SDK 章，各写各的、互相引用，无重复拥有。备选 = 指南独立成文：短期省事、长期漂移，否决。**何时重新考虑**：无。
- **[决议-8] SDK 只读注入、不验签：不试图鉴别注入头真伪、不持有验签密钥材料、不做本地权限判定。** 理由：伪造头无效的保证在入口拓扑——线上应用容器仅经 app-proxy 可达（F054 AC-33）且 app-proxy 剥离伪造头（AC-32），本地迷你代理是唯一入口且剥离（F053 AC-23 / AC-25）；SDK 若验签就要把验签密钥发进应用容器，新增一类凭据分发面与泄漏面（INV-28 之外的新面），且验签失败与「无注入」在应用侧无区别，收益为零；权限判定只在服务端门面（F052 / INV-30）。备选 = 签名头 + SDK 验签：属纵深防御，但前提是入口拓扑不可信，与 F054 AC-33 承诺相悖。**何时重新考虑**：运行时形态引入「应用容器可被 app-proxy 之外访问」的部署（本版无此形态、INV-33 双形态一致）。
- **[决议-9] storage 本版 = 四操作最小集（上传 / 下载 / 列举 / 删除，含元信息读取）；不提供绕过应用的下载直链 / 分享链接 / 附件级权限；服务端句柄归 F054、SDK 只消费；不提供清空整个附件空间的操作。** 理由：DEV-07 表 storage 的三条理由（按应用收窄、不计配额、不暴露底层实现）都指向「平台中介、最小面」；直链会把对象存储的可达性与签名机制暴露给用户侧（Discovery 已指出 sharepoint / 匿名读策略的既有泄漏面），且附件级权限本版无需求；清空操作没有业务场景、误用即毁数据（INV-35「资产删除唯经显式删除」同向）。**何时重新考虑**：PRD-2 数据面「附件字段」或大文件场景需要短时下载句柄时，由 F054 定义句柄形态、SDK 再暴露。（句柄形态已由 F054 AC-45 定义：四操作、按应用隔离、越界拒绝、单文件上限。）
- **[决议-10] SDK 公开面恰为三模块，准入门槛「平台特有 ∧ 写错了会出安全事故」写进指南与 design 并作为 spec 评审项；公开面清单可自动化校验。** 理由：PRD-1 DEV-07 规则明令「不得按惯性加回」并要求「实施时若要新增模块，须先证明它同时满足两条」；把门槛写进可校验的清单比写进备忘录更能防「顺手包一层」。**何时重新考虑**：无（门槛本身不变，过门槛的新模块另起 AC）。
- **[决议-11] auth 暴露的身份含「主体类型」（自然人 / 服务账号）字段，来源为 F054 AC-31 / F053 AC-23 注入的同一结构，SDK 不自行推断。** 理由：DEV-05 要求 `dev` 输出明示注入身份来源避免开发者误以为在以他人身份运行（F053 AC-24），应用侧同样需要一个可判定的信号来区分本地与线上（例如在页面角标显示「本地开发 · 服务账号」）；若 SDK 靠「主部门为空」推断会与「无部门的自然人」混淆。备选 = SDK 不带该字段、由应用自行比对环境变量：又是一处静默的本地 / 线上分叉，否决。
