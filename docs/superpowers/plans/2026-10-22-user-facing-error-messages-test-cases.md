# 错误处理：统一验收清单

适用分支：`feat/3.0.0`，合并提交 `46a62373b`。合并本次错误提示用例与另一会话「评估 platform 错误传递方式」整理的标签、PDF 用例，重复的网络、超时场景只测一次。共 21 项，**尚未逐条在真实后端执行**；已完成的自动化与浏览器模拟结果见 [验证记录](2026-10-22-user-facing-error-messages-verification.md)。

测试前准备：使用测试环境、管理员账号、可编辑的知识库和测试文件。每次只点击一次提交按钮；记录提示内容/次数、弹窗/输入是否保留、loading 是否结束。切换语言后等待语言资源加载完成再测试。

## 一、可直接操作验收

无需修改后端数据。网络失败可在浏览器开发者工具 Network 中找到本次提交请求，启用 Request blocking，只阻断该请求的路径，再重新操作；测完立即关闭阻断。不要通过清空登录态模拟网络失败，也不要阻断整站请求。

| ID | 页面与场景 | 操作 | 预期 |
| --- | --- | --- | --- |
| U01 | 审批管理：提交网络失败 | 打开新增或编辑弹窗，填写/选择内容，阻断对应提交接口，点击一次提交 | 仅一条网络失败提示；没有 `[object Object]`、URL、堆栈或 JSON；弹窗及内容保留，不提示成功 |
| U02 | 审批管理：失败后恢复 | 接 U01，解除阻断，在原弹窗再次提交 | 恢复正常提交，页面刷新为正确结果；不残留失败 loading，不因上次失败多发一次请求 |
| U03 | 知识库：段落删除失败 | 使用可丢弃的测试段落，阻断删除接口，执行删除 | 一条可读提示；失败后列表回滚或重载为实际数据，段落没有在界面永久消失；按钮可继续操作 |
| U04 | 知识库：段落编辑失败 | 修改测试段落，阻断保存接口，点击保存 | 一条可读提示，不显示成功；编辑内容保留或可恢复，loading 结束；解除阻断后仍可提交 |
| U05 | QA 导入：本地 Excel 校验 | 分别选择空表、缺少 question 或 answer 列的 Excel，再选择一份合格 Excel | 空表/缺列仍有具体校验原因，不退化成通用错误；不合格文件不上传，合格文件可继续原有流程 |
| U06 | client：文件上传网络失败 | 在知识库上传测试文件，只阻断文件上传请求 | 摘要指出失败文件，文案可读，不拼接 Axios/HTTP/URL 等技术串；不误显示上传成功；解除阻断后可重试 |
| U07 | platform/client：切换语言 | 分别切换中文、英文、日文，重做一次网络失败 | 使用当前语言；不显示 `api_errors...` 键、`undefined`、未替换的占位符；每次操作的提示不重复 |
| U08 | 2FA：既有认证提示（入口开放时） | 使用专用测试账号，在原有验证步骤输入错误验证码；再用正确验证码验证 | 错误码仍显示原有本地化提示，正确验证码仍按原流程继续；不要用真实个人账号反复试错。部署未开放入口时记录“不适用”，不能记通过 |
| U09 | client 知识库：搜索标签加载失败 | 进入知识库详情页，在文件列表上方找到搜索框；阻断标签查询请求，进入页面或聚焦搜索框 | 显示一条可读失败提示；搜索框仍可输入，不把加载失败误当成成功的空标签列表 |
| U10 | client 知识库：标签失败后恢复 | 接 U09，解除阻断，再次聚焦搜索框 | 已有标签正常显示，可选择标签搜索；没有上次失败遗留的 loading |
| U11 | client 知识库：快速切换 | 在 Network 开启限速，进入 A 知识库触发标签查询，尚未返回时切到 B；让 A 的旧请求失败，B 请求正常返回 | 不弹 A 的过期错误，不把 A 的标签填到 B；B 的标签正常显示、可搜索。若无法稳定制造顺序，交由 QA 延迟/拦截指定请求，不记通过 |
| U12 | client 知识库：标签编辑失败与重试 | 在测试文件的标签编辑弹窗，依次验证新增标签、删除标签、单文件保存及批量保存：阻断对应请求后操作，再解除阻断重试 | 每项失败仅提示一次，不误显示成功；失败删除的标签仍在，保存失败不关闭弹窗，选择/输入保留、按钮解锁；重试后正常生效。具体业务原因另测 M02，未知错误另测 M01 |
| U13 | client 知识库：PDF 正常预览 | 打开多页 PDF，缩放、跳页，再切换另一份 PDF 和关闭预览 | 页面正常渲染，缩放/跳页可用，不出现失败提示；取消旧渲染不误报错误 |

建议按页面连续测：审批 U01–U02 → 知识库段落 U03–U04 → 导入/上传 U05–U06 → client 标签 U09–U12 → PDF U13 → 三语言 U07 → 2FA U08（如开放）。接口被阻断属于前端失败验证，不能据此证明后端错误分支正确。

## 二、开发/QA 的模拟失败验收

通过测试环境接口 Mock 或本地响应替换模拟，**不修改生产配置、配额或数据库**。需要同时检查响应原文仍可在 Network / 错误证据中取得，但不会进入 toast 或文件失败提示。以下 HTTP 200 响应均表示业务失败，不应显示成功。

| ID | 注入位置与输入 | 预期 |
| --- | --- | --- |
| M01 | 审批提交返回 HTTP 200，`status_code: 49999`，`status_message: {"detail":"PRIVATE_TEST"}`；再把 status_message 分别改为数组及普通技术字符串 | 均使用通用本地化兜底，一次操作只提示一次；不出现 PRIVATE_TEST、对象 JSON 或 `[object Object]`；弹窗不误关闭 |
| M02 | 上传返回已登记业务码 19403，data 为 `{"used_gb":10,"quota_gb":10}`；标签操作另返回已登记业务码 10987 | 上传显示存储配额的具体本地化提示，10/10 参数正确；批量上传保留早停及合并摘要。标签显示对应的具体本地业务原因，不统一抹成“操作失败”；不直接采用后台技术字符串 |
| M03 | 解析失败返回 10019，data.exception 为 `PRIVATE_TEST`；另用 10014 验证未配置模型 | 保留 ASR 初始化/未配置的具体指引，提示中没有 PRIVATE_TEST；文件保持失败状态，不误标为成功 |
| M04 | 文件状态轮询为失败，remark 分别是普通技术串、含 exception 的 JSON、未知错误码对象；对同一文件连续轮询 | platform 显示“解析失败”等本地兜底，client 显示本地兜底；同一轮上传中同一失败文件不重复通知；原始 remark 独立保留，不能复用 `_raw` 重试字段，也不新增全量控制台输出 |
| M05 | 已登记业务码的 data 加入 `defaultValue: "PRIVATE_TEST"`、`lng: "missing"`、`ns: "missing"` | 仍显示当前语言登记的业务文案；后端参数不能覆盖翻译配置或通过兜底透出 PRIVATE_TEST |
| M06 | 两端各人为延迟受测请求直至超时；另验证取消上传/请求 | 超时提示“请求超时，请先确认操作是否完成，再重试”或对应语言，不显示底层异常；主动取消不弹失败提示、不误显示成功；可重新操作。重试前先确认原操作是否已完成，避免重复写入 |
| M07 | client PDF 已成功打开，Mock 页面读取或渲染失败；让多页同时失败 | 显示本地化 PDF 加载失败提示，同一文档只提示一次，不出现原始异常或未处理 Promise 拒绝；当前文档渲染过程中改变缩放后发生的真实失败仍应提示 |
| M08 | 延迟 PDF A 的页面渲染，在切换到 PDF B 或关闭预览后，再让 A 渲染失败；另模拟正常渲染取消 | 不弹旧文件或取消错误，不干扰 B 的内容和正常操作；B 自己的真实失败仍能正常提示 |

M01 响应示例（仅用于 Mock）：

```json
{
  "status_code": 49999,
  "status_message": { "detail": "PRIVATE_TEST" },
  "data": { "exception": "PRIVATE_TEST" }
}
```

M04 只修改文件状态查询响应中的目标测试文件，保留其原 id 和文件名，设置原有失败状态值及 remark；不要把整个查询接口改成请求失败，否则测不到异步解析链路。未知诊断原文不会自动作为提示展示，故后端应通过登记错误码提供业务原因。

M07–M08 需要 QA/开发在 PDF 页面读取或渲染环节注入失败。**把 PDF 下载接口改成 500 只能验证下载失败，不能替代这两项。** 没有注入条件时标记“未测”，不要用截图正常或下载失败替代。
