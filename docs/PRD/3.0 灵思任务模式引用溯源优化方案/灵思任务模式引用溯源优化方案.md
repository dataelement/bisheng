## 0. 结论

任务模式的角标溯源在 3002 真机连续两次 run 落成 0 引用。诊断结论是：**F047 的下游一半是对的，上游一半是结构性失败点。**

保留的部分：私有区字符标记字法、Redis 来源登记簿、`message_citation` 表、`/api/v1/citations/resolve` 接口、导出与下载的剥标逻辑、client 与 platform 两套前端解析器。这些被 22 个测试钉住，换掉没有收益。

要换的部分：模型侧契约。现在要求第三方模型（DeepSeek、Qwen）在 11 万到 15 万字符的上下文里、在 `write_file` 的 JSON 参数中，逐字抄写形如 `knowledgesearch_0a3e7f35:0` 的随机 hash id 并用私有区字符包裹，同时规则埋在系统提示词 37% 处、交付步骤只字不提引用、写文件路径没有任何校验，完成时零引用也只打一条 info 日志。改法是：**来源改由后端编号成短句柄 `[S3]`，模型只写编号；规则搬到系统提示词真末尾并每轮重注入来源表；写盘边界把句柄确定性转回现有的私有区标记，下游零改动；完成时审计「检索到却零引用」并如实呈现给用户。**

这个改法不是新发明。bisheng 日常模式的私有区标记方案借鉴自 OpenAI 的 citation formatting，但 OpenAI 原方案里 source_id 是 `turn0search1` 这种由系统按调用序号和结果序号编出来的短句柄，而且它的模型是训练过的。bisheng 借鉴时保留了信封，把里面换成了随机 hash，又用在没有训练过的模型上。本方案是把丢掉的那一半补回来。

一句诚实声明：本方案的 P0 阶段只改变**可见性**（用户能看到「检索到资料但报告未标注来源」），不改变两次 run 的引用产出。P1 阶段能否让 deepseek-v4-flash 和 deepseek-v4-pro 真正写出引用，是待验证的假设，须在 116 测试环境用 A/B 数据证明，不能从 trace 推出。

## 2. 问题定位

### 2.1 两次真机 run 的证据

| 观察项 | run A（deepseek-v4-flash，svid `fd018ec3…`） | run B（deepseek-v4-pro，svid `0277db9f…`） |
|---|---|---|
| LLM 请求数 | 19（主代理 15、子代理 4） | 10（全部主代理） |
| 呈现给模型的来源 id | 135 个（主 94、子 45） | 70 个 |
| 规则在系统提示词中的位置 | 第 4,819 字符处，占 36.5%；后接 6.9k 英文框架提示 | 同 |
| 规则占整个请求的比例 | 末次请求 0.83% | 末次请求 1.08% |
| 主代理输出标记 | 0 | 0 |
| 子代理输出标记 | 15 个（4 个不同真实 id），出现在回传给主代理的消息里 | 无子代理 |
| 报告写入方式 | 一次 `write_file` 写 md（6,711 字符）加一次写 html | 一次 `write_file` 写 md（6,273 字符） |
| 报告里的来源形态 | `[^1]`…`[^9]` 脚注 18 处，0 处定义；附录 A 按「来源文档 / 站点」编号 9 条 | 文首「评估依据：知识库中《…》」、文末「附注」；正文零 id |
| 完成时持久化 | 0 条，日志 `none referenced in report/answer` | 同 |

订正：此前口头汇报的「主代理曾输出 120 个标记」是把子代理的 15 个标记在 8 次请求里的重复出现算进去了，主代理两次都没有输出过标记。

### 2.2 三个结构性原因

**第一，模型要抄的 id 不透明且不断膨胀。** 每次检索都给同一文档重新生成 uuid，run B 里 10 次请求累计 470 个 id。一个完整标记在 o200k、cl100k、Qwen3、DeepSeek-V3、Kimi-K2 五家 tokenizer 里都是 20 到 21 个 token，其中 14 个是十六进制 hash 的逐字符抄写，私有区字符本身在五家词表里都不是单 token 而是 3 个字节 token。`[3]` 是 3 个 token。

**第二，规则的位置和形态都不利于长上下文。** 规则拼在内核提示词末尾，但 deepagents 随后又追加约 6.9k 字符英文框架提示，规则被压在中段。语言指令为同一个「被埋」问题专门做了尾巴中间件，引用规则没有。规则里 5 条是禁止型（禁脚注、禁编号、禁 URL、禁末尾汇总、禁来源名），文献量化数据表明禁止型约束在多轮工具调用后衰减到三成，要求型约束稳定在九成以上。两个模型退回的形态恰好都是被禁止的形态。同一 flash 模型在子代理里（规则位于提示词 15% 处、上下文不超过 82k）会产标记，在主流程里不产，说明不是模型不会。

**第三，写文件路径没有校验，完成时没有可见性。** 交付步骤 3a 描述 markdown 规范时不提引用；`write_file` 工具描述是 deepagents 默认文案；写盘时唯一的后处理是把转义写法修成真字符；完成时零引用只打 info，`output_result` 不写任何字段，前端无从显示，用户看到的就是「连标记都没有」而系统什么也没说。

### 2.3 与日常模式的差异

日常模式用同一份规则、同一个标记格式却基本可靠，原因有三：上下文短；正文产生在 assistant 消息里而不是工具参数里；落库时若正文无标记会把本轮全部检索来源落库，前端据此仍能显示来源面板。任务模式三者都不具备，且第三条属于兜底，本方案有意不沿用。

## 3. 业界路线对照

| 路线 | 代表 | 做法 | 对 bisheng 的可移植性 |
|---|---|---|---|
| 自家模型训练 + API 解析 | OpenAI Deep Research、Anthropic Citations、Gemini Deep Research | 模型内部输出训练过的标记，API 层解析成结构化字段（字符区间、从原文抽取的 cited_text、字节区间） | 不可移植，DeepSeek、Qwen 没有这份训练 |
| 系统编号表 + 行内短句柄 | Perplexity、LangChain open_deep_research、Manus、MiniMax 社区实现、通义 WebWeaver | 检索结果由系统按顺序编号，模型写 `[3]`，后端按表解析；写作阶段重新注入编号规则与来源表；压缩时强制保留 Sources 段；校验索引不越界 | 可移植，本方案采用 |
| 写作与引用分离 | Anthropic Claude Research 的 CitationAgent | 研究结束后独立一步对着报告和文档定位引用 | 可做但属事后归因，按 D4 不做写回 |

调研中没有任何一个产品让第三方模型在长报告里手抄不透明 hash id。三个值得借鉴的细节：open_deep_research 在子代理压缩阶段就要求每个 URL 分配编号并在结尾列 Sources，明说「后续 LLM 会合并，不要丢来源」；WebWeaver 让写作按章节定向取证据，引用 id 只在小上下文里出现，引用准确率报告 93.4%，高于 OpenAI 75.0% 和 Gemini 78.3%；Perplexity 集成文档要求校验 `[n]` 不越界，越界通常意味着来源不够或被截断。

也要看到编号不是万灵药。Perplexity 引用审计显示 1,826 条数字型引用里 34.7% 打开后找不到对应数据；「Cited but Not Verified」论文显示搜索深度从 2 次工具调用增到 150 次，事实支持率平均掉 42%。所以业界标配还包括写完后的校验环节，对应本方案的 `citation_audit`。出处见附录 E。

## 4. 目标架构

### 4.1 数据流

```
检索工具（知识库 / 联网，主图与子图共用实例）
  │ 生成 registry item（现有）→ 写 Redis 登记簿（现有）
  │ 记录本 run 见过的 key（新，按 svid）
  │ 按 identity 去重分配句柄 S1、S2…（新，会话级句柄表）
  ▼
模型看到的工具结果：<ref>S3</ref> / "ref": "S7"（长 key 不再出现）
  │ 系统提示词真末尾：来源编号短规则（新，独立尾巴中间件）
  │ 每轮临时注入：本轮可用来源编号表（新，awrap_model_call）
  ▼
模型写 output/*.md 与最终回复时句末写 [S3] / [S3][S7]
  │ 写盘边界（write / edit / awrite）与 answer 路径：
  │   [Sn] → 句柄表 → 完整 key → 现有私有区标记（新，确定性转换）
  │   [n]、[^n]、未知句柄：保留原样，只计数（D2）
  │ 写后发现 output/*.md 零句柄且表非空 → 一次 nudge（D3）
  ▼
磁盘 md 与 answer 已是私有区标记 → 现有 _persist_report_citations 零改动
  │ 完成时 citation_audit：sources_seen / cited / unknown_handles / footnotes_without_defs / status
  │ status=uncited → WARNING 日志 + 前端按 citation_audit 渲染一行 i18n 提示
  ▼
前端预览、悬浮卡、分享、历史重载、下载剥标：全部沿用现有链路
```

### 4.2 关键设计点

**句柄表**：Redis HASH `linsight:cite_handles:{session_id}`（hash tag 取 session_id，追问轮沿用同一表），字段 `h:<n>` 存 key、类型、标题、定位；`id:<identity>` 存编号；`next` 存下一个编号；TTL 30 天与登记簿一致。identity 去重：知识库按 `document_id + chunk_index`，网页按规范化 URL。分配用进程内锁加读改写，不写 Lua，依据是会话运行锁保证同一会话同一时刻只有一个 worker 在跑。Redis 异常时返回空映射并告警，工具输出退回原始 key，旧契约仍可用。

**来源计数不从主图快照取**：`_capture_values_snapshot` 只在 `not namespace` 时调用，看不到子代理子图里的检索。run A 子代理见到 45 个 id，主图只收到 4 个。计数必须在工具层做，主图和子图共用同一批工具实例。

**审计的位置**：必须在 `get_final_result_file` 与 `build_fallback_report_file` 之后、组装 `output_result` 之前计算，三条完成路径同改，因为判定要读最终 md；后端不改写 answer，用户可见提示由前端按 `citation_audit` 渲染（D6）。

**交付步骤 3a 的门控**：3a 里补一句引用要求用占位符实现，按 `has_kb or has_web` 解析，与 `_with_citation_rules` 同一门控；否则没有知识库和联网的任务会引用一段不存在的规则。

**尾巴中间件**：新建独立实例，插在语言尾巴之前，主图与 researcher 各一份；语言指令文本一字不动，它自述「仅约束输出语言」，把引用段塞进去与其自身措辞冲突。

**写边界只认三种形态**：`[S3]`、`[S3][S7]`、`[S3, S7]`（含中文顿号逗号）。`[3]`、`[^3]`、`[S3](url)`、代码块内、`[S3]: 标题` 定义行一律不动。未知句柄字面保留并计入 `unknown_handles`。已是私有区标记的文本不含 `[Sn]`，转换幂等。`edit_file` 的 `old_string` 也要先转换，因为磁盘上已是私有区标记而模型记忆里是 `[S3]`。

**kill switch**：`LinsightConf.citation_handles_enabled`，默认开；关掉时工具输出、规则文本、写边界、每轮来源表四处联动回到逐字 id 契约。shipped `config.yaml` 只加注释掉的键，避免老镜像因新顶级键拒启。

## 5. 分阶段计划

### P0 度量、诚实呈现、提示词位置（不超过 2 人天）

只改变可见性，不改变引用契约，目的是拿到 uncited 率基线。

| 改动 | 落点 |
|---|---|
| 按 svid 记录本 run 见过的 key | 新文件 `citation/domain/services/linsight_citation_scope.py`；`base_search` 在写登记簿之后记录；`_LinsightWebCitationWrapper._arun` 同样；scope 由 `task_exec._create_agent` 构造并注入 `create_linsight_agent` |
| 完成时审计 | 新方法 `_audit_report_citations`，三条完成路径在兜底报告生成之后、组 `output_result` 之前调用；写 `output_result.citation_audit`；`status=uncited` 打一行 WARNING；answer 不改 |
| 前端提示 | `ResultSection` 读 `output_result.citation_audit`，`status=uncited` 时在摘要下方渲染一行灰字（三语 i18n，key `com_linsight_citation_uncited`，含 sources_seen 计数）；历史与分享页同一数据通道 |
| 3a 补一句（占位符门控） | 「正文中凡依据检索资料写出的事实、数字、引文，在该句或该段末尾按 Citation Rules 逐字复制来源标识并用引用标记包裹。」 |
| 独立尾巴中间件 | `_CitationTailMiddleware`，文本见附录 C，插在语言尾巴之前，主图与 researcher 各一份 |
| 测试 | `test_citation_scope.py`、`test_citation_audit.py`、`test_citation_tail_middleware.py`；更新 `test_task_exec_report_citations.py` 的 fixture；前端 `ResultSection` 单测覆盖三种 status |

html 或 pptx 是唯一交付物且检索到了资料时也判 `uncited`，不判 `no_sources`。

| 工具输出改写 | `base_search` 把 `<chunk_id>key</chunk_id>` 替换成 `<ref>S3</ref>`，`format_retrieved_chunk` 本身不改；网页结果加 `"ref": "S7"` 并移除 `citation_key`、`itemId` |

### P2 导出烘焙（约 3 人天，需产品确认版式）

导出 docx、pdf、zip 内 md、单文件转换，以及前端「另存为 md」，统一把私有区标记按首现顺序烘成 `[n]` 并在文末追加「参考资料」列表（D7）；句柄表或登记簿过期则退回剥标并在日志标记；html 交付物把 `[Sn]` 转成上标加附录（D5）。同步把 F054 AC-07、AC-12 改为烘焙措辞（D8）。不做 Badge（D6）。

### P3 条件触发

子代理结构化 findings（`response_format`）、离线归因诊断，只在 P1 的 A/B 数据出来之后再议。

## 6. 需求场景矩阵

| 场景 | 推荐方案行为 | 仍未覆盖 |
|---|---|---|
| S1 模型差异 | flash 的编号习惯与 `[Sn]` 同构，预期首写命中；pro 靠短规则、尾部来源表、一次 nudge，仍零则如实显示 uncited；claude 类的转义写法由现有 unescape 处理 | 换句柄能否改变引用产出无 A/B 前数据 |
| S2 交付物类型 | 单文件与多文件 md 在写边界各自转换；docx、pdf 在 P1 剥句柄、P2 烘焙；html 在 P1 保留字面、P2 上标；pptx、xlsx 不处理，audit 标记不可引用格式 | 只有 html 或 pptx 交付物时正文无法渲染角标 |
| S3 子代理与直接检索 | 同一 session 句柄表在工具层分配，天然唯一；交接行改为编号措辞 | 结构化 findings 留 P3 |
| S4 混合来源与追问 | 知识库、网页、临时库同表；追问轮沿用编号；本任务上传的附件不可引用，规则里告知模型 | 上传件同时存在于知识库时可能误报 uncited |

## 8. 明确不做

| 不做 | 理由 |
|---|---|
| 沿用日常模式的 `strip_unregistered_citation_markers`（按文本重叠硬贴 key）和「无标记则全量落库」 | 把「模型没标」伪装成「已溯源」，违反仓库「不用兜底掩盖模型缺陷」的规则 |
| 把 `[^n]` 或附录表自动映射为引用 | 同上，run A 的附录表粒度是文档不是 chunk，映射必错 |
| 二次 LLM 事后归因写回 | D4；精度低于生成时引用 |
| `write_file` 拒写或返回 error | 进入连续失败计数被误诊为「内容过长」，软着陆阶段可能零交付 |
| 在 `wrap_tool_call` 放提示 | deepagents 文件系统中间件的卸载会整体替换工具消息，历史上已因此出过不动点循环 |
| `list_sources` 工具 | 每轮来源表已够，多一个工具增加 schema 长度与轮次 |
| 改 `citation.yaml` 字面、`format_retrieved_chunk`、resolve 接口、`message_citation` 表、两套前端解析器 | 下游契约正确且被测试钉住 |
| 接 Anthropic Citations 或 OpenAI annotations | 多厂商不可移植 |
| 登记本任务上传的附件为来源 | F062 临时知识库另立 |
| 前端复制加剥句柄 | 磁盘 md 无已知句柄；未知句柄留在预览里正是「不掩盖」。另存 md 在 P2 与后端同步烘焙（D7） |

## 附录 B 写边界正则与容错文法

```python
_HANDLE = r"S\d{1,4}"
_GROUP = rf"\[\s*{_HANDLE}(?:\s*[,，、]\s*{_HANDLE})*\s*\]"
_RUN_RE = re.compile(rf"(?<![\w\[])(?:{_GROUP}\s?)+(?!\()")   # 连续多组合并成一组标记
_DEF_LINE_RE = re.compile(rf"^\s*{_GROUP}\s*[:：]", re.M)     # 定义行只计数
```

|---|---|
| `[S3]` | 转换 |

## 附录 D 反驳核验记录

方案初稿经三位独立核验者反驳，三条均被部分推翻，修正已并入正文：

1. **P0 的来源计数钩子点错了。** 初稿把 `sources_seen` 挂在 `_capture_values_snapshot`，它只消费主图顶层 values，子代理的检索看不到；当检索全部委派给子代理且子代理像 run B 那样用自然语言回传时，audit 会判 `no_sources` 而不是 `uncited`，恰好在最需要的场景下继续静默。修正：工具层按 svid 记录（§4.2）。
2. **注记复用了软着陆注记的位置。** 该位置在兜底报告生成之前，注记会被烘进 `报告.md`，且此时还读不到最终 md 无法判定。修正：移到兜底报告之后、组 `output_result` 之前（§4.2）。
3. **3a 补句与尾巴中间件的门控不对。** `_build_linsight_system_prompt` 没有 `has_web` 参数，无条件补句会在无知识库无联网的任务里引用不存在的规则；语言尾巴自述只约束语言，不能塞引用段。修正：占位符按同一门控解析、独立尾巴实例（§4.2）。
4. **对两次 run 的效果声称过头。** run A 的 trace 证明 flash 手里有 15 个可直接复制的短标记仍改写成按文档粒度的脚注加附录，失败点是写文件时的格式选择而不是抄写成本；run B 的 pro 主动选择自然语言来源。修正：P1 改变引用产出定为待 A/B 验证的假设，只认 `[Sn]` 是有意不静默错配（§0、§7）。
