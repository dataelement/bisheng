日期：2026-11-24。基线：`origin/feat/3.1.0-beta2` 的 `50bd1b7eb1`。分支：`codex/beta2-retire-use-20261124`。

## 问题与当前行为

116 的前台产物在打开工作流、助手时发送 `POST /api/v1/permissions/check`、`action=use`。入口仅对 `visible` 做超管特权预检，而深层才将 `use` 转为个人 `visible` 关系，导致具有超管身份、没有个人可见关系的用户被拒绝；授权管理使用其他入口，仍能打开。现场目标 `9ebc90c0fac64c10bcb89b647720948b` 的投影是 CURRENT，这不是投影缺失的 25008 问题。

本轮按用户明确要求完成 F118 已确认的动作退役，进一步停止线上旧协议别名兼容：

- 前台对话预检、应用列表、广场、工具选择、知识检索、DSH、桌面托管应用入口、助手引用、会话续聊与异步工作流均请求 `visible`。
- 列表接口和前端类型不再接受 `use`；移除服务内别名转换和托管应用广场的 use 专用分桶。
- 统一动作校验在 HTTP 与业务授权的身份短路之前执行。`use`、`use_kb` 等退役动作返回 25001；仅支持可见性筛选的列表按参数校验拒绝非法动作。
- 不按删除动作的理由扩大个人可见关系、租户范围、凭据 data_scope 或管理动作。失去 visible 的普通用户仍被拒绝；管理列表依旧要求管理动作。
- 当前 Catalog 如果异常返回退役动作，明确失败，不再静默过滤旧动作。

## 全仓扫描边界

`bisheng` 在线源代码中，剩余的精确退役动作字面值只在以下三处：

1. `permission/migration/f048_model_mapper.py`：解释旧模型输入。
2. `permission/migration/f118_plan.py`：移除旧动作，同时保留原主体、可见范围和其他动作。
3. `core/openfga/authorization_model_f048.py`：拒绝向当前模型重新引入退役动作。

两个前端应用的生产源代码已无 `use` / `use_kb` 动作字面值。新增源码契约检查防止线上调用重新引入退役动作。历史迁移、审计材料和明确验证拒绝旧动作的测试保留原词；CLI 的 `platforms use` 是平台切换命令，与资源权限无关。
