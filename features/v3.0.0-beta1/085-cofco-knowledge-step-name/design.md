# F085 检索步骤显示知识空间名称：设计草案

状态：待确认，未开发。更新：2026-11-05。依据：[spec.md](./spec.md)；核对基线：1111分支 `f9a687415`。

## 1. 怎么改

每条知识检索步骤显示“检索知识空间：制度与流程”或“检索知识库：产品手册”。名称拿不到时显示“检索知识库”，不显示 `search_knowledge_base`。

后端将已确认的目标名称附在现有步骤数据中，一起推送和保存；前端显示名称，刷新历史读取相同快照。复用现有扩展信息和步骤历史，不增加表、列或迁移脚本。这里只设计任务模式的对应步骤。

## 3. 名称从哪里来

执行/恢复时，将当前已用于提示词和工具白名单的同一批知识对象作为候选。在业务服务/适配器中，通过现有权限服务按当前用户、租户和对象真实类型批量确认名称可见，再整理成 `knowledge_id → 已允许公开的类型、显示名` 的映射。组织知识库复用 `batch_check_business_actions` 的knowledge_library/visible规则；空间由知识领域先核验绑定关系，再调用现有可见性入口。不得把知识对象ID当成空间ID直接授权。

名称可见性检查只过滤新展示信息，不扩大或修改现有检索白名单、提示词和检索调用流程。权限校验失败、无上下文或无法核实的候选省略名称，中文兜底；不为此拒绝原有检索。映射跟随本次执行传入步骤转换器，不在每条步骤到来时重新查库，也不在转换器里增加数据库或权限依赖。

图示K节点拟新增 `KnowledgeStepMetadataResolver`，放在 `linsight/domain/services/knowledge_step_metadata.py`，负责组织候选、调用现有权限入口批量核验并构建名称映射。`task_exec.py` 在执行/恢复时使用它；纯 `StreamEventMapper` 只消费映射和真实参数，不查库、不鉴权。该类仅明确本设计的代码落点，当前未实现。

实际参数中的 `knowledge_id` 必须命中这份映射才可以附名称。模型生成的 `knowledge_name`、自由文本调用理由或查询结果正文不作为名称来源。个人知识库只使用通用称呼，前端翻译该称呼。

不把 `knowledge_id` 当成 `knowledge_space.id`：本工具使用既有知识对象ID和类型。空间名称取这批已解析对象的对应展示名，不凭另一张表的同号ID查询。

不改变工具白名单、检索实现和授权流程；不为了显示名称增加跨租户或绕过权限的查名通道。没有可靠名称时使用中文兜底，显示补充失败不应阻断检索。

## 4. 传递与保存

在已有 `ExecStep.extra_info` 中增加可选对象 `knowledge_target`：

| 字段 | 约定 |
|---|---|
| `version` | 1；未知版本忽略，走中文兜底。 |
| `knowledge_id` | 规范化字符串，用于与本次真实参数核对，标题不直接显示。 |
| `kind` | `space/knowledge_base/personal`；未知类型不伪装成空间。 |
| `name` | 可选。已确认且允许公开的名称；personal类型不发送真实名称。 |

按call_id固定每次调用的名称快照。同一轮检索多个不同对象时，各条调用分别命名；当前工具一次只接收一个ID，不新增“传多个空间”的调用能力。

参数尚未拼完整时先不生成目标信息，显示中文通用名。参数完整并且命中映射后，可对同一call_id补充更新；结束帧必须继续携带同一对象。原 `name/params/call_reason/namespace` 及调用标识不改。

转换器的开始、补充和结束分支都保留该对象；步骤保存直接复用原history扩展结构。结束帧替换开始帧时不能丢失快照，补发/恢复同一call_id也不得换成另一个对象的名字。无法恢复已开始调用的可靠快照时使用中文兜底，不生成猜测名称；后续新调用才使用新的执行上下文。

前端在现有 `extraInfo` 里读取目标；缓存比较器只比较本次渲染实际需要的版本、类型、ID和名称值，不能直接比较整个扩展对象的引用，避免每个流事件都触发重绘。两个缓存关口（步骤行及步骤组）使用同一比较规则。

## 5. 页面规则

| 情况 | 标题 |
|---|---|
| 已确认的空间名称 | 检索知识空间：制度与流程 |
| 已确认的知识库名称 | 检索知识库：产品手册 |
| 个人知识库 | 检索个人知识库 |
| 已知类型、名称缺失 | 检索知识空间 / 检索知识库 |
| 旧记录、类型未知或非法数据 | 检索知识库 |

标题使用“检索”这个中性动作，正在执行、完成或失败继续由现有状态反馈表达。不能因为步骤收到end就写成“检索成功”。F084的故障分类放在该步骤原有详情位置，不挤掉目标名称。

保留原组标题和调用次数。例如“检索知识库8次”仍代表8次实际调用，不能按空间名称去重，也不能把调用次数当成检索命中数量。相同ID可重复出现在多行，同名不同ID仍按各自调用处理。

长名称最多两行，展开后完整展示名称、已有查询参数和检索结果；桌面Tooltip只作补充，手机通过点击展开查看。名称按纯文本渲染，不作为HTML或Markdown解析。不增加跳转空间的链接或新操作。

复用现有StepRow/ToolRowLite和已落地Tooltip；只改变目标文案及必要换行。涉及视觉样式变化按项目规范由设计师确认，草案及HTML示例不代表已修改产品设计规范。

新文案使用既有本地化机制，同步zh-Hans/en/ja；真实资源名称保持原文，通用个人知识库和步骤前缀随界面语言切换。

## 6. 历史、分享和性能

本人的已授权会话历史显示当时保存的名称快照，空间后续改名不回改历史。旧历史缺少目标快照时直接中文兜底，不批量回填、不根据今天可用空间列表猜旧目标，也不为每条历史记录发请求补名字。

现有分享/他人只读序列化出口负责裁剪名称；只有既有授权上下文已能证明目标名称可见时才保留，否则省略 `name` 并使用通用中文。个人知识库始终使用通用称呼。不能因为拥有会话访问权就新增读取任意空间名称的权利；原历史参数和结果的可见边界也不扩大。

一轮执行批量完成名称可见性核验并复用一份名称映射，常规每条步骤只做内存查找，不增加每行数据库或权限访问。补充开始帧只在本次目标首次可靠解析时产生一次，不随token重复发送。恢复按现有流程重新装配可用上下文，已有调用沿用快照。

## 7. 决策与已知坑

| 决策 | 原因与重新评估条件 |
|---|---|
| 另附显示信息，保留内部工具名 | 直接改工具名会影响模型调用、工具识别、图标和步骤归类。只有工具接口本身变更才另行迁移。 |
| 候选对象批量核验后复用，不逐行查名 | 现有名单已有名称但不等于已授权，先统一核验再传递；逐行查询会放大开销。若以后候选名单只含ID，再评估统一批量解析。 |
| 新记录保存快照，旧记录中文兜底 | 现有历史可以直接承载扩展数据，额外表与历史回填没有必要。若以后明确要求给所有旧记录补名字，再单独设计。 |

必须留意：已选ID不等于名称可见；开始参数可能为空；结束帧会覆盖开始帧；渲染比较器目前忽略extraInfo；工具已配置中文完成态不等于所有运行态都已本地化；个人知识库已有隐私别名不能被新名称覆盖。

## 8. 与F084一起交付

F085在 `extra_info.knowledge_target` 保存“检索的是谁”，F084在对应步骤/失败项保存 `failure_info` 表达“哪类服务失败”。两者只在同一个call_id上关联，不共用一个泛化的display_name字段，不互相覆盖。检索失败可能来自Embedding模型或Milvus，不能据空间名称判断故障服务。

两项都更新后端和前端，后端先部署、前端后部署；旧版本忽略新字段，新前端对缺失字段中文兜底。无DDL、数据回填或维护脚本，遵循constitution C1—C8；正式契约登记和实施任务在设计确认后推进。

## 9. 验证

覆盖主任务/子任务、同一空间重复8次、不同空间交错、同名对象、开始空参数、补充帧、结束覆盖、恢复与刷新、长名称、个人知识库、非法ID、未知版本以及分享隐藏名称。验证缓存比较器在只更新名称时会刷新，名称不变时不会因新对象引用多余重绘。

中文兜底验证无需后端新数据，真实名称与历史一致性需要新后端接线。三语、移动端完整名称与失败步骤联合验证列入实施验收。当前只有设计文档和HTML示例，没有产品运行验收结论；按约定不默认运行本地前端测试或构建。
