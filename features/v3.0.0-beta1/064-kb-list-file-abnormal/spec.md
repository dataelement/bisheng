# Feature: 文档知识库外层列表展示文件解析异常

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How（决策、数据流、字段、API、Service、前端、文件清单、性能指标）一律不写在这里。**
> How 的唯一真相在 [design.md](./design.md) 与 [tasks.md](./tasks.md)。

**关联 PRD**: 中信保客户文档知识库数量较多，管理者需在外层列表直接确认是否存在解析异常文件
**优先级**: P1
**所属版本**: v3.0.0-beta1
**依赖**: F027（知识库列表游标分页）、F048（visible-first）、F051（行操作懒加载）。无前置未交付 Feature。

> **范围边界**
> - **本次纳入**：
>   - 管理后台文档知识库外层列表展示库级文件解析异常。
>   - 任一有效文件处于解析失败、解析超时或违规时，该库【文件状态】显示红色标签【异常】。
>   - 管理者可筛选仅异常知识库，再进入知识库处理具体文件。
>   - 从异常行进入详情时，内层文件列表预勾选失败 / 超时 / 违规。
> - **本次明确排除**：
>   - 不展示异常文件数，不分状态（失败 / 超时 / 违规）子标签，不出「正常」。
>   - 不改 QA 知识库列表、知识空间列表、工作台选库器。
>   - 不改文件解析管线写状态的逻辑。
>   - 不在知识库表反范式维护汇总字段。
>   - 不为 OpenAPI v2 增加筛选参数（列表行可带只读布尔字段，因共用组装）。
>   - 不新增领域对象、错误码、不变量。

## 1. 用户故事

作为 **文档知识库管理者**，
我希望 **在外层列表直接看到哪些知识库存在解析异常文件，并能只列出这些库**，
以便 **不必逐个进入知识库排查，降低定位成本**。

作为 **文档知识库管理者**，
我希望 **从异常知识库进入后立刻看到异常文件**，
以便 **尽快处理解析失败、超时或违规文件**。

---

## 2. 验收标准

> AC-ID 在本特性内唯一。Small feature，采用 EARS 句型。

- **AC-01** — WHEN 管理者打开文档知识库外层列表, THE SYSTEM SHALL 在每行展示【文件状态】列；WHEN 该库存在任一有效文件处于解析失败、解析超时或违规, THE SYSTEM SHALL 显示红色标签【异常】。
- **AC-02** — WHEN 知识库内没有有效文件处于解析失败、解析超时或违规, THE SYSTEM SHALL 将【文件状态】列留空，不得显示「正常」或其他成功态标签。
- **AC-03** — WHEN 管理者筛选「仅异常」, THE SYSTEM SHALL 只返回存在上述异常有效文件的文档知识库，并保持既有名称搜索与游标分页语义。
- **AC-04** — WHEN 管理者未筛选异常, THE SYSTEM SHALL 保持现有列表集合、排序与游标契约，仅额外携带每行是否异常的只读标记。
- **AC-05** — WHEN 管理者点击带【异常】标签的知识库进入详情, THE SYSTEM SHALL 打开该库文件列表并预筛选解析失败、解析超时与违规文件。
- **AC-06** — THE SYSTEM SHALL 只把 `file_type` 为文件（非文件夹）且未删除的记录计为有效文件；排队中、解析中、重建中不得使该库显示【异常】。
- **AC-07** — THE SYSTEM SHALL 不在 QA 知识库列表展示【文件状态】或提供异常筛选；IF 对 QA 类型请求仅异常筛选, THEN THE SYSTEM SHALL 返回空页。
- **AC-08** — THE SYSTEM SHALL 继续按调用者对文档知识库的既有可见性返回列表，不得因文件异常标记绕过或扩大可见范围。

---

## 3. 边界情况

- 知识库没有任何文件：【文件状态】留空，不会出现在「仅异常」结果中。
- 库内只有文件夹、或只有解析中 / 排队 / 重建中的文件：不标异常。
- 异常文件被删除或重试成功后，下一次列表请求不再标异常。
- 名称搜索与「仅异常」同时使用时，结果必须同时满足两个条件。
- 文档知识库按库级可见；可见即可看到该库异常标记，不按文件级权限再过滤。
