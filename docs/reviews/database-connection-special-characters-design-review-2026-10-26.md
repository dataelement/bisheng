# 数据库密码含特殊字符时的连接问题

目前先不改代码，整理给相关伙伴确认。

## 背景

客户的数据库密码可能包含 `@` 等特殊字符。毕昇应该正确处理，不能要求客户换成简单密码来规避。

## 问题与原因

已用模拟密码复现：密码为 `p@ss` 时，直接拼接连接串会把部分密码当成主机地址，导致解析错误。涉及两处：

- [工作流 SQL 节点](../../src/backend/bisheng/workflow/nodes/agent/agent.py)：直接拼接账号、密码和地址，没有处理特殊字符。
- [主库配置](../../src/backend/bisheng/core/config/settings.py)：密码解密后直接写回连接串，同样可能解析错误。

这是参数解析问题，尚未连接真实数据库验证。并不是所有字段含 `@` 都有问题，例如本次账号含 `@` 的样本解析正常。

## 建议怎么改

统一用 SQLAlchemy 的结构化连接对象，账号、密码、地址分别处理，替代手工拼接和正则替换。

- 工作流分字段填写的密码原样传入，不要求用户手动转义。
- 主库密码按现有规则解密，再作为密码字段设置；保留现有配置格式和加密方式。
- 完整连接串按标准 URL 解析，避免重复编码或解码；不能全局替换 `@`，也不能自动猜测有歧义的连接串。
- 同步转异步只修改驱动字段，避免整串替换误改密码；日志隐藏密码。

## 需要确认

请数据库、部署和工作流伙伴确认：现有配置是否有特殊写法，以及各 SQL 节点支持的地址格式。建议先覆盖主库和工作流 SQL，Redis 另行评估。

验证重点：特殊字符密码、现有加密配置、同步/异步连接、MySQL 和达梦兼容，以及工作流其他数据库的实际连接。

参考：[SQLAlchemy 官方说明](https://docs.sqlalchemy.org/en/20/core/engines.html#escaping-special-characters-such-as-signs-in-passwords)。
