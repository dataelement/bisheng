01一期范围已经收敛

唯一目标：建设客户端模型调用审计。采集边界是模型接口实际接收的全部输入和实际返回的全部输出；不做内容检查、改写或自动处置。D-05 已确认审计故障不使模型调用失败。

一期纳入

  • 请求元数据、状态、耗时和真实用量关联。
  • 模型接口实际接收/返回的完整内容：消息、工具字段、多模态载荷或引用及流式片段。
  • 对话、任务、子任务、修订、分支和客户端重试。
  • 上下文快照、压缩事件及压缩来源关系。
  • 正文加密、作用域内去重、过期清理和查看留痕。
  • 授权查询、正文按需查看和完整性标记；审计侧不自行截断大正文。

一期不纳入

  • 敏感词词库、安全围栏、内容风险判定和策略发布。
  • 基于内容的输入拒绝、流式截断、脱敏、改写、模型替换和自动重试。
  • 图片 OCR、图像语义、音视频和附件全文解析。
  • 未进入模型请求的客户端本地工具、文件、屏幕和网络行为。
  • 全文检索、批量原文导出和自动用户处置。
  • 为未来安全围栏预设组件归属、接口或算法。

安全围栏后续作为独立需求重新确认目标、误判处理、执行位置、可用性语义和验收标准。本期审计表、API 和采集链路不构成未来方案承诺。

02用户价值与使用入口

使用者建议入口核心操作
审计员审计中心 → 客户端模型调用按用户、模型、时间、状态和完整性查询；查看请求和对话关系。
正文审计员请求详情 → 正文独立授权后按需读取输入输出；系统记录查看人、时间、对象和结果。
客户端用户原有聊天界面审计写入与模型调用解耦；审计故障不改变模型调用结果。

必须回答的问题

  • 谁在何时通过哪个登录会话调用了哪个模型？
  • 这次请求属于哪个对话、任务和分支？
  • 实际发送了哪些有序上下文，实际收到了哪些输出？
  • 正文是否待写入、完整、部分、未采集或已过期？
  • 真实用量已记录还是未知？

事实边界

  • 客户端声明对话和压缩关系，服务端不把声明当作事实证明。
  • 审计列表显示最近成功写入进度与已知缺口；进度不证明覆盖完整，无审计行不等于无模型调用。
  • 业务调用明细不能单独证明供应商已经收到请求。
  • 摘要不能替代原文；原文缺失时必须明确显示。
  • 用户放入模型输入的疑似凭证按原文留存，仅正文授权者可见。

04数据、压缩与完整性

PENDING异步写入中，模型调用可能已完成。
COMPLETE预期范围全部持久化。
PARTIAL只保留到最后确认位置。
NOT_CAPTURED仅元数据模式或采集失败。
EXPIRED内容已按保留期清理。

完全无审计行时不能展示伪造的 PARTIAL：按请求编号仅可报告“有业务调用明细，审计待写入或缺失，模型接口进入及供应商接收状态未证实”。超时后有模型接口进入证据才算已知缺口；仅有业务明细是待核实候选缺口。阈值由 D-09 确认。

核心逻辑对象

对象职责
dsh_audit_conversation租户、用户和客户端对话的稳定聚合。
dsh_audit_requestrequest_id、主体、模型、任务/分支、业务状态和完整性。
dsh_audit_content作用域、摘要、加密正文、密钥版本和过期时间。
dsh_audit_content_ref每次请求实际使用的 stage、channel、角色、顺序和正文引用。
dsh_audit_context_event / edge压缩、摘要与来源消息关系，保存缺失、过期和冲突状态。
dsh_audit_content_access正文查看人、目标、时间、结果和理由。

压缩前后

  • R1 保存 A。
  • R2 引用 A，新增 B / C。
  • R3 新增摘要 S / D，并记录 S 声明替换 A / B / C。
  • 旧快照不被摘要覆盖；来源缺失时不补造。

去重与清理

  • 只在同租户、同用户、同对话内复用正文。
  • 无 conversation_id 时仅在单次请求内复用。
  • 摘要命中仍核对编码、长度和解密内容。
  • 只有无有效引用的正文才能删除。

05客户端关联与兼容

服务端通过能力字段 audit_context_versions: [1] 声明支持。新客户端确认能力后才发送可选 audit_context；字段在供应商调用前剥离。旧客户端继续调用并形成请求级记录。

audit_context
  version: 1
  conversation_id: UUID
  context_revision_id: UUID
  run_id / parent_run_id: UUID?
  logical_call_id / branch_id: UUID?
  messages: MessageRef[]
  compaction: CompactionRef?
组合预期行为
旧客户端 → 新服务端保留请求级审计，显示“未关联对话”，不拒绝合法调用。
新客户端 → 新服务端能力协商后上报对话、任务、消息修订和压缩关系。
新客户端 → 旧服务端能力字段缺失则不发送新增字段，不用失败后自动重试模型请求来探测。

audit_context 是 BiSheng 扩展，不是 OpenAI 标准字段。它不能携带 tenant_id、user_id、session_id 或权限身份。

06可靠性、权限与失败语义

D-05 已确认，模型主流程优先：模型请求和流式响应不等待审计存储写入；审计故障不使调用失败。代价是极端情况下可能完全无记录，须尽力告警和事后对账，不能宣称逐条缺口都实时可见。
场景已确认处理口径
请求记录写入失败模型调用继续；增加 begin gap 指标和结构化告警，完全未入库时不可查询。
输出批次写入失败有界异步重试；超过预算后标记 PARTIAL/NOT_CAPTURED，模型输出继续。
流式连接或进程中断只展示持久化确认范围；超时回收 RUNNING，不能补造后续正文。
用量缺失标记未知，不按文本长度估算，也不填成零。
正文密钥不可用元数据可查，正文不可用；不输出密文、不降级保存明文。
访问日志写入失败拒绝本次正文读取，不影响普通元数据查询。

权限（D-06 待确认）

  • 一期不做“查看人—被审计用户”逐人授权。
  • 建议元数据沿 DSH 管理范围：全局超管按所选租户查看，租户管理员仅本租户。
  • 正文独立授权，默认仅全局超管可看；所有正文读取留痕。
  • 既有 DSH 操作审计不是只有超管可看，不能直接套作正文权限。

架构法则

  • Endpoint → Service → Repository → DB。
  • MySQL / DM8 双库兼容。
  • 租户隔离自动注入。
  • 独立正文密钥，不复用 HMAC / License 密钥。
  • 共享持久化为真相，不使用本地文件队列。

07验收与交付

  1. 确认需求。D-03 采集边界与 D-05 故障语义已确认；继续确认 D-01、D-02、D-04、D-06、D-07、D-08、D-09 和目标版本。
  2. 冻结契约。冻结审计模式、关联对象、完整性状态、保留期、权限动作与 D-09 阈值。
  3. 先做存储。完成迁移、完整加密载荷、幂等、清理和 MySQL/DM8 验证，功能保持 OFF。
  4. 接入调用链。用受控供应商核对输入输出，并按 D-05 验证异步写入、队列溢出、取消和用量语义。
  5. 完成查询与权限。交付管理 API、最近成功写入进度和已知缺口、页面、正文访问日志及越权测试。
  6. 分档启用。服务端先发布，从 METADATA 开始，稳定后再决定是否启用 CONTENT。

下列留存类 AC 仅在对应模式开启且审计事实成功持久化时适用；审计延迟或失败按 AC-17、AC-24、AC-25 验收。

AC-06重复正文减少允许作用域内的存储副本，同时保留每次出现、顺序和调用次数。
AC-07压缩请求持久化成功时新增实际发送的摘要与声明来源，不覆盖已留存历史原文。
AC-08多次压缩、消息修订或分支可追溯，并能还原任一完整留存请求的实际上下文。
AC-09压缩来源缺失、未采集或已过期时分别显示，不补造历史内容。
AC-10内容审计开启且持久化完整时，按模型接口实际形态还原完整输入输出，不因大正文自行截断。
AC-11仅元数据模式且写入成功时记录调用事实并标明正文未采集；失败按 AC-17 处理。
AC-12流式输出正常结束且审计写入成功时按接收顺序保存；审计缺失时不得标记完整。
AC-13流式中断且仍有持久化记录时只展示最后确认内容；完全无记录按 AC-17 报缺口。
AC-14图片或附件进入模型接口时留存其实际载荷或引用形式；未发送的客户端本地内容不审计。
AC-15审计记录成功留存时保存业务失败、取消和客户端重试的真实状态；审计故障不自动重试模型。
AC-16审计记录成功留存时关联真实用量；缺失时标记未知，不估算、不改写额度账本。
AC-17审计失败、积压或完全丢失不使模型调用失败、中止或自动重试；不完整记录不能标记完整。
AC-18仅具备元数据权限时，详情、搜索、错误和接口均不得返回正文。
AC-19授权管理员查看本租户其他用户原文应留痕；无正文权限或超出租户范围须拒绝。
AC-20正文到期清理不误删仍被有效请求引用的内容，并展示正文已过期。
AC-21组合时间、用户、模型、状态和完整性过滤时，在授权范围内稳定分页。
AC-22功能关闭或服务端不支持关联字段时，既有客户端和非客户端业务行为保持一致。
AC-23模型调用前校验失败不产生“已调用模型”审计；未发给模型的本地工具结果不审计。
AC-24异步写入时显示最近成功写入进度、积压和已知缺口，进度不证明覆盖完整；有业务调用明细而审计缺失时不能回答“未调用”，超时后区分已知缺口与待核实候选缺口。
AC-25供应商超时或取消时区分本服务发起调用与供应商接收未知；受控供应商对照完整输入输出。
AC-26模型输入中的疑似凭证按原文留存且仅正文授权者可见；传输层凭证不得进入审计或普通日志。
AC-27大正文和队列满载时主流程语义不变，首字和总耗时 P95/P99 不超过 D-09 阈值。
