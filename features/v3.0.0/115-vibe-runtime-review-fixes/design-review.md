## 本轮自审已修正的问题

| 项 | 观察到的问题 | 已落到设计 |
| --- | --- | --- |
| R1 | 把原运行任务的唯一 UserTenant 身份前置直接用到 Web 新建，会破坏部分旧单租户创建行为 | D6、§4.6：同一 user 应用模块提供新建薄入口；关闭多租户固定 1，不要求补成员行；原 runtime 严格合同不变 |
| R2 | 用请求上下文的 actor resolver 查询负责人，可能取到审批阅读者身份 | §4.4 C、§5：负责人使用自身真实事实，明确不得借用请求 actor 缓存或强设超管 |
| R3 | 单纯采用 grant 来源会遗漏失效人员、投影中间态或分页截断，错误产生 owner-only | §4.4 B–C：CURRENT/版本/Catalog 前后复核、目录三态、预算失败显式 unavailable；非支持来源不能静默忽略 |
| R4 | backend 先返回 null 时旧 UI 仍会 `??0` | §4.5、§7.3：先兼容前端识别未知，再升级运行层/后端，整组镜像到位后验收 |
