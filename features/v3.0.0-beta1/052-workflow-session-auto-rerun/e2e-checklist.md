# E2E 验证清单：F052 工作流会话打开时自动重新运行

**状态**：待在包含 F052 构建的专用环境执行
**页面范围**：免登录 `/workspace/chat/flow/:flowId`；需登录 `/workspace/chat/flow/auth/:flowId`
**前置条件**：准备一个可快速正常结束、可失败、可等待输入的在线工作流；至少准备两个已有历史会话；打开浏览器 Network 的 WS Frames 便于核对 `check_status` 与 `init_data` 次数。

## API 自动化

- [ ] 在专用环境设置 `F052_E2E=1` 和 `E2E_API_BASE`，运行：
  `uv run pytest test/e2e/test_e2e_f052_workflow_session_auto_rerun.py -v`
- [ ] 预期：匿名 `/api/v1/env` 返回 `workflow.auto_rerun_on_open`，值严格为 boolean，且 `workflow` 下不泄露其他运行参数。（AC-01、AC-02）

## 统一开关与页面范围

- [ ] 在系统配置中保持 `workflow.auto_rerun_on_open: false`，分别首次进入免登录、需登录页面并切换历史会话；已结束会话只显示既有手动重新运行入口，不发送额外 `init_data`。（AC-01）
- [ ] 改为 `workflow.auto_rerun_on_open: true` 并保存；重新打开两类独立工作流页面，确认统一生效且无需修改工作流配置。（AC-02）
- [ ] 打开独立助手页、应用中心会话和工作流编排调试页；确认行为与修改前一致。（AC-13）

## 已结束会话的首次打开与切换

- [ ] 免登录页面首次打开一个已结束的本地历史会话；确认先发送 `check_status`，收到 `workflow_status_checked/finished` 后只发送一次 `init_data`，并在同一会话产生新一轮结果。（AC-03、AC-09、AC-12）
- [ ] 需登录页面首次打开一个已结束的服务端历史会话；确认同上。（AC-04、AC-09、AC-12）
- [ ] 在免登录本地历史中从会话 A 切到已结束会话 B；确认 B 自动运行一次。（AC-05）
- [ ] 在需登录服务端历史中从会话 A 切到已结束会话 B；确认 B 自动运行一次。（AC-06）
- [ ] 从 A 切到 B 再切回已经结束的 A；确认每次激活最多运行一次，切回后的 A 可作为新激活再次运行。（AC-10）
- [ ] 快速执行 A → B → A，并让 B 的状态结果延迟返回；确认迟到结果不会启动 A 或后台启动 B。（AC-09、AC-10）

## 打开后不持续重试

- [ ] 打开仍在 RUNNING、WAITING 或等待用户输入的会话；确认只恢复状态，不发送 `init_data`。（AC-07）
- [ ] 在当前已打开的会话中分别触发正常完成、执行失败和用户手动终止；每种情况均确认只出现手动重新运行入口，不自动发送 `init_data`。（AC-08）
- [ ] 在当前会话运行中断网后恢复网络；确认连接异常不会触发自动重新运行。（AC-08）
- [ ] 让自动重新运行本身失败；确认不发生第二次自动重试，手动重新运行仍可用。（AC-08、AC-09、AC-12）
- [ ] 创建没有历史的新会话；确认只执行现有首次运行一次，不产生额外运行。（AC-11）

## 回归检查

- [ ] 手动“重新运行”仍会等待后端停止确认，再对原会话发送一次 `init_data`。
- [ ] 删除或关闭正在运行的会话后，不再收到该会话的后台输出；切换会话不会串用其他会话的重启回调。
- [ ] 两类独立页面均正常加载，无新增 console error；配置请求失败时页面仍可使用并按关闭处理。
