# Design 昆联反向调用 Workflow 人工输入与恢复

- **Feature ID**: F123（拟用，合入前复核）
- **Status**: CONFIRMED，4A 的 T001–T012 已实现
- **Mode**: 隔离 Mock；正式环境待验证
- **关联**: [规格](./spec.md)、[F122 固定版本运行设计](../122-kunlian-workflow-invocation/design.md)、[版本契约](../release-contract.md)、[架构约束](../../../docs/constitution.md)。

## 1. 范围与依赖

在 F122 的固定版本运行上增加一次原生文本表单等待。昆联用同一会话轮询、提交并读取终态。实际执行图限「开始 → 文本输入 → 输出 → 结束」，保持 F122 的预置输入和无交互执行路径。Mock 通过隔离 ASGI 应用和独立执行进程验证，正式协议由 EXT-01 至 EXT-04 决定。

现有图引擎使用 `MemorySaver`，暂停前变量由 `GraphState` 保存。旧续跑任务从原进程取 `Workflow` 对象。F122 把调用时提供的输入交给同一个任务继续执行。F123 复用固定图、图引擎、原生表单、会话归属和条件领取，增加保存等待点和独立恢复。见[图引擎](../../../src/backend/bisheng/workflow/graph/graph_engine.py)、[GraphState](../../../src/backend/bisheng/workflow/graph/graph_state.py)、[F122 Worker](../../../src/backend/bisheng/worker/workflow/kunlian_workflow_run.py)及[旧续跑任务](../../../src/backend/bisheng/worker/workflow/tasks.py#L379)。

## 2. 方案选择与跨进程探针

| 决策 | 拟采用 | 依据 |
| --- | --- | --- |
| D-01 恢复材料 | 在输入节点等待点保存版本化 JSON，包含图检查点、毕昇变量和恢复所需的运行上下文。另一 Worker 用原冻结图构造执行器并恢复到同一节点。 | 旧进程内对象无法跨 Worker 使用。只保存图检查点会丢失毕昇变量。重新运行冻结图的前缀会重复执行暂停前节点。 |
| D-02 持久化 | 在 F122 `workflow_kl_run.material` 中扩展版本化交互内容，继续由同一运行行维护等待状态、期限和提交回执。 | 首轮只有一次交互，同一行能原子判定答案、超时和调度。独立检查点库会增加两套状态之间的恢复工作。 |
| D-03 协议与兼容 | F122 候选提交增加显式交互模式，沿用会话轮询，增加一次答案提交入口。 | 显式模式避免把省略输入的 F122 旧调用变成等待。已受理会话仍沿用原接入方、租户和实际用户。 |
| D-04 调度边界 | 首次执行和恢复分别领取。任务携带阶段，恢复任务绑定当前交互标识。已领取的恢复任务失联后由补偿归为失败。 | 旧的首次执行投递不能领取恢复阶段。领取后重跑可能重复执行恢复后的节点，首轮按一次领取和可查询失败处理。 |

设计探针复用了现有 Python 3.11 环境和真实 `Workflow`、`GraphEngine`、节点实现，使用 LangGraph `1.2.10` 和 `langgraph-checkpoint` `4.1.1`。测试替换了用户读取和存储客户端，运行图由已有线性样例缩减得到。临时目录 `/tmp/bisheng-f123-probe.j09EnC` 的 JSON 只在探针进程间传递，产品持久化使用数据库。

## 3. 运行状态和原子边界

| 状态 | 进入条件与后续操作 |
| --- | --- |
| `QUEUED` → `RUNNING` | 沿用 F122 版本受理与首次领取。交互图通过首轮形态校验后冻结，Worker 以当前实际用户运行到预定输入节点。 |
| `RUNNING` → `WAITING_INPUT` | 首次 Worker 持有效领取标识，在执行期限内同一事务保存快照、表单、交互标识和等待截止时间，清除该阶段领取。事务提交后退出任务。 |
| `WAITING_INPUT` → `RESUME_QUEUED` | 当前用户通过授权，答案符合冻结表单，且等待期限内尚未消费该交互。一个事务记录答案、提交回执及恢复排队期限。提交后尽力投递，未被领取的恢复任务可按阶段补投。 |
| `RESUME_QUEUED` → `RESUMING` | Worker 复核连接、实际用户和 Workflow `use`，在恢复排队期限内按状态及交互标识领取。使用新领取标识和独立执行期限，从保存的等待点提交输入。 |
| `SUCCEEDED`／`FAILED` | 只允许当前执行阶段及领取标识写入终态。等待截止前没有答案时进入 `FAILED / INPUT_TIMEOUT`。恢复排队、权限拒绝、恢复数据无效及执行超时分别映射到可区分的安全错误。 |

所有状态变化在原会话行上条件写入。首次领取、失败或完成，以及提交和恢复阶段，都在取得运行行锁后读取时钟，避免争锁前的旧时间绕过截止线。轮询到期后可收敛到同一个超时终态，补偿任务也可收敛无人轮询的会话。已接受的答案按照恢复排队期限处理，等待超时扫描只处理 `WAITING_INPUT`。运行终态及结果沿用 F122 保留期边界，查询在完成授权后再检查保留期限。

已完成、已超时、阶段不匹配及领取标识失效的任务均不能写入结果。初次任务和恢复任务的消息只携带会话、阶段以及恢复所需的交互标识，可信租户放在任务消息头。工作流下线只影响新受理，恢复按原冻结图执行。待恢复任务的权限服务临时不可用时保持待领取，按恢复排队期限重试或进入超时终态。明确撤权、停用或权限目录禁用 `use` 时结束待恢复任务，查询仍遵守当前权限。补偿发现待恢复行缺少有效交互标识时，单独收敛为失败，同批其他会话仍可投递。

## 4. 等待数据与恢复协议

| 数据 | 生命周期 |
| --- | --- |
| 运行模式与冻结图 | 受理时写入交互模式、原发布图及对应表单约束。沿用 F122 会话主键与版本绑定。终态释放冻结图。 |
| 等待快照 | 保存快照格式版本、引擎兼容标识、运行会话、Workflow 版本、图摘要和预期输入节点。图检查点包含图位置和通道状态，毕昇上下文包含变量、恢复所需的记忆配置及节点计数。只接收首轮图支持的有界 JSON 类型。 |
| 表单与答案 | 等待时提供最小的文本字段定义。与原生表单一致，必填项拒绝空白文本。原始答案通过冻结 Schema 校验后存入原会话，与去重事实同事务提交。恢复时才将省略的选填项作为空文本交给节点，避免把字段标签当成答案。表单内部资料、上下文和答案在终态清理。 |
| 提交回执 | 保存交互标识、提交标识摘要、答案摘要及首次受理的最小回执。终态仅保留回执摘要和必要标识以支持重试，保留期届满时一并清理。 |

恢复时重新构造冻结图的 `Workflow`，以当前验证的原用户和可信租户实例化。用当前会话标识作为交互图检查点的线程标识，通过检查点接口恢复等待位置，并把毕昇上下文放回对应节点共享的 `GraphState`。核对原始答案符合冻结表单且摘要与回执一致，并确认下一节点正是快照绑定的输入节点后，将答案交给现有表单输入路径。检查点缺失、格式或引擎不兼容、图摘要、下一节点或答案不匹配时，返回 `RESUME_STATE_INVALID`，保护原会话并进入失败终态。

首轮解码仅支持已验证的检查点结构。出现尚未验证的挂起写入或未知类型时拒绝恢复，扩展前先补相应探针。快照不存运行对象、客户端或凭据，不使用 pickle 或由数据指定的类型加载。运行日志只记录会话、阶段、版本和安全错误分类，沿用 F122 图异常脱敏。正式字节上限、保留时间和引擎升级兼容窗口在 `TODO [F123][EXT-03]` 留待确认。

## 5. 候选 Mock 接口

| 接口 | 候选语义 |
| --- | --- |
| `POST /api/v2/kunlian/workflow-runs` | 沿用 F122，显式传 `mode: "interactive"` 进入等待路径。首轮交互模式的 `input` 省略或传空对象。非空预置输入和交互模式同时出现时拒绝，未指定模式时保持原合同和原请求摘要算法。交互模式进入其请求摘要，同一启动键切换模式按冲突处理。 |
| `GET /api/v2/kunlian/workflow-runs/{session_id}` | 轮询沿用原会话和归属校验。`WAITING_INPUT` 提供 `interaction_id`、文本表单及 `expires_at`。恢复阶段提供当前状态，终态按 F122 返回结果或安全失败分类。 |
| `POST /api/v2/kunlian/workflow-runs/{session_id}/interactions/{interaction_id}/submit` | 请求携带 `Idempotency-Key` 和文本 `input`，键的范围为原会话及该交互。首次受理 `202`，同键同答案重放 `200` 并返回原受理回执。查运行进度和最终结果使用原会话的 GET。 |

未认证返回 `401`，无权查看会话及交互标识不可见统一返回 `404`，依赖临时不可用返回 `503`。内容与表单不符返回 `422`，同键改答案、已消费或等待已超时返回可区分的 `409`。在已授权且仍处于保留期的会话内先检查已受理回执，再判断是否还可提交。请求体不能覆盖实际用户、接入方、租户、版本或恢复材料。

## 6. 模块计划与边界

| 计划落点 | 职责 |
| --- | --- |
| `src/backend/bisheng/workflow/domain/schemas/kunlian_workflow_invocation.py` | 增加显式模式及交互提交合同，复用现有最小图和文本校验。 |
| `src/backend/bisheng/workflow/domain/repositories/kunlian_workflow_run.py` | 持久化、回执、领取、超时竞争和保留期清理。复用现有列和双库 JSON 类型。 |
| `src/backend/bisheng/workflow/application/kunlian_workflow_invocation.py`、`src/backend/bisheng/open_endpoints/api/endpoints/kunlian_workflow_runs.py` | 复用 F122 的授权、会话归属和安全错误。增加隔离候选的轮询视图、提交和补投。 |
| `src/backend/bisheng/workflow/graph/`、`src/backend/bisheng/worker/workflow/kunlian_workflow_run.py` | 提供交互模式专用的等待快照及恢复适配，按阶段分派任务。旧浏览器、开放运行入口和常规 Worker 保持原行为。 |
| `src/backend/test/workflow/` | 使用隔离数据库和独立执行进程验证 Mock HTTP、图执行及故障边界。 |

本设计不增加数据列或新权限动作。对 `material` 的扩展仅用于显式交互运行，读取端和 Worker 必须识别其格式才能启用。正式启用前确认所有相关执行实例支持该格式，回退先关闭新交互受理，再保留支持实例处理已有会话，直到已受理会话终态或按等待期限收敛。遵循 C1 分层、C2 双库、C3 租户作用域、C4 原 `use` 授权、C5 正式错误码登记、C6 凭据保护及 C8 共享存储。当前无前端代码工作，C7 不适用。
