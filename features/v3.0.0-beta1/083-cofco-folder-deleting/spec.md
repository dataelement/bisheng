# F083 知识空间文件夹删除等待反馈

## 范围

第一阶段为中粮定制线的小型前端功能。删除确认后立即关闭弹窗，等待删除接口期间保留文件夹行，在列表、卡片及手机列表显示加载图标与「删除中」。沿用既有权限、删除接口和审批 pending 语义，第一阶段不改后端、迁移或删除性能。

第二阶段（2026-11-05 追加，用户已确认规格）补齐刷新后的状态恢复，涉及后端可查询的删除执行状态；仍不改变删除范围、权限校验及审批规则，不将性能优化或上传批次并发控制混入本次范围。迁移范围由后续设计确认，不预先承诺为空。

## 行为

- 单删、批删中涉及的文件夹分别记录本页状态；独立目录可并发删除，重复操作不重复提交。
- 处理中的目录及其子项暂停打开、上传、新建、覆盖、重命名、移动、删除等操作。行、目录树和移动目标入口统一提示「文件夹正在删除中，请稍后操作。」，保持当前页面，其他目录可用。
- 搜索命中未加载中间祖先的后代时，通过既有目标路径接口校验范围；已打开菜单、移动确认、覆盖和撤回移动在提交前再次校验。
- 直接成功：移除并刷新列表、目录树与额度；审批 pending：结束本地删除状态，保留资源并沿用审批锁及刷新。
- 明确失败：结束删除状态、刷新并提示「删除失败，请刷新后重试。」。
- 超时、断连和无法确定结果的服务端异常：提示「删除请求异常，请刷新列表查看结果。」；成功刷新后针对该目标查询实际路径。成功且包含目标表示此刻存在，恢复可操作；明确 18020 表示不存在，移除并刷新；失败或空结果不解除锁。不会仅凭分页或筛选未出现目标判断已删除，也不扫描父目录。
- 切换空间或目录后，旧删除响应只能更新其原空间状态与刷新事件，不改写新位置列表。刷新中保留处理中行。

## 边界

第一阶段状态由知识页面本地 hook 与 props 维护，不新增 Recoil、Context 或库。状态持续到该页面卸载；整页刷新重新依据服务端列表。第一阶段后端没有删除进行中字段，异常后存在性查询只表示当前快照，不证明原服务器请求已停止。第二阶段已新增基于既有字段的服务端状态能力，验证边界见 verification.md。第二阶段完成后，以下验收条件取代这一刷新限制。

## 第二阶段：跨刷新恢复验收条件（2026-11-05 已确认）

关联需求：本会话 2026-11-05 用户要求修复“删除中刷新后状态丢失，无法判断是否已取消／完成”。

- **AC-01**：删除进入耗时处理阶段前，服务端即能提供对应租户、空间、目录 ID 的执行状态；不能等目录已移除后才有记录。
- **AC-02**：用户刷新、重新进入空间或换标签页后，仍存在且正在删除的目录恢复加载图标及「删除中」，恢复该目录及其后代的操作拦截；其他目录保持可操作。
- **AC-03**：服务端确认删除完成后，页面自动移除目标并刷新列表；数据库已完成删除但外部清理仍在后台进行时，不把目标重新显示为可操作目录。
- **AC-04**：服务端明确失败时，结束「删除中」、刷新并使用既有失败提示；超时、断连或执行进程中断等不能确认结果的情况显示「状态待确认」，继续查询，不把“不存在状态记录”或“目录仍存在”当作删除完成／失败。
- **AC-05**：状态待确认不能永久把目录伪装为仍在执行；必须有服务端过期／失联识别及明确的恢复规则，恢复规则在设计阶段列明。前端不会自动重发 DELETE。
- **AC-06**：以目录 ID 关联状态；旧目录删除后出现的同名新目录不继承旧目录的删除状态。上传与删除的并发根因单独处理。
- **AC-07**：状态查询沿用租户隔离及空间／资源可见权限，不暴露其他租户或无权查看目录的状态。需要审批的请求仍展示既有「待审核」，不直接标记为正在删除。
- **AC-08**：回归覆盖删除前半段刷新、执行成功、失败、客户端断连、服务端进程中断、同名不同 ID、多标签页及子目录入口。无授权不对真实账号／业务数据执行破坏性测试。
