## 发现与修订

| 问题 | 修订后的确定合同 | 设计位置 |
| --- | --- | --- |
| 只重查原违例可能遗漏修复新引入的错误 | 无论 before 是否违规，所有 dirty 闭包都完整核验 after；原生无关探针保留 | §16.5 |
| 只有本地材料 SHA 无法恢复已部分提交的历史 | 首个历史效果前发布安全的共享 HistoryReplayPlan/预期目录/flow 并真实回读，preparing 绑定 descriptor；私有回滚备份独立保留 | §16.4 |
| 当前原生引用状态不等于旧 frozen+1/提交链 | 原 frozen-after 与有证明的 current-state 分别核验；旧 checkpoint 不改，新全量 manifest 绑定两者及变更证据 | §16.9 |
| 维护补充与同计划规则缺少入口 | frozen_resume 路由、不可变内容寻址候选、唯一当前事实匹配和当前 phase CAS；不覆盖旧 flow 或凭文件时间选最新 | §16.4 |
| 独立控制连接失锁不能 fence 已发 FGA | 禁止透明重连，durable attempt/原生意图绑定；SQL token CAS，外部请求未终结不能接管新意图；无证据返回真实阻塞 | §16.7 |
| 锁行首次插入可能在 NOWAIT 前长时间阻塞 | 前置检查后独立短事务 bootstrap/提交，有界唯一冲突处理；dry-run 不插种子 | §16.7 |
| 恢复先查完整原 before 会拒绝自身已提交修复 | 先识别 Run/阶段；未提交 BEFORE、已提交 AFTER、未知批次分别核验 | §16.3、§16.7 |
| 未来实际 ID 不能预先写入目录，原进程内结果也不持久 | 保留原 sql-v1 cursor/fold；独立 sql_results_v1 与业务同事务保存有界 tail，ACK 后共享化，下一批覆盖前持久前驱，末批再签 admission | §16.7 |
