## 拟纳入正式规格的业务结果

| 能力组 | 用户可观察的结果／代表性验收场景 |
|---|---|
| 空间与组织 | 原生空间行为不变；通过毕昇新建个人与部门外部空间。部门批建部分失败可恢复，一个部门只有一个有效库，授权就绪前不可读取。 |
| 模型 | 只可选择目标环境可用模型。摘要、Wiki和标签按已确认的用途继承，VLM独立；必需模型不可用时不显示就绪。包括空库在内禁止原地改Embedding。 |
| 文件和权限 | 内容只在WeKnora管理的存储，毕昇保留权限及必要控制记录。上传可覆盖本批分块；接收与处理分开；失败可逐项恢复。预览、下载、列表及检索分别保持原有动作和范围。 |
| 标签与Wiki | 零模板、零候选也能按库完成一次初始化，首批最多20个候选，每篇最多3个自动标签，回填不覆盖人工标签。Wiki派生内容按空间共享，原文另判文件权限；删除来源后不返回未确认清理的旧内容。 |
| 使用入口 | 日常、任务/子Agent、工作流、助手和开放检索使用同一空间身份和可读范围；受限标签不回退全库，历史引用不误指新版本。业务管理员仅从毕昇操作集成库。 |
| 一致性与兼容 | 丢响应、重复提交、撤权、代次变化、恢复期间不多建库、不越权、不复制原文；上游不能证明正确的可选操作，服务端和界面均不得伪装成功。 |

不纳入首期全量等价承诺：存量Native自动迁移、上传前编辑分块并冻结提交、schema变更与批量值迁移、未经验证的完整目录移动及版本链合并/推荐。各项细分与开放条件按主方案§15.2。不能把空库标签、空间级Wiki、部门批建等必做项降为“可选”来通过验收。

## 组织方式与下一道门禁

建议一份总Feature规格，按用户旅程编号AC，并映射需求ID、首期范围和外部依赖。设计阶段再拆：原生回归与Provider契约、部门建库及恢复、文件与授权、标签与Wiki、多入口检索及引用、部署与验收。WeKnora侧扩展须作为明确交付依赖，不将下载的源码目录等同于可发布的上游产物。

总Feature范围、正式规格与技术设计已先后确认。进入设计后的QA参考用例及开发任务拆解阶段；实施与目标环境验证状态以本Feature的任务记录为准。
