# 科室库绑定的组织管理员范围

- Feature ID: `072-clinic-binding-admin-scope`
- Status: `implemented-local-verified`
- Created: `2026-10-09`
- Source: 用户确认多组织范围合并，班组及以下管理员可选择最近上级科室；同时覆盖下拉、创建及改绑。

## 需求与验收

| Requirement | 行为 | Acceptance | 验证 |
|---|---|---|---|
| REQ-1 | 保留公司、部门、科室管理员的现有授权子树；多个授权取并集并按组织 ID 去重 | AC-1 多个独立及重叠授权同时展示，不包含无关组织 | 现有多组织回归及新增混合授权用例 |
| REQ-2 | 班组及以下管理员沿父链查找最近的有效科室，只补入该科室，不包含兄弟科室 | AC-2 班组及更深层级均可选择最近科室；多个班组归属同一科室仅显示一次 | 参数化下拉契约用例 |
| REQ-3 | 下拉、创建与改绑使用同一候选范围；保留改绑所需知识库编辑权限 | AC-3 最近科室可创建/改绑，兄弟科室或无编辑权限请求被拒绝 | 创建校验及 SQLite/Fake OpenFGA 改绑集成用例 |
| REQ-4 | 当前租户有效组织之外不产生候选；无授权、父链缺失或循环时不得额外扩权；已绑定标记和编辑排除当前库不变 | AC-4 异常父链安全结束，无关科室拒绝，已有绑定逻辑回归通过 | 负向范围用例及现有绑定回归 |

## 边界与风险

- 不修改组织授权事实源、不迁移线上数据、不更改接口或前端选择契约。
- 不修复已绑定科室的并发唯一性问题，不补齐历史默认权限，不扩大普通组织成员资格。
- 系统管理员行为保持；默认查看者仍覆盖绑定科室及其下级。
- 班组管理员可创建归属上级科室的库；创建者仍拥有新库。此影响已向用户说明并确认。
- 代码回退只能恢复后续限制，已创建的库及权限不会自动撤销。
