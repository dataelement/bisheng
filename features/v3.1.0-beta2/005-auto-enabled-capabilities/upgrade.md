# F005 工作台使用方式升级说明

本文给执行升级的人看。F005 改变了工作台配置里工具、技能和知识库在用户端的使用方式。升级不需要执行脚本。只有一个操作要求：升级后先刷新管理端页面，再保存工作台配置（第三节）。

## 一、变更一览

| 对象 | 变更 |
| --- | --- |
| 数据库 | `linsight_skill` 新增 `auto_enabled` 列，由 Alembic 迁移添加。没有数据迁移。 |
| 工作台配置（工具） | 每个工具新增 `auto_enabled`（自动启用）。升级前的配置读出来都是 False，原有的「默认勾选」不变。 |
| 工作台配置（知识库） | 每个知识库的「是否默认勾选」（`default_checked`）换成「展示在输入框」（`show_in_composer`）。配置了的知识库在新会话里一律预先勾选。 |
| 存量知识库配置 | 后端在读取时转换，不改写数据库：升级前勾了「默认勾选」的知识库保留并展示在输入框；没勾的从配置里移除。 |
| 前端 | platform 和 client 都有改动，必须与后端同一批发布。 |

## 二、升级步骤

1. 部署新版本后端，执行 Alembic 迁移，重启 API 进程。
2. 发布 platform 和 client 的新构建。使用了 CDN 或浏览器缓存时，清掉旧的静态资源。
3. 通知租户管理员：如果升级前打开过管理端的工作台配置页，先刷新页面，再保存配置。

## 三、为什么要先刷新管理端

旧版管理端页面只发送 `default_checked`。如果管理员用缓存的旧页面保存配置，后端会把每个知识库都保存为「展示在输入框」。升级前没勾「默认勾选」的知识库就不会被移除，而是保留下来并显示在用户的输入框里（design 坑 13）。

如果已经发生：管理员在新页面里删掉不需要的知识库，重新保存即可。

## 四、升级后验证

| # | 操作 | 预期 |
| --- | --- | --- |
| 1 | 管理员打开「构建 → 工作台」的知识库配置 | 只剩升级前勾了「默认勾选」的知识库，列头为「展示在输入框」，全部勾选。 |
| 2 | 普通用户新建会话 | 输入框里有这些知识库的标签；「+」菜单里它们为已勾选。 |
| 3 | 管理员取消某个知识库的「展示在输入框」并保存；普通用户清掉新会话草稿后新建会话 | 输入框里没有它的标签，「+」菜单里它仍为已勾选，发送后检索范围包含它。 |
