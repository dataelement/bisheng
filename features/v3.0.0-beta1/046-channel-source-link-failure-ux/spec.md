> - **本次明确排除**：

>   - 网页 URL 爬取路径的失败反馈——已有独立的爬取队列 UI，不在本期
>   - 帮助入口的图文/动图教程页——本期仅文字指引浮层

## 1. 用户故事

作为 **频道创建者**，
我希望 **添加公众号信息源失败时能明白问题出在链接识别、知道怎么获取正确链接、并能直接改完重试**，
以便 **不被误导以为系统故障，也不用刷新页面才能重新提交**。

---

## 2. 验收标准

> AC-ID 在本特性内唯一。

| ID | 角色 | 操作 | 预期结果 |
|----|------|------|---------|
| AC-01 | 创建者 | 搜索公众号名称，结果为"系统暂未收录" | 原状态提示下方出现「如何获取公众号链接」帮助入口 |
| AC-02 | 创建者 | 悬停帮助入口 | 显示指引浮层（PRD 指定文案）；鼠标移出入口及浮层区域后自动收起 |
| AC-03 | 创建者 | 提交的公众号文章链接识别失败 | 仅显示中央失败弹窗：标题「公众号文章链接未识别」、说明「暂时无法读取该链接。请确认链接完整、页面可以正常访问。」、主按钮「返回修改」；**不出现顶部红色报错** |
| AC-04 | 创建者 | 点击「返回修改」或弹窗右上角 × | 关闭弹窗返回添加页；输入框保留原链接；页面提示「请检查并修改公众号链接。修改完成后，按回车重新识别。」，不再显示"正在添加中"；「暂不添加」按钮保留；页面同样展示「如何获取公众号链接」帮助入口（PRD 优化目标 1：未收录界面**及关闭失败弹窗后的页面**均提供复制链接引导） |
| AC-05 | 创建者 | 返回后**未修改**链接直接再次回车 | 重新发起识别请求（不再无反应）；识别仍失败则再次显示失败弹窗 |
| AC-06 | 创建者 | 返回后修改链接再回车 | 按新链接正常发起识别；成功路径行为与现状一致 |
| AC-07 | 用户 | 切换界面语言至 en / ja | 本特性新增的全部文案均有对应译文，无中文残留 |

---

## 3. 边界情况

- 识别成功路径（含公众号名称搜索命中、网页 URL 确认爬取）行为不变，无回归。
- 失败弹窗展示期间用户点击遮罩不应产生"正在添加中"残留状态（关闭动作统一收敛，见 design.md §4）。
- 识别请求进行中重复回车不重复发起（防抖语义维持）。
