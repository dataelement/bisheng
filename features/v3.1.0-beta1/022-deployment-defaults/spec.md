# Feature: 默认启用 Vibe App、沙箱和 BS Client

**关联需求**：2026-11-16 用户在本聊天提出的三项部署调整，以及随后确认的 Spec Discovery 范围。
**优先级**：P1
**所属版本**：v3.1.0-beta1
**依赖**：现有应用工场、执行沙箱、DSH 桌面接入；标准 Helm 交付 F009 的既有部署能力。
**状态**：用户确认范围并补充 AC-04，2026-11-17 确认继续，已实现；实际验证边界见 verification.md。

## 1. 用户故事

作为部署人员，我希望默认部署启用 Vibe App、沙箱和桌面接入，并允许 Vibe App 下载基础镜像未预装的依赖，以减少手工开关配置。

作为桌面用户，我希望未预先填写平台部署地址时也能正常使用 DSH 相关功能，包括登录、Chat、会话管理和 Work 工具。

作为维护旧环境的部署人员，我希望使用新的 `bs_client` 配置名称，同时保留已有 `dsh` 配置的兼容性。

## 2. 验收标准

- **AC-01** — WHEN 使用本版本提供的全新默认 Compose 或 Helm 部署方案，THE SYSTEM SHALL 默认启用 Vibe App、执行沙箱和桌面接入，并提供相应运行服务与连接配置。
- **AC-02** — WHEN Vibe App 声明了基础镜像未预装、且在默认依赖源中可取得的第三方依赖，THE SYSTEM SHALL 在在线依赖准备阶段下载这些依赖，使其可供后续安装和应用使用；Python 与 Node 应用均适用。
- **AC-03** — WHERE 部署人员显式配置内部依赖源或离线模式，THE SYSTEM SHALL 遵循该配置；离线缺包或下载失败时明确报告失败，不自动改用其他公网源。
- **AC-04** — WHEN 桌面接入已启用而未配置 `platform_public_url`，THE SYSTEM SHALL 正常提供 DSH 相关功能，包括功能发现、桌面登录授权与令牌换取/续期、Chat 模型调用、个人信息与会话管理、Work 工具/技能访问及 Work MCP 调用；需要平台地址的环节使用当前请求的对外地址，不能因地址留空而拒绝这些功能。
- **AC-05** — WHERE 已配置 `platform_public_url`，THE SYSTEM SHALL 以该配置为准生成登录授权地址，并约束相关浏览器来源及 Work MCP 入口。
- **AC-06** — THE SYSTEM SHALL 使用 `bs_client` 作为新部署配置的顶层名称，并兼容仅含旧顶层 `dsh` 的配置；二者同时存在时，以整个 `bs_client` 配置块为准，不合并旧块中未指定的字段。
- **AC-07** — WHEN 浏览器从与有效平台地址不同的来源提交登录授权或撤销会话请求，THE SYSTEM SHALL 拒绝该操作；缺少浏览器来源、错误内容类型及不合法地址亦不得绕过现有校验。
- **AC-08** — WHEN 部署人员显式关闭相关功能或升级保留已有配置，THE SYSTEM SHALL 保留明确的关闭选择、既有凭据、依赖源和离线策略；新默认值只作用于缺省项。
- **AC-09** — THE SYSTEM SHALL 保留现有身份认证、权限、PKCE、会话隔离、运行时独立身份及应用出站限制；默认开关不替代真实运行准入条件。
- **AC-10** — THE SYSTEM SHALL 提供与新默认值一致的部署说明，区分配置校验、依赖下载验证和真实部署验收，不将源码修改描述成镜像已发布或线上已生效。

## 3. 边界与范围

- 对外地址应支持 HTTP/HTTPS、非默认端口及 IPv6；显式配置的非法地址继续报错。
- `platform_public_url` 为可选覆盖项，不构成开启或使用 DSH 的前置条件；普通用户的权限、账号状态和配额等正常业务约束继续生效。
- 未配置地址时，反向代理须正确传递对外 Host/协议；来自未受信任客户端的转发头不能任意覆盖有效地址。代理信任边界的具体处理写入设计。
- 新旧配置同时存在时，新块即使为空或显式关闭也优先；被忽略的旧块不应使新块受到旧值干扰。
- Vibe App 的下载、安装/编译与正式运行继续遵循既有分阶段出网合同；本需求不授权应用任意访问公网或基础组件网络。
- 默认启用不更改既有宿主隔离和集群网络、存储等运行前提；部署人员应能从说明和错误信息识别未满足的条件。
- 本次仅交付源码、部署文件、说明和验证记录；不发布镜像、不改线上环境，不自动重写已有客户配置。
- 不变更客户端协议标识、API 路径、Redis 键、数据库表或第三方包的版本解析规则；配置顶层名称变更不等于重命名整个 DSH 协议。
