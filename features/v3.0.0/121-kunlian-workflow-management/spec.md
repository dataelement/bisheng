## 1. 目标与范围

昆联用户能从昆联平台发起新建、查询和打开工作流，在毕昇画布完成编辑、保存、发布及下线。毕昇提供已发布版本的登记资料和状态，昆联同步后在工具目录展示对应版本，下线后取消该版本的可选状态。

首轮复用毕昇画布，昆联侧提供新建入口、按当前用户查询的列表和详情入口。昆联可以展示发布及登记状态。创建、草稿编辑、发布与下线由用户在毕昇页面完成。昆联后端直写工作流是后续选项，需先确认确有该交互需求及可信委托契约。发布和下线变更由昆联拉取。

| 角色 | 可完成的业务操作 |
| --- | --- |
| 昆联用户／工作流创建者 | 从昆联打开毕昇新建入口。通过创建权限校验后得到草稿和工作流标识，按毕昇现有规则获得初始所有者权限。 |
| 查看者／编辑者 | 按本人在当前授权租户的权限查询工作流和允许查看的详情。具备编辑权限时在既有画布保存草稿和候选版本。 |
| 发布者／下线操作者 | 按毕昇对应动作权限发布指定版本或下线，查看工作流状态和昆联登记状态。 |
| 昆联同步器 | 在登记授权范围内取得已发布版本的最小工具资料，更新昆联侧登记状态。昆联同步身份只执行同步职责。 |

本期覆盖工作流管理入口、可见性、版本发布和登记同步。授权与撤权沿用毕昇现有入口。反向运行、Session／事件／交互、跨系统执行绑定、全局依赖治理、权限镜像、独立昆联配额和昆联侧重建画布留在对应工作包。两边的生产接口、部署和真实联调待后续完成。

## 2. 用户操作与现有能力复用

下表是当前分支已核对的入口，用于界定复用范围。路径为毕昇既有浏览器接口和页面锚点，双方对外路由、请求响应及服务调用身份在设计阶段确定。

| 环节 | 昆联侧如何操作 | 毕昇已有能力及本期缺口 |
| --- | --- | --- |
| 登录与跳转 | 从昆联打开新建入口或指定工作流详情。已有有效毕昇会话时直接进入，缺会话时走 F118 登录及安全回跳。 | 复用 F118 和 Platform 工作流画布 `/flow/:id/`。补新建落点、已存在流程落点和回跳联动。 |
| 创建 | 用户从昆联点「新建工作流」，进入毕昇创建页提交，成功后进入新草稿。 | `POST /api/v1/workflow/create` 已包含创建资格、毕昇配额、初始版本和所有者授权流程。本期明确重复提交、创建未完整成功和安全回跳的行为。 |
| 查询列表与详情 | 昆联侧显示当前用户有权查看的列表，点开详情或跳到毕昇。支持名称搜索和分页；如提供「我创建的」，它只是一项筛选。 | `GET /api/v1/workflow/list` 支持工作流类型、`action=visible` 和游标。`GET /api/v1/workflow/get_one_flow/{flow_id}` 可复用详情及权限判断。昆联查询须有受信用户身份与租户，外部摘要及操作提示需要单独收敛。 |
| 编辑与保存 | 从昆联打开原流程，在毕昇画布编辑并保存。具备查看但无编辑权限的人只获得允许查看的内容。 | 复用 `GET/POST /api/v1/workflow/versions` 和 `GET/PUT /api/v1/workflow/versions/{version_id}` 的版本能力。`PATCH /api/v1/workflow/update/{flow_id}` 是已有元数据入口，跳过图数据。并发草稿保存的冲突行为需明确。 |
| 发布与下线 | 用户在毕昇选择候选版本发布，或对当前已发布流程下线。昆联可查看结果及登记状态。 | `PATCH /api/v1/workflow/status` 已区分 `publish`、`unpublish` 权限，校验版本归属并进入发布服务。平台节点校验沿用 F119／F120。同步事实要覆盖接入范围内所有能改变发布状态的入口，避免另一个入口下线后漏同步。 |
| 工具登记 | 昆联同步器读取符合登记范围的发布记录，按版本更新工具目录。 | 复用毕昇发布版本和外部资源绑定。补按发布版本提供的工具资料、依赖摘要、上下线状态和同步结果。浏览器列表和详情不能充当同步进度。 |

复用依据见[工作流路由](../../../src/backend/bisheng/api/v1/workflow.py)、[版本与详情服务](../../../src/backend/bisheng/api/services/flow.py)、[发布服务](../../../src/backend/bisheng/api/services/workflow.py)和[Platform 路由](../../../src/frontend/platform/src/routes/index.tsx)。上述复用点为源码核对结果。

## 3. 业务需求

| ID | 需求 |
| --- | --- |
| REQ-01 | 从昆联发起新建或打开指定工作流时，使用 F118 已验证的实际用户和当前有效租户。回跳目标须受约束，链接只携带业务定位信息。无法验证身份、目标或租户时拒绝进入相应操作。 |
| REQ-02 | 创建使用既有毕昇创建资格、配额和所有者规则。创建成功可定位到同一工作流及初始草稿；同一逻辑创建的重复提交不得产生重复对象，创建或初始所有者关联未完整完成时不得显示成功。 |
| REQ-03 | 查询返回当前用户在有效租户范围有权查看的工作流及详情。列表、详情、版本和跳转均由毕昇校验，区分查看、编辑、发布和下线，撤权后旧列表、深链接或直接请求无法继续获得该权限下的访问。 |
| REQ-04 | 用户通过毕昇画布保存草稿和候选版本。保存时检查编辑权，提示并发覆盖冲突；已发布版本的图、输入输出与资源绑定不受后续草稿保存影响。 |
| REQ-05 | 发布必须由有权用户选择归属正确的候选版本，确认图和已配置资源引用有效，形成可识别的已发布版本。校验失败或候选内容变化时，原发布状态保持有效，昆联不得收到新版本可登记的结果。 |
| REQ-06 | 对符合昆联登记范围的已发布版本，毕昇提供足够登记工具的资料，包括工作流及版本标识、名称／用途描述、业务输入输出 Schema、已发布的外部依赖摘要、可用状态及变更顺序。资料与该版本一致，且不含草稿图、凭据、样例业务数据或内部运行记录。资料不足时，昆联不得将其显示为可用工具。 |
| REQ-07 | 毕昇发布状态是权威事实，昆联同步器负责其工具登记。分别呈现毕昇发布状态与昆联登记状态。目录同步须区分待同步、已同步与失败待补偿，并能够在重试、重复、乱序、漏消息或中断后收敛到权威状态。 |
| REQ-08 | 下线复用毕昇动作权限，生效后对应版本不得再被新登记或接受新的生产调用。昆联同步到下线后移出可选工具。延迟的旧发布信息不能恢复已下线版本；当前状态不可确认时不能以旧目录为调用授权。 |
| REQ-09 | 新版本发布后，昆联按毕昇当前发布状态更新可选版本。已登记的版本标识保持独立，历史绑定不能自动改指新版本。正在运行的会话及历史记录遵循原运行合同，本期下线操作不承担在途取消。 |
| REQ-10 | 创建、发布、下线及同步异常应能按工作流、发布版本和操作关联信息定位。业务授权与同步授权分别受限，跨租户、伪造主体和超范围读取或写入均须拒绝。 |

## 4. 发布与下线的同步口径

| 事件 | 毕昇 | 昆联 |
| --- | --- | --- |
| 发布成功 | 先确认本地已发布版本，再提供该版本的登记资料和最新状态。登记失败时，毕昇仍显示实际发布状态，并可定位同步失败。 | 取得并校验登记资料后，将该发布版本登记为可选工具。资料缺失、状态未知或登记未成功时，保持待同步或失败。 |
| 保存草稿 | 只更新草稿，不改变正在登记的发布资料。 | 继续使用已登记发布版本的资料。 |
| 发布新版本 | 提供新版本资料和旧版本不再是当前可选版本的事实。 | 更新当前可选项；已经保存的旧版本绑定仍指向原版本，是否允许旧绑定发起新运行由后续反向调用合同定义。 |
| 下线 | 先关闭新使用，保留可被同步端识别的下线状态与版本定位信息。 | 同步下线状态，取消对应工具版本的可选性。补偿后不得恢复较旧的发布状态。 |
| 同步中断或状态错乱 | 提供权威状态供核对，能够识别同一版本后来发生的发布和下线。 | 从可恢复位置续取或对账。重复处理应收敛为一份登记，旧状态不覆盖新状态。 |

**首轮由昆联拉取。** 昆联同步器在已授权范围内获取初始可登记版本及后续状态变化，并读取对应的版本资料，负责更新昆联工具目录。拉取需要可续取的变化范围、明确的下线记录和全量核对能力。正式路径、顺序标识、时效、确认方式和失败处理见详细设计。

## 5. 验收标准

以下是待验证的预期行为。V-01 为浏览器及管理入口，V-02 为权限与版本集成，V-03 为登记合同与同步故障，V-04 为双方真实联调。Mock 与真实环境证据分别登记。

| ID | Requirements | 可观察验收结果 | Verification |
| --- | --- | --- | --- |
| AC-01 | REQ-01 | WHEN 已登录昆联的 A 打开新建入口或已有流程，THE SYSTEM SHALL 在有效毕昇会话下进入正确页面，缺会话时经 F118 回到原授权目标。 | V-01、V-04 |
| AC-02 | REQ-01、REQ-10 | IF 使用伪造用户、错误租户或非法回跳目标，THEN THE SYSTEM SHALL 拒绝访问目标，无工作流写入，也不在链接或回执中暴露凭据。 | V-01、V-02 |
| AC-03 | REQ-02 | WHEN 有创建资格的 A 提交并重复发送同一逻辑请求，THE SYSTEM SHALL 得到同一个工作流和初始草稿，创建者、租户和初始所有者与可信上下文一致。 | V-02 |
| AC-04 | REQ-02 | IF 无创建资格、超配额或初始所有者关联失败，THEN THE SYSTEM SHALL 返回可区分的未完成结果，昆联不展示为创建成功。 | V-02 |
| AC-05 | REQ-03 | WHEN A 通过毕昇授权 B 查看，THE SYSTEM SHALL 允许 B 在可见列表找到工作流并打开详情。仅查看权限不允许保存、发布或下线。撤权后重新查询、旧链接和直接请求均不能继续访问原受限内容。 | V-01、V-02、V-04 |
| AC-06 | REQ-03、REQ-10 | IF 跨租户读取或登记身份越权请求编辑、发布，THEN THE SYSTEM SHALL 拒绝且不返回目标详情。 | V-02、V-03 |
| AC-07 | REQ-04 | WHEN 编辑者保存草稿并重新打开，THE SYSTEM SHALL 保留已保存内容。若两人基于同一旧草稿修改，后提交的冲突可见，已发布图及登记资料不变。 | V-01、V-02 |
| AC-08 | REQ-05、REQ-06 | WHEN 有发布权的用户发布校验通过的候选版本，THE SYSTEM SHALL 提供该确切版本的发布状态及可登记资料。所配置 Agent 的固定版本或检索资源引用与发布时一致。 | V-02、V-03 |
| AC-09 | REQ-05 | IF 候选版本异属、无发布权限、资源无权或失效、校验与提交之间内容发生变化，THEN THE SYSTEM SHALL 阻止该次发布，不产生该版本可登记的变化。 | V-02、V-03 |
| AC-10 | REQ-06、REQ-07、REQ-10 | WHEN 昆联同步已发布版本，THE SYSTEM SHALL 返回与该版本匹配且符合授权范围的最小登记资料。资料不足或昆联登记失败时显示待处理或失败，能够按关联信息定位，不显示可选成功。 | V-03、V-04 |
| AC-11 | REQ-07、REQ-08 | WHEN 发布和下线变化发生重复、乱序或同步中断，THE SYSTEM SHALL 在补偿后收敛到当前状态。下线版本不得通过新登记或新调用的可用性校验，旧发布变化不能恢复可选性。 | V-03、V-04 |
| AC-12 | REQ-07、REQ-09 | WHEN V2 发布替换 V1，THE SYSTEM SHALL 在昆联更新当前可选项到 V2，原 V1 标识不变。重复同步不产生重复登记，既有 V1 绑定不得静默指向 V2。 | V-03、V-04 |

V-04 按「A 从昆联新建 → A 在毕昇授权 B → B 查到流程 → A 保存并发布 V1 → 昆联可查 V1 的工具登记 → A 下线 → 昆联工具不可选」验收。反向调用入口的端到端执行证据归后续工作包；本期验证可用性判定和下线状态。真实环境未执行。
