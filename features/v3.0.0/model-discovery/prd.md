### 从 API 获取模型并批量配置

**撰写：Jianghan's codex**

#### 功能说明

管理员过去需要逐个填写模型名称和类型。新增模型列表获取能力后，管理员填写连接信息，在弹窗中搜索并勾选模型，将所选模型一次加入配置列表。模型选择和参数编辑在页底统一保存后生效。

适用模型管理中原本可以创建、编辑服务商的管理员。查看、编辑、共享服务商的租户权限沿用原有边界；共享只读服务商继续按原权限展示。

#### 页面与操作流程

1. 管理员进入【模型管理】并新增或编辑服务商，填写服务商名称、API 地址与 API Key。
2. 必填连接信息完整后，系统打开模型选择弹窗并获取模型；管理员也可点击【选择模型】再次打开。API 地址和凭据继续由对应供应商表单校验。
3. 弹窗展示当前凭据可见的模型，提供名称搜索、类型筛选、多选、当前结果全选及已选计数。已配置的名称显示【已添加】，保留其原配置。
4. 管理员确认所选模型后，弹窗关闭，所选项加入页面列表。关闭弹窗会保留本次选择草稿；变更连接信息会清理查询结果和草稿，旧请求结果按旧连接作废。
5. 管理员按需展开模型，编辑名称、类型和参数，最后点击页底【保存】。服务端按既有配置权限、重复名称及模型有效性校验后持久化；失败时展示错误并允许修正后重试。

#### 规则与边界

**模型类型：**统一显示 LLM、Embedding、Rerank、ASR、TTS。系统优先读取供应商能力元数据，再根据已知型号族识别；未知类型由管理员选择。供应商列表里的图像、视频及当前运行适配器待适配的能力保留展示并标明状态。列表结果代表当前凭据可见范围。

**筛选和选择：**搜索仅影响当前展示结果；跨筛选的已选项继续保留；全选仅作用于当前可选结果。重复模型按模型名称去重，已有模型的稳定 ID、参数和引用保留。

**异常与恢复：**鉴权失败、连接失败、超时、返回空列表与格式异常分别展示原因，并提供重新获取或手动添加。供应商未提供列表接口时，管理员使用【手动添加模型】继续配置。

**名称与保存：**手动新增的空模型默认展开。模型名称为必填文本，保存前去除首尾空白，长度 1～100 个字符；空名称、超长名称或重复名称会阻止保存并显示对应提示。类型为单选，范围由现有供应商运行适配决定。切换类型会初始化该类型配置；仅修改名称保留当前参数。TTS 的音色沿用原必填要求。

#### 后端逻辑影响与变化

新增 `POST /api/v1/llm/models/discover`，复用模型管理的管理员鉴权。编辑已有服务商时，服务端确认其访问及编辑权限，合并保存的脱敏凭据后查询供应商。接口返回模型名称、展示名、推断类型和识别依据；凭据留在服务端调用链中。

模型发现只读取供应商列表。创建、更新、模型状态校验、密钥脱敏、租户归属、共享权限、默认模型引用和页底保存继续使用原接口。新增模型在最终保存前属于页面草稿。

#### 旧版本兼容、升级与数据迁移

已有模型和服务商直接进入新配置页，原有手动添加、编辑、删除与保存入口继续可用。模型发现自身沿用存量对象与结构；历史 Token 配置转换见下节。

### 统一模型参数并继承历史配置

**撰写：Jianghan's codex**

#### 功能说明

已添加模型采用紧凑列表，收起时展示名称、类型和配置状态。展开后，模型名称、类型、供应商联网搜索与高级参数入口按统一列宽排列；窄容器自动换行。输出长度统一进入高级参数编辑，管理员在一个入口维护模型参数。

高级参数为选填 JSON 对象，空值表示使用默认参数。初次打开时展示已保存值，示例作为底纹提示。输入非法 JSON、数组或其他非对象内容时显示格式错误并保留编辑内容；修正后可保存。弹窗【保存】更新页面草稿，页底【保存】完成持久化；【取消】保留原值，显式清空并保存恢复高级参数默认值。

联网搜索使用供应商内置搜索，开关按现有供应商范围展示，具体型号需支持该能力；旁边提供用途提示。

#### 每日调用限制

每日调用限制保持服务商级配置。新服务默认关闭，次数默认 1；已有服务回填原 `limit_flag` 和 `limit`。关闭开关保留填写次数，最终保存继续提交原开关和数值字段。

开启后，同一服务商下的模型共用该服务商当日调用计数，以服务运行环境的日期划分。调用检查沿用调用前递增、超过配置次数拒绝的规则。页面布局和 Token 升级继续保留服务商配额字段、当日计数及日期分桶方式。

#### 后端逻辑影响与变化

高级参数继续使用模型 `config.user_kwargs`。LLM 使用 `max_tokens` 表示最大输出长度；Ollama 延续 `num_ctx` 的上下文长度语义。星火适配器返回合并后的高级参数，保证参数进入实际模型客户端。实例运行参数与连接配置保留原有优先级。

#### 旧版本兼容、升级与数据迁移

本期包含一次存量数据转换，适用于已完成目标版本表结构升级、仍保留语言模型 `config.max_tokens` 的环境。新安装直接使用统一参数结构。最早可直接升级的产品版本号由发布负责人在正式发布清单中确认；脚本按目标表结构和旧字段识别转换范围。

| 历史配置 | 升级后结果 |
| --- | --- |
| 有效旧 `max_tokens` 与其他高级参数并存 | 有效旧值写入高级参数并移除旧字段，其他参数保留；冲突时继承旧字段原先更高的生效优先级 |
| Ollama 旧独立 Token 值 | 写入高级 `num_ctx`，延续上下文长度语义 |
| 旧值为 0、空或 null | 保留高级参数中的既有值，清理旧字段 |
| 已使用高级参数且缺少旧字段 | 保持当前配置，重复升级跳过该模型 |
| 高级参数损坏、旧值异常或服务关联失效 | 报告模型标识，整批停止写入，修正后重新预检 |

迁移保持模型及服务商 ID、名称、类型、租户归属、状态、授权关系和默认引用；每日调用限制及其 Redis 计数保留。结构与索引使用目标版本升级结果，业务数据转换通过独立脚本执行。

升级期间暂停模型配置写入并处理完在途模型调用。先完成目标结构升级，在目标后端环境预检、备份并转换，完成后重启 API、Worker 与 Linsight，刷新各进程模型缓存后恢复服务。全部目标模型完成转换、原参数及对象关联核对一致后，升级生效。

迁移默认只读，提供全租户和指定租户范围。正式写入前创建私有备份，整批预检通过后统一提交；异常中断后根据数据库与备份核对结果，再幂等重跑。恢复时只还原备份中的模型配置，并检查配置仍等于升级后的值；升级后编辑产生的冲突要求人工处理，新增模型保留。

前端继续兼容尚未转换的旧字段，打开高级参数时带入原生效值。这条兼容路径覆盖分阶段升级和失败恢复；统一升级脚本承担正式的存量转换。
