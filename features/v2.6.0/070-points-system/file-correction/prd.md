# 知识库文档纠错 · 已确认 PRD

**状态**: 2026-10-13 对话确认后落盘。代码先于本文写入工作区。  
**版本**: v2.6.0  
**归属**: 积分系统 F070。本文放在 `features/v2.6.0/070-points-system/file-correction/`。  
**写模型**: 毕昇知识库、审批和积分账本。门户只改规则 G8 的展示默认值，不自建纠错规则。

## 1. 目标

登录读者发现知识库文档有错误时，可以提交一条文字纠错。文档上传人在消息中心待办里处理。处理只有三个互斥结果：采纳、采纳并更新、拒绝。积分只发给反馈人，记入现有的「我的积分」。

## 2. 谁可以提交

提交人必须是已登录、并且已经能查看该文档的读者。

文档必须属于公共库、部门库、团队库或科室库。科室库在系统里的层级是 `team_ks`。

阅读页按钮文案是「纠错」。库层级看不清时，按钮不出现。服务端仍然拒绝不合规的提交。

## 3. 谁来处理

处理人在提交时冻结为该文档的上传人，对应 `knowledgefile.user_id`。平台管理员不能代批。

下面两种情况在提交时直接拒绝，不产生待办，也不发积分：

- 读者自己就是上传人。
- 没有可用上传人：上传人缺失、账号已删除（`user.delete = 1`）或账号不存在。

## 4. 纠错内容

只有一个必填文本，最多 500 个字符，按 Python `len` 计。不能带附件。

正文只给反馈人和被冻结的上传人看，使用真实姓名，不匿名。采纳不会扩大这篇文档的阅读权限。

同一个人、同一篇文档，同时只能有一条待处理纠错。该条被采纳、拒绝或撤回之后，可以再提交。

## 5. 三个处理结果

点一个结果，这条纠错就结束。

| 动作 | 上传人要做什么 | 文档 | 给反馈人的积分 |
|---|---|---|---|
| 采纳 | 不用写反馈，不用上传文件 | 版本不变 | 1 分 |
| 采纳并更新 | 必须提供一份新文件 | 新文件成为当前主版本，旧文件成为历史版本 | 2 分 |
| 拒绝 | 必须填写原因 | 文件不变 | 0 分 |

没有「纠错反馈」这个动作。

采纳的 1 分：同一反馈人、同一文档、每个上海自然日最多入账 1 次。当天再次采纳，纠错单仍是已采纳，这次是 0 分。下一天可以再入账。

采纳并更新的 2 分：同一反馈人、同一文档、每个自然日不设上限。每一条真正把新版本变成主版本的纠错单都发 2 分。新版本没有成为主版本时，纠错单保持待处理，不发分。

同一天里，1 分的采纳和每一笔 2 分的采纳并更新可以同时入账。拒绝不占用这两个名额。

金额写死为 1 和 2。管理端修改规则 G8「文档纠错被采纳」的分值，不会改变这两笔金额。G8 的每日上限必须是空的，不能用来卡住采纳并更新。

平台超管、规则停用、积分总开关关闭时，沿用现有积分行为：处理动作成功，不发分。

## 6. 审批与文档删除

走现有消息中心的待办和申请。待办标题是「纠错：文档名」。

没有自动超时。待处理时，反馈人可以撤回。

删除文档时，这条文档上仍待处理的纠错取消，不发分。已经发出的积分不追回。

## 7. 明确不做

- 个人库、我的收藏、专家问答、对话点踩
- 平台管理员代为采纳或拒绝
- 上传人在「采纳」时填写回复
- 「纠错反馈」动作
- 给采纳并更新设置每日积分上限
- 按新旧文件的差异大小决定给不给 2 分
- 采纳后把文档开放给更多人
- 第二套积分账户
- 复用积分模块错误码 `182xx`

## 8. 验收标准

| ID | 角色 | 操作 | 预期结果 |
|---|---|---|---|
| AC-01 | 其他读者 | 在公共、部门、团队或科室库打开可看文档并提交说明 | 生成待处理纠错，上传人待办标题为「纠错：文档名」 |
| AC-02 | 上传人本人 | 对自己的文档提交 | 拒绝，码 18402。无纠错单，无待办，无积分 |
| AC-03 | 读者 | 文档没有可用上传人时提交 | 拒绝，码 18403。无纠错单 |
| AC-04 | 读者 | 个人库、收藏，或不能查看的文档 | 库不允许为 18404。不能查看为 18405，且不返回文档正文 |
| AC-05 | 读者 | 说明为空，或超过 500 字 | 18400 或 18401 |
| AC-06 | 读者 | 同一文档已有自己的待处理纠错时再提交 | 18406，待处理仍只有一条 |
| AC-07 | 上传人 | 采纳 | 纠错已采纳，版本不变，反馈人 +1 |
| AC-08 | 上传人 | 同一天对同一人同一文档再次采纳 | 纠错已采纳，这次 +0，当天该文档该人的采纳入账仍是 1 |
| AC-09 | 上传人 | 采纳并更新，新文件已解析且属于同一知识库 | 新文件成为主版本，旧文件不再是主版本，反馈人 +2 |
| AC-10 | 上传人 | 同一天对同一人同一文档再做一次采纳并更新 | 再 +2。与当天的采纳 1 分可以同时存在 |
| AC-11 | 上传人 | 新文件未解析完就采纳并更新 | 18409。纠错仍待处理，版本不变，积分为 0 |
| AC-12 | 上传人 | 拒绝但不填原因 | 拒绝失败，码 18103。纠错仍待处理 |
| AC-13 | 上传人 | 填写原因后拒绝 | 已拒绝，文件不变，积分为 0，不占用采纳名额 |
| AC-14 | 平台管理员 | 代为采纳或拒绝 | 18408。纠错仍待处理 |
| AC-15 | 反馈人 | 待处理时撤回 | 已撤回，可再次提交 |
| AC-16 | 有删除权的人 | 删除仍有待处理纠错的文档 | 待处理纠错取消，不发分；已发积分保留 |
| AC-17 | 外人 | 查看纠错正文 | 18407，不返回正文 |
| AC-18 | 反馈人是平台超管，或 G8 停用，或积分关闭 | 上传人采纳 | 纠错已采纳，不发分 |

## 9. 残留风险

多人可以靠连续提交很小的版本更新刷 2 分。系统不比较新旧文件差了多少。版本历史、解析和存储会增长。这是已接受的风险，用来换反馈人每条真实更新都能得分。
