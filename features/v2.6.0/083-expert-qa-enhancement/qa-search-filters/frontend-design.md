# 专家问答前端页面与组件设计

Status: DESIGN_PREVIEW
Created: 2026-10-14
Related requirements: [requirements.md](./requirements.md)

设计阶段按用户“先设计一下前端页面和相关组件”制作了独立交互页面稿，使用示例数据。当时正式页面与后端查询尚未接入，页面稿的筛选结果不作为服务端实现证据。

后续实施记录：用户已确认该设计并要求接入真实接口，正式组件及后端在本地完成；页面稿保留为历史设计材料，当前状态见 [verification.md](./verification.md)。

## 页面结构

```text
门户导航                                                 56px
紧凑横幅：标题 + 说明                                    100px
┌ 搜问题、回答、专家……             搜索  清空  我要提问 ┐
└ 业务域 ▾  状态 ▾  受邀专家 ▾  提问时间 ▾  更多筛选 ▾ ┘ 106px
业务域 / 我的问答       最新 / 最热 / 未回答      专家榜单
  内容独立滚动            问题内容独立滚动          内容独立滚动
                         固定分页
```

- 沿用深蓝导航、浅蓝背景和白色卡片，内容宽度 1328px 内三栏对齐。
- 横幅去除重复提问按钮，缩短为 100px。搜索筛选区默认两行，控件高度 36–40px，不把五个人员字段展开成常驻第三行。
- 搜索、筛选、排序区、左右标题和分页留在滚动容器之外；仅内容滚动，不使用累加多个 sticky 偏移的方式。
- 已选更多条件以紧凑可移除标签显示在第二行右侧。条件较多时横向滚动，不换行增加高度。
- 下拉、日期和更多筛选使用浮层，展开不挤压问题列表；浮层跟随触发器，限制在视口内。

## 用户交互

| 操作 | 结果 |
|---|---|
| 输入关键词 | 仅修改输入草稿，不立即刷列表；右侧搜索按钮可点 |
| 回车或点击搜索 | 提交关键词，第一页，列表回顶；匹配问题、回答、可展示专家姓名 |
| 点击输入框清除图标 | 清除输入与已生效关键词，保留结构化条件 |
| 更改业务域、状态或受邀专家 | 立即生效，第一页；业务域与左侧同步 |
| 点击提问时间 | 浮层选择起止日；点“应用”后生效；错误区间保留浮层并提示 |
| 点击更多筛选 | 浮层展示部门、岗位、职务、职位族、职位类，顶部说明“按受邀专家筛选，未回答也包含” |
| 修改更多筛选 | 即时生效；同一受邀专家满足全部人员条件；关闭浮层保留选择 |
| 删除单个条件标签 | 只清除该条件，其他条件和关键词保留 |
| 清空 | 清空关键词、所有筛选及个人范围，回到最新、第一页 |
| 点击左侧我提问的/邀请我的 | 作为个人范围叠加，独立于上方状态条件 |
| 切换排序、翻页 | 保留搜索与筛选；排序回第一页，翻页仅切换页码 |
| 没有匹配问题 | 显示“未找到符合条件的问题”、调整建议及清空条件入口 |

搜索草稿和已生效关键词分离：用户输入新文字后选择筛选，筛选仍作用于已提交的关键词；下一次搜索才提交草稿。输入期间不显示伪搜索结果。

当“未回答”排序与“已解决/已回答未解决”筛选冲突时，选择后者将排序恢复“最新”；点击“未回答”排序时清除冲突的状态条件，避免互斥条件造成看似失效的页面。

## 组件设计

| Component | 职责与 Props | 事件 / 状态 |
|---|---|---|
| `ExpertQaSearchFilters` | 组合搜索与筛选两行；传入 `draftKeyword/query/options/loading` | `onSearch/onKeywordClear/onFilterChange/onReset/onAsk`；不自行请求数据 |
| `ExpertQaFilterPicker` | 可搜索的单选下拉；`label/value/options`；受邀专家带部门辅助文本 | `onChange(value)`；只管理展开和选项搜索，外部控制选中值 |
| `ExpertQaDateRangeFilter` | 起止日期和验证；`value` 为已生效日期范围 | 管理局部日期草稿；`onApply` 原子提交、`onClear` 清除 |
| `ExpertQaCareerFilters` | 更多筛选浮层；五个职业/部门条件，已选计数 | `onChange(field,value)`；即时生效，收起不清空 |
| `ExpertQaAppliedFilters` | 更多条件标签，超长省略，完整内容可查看 | `onRemove(field)`；横向滚动，不改变固定区高度 |
| `ExpertQaFilterPopover` | 定位、视口边界、外部点击关闭、Escape 和焦点返回 | 使用 Portal，避免父级 overflow 裁切；一次仅打开一个筛选浮层 |
| `ExpertQAPage` | 正式集成时维护生效查询、排序、分页、请求状态 | 调用现有 API，取消旧请求；筛选组件不拥有第二份生效条件 |

沿用 React、lucide-react 和 CSS Modules，不引入组件库。现有 `FilterSelectDropdown` 可作为样式来源，但其搜索、键盘操作和浮层裁切能力不足，设计为问答专用组件；本轮不修改这个共享组件。

## 查询状态契约

```ts
type ExpertQaQuery = {
  keyword: string;
  domain: string;
  displayStatus: '' | 'unanswered' | 'pending_adopt' | 'solved';
  invitedExpertId: string;
  askedFrom: string;
  askedTo: string;
  departmentId: string;
  major: string;
  position: string;
  jobFamily: string;
  jobCategory: string;
  personalScope: '' | 'mine' | 'invited_me';
};
```

`draftKeyword`、浮层是否展开和日期草稿不进入 API 参数。变更生效条件时，与 `page=1` 在同一状态更新中完成，避免用新条件请求旧页码。正式接入的滚动重置键包含完整生效条件、排序、页码。

## 窄屏与可访问性

- ≤1080px 隐藏榜单，≤820px 隐藏左栏；业务域和个人范围仍可从操作区访问。
- 窄屏横幅 80px，搜索保留按钮，个人范围出现在筛选行；常用筛选与条件标签横向滚动，“更多筛选”固定在该行右侧，始终可见。浮层宽度不超过视口减 24px。
- 所有触发器有标签和展开状态，支持 Tab；下拉支持输入搜索、上下箭头和回车，Escape 关闭并返回触发器焦点。
- 日期错误贴近字段展示，不能只用颜色；清除按钮有具体名称。正文滚动区域可获得键盘焦点。
- 正式加载只在问题列表内显示加载状态，固定控件继续可用；请求失败保留条件并重试。选项接口失败使用重试提示，不能以空选项伪装成功。

## 页面稿与验证

页面稿位于门户仓库 `frontend/designs/expert-qa-search/`。其中页面、搜索控件、浮层和示例查询模型分离，便于审查；正式接入前按上面的 Props 契约整理为生产组件。

已完成页面稿类型、构建及定向 ESLint 检查，并在四种视口验证搜索回车/按钮、业务域同步、更多条件标签删除、同一受邀专家匹配、日期错误、清空、分页、浮层键盘关闭、独立滚动与视口遮挡。结果与正式功能未验证边界见 [verification.md](./verification.md)。
