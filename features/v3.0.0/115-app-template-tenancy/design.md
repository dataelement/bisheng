# F115：工作流与助手模板租户隔离及管理员管理

**关联**：[spec.md](./spec.md) · [tasks.md](./tasks.md)
**版本**：v3.0.0；最后更新：2026-11-02。
**状态**：用户于 2026-11-02 指示“开始开发”，设计已确认；实现与本地回归已完成，部署环境验收待执行。

## 1. 目标与非目标

让工作流、助手模板成为当前租户内的公共可用资产，仅全局管理员或当前租户管理员可维护。保留现有模板接口路径与模板表，补齐助手模板的新增与使用流程。

不增加跨租户共享、模板授权模型、历史数据分发或数据迁移；不修改应用本身的权限体系，不接管任务模式 PPT 模板。

## 2. 关键约束

遵循 [constitution.md](../../../docs/constitution.md) C1–C8 与 [release-contract.md](../release-contract.md)。

- 当前租户以服务器认证及管理视图解析结果为准；全局管理员也只管理所选租户。
- 模板是租户内公共资产，不另建逐模板 Grant；管理员身份走现有权限应用协议，源应用访问仍走现有资源动作授权。
- 工作流报告模板的文档复制依赖模板内容可见性，不能只修列表而漏掉该内部读取入口。
- 模板表已有 tenant_id，无新增字段、索引或迁移；启动预置模板归属不变。
- 保持既有工作流模板使用时清理知识库、工具等资源绑定并采用默认模型的行为；助手模板采用同样的可移植配置语义，见决策 4。

## 3. 方案对比与选定

### 决策 1：模板业务范围采用严格租户过滤

- **备选**：修改全局可见租户集合；在各模板查询手写租户条件；在模板 Repository 使用现有 strict_tenant_filter。
- **选定**：模板 Repository 的完整查询/写入操作包在严格过滤上下文内，每次使用独立会话；不改变全局事件或其他资源的共享策略。
- **原因**：tenant_filter.py 已支持忽略根租户共享可见集合而按当前租户过滤；Template 已注册自动过滤。严格查询覆盖列表、详情、重名检查、排序基准、源应用与报告模板授权依据。
- **重新考虑条件**：未来明确引入独立的模板共享产品能力；当前需求下不得扩大读取范围。

### 决策 2：集中模板业务与身份校验，保留 HTTP 地址

- **备选**：只隐藏按钮；直接在旧 endpoint 追加 ORM 与权限分支；抽出模板 Service/Repository。
- **选定**：保留 api/v1/skillcenter.py 作为薄接口层，新增 app_template/domain/{schemas,services,repositories}/；Service 编排身份、来源与业务校验，Repository 承担所有模板及源数据 ORM 操作。
- **原因**：旧 endpoint 全部仅校验登录，并混合存取与业务；继续堆逻辑会重复权限判断并违反 C1。模板身份判定使用 permission.application.identity.resolve_permission_actor，允许 super_admin 或当前租户在 tenant_admin_tenant_ids 中；失败不降级为菜单授权。
- **重新考虑条件**：模板引入 owner、独立可见范围或逐模板授权时，再接入资源 Catalog；本次不建新授权模型。

### 决策 3：客户端不能指定模板归属或任意源快照

- **备选**：继续接受继承数据库模型的创建参数；使用只含业务输入的创建 schema。
- **选定**：创建只消费 name、description、flow_type（5/10）、flow_id；旧字段 tenant_id、id、时间、排序及 data 均不参与写入，源快照由服务端读取；归属由自动注入填写。
- **原因**：当前 TemplateCreate 继承包含 tenant_id 的 TemplateBase；自动填充对显式错误租户只告警，不覆盖。仅调用 strict_tenant_filter 无法修复伪造创建归属和任意快照绕过来源校验的问题。
- **重新考虑条件**：将来新增受控导入模板功能时另设明确的导入契约，不能复用本创建入口透传任意字段。

### 决策 4：助手模板保留可移植设置，使用现有助手创建与保存流程

- **备选**：直接复制助手整行及全部资源绑定；仅存名称描述；保存可移植配置快照。
- **选定**：服务端按助手类型读取真实 Assistant，存储 prompt、desc、guide_word、guide_question、temperature、max_token、knowledge_auth 等可编辑配置白名单；不存身份、状态、派生系统提示词、时间或权限标记。实例化时使用当前租户默认助手模型，知识库、工具与关联应用绑定置空，用户可在新助手中配置。
- **原因**：现有助手卡片排除了模板入口；旧创建接口只从 Flow 读 data；CreateApp 的模板分支只处理工作流。复制整行会带入身份及过期资源引用；只存名称不能复用助手配置。工作流模板已有默认模型替换及资源绑定清理行为，助手沿用相同语义。
- **实现边界**：模板新增只发送源应用标识，由后端保存白名单快照。使用助手模板时前端先创建空提示词的助手，再通过已有保存接口写入快照，避免 create 的 prompt 1000 字限制截断长提示词；保存前取新助手返回的默认模型，保留用户填写的新名称、描述。仅全部成功才关闭并跳转；第二步失败显示错误、记录已创建助手 ID，重试复用该草稿，不能重复创建或假报成功。整个流程沿用现有配额、创建授权与资源投影。助手创建端点已移除 JWT 租户显式赋值，交由当前操作租户自动注入，确保超管切租户后创建到所选租户。
- **重新考虑条件**：需要模板绑定资源或要求创建与配置跨接口原子性时，再扩展独立的后端实例化能力；本次不重构应用生命周期。

## 4. 改造前事实与当前实现

### 4.1 改造前已核查代码（用于理解改造原因）

- api/v1/skillcenter.py：列表、详情、新增、修改和删除均只有登录依赖；新增未区分源应用类型。
- database/models/template.py：已有 tenant_id；TemplateCreate 继承数据库基础模型。core/database/tenant_filter.py 已显式导入 Template，提供严格租户过滤和创建自动填充。
- common/middleware/admin_scope.py：模板路径尚未纳入管理视图前缀和写请求范围校验；直接套严格过滤仍无法正确响应全局管理员的租户切换。
- platform/pages/BuildPage/apps.tsx：管理入口跟随 create_app；cardComponent/index.tsx 的添加模板要求 edit、isAdmin 且不是 assistant；appTemps.tsx 的删除排序未判断管理员身份。
- platform/pages/BuildPage/CreateApp.tsx：选择模板固定按 flow 请求，模板创建分支未处理 assistant。
- api/services/report_template.py：ais_app_template_asset 扫描 Template.data 作为报告文档复制的补充授权依据；必须同步收紧，避免隐藏列表后仍由别租户模板授权复制。
- database/data/template.json：本地解析验证，预置 10 个工作流模板和 21 个旧技能模板，没有助手模板；不将旧技能转换为助手模板。

### 4.2 当前实现数据流

读：登录身份 → 管理视图解析 → 模板 Service 验证当前租户有效 → Repository 严格过滤 → 现有成功响应。

写：同上 → Service 校验管理员身份 → Repository 严格加载目标/来源 → 校验源应用 visible 动作及所属租户 → 保存快照或更新/删除 → 返回结果。其他租户的来源即使作为共享应用可读，也不得成为本租户模板来源。

从模板创建：前端读取当前类型的本租户模板 → 工作流保持现有模型替换/资源清理/报告复制流程；助手按决策 4 创建并保存 → 成功后进入编辑页。

### 4.3 职责与字段

| 文件/结构 | 职责 | 边界 |
|---|---|---|
| api/v1/skillcenter.py | 参数与登录依赖、调用模板 Service、响应 | 不直接查询 ORM，不作跨租户兜底 |
| app_template/domain/schemas/template.py | 创建/修改/读取的业务 schema | 不继承数据库写入字段 |
| app_template/domain/services/template_service.py | 当前租户、管理员、来源与白名单快照编排 | 不写 ORM，不直接使用 OpenFGA |
| app_template/domain/repositories/template_repository.py | 严格会话下的模板及来源读写、同租户重名与排序 | 不判断用户角色，不扩大租户范围 |
| app_template/domain/services/template_service.py 的报告资产检查入口 | 查询当前租户模板快照是否含指定报告 key | 仅供现有报告文档复制授权 fallback，不授予源工作流编辑权 |
| platform/pages/BuildPage/templatePermissions.ts | canManageAppTemplates，基于已认证 is_global_super / admin / is_child_admin | 不以 create_app 或部门管理员作为管理资格 |
| flow_type | 5=助手，10=工作流 | 新增与页面只支持这两类；旧技能数据保留原样 |
| flow_id | 对应类型的源应用 ID | 名称维持兼容，不能拿助手 ID 查询 Flow |
| data | 工作流为既有 DAG，助手为白名单配置对象 | 内部结构按 flow_type 分支，不携带源身份 |

前端 apps、卡片、模板管理页共用管理员判断；卡片新增独立 canAddTemplate 能力，保留 isAdmin 对其他动作的含义，避免把租户管理员伪装成全局管理员。模板管理路由沿用已有 create_app 导航能力，但页面在加载前增加管理员门禁；已有路由解析为租户管理员补齐 create_app。普通用户仍可在应用创建的模板选择器中读取模板。

前端创建弹窗按模板类型读取，未完成详情加载时禁用创建；切换租户时清空列表/选择器/弹窗草稿并忽略旧响应。AppTempSheet 每次打开重新读取模板，避免新增后仍显示旧列表。新增弹窗校验失败立即返回、提交中禁止重复请求。助手 API 类型在客户端边界校正为实际返回的 UUID 标识及可编辑字段。

## 5. 已知坑与处理位置

| 事实 | 不处理的后果 | 处理位置 |
|---|---|---|
| strict_tenant_filter 不覆盖显式 bypass；自动填充也不修正伪造 tenant_id | 看似加了过滤仍可写到其他租户 | Repository 不使用 bypass、创建 schema 不接收归属字段；测试真实自动过滤事件 |
| 管理视图只有命中管理路径才改变当前租户 | 超管切换后读写仍落在原租户 | admin_scope.py 增加 /api/v1/skill/template；同步前端 managementScope.ts 的写路径及现有 X-Management-Tenant 校验 |
| 读取 ID 的旧返回值是列表，找不到时可能为 [null] | 改成对象会破坏模板选择器；返回空对象会触发前端空指针 | 成功继续返回 [template]；不存在及其他租户统一拒绝，并由调用方捕获失败 |
| 报告模板 fallback 直接扫描模板快照 | 根租户模板仍可能成为子租户报告文档复制凭据 | report_template.py 改调模板 Service 的严格读取入口，不改变有合法源应用授权的既有路径 |
| 卡片的 isAdmin 同时参与其他菜单逻辑 | 为支持租户管理员而修改此值，会误开放其他超管菜单 | 添加独立模板能力参数，现有 isAdmin 不变 |
| 模板快照是复用配置，原应用删除后仍可使用 | 每次使用时回查源应用会让模板意外失效 | 源权限只在新增时校验，使用时读取已授权的本租户快照 |
| 前端模板对象会被工作流初始化逻辑原地修改 | 再次使用时共享对象可能含旧配置 | 使用前深拷贝快照，租户切换清空选中模板、列表及助手创建草稿 |
| 旧助手创建端点显式写 login_user.tenant_id；管理视图不会修改 JWT 身份 | 超管切租户用助手模板时仍向根租户创建助手 | api/v1/assistant.py 移除该显式赋值；真实自动填充测试验证根 JWT + 子租户 scope 持久化归属为子租户 |
| 预置工作流模板 360/374/376 的历史描述超过新增表单的 200 字限制（225/227/217） | 排序请求带上完整历史描述会被新输入校验拒绝 | appTemps.tsx 排序仅发送 order_num；listSorting 加长描述回归，不重写历史元数据 |

## 6. 对外契约与依赖

### 6.1 提供的契约

| 契约 | 保留/变更 | 消费方 |
|---|---|---|
| GET /api/v1/skill/template | 地址、列表成功形状和 id 查询成功返回列表保留；严格当前租户 | 模板选择器、管理页 |
| POST /api/v1/skill/template/create | 地址保留；flow_type=5/10、flow_id 必填；服务端读取来源，禁止透传快照/归属 | CreateTemp |
| POST /api/v1/skill/template/{id} | 元数据写入仅消费 name、description、order_num、guide_word；忽略归属、类型、来源及快照字段；仅管理员可写，重名限定当前租户；排序只传 order_num | 修改与排序 |
| DELETE /api/v1/skill/template/{id} | 地址保留；仅管理员删除当前租户目标 | 管理页 |
| 模板 Service 的报告资产检查 | 当前租户快照的 key 存在性，不返回其他租户内容 | report_template.ais_app_template_asset |

沿用 resp_200 成功信封。无权限复用 PermissionDeniedError（19000）；缺租户上下文复用 NoTenantContextError（20004）；同租户重名复用 FlowTemplateNameError（10530）。目标不存在或不属于当前租户均返回既有 NotFoundError（业务 404）；参数类型/来源缺失走参数校验。复用现有错误及三语文案，不申请新错误码。接口调用方一律捕获并展示已有错误对象。

### 6.2 依赖与风险

- 现有管理视图与 X-Management-Tenant：前后端路径规则必须成对更新；旧页面写入与当前视图不一致时按既有 26073 拒绝，不猜测客户端归属。
- 权限应用协议的身份与 visible 判定：不可判定时抛错；普通菜单权限不可作为 fallback。
- 现有工作流/助手创建、配额、权限投影与助手保存：保持调用语义；不直接插入新应用绕开既有生命周期。
- SQLAlchemy 租户事件与 MySQL/DM8：只用既有 ORM、JsonType；本次不新增依赖或系统二进制。
- MinIO 报告文档复制：保留既有所有权与复制规则，只收紧“当前租户模板资产”的授权依据。
- 初始化器与历史数据：不改写、不复制既有记录；根租户模板从子租户页面消失是预期行为。

## 7. 测试与可观测

后端使用真实 SQLAlchemy 租户事件和隔离测试库验证根租户及两个子租户的列表、详情、同名、排序、新增归属、伪造字段、来源权限、删除、助手快照与报告 key；测试权限应用端口的允许/拒绝/异常，不能仅 mock Repository 宣称租户隔离通过。配合 API 端到端测试验证普通用户、租户管理员、全局管理员及过期管理范围请求。

前端 Vitest 验证管理员能力矩阵、两个模板类型的卡片入口、普通用户的管理页拒绝、列表切租户清空、助手快照创建/保存及失败重试；回归现有排序、托管应用卡片与路由测试。执行 lint、typecheck、arch-guard 与 /e2e-test；MySQL/DM8 实机验证归中央回归，缺少环境须明确记录，不能用 mock 替代已交付证据。

手动验证：在 /build/apps 使用根租户超管、子租户 A 管理员、A 普通用户（含 create_app）及 B 管理员；打开 /build/temps/flow 和 /build/temps/assistant，验证 A 无根/B 模板、普通用户无管理入口、两个类型可新增/使用；超管切换 B 后仅见 B，旧标签页写 A 不能误落 B。新增同名模板分别在 A/B 成功；A 普通用户直接请求删除被拒绝。报告模板验证使用同租户模板可复制，其他租户模板不能提供 fallback 授权。

不引入独立指标系统；请求失败沿用现有错误响应、访问日志与管理范围冲突响应。测试结果和未完成的实机验证写入 tasks.md。

## 8. 后续与已知限制

模板不包含跨租户共享、迁移或资源绑定自动授权；助手绑定资源需在新实例配置，避免模板携带资源权限。助手实例化复用两次既有请求，第二次失败可能留下用户可见草稿，按决策 4 保留 ID 并允许重试；若未来要求原子创建，再单独扩展后端契约。
