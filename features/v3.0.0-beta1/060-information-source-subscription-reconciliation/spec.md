# Feature: 信息源订阅对账、公共文章同步与知识空间一次投递

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> 本文档只定义信息源订阅、文章同步和知识空间投递的业务目标、保证边界与验收标准。
> 实现决策、数据流、字段、任务、锁、文件清单与运维步骤由后续 `design.md` / `tasks.md` 维护。

**关联需求**: [毕昇侧信息源订阅对账与新增文章同步轻量改造方案](../../../docs/architecture/proposals/2026-08-20-information-source-subscription-reconciliation.md)
**优先级**: P1
**所属版本**: v3.0.0-beta1
**依赖**: v2.6.0 F031、Information 同步查询协议 v1.1、既有频道知识同步能力

> **Spec Discovery 已确认**：
> - 一个部署环境只配置一个 Information API Key；多个部署共享同一 Key 不受支持；
> - 订阅状态采用周期最终一致，不要求频道变更后同步强一致；
> - 自动取消远端多余订阅稳态默认开启，灰度环境可显式关闭；
> - 公共文章首次同步默认 20 篇，并允许通过系统配置调整；
> - 上游文章接口按 `min_create_time >=` 返回包含边界数据，文章 ID 可用于本地幂等写入；
> - 知识空间只对本轮新增文章尝试投递一次，失败即终态，不自动重试或补偿。

> **范围边界**
> - **本次纳入**：
>   - 汇总全部活跃租户频道的信息源需求，与当前 API Key 的远端实际订阅周期对齐；
>   - 以远端当天同步完成状态为门禁，周期拉取并幂等保存公共文章；
>   - 首次同步文章数量支持系统配置，默认 20；
>   - 将本轮首次同步成功的新增文章按频道与子频道规则向知识空间异步投递一次；
>   - 为订阅、文章和知识投递链路提供必要的日志、指标、开关与失败边界。
> - **本次明确排除**：
>   - 不支持多个 API Key、租户级 API Key 或多个部署共享同一 API Key；
>   - 不保证文章标题、正文后续更新、撤稿和删除同步；
>   - 不把知识空间视为频道文章镜像，不扫描或比较知识空间中的已有文件；
>   - 不为知识投递增加持久 delivery、outbox、稳定投递标识、配置游标或自动重试；
>   - 不自动回补知识配置创建前的历史文章，不恢复用户主动删除的频道文件；
>   - 不新增管理端同步状态页面或新的对外 HTTP API。

---

## 1. 用户故事

### 1.1 频道管理者

作为频道管理者，
我希望频道引用的信息源能够在可接受的周期内自动收敛为远端订阅，
以便不依赖人工维护订阅状态，且移除来源后不会永久占用订阅额度。

### 1.2 信息消费者

作为频道信息消费者，
我希望毕昇在 Information 当天真正完成采集后及时同步新增文章，
以便不会因为毕昇任务执行过早而错过当天稍后才出现的文章。

### 1.3 知识空间管理者

作为配置了频道知识同步的知识空间管理者，
我希望本轮新增文章按照频道和子频道规则被尝试投递到目标知识空间，
以便日常新增内容可以进入既有知识处理链路，同时不影响空间中的其他来源文件。

### 1.4 运维人员

作为私有化部署运维人员，
我希望不同部署的公网同步请求不要集中在整点，并能从日志和指标识别远端未就绪、订阅漂移和投递失败，
以便控制上游瞬时压力并快速定位同步异常。

## 2. 验收标准

### 2.1 平台订阅状态对齐

- **AC-01** — THE SYSTEM SHALL 将全部活跃租户中所有频道当前引用的信息源并集作为该部署的期望订阅集合；单租户模式与多租户模式使用相同的平台级订阅语义。
- **AC-02** — WHEN 订阅对账周期到达, THE SYSTEM SHALL 使用期望订阅全集与当前 API Key 的远端实际订阅全集计算缺失项和多余项。
- **AC-03** — IF 任一活跃租户的频道来源集合未能完整读取, THEN THE SYSTEM SHALL 不执行本轮任何远端订阅或取消订阅操作，并保留到后续周期重新对齐。
- **AC-04** — IF 远端实际订阅未能完整读取全部分页, THEN THE SYSTEM SHALL 不基于不完整结果执行任何订阅或取消订阅操作。
- **AC-05** — WHEN 期望集合存在远端缺失来源, THE SYSTEM SHALL 逐个发起订阅；单个来源失败不得阻止其他来源继续处理，并应保留未收敛结果供后续周期再次对齐。
- **AC-06** — WHERE 自动取消订阅开启, WHEN 远端存在期望集合之外的来源, THE SYSTEM SHALL 逐个发起取消订阅；该设置稳态默认开启。
- **AC-07** — WHERE 自动取消订阅关闭, THE SYSTEM SHALL 继续补齐缺失订阅但不取消任何远端来源，并应报告仍然多余的订阅数量。
- **AC-08** — WHEN 本轮订阅和取消订阅尝试结束, THE SYSTEM SHALL 重新读取远端实际订阅全集并报告仍缺失和仍多余的来源；单个来源失败不得被报告为整体已收敛。
- **AC-09** — WHEN 部署更换 Information API Key, THE SYSTEM SHALL 使用新 Key 将当前期望订阅全集重新走订阅流程，不依赖旧 Key 下的本地订阅推断。
- **AC-10** — THE SYSTEM SHALL 默认每 60 分钟发起一次订阅对账，并允许运维调整周期；每轮公网请求默认在 `0～600` 秒随机时间窗口内错峰执行，且随机窗口可配置。

### 2.2 公共文章同步

- **AC-11** — THE SYSTEM SHALL 以远端实际订阅全集作为公共文章处理范围，不依赖本轮租户频道快照；同一轮中，同一来源最多执行一次文章拉取，不得按租户重复拉取和写入。
- **AC-12** — IF 远端来源最近一次成功同步不属于 Information 当前业务日, THEN THE SYSTEM SHALL 不请求该来源文章、不将其标记为当天已处理，并在后续轮询周期继续检查。
- **AC-13** — WHEN 远端来源已在当前业务日成功同步且文章集合相对本地检查点没有变化, THE SYSTEM SHALL 记录本轮已检查结果而不重复拉取文章。
- **AC-14** — WHEN 远端来源已在当前业务日成功同步且文章集合发生变化或本地尚无同步状态, THE SYSTEM SHALL 拉取该来源满足增量边界的全部文章分页。
- **AC-15** — THE SYSTEM SHALL 以远端文章 ID 保持本地文章唯一；上游包含边界重复返回同一文章时，本地不得产生重复文章。
- **AC-16** — IF 文章分页、结果完整性校验或任一文章写入未完整成功, THEN THE SYSTEM SHALL 不推进该来源的公共文章进度和远端检查点。
- **AC-17** — WHEN 某来源的目标文章分页全部处理成功, THE SYSTEM SHALL 推进该来源的公共文章进度，并记录本次已处理的远端同步状态和文章集合状态。
- **AC-18** — WHEN 远端当天同步成功但没有新增文章, THE SYSTEM SHALL 记录远端检查结果，使相同远端状态不再触发重复文章拉取。
- **AC-19** — WHILE 同一来源已有文章同步任务执行, THE SYSTEM SHALL 阻止同一部署中的另一个任务并发执行该来源的新增判断和写入；无法确认互斥时不得无保护执行。
- **AC-20** — WHEN 某来源首次执行公共文章同步, THE SYSTEM SHALL 默认覆盖最新 20 篇文章；运维可将首次同步数量配置为 `1～100`，且相同时间边界的数据不得因数量截断而遗漏。
- **AC-21** — IF 首次同步在进度提交前中断, THEN THE SYSTEM SHALL 在后续周期继续覆盖原首次同步范围，不得因远端随后新增文章而把原范围中的失败文章挤出。
- **AC-22** — THE SYSTEM SHALL 默认每 30 分钟轮询一次远端文章状态，并允许运维调整周期；每轮公网请求默认在 `0～600` 秒随机时间窗口内错峰执行，且随机窗口可配置。

### 2.3 知识空间一次投递

- **AC-23** — WHEN 一篇文章在本轮公共文章同步中首次成功写入本地公共文章库, THE SYSTEM SHALL 将其作为知识空间新增文章候选；已存在文章的边界重复写入不得产生新的知识投递候选。
- **AC-24** — WHEN 存在新增文章候选, THE SYSTEM SHALL 在每个活跃租户范围内查找引用对应信息源的频道及其已启用知识同步配置，且不得跨租户读取或写入配置、知识空间和知识文件。
- **AC-25** — WHEN 知识同步配置绑定主频道, THE SYSTEM SHALL 投递该频道来源中的新增文章；WHEN 配置绑定子频道, THE SYSTEM SHALL 仅投递满足该子频道当前筛选规则的新增文章。
- **AC-26** — WHEN 同一篇新增文章按业务配置命中多个租户、知识空间或目录, THE SYSTEM SHALL 分别向每个命中的有效目标发起一次投递尝试。
- **AC-27** — WHEN 单个知识目标或单篇文章投递失败, THE SYSTEM SHALL 记录该次真实失败并继续尝试同批其他文章和其他目标，不得把失败项报告为已接受。
- **AC-28** — IF 知识投递因文件重名、文章不存在、目标删除、权限、额度、敏感内容、存储、任务或未知异常失败, THEN THE SYSTEM SHALL 将该结果视为终态，不自动重试或生成补偿任务。
- **AC-29** — IF 已接受的知识文件后续解析失败、超时或违规, THEN THE SYSTEM SHALL 保留知识模块产生的真实状态，信息源同步链路不得再次投递该文章。
- **AC-30** — THE SYSTEM SHALL 不通过标题、正文、文件名、内容哈希或其他知识文件属性推断历史投递状态，不得修改或删除知识空间中非本轮投递创建的文件。
- **AC-31** — WHEN 新增或重新启用一条知识同步配置, THE SYSTEM SHALL 只处理此后新同步的文章，不自动导入配置生效前的历史文章；用户删除已投递文件后，日常同步不得自动恢复。
- **AC-32** — WHERE 知识空间投递开关关闭, THE SYSTEM SHALL 停止为新文章发送知识投递任务；重新开启后不得自动补投关闭期间的文章。该开关稳态默认开启。

### 2.4 可观测、兼容与安全边界

- **AC-33** — THE SYSTEM SHALL 分别记录订阅快照完整性与剩余漂移、各来源远端就绪状态与文章同步结果、知识投递接受与失败分类，并提供可用于持续告警的计数和延迟指标。
- **AC-34** — THE SYSTEM SHALL 不在日志、指标、监控展示或错误信息中输出 Information API Key；失败来源或文章 ID 只能记录有限样本。
- **AC-35** — THE SYSTEM SHALL 在 MySQL 和 DM8、单节点和多节点部署中提供相同业务行为；任务由不同节点执行时不得因节点本地状态不同而形成不同订阅或文章进度结论。
- **AC-36** — THE SYSTEM SHALL 保持现有频道、知识同步配置和知识文件的用户侧操作接口不变；本特性不新增管理端页面或新的对外 HTTP API。
- **AC-37** — THE SYSTEM SHALL 将信息源展示元数据作为平台公共目录供不同租户频道复用；删除单个频道或租户不得删除其他租户仍可能使用的公共来源元数据。

## 3. 边界情况

- 多租户开启时，频道和知识配置继续按租户隔离；远端订阅意图与公共文章仅在平台层汇总一次。
- 活跃租户枚举、任一租户频道快照或远端订阅分页不完整时，不得用局部集合执行取消订阅。
- 自动取消订阅默认开启；灰度期间关闭后，只允许订阅集合向“补齐”方向变化，多余项保持可观测。
- 单个来源订阅或取消失败时，其他来源继续处理；失败项在下一周期重新进入差集。
- Information 当天同步晚于毕昇首次轮询时，毕昇不得因早先执行过空同步而跳过当天后续轮询。
- 上游在增量边界返回多个相同创建时间的文章时，全部边界文章都应被处理，本地重复写入无副作用。
- 公共文章写入部分成功时，成功的新文章可进入一次知识投递；公共文章进度仍不得推进，失败文章后续继续同步。
- 新文章写入成功后、知识任务成功发出前进程崩溃可能造成漏投；本期接受该窗口，不以扫描知识空间方式补偿。
- 异步投递请求可能因运行环境被重复执行；应用不主动重试，重复执行若产生文件重名则按真实终态失败记录。
- 两条知识同步配置指向同一目录时分别尝试；本期不做跨配置去重或结果合并。
