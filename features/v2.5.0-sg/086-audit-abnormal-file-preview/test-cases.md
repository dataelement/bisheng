## 1. 用例覆盖概览

以下编号均为 TC-086 的后缀。P0 用于核心查看能力、权限泄露、跨文件串读与意外下载；P1 用于失败反馈及列表上下文回归。优先级不是执行顺序。

| REQ-01 的验收条件 | 正常 | 异常 | 边界 |
|---|---|---|---|
| AC-01 点击文件名查看该文件正文 | 01 有权且可预览 | 见 AC-02 | 01 同名不同文件，不能只看标题 |
| AC-02 权限及不可用 | 01 为允许对照 | 02 可见记录但正文被拒；03 文件或预览不可用 | 03 预览地址为空或文件无法展示，不回退为下载 |
| AC-03 返回列表且不自动下载 | 04 列表状态；05 无自动下载 | 03、05 失败也不下载 | 04 非首页、有筛选、勾选非预览行 |
| AC-04 快速切换不串内容 | 06 新文件先返回 | 06 旧请求晚到且失败，不覆盖新成功 | 07 关闭后原请求才结束 |

## 2. 用例清单

**公共准备 F1（修订 1）：** 每例独立准备测试租户与会话，从审计「异常文件」进入。允许账号可以看到异常记录且有目标文件的预览权限；拒绝账号可看到该记录但没有正文预览权限。各文件按准备时记录的空间 ID、文件 ID 标识，不用文件名作身份。仅使用无敏感信息的合成文件；清理本例创建的测试数据、响应拦截与监听，不改共享权限。隔离验证不需真实账号时，以既有接口的响应作为消费方输入，不能据此证明服务端授权正确。

| 数据 ID | 独立准备的数据／完成状态 |
|---|---|
| A、B | 两条不同文件 ID 的可预览异常记录，文件名相同 `审计-样本（甲）.pdf`；两份有效 PDF 第一页分别只有标记 `AUDIT-A-086`、`AUDIT-B-086`，各自返回不同预览资源。提供与正文不同的失败备注 `解析失败`。 |
| U1、U2、U3、U4 | U1 列表加载后该测试文件被移除；U2 仍有记录但无可用预览地址；U3 既有预览器不支持的测试文件；U4 预览读取时连接失败。每组独立准备，不预设错误码或文案。 |
| L | 失败状态过滤后至少 22 条稳定记录（每页 20 条）；第 2 页存在 A、B，已勾选 B 而未勾选 A。禁用后台数据变动，记录实际页码、筛选、行 ID 顺序、勾选集合。 |
| R1、R2 | A 的响应可手动释放；R1 释放 A 的成功结果，R2 释放 A 的失败结果。B 的响应独立可完成。两者均使用事件屏障而非按毫秒猜测。 |

|---|---|---|---|---|---|---|---|---|
| TC-086-01 | 点击同名文件中的目标行，仅打开该文件正文 | P0 | 功能 | REQ-01 / AC-01 | F1；允许账号；两条记录同屏 | 1. 点击 B 行文件名。 2. 等待该预览完成。 | A、B | 在当前页只打开一个只读弹窗，标题为 B 文件名；正文能读到 `AUDIT-B-086`，不是 A 的标记或失败备注。请求指向 B 的实际文件与空间。 |

## 3. 异常与边界专项清单

| 专项 | 数据、关联用例与剩余边界 |
|---|---|
| 权限、数据不存在 | AC-02：01/02 配对；03-U1 检查记录与内容生命周期不同步。共享环境用真实预览鉴权验证；不提升账号权限来使预览成功。 |
| 空值、格式 | AC-02：03-U2 无可用地址（包含缺失、null、空字符串的实际契约等价形态）；03-U3 不支持格式。无新增上传、格式转换及文件名长度限制，不设计新的上限。 |
| 特殊字符、重复访问 | AC-01/04：01 使用中文及括号、同名文件；06 用实际 ID 区分。同一文件重开不等同于重复写请求，不要求缓存或限制请求次数。 |
| 并发、弱网、超时 | AC-02/04：03-U4、06、07；以请求挂起、释放、拒绝及结果稳定为观察边界，不规定时延 SLA。若取消有效，同时确认旧请求不再可提交结果。 |
| 非法流转与副作用 | AC-03：04/05 检查异常状态、重试／删除调用及下载事件。预览不应改变文件异常状态；既有预览审计日志不是异常状态变更，不要求后台零写入。未新增通知、埋点或存储契约，不为其添加断言。 |

## 4. 自动化可行性标注与证据边界

开发候选位于 `src/frontend/platform/test/`，只在可独立驱动的**真实消费逻辑**上验证请求参数、响应选择和状态，替换网络或外部资源；不能用模拟状态机证明产品行为。未核实可驱动的非 UI 入口时保留缺口，不为测试强制拆分业务代码。浏览器实际显示、授权服务和自动下载结论由测试工程师在独立验收工程针对确定构建验证。

| 用例 | 研发候选（开发期隔离、非 UI） | 测试岗位建议（开发完成后） |
|---|---|---|
| 01 | 可自动化：真实消费方接受 B，记录请求目标并比对独立预设的资源 B。 | 需浏览器与已知 PDF；读第一页标记，确认确实内嵌而非仅生成地址。 |
| 02 | 可自动化：输入既有拒绝响应，观察不设置内容、不走回退；不将模拟拒绝称为鉴权通过。 | 需真实权限配置和拒绝账号；核对反馈及请求记录。 |
| 03 | 可自动化：分别控制资源缺失、空地址、格式不支持及连接失败；核对实际失败处理。 | 需浏览器验证失败可见且可关闭，真实存储缺失使用一次性测试文件。 |
| 04 | 需工具：若列表状态仅由组件管理，开发期核查调用边界；不把静态检查称为交互证据。 | 可自动化：浏览器读列表快照，关闭后逐字段比较，记录变更请求。 |
| 05 | 可自动化：监测消费方是否发起下载调用，仅能排除显式下载路径。 | 需浏览器下载、导航及新页面事件监听；同时验证内嵌资源未诱发下载。 |
| 06 | 可自动化：用两组可控 Promise 驱动真实选择逻辑，观察旧成功／错误是否被接纳。 | 需可控网络响应与弹窗内容观察，校验中间状态而非只看最后截图。 |
| 07 | 可自动化：关闭后释放成功／失败结果，检查是否重新发布正文或错误。 | 需浏览器及网络屏障；验收关闭后没有回弹或旧提示。 |

复核方法：从四条 AC 推导正反例，再按权限、列表副作用及响应顺序检查遗漏；同名异正文和迟到失败是区分错误实现的反例。当前仅完成定义与作者自查；全部用例 **未执行／未验证**，未生成 UI 或独立验收结论。
