## 0. 范围和确认状态

### 0.1 本轮授权

用户已明确要求按第一批范围编写 `spec.md`，重点明确节点配置、输入输出、版本固定、调用身份和异常处理。用户于 2026-11-05 确认本规格并要求继续编写 `design.md`。

用户补充允许功能数据和接口调用先使用 Mock，并要求标注 `# TODO`。本次将该要求补入规格，供后续设计和实施使用。

本期目标流程为「开始 → 昆联平台 Agent → 输出」。A 配置并发布工作流，B 获得运行授权后，以 B 的当前身份和权限调用昆联 Agent，结果可供下游节点使用。

### 0.2 本次纳入

- 在 Workflow 画布新增独立的昆联平台 Agent 节点。
- 根据当前编辑者和租户展示授权 Agent，选择具体可用版本，展示参数说明。
- 配置常量或上游变量作为输入，保存节点配置，支持节点试运行和工作流运行。
- 发布前校验配置、资源权限和版本状态，发布后固定 Agent 版本及输入输出含义。
- 按试运行操作者或正式运行实际发起人的可信身份执行同步调用。
- 校验成功结果并交给下游，处理鉴权拒绝、版本不可用、参数错误、上游错误、超时及结果未知。
- 在既有运行界面展示节点状态和可定位的关联信息，保护调用凭据。

### 0.3 后续批次与兼容边界

下列能力由后续批次单独规划。

- 昆联 Agent 异步查询、实时进度订阅、人工输入、断点恢复和远端取消。
- Workflow 对外管理接口适配、工具登记、发布／下线同步及昆联反向调用 Workflow。
- 模型、知识库、MCP 工具／连接器和 Skill 的独立调用节点。
- 通用 Token Exchange、新增 SSO 或用户同步能力、权限镜像、创建配额和统一文件传输通道。
- 历史 Agent 配置迁移、旧节点入口隐藏或移除、存量账号或授权迁移。

本特性扩展既有 Workflow 节点、版本和运行行为。外部身份关联仍由 F118 管理，用户、租户、成员、凭据和权限继续由原领域负责。本稿未定义新的独立领域对象或跨特性不变量。

### 0.4 Mock 开发与待替换标记

开发和测试可以先使用 Mock 数据或接口，覆盖以下内容。

- Agent 列表、可用版本、参数说明和使用权限判定。
- 同步执行的结构化成功结果、鉴权／授权拒绝、版本失效、错误、超时和非终态。
- 多用户、不同租户、版本变化及重复请求等契约样例。

Mock 应通过正常的节点配置、发布、试运行及 Workflow 执行入口验证功能，并明确标识当前使用模拟数据。外部身份及授权结果可以模拟，本地既有身份、租户和工作流授权检查仍须执行。

所有临时模拟数据来源、模拟接口调用边界及待确认的协议假设，都需要添加可检索的 TODO 注释，说明当前模拟内容、对应待确认项和替换条件。Python 使用 `# TODO`，其他语言使用合法注释中的 `TODO` 标记。注释内容使用中文，例如下列待替换说明。

```text
# TODO [F119][EXT-01] 当前 Agent 目录为 Mock，收到昆联正式资源契约后替换并补真实联调验证。
# TODO [F119][EXT-02] 当前用户身份传递为模拟契约，确认 Access Token 复用规则后接入真实鉴权。
# TODO [F119][EXT-03] 当前 invoke 为 Mock，确认同步超时和幂等语义后替换并补失败路径联调。
```

TODO 注释用于追踪替换工作。运行时须能识别 Mock 与真实来源，真实调用失败按失败处理，不能自动转为模拟成功。

### 1.3 用户可配置与可查看的内容

| 内容 | 业务规则 |
| --- | --- |
| 节点名称与说明 | 用于画布识别及运行定位。 |
| 昆联 Agent | 从当前用户有权使用的资源中选择，能够识别所选资源。 |
| Agent 版本 | 明确选择可用版本，能够识别版本并查看对应参数说明。发布时必须确定具体版本。 |
| 输入映射 | 按参数配置常量或上游变量，展示类型、必填及其他已支持的约束。 |
| 输出变量 | 根据版本定义查看可供下游引用的输出及类型，输出声明与实际结果共同决定成功。 |

身份、租户及调用凭据由可信运行上下文确定。节点配置只表达业务资源、版本和参数映射，用户不能通过填写地址、认证头、凭据或身份字段改变实际调用目标及执行主体。

### 1.4 输入与输出规则

输入支持常量和上游变量引用。值按版本约定保留字符串、数值、布尔、对象、数组及允许的空值，零值、`false`、空字符串、未提供和显式空值分别判断。对象和数组可作为完整值传递，一期可识别的参数描述范围见 EXT-01。

必填缺失、变量不存在、类型不符或不支持的参数描述必须可定位。可选参数的省略、默认值和额外字段只按已确认的版本契约处理。配置阶段无法确定实际值时，执行前再次校验实际输入。

输出须符合发布时绑定的参数含义。成功结果能够作为结构化变量被下游引用。响应中的运行元信息用于调用定位，不能混入业务输出或覆盖其他节点变量。

## 2. 验收标准

以下 AC 定义期望行为，验证方式见第 5 节。本地实施和 Mock 证据见 verification.md；正常 API／Worker、浏览器及真实环境验收尚未完成。

### 2.1 节点选择、配置与参数映射

| ID | Requirements | 验收标准 | Verification |
| --- | --- | --- | --- |
| AC-01 | REQ-01 | WHEN 有工作流编辑权限的用户添加平台 Agent 节点并选择资源，THE SYSTEM SHALL 仅提供当前用户及租户有权使用的 Agent 和可用版本，展示所选版本对应的输入输出说明。 | V-01 |
| AC-02 | REQ-01 | IF 目录为空、无使用权限或查询失败，THEN THE SYSTEM SHALL 分别展示可识别的结果，查询失败时不得把未过滤目录或先前用户的资源作为可选结果。 | V-01 |
| AC-03 | REQ-01、REQ-02 | WHEN 编辑者保存并重新打开节点，THE SYSTEM SHALL 保留 Agent、版本和输入映射。配置不完整的草稿可以保存，但必须标出缺项并阻止试运行和发布。 | V-01 |

| AC-12 | REQ-04、REQ-06 | IF 身份映射缺失、成员或租户无效、本地业务授权拒绝，或执行前调用凭据已经失效，THEN THE SYSTEM SHALL 拒绝该次执行。需要重新授权时提供明确提示，不自动借用创建者、管理员或其他用户的凭据。 | V-03 |

| AC-20 | REQ-07 | WHEN 节点开始、成功或失败，THE SYSTEM SHALL 在既有运行界面展示对应状态及原因，并能关联到本次工作流运行、节点执行、目标 Agent 版本和已有昆联运行标识。远端尚未提供运行标识时不得伪造。 | V-05、V-06 |
| AC-21 | REQ-04、REQ-07 | WHILE 展示配置、运行详情、日志和错误，THE SYSTEM SHALL 保护访问令牌、客户端密钥、同步 Key 和认证报文，限制业务结果的访问权限，不将秘密暴露到前端可读内容、工作流定义、节点变量或错误正文。 | V-03、V-05 |
| AC-22 | REQ-08 | WHEN 接入平台 Agent 节点，THE SYSTEM SHALL 保持已有本地 Agent 及其他节点的配置和运行行为，以及既有身份和业务授权合同。没有平台 Agent 节点的工作流不增加昆联资源服务依赖。 | V-06 |

## 3. 边界情况

| 场景 | 期望结果 | 对应 AC |
| --- | --- | --- |
| 已保存的 Agent 后来不再可选 | 保留可诊断的原配置，发布与执行重新判断资格，不静默改选其他资源。 | AC-03、AC-06、AC-09 |
| Schema 无法识别或版本说明不完整 | 指出不支持或缺失的约束，阻止无效试运行和发布。 | AC-05、AC-06 |
| 常量合法但上游运行值不合法 | 配置校验不替代实际输入校验，执行调用前拒绝。 | AC-04 |
| 同一 Agent 被多个节点使用 | 各节点使用自己的映射和运行结果，失败或重试不混用其他节点输出。 | AC-13、AC-14、AC-17 |
| 列表可见但发布或运行时被撤权 | 按当前操作者及动作拒绝，不把目录曾经可见当作持续授权。 | AC-06、AC-10、AC-12 |
| 服务凭据有效但用户无权 | 按实际用户拒绝，服务鉴权不扩大用户授权。 | AC-10、AC-12 |
| 排队后凭据过期 | 执行前拒绝或仅通过双方已确认的方式取得同一用户的有效授权，身份不能改变。 | AC-11、AC-12 |

验证按独立风险组织。同一证据可以覆盖多条 AC，各层仅补充独立边界证据。V-01 至 V-06 中的本地功能可先基于 Mock 验证，记录须分别注明模拟环境与真实环境的结果。真实双系统身份审计与授权结果需要昆联测试环境，本地契约样例仅证明毕昇侧对约定报文及失败的处理。

Mock 开发阶段可以独立记录完成，须满足以下条件。

- 正常入口可完成配置、发布、试运行及最小流程，成功与失败路径有本地可执行证据。
- 临时模拟内容和待确认假设具有对应 TODO，验证记录说明使用的样例契约及模拟范围。
- 本地已有身份、租户和工作流授权检查保持有效，真实接口替换和切换边界有验证依据。
- 对应真实联调继续标为 NOT_RUN。

完成真实首批验收须满足以下条件。

- 对应需求、AC 和外部合同已明确，V-01 至 V-07 有可追溯的实际结果，Mock 证据与真实证据分别登记。
- 至少一条真实同步最小流程成功，确认实际执行人为 B，并验证一条真实拒绝路径。
- 固定版本、参数校验、超时及重复执行保护有可执行证据，相关旧节点回归通过。
- 外部环境缺失或合同未确认的验证保留 NOT_RUN，不能计为首批功能验收通过。
