# 对象存储的浏览器访问路径与桶名解耦

**版本**：v3.1.0-beta1。**优先级**：P1。**状态**：2026-11-11 补上最终用户页面的 `/workspace/object/` 请求，待确认这一处变更。

**关联需求**：无独立 PRD。依据为本会话已确认的需求发现：浏览器访问对象的路径与桶名解耦；站点入口配置不随桶名改变；已保存的旧路径在读出时兼容；带对象存储公开主机名的服务端拉取不在本次范围。

**依赖**：无。不取得知识库文件、会话消息、用户、工作流、品牌资源或应用附件的写入权，只改变浏览器取得对象内容时使用的路径，以及这些路径在读出和再次提交时的解释。

## 1. 目标与范围

作为部署这个平台的人，我希望只修改公共桶或临时桶的名称，站点入口配置保持不动，以便换桶时不必同步修改入口路由。

作为已经在使用预览、下载、图片、附件和头像的用户，我希望这些内容在路径调整后仍能打开，以便不因为入口路径变化而丢失既有内容。

作为平台，我希望浏览器不能凭一条路径取走公共桶和临时桶以外的对象，以便应用附件这类私有内容不会因为路径规则放宽而被下载。

本次纳入：

- 浏览器取得对象内容时，对象路径是 `/object/{桶名}/{对象键}`。最终用户页面发出的请求可以在这之前带有 `/workspace`，即 `/workspace/object/{桶名}/{对象键}`。两条请求返回同一对象内容。
- 只有当前配置的公共桶和临时桶可以通过这条路径取出内容。
- 新发给浏览器的对象地址使用该路径。
- 已保存在业务数据中的旧路径不改库；读出时，第一段是当前公共桶或临时桶的路径，以新路径形式交给浏览器。
- 再次提交旧路径或新路径时，都能定位到同一个对象。
- 更换公共桶或临时桶的名称后，不需要修改或重新发布站点入口的路由配置。本地开发时的页面访问与部署后使用同一条路径规则。

本次明确排除：

- 不搬迁已有对象，不把旧桶中的文件复制或移动到新桶。
- 不修改数据库、消息正文或知识库切片里已经保存的原文。
- 不改变对象存储公开主机名，也不处理签名所使用的主机名与浏览器访问主机名不一致的问题。
- 不改变报告模板、微调训练集、阿里云语音识别、灵思任务进程取文件、应用发布拉取构建包、频道文章导入这些使用完整主机名的服务端拉取。
- 不把站点自身的 `/assets/` 静态资源当作对象存储路径。

## 2. 验收标准

- **AC-01** — WHEN 浏览器请求当前公共桶或临时桶中的对象，THE SYSTEM SHALL 通过 `/object/{桶名}/{对象键}` 返回该对象的内容；若请求路径是 `/workspace/object/{桶名}/{对象键}`，THE SYSTEM SHALL 返回同一对象内容。地址上既有的签名在原有效期内仍然有效。
- **AC-02** — WHEN 只修改公共桶或临时桶的名称并让使用该配置的服务生效，THE SYSTEM SHALL 用新桶名经 `/object/` 路径提供对象内容，且不要求修改或重新发布站点入口的路由配置。站点入口的路由配置中不出现具体桶名。
- **AC-03** — IF 浏览器请求 `/object/` 或 `/workspace/object/` 下不属于当前公共桶或临时桶的对象，THEN THE SYSTEM SHALL 不返回对象内容；该地址带有有效签名时也同样拒绝。
- **AC-04** — IF 要签发给浏览器的对象地址所指向的桶不是当前公共桶或临时桶，THEN THE SYSTEM SHALL 拒绝签发该浏览器地址。
- **AC-05** — WHEN 接口把已保存的对象路径交给浏览器，且该路径的第一段是当前公共桶或临时桶，THE SYSTEM SHALL 以 `/object/{桶名}/{对象键}` 给出；数据库、消息正文和知识库切片中的原文保持不变。
- **AC-06** — WHEN 调用方用旧形式 `/{当前公共桶或临时桶}/{对象键}` 或新形式 `/object/{当前公共桶或临时桶}/{对象键}` 定位同一个已保存对象，THE SYSTEM SHALL 定位到该对象。
- **AC-07** — WHEN 已保存路径的第一段不是当前公共桶或临时桶，THE SYSTEM SHALL 不把该路径改写到新桶名下，也不搬移对象。
- **AC-08** — WHEN 浏览器打开原先由页面直接获取的知识库预览与下载、批量下载包、知识库切片图片、会话附件、工作台文件与封面、头像、图标、应用与工作流标识、语音合成结果、灵思任务结果、引用材料、评估结果或工作流输出文件，THE SYSTEM SHALL 仍返回对应对象的内容，并保持原有的权限、签名有效期和匿名可读范围。
- **AC-09** — WHERE 页面在本地开发环境中访问上述对象，THE SYSTEM SHALL 使用与部署环境相同的路径规则：对象路径为 `/object/{桶名}/{对象键}`，最终用户页面的请求还可以带 `/workspace` 前缀。
- **AC-10** — WHEN 服务端组件使用带对象存储公开主机名的完整地址拉取对象，THE SYSTEM SHALL 保持该地址的主机名，不改写成 `/object/` 浏览器路径。
- **AC-11** — IF 平台不能判定 `/object/` 后的桶名是当前公共桶或临时桶，THEN THE SYSTEM SHALL 不返回对象内容。请求带 `/workspace` 前缀时同样不返回。

## 3. 明确接受的边界

- 更换桶名不会把旧桶里的对象带到新桶。正文里仍指向旧桶名的链接打不开，是因为对象还在旧桶，不是读出改写的漏网。
- 读出改写只作用于交给浏览器的结果。已经写在数据库和知识库切片里的字保持原样。
- 判定桶名的能力不可用时，浏览器拿不到对象内容。这优先于「入口服务正常时仍能打开旧图片」。
- 原有下载、预览和查看权限的判定时机与结果不因路径变化而放宽或收紧。
- `/assets/` 下的站点静态文件继续由站点自身提供，不进入 `/object/`。

## 4. 后续流程

design 已经要求 `/object/` 与 `/workspace/object/` 返回同一对象内容。确认上面这一处规格变更后，不需要重写设计。确认前不改入口配置，也不改签发与解析代码。
