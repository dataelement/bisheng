# Feature: 工作流嵌套工作流

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> 所有 How（引擎嵌套方式、事件转发、校验落点、字段、API、前端组件）一律写在 [design.md](./design.md)。

**关联 PRD**: [docs/PRD/3.0-SEC/工作流嵌套工作流/工作流嵌套工作流 PRD.md](../../../docs/PRD/3.0-SEC/工作流嵌套工作流/工作流嵌套工作流%20PRD.md) §3 需求澄清规则、§4 验收对照
**优先级**: P0
**所属版本**: v3.0.0（开发分支 `feat/SEC-3.0.0-1016`，择期合回 `feat/3.0.0`）
**依赖**: 无

> **规则来源**：PRD §3 的规则（R-x.y）是需求口径的唯一来源，本 spec 不重抄规则正文，只把它们写成可验收的 AC。AC-NN 与 PRD 的 AC-SW-NN 编号一一对应。
>
> **范围边界**
> - **本次纳入**：
>   - 工作流画布新增【子工作流】节点：选择子工作流、配置输入参数、引用返回结果。
>   - 【结束】节点新增「返回结果」开关与配置。
>   - 子工作流的选择条件、嵌套层数限制、上线校验、保存提醒、删除拦截。
>   - 子工作流的运行：参数传入、静默执行、结果回传、失败信息、调试面板展开。
> - **本次明确排除**：
>   - **含【输入】节点或交互型【输出】节点的工作流作为子工作流**：产品取舍，子工作流定位为「给参数、出结果」的后台流程（PRD §5、附录 A.2）。
>   - **超过 2 层的嵌套**：子工作流内不能再含【子工作流】节点。
>   - **子工作流版本固定或上线冻结**：运行时始终调用子工作流的当前版本（PRD R-4.1）。
>   - **子工作流节点的失败分支或重试**：失败即父工作流整体失败；节点通用异常处理另行立项。
>   - **运行时校验运行者对子工作流的权限**：随父工作流授权（PRD R-5.1）。
>   - **跨租户选用工作流**。
>   - **开放 API 单独暴露子工作流**：调用方只看到父工作流的结果。
>   - **client 端会话界面改动**：子工作流静默执行，会话里只出现父工作流的内容。

## 0. 术语

沿用 PRD §3 开头的术语定义：父工作流、子工作流、输入参数、返回结果、交互型【输出】节点。补充两条：

| 术语 | 定义 |
|---|---|
| 当前版本 | 工作流构建界面中显示的版本，即运行时读取的版本。 |
| 引用方 | 当前版本中含有指向某工作流的【子工作流】节点的工作流，不区分是否上线。 |

## 1. 用户故事

**A. 工作流编排者**
作为 **工作流编排者**，
我希望 **把已有工作流作为一个节点放进新的工作流，给它传参数并使用它返回的结果**，
以便 **复用已经调好的流程，不必在多个工作流里重复搭同一段节点**。

**B. 被复用工作流的维护者**
作为 **被复用工作流的维护者**，
我希望 **修改它时知道哪些工作流在引用它，并且修改保存后引用方自动用上新版本**，
以便 **一处修改、处处生效，同时不会在不知情的情况下破坏别人的工作流**。

**C. 终端用户**
作为 **终端用户**，
我希望 **使用父工作流时不需要任何子工作流的权限，也看不到子工作流的内部消息**，
以便 **像使用普通工作流一样使用组合出来的工作流**。

## 2. 验收标准

### 2.1 配置

- **AC-01**（R-1.1、R-1.2、R-1.3）— WHEN 编排者在【子工作流】节点选定一个子工作流, THE SYSTEM SHALL 按该子工作流开始节点的自定义全局变量逐项列出输入参数；WHEN 父工作流为某参数配置了值, THE SYSTEM SHALL 在运行时用该值覆盖子工作流中的对应变量，未配置值的参数使用子工作流中该变量自身的值。
- **AC-02**（R-1.4）— IF 用户添加或修改的自定义全局变量与同一工作流内已有变量同名, THEN THE SYSTEM SHALL 提示重名错误并拒绝该修改。
- **AC-03**（R-2.1–R-2.5）— THE SYSTEM SHALL 只在「选择工作流」下拉列表中列出同时满足以下条件的工作流：当前用户有编辑及以上权限；不含【输入】节点和交互型【输出】节点；不含【子工作流】节点；不是当前工作流本身；与当前工作流同租户。是否上线不影响是否列出。

### 2.2 层数、上线与保存

- **AC-04**（R-3.2）— WHEN 父工作流上线, IF 它引用的某个子工作流含【子工作流】节点、【输入】节点或交互型【输出】节点, THEN THE SYSTEM SHALL 拒绝上线，提示中写明该子工作流的名称和原因；父工作流保存草稿时不拦截，只在画布上的【子工作流】节点给出提示。
- **AC-05**（R-3.3）— WHEN 一个正被引用的工作流保存的内容含【子工作流】节点、【输入】节点或交互型【输出】节点, THE SYSTEM SHALL 保存成功，并弹窗列出全部引用方，提示它们运行到子工作流节点时会失败。
- **AC-06**（R-3.4）— IF 子工作流运行中到达【子工作流】节点、【输入】节点或交互型【输出】节点, THEN THE SYSTEM SHALL 使父工作流的【子工作流】节点失败，失败信息符合 AC-20。

### 2.3 版本、权限与变更

- **AC-07**（R-4.1）— WHEN 子工作流修改并保存、或切换了当前版本, THE SYSTEM SHALL 让所有父工作流在下一次运行时执行子工作流的新当前版本，父工作流无需任何操作。
- **AC-08**（R-4.2）— THE SYSTEM SHALL 允许调用从未上线的子工作流；该子工作流不出现在终端用户的工作台中。
- **AC-09**（R-5.1、R-5.2）— WHEN 只对父工作流有使用权限、对子工作流无任何权限的用户运行父工作流, THE SYSTEM SHALL 正常执行子工作流，子工作流内部节点以该用户身份执行。
- **AC-10**（R-5.3）— WHEN 编排者在配置完成后失去对子工作流的编辑权限, THE SYSTEM SHALL 不影响父工作流运行。
- **AC-11**（R-5.4）— IF 用户删除一个正被引用的工作流, THEN THE SYSTEM SHALL 拒绝删除并列出全部引用方；引用全部解除后允许删除。
- **AC-12**（R-5.5）— WHEN 一个正被引用的工作流保存时其输入参数或返回结果有增删改, THE SYSTEM SHALL 保存成功，并弹窗列出受影响的父工作流。
- **AC-13**（R-5.6）— WHEN 父工作流传入的参数在子工作流中已不存在, THE SYSTEM SHALL 忽略该参数；子工作流新增而父工作流未传的参数，使用子工作流自身的值。
- **AC-14**（R-5.7）— IF 父工作流引用的返回结果在子工作流中已不存在, THEN THE SYSTEM SHALL 使【子工作流】节点失败，失败信息写明缺少的返回结果名称，不以空值代替。

### 2.4 执行展示

- **AC-15**（R-6.1）— WHILE 子工作流作为子工作流运行, THE SYSTEM SHALL 不向会话推送它的任何消息：内部节点的「展示在会话中」不生效，开场白、引导问题和普通【输出】节点的消息都不出现。
- **AC-16**（R-6.2）— THE SYSTEM SHALL 让子工作流开始节点的用户信息、当前时间和聊天记录取父工作流本次运行的值。
- **AC-17**（R-6.3）— WHEN 编排者在父工作流的调试面板查看【子工作流】节点, THE SYSTEM SHALL 支持展开查看子工作流每个内部节点的输入、输出与耗时。
- **AC-18**（R-6.4）— WHEN 通过开放 API 调用父工作流, THE SYSTEM SHALL 返回与平台内运行一致的结果，响应中不出现子工作流内部节点的消息。

### 2.5 数据类型与异常

- **AC-19**（R-7.1、R-7.2、R-7.3）— THE SYSTEM SHALL 原样传递输入参数和返回结果的值，不做类型转换；「输入」方式的固定值按字符串处理；【子工作流】节点「输出结果」和【结束】节点「返回结果」只显示名称，不显示类型。
- **AC-20**（R-7.4、R-7.5）— IF 子工作流内任一节点失败, THEN THE SYSTEM SHALL 使父工作流整体失败，失败信息包含子工作流名称、失败的内部节点名称和原始错误信息。
- **AC-21**（R-7.6）— THE SYSTEM SHALL 把子工作流的运行耗时计入父工作流本次运行，不单独计算超时；子工作流内的节点沿用同一个单节点执行次数上限，超过时父工作流失败；子工作流中模型调用的记录归属父工作流。

## 3. 边界情况

- 当【结束】节点的「返回结果」开关关闭时，该工作流作为子工作流运行后不返回任何结果；父工作流的【子工作流】节点「输出结果」为空列表。工作流单独运行时行为与改动前一致。
- 当子工作流有多个【结束】节点时，以实际执行到的那个【结束】节点的返回结果为准。
- 当父工作流在一次运行中多次调用同一个子工作流（多个【子工作流】节点选同一工作流）时，每次调用相互独立。
- 当子工作流被删除后父工作流仍有指向它的节点（例如通过数据迁移造成）时，【子工作流】节点运行失败，失败信息说明子工作流不存在。
- 当用户中止父工作流运行时，正在执行的子工作流一并中止。
