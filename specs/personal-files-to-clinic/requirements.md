# 个人知识库文件迁入科室库

- Status: CONFIRMED
- Created: 2026-09-22
- Scope: 编写脚本、文档和本地验证；不执行真实迁移。

## 已确认口径

用户确认完整相对路径匹配、包含子目录、保留完整路径；只从主组织向上找最近的科室；原始上传人缺失时允许使用当前上传人。

用户追加：日常报告仅列出匹配目录但未完成迁移的文件及原因，不记录成功文件、未匹配文件、完整计划或堆栈。默认预览只列筛选不通过项；恢复状态单独保存。

用户确认：增加显式选项，目标库所有者不存在或禁用时，使用已校验的 `--operator-id` 作为迁移文件的权限所有者；文件上传人和科室库所有者不因此改变，其他校验保留。

## 需求与验收

| Requirement | Acceptance | 验证方法 |
|---|---|---|
| REQ-1 扫描指定租户的全部有效个人库，支持指定完整目录路径；省略路径扫描全部文件 | AC-1 只匹配路径及后代，保持完整目录结构，不包含回收站、收藏库、其他租户 | 规划测试、SQLite 查询集成 |
| REQ-2 按 original_uploader_id，缺失时用 user_id，取唯一主组织向上最近 office | AC-2 科室绑定的有效科室库按 space_id 升序取首个；无用户、无主组织、无科室、无科室库分别记录原因 | 规则参数化测试 |
| REQ-3 原地移动且不覆盖、不重新解析 | AC-3 保留文件/文档/版本 ID、原对象、分块及向量；完整版本链一致迁移；目标目录逐层复用或创建，冲突跳过 | 迁移集成、外部 I/O 仿真 |
| REQ-4 默认预览、显式 apply、可审计和恢复 | AC-4 预览不写业务数据；写前保存原状态；权限、索引读回验证；失败继续且报告原因，报告无法写入则停止；恢复按数据库实际归属修复外部状态 | 失败路径、恢复及只读测试 |
| REQ-5 显式允许所有者失效时使用操作人接管文件权限 | AC-5 默认仍拒绝；开关仅作用于无效目标库所有者，权限 owner 使用有效操作人，上传人/库所有者不变，恢复固定原权限接管账号 | SQLite 迁移、拒绝及恢复测试 |

## 边界

只支持已就绪的共享存储规范文档；未解析、版本链不完整、审批中或投影未就绪的文件跳过/记录，不自动修复或重解析。不创建科室库、不跨租户迁移、不修改组织和绑定。
