# Feature: 网页读取内置工具

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答做什么、验收标准、不做什么。实现方案见 [design.md](./design.md)，执行流水见 [tasks.md](./tasks.md)。

**关联 PRD**: 无独立 PRD；需求来自 2026-10-19 会话，Spec Discovery 结论见本文范围边界
**优先级**: P1
**所属版本**: v3.0.0
**依赖**: 联网搜索内置工具的 DeepSeek 引擎（提交 e5f616b10、eb03de547）；网页角标机制（F069、F072）

> **范围边界**
> - **本次纳入**：
>   - 新增内置工具「网页读取」：agent 给出一个网址，工具返回该网页的正文。
>   - 读取引擎可选。第一期只提供 DeepSeek 一个引擎，配置结构允许以后增加其他引擎。
>   - 管理员在内置工具设置里为「网页读取」单独配置引擎、秘钥、可选的 Base URL 和正文长度上限。它与联网搜索的配置互不影响。
>   - 所有能选内置工具的场景都可以使用：助手、工作流 agent 节点、工作流工具节点、任务模式、日常模式。
>   - 每次成功读取的网页注册为一个可引用来源，模型引用后显示角标，点开角标可以看到网页信息并跳转原网页。
>   - 各场景的工具调用展示使用「网页读取」这个名称，不显示内部工具名，也不显示「工具已删除」。
>   - 已部署的老环境升级后，内置工具列表里自动出现「网页读取」。
> - **本次明确排除**：
>   - 联网搜索选 DeepSeek 时自动附带网页读取能力。已否决，原因是工具能力不应随搜索引擎切换而出现或消失。
>   - 复用联网搜索里填写的 DeepSeek 秘钥。已否决，原因同上。
>   - DeepSeek 以外的读取引擎，例如 Jina Reader、Firecrawl。配置结构预留，另起需求接入。
>   - 一次调用读取多个网址、整站爬取、读取需要登录的页面。
>   - 由平台自己的服务器直接抓取网页。第一期抓取由 DeepSeek 服务端完成，平台不发起对目标网址的请求。
>   - 现有 API 工具（`jina_get_markdown`、Firecrawl 抓取等）的改造或下线。

## 1. 用户故事

作为 **平台管理员**，
我希望 **在内置工具里配置一次网页读取的引擎和秘钥**，
以便 **助手、工作流、任务模式和日常模式都能使用这个能力，而不必每个应用单独配 API 工具**。

作为 **应用搭建者**，
我希望 **在助手或工作流里勾选「网页读取」**，
以便 **agent 在搜索结果摘要不够用时，能读取网页全文再回答**。

作为 **终端用户**，
我希望 **回答里来自网页全文的内容也带角标，并且能点开看到来源网页**，
以便 **核实回答的出处**。

## 2. 验收标准

### 2.1 配置

- **AC-01** — THE SYSTEM SHALL 在内置工具列表中提供「网页读取」工具。新部署环境和从旧版本升级的环境都满足此条，升级环境不需要手工操作。
- **AC-02** — WHEN 管理员打开「网页读取」的设置, THE SYSTEM SHALL 显示读取引擎选择（第一期只有 DeepSeek）、API Key（必填）、Base URL（选填，输入框以占位提示显示默认地址）和正文长度上限（默认 20000 字）。
- **AC-03** — IF 管理员未填写 API Key 就提交设置, THEN THE SYSTEM SHALL 在 API Key 字段下提示必填，不保存设置。
- **AC-04** — THE SYSTEM SHALL 把「网页读取」的设置与联网搜索的设置分开保存。修改其中一个工具的引擎或秘钥，不改变另一个工具的设置和行为。
- **AC-05** — WHEN 管理员保存设置时 Base URL 留空, THE SYSTEM SHALL 在调用时使用所选引擎的默认地址。
- **AC-06** — THE SYSTEM SHALL 在界面上对 API Key 做掩码显示，与联网搜索秘钥的显示方式一致。

### 2.2 读取行为

- **AC-07** — WHEN agent 以一个网址调用「网页读取」, THE SYSTEM SHALL 返回该网页的标题、网址和 Markdown 正文。
- **AC-08** — THE SYSTEM SHALL 去掉引擎在正文中非字母数字字符前额外加的反斜杠（例如 `\#`、`\-`、`\:` 还原为 `#`、`-`、`:`）；原文代码块内的反斜杠保持原样。
- **AC-09** — IF 正文长度超过配置的上限, THEN THE SYSTEM SHALL 只返回上限以内的正文，并在返回内容中明确告诉模型正文已截断以及原文总长度。
- **AC-10** — IF 网址不是 http 或 https 协议，或者网址中带有用户名或密码, THEN THE SYSTEM SHALL 不调用引擎，并向模型返回说明原因的错误信息。
- **AC-11** — IF 引擎读取失败（网页不存在、站点拒绝抓取、超时、秘钥无效等）, THEN THE SYSTEM SHALL 把失败原因作为工具结果返回给模型，当前对话或任务继续执行，不中断。
- **AC-12** — IF 网页读取成功但正文为空, THEN THE SYSTEM SHALL 告诉模型该网页没有可读正文，不把空结果注册为引用来源。
- **AC-13** — IF 管理员尚未完成「网页读取」的设置而某个应用调用了它, THEN THE SYSTEM SHALL 向模型返回「网页读取尚未配置」的说明，对话或任务继续执行。

### 2.3 场景可用性

- **AC-14** — WHEN 搭建者在助手中勾选「网页读取」, THE SYSTEM SHALL 让该助手的 agent 在对话中可以调用它。
- **AC-15** — WHEN 搭建者在工作流 agent 节点中勾选「网页读取」, THE SYSTEM SHALL 让该节点的 agent 在运行中可以调用它。
- **AC-16** — WHEN 工作流工具节点选择「网页读取」并传入网址, THE SYSTEM SHALL 输出该网页的读取结果。
- **AC-17** — WHEN 管理员把「网页读取」加入任务模式的可用工具且用户启用它, THE SYSTEM SHALL 让任务模式的 agent 可以调用它。
- **AC-18** — WHEN 管理员把「网页读取」加入日常模式的可用工具且用户在输入框工具选择里启用它, THE SYSTEM SHALL 让日常模式的 agent 可以调用它。

### 2.4 角标溯源

- **AC-19** — WHEN 一次网页读取成功, THE SYSTEM SHALL 把该网页注册为一个可引用来源，并在工具结果里给模型提供该来源的引用标识。助手、工作流、任务模式、日常模式都满足此条。
- **AC-20** — WHEN 模型在回答中引用了网页读取的来源, THE SYSTEM SHALL 显示角标；用户悬停或点开角标时，卡片显示网页标题、站点名和正文开头，点击后在新窗口打开原网页。
- **AC-21** — WHEN 模型在同一次回答中既引用联网搜索结果又引用网页读取结果, THE SYSTEM SHALL 让两类角标各自指向正确的来源，编号不冲突。
- **AC-22** — WHEN 用户重新打开历史会话, THE SYSTEM SHALL 仍能显示网页读取来源的角标和卡片内容。

### 2.5 调用展示

- **AC-23** — WHILE agent 正在调用或已经调用「网页读取」, THE SYSTEM SHALL 在日常模式的工具调用卡片、任务模式的执行步骤和助手运行日志里显示本地化的工具名「网页读取」以及被读取的网址或网页标题。
- **AC-24** — THE SYSTEM SHALL 不在任何场景把「网页读取」的调用显示为「工具已删除」或原始内部工具名。
- **AC-25** — THE SYSTEM SHALL 为新增的界面文案同时提供简体中文、英文、日文三种语言。

### 2.6 权限

- **AC-26** — THE SYSTEM SHALL 让「网页读取」的可见范围和使用权限与联网搜索等其他内置工具一致，不另设权限规则。

## 3. 边界情况

- 当同一次回答里多次读取同一个网址时，多次读取共用一个引用来源，角标卡片指向同一网页。
- 当网页需要执行 JavaScript 才能显示内容时，引擎可能只返回一段占位提示。系统按引擎返回的内容如实交给模型，不伪造正文。
- 当目标站点整体拒绝 DeepSeek 抓取时（实测维基百科即如此），按 AC-11 返回失败原因。
- 当正文恰好等于长度上限时，不提示截断。
- 当管理员把长度上限改为非正整数或超出允许范围时，设置界面应拒绝保存并提示有效范围。有效范围在 design.md 中确定。
- 多租户环境下，「网页读取」的设置归属与联网搜索内置工具的设置归属保持一致。
