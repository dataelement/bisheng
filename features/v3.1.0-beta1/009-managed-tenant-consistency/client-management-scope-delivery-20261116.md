# 客户端审计与敏感词控制跟随管理视图

2026-11-16。基线为发布线1fa960757248ac910c9515d0b458f1a7731daf92，开发分支codex/beta1-client-management-scope。用户要求两个页面沿用顶部管理视图，不在业务内维护独立管理租户；按既有统一上下文缺陷补漏处理。当前为本地开发结果，未合并、推送或部署。

## 修改与原因

原审计页将平台管理员默认目标写为Root，再从自己的租户下拉框选择；敏感词页也维护selectedTenant。两者会与公共请求层已确认的管理目标产生不同值，后端范围校验可拒绝错目标。截图中全部错误的现场原因未在本轮重新验证。

两页改用无独立选择状态的DshTenantScope，复用现有useAdminScope与公共bootstrap确认会话；超管使用管理目标，其他管理员使用真实主属，兼容旧身份响应。删除无人使用的ModelAuditTenantSelect。接口参数和保存URL继续传同一目标，保留既有后端和Gateway协议，不另存租户。未确认目标时不挂载业务查询/保存组件；失败可重试，不默认Root。

切换沿原整页刷新及旧请求范围门禁；同时以人员/租户为子树边界，清除审计分页、人员筛选、展开正文和敏感词草稿、策略缓存。旧请求取消/迟到响应保护保持。原审计采集配置与敏感词编辑权限保持，不新增后端授权或计量规则。
