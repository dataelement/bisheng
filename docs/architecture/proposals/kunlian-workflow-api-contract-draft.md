# 昆联 × 毕昇 Workflow 接口契约评审稿

本稿展开 10 月 23 日总体设计中的 K-01 至 K-14，供双方逐项确认。已交付的浏览器 SSO 和全量用户同步沿用 11 月 2 日开发包。下文路径来自总体设计，字段、状态值及 HTTP 状态是评审建议，正式 Base URL、OpenAPI、消息 Schema 和联调样例由双方确认。标为待确认的协议可采用昆联现有能力。[待联调接口清单](./kunlian-workflow-agent-phase1-confirmation-checklist.md) · [功能开发规划](./kunlian-workflow-development-plan.md)

## 通用约定

| 事项 | 评审建议 |
| --- | --- |
| 调用身份 | 区分调用服务、实际用户、租户。平台资源接口由昆联按可信身份判断权限。业务参数中的用户 ID、租户 ID 和运行上下文字段只用于业务关联或匹配校验。 |
| 资源版本 | 跨系统 ID 按不透明字符串处理。发布图绑定具体版本，版本不可用时返回明确错误。 |
| 请求关联 | 约定 Trace ID 与请求 ID 的透传方式。工作流运行、节点运行、Agent 运行及业务回执各有独立标识。 |
| 分页和变更 | 列表用不透明分页游标，末页明确结束。增量的持久进度与同一次遍历的分页令牌分别定义。昆联提供排序、游标有效期及失效后的恢复办法。 |
| 错误 | JSON 接口提供稳定错误码、可读说明和请求 ID。建议 401 表示认证失败，403 表示权限不足，409 表示版本、状态或幂等冲突，422 表示输入校验失败。明确限流和重试信号。模型兼容接口、OIDC 和 SSE 按各自契约返回。 |
| 重试和幂等 | 读请求可在约定范围内重试。执行或写入按一次逻辑操作分配幂等键，确认去重范围、有效期及同键异参冲突。同次操作结果未知时先按契约确认原结果。 |

## 主流程

### K-01 调用鉴权与实际用户身份

| 方向 | 请求和验证 | 失败及验收 |
| --- | --- | --- |
| 毕昇 API／Worker → 昆联 | 优先确认浏览器 SSO 获取的 Access Token 能否由毕昇服务端用于 Agent、资源和权限接口。若支持，明确允许的接口、受众、scope、有效期、运行用户和租户如何取得，以及排队后令牌过期如何处理。若无法复用，请昆联提供现有服务鉴权及实际用户委托方式，包括可信字段、签发与验证责任。 | A 配置、B 运行，昆联审计确认实际执行人是 B。凭据过期、跨租户、缺少委托或无 Agent 使用权限时拒绝。 |
| 昆联后端 → 毕昇 | 昆联代 B 查询、代 A 授权时，确认毕昇可验证的操作者、租户、受众和动作范围。毕昇按自己的 Workflow 权限再校验。 | 非授权操作者、错误受众或超出 scope 的操作拒绝。 |

### K-02 身份目录和增量

昆联提供，毕昇身份同步任务调用。本节确认总体设计的增量契约，已交付的全量用户列表和成员详情沿用开发包。

| 接口 | 请求建议 | 响应和边界 |
| --- | --- | --- |
| `GET /identity/tenants` | 按已授权目录范围请求，支持全量初始查询和增量分页。 | 租户 ID、状态、变更标识。明确停用、删除和首次初始化的表示。 |
| `GET /identity/users` | 约定 `updated_after`、分页令牌和页大小。 | 用户稳定 ID、OIDC 映射字段、状态和变更标识。明确更名和删除的表示。 |
| `GET /identity/memberships` | 同样支持全量初始化和增量分页。 | 用户与租户或组之间的稳定关联、关系状态及变更标识。确认 `user_group` 和组成员的表达方式。 |

三类接口分别确认凭据范围、分页顺序和游标续跑。同一时间点的变更需有稳定续读规则。验收覆盖首次全量、连续增量、停用与删除，以及重放一页后结果收敛。

### K-03 授权资源列表与版本详情

昆联提供，毕昇 API 代理给画布。昆联根据当前编辑者和租户过滤结果。

| 接口 | 请求建议 | 响应和边界 |
| --- | --- | --- |
| `GET /resources` | 配置 Agent 节点时用 `types=agent&action=use`。其他节点按资源类型过滤，分页参数待确认。 | 资源 ID、名称、类型、状态和可选版本发现方式。昆联明确列表是否直接返回可选版本 ID，或提供现有的版本发现入口。 |
| `GET /resources/{resource_type}/{resource_id}/versions/{version_id}` | 使用列表获得的具体资源与版本，Agent 的 `resource_type` 为 `agent`。 | 实际版本 ID、可用状态、输入输出 Schema。确认 Schema 方言、版本内稳定性及无权、停用和不存在的响应。 |

Agent 列表的候选响应如下。仅在昆联确认由此返回可选版本时使用 `versions` 字段。

```json
{
  "items": [
    {
      "resource_type": "agent",
      "resource_id": "agent-001",
      "name": "设备故障诊断",
      "versions": [{"version_id": "agent-001-v1", "status": "AVAILABLE"}]
    }
  ],
  "next_cursor": null
}
```

验收时，用户只能选择有权使用的版本。版本详情能够配置画布字段，V2 上线后原发布图仍引用 V1。

### K-04 资源权限预检

昆联提供，毕昇保存、测试或发布服务调用。正式 HTTP 路径待确认，单项 `check` 与批量 `batch_check` 可复用昆联现有能力。

- 请求建议包含带关联项 ID 的检查列表，每项指定资源类型、资源 ID、版本和动作。服务端从可信凭据解析操作者和租户。
- 响应逐项返回允许或拒绝及原因。单项无权与整次请求鉴权失败分别表达。缺失、重复或无法识别的判定项不能作为通过依据。
- 验收用一批包含允许、无权及停用版本的请求核对逐项结果。执行时 `invoke` 仍按实际运行人校验当前权限。

### K-05 创建资格与配额

昆联提供规则检查或可信网关机制，毕昇创建服务消费。请求需明确创建 Workflow 的动作和业务上下文，实际用户与租户由可信身份确定。建议响应包括是否允许、拒绝原因和适用策略，配额剩余值按昆联契约提供。

双方确认何处执行最终校验。如果配额为硬限制，明确并发创建如何预留、结算和释放，及创建结果未知后的处理。验收覆盖无创建资格、达到配额和并发争抢最后一个名额。

### K-06 Agent 同步执行

昆联 Agent Runtime 提供 `POST /agent-runtime/invoke`，毕昇 Worker 在运行到平台 Agent 节点时调用。发布版本决定 `agent_ref`，实际用户来自 K-01，`run_context` 用于串联记录。

```json
{
  "agent_ref": {
    "resource_type": "agent",
    "resource_id": "agent-001",
    "version_id": "agent-001-v1"
  },
  "input": {"equipment_id": "EQ-001", "alarm_code": "TEMP_HIGH"},
  "response_mode": "wait",
  "run_context": {
    "session_id": "wf-session-001",
    "node_run_id": "wf-node-run-001",
    "trace_id": "trace-001"
  }
}
```

```json
{
  "agent_run_id": "agent-run-001",
  "agent_version_id": "agent-001-v1",
  "status": "SUCCEEDED",
  "output": {"diagnosis": "轴承温度异常", "recommended_action": "检查润滑和负载"}
}
```

| 确认点 | 预期行为 |
| --- | --- |
| 成功与失败 | 昆联返回实际执行版本和终态。毕昇校验版本及输出 Schema，成功才把输出交给下游。无权、停用版本和非法参数应有可区分的结果。 |
| 超时 | 昆联确认同步等待上限、超时起算点、网关限制和客户端断连后是否继续执行。明确如何区分未受理、执行失败和结果未知。 |
| 幂等 | 确认幂等键位置、作用域及有效期。同键同请求并发或重放的响应需要明确，同键异参返回冲突。超时后能否重放或查原结果按昆联已确认的机制处理。 |
| 验收 | A 创建、B 运行，昆联按 B 权限执行。返回版本与发布版本一致，结果可被下游消费。测试无权、版本错配、超时和同键重放。 |

### K-10 发布环路检查

昆联依赖服务提供 `POST /dependencies/cycles:check`，毕昇发布服务调用。请求建议包含候选 WorkflowVersion 和引用清单，每条边包含资源类型、资源 ID、版本 ID。响应区分通过、成环和检查不可用，成环时返回可用于定位的依赖路径。

通过检查后，毕昇提供发布事件与版本依赖清单，昆联内部同步器按 I-02 登记。双方确认发布检查与登记之间的并发边界和失败处理。验收覆盖正常发布、间接环路拒绝，以及重复发布事件后依赖记录收敛。

### K-13 Workflow 变更同步

毕昇是 Workflow 权限和版本的权威来源。双方选择昆联接收／订阅毕昇事件，或昆联从毕昇变更接口拉取。

- 候选事件字段包括 `event_id`、事件类型、租户、Workflow ID、对象修订号、发生时间及变更摘要。拉取使用可续跑的全局游标，对象修订号用于判断同一 Workflow 的新旧。
- 确认订阅鉴权、消费确认、重试、事件保留期和全量补偿。昆联用它更新权限镜像、所有者或发布版本信息。
- 验收覆盖授权后可见、撤权后新访问被拒绝，以及事件重复、乱序和遗漏后的镜像收敛。

## 按场景启用

### K-07 模型推理与知识检索

| 接口 | 请求建议 | 响应、失败与验收 |
| --- | --- | --- |
| `POST /model-gateway/chat/completions` | 毕昇模型节点传模型选择、消息、采样参数和流式开关。昆联按可信用户、租户与模型权限检查。 | 返回生成结果、实际模型版本和用量。流式场景确认事件格式、结束标志、中途失败和取消方式。验收覆盖正常生成、无权限及中途失败。 |
| `POST /knowledge/retrieve` | 毕昇检索节点传查询文本、知识库引用、结果数量和双方约定的过滤条件。昆联按实际用户裁剪数据范围。 | 返回有权命中的片段、文档／片段标识、分数和引用。区分无匹配、无访问权限和服务失败。验收覆盖同一查询在 A／B 数据范围下返回不同结果。 |

知识检索候选请求和响应字段如下。知识库是否需要版本 ID、结果限制和引用结构由昆联确认。

```json
{
  "query": "轴承温度异常如何处理？",
  "knowledge_refs": [{"resource_id": "kb-maintenance"}],
  "top_k": 5
}
```

```json
{
  "hits": [
    {
      "document_id": "doc-001",
      "chunk_id": "chunk-001",
      "content": "优先检查润滑和负载。",
      "score": 0.91,
      "citation": {"title": "设备维护手册", "location": "第 12 页"}
    }
  ]
}
```

### K-08 工具与连接器调用

昆联提供 `POST /capabilities/invoke`，毕昇能力节点直调。请求包含已授权能力引用、动作、结构化参数及调用关联标识。写入动作按契约传幂等键。

响应区分 `SUCCEEDED`、`FAILED`、`ACCEPTED` 和 `UNKNOWN`。同步成功返回结果，已受理或结果未知时应提供可用于后续核对的标识。验收覆盖一次成功写入、同键重放未重复写入，以及结果未知时通过 K-11 查询原结果。

### K-09 异步执行、状态与人工交互

昆联 Agent Runtime 提供，毕昇 Worker 或恢复任务调用。异步发起复用 K-06 的 `invoke`，运行查询及操作路径以 `/agent-runtime/runs/{agent_run_id}` 为基准，具体前缀待确认。

| 接口 | 请求与响应建议 | 验收重点 |
| --- | --- | --- |
| `POST /agent-runtime/invoke` 异步模式 | 沿用 Agent 引用、输入和幂等键，选择异步模式。受理响应返回 `agent_run_id` 和初始状态。 | 受理后可查询同一运行。同键重放按约定返回原运行。 |
| `GET` 运行详情 | 按运行 ID 查询当前状态、已完成输出、失败原因或等待中的交互标识。 | 状态和终态映射明确，毕昇可依据权威终态恢复节点。 |
| `GET …/events` | 按事件序号或游标续订进度。明确事件保留、断线续订和重复处理。 | 断线恢复后，重复事件只生效一次。 |
| `POST …/cancel` | 按运行 ID 提交取消请求。响应区分已受理、已终止和已经完成。 | 取消与完成并发时，以最终状态为准。 |
| `GET …/interactions/{interaction_id}` | 读取待填写内容、Schema、当前状态和修订号。 | 实际用户只有在获授权时才能读取交互。 |
| `POST …/interactions/{interaction_id}/complete` | 提交表单输入和预期修订号，约定幂等键。响应区分已受理、重复提交及修订冲突。 | 重复提交只恢复一次，旧修订或无权限时拒绝。 |

昆联可提供运行事件通知，由毕昇的 W-16 接收。双方确认事件格式和签名。回调和查询返回同一终态时，毕昇按运行 ID 与节点执行标识去重。

### K-10 依赖方与影响查询

昆联依赖服务提供 `GET /dependencies/dependents` 和 `GET /dependencies/impact`，毕昇在版本停用或归档时调用。请求指定目标资源与版本，确认分页和影响范围。前者返回直接引用方，后者返回约定范围内的受影响资产及阻断原因。验收覆盖仍被引用的版本、无引用版本，以及归档检查期间新增引用的处理。

### K-11 业务回执查询

昆联提供 `query_receipt` 的 HTTP 契约，路径待确认。毕昇按已授权的调用范围使用幂等键或业务回执查询原操作。响应给出查询到的状态、原结果或失败原因，并明确找不到、保留期已过和暂未可见的语义。验收模拟操作已成功但响应丢失，毕昇能查回原结果并避免重复写入。

### K-12 文件传输

两端有文件输入或输出时，双方选择昆联文件 API 或约定的 S3 方式。确认上传所需的名称、类型、大小和校验和，响应返回稳定的对象引用。下载前校验调用者、实际用户和租户，按约定签发短时 URL。验收覆盖正常上传下载、跨租户拒绝、签名过期及校验和不匹配。

### K-13 Session 回调

只有需要主动通知对方 Session 状态时才启用。双方确认发送方、接收地址及签名方式。候选消息含 `event_id`、Session ID、对象修订号、状态和关联运行 ID。确认哪些状态可推送、接收确认、重试和补偿查询。验收覆盖回调重复、乱序和遗漏后的状态收敛。

### K-14 Agent 反向调用 Workflow 的版本绑定

昆联提供可验证的绑定来源，双方可选查询、同步记录或可信签名凭据。昆联 Agent Runtime 反向调用毕昇时，毕昇核对调用方 AgentVersion、目标 WorkflowVersion、租户和绑定状态。版本绑定失效或目标不匹配时拒绝。验收覆盖绑定有效时调用正确版本、绑定撤销后拒绝及同次工具调用重放。

## 联调交付

请按编号确认支持状态、正式路径、Base URL、鉴权方式及可联调时间。HTTP 接口附 OpenAPI，事件附消息 Schema。样例覆盖固定 Agent V1／V2、同租户 A／B 的权限差异、跨租户 C、资源停用、超时与幂等、发布环路、知识检索成功和拒绝。按场景启用的能力另附对应的状态、事件或回执样例。
