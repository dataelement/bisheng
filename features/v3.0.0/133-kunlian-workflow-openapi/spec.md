- 依赖：开放平台凭据与身份底座、F048 统一业务授权、F118 昆联可信身份映射、F121/F122/F123/F127/F128 Workflow 能力、F130 租户及成员资格。

## 1. 目标与用户故事

作为昆联服务端集成方，我希望使用 API Key，并随请求仅提供毕昇登录账号user_account，代表该用户查询、执行、编辑、发布及管理 Workflow 授权，无需每次通过浏览器 SSO 建立会话。

作为平台管理员，我希望明确限定每个昆联 Key 允许的外部租户和业务能力，并能够撤销凭据及追溯代操作行为，而不放宽其他开放平台调用方的既有安全规则。

作为被代表用户，我希望外部调用遵守我当前有效的租户资格和工作流权限，不能因持有集成 Key 而越权。

## 2. 已确认范围与信任边界

### 2.1 纳入

- A 查询：工作流列表、详情、版本、输入输出定义。
- B 执行：启动、状态、结果、取消、人工输入提交。
- C 编辑管理：创建、修改画布与元数据、版本管理。
- D 发布管理：发布、下线。
- E 授权管理：查询权限、授予其他用户权限、撤销权限。
- 一个 Key 可覆盖多个显式获准的昆联租户；可代表这些租户内所有有效且已经映射的昆联用户，无需逐用户配置代表名单。
- 可代表所属租户的租户管理员；始终禁止代表全局超级管理员。普通用户具有工作流管理权限时可执行对应动作，不以管理员身份为前提。
- 正式业务Query仅提供user_account，精确匹配毕昇登录账号user_name，不是显示姓名。移除external_tenant_id和external_user_id两个公开参数；服务端从唯一有效成员关系与可信昆联绑定反查租户及内部外部标识，保留Key范围校验。账号不存在、停用、重复或无法唯一确定有效租户时拒绝，不回退默认身份。
- 昆联服务端持有 Key 即承担实际操作人代传责任；本次不要求每次请求附带该用户浏览器会话或用户令牌。

### 2.2 明确排除

- 删除工作流，以及通过版本管理变相删除整个工作流。
- 用户、租户、角色、菜单管理及管理员任命。
- 通过业务请求自动创建、同步或映射未知用户及租户。
- 给 Key 或被代表用户增加其本来没有的资源权限。
- 将新的跨租户、全有效用户范围及租户管理员代操作规则推广到普通开放平台 Key。
- 以本轮审批代替部署、数据库变更、真实环境配置或数据写入授权。
- 登记全量快照、增量同步和同步回执不因本次 ABCDE 选择自动纳入；已有相关能力保持原合同。

## 3. 功能需求

### REQ-01：调用方凭据与受控范围

平台应识别有效昆联 API Key，明确其允许的昆联外部租户集合与业务能力。一个 Key 可覆盖多个租户，但不能因目标账号或工作流存在而自动扩大范围。仅毕昇平台全局超级管理员可签发、撤销、轮换 Key 及修改其允许租户与业务能力；租户新增和用户同步不自动扩展 Key 范围。这里的凭据管理者与被代表的昆联用户是不同角色，仍禁止代表全局超级管理员调用业务接口。凭据应支持失效、撤销和轮换；原凭据撤销后不得接受新的业务操作。

### REQ-02：可信用户解析与资格检查

平台应通过user_account精确定位唯一有效毕昇用户，从其唯一有效成员关系确定本地租户，并反查Key绑定连接下的可信昆联映射；最终验证Key允许的外部租户范围及当前用户、成员、租户和映射资格。公开请求不再接受external_tenant_id或external_user_id选择身份。身份缺失、冲突或不可确认时拒绝，不以调用方传入的本地用户、租户、角色等字段替代验证，不静默回退到 Key 所有者或默认租户。

### REQ-03：管理员代操作与权限交集

有效操作必须同时处于 Key 的租户和能力范围，以及实际用户当前业务权限内。允许租户管理员在其所属且本次选定的获准租户内操作；禁止代表全局超级管理员。租户管理员快捷授权不得越过 Key 租户范围或目标工作流归属检查。

### REQ-04：查询

平台应按实际用户权限提供工作流列表、详情、版本及输入输出定义。列表在服务端限定范围；详情、版本与定义均核验所属工作流和租户。无权对象不得泄露图、资源内容或其他用户的敏感信息。

### REQ-05：创建与编辑管理

平台应以实际用户资格创建工作流，遵循既有配额及创建规则，创建归属由可信身份确定。应支持元数据、画布和版本管理，遵守版本归属、并发冲突和已发布材料保护，不允许绕过发布管理修改已发布运行语义。

### REQ-06：发布与下线

平台应按实际用户对应权限发布或下线工作流，遵守既有版本校验、图校验及发布事务规则。下线后拒绝新启动；已受理运行继续采用既有冻结版本规则。发布失败不得对外形成部分成功的可调用状态。

### REQ-07：执行、交互与运行隔离

平台应提供启动、状态、结果、取消和人工输入提交。已受理运行绑定接入方、租户、实际用户、工作流和版本；后续请求不能通过更换身份参数读取或控制其他归属运行。正式昆联接口不要求、不使用客户端Idempotency-Key，不承诺跨HTTP重试查回原运行；重复启动可能创建新运行。人工答案仍通过交互状态原子消费，不能因重复请求再次执行已消费等待点。Worker重复投递和终态保护保留。取消受理与最终取消应可区分；不可取消的原终态不得被覆盖。

### REQ-08：工作流授权管理

平台应按实际用户的授权管理资格查询、授予和撤销目标工作流权限。被授权用户必须是选定租户内可操作的有效用户。不得借此修改全局身份、绕过可授予范围、破坏受保护授权来源，或无权为自身提权。授权变更应遵循既有并发和投影确认规则，未确认生效不得报最终成功；正式接口不使用客户端请求键查回原授权操作；每次HTTP请求视为独立操作，原修订及投影规则继续防止并发覆盖。结果不明或PENDING应通过操作引用受控核对，不能承诺重新提交即查回原操作。

### REQ-09：凭据生命周期、审计与异步资格

平台应可追溯调用 Key 标识、接入方、外部及本地租户、实际用户、动作、目标和结果，不记录 Key 明文或外部令牌。异步执行不得丢失可信身份或切换租户；领取执行、恢复和后续操作应核验适用的当前资格。

同一受信昆联接入方轮换 Key 后，新 Key 仍获准原租户与所需能力，且被代表用户相同并保持有效资格与权限时，应可查询和控制原运行。运行保留原 Key 的审计事实，新操作记录实际使用的新 Key；不能据此允许不同接入方接管运行。

Key 撤销、租户范围收缩或用户撤权后，排队或等待恢复的运行不得再启动或恢复；执行中节点尽力停止，无法中断时可返回，但不得继续推进下一节点。不得承诺回滚已经发生的外部副作用，也不得自动回滚已生效业务事实。平台侧应保留受控处置渠道，避免运行无人可管。轮换接续不复活已因撤销而终结的运行；撤销终态、清理及平台处置合同在设计中明确。

### REQ-10：兼容与交付边界

本能力应显式受控开通，不改变普通开放平台凭据、浏览器 SSO、其他租户或非 Workflow 资源的既有合同。交付应包含与实际实现一致的接口说明和调用示例，明确认证、身份、错误、分页、重试、冲突及异步状态语义；Mock 证据不得冒充真实昆联验收。

## 5. 设计阶段必须解决但不在本稿预定的事项

- 跨租户昆联凭据与既有单租户 service account 的关系：不得直接删除全局守卫；管理资格已确认为仅毕昇全局超级管理员，设计需明确范围收缩、轮换和撤销流程及其最大生效时限。
- API Key 的传输方式、外部身份字段、与旧身份请求头冲突时的行为及唯一映射规则。
- 查询、写入、发布、运行、授权的完整接口合同及能力划分；不得把浏览器接口公开即视为完成。
- 已受理运行遇到 Key 撤销、范围收缩、用户撤权时的停机、终态、清理和恢复规则，避免无人可管理的运行。
- 既有 F121/F122/F123/F127/F128 候选与正式接线的复用、兼容、替换点，以及写接口尚缺的覆盖。
- 幂等范围、并发控制、保留期限、响应上限、限流和审计失败策略。
- MySQL/DM8 与真实权限、Broker/Worker 的验证边界；不以 SQLite 代替双数据库并发验收。

以上均应在设计评审中闭合；不得在未确认设计前实施。
