## 原因与修复

1. 截图文案对应 19703。新的请求准入对非超管只绑定当前租户，没有设置管理标记；`KnowledgeSpaceService.list_admin_spaces` 在真实管理员判断前要求该标记，子租户管理员因此失败。修复在已认证 TENANT 准入中补齐所属租户管理标记，不修改登录身份、管理员校验或独立凭证范围。
2. 子租户可见集合包含所属租户与 Root，供显式共享授权使用。QA 清单对租户管理员跳过逐条权限，而查询没有限定严格当前租户，于是 Root 数据进入列表。名称分页与时间游标查询均在 `strict_tenant_filter` 下运行管理员扫描；普通用户继续通过可见 ID 枚举读取已授权共享资源。

没有修改现场数据、用户绑定或权限投影。这里复现的是本地源码路径，未连接用户截图所在环境。
