# Feature: F078 中粮 E+ 机器人事件指标与频道文章分片配置

**状态**：用户于 2026-10-27 确认日志携带标识、监控侧去重并要求继续；Spec 与 Design 均已确认；已实现，验证证据见 validation.md。
**关联 PRD / 需求依据**：[本次需求与 Discovery 确认记录](../../../docs/cofco-1028-eplus-es-shards-discovery.md#6-确认记录)；用户于 2026-10-27 确认“沿用现有的指标日志方式，后端只记录事件，不用 Redis 聚合，人数由监控侧去重统计。ES 迁移可以暂停频道文章写入”。同日用户要求按评审建议修改，并提出监控仅处理请求结束时的指标日志；本版据此收敛为自包含终态指标。无独立外部 PRD。
**优先级**：P1；迁移数据完整性和敏感信息保护为必须通过的验收项。
**所属版本**：v3.0.0-beta1 / 中粮定制分支 `feat/cofco-1028-3.0.0-beta1`。
**依赖**：F073 E+ 机器人、v2.6.0 F042 指标日志、既有频道文章存储与配置能力。

## 1. 范围与用户故事

作为监控人员，我希望从各节点现有日志管线取得包含完整统计信息的 E+ 请求终态事件，无须关联请求开始与结束日志，即可按结束时间统计请求量、有问答结束的使用人数、会话数与回答成功率；另通过连接生命周期及存活事件判断当前机器人连接数。

作为运维人员，我希望通过配置控制频道文章的主分片数量，并在可暂停频道文章写入的维护窗口迁移存量数据，以便让新建索引与旧索引最终采用相同的目标配置。

本次纳入：正式 E+ 请求的自包含终态指标（含准入结果、最终业务结果和单次耗时）、连接生命周期与存活事件；频道文章索引默认 3 个主分片及配置校验；读取服务配置的手动迁移脚本、检查结果和操作说明。

本次排除：后台统计页面、统计查询接口、看板或采集平台部署；后端人数/连接数跨节点聚合、固定 5 分钟或 24 小时统计窗口、历史使用人数回填；新增接收/排队/开始阶段的问答指标、监控侧跨阶段日志关联、实时在途问答数及实时在线用户数；新增统计用 Redis 数据结构或数据库数据；无停写在线迁移；调整其他业务索引或副本策略；本地开发期间执行生产迁移、自动提交/推送或合入主线。

## 2. 验收标准

### 2.1 E+ 请求终态、用户与统计口径

- **AC-01** — WHEN 一条可识别的正式 E+ 业务消息形成最终处理结果, THE SYSTEM SHALL 输出一条自包含终态指标，使监控仅凭该条日志获得租户、机器人、稳定脱敏用户识别、业务消息与会话识别（已建立会话时）、是否已准入问答、最终结果、结果发生时间和从接收到结束的耗时；不要求关联请求接收、排队或开始日志。
- **AC-02** — WHEN 请求因无权限、繁忙或其他准入前错误而结束, THE SYSTEM SHALL 记录与已准入问答可区分的处理结果；重复回调的处理结果须与原业务问答终态区分，不得覆盖原业务结果或增加正常问答量；排队中和处理中提示不构成终态。
- **AC-03** — WHEN 一条已准入问答结束, THE SYSTEM SHALL 仅在生成正常完成且最终回复获得 E+ 成功确认时将其判为成功；准备失败、排队超时、执行失败、恢复时确认中断或回复发送失败均判为已准入问答失败，并在同一终态指标中给出可区分的失败原因；最终回复获确认不表示用户已阅读。
- **AC-04** — WHEN 同一租户的同一用户从不同节点、不同机器人或不同单聊/群聊发起请求并输出终态指标, THE SYSTEM SHALL 提供一致的脱敏用户识别信息，使监控可以在租户内跨机器人和会话去重；不同租户的用户不得因原始标识相同而合并。
- **AC-05** — WHEN 同一业务终态被重复记录、重复采集或在恢复后再次观测, THE SYSTEM SHALL 提供一致的业务消息识别信息及终态，支持监控按租户、机器人和业务消息去重；拒绝结果与重复回调处理结果须独立分类，不同租户或机器人的同名消息不得合并；消息去重与跨请求的用户去重仍由监控完成。
- **AC-06** — WHEN 监控选择统计窗口, THE SYSTEM SHALL 使其仅使用结果发生时间处于该窗口的终态指标完成统计：已结束问答数为已准入问答的成功数与失败数之和，回答成功率为成功数除以成功数与失败数之和；无权限/繁忙等准入前拒绝、重复回调及未结束问答不进入该分母。使用人数指窗口内至少有一条已准入问答结束（成功或失败）的去重用户数，完成回答人数仅包含成功问答的去重用户，有问答结束的会话数按会话去重；总已结束请求量为已结束问答数加准入前结束请求数（含无权限、繁忙及其他准入前错误），重复回调不计入而单列。零条已结束问答时成功率为无样本，不显示为 0% 或 100%。

### 2.2 E+ 连接与职责边界

- **AC-07** — WHEN 机器人连接发生尝试建立、认证成功、认证失败、断开、重试或被接管, THE SYSTEM SHALL 记录对应连接事件和可分类的原因，使监控能够区分各阶段并关联同一次连接；一条机器人连接不能被解释为一个使用者。
- **AC-08** — WHILE 机器人连接已认证且仍有效, THE SYSTEM SHALL 持续输出可识别该连接的存活事件，即使期间没有用户请求；连接关闭、失效或失去其业务所有权后，不得继续以该连接身份宣告存活。
- **AC-09** — IF 工作进程异常退出而没有正常断开事件, THEN THE SYSTEM SHALL 使监控能够依据最近存活事件及明确的过期规则停止将该连接计作存活；不能仅凭历史连接成功事件永久计数。
- **AC-10** — THE SYSTEM SHALL 沿用现有结构化指标日志方式，问答只记录最终处理结果及单次测量值，连接记录生命周期及存活事件；人数、请求量、成功率、会话数及连接数由监控侧聚合，不在后端新增 Redis 聚合、全局统计缓存或按窗口扫描用户数据的任务。
- **AC-11** — WHEN 现有指标总开关或 E+ 指标开关关闭, THE SYSTEM SHALL 停止输出相应的新增 E+ 指标；开关和指标输出失败不得改变请求准入、队列、问答、回复及既有连接单活规则，已有指标格式和含义保持兼容。
- **AC-12** — WHEN 输出新增指标事件, THE SYSTEM SHALL 不输出消息正文、回答内容、Secret、凭据、原始用户身份标识、完整媒体临时地址或图片字节；正式 E+ 入口与机器人调试调用必须可区分，调试调用不得被默认计入正式使用量。
- **AC-13** — WHEN 交付 E+ 指标, THE SYSTEM SHALL 同时提供终态分类、成功率分子/分母、消息与用户去重、按结果发生时间归属窗口、零样本、连接存活判断及样例说明；明确窗口内人数不代表实时在线或窗口内全部新发请求人数，未结束及未产生终态日志的请求不进入该窗口。指标沿用现有尽力输出的日志能力，不承诺进程崩溃或采集丢失时仍有完整业务审计，不为追求日志完整性增加持久投递或请求重放。

### 2.3 频道文章主分片配置

- **AC-14** — WHEN 创建新的频道文章索引且配置未指定主分片数量, THE SYSTEM SHALL 使用 3 个主分片；原有配置文件缺少该配置时仍可加载。
- **AC-15** — WHEN 配置指定 ES 支持的有效正整数主分片数量, THE SYSTEM SHALL 在所有频道文章索引创建路径使用该数量；指定 1、3 或其他有效数量时不能被独立的默认值覆盖。
- **AC-16** — IF 主分片配置为零、负数、布尔值、非整数值或非法文本, THEN THE SYSTEM SHALL 在配置校验时给出明确失败，不静默改用 3，也不继续创建或迁移索引。
- **AC-17** — WHEN 服务启动、重启或主分片配置改变但频道文章索引已存在, THE SYSTEM SHALL 保持现有文章数据与索引可用，不自动删除或重建已有索引；配置目标与实际分片的差异由手动迁移处理。

### 2.4 历史数据迁移

- **AC-18** — WHEN 运维人员运行频道文章迁移脚本, THE SYSTEM SHALL 使用与目标服务相同的配置来源和 ES 环境确定目标主分片数；缺省时采用 3，不要求运维在命令行重复输入目标数量。
- **AC-19** — WHEN 未显式要求执行迁移, THE SYSTEM SHALL 仅检查并显示实际索引、当前与目标主分片数、文档数量、迁移前置条件和操作计划；不得创建、修改或删除索引、文档、别名、写入限制或业务配置。
- **AC-20** — WHEN 当前主分片数已经符合配置, THE SYSTEM SHALL 报告无需迁移并保持原状；源不存在、指向关系不唯一或目标与已有数据冲突时，须明确说明并停止，不擅自创建空数据替代源数据或覆盖其他索引。
- **AC-21** — WHEN 运维人员显式执行迁移, THE SYSTEM SHALL 要求先暂停并排空所有频道文章写入，在迁移期间阻止源数据新增、更新和删除；完整性基准必须覆盖停写完成前已确认成功的全部变更，包括尚未检索可见的新增、更新和删除，并清楚说明维护范围及恢复条件；仅停止定时同步而仍允许其他写入不满足停写前提。
- **AC-22** — WHEN 源频道文章数据通过原有具体索引名称或既有别名访问, THE SYSTEM SHALL 均能按配置完成主分片数量调整，保留全部文章内容、文档身份、路由信息、字段类型、分析行为及既有副本策略；目标不得遗漏 AC-21 基准中的新增文章、保留其更新前的旧内容或恢复其中已删除的文章。
- **AC-23** — IF 数据复制未完成、有失败项、目标与 AC-21 所定义的完整性基准在数据身份/数量/内容上不一致或实际目标主分片数不符合配置, THEN THE SYSTEM SHALL 明确报告失败并禁止切换业务访问；不能仅凭迁移请求已受理、任务已结束或源/目标的旧可见视图相互一致判断成功。
- **AC-24** — WHEN 迁移即将执行会使原业务索引不可恢复的切换操作, THE SYSTEM SHALL 先确认已保留并验证可恢复的数据副本；不能在校验通过前删除唯一完整源数据，也不自动清理恢复副本。
- **AC-25** — IF 迁移中断、任务失败或切换结果暂时无法确认, THEN THE SYSTEM SHALL 返回失败或待核实结果并保留可定位的迁移任务、源、目标及恢复资料；重试时须识别已有状态，不盲目重复复制、覆盖数据或误报成功。
- **AC-26** — WHEN 迁移成功并恢复频道文章写入, THE SYSTEM SHALL 通过现有业务访问入口正常查询、写入、更新和删除文章，且最终主分片数量与配置一致；其他索引、频道订阅关系和已读数据保持不变。
- **AC-27** — WHEN 交付迁移脚本, THE SYSTEM SHALL 提供配置加载、试运行、维护停写、显式执行、结果核验和失败恢复说明，区分恢复写入前与恢复写入后的回退条件；恢复写入后的回退不能遗漏新产生的数据。

## 3. 边界情况与证据要求

- 请求在 23:59 发起、次日 00:01 结束，其终态、已结束问答量、使用人数和成功率样本均归入 00:01 所在窗口。按结果发生时间归属，日志采集延迟不能改变其业务时间；分子与分母使用同一组已结束问答（AC-01、AC-06、AC-13）。
- 群聊人数按实际消息发送者去重；同一人在多个会话、多个机器人提问时，租户整体人数不得简单相加各机器人的人数。只消费终态日志免去跨阶段关联，但仍需做消息去重及跨请求的用户去重（AC-04、AC-05、AC-06）。
- 尚在准备、排队或处理中的请求暂不计入人数和成功率；准入前拒绝与重复回调不计为正常问答。没有已结束问答时没有成功率样本（AC-02、AC-06、AC-13）。
- 进程异常退出时无法产生的终态日志不凭空补造；恢复流程确认中断请求为失败时，可以输出对应业务失败终态，并沿用原业务消息识别信息和已确认的结果发生时间。没有终态证据的请求不纳入成功率；不建立日志可靠投递或全量回填链路（AC-03、AC-05、AC-13）。
- 正常断线、重连、工作进程崩溃与租约转移分别验证连接事件和存活过期规则；只凭问答终态日志不能计算当前连接数，连接仍须有生命周期和存活事件（AC-07、AC-08、AC-09）。
- ES 应覆盖关闭自动刷新后，在停写前成功执行新增、更新、删除并立即迁移的验收场景；完成迁移后新增文章存在、更新为最终内容、删除文章不再出现。不能仅比较迁移时恰好可检索到的旧数据（AC-21、AC-22、AC-23）。
- 空的现有文章索引可以迁移；不存在的源与空索引不是同一状态。分片已达标时只报告跳过（AC-20）。
- 无论源是具体索引还是别名，迁移失败都不得把半成品交给业务；首次切换和再次迁移均须有可核验的恢复边界（AC-22、AC-23、AC-24、AC-25）。
- 本地单元测试、模拟测试、真实 ES 迁移演练、多节点 E+ 验收和生产迁移分别记录执行证据；未执行项不能标为通过。本次开发不直接执行生产迁移。
