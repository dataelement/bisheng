# BiSheng 3.1.0-beta1 知识迁移证据准备说明

本说明供研发、DBA 和实施人员配合[升级指南](v3.1.0-beta1.md)第六阶段使用。接口原核对基线为 `c3319b055033da7a2f4466cb2a0c9f6e94db63d3`；F118 脚本性能修复 `c0dee485f9fa701f8d8a4adf2b2aa2d605fe1cc0` 保持本证据格式不变。在全部业务写端和消费者停止、完整备份及中性 DDL 已完成、历史准备已核对完成后执行。

F118 命令的 `--backup-ref` 和 `--schema-ref` 指向的是**迁移协议的证据封装对象**，不是 SQL 文件、备份压缩包或普通 JSON 路径。对象位于配置的持久 MinIO bucket，具备当次 Run、环境、writer 和全部租户的身份约束。正式 CLI 会读取对象并校验内容哈希及身份。

## 一 保存真实备份与结构材料

先由 DBA/运维完成并验证恢复材料，生成两个无凭据正文的 manifest：

| 材料 | 至少记录 |
| --- | --- |
| backup manifest | 维护环境、停写时点、各存储备份位置和校验和、旧镜像/config/Secret 引用、全部租户清单、恢复验证结果、历史准备计划及精确物理备份的位置和摘要 |
| schema manifest | 原数据库 schema 和 Alembic current、目标 schema/head、结构升级执行记录及摘要、历史业务原列核对结果 |

完整 SQL、密钥和模型配置备份保存在受控私有备份位置；迁移持久 bucket 中只存不含这些正文的证据和引用。不要把含凭据的完整备份上传到公开 bucket。

使用现场已有对象存储工具保存 manifest，下载回读核对原始字节的 SHA256。将实际对象键及哈希填入下列输入文件 `/app/data/upgrade/3.1.0-beta1/f118-materials.json`。其中租户 ID 必须是现场**全部实际租户**的升序唯一清单，包含停用等仍在 tenant 表中的租户；不要仅列当前活动租户。

下面为填写模板，两个哈希和对象键必须替换；`[1, 2]` 也只是格式示例：

```json
{
  "run_id": "upgrade-310b1-20261119",
  "environment": "production",
  "writer_contract_version": "f118-v1",
  "tenant_ids": [1, 2],
  "backup": {
    "object_key": "实际backup-manifest对象键",
    "sha256": "实际64位小写十六进制SHA256"
  },
  "schema": {
    "object_key": "实际schema-manifest对象键",
    "sha256": "实际64位小写十六进制SHA256"
  }
}
```

`run_id` 最长 64 字符，首位为字母或数字，其余只允许字母、数字、`_ . : -`。环境标识按本次维护记录填写，后续 CLI 必须一致。不要复用其他环境、其他租户集合或其他 Run 的材料。

## 二 生成协议封装及描述符

当前发行源码没有独立的“备份生成 CLI”。下列片段复用正式迁移的 codec、对象存储适配器和只读租户清单接口，将**已经核验的真实材料引用**封装为正式 CLI 接受的格式；仅写入两个证据对象和本地描述符文件，不写业务 SQL/FGA，也不冻结或执行迁移。

该片段不备份数据库，不检查服务是否已停止，也不证明原始备份可恢复。第一节的真实备份、回读和恢复验证必须先完成。已冻结 Run 应使用原有描述符，不能重新生成替代材料。

在升级指南的同一个维护容器 `/app` 下执行，沿用其 `config` 和 `PYTHONPATH`。下列文件直接保存到继承的 `/app/data` 持久挂载，无需另加 volume；先完成升级指南中的私有子目录初始化：

```bash
python - <<'PY'
import asyncio
import json
import os
import re
from pathlib import Path

from scripts.unify_knowledge_spaces import _runtime
from bisheng.core.context.tenant import tenant_execution_scope
from bisheng.knowledge.application.unification_inventory_codec import (
    digest, encode_inventory_page, record_from_values,
)
from bisheng.knowledge.domain.repositories.unification_run_repository import (
    KnowledgeUnificationRunRepository,
)

async def main():
    inputs = json.loads(Path('/app/data/upgrade/3.1.0-beta1/f118-materials.json').read_text())
    run_id = inputs['run_id']
    if not isinstance(run_id, str) or not re.fullmatch(r'[A-Za-z0-9][A-Za-z0-9_.:-]{0,63}', run_id):
        raise ValueError('Invalid run_id')
    if not isinstance(inputs['environment'], str) or not inputs['environment']:
        raise ValueError('Environment is required')
    if inputs['writer_contract_version'] != 'f118-v1':
        raise ValueError('Writer contract does not match this release')
    tenant_ids = inputs['tenant_ids']
    if (not isinstance(tenant_ids, list) or not tenant_ids
            or any(type(t) is not int or t <= 0 for t in tenant_ids)
            or sorted(set(tenant_ids)) != tenant_ids):
        raise ValueError('A complete sorted tenant inventory is required')
    for kind in ('backup', 'schema'):
        ref = inputs[kind]
        if (not isinstance(ref, dict) or set(ref) != {'object_key', 'sha256'}
                or not isinstance(ref['object_key'], str) or not ref['object_key']
                or not isinstance(ref['sha256'], str)
                or not re.fullmatch(r'[0-9a-f]{64}', ref['sha256'])):
            raise ValueError('A verified material descriptor is required: ' + kind)
    output = {key: inputs[key] for key in (
        'run_id', 'environment', 'writer_contract_version', 'tenant_ids'
    )}
    destination = Path('/app/data/upgrade/3.1.0-beta1/f118-inputs.json')
    if destination.exists():
        raise FileExistsError('Preserve and inspect the existing descriptor file')
    with tenant_execution_scope(1):
        async with _runtime(None) as runtime:
            repository = KnowledgeUnificationRunRepository()
            async with runtime.sessions() as session, session.begin():
                actual = await repository.alist_actual_tenant_ids(session)
                if tuple(tenant_ids) != actual:
                    raise ValueError('Actual tenant set differs from backup evidence')
                frozen = await repository.aget_global_freeze(
                    session, run_id=run_id,
                    writer_contract_version=inputs['writer_contract_version'],
                    tenant_ids=actual,
                )
                if frozen is not None:
                    raise ValueError('Use the original descriptors for the frozen Run')
            for kind in ('backup', 'schema'):
                record = record_from_values(
                    'evidence_material', material_kind=kind,
                    environment=inputs['environment'],
                    writer_contract_version=inputs['writer_contract_version'],
                    tenant_inventory_digest=digest(actual),
                    material_ref=inputs[kind],
                )
                content = encode_inventory_page(
                    run_id=run_id, section='evidence', scope='global',
                    tenant_id=None, page_index=0, records=(record,),
                    kind='verification',
                )
                output[kind + '_ref'] = await runtime.store.aput_canonical(
                    run_id=run_id, kind='verification', content=content,
                )
    fd = os.open(destination, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
    with os.fdopen(fd, 'w') as file:
        json.dump(output, file, ensure_ascii=False, indent=2)
        file.flush()
        os.fsync(file.fileno())
    print(json.dumps(output, ensure_ascii=False, indent=2))

asyncio.run(main())
PY
```

输出文件的 `backup_ref/schema_ref` 形如：

```json
{
  "object_key": "f118/unification/当次Run/verification/内容SHA256.json",
  "sha256": "内容SHA256"
}
```

封装由原 codec 按规范 JSON 编码，再由 `UnificationArtifactStore` 写入并回读校验；不要手工格式化后覆盖对象，其键与原始字节哈希绑定。保留 `/app/data/upgrade/3.1.0-beta1/f118-materials.json`、`f118-inputs.json`、两个原 manifest 以及各自原始备份。

回到升级指南第六阶段，使用输出中相同的 Run、环境及两个描述符先 preview，再 apply。最终 `ready` 由正式迁移及全租户校验产生，生成证据对象本身不表示升级成功。
