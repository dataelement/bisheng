这条线 · 7 站到达

1

登录平台

把密钥喂给 CLI,它会在你本机记住凭据,后面就不用再输了。

终端
$ cat deploy.key | bisheng login http://你的毕昇地址 --api-key-stdin
# ✓ 资源归属人: 张三   租户: 1   凭据已写入 ~/.bisheng
2

写一个能跑的小应用

这就是你要部署的东西——一个自己在电脑上能跑起来的小程序。下面用 Python 标准库写一个只返回一句话的网页。记住三条铁律,否则上了平台会起不来。

main.py
import os
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

# 铁律①:监听平台注入的 PORT 环境变量,别写死端口
PORT = int(os.environ.get("PORT") or 8080)

class App(BaseHTTPRequestHandler):
    def do_GET(self):
        self.send_response(200)
        self.send_header("Content-Type", "text/html; charset=utf-8")
        self.end_headers()
        self.wfile.write("<h1>你好,毕昇 👋</h1>".encode())

# 铁律②:绑 0.0.0.0,不是 127.0.0.1
ThreadingHTTPServer(("0.0.0.0", PORT), App).serve_forever()
铁律③

容器里根目录是只读的,程序要写文件(数据库、缓存)只能写进 /data 目录,那里才可写。

3

写一张应用清单

清单告诉平台:这个应用叫什么、用什么运行环境、监听哪个端口。它是 CLI 唯一读的配置文件,写错的字段会当场报错,不会静默忽略。

bisheng-app.yaml · 应用清单MANIFEST
name我的第一个应用
slugmy-first-app · 全局唯一
runtimepython3.11
port8080
requirements.txt可留空 · 纯标准库不用装依赖
省心

只用标准库时,依赖留空最稳——构建不需要联网拉包,在内网 / 信创环境不会卡在「装不上包」。

4

一键部署

在应用目录里跑一条命令。CLI 会自动帮你打包 → 上传 → 构建镜像 → 启动探活,最后生成一张发布审批单。你不用管中间那些活儿。

终端
$ bisheng deploy --yes
  打包条目 3 个 → 上传 100% → 依赖构建 → 启动探活
  ✓ 平台已接收   审批单已生成:等待管理员通过
5

等审批通过

发布要过一道审批。管理员在 客户端头像菜单 → 审批中心 → 待我审批 里点「通过」,你的应用就会自动上线:容器拉起、健康检查变绿。

状态

审批通过后不用你再操作;想看进度,回「构建 → 应用」,卡片上会显示「已上线」。

6

授权给大家

上线 ≠ 公开。刚上线时只有你自己能进。到「构建 → 应用」找到它,点卡片上的齿轮 → 管理权限 → 添加权限,把「查看者」授权给需要的人:选部门 / 用户组,想全员就勾顶层部门 +「包含子部门」。

别走捷径

授权就在这个界面点几下完成,一步到位——不用找后台、也不用改配置。

7

抵达 · 大家用起来

被授权的人打开应用中心,就能在「探索更多应用」里看到你的应用,点「进入应用」在新标签打开。用过一次,它还会自动出现在每个人的「最近使用」里。

六个最常见的翻车点

本地跑得好好的,上了平台却起不来?八成是踩了下面某一条。

  • ✕
    绑了 127.0.0.1 → 容器里探针连不上,一直卡在「启动中」。永远绑 0.0.0.0。
  • ✕
    端口写死 → 平台按清单注入 PORT 环境变量,读它,别写死。
  • ✕
    往当前目录写文件报只读 → 根目录只读,只能写 /data。
  • ✕
    页面外链 / 表单少了前缀 → 应用挂在 /apps/{slug} 下,外链要带 BISHENG_APP_BASE_PATH。
  • ✕
    构建卡在装依赖 → 能用标准库就别加依赖;真要装,确认构建环境能联网。
  • ✕
    别人访问不了 → 上线不等于公开,记得回第 6 步授权。

就这么多。你已经会部署了。
