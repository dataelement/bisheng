## 1. 结论

### 1.1 首发 6 类模板

每个模板 = 「一张表 + 一条流 + 一个看板」的**微应用**，附自动数据后台，身份/权限由平台桥接零配置。**不做行业大套件**（证据：唯一有公开使用量的钉钉模板中心显示，日报 49 万+人、走访记录 14 万+人、外出审批 19 万+人这类单点微应用的真实使用量碾压 CRM/进销存等套件一个量级）。

| # | 模板 | 场景示例 | 证据强度 | 用到的基础组件 |
|---|------|---------|---------|---------------|
| 1 | **信息收集上报** | 日报/走访记录/报名登记/问卷/基层报数汇总 | 通用最强（钉钉日报 49 万+人）+ 央国企强（「层层报数」刚需，国网安徽报表提前 5h） | 数据库 · 身份自动带入（人/部门）· 数据后台 |
| 2 | **业务台账** | 物资/设备/合同/合规台账，导入导出与查询 | 央国企强（中海油原话「线下台账线上化」是低代码第一需求）+ 通用中 | 数据库 · Excel 导入导出 · 数据后台 |
| 3 | **检查整改闭环** | 巡检/安全检查记录 → 隐患登记 → 整改跟踪 → 汇总看板 | **央国企案例密度最高**（晋城供电/山西二建/金风科技/特科院，整改率 60%→95% 案例）+ 通用 5 平台类目重合 | 数据库 · 身份 · 状态流转 · 看板 · 消息通知 |
| 4 | **数据看板 + AI 解读** | 上传 Excel/选数据表 → 图表看板 + 管家解读结论 | 通用强（仪表盘为各平台核心件；美团 NoCode 明星场景「一个早上做完数据分析工具」）；**AI 差异化主打** | 数据库 · 模型 ·（衔接管家值守态） |
| 5 | **知识问答页** | 部门 FAQ/制度问答页，对接平台知识库 | AI 平台侧中强（传统低代码做不了）；**BiSheng 知识库资产的最短变现路径** | 知识库检索 · 模型 · 身份 |
| 6 | **轻审批 · 督办跟踪** | 用章/外出等申请登记，事项督办催办台账 | 通用最强（外出审批 19 万+/补卡 9 万+）+ 央国企中（督办案例）| 数据库 · 身份 · 状态流转 · 消息通知 |

边界说明：模板 6 承载**业务自建的轻流转与督办台账**；正式的组织级审批仍走平台审批中心，模板不与其重叠。

**PoC 任务集对齐**：Wave-0 引擎对测的 3 个任务 = 模板 1（信息收集上报）/ 模板 4（数据看板+AI 解读）/ 模板 5（知识问答页）——与方案 §4.2 一致。

### 1.2 二批候选（v3.1，按客户触发）

| 模板 | 缓入理由 |
|------|---------|
| 项目/任务跟踪 | 通用证据强，但央国企基层偏弱，且飞书系产品竞争激烈 |
| CRM-lite（客户跟进） | 通用市场热门第一，**但央国企基层自建清单中几乎不出现**——BiSheng 客户群以央国企/金融为主，留给通用企业客户触发 |
| 班组报工 / 生产小工单 | 制造类客户触发（烟草班组报工、扫码报工案例） |
| 在线考试 / 培训考核 | 央国企有实证（常州公交安规考试）但需题库组件 |
| 党建学习台账 | 央国企特色场景，但证据多来自厂商方案页且内容敏感——与首个客户共创后再模板化 |

### 1.3 明确不做（形态不适配或有专业壁垒）

- **值班智能排班**：约束求解问题非表单形态，且所有热门榜均无自建实证（值班表登记可归入台账模板）；
- **电力两票**（操作票/工作票）：强安全规程 + 专业厂商领域；
- **IoT/智慧工地/视频监测**：重硬件集成、GIS、视频流；
- **MES/ERP/WMS 级全流程系统**：长期迭代 + 系统集成产物，非对话生成可承载；
- **正式公文流转**：电子签章、密级管理，属 OA 域；
- **财务共享 / 业财一体化、对外监管报送**：重系统对接；
- **移动重采集型巡检**（扫码/GPS/离线）：首发的检查整改模板为 PC/H5 记录形态，产品文案须明示此边界、管理预期。

## 2. 关键证据与判断

**通用侧（模板市场实证）**：
- 业务人员自建应用的基本盘 = 「**收数—流转—记账—看数**」闭环：表单收集上报 + 轻审批 + 业务台账 + 自动看板。
- 「厂商想卖的」（CRM/进销存/MES 行业套件）≠「用户真在用的」（日报/走访/补卡类微应用，唯一有公开使用量的钉钉数据显示后者量级碾压）。
- AI 造应用平台（秒哒/美团 NoCode/扣子）在此之上新增一层「轻页面/小工具/问卷」，且知识问答成为传统低代码没有的新形态。

**央国企侧（场景特写）**：
- 与通用企业的差集内核 = 「**上级要查、必须留痕**」：记录-检查-整改类应用（巡检、隐患排查整改闭环、台账、层层填报、督办）案例密度远高于经营类；
- CRM/获客/增长类在央国企基层自建清单中几乎不出现；
- 招行（半年 2831 应用、59.4% 业务人员开发）验证强监管机构的全民开发可行性，但其应用构成未公开。

**取舍逻辑**：首发 6 类 = 通用与央国企证据的交集（1/2/3/6）+ BiSheng 的 AI 差异化独有项（4/5）；二批 = 单侧证据强或需特定客户触发；不做 = 形态不适配（求解/集成/移动重采集）或有专业壁垒。
