# 子租户挂载后的部门页面刷新修复

- 日期：2026-11-17
- 目标分支：`feat/3.1.0-beta1`
- 基线：`19a79c8130`
- 流程：SDD Guide §1 Hotfix；不修改 API、租户归属或权限契约。

## 问题与修复

`MountTenantDialog` 成功后调用组织页的 `handleTreeChange()`。这个通用刷新流程会重新请求所有已加载的树层级，再通过 `reveal(selectedDept.id)` 定位原选中部门。

挂载后，子租户根及其后代已不属于 Root 组织视图。`DirectoryRepository.scope()` 排除这些子树，`require_department()` 对跨越该边界的请求返回 21009。继续刷新旧子树和选中节点会让挂载成功后再弹出权限错误。

本次只调整成功后的页面状态衔接：

- 删除组织树正常/含归档两种模式的查询缓存；删除缓存不会主动刷新旧层级。
- 重新挂载组织目录内容，清除原选中部门、快照、搜索、展开节点、成员定位和弹窗。
- 从当前管理视图的根层级重新加载，自动选择新目录中的首个根节点。
- 取消或挂载失败不触发该流程；真实的目录刷新失败继续交由统一错误处理展示。

后端的租户边界校验保持原样。解绑和普通编辑继续使用原有刷新流程。

## 验证

`systemDepartmentsTenantMount.test.tsx` 使用真实 `useLazyDepartmentTree` 和 React Query，只替换视觉组件、弹窗完成事件及网络边界，覆盖：

1. Root → 部门 95 → 部门 96 已加载并展开，选中 95 后挂载成功：不再读取 95/96 的子层级、不再定位 95、不刷新其成员；清除含归档模式旧缓存；转到 Root。
2. 取消挂载保留原部门，不刷新目录。
3. 新目录为空时清除旧选中项，不展示旧成员。
4. 新目录加载失败正常报错，不恢复旧部门数据。

验证结果：

- `pnpm lint`、`pnpm typecheck`、`pnpm check-i18n` 通过。
