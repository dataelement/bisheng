# 自定义联网搜索 E2E 验证清单

**状态：未执行 / PARTIAL。** 以下是待执行步骤，不代表任何验收标准已通过。规格见 [spec.md](./spec.md)；settings、schema 和 test 管理 API 已实现，但尚未在隔离部署中端到端验证。

## 安全前置条件

- [ ] 仅在专用、可销毁的完整部署运行：独立数据库、Redis、搜索工具配置、密钥及工作进程，不与任何共享或生产环境共用。确认联网搜索配置的实际作用域；独立租户本身不能证明全局配置隔离。
- [ ] 使用仅属于该部署的全局超管、普通用户、租户管理员及第二租户账号；明确验证账号和目标部署，禁止使用默认凭据或现有真实密钥。
- [ ] 准备受控搜索服务和 OpenAPI 文档，按部署出站策略使用明确授权的测试 origin，勿使用环回、元数据或未授权网络。记录请求但不记录真实密钥；使用一次性合成 secret。提供可切换的成功、空数组、非数组、字段缺失、HTTP 错误及超时响应，以及有效/无效 URL。
- [ ] 准备 GET query 和 POST JSON body 示例，必需查询词、字符串/数字/布尔固定参数，结果含 title、url、snippet、source、siteIcon、datePublished。测试数据使用 `e2e-custom-web-search-` 前缀，不得包含真实业务内容。
- [ ] 记录隔离部署初始其他 provider 与网页读取设置，以及版本和测试时间；准备销毁整个测试部署。不要用批量删除、共享配置快照回写、清空 Redis 或恢复操作来清理共享环境。
- [ ] 变更配置及多用户并发测试仅串行执行，除专门的并发用例。结束时销毁整个隔离环境及一次性凭据；中断后同样销毁，不对共享环境执行清理。

## 管理端与配置

### AC-01、AC-02、AC-03、AC-13：配置与导入
- [ ] 在内置工具设置入口以专用全局超管打开联网搜索：确认已有 provider 仍可选且出现自定义选项。
- [ ] 分别粘贴文档及从受控 URL 导入 OpenAPI；选择搜索操作、查询词参数，配置无认证及 API Key（受支持位置），配置列表、标题、链接、摘要映射和不同类型固定参数。
- [ ] 对 GET query 和 POST JSON body 分别测试；在受控上游核对查询词及固定参数位置、类型和值。固定参数不得放密钥。
- [ ] 在工作台的另一设置入口重复导入、编辑和读取，确认两入口一致。

### AC-04、AC-05：预览与不保存
- [ ] 映射可选来源、图标、发布时间并用测试词执行；核对原始响应预览和映射结果的必填及可选字段。
- [ ] 在测试前记录已保存设置及 revision；修改未保存草稿并测试成功、失败各一次，重新读取设置，确认均未被写入或启用。

### AC-06、AC-10：校验、空结果和失败
- [ ] 分别尝试无效 OpenAPI、外部引用、路径参数、缺少必填配置、不支持的操作/参数、无效字段映射；确认指出原因且不能保存，原配置未变化。
- [ ] 断开受控上游，仅保存静态有效配置，确认无需在线测试也可保存；恢复上游后继续。
- [ ] 受控服务返回空数组，确认测试与运行显示成功空结果；分别返回非数组、缺失必填映射、HTTP 错误、超时，确认明确失败而非伪装为空结果，失败不改变已保存配置。

### AC-07、AC-11：密钥和其他设置
- [ ] 保存带一次性合成 API Key 的有效配置，刷新并从两个入口重开：配置保留，密钥不以明文显示。检查设置读取、列表及详情的完整响应，不得包含该 API Key 明文或用于存储该 API Key 的密文；在隔离环境中通过受控方式比较已存密钥密文，不将任何密钥或密文写入测试证据。beta2 设置响应不再包含 operation proof；搜索 API Key 仍只返回配置状态。
- [ ] 分别保留、替换密钥并重新读取；用受控上游确认实际使用预期密钥。切到无认证并清除密钥，确认其不再用于请求；必需认证却无有效密钥时拒绝保存。
- [ ] 在隔离环境切换 provider、保存并切回；比较其他 provider 所有原有配置及网页读取设置，确认未改变。并发两份草稿，先保存一份，再保存旧 revision，确认冲突且没有部分覆盖或密钥变更。

## 执行与引用

### AC-08、AC-09、AC-10、AC-13：实际搜索
- [ ] 保存并选择自定义 provider，在工作台、工作流和 Linsight 各发起搜索。受控上游确认收到查询词、固定参数及正确认证；调用方收到映射的标题、摘要、URL 和可选字段。
- [ ] 对有有效 HTTP(S) 链接及可用内容的结果检查网页来源和引用，刷新或重新打开历史记录后确认引用仍可用；缺失或无效 URL 不得成为有效网页引用。
- [ ] 在每个实际调用路径验证空数组与请求/映射失败可区分；测试一个受控错误不应静默回退其他 provider。

## 权限、隔离和安全

### AC-12：授权与脱敏
- [ ] 分别用全局超管和当前租户管理员验证本租户配置读取、保存、导入和测试；用匿名、普通用户、其他租户管理员及数据范围收窄身份直接调用对应 API，确认服务端拒绝而非仅隐藏按钮。普通工具 owner/manager 授权不授予配置能力。对错误 ID、非联网搜索工具、已删除对象和其他租户对象验证拒绝；不得泄露其他租户存在性或密钥。
- [ ] 在第二个隔离租户重复读取、配置、测试及实际使用；确认仅访问有权使用的配置和凭据。若工具共享，按既有授权验证，不假设共享会自动授予管理权限。
- [ ] 用合成 secret 让受控上游在嵌套 JSON 的键和值、URL 编码及 Base64 值、响应头和错误正文中回显。检查预览、映射结果、错误、日志、浏览器网络响应及前端状态无该 secret 或设计要求覆盖的编码形式；不在测试记录复制密钥。
- [ ] 验证导入、测试和运行对未授权私网、重定向、混合 DNS、重绑定及不安全地址按设计拒绝；需要受控网络基础设施，不以访问真实元数据服务验证。
