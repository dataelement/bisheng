# 复制、元数据与模型重建调整：实施与审查

日期：2026-11-18。当前修复分支 codex/3.1.0-beta1/knowledge-ux-task-diagnostics-20261118；本批基线 7a55762bc1。用户明确确认按调整方案实现，修正了上一批“全失败不切换模型”及“权限/索引完全交给后台初始化”的策略。本轮不合并、推送或部署。

## 结果与边界

1. 纯新增元数据字段使用 schema CAS 和零文件完成回执，不遍历历史版本、不启动索引任务。为检测旧同名键，按200条有界读取文件 user_metadata 标量；有 SQL 残留时只处理受影响文件。改名、删除和修改值仍走索引同步。保留同事务未提交文件/版本写入检查，已提交的无关模型变化不使纯新增失败。
2. 复制确认持久创建目标/配置/目录/版本/授权并初始化空索引后，目标即正常可用。文件异步逐项处理，失败不遮挡目录或侧栏、菜单。复制输入先保存为 MinIO JSONL 包、验证身份头/字节数/SHA256，登记 artifact 后才发布独立输入检查点；默认重试不读取源内容。用户明确选择“按当前版本重新复制”才重新授权读取逻辑文档当前主版本，复用目标文件/版本/权限 ID。其选择纳入幂等摘要，不能用同一请求键改变含义。
3. 模型探测在释放 SQL 准入锁后实际调用，确认时再次探测及重验原计划；成功后先激活新模型，再逐文件重建。SPACE 和旧普通文档 Worker 均使用新的 Milvus 集合，保留 ES 分段、原文和人工 Chunk。全失败或可收尾的全局失败结束重建状态，保留新模型和失败文件，支持原任务失败项重试；从未假称自动回滚旧模型。
4. 原集合在同一模型变更事务记录到独立 knowledge_vector_cleanup 表，由标准建表发现流程创建，不变更现有列。现有 Beat 分派清理，等待原 writer 汇合且全局无资源再使用该物理集合后才删除；传输失败保持待重试，不依赖在线 embedding。清理记录独立于空间根记录，空间删除后仍可恢复清理。
5. 移动保护保留；活动复制的删除保护保留。源空间普通修改不再因整个复制而锁定，源输入已经独立后可以释放依赖；失败复制目标删除后也释放源依赖。迟到复制仍校验目标内容、任务租约和删除围栏，不覆盖或复活用户后来修改/删除的文件。

未扩展为全局损坏修复：纯新增的残留判定以 SQL 文件元数据为依据，不扫描仅留在 ES/Milvus、且 SQL 和任务账本均已丢失证据的历史孤立脏键。此类存量数据需独立核对/维护。持续 R2/权限控制面故障时仍应安全保留操作等待恢复，不绕过所有权/CAS 强行发布。

复制输入包为额外持久对象，登记在现有 artifact 清理台账，随所属文件/空间删除清理；本批没有改动存储计费/配额算法。初始权限/索引初始化依然可能耗时或失败，其未完成状态不能对用户伪装为可用。
