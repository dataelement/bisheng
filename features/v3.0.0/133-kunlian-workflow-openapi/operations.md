# F133 异常处置边界与上线门禁

本文件是受控操作说明，不是已执行记录。禁止根据本说明直接修改真实库、OpenFGA或秘密；执行需环境管理员另行授权。

## 1. 授权操作持续 PENDING

- 保留原接入方、外部租户、实际用户、workflow_id、服务端内部操作ID和operation_ref；客户端不提供Idempotency-Key，重复HTTP不承诺查回，不能盲目重试。
- 授权PENDING只能由平台凭operation_ref核对F048 ledger及权限投影状态，不能在同一HTTP请求中查回；若F048 ledger已FINALIZED，则按原生效修订返回APPLIED。
- 若ledger仍投影中或失败，复用既有F048补偿/恢复流程，不能直接写OpenFGA tuple或把receipt强制改成APPLIED。
- 若昆联receipt已claim但F048 ledger不存在，存在“意图已提交、业务尚未执行”的崩溃窗口；当前实现保持PENDING，不自动再执行。需核对审计和业务当前授权后，由受权平台维护人员决定恢复原意图或终结；本期未提供自动修复端点，不得宣称该窗口可自动恢复。

## 2. 审计 INTENT 未完成

- 意图持久化失败时业务准入拒绝；客户端不得据此承诺安全重试或通过重复HTTP查回。
- 业务已发生而finish失败时保留INTENT并告警；不能据此认定未执行或向业务声称已回滚。
- 按trace_id、workflow/session/operation引用及服务端内部操作ID核对实际结果，保留核对证据；不得从缺FINISHED推导重复提交安全。
- 审计不包含Key明文、Token、原始body/query；故不能以审计记录重放敏感业务输入。

## 3. Key撤销、轮换与运行处置

- 业务HTTP操作人Query仅为 `user_account`，精确匹配毕昇 `user_name`；不再要求外部租户/用户Query。租户必须从有效成员关系唯一解析，无成员或多租户歧义均拒绝，不回退默认租户。
- 每次HTTP与Worker边界从权威凭据、映射和用户资格重验；账号入口不绕过Key绑定连接和内部用户/租户映射。Key的 `tenant_ids` 仍限定外部租户范围，不得删除或放宽为所有租户。
- 原Key撤销后，排队/等待恢复不推进；进行中外部节点仅尽力停止，不能承诺撤销已发生副作用。
- 同一接入方新Key可按相同实际用户的当前资格查询/取消旧运行；原Key撤销后不接受其等待恢复答案。不通过修改原运行identity实现复活。
- 运行仍有截止和有界补偿。权限依赖暂不可确认不应误当成功，待依赖恢复或截止收敛。
- integration_id应由平台维护且绑定同一可信昆联连接，不能为不同接入方复用同名字。

## 4. 上线前必须验证

- Python3.11、MySQL和DM8真实锁/CAS/唯一约束竞争。
- 正式权限Catalog/OpenFGA的普通用户允许/拒绝、授权投影及撤权。
- 独立API/Worker/Broker/Beat进程的投递失败、恢复、取消与补偿。
- 真实昆联目录状态/映射/身份与两租户隔离。
- 新表升级按项目建表机制执行，不用HTTP入口临时建表，不写迁移数据回填。
- 资源限额与清理以当前实现及验证记录为准，不能把仅有请求速率控制当作执行并发配额。

完整前后清理与验收步骤见 [e2e-checklist.md](./e2e-checklist.md)。
