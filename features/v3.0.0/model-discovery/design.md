# 技术设计

## 功能基线

PR 分支 `codex/model-discovery-pr` 以官方 `upstream/feat/3.0.0` 的 `d8326651b` 为当前集成基线。3006 演示分支 `codex/model-discovery-3006` 中 `b81a5ac4b..c20844e54` 的模型功能完整提取到本分支，保留官方模型名称去空白工具、10803 部分初始化失败提示、服务商翻译元数据、名称状态校验、连接字段提示、Minimax 原生搜索和参数示例草稿。其他 DSH、灵思和知识空间功能留在原交付中。产品规则见 prd.md，历史环境证据见 deployment.md。

## 模型发现接口

新增 `POST /api/v1/llm/models/discover`，复用模型管理的管理员身份。编辑已有连接时，LLMService 复核访问和编辑权限，通过 JsonFieldMasker 复用脱敏密钥；供应商类型必须与已保存连接一致。当前服务的 strip_config_whitespace 与代理空值处理继续保留。

发现服务支持 OpenAI 兼容、Anthropic 分页、Ollama 与 Xinference 列表协议。限制单页 4 MiB、5000 个模型、50 页与总时限 55 秒。分页继续请求相同已验证源地址，重定向按业务错误返回。允许企业内网推理地址，校验 HTTP/HTTPS、URL 凭据及云元数据地址。上游正文留在上游，错误返回固定原因码。

类型按供应商元数据、型号族规则、人工确认的顺序处理。型号族按能力族匹配通用版本语法，图像/视频保留为待适配；自定义别名由管理员选择。供应商列表的可见性与当前实际运行适配能力分别表达。

## 连接与配置状态

API 层位于 controllers/API，ModelDiscovery 管理查询、筛选和选择草稿。连接版本递增后清空缓存并废弃旧请求；关闭弹窗后的迟到响应可以进入该连接缓存，同时保持关闭状态。关闭后重新打开保留本次选择，确认添加后收起；全选只影响当前可选结果，跨筛选选择保留。

ModelItem 按稳定模型项维护展开状态；手动新增空模型默认展开。父页按 ID 更新名称、类型与 config。名称修改保留同类型参数，类型变更初始化配置；新增与已有模型共同经过最终保存。

展开区使用可换行表单，名称占弹性宽度，类型固定短框，参数操作区为各行一致的宽度。搜索位置单独保留，使 LLM 与 Embedding 等行的类型和高级参数入口纵向对齐。类型在三种语言中统一为 LLM、Embedding、Rerank、ASR、TTS。

新文案显式读取 model namespace，配置页同时声明 bs 与 model。三语言检查使用实际资源且默认 namespace 保持 bs，覆盖发现、选择、类型、计数、错误及参数提示，防止再次显示原始 key。

## 高级参数与旧值兼容

modelAdvancedParams 负责编辑器展示与保存：打开时将有效旧 config.max_tokens 合入高级 JSON，保持旧字段高于同名高级值的既有优先级；Ollama 映射为 num_ctx，其余语言模型使用 max_tokens。确认编辑后移除旧字段，保存 user_kwargs 及其他 config；后端 DAO 继续以完整 config 更新。打开或取消仅维护草稿。

API 或历史版本保存为对象的 user_kwargs 先转换为编辑器 JSON 文本，确认编辑后保存为字符串；读取兼容与后台双形态参数解析一致。高级示例通过复制模板生成，公共模板保持原值。保存校验要求 JSON 对象，既有损坏文本展示原文以便修正。星火原来构造合并参数后返回基础 params，现返回 user_kwargs，确保高级值进入客户端。实例运行参数与连接参数保留原有优先级。

联网搜索沿用供应商原生能力，并提供用途提示。纳入并行分支 45400d5e9 的腾讯参数恢复，将开关映射到 extra_body.enable_enhancement；依据为[腾讯官方 OpenAI 兼容说明](https://cloud.tencent.cn/document/product/1729/111007)。开关按现有供应商范围显示，型号是否支持由上游能力决定。

## 存量 Token 升级

产品合同见 prd.md，运维步骤见 upgrade.md。model_token_config_upgrade 提供 Python JSON 变换及统一事务：在明确租户范围下锁定语言模型记录，预检全部关联和旧值，成功后以全新私有备份记录前后配置，统一写入 config 并回读确认。配置损坏或关联异常时整批停止。

恢复时核对模型、租户及服务标识，并要求当前配置等于升级后记录；已恢复项幂等跳过，后续编辑及新增记录受到保护。JSON 在 Python 中转换，服务端数据维护通过独立 CLI 执行，结构升级继续由目标版本 Alembic 管理。

脚本只写模型 config，模型和服务商的 ID、状态、权限、默认引用与每日配额字段保留。维护窗口结束后重启 API、Worker 和 Linsight，刷新进程内缓存；保留当日 Redis 调用计数。新安装及已迁移模型按现有高级参数使用，前端旧字段兼容路径覆盖分阶段升级和失败恢复。

## 每日调用限制与交付检查

本 PR 保持每日限流工具、模型和服务商结构、创建/更新中的配额字段赋值逻辑。前端 saveData 继续携带 formData.limit_flag 与 formData.limit。同步和异步检查覆盖关闭、阈值、同服务商共享、服务商隔离与日期分桶；真实组件检查覆盖回填和保存。

验证结果、官方基线问题对比及真实环境边界见 verification.md。发布时按当前环境构建完整候选，只合入本功能文件及语言键，保护当前 client、其他后端能力和业务配置。
