# Requirements — F062 门户课程管理与播放进度

| 属性 | 值 |
|------|----|
| Feature ID | F062 |
| 状态 | Media Compatibility Fix Complete / Live Verification Pending |
| 目标版本 | v2.6.0 |
| Owner | BiSheng + 首钢知识门户 |
| 最后更新 | 2026-07-19 |

## 1. 背景

首钢知识门户首页的“专业课程 · 岗位赋能”模块目前读取前端静态 mock 数据，课程详情页也使用计时器模拟播放，后台没有课程配置入口，无法交付真实课程内容。需要在门户管理端提供课程配置能力，并由 BiSheng 统一持久化课程元数据、视频对象和登录用户的播放进度。

本 Feature 将课程统一建模为“课程目录 + 一个或多个课程视频”。单视频课程是仅包含一个视频的目录，多视频课程是包含多个有序视频的目录，不再使用额外的单课/系列课类型分支。公开详情页根据已启用视频数量自适应展示：一个视频时隐藏目录，多个视频时显示目录。

## 2. 目标

- 管理员可以配置课程、标签和多个视频，并控制启用状态、首页展示与顺序。
- 上传视频进入 BiSheng 持久化 MinIO，外链视频使用浏览器可直接播放的媒体地址。
- 访客和登录用户均可浏览、播放已发布课程；登录用户可跨会话续播并显示完成状态。
- 删除、替换、禁用等生命周期操作具有明确的数据和文件语义。
- 数据结构、迁移与查询同时兼容 MySQL 和 DM8，并遵守现有租户隔离规则。

## 3. 非目标

本期不包含以下能力：

- 字幕、副标题、课程封面和视频封面；
- 分类树、搜索、筛选和分类导航；
- 课程附件、考试、证书、评论；
- 视频转码、切片或自适应码率；
- 访客播放进度持久化；
- 将现有 5 条前端 mock 课程迁移为正式数据；
- 对单个课程建立 OpenFGA/ReBAC 授权关系。

## 4. 角色与术语

| 名称 | 定义 |
|------|------|
| 门户管理员 | 已登录且具备门户后台管理员身份的用户，可维护本租户课程 |
| 门户用户 | 已登录门户的普通用户，可读取本租户公开课程并上报本人进度 |
| 访客 | 未登录用户，仅可读取和播放公开课程，不持久化进度 |
| 公开课程 | `enabled=true` 的课程；首页还需同时满足 `show_on_home=true` |
| 可播放视频 | `enabled=true`、来源配置完整，且所属课程为公开课程的视频 |
| 上传视频 | `source_type=upload`，媒体对象存储在 BiSheng 持久化 MinIO |
| 外链视频 | `source_type=url`，地址是浏览器 `<video>` 可直接播放的媒体 URL |

## 5. 功能需求

### REQ-001 课程与目录管理

门户管理员必须能够维护当前租户的课程目录、标签和视频列表。

#### Acceptance Criteria

- **AC-001-01** 管理端支持课程列表、新增、编辑、删除、启用/停用和排序；课程字段至少包含稳定 ID、课程名称、讲师、所属单位、描述、启用状态、是否首页展示、排序值、创建时间和更新时间，不包含副标题字段。
- **AC-001-02** 每个课程支持零到多个标签；标签包含显示文本和显示类型，显示类型仅允许 `domain`、`level`、`gray`，标签按课程内顺序返回并随课程整体保存。本期不提供独立标签实体、标签库或标签查询接口。
- **AC-001-03** 每个课程统一包含有序的 `videos[]`。草稿课程允许暂时没有视频；公开课程至少包含一个已启用且来源完整的视频。
- **AC-001-04** 视频支持新增、编辑、删除、启用/停用和排序；字段至少包含稳定 ID、标题、来源类型、来源定位信息、时长秒数、启用状态、排序值、创建时间和更新时间。
- **AC-001-05** 当课程不满足 AC-001-03 的公开条件时，服务端拒绝将其启用；课程已启用时，删除或停用最后一个可播放视频也必须被拒绝，管理员需先停用课程。两类拒绝均返回稳定、可识别的业务错误。
- **AC-001-06** 管理页面对删除课程、删除视频、替换上传文件、修改外链地址和切换来源类型执行二次确认；取消确认不得发起变更请求。
- **AC-001-07** 课程与视频部分更新必须区分“字段未提交”和“字段显式为 `null`”：未提交字段保持原值，所有不可空业务字段显式为 `null` 时返回参数校验错误且不修改数据。外链视频不得通过部分更新把正整数时长改为 `0` 或空值，已发布课程的可播放约束必须保持成立。

#### P1 回归记录 BF-062-01

- 当前错误行为：`CourseUpdate` 与 `VideoUpdate` 接受显式 `null`；部分字段在 flush 时触发 500，`duration_seconds=null` 还会被转换并持久化为 `0`。
- 复现路径：向课程更新接口提交 `{"name": null}`，或向已启用外链视频更新接口提交 `{"duration_seconds": null}`。
- 期望行为：门户 BFF 与 BiSheng 均在 schema 边界拒绝显式 `null`，字段省略仍保持部分更新语义；领域服务不得将空时长转换为 `0`。
- 影响范围：仅课程/视频更新请求校验，不改变创建接口、既有合法数据、表结构或公开读模型。

### REQ-002 视频来源、校验与存储

系统必须支持上传文件和直接媒体外链两种视频来源，并仅接受浏览器兼容格式。

#### Acceptance Criteria

- **AC-002-01** 上传视频仅接受以下实际容器与编码组合：带有效 `ftyp` 的 MP4/QuickTime ISO-BMFF + H.264（若有音轨则每条音轨必须为 AAC 或 MP3），或 WebM + VP8/VP9（若有音轨则每条音轨必须为 Vorbis 或 Opus）；无音轨视频允许。服务端必须使用文件签名和媒体探测结果校验实际容器、主视频编码和音频编码，不得只校验扩展名或请求 MIME。`major_brand=qt  ` 的 QuickTime 文件只有在满足上述 H.264 + AAC/MP3 轨道矩阵时才允许；3GP/3G2 等其他 ISO-BMFF 变体仍须拒绝。
- **AC-002-02** 单个上传文件最大为 1 GiB（1,073,741,824 字节）；超过限制时在文件写入 MinIO 前终止接收并返回明确错误。AVI、MKV、3GP/3G2 以及不符合 AC-002-01 的文件必须被拒绝，系统不执行转码或重新封装。
- **AC-002-03** 校验通过的上传视频存入 BiSheng `bisheng` 持久化 MinIO bucket；数据库只持久化服务端生成的对象名及媒体元数据，公开读接口按请求生成有时效的播放地址，不扩展 bucket 匿名读策略。
- **AC-002-04** 上传视频时长由服务端通过 `ffprobe` 自动获取且不可由管理员覆盖；外链视频时长由管理员填写，必须为正整数秒。
- **AC-002-05** 外链仅允许绝对 `http` 或 `https` URL，并应是浏览器媒体元素可直接播放的 MP4/WebM 资源；不得接受 iframe、站点播放页、`javascript:`、`data:` 或相对地址。管理端提交前必须以当前浏览器 `<video>` 的 `loadedmetadata`/错误事件完成可播放预检；服务端只做安全的 URL 结构校验，不下载外链媒体进行探测、转码或持久化。
- **AC-002-06** 课程总时长不单独存储，所有读模型均按当前已启用视频的 `duration_seconds` 求和；增删、启停、替换或调整视频后返回值同步变化。
- **AC-002-07** 上传或替换上传文件失败时，管理端必须在当前上传操作区域内可见地展示上游 `status_message`。`25005` 保持稳定，但服务端应返回安全、具体且可操作的原因，例如“检测到 HEVC/H.265 视频编码。请转换为 H.264”或“检测到 3GP 容器。仅支持兼容的 MP4、QuickTime 或 WebM”；不得仅将错误放在可能已滚出视口的页面顶部，替换弹窗内的错误不得被遮挡。前端不得展示 `data.exception`、文件路径、探测原始输出或堆栈等内部信息。
- **AC-002-08** 兼容媒体中的字幕、时间码、数据、metadata、attachment 和 `attached_pic` 封面等辅助轨不得导致整个上传被拒绝；辅助轨不参与主播放编码判定。文件必须恰有一个非 `attached_pic` 主视频轨；缺少主视频轨或包含多个主视频轨时仍返回 `25005`。H.265/HEVC、ProRes、MPEG-4 Visual 及其他未列入 AC-002-01 的主视频/音频编码继续被拒绝，系统不执行转码。

#### P1 回归记录 BF-062-03

- 当前行为：上传接口错误已被解析为 `CourseApiError`，页面也进入失败分支，但错误只渲染在课程管理面板顶部；普通上传区位于滚动容器下方时用户看不到提示，替换上传时面板顶部提示还会被弹窗遮挡。
- 期望行为：普通上传失败时在普通上传区域内提示，替换上传失败时在替换弹窗内提示，并直接复用后端返回的安全业务文案 `status_message`。
- 最小复现：在课程管理页上传一个容器或编码不受支持的视频，接口返回 `status_code=25005` 后，当前操作区域没有可见错误提示。
- 影响范围：仅影响管理端本地文件上传与替换上传的错误反馈，不改变上传协议、课程数据模型、BFF 或后端媒体校验逻辑。

#### 媒体兼容性回归记录 BF-062-06

- 当前错误行为：BiSheng 只检查 `ftyp` 的 major brand 是否命中有限 `_MP4_BRANDS` 集合，并拒绝任何非音视频流；同时 MP4 音轨只允许 AAC。结果是主视频为 H.264、浏览器可播放，但使用其他合法 MP4 brand、MP3 音轨或携带字幕/时间码/metadata/封面辅助轨的文件也统一返回 `25005`。
- 期望行为：按 AC-002-01/08 扩大已确认兼容矩阵，只使用真实容器与主播放轨判定可播放性；保留 MOV、伪容器和不支持主编码的拒绝行为，并以安全动态 `status_message` 说明检测到的容器或编码。
- 最小复现：构造 `ftyp` major brand 不在旧白名单但 `ffprobe` 确认为 MP4 的 H.264 文件，或上传 H.264 + MP3、H.264 + AAC 且带字幕/data/`attached_pic` 的 MP4；旧实现均抛出 `PortalCourseMediaUnsupportedError`。
- 影响范围：仅修改 BiSheng 上传媒体探测/错误文案及相关跨层契约测试；不修改上传 API、BFF 路由、课程 DTO、数据库、MinIO 对象结构、转码能力或播放进度。

#### QuickTime 兼容性回归记录 BF-062-07

- 当前错误行为：文件 `/Users/wenruli/Desktop/downloadVideo_8.mp4` 的文件名后缀是 `.mp4`，实际 `major_brand=qt  `；其唯一主视频轨为 H.264 High/yuv420p，音频为 AAC-LC，目标浏览器可以直接播放，但 `_detect_container` 在运行轨道校验前仅凭 `qt  ` 品牌返回 `25005`。
- 期望行为：QuickTime `qt  ` 文件不再被容器品牌单独否决；只有唯一 H.264 主视频轨且所有音频轨为 AAC/MP3 时才允许，并沿用现有 `.mp4`/`video/mp4` 存储输出。不满足轨道矩阵、3GP/3G2 或伪容器仍按既有安全错误拒绝。
- 最小复现：以有效 `ftypqt  ` 文件头配合 `ffprobe` 的 H.264 + AAC 结果调用 `PortalCourseMediaService.probe()`；旧实现返回“检测到 MOV 容器”，真实样本同样稳定复现 `status_code=25005`。
- 影响范围：仅修改 BiSheng 容器候选识别、媒体回归测试和 F062 规格；不修改上传 API、数据库、MinIO 路径结构、前端、BFF、转码/重新封装或播放进度。

### REQ-003 公开课程展示

门户首页、全部课程页和详情页必须读取真实配置，并对访客开放。

#### Acceptance Criteria

- **AC-003-01** 首页课程模块仅返回 `enabled=true AND show_on_home=true` 的课程，不设置固定条数上限。
- **AC-003-02** `/course` 页面返回当前租户全部 `enabled=true` 的课程，本期不展示搜索、筛选或分类导航。
- **AC-003-03** 首页与全部课程页使用同一课程顺序：`sort_order ASC, created_at DESC, id ASC`；首页不得维护第二套排序值。
- **AC-003-04** 课程详情只返回已启用视频，并按 `sort_order ASC, created_at ASC, id ASC` 排列。停用课程的公开列表和详情均不可见，按不存在处理；停用视频不出现在公开响应中。
- **AC-003-05** 访客和登录用户均可读取课程列表、详情与播放地址。访客不因点击课程被强制跳转登录，且每次从 0 秒开始播放。
- **AC-003-06** 上线后不迁移或回退使用现有 5 条 mock 课程；没有后台配置时，相关页面以空状态呈现。

### REQ-004 课程播放体验

课程详情页必须使用真实媒体播放器，并以课程目录呈现多个视频。

#### Acceptance Criteria

- **AC-004-01** 详情页展示课程名称、标签、讲师、所属单位、描述和总时长，并使用浏览器原生兼容的视频播放能力播放选中视频。公开响应只有一个已启用视频时隐藏视频目录并直接播放该视频；有两个及以上已启用视频时展示有序视频目录。
- **AC-004-02** 单视频课程与多视频课程使用同一页面和 `videos[]` 数据结构，不增加课程类型字段；单视频模式自动选择唯一视频，多视频模式默认选择排序第一的可播放视频，切换目录项后播放对应视频。
- **AC-004-03** 播放器以真实 `<video>` 作为媒体内核，但使用与旧版课程页视觉一致的自定义舞台和控制条，不显示浏览器原生 `controls`。控制条必须真实支持播放/暂停、前后 10 秒、当前时间/总时长、进度拖动、倍速、音量/静音和全屏；浏览器拒绝播放、全屏失败或媒体加载失败时必须提供可见反馈，不得伪造播放或完成状态。
- **AC-004-04** 多视频模式下，登录用户目录项必须区分“已学完”“正在播放”“已暂停”“学习中”“未播放”五种状态：完成项使用绿色样式；实际播放或播放后暂停的当前项使用蓝色选中样式；部分学习且非当前项显示“学习中 · 已学 MM:SS/HH:MM:SS”；无进度项使用灰色样式并显示视频时长。单视频模式继续隐藏目录，并在播放器状态区域显示对应个人学习状态。
- **AC-004-05** 登录用户的目录头明确显示“已学 X · 未学 Y”；“已学”仅统计 `completed=true`，“未学”统计其余可播放视频并包含部分学习项。完成事件本地生效后统计立即更新。访客目录头只显示“登录后可记录学习进度”，不得显示伪造的个人统计数字。
- **AC-004-06** 页面初次加载、视频切换或新媒体尚未实际播放时，当前选中项按其持久化学习状态展示，不得仅因被选中就显示“正在播放”或“已暂停”。只有真实 `playing` 事件进入“正在播放”；已实际播放的视频触发非 ended 的 `pause` 后进入“已暂停”；`ended` 后立即进入完成状态。
- **AC-004-07** 目录项的选中状态与播放/学习状态必须解耦。任意选中项均使用蓝色背景、蓝色编号和蓝色加粗标题；状态图标与文案仍按已学完绿色、学习中黄色、未播放灰色、正在播放/已暂停蓝色展示。点击目录项只改变选中视频，不得伪造正在播放或已暂停状态。
- **AC-004-08** 单视频和多视频详情页共用同一课程信息卡，并恢复旧版视觉结构：展示标签、课程标题、课程时长、主讲、所属单位、更新日期和描述，不展示副标题。更新日期优先取 `updatedAt`，为空时回退 `createdAt`，有效值格式化为 `YYYY-MM-DD`，无有效值显示 `—`；缺失主讲或所属单位显示 `—`，空描述显示“暂无课程描述”。桌面端四栏展示统计，`720px` 以下按两列换行且不得横向溢出。

### REQ-005 登录用户播放进度

系统必须按租户、登录用户和视频保存唯一一行可覆盖的播放进度。

#### Acceptance Criteria

- **AC-005-01** 进度记录以 `(tenant_id, user_id, video_id)` 唯一；字段至少包含 `progress_seconds`、`completed`、`completed_at`、创建时间和更新时间。重复上报更新原行，不新增历史明细行。
- **AC-005-02** 登录用户打开课程详情时一次加载该课程所有可播放视频的本人进度。未完成视频被选中时从保存位置续播；服务端返回的秒数须限制在 `[0, duration_seconds]`。
- **AC-005-03** 播放期间客户端每 10 秒上报一次当前位置，并在暂停、切换视频、页面进入隐藏状态和离开页面时追加一次尽力上报；暂停或未开始播放时不运行周期计时器。
- **AC-005-04** 未完成记录允许在用户向后拖动后以更小的 `progress_seconds` 覆盖旧值；服务端不得强制使用最大历史进度。
- **AC-005-05** 收到视频原生 `ended` 事件时客户端立即上报 `completed=true`。服务端首次完成后固化完成状态和完成时间，并忽略该行后续所有进度上报。
- **AC-005-06** 已完成视频再次播放时从 0 秒开始且客户端不再上报该视频；重播期间目录项临时按真实播放事件显示“正在播放”或“已暂停”，但仍计入“已学”数量。切换离开或播放结束后，该目录项恢复绿色“已学完”状态。
- **AC-005-07** 访客不调用进度读写接口；任何未认证的进度请求必须被拒绝，且不得生成匿名进度记录。

### REQ-006 删除、替换与补偿

课程元数据、进度记录和 MinIO 对象必须具有一致且可恢复的生命周期语义。

#### Acceptance Criteria

- **AC-006-01** 删除视频时同步删除该视频全部用户进度；删除课程时同步删除其全部视频、标签及所有后代进度。该删除是永久操作，不提供回收站。
- **AC-006-02** 停用课程或视频只改变可见性，不删除元数据、进度或上传对象；重新启用后原进度继续有效。
- **AC-006-03** 修改课程元数据、视频标题、外链时长、启用状态或排序不清除进度；读取时仍按当前视频时长截断返回秒数。
- **AC-006-04** 替换上传文件、修改外链 URL 或切换 `source_type` 时，必须清除目标视频的全部用户进度；仅保存其他字段不得清除进度。
- **AC-006-05** 上传文件替换必须先完成新文件校验与持久化，再提交视频来源变更和进度清理；只有数据库提交成功后才删除旧对象。新文件校验、上传或数据库提交失败时，旧来源与旧进度保持可用。
- **AC-006-06** 上传对象的物理删除在数据库提交后执行。同步删除失败时必须记录持久化清理任务并自动重试，避免永久孤儿对象；外链删除只处理元数据，不发起远端删除。
- **AC-006-07** 若新对象已上传但后续数据库提交失败，新对象也必须进入同一持久化清理机制；清理重试必须幂等，且不得删除仍被有效视频记录引用的对象。
- **AC-006-08** 删除或来源替换事务提交成功后，即时 Celery 投递仅作为尽力加速路径。broker 连接或消息编码失败不得把已经提交的业务操作转换为 500；持久化清理任务必须保留为待扫描状态，并由全局恢复扫描自动补投。投递失败必须记录 `tenant_id`、`job_id` 和异常类型，非 broker 类编程异常不得被静默吞掉。

#### P1 回归记录 BF-062-02

- 当前错误行为：删除/替换已完成数据库提交后直接调用 `apply_async`；broker 不可用时异常冒泡，接口返回 500，但业务数据事实上已经改变。
- 复现路径：创建包含上传视频的课程，在 Celery broker 不可用时删除课程、删除视频或替换来源。
- 期望行为：已提交操作返回成功，清理任务继续由 beat 扫描恢复；日志可定位租户、任务和异常类型。
- 影响范围：只调整提交后的即时投递失败语义，不改变数据库事务、MinIO 删除规则、重试间隔或清理任务状态机。

### REQ-007 认证、授权与租户隔离

所有管理、读取和进度写入必须遵守现有门户会话及 BiSheng 多租户边界。

#### Acceptance Criteria

- **AC-007-01** 管理 BFF 接口必须验证门户管理员会话，BiSheng 管理接口必须再次验证管理员身份；普通登录用户和访客不能执行课程写操作。
- **AC-007-02** 公共 BFF 使用已配置的 BiSheng 服务身份读取当前门户租户数据；公共响应不得泄露其他租户课程、MinIO 对象名、内部存储凭据或管理员字段。
- **AC-007-03** 进度 BFF 必须使用当前门户会话对应的 BiSheng 用户令牌调用下游；服务端从认证上下文取得 `tenant_id` 和 `user_id`，不得信任请求体传入的身份字段。
- **AC-007-04** 新增数据表必须包含 `tenant_id` 并接入 BiSheng 自动租户过滤；所有唯一约束、查询、更新、删除和清理任务均包含租户边界。
- **AC-007-05** 上传对象名由服务端生成并与用户文件名解耦；临时文件名、日志和错误响应不得暴露路径、访问密钥或原始异常堆栈。
- **AC-007-06** 外链 URL 只作为媒体 `src` 使用并进行协议和长度校验；前端不得将其拼接为 HTML，也不得允许脚本协议。

### REQ-008 兼容性、可运维性与发布

实现必须可在现有部署链路内稳定处理大文件，并具备可诊断能力。

#### Acceptance Criteria

- **AC-008-01** Alembic upgrade/downgrade、模型与查询同时兼容 MySQL 和 DM8；不得使用仅单一数据库支持的枚举、UPSERT、部分索引或级联语法。
- **AC-008-02** 门户 Nginx、BFF multipart 转发和 BiSheng 接收链路支持 1 GiB 文件及合理 multipart 开销，并配置显式上传/读取超时；业务层仍以 AC-002-02 的 1 GiB 精确上限为准。
- **AC-008-03** API 使用统一响应结构和 F062 专属错误码，至少区分：课程不可发布、媒体过大、媒体格式不支持、外链无效、课程/视频不存在和来源替换失败。
- **AC-008-04** 上传、媒体探测、进度写入、数据库删除和对象清理失败均输出带请求/资源标识的结构化日志；日志不得包含令牌、密钥或完整本地路径。
- **AC-008-05** 本 Feature 不新增转码运行时依赖；复用 BiSheng 镜像中已有 `ffprobe`。若运行环境缺少该命令，上传必须明确失败且不产生有效视频记录。
- **AC-008-06** 发布采用“先迁移和后端、再 BFF、最后前端”的兼容顺序；回滚前端或 BFF 不得要求删除课程数据，数据库 downgrade 仅在明确接受永久数据丢失时执行。
