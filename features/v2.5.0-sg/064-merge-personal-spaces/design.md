# 合并设计

Status: `confirmed`

新增 scripts/merge_personal_knowledge_spaces.py 和 test/scripts/test_merge_personal_knowledge_spaces.py, 补 README。本目录 spec.md/requirements.md/design.md/tasks.md/verification.md 为交付记录。

根据用户最终明确要求, 合并为真正的单文件脚本。Snapshot、Candidate、目录映射、迁移执行、复制、版本图、权限/标签/对象/索引处理及保护逻辑全部内置, 来源于此前已验证实现; 不导入 scripts 下任何其他文件。不通过动态读取或执行其他脚本绕过独立要求。只使用现有 Bisheng 业务模块与运行环境。新规划器直接扫描真实个人库, 不伪造部门 scope 或根目录, 本地 MigrationBackend 的规划入口服务于复制后的重校验。合并目标必须已存在, 不调用默认库创建入口。

根目录没有物理 folder ID, 在 move_knowledge_space_files.py 的 TargetContext、结果和目标权限构造中支持 folder=None, parent 授权为 knowledge_space:<id>。不创建虚构 folder:0。原文件夹行为保持不变。

按真实 owner 和默认名称识别重复组, loader 补齐空库所有者。所有来源文件含失败/逻辑入口均进入规划或跳过清单。目录单独保留并映射, 之后按来源库 ID/文件 ID 串行处理物理文件和版本链。每单元执行前和删除来源前重新构建计划, 来源或目标变化停止/跳过。

只有来源全部单元成功且无跳过项才进入删库; 再次检查来源只剩已映射目录且目标目录仍在、文档无残留、没有活跃审批或频道同步绑定。独享存储若索引/集合被其他库共用, 禁止整库删除; 共享路由由既有业务服务保护。复用 delete_space(force=True), 仅传入已经通过空库检查的来源 ID。删除后校验库、scope、文件、版本文档、成员和必要权限残留, 失败记录并停止。生产期间必须停写并串行执行, 无全局跨存储事务。

验证采用规划/内存编排、真实底座回归和失败注入。上线先小范围 --user-id 预览, 再在维护窗口 apply。当前只开发验证, 不执行真实迁移。

删库前还检查来源目录原路径、目标目录层级以及迁入文件 ID/归属/名称/路径/状态; 后续同名覆盖已删除的目标 ID 从预期集合移除。目标丢失或移动时保留来源库。删库异常在 JSON 和 JSONL 中显式标记 failed, 不继续下一个来源。

性能修复后, 先通过个人 scope 和用户元数据发现重复组, 按用户查询重复默认库的数据。当前迁移单元通过来源 ID、目标文件夹名称/路径/同名文件查询, 再展开完整版本图; 补查成员的其他版本链接以拒绝损坏图。跨库引用只返回引用 ID 集合, 不加载无关文件的完整模型。整体来源收尾读取当前用户并查询其他库的同集合/索引元数据; 删库后按已删除 source ID 直接检查四类残留, 防止因重复组消失漏查孤儿记录。

PlanningIndex 在一次规划内构建空间、目录路径/名称、文件/文档/版本和引用索引; 复查只重建当前单元, 不复用过期快照。汇总 JSON 每 20 单元或 10 秒在单元边界保存, 来源结束和 finally 强制保存; JSONL 写入时机与 fsync 保持不变。无跨用户并行, 无数据库结构变更。


## 原记录迁移策略变更

2026-09-10 最新设计覆盖旧 copy/delete 流程: Backend.execute_records 优先读取 Milvus, 无可读数据则 ES; 两索引独立写入, 失败收集 issues。_rehome_file_records 在一个事务中验证并删除同名旧链、修改来源文件和文档归属, 保留原 ID 与对象地址。提交后清理索引/权限, 失败标记 status=3, 不回迁。被覆盖对象仅列审计待回收, 防止对象复用误删。空库先调用业务入口, 异常后 _delete_empty_space_records 重验非空保护并删除空库数据库记录; 外部遗留另记清单。
