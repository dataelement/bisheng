# Feature: F073 中粮 E+ 智能机器人接入毕昇助手

> **本文档只定义做什么、如何验收和本期边界。** 实现路线、协议适配、数据结构与权限落点在需求确认后写入 [design.md](./design.md)。

**需求来源**: 2026-09-23 用户讨论；客户提供的《中粮 E+ 开发者文档》离线全站 HTML「智能机器人」章（概述、接收消息/事件、被动/主动回复、模板卡片、回调加解密、Markdown、长连接等）
**优先级**: P1（客户接入）；知识越权与未授权使用为 P0 验收项
**所属版本**: v3.0.0-beta1 / 中粮 923 客户线，最终发布归属待排期确认
**依赖**: 既有助手应用、知识空间及权限能力、已同步的中粮部门用户
**状态**: Spec 与 Design 已于 2026-09-28 确认；进入实现

## 1. 范围与用户故事

**本次纳入**：中粮 E+ 智能机器人接入毕昇指定助手的会话能力；租户内助手应用与机器人一对一、机器人绑定多个知识空间；单聊和群聊的文字、纯图片、图文混排输入；按 E+ 原始用户 ID 识别使用者；保留助手的其他工具；内部毕昇助手入口保持原行为。

**本次不做**：按知识空间内部的单文件/文件夹个人权限再筛选；按提问者个人知识空间权限扩大机器人范围；E+ 语音、文件、视频、模板卡片等其他消息形态；以 E+ 后台的机器人「可见范围」代替毕昇知识空间授权。机器人输出以文字回答为目标，不要求主动发送图片或卡片。

作为 **中粮 E+ 员工**，我希望在单聊或群聊中向机器人发送文字和图片并收到回答，以便不进入毕昇页面也能使用指定助手。

作为 **毕昇管理员**，我希望按 E+ 机器人限定它可以使用的知识空间，以便群聊和单聊都不会借用提问者的个人权限跨空间检索。

作为 **毕昇内部助手用户**，我希望原有入口、工具和权限规则保持不变，以便客户接入不影响日常使用。

## 2. 验收标准

### 2.1 接入、身份与会话

- **AC-01** — WHEN 中粮 E+ 的已配置机器人收到一条有效单聊或群聊消息, THE SYSTEM SHALL 以与该机器人一对一绑定的毕昇助手能力处理并向原会话返回回答；一个助手应用最多绑定一个机器人，一个机器人也只能绑定一个助手应用。
- **AC-02** — WHEN 消息携带 `from.userid`, THE SYSTEM SHALL 使用既有 `WECOM_SOURCE='wecom'` 与该值精确匹配当前租户用户；该值与网关从 IAM 获取并放入组织同步报文 `external_user_id` 的 `userid` 相同。仅对应用户存在且可用时允许使用机器人，不得以昵称、群 ID 或助手创建者替代该用户身份。
- **AC-03** — IF 当前租户中没有对应的可用用户, THEN THE SYSTEM SHALL 仅向原会话返回「无权限使用」，且不调用助手、工具或知识检索。
- **AC-04** — WHEN 群聊中不同成员先后提问, THE SYSTEM SHALL 分别识别并校验每条消息的实际发送者；一个成员可用不代表其他成员可用。
- **AC-05** — WHEN E+ 重复投递同一消息, THE SYSTEM SHALL 不重复生成或发送业务回答。
- **AC-06** — WHEN 机器人在单聊和不同群聊中被使用, THE SYSTEM SHALL 保持会话上下文相互隔离，不把一个会话的消息带入另一个会话。

### 2.2 输入与图片理解

- **AC-07** — WHEN E+ 向机器人交付文字、纯图片或图文混排消息, THE SYSTEM SHALL 在单聊和群聊中按一致的输入语义处理：图片与同条消息中的文字共同构成一次提问；纯图片不要求附带文字；群聊中 @机器人 的提及不作为提问内容。纯图片以 E+ 实际投递为准（E+ 文档声明仅单聊投递，见 §3）。
- **AC-08** — WHEN 消息中有图片, THE SYSTEM SHALL 提供与毕昇日常对话一致的图片处理效果，使图片中可识别的信息可参与本轮回答；不得仅因助手原有入口只接收文字而丢弃图片。
- **AC-09** — IF 图片无法获取或当前部署无法理解该图片, THEN THE SYSTEM SHALL 明确告知不能读取/理解图片，不得声称已看过图片或编造其内容；同条消息中可独立处理的文字仍应按可用能力处理。
- **AC-10** — WHEN 图片与文字混排, THE SYSTEM SHALL 保留同一消息内文字和图片的关联，不将图片作为脱离上下文的另一轮提问。

### 2.3 机器人知识范围与工具

- **AC-11** — WHEN 具备该助手 E+ 接入管理权限的管理员配置机器人及可用知识空间, THE SYSTEM SHALL 支持机器人 ID、连接地址、Secret、可选 CA 根证书、启用状态和多个知识空间，并使空间配置仅影响该机器人；管理员可绑定本租户任意有效空间，不要求管理员本人具备这些空间的个人权限，跨租户、已删除或不存在的空间必须拒绝；Secret 不回显，管理员可查看连接状态并修改或轮换配置。配置允许在助手未上线时预先保存，但只有助手已上线且 E+ 配置已启用时才建立连接；助手下线或关闭 E+ 配置时必须断开连接。
- **AC-12** — WHEN 机器人回答涉及毕昇知识空间的问题, THE SYSTEM SHALL 仅检索并引用该机器人当前绑定的空间；单聊与群聊规则相同，不因提问者对其他空间有个人权限、是空间管理员或拥有更高角色而扩大范围。
- **AC-13** — WHEN 机器人已绑定某知识空间, THE SYSTEM SHALL 允许该机器人使用空间内可检索文件的内容，不再按发送者的单文件/文件夹个人权限缩小范围。
- **AC-14** — WHEN 一轮消息开始执行, THE SYSTEM SHALL 以此时机器人绑定的空间集合作为本轮固定检索范围；执行过程中即使管理员修改绑定，本轮仍按启动时快照正常完成，下一轮才使用新绑定。历史会话继续完整提供给模型，不因空间解绑或版本变化过滤；客户接受历史中可能保留既往空间信息的边界。
- **AC-15** — WHEN 助手调用其他既有工具, THE SYSTEM SHALL 保留该工具的正常能力及适用的原有授权；若工具会读取毕昇知识空间，也必须遵守 AC-12 的机器人空间上限，不得形成绕过路径。
- **AC-16** — THE SYSTEM SHALL 不把 E+ 机器人后台的员工「可见范围」解释为毕昇知识空间授权；两者分别生效。

### 2.4 兼容与失败边界

- **AC-17** — WHEN 用户从毕昇内部助手应用发起原有对话, THE SYSTEM SHALL 保持原有文字会话、工具、知识权限和历史行为不变；E+ 机器人专属的空间上限及空间内文件放宽规则不得作用到内部入口。
- **AC-18** — IF 消息不属于有效配置的机器人或来源无法确认, THEN THE SYSTEM SHALL 不调用助手或访问知识内容，也不向非原会话泄露结果。
- **AC-19** — WHEN E+ 正常交付消息, THE SYSTEM SHALL 在 E+ 智能机器人协议允许的回复时限与频率内完成答复或给出明确失败反馈；不得把下载失败、解析失败或模型失败伪装成成功回答。
- **AC-20** — WHEN 同一会话的前一条消息尚未完成, THE SYSTEM SHALL 将后续消息按到达顺序排队且不并发执行；图片应在入队时完成下载保存，消息真正开始执行时才发送「处理中」并加载前一轮完整历史。同一用户与机器人已有 3 条消息在途时，第 4 条 SHALL 直接回复「消息处理中，请稍后再试」且不进入队列。

## 3. 边界与待验证条件

- 客户文档（接收消息章与长连接章）**明确声明纯图片消息仅支持单聊**；群聊只投递文字与图文混排。因此群聊发图须随文字 @机器人（即图文混排）才能被处理，群聊纯图片不在验收范围内。毕昇解析逻辑不区分单群聊，若客户环境实际投递了群聊纯图片，仍按 AC-07 处理；不能靠毕昇侧代码补出未收到的消息。
- “按日常对话方式处理图片”指复用既有图片处理思路，并不等于已确认所有部署都配有视觉模型。图片中文字提取与一般图像/图表理解能力不同；验收时须按客户最终部署能力分别验证，不可将 OCR 成功视为完整图像理解。
- 助手应用与机器人在租户内一对一；多个机器人绑定同一空间允许，单个机器人可绑定零到多个空间。无绑定时知识空间检索范围为空，不自动回退到用户或助手原有空间。
- 本 Feature 的空间边界只约束**毕昇知识空间**；其他外部工具的数据授权沿用其自身规则，但不能借其间接调用毕昇知识空间绕过 AC-12。
- E+ 消息中的图片下载地址有效期较短；无法及时获取时按 AC-09 明确失败，不假定地址长期可用。
