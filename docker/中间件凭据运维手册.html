中间件凭据运维手册

更新：2026-11-15。普通 Linux Docker 部署；仍使用原命令。

一、准备

  1. 登录部署机器。使用公司分配的部署账号。完成标志：终端出现该机器的命令提示符。
  2. 进入项目根目录。输入 cd /实际项目目录，替换为交付目录。完成标志：执行 pwd 显示该目录。
  3. 检查 Docker 权限。输入 docker ps。完成标志：显示容器列表或表头；权限不足时，请管理员授权该账号后重新登录。
  4. 核对交付版本。按交付单核对脚本和前后端镜像。完成标志：版本配套；旧后端镜像不支持本方案时必须先取得新镜像。

Docker 是运行服务的软件。部署账号需要 Docker 授权和部署文件访问权，不要求 root 登录；当前不支持 Docker rootless 模式。

二、首次部署

  1. 执行原命令。输入 bash docker/install.sh。完成标志：出现部署检查或密码提示；公司既有入口若是 bash scripts/deploy.sh install，继续使用该入口，不要重复执行两个入口。
  2. 输入当前提示的密码。完成标志：出现确认密码提示；输入时不显示字符是正常现象。
  3. 再次输入同一密码。完成标志：进入下一项；两次不一致时重新输入当前项。
  4. 按下一项提示重复密码输入。完成标志：MySQL、Redis、MinIO、Elasticsearch、Milvus 全部完成。
  5. 等待命令结束。完成标志：报告部署完成并返回终端；报错时按第五节处理。
  6. 打开交付单中的访问地址。完成标志：显示登录页面。

MySQL、Redis、ES、Milvus 密码至少 6 位；MinIO 因组件自身要求至少 8 位。纯数字、纯字母或纯符号均可，不要求三类同时出现；已知默认密码和占位符仍会拒绝。脚本自动生成外置主密钥并加密配置。不需要手工创建密钥、解密文件或把密码补写进 .env。

三、重新部署或修改密码

  1. 执行原部署命令。完成标志：出现逐项询问是否修改密码。
  2. 回答当前项。输入 y 修改，输入 n 或回车保留。完成标志：出现新密码提示或进入下一项。
  3. 输入新密码。完成标志：出现确认提示；屏幕不显示字符。
  4. 再次输入新密码。完成标志：进入下一项；不一致时重新输入。
  5. 完成其余各项选择。完成标志：五项全部作出选择；每项独立决定。
  6. 阅读维护提示。完成标志：了解组件和短暂停服影响；时间不合适时按提示退出。
  7. 确认本次维护。同意时输入提示要求的 yes。完成标志：开始改密与配置切换。
  8. 等待命令结束。完成标志：报告成功并返回终端；后端自动使用更新后的配置。
  9. 登录系统。完成标志：能够进入系统并查看已有知识库。
  10. 下载已有文件。完成标志：内容正确；MinIO 改密后请从页面重新获取临时下载链接。

四、旧版升级

  1. 保留原部署目录。完成标志：原 .env、密钥、凭据和数据都在。
  2. 执行原部署命令。完成标志：识别受支持的旧包并提示维护确认。
  3. 按提示确认转换。完成标志：开始转换，实际密码保持不变。
  4. 等待转换结束。完成标志：报告原生文件转换完成，加密恢复备份保留。

支持经身份核验的受管 v1 包。未经验证的旧原生布局明确停止。旧 ES 未开启认证时，原命令会询问是否启用；回车或 n 保留现状，输入 y 后按提示录入两次新密码。若 ES 已开启认证但原配置缺凭据，按提示录入当前 elastic 密码。状态未知时保留现场联系交付人员。

五、ES 认证升级的选择与自检

  1. 执行原命令。输入 bash docker/install.sh。完成标志：脚本报告原 ES 安全状态。
  2. 回答是否开启认证。看到“是否为Elasticsearch开启认证”时输入 y，或输入 n 保留现状。完成标志：出现密码提示或进入下一阶段。
  3. 输入新密码。选择 y 时按提示输入至少 6 位的密码。完成标志：出现再次输入提示；输入时屏幕不显示字符。
  4. 再次输入同一密码。完成标志：进入维护确认。两次不一致时按提示重输。
  5. 确认维护窗口。按原命令提示输入 yes。完成标志：脚本开始核对旧索引并切换 ES。
  6. 等待脚本结束。完成标志：命令返回成功，原索引、别名和读写检查通过。报错时保留现场，按下一节续跑。

中断后只重新执行原命令。出现“继续原计划/配对回退”时，默认选择继续；配对回退到无认证需要明确输入 yes。不要删除 ES 数据目录或自行重置 elastic 账号。166 实际部署仍由你手动验收，本地开发测试不等于 166 通过。

六、失败后恢复

  1. 记录最后一条错误。完成标志：取得错误文字；不要发送密码、密钥或整个配置文件。
  2. 保留全部部署文件。完成标志：.env、密钥、凭据和数据未删除或覆盖。
  3. 修复错误指出的外部条件。例如恢复磁盘空间、网络或 Docker 授权。完成标志：条件恢复；无法判断时联系交付人员，不要手动改数据库密码。
  4. 重新执行同一个命令。完成标志：识别未完成状态并显示恢复提示。
  5. 按提示选择恢复。完成标志：继续原计划或走系统提供的恢复路径；不要删除状态文件强行重来。

密钥丢失时不能靠放开权限恢复。请从受保护的配套备份恢复密钥和对应凭据，再由交付人员核对版本。

七、文件与范围

BISHENG_CREDENTIALS_DIR 指向当前凭据包；.env 保存部署参数和路径，不等于后端配置。部署生成的输入、原生配置包、历史和恢复材料加密，运行所需明文仅在内存或受检查的内存文件系统中使用。

主密钥不写入代码或镜像，以权限受控文件保存（600 或经验证的 640），不能设置为所有人可读写。备份必须包含配套密钥与凭据，保存到公司批准的受限位置，不上传代码仓库。

明确例外：按用户确认，Milvus 原生内部消息可保存 Base64 凭据，这不属于加密；部署生成的 Milvus 材料仍加密。DM 待验证；Gateway、Helm v2、rootless 不属于当前已验收范围。

此前 166 隔离环境的部署、改密、迁移清理和扫描是历史验收，隔离环境已按要求删除。当前新代码放在 /root/bisheng-feat-3.1-beta2，166 原有项目上的 ES 迁移由你手动执行；完整故障矩阵和最终发布镜像仍待验收。
