# 全平台视图管理子租户托管应用时误报负责人权限

## 现场证据

2026-10-30，通过用户已登录 Chrome 在截图地址 `192.168.106.120:3002/build/apps/18bce12e6ae34a07abd798c2c13b3daf` 核验。用户切换为系统管理员后，页面明确显示 admin / 整个平台；应用“档位测试应用-标准”的基本信息、运行实例、审批状态及两条版本记录均正常加载，环境变量区显示负责人权限错误。

Network 实际请求 `GET /api/v1/apps/18bce12e6ae34a07abd798c2c13b3daf/secrets`：HTTP 200，业务码 16254，消息 `Only the application owner may perform this action`。错误由发布页自动读取环境摘要触发。未执行应用下线、删除、写配置或其他现场变更。

## 根因与修复

环境摘要读复用了负责人写事务的 strict tenant 过滤；全平台视图下，超管当前租户仍是其归属租户，子租户应用在业务鉴权前就被过滤掉，Repository 统一报负责人限制。指定目标租户的视图本来可读取，同一应用会因视图不同得到矛盾结果。

增加管理摘要专用只读事务：先使用现有管理视图过滤定位应用，再临时绑定应用租户，严格读取配置、版本和运行快照；成功或异常后恢复原请求上下文。Service 在读配置前继续检查请求租户与 owner / 超管 / 租户管理员 / 现有 edit 资格。非 owner 仍只取得冻结版本声明的名称及配置状态，不能取得私有未声明名称、值、掩码或逐项更新时间。

读侧应用不存在或不在当前视图内使用 16101，管理资格不足使用 16106。保存、删除与运行重建保持原有业务资格；负责人专属修改仍返回 16254。没有新增错误码、接口、依赖或数据库变更。
