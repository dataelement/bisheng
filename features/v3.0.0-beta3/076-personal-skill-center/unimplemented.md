# 个人 Skill 上传与技能中心：未完成功能与实现方案

对照《0930 中粮需求响应》「个人 Skill 上传与技能中心」，以及已合入当前分支的 [PR 2501](https://github.com/dataelement/bisheng/pull/2501) 前端预览。技能中心页面以这个预览为准，见 [design.md](./design.md) 决策 6。

需求口径见 [spec.md](./spec.md)，实现决策见 [design.md](./design.md)。本文只记录相对需求仍未落地的部分。

页面预览已经合入。个人技能仍只存在当前浏览器。要落到服务端、换设备还能用、并进入任务自动匹配的部分都还没有实现。

Kimi 创建、Office 转技能、个人技能分享和公开发布，需求已明确不在本期，不列入下面的未完成项。

## 当前影响：输入框里点技能进了详情，不能勾选

点开详情是技能中心里的动作：点击整张卡片打开右侧详情。输入框【+】菜单里点一行，仍是为本次任务勾选或取消，和原来的「添加技能」一样。菜单里名称或说明被截断时，只在悬停或聚焦时于右侧展开全文。

预览把这两处做成了同一件事。`SkillMenuPanel` 点一行会跳到技能中心并打开详情，同时藏起原来的 `SkillSelector`。任务只装载输入框上方已经挂着的技能名（`materialize_session_skills`）。菜单不能勾选之后，任务只拿得到管理员设成默认勾选、且用户没有摘掉的技能。

已定：输入框恢复勾选。点一行保持菜单打开，选中后挂到输入框上方，再点一次取消。名称或说明被截断时，悬停或聚焦只在右侧展开全文。进入详情只从技能中心的卡片进入。预览里 `SkillMenuPanel` 的跳转要改回来。

## 未完成

### 保存与归属

- 按登录身份把文件、元信息和所有者写到服务端。现在写入 IndexedDB，换浏览器或换电脑就没有了。
- 用稳定技能 ID 做新增、更新、详情、读取和删除。现在的个人技能 ID 是浏览器本地生成的。
- 保存成功才算添加成功。现在校验通过后写进本机就提示成功。
- 保存中断后先向服务端查询再决定重试；失败重试复用同一次导入标识。做法见 [design.md](./design.md) §7.4，验收 AC-24。
- 服务端按实际字节校验：上传 50 MiB（11052）、解压后 200 MiB（11059）、`SKILL.md` 1 MiB（11073）、最多 1000 项（11074）、路径不得越界。现在只在浏览器里检查。11052 和 11059 与企业上传共用，译文改为带 `{{limit_mb}}`，每处抛错都要带上实际上限。做法见 [design.md](./design.md) §6。
- 加密压缩包给出单独原因。现在只报「压缩包读取失败」。损坏、缺少 `SKILL.md`、路径越界、0 字节和多技能包用 11067、11068、11069、11071、11072，不共用 11051，也不占用已有文案的 11060 和 11070。做法见 [design.md](./design.md) §7.5，验收 AC-23。
- 按需求列出的 MIME 类型校验：Markdown 接受 `text/markdown`、`text/plain`；ZIP 接受 `application/zip`、`application/x-zip-compressed`；另接受 `application/octet-stream` 或空值。实际内容须与所选格式一致。做法见 [design.md](./design.md) §7.5，验收 AC-23。`.skill` 与 ZIP 使用同一组 MIME。

### 权限与隔离

- 个人技能只对当前租户的上传者本人可见、可改、可调用。
- 其他人用 ID 访问时按不存在处理，响应里不出现名称、正文、附件，也不暴露这条技能是否存在。
- 客户端传来的所有者和来源以服务端登录身份为准。
- 管理操作记审计日志：操作者、租户、技能 ID、来源、版本和结果，不记录正文和凭据。做法见 [design.md](./design.md) §7.1，验收 AC-17。
- 管理端的技能列表、启停、默认勾选和删除不能看到或改到个人技能。需求把个人技能的管理员浏览列为后续独立需求。
- 开放接口的任务模式按名字读取本租户已启用技能（`task_mode_service.py`）。个人技能落库后，不能经这个接口被其他调用方选用。

现有技能权限只到租户和管理员：管理接口要求租户管理员；已登录用户通过 `GET /api/v1/linsight/skill/selectable` 能看到本租户全部已启用技能。创建时写入的 OpenFGA 所有者记录不参与使用鉴权。

### 更新、启停、删除的生效

- 更新保留稳定 ID 和启停状态，新包校验并保存成功后整体切换；失败继续用旧版本。
- 并发更新校验原版本，过期时提示「该 Skill 已更新，请刷新后重试」。现在这条提示只对同一浏览器里的本地记录有效。版本用内容哈希，不用更新时间。做法见 [design.md](./design.md) §7.2，验收 AC-18。
- 启停和删除的重复提交返回当前结果，不报错。做法见 [design.md](./design.md) §7.3，验收 AC-19。
- 停用后不再进入新任务、恢复和重新规划的候选。已经返回的内容留在当前步骤；会话目录里的副本留到任务结束。下一步 `read_file` 和代码执行器执行前再查一次，已停用则拒绝。做法见 [design.md](./design.md) §7.8，验收 AC-09。
- 删除成功后立即从技能中心和之后的候选中移除。已装进本次任务会话目录的文件留到该任务结束。正在跑的任务读会话自己的副本，删除和覆盖时直接回收旧对象，做法见 [design.md](./design.md) §7.8，验收 AC-15。
- 删除确认文案改为需求原文：「删除‘{名称}’后，后续任务将无法使用该 Skill，已有对话和生成结果保留。」按钮为【取消】【删除】，失败提示「删除失败，请重试」。预览现在写的是从当前浏览器删除，按钮是「删除技能」。做法见 [design.md](./design.md) §7.6，验收 AC-20。

### 技能中心与自动调用

- 服务端提供两个读取方法，共用归属条件。技能中心列已启用的企业技能和本人全部个人技能（含停用）；任务候选只取已启用的企业技能和已启用的个人技能。现在企业技能来自 `/api/v1/linsight/skill/selectable`，个人技能由前端另查本地库再拼在一起。做法见 [design.md](./design.md) 决策 3。
- 每次任务把这份候选整包拷进会话：本租户已启用的平台技能，加上本人已启用的个人技能。勾选只在提示词里强调「用户选中了这个技能」，未勾选的同样拷入整包。个人技能现在不进入任务。
- 新建任务按当时的候选整包拷入，并重新生成 “Available Skills”。同一次会话的恢复和继续提问不重写检查点里的名单。已经返回的内容留在当前步骤；下一步读取和代码执行前再查启停和删除。做法见 [design.md](./design.md) §7.8，并与 AC-09、AC-15 一致。
- 技能中心仍同时列出同名的平台技能和个人技能，并标来源。两份都已启用时，输入框菜单分两行，不按名字藏掉企业技能，任务目录只装载个人技能。个人技能停用或删除后，输入框只显示企业技能那一行，新任务装载企业技能。做法见 [design.md](./design.md) §7.7，验收 AC-26。
- 依赖的工具或执行环境缺失时，任务中说明「该技能需要的工具当前不可用」。做法见 [design.md](./design.md) §7.8，验收 AC-25。
- 个人技能文件缺失时，详情里说明原因并提供「更新技能」。做法见 [design.md](./design.md) §7.6，验收 AC-21。
- 当前打开的技能被停用、撤权或删除时，提示原因并返回列表，保留其他技能。用户停用自己的个人技能时留在详情里。本期的撤权就是管理员停用。做法见 [design.md](./design.md) §7.6，验收 AC-22。预览里地址指向不存在的技能时，详情直接不打开，没有提示。

- 技能中心页面已定，见 [design.md](./design.md) 决策 6 和 `spec.md` AC-06、AC-07、AC-12。正式实现保留现在的「我的技能」列表（「我创建的」「企业提供」两组）和「技能广场」卡片，只把数据源从浏览器换成服务端。

## 实现方案

个人技能加在现有 `linsight_skill` 上，不新建一套表，也不再把 IndexedDB 当正式存储。

### 已定：平台技能按租户授权

平台技能的使用范围定在租户。租户管理员启用后，该租户每个登录用户都能用；停用后，该租户谁都不能用。本期不加按人或按部门的授权。

创建时写入的 OpenFGA 所有者是上传的管理员，不作为使用权限。拿它做使用校验会把同租户的其他用户全部挡住。

和工作台里另外两个开关分开：

- **启用 / 停用**决定这个技能能否被本租户使用、能否进入候选。
- **技能入口**（`skillEntry.enabled`）只决定输入框里出不出现技能菜单。
- **默认勾选**只决定新任务要不要预先挂上，用户可以摘掉。

平台技能的正文和附件继续只给租户管理员。普通用户在技能中心只看名称、用途说明和来源。按人或按部门分配平台技能另行立项。

### 已定：输入框勾选，技能中心进详情

输入框【+】里的技能列表用来勾选本次任务。点一行不关闭菜单、不跳转：未选中则挂到输入框上方，已选中再点一次则取消。勾选结果随请求提交，用来在提示词里强调，不是唯一的装载名单。未勾选的候选技能仍会带上，见下文「已定：不选也会带上」。

底部的【上传技能】【管理技能】保留。管理技能打开技能中心。技能中心里点击整张卡片才打开右侧详情。

预览当前点一行会跳到技能中心详情，这与本决定不符，实现时改回勾选。

### 已定：不选也会带上，选中的在提示词里强调

每次任务都带上当前用户的候选：本租户已启用的平台技能，加上该用户已启用的个人技能。同名时只带个人技能。不另调一个模型来生成名单。这些技能的名字和用途说明写进同一次任务的 “Available Skills”，由任务模型自己判断要不要读 `SKILL.md`。

用户在输入框勾中的技能，在这段提示里单独标明「用户选中了这个技能」。默认勾选且用户没有摘掉的，也算选中。用户没勾的候选仍然出现在名单里，但不加这句强调。这句由平台在贴名单时按会话上的勾选追加，不写进 `SKILL.md`；现有 `SkillsMiddleware` 读不到勾选，要在外面包一层。整包要在建代码执行器之前拷入，否则 E2B 拍下的文件清单里没有技能包。做法见 [design.md](./design.md) §7.8。

现在的装载只拷贝请求里点名的技能整包。实现时改为在任务开始时把每个候选的整包都拷进会话。用户勾中的在提示词里标明「用户选中了这个技能」，未勾选的不加这句。停用、删除和他人的个人技能在装载前剔除。同名时只拷个人技能的整包，见下一节。

### 已定：同名时个人技能覆盖企业技能

「我的技能」的两个分组都保留同名技能，用来看来源。任务目录里不同时保留同名的两份文件。

同名去重只在任务候选里做。该用户有同名且已启用的个人技能时，只把个人技能的整包拷到 `/skills/{名字}/`。同名的企业技能不进入这次任务，提示词里也只有个人技能这一条。该用户没有同名个人技能，或同名个人技能已停用、已删除时，仍把企业技能的整包拷进这次任务。企业技能本身不删除，其他没有这份个人技能的用户照常使用。

用户勾选了这个名字时，对留下的个人技能标明「用户选中了这个技能」。勾的是企业技能卡片、但被个人技能覆盖时，同样强调留下的个人技能。

### 已定：个人技能配额

每个用户在当前租户最多 20 个个人技能，上传文件合计最多 200 MiB（209715200 字节）。容量按上传字节计，不是解压后的大小。停用的个人技能仍占用个数和容量，删除后释放。企业技能不计入。

超出时拒绝这次新增，不删除已有技能。当前没有服务端上的个人技能，没有存量需要处理。上传前展示「已用个数 / 20」和「已用容量 / 200 MiB」。个数超出为 11061，容量超出为 11062。

### 已定：同名再次上传先提示，确认后再覆盖

同一用户再次上传与自己已有个人技能相同的标识时，先提示该技能已存在，不写入。用户确认覆盖后，用新文件替换，保留原技能 ID 和启停状态。未确认则保留旧文件。个数不变；合计容量按新文件重算，替换后超过 200 MiB 则拒绝覆盖。

与企业技能同名不在这里覆盖企业技能。「我的技能」的两个分组仍然都列出；任务里按已定规则只放个人技能。

### 已定：运行中删除与临时文件

删除立即成功。技能从技能中心和之后的候选里消失。新任务、恢复和重新规划不再装载它。已经返回给模型的内容留在当前步骤。会话目录里的副本留到该任务结束，不靠删这些文件来停用。下一步 `read_file` 读 `/skills/{名字}/` 之前，以及代码执行器执行之前，再查一次，已删除则拒绝。装载时在会话版本上记下每个目录对应的技能 ID 和归属用户，读取和执行前按这一行判断。正在跑的任务读的是会话自己的副本 `workspace/{会话}/skills/`，不再回到技能对象，所以这次请求里直接删掉对象。

取消上传、校验失败、同名未确认覆盖，都不写入对象存储。校验在内存中完成。请求结束时删除本次解压用的临时目录，不按天数保留。进程崩溃留下的、没有技能记录的对象由后台清扫删除。

### 动工前还要定下的事

无。

### 1. 归属与数据

表上增加 `owner_user_id`。`0` 表示现有租户技能（内置、管理员上传），非 0 表示该用户的个人技能。`created_by` 继续只表示创建人。用 `0` 而不用空值：MySQL 唯一索引里空值互不相等，挡不住平台技能重名。

唯一键从「租户 + 技能名」改为「租户 + 归属用户 + 技能名」，这样个人技能可以和平台技能、其他人的个人技能同名。

迁移要同时兼容 MySQL 和 DM8：先确认存量行无同租户重名，把存量行的 `owner_user_id` 填 `0`，再替换唯一约束 `uq_linsight_skill_tenant_name`。

只改唯一键不够。下面这些地方现在都只按「租户 + 名字」定位，都要加上归属条件：

- `LinsightSkillDao` 的 `get_by_name`、`set_enabled`、`set_default_checked`、`delete_by_name`，以及 `list_enabled`、`get_page`。批量更新不经过租户过滤，必须显式带上租户和归属条件，和现有 `set_enabled` 显式带租户的做法一致。
- `SkillService._check_duplicate` 还要求整个租户内展示名唯一，这会挡住与平台技能同名的个人技能。重名检查改为只在同一归属范围内进行。
- 管理端接口固定只操作 `owner_user_id = 0` 的行，旧客户端的请求和响应不变。

### 2. 对象存储

现在的对象键是 `linsight/skills/{租户}/{名字}/{哈希}.zip`，删除按 `linsight/skills/{租户}/{名字}/` 前缀批量删除。个人技能若沿用这个前缀，用户删掉自己的技能，会连同同名的平台技能和别人的同名个人技能一起删掉。

也不能在原前缀下加一层 `u{用户}`：`u123` 本身就是合法的技能名，同样可能撞前缀。

个人技能放到独立前缀：

```text
linsight/personal-skills/{租户}/{用户}/{名字}/{哈希}.zip
```

租户技能保留原路径，存量对象不搬。`SkillStore` 的对象键、本地缓存目录、读取和删除都按归属选择对应前缀。

### 3. 上传与候选目录

个人技能单独开路由，用普通登录用户的鉴权，不复用要求租户管理员的管理接口。上传复用 `SkillStore` 现有的解包和路径校验，但使用固定上限：50 MiB、解压 200 MiB、`SKILL.md` 1 MiB、1000 项，不读管理员那套更大的系统配置。

登录用户写入 `owner_user_id`。同一用户再次上传相同标识时，先提示重复、不写入；用户确认覆盖后替换文件，保留原 ID 和启停状态。文件、元信息和归属都写完才返回成功。

两个读取方法共用同一套归属条件。平台技能按已定的租户粒度放进来，不再按用户过滤：

- 技能中心：`owner_user_id = 0` 且本租户已启用的平台技能，加上 `owner_user_id = 当前用户` 的全部个人技能，停用的也列出并返回启停状态
- 任务候选：`owner_user_id = 0` 且本租户已启用的平台技能，加上 `owner_user_id = 当前用户` 且已启用的个人技能。输入框菜单、任务装载、开放接口的任务模式都读这一份

访问他人的个人技能时按不存在处理，返回 11053，不返回 11054，以免暴露这条技能存在。与 `design.md` 第 6 节、`spec.md` AC-08 一致。

个人技能的单条操作已定，见 [design.md](./design.md) 决策 5 和 `spec.md` AC-08。先查出当前租户的这一行；归属不是本人就返回 11053，不调用 `require_business_action`。归属是本人，再调用统一授权，资源类型仍是 `linsight_skill`。列表和任务候选继续按归属做一次查询，不逐条授权。企业技能的使用不读创建时的所有者记录。

### 4. 任务装载与自动匹配

已定，不另做一次模型调用。每个候选在任务开始时把整包拷进 `/skills/{名字}/`，名字和用途说明进入同一次任务的 “Available Skills”。用户勾中的技能（含默认勾选且未摘掉的）在提示词中标明「用户选中了这个技能」。未勾选的同样拷入整包，只是没有这句强调。

同一用户的个人技能与企业技能同名时，只拷个人技能的整包，企业技能不进入这次任务的目录，提示词里也只列出个人技能。企业技能记录保留，供没有这份个人技能的其他用户使用。用户勾选了这个名字时，对留下的个人技能加「用户选中了这个技能」。

装载时在会话版本上记下每个目录对应的技能名、技能 ID、归属用户和内容哈希。新建任务重新取候选并整包拷入。同一次会话恢复和继续提问时，已有的技能目录不写入同名的另一份技能；读取和执行前按快照里的技能 ID 判断，不按目录名判断。“Available Skills” 写入检查点的 `skills_metadata`，同一次会话恢复和继续提问不再扫描磁盘。已经返回的内容留在当前步骤。下一步 `read_file` 和代码执行器执行前再查启停和删除，已停用或已删除则拒绝；本地执行直接打开会话目录，只拦 `read_file` 不够。开放接口的任务模式改为读取任务候选，个人技能只对其所有者生效。

### 5. 运行中删除与临时文件

已定。删除或停用后，立即从之后的候选中移除。新任务、运行恢复和重新规划不再装载。已经返回的内容留在当前步骤。会话目录里的副本留到该任务结束。下一步读取和代码执行前再查一次，已停用或已删除则拒绝。删除时直接删掉对象，覆盖时删掉这一行不再指向的旧对象；正在跑的任务读的是会话自己的副本。同一次会话恢复时，已有的技能目录不写入同名的另一份技能，快照记下目录对应的技能 ID 和归属用户。

取消或失败的导入不写对象存储。请求结束时删除解压临时目录。没有技能记录的残留对象由后台清扫删除，不设面向用户的保留时限。

### 6. 前端

去掉 IndexedDB 预览库和预览开关，技能中心改为调用上述接口。页面结构留下现在的实现：「我的技能」是「我创建的」「企业提供」两组列表，「技能广场」是企业技能只读卡片。搜索、排序、上传弹窗、启停和删除留下，数据源换成服务端。

输入框里的技能列表按已定口径恢复勾选，不跳转详情。两份都已启用时同名的企业技能和个人技能各一行；个人技能停用或删除后只剩企业技能那一行。进入详情只从技能中心的卡片进入。审计、版本、导入重试、加密包、删除文案和工具不可用的做法见 [design.md](./design.md) §7，这里不另写一套。

个数和容量按已定额度展示：已用个数 / 20，已用上传容量 / 200 MiB。停用的个人技能仍计入，企业技能不计入。超出时拒绝新增。
