# F045 E2E Checklist — 部门知识空间唯一管理员

> 环境:平台(:3001)超管账号 + client(:4001/workspace)普通账号。
> 前置:后端已跑 `alembic upgrade head`;存量环境先跑 `scripts/migrate_department_space_admin.py --apply`。

## 1. 创建(AC-01~04)

- [ ] 平台 → 工作台配置 → 知识空间 → 部门知识空间管理:勾选新部门,变更预览出现「\*空间负责人」搜索框
- [ ] 不选负责人 → 保存按钮禁用 + 红字提示(AC-01 前端面)
- [ ] 直接 curl batch-create 不带 admin_user_id → 业务码 18003(AC-01 服务端)
- [ ] 选停用账号(构造请求)→ 18004(AC-02)
- [ ] 选正常用户创建成功 → client 端该空间成员/权限界面:负责人以管理员身份展示(AC-03)
- [ ] 创建的空间中:成员列表、权限列表、人数统计、空间详情负责人信息均无超管(创建者)身影(AC-04/12);人数与名单一致
- [ ] KnowledgePage 的「配置部门知识空间」对话框同样强制选负责人

## 2. 负责人能力(AC-03)

- [ ] 负责人登录 client:能管理成员、审批加入申请(auth_type=APPROVAL 时)、改空间设置

## 3. 更换(AC-05~07)

- [ ] 平台已创建列表:每行显示「空间负责人:xxx」+「更换负责人」
- [ ] 更换为另一有效用户 → 新负责人立刻有管理权,旧负责人失去管理身份;曾是普通成员的回退为成员,纯负责人被移出(AC-07)
- [ ] 两个超管同时更换(可用两个窗口)→ 后提交者收到 18006,不出现两个管理员(AC-05/06)
- [ ] 新旧负责人各收到站内信(assigned / revoked)

## 4. 失效与待配置(AC-08~11)

- [ ] 超管在用户管理停用负责人账号 → 空间打【待配置负责人】徽标;超管收到站内信(AC-08)
- [ ] 待配置期间:权限页新增授权 → 18005;新用户申请加入(APPROVAL 空间)→ 18005;已有成员浏览/检索/问答正常(AC-09)
- [ ] 确认超管未被自动写成负责人或审批人(AC-10)
- [ ] 平台补配新负责人 → 徽标消失,授权/加入恢复(AC-11)
- [ ] SSO/网关同步停用负责人(如环境具备)→ 同样进入待配置
- [ ] 调岗出企业(多租户环境)→ 原租户空间进入待配置

## 5. 自动同步已下线(AC-15)

- [ ] 任免部门管理员 → 部门空间成员/权限无任何变化
- [ ] 调岗、SSO 同步 → 不再增删空间 ADMIN 成员

## 6. 存量迁移(AC-16/17)

- [ ] 构造:空间 A 恰一名有效 ADMIN;空间 B 两名 ADMIN;空间 C 仅 CREATOR
- [ ] dry-run 输出计划正确;--apply 后:A 沿用、B/C 待配置;所有 CREATOR 行与 owner 关系被清除;department_admin 来源成员按提升前角色回退
- [ ] 重跑脚本 → 幂等(无新变更)

## 7. 兜底对账(T012)

- [ ] 手工删掉某负责人的 manager 元组 → 等 Beat(或手动触发 reconcile_department_space_admins)→ 元组被补回,日志有 repaired 记录

## 8. 回归

- [ ] 普通(非部门)知识空间创建:创建者照常展示,行为零变化
- [ ] 空间广场:部门空间卡片显示负责人名而非超管名
- [ ] 部门空间改 PRIVATE:负责人管理权保留(成员清理不误伤)
