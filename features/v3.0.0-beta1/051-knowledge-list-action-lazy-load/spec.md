# Feature: F051 知识库列表动作权限懒加载

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> 本文档只定义知识库列表与单行操作菜单的权限体验、失败行为和验收标准。
> 实现决策、接口复用、状态组织、缓存与文件清单由后续 `design.md` / `tasks.md` 维护。

**关联需求**: 2026-08-25 用户确认的知识库列表性能优化需求
**优先级**: P0
**所属版本**: v3.0.0-beta1
**依赖**: v2.6.0 F027、v3.0.0-beta1 F048

> **范围边界**
> - **本次纳入**：
>   - 文档知识库与 QA 知识库列表不再为每一行预先计算编辑、删除、权限管理等非可见动作；
>   - 列表仍返回已由服务端确认的可见能力，并保持既有可见或可用资源筛选语义；
>   - 用户打开单个知识库的三点操作菜单时，按该资源的当前有效动作懒加载并展示操作项；
>   - 懒加载期间、失败时及权限变化后的操作继续保持失败关闭；
>   - 管理员与普通用户遵循同一交互时机，具体动作能力仍以服务端有效权限为准。
> - **本次明确排除**：
>   - 不修改 F048 Catalog、权限模型、Grant、权限模式、OpenFGA Authorization Model 或权限迁移数据；
>   - 不改变资源操作接口自身的最终鉴权，列表或菜单状态不能替代执行时鉴权；
>   - 不改造知识空间、工作流、助手、工具、频道或仪表盘等其他资源列表；
>   - 不改变知识库复制操作既有的菜单能力与资源可见性组合规则；
>   - 不新增权限管理入口，也不恢复旧 relation、`permission_id` 或角色名资源放行逻辑。

---

## 1. 用户故事

### 1.1 知识库列表访问者

作为知识库列表访问者，
我希望列表首屏只承担资源筛选与基础信息加载，
以便不会因为尚未使用的设置、删除和权限管理动作而等待多轮权限计算。

### 1.2 知识库管理者

作为具备部分或全部管理动作的知识库协作者，
我希望打开某个知识库的操作菜单后看到自己当前可执行的操作，
以便按需获得准确能力而不拖慢整个列表。

### 1.3 仅查看用户

作为仅具备查看能力的用户，
我希望可以打开统一的操作入口，但不会看到或执行未经授权的管理操作，
以便界面不会通过列表快照扩大我的权限。

## 2. 验收标准

### 2.1 列表权限负载

- **AC-01** — WHEN 用户请求文档知识库或 QA 知识库列表, THE SYSTEM SHALL 只为列表返回项携带已确认的可见能力，不得为装饰列表行预先计算编辑、删除、权限管理或其他非筛选所需动作。
- **AC-02** — WHEN 列表按可见能力筛选资源, THE SYSTEM SHALL 保持现有资源可见范围、排序、搜索、游标和分页结果，不得因移除其他动作预加载而新增或遗漏资源。
- **AC-03** — WHEN 调用方要求列表只包含具备某一具体动作的资源, THE SYSTEM SHALL 继续以该具体动作筛选候选资源，但不得因此为返回行补齐与筛选无关的其他动作。
- **AC-04** — WHEN 超级管理员或当前租户管理员请求知识库列表, THE SYSTEM SHALL 保持既有租户和业务范围，并使列表行权限负载与普通用户保持相同的最小动作形态。

### 2.2 单资源动作懒加载

- **AC-05** — WHEN 用户打开一个非处理中知识库的三点操作菜单, THE SYSTEM SHALL 在展示权限相关操作项前获取该知识库对当前用户的有效动作。
- **AC-06** — WHILE 单资源动作仍在加载, THE SYSTEM SHALL 展示明确的加载状态，并禁止触发尚未确认权限的设置、删除或权限管理操作。
- **AC-07** — WHEN 单资源动作加载成功, THE SYSTEM SHALL 只展示当前用户获准的设置、删除和权限管理操作，并保持复制操作的既有显示规则。
- **AC-08** — WHEN 用户关闭一个知识库的操作菜单且未选择操作, THE SYSTEM SHALL 不打开设置页、删除确认或权限管理界面。
- **AC-09** — WHEN 用户随后打开另一知识库的操作菜单, THE SYSTEM SHALL 根据另一资源自身的有效动作展示操作项，不得复用前一资源的授权结果。

### 2.3 失败关闭与权限变化

- **AC-10** — IF 单资源动作加载失败或权限结果不可判定, THEN THE SYSTEM SHALL 不展示设置、删除和权限管理操作，并向用户反馈权限检查失败。
- **AC-11** — IF 用户在菜单显示后失去某项动作权限, THEN THE SYSTEM SHALL 在其执行该操作时按服务端最新权限拒绝请求，不得以已显示的菜单项作为放行依据。
- **AC-12** — WHERE 多租户开启, THE SYSTEM SHALL 只返回当前租户业务范围内知识库的动作能力，且不得展示或执行跨租户资源操作。

### 2.4 兼容与回归

- **AC-13** — WHEN 用户进入文档知识库或 QA 知识库详情、上传、问答或设置相关页面, THE SYSTEM SHALL 保持这些页面既有的具体动作鉴权结果。
- **AC-14** — WHEN 既有调用方使用知识库列表作为资源选择器, THE SYSTEM SHALL 保持原有可选资源集合与选择行为，不要求调用方依赖列表返回的管理动作。
- **AC-15** — THE SYSTEM SHALL 保持知识库处于复制中、未发布或其他既有处理中状态时的操作入口、加载提示和禁止操作行为。

## 3. 边界情况

- 用户连续快速打开同一知识库或在多个知识库之间切换操作菜单时，最终展示必须对应当前打开的资源，迟到结果不得覆盖当前资源状态。
- 用户在动作加载过程中关闭菜单时，不得因请求随后成功而自动重新打开菜单或触发任何操作。
- 单资源没有任何设置、删除或权限管理动作时，菜单不得展示这些操作；复制项仍独立遵循既有规则。
- 列表为空、搜索无结果或可见资源集合为空时，不应发起单资源动作查询。
- 权限服务不可用、Catalog 未就绪、资源不存在或资源已跨租户时，懒加载保持失败关闭，不得回退到角色名、列表快照或旧权限路径。
- 资源动作在一次菜单打开期间发生变化时，菜单显示可能先反映已取得的结果，但任何后续业务操作必须以服务端执行时鉴权为最终结论。
