# Feature 毕昇 Workflow 调用昆联 Agent 长任务与取消

- **Feature ID**: F124（拟用，合入前复核）
- **Version**: v3.0.0
- **Status**: DRAFT，待确认
- **Mode**: SPEC_ONLY，首轮 Mock 优先
- **关联**: [开发规划 4B](../../../docs/architecture/proposals/kunlian-workflow-development-plan.md#下一批需求发现--人工输入长任务与取消)、[F119 平台 Agent 节点规格](../119-kunlian-platform-agent/spec.md)、[F123 原生 Workflow 人工输入规格](../123-kunlian-workflow-interaction/spec.md)、[版本契约](../release-contract.md)。

## 1. 目标与范围

毕昇 Workflow 执行已绑定的昆联 Agent 版本时，可以异步启动长任务。毕昇关联这一次 Agent Run，轮询状态、进度摘要和最终结果。成功时把校验后的输出传给下游节点；用户停止或本地等待超时后，工作流不再消费迟到的结果，昆联是否已停止则按远端可确认事实展示。

首轮在现有平台 Agent 节点上显式启用长任务能力，以一条「开始 → 平台 Agent → 输出 → 结束」的流程验收，一次运行包含一个长任务节点。复用 F119 的固定版本、输入输出映射、实际运行人和 Workflow 权限边界。原有同步配置继续按原合同执行，收到意外的异步回执也不自动切换模式。

首轮覆盖异步启动、状态和结果查询、使用现有 Workflow 停止入口触发取消、超时及有界的异常收敛。远端等待人工输入归 4C；本期识别该状态并提示不支持，不把它当成功。原生 Workflow 人工输入由 4A 处理。本期不新增独立 Agent 管理或取消入口，不引入回调、事件订阅、通用跨 Worker 图恢复或双向递归调用。

## 2. 用户故事

- 作为工作流运行者，我希望启动长任务后能用原运行查看进度和结果，断开原请求后也不用重新启动 Agent。
- 作为工作流运行者，我希望点停止后毕昇立即停止等待和下游执行，并能区分取消请求已发出、昆联已受理以及昆联已确认取消。
- 作为排障人员，我希望区分本地等待超时、远端执行失败和远端结果未知，并用 Workflow 运行、节点执行及昆联 Agent Run 标识核对同一次调用。

## 3. 业务需求

| ID | 需求 |
| --- | --- |
| REQ-01 | **固定版本异步启动。** 对显式启用长任务、具备该能力的固定 Agent 版本，以已冻结的参数映射和实际运行人启动。昆联确认受理后，毕昇关联原 Workflow 运行、节点执行和 Agent Run ID，进入等待结果；不要求启动请求一直保持到远端结束。发布新版本或改草稿不影响已经启动的任务。 |
| REQ-02 | **启动去重与未知结果。** 同一逻辑节点执行重复投递或重试只对应一次远端运行，同一启动标识改版本或改输入时拒绝。启动请求发出但结果未知时，优先按原关联查回；只有确认重放安全时才能以原标识、原参数重放。无法安全确认时保持远端结果未知，不另起任务，不伪造 Agent Run ID。不同 Workflow 运行或同一流程内不同合法节点执行的结果不得混用。 |
| REQ-03 | **状态、进度和结果轮询。** 按同一个 Agent Run 查询。昆联有可信进度时展示摘要，无进度时只展示状态。成功须确认运行归属、固定版本和输出结构，结果可用后只向下游提交一次。失败、已取消、未支持的人工等待、结果不可用及结果错配须可区分；旧状态不得覆盖已确认终态。状态与结果合并返回或分开读取均可。 |
| REQ-04 | **停止与取消。** 通过毕昇现有停止入口接受本地停止后，立即禁止新的下游执行及该节点尚未提交的输出。对于已知且尚未终态的 Agent Run，按原运行身份尽力请求取消；重复停止或取消重试只对应同一个取消意图。取消请求已发出、远端已受理、远端已确认取消必须可区分。已确认终态的 Agent Run 不再发取消，不改写既有结果。 |
| REQ-05 | **超时与结果收敛。** 区分启动受理超时、已启动但未在本地截止前得到可用结果、取消确认超时。临时查询失败按可重试错误处理；轮询和重试不延长原执行截止时间。已知仍未终态的远端任务在本地超时后也按原身份尽力取消。远端未知或取消未确认时如实展示，不能据此宣称远端失败或已取消。取消或后续核对有独立的有限窗口，不阻塞本地收敛。 |
| REQ-06 | **权限与脱敏。** 启动、查询、提交输出和取消遵守现有 Workflow 操作权限及执行归属；远端按原实际运行人、可信租户和接入方校验相应操作资格。无权、撤权、停用或凭据无效时，停止该受保护操作，不改用其他身份。业务入参不能覆盖身份、目标版本或运行关联；状态及日志不得泄露凭据、未授权输出或原始远端异常。 |
| REQ-07 | **Mock 与兼容。** 首轮用明确标识的 Mock 模拟启动、非终态轮询、成功结果、失败、取消和超时；保留 F119 同步执行及无平台 Agent 节点的流程行为。正式替换位置保留关联待确认项的 `TODO`，真实失败不得回落为 Mock 成功。 |

## 4. 状态与竞争边界

下列名称表示可观察的业务含义，正式字段和枚举以双方确认的契约为准。

| 场景 | 毕昇 Workflow／节点 | 昆联 Agent Run |
| --- | --- | --- |
| 远端受理启动 | 等待结果；原运行可查询，不发布节点输出。 | 已有可信 Agent Run ID，可继续查排队、运行和进度。 |
| 启动未发出就超时 | 按启动超时结束本地执行，无需核对或取消。 | 未启动，不记为远端结果未知。 |
| 启动响应丢失或受理超时 | 展示启动结果未知；仍允许在原窗口内安全核对。同一执行不换标识补发。 | 可能已创建任务；找回前不显示虚构 ID 或终态。 |
| 远端成功且结果可用 | 未到截止且未停止时，校验并提交一次输出；下游继续原 Workflow。远端已成功但结果尚不可用时继续等待；截止后显示本地结果未取得。 | 只记录核验后的远端状态；已知成功不会因结果读取失败改为远端失败。 |
| 远端等待人工输入 | 节点明确以当前不支持的交互状态结束，阻断依赖结果的下游。 | 记录已确认的等待状态；不发人工输入，也不把等待标成远端失败。 |
| 停止先于输出提交 | 本地停止生效；后到成功不会产生输出或触发下游。若输出已先提交，停止不回写已完成的节点。 | 对尚未终态的原 Run 请求取消；如果最终确认远端成功、失败或已取消，分别记录其事实。 |
| 停止时尚无 Agent Run ID | 未发送启动则不再发送；在途请求只按原关联核对。没有可信标识时不得取消其他运行或重放可能创建新任务的请求。 | 如在核对窗口内找回原 Run 且它尚未终态，再尝试取消；否则保持远端结果未知。 |
| 取消受理、拒绝或确认超时 | 保持本地停止或超时，不恢复下游；展示取消进展或未确认原因。 | 取消受理只代表远端收到请求。仅远端确认取消终态时展示已取消。 |
| 到达本地截止仍未提交有效输出 | 按现有流程规则结束本地等待并阻断依赖输出的下游，重复查询或重试不续期。 | 已知未终态时尽力取消；允许在限定窗口内核对迟到的真实状态，但不改变本地终态。 |

## 5. 验收标准

| ID | Requirements | 可观察验收结果 | Verification |
| --- | --- | --- | --- |
| AC-01 | REQ-01、REQ-03、REQ-06 | 以 A 配置发布、B 实际运行的最小流程启动 Agent V1。启动回执先于结果，原请求结束后仍可查同一 Agent Run 的运行中状态、进度及最终结果；发布 V2 后仍按 V1 完成，正确输出只被下游消费一次。 | V-01、V-04 |
| AC-02 | REQ-02 | 同一节点重复投递以及模拟昆联已受理但首个响应丢失时，只产生一个远端 Run；核对成功复用原 Run ID，无法安全核对则报告未知。同一启动标识改输入或版本被拒，独立运行有独立关联。 | V-02、V-04 |
| AC-03 | REQ-03、REQ-05 | 模拟查询暂时失败后恢复、远端明确失败、结果未就绪、返回错误 Run 或版本、输出结构不符、收到旧状态。临时失败可在截止前继续查询，其他失败有明确分类；无效输出和人工等待不被当作成功，旧状态不能覆盖已确认终态。 | V-02、V-04 |
| AC-04 | REQ-04 | 在运行中重复停止或模拟取消响应丢失，只处理同一个取消意图。可观察到取消受理先于确认已取消。取消拒绝或确认超时分别展示，毕昇保持停止；对已确认终态的 Agent Run 不再发取消。 | V-01、V-02、V-04 |
| AC-05 | REQ-02、REQ-04、REQ-05 | 分别模拟停止早于启动发送、停止时启动响应未知、停止与成功竞争、等待截止后收到成功。停止生效前且未到截止时已提交的成功结果可以保留；后到结果只用于核对，不能触发下游或发起新的 Agent Run。 | V-02 |
| AC-06 | REQ-05 | 控制时钟分别触发发送前超时、发送后受理超时、本地等待超时和取消确认超时。核对不同提示、截止时间不续期，以及未启动、远端未知、已成功但结果不可用、已确认取消之间的区别。 | V-02、V-04 |
| AC-07 | REQ-06 | 错误用户、租户或接入方不能查询、读取结果或取消；运行人撤权后不得借用发布者或管理员身份补发。日志与状态只暴露授权范围内的关联信息和安全错误，不返回认证材料。 | V-02、V-04 |
| AC-08 | REQ-07 | F119 同步流程及无平台 Agent 节点的流程行为兼容；Mock 能区分来源，正式适配失败不返回模拟成功；待替换点可追踪。 | V-03 |

| ID | 验证方式 | 当前状态 |
| --- | --- | --- |
| V-01 | 隔离 Mock 流程验收：用现有运行和停止入口执行最小图，核对异步成功与取消确认闭环。 | `NOT_RUN` |
| V-02 | 用可控时钟和故障样例进行定向集成验证，核对幂等、停止与结果竞争、权限、状态和超时。 | `NOT_RUN` |
| V-03 | F119 同步路径及无平台 Agent 节点流程回归；核对 Mock 来源和正式替换边界。 | `NOT_RUN` |
| V-04 | 昆联提供契约、身份和测试环境后，验证真实异步启动、状态与结果、取消、幂等和权限。真实证据单独登记。 | `NOT_RUN`，待正式契约及环境 |

## 6. 昆联待确认的能力

以下按业务能力列出，优先复用昆联已有接口。同一接口可覆盖多项，不预设正式路径、接口数量、字段或时限。

| ID | 能力 | 待确认内容 |
| --- | --- | --- |
| EXT-01 | 异步启动及查回 | 支持长任务的固定版本如何识别；受理与拒绝回执、Agent Run ID；启动幂等键作用域、有效期及同键异参行为；响应丢失时能否按原关联查回，或是否支持保证不会创建新任务的安全核对。 |
| EXT-02 | 查询状态、进度与结果 | 查询标识、状态及终态含义、进度摘要、结果是否和状态同返、结果晚于成功状态的处理；固定版本证明、错误、限流、建议轮询间隔和保留期。 |
| EXT-03 | 取消 | 是否支持取消排队中和运行中任务，如何区分受理、已取消、不可取消和已终态；取消幂等及状态查询、取消与执行成功的竞争、超时后何时停止核对。 |
| EXT-04 | 实际用户与租户 | 优先确认现有 SSO Access Token 是否可用于启动、查询和取消，权限作用域、有效期以及长任务期间过期或撤权处理。无法复用时确认现有可信委托方式。 |
| EXT-05 | 联调材料 | 测试地址、OpenAPI、支持异步的固定 Agent 版本、授权与无权测试身份、正常／失败／取消／超时样例、可核对同一次 Run 的审计信息及可联调时间。 |

规格确认后再编写 `design.md`，确定如何沿用 F119 的执行关联与既有运行入口、何时让出执行资源、如何保存查询和取消所需事实，以及 Mock 契约与安全的异常收敛方式。本轮仅编写规格。
