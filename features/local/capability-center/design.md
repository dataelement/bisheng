# 交互与实现

网页工作区以“工具与技能”聚合能力发现、详情、试用和 Work 指令。后台“构建 → 工具”增加技能分类，复用原导入、新建、编辑、删除、单项启停及权限接口。工作台设置去掉工具展示名单和技能管理区域。连接器保持服务账号授权概念。

用户在输入框按任务选择能力：工具默认空集，技能由任务模式显式多选；用户可以关闭全部工具并单独选择知识空间。保留用户亲自操作过的工具偏好，管理员旧默认值退出执行路径。原配置字段保持历史兼容，读取端直接使用权限目录。

CapabilityCatalogService 通过 ToolServices(action=use) 投影安全字段；picker_tools 返回全部授权工具的分组及空默认选择。WorkCapabilitiesService 读取相同权限资源与已启用租户技能；历史 publication 表保留审计兼容，发布接口返回 410。执行仍验证权限、参数、工具依赖、内容哈希并记录审计。凭据留在宿主侧执行器。技能中途停用使下载作废。

网页前台基于 fa7fcf01a → 9db82c31a；管理端以实际 3007 平台构建 c14a4f0c4 建立独立分支，保留积分和模型管理增量。后台与实际 enterprise-work-v120 源码逐文件匹配后更新。演示服务为既有内网只读服务。

## 输入菜单层级

加号菜单一级按任务模式、技能、工具、文件、知识空间排序。技能与工具使用同一个 ComposerSubmenu 机制，各自在弹层内打开二级内容；具体工具及联网搜索统一在工具二级页。返回恢复一级，关闭后重置导航。任务与资源选中状态独立于菜单导航。

## 工具正文引用

技能、知识空间与工具使用同一个 ComposerEditor 文档。工具引用以 tool:<group-id> 映射原完整元数据，正文使用 /工具名称，引用文字与提示词分开序列化。删除、菜单取消选择和原生撤销同步工具状态。工具列表以名称、说明和选中标记构成，底部工具栏仅保留任务模式等独立控件。
