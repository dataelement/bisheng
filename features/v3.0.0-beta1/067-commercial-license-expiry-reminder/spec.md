# Feature: 商业授权统一到期提醒（F067）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How 一律不写在这里。** How 的唯一真相在 [design.md](./design.md)。

**关联 PRD**: 《3.0 beta2》§5.3 统计看板/ETL到期提醒
**优先级**: P1
**所属版本**: v3.0.0-beta1
**依赖**: v2.6.0 F037（Gateway 状态接口与管理后台 Banner 入口）；ETL4LM 2.1.0-beta1 授权查询能力；商业看板服务写入对应授权记录。无本版本未交付 Feature 前置。

> **范围边界**
> - **本次纳入**：
>   - 平台统一提醒 Gateway 授权、ETL 授权、商业版看板授权；提示中写明授权名称、到期日期和剩余天数。
>   - 各商业模块的当前授权状态持久保存，每个模块至多一条当前记录（已裁定：`license_info`）。
>   - ETL 授权由平台向 ETL 授权查询接口拉取后写入上述记录。
>   - 商业看板授权由看板服务定期更新对应记录；平台不向看板拉授权。
>   - Gateway 授权由管理后台先读取 Gateway 状态接口，再交给平台写入对应记录；平台不反向调用 Gateway。
>   - 管理后台从平台聚合查询读取全部授权状态，供超管 Banner 使用。
> - **本次明确排除**：
>   - 订阅信息服务授权（PRD 本期不纳入）。
>   - 在线续期、授权文件上传、邮件或飞书通知。
>   - 授权过期后的新功能降级（Gateway 既有付费接口降级保持不动；不新增看板 / ETL 过期拦截）。
>   - 用 ETL 服务地址、`BISHENG_DASHBOARD_PRO` 等配置推断授权是否有效或何时到期（它们只表示装没装）。
>   - 开源版（无对应商业模块）展示到期 Banner。

---

## 1. 用户故事

作为 **平台超级管理员**，
我希望 **Gateway、ETL、商业版看板任一授权临近到期或已过期时，在管理后台顶部看到写明名称、到期日和剩余天数的提醒**，
以便 **立刻知道该续哪一项，而不是对着「软件授权」猜测**。

作为 **普通用户**，
我希望 **使用因授权过期而受限的能力时，错误指出具体是哪一项授权**，
以便 **把问题交给管理员续对的那一项，而不是当成系统故障**。

## 2. 验收标准

> AC-ID 在本特性内唯一。字段名 / 表结构 / 接口路径等实现细节见 design.md。

### 2.1 提醒规则与可见性

- **AC-01** — THE SYSTEM SHALL 只把 Gateway 授权、ETL 授权、商业版看板授权纳入本期统一提醒；不得把订阅信息服务授权纳入。
- **AC-02** — WHERE 某项授权剩余天数大于 30, THE SYSTEM SHALL 不为该项展示到期提醒。
- **AC-03** — WHERE 某项授权剩余天数为 1 至 30（含 1 与 30）, THE SYSTEM SHALL 为该项展示即将到期提醒，并写明授权名称、到期日期和剩余天数。
- **AC-04** — WHERE 某项授权剩余天数小于或等于 0, THE SYSTEM SHALL 继续展示同一条提醒，文案明确为该项「已过期」，并写明授权名称。
- **AC-05** — IF 某项授权的状态未能取得, THEN THE SYSTEM SHALL 不得把该项展示为已过期，也不得用功能开关推断它已过期或仍有效。
- **AC-06** — WHEN 平台超级管理员登录或刷新管理后台, THE SYSTEM SHALL 获取一次聚合授权状态；页面持续打开期间不得轮询。
- **AC-07** — WHEN 非平台超级管理员进入管理后台, THE SYSTEM SHALL 不展示到期提醒 Banner。
- **AC-08** — THE SYSTEM SHALL 不按剩余天数区分黄色预警、红色紧急等展示级别；即将到期与已过期使用同一种 Banner 样式。
- **AC-09** — THE SYSTEM SHALL 不提供关闭 Banner 的入口；Banner 在当前页面会话中持续展示。

### 2.2 文案

- **AC-10** — WHEN 仅有一项授权需要处理, THE SYSTEM SHALL 直接展示完整信息，语义等价于：「{授权名称}将于 {到期日期} 到期，剩余 {N} 天。请联系授权提供方续期。」或该项已过期的对应完整句。
- **AC-11** — WHEN 多项授权同时需要处理, THE SYSTEM SHALL 在同一条 Banner 中逐项写明授权名称和状态，不得只展示汇总数量。
- **AC-12** — THE SYSTEM SHALL 使 Banner 与业务错误中的授权名称使用业务用词（Gateway 授权 / ETL 授权 / 商业版看板授权），不得再使用「软件授权」这类无法区分对象的通用文案。
- **AC-13** — THE SYSTEM SHALL 为新增用户可见文案提供 zh-Hans / en / ja，且不在源码中硬编码中文。

### 2.3 状态来源与持久化

- **AC-14** — THE SYSTEM SHALL 为每个纳入本期的商业模块持久保存至多一条当前授权状态；聚合提醒只读取这些已保存的标准状态。
- **AC-15** — THE SYSTEM SHALL 不接收、不存储授权密文、私钥或设备指纹。
- **AC-16** — WHERE ETL 解析服务已配置, THE SYSTEM SHALL 通过 ETL 提供的授权查询接口取得状态并写入对应记录；IF 该接口失败或未配置 ETL, THEN THE SYSTEM SHALL 按 AC-05 处理 ETL 项，且不得覆盖为已过期。
- **AC-17** — WHERE 商业看板服务会更新对应记录, THE SYSTEM SHALL 在聚合时读取该记录，不得由平台向看板服务拉取授权。
- **AC-18** — WHEN 管理后台能够从 Gateway 状态接口取得授权数据, THE SYSTEM SHALL 由平台把该数据写入 Gateway 对应记录后再纳入聚合；IF Gateway 状态接口不可达（含开源部署）, THEN THE SYSTEM SHALL 按 AC-05 处理 Gateway 项。
- **AC-19** — WHEN 平台超级管理员请求聚合授权状态, THE SYSTEM SHALL 返回各项的授权标识、展示用授权名、展示状态、到期日期、剩余天数和最近检查时间；展示状态只允许「正常 / 即将到期 / 已过期 / 未取得」四档，不得再下发预警、紧急等展示等级。
- **AC-20** — WHEN 非平台超级管理员请求聚合授权状态, THE SYSTEM SHALL 不返回可供展示的到期项（不得 403 打断页面）。

### 2.4 业务错误点名

- **AC-21** — WHEN 普通用户因某项商业授权过期而无法使用对应能力, THE SYSTEM SHALL 使业务错误指出该具体授权（例如「商业版看板授权已过期，当前无法访问该看板」），并携带可区分授权对象的标识。
- **AC-22** — THE SYSTEM SHALL 不在本期新增看板或 ETL 过期后的功能拦截；仅当既有能力已经拒绝时，按 AC-21 点名。Gateway 既有过期拦截保持有效，但文案须满足 AC-12。

### 2.5 回归

- **AC-23** — WHERE 开源部署没有 Gateway、未配置 ETL、也没有商业看板授权记录, THE SYSTEM SHALL 不展示到期 Banner，且不因状态接口不可达而弹出错误。
- **AC-24** — THE SYSTEM SHALL 保持 Gateway 既有「只拦网关付费接口、透传平台核心接口」的降级范围不变。

## 3. 边界情况

- 永久有效的授权（无到期日）：不展示到期提醒。
- 某源从未成功写入过记录：该项视为未取得，不展示。
- 某源本次拉取失败、但上次成功写入过到期日：不得改写成已过期；提醒是否出现以可读的到期信息为准，见 design.md。
- ETL 已到期时剩余天数为 0；Gateway 剩余天数可为负数。两者都按 AC-04 展示已过期。
- 只部署了其中一部分商业模块：只提醒已部署且状态已取得、且落入 30 天阈值的项。
- 跨过 30 天阈值后，须等下一次登录或刷新才出现或消失 Banner（AC-06）。
- 子租户管理员不是平台超级管理员：不展示 Banner（AC-07）。
