# v2 密钥鉴权错误码与 HTTP 状态码审查

日期：2026-09-15。依据：`docs/product/3.0 开放 API 鉴权与身份传递 PRD.md` v2.9，含 2026-09-14 身份输入订正，重点对照 §4.3、§4.4、§4.6.3、§4.10 和附录 C。

## 结论

错误类中登记的 PRD 状态码基本正确，主要偏差发生在异常包装、框架解析、中间件抢先拒绝和主体失效判定。下列问题已修正，并新增 HTTP 回归测试，同时断言响应体 `status_code` 和 HTTP 状态。

## 发现与修正

| 级别 | 场景 | 修正前 | 修正后 |
|---|---|---|---|
| P1 | v2 请求携带失效登录 Cookie/JWT | 登录中间件可能抢先返回 `19103/401`、`19104/401`、`20004/403` 等，与 API 密钥无关 | v2 由密钥管线决定身份与错误；缺少/非法密钥为 `26001/401` |
| P1 | 密钥缺失/无效，同时 JSON 或表单无法解析 | FastAPI 先报解析错误，未执行密钥依赖；部分响应只有 `detail` | 补跑凭据、权限位和身份头检查；分别为 `26001/401`、`26002/401`，凭据依赖故障为 `26030/503` |
| P1 | 助手调用的资源权限拒绝、资源不存在、权限服务异常 | 被宽泛捕获，统一返回 HTTP 500 和字符串，丢失业务码 | 交给统一异常处理；保留原业务码，分别为 HTTP 403、404、503；流式请求在开始发送前同样生效 |
| P1 | 旧业务错误使用 `http_exception()`，例如知识库类型不支持 | 五位业务码直接成为 HTTP 状态，真实服务器可能无法发送合法响应 | 保留错误类型及业务码，只把合法状态写入 HTTP 层 |
| P1 | 权限枚举不完整、投影/评估失败、Catalog 未就绪或模型不匹配 | 默认映射 HTTP 400，被错误归类为调用参数问题 | 保留权限模块业务码，HTTP 503，符合 PRD“评估失败返回 5xx” |
| P1 | PAT 因持有人停用/删除被级联撤销 | 先命中“密钥已撤销”，返回 `26002/401`，掩盖持有人原因 | 返回 `26043/401`；手动撤销、重新获取和单纯过期仍为 `26002/401` |
| P2 | 服务账号停用/删除 | 合并成 `26002/401` | 使用既有 `26027/401`；此编号来自已实现的 F053 错误分配，PRD 附录 C 的注释要求与密钥无效区分 |
| P1 | 子租户服务账号密钥首次校验 | 中间件已设置默认租户，账号查询被错误过滤，合法密钥可能被拒绝 | 根据已校验的凭据读取主体，再明确比较租户；默认租户上下文不干扰密钥认证 |
| P2 | `application/*+json`、大小写变化或未声明 Content-Type 的 JSON 包含裸 `user_id` | 旧身份参数可能绕过专门检查，被当普通参数忽略或返回通用 400 | `26019/400`，错误信息指向 `X-On-Behalf-Of` |
| P2 | 委托用户 ID 超出数据库整数范围或超过 Python 整数转换限制 | 可能变成驱动/转换异常，返回 5xx | `26005/403`，与无效委托目标一致 |
| P2 | 非日常聊天端点的非法请求含 `task_mode/run_mode/execution/background` | 全局异常处理误报 `26015/26017` | 仅日常聊天端点使用这两个能力码；其它端点仍返回自身参数错误 |

共享的 WebSocket 密钥定期校验移到 domain service；API 依赖保留原导出，避免助手接口跨模块导入 API 层。校验频率、连接关闭行为不变。

## PRD 错误码核对表

下表为响应体业务码与 v2 HTTP 状态的对应关系。运行场景测试覆盖凭据、主体生命周期、身份头、PAT 开关、权限故障和接口错误传播；错误类参数化测试覆盖表中全部已实现编号的异常序列化。

| `status_code` | 场景 | HTTP |
|---|---|---|
| 26001 | 密钥缺失或格式非法，登录 JWT 不能替代 | 401 |
| 26002 | 密钥不存在、普通撤销、过期或不匹配 | 401 |
| 26003 | 缺所需权限位 | 403 |
| 26004 | 无委托能力或目标不在范围内 | 403 |
| 26005 | 委托目标无效、非正整数或不存在 | 403 |
| 26006 | 端点不支持委托 | 403 |
| 26007 | 委托目标是特权主体 | 403 |
| 26010 | 两个身份头同时出现 | 400 |
| 26015 | 日常聊天要求未开放的异步执行 | 400 |
| 26016 | 持 `delegate` 却漏传委托身份头 | 400 |
| 26017 | 日常聊天要求任务模式或非法运行模式 | 400 |
| 26018 | 外部用户标识为空、超长或含非法字符 | 400 |
| 26019 | 已移除的身份头或裸 `user_id` | 400 |
| 26040 | PAT 部署级或租户级能力未开 | 403 |
| 26041 | PAT 权限位超出白名单 | 400 |
| 26042 | PAT 有效期超限 | 400 |
| 26043 | PAT 持有人失效，包括相应级联撤销 | 401 |
| 26044 | PAT 数据范围受限 | 403 |

`26041/26042` 属于令牌签发参数校验，当前签发接口在 v1；本次核对其错误定义，未把 v1 的历史信封响应改成 v2 的 HTTP 契约。`26012` 属于服务账号登录场景，当前服务账号独立于自然人用户表，不是 v2 调用入口。`26008/26009/26011` 是 P2 预留，`26013/26014` 已废止，不新增返回路径。

业务资源权限错误按 PRD §4.4.1 保留原业务码，不统一替换成 `26003`。`26027`、`26030`、`26031` 是既有实现补充码，分别采用 401、503、500。

## 验证与边界

- 现有 Open API 测试集、v3 路由兼容性检查、知识检索权限回归、JWT 版本及租户认证回归合并运行：**416 passed**（10.87 秒，2 条依赖弃用警告）。
- 全部已注册 v2 HTTP 路由逐项覆盖缺失密钥和非法密钥；两个 WebSocket 路由验证握手前拒绝；助手同时覆盖流式/非流式请求开始前的业务错误。
- Ruff 格式、lint 与修改文件的架构守卫通过。
- 本机直接运行 pytest 会被缺失的部署环境变量阻断。本次使用仓库既有配置替身，并为 `open_api` 与 `knowledge_qa_filter` 提供真实配置类默认值；持久化场景使用现有 SQLite 内存测试夹具，外部依赖使用测试替身。
- 未连接真实 MySQL/DM8、Redis、OpenFGA 或商业网关；因此不把这些结果表述为部署环境 E2E 验收。
- WebSocket 依照既有设计以 1008 拒绝握手，原因携带业务码；没有先 accept 再断开。PRD §4.6.1 未规定 WS 专用 JSON 响应格式，本次不增加新握手协议。SSE 已发送响应头之后发生的业务失败仍走流内终态，HTTP 状态无法在发送后改写。

新增回归文件位于 `src/backend/test/open_api/`：`test_error_contract.py`、`test_credential_error_contract.py`、`test_route_error_contract.py`。
