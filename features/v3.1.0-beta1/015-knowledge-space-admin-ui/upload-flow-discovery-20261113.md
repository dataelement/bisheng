# 四步上传恢复：现状与范围

日期：2026-11-13。分支：codex/3.1.0-beta1/knowledge-space-admin-ui。基线：a3ebe5828c。当前仅整理规格，尚未修改业务实现。

## 已确认的用户要求

恢复旧版“上传文件 → 分段策略 → 原文对比 → 数据处理”步骤和 UI。空间已配置规则时优先采用空间有效配置，否则采用系统默认；用户可修改本次规则，最终处理仍使用前端提交规则。保留本轮已完成的管理/普通范围、目录定位与文件详情入口调整。

## 当前代码事实

- filesUpload.tsx 在目标 upload_file 动作确认后挂载 SpaceFileUploadPanel；该组件选文件后立即暂存、注册正式 SPACE 文件并跟踪处理状态，没有独立的策略与原文对比步骤。
- 旧四步页面在 0e03dcc367 的前一版本；FileUploadStep1、FileUploadStep2、PreviewResult、FileUploadStep4 及 StepProgress 仍在仓库。旧最终提交和状态查询面向原知识库，不能直接覆盖当前 SPACE 文件注册、目录及精确 ID 状态链。
- 当前 GET /knowledge/space/{id}/files/upload-settings 使用 require_upload_container，按当前空间/文件夹的 upload_file 授权返回 effective_defaults；其规则由现有服务端合并空间/系统默认，适合直接作为上传 UI 初值。
- 当前 POST /knowledge/space/{id}/files 与 folders/upload 已接受 overrides；最终提交可继续传递用户确认后的文档/表格规则，无需改现有正式文件注册契约。
- 旧 POST /knowledge/preview 及 PUT/DELETE 预览调用 KnowledgeService，按空间根 edit 进行鉴权，未绑定本次上传容器。仅文件夹 upload_file 用户会被阻断，直接移植旧前端不能满足现有授权范围。
- SPACE 正式处理已按规则摘要查找预览缓存；恢复时必须保证预览与最终提交使用一致的路径和规则，防止页面看见的切分结果与实际入库结果不同。

## 拟恢复范围

1. 复用旧四步外观、规则表单与原文/分块展示，接回当前 SPACE 暂存上传、正式注册和状态跟踪；保留文件夹、普通/管理视图、大小/格式、重试及生命周期保护。
2. 上传步骤只暂存文件；策略步骤读取有效默认并允许修改；预览步骤使用该次规则进行真实解析；确认后才注册处理，提交明确的规则快照。
3. 为上传预览补齐当前容器 upload_file 授权与临时文件/预览归属校验，不能以放宽旧根 edit 检查替代。正式文件的元数据、分段调整及旧知识库调用维持各自原权限。
4. 对空间默认、系统默认、手动修改、预览/提交一致、只有文件夹授权、跨身份/租户/目标、重试及重复提交进行自动化与浏览器验证。真实环境写入 E2E 另行记录环境与结果。

## 流程分级

需求本身的四步及默认策略已经由用户明确提出，作为范围发现输入。代码排查确认，完整恢复还涉及上传预览接口与资源授权衔接，超出纯 UI 修复。依照根 AGENTS.md §6 和 docs/SDD-Guide.md §1，按 Full SDD 的规格、设计确认点推进；本轮先提交 AC-21 至 AC-25 的可评审规格，不在确认前变更业务代码。
