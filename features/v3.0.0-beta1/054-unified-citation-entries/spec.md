# Feature: 全问答入口统一溯源角标（F054）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
> spec 只回答 **做什么 / 验收标准 / 不做什么**；所有 How 在 [design.md](./design.md)。
> **前置**：Spec Discovery 已完成并裁定三个口径，见 [discovery.md](./discovery.md) §4。

**关联需求**: 产品文档《1.1 全问答入口统一展示溯源角标》（通用需求）

**依赖**: F029（知识库检索权限过滤 / INV-7）· F041（`shared` / `per_user` 来源权限双档）· 现有 citation 子系统（`bisheng/citation/`）

> **范围边界**
> - **本次纳入**：
>   - **频道文章 AI 问答接入溯源**：文章内容作为**第三种来源类型**登记、模型引用、前端角标、点击打开原文。
>   - **「来源已失效」状态**：与「暂无权限」区分开，前端呈现为不可点的独立状态。
>   - **来源详情权限收紧**：一律按**当前登录用户**校验；匿名 / 分享场景等同无权限（discovery §4.1）。
>   - **工作流临时文件停止产生角标**（discovery §4.4）。
>   - 溯源相关用户可见文案补齐三语（zh-Hans / en / ja）。
> - **本次明确排除**：
>   - **灵思任务模式接入** —— 由 **F047** 独立交付（其 spec / design 已定稿）。本 Feature 不重复实现，仅共用同一套引用注册与解析链路。[待澄清：是否改为并入本 Feature 一并交付]
>   - **临时来源的溯源能力**（日常模式上传附件、工作流临时文件、灵思上传附件）—— 下一版单独立需求（discovery §4.5）。本期只做「关掉」，不做「支持」。
>   - **提示词被改写后的角标兜底** —— 维持现状，管理员改写提示词后该入口不出角标属预期行为（discovery §4.2）。
>   - **平台端与用户端角标组件合并** —— 平台端继续使用现有实现；合并的前置是公共主题接入，属独立基建（discovery §4.3）。
>   - **知识空间 / 工作流 / 日常模式 / 助手的溯源改造** —— 已上线，本期不动（discovery §2.1）。
>   - **「参考资料」汇总面板**（结果区聚合本次全部来源）—— 本期只做行内角标 + 单来源详情面板。
>   - **导出件的可见引用（烘焙）** —— 用户裁定会话导出维持现状（继续剥离角标）；烘焙能力整体归 **F047 Phase 2**。

## 1. 用户故事

作为 **在频道里就文章向 AI 提问的业务用户**，
我希望 **答案里引用文章内容的地方带可点击角标，点开能回到原文**，
以便 **确认这句话是文章原文还是模型自己的发挥**。

作为 **对数据可见性敏感的管理员 / 合规角色**，
我希望 **任何人看到的来源详情都按他本人的权限实时判定，包括通过分享链接访问的人**，
以便 **不会因为一条分享链接把知识库文件的内容和下载入口一并泄漏出去**。

作为 **阅读历史答案的用户**，
我希望 **来源已经被删除或失效时，角标明确告诉我"来源已失效"，而不是点开一片空白**，
以便 **区分"我没权限"、"来源没了"和"系统坏了"**。

## 2. 验收标准

> AC-ID 在本特性内唯一。错误码 / 字段等实现细节见 design.md。

### 2.1 频道文章问答接入溯源

- **AC-01** — WHEN 频道文章 AI 问答读取文章内容用于作答, THE SYSTEM SHALL 为该文章登记一条带**稳定定位标识**的溯源来源，携带足以展示与跳转的信息（文章标题、摘要、原文链接或文章文档标识），并使模型在读到该内容时能获得对应来源标识。
- **AC-02** — THE SYSTEM SHALL 为文章来源使用**真实稳定的定位标识**（文章文档标识或原文链接），不得伪造知识库片段标识。
- **AC-03** — WHEN 模型撰写答案并使用了已登记的文章来源, THE SYSTEM SHALL 使答案正文在对应句 / 段位置内联携带该来源的溯源标记；未使用时不产生标记。
- **AC-04** — WHEN 用户悬浮文章角标, THE SYSTEM SHALL 展示来源类型、标题、引用摘要与来源名。
- **AC-05** — WHEN 用户点击文章角标, THE SYSTEM SHALL 打开该文章原文。
- **AC-06** — WHEN 频道文章问答的一轮回答结束, THE SYSTEM SHALL 仅把答案中**实际引用到**的来源持久化并绑定到该回答消息；重复处理同一条回答不产生重复来源记录。

### 2.2 导出维持现状

> 用户裁定（2026-09-07）：**会话导出继续剥离角标**，本期不做烘焙。
> 导出烘焙（可见编号 + 文末参考资料）整体归 **F047 Phase 2**，不在本 Feature 范围。

- **AC-07** — WHEN 用户导出会话为 Word / PDF / Markdown / 纯文本, THE SYSTEM SHALL 保持现有行为：正文中的隐藏溯源标记被完整剥离，导出件中不出现任何角标、编号或参考资料段。

### 2.3 状态与文案

- **AC-08** — WHERE 某角标对应的来源已被删除或已不可解析（且不因权限被过滤）, WHEN 用户查看该答案, THE SYSTEM SHALL 把该角标呈现为**「来源已失效」**的不可点状态，并保留答案正文完整。
- **AC-09** — WHERE 查看者对该来源无查看权限, WHEN 用户查看该答案, THE SYSTEM SHALL 把该角标呈现为**「暂无权限查看该来源」**的不可点状态，且与「来源已失效」在文案上可区分。
- **AC-10** — WHERE 无权限与已失效同时成立, THE SYSTEM SHALL 一律呈现为「暂无权限查看该来源」（从严，不向无权限者暴露该来源是否曾经存在）。
- **AC-11** — THE SYSTEM SHALL 使所有用户可见的溯源文案具备 zh-Hans / en / ja 三语，且不在源码中硬编码中文。
- **AC-12** — THE SYSTEM SHALL 在任何用户可见状态下**只展示角标序号与可读来源信息**，内部引用键、片段标识与协议标记始终不可见（含复制答案文本、导出、分享等状态）。

### 2.4 来源详情权限

> **口径**（discovery §4.1 裁定 + 评审对齐）：本次收紧**只作用于「无已登录用户」的调用**。
> F041 已登记的 INV-7 例外（工作流 / 助手入口「用户知识库权限校验」开关关闭时产生的 `shared` 档来源）**保持不变**，不在本 Feature 收紧范围内。

- **AC-13** — WHEN 已登录用户请求来源详情, THE SYSTEM SHALL 按**该用户本人**的权限实时判定，并保持 INV-7 现有两档语义完全不变：`per_user` 档无权限则整条不返回；`shared` 档保留来源元数据、但完整文件的预览 / 下载入口仍按该用户权限把关。
- **AC-14** — WHERE 请求来源详情的调用不携带已登录用户身份（含通过分享链接的免登录访问）, THE SYSTEM SHALL 不返回**知识库来源与文章来源**的详情（知识库来源含 `shared` 档）；**网页来源仍照常返回**（公开 URL、不含租户数据，收紧它与本次意图无关）。
- **AC-15** — WHERE 分享页中的角标因 AC-14 无法解析, THE SYSTEM SHALL 按 AC-09 呈现为不可点状态并保留答案正文，不得报错、不得使页面渲染失败。
- **[待澄清]** F053 正在把免登录分享页改走 share_link 通道并引入「share-token 会话执行主体」。届时分享页将**携带主体**而非匿名，AC-14 的判据需与 F053 owner 对齐：是仍一律拒绝，还是按 share-token 主体判定。本 Feature 先按「无已登录用户即拒绝」实现。

### 2.5 临时来源不产生角标

- **AC-16** — WHEN 工作流 Agent 检索**输入节点上传的临时文件**, THE SYSTEM SHALL NOT 为其登记溯源来源，答案中不出现指向临时文件的角标。
- **AC-17** — THE SYSTEM SHALL 不改变临时文件检索本身的召回结果与答案内容（仅不再产生角标）。

### 2.6 非侵入与兼容

- **AC-18** — THE SYSTEM SHALL 保持工作流、日常模式、助手、知识空间四类已上线入口的溯源行为不变。
- **AC-19** — IF 来源登记 / 标注过程发生任何异常, THEN THE SYSTEM SHALL 回退到不带溯源的结果并继续作答，溯源失败不得使问答报错或中断。
- **AC-20** — IF 历史消息缺少结构化溯源数据, THEN THE SYSTEM SHALL 原样保留答案，不补造角标、不报错。
- **AC-21** — WHEN 同一答案在流式生成、生成完成、历史回看、分享等状态下展示, THE SYSTEM SHALL 使用同一份溯源数据，角标序号与来源归组保持一致。
- **AC-22** — WHERE 某问答入口支持重新生成, WHEN 用户重新生成答案, THE SYSTEM SHALL 按同一规则为**新答案**产生并保存溯源，且不使新答案沿用旧答案的来源绑定。

## 3. 边界情况

- **文章问答未引用文章内容** → 答案无角标，不持久化来源（正常，非缺陷）。
- **同一句引用多个来源** → 渲染为相邻的多个角标；同一来源重复引用复用同一序号。
- **模型漏发或错发标记** → 已注册的正常渲染；未注册的标记在保存前清除，不产生悬空角标。
- **答案中同时含知识库、网页、文章三类来源** → 按统一规则混合编号，各自呈现自己的类型与跳转方式。
- **分享页含多个角标且查看者未登录** → 全部呈现为不可点状态，正文与排版不受影响。
- **重新生成** → 工作台 Agent 流程当前已无重新生成入口，AC-22 以「入口存在时」的条件式表述覆盖；实现期按各入口实际情况落测。
- **工作流临时文件与知识库来源混用** → 知识库来源照常出角标，临时文件来源不出角标；答案正文不因此断裂。
