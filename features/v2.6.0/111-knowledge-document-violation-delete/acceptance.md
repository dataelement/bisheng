# 知识文档违规删除验收矩阵

- 状态：实现前。业务代码尚未落地，本文件只列用例，没有执行，没有通过结论。
- 依据：同目录 [design.md](./design.md)，以及 2026-10-15 已确认的需求口径。
- 主模块：毕昇知识库违规删除；积分模块只被调用。门户积分规则页是规则编辑消费者。
- 环境：流转用例要用毕昇 `config.yaml` 的 171 MySQL，并查表。达梦在 macOS 上不跑，留到 CI。不把页面显隐当功能通过。

## 需求追踪

| 行为 | 验收 |
|---|---|
| 新增违规删除，按影响范围扣分，并删除原件和全部发布、分享副本 | VD-01 至 VD-06、VD-14 |
| 月奖豁免、自己的上传、找不到被扣人：删除且不记账 | VD-07 至 VD-10 |
| 同一文档扣分只成功一次，含恢复后再删 | VD-11、VD-12 |
| 无权限、个人库、无文档身份、发布准备中：拒绝且不写库 | VD-15 至 VD-18 |
| 普通删除和专家问答 R1–R3 保持原行为 | VD-19、VD-20 |
| R4–R6 三档分值可编辑，非法分值拒绝 | VD-21、VD-22 |
| 扣分失败后按确认时的金额补扣 | VD-13 |

没有未关闭的产品歧义。弹窗用词不锁，不单列文案用例。

## 检查清单里适用的项

适用：主成功和只删不扣、恢复后再删、权限与个人库、重复提交、并发、补扣、规则停用、旧文件无文档身份、MySQL 查表、错误码不带正文。

不适用：分页、导出、上传新文件、自动扫敏感词、性能门槛。达梦列结构留到 CI，本矩阵不把未跑标成通过。

## 用例

建议落点：`src/backend/test/knowledge/test_knowledge_violation_delete_flow.py`。规则编辑校验可放 `src/backend/test/points/test_library_scope_rule_expr.py`。专家问答回归点名现有 `test/qa_expert/test_moderate_delete_points_notify_flow.py` 里的 R1 用例，不把新断言写进那个文件。

接口：

- 预览 `POST /api/v1/knowledge/space/files/{file_id}/violation-delete/preview`
- 确认 `POST /api/v1/knowledge/space/files/{file_id}/violation-delete`
- 规则 `PUT /api/v1/points/admin/rules/{rule_id}`

| ID | 优先级 | 层级 | 角色与初始状态 | 步骤 | HTTP | 落库与副作用 | 再打一枪 |
|---|---|---|---|---|---|---|---|
| VD-01 | P0 | 接口流转 | 部门库管理者。文档在公共库和部门库都可见。上传者无月奖身份。R4 公共库分值为 3 | 预览后带 R4 确认扣分 | 成功。预览档位为公共库、金额 3。确认 `deleted=true`、`deducted=true` | `knowledge_document.lifecycle_status=recycled`。两库入口 `knowledge_file.deleted_at` 非空。`user_point_log` 一条，`delta=-3`，`rule_code=R4`，`biz_type=knowledge_document`，`biz_id` 为文档 id。`user_point_account` 余额减少 3 | 再确认一次，流水仍为 1 条 |
