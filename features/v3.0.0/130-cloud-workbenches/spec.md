# Feature: 企业云端工作台

**版本**：v3.0.0 / `feat/bisheng-work-130`。**关联**：[design.md](./design.md) · [tasks.md](./tasks.md)。

本文件于 2026-11-09 按用户“修复两个 PR、验证后合并并部署”的授权，补记 [PR #2595](https://github.com/dataelement/bisheng/pull/2595) 已实现的需求边界；不声称此前执行过缺失的 SDD 确认步骤，不新增产品能力。

## 1. 用户故事与范围

员工使用当前企业账号发现并使用有权访问的云端工作台；开发者在明确修改应用功能时获取有权编辑的源码，通过既有发布流程迭代。应用所有者可让团队成员共享云端业务记录。

范围为企业托管应用的桌面身份适配、浏览器目录、在线开发规范和记录协作。桌面配套实现属于 bisheng-desktop PR #125；此仓库不交付桌面安装包。多人逐字协同编辑、多实例共享 SQLite、自动审批和自动扩大团队可见范围均不属于本次能力。

## 2. 验收标准

| ID | 角色 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| AC-01 | 当前员工 | 查看云端工作台目录 | 仅返回本人当前租户内、上线且具有使用权限的应用；支持继续分页 |
| AC-02 | 桌面用户 | 打开有权使用的应用 | 进入正式托管网址；访问凭据只适用于该应用，短期票据只能兑换一次 |
| AC-03 | 桌面用户 | 设备会话撤销、过期或身份失效后再次访问 | 拒绝访问；已有长连接在重新鉴权后关闭 |
| AC-04 | 应用开发者 | 获取指定版本源码 | 必须具有编辑权限；不向仅有使用权限者提供源码，不导出密钥或业务数据库 |
| AC-05 | 应用开发者 | 提交首次或迭代发布 | 沿用扫描、预检、审批和上线流程；迭代基线已变化时拒绝覆盖，异步执行前重新校验当前身份和动作 |
| AC-06 | 普通员工 | 从客户端应用页或管理端构建页进入目录 | 到达同一云端应用目录；使用应用不会自动下载源码或触发发布 |
| AC-07 | 应用成员 | 并发修改同一共享记录、重试写入、恢复订阅 | 拒绝旧版本覆盖；同一用户同一操作重试不重复写入；断线按游标补偿，超出保留范围时重新读取快照 |
| AC-08 | Agent / 应用开发者 | 获取企业在线指南与 SDK | 可读取中英文规范；现有 SDK 0.1.1 与新增 0.1.2 均可按固定版本下载和校验 |

## 3. 验收边界

自动化使用合成身份和外部服务替身；通过不代表真实部署、桌面安装包、双用户端到端发布、24 小时运行或 Kubernetes 验收完成。实际环境证据记录在 tasks.md；QA 参考见 [test-cases.md](./test-cases.md)。
