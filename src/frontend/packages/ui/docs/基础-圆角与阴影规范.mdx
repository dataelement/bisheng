# 圆角与阴影规范 Radius & Shadow

圆角决定一块表面看起来有多柔和，阴影决定它「浮」得有多高。两者都只从固定档位里取值——圆角八档、投影两档，不自造数值。

## 1. 圆角 Radius

**值从八档阶梯里取（§1.1），取哪一档按四条使用原则定（§1.2）。**

### 1.1 阶梯一览

<RadiusLadder />

类名即 token 名（`rounded-sm` 就是 4px 档），完整的 CSS 变量与 Tailwind 类对照见「设计变量 Design Token」页。

### 1.2 使用原则

先按**尺寸定档**取到基准档，用**同级同档**校齐一组模块；嵌套时按**嵌套同心**算内层，贴边时按**贴边归零**去掉圆角。

#### 1.2.1 尺寸定档：越大的东西用越大的圆角

- **控件随自身尺寸取**（按钮、输入框、选择器、菜单项）：small 用 sm（4px）、medium 用 md（6px）、large 用 lg（8px），按钮三档即照此（见「组件 → Button」）。**拿不准就用 md**。
- **容器随大小取**：卡片、下拉面板用 xl（12px）；弹窗、大卡片容器用 2xl（16px）；抽屉、超大容器用 3xl（24px）；特大区块用 4xl（32px）。**弹窗统一 16px**。
- **胶囊与圆形用 full**：头像、pill 标签、圆形 icon 按钮（仅限单 icon，见「组件 → Button」）。

#### 1.2.2 同级同档：同级模块圆角一致

**同一个界面中，相同重要程度的模块取同一档圆角。** 并排的卡片、同一列表的条目、同一行的控件都算同级。

<PeerDemo />

- 同级模块尺寸有差、按尺寸定档（§1.2.1）会分到不同档时，**统一取较大的那一档**。
- 重要程度不同的不受此限——弹窗 16px 里嵌 8px 卡片，正是该有的层次差别。

#### 1.2.3 嵌套同心：内层 = 外层 − 内边距

**内层圆角 = 外层圆角 − 内边距**（归并到最近档位，最小 4px），这样内外两段圆弧同心，角部间隙均匀。例如弹窗 16px、内边距 8px 时，贴边卡片用 8px。

<NestDemo />

#### 1.2.4 贴边归零：贴边的角不留圆角

圆角属于「浮在内容之上的独立表面」。容器在移动端铺满屏幕或贴住屏幕边缘时，**贴边那侧的角改直角**——不是缩一档，是归零：

- **全屏展示**：四角全部直角。
- **从底部滑入贴底**：只保留顶部两角的容器档圆角，底部两角直角。
- 移动端仍居中、四周留边的容器不受影响，照 §1.2.1 取档，不因屏幕变窄而缩档。

断点与判定口径见「多端适配 Responsive」。

### 1.3 正误对照

| ✅ 推荐 | ❌ 不推荐 | 原因 |
|---|---|---|
| `rounded-2xl`（弹窗 16px） | `rounded-[20px]` | 20px 不在阶梯上，同类弹窗一个 16 一个 20，并排就对不齐 |
| 并排三张卡片都用 `rounded-xl` | 一张 `rounded-lg`、一张 `rounded-xl`、一张 `rounded-2xl` | 同级模块各取各的档，读不成一组（§1.2.2） |
| `rounded-sm`（4px） | `rounded-[5px]`、`rounded-[0.185rem]` | 离散值与 4px 肉眼难辨，却让「同一控件同一圆角」失效 |
| `rounded-sm` | `rounded`（裸类） | 两者同为 4px，但裸类不带 token 名，看不出取的是哪一档 |

## 2. 阴影 Shadow

BISHENG 的投影走「淡」路线：带一点蓝黑色、透明度很低，把浮层轻轻托起来，而不是砸出一圈黑晕。投影只有两档，按元素浮起的高度取。

### 2.1 投影两档

| 档位 | 投影值 | Tailwind 类（即 token 名） | 用在哪 |
|---|---|---|---|
| 浮层投影 Popup | `0 2px 16px -2px rgba(0,23,66,0.10)` | `shadow-popup` | 下拉菜单、选择器面板、气泡卡片、悬浮提示——点开即现、点外即走的临时浮层 |
| 模态投影 Modal | `0 0 16px 0 rgba(3,7,117,0.05)` | `shadow-modal` | 弹窗、抽屉——要求用户处理完才关闭的打断式浮层 |

<ShadowTiers />

代码里取用类名即可，不要自己写投影值。

### 2.2 使用规则

- **只用这两档，不自造投影**：Tailwind 自带的预设投影档和手写的投影值都不使用。第三方组件自带的投影可以整个去掉，但不能改成别的值。
- **投影颜色用蓝黑，不用纯黑**：两档投影色都带一点蓝、透明度不超过 10%；纯黑在浅色界面上发灰发脏，混排还会打乱层次。按两档取值，这条自动满足。
- **页面内静止的区块不加投影**：普通卡片、表格、表单区用边框和填充分层。只有真正浮在内容之上的元素（下拉、气泡、弹窗、抽屉）和拖拽中的元素才带投影——什么都浮起来，等于什么都没浮起来。
- **投影可以和 1px 浅色边框搭配**：暗色模式下投影不明显时，边框还能帮浮层勾出轮廓。是否带边框由各组件自定，不作硬性要求。

### 2.3 正误对照

<ShadowContrast />

| ✅ 推荐 | ❌ 不推荐 | 原因 |
|---|---|---|
| 下拉面板：`shadow-popup`（浮层投影） | `shadow-lg`（Tailwind 纯黑预设） | 一次违反两条：不在两档内，且是纯黑——又重又灰，混排会打乱层次 |
| 静态卡片：只用边框分层 | 页面里每张卡都加投影 | 投影表达的是「浮起的高度」，静态内容浮起来没有意义，还让真正的浮层失去对比 |

## 3. 例外与新增

- **圆角与投影一律取表内档位**：出现表外的手写值即视为未走规范；确属例外的，在对应组件文档里写明原因并注明「见圆角与阴影规范」。
- **新档位先进规范、再进代码**：先由设计师在本文与 design token 里定档，之后才能出现在代码里，不允许先用后补。
