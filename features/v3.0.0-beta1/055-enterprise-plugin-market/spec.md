# F055 企业插件市场

更新：2026-10-19。企业插件采用企业登录与在线席位校验。后台保留【构建 → DSH】中的导入、查看、删除。

## 用户与页面

- 登录租户的管理员管理本租户插件；持有有效席位的员工连接企业服务，在 Desktop 安装和使用本租户可用插件。全局管理员进入本页时同样使用登录租户。
- 页面展示标题、说明、导入按钮和插件列表。列表列为插件名称、版本、适用系统、更新时间、操作；每行提供详情和删除。
- 详情只读展示版本、发布者、许可证、权限声明、服务地址及更新说明。
- 页面按登录身份取租户，搜索、状态筛选、状态列、上下架按钮、租户管理视图均已移除。其他管理页面选过的租户范围对本市场保持独立。
- 超过一页时显示分页；删除最后一行后回到有效页。导入显示上传进度和校验结果，失败任务保留重试入口。

## 导入与删除

1. 管理员导入一个完整离线 ZIP（单插件、多平台）。校验通过后自动供员工安装；上传有效新版本切换当前版本，失败保留原版本。
2. 当前可用插件的相同包重复上传保持当前版本。已删除或旧版下架的插件可以通过再次导入恢复；同一插件同一版本仍保持摘要不可变。
3. 删除前确认影响，并携带当前 revision。删除后从管理列表、详情、员工目录和下载入口移除；其他租户的记录保持独立。并发版本变更导致旧 revision 删除失败，刷新后重试。
4. 删除采用持久化标记，保留版本及后台操作记录。已安装插件在在线席位校验通过且插件使用策略有效时继续使用；新安装、更新需当前可用版本。历史制品自动回收留待容量治理。
5. 旧 publish/unpublish/disable 接口和设备报告保留协议兼容，首版页面提供导入、查看、删除。旧禁用状态仍按原策略生效；明确再次导入可恢复可用。
6. 管理员负责选择导入内容。系统校验包结构、依赖、平台和摘要；权限/来源声明由管理员查看，真实内网服务可用性另行验证。

## Desktop 与范围

企业模式内置市场，通过已确认的企业地址读取目录、授权下载和在线发布状态。员工分发接口复用 Desktop 登录凭据并在线确认席位；管理员导入和管理采用平台租户管理员身份。客户端确认席位有效后显示“来自企业”，后台按 60 秒周期同步。席位回收、会话到期或连接失败时收起入口并停用运行实例，重新确认成功后按用户启用状态恢复。

市场协议为 `contract_version=2`，同步响应包含企业、账号、设备、同步时间和插件发布状态。安装、更新、启用均在线复核。完整依赖在发布包内准备，安装执行摘要、文件清单、平台和依赖校验，并由真实 Cordis Loader 加载；更新失败恢复旧运行版本。

ZIP 上限 512 MiB、展开上限 1 GiB、50,000 项；manifest 8 MiB；配置 JSON 64 KiB。当前支持单插件完整包；批量集合包导入、配额/清理和结构化配置向导留待后续。插件作为管理员选择的可信宿主代码运行，逐操作权限和进程隔离由宿主环境提供。

BISHENG 与配套 Desktop 按协议 2 协同发布。确定性测试、部署健康、登录用户完整流程及原生 Desktop UI 的证据分别记录于 tasks.md 和 deployment.md。

## 在线访问验收

- AC-ONLINE-1：有效 Desktop 席位可查询目录、下载、同步和安装，市场只依赖既有企业服务配置。
- AC-ONLINE-2：普通平台登录和失效 Desktop 席位在全部员工分发接口被拒绝，平台管理员继续管理本租户插件。
- AC-ONLINE-3：账号切换和退出清理上一身份的可见目录与运行实例，企业、账号与设备范围保持一致。
- AC-ONLINE-4：后台说明和删除提示准确展示在线席位条件；中、英、日三语同步。
- AC-ONLINE-5：升级保留已安装插件和配置，旧市场公钥及租约缓存由客户端清理；插件包完整性和更新回退继续验证。
