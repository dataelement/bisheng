# 积分按模型真实价格扣除：确认的需求来源

2026-11-10，Callum 提出【后台模型与积分管理优化】：积分要按模型真实价格扣，四类 token（未命中缓存的输入、缓存命中、缓存写入、输出）各按该模型单价计价，金额再按积分单价换成积分。

2026-11-11，产品负责人与 Callum 确认需求定稿（《积分体系升级-需求文档 v1.0》）：

- 只管记账。额度分配、积分用完后的拦截沿用现有能力，不重做。
- 范围：工作台的日常对话、知识空间问答、频道问答，加上已在扣费的灵思（任务模式）和桌面客户端（Chat、Work）。应用广场、工作流、助手、知识库入库、开放 API、非聊天模型、桌面员工自带 Key 和生图插件都不做；首钢定制的知识库文件自动编码不动。
- 补齐三处漏扣：知识空间问答（主对话和看图）、频道问答的看图、日常对话的回答溯源（溯源照常扣，但不因额度不足失败）。
- 旧算法（token × 倍率）整体删除，不留开关；管理员可以改价格。
- 添加模型时按「服务提供方类型 + 模型名」匹配内置价格表自动带出价格，可改；匹配不上默认为 0，表示免费，积分用完也能用。没有「未定价」状态，没有价格系数。
- 积分倍率只用于展示，固定按「输入:输出 = 3:1」相对基准模型计算。
- 积分设置：计价币种可在人民币和美元之间切换（切换时二选一：保持预算不变 / 保持数字不变），积分单价默认 0.01 元，汇率可配，基准模型在用户可选模型表上方选择，默认取日常对话默认模型。
- 历史数据不处理；升级时已有模型按同样规则补价。「拉取厂商模型列表」与价格表自动对应放到下一版。

2026-11-11，109 测试服务器实测：千问、OpenAI 经毕昇调用，普通和流式都返回缓存命中数；未命中时千问给 0、OpenAI 不返回；缓存写入两家均未返回。

2026-11-12，技术评审（v2.0 方案）结论为修订后再开发，提出 8 个阻塞项与 6 个应修项；逐条核实全部成立，方案修订为 v2.1，部署统一为「停服 → 数据迁移 → 开服」。同日 Callum 确认基于 `feat/3.1.0-beta1` 开始开发。评审后新增、尚待产品确认的三点见 spec.md 的「待澄清」标记。
