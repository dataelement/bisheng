# F054 — 大部门授权的请求时成员关系

## 范围与确认

针对大部门授权导致具体用户鉴权随部门子树规模衰减的问题，改由毕昇提供用户的完整部门归属事实，由 OpenFGA 执行最终权限判断。需求和模型方案已在本次会话中讨论确认，用户指令为“OK按照这个方案去修复”。沿用用户指定的 `hotfix/3.0.0-beta1-fix2` 分支。

不增加业务端点参数，不修改资源业务规则，不修改 OpenFGA 服务源码，不建立永久的祖先部门 × 用户成员展开表。

## 验收标准

| ID | 标准 |
|---|---|
| AC-01 | 用户属于部门 D 时，包含下级成员的 D 及其祖先部门授权均可参与最终鉴权；不枚举 D 的兄弟或子部门。 |
| AC-02 | 只授权部门直属成员时，下级部门用户不得因此获得权限。 |
| AC-03 | 下载、编辑、删除、权限管理及授予等级仍由原有资源、模型、Grant 和状态门禁共同决定；组织事实不得直接返回资源 ALLOW。 |
| AC-04 | Check、BatchCheck、ListObjects、StreamedListObjects 对同一用户使用同一语义；API、Celery、Linsight 的生产装配入口均安装事实提供器。 |
| AC-05 | 新的鉴权操作重新读取组织事实，观察成员移除及部门迁移；用户之间隔离，无跨请求的组织事实缓存，不写入永久祖先成员 tuple。 |
| AC-06 | 部门深度不再增加资源鉴权中的 OpenFGA 部门递归深度；输入的去重部门总数上限为 100，超限、中断、缺失祖先、循环和未完成投影均不得以部分事实继续查询。 |
| AC-07 | 无关的系统/租户身份、直属成员和部门管理员检查不增加组织查询；依赖部门子树的旧身份/LLM 权限缓存不得绕过新事实读取。 |
| AC-08 | 模型切换使用既有离线发布协议；发布前检查 Store 不存在永久 `department.subtree_member` tuple，保留资源上引用该 userset 的既有授权。 |

遵守 release-contract 的 INV-9、INV-10、INV-27；组织事实归组织域，资源最终判定归 OpenFGA。实施与验证见 design.md、tasks.md、test-report.md。
