## 表 2：跨 Feature 不变量

F001/F003 沿用 v3.0.0 及其引用版本的既有不变量；窄屏交互的验收约束归对应特性 spec。F118 对全平台 use 动作、业务引用及强制删除的合同增量，见本文件末尾 F118 章节，未变更项继续沿用。
下文登记 F009 标准 Helm 的窄增量；F118 等其他增量及对应 spec 继续有效。

F009 的用户需求已于 2026-11-06 确认，正式规格已于 2026-11-10 确认：

- **仅 Kubernetes 环境诊断门槛**：取消 F059 对环境实测报告及 24 小时有效期的强制运行前提，手动诊断与业务状态解耦。限定替代 F059 AC-13/AC-23/AC-30/AC-31 及 F086 AC-58 中“必须先完成 Kubernetes 环境实测方可运行”的部分；不删除权限清单、实际应用检查、安全控制或运行错误处理。Docker/legacy 宿主隔离合同及其有效性要求不变。
- **官方环境首次种子**：在 F086 AC-14/AC-15/§2.11 及 INV-42 的全局环境管理资格上增加受控系统初始化窄例外：仅从受信发行物校验并补齐官方记录和缺失默认项，记录系统来源，不伪造管理员。人工登记/替换/默认切换仍仅平台超管；不向 Manager、普通用户、租户管理员或服务账号授予该管理权，不覆盖用户默认项或改变被冻结版本。原领域 Owner 与其他主体矩阵不变。

F059 的实际准入、UID 停止证明及保护历史、单写、未知状态数据保护和 F048/F114 权限要求继续保留；发布必审、档位/版本冻结、运行期出站、物料身份隔离与未来正式发行矩阵均不变。F114 已替代早期 owner-only 限制，恢复按 edit、涉及正式启动另需 publish，不能借继承旧数据保护条款恢复旧资格；应用清单 v1 兼容不恢复已退役的运行控制协议 v1。历史版本文档不改写为新版本行为，具体新验收口径及继承表见 [F009 spec](./009-standard-helm-delivery/spec.md)。

沿用 v3.0.0 及其引用版本的既有不变量。F001 不新增全局业务不变量。F009 对身份、管理目标、组织归属和普通策略生效的拟明确规则见其 spec，原完整规格已确认，用户要求重新收敛最小修复；已确认范围见F009 scope-revision，设计已实施，不新增业务操作表或DSH按人刷新；不修改平台身份或 F048 唯一资源权限判定，也不改变普通配额允许轻微并发超额的保证。
