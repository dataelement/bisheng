# Feature: 工作台窄屏新版完整侧栏

**关联 PRD**：本次会话中用户提供的窄屏截图与确认：主要修复屏幕宽度小于 768px 时的适配；菜单打开新版完整侧栏，包含模块、项目和历史会话。
**优先级**：P1
**所属版本**：v3.1.0-beta1
**状态**：Spec Discovery、规格已确认；2026-10-30 用户在设计确认中明确修正为主屏右推、露出底层新版侧栏，按该指示实施。
**依赖**：当前发版线既有新版工作台侧栏、菜单授权、项目和历史会话能力。

## 范围边界

本次纳入：

- 浏览器窗口宽度小于 768px 时的工作台全局菜单，覆盖手机、平板和电脑窄窗口。
- 从聊天、任务、知识空间、频道、应用、工具与技能、广场和设置入口打开同一套新版完整侧栏。
- 工具与技能首页在窄屏上的标题、搜索、分类、上传和列表排版。
- 菜单开关、导航后收起、尺寸跨断点切换，以及触屏和键盘操作。

本次明确排除：

- 宽度大于或等于 768px 时的桌面布局改版，以及频道双栏的独立宽度问题；本轮由用户明确收敛到小于 768px 的布局切换。
- 其他业务页面内部的全面排版重做；本次仅保证共用全局菜单可用，工具与技能首页为截图对应的修复页面。
- 独立分享页和独立应用的导航结构；这些页面不属于工作台全局导航。
- DSH 桌面宿主的导航或嵌入协议改动；其导航由宿主提供。
- 后端项目模型、菜单授权、会话存储和业务接口变更；项目沿用当前已有能力，不扩大为项目后端建设。

## 1. 用户故事

作为在手机、平板或电脑窄窗口使用工作台的用户，我希望通过菜单打开与新版工作台一致的模块、项目和历史会话入口，以便在有限宽度下完成导航、继续会话并使用工具与技能。

## 2. 验收标准

### 2.1 全局导航

- **AC-01** — WHEN 浏览器窗口宽度小于 768px 且用户进入工作台页面, THE SYSTEM SHALL 默认收起全局侧栏，主内容使用页面可用宽度，不为旧版图标栏预留空间。
- **AC-02** — WHEN 用户点击工作台页面的全局菜单入口, THE SYSTEM SHALL 从左侧打开新版完整侧栏，提供该账号有权访问的模块、项目、历史会话和账号入口，并保持与桌面端既有导航能力一致。
- **AC-03** — WHILE 窄屏全局菜单打开, THE SYSTEM SHALL 将主屏保持原宽度并向右推出 240px，露出其下方的新版完整侧栏；保持原有主屏在上、侧栏在下的层级，主面板保留原有左侧圆角与外阴影，窗口裁切推出部分，不产生整个文档的横向滚动，也不显示旧版窄图标栏。
- **AC-04** — WHEN 用户通过侧栏选择模块、项目内会话、历史会话或账号入口, THE SYSTEM SHALL 前往对应页面并收起侧栏；选择当前页面的入口也应收起侧栏。
- **AC-05** — WHEN 用户点击菜单外的遮罩、菜单关闭按钮或按 Escape, THE SYSTEM SHALL 关闭菜单并恢复页面操作；通过关闭操作退出时，应将键盘焦点交还打开菜单的入口。
- **AC-06** — WHILE 窄屏全局菜单打开, THE SYSTEM SHALL 支持独立滚动菜单内容，并限制键盘焦点停留在当前活动菜单或其打开的子弹窗中，背景页面不可被点击或滚动。
- **AC-07** — WHEN 用户从日常聊天或任务页打开全局菜单, THE SYSTEM SHALL 在新版侧栏中访问历史会话，不再以旧版聊天历史侧栏替代新版全局菜单；应用专属的会话选择能力继续可用。

### 2.2 工具与技能首页

- **AC-08** — WHILE 工具与技能首页处于小于 768px 的窗口且全局菜单收起, THE SYSTEM SHALL 只显示一处页面标题，搜索、分类、对应分类下现有的上传入口和工具启用开关均保持可见、可操作；长名称或描述不得撑宽整个页面。菜单打开期间允许主屏整体右移后被窗口裁切。
- **AC-09** — WHEN 用户在窄屏工具与技能首页搜索、切换分类、上传技能或打开条目详情, THE SYSTEM SHALL 保持现有业务行为，不因窄屏呈现而移除功能或清空已输入的搜索内容。

### 2.3 边界与回归

- **AC-10** — WHEN 浏览器窗口在 767px 与 768px 两侧往返切换, THE SYSTEM SHALL 在窄屏收起式菜单与既有桌面常驻侧栏之间切换，不保留遮罩、背景锁定或重复菜单；窄屏菜单不应在回到窄屏时自动重新打开。
- **AC-11** — WHILE 仅打开或关闭全局菜单，或窗口跨越断点, THE SYSTEM SHALL 保留当前路由、聊天草稿和工具与技能页的搜索及分类状态，不因导航外观切换而启动新的会话。
- **AC-12** — WHERE 用户使用触屏、中文／英文／日文或浅色／深色主题, THE SYSTEM SHALL 保持菜单和工具与技能首页主要操作可用；触屏操作不依赖悬停，菜单开关的点击范围至少为 44×44px。
- **AC-13** — WHERE 用户无某模块访问权，或菜单数据尚未就绪, THE SYSTEM SHALL 沿用现有授权与加载行为，不因新版窄屏菜单暴露额外入口或业务内容。
- **AC-14** — WHERE 工作台嵌入 DSH 桌面宿主, THE SYSTEM SHALL 保持宿主现有导航职责，不因窗口窄于 768px 增加网页全局菜单或遮罩。

## 3. 边界情况

- 验证宽度至少覆盖 320、375、575、576、767、768、820 和 1024px；宽度大于或等于 768px 的验收仅检查本次改动造成的导航回归。
- 菜单内容超过屏幕高度时，底部账号入口仍可到达；横屏和安全区不得挡住关闭入口。
- 菜单中的更多操作、项目操作、会话操作及子弹窗不能因为菜单外部点击判断而立即被关闭；完成导航后再收起全局菜单。
- 菜单未关闭时发生路由导航，或窗口变宽，关闭后应恢复背景滚动和键盘操作。
- 侧栏关闭与重新打开不应丢失本次会话中已展开的项目和已加载的会话列表。
- 项目和会话为空、加载失败、长名称，以及工具分类数量不同，均保留现有空态／错误态，主要导航和搜索不被挤出窗口。
