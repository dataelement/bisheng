# F075：机器人问答调试客户端设计

状态：用户已确认设计（2026-10-10）；代码和评审修复已实现，本地 E+ 回归通过；前端/现场待验，未合并或部署。更新：2026-10-10。证据见 [verification.md](./verification.md)。

关联：[spec.md](./spec.md)。需求来源：本次会话；版本约束见上一级 `release-contract.md`，全局规则遵循 `docs/constitution.md` C1–C8。

## 1. 目标与非目标

管理员在我们自己的环境复现机器人知识问答，直接看到真实工具调用、来源和回答。不模拟 E+ 服务，不修本轮发现的来源归属或部门空间检索问题。

## 2. 关键约束

正式机器人继续使用原连接与队列。调试服务独立启动，默认关闭；不得申请正式租约、导入正式历史或写正式 E+ 会话/消息/轮次。只读实际保存的助手配置，不读取编辑页面尚未保存的表单。

模型、索引、数据库仍共用，存在正常费用和资源竞争；不承诺零影响。第一版只允许机器人知识工具，明确展示与正式工具清单的差异。

## 3. 方案对比与选定

### 3.1 入口：机器人配置区按钮 → 独立页面

建议在助手编辑页「E+ 机器人」配置区增加「机器人调试」按钮，打开独立页面并带入助手 ID；不增加一级菜单，不改已有助手测试聊天。

按钮仅在部署显式配置了同源调试入口、后端确认操作人为授权管理员时显示。关闭调试部署时不显示。直接访问调试地址同样必须在服务端鉴权，隐藏按钮不是安全边界。

备选：只提供独立 URL，改动最少但测试人员需要手工选助手；增加正式菜单，则把临时诊断能力产品化。选择配置区按钮是因为现有机器人绑定就在该区域，定位更直接。若未来要长期对外提供，再评估正式产品入口。

这是对 spec 中「不加入正式产品菜单」的入口补充，用户已确认并同步到 spec。

### 3.2 独立调试进程，不模拟 E+ 服务端

调试页面使用同源代理路径 `/robot-debug/`，请求仅转发到单独启动的调试服务。独立服务使用相同配置及基础设施初始化，验证既有登录身份和租户；不提供新的匿名登录方式，不允许在 URL 中传密钥。

备选：把接口直接注册到正式 API，部署简单但不满足独立停止和进程隔离；模拟 E+ 服务端加独立 Worker，覆盖通信但增加无关协议工作。本次已有通信成功证据，选择直接复用助手链路。以后需要测去重、重连和排队时，再新增协议模拟层。

部署若无法安全转发既有登录身份，则不开入口，先解决认证接入，不以固定管理员身份或免登录模式降级。

### 3.3 追踪真实执行，不另写问答算法

沿用助手配置中的模型、提示词和执行模式，构建 E+ 执行上下文，使用机器人当前绑定空间。调试适配器只隔离传输、历史和非知识工具，不改检索策略或工具格式化结果。

工具追踪在本次请求的实际工具实例执行边界记录：开始、输入、成功结果或异常；原样保留交给模型的成功格式化结果。原始召回元数据单独显示，不能把未进入模型输入的文件 ID 描述成模型已知信息。不进行进程级 monkey patch。安全例外：调试工具异常正文在进入执行器前替换为错误类型，防止旧 ReAct 将供应商敏感异常作为观察结果交给模型；不改变正式执行器。

备选 `/filelib/answer` 固定召回后总结，无法验证助手是否选择了工具；单独写 RAG 则可能复现不了真实错误。若正式链路日后重构，调试适配器必须同步回归，而不是保留第二套算法。

## 4. 当前代码与拟新增流程

现有助手编辑页的 `EPlusRobotSettings.tsx` 保存机器人绑定；已有测试聊天并非机器人空间范围。E+ Worker 通过 `AssistantAgent` 创建模型和工具后执行；正式消息传输、调度和持久化在机器人编排层。

拟新增流程：打开调试 → 管理员与助手权限校验 → 校验本租户机器人绑定和测试用户 → 读取已保存配置 → 构建独立历史和 E+ 上下文 → 实际执行助手 → 展示答案与工具追踪。

第一版页面使用既有组件和页面布局：顶部显示助手、机器人、模型、执行模式、绑定空间、测试用户及工具差异；主体聊天；诊断区按本轮调用顺序显示工具、结果及来源。窄屏上下排列。提供停止与清空测试历史。

新增独立服务入口、准入服务、助手调试适配器、事件记录器和页面；配置区仅加入口。准入读取复用仓储/现有业务适配器，服务不写 ORM。若必须为助手增加观测接线，则使用默认关闭、请求局部的可选观察者，回归证明无观察者时正式输出不变。

不新增业务表、迁移或正式队列。测试历史仅存当前页面内存，刷新即清空；每轮发送受长度及条数限制的历史，明确标为测试输入，不承认其为正式历史。服务不保存历史全集，不写共享本地文件。

## 5. 已知坑

- 知识工具包装器会直接检索并格式化结果，不走工具内部默认总结提示词。追错位置会出现「没日志」而误判没调用工具；在调试适配器记录实际执行的工具实例和结果。
- 当前格式化结果可包含空间 ID、空间名、文件标题，但未必包含文件 ID。页面必须分开展示模型实际结果和原始元数据，缺失字段不补猜测。
- 机器人检索绑定空间集合，不由模型根据名字准确选择一个空间。不能为了诊断自动限制到用户问题提及的空间。
- 旧 ReAct 可能一次返回完整答案；函数调用模式可流式返回。页面如实显示执行模式，不把整段答案模拟打字当作真实流。
- 部门空间只有实际在绑定范围内才应被检索，普通空间列表未出现不能作为其不可检索的证据。

## 6. 调试契约与依赖

以下只属于调试服务，不注册到正式开放 API：

- `GET /robot-debug/api/status`：管理员准入探测，未启用时无独立进程/路由，不依赖菜单权限。
- `GET /robot-debug/api/assistants/{assistant_id}/context`：校验管理员及助手 edit，返回脱敏配置、有效绑定空间、合法测试用户；真实模型名、执行模式和工具差异在 run 初始化后由 `context` 事件返回，不为预览再次初始化模型与工具。
- `POST /robot-debug/api/assistants/{assistant_id}/run`：输入 `query`、`test_user_id`、独立测试历史；服务每轮重新校验全部准入和绑定，浏览器不能指定知识空间。
- 运行响应采用事件流，事件包含 `run_id`、递增 `seq`、`type` 和 `data`。类型为 `context`、`tool_start`、`tool_end`、`tool_error`、`answer_delta`、`completed`、`failed`；无工具调用在结束摘要中明确显示 `tool_call_count=0`。
- 工具结束事件区分 `model_tool_output` 与 `retrieval_metadata`；异常仅返回脱敏摘要，服务日志记录关联 ID，不输出密钥或默认打印检索正文。
- 断开请求即取消本地任务；一个页面只运行一轮，服务限制总并发 1、总时长 180 秒；多进程或多副本部署必须以 Redis 协调准入，不能用进程内锁冒充全局限流。

依赖既有用户认证、租户上下文、统一助手 edit 权限和有效用户读取；依赖 F073 绑定边界、助手执行器、知识工具包装器及真实 Milvus/ES/LLM。以上内部格式或工具执行方式变化都需要两种模式回归。不得返回 Bot Secret、证书、APIKey、认证头或模型配置全文。

## 7. 测试与验证

后端覆盖管理员/普通用户、跨租户/失效用户、助手权限、无绑定、绑定变化、工具差异、两种执行模式追踪、多次工具调用、失败/超时/取消、历史隔离和禁止正式传输/持久化。仅用替身的单元测试不代表真实知识链路已通过。

现场在 105 登录授权管理员后从助手配置区进入，核对页面绑定与保存配置一致；分别提问正常知识、无结果、跨空间同名文件、部门空间和无需检索的问题。将每轮实际工具结果与答案对照，记录是否复现错误，不修改提示词或索引来制造通过。

本地不执行前端测试/构建，按用户约定交镜像构建验证；部署后再验证入口、访问控制、断开停止及真实问答。当前设计未部署，无可宣称通过的现场结果。

## 8. 后续边界

不支持图片、完整空间文件列表、正式历史导入、其他副作用工具和客户 E+ 协议。若要复现依赖正式历史或其他工具的错误，需要单独确认扩展，当前测试页面明确提示差异。
