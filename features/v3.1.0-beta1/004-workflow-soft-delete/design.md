# 工作流逻辑删除设计

**版本**：v3.1.0-beta1。**更新**：2026-11-04。**状态**：设计已确认，代码已实现，部署环境验收待完成。

关联：[已确认规格](./spec.md) · [版本契约](../release-contract.md)。本文描述当前实现；实际验证结果见 verification-report.md。

人类评审入口：[图文设计摘要](./design-summary.html)。摘要用于快速理解效果、流程和取舍；本文件保留研发定位及实现约束。

## 1 目标与非目标

用一个删除标记保留工作流定义与历史，并阻止正常查询和新操作访问已删除工作流。保留既有授权、审计及分享清理链路。

不开发错误分类；不增加三态、删除操作表、后台补偿、业务版本号、回收站或在途实例协调。

## 2 约束

遵循 `docs/constitution.md` C1–C8、后端 AGENTS.md 与 Alembic AGENTS.md。共享 `flow` 表还承载其他类型，本期只改变 `FlowType.WORKFLOW=10` 的删除语义；其他类型不被转成逻辑删除。

既有权限撤销成功后才提交业务删除状态。保留现有跨系统失败窗口，不因本特性重构权限运行时。历史读取仍使用原有会话/审计/文件授权，不以工作流是否正常存在作为历史访问的额外前提。

## 3 设计决策

### 3.1 单个标记与现有事务

- 选定：`Flow` 表模型新增整数 `is_delete`，非空、Python 默认 0、数据库默认 0。0 正常，1 已删除；与版本表既有语义一致。
- 否决：三态、删除时间/操作者新列、删除操作表和协调器。用户已选择低复杂度方案，现有审计承担操作追溯。
- 原因：当前主记录物理删除，而版本已经采用 `is_delete=1`。用一个标记即可在原事务内保留主记录，不改变上下线状态。
- 重审条件：以后正式要求回收站、严格删除进度或自动跨系统恢复。

### 3.2 显式过滤与历史专用读取

- 选定：现有 DAO 的正常查询显式添加未删除条件，直接 SQL/ORM 和 UNION 内部查询逐项补齐。新增历史读取放在工作流域 Repository，返回名称、描述、logo、类型等必要元数据，不返回定义内容。
- 否决：全局 ORM 删除钩子、对普通 API 开放 `include_deleted`。联合子查询、列投影与历史读取路径不同，全局钩子仍需特殊处理，且易误伤历史。
- 原因：`FlowDao._build_apps_subquery` 已集中统一应用列表，工作流分支缺删除过滤；模板来源等路径直接读取模型。
- 重审条件：未来多个领域统一采用有完整覆盖保证的软删除框架。

### 3.3 有条件写入与父记录锁

- 选定：主记录编辑按明确可写字段更新，WHERE 带 `is_delete=0`；禁止通用保存回写删除字段或缺失记录时转 INSERT。版本创建、修改及切换与删除均先锁定同一父记录，并在同一 SQL 事务完成父状态检查及子记录写入。
- 否决：新增 `revision` 体系、锁定整个任务执行过程。前者超出本期范围，后者会放大延迟且用户已放宽在途要求。
- 原因：当前 `session.add` 保存对象，版本更新还有分段提交；仅在入口检查一次不能保护删除与保存并发。
- 重审条件：未来需要通用编辑冲突提示或完整运行生命周期保证。

## 4 当前代码与目标流程

### 4.1 实现后的删除链路

`api/v1/flows.py` 读取主记录 → `FlowService.project_flow_delete` 校验删除权限并执行 F048 删除投影 → `FlowDao.delete_flow` 标记主记录及版本（非工作流保持原删除行为） → 遥测 → `delete_flow_hook` 写审计、清用户组入口、保存会话信息、清访客链接。

实现保持原有调用顺序及响应：仅将工作流主记录的物理 DELETE 替换为 UPDATE。事务内先锁父记录、确认正常，再标记主记录与全部关联版本。非工作流类型沿用原分支；重复删除通过正常查询走现有 NotFoundError。

### 4.2 字段与接口

| 项目 | 契约 |
|---|---|
| `flow.is_delete` | Integer，NOT NULL，server_default=0；不放入可编辑请求或普通详情响应 |
| `flowversion.is_delete` | 保持现有字段及 0/1 语义，删除工作流时统一设为 1，定义内容不清空 |
| `DELETE /api/v1/flows/{flow_id}` | URL、成功结构和现有异常处理不变，不增加进度接口 |
| 正常资源读取 | 已删除记录与不存在记录采用同一正常读取语义 |
| 历史专用读取 | 内部同步/异步与批量元数据读取，按调用方历史授权后使用，不对外开放过滤绕过参数 |

迁移只增加一列及默认值，不做数据读写回填、不新增低选择性单列索引。创建新库依赖表模型，升级现有库依赖 Alembic；两者列定义一致。新增 revision 为 `v310b1_f004_workflow_soft_delete`，父版本为实施前实测的单 head `v310b1_f003_audit_operator_dept`。DDL 使用共享 `column_exists` 防重入。

### 4.3 改动归属和覆盖入口

下列路径均位于 `src/backend/bisheng/`，已按模型、表名、别名和调用方检索覆盖，包含配额及共享扫描的原始 SQL。

| 模块 | 负责改动 | 边界 |
|---|---|---|
| `database/models/flow.py` | 表模型字段；既有单条/批量/简单信息/名称/用户/列表/计数过滤；UNION 内部过滤；既有删除及保存方法的并发保护 | 不新增 DAO 入口，不改变其他类型删除行为 |
| `database/models/flow_version.py` | 既有版本创建、修改和切换入口的父记录锁、删除状态检查及事务合并；正常版本读取排除不可用记录 | 不改变历史明确读取已删除版本的既有用途 |
| `api/v1/workflow.py`、`api/services/flow.py`、`api/services/workflow.py` | 新建重名排除已删除；入口缺失判断；版本处理及新操作通过正常父资源读取 | 新增 ORM 查询不放在 endpoint/Service |
| `workflow/domain/repositories/` | 新增历史元数据 Repository；必要的新专用查询/字段更新能力 | 不绕过租户隔离，不开放完整定义 |
| `api/services/f048_application_permission.py`、`api/services/permission_migration_source.py` | 正常授权目标、权限重建来源排除已删除工作流 | 不修改 F048 协议/投影算法 |
| `app_template/domain/repositories/template_repository.py` | 模板来源读取排除已删除记录 | 已有模板快照保留 |
| `workstation/domain/services/workstation_service.py` | 推荐候选引用校验遵守删除状态 | 不改变推荐策略 |
| `tenant/domain/services/f048_permission_subject.py`、`tenant/domain/services/resource_type_registry.py` | 资源候选与原始 SQL 工作流类型条件排除删除记录 | 历史授权显示按用途保留必要信息，不复活业务入口 |
| `department/domain/services/department_service.py` | 活跃归属资产计数排除已删除工作流 | 不把删除后的保留数据当作可操作资产 |
| `chat_session/domain/chat.py`、`api/services/audit_log.py` 等历史调用方 | 历史列表、按名搜索、审计和展示使用已有会话快照或历史专用元数据读取 | 历史访问权限不变，正常应用搜索不展示墓碑记录 |
| `common/chat/clients/workflow_client.py`、`workflow/domain/services/published_workflow_service.py` 及 v1/v2/v3 入口 | 新调用、预览、分享入口查未删除父资源，补齐构建预览空 chat_id 直接放行的删除漏洞 | 不改变 Worker 调度、运行状态机及在途结果保证 |

工作流业务配额的计数调用方需沿调用链检查，使用未删除口径；如果沿用集中应用计数，通过该集中查询修正，不增加第二套计数实现。

## 5 已知坑与处理位置

| 代码事实 | 忽略的后果 | 处理 |
|---|---|---|
| 统一列表通过三类应用 UNION 构造 | 只过滤普通 DAO，列表、统计或分页仍会出现删除工作流 | `flow.py` 的 Flow 内层 SELECT 同时约束，外部列表与计数复用 |
| 模板、推荐、权限迁移及资源归属存在直接读表路径 | 正常查询已隐藏但旧 ID 仍能被引用，或重新建立授权 | §4.3 覆盖入口逐项核查，包含 raw SQL |
| 版本更新、切换包含多次 commit | 删除与版本修改穿插后可能留下未删除版本 | `flow_version.py` 先锁父记录，父/版本修改合并事务 |
| 历史代码复用普通 Flow 查询 | 加过滤后历史名称、搜索或展示可能缺失 | 历史快照与专用元数据读取，不把普通查询改成全量 |
| Redis 保存执行定义、Worker 内存保存等待实例 | 删除不等于立即停止任务 | 保留现有机制，按 spec 已接受边界处理 |
| 权限投影与 SQL 删除不是同一事务 | 权限撤销后 SQL 失败时可能留下不可用但未标记记录 | 原样反馈异常并保留日志，本期不扩展自动补偿 |

## 6 契约与依赖

对外提供：现有删除 API、普通工作流读取 API 的删除后不可用语义，以及历史会话读取能力。内部提供：既有 `FlowDao` 方法名称及返回类型保持，新增字段不进入客户端可写结构；`FlowVersionDao` 既有方法保持接口但强化父状态检查和事务边界。

依赖：现有 F048 删除投影成功结果、会话保存的名称/描述/logo、分享链接清理、用户组资源清理及审计；任一依赖顺序变化需重新检查 AC-04、AC-05、AC-09。依赖 MySQL/DM8 的事务及行锁能力，不增加外部服务、二进制或配置项。
