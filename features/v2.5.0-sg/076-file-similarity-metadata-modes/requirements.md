# 需求说明：文件相似度两套规则

- Feature ID: `076-file-similarity-metadata-modes`
- Status: `implemented-local-verified`
- Created: `2026-10-15`
- 请求停止点：用户确认实施，本地实现和验证完成；部署及线上数据操作不在本次授权范围。

## 需求入口与澄清记录

当前库内推荐和发布推荐均要求文件编码前三段一致；库内另有 TF-IDF 复核，发布推荐目前没有。用户希望允许分类或业务域不一致的文件使用另一套配置参与比较。

用户于 2026-10-15 明确：

1. 一致条件为一级分类、二级分类、业务域三项全部相同。
2. 库内推荐和发布推荐都采用两套规则。
3. 两套初始参数相同，沿用 `0.85 / true / 0.3`。
4. 任一分类或业务域缺失时归入不一致组；双方都缺失也不算一致。

## 范围与约束

- 包含分组、独立参数、配置兼容及保存校验、两个推荐入口与必要的共用相似校验、历史补算脚本的同口径筛选。
- 保留公司、租户、库范围和既有权限限制；分组不改变候选资格或审批流程。
- 不新增表、迁移、前端配置表单、分数权重或候选数量配置。
- 不调整页面 80%/20% 展示权重，不改变关联版本和“不关联”的业务含义。
- 不部署、不写线上配置、不批量重算历史数据、不重新打开已处理提醒。

## 发布影响与回退

- 不一致组启用后，同公司允许的知识库范围内跨分类候选会增加；即使两组参数相同，也不等于旧候选范围。
- 发布推荐增加 ES 读取、分词和 TF-IDF 运算；定向验证需记录正文读取批次，不承诺未经测量的线上耗时。
- 回退业务代码不需要 Schema 回退。新代码生成的跨分类候选仍可能留在既有候选表中，代码回退不等于恢复旧候选快照；必要的数据恢复或重算需另外授权。
