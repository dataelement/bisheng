> **范围边界**
>
> 本 Feature 是专业开发者通道的**调用面**（PRD-1 DEV-02「工具走 MCP」的那一半）与整个开放面的**检索地基**：让开发者的本地 coding agent 凭一把服务账号密钥、以标准 MCP 协议调平台六类工具；并把「文件级过滤 + fail-closed」的检索能力抽成一个会话解耦的**统一检索门面**——MCP 检索工具、v2 `POST /filelib/retrieve`、F055 托管运行期、F057 SDK retrieve 四处共用，F050 模式 D 集合相等依赖它。模型协议面（DEV-02 的另一半）归 F051。
>
> **候选 INV-36 的承接**（随本 spec 定稿转正）：本 Feature 承接「托管运行期检索 = 能力声明白名单 ∩ 当前访问用户可见范围（文件级、双层过滤、fail-closed）」中**门面**这一层——以「执行身份 + 可选声明白名单」为入参、对任何执行身份做同一强度的文件级过滤、无法确立执行身份即拒绝、评估失败即报错；白名单内的库被删除或应用侧授权已收回时门面给出带库标识的「能力已收回」可区分信号（AC-46，供 F055 转成应用可见的收回错误、不静默剔除）；F055 承接注入通道与审批期例外（预览实例以 owner 为执行身份调用门面、计审计），F057 承接 SDK retrieve；本地 dev 与 MCP 面锚定开发者服务账号被显式授予的范围。
>
> - **本次纳入**：
>   - **MCP Server 对外工具面**：标准 MCP 协议、经网络传输、任何标准 MCP 客户端零改造接入；服务账号密钥鉴权（与开放 API 同一鉴权语义，F049）；**一律模式 S**（以服务账号自身身份执行，可见范围 = 密钥权限位 ∧ 该服务账号被显式授予的资源）；工具清单按密钥权限位过滤；撤销 / 到期 / 停用 5 秒上界；权限位编辑即时生效；每次工具调用可归属到密钥与服务账号；MCP 会话与平台会话解耦；错误对本地 agent 可诊断
>   - **六类工具**（权限位映射按 DEV-01 ① / 伴生 B.2）：① **知识库检索**（`knowledge:read`，经统一检索门面）② **知识库清单查询**（`knowledge:read`）③ **模型清单查询**（`model:invoke`；模型调用本身归 F051）④ **用户身份 / 组织查询**（`identity:read`）⑤ **应用数据表结构与数据读写**（`app:manage`，表清单 / 表结构读取 + 行级增删改，**不含 DDL**——§4 决议-8）⑥ **应用状态 / 日志自查**（`app:manage`，含审批终态与驳回理由全文）——⑤⑥ 的服务端能力由 F054 / F055 提供，本 Feature 只做工具面接线与 owner 收窄判定
>   - **统一检索门面**：会话解耦的纯检索能力；入参 = 执行身份（服务账号 / 自然人访问用户）+ 查询 + 可选声明白名单 + 检索参数；**文件级过滤且过滤发生在返回前**；fail-closed（执行身份缺失即拒绝、评估失败即报错、绝不返回未过滤或部分过滤的结果集）；知识空间按文件级、文档知识库按库级（现权限模型无文件级，§4 决议-3）；检索面对库只有「可及 / 不可及」两态（存在性不泄露）；能力收回信号（AC-46）；四处消费——MCP 检索工具（执行身份 = 服务账号）、**v2 `POST /filelib/retrieve`**（F049 期只加鉴权、过滤强度维持现状，本 Feature 把它收敛到同一门面）、F055 托管运行期（执行身份 = 当前访问用户，白名单 = 能力声明）、F057 SDK retrieve；模式 D 集合相等（伴生 AC-12）由门面保证、F050 承接验收
>   - **三面入口拒绝持 `delegate` 密钥中的 MCP 面**（INV-31）：在通道入口按权限位直接拒绝、错误指向「委托专用、本地开发另发一把」、不得静默落回模式 S、不得只回参数错误码；MCP 面亦拒绝任何身份传递类请求头
>   - **`identity:read` 组织查询的边界**：本租户全量可读、跨租户读不到、无收窄机制、平台不做更细收窄；结果只含自然人（服务账号不出现）
>   - **应用类工具按 owner 收窄**：只对该密钥所属服务账号的资源归属人 owner 的应用放行；租户管理员名下服务账号的密钥同样拒（管理员查他人应用走应用详情页）；日志内容范围同 WB-13；判定为业务规则前置拦截
>   - **开放能力层开关**（F049 拥有）的消费：未部署时 MCP 面不可达、无新增常驻负担；统一检索门面不受该开关影响（它服务恒在的 v2 开放 API）
>   - **MCP Server 接入地址**：供 F053 接入信息区展示与一键复制；地址不含密钥或任何可换取密钥的凭据

>   - **模型协议面与模型调用**（OpenAI 兼容直连、流式、按名解析、逐条审计）——F051；本 Feature 只做「模型清单查询」工具（§4 决议-4）

>   - **服务账号 / 密钥 / 权限位清单 / 签发表单 / 开放能力层开关的定义**——F049；本 Feature 只消费

>   - **托管运行期的能力声明冻结 / 审读 / 注入通道 / 收回错误态、审批期临时预览实例、应用运行期凭据**——F055；本 Feature 只提供门面与 MCP 应用状态工具
>   - **实例状态 / 日志只读接口、每应用数据库及其服务端接口（表清单 / 结构 / 行读写，F054 AC-56）、WB-13 运行日志 tab、WB-06 数据面**——F054；MCP 两个应用工具只消费
>   - **受控联网搜索工具**（PRD-1 v1.x 曾列，v2.0 已砍——六类工具表中不存在）
>   - **第三方 MCP server 接入网关化**（PRD-1 §5.2 顺延）与**本地端专有插件**（§5.1 不做——四面供给全走标准协议）
>   - **MCP 工具的 per-tool 授权粒度**：权限位到模块 + 动作级即止（伴生 §六「不做按端点细粒度权限」原样继承）；不做密钥级资源白名单（伴生 D3 / §六）

## 1. 用户故事

作为 **开发者的本地 coding agent**（本域主用户，PRD-1 §3.1「操作者是 agent，不是人」），
我希望 **拿到一个 MCP 地址和一把密钥就能列出、调用平台的知识库检索 / 清单、模型清单、组织查询、应用数据与状态日志工具，被拒时得到能自行判断下一步的结构化错误**，
以便 **在本地对话里独立完成「查能力声明该填哪些库 → 写代码 → deploy → 读审批结果与日志 → 修 → 再发」的闭环，不需要开发者中途接管**。

作为 **专业开发者**，
我希望 **本地经 MCP 检索到的知识库内容与我这把 key 的服务账号在平台里被授予的范围完全一致——不多不少，也与我用同一把 key 调 v2 检索接口拿到的一样**，
以便 **开发期据此写代码不会「本地能跑、线上越权」，最坏只是「本地看得少」**。

作为 **租户管理员**，
我希望 **开发者能力的边界只由我在签发表单勾的权限位与在服务账号详情页授的资源决定；`identity:read` 这种高危位一旦给出，我清楚它意味着本租户组织架构全量可读、无法收窄；开发者的 key 只能碰他自己 deploy 的应用**，
以便 **一把 key 泄漏的爆炸半径可预估、可一键吊销收口**。

作为 **安全与合规负责人**，
我希望 **开放面上的一切检索走同一条文件级过滤路径且 fail-closed——旧的「只查到知识库一级」的检索路径不再被任何调用方使用；委托专用的 key 在 MCP 面直接被拒、绝不静默变成以服务账号身份跑**，
以便 **模式 D「不多不少」的承诺与托管应用「声明白名单 ∩ 访问用户可见范围」的承诺有同一个可审计的实现基础**。

作为 **托管应用的普通使用者**（间接用户，经 F055 能力总线到达门面），
我希望 **应用里检索到的内容不超过我自己在平台里能看到的范围，也不超过应用声明接入的范围**，
以便 **用同事造的应用不会看到不该看的东西，也不会因为应用作者权限大而放大给我**。

## 2. 验收标准

> AC 编号在本特性内唯一。括号内标注对应 PRD-1 条目与验收序号（如 `↔DEV-02 验收 8`）或伴生 PRD 章节 / AC（如 `↔伴生 §4.4.6`）；与姊妹 Feature 存在调用关系的条目注明「F0xx 调用 / 承接 / 消费」。错误码仅作可观测行为引用，定义在 design.md。

### 2.1 MCP Server 接入与鉴权

- **AC-01** — WHERE 开放能力层已部署, THE SYSTEM SHALL 对外提供一个遵循标准 MCP 协议、经网络传输可达的 MCP Server；任何标准 MCP 客户端（本地 coding agent）以「地址 + 服务账号密钥」配置即可接入并列出工具，平台不提供、也不要求任何本地端专有插件。（↔DEV-02 需求描述 / §5.1；DEV-01 ⑤）
- **AC-02** — WHEN MCP 客户端建立连接或调用任一工具, THE SYSTEM SHALL 要求携带有效服务账号密钥（`bs-sak-`，与开放 API 同一鉴权语义）；缺失 / 无效 / 已撤销 / 已过期 → 拒绝连接或调用、不列出工具、不执行任何工具逻辑；**不存在无凭据回落路径**（INV-27）。密钥经请求头 / 传输层凭据传递，不接受经查询参数传递。（↔铁律 1；DEV-01 验收 2）
- **AC-03** — THE SYSTEM SHALL 使 MCP 面一切工具以密钥主体（服务账号）**自身身份**执行（模式 S）：可见范围 = 密钥权限位 ∧ 该服务账号被显式授予的资源；不继承资源归属人或任何自然人的权限；两层任一不满足即拒绝，且两种失败可区分（缺权限位 vs 无资源授权）。（↔DEV-01 ① / 验收 6；伴生 §4.4.1；NFR-1.1）
- **AC-04** — WHEN MCP 客户端请求工具清单, THE SYSTEM SHALL 只列出该密钥持有权限位所覆盖的工具（按 DEV-01 ① 映射：`knowledge:read` → 检索 + 清单；`model:invoke` → 模型清单；`identity:read` → 身份 / 组织；`app:manage` → 应用数据 + 应用状态 / 日志）；未勾选任何权限位的密钥可完成 MCP 连接握手（握手不属能力）、工具清单为空、任何工具调用被拒——与 DEV-01 验收 5「仅可 `login` / `skills sync`」一致；IF 客户端直接调用一个该密钥未持位的工具, THEN THE SYSTEM SHALL 返回**指明缺少哪一位**的拒绝，而非泛化「未知工具」。（↔DEV-02 需求描述「按密钥权限位过滤」/ 验收 1；DEV-01 验收 5；§4 决议-6）
- **AC-05** — WHEN 密钥被撤销 / 到期、或其服务账号被停用 / 删除, THE SYSTEM SHALL 使 MCP 面自下一次工具调用起拒绝（生效上界 5 秒，INV-28）；已建立的 MCP 会话不得继续调用工具。（↔DEV-01 ④ / 验收 2 / 7）
- **AC-06** — WHEN 租户管理员编辑密钥权限位, THE SYSTEM SHALL 使 MCP 面自下一次工具清单请求或工具调用起按新权限位判定，无需重连、无需重签。（↔DEV-01 ② / 验收 5）
- **AC-07** — WHEN 任一 MCP 工具被调用, THE SYSTEM SHALL 使该调用可在审计中归属到密钥（掩码）与其服务账号（含资源归属人）：工具名、目标对象摘要（知识库 / 应用标识等）、结果（成功 / 拒绝类别）、时间；不记录密钥明文、不记录检索片段正文（可能含知识库内容）。（↔DEV-01 验收 1；GOV-04；§4 决议-12）
- **AC-08** — THE SYSTEM SHALL 使 MCP 面的连接与工具调用不创建、不读取、不写入任何平台会话——不产生会话记录、不出现在任何人（含资源归属人）的会话列表；MCP 会话与平台会话解耦。（↔伴生 §4.5 定义 6 边界 a 同向）
- **AC-09** — WHEN 工具调用因凭据无效、缺权限位、无资源授权 / 不可及、非 owner、权限评估失败等任一原因被拒, THE SYSTEM SHALL 返回结构化错误，含**类别 + 原因 + 下一步指引**三要素（下一步指引如：找管理员加权限位 / 申请资源授权 / 换一把 key / 稍后重试）；不得以泛化「未知工具」「内部错误」掩盖。（↔伴生 §4.4.1「两种失败可区分」；DEV-02 ④「对本地 agent 可诊断」）

### 2.2 六类工具

- **AC-10** — WHEN 持 `knowledge:read` 的密钥调用「知识库检索」工具, THE SYSTEM SHALL 接受查询文本（及可选的目标知识库范围与返回条数上限），经统一检索门面（§2.3）以该服务账号为执行身份执行文件级过滤检索，返回含知识库 / 文件标识与片段正文、足以引用溯源的结果，结果 ⊆ 该服务账号被显式授予的知识库范围（入参出参字段清单见 design §6）。（↔DEV-02 六类工具表 / ① / 验收 2；伴生 B.2）
- **AC-11** — IF 检索工具显式指定的目标知识库中任一**不可及**（不存在 / 未授予 / 类型不支持三种情形一律归为「不可及」）, THEN THE SYSTEM SHALL 以「不可及」拒绝**整个请求**并指出哪些标识不可及，不静默剔除后返回缩水结果；三种情形给**同一响应**（存在性不泄露，检索面对库只有「可及 / 不可及」两态）；未指定目标 → 在全部被授予范围内检索。（↔伴生 §7.2 同标准；§4 决议-7）
- **AC-12** — WHEN 持 `knowledge:read` 的密钥调用「知识库清单查询」工具, THE SYSTEM SHALL 返回含标识与名称的清单，其集合 = **该服务账号被显式授予且为门面支持类型的知识库集合**（取证基准 = 主体侧授权页〔F049 §2.7〕列出的知识库授权集合 ∩ 门面支持类型〔AC-27〕）；未授予或不支持类型的知识库**不出现**（不是出现但标记不可用）；清单结果可直接用于能力声明填写。（↔DEV-02 六类工具表；DEV-01 验收 6；伴生 B.2；F055 预检消费同一可及性判定）
- **AC-13** — WHEN 持 `model:invoke` 的密钥调用「模型清单查询」工具, THE SYSTEM SHALL 返回本租户能力总线已启用的可用模型清单，每项含模型管理页原名、模型类型、以及**可直接用于模型协议面调用的唯一名称**（按 F051 名称解析规则：同名歧义时给出带服务商限定的名称，并标注是否为对话类模型）——清单里的名称在 F051 模型面调用必可解析（三处同源：本工具 / F051 解析 / F055 预检）；范围为租户级配置、非 per-user；模型调用本身不经 MCP（F051）。（↔DEV-02 六类工具表；伴生 B.2；GOV-05 模型项；§4 决议-4）
- **AC-14** — WHEN 持 `identity:read` 的密钥调用「用户身份 / 组织查询」工具, THE SYSTEM SHALL 提供按用户标识点查身份与组织架构查询（部门树与成员）；返回内容限于身份与组织归属信息、不含任何凭据类信息（字段清单见 design §6）；结果只含自然人——**服务账号不出现**。（↔DEV-02 六类工具表 / ②；伴生 B.2；INV-29 同向；§4 决议-11）
- **AC-15** — WHEN 持 `app:manage` 的密钥调用「应用数据表结构与数据」工具, THE SYSTEM SHALL 对该密钥资源归属人 owner 的应用（AC-34）提供其每应用数据库的**表清单 / 表结构读取与行数据的读写**（写 = 行级增删改，**不含 DDL**——表结构由 `bisheng-app.yaml` 声明、平台建表、变更走 F055 发布管线）；读与写均只对 owner 应用放行；**每次写操作计审计**（GOV-04「生产数据行编辑」事件，写入方 = 服务端能力所在的 F054）；分页 / 条数上限由平台设定。服务端接口由 F054 AC-56 / AC-45 提供（与应用详情页数据 tab 共用），本 Feature 只做接线与 owner 判定。（↔DEV-02 六类工具表「操作应用自有数据」；伴生 §4.2.4 `app:manage`「读写」/ B.2；GOV-04；§4 决议-8）
- **AC-16** — WHEN 持 `app:manage` 的密钥调用「应用状态 / 日志自查」工具, THE SYSTEM SHALL 对该密钥资源归属人 owner 的应用返回：应用运行状态（F054 只读接口）；最近一次发布的审批状态含**驳回理由全文**与待上线成因（F055 审批状态只读接口，与发布面一致）；运行日志（可按时间范围 / 最近若干条）——内容范围与应用详情页运行日志（F054 WB-13）、CLI `logs`（F053）**完全一致**：应用运行输出与错误信息、不含平台侧日志、不出现密钥值（返回字段清单见 design §6）；非本人 owner 的应用按 AC-34 拒绝。（↔DEV-02 六类工具表 / ③ / 验收 7；DEV-04 日志三入口表 / 验收 12；F054 AC-23 / AC-55；F055 AC-38；F053 AC-41）
- **AC-17** — WHERE 工场运行时层未部署, THE SYSTEM SHALL 使两类应用工具不出现在工具清单，直接调用得到「本环境未启用应用工场」类明确错误；其余四类工具不受影响。（↔GOV-10 三层形态；F054 AC-30 同向）
- **AC-18** — THE SYSTEM SHALL 使六类工具与平台内同源：同一服务账号经 MCP 与经平台既有能力（清单 / 检索 / 模型 / 组织 / 应用状态）看到的结果一致；MCP 面**不新增数据面**——无 MCP 专属的数据副本、旁路查询或独立权限判定。取证基准：清单 = 主体侧授权页集合 ∩ 支持类型（AC-12）；检索 = 同一执行身份在平台内检索的集合（AC-40 / 41）；模型清单 = 模型管理页已启用清单；组织 = 平台组织管理视图；应用状态 / 日志 = 应用详情页发布 tab / 运行日志 tab。（↔DEV-02 一句话「同一工具面、内外同源」/ 六类工具表「不新增数据面」）

### 2.3 统一检索门面

> 能力收回信号（白名单内库已删除 / 应用侧授权已收回 → 带库标识的「能力已收回」可区分错误）见末尾追加的 **AC-46**（审查修订，编号稳定故不插入本节）。

- **AC-19** — THE SYSTEM SHALL 提供一个**会话解耦**的统一检索门面：入参 = 执行身份（服务账号，或自然人访问用户）+ 查询 + 可选声明白名单 + 检索参数（平台设上限）；出参 = 经过滤的、含知识库与文件标识、可引用溯源的片段结果（字段清单见 design §6）；不创建平台会话、不写消息记录。四处消费：MCP 检索工具（AC-10）、v2 `POST /filelib/retrieve`（AC-25）、F055 托管运行期检索（F055 AC-50 调用）、F057 SDK retrieve（F057 承接）；F050 模式 D 以被代表用户为执行身份调用它（AC-43）。（↔DEV-02 ①；GOV-05；伴生 §4.4.6；Discovery §2.3 / N3；§4 决议-2）
- **AC-20** — THE SYSTEM SHALL 使门面对每次检索执行**文件级过滤，且过滤发生在结果返回前**（不存在先返回后过滤、或只过滤一部分的路径）；对知识空间按文件级有效可见性过滤——覆盖单文件直接授权、文件切自定义模式后与所在资源脱钩、不同文件夹授权不同、系统标记与跨租户共享四类来源；对文档知识库按库级可读性过滤（现权限模型无文件级，§4 决议-3）。（↔伴生 §4.4.6 / 附录 B.1；DEV-02 ①「过滤强度必须是文件级」；GOV-05 过滤强度）
- **AC-21** — WHEN 门面收到声明白名单, THE SYSTEM SHALL 把检索范围限定为**白名单 ∩ 执行身份可见范围**：白名单外的知识库整体不可及——即使执行身份本人有权限、即使执行身份是租户管理员（身份短路不越过白名单）；白名单内、执行身份无权的库或文件不出现在结果中；声明范围内的结果与该执行身份在平台内自行检索（限定同一范围）**集合相等**。（**INV-36 承接**；↔GOV-05 两层过滤 / 验收 5 / 6；F055 AC-50 / AC-51 调用）
- **AC-22** — WHEN 门面未收到声明白名单（MCP 面、v2 检索、本地 dev 期）, THE SYSTEM SHALL 在执行身份的全部可见范围内检索，或在调用方显式指定且全部可及的子集内检索（任一不可及 → 按 AC-11 拒绝整个请求）。（↔DEV-05 ③；NFR-1.1）
- **AC-23** — IF 执行身份缺失或无法确立, THEN THE SYSTEM SHALL 拒绝检索，绝不回退为按白名单全量放行、按任何固定 / 配置身份放行、或返回「公开子集」。（↔GOV-05 fail-closed；NFR-1.4；铁律 2 同向；INV-30）
- **AC-24** — IF 权限引擎不可用、评估失败或结果不可判定（含任一目标库 / 文件的可见性无法判定）, THEN THE SYSTEM SHALL 返回带错误码的明确错误、不返回任何结果——**不得返回未过滤或部分过滤的结果集，也不得静默缩成空集或子集后当作成功响应**；调用方（MCP 工具 / v2 端点 / F055 / F057）原样向其调用者暴露该错误。（↔INV-30；伴生 铁律 3 / AC-13；DEV-02 验收 9；GOV-05 验收 7；§4 决议-9）
- **AC-25** — WHEN v2 `POST /filelib/retrieve` 被调用（F049 已加鉴权）, THE SYSTEM SHALL 使其经同一门面执行（执行身份 = 密钥主体；F050 后模式 D 为被代表用户），过滤强度由「知识资源级一次校验」升级为文件级过滤 + fail-closed；对外请求 / 响应契约保持兼容——除结果集因过滤收窄外无变化；代码注释与对外接口文档（若有）中「已有 per-user 文件级过滤」的失实表述订正为与实现一致（伴生 B.1 已指出该表述与实现不符）。（↔伴生 §4.4.6 / 附录 B.1 / B.1 表 `POST /filelib/retrieve` 行；F049 排除项「随 F052 收敛」）
- **AC-26** — THE SYSTEM SHALL 使门面成为开放面上**唯一**的检索路径：MCP 检索工具、v2 检索端点、托管运行期检索、SDK retrieve 之外不存在绕过门面的路径；仅做知识资源级一次校验的旧检索路径在开放面上不再被任何调用方使用。（↔DEV-02 ①「不得复用旧路径」；伴生 §4.4.6「补齐后收敛到同一条路径」）
- **AC-27** — THE SYSTEM SHALL 使本版门面支持的知识库类型 = 文档知识库 + 知识空间；检索请求（显式指定或白名单内）中出现不支持类型的库（如 QA 库、个人库）时按 AC-11「不可及」处理，**不单列「类型不支持」**（存在性不泄露）；「类型不支持」的可区分信号只出现在两处：知识库清单工具不列出该类库（AC-12）、F055 预检拒绝含该类库的能力声明（F055 AC-07 消费同一「门面支持类型」判定）。（↔Discovery §2.3 待澄清；§4 决议-10）

### 2.4 `delegate` 入口拒绝（INV-31 · MCP 面）

- **AC-28** — IF 密钥持有 `delegate` 位, THEN THE SYSTEM SHALL 在 MCP 面**通道入口**（连接建立 / 首次能力协商）按权限位直接拒绝，错误明确指向「这把密钥配置为委托专用，本地开发请另发一把」；不列出任何工具、不执行任何工具。（↔伴生 AC-49 / §4.2.4；DEV-02 ④ / 验收 10；INV-31）
- **AC-29** — THE SYSTEM SHALL NOT 使持 `delegate` 的密钥在 MCP 面表现为按服务账号身份正常执行（静默落回模式 S），也不得只返回「缺少身份头」类参数错误码。（↔伴生 AC-49 / AC-38 同向；DEV-02 ④ / 验收 10；INV-31）
- **AC-30** — IF MCP 面收到任何身份传递类请求头（代表平台用户 / 外部用户标识）, THEN THE SYSTEM SHALL 拒绝并提示「MCP 面不承载委托」——不静默忽略后按服务账号身份继续执行。（↔F049 AC-33 同向；DEV-02 ④；GOV-05 信任机制分界）

### 2.5 `identity:read` 组织查询边界

- **AC-31** — WHEN 持 `identity:read` 的密钥查询组织架构, THE SYSTEM SHALL 返回本租户**全量**组织架构（部门树、部门成员、用户身份）；THE SYSTEM SHALL NOT 提供任何把可读范围收窄到部分部门的机制或配置——边界由「给不给这个位」承担。（↔DEV-02 ② / DEV-01 ③；伴生 §4.2.4 扩展位表）
- **AC-32** — THE SYSTEM SHALL 使跨租户的部门与用户一律读不到；按用户标识点查其它租户的用户时与「不存在」给同一响应。（↔DEV-02 ② / 验收 5「真实边界是租户隔离」）
- **AC-33** — IF 密钥未持 `identity:read`, THEN THE SYSTEM SHALL 拒绝身份 / 组织查询并指明缺位；本地 `dev` 期应用查身份 / 组织同按本位判定（`dev` 注入的服务账号自身身份不消费本位——F053 决议-9）。（↔DEV-02 验收 5；DEV-01 ①）

### 2.6 应用类工具 owner 收窄

- **AC-34** — WHEN 应用数据 / 应用状态 / 日志工具被调用, THE SYSTEM SHALL 只对**该密钥所属服务账号的资源归属人为 owner** 的应用放行；对其它应用（含不存在的）一律拒绝、不返回内容，提示形状为「非你名下应用」类、不带 owner 名——不透露不可见应用的存在性与 owner。三入口（MCP 工具 / CLI `logs` / `deploy` 服务端）**权限判定一致** = 都按密钥归属人 owner 判；提示形状允许不同（`deploy` 服务端按 PRD-1 DEV-04 验收 9「提示应用归属」，F055 AC-04）。（↔DEV-02 ③ / 验收 3；DEV-01 ③ 落地口径 ②；DEV-04 验收 9 / 12；F055 AC-04 同判定；§4 决议-5）
- **AC-35** — THE SYSTEM SHALL 使 AC-34 对**租户管理员名下服务账号的密钥同样成立**（管理员查他人应用走应用详情页，不走开发者 key 通道）；该判定为业务规则前置拦截，不受权限运行时的管理员短路影响。（↔DEV-02 ③ 例外 / 验收 6；F054 §3「仅 owner 限制为前置拦截」）
- **AC-36** — WHEN 服务账号的资源归属人被更换, THE SYSTEM SHALL 使应用类工具自此按新归属人 owner 的应用放行，原归属人 owner 的应用不再可及（应用 owner 不随之变更——F049 AC-27 定义 6 边界 d；F054 AC-07）。（↔DEV-01 ③）

### 2.7 开放能力层开关（F049 拥有，本 Feature 消费）

- **AC-37** — WHERE 开放能力层未部署, THE SYSTEM SHALL 使 MCP Server 不可达（地址不服务、不出现在任何接入信息中）、无新增常驻负担；服务账号模块（F049 AC-49）与 v2 开放 API 不受影响；**统一检索门面不受该开关影响**（v2 `POST /filelib/retrieve` 恒经门面执行）。（↔GOV-10 规则 / 验收 4；NFR-4）
- **AC-38** — WHERE 仅部署开放能力层、未部署工场运行时层, THE SYSTEM SHALL 使四类非应用工具（检索 / 清单 / 模型清单 / 身份组织）正常可用，两类应用工具按 AC-17 表现。（↔GOV-10 验收 3 / 三层形态表）

### 2.8 集合相等与 fail-closed 验收

- **AC-40** — THE SYSTEM SHALL 使经 MCP 检索的结果与对该服务账号授予范围的预期集合**相等**——不多给也不少给；验收样本须含：未授予知识库、同一知识空间内文件级权限差异（部分文件无权）、文档知识库（库级）各至少一例。（↔DEV-02 验收 8；DEV-01 验收 6）
- **AC-41** — THE SYSTEM SHALL 使同一把持 `knowledge:read` 的密钥经 v2 `POST /filelib/retrieve` 与经 MCP 检索工具、在同一查询与范围下得到**相同的可见集合**。（↔DEV-01 ① / 验收 6）
- **AC-42** — WHEN F055 托管运行期以当前访问用户为执行身份、能力声明为白名单调用门面, THE SYSTEM SHALL 使声明范围内的检索结果与该用户在平台内自行检索（限定同一范围）的集合相等（含库内无权文件不出现）——F055 AC-50 调用本门面并承接其运行期验收。（↔GOV-05 验收 6；INV-36）
- **AC-43** — WHEN 以某被代表用户为执行身份调用门面, THE SYSTEM SHALL 使结果与该用户在平台内自行检索的集合相等（纯替换、无意外收窄、无超集）——能力由本 Feature 交付，模式 D 的准入与验收由 F050 承接。（↔伴生 AC-12 / §4.4.6；Discovery N3）
- **AC-44** — WHEN 人为使权限引擎不可用, THE SYSTEM SHALL 使 MCP 检索工具、v2 `POST /filelib/retrieve`、托管运行期检索三处均返回明确错误、零结果，而非未过滤或部分过滤的结果。（↔DEV-02 验收 9；伴生 AC-13；GOV-05 验收 7；NFR-1.4）
- **AC-45** — THE SYSTEM SHALL 使未持对应权限位的工具调用被逐位拒绝——按 DEV-01 ① 映射表逐位验证：仅持 `knowledge:read` 不能调模型清单 / 身份组织 / 应用工具；仅持 `model:invoke` 不能检索；仅持 `app:manage` 不能查组织；每种拒绝均指明缺位（AC-04）。（↔DEV-02 验收 1；DEV-01 验收 5）

### 2.9 追加（2026-08-17 审查修订，编号末尾追加）

- **AC-46** — WHEN 门面收到声明白名单、且白名单内某知识库已被删除或其应用侧授权已收回, THE SYSTEM SHALL 返回**带该库标识的「能力已收回」可区分错误**、不返回部分结果、不静默剔除该库后继续检索（供 F055 AC-53 转成应用可见的带能力名「已收回」错误）；WHEN MCP 检索工具显式指定该库（无白名单语义）, THE SYSTEM SHALL 仍按 AC-11「不可及」处理。（**INV-36 承接**；↔GOV-05 能力收回后行为 / 验收 4；F055 AC-53 消费；属 §2.3）
- **AC-47** — THE SYSTEM SHALL 使 MCP 面的错误响应与任何工具返回体**不回显密钥值**（掩码之外的任何片段一律不出现）；日志与审计同 AC-07。（↔NFR-2 密钥零暴露；属 §2.1）

## 3. 边界情况

> 只写期望的对外行为；机制与落点见 design.md §4 / §5。

- **门面的执行身份只有两种，白名单可选**：MCP 面与本地 dev 期 = 服务账号（无白名单，范围 = 被显式授予的资源）；托管运行期 = 当前访问用户（白名单 = 能力声明）；模式 D = 被代表用户（无白名单）；审批期预览 = F055 以 owner 为执行身份调用（INV-36 唯一例外，由 F055 承接与计审计，门面本身不感知「例外」）。门面对任何执行身份做同一强度的过滤——它不知道也不关心调用方是谁，只认执行身份 + 白名单。
- **「与工作台检索集合相等」的基准锚点**：验收基准 = 该执行身份在平台工作台经**完整文件级过滤**的检索路径得到的集合；平台内若存在过滤强度不同的检索变体，以完整文件级过滤路径为准（哪条是完整路径由 design 核实指定），变体间在边界样本上的差异不构成对门面的验收豁免。
- **文档知识库 vs 知识空间**：知识空间存在四类文件级可见性差异来源、门面按文件级；文档知识库现权限模型只有库级、门面按库级（§4 决议-3）。「集合相等」在两种类型上分别按各自粒度成立；将来文档知识库引入文件级权限，门面按平台既有可见性判定自动跟随、不自造模型。
- **不支持的知识库类型**：QA 库、个人库等本版不可经门面检索——检索请求中显式指定或白名单内出现，整请求按「不可及」拒绝（不单列「类型不支持」，AC-27）；可区分的「类型不支持」信号只在清单工具（不列出）与 F055 预检（拒绝能力声明）两处。
- **权限判定的高频放大**：MCP / 托管运行期检索是高频调用，逐目标的权限判定会被放大（现状与量化在 design）。对外行为口径：**门面结果正确性优先**——任何缓存或批量优化不得破坏撤销 5 秒上界（INV-28）与 fail-closed（INV-30）；性能指标与手段在 design。
- **fail-closed 与「静默缩集」的区别**：门面调用面在权限评估失败时必须给出**明确错误**（AC-24），而非静默缩成空集或子集后当作成功；这一严格取向只作用于门面及其四个调用方，不翻转平台内对话检索链的既有取向（§4 决议-9，前提待 design 核实）。
- **管理员短路与门面**：MCP 面执行身份恒为服务账号，服务账号不得持有管理员身份（F049 AC-22）→ MCP 检索永不命中管理员短路，key 泄漏不等于全租户知识外泄；托管运行期访问用户可能是租户管理员——其身份短路只作用于「可见范围」层，**白名单收窄仍生效**（AC-21）。
- **MCP 会话与平台会话解耦**：MCP 连接是协议会话、不是业务会话；不建会话记录、不进任何人的会话列表；同一密钥可并发多个 MCP 客户端连接，互不可见。
- **工具错误对本地 agent 必须可诊断**：agent 没有界面、没有人替它看日志——每种拒绝必须自带「类别 + 原因 + 下一步指引」三要素（AC-09）；缺权限位与无资源授权两种失败必须可区分（AC-03，伴生 §4.4.1）；「类型不支持」在检索面不单列、归入「不可及」（AC-11 / AC-27）。`26016` 类参数错误对 agent 是天书——`delegate` 拒绝必须按位在入口给出可读指引（AC-28）。
- **存在性不泄露**：不可及知识库（不存在 / 未授予 / 类型不支持）、非本人 owner 的应用（含不存在的）、跨租户用户（含不存在的）三处均与「不存在」同一响应；owner 收窄的提示只说「非你名下应用」、不带 owner 名，不透露不可见应用的存在性与 owner。
- **`identity:read` 的两个方向**：给了 = 本租户全量组织架构可读、无法收窄（AC-31）；没给 = 连点查都拒（AC-33）。「读自己」（`dev` 注入的服务账号自身身份）不经本位。结果永不含服务账号——它们刻意不属于任何部门（伴生 D10）。
- **应用类工具依赖工场运行时层**：未部署 → 不出现在清单、直接调用得到「未启用」类错误（AC-17）；其服务端能力归 F054 / F055，本 Feature 的工具面接线与 owner 判定不阻塞其余四类工具的交付。
- **未部署开放能力层**：MCP 地址不服务、接入信息区不出现（F053）、三扩展位不出现（F049）；但门面恒在——v2 检索端点从 F049 期的「库级一次校验 + fail-closed」在本 Feature 上线后收敛到门面（AC-25），与开关无关。
- **密钥传递方式与 F049 一致**：请求头 / 传输层凭据，不走查询参数（会进访问日志）。
- **检索参数有上限**：条数 / 正文长度等由平台设上限，调用方超出即按上限截断并在响应中可见（不静默）；上限取值在 design。
- **审计不记检索正文、响应不回显密钥**：MCP 调用审计记工具名 / 目标摘要 / 结果 / 时间，不记片段正文（可能含知识库内容）；错误响应与工具返回体不出现密钥值（AC-47）；应用数据工具的每次写操作计审计（AC-15）；高频检索的审计存储分层是 design 事项（F056 高频事件分层同向）。

## 4. 待澄清决议

> 2026-08-17 用户授权全自动模式：以下各项按建议直接定案，记录理由与「何时重新考虑」供追溯。

- **[决议-1] MCP Server 部署形态：不引入新的常驻进程与端口，MCP Server 随平台后端 API 进程一同提供、地址位于平台 API 同源路径之下，受开放能力层开关条件启用。** 理由：GOV-10 / NFR-4「不装的环境无新增常驻负担」——同进程条件启用天然满足「不装即零成本」；六类工具全部是对既有领域能力的「薄封装 + 鉴权」（Discovery §2.9），复用 F049 鉴权依赖与租户上下文注入最直接；不新增部署单元、端口、nginx location，商业版 Java 网关只放行 API 前缀——同源路径可零改造穿透。备选 = 独立进程 / 端口（「整层可不装」在部署上更干净，但每个环境多一个进程与端口、且鉴权与租户注入要跨进程重做）。**何时重新考虑**：MCP 长连接在 nginx / 网关双层代理下出现兼容问题、MCP 流量成为 API 进程的负载源、或需要独立伸缩时——抽为独立进程，工具面契约不变。传输形态（单一 streamable 还是兼容 SSE）在 design 定。
- **[决议-2] 统一检索门面 owner = F052**（Discovery N3 已定，此处落 spec）。F050（模式 D 集合相等）、F055（托管运行期「白名单 ∩ 访问用户」）、F057（SDK retrieve）只调用不拥有；批次 A 顺序 F049 → F052 → F051 → F053 → F050。理由：三处消费方对过滤强度与 fail-closed 的要求完全相同，门面若分散在各消费方会造出三条强度不一的路径——正是伴生 B.1 已核实的分叉再现；MCP 检索是四个调用方中最早需要它、且验收最完整（DEV-02 验收 8 / 9）的一个。
- **[决议-3] 文档知识库按库级过滤，知识空间按文件级过滤。** 理由：文档知识库现权限模型无文件级可见性差异（无单文件授权 / 文件夹 / 自定义模式脱钩），「含文件级权限」在它身上无对象；本 Feature 不新建权限模型（那是权限体系级改动，与检索门面正交）；「与平台内自行检索集合相等」在文档知识库上按库级即成立。**何时重新考虑**：文档知识库引入文件级权限时——门面按平台既有可见性判定，无需改门面语义，只需验收样本补例。
- **[决议-4] 模型清单查询归本 Feature，模型调用归 F051。** 理由：MCP 工具面的鉴权、工具注册、按位过滤、审计归属是一套，模型清单只是其中一个只读工具；「可用模型范围 = 租户能力总线已启用模型」的口径由 GOV-05 / F051 定义，本 Feature 只读该口径。两者的位相同（`model:invoke`），但数据面不同（清单是元信息、调用是裸协议透传）。
- **[决议-5] 应用类工具的 owner 判定基准 = 密钥所属服务账号的资源归属人（调用期取当前值）与应用 owner 字段（F054 AC-07）相等。** 理由：DEV-01 ③ 落地口径 ②「只能操作自己的应用以它判定」；调用期取当前值使归属人更换后新归属人的应用即时可及、旧的即时不可及（AC-36），与 F049 定义 6 边界 d「归属人变更不追溯已有资源」一致（应用 owner 不变，变的是 key 这头）。
- **[决议-6] 工具清单按密钥权限位过滤，且直接调用未持位工具返回「指明缺位」的拒绝而非「未知工具」。** 理由：agent 面对未过滤清单会反复尝试无权工具、每次撞墙；只过滤清单不校验调用则清单成了绕过点；两者都做，且拒绝可诊断（AC-04 / AC-09）。备选 = 清单全列、调用时拒绝——被否决，理由同上。
- **[决议-7] 检索工具显式指定的目标知识库中任一不可及 → 拒绝整个请求（指出不可及标识），不静默剔除后返回缩水结果；「不存在」「未授予」「类型不支持」同一「不可及」响应。** 理由：伴生 §7.2 立的标准——不接受「返回 200 + 静默缩水的结果集、调用方无从察觉」；agent 指定了库就是有意图，少给等于静默错误；同一响应防探测存在性（检索面对库只有可及 / 不可及两态）。未指定目标 → 全部被授予范围（AC-22）。
- **[决议-8] 应用数据工具 = 表清单 / 表结构读取 + 行数据读写（行级增删改），不含 DDL；写限归属人 owner 的应用、每次计审计。**（审查修订：原「只读」被否决）理由：伴生 §4.2.4 是权限位 SSOT——`app:manage` 明写「应用数据表结构与数据**读写**」；PRD-1 DEV-02 六类工具表用途栏写「开发与排障时**操作**应用自有数据」，开发期 agent 造测试数据 / 修脏数据是真实诉求；护栏 = owner 收窄（AC-34）+ 每次写计审计（GOV-04「生产数据行编辑」）+ 不做 DDL（表结构由 `bisheng-app.yaml` 声明、平台建表、改删列走 F055 发布管线的显式确认 + 迁移前快照）；服务端接口与应用详情页数据 tab 共用（F054 AC-56），本 Feature 不另造写路径。**何时重新考虑**：出现经工具误写生产数据的实际事故时，评估对写操作加二次确认类交互（MCP 面无人在场，形态待定）。
- **[决议-9] 门面的严格 fail-closed（评估失败 → 明确错误）只作用于门面调用面（开放面四处），不翻转平台内既有对话检索链的取向。** 前提**待 design 核实**：F048 基线上权限检查已为「失败即拒」（Discovery §2.2），平台内检索链是否仍残留「静默缩集」取向、残留在哪一层，由 design 探查阶段核实——本决议只定「门面调用面必须是明确错误」与「本 Feature 不改平台内检索链的既有行为」两条，不预设现状。理由：INV-30 的适用对象是开放面；即便平台内仍有降级取向，全局翻转的影响面也远超本 Feature。**何时重新考虑**：产品决定平台内检索也改明确错误态时，由门面之外的独立 Feature 承接。
- **[决议-10] 门面本版支持的知识库类型 = 文档知识库 + 知识空间；QA 库、个人库在检索请求中一律按「不可及」处理，可区分的「类型不支持」信号只出现在清单工具（不列出）与 F055 预检（拒绝能力声明）两处。**（审查修订：原「门面报『类型不支持』错误」被否决——检索面对库只有可及 / 不可及两态，单列类型会泄露存在性）理由：现开放面检索对这两类本就不支持；声明期由预检拦住、清单工具让 agent 从一开始就看不到它们，运行期兜底则统一为「不可及」。**何时重新考虑**：QA 库需要经开放面检索时（届时按其权限模型定粒度）。
- **[决议-11] 组织查询结果不含服务账号；`dev` 注入的服务账号自身身份不消费 `identity:read`。** 理由：服务账号刻意不属于任何部门（伴生 D10），出现在组织树里既不真实又违背 INV-29「失败方向是看不到」的取向；`dev` 期「读自己」与「读全租户组织架构」风险量级不同——F053 决议-9 已裁定并回修 PRD-1 DEV-01 ① 表，本 spec 与之一致。
- **[决议-12] MCP 面每次工具调用计审计归属（密钥掩码 + 服务账号 + 工具名 + 目标摘要 + 结果 + 时间），不记检索正文；高频检索的审计存储分层是 design 事项。** 理由：DEV-01 验收 1「key 的每次调用可在审计中归属到 key 与其服务账号」；GOV-04 要求密钥类事件全链路留痕；检索正文含知识库内容，记入审计等于把知识库内容复制进审计表。**何时重新考虑**：审计写放大成为瓶颈时，与 F056 高频事件分层一并处理（口径不变，只改存储）。
