## 服务器现状

- 当前运行时 `multi_tenant.enabled=false`。
- 网关没有 `custom.kunlian` 配置；后端没有 `sso_sync.kunlian` 配置，均无昆联秘密环境变量。
- 八张昆联集成表和用户领域投影状态表均已存在、均为零行；本轮无需新增表或迁移已有字段。
- 只有本地租户 `default`（ID 1）和本地管理员 `admin`（ID 1）；尚无昆联专属租户。
- 网关与后端在同一 Docker 网络；后端服务别名为 `backend`，网关当前实际地址为 `172.19.0.12`。该地址由 Docker 动态分配，重建后必须复核，不能据此长期信任整个网段。
- 本轮没有修改业务源码、运行时配置、租户、用户、角色、授权或同步策略，也没有重启业务服务。

## 拟执行的最小方案

1. **目录兼容修复。** 仅适配本次附加的组织／岗位展示字段；保留其余字段的严格校验，不将展示字段作为身份、租户或授权依据。不全局设置 extra=ignore。以真实响应字段结构制作无个人信息的夹具，覆盖列表、单成员和未知字段拒绝回归，再部署这项最小修复。
2. **备份并配置。** 备份当前配置、数据库及 OpenFGA 授权存储的可恢复基线，保留当前制品和目录映射。将昆联提供的凭据及我方生成的独立内部签名、CSRF、加密秘密注入受限环境文件；仓库仅保留引用。补充配置草案见下方两个文件，合入已有节点，不能整体覆盖现有配置。
3. **启用多租户和专属映射。** 开启现有部署的多租户模式，通过现有租户服务创建 `bisheng-workflow`／`毕昇-Workflow` 专属租户，由现有本地管理员管理；将昆联固定测试租户映射到新建租户，不迁移默认租户的用户或 Workflow，不按同名账号合并身份。
4. **先同步、后开放登录。** 先保持两端登录关闭，登记初始策略并执行全租户完整目录同步；只为已明确映射的试点租户投影影子账号，其他外部租户保持未映射。仅为交付的测试账号显式配置工作流构建／新建所需角色和菜单，不授予管理员或其他租户资产权限。
5. **登录启用与验收。** 同步及试点用户投影核验后提升策略版本、启用后端登录和网关入口。验证公网入口、换码、回调、实际用户与租户、管理页、新建 Workflow、退出和旧会话拒绝；校验既有本地管理员仍可登录。创建的验收 Workflow 记录精确 ID，不批量清理现有资源。

## 影响与回退

- 开启多租户会改变整个测试部署的租户解析和访问边界；重建网关、API、Worker／调度进程会带来短暂中断，已有登录可能需要重登。需覆盖已有管理员与默认租户访问回归。
- 创建专属租户、影子账号和菜单角色属于实际数据及权限变更；保留已有默认租户、用户、工作流和人工授权，不批量迁移或覆盖。
- 未成功开放登录时可恢复配置并停用本次新增映射；已建立真实会话后须按既有安全禁用流程先提升策略、关闭登录并验证旧会话拒绝，再恢复部署配置。不能仅回滚代码或关闭多租户开关，也不自动删除本次新增记录。
- 完整 MySQL／DM8 双库、两实例故障、上游停用和全部验收用例仍待执行；本次单账号基本闭环不得代替这些证据。

依据用户提供的 AGENTS.md §4.4、§6，运行时配置、权限和数据变更需先说明影响并取得确认。上述步骤在获得本次具体方案确认后执行。
