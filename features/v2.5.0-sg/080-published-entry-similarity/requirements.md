# 需求

用户要求：两个相似文档分别发布到同一个目标知识库后，仍能识别两者相似。来源可为不同知识库。

当前错误：候选查询要求目标库 KnowledgeFile 自身关联主版本；发布入口只有 reference_document_id，因此漏选。解析成功会刷新相似候选，发布投影完成没有相应触发。

| Requirement | Acceptance | 验证 |
|---|---|---|
| REQ-001 发布推荐包含有效发布入口 | AC-01 A 先发布到目标库，B 后选择该目标库时，达到阈值可推荐 A；A/B 可以来自不同库 | 实际 ORM + 推荐服务测试 |
| REQ-002 发布后形成库内提醒 | AC-02 两个独立文档的入口均在目标库有效且就绪后形成相似关系；发布完成触发刷新，重复任务不重复建候选 | 发布完成、持久任务、缓存读写集成测试 |
| REQ-003 入口与正文身份分离 | AC-03 目标入口负责权限/展示/预览，当前主版本负责 SimHash/元数据/正文；更新主版本后不使用旧指纹 | 受控 ES 查询与主版本切换测试 |
| REQ-004 保留边界 | AC-04 无查看权限、撤回/删除/准备中/投影未就绪入口不入选；同一文档多入口/多版本不互相推荐；不改变租户、公司及两套阈值 | 参数化拒绝及兼容回归 |
| REQ-005 不破坏版本业务 | AC-05 识别与关联能力分别表达；无权关联或现规则禁止的发布入口仅展示相似和预览，不出现可点击后必然报错的版本操作 | 后端能力字段及前端组件测试 |

范围：第二次发布时的推荐及发布后的目标库内相似提醒；与目标库原有普通文档比较保持一致。

不包含：自动合并、不为发布入口建立独立版本链、不改变分享权限/审批/版本归属，不全量重算历史、不重开已处理提醒、不部署或写线上数据。历史已发布文件的批量重算若需要另行预览和确认。
