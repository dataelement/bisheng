# 模块首页布局

2026-11-03，用户确认内容区采用「最大 1000px，居中，更紧凑」。本次为既有首页的视觉规整，不增加业务能力或更改 API 契约。

## 范围与参数

适用于桌面端（浏览器宽度 ≥768px）的知识空间、订阅、应用、工具与技能首页，包括订阅无频道时的发现首页。移动端继续使用各模块原有导航与布局。

| 项目 | 统一规则 |
| --- | --- |
| 内容宽度 | `min(1000px, 右侧可用宽度 − 64px)`，在右侧主体内居中 |
| 页面留白 | 上下 32px，两侧至少 32px |
| 页头高度 | 32px |
| 页面标题 | `text-h2`，20px / 28px，Medium 500；语义标签仍为 h1 |
| 标题位置 | 左对齐，与工具栏和正文内容列共用左边缘 |
| 页头操作 | 同行靠右，保留各页现有搜索或创建入口 |
| 页头至工具栏 | 16px；无工具栏的订阅保留原分组间距 |
| 滚动 | 页头保留在顶部，正文在各自内容区滚动 |

统一框架由 `src/frontend/client/src/components/ModuleHome/ModuleHome.tsx` 的 `MODULE_HOME_FRAME`、`MODULE_HOME_COLUMN`、`ModuleHomeHeader` 提供。应用首页也复用内容列常量，避免单独维护宽度。知识空间的尺寸与动画使用页面局部规则；桌面内部尺寸固定、卡片宽度随内容区伸缩，具体见 [知识空间规范 v1.40](knowledge-space-design-spec.md#v140--桌面窗口变化保持组件尺寸2026-11-03)。网格容器位于受限的内容列内，容器单位以实际内容列宽度计算。

本约定覆盖知识空间旧规范中的页面宽度、页边距、页头高度、页面标题和创建按钮局部几何覆盖；创建按钮使用共享 Button 的原生 medium 尺寸。卡片内容及业务行为不在本次调整范围。

## 验证记录

使用实际首页组件、实际样式和演示数据进行浏览器测量；数据依赖替换为夹具，不视为真实后端联调。

以下为首轮 24px 标题时的测量记录；后续标题调整见文末，内容列宽度和页头外框规则继续沿用。

- 1280px 浏览器、侧栏占位 240px：应用、订阅、订阅空状态、工具与技能的内容列均为 976px，左边缘 x=272，标题行距右侧页面顶部 32px，标题均为 24px / 32px / 500，无页面横向溢出。
- 知识空间外框 1440px、侧栏占位 240px：右侧宽 1200px，页头和内容列均为 1000px，左右实际留白各 100px；标题 24px / 32px / 500，常规卡片高度仍为 126px。
- 知识空间外框 1024px、侧栏占位 240px：内容列 720px，72 张长文本卡片在正文内产生纵向滚动，页面与内容列均无横向溢出。
- 知识空间外框 1920px、侧栏占位 240px：右侧宽 1680px，页头和内容列仍为 1000px，两侧留白各 340px，无横向溢出。
- 客户端 lint、全仓类型检查通过；知识空间、能力中心和订阅相关既有测试 31 项通过。Jest 本次运行通过临时 preload 禁用不可用的可选 canvas，未修改项目依赖。
- 全仓 lint 被未改动的 platform 文件中 8 处既有错误阻断。额外运行的 `MainLayout.mobile.test.tsx` 有 2 项失败：其 Recoil mock 缺少 `useRecoilValue`，在未改动的 `useGetBsConfig` 调用处失败。

真实登录环境的完整导航和接口联调未在本次验证中完成；本地页面未登录时会跳转到管理端。

## 标题调整（2026-11-03）

用户要求四个首页的标题改为 20px。公共页头统一使用 `text-h2`（20px / 28px），字重继续为 500，在原 32px 页头内垂直居中；1000px 内容上限、32px 页面留白和现有对齐规则继续沿用。

工具与技能、应用、订阅及订阅空状态的实际组件预览测得标题均为 20px / 28px / 500，页头仍为 32px；知识空间引用同一公共页头。公共页头的定向 ESLint 和差异空白检查通过。
