**所属版本**: v3.0.0-beta2

## 范围边界

### 本次纳入

- DSH Desktop 仅配置 BiSheng Nginx 公开地址，通过浏览器完成 BiSheng 用户登录与授权；支持客户端发起、固定网页入口唤起及当前授权事务内的票据粘贴兜底。
- 按自然人分配固定 License 席位，并限制已分配人数不超过授权上限。
- 为已分配席位的用户提供 DSH 专用登录凭证。
- DSH Desktop 使用 BiSheng 已配置且被管理员允许的模型驱动 Agent。
- 对 DSH 模型调用执行月 token 上限控制并保留调用记录。
- 管理员在 BiSheng 统一管理席位、模型范围、用量、撤销与重新分配。

### 本次明确排除

- 不复用开放 API 的 PAT、SAK 或其他 API Key 作为 DSH 登录凭证。
- 不改变 PAT 的既有用途，PAT 与 DSH 席位、模型调用无关联。
- 不因用户登出、客户端离线、异常退出或凭证过期自动释放席位。
- 不按设备计数或收费，一个自然人始终只占一个席位。
- 不迁移或复制 BiSheng 现有模型配置，不新增“DSH 模型”类型。
- 不要求 BiSheng 常规业务部署 Gateway；启用 DSH 能力时须部署 Gateway 并启用其 DSH 授权模块。
- 不包含 RPM/TPM、金额预算、部门共享池、聚合看板和用量导出。

## 1. 用户故事

### US-A DSH 用户

作为 **已拥有 BiSheng 账号的 DSH Desktop 用户**，
我希望 **通过浏览器登录并在 DSH Agent 中使用管理员开放的 BiSheng 模型**，
以便 **无需单独配置模型密钥即可使用企业模型能力**。

### US-B 系统管理员

作为 **BiSheng 系统管理员**，
我希望 **在同一管理入口的不同视图管理 DSH 席位与登录、可用模型和月用量上限**，
以便 **统一管理员工的 DSH 使用资格与模型成本**。

### US-C License 管理者

作为 **企业 License 管理者**，
我希望 **实际获得 DSH 使用资格的自然人数不超过授权席位数**，
以便 **未修改的官方 DSH 接入链路按商业授权限制使用资格**。

2026-09-09 用户已确认：不承诺客户拥有服务器控制权并修改开源模型执行链后仍无法绕过，模型执行保留在 BiSheng。

### US-D 审计人员

作为 **审计人员**，
我希望 **能够追溯每次 DSH 模型调用的用户、模型、用量和结果**，
以便 **定位滥用、超额和调用异常**。

## 2. 验收标准

### 2.1 登录与身份确认

- **AC-01** — WHEN DSH Desktop 发起登录, THE SYSTEM SHALL 在浏览器中使用 BiSheng 既有用户登录能力完成身份认证。
- **AC-02** — WHEN 用户完成登录并确认授权 DSH, THE SYSTEM SHALL 向本次 DSH 登录返回一次性身份凭据。
- **AC-03** — IF 一次性身份凭据无效、过期或已被使用, THEN THE SYSTEM SHALL 拒绝本次 DSH 登录且不分配席位。
- **AC-04** — IF 用户已被停用、删除或不属于当前租户, THEN THE SYSTEM SHALL 拒绝本次 DSH 登录。

### 2.2 固定席位

- **AC-05** — WHEN 从未分配过席位的用户首次通过 DSH 登录且仍有容量, THE SYSTEM SHALL 为该自然人分配一个固定席位。
- **AC-06** — WHEN 已分配席位的用户再次登录, THE SYSTEM SHALL 继续使用原席位且不得重复计数。
- **AC-07** — IF 已分配席位数达到 License 上限, THEN THE SYSTEM SHALL 拒绝新的席位分配并向用户说明席位已满。
- **AC-08** — WHILE 用户席位处于已分配状态, THE SYSTEM SHALL 在用户登出、客户端离线、异常退出和登录凭证过期后继续保留该席位。
- **AC-09** — WHEN 管理员明确撤销用户席位, THE SYSTEM SHALL 释放一个 License 名额并将该用户标记为已撤销。
- **AC-10** — WHILE 用户席位处于已撤销状态, THE SYSTEM SHALL 拒绝其通过再次登录自动获得席位。
- **AC-11** — WHEN 管理员明确重新分配已撤销用户的席位且仍有容量, THE SYSTEM SHALL 恢复该用户的 DSH 使用资格。
- **AC-12** — WHEN 同一用户并发发起首次登录, THE SYSTEM SHALL 最多分配一个席位且 License 计数不得超过上限。

### 2.3 DSH 专用凭证

- **AC-13** — WHEN 用户身份有效且席位已分配, THE SYSTEM SHALL 向 DSH Desktop 签发仅用于 DSH 能力的访问凭证。
- **AC-14** — IF 用户没有已分配席位, THEN THE SYSTEM SHALL 拒绝签发或刷新 DSH 访问凭证。
- **AC-15** — IF DSH 访问凭证无效、过期、租户不匹配或对应席位已撤销, THEN THE SYSTEM SHALL 拒绝 DSH 模型调用。
- **AC-16** — THE SYSTEM SHALL 拒绝使用普通 BiSheng 登录凭证、PAT 或 SAK 代替 DSH 访问凭证调用 DSH 能力。
- **AC-17** — WHEN 管理员撤销席位, THE SYSTEM SHALL 使该用户后续的凭证刷新和新的 DSH 模型调用失效，同时不影响其正常登录 BiSheng 或使用既有开放 API 凭证。

### 2.4 模型使用与用量治理

- **AC-18** — WHEN 已授权的 DSH 用户查询可用模型, THE SYSTEM SHALL 仅返回既有模型业务确认当前租户合法可访问、可用且被管理员开放给 DSH 的模型，包括符合既有共享规则的 Root 模型。
- **AC-19** — WHEN 已授权的 DSH 用户选择可用模型发起请求, THE SYSTEM SHALL 使用对应的 BiSheng 模型能力返回 Agent 所需的模型结果。
- **AC-20** — WHERE DSH 请求选择流式响应, THE SYSTEM SHALL 持续返回模型输出，直至正常完成、用户取消或调用失败。
- **AC-21** — IF 请求的模型未开放、已停用、已删除或既有模型业务不允许当前租户访问（包括未经授权的跨租户模型）, THEN THE SYSTEM SHALL 拒绝该模型调用。
- **AC-22** — IF 当前用户在所选模型上本月已累计实际 token 用量达到或超过该用户与该模型配置的月上限, THEN THE SYSTEM SHALL 拒绝该模型的新调用；其他模型独立判断，不能借用或共用额度。
- **AC-23** — WHEN DSH 模型调用完成或失败, THE SYSTEM SHALL 记录用户、租户、席位、模型、用量、调用结果和可追踪标识。
- **AC-24** — THE SYSTEM SHALL 将 DSH 产生的模型用量与非 DSH 场景区分展示和审计。

### 2.5 统一管理

- **AC-25** — WHEN 管理员进入 DSH 管理页面, THE SYSTEM SHALL 展示 License 状态、已用/总席位数及用户级席位状态。
- **AC-26** — WHEN 管理员查看席位列表, THE SYSTEM SHALL 展示用户席位及登录情况，不展示模型或用量列；登录会话以弹窗展示。模型范围与每模型月上限在“模型管理 → DSH 开放范围”按模型、用户配置，用户无需先登录 DSH；每模型用量和最后调用保留在 DSH 管理页的用户用量视图。
- **AC-27** — WHEN 管理员修改用户的 DSH 可用模型或月上限, THE SYSTEM SHALL 对该用户后续的新模型调用生效。
- **AC-28** — IF 撤销或重新分配操作尚未完成, THEN THE SYSTEM SHALL 显示可识别的处理中或失败状态，不得展示为已成功。
- **AC-29** — THE SYSTEM SHALL 记录管理员对席位、模型范围和月上限的变更审计，保留操作者、目标、前后值、版本、时间与操作结果；策略已提交但尚未生效时必须可区分，不以最新配置覆盖历史。

### 2.6 隔离与可选组件

- **AC-30** — WHERE 多租户开启, THE SYSTEM SHALL 将登录、席位、用量和管理查询限定在当前租户；模型访问遵循既有租户权限及合法 Root 共享规则，不泄露其他租户用户、用量或模型供应商配置。
- **AC-31** — IF 系统无法确认用户的 DSH 授权与席位状态, THEN THE SYSTEM SHALL 拒绝新的 DSH 登录和模型调用，同时保持 BiSheng 常规业务及开放 API 可用。
- **AC-32** — WHERE 已部署 Gateway 且 DSH 授权模块有效启用, THE SYSTEM SHALL 支持本期 DSH 能力；未部署或未启用时应明确提示 DSH 不可用，且不影响 BiSheng 常规业务。

---

### 2.7 规模与高频调用

- **AC-33** — WHERE 授权席位达到万级, THE SYSTEM SHALL 支持有界分页、账号/名称检索、席位状态及登录状态筛选；不要求管理页面一次加载全部用户；不提供部门筛选、不向 Gateway 同步部门数据。
- **AC-34** — WHILE 模型调用频繁, THE SYSTEM SHALL 按已累计实际用量实时判断是否允许新调用，不预占在途请求用量；达到或超过所选模型的月上限后拒绝该模型的新请求，其他模型额度独立；已准入的并发请求允许完成并产生超额，实际用量完整记录；不得因持久化展示延迟继续放行，额度状态无法确认时拒绝新调用并明确提示不可用。

## 3. 边界情况

- DSH 签名授权过期、缺失、失效或实例未激活时，不得新分配席位、签发凭证或发起新的 DSH 模型调用。旧商业授权与 DSH 授权独立判定；可解码且字段可解析的旧 trial 期满，不否定仍有效的 DSH 签名授权，也不延长旧 SSO 等能力。外层缺失、损坏或无法解析时无法确认 DSH 授权，必须拒绝 DSH。
- 未获得用量时保留调用明细，status=USAGE_UNKNOWN、token字段=NULL，记录缺失情况；不估算、不记零、不冻结用户或模型。后续请求继续按已记录的逐模型用量和上限判断。可靠补记可选且幂等，不是继续调用的前提。
- 管理员撤销席位与用户发起模型请求并发时，撤销完成后的新请求必须被拒绝，且不得重新占席。
- 管理员重新分配席位时若容量已满，重新分配必须失败且原状态保持已撤销。
- 用户获取模型列表后模型被停用、删除或取消开放时，后续调用必须按最新状态拒绝。
- 多个客户端使用同一自然人账号时只计一个固定席位；是否允许同时登录不改变席位计数。
- 用量接近月上限时，已累计实际用量未达限即可接受新请求；已准入请求可继续完成并造成超额，不因达限中断，不截断超额记录。超额随在途数量和实际用量变化，不承诺固定超额上界。
- 模型调用失败或流式响应中断时，已经发生的实际用量仍须可追踪。
- 席位或用量数据暂时无法加载时，管理页面必须明确展示数据不可用，不得将未知状态显示为未占用或零用量。
- 新 Gateway 必须继续接受旧 License，保持其原有 trial/pro 能力、有效期、状态展示及降级行为；旧 License 缺少 DSH 扩展不得使既有功能失效，也不得被解释为自动获得 DSH 或无限席位。只有显式有效 DSH 授权才可开通席位；DSH 扩展失效不能连带改变旧商业能力。

## 2026-09-09 用户确认的调整

- 一个用户可配置多个模型，每个“用户＋模型”组合仅有一份配置，分别设置月 token 上限；不再执行跨模型共用的用户总上限。0 只禁止该模型新准入。
- 一期不实现 RPM、TPM 或并发限流，也不预埋无效限流字段。实际用量结算和在途可超额规则不变。
- 主配置 `Settings.dsh` 及模型额度均使用明确类型对象，字段提供含义、单位和取值边界。
- 毕昇新增业务不手写 SQL，由 ORM 生成查询与更新；Gateway 保留既有 Mapper 风格并核对兼容性。DM8 真库本轮按用户授权暂缓，以可移植性审查作为本轮条件，不宣称 DM8 实测通过。


2026-09-10 用户确认的存储细化：每个租户、用户、模型组合在额度配置表内独占一条记录；各自保存额度及版本，按模型检索可使用索引。不另建主从明细表；此功能未发版，不新增 Alembic，109 独立联调实例单独调整表结构。此项不改变一期功能范围和 DSH 客户端公共协议。


## 2026-09-10 用户确认的两层开关与下载配置

- 部署文件开关决定是否显示 DSH 管理界面，初始化部署默认关闭。
- DSH 管理页的实例业务开关默认关闭；关闭后隐藏模型开放范围管理和 DSH 用户入口，不再支持模型转发及新登录。管理入口在部署开启时保留，便于重新开启。
- 已有席位、模型授权、令牌与用量保留，业务重新打开后仍按既有有效期和权限判断，不重置额度或延长令牌；已准入调用的实际用量继续记录。
- 管理页允许超级管理员保存统一的客户端下载地址；支持无凭证 HTTP/HTTPS 地址和留空，保存后不需重新构建前端。License 继续由 Gateway 部署配置，不在界面管理。
- 细化验收 AC-SET-01～08 见 [管理配置修订](./management-settings-revision.md)，不引入部门、限流、个人令牌或截图中的 License 编辑功能。

## 2026-09-11：License 与业务数据解除部署绑定

用户确认：指纹输入保留，本期不校验指纹与目标机器或部署环境的匹配；移除 installation_id 以及相关的数据和协议绑定；不兼容未发布的旧 DSH 测试 License；继续兼容旧 SSO License。

- **AC-UNB-01**：同一份合法 DSH License 可在两个独立环境使用，各自的总席位上限均为 License 授予数，不跨环境累计。
- **AC-UNB-02**：同一环境的所有 Gateway 副本共享席位计数；并发分配仍不超过上限，一个自然人不因设备或租户切换重复占席。
- **AC-UNB-03**：更换 Pod、节点或 License 不改变用户、模型授权、席位和用量的归属；迁移保留数据库、Redis、共享 Secret 后可继续使用。
- **AC-UNB-04**：License 指纹与运行机器不同不拒绝授权；签名被篡改、授权过期或无效仍拒绝 DSH 使用。
- **AC-UNB-05**：客户端公开接口保持 0.5.0 的路径、字段及调用顺序；本次切换允许清退旧登录凭证并重新登录，不要求客户端理解安装标识或 License schema。
- **AC-UNB-06**：此未发布功能直接更新建表脚本及测试环境结构，不新增 Alembic 或重复明细表；持久化授权和用量保留，迁移前检查重复用户、幂等记录和待投影用量。

目标设计见 [解绑修订](./installation-unbinding-revision.md)，客户端影响见 [兼容说明](./client-installation-unbinding-compatibility.md)。这些验收项尚未实施验证。
