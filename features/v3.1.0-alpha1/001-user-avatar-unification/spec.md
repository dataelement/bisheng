# Feature — 网页用户头像统一

- **需求来源**　用户在 2026-11-19 确认的网页内部统一范围与默认头像样式。
- **归档版本**　v3.1.0-alpha1 · F001 · [版本契约](../release-contract.md)
- **状态**　需求发现与 12 条正式验收标准已确认。
- **依赖**　现有个人资料、Client 站内通知及两端资源权限管理。

## 1. 用户故事与范围

作为用户，我希望在 Client 更换一次头像后，从 Client 侧栏、账号设置和 Platform 账号菜单都能看到同一张头像。

作为通知接收人或资源权限管理员，我希望通过同一张头像辨认发件人、已授权成员和待选人员；用户没有上传头像时，我希望各处的默认头像一致。

首批验收覆盖 Client 侧栏与账号设置、Platform 账号菜单、Client 消息通知、两端通用资源权限的已授权名单和选人流程。用户随后要求统一两端所有现有的自然人头像位置，补充范围包括知识和频道创建者、组织和租户人员、模型授权、聊天及分享记录、日志与标注。网页与其他终端之间的同步属于后续阶段。

## 2. 验收标准

### 2.1 头像展示

- **AC-01** — WHEN 同一部署中的同一用户有可加载的个人头像，THE SYSTEM SHALL 在本期覆盖的本人入口、可见通知发件人和可见权限人员行显示该用户的同一张当前头像。既有已上传的头像在升级后仍可使用。
- **AC-02** — IF 用户头像缺失、为空、已过期或图片加载失败，THEN THE SYSTEM SHALL 在相应入口显示 Client 现有的圆形灰底白字头像。去掉昵称首尾空白后，取首个 Unicode 字符并转为大写，空昵称显示 `?`。各入口沿用原有头像或图标位尺寸。
- **AC-03** — WHEN 两个账号拥有相同昵称且各有不同的头像，THE SYSTEM SHALL 在通知和权限管理中分别显示对应账号的头像。

### 2.2 本人头像更新

- **AC-04** — WHEN 用户在 Client 账号设置成功更换本人头像，THE SYSTEM SHALL 在该页与已打开的 Client 侧栏显示新头像，无需手动刷新页面。
- **AC-05** — WHEN 在 Client 更换头像后打开或刷新 Platform，或切回已打开的 Platform 浏览器标签页或窗口，THE SYSTEM SHALL 从同一账号的当前资料显示新头像，无需重新登录。
- **AC-06** — IF 新头像保存失败，THEN THE SYSTEM SHALL 保留更换前的头像或默认样式，并在账号设置中显示失败提示，允许再次上传。

### 2.3 消息通知

- **AC-07** — WHEN 发件人在通知所属租户内仍具有有效身份，且接收人在其更换头像后重新进入 Client 消息通知页或刷新该页，THE SYSTEM SHALL 在同一条历史通知上显示更新后的头像。仅加载页面和头像时，通知的已读状态保持原值。
- **AC-08** — WHEN 查看由系统发出且没有自然人发件人的通知，THE SYSTEM SHALL 在头像位显示系统图标。IF 某条历史通知的自然人发件人已无法识别或在通知所属租户内已无有效身份，THEN THE SYSTEM SHALL 保留可见的通知，用现有发件人显示文本生成默认头像，文本为空时显示 `?`。

### 2.4 权限管理

- **AC-09** — WHEN 有权限的管理者在 Client 或 Platform 打开资源的已授权名单，THE SYSTEM SHALL 在直接授权和继承授权的用户行显示可见用户的当前头像，头像不可见或不可用时使用统一默认头像。对仍在可见范围内的用户，更换头像后重新打开名单应显示新头像。
- **AC-10** — WHEN 有权限的管理者在资源权限弹窗或新建频道、知识空间的权限设置中选人，THE SYSTEM SHALL 在候选搜索结果和已选人员行显示对应用户的当前头像或统一默认头像。仍出现在候选列表中的已授权人员，以及返回频道、知识空间权限草稿后的已选人员，均适用此规则。
- **AC-11** — WHEN 查看已有权限界面中的部门或用户组条目，THE SYSTEM SHALL 用相应的主体图标标识这些类型。
- **AC-12** — IF 用户无权查看通知、资源授权名单或人员候选，或某账号位于该入口现有可见范围之外，THEN THE SYSTEM SHALL 继续按现有规则拒绝访问或裁剪结果。直接请求列表数据时，调用者也只能取得范围内人员的个人头像。

### 2.5 两端已有头像位置

- **AC-13** — WHEN 用户在 Client 或 Platform 查看任何已有的自然人头像位置，THE SYSTEM SHALL 优先显示当前入口有权读取的个人头像，在图片缺失或加载失败时按 AC-02 回退。包括知识广场及预览、知识首页、频道创建者及成员、组织与租户选人、模型名单、聊天、日志和标注。
- **AC-14** — WHEN 用户查看历史消息或分享，THE SYSTEM SHALL 使用该条消息可见的作者资料。查看者头像仅适用于身份已匹配的本人消息。缺少作者图片时用可见昵称回退，昵称也缺失时显示 `?`。

## 3. 边界场景

| 场景 | 预期 |
| --- | --- |
| 历史昵称以汉字、补充平面字符或拉丁字母开头 | 按 AC-02 显示首字符，补充平面字符完整显示。 |
| 各入口暂时取不到头像，随后收到新的可用头像 | 首次显示默认头像，后续重新读取该用户资料时显示可用头像。 |
| 发件人已停用、被删除或迁出通知所属租户，接收人仍能查看历史通知 | 保留原通知，头像按 AC-08 回退。 |
| 某人已超出资源主体可见范围，其历史授权行仍按既有规则可见 | 保留该授权行，用对应显示昵称或 `?` 回退。 |
| 搜索、分页或重新打开权限名单 | 头像始终匹配当前行的用户。现有筛选、授权和撤销按原有权限执行。 |
| 退出后以另一个账号登录 | 本人入口只显示当前登录账号的头像。 |

刷新验收以重新打开相关页面或列表、刷新浏览器、切回 Platform 窗口或标签页为准。
