## 1. 什么时候用

轻提示是**用户操作之后从页面顶部滑出、几秒后自己消失**的一条反馈，用来告诉用户「刚才那一下成了没有」。它不挡住页面、不需要用户理会，用户可以边看提示边继续操作。

**只有用户主动做了什么，才给轻提示。** 用户没动手的事（后台任务、别人的操作）不要用它弹，那种消息会在用户毫无准备时闪一下就没了。

选哪种反馈，按「这条信息有多重要」来分：

| 信息重要程度 | 用什么 | 例子 |
|---|---|---|
| 知道一下就行，错过也没损失 | **轻提示**（本文） | 已保存、已复制、已发送 |
| 用户必须看到并做出选择 | 二次确认弹窗 | 确认删除这个知识库吗 |
| 需要用户对照着修 | 页面内提示条 / 表单项报错 | 名称已存在，请换一个 |
| 关键失败，丢了会出事 | 弹窗 | 导入中断，12 份文件未入库 |

**重要的失败不要用轻提示。** 它三秒就没了、也不进历史记录，用户一旦错过就再也找不回来——信息越重要，越要用挡住用户的方式说。

| ✅ 推荐 | ❌ 不推荐 |
|---|---|
| 保存成功 → 轻提示「已保存」 | 支付失败 → 轻提示「支付失败」 |
| 复制链接 → 轻提示「链接已复制」 | 表单有 3 项没填 → 轻提示「请检查表单」 |
| 删除失败 → 轻提示「删除失败，请重试」 | 导入中断 → 轻提示「12 份文件未入库」 |

## 2. 类型 Type

四种类型，靠**图标 + 浅色底**区分语义，用哪种取决于这件事的结果：

| 类型 | 什么时候用 | 图标与浅底取色 |
|---|---|---|
| **成功 Success** | 操作做成了 | 成功色 |
| **失败 Error** | 操作没做成 | 危险色 |
| **警告 Warning** | 做成了，但有副作用或有条件 | 警告色 |
| **信息 Info**（默认） | 单纯告知，没有成败之分 | 品牌色 |

- **每种类型必须带图标**，不做纯文字的轻提示——颜色分不清的用户靠图标读语义。
- 拿不准用哪种就用 **Info**。把「没成功」的事包装成 Info 会让用户以为一切正常。
- 不做「加载中」类型。异步等待期间的反馈由触发它的那个按钮自己承担（见 [组件-Button按钮.md](组件-Button按钮.md) §5.2 的 loading 态），轻提示只报最终结果。
- 色值一律取功能色 token，不写裸色值；取色规则见 [基础-色彩规范.mdx](基础-色彩规范.mdx) §3。

## 3. 位置与堆叠

- **固定在页面顶部居中，距视口顶部 16px**，随页面滚动始终停在原处。位置不可配置——位置固定，用户才知道该往哪看。
- **最多同时显示 3 条**，纵向排列、间距 8px，新的一条追加在最下方。
- **第 4 条来的时候，最上面那条（最旧的）立即消失**，给新的让位。最新的消息永远看得见。
- **同一条消息重复触发时，更新已有的那条并重新计时，不新增。** 用户连点三次保存，应该只看到一条「已保存」。
- **轻提示永远在最上层**，盖住弹窗与抽屉——在弹窗里点保存，提示必须能看见。具体层级数值随弹窗期的层级表统一定（见 [01-设计规范.md](01-设计规范.md) §5）。

## 4. 尺寸与样式

| 项 | 规格 |
|---|---|
| 高度 | 单行 40px，垂直不设内边距、文字居中；换行时改为上下各 12px 内边距，高度自适应 |
| 宽度 | 跟着内容走，最宽 480px；超出换行 |
| 水平内边距 | 16px |
| 圆角 | 12px（容器档 `xl`） |
| 投影 | `shadow-popup` 浮层投影 |
| 边框 | 无 |
| 底色 | 对应类型的功能色浅底 |
| 图标 | 16px，取对应类型的功能色主色，在文字左侧，间距 8px |
| 文字 | `text-body`（桌面 14/22），字重 400，取主文字色 |

- **文字用主文字色，不用语义色。** 语义已经由图标和浅底说清楚了；橙色、绿色的正文在浅底上对比度不够，一整句读起来费劲。
- 圆角与投影的档位含义见 [基础-圆角与阴影规范.mdx](基础-圆角与阴影规范.mdx)；轻提示是「弹出即走」的临时浮层，取浮层档，不取弹窗那档。

## 5. 内容形态

### 5.1 文案

正文遵循 [基础-文案规范.md](基础-文案规范.md)，以下是轻提示自己的细则：

- **一句话说清结果，控制在 20 字以内**，最多两行；两行还说不完，说明这事该用弹窗。
- **用动词开头说已经发生的事**：「已保存」「链接已复制」，不写「操作成功」这种等于没说的话。
- **句末不加句号**，也不加感叹号。
- **失败要说怎么办**：「上传失败，请压缩后重试」，别只甩一句「上传失败」。
- 只放纯文字，不放链接、不放富文本、不放第二行说明。

| ✅ 推荐 | ❌ 不推荐 |
|---|---|
| 已保存 | 保存成功！ |
| 链接已复制 | 复制成功。 |
| 上传失败，请压缩后重试 | 操作失败 |
| 已删除 3 个文件 | 您选择的文件已被系统成功删除 |

### 5.2 操作按钮

- **最多放一个操作按钮**，用链接按钮（Link）样式，放在文案右侧、间距 16px。
- **按钮必须是能撤回或跟进的实际动作**，比如「撤销」「查看」。**不许是「关闭」「取消」「知道了」**——那是轻提示自己会做的事，白占位置。
- **带操作按钮时停留时长翻倍**（见 §6）。按钮短到来不及点，等于没给。
- 需要两个及以上动作，改用弹窗。

### 5.3 关闭按钮

- **默认不放关闭按钮**。反正三秒就走，多一个图标只是噪音。
- **只有设为不自动关闭时才必须放**，14px 图标，贴最右侧——不会自己消失的东西，必须给用户一个出口。

## 6. 停留与关闭

- **默认停留 3 秒**，从完整出现的那一刻开始算。
- **文案超过 20 字的部分，每多一个字加 100 毫秒**，让长文案读得完。
- **带操作按钮时，上面算出的时长翻倍**，留出看见并点中它的时间。
- **最终时长钳制在 3～10 秒**。算出来超过 10 秒，说明文案太长了，回 §5.1 改文案，不是靠延长时间硬撑。
- **鼠标悬停或键盘焦点落在轻提示上时暂停计时，移开后从头重新计时**——用户正在读或正要点按钮，这时候消失最挖苦。
- **触屏没有悬停，计时照常走**，不做暂停（见 [基础-多端适配原则.md](基础-多端适配原则.md) §2）。
- **按 ESC 关闭最新的那一条。**
- 设为不自动关闭（时长为 0）只用于「必须等用户处理完」的极少数场景，且必须配关闭按钮（见 §5.3）。这种情况多半说明该用弹窗，用前先想清楚。

## 7. 动效

| 环节 | 规格 |
|---|---|
| 进场 | 从上方 8px 处滑入并淡入，200ms |
| 出场 | 向上移 8px 并淡出，160ms |
| 其余条目补位 | 200ms |
| 缓动曲线 | `cubic-bezier(0.2, 0, 0, 1)` |

轻提示比弹窗、抽屉体量小得多，动效快一档才不显得拖沓；出场比进场再快一点，让位置尽早腾出来。

## 8. 移动端适配

> 跨组件通用原则见 [基础-多端适配原则.md](基础-多端适配原则.md)，此处只写轻提示自己的细则。

| 项 | 窄屏 / 触屏规则 |
|---|---|
| 位置 | 仍在顶部，左右各留 16px，宽度自适应，最宽占满剩余宽度 |
| 文字 | 随正文 token 抬到 16/24——轻提示的字是拿来读的，不是控件上的字 |
| 堆叠 | 同桌面，最多 3 条、间距 8px |
| 悬停暂停 | 不生效，计时照常走 |
| 操作按钮 | 热区扩到 ≥44×44px，视觉尺寸不变 |
| 动效 | 与桌面一致 |

不做底部弹出的手机版轻提示：底部要和导航栏、输入框、键盘抢位置，且会引出第二套组件（见多端适配原则 §5）。

## 9. 无障碍

- 轻提示的容器**常驻在页面里**，内容变化时才播报——容器和消息一起插入，屏幕阅读器读不到。
- **成功与信息用 `role="status"`（礼貌播报）**，读完用户当前这句再念，不打断。
- **失败与警告用 `role="alert"`（打断播报）**，立刻念。仅限这两类——什么都打断等于什么都不重要。
- **出现时不抢焦点**，用户正在填的表单不能被打断。
- **操作按钮必须能用 Tab 到达**，且焦点落上去时暂停计时（见 §6）。
- 图标是装饰，加 `aria-hidden`，别让屏幕阅读器把它念成一遍多余的「成功」。

### 10.3 入参两种写法并存

`TShowToast`（`common/types.ts:226`）同时开着 `severity?: NotificationSeverity` 与 `status?: 'error' | 'success' | 'warning' | 'info'` 两个字段，`useToast` 里 `status` 优先。业务实际用量：**`status:` 字符串 72 个文件、`severity:` 枚举 45 个文件**。两边的四个语义值完全一致（info / success / warning / error），与本文 §2 的四类型对得上——收敛时只需并成一个字段，不涉及语义改动。

显式传 `duration` 的只有 3 处（5000 ×2、10000 ×1），其余全走默认 3000。

### 10.4 迁移时会踩的两个坑

- **`duration: 0` 现在的语义是「立刻隐藏」**，不是「不自动关闭」——`useToast` 直接把它塞进 `setTimeout`。落地本文 §6 要反转这个语义。已核查：当前**没有任何 `showToast` 调用传 0**（代码里的 `duration: 0` 全是 framer-motion 的动画参数），改语义不影响存量。
- **`hooks/Files/useDelayedUploadToast.ts` 里的 `showToast(...)` 整段被注释掉**，计时器空转，上传延迟提示实际不会出现。迁移时一并处置：要么接回来，要么连 hook 删掉。

实现时定下的三件事：

- **容器 portal 到 `<body>`，z-index 取 `9999`**（原私有撤销 toast 的层级），Modal 期层级表定稿后回填 §3。留在挂载点原地时，容器会跟着所在页面区块一起排版——组件站上就被 z-20 的站点顶栏压住，z-index 调到 10 万也没用（层级只在自己所处的层叠上下文里比）。§3「永远在最上层」只有 portal 到 body 才成立，业务侧同理：弹窗、抽屉里带 transform 的祖先都会埋掉它。
- **暗色底色**：功能色暂无暗色阶，浅底 + 主文字色在暗色下会白字压浅底，故暗色回退为同一个功能色 token 的 15% 透明底（仍是 token，不是裸值），待 §12 拍板。
- **进场不用 `requestAnimationFrame`**：后台标签页里 rAF 会冻结，导致提示永远停在透明态；改为读一次布局强制刷新起始态再切类。

### 11.2 落地要求（给实现窗口，已按此执行）

1. 组件形态：命令式 API（`toast.success('已保存')` / `toast.error(...)`），不做 JSX 挂载式用法——轻提示由事件触发，业务不该为它维护 state。
2. 容器单例挂在 App 根节点，常驻 DOM（呼应 §9 的 live region 要求），不随消息创建销毁。
3. 时长公式：`clamp(3000 + max(0, 字数 − 20) × 100, 3000, 10000)`，带操作按钮时先 `× 2` 再钳制。字数按 `Array.from(text).length` 计（中文按字、英文按字符）。
4. 去重口径：按 `id` 更新；业务未传 `id` 时以「类型 + 文案」哈希作为默认 id，实现 §3「同一条消息重复触发只更新不新增」。
5. 队列上限 3，超出时 `shift()` 移除最旧一条（与 §3 一致）。
6. 色值取功能色 token 的 `tint` 浅底档与主色档，禁止裸 hex；圆角取 `rounded-xl`、投影取 `shadow-popup`，禁止 Tailwind 预设投影（见圆角与阴影规范 §2.2）。
