# Feature: 报告节点优化（手动保存 + 变量显示节点名称）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
> spec 只回答 **做什么 / 验收标准 / 不做什么**；所有 How（决策、数据流、字段、API、Service、前端、文件清单）一律在 [design.md](./design.md) 与 [tasks.md](./tasks.md)。

**关联 PRD**: [3.0.0-beta1 需求文档 §报告节点优化](https://dataelem.feishu.cn/wiki/Ifj6wOgSmiyClfkMQySc7ZmvnNb)
**优先级**: P1
**所属版本**: v3.0.0-beta1
**依赖**: 无

> **范围边界**
> - **本次纳入**：
>   - 报告模板编辑器内新增「保存」按钮（插入变量按钮右侧），手动触发模板保存
>   - 插入变量时，文档内占位符携带**节点名称**（人眼可读），执行期仍按节点 ID 取数（需求口径已与用户对齐；实现选型见 design.md §3）
>   - 独立报告页（非工作流）共用同一模板/解析机制，随本特性一并生效、不回归
> - **本次明确排除**：
>   - 既有**自动保存 bug 的根因修复**——单独走 hotfix 轨道；本期手动保存是兜底能力，不以修复自动保存为前提
>   - 存量模板中旧格式占位符的**批量迁移/改写**——只做解析兼容（INV-8），不动存量文档
>   - OnlyOffice 服务端插件的改造——占位符仍以纯文本形式插入
>   - 节点改名后已插入占位符的**显示名同步刷新**——显示名是插入时快照，改名后仍按 ID 正常执行（AC-05），不追求显示名实时一致

---

## 1. 用户故事

作为 **工作流编排者**，
我希望 **能手动保存报告模板，并在模板中一眼看出每个变量来自哪个节点**，
以便 **不因自动保存失效丢失配置，且调试多变量报告时不用对着一串节点 ID 猜来源**。

---

## 2. 验收标准

> AC-ID 在本特性内唯一。

| ID | 角色 | 操作 | 预期结果 |
|----|------|------|---------|
| AC-01 | 编排者 | 在报告模板编辑器点击「保存」按钮 | 模板当前内容成功落盘；前端提示保存成功 |
| AC-02 | 编排者 | 点击「保存」但保存链路异常（如文档服务不可用） | 前端给出明确失败提示，不静默失败 |
| AC-03 | 编排者 | 通过「插入变量」选择某节点的某字段 | 文档中插入的占位符**包含该节点的名称**，人眼可直接识别来源节点 |
| AC-04 | 系统 | 执行含新格式占位符的工作流 | 按占位符中的**节点 ID** 取数并正确渲染报告（显示名不参与取数） |
| AC-05 | 系统 | 节点被改名后执行含旧显示名占位符的工作流 | 仍按节点 ID 正常取数执行；不因显示名过时而失败 |
| AC-06 | 系统 | 执行含存量旧格式 `{{nodeId.field}}` 占位符的工作流 | 解析与执行行为与升级前完全一致（INV-8 向后兼容） |
| AC-07 | 用户 | 在独立报告页（非工作流）使用模板保存与变量功能 | 行为与工作流报告节点一致，无回归 |

---

## 3. 边界情况

- 节点名称含分隔符/花括号等特殊字符时，占位符仍须无歧义可解析、执行不出错（转义/过滤策略见 design.md §5）。
- 同一工作流存在同名节点时，显示名允许重复（PRD：唯一性由编排者自行保证），执行期以 ID 区分、结果不受影响。
- 手动保存与自动保存并发触发时，不得损坏文档或丢失较新内容（策略见 design.md §5）。
