# F115：应用运行信息、审批当前可见范围与知识库创建

> **本文档定位：纯 What。** 只定义需求、验收标准与边界；实现选择、接口、数据模型及文件变更在设计阶段确定。

**优先级**：P0（权限边界与错误信息一致性）。\
**所属版本**：v3.0.0；发版线 `feat/3.0.0`。\

**关联 PRD**：[本轮已确认需求发现](./discovery.md) D1–D4（直接需求来源）；[应用工场 PRD-1](../../../docs/PRD/3.0-release/3.0%20应用工场%20PRD-1%20专业开发者通道与应用运行时.md) RT-01、RT-03、GOV-01、GOV-04（既有产品背景）。\

## 范围

**本次纳入**：

- 发布页显示当前执行体的真实健康状态、实际重启次数与启动时间，区分未知和真实零值。
- 模型调用的访问用户候选与筛选保持真实、范围一致，明确无用户记录、搜索无匹配、加载与失败状态。
- 应用发布审批只读展示当前有效的人员、部门、用户组访问授权；能确认时显示“仅负责人可见”。
- 当前有效的租户管理员可在所属租户新建文档和 QA 知识库，入口与实际创建资格一致。

**本次明确排除**：

- 不建设新的监控系统，不扩大探活体系，不为补显示而重启或重建现有应用。
- 不猜测、回填模型调用的历史访问身份，不替现有应用改码转发访问者身份。
- 不修改审批决定、版本内容或历史快照，不把可见范围变更变成发布审批事项。
- 不迁移、移交应用或知识库，不批量补授权，不更改已有角色、部门或用户组绑定。
- 不新增权限动作，不扩大普通用户、一般部门管理员或知识库复制资格。
- 不扩展源码审读、审批预览、模型调用或其它平台能力的授权。

## 1. 用户故事

1. 作为应用管理者，我希望看到当前实例实际的健康、重启和启动情况，以便判断运行是否正常，并识别信息暂不可用。
2. 作为有审计资格的管理员，我希望按真实访问用户筛选模型调用，并知道候选为空的原因，以便准确定位调用而不误判应用自身调用。
3. 作为有权阅读应用发布审批的人，我希望看到应用当前已授权的人员、部门和用户组，以便理解当前访问范围，且不把它误认为冻结的发布内容。
4. 作为首次发布的负责人或审批阅读者，我希望在确实只有负责人可见时看到明确说明，以便知道是否还需要设置可见范围。
5. 作为租户管理员，我希望无需额外创建菜单授权即可在所属租户新建文档或 QA 知识库，以便履行本租户管理职责。

### 术语

- **当前可见范围**：当前有效的普通访问授权对象，按既有 `use` 动作及身份、租户规则判定；不等同于应用此刻已经上线、可以建立运行连接。草稿、待审批或已下线本身不应清空其有效授权范围。
- **负责人**：应用当前记录的资源归属自然人；是否仍具有效访问资格应另行确认，不因名字仍在审批单上而推定有效。
- **租户管理员**：具备当前有效租户管理资格的自然人；不同于只有部门管理资格的人员。

## 2. 验收标准

### 2.1 当前执行体的运行信息（D1）

- **AC-01** — WHEN 有权查看运行状态的用户打开或刷新应用发布页，THE SYSTEM SHALL 仅以该应用当前精确绑定的执行体展示运行信息，不混入其它应用、旧实例、审批预览或维护执行体的信息。
- **AC-02** — WHEN 当前执行体已有可用的应用探活或就绪结果，THE SYSTEM SHALL 按真实结果展示健康正常或异常；Docker 未配置原生健康检查不能成为忽略已有平台应用探活结果的理由。
- **AC-03** — WHILE 当前执行体仍在启动且尚无已完成的健康判定，THE SYSTEM SHALL 表达启动中；IF 无法确认当前健康，THEN THE SYSTEM SHALL 表达未知，不以“进程运行中”或缺失结果推断健康正常。
- **AC-04** — IF 运行信息查询失败或观测依赖不可用，THEN THE SYSTEM SHALL 明确表示相关信息暂不可确认并允许刷新；仍可独立确认的信息保持可读，不把查询故障伪装成应用健康、零次重启或不存在。
- **AC-05** — WHEN 显示重启次数，THE SYSTEM SHALL 使用当前执行体中应用容器的真实重启计数，不累加应用历史发布次数、版本升级次数或被替换执行体的计数，也不混入初始化或维护容器的计数。
- **AC-06** — WHEN 可确认重启次数为零或正整数，THE SYSTEM SHALL 如实显示该值；IF 无法取得或确认计数，THEN THE SYSTEM SHALL 显示未知，不以零代替。
- **AC-07** — WHEN 可取得当前应用容器的实际启动时间，THE SYSTEM SHALL 展示该时间，不用审批时间、发布时间、Pod 创建时间或初始化容器的启动时间代替。
- **AC-08** — WHEN 展示有效启动时间，THE SYSTEM SHALL 遵循平台已有的统一时区展示口径；IF 时间缺失、无效或未实际启动，THEN THE SYSTEM SHALL 显示未知或尚未启动，不显示虚构日期。
- **AC-09** — WHEN 应用停止、执行体不存在或已被替换，THE SYSTEM SHALL 区分这些状态，且不得把已失效执行体的健康、重启或启动信息继续标为当前实例信息；刷新后应反映当前绑定。
- **AC-10** — WHERE 应用运行于 Docker 或 K8s，THE SYSTEM SHALL 对上述状态采用一致的产品含义，且读取或刷新运行信息不得触发发布、重启、重建或资产变更。

### 2.2 模型调用访问用户候选与过滤（D2）

- **AC-11** — WHEN 查询模型调用的访问用户候选，THE SYSTEM SHALL 将候选限定在调用者当前有权查询的具体租户、应用、时间及其它已选筛选条件内，与相应记录查询的范围一致。
- **AC-12** — WHEN 记录中存在经平台验证的自然人执行身份，THE SYSTEM SHALL 允许该真实身份成为访问用户候选；不得依据应用负责人、当前登录人、调用时间接近或应用标识推测访问用户。
- **AC-13** — WHEN 模型调用仅以应用自身或服务账号自身身份执行，THE SYSTEM SHALL 不把该调用者冒充为自然人访问用户；应用缺少访问者身份不等于数据查询失败。
- **AC-14** — WHEN 当前查询范围存在自然人访问记录，即使同时存在应用自身调用，THE SYSTEM SHALL 提供对应自然人候选，并允许选择和按该用户筛选；不得因混合身份记录而使整个候选列表为空。
- **AC-15** — WHEN 展示访问用户候选，THE SYSTEM SHALL 保留能够对应记录的真实身份标识；不得混入无相关调用记录的全租户人员，或用负责人等其它账号替换已不存在或不可确认的历史身份。
- **AC-16** — WHEN 选择访问用户并查询记录，THE SYSTEM SHALL 仅返回该真实身份与其它已选条件同时匹配的模型记录，不能将同一应用的其它用户或应用自身调用归给该用户。
- **AC-17** — IF 查询成功且当前范围没有自然人访问记录，THEN THE SYSTEM SHALL 明确提示当前范围没有访问用户记录，并说明应用自身调用不代表自然人访问，不仅显示无含义的空白。
- **AC-18** — IF 访问用户搜索成功但没有匹配候选，THEN THE SYSTEM SHALL 提示没有匹配用户，区别于整个范围没有自然人记录；清除搜索后可恢复当前范围的真实候选。
- **AC-19** — WHILE 候选正在加载，THE SYSTEM SHALL 表达加载状态；IF 加载失败，THEN THE SYSTEM SHALL 表达失败并允许重试，不将失败展示成“没有访问用户记录”或“没有匹配用户”。
- **AC-20** — WHEN 具体租户、应用、时间或相关查询条件改变，THE SYSTEM SHALL 使候选及筛选结果对应新范围，不保留或泄露旧范围的候选与结果；不再适用的已选身份不得导致界面悄悄查询旧范围。
- **AC-21** — WHEN 提供上述查询与提示，THE SYSTEM SHALL 保留已有可信访问者与 SDK/OBO 身份规则，不回填或改写历史记录；需要按人记录的新调用仍须带有依既有规则验证的访问者身份。

### 2.3 审批中的当前可见范围（D3）

- **AC-22** — WHEN 有合法阅读资格的用户打开或刷新应用发布审批详情，THE SYSTEM SHALL 展示查询时应用当前有效的可见范围，不继续把提交时的空占位或旧授权快照当作当前范围。
- **AC-23** — WHEN 识别当前可见范围，THE SYSTEM SHALL 以现有 F048 `use` 生效动作和既有身份、租户条件为准，涵盖直接授权及现有继承语义，包括归属人的有效所有者访问资格；草稿、待审批或已下线本身不应清空有效授权范围，也不表示应用已经可以运行访问。
- **AC-24** — WHEN 存在有效的普通访问授权对象，THE SYSTEM SHALL 按人员、部门、用户组分别展示对象名称及类型，能区分同名不同类型对象；部门和用户组不展开成全部成员。
- **AC-25** — WHEN 展示普通访问授权对象，THE SYSTEM SHALL 排除服务账号，并说明管理员仍按平台既有规则访问，不把所有因管理员身份而隐式可见的账号逐一列作普通人员授权。
- **AC-26** — IF 某对象只有其它管理动作而没有生效的 `use`，THEN THE SYSTEM SHALL 不将其认作当前访问授权对象；不能单凭“所有者”“管理者”等权限模型名称判定可见。
- **AC-27** — WHEN 授权被撤销、相关人员停用或迁离租户，或权限模型动作发生变化，THE SYSTEM SHALL 在后续打开或刷新时按现有有效资格反映变化，不把已失效对象继续表达为可以访问；部门或用户组的展示不承诺其每一名成员都已获得访问资格。
- **AC-28** — IF 当前范围查询成功且完整、负责人当前具备有效访问资格，且没有负责人以外的有效普通访问授权对象，THEN THE SYSTEM SHALL 明确显示“仅负责人可见”；此文案不否定 AC-25 所述管理员隐式访问规则。IF 完整查询确认负责人也没有有效访问资格且无其它有效普通访问授权对象，THEN THE SYSTEM SHALL 表达当前没有有效普通访问对象，而非“仅负责人可见”。
- **AC-29** — WHEN 首次发布的审批详情被打开，THE SYSTEM SHALL 依据当前有效范围决定显示“仅负责人可见”或具体授权对象；首次发布本身、历史快照为空、负责人失效或当前查询失败均不能单独作为“仅负责人可见”的依据。
- **AC-30** — WHEN 显示该区域，THE SYSTEM SHALL 明确标注“当前可见范围，授权变更即时生效，不影响审批”的含义；变更可见范围仍走既有授权流程，不创建新发布审批、不重置现有审批进度，也不要求重新提交版本。
- **AC-31** — WHEN 读取当前可见范围，THE SYSTEM SHALL 保持原审批快照和历史记录不变；代码、版本、能力声明、资源档位、发布说明及审批决定继续遵守各自原有冻结规则，不能因刷新可见范围被替换成应用最新内容。
- **AC-32** — WHERE 应用发布审批处于进行中或已经进入通过、驳回、撤回、取消等终态，THE SYSTEM SHALL 对仍具合法阅读资格的用户提供相同含义的当前可见范围；进入终态本身不新增阅读资格。
- **AC-33** — WHEN 用户具备该次审批的合法阅读资格，THE SYSTEM SHALL 允许其只读查看该审批所对应应用的当前人员、部门、用户组访问授权摘要，不额外要求长期应用 `manage_permission`；该例外只用于当前审批展示，不成为任意查询应用授权目录的资格。
- **AC-34** — WHEN 用户通过 AC-33 查看当前摘要，THE SYSTEM SHALL 不因此授予授权增删、权限模型选择、应用管理、源码审读或预览资格；审批之外的完整授权主体查询及授权变更仍须遵守 F114 的 `manage_permission` 规则，原有审批审读与预览资格另行判定。
- **AC-35** — IF 用户没有该审批的阅读资格、已失去资格，或请求违反现有租户隔离，THEN THE SYSTEM SHALL 拒绝读取当前可见范围，且不泄露授权对象信息；知道审批或应用标识不能代替资格。
- **AC-36** — IF 对应应用已删除，THEN THE SYSTEM SHALL 明确表示无法读取当前可见范围的原因，不显示“仅负责人可见”，也不恢复应用、授权或审批；其它依法可读的冻结审批内容保持可读。
- **AC-37** — IF 不能完整确认当前授权或对象资格，THEN THE SYSTEM SHALL 明确表示当前可见范围暂不可确认，并允许重新查询；不得把失败、部分结果或缺失信息当作完整名单、无人可见或“仅负责人可见”，其它依法可读的冻结审批内容仍保持可读。
- **AC-38** — WHERE 既有“我的审批”“我的申请”或审批管理详情允许阅读该应用发布审批，THE SYSTEM SHALL 保持上述当前范围含义一致；本次不新增审批管理入口或异常处理资格。

### 2.4 所属租户的知识库新建资格（D4）

- **AC-39** — WHEN 当前有效的租户管理员进入文档知识库页面，THE SYSTEM SHALL 提供新建入口，并允许其在自己所属租户创建文档知识库，不要求另有创建知识库菜单授权。
- **AC-40** — WHEN 当前有效的租户管理员进入 QA 知识库页面或提交新建，THE SYSTEM SHALL 提供与文档知识库一致的本租户新建资格，不因知识库类型不同而缺失入口或被创建菜单拒绝。
- **AC-41** — WHEN 判断是否可以新建知识库，THE SYSTEM SHALL 使页面入口与实际创建资格一致，并以服务端确认的当前身份和所属租户判定；仅修改界面、伪造管理员标记或绕过页面直接请求均不能获得额外资格。
- **AC-42** — WHEN 按上述资格创建知识库，THE SYSTEM SHALL 保持资源归属为实际创建自然人及其所属租户，不把页面管理视角、选中的其它租户或服务账号改写为创建人和资源租户。
- **AC-43** — IF 租户管理员试图在所属租户以外创建知识库，THEN THE SYSTEM SHALL 拒绝，不允许通过篡改租户信息或沿用其它租户管理页面完成创建。
- **AC-44** — IF 打开新建表单后，人员被停用、租户管理资格被撤销或所属租户变化，THEN THE SYSTEM SHALL 在实际提交时重新按当前有效资格判定；不再有创建资格或表单目标不再属于当前所属租户时拒绝，不能写入旧租户或静默改写到其它租户。
- **AC-45** — WHEN 无创建菜单且不具租户管理员或其它既有创建资格的普通用户尝试新建，THE SYSTEM SHALL 保持拒绝，不因本次修复取得创建资格。
- **AC-46** — WHEN 普通用户已有有效创建菜单授权，THE SYSTEM SHALL 保留其原有新建资格及其它既有校验，不要求该用户同时成为租户管理员。
- **AC-47** — WHEN 平台超管新建知识库，THE SYSTEM SHALL 保持其既有创建资格与归属规则，不把管理视角切换改为创建到所选租户的能力。
- **AC-48** — WHEN 用户只有一般部门管理员身份，THE SYSTEM SHALL 不因该身份获得本次新增的租户管理员创建资格；其其它合法创建途径不受影响。
- **AC-49** — WHEN 用户复制知识库，THE SYSTEM SHALL 继续要求原有创建菜单资格与源资源的读取资格；本次本租户新建例外不自动放开复制、源资源读取或其它资源动作。
- **AC-50** — WHEN 租户管理员按新增资格提交新建，THE SYSTEM SHALL 继续遵守已有模型可用性、容量、名称、租户状态等创建条件；不得通过新增角色、补写个人菜单或批量授权来改变已有账号配置。

### 2.5 共同约束

- **AC-51** — WHEN 展示本功能新增或修改的状态、提示及范围说明，THE SYSTEM SHALL 在简体中文、英文和日文中提供含义一致的文案，保留真实零值、未知、无记录、查询失败及“仅负责人可见”的区别。
- **AC-52** — WHEN 使用上述运行信息、审计查询、审批摘要或新建资格，THE SYSTEM SHALL 保持现有身份有效性、具体租户视角及资源权限边界，不迁移存量资源、改写历史记录或自动补授权；本规格的明确例外仅为 AC-33 的审批只读摘要与 AC-39、AC-40 的本租户知识库新建。

## 3. 边界情况

| 场景 | 期望的可观测结果 | 验收关联 |
| --- | --- | --- |
| Docker 没有原生健康检查，但已有平台探活事实 | 使用真实应用探活结果；没有可确认结果才表达未知 | AC-02、AC-03 |
| 进程运行但探活失败、执行体正在启动、观测依赖失败 | 分别表达异常、启动中、暂不可确认，不能统称健康 | AC-02–AC-04 |
| 重启计数为零、缺失；应用容器与初始化容器时间不同 | 零与未知不同；只显示当前应用容器事实 | AC-05–AC-08 |
| 停止、删除执行体、版本替换后刷新 | 不把旧执行体信息当作当前值；读取没有生命周期副作用 | AC-09、AC-10 |
| 历史记录只有应用自身身份，或与自然人记录混合 | 前者明确无访问用户；后者保留真实用户候选 | AC-12–AC-17 |
| 搜索无匹配、加载失败、具体租户切换 | 三者不能混为无记录；重试与新范围不泄露旧信息 | AC-18–AC-20 |
| 首发审批之后授权增加、减少，或人员迁租户/停用 | 刷新显示当前有效对象；不回写审批快照 | AC-22–AC-32 |
| 审批阅读者没有长期管理授权 | 只读当前摘要；不因此获得授权管理、源码或预览权限 | AC-33、AC-34 |
| 已无任何有效普通访问对象，且负责人也失效 | 不能显示“仅负责人可见”；完整查询可表达当前无有效普通访问对象，并与依赖失败区分 | AC-23、AC-27–AC-29、AC-37 |
| 应用删除、权限或组织信息不能完整确认 | 明确原因，不显示误导性的负责人可见或完整名单；保留合法冻结内容 | AC-35–AC-37 |
| 租管无创建菜单，或表单打开后资格变化 | 前者可在所属租户新建；后者重新校验并按当前资格拒绝不再合法的提交 | AC-39–AC-44 |
| 复制知识库、一般部门管理员、普通有/无菜单用户 | 本次不扩大复制或部门管理资格，普通用户沿原创建规则 | AC-45–AC-50 |
