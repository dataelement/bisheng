# 微调任务菜单权限与模型只读修复

日期：2026-11-19。基线：`c25b47d5337d5dc65245be127e905d0c26abbefa`。工作分支：`codex/3.1.0-beta1/workspace-bugfixes-20261118`，沿用原独立 worktree；本次未合并、推送或部署，未在 116 创建训练任务或修改业务数据。

## 用户确认的合同

| 业务 | 普通用户 | 全局超管 / 当前租户管理员 |
| --- | --- | --- |
| 微调任务列表、详情、创建、停止、重命名、删除、发布、取消发布 | 当前有效 `model` 菜单 | 保留固有权限 |
| 任务所需的服务/基础模型选项、GPU、训练数据读取、个人文件上传 | 当前有效 `model` 菜单 | 保留固有权限 |
| FT 服务列表（完整配置）、添加、删除及部署详情 | 拒绝 | 允许管理当前租户服务 |
| 通用模型目录列表 | 保留只读模型目录 | 保留现有能力 |
| 添加/编辑/删除模型、上下线、探测、系统模型设置 | 拒绝，单租户/多租户一致 | 保留原管理员校验 |
| 数据集页面创建、删除等管理 | 当前有效 `dataset` 菜单，独立于 `model` | 保留固有权限 |

微调任务发布/取消发布只处理对应训练产物，不授予 `/llm` 通用模型配置写权限。当前租户内任务按菜单统一管理，允许操作其他成员创建的任务；用户换租户后，历史创建者身份不能继续授予原租户资源权限。

## 改动与隔离边界

- `get_finetune_user` 核验当前有效 `model` 菜单，并保留已认证全局超管及 permission identity 核验的当前租户管理员能力。未修改 `get_tenant_admin_user` 的语义。
- FT 管理路由 `/server/*` 保持管理员要求。新增 `/finetune/server/options` 只返回当前租户支持微调的服务 id/name；基础模型选项仅返回 id/model/sft_support，不返回配置/服务地址。
- 新增 `/finetune/training-data` 和 `/training-data/download`，供只有模型菜单的任务用户读取当前租户训练数据。沿用训练数据列表的 `list/total` 格式；数据集管理接口仍使用 `dataset`。任务详情返回 `model_online`，移除普通用户对 FT 管理详情的调用。
- 任务相关的服务、部署模型、模型名称及训练模型标记采用严格当前租户查询；按 id 缓存服务不再作为查询来源。原生 UPDATE/DELETE 显式限定当前租户，包括任务状态、服务/模型删除以及 SFT 模型标记变更。
- 创建前检查所有个人文件必须绑定当前租户/本人，预设文件必须对应当前租户记录（传入 id 时必须匹配 URL）；完成全部验证后才签名和调用训练服务。基础模型还必须属于所选服务。跨租户对象、原租户上传、其他用户个人上传、任意对象键均不会签名或启动训练。
- 模型管理移除单租户菜单回退，普通用户仅查看目录；URL 中的 `systemModel` 参数也不能打开设置。微调页面隐藏普通用户的 FT 管理按钮且不挂载管理弹窗；切换用户/租户重建页面，退役原任务详情和表单。切换服务时清空旧基础模型并丢弃晚到的选项响应。
- 未改数据库结构、角色菜单数据或部署配置。审计报告 A01/A02 不在本次实施范围。
