# F109 共享存储每日全量对账

Status: Implemented; local verification passed; live integration pending

## 已确认范围

用户已确认简化流程并明确要求开始实施：每天北京时间 02:00，以 MySQL 规范文档为入口，每批查询、对比完成后再批量修改。不新增表、版本字段、内容清单、持久化游标或反向孤儿扫描。不提交、不部署、不运行生产对账。

- REQ-001：扫描全部 SPACE 规范文档（含 READY），按 ID 游标分批，发布/分享入口聚合为一份文档。
- REQ-002：批量读取 ES/Milvus 全部对应切片；公共属性和 knowledge_ids 以 MySQL 为准，保留正文、向量、页码和位置。缺失、重复、版本/正文异常走现有投影重建。
- REQ-003：异常隔离到文档/批次/存储端，有限重试，查询失败不能解释为缺失；MySQL 分页失败或任务锁失效时本轮未完成。
- REQ-004：每日 02:00 默认调度，Redis 租户任务锁续期、防重入、安全释放；日志报告扫描、差异、修复、重建提交、失败、跳过及完成状态。
- REQ-005：修复前锁定并复核 MySQL 快照，忙碌/已变化的文档跳过；两端独立回读，明确区分修复成功和重建提交。

## 验收

| AC | 要求 | 验证 |
|---|---|---|
| AC-001 | MySQL 游标覆盖 READY 文档；同批全部对比后修改 | Repository/服务回归 |
| AC-002 | 属性修复保留向量、支持清空、ES 逐项失败可隔离 | 存储适配器测试 |
| AC-003 | 查询失败不触发缺失重建；单篇、单端、单批失败不阻断后续 | 注入故障的服务回归 |
| AC-004 | 重建推进现有内容代次并标记 pending；原摘要保留 | Repository/loader 回归 |
| AC-005 | 02:00 注册、租约丢失停止写、正确汇总 | Worker/调度回归 |
| AC-006 | 分页不截断、修复回读、并发快照变更拒绝 | 适配器/服务测试及真实服务手工验证 |

不能证明两端同时缺失相同切片或向量语义正确；原文件不存在时重建失败由既有投影重试和日志体现。
