# 知识库任务精简：需求说明

## 阅读摘要

按四个独立批次精简知识库任务：推荐池准备与重建合并、删除标题旧任务入口、统一热搜重建入口、统一推荐投影批量处理。优先减少实际投递，其次减少重复入口。保留租户隔离、版本控制、失败恢复和原有业务结果。

用户已授权实施，四项代码和本地回归已完成。真实服务联调与生产切换尚未执行，不包含部署或清队列。

## 范围 Scope

### 包含 Includes

1. 推荐池：取消准备任务向重建任务的正常二次投递。
2. 标题：删除旧 Celery 入口，保留首次解析内的标题提取和别名生成。
3. 热搜：手动和定时触发使用同一个租户重建任务。
4. 推荐投影：单条与批量统一到有界批量任务，保留每个事件的版本语义。
5. 必要的生产者、任务注册、配置模板、响应任务名及定向测试同步调整。

### 不包含 Excludes

- 用户推荐缓存失效接口统一，留作后续低优先级事项。
- 自动发布、PDF、全文 Outbox、文档投影、统计、对账和迁移任务合并。
- 推荐算法、排序、权限规则、全文内容、数据库 Schema、依赖和队列名称变更。
- 跨解析任务的 Redis 聚合调度器、全局消息去重平台或新队列。
- 已完成的相似候选计算内联改动；实施时保留该工作区状态。
- 生产清队列、部署、历史消息迁移和回滚执行。

## 需求与验收 Requirements

### REQ-001：推荐池单次交付完成准备与重建

- AC-001：正常租户重建从触发到完成只发布一个租户工作任务；任务内部不再发布另一个重建任务。跨租户分发和失败重试消息不计入该正常路径。
- AC-002：同一请求失败重试复用 generation、config_version、fingerprint；较旧请求不能覆盖较新请求的推荐池。准备状态不可确认时失败退出，不绕过版本校验继续激活。
- AC-003：配置缺失、配置版本改变、指纹改变、池不完整时沿用已有跳过/拒绝激活行为；保留最多三次重建重试及显式租户上下文。

### REQ-002：移除标题兼容任务，保留标题业务

- AC-004：运行代码、任务注册、路由白名单、部署模板不再声明或投递 extract_knowledge_file_title_celery；历史文档中的说明不要求删改。
- AC-005：首次解析依次执行标题处理和正式解析，标题失败仍继续解析；重试解析不额外执行标题处理；解析交付跟踪与优先级语义保持。

### REQ-003：统一租户热搜重建入口

- AC-006：管理接口和租户分发投递同一个热搜重建任务，携带正确租户和触发来源；接口返回 task_name 与实际投递一致，返回结构与授权检查不变。
- AC-007：同一租户仍使用已有互斥锁；定时任务保留三次自动重试及原执行限制，手动任务保留当前无自动重试行为；跨租户分发独立保留。

### REQ-004：有界批量刷新推荐投影

- AC-008：单文件及文件列表操作均投递统一任务；空批不投递；每批最多 100 个事件，不改变原来的租户归属。
- AC-009：普通更新仍可从源记录推导版本；显式刷新/删除保留事件版本。重试、延迟消息和乱序消息不能通过本次改造绕开仓储已有版本保护。
- AC-010：同一业务调用内去掉完全相同事件，并按文件保留必要事件顺序；不凭当前时间或列表顺序猜测不同类型事件的新旧关系。批量删除/更新继续批量处理，独立文件解析仍立即投递单元素批次。
- AC-011：批次内失败回滚该批事务并按现有五次退避重试；已提交的其他批次不回滚；资源级分页刷新与定期增量/全量校准保留。

### REQ-005：有证据的切换与范围保护

- AC-012：修改范围可逐批审查；任务注册和模板检查能发现悬空任务名；不修改无关工作区内容。
- AC-013：交付文档明确停止旧生产者、处理旧消息、更新 Worker 与生产者以及回滚顺序；代码完成不等于生产切换完成，禁止自动清空共享队列。

## 澄清记录 Clarifications

- 用户要求的是规划，不是本轮实施。
- 后续用户明确要求“开始实施”，授权执行 T001–T004；生产发布与队列操作仍不在范围内。
- 按上一轮最终推荐的四项作为本期范围；第五项用户缓存失效接口统一不纳入。
- 用户此前表示不需要保留相似候选旧任务入口。本计划提出其他冗余入口也在切换后删除，不将该意见视为清理生产队列或丢弃其他历史消息的授权。

## 收益与风险

- 推荐池：正常每租户每次重建少一次 Celery 投递，不承诺减少推荐算法计算量。
- 标题与热搜：主要减少注册入口和维护分叉，不虚报节省正常任务数。
- 推荐投影：当前批量删除和部分批量更新已经合批；本次收益是入口统一、有界处理、调用内去重。拆分超大批次可能增加消息数，但降低单任务占用和重试范围。
- 删除任务名与更改消息参数不兼容旧消息，不能让新旧生产者任意混跑。
- 推荐池 generation 初始化、重投递、并发激活为最高风险边界，必须先验证后切换。
