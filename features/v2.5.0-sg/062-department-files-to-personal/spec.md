## 1. 目标与边界

新增独立运维脚本，扫描部门知识库根目录下指定名称的目录，递归收集文件，按每个文件的 `user_id` 迁移至该用户的默认个人知识库。目标不存在时调用系统现有创建入口；保留指定目录本身和内部层级。

示例：`部门库/待整理/制度/a.pdf → 张三的知识库/待整理/制度/a.pdf`。

包含：预览、来源筛选、上传人路由、按需创建个人库和目录、普通文件和完整版本链迁移、目标校验、失败补偿、结果报告和操作记录。

不包含：真实业务环境执行、自动调度、公共/班组/科室/个人来源库、来源空目录清理、首次上传人回填、重新解析、在线 API 或页面调整、数据库迁移、依赖及配置变更。

已确认的安全边界：只迁移成功状态且关系完整的文件；向量模型不一致、外部逻辑引用或审批锁定等无法安全复用既有迁移能力的单元跳过并说明原因，不隐式扩大迁移范围。

## 3. 代码事实与复用边界

- `src/backend/scripts/move_knowledge_space_files.py` 的 `build_explicit_target_context()` 只允许公共或部门目标；分类预检还依赖门户分类，因此不能直接调用原脚本的 CLI 或整套预检。
- 同文件中的 `BishengMoveOperations`、`move_one_file()`、`move_version_chain()`、`DatabaseVersionGraphStore`、`TargetFolderManager` 和 `RollbackJournal` 已包含迁移基础能力。按实际接口复用，不复制整份脚本，不通过修改全局变量或伪造分类绕过预检。
- `KnowledgeSpaceService.ensure_personal_default_space_for_owner()` 支持为指定用户创建默认个人库，无需模拟登录；调用期间临时切换服务用户并在 finally 恢复。按用户串行调用，避免共享身份并发污染。
- `KnowledgeSpaceService._find_personal_default_space()` 按用户 ID 与默认库名查找；预览只复用只读查询语义，不调用 ensure 方法。
- `KnowledgeFile.reference_document_id` 和 `KnowledgeDocument.predecessor_logic_file_id` 表示新发布/分享关系。参考迁移脚本的来源删除路径直接处理物理文件，不能推定其兼容这些关系。

## 4. 实现设计

### 4.1 参数与扫描

提供 `--folder-name`（必填、单个目录名）、`--tenant-id`（多租户开启时必填）、`--report-dir` 和 `--apply`。默认只生成预览；apply 按已确认的同名覆盖规则执行，无需额外覆盖选项。

通过严格租户上下文扫描部门 scope，按空间 ID、文件 ID 稳定排序。目录名称精确匹配，不依赖门户分类标签；目录后代依据 ID 路径边界判定，避免把 `/12` 与 `/123` 混淆。扫描包含成功和非成功文件，后者进入跳过报告，不静默遗漏。

读取用户、默认个人库、目标目录和文件快照；按单文件或完整版本链形成候选。所有被选文档的关联关系必须完整读取，不能仅凭选中文件没有 `reference_document_id` 判断无外部引用。

### 4.2 预览与资源创建

预览使用“目标用户 ID + 默认库名称 + 相对路径”的描述，不使用虚构数据库 ID，也不提前创建知识库。缺失个人库时报告“执行时创建”，其模型兼容性等依赖实际创建结果的检查明确标为执行前待确认。

apply 在操作记录成功创建并落盘后，重新检查候选，按上传人调用现有个人库创建服务，校验返回空间的租户、类型、所有者、模型和权限。仅在一个用户存在可迁移候选时触发创建。新建空个人库在后续迁移失败时保留并记录，不自动删除用户资源。

目录从个人库根逐层映射，创建来源指定目录及实际文件所需的下级目录。不复制空目录，也不清理来源空目录。目标冲突按同目录同名判断；参考脚本额外的全库 MD5 去重规则不自动引入本功能。

### 4.3 迁移与失败处理

先检查成功状态、版本图、用户一致性、关系边界、模型兼容性、目录深度和目标冲突，再准备实际 `TargetContext`。迁移底座只接收已经验证且存在真实目标 ID 的单元。

执行顺序：准备必要目标资源并记录 → 记录来源快照 → 复制并验证 → 重校验并记录旧目标 → 删除同名旧目标及完整版本链 → 删除来源 → 验证规定范围内的来源清理及目标状态 → 记录单元完成。

标签和对象沿用既有迁移能力；权限只写目标 owner/parent 必要关系并验证。新个人库创建继续由现有 Service 和 PermissionService 承担，不手工插表或操作底层 OpenFGA 客户端。

失败时复用既有来源恢复、目标清理和版本图补偿能力，明确记录补偿结果，不将“调用补偿”视为“恢复成功”。一旦开始覆盖旧目标，任何后续失败均保留新副本；旧目标删除失败立即停止，不继续删除当前来源。旧目标内容永久删除，普通来源补偿无法恢复。只清理本次创建且确认仍为空的目录，不删除预先存在的目录。失败后停止剩余单元。

操作记录覆盖来源/目标文件 ID、文档版本 ID、用户 ID、目录映射、创建资源、执行状态和错误。报告不含凭据。操作记录是排查和恢复依据，不承诺提供覆盖所有跨存储故障的一键回滚工具。

## 6. 风险与暂停点

- apply 改变文件位置、文件 ID 和权限归属，旧文件 ID 关联可能失效；涉及外部逻辑引用的文档按 AC-10 跳过，其他历史链接沿用参考脚本限制，不额外迁移。
- 数据库、对象存储、搜索及权限系统没有全局事务，断电/进程强杀可能留下部分完成状态；操作记录与逐单元补偿降低影响，但不是完整数据库备份。
- 同名覆盖会永久删除旧目标文档及完整版本链，包括本批次已迁入的内容；JSONL 只能追溯步骤与清理残留，无法恢复已删除的旧对象。用户已明确确认该行为。
- 执行时需避免并行迁移或用户同时修改同一范围；本脚本不新增全局锁或停写系统。逐单元重校验不能宣称完全消除并发竞争。
- 用户已确认规格并授权实现；脚本、测试和说明已交付。真实环境 apply 不在本次授权范围内，未执行。
