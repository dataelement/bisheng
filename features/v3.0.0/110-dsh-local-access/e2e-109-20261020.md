## 独立发现：火山模型响应迟缓

正式镜像复测模型 7 时，非流式调用实际完成约 104.7 秒，超过测试客户端 90 秒读取时限；模型 7 的自动化复测为 6 passed / 1 failed（ReadTimeout）。同一客户端流式请求约 60 秒无响应而取消，审计保留 CANCELLED / INTERRUPTED，计量为 USAGE_UNKNOWN，没有人工补写成功或重置额度。

从 Backend 容器直接请求供应商，绕过 DSH 路径：火山在 15.17 秒触发 ReadTimeout；百炼 qwen-max 在 0.54 秒返回 HTTP 200 和合成标记。因此当前证据指向模型 7 对应供应商的响应迟缓，而非 Gateway 或原生会话校验。未更改该模型配置，也未自动切换或伪造返回。

同一正式镜像、同一套额度 / 审计测试改用已配置的模型 2 后，7 项全部通过；原客户端无需重新登录即可完成百炼调用。火山模型是否恢复不在本次通过结论内。

客户端在该超时场景显示 `Enterprise login is not available yet.` / `UNKNOWN`，文案未准确反映供应商响应迟缓，已作为后续问题保留。原生会话未失效，有同 session_id 的后续百炼成功请求作为证据。
