# 知识空间问答跳转新对话后页面崩溃

## 现场与根因

2026-10-30，Chrome 当前页面为 `192.168.106.120:3002/workspace/c/new`，从知识空间提问后出现前端错误页。现场版本 `v3.0.0 (20261030-1041)`，错误码 `7YDW-QC6G`；下载诊断日志的追踪 ID 为 `36a14358f2de4110`，同一次调查初始截图追踪 ID 为 `269f8b4e2fc04938`。

诊断日志为 React error #185。对应公开业务脚本 `workspace/assets/main.wUYH7M14.js:2:767801`，定位到模型选择回调写入现有 Recoil chatModel；堆栈中的 replaceState 是共享状态库更新，并非浏览器跳转。真实 RecoilRoot + 原 chatModel + 原模型解析与会话知识选择组合测试复现 `Maximum update depth exceeded`，在模型写入处失败，修复前原有 14 项手工 useState 夹具测试仍通过。

问题接收逻辑先更新知识选择、模型，再把 React 局部状态标记为准备完成。共享模型库会同步通知订阅者，导致准备状态尚未提交就重入同一个 effect，反复选择模型而崩溃。

## 修复

在改变知识选择和模型之前，用 ref 标记该问题正在准备，防止同步重入重复执行。原 preparedAsk 状态仍用于等待选择更新后的渲染，确保选择相同时也能继续提交；不回退为仅 ref 的旧实现。每个新问题重置准备标记，沿用现有提交防重、模型不可用退回编辑和附件等待流程。

没有新增 Recoil atom、生产导入、跨页状态或 API。新增测试直接使用已有共享模型对象和真实 Recoil 实现。两个知识问答输入测试原先按旧 button/title 定位模型选择器，与已落地 combobox 不符；测试选择器改为当前可访问角色和完整展示文本，保留选模、携带模型 ID、清理空白和新建对话行为断言。未改选择器产品实现。
