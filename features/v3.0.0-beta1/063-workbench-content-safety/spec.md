# Feature: 日常模式与任务模式内容安全审查（F063）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
> spec 只回答 **做什么 / 验收标准 / 不做什么**；所有 How 在 [design.md](./design.md)。

**关联 PRD**: 《3.0 beta2》§5.2 日常模式和任务模式安全内容审查
**优先级**: P1
**所属版本**: v3.0.0-beta1
**依赖**: 既有 `sensitive_word` 租户词表（知识空间 / 频道已用）· 工作台首页配置页 · 日常/任务统一入口 `POST /api/v1/workstation/chat/completions` · 商业版开关 `BISHENG_PRO` / `appConfig.isPro`

> **范围边界**
> - **本次纳入**：
>   - 商业版工作台首页增加内容安全审查配置（内置词表 / 自定义词表 / 自动回复）。
>   - 日常模式：审查用户输入文本，以及模型返回给用户的**最终回答**（流式每满 100 字审查一次，结束时再审剩余）。
>   - 任务模式：只审查用户输入文本；命中则不创建任务。
>   - 命中后用配置的固定自动回复替换本次回答，不调用或立即停止大模型。
> - **本次明确排除**：
>   - 用户上传的文件、文件解析结果、ASR 转写以外的附件字节 —— PRD 写明本期不审。
>   - 日常模式的思考过程、工具调用参数/结果、角标/引用块 —— 只审最终回答正文。
>   - 任务模式的模型输出、中间步骤、交付物。
>   - 知识空间问答、频道订阅问答、工作流 / 助手（工作流已走 Gateway 审查，本期不改）。
>   - 开源版交付该能力（PRD：开源版无该功能）。
>   - 模型审查（只做关键词匹配，与工作流现状一致）。
>   - 独立审计表 / 应用日志「是否命中」列（工作流 Gateway 的 `gt_block_record` 不在本期搬到工作台）。
>   - 按部门 / 按会话覆盖词表（沿用租户一份策略）。

## 1. 用户故事

作为 **有合规准入要求的项目管理员**，
我希望 **在工作台首页打开内容安全审查，用敏感词表管日常对话和任务提交**，
以便 **日常模式、任务模式与工作流一样能过项目准入，而不只是工作流有审查**。

作为 **工作台用户**，
我希望 **输入或回答命中审查时立刻看到固定提示，而不是模型继续生成违规内容**，
以便 **知道这次不能继续，而不是对着半截回答或一个失败任务发愣**。

作为 **开源版部署的管理员**，
我希望 **首页上看不到这项配置、运行时也不审查**，
以便 **商业版能力不会出现在开源交付里**。

## 2. 验收标准

> AC-ID 在本特性内唯一。字段名 / 存储键 / 函数名等实现细节见 design.md。

### 2.1 配置

- **AC-01** — WHERE 商业版（`isPro`）且当前用户可管理本租户工作台配置, THE SYSTEM SHALL 在管理后台「构建 → 工作台 → 首页」最下方展示「内容安全审查」折叠面板；说明文案为「通过敏感词表对会话内容进行安全审查」。
- **AC-02** — WHERE 开源版, THE SYSTEM SHALL 不展示该面板，且日常/任务请求不执行内容安全审查。
- **AC-03** — THE SYSTEM SHALL 允许选择「内置词表」和/或「自定义词表」（可多选）；自定义词表支持文本框手输（每行一个）以及上传 `.txt`（按换行、逗号、空格拆分后展示到文本框）。
- **AC-04** — THE SYSTEM SHALL 提供自动回复输入框，占位示例为「当前对话内容违反相关规范，请修改后重新输入」，上限 500 字。
- **AC-05** — WHEN 开启审查并保存, THE SYSTEM SHALL 校验：至少选择一个词表、自动回复非空、自动回复不超过 500 字；失败时分别提示「请至少选择一个敏感词表」「自动回复内容不能为空」「自动回复内容不能超过500字」，且不写入。
- **AC-06** — WHEN 关闭审查并保存, THE SYSTEM SHALL 保留已填词表与自动回复；再次开启后仍是关闭前的内容。
- **AC-07** — THE SYSTEM SHALL 用同一份租户策略同时约束日常模式与任务模式；不提供两套入口、两套词表。

### 2.2 日常模式

- **AC-08** — WHEN 审查已开启且用户发送的**文本**命中词表, THE SYSTEM SHALL 不调用大模型，在本轮助手气泡中展示自动回复，并结束本轮。
- **AC-09** — WHEN 审查已开启且模型**最终回答**正文命中词表, THE SYSTEM SHALL 停止继续流式输出，把当前助手回答整段替换为自动回复（思考/工具卡片不作为最终回答送审）。
- **AC-10** — WHILE 日常模式正在流式输出最终回答, THE SYSTEM SHALL 每累积满 100 字审查一次已输出的最终回答全文；流式结束时对不足 100 字的余量再审查一次。
- **AC-11** — WHEN 用户只上传文件、输入框文本未命中（含空文本）, THE SYSTEM SHALL 不因文件名或文件内容拦截本轮（本期不审文件）。

### 2.3 任务模式

- **AC-12** — WHEN 审查已开启且用户提交任务的**文本**命中词表, THE SYSTEM SHALL 不创建任务、不发出任务交接事件，在本轮助手气泡中展示自动回复，并结束本次请求。
- **AC-13** — WHEN 任务已创建并开始执行, THE SYSTEM SHALL 不审查任务过程输出与交付物。

### 2.4 商业版与工作流对齐

- **AC-14** — THE SYSTEM SHALL 只使用关键词匹配（内置词表 ∪ 自定义词表），匹配逻辑与现有工作流/知识空间敏感词审查同一套词表引擎，不做模型审查。
- **AC-15** — THE SYSTEM SHALL 把命中后的自动回复作为普通助手消息落库；刷新会话后仍能看到该轮用户输入与自动回复，而不是空白或半截模型输出。

## 3. 边界情况

- 开关关闭：不审查，行为与今天完全一致。
- 开着但词表实际为空（绕过前端直接写库）：视为未生效，不审查。
- 敏感词跨「每 100 字」边界：按**已累积的最终回答全文**匹配，不得只拿最近 100 字窗口（否则会漏掉跨窗口的词）。
- 用户输入命中：本轮仍要留下用户气泡（前端已乐观插入），助手侧只出现自动回复。
- 任务模式命中：不得出现任务卡片、排队或 `start-execute`。
- 统一入口与遗留 `POST /api/v1/linsight/workbench/submit` 两条提交任务的路都要拦。
- 分享链接打开的会话：审查仍按该会话所属租户的策略执行（内容安全不是权限过滤）。
- 语音输入转成的 `text`：视为用户输入文本，要审；原始音频文件不审。
