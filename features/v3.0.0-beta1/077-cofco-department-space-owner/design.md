# F077 实现设计

**范围**：仅中粮部门知识空间；普通资源创建者保护不变，无数据库结构或权限模型迁移。

## 负责人及交接

`department_knowledge_space.admin_user_id` 继续作为唯一配置负责人。部门业务适配器确认空间绑定和企业一致，并校验负责人具有当前企业有效成员关系，之后才调用专用权限业务口。该口不提供 HTTP 接口。

负责人使用既有 `owner` 模型，授权来源为受保护的 `SPACE_MEMBERSHIP`，来源引用为 `{space_id}:admin:{user_id}`。校准时只撤销本部门空间历史受保护的创建者来源和负责人来源，再以当前配置负责人为准补齐所有者。独立直接授权、组织继承和其他所有者来源保留。普通授权增删入口仍禁止修改受保护来源；实际创建人的业务审计字段不改写。

沿用 F048 变更台账、SQL 准备、权限投影、完成及可见性更新链路，不直接写 OpenFGA。部门负责人流程保留旧 ADMIN 成员行以兼容成员列表和审批人解析；该身份的实际权限通过受保护 owner 来源提供，旧成员 manager 投影清除。

原先已有成员行时记录原角色，包括原本就是管理员的情况。交接后恢复原角色及成员授权；仅因负责人身份新增的行在退出后删除。独立授权不受影响。

## 并发和失败恢复

在投影及成员恢复期间，对同一部门绑定持有 SQL 行锁；配置变更的条件更新必须等待该锁。提升前确认用户仍是负责人，退出前确认用户已不是负责人，避免并发请求把权限落给过期负责人。按空间串行，不改变知识列表和用户检索路径。

投影失败向调用方报错，业务配置和外部权限之间不能跨系统原子提交。恢复成功前保留旧成员角色记录；重复保存同一负责人及既有六小时校准任务会清理未完成的旧负责人角色。待配置空间校准时撤销遗留的负责人 owner，不自动指定其他人。审批人仍使用既有刷新机制。

## 页面与升级

权限设置展示服务端真实的所有者模型，不再把负责人伪装成创建者，也不在投影缺失时补一个虚拟身份。保护标记和权限模型保持服务端结果。

存量升级使用既有周期校准任务，或由管理员重复保存当前负责人触发立即校准；没有新增手工数据脚本、DDL 或权限模型迁移。升级后必须核对负责人、旧成员权限和审批人，见验收清单。本次开发没有访问或修改 105 数据。
