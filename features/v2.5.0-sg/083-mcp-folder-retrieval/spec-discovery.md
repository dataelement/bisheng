## 3. 建议的工具契约

新增 `retrieve_folder_chunks`，只读，不生成模型答案。保留已有十个工具，新增后共十一个。

| 参数 | 建议契约 |
|---|---|
| `external_id` | 必填，复用现有严格账号字符串及目标用户/当前租户解析 |
| `query` | 必填，去除首尾空白后 1～2000 字符 |
| `knowledge_id` | 必填，严格正整数，限定一个知识空间 |
| `folder_id` | 必填，复用正整数或 ASCII 正数字符串兼容规则；规范化后再做归属与权限校验 |
| `recursive` | 严格布尔，默认 `true`；`false` 仅检索目录直接包含的文件 |
| `top_k` | 默认 `5`，范围 1～50，沿用现有检索语义 |
| `max_content` | 默认 `15000`，范围 1～15000，沿用现有字符预算语义 |
| `filters` | 可选，复用现有标签过滤结构；只允许引用本次 `knowledge_id`，与文件夹范围取交集 |

返回沿用 `{chunks, total}` 和既有片段字段。`document_id` 为指定空间内且属于所选文件夹范围的授权文件入口；`total` 为本次返回的片段数。

```json
{
  "name": "retrieve_folder_chunks",
  "arguments": {
    "external_id": "00012345",
    "query": "设备检修前需要完成哪些检查？",
    "knowledge_id": 118,
    "folder_id": "305",
    "recursive": true,
    "top_k": 5,
    "max_content": 15000
  }
}
```

## 4. 业务边界与失败行为

1. Token 继续校验接入资格；业务权限来自 `external_id` 解析的目标用户及其当前租户，不回退 Token 用户，不新增身份或租户选择规则。
2. 必须先校验空间和指定文件夹可读，再解析目录内文件范围。跨空间目录、跨目标租户目录、不存在、已删除、非目录或无目录权限均拒绝，不转为整库检索。
3. `folder_id` 不能省略、传 `null` 或 `0`；整空间检索继续使用原 `retrieve_chunks`。`"000305"` 与 `305` 表示同一目录，布尔、空白、带符号或小数的 ID 均拒绝。
4. 目录可读不代表所有后代文件可读；逐文件沿用现有授权与活跃入口规则。无权文件不返回正文、名称、入口 ID 或来源链接；权限检查异常必须返回错误，不能伪装为空结果。
5. 文件夹约束必须在召回前进入共享检索范围解析，禁止整库取 Top-K 后才按路径过滤；返回入口仍须属于所选目录范围，不能因 canonical 去重映射到目录外的同文档入口。
6. 合法空目录、无可检索文件、标签交集为空或无匹配内容时，成功返回 `chunks=[]、total=0`；空文件集合绝不能被当作未设置过滤条件。
7. 不漏扫目录后续批次。完整范围无法在资源预算内安全处理时明确失败，不返回无提示的部分目录结果，不放大为整库检索。批量与容量边界在完整设计中落实。
8. 默认递归包含任意深度子目录；路径匹配保留 `/` 分隔边界，不能将目录 `3050` 误算为 `305` 的子目录。
9. 沿用共享存储、当前主版本和内容/入口代次校验及来源链接语义；不返回历史版本或失效投影，不在共享检索失败时回退旧索引。
10. 只读：不创建目录/个人库、不修正文件状态、不写业务数据、不变更权限和 Token 规则。

## 5. 包含与排除范围

包含：新工具 schema/注册、文件夹范围解析、共享检索内部范围透传、相关回归与受控 SDK 集成验证，以及 `docs/api/mcp-usage.md` 更新。

不包含：多目录或跨空间联合检索、按路径名称自动找目录、修改原 `retrieve_chunks` 对外参数、扩展 REST 检索对外参数、新增检索引擎或索引字段、数据库迁移、真实权限变更、提交/合并/推送或部署。

不改变现有领域对象 Owner；目录/文件事实与权限仍由 knowledge 领域提供，不新增领域对象或写入关系。

## 7. 风险与下一阶段

- 本次新增只读公开工具，主要风险为目录范围失效造成越界检索，以及大目录文件范围展开的延迟和参数体积。通过召回前限域、空集短路、授权回映射约束和明确失败处理控制。
- 旧客户端参数保持兼容；使用新工具需要刷新 MCP 工具清单。无需数据迁移，回退新增工具和内部适配代码即可撤回能力。
