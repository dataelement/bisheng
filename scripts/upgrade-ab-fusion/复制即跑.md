## 12. 融合准备 (B 必须已是 2.5.0-sg; 默认不写 A)

在 **B** 上跑. 本地 mysql 是 B, A 走 SSH. `A_SSH_HOST` / `A_SSH_USER` / `A_SSH_PORT` **必填**, 脚本不再默认演练 IP.

本轮演练先密码登录 A (不种密钥):

```bash
cd /data/bisheng/scripts/upgrade-ab-fusion
cp -n env.sh.example env.sh
# 编辑 env.sh, 本轮演练填:
#   A_SSH_USER=Oper1
#   A_SSH_HOST=10.171.0.50
#   A_SSH_PORT=52012
#   A_SSH_AUTH=password
# 生产改成现场地址; 有密钥后可 A_SSH_AUTH=auto 并设 A_SSH_KEY.
export SSHPASS='...'   # 不要写入仓库
# 已有 env.sh 则 load_env 会自动 source
APPLY=0 bash p4/00-install-control.sh
APPLY=0 bash p5/00-protect-a-baseline.sh
# APPLY=1 bash p4/00-install-control.sh
# APPLY=1 bash p5/00-protect-a-baseline.sh
# 00-protect APPLY=1 会在 A 记下 fusion_a_baseline, 并写出
# logs/p5/a-space-meta.tsv / a-space-file-ids.tsv / a-pre-chat-ids.tsv, 迁后 40-verify 对照.
```

开跑会打印 `连接 A: user@host:port auth=...`. 对不上就停. 密码登录需要 B 上有 `sshpass` (缺则脚本尝试安装).


`create` 用户拷贝 B 的 `password` 哈希, 可用 B 原密码登录 A; `bind` 不改 A 密码. B 不要开组织同步; A 继续作为唯一同步端.
B 独有模型/自定义工具: 先在 A 配好 (密钥手填), 填回 `p4/model-map.csv` / `tool-map.csv`.
自定义工具 **尽量沿用 B 的 tool_key** (A 不冲突); 冲突则另写 `p4/tool-key-map.csv` (`b_key,a_key`).
工作流 JSON 里用到的模型不在 map 里时, `p5/30-apply.sh` 生成 SQL 会失败. `gaps-model-tool.tsv` 里被工作流引用的项必须先消掉.
