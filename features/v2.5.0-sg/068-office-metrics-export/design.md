## 检索结论与现有边界
- `scripts/export_portal_category_usage.py` 已有组织子树、当前主组织上传人、有效库存及文档身份处理；只复用纯函数/查询惯例，不改变旧报表。
- `knowledge/domain/document_identity.py` 提供 `document:<id>` / `file:<id>` 稳定身份；不做文件名或 MD5 模糊合并。
- `KnowledgeSpaceScope` 明确区分 `public/department/team_ks/team/personal`，分别映射五类库。
- `KnowledgeFileDao.active_inventory_predicate()` 排除删除、历史版本和无效引用；另加文件类型、成功状态、空间状态和收藏排除。
- `scripts/export_user_daily_activity.py` 当前按有效操作统计，不能复用其日活计算当作登录次数。
- 成功登录路径写 `base_telemetry_events.user_login`，另维护 `mid_user_engagement_stat` 的 participation 日统计；后者的组织可能是事件时组织。
- 三类问题投影在 `mid_realtime_qa_question_fact`；专家原始问题是数据库 `Question`，AI 原始成功事件是 `base_telemetry_events.portal_qa`。
- 现有投影构造可能创建索引；脚本直接取得 ES 连接、只读查询，不实例化有 ensure 副作用的投影类。
- 当前工作区另有缓存、知识服务、同步审计及测试改动，本功能不编辑这些文件。

## 数据来源与取舍
| 指标/维度 | 主来源 | 校验来源及处理 |
|---|---|---|
| 组织及当前归属 | Department、UserDepartment、用户/租户关系 | 校验组织路径、主关系唯一、租户和子树；不采用 ES 缓存组织作为当前归属 |
| 五类知识库存 | Knowledge、KnowledgeFile、KnowledgeDocumentVersion、KnowledgeSpaceScope | 精确有效库存和文档关联；文件入口明细保留上传人及去重身份 |
| 成功登录 | base_telemetry_events 中 user_login 原始事件 | 按用户/日与 participation 的 login_count 核对，不把两种来源相加或取最大冒充事件合并；不一致单列并阻止受影响指标被标记为已核验 |
| 智能/文档问答 | base_telemetry_events 中成功 portal_qa 事件 | 与实时问题事实按租户、类型、问题 ID 对齐；无稳定问题 ID 的旧事件单列异常，不擅自当成新问题 |
| 专家问答 | Question 数据库记录 | 以问题 ID 去重，与实时 expert 事实核对；不按回答行数计数 |

原始记录为主可以绕过投影延迟，不丢弃原始新增记录。若派生数据证明存在原始记录未覆盖的历史，报告来源差异，不自动拼接无事件身份的计数。目标环境若存在额外登录来源，先校验成功语义和稳定关联键；本设计不授权猜测合并或线上回填。

## 流程与接口
1. 参数要求 `--tenant-id`、`--company-department-id`、`--manufacturing-department-id`、`--output-dir`；可选 `--office-map`、`--verbose`。不设业务起止日期参数。
2. 校验公司/制造部同租户且存在祖先关系。固定十行通过制造部子树内唯一精确名称定位；括号/空白只做明确规范化。重名或无匹配时要求映射文件指定 ID，不模糊猜测。
   依据用户 2026-09-30 确认，以当前 `parent_id` 关系迭代构建路径并缓存；不依赖旧 `path` 前缀。输入组织记录复制后仅在内存处理，原路径差异逐条写入诊断；父链环路和租户内父节点缺失拒绝统计。
3. DB 在同一只读事务中读取组织、当前主关系和库存，结束时 rollback；实际一致性取决于已有数据库隔离级别，不更改运行配置。不额外按在职状态抹除具有当前主组织的历史行为用户。
4. ES 使用 PIT 与完整分页，记录扫描开始/结束和实际事件时间范围；SQL 与 ES 不宣称同一全局事务快照。查询拒绝部分结果，重复游标、身份冲突和缺少必需字段要报错。
5. 流式写明细，聚合仅保留必要身份集合与计数。SQL 使用分批和可移植 ORM，避免逐科室重复扫库、超大 IN 和截断 TopN。
6. 集中计算所有分子、分母，导出后读回核对。只在必需数据和分页校验通过后生成正式主表；异常诊断可先落盘。

## 聚合规则
- 库类型列按 `(组织范围, space_level, document_identity)` 集合计数；总贡献对五类集合取并集。部门、公司按各自成员范围重新求并集。
- 五类库存按人员贡献归属，即使文件位于其他部门空间也不因空间所有者而改写上传人归属。
- 明确属于其他公司的行为不进入本公司明细或来源差异核对。制造部部门库中的外部人员贡献仍进入库分母和知识核对明细。归属未知保留诊断。
- 缺少租户成员关系但有当前主组织的用户仍按主组织统计并提示，不将旧关系缺失误判为没有贡献。
- 科室贡献比独立限定制造部部门库：`level=department` 且空间组织所有者为制造部；多个符合条件空间取并集。库所有者不同于上传人组织，二者不可混用。
- 相同文档被不同入口上传人归入多个科室时，保留各科室贡献集合，部门/公司总量仍全局去重，另列归属冲突诊断；不承诺各科室贡献数可相加。
- 智能和文档问答键 `(tenant_id, qa_type, question_id)`；同一会话多题不合并。登录按稳定事件 ID 去重，缺失 ID 不用秒级时间猜测合并。
- 用户确认的历史兼容模式 `--qa-history-policy raw`：仅对缺问题 ID 的旧成功问答使用事件 ID；原始事件/专家数据库优先，看板独有记录不叠加且逐条诊断。不按同用户同秒猜测问题关联，不宣称旧记录的真实问题去重完整性；主表备注和统计口径明确说明。默认 strict 保留原缺口拒绝策略，登录及查询完整性校验不变。
- 制造部其他科室/直属人员进部门合计，不进入主表十科室的使用占比分母。比例不能直接求和。
- 分母为零时比例留空并备注“分母为 0”；未知值也留空，但备注说明具体来源错误，避免与已确认零混淆。比例 CSV 显示两位小数百分数，分子分母单独保留整数。

## CSV 交付
| 文件 | 内容 |
|---|---|
| 科室指标汇总.csv | 固定十行及制造部合计，原表列顺序 |
| 其他组织统计.csv | 制造部其他科室、直属人员的指标 |
| 知识核对明细.csv | 文件、文档身份、库类型、空间、上传人、当前归属、计入范围 |
| 登录核对明细.csv | 原始事件 ID、时间、登录人、当前归属及计入范围 |
| 问答核对明细.csv | 来源、类型、问题 ID、提问人、当前归属及计入范围 |
| 指标分子分母.csv | 每行每个比例的精确分子、分母、范围和结果状态 |
| 统计口径.csv | 公式、组织参数、导出时间及零分母规则 |
| 来源诊断.csv | 来源索引/表、读入数量、覆盖范围、异常和差异 |

CSV 使用 UTF-8 BOM 与标准转义，对可能被表格软件执行的外部文本做公式防护，保留数值字段类型语义。用户名、文件名按核对必要性导出，不写密码、令牌、正文或问答内容。输出目录已存在则拒绝覆盖。

- 交付脚本即可，不要求服务重启、索引重建或迁移。回退为停止使用新脚本；本任务不删除既有输出。
