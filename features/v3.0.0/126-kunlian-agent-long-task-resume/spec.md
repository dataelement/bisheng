# Feature 毕昇 Workflow 调用昆联 Agent 的长任务挂起与恢复

- **Feature ID**: F126（拟用，合入前复核）
- **Version**: v3.0.0
- **Priority**: P0
- **Status**: CONFIRMED，用户确认进入设计
- **Mode**: SPEC_ONLY，Mock 优先
- **关联 PRD**: 《2026-10-23-kunlian-bisheng-workflow-integration.html》S06、A08 中的 Worker 释放、结果恢复与取消。[已确认的 4D 开发范围](../../../docs/architecture/proposals/kunlian-workflow-development-plan.md#下一批-4d-的规格入口)
- **依赖**: [F119 平台 Agent](../119-kunlian-platform-agent/spec.md)、[F124 普通异步 Agent](../124-kunlian-agent-long-task/spec.md)。[F123 原生输入](../123-kunlian-workflow-interaction/spec.md)和 [F125 Agent 人工输入](../125-kunlian-agent-interaction/spec.md)提供跨 Worker 恢复的参考及兼容基线。遵循[版本契约](../release-contract.md)。

## 1. 目标与范围

用户在毕昇有会话的运行页执行已发布的 Workflow。昆联接受固定版本的异步 Agent 调用后，毕昇保存可恢复的运行状态，释放该 Workflow 占用的执行槽。昆联仍在处理时，Worker 可以执行其他任务。结果就绪后，独立 Worker 能从原 Agent 节点继续同一次 Workflow，将核验后的结果交给下游一次。

首轮用「开始 → 平台 Agent → 输出 → 结束」线性流程验收。仅覆盖一个普通异步 Agent 节点，使用固定 V1 的 Mock Agent，以状态查询确认远端结果。查询和停止沿用现有毕昇会话入口。已受理运行在刷新、换 Worker 或另发版本后保持原执行、原版本、原 Run 和原截止时间。

通用图恢复、分支／循环／多个异步节点、远端人工输入扩展、SSE 或回调通知、昆联反向调用时的对外 Session 取消和事件续取，留在对应工作包。首轮以隔离 Mock 验收；正式接口与真实环境分别验收。

## 2. 用户故事

- 作为 Workflow 运行者，我希望 Agent 在后台处理时可以离开页面，稍后回到原会话查看同一运行和结果。
- 作为 Workflow 运行者，我希望停止后，远端迟到的结果无法推动本次 Workflow 继续，同时能看到远端是否已确认取消。
- 作为 Workflow 发布者，我希望发布 V2 后，先前启动的 V1 运行仍使用原版本和上下文完成。
- 作为平台运维人员，我希望长时间等待的 Agent 释放执行槽，并能在原 Worker 退出后由另一 Worker 接续。

## 3. 业务需求

| ID | 需求 |
| --- | --- |
| REQ-01 | **运行绑定。** 对首轮范围内的普通异步 Agent，沿用已发布的 Workflow 与固定 Agent 版本、输入输出约定和实际运行身份。受理后，Workflow 执行、节点执行、Agent Run 和截止时间在同一次运行内保持关联。刷新、重新派发或发布新版本均不得改变这些事实。 |
| REQ-02 | **挂起并释放执行槽。** 在确认原 Agent Run 且保存足以继续的节点与上下文后，当前 Workflow 执行任务退出，释放执行槽。会话仍可查询等待远端结果的状态，期间下游执行次数为零。远端等待与用户表单等待在会话中可区分。 |
| REQ-03 | **同次运行恢复。** 结果就绪后，独立 Worker 从原节点及暂停前上下文继续。只查询已绑定的 Run，校验 Run、版本和输出约定。前序节点及远端启动各发生一次，下游只消费一次有效输出。恢复材料缺失或无效时给出明确失败，禁止从图头重跑。 |
| REQ-04 | **重复派发与失败补偿。** 等待期间的查询、接管或恢复派发重复时，只有当前有效执行者可推进原运行。已保存等待或结果后漏投、原执行者退出或失去领取资格时，另一 Worker 可在原期限内继续。迟到的旧执行者无法覆盖新进度或终态。启动响应未知沿用 4B 的查回规则，仅在确认同键重放安全时重试。 |
| REQ-05 | **停止、超时与取消。** 继续使用现有 Workflow 停止入口。停止或超时在结果被有效提交前生效时，阻断新的恢复和下游输出，并按原 Run 发起或核对取消，漏投可补偿。区分本地停止或超时、远端取消受理、确认取消、拒绝或未确认。晚到的远端结果仅用于核对，重复动作不能续期。 |
| REQ-06 | **身份和结果访问。** 查询、停止和接管沿用原会话归属、可信租户和既有权限。恢复前复核实际运行用户当前的权限。用户停用、撤权或权限未知时，不得执行受保护操作或向无权主体返回结果。状态及日志仅暴露允许访问的关联信息和稳定失败原因。 |
| REQ-07 | **兼容和来源隔离。** 复用现有平台 Agent 节点和会话入口。F119 同步调用、F123 原生输入和 F125 Agent 单文本交互保持原行为。Mock 在隔离验证环境中明确装配，正式来源失败时返回明确失败。 |

## 4. 状态与异常边界

| 情形 | 可观察结果 |
| --- | --- |
| 已受理并等待远端 | 原会话可读到同一次运行的等待进度。下游尚未执行；用户刷新不触发重新启动。 |
| 远端成功但结果暂不可用 | 在原期限内查询原 Run。超时后显示本地结果未取得，并保留已核对的远端成功事实。 |
| 远端失败、取消或返回错配结果 | 记录可区分的失败或取消原因。其他 Run、其他版本或不符合输出约定的数据均不能驱动下游。 |
| 普通异步 Agent 返回人工输入请求 | 仍按 4B 的普通异步边界报告该运行配置无法处理人工输入，不展示可提交表单。F125 的显式交互流程继续使用原入口。 |
| 停止或到期与有效结果竞争 | 以先发生的有效本地裁决为准。先提交的有效结果可保留；先停止或到期的运行不能被晚到结果恢复。已确认的远端终态独立记录。 |

## 5. 验收标准

| ID | Requirements | 可观察结果 | Verification |
| --- | --- | --- | --- |
| AC-01 | REQ-01、REQ-02 | **当** 固定 V1 的 Mock Agent 持续运行且 Workflow 已挂起，**系统应** 保持原会话、运行与截止时间，下游执行次数为零。仅启动一个且只有一个执行槽的 Workflow Worker，在远端结果仍未就绪时，同一个 Worker 必须完成投递到同一队列的另一条 Workflow 任务。 | V-01 |
| AC-02 | REQ-01、REQ-03 | **当** Worker A 在挂起后退出、随后发布 V2 且原 Agent Run 返回有效结果，**系统应** 由独立 Worker B 沿用已受理的 V1 Workflow、V1 Agent、原节点和暂停前上下文继续。核对前序节点、远端启动和下游输出各发生一次。 | V-02 |
| AC-03 | REQ-03、REQ-04 | **如果** 保存等待或结果后漏投，或恢复任务重复投递、原领取者在输出前失效，**系统应** 在原期限内收敛到同一次恢复和一次下游输出。旧领取者晚到的更新被拒绝；无法验证恢复材料时以可查询失败结束。 | V-02、V-03 |
| AC-04 | REQ-03、REQ-04 | **如果** 启动响应丢失、查到的 Run／版本错配、结果不符合约定或远端成功但结果暂不可用，**系统应** 分别记录原启动的查回事实或对应失败，且不会新建另一逻辑 Run 或提交无效输出。结果暂不可用只在原期限内查回。 | V-03 |
| AC-05 | REQ-05 | **当** 停止或超时先于有效结果提交，**系统应** 保持原本地终态，补齐漏投的取消动作并区分受理与确认。重复停止和迟到结果不得增加有效取消意图、延长截止或触发下游。有效结果先提交时按原成功裁决处理。 | V-03、V-04 |
| AC-06 | REQ-06 | **如果** 其他用户或租户查询或停止原执行，或原用户在恢复前已撤权、停用或无法确认权限，**系统应** 拒绝相应受保护动作和结果读取。Worker 切换后仍以原实际运行身份核验。 | V-03、V-04 |
| AC-07 | REQ-01、REQ-02、REQ-07 | **当** 用户刷新或重新打开同一会话，**系统应** 展示原运行的等待、停止或成功状态。同步调用、原生输入和 Agent 单文本表单通过原路径回归；普通异步流程遇到远端人工输入时不会开启表单。正式来源异常时返回明确错误。 | V-04 |

| ID | 验证方式 | 当前状态 |
| --- | --- | --- |

| V-03 | 隔离故障注入和权限验证。覆盖启动查回、漏投、重复领取、失效执行者、结果异常、停止与结果竞争、超时及越权拒绝。 | 隔离 Mock 已通过，见[验证记录](./verification.md) |
