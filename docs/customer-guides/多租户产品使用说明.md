# BiSheng 多租户产品使用说明

> 适用版本：v2.5.1 及以上（本文依据 v3.0.0-beta1 核实）
> 读者：实施工程师、系统管理员、售前顾问

---

## 1. 适用场景与基本概念

多租户用于**一套 BiSheng 服务同时承载多个相对独立的组织单元**的场景，典型如集团总部与下属分子公司：各分支机构的知识库、应用、会话数据彼此不可见，配额独立核算，但共用同一套部署，由总部统一运维。

### 1.1 两层组织结构

平台的租户结构固定为**两层**：

```
总部租户（Root）
├── 分支机构 A（子租户）
├── 分支机构 B（子租户）
└── 分支机构 C（子租户）
```

- **总部租户**：系统初始化时自动创建，全局唯一，不可删除、不可停用。开启多租户前的所有存量数据都归属于它。
- **子租户**：由管理员从部门树中"标记"产生，数量不限。

> **不支持三层及以上结构。** 已成为子租户的部门，其下级部门不能再次标记为子租户。如果客户的组织是"集团—分公司—子公司"三级，只有其中一级能作为租户边界，其余层级用部门树表达（部门树本身层级不限，但部门不构成数据隔离边界）。

### 1.2 租户与组织架构的关系

**这是理解多租户的关键：租户不是独立于组织架构的概念，而是部门树上的一个标记。**

创建子租户的动作，本质是把部门树中的某个部门节点标记为"子租户根"。此后该部门及其所有下级部门构成这个子租户的范围：

- 用户属于哪个租户，由他的**主部门**决定——主部门落在哪个子租户的范围内，他就属于哪个租户；不在任何子租户范围内的用户，属于总部租户。
- 因此**没有"添加租户成员"这一操作**，成员管理统一在组织架构中完成。调整用户的主部门，其租户归属自动跟随变更。

### 1.3 一人一租户

每个用户在同一时间只属于一个租户，登录后即进入该租户，**使用过程中不需要也无法切换租户**。这一设计使普通用户对多租户完全无感知——他看到的就是自己机构的数据。

## 2. 开启多租户

多租户是**部署级开关**，需要在服务端配置并重启，不能在界面上开关，也不能对不同用户分别启用。

### 2.1 操作步骤

**第一步：修改配置**

编辑后端 `config.yaml`：

```yaml
multi_tenant:
  enabled: true
  default_tenant_code: "default"
```

**第二步：执行数据库迁移**

```bash
cd src/backend
uv run alembic upgrade head
```

**第三步：重启后端服务**

包括 API 服务与所有 Celery Worker。

### 2.2 开启后的状态

- 所有存量数据（知识库、应用、会话、模型配置等）**全部归属总部租户**，无需迁移，用户无感知。
- 管理员菜单中出现「租户管理」入口（仅超级管理员可见）。
- 左侧菜单「系统」→ 组织与成员中，部门设置页出现「标记为子租户」按钮。

> **务必先开启多租户再创建子租户。** 关闭状态下即使通过接口创建了子租户，租户隔离逻辑也不会生效，数据不会被隔离。

### 2.3 关闭多租户

将 `enabled` 改回 `false` 并重启即可回到单租户模式，所有功能按单一组织运行。但**已经拆分到子租户的数据不会自动合并回总部**，关闭前请确认没有子租户在使用，否则这部分数据将无法从界面访问。

## 3. 创建分支机构（子租户）

### 3.1 前置准备

创建子租户前必须先在组织架构中建好对应部门，并把该机构的人员加入这个部门（包括未来要担任管理员的人）。**子租户的初始管理员只能从该部门及其下级部门的成员中选择**，选不到人说明部门里还没有人。

### 3.2 操作步骤

1. 以超级管理员登录，点击左侧菜单 **「系统」**
2. 切换到 **组织与成员** 标签页
3. 在左侧部门树中选中目标部门（不能是根部门）
4. 在右侧切换到 **设置** 标签页，滚动到底部
5. 点击 **「标记为子租户」**
6. 在弹窗中填写：
   - **租户名称**（必填）：默认预填部门名称，可修改，最长 128 字符
   - **初始管理员**（必填，可多选）：只能搜索到该部门子树内的成员
7. 点击 **「确认挂载」**

创建成功后，该部门在部门树中会显示蓝色的「子租户」标签，部门图标变为高亮色。

### 3.3 注意事项

- **该操作不可撤销**（只能通过"取消挂载"解除，解除过程见 §8.2），弹窗中会有橙色提示。
- 租户编码由系统自动生成，无需填写，且**创建后不可修改**。
- 若部分管理员授权失败，租户仍会创建成功，界面会提示哪些用户未授权成功，可在成员管理中补授。
- 一个部门被标记为子租户后，它的**下级部门不能再被标记**（两层结构限制）。

## 4. 成员与管理员管理

### 4.1 成员归属

如 §1.2 所述，成员归属由主部门自动决定，**租户管理界面中没有"添加成员""移除成员"按钮**。要调整某人的租户归属，请到左侧菜单「系统」→ 组织与成员 中修改他的主部门。

### 4.2 调岗的影响

当用户的主部门变更到另一个租户范围内时：

- 该用户的租户归属立即变更；
- **该用户会被强制下线，需要重新登录**（原有登录凭证立即失效）；
- 重新登录后，他将看到新机构的数据，**原机构中由他创建的知识库、应用等资源不会跟随转移**，仍留在原租户。

> 如果调岗人员名下有重要资源，建议**先完成资源交接再调整部门**。平台可配置为在此情况下阻断部门变更并提示先行交接，需要时请联系实施人员开启。

### 4.3 设置租户管理员

1. 进入 **租户管理**（左侧菜单，仅超级管理员可见）
2. 在租户列表中，**点击该租户的「用户数」数字**，打开成员对话框
3. 在成员列表中找到目标用户，点击 **「设为管理员」**；取消则点击 **「取消管理员」**（需二次确认）

管理员用户名后会显示「管理员」标签。

> 总部租户不在此处设置管理员——总部的管理权限由超级管理员承担，该租户的成员对话框中不显示管理员操作按钮。

### 4.4 租户管理员的权限范围

子租户管理员可以在本机构范围内：

- 管理本机构的用户组、角色与资源权限
- 注册与管理本机构自有的模型服务
- 配置本机构的系统默认模型、工作台设置
- 查看本机构的配额使用情况

子租户管理员**不能**：创建或删除租户、标记或解除子租户、跨机构查看数据、修改总部共享给本机构的模型、修改总部的任何配置。

## 5. 配额管理

### 5.1 设置配额

1. 进入 **租户管理**
2. 在目标租户行点击 **「配额设置」**
3. 设置 **「知识库存储用量 (GB)」**
4. 保存

- 取值范围 0.1 ~ 99999，最多一位小数
- **留空表示不限制**
- 标签右侧会显示该租户当前已用量

租户列表的「存储用量」列会以进度条形式展示"已用/配额"，未设置配额的显示为 `-`。

### 5.2 总部配额是集团总量上限

总部租户的配额有特殊含义：**总部的用量统计包含自身用量与所有子租户用量的总和**。

这意味着如果总部配额设为 100GB，即使某个子租户自己的配额还有剩余，只要全集团累计已达 100GB，该子租户也会被阻止上传。适合需要控制整体采购容量的场景。

### 5.3 超出配额的表现

存储达到上限后，知识库文件上传会被拒绝。提示文案区分两种情况，便于快速定位是哪一层超限：

- **本机构配额用尽** —— 提示当前租户配额已耗尽，需要为该机构扩容
- **集团总量用尽** —— 提示"集团总量已耗尽"，说明是总部配额封顶，此时给单个子租户加配额没有用，必须调整总部配额

删除文件释放空间后即可恢复上传，无需管理员干预。

## 6. 模型配置与共享

### 6.1 总部模型共享给分支机构

超级管理员在总部创建模型服务时，配置抽屉中有 **「共享给子租户」** 开关（默认开启）：

- **开启**：所有子租户都能使用这个模型服务
- **关闭**：仅总部可用

该开关**仅在超级管理员配置总部的模型服务时出现**，子租户管理员看不到它。共享是面向全部子租户的统一开关，不能指定共享给其中某几个机构。

### 6.2 分支机构看到的共享模型

子租户成员在模型管理页看到总部共享的模型时：

- 模型名称旁显示 **「XX 共享 · 只读」** 标签
- 「模型配置」按钮与可用性开关**均为禁用状态**

即分支机构可以**使用**这些模型，但不能修改、停用或删除。

### 6.3 分支机构自建模型

子租户管理员可以在本机构注册自己的模型服务，与总部共享的模型并存使用。这适用于分支机构有独立的模型采购、独立计费或数据合规要求的场景。

> 部署时可配置模型端点白名单，限制子租户管理员只能注册指定域名下的模型服务。需要时请联系实施人员。

### 6.4 系统默认模型的继承

知识库、助手、评测、工作流、工作台这五类场景的默认模型选择支持按租户配置：

- 子租户**未配置**时，自动继承总部的设置，界面显示「继承自 Root」标签
- 子租户**一旦自行配置**，即与总部脱钩，此后总部的调整不再影响该机构

## 7. 超级管理员的管理视角切换

超级管理员可以临时切换到某个分支机构的视角，代为查看和配置其模型相关设置。

### 7.1 使用方式

在 **模型管理** 页或 **工作台配置** 页，顶部有 **「管理视图：XXX」** 下拉按钮：

1. 点击下拉，选择目标租户（列表含总部与所有启用中的子租户）
2. 选中后当前页面数据自动刷新为该租户的配置
3. 切回总部选择列表第一项

切换视角**不会登出、不会跳转页面、不改变自己的租户归属**，只影响当前页面看到的配置数据。切换后按钮上会持续显示当前所处的视角。

### 7.2 作用范围

管理视角**仅在模型管理与工作台配置这两处生效**。知识库、应用、会话等业务数据不在此范围内——超级管理员无法通过视角切换查看分支机构的业务数据。

视角在一段时间无操作后自动失效，回到默认的总部视角。

## 8. 租户状态管理

租户列表中每行展示当前状态：**正常 / 已停用 / 已归档**。

### 8.1 停用与启用

在租户管理页点击 **「停用」**（需二次确认）：

- 该租户**全体成员立即被强制下线**，且无法再登录
- 数据完整保留，不做任何删除或迁移
- 后台任务与定时同步不再为该租户执行

点击 **「启用」** 即可恢复，成员重新登录后一切如常。

> 总部租户受系统保护，不显示停用按钮。

### 8.2 解除子租户（取消挂载）

如果要把某个分支机构合并回总部：

1. 进入左侧菜单 **「系统」→ 组织与成员**
2. 选中该子租户对应的部门
3. 在右侧 **设置** 标签页底部点击 **「取消挂载」**，二次确认

执行后：

- 该机构名下的**所有资源自动迁回总部**，不会丢失
- 部门恢复为普通部门，其成员归属自动回到总部
- 该租户转为 **已归档** 状态

> **已归档是终态，不可恢复。** 归档后的租户在列表中只保留记录供审计追溯，不能再被启用，也不能再编辑或设置配额。如果只是想临时冻结一个机构，请使用"停用"而不是"取消挂载"。

### 8.3 删除租户

只有**已停用或已归档**的租户才显示「删除」按钮，且需要：

1. 确保该租户下已无成员（只要还有人的主部门在该租户范围内，删除就会被拒绝）
2. 在确认框中**手动输入该租户的租户编码**，才能激活删除按钮

删除是物理删除，且会**连带删除该租户名下的部门**，请谨慎操作。日常的机构下线建议使用「停用」或「取消挂载」，删除仅用于清理确认不再需要的空租户。

## 9. 数据隔离范围说明

### 9.1 隔离了什么

开启多租户后，以下数据均按租户隔离，跨租户不可见：

| 类别 | 具体内容 |
|------|----------|
| 知识与文档 | 知识库、知识空间、文档文件、问答知识库 |
| 应用 | 工作流、助手、看板、工具 |
| 会话数据 | 对话记录、消息、会话历史 |
| 渠道 | 频道、信息源、文章 |
| 组织与权限 | 部门、用户组、角色、资源授权关系 |
| 模型 | 模型服务、模型、系统默认模型配置、调用与用量记录 |
| 运营数据 | 配额、审计日志、组织同步配置 |
| 其他 | 灵思会话与技能、评测与标注、微调任务 |

用户账号本身是全局的（同一账号不会因为多租户而重复创建），但其可见的业务数据严格限定在所属租户内。

### 9.2 可见性方向

- **分支机构之间完全隔离**，互不可见，也不能互相共享资源。
- **总部默认看不到分支机构的业务数据**。超级管理员如需查看，只能通过 §7 的管理视角，且范围仅限模型与工作台配置。
- **分支机构可以看到总部共享的模型服务**（只读），这是唯一的跨租户共享内容。业务资源（知识库、应用等）不支持跨租户共享。

### 9.3 同一租户内部并非默认互通

**这一点客户容易误解，请在方案沟通中明确：** 同属一个租户的成员，默认**看不到彼此创建的资源**。租户隔离解决的是"机构之间不互通"，机构内部的资源可见性由权限体系单独控制——资源创建者需要显式授权给指定的用户、部门或用户组，对方才能访问。

这是有意的安全设计，避免同机构内所有人的知识库互相可见。

### 9.4 授权范围限制

资源只能授权给**本租户内**的用户、部门或用户组。不能把总部的知识库直接授权给分支机构的某位员工——跨租户的访问只能通过 §6 的模型共享机制，业务资源没有对应能力。

### 9.5 隔离级别说明（合规相关）

BiSheng 多租户采用**逻辑隔离**：所有租户共用同一套数据库与存储服务，通过数据层的租户标识实现隔离，平台的数据访问层统一强制附加租户过滤条件。知识库的向量索引与全文索引按知识库独立创建，租户之间无法互相检索。

**这不是物理隔离。** 平台不提供"每个租户使用独立数据库实例/独立存储实例"的部署形态。如果客户的合规要求明确规定数据必须物理分离（独立库、独立存储、独立服务器），则需要为该客户单独部署一套 BiSheng 实例，而不是使用多租户功能。这一点建议在方案阶段主动确认，避免交付后返工。

## 10. 常见问题

**Q：能不能做三层结构，比如集团—分公司—子公司？**
不能。租户结构固定两层。可以让分公司作为子租户，子公司用部门表达；但子公司之间的数据不构成隔离边界，同一分公司下的所有部门共享同一份数据可见范围（具体到某份资源仍受权限控制）。

**Q：一个用户能同时属于两个机构吗？**
不能。每人同一时间只属于一个租户，由主部门决定。可以给用户设置兼职部门，但兼职部门不改变租户归属。

**Q：用户能自己切换机构吗？**
不能，也不需要。登录后自动进入所属机构，界面上没有切换入口。

**Q：总部管理员能看到分支机构的知识库吗？**
不能。管理视角只覆盖模型与工作台配置，不包括业务数据。如果确有需要，只能由分支机构的成员主动把资源授权出来，或者由超级管理员在数据库层面处理（不推荐）。

**Q：分支机构 A 能把知识库共享给分支机构 B 吗？**
不能。跨租户共享目前只支持模型服务，且方向固定为总部→分支。

**Q：开启多租户后，原来的数据会不会丢？**
不会。存量数据全部归入总部租户，路径与访问方式不变，用户无感知。

**Q：分支机构的配额和总部是什么关系？**
分支机构受"自己的配额"和"总部配额"双重约束，任一超限都会被阻止。总部配额相当于全集团的总量上限。

**Q：删了子租户对应的部门会怎样？**
该租户会进入异常状态并通知超级管理员处理，其成员的租户归属会回落到上级最近的租户。请避免直接删除已标记为子租户的部门，应使用"取消挂载"。

**Q：界面上哪里能看到我当前在哪个租户？**
普通用户界面不展示租户信息（对用户而言就是"我的系统"）。管理员可在租户管理页查看全部租户，以及在模型管理页的管理视图按钮上看到当前视角。

| 文档用语 | 界面用语 | 说明 |

| 取消挂载 | 取消挂载 | 解除子租户，资源迁回总部 |
| 管理视角 | 管理视图 | 超级管理员临时切换的配置视角 |
