# 警告提示规范 Alert

> 设计系统 · 警告提示 v1 · 2026-10-21

## 1. 什么时候用

警告提示是**嵌在页面里的一条提示**，用来说明「这个页面或这块区域当前处在什么状态」：配置还没完成、额度快用完了、这项功能暂不可用。它不浮起来、不挡页面、**不会自己消失**，状态解除或用户关掉才走。

**事情是「一直在」的，用警告提示；事情是「刚发生」的，用轻提示或通知提醒。** 四种反馈的分界：

| 这条信息 | 用什么 | 例子 |
|---|---|---|
| 页面 / 区块的持续状态，用户要对照着处理 | **警告提示**（本文） | 知识库未配置向量模型，无法检索 |
| 用户刚才点的那一下的结果 | 轻提示 Toast | 已保存、链接已复制 |
| 后台、系统、别人引起的事 | 通知提醒 Notification | 知识库解析完成 |
| 必须当场决定 | 弹窗 | 导入中断，12 份文件未入库 |

- **一块区域只放一条。** 两条叠着就没人读了；有两件事要说，合成一条或只说最要紧的那件。
- **说的是状态，不是操作结果。** 「保存成功」「删除失败」是轻提示的事，不放这里。
- **不要拿它做营销和引导。** 「试试新功能」一类不走警告提示——它出现就意味着「有件事影响你用这个页面」，掺一次无关的，以后每条都会被忽略。
- **表单单个字段的错误不用它**，用字段自己的报错，见 [组件-Input输入框.md](组件-Input输入框.md)。

| ✅ 推荐 | ❌ 不推荐 | ❌ 错在哪 |
|---|---|---|
| 页面顶部：未配置向量模型，当前知识库无法检索 → 「去配置」 | 点保存后在页面顶部出现「保存成功」 | 操作结果，该用轻提示 |
| 列表上方：本月调用额度已用 90%，超出后将暂停服务 | 「全新工作流编辑器上线，立即体验」 | 营销引导，不是页面状态 |
| 表单顶部：3 个必填项未填写 | 「名称」字段下方用警告提示报「名称已存在」 | 单字段错误，用字段报错 |

## 2. 类型 Type

四种类型，靠**图标 + 浅色底**区分语义：

| 类型 | 什么时候用 | 图标与浅底取色 |
|---|---|---|
| **信息 Info**（默认） | 单纯告知，没有好坏之分 | 品牌色 |
| **成功 Success** | 某个状态已就绪、已达成 | 成功色 |
| **警告 Warning** | 还能用，但有风险或有条件 | 警告色 |
| **失败 Error** | 当前用不了，必须处理 | 危险色 |

- **每种类型必须带图标**，不做纯文字款——颜色分不清的用户靠图标读语义；图标与轻提示同一套。
- 拿不准用哪种就用 **Info**。
- 不做「加载中」类型。
- 色值一律取功能色 token，不写裸色值；取色规则见 [基础-色彩规范.mdx](基础-色彩规范.mdx) §3。暗色模式浅底由 token 自动翻转为深色底，不单独调。

## 3. 位置与宽度

- **放在它所描述的那块内容的正上方**：说页面的放页面顶部，说某个列表的放列表上方。
- **宽度撑满所在容器，四周留 8px 外边距**，不贴边、保留圆角。
- **不做贴边直角的通告条**。贴边的横幅看起来像页面结构的一部分，用户会把它当装饰忽略掉。
- 它在内容流里，跟着页面滚动，**不固定、不浮层、没有层级**。

## 4. 尺寸与样式

| 项 | 规格 |
|---|---|
| 高度 | 单行（只有一句话）40px，垂直不设内边距、文字居中；带标题或正文换行时改为上下各 12px 内边距，高度自适应 |
| 水平内边距 | 16px |
| 圆角 | 12px（容器档 `xl`） |
| 投影 | 无——它嵌在页面里，不浮起 |
| 边框 | 无 |
| 底色 | 对应类型的功能色浅底 |
| 图标 | **始终 16px**，取对应类型的功能色主色，在文字左侧，间距 8px；单行时与文字居中，多行时与第一行居中对齐 |
| 标题 | `text-body`（14/22），字重 500，主文字色 `text-1`，最多 1 行 |
| 正文 | `text-body`（14/22），字重 400；有标题时取次要文字色 `text-2`，无标题时取主文字色 `text-1` |
| 标题与正文间距 | 4px |
| 操作区 | 固定在右侧；与文字间距 16px；按钮之间 8px；关闭按钮与操作按钮之间 16px |
| 关闭按钮 | 16px 图标，贴最右侧；颜色 `text-4`，悬停转 `text-2` |

- **文字用主文字色，不用语义色。** 语义由图标和浅底说清，彩色正文在浅底上对比度不够。
- **图标不随有无标题变大。** 轻提示、通知提醒、警告提示三者同为 16px，一套图标一个尺寸。
- **操作区在单行时与文字居中，多行时与第一行居中对齐**，和图标一样跟着首行走。

## 5. 内容形态

从左到右：图标 → 文字（标题可选，正文必填）→ 操作按钮（可选）→ 关闭按钮（可选）。

### 5.1 标题（可选）

- **一句话说出状态，不加句号**：「向量模型未配置」「额度即将用完」。
- **最多 1 行**，超出截断加省略号。
- 只有一句话要说时不要硬凑标题，直接写正文。

### 5.2 正文（必填）

正文遵循 [基础-文案规范.md](基础-文案规范.md)，以下是警告提示自己的细则：

- **说清「现在是什么状态」和「用户能做什么」**：「未配置向量模型，当前知识库无法检索，请先在设置中配置」。
- **最多显示 2 行**，超出截断加省略号，不做展开。两行说不完，把细节放到操作按钮指向的页面，不是把提示写长。
- **文字本身要说清是警告还是错误**，不能只靠颜色：「无法检索」比「请注意」有用。
- **失败和警告要给出路**：说下一步做什么，或配一个操作按钮。
- 只放纯文字，不放富文本、不放图片；要跳转，用操作按钮。

| ✅ 推荐 | ❌ 不推荐 | ❌ 错在哪 |
|---|---|---|
| 未配置向量模型，当前知识库无法检索 → 「去配置」 | 请注意配置 | 没说什么没配、后果是什么 |
| 本月调用额度已用 90%，超出后将暂停服务 | 额度不足！ | 没说还剩多少、超了会怎样；感叹号在吓人 |
| 该模型已下线，工作流中 3 个节点需要更换模型 → 「查看节点」 | 该模型已于 2026 年 9 月 30 日由供应商宣布停止服务，受影响的节点包括……（四行） | 超过两行，细节该放到「查看节点」里 |

### 5.3 操作按钮（可选）

- **最多两个**，固定在右侧，都用 `small`（24px）尺寸（见 [组件-Button按钮.md](组件-Button按钮.md) §3）——提示条只有一行高，medium 的按钮会撑破它。
- **主动作用品牌色文字按钮（`primary × text`），次动作用默认文字按钮（`default × text`）。** 不放实心和次强调按钮——浅色底上再铺一块色，提示条就成了卡片。
- **按钮必须是处理这个状态的实际动作**：「去配置」「查看」「重试」。**不许是「关闭」「知道了」**——那是关闭按钮的事。
- **点了操作按钮，提示不自动消失**，状态解除后由业务撤掉。

### 5.4 关闭按钮（可选）

- **默认不放。** 它说的是当前状态，状态没解除就不该让用户关掉。
- **只有「用户知道了就行、不需要处理」的提示才放关闭**，比如额度提醒；影响使用的失败不给关闭。
- **关掉后要不要记住（刷新不再出现），由业务决定**，组件不存状态。
- 规格见 §4。

## 6. 动效

| 环节 | 规格 |
|---|---|
| 出现 | 随页面渲染，不做进场动效 |
| 关闭 | 淡出同时高度收起，200ms，下方内容跟着补位 |
| 缓动曲线 | `cubic-bezier(0.2, 0, 0, 1)` |

它是页面的一部分，出现时不该「飞进来」；关闭要收高度，不然下面的内容会猛地跳上来。

## 7. 移动端适配

v1 不做。桌面规则在窄屏下照用；等移动端出现真实场景再定操作区是否换行到文字下方，见待决策清单。

## 8. 无障碍

- **常驻在页面里的提示不加 live region**，页面加载时屏幕阅读器按阅读顺序自然读到。
- **由用户操作触发、动态插入的提示**：失败与警告用 `role="alert"`（打断播报），成功与信息用 `role="status"`（礼貌播报）。
- **出现时不抢焦点。**
- 关闭按钮 `aria-label` 为「关闭」，操作按钮与关闭按钮都能用 Tab 到达。
- 图标是装饰，加 `aria-hidden`；语义靠文字说清（§5.2）。

## 9. 落地要求（给实现窗口）

1. 组件形态：JSX 挂载式 `<Alert type="warning" title=... description=... actions=[...] closable onClose />`，不做命令式 API——它跟着页面状态走，由业务 state 控制显隐。
2. 位置：放在 `packages/ui/src/components/Alert/`，`@bisheng/ui` 导出 `Alert`；demo 页 `docs/components/alert.mdx`（ASCII 文件名）。
3. 样式 token：`rounded-xl` + 四类 `*-tint` 浅底（与 `Toaster.tsx` 同一组类名，含暗色自动翻转），禁止裸 hex、禁止边框、禁止投影；单行 `h-10 px-4`，多行 `px-4 py-3`；标题 `text-body font-medium text-text-1`，正文 `text-body text-text-2`（无标题时 `text-text-1`）；图标 16px 取功能色主色（成功 / 危险 / 警告）与品牌色（信息），类名以 `packages/ui/design-token.cjs` 的 FUNCTIONAL / BRAND 导出为准；关闭按钮 `text-text-4 hover:text-text-2`。
4. 外边距 8px 由组件自带（`m-2`），业务不再另包一层。
5. 文字截断：标题 `line-clamp-1`，正文 `line-clamp-2`；被截断的完整文案放 `title` 属性兜底。
6. 操作区：`actions` 最多接两项，超出只渲染前两项并在开发态 warn；按钮用 Button 的 `small` 档，`primary × text` / `default × text`。
7. 关闭动效：高度 + opacity 过渡 200ms，时长与曲线用预设具名值 `duration-200` / `ease-notice`（`tailwind-preset.cjs`），不写任意值（原因见 Notification §10.9）。关闭后组件卸载，`onClose` 回调由业务决定是否持久化。
8. 无障碍：`role` 按 §8 由 `live` 属性控制（默认不加；`live` 时按类型取 `alert` / `status`）；图标 `aria-hidden`；关闭按钮 aria-label 走文案键 `com_ui_close`。
9. 上线前照元规范 §5 清单：在 `src/frontend/client/rspress.config.ts` 的 `themeConfig.sidebar` 注册本文入口与 demo 页。
