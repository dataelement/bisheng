### 历史准备与 CPU

实际 `capture()`，原生 SQLite，含原测试中的目录、文件、文档、既有孤儿和 parent tuple；只增加指定数量的健康/缺失根及 mode：

根/成员同时放大为 100/200 时，`str(root_id)` 从旧版 10,000/40,000 次降到 100/200 次。

深链 100/200 节点的保留传播均每节点各访问一次 SQL-child 和 incoming 索引；任一未证明可删的下游仍阻止其依赖链。

### 大 payload 完整摘要的独立进程探针

每行约 64 KiB，完整摘要相同；新实现使用私有磁盘行，旧实现使用原内存行。
复现脚本：[history_payload_probe.py](evidence/v310b1-migration-performance-fix-20261119/history_payload_probe.py)。
进程 RSS 包含导入与输入准备；Python 分配计数只覆盖摘要阶段。

| 行数 | 旧→新进程峰值 RSS | 旧→新摘要 Python 峰值 |
| --- | --- | --- |
| 1,000 | 334.0 → 59.7 MiB | 131,717,961 → 336,870 bytes |
| 2,000 | 617.4 → 59.5 MiB | 263,317,129 → 351,515 bytes |

这证明大行摘要不再整体复制/编码，不是整次 F118 迁移的 RSS 上限。
