# Design 毕昇 Workflow 调用昆联 Agent 的人工输入与恢复

- **Feature ID**：F125（拟用，合入前复核）
- **Version**：v3.0.0
- **Status**：W1～W4 隔离 Mock 已验证，正式契约及环境待确认
- **关联**：[规格](./spec.md) · [4A 恢复设计](../123-kunlian-workflow-interaction/design.md) · [4B 长任务设计](../124-kunlian-agent-long-task/design.md) · [版本契约](../release-contract.md)

## 1. 目标与边界

在已发布的「开始 → 平台 Agent → 输出 → 结束」流程中，固定版本的昆联 Agent 可暂停一次并请求一个必填文本字段。原运行用户在毕昇会话提交后，另一 Worker 接续原 Agent Run 和原 Workflow。停止与取消沿用 4B。

首轮限定有会话的 Client 运行页和隔离 Mock。多轮交互、复杂表单、通用图恢复、事件订阅及昆联反向调用扩展归后续工作包。同步 Agent、普通 4B 异步 Agent 和 4A 原生输入继续各自执行。

## 3. 关键决策

| 决策 | 选定及依据 | 复核条件 |
| --- | --- | --- |
| D-01 暂停位置 | 在显式启用的 Agent 节点之前设置静态图检查点。Worker 到达该点后用节点的变量查询与 4B 服务执行一次启动和轮询。遇到人工等待时保存这个检查点。节点内动态中断会重入节点函数，当前 `BaseNode.run` 还会记录结束日志，有重复启动和误报失败的风险。 | 启用多节点交互、分支或循环时，重新验证检查点形态和节点重入语义。 |
| D-02 权威存储 | 把等待、表单、提交回执和恢复派发放进原执行行，复用 4B 的行锁判定。进程对象或 Redis 单独保存会使等待、停止和输出各有一套判定。首轮每次执行只保存一份有界检查点。 | 检查点容量、更新频率或升级兼容成为发布约束时，评估独立存储与一致性方案。 |
| D-03 派发与补偿 | 初始执行和交互恢复分别领取。未领取的恢复任务可按原派发 ID 补投，已领取的任务失联后只收敛远端事实和本地终态，沿用 4A 的一次领取原则。整图重放可能重复执行暂停前节点或已经开始的下游。 | 要求自动接管已领取且部分执行的任务时，须另行证明可安全恢复的步骤和副作用。 |

### 3.1 跨进程设计探针

使用 F124 样例、真实 `Workflow`、`GraphEngine`、平台 Agent 与输出节点验证静态边界。进程 A（PID 47988）临时为 Agent 增加 `interrupt_before`，只运行开始节点，导出该点的 JSON 检查点和变量。进程 B（PID 48002）重建同一图，恢复后仍以 Agent 节点为下一步。向该节点注入测试结果后，原图执行成功，开始节点未重跑，Agent 输出门禁进入一次，下游输出一次。两阶段均退出 0。

## 4. 执行与状态

### 4.1 受理、暂停和恢复

1. **发布与受理。** 节点候选配置 `allow_interaction` 缺省为 `false`。只在 4B 异步模式、固定版本具备 `supports_interaction`、已发布且有会话的线性样例中启用。发布时校验四个执行节点、顺序及纯输出形态，忽略仅作注释的节点。将交互能力、版本与 Schema 摘要纳入 F119 冻结绑定，旧节点保持原摘要。受理复用 F119 的 Flow 行锁，与发布串行核对唯一当前 `FlowVersion` 及图摘要。在原执行 JSON 内记录同一时刻的版本 ID 和冻结图，客户端无法覆盖配置。恢复只读取该绑定，新发布的版本不参与选择。[F119 发布事务](../../../src/backend/bisheng/workflow/domain/repositories/platform_node_publication.py#L22)
2. **执行到等待点。** 4C Worker 单独驱动图到 Agent 前的静态中断，明确停止于该点。普通 `Workflow.run` 的自动继续循环维持原用途。沿用平台 Agent 节点的输入解析和 4B 启动键。若在人工等待前已取得有效结果，原 Worker 从该点进入平台 Agent 输出提交。若返回可信人工等待，则在原执行行的同一短事务内绑定远端等待事实、保存快照和表单、设定等待截止、结束原派发并释放 Worker。待填状态在事务提交后可见。
3. **恢复原调用。** 本地受理答案时原子登记一个 `INTERACTION_RESUME` 派发。Worker B 复核原实际用户和冻结绑定，领取后在同一锁内把原调用的执行许可交给新领取者。新派发 ID 只标识执行权限，节点序号、Agent Run ID、启动键和交互绑定均保持原值。重建冻结图、恢复检查点和变量，再向原远端交互提交答案并继续 4B 轮询。先校验恢复材料，避免远端已接受答案后才发现本地图无法恢复。
4. **续跑与输出。** 结果需匹配原 Run、固定版本及冻结输出 Schema。Worker 通过内部执行上下文把已核验结果交给原平台 Agent 节点，由 `output_commit_scope` 完成一次输出提交。续跑保留原变量写入和下游开始门禁。检查点已经包含开始节点的结果，恢复阶段没有 Agent 启动权限。

### 4.2 等待点与执行材料

| 数据 | 保存和校验 |
| --- | --- |
| 原运行关联 | 执行 ID、原会话、租户、实际用户、来源与连接策略、Workflow 版本和图摘要、Agent 固定版本、节点 ID 和序号、已绑定的 Agent Run ID。已存在的执行字段继续复用。 |
| 检查点 | 版本化 JSON，绑定执行 ID、冻结图摘要、Workflow 版本、预期 Agent 节点及引擎兼容标识。保存检查点、开始节点的变量和步数、空历史的记忆配置及原回调来源。早期 W1 等待点缺少来源时按普通浏览器来源读取。独立检查预期下一步只有 Agent 节点、没有挂起写入及意外节点或历史。复用 4A 的 JSON 深度与 256 KiB 上限。内存检查点可重建，数据库执行行承载跨进程材料。 |
| 表单与答案 | 本地交互 ID 对应原远端交互 ID 及修订。保存有界字段定义、等待期限、状态和答案摘要，已接受的必要答案在恢复期间保存。首轮仅接受一个必填字符串，拒绝空白、超限和额外字段。文本标签与内容按纯文本处理。 |
| 受理与恢复派发 | 绑定本地交互、提交标识摘要、答案摘要、固定远端提交键、阶段期限、派发及领取标识。终态清理答案、表单和检查点，回执保留期内保存最小去重及终态事实。队列只携带执行、交互、派发标识，租户通过可信任务头传递。 |

### 4.3 状态和时间

4C 阶段保存于 `calls[call_key].long_task.interaction` 的版本化子记录。工作流执行行状态、4B 本地节点状态、远端 Run 状态和取消状态分别保存。首次等待落库后由 4C 阶段决定期限，普通 4B 总等待截止只用于启动至首次等待之前的主动轮询。

| 4C 阶段 | 锁内判定及状态出口 |
| --- | --- |
| `WAITING_INPUT` | 原执行仍有效时保存快照，结束原派发并把执行行转为等待。无答案到期时记人工等待超时，关闭输出。 |
| `SUBMIT_QUEUED` | 只在表单、身份、修订及等待截止均满足时原子登记答案、回执和唯一恢复派发。事务提交后确认本地已接收。Worker 未领取时可补投同一派发，队列阶段到期则结束。 |
| `SUBMIT_IN_FLIGHT`／`SUBMIT_UNKNOWN` | 领取者复核权限与期限后，在同一执行行取得发送许可。明确远端受理后进入结果等待，明确拒绝收敛为失败。送达不明先按原 Run、交互和提交键核对，明确安全才重放同一请求。普通运行中状态本身不能证明本次答案已受理。 |
| `WAITING_RESULT` | 以首次可信受理为基准设置独立结果期限。继续查询原 Run，即使最近一次远端观察仍是 `WAITING_INPUT`。校验结果并继续原图。旧等待帧不重新展示表单。确认是新的交互时收敛为不支持的第二次人工等待。 |
| `TERMINAL` | 清理明文答案、表单和检查点。保留本地结果、最后确认的远端事实以及最长 24 小时的去重回执。提交或取消的迟到回执可在 15 秒核对窗口内补充远端事实，本地终态和下游执行资格保持锁定。 |

Mock 使用可控时钟。人工等待 120 秒，自本地受理起恢复排队及提交核对共 30 秒，远端受理后结果等待 30 秒。单次调用沿用 4B 请求上限且受阶段剩余时间约束，取消核对沿用 4B 的 15 秒独立窗口。阶段截止只设一次，行锁取得后读取时钟。补偿扫描、领取、轮询、结果就绪和输出提交统一读取当前有效阶段的期限。正式时限和容量待双方确认。

### 4.4 幂等与停止补偿

- **提交幂等。** 先核验原会话、当前权限、交互和修订，再检查既有回执。相同提交标识及答案返回已有受理或进度。同键异参或新键消费已受理交互返回冲突。终态表单清理后，在保留期内通过交互修订和摘要比对已有回执。首次提交必须通过保存的表单校验，无效输入不写入接受事实。远端提交键绑定同一次调用、原远端交互及修订，响应丢失和补偿都沿用该键。
- **停止与发送竞争。** 4C 发送许可、主动停止、阶段到期、输出提交共用原执行行判定。停止先取得判定权时，即使本地已接收答案，也拒绝发放发送许可。实际发送前若能确定停止已生效且传输尚未接手，放弃发送。传输已接手或无法证明是否接手时按在途或未知处理，停止后只做核对。网络调用在锁外执行。Mock 分别验证停止先于发送许可和请求在途两种顺序。正式接口需确认取消与提交在途时的可核验事实。
- **远端取消。** 主动停止或阶段超时在同一事务关闭本地输出，并按 4B 建立一个取消意图。沿用原 Run ID、取消键和补偿入口。已知远端终态时只记录事实，取消受理与已确认取消分开展示。失去原运行权限时停止外部动作，保留最后可信状态。
- **漏投与 Worker 失联。** 沿用 4B 按可信租户扫描的补偿装配，增加 4C 阶段分流。事务提交后唤醒，漏投仅补投尚未领取的同一恢复派发。已领取任务失联时在原窗口内按关联做只读核对，期限后关闭本地运行，并按 4B 规则收敛远端事实。快照损坏、领取失效或下游开始后 Worker 退出时不自动重跑原图。只读核对和图恢复分别领取，旧任务写回必须匹配当时的阶段和领取标识。
- **隔离装配。** 4C 补偿启用时，把 `register_interaction_resume(app)` 返回的任务传给 `register_long_task_reconcile(..., resume_task=...)`。补投按秒限频，始终使用持久化的原执行、交互及派发标识。传输接手后的回执核对使用原 Run、远端交互标识、修订和提交键，单次核对租约最长 5 秒。若 Agent 输出已提交但 Workflow 执行行仍在运行，扫描在结果阶段截止时关闭执行行并保留 Agent 节点成功事实。

## 5. 浏览器契约与落点

| 接口或模块 | 设计落点 |
| --- | --- |
| 现有 Workflow WebSocket `check_status` | `WorkflowClient` 通过注入的 `BrowserPlatformAgentRuntime` 读取已授权的 4C 执行。显式指定执行 ID 时仅查该执行。无显式 ID 时先解析当前可信引用，Redis 引用丢失后只在同一授权会话存在唯一活跃 4C 执行时恢复，歧义不猜测。4C 等待分支直接返回已保存的交互视图，不走原生输入重发或自动新运行。 |
| `processing/info` 的 `agent_interaction` | 返回执行 ID、本地交互 ID、修订、状态版本、阶段、截止时间及可提交时的文本表单。Worker 只推送有待办的提示，Client 收到提示后调用 `check_status`。表单由会话状态入口再次授权后返回。Client 按会话、执行、交互和单调状态版本忽略旧帧，重连恢复同一表单或提交状态。 |
| WebSocket 动作 `agent_interaction_submit` | 参数为执行 ID、本地交互 ID、修订、提交 ID 和文本答案，身份由现有会话准入提供。响应表示本地受理，远端受理随同一执行状态更新。该动作进入交互端口，原生 `input` 保持原路径。提交动作日志只记录动作和连接追踪字段。 |
| 现有 WebSocket `stop` | 对 4C 会话复用原执行定位及 `stop_long`。即使当前连接没有活跃 Redis 读取器，也能通过原执行 ID 停止等待中的运行。持久化停止后返回，再通知 4B 补偿。 |
| Client 与 Platform | Client 复用共享 `WorkflowForm` 的纯文本输入，未确认的答案和提交 ID 只留在页面内存。Socket 重连后，服务端仍返回原交互及修订时沿用该提交 ID。受理、停止或超时后关闭输入，状态与取消继续按执行归并。Platform 从固定版本响应读取交互支持和隔离装配可用性，仅异步模式可显式启用。 |
| 应用、领域与 Worker | [应用端口](../../../src/backend/bisheng/workflow/application/platform_agent.py) 负责授权和原执行定位，[领域服务](../../../src/backend/bisheng/workflow/domain/services/platform_agent_service.py) 负责 Provider 交互和安全状态，[执行仓储](../../../src/backend/bisheng/workflow/domain/repositories/platform_agent.py) 负责同一行判定。拟在 `workflow/graph/platform_agent_interaction.py` 接入窄的等待点校验，在 `worker/workflow/platform_agent_interaction.py` 接入阶段执行器。复用 [4B 补偿入口](../../../src/backend/bisheng/worker/workflow/platform_agent_long_task.py)，仅由隔离环境装配。 |

查询、提交、领取、远端操作和输出各按原用户及资源的当前权限复核。当前会话归属、Workflow `use`、原租户／接入方、身份版本与原连接策略必须匹配，Provider 校验 Agent 操作资格。权限服务暂不可用时停止相应操作，未领取的派发可在原期限内重试。日志、回执、消息与检查点均不携带令牌或委托凭据。

浏览器读取绑定 WebSocket 路径上的 Workflow 和会话。执行记录持久化可信登录来源，昆联来源另绑定身份关联标识。Redis 引用丢失后，在原执行仍活跃时仅补回空引用，再按同一执行读取输出流。Client 在交互和取消核对期间每秒读取状态。

新建执行前校验已有会话归属，读取结果前复核原会话、实际用户、Workflow 和 Agent 权限。显式停止只处理指定执行。断线期间发出的停止在重连时先于状态查询和答案重试发送。无效提交返回可回查提示，Client 保留状态版本并重新取得表单。权限校验失败时返回安全错误，Client 清理本地表单和未确认答案，停止轮询并忽略已缓冲的交互状态。

没有历史输出的会话首次打开时，Client 在 `init_data` 附带 `initial_open`。已停止的 4C 会话刷新时应回读原终态并保持输出次数，显式重跑沿用原启动动作。客户端断线后的连接清理应保留该会话的运行事实。

毕昇浏览器消息示例如下。修订由服务端生成并按不透明字符串回传，状态版本为同次交互内单调递增的整数，截止使用 UTC 时间。表单只在有权提交且仍处于等待时返回。4B 长任务摘要继续承载取消事实。

```json
{
  "agent_interaction": {
    "execution_id": "a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0a0",
    "interaction_id": "interaction-1",
    "revision": "1",
    "status_version": 1,
    "phase": "WAITING_INPUT",
    "expires_at": "2026-11-09T08:00:00Z",
    "form": {"type": "text", "label": "补充信息", "required": true, "max_length": 2000}
  }
}
```

提交动作回传 `execution_id`、`interaction_id`、`revision` 和客户端生成的 `submission_id`，以及字符串 `answer`。表单标识、状态版本和阶段期限来自服务端。
