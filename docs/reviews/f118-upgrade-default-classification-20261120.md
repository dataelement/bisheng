## 实施

- 历史准备保存完整选中事实和计数提示；真正阻塞在 apply 写入前拒绝。新策略不改写旧制品。
- 全局缺父、平面普通文件必须证明 SQL/FGA/历史权限操作不存在，保留原行及物理内容。新 M2 控制页保存原行指纹及独立保留证明；M3、续跑和 M4 签发 Coverage 前重新验证全局父缺失、SQL 权限和完整 Store 的对象/入向边。
- 旧模型原名称及原索引不变，来源版本包含名称哈希，不伪造模型目标。注册后的来源可读取失效原因，执行拒绝；显式更换合法 Embedding 走原授权、模型绑定和重建事务。新建、复制和导入仍走严格提取器。
- 成功 NORMAL 文件的权限空集经全局检查后，仅通过原生 RESOURCE_CREATE 初始化 INHERIT；不添加个人/全员 Grant。原创建者和父 mode 也进入计划并重验。
- FAILED_CLOSED GRANT_MUTATION 复用原 operation/tuple、校验和、pin 和版本围栏；SQL 授权意图冻结，native recovery/finalizer 负责精确 AFTER 与 SQL 收尾。中断沿原回执续跑，不直接改 CURRENT。

### 删除权限已关闭、业务行仍在（AC-143）

真实只读诊断发现 14 个知识范围的当前权限 DELETE 已 FINALIZED 而业务行仍在。2 个完全关闭；12 个普通用户 marker 已缺失、仍有服务账号 marker。不是把业务行伪报物理删除，而是保留数据并闭合原删除意图。默认历史准备冻结原生 DELETE 账本、SQL mode/Grant/来源、业务指纹及完整对象关系，使用原生预留/版本围栏/投影/finalizer 关闭残留；缺原 user marker 走 checksum-bound 恢复，不手改 SQL 状态或 tuple 状态。相同 scope 的确定冗余父边并入一个 DELETE 投影，避免后续父修复覆盖关闭意图。新清理计划 schema 2 防止旧脚本忽略字段，原 schema 1 计划仍原样读取。

M2 控制页明确保留物理存在事实和原删除证明，强制 marker restore=false，两个主体的实际 enabled 均缺失才允许冻结；完整目标图验证确保迁移后仍关闭。M3/续跑及最终 Coverage 前原生重读账本及业务身份，源配置仍完整登记。正常成员元数据转换不构成 FGA 授权；没有新 Grant/enable 写入。未知用户 marker、外国 scope、未完成/变化账本及 pin/业务漂移拒绝。
