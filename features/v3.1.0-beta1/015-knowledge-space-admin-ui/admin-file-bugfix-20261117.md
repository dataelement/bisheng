| BUG-01 | 存在。`SpaceDirectoryRow` 的状态区用 `!folder` 排除了所有文件夹；接口已有 `has_abnormal_files`。 | 表格、列表、卡片均展示服务端允许披露的文件夹异常；正常文件夹不显示异常。保留后端仅向创建者返回该标记的既有规则，不用其他字段推断或扩大披露。 |

| BUG-03 | 存在。后台保留重命名、下载和删除，但缺少标准单项标签编辑、移动、失败重试入口。 | 文件菜单补齐下载、权限、标签、重命名、移动、重试、版本、删除。标签按原接口全量替换；移动和重试只处理该行，不借用勾选的其他行；保留预检、确认、幂等和后端鉴权。文件详情已有元数据及分段管理继续保留。前台特定客户开关下的编码扩展不属于本次标准菜单恢复。 |
| BUG-04 | 部分存在。历史版本抽屉及版本写入实现已存在，但没有直接版本管理/相似文档入口、版本号及相似提示。 | 严格遵循运行时版本开关；已解析文件有空间 edit 时提供版本管理；多版本显示 Vn 和原历史入口，历史读取仍只要求文件 visible。相似单版本文件按空间 manage_permission 展示直接提示，菜单可进入处理面板；上传版本、关联文档及保留两份继续调用原实现。 |
| BUG-05 | 存在。`HeaderTenantScope` 设置管理租户成功后原地 reload，将旧空间/目录/文件 ID 带入新租户。 | 设置成功后整页 replace 到 `/filelib` 或原管理/QA 页签入口，清除旧资源路径、目录、文件、配置及过滤参数；普通页签再按新租户列表选择首空间，无空间时显示空状态。切换失败保持原地址，其他模块保持原刷新流程。 |

第 5 项采用成功切换后回知识入口的方案。整页跳转销毁旧表单、弹窗和请求所有者，原有缓存清理仍执行；使用 replace 避免把旧资源地址作为本次切换的返回目标。手工打开其他租户的旧深链仍由服务端按原隔离规则拒绝，不通过吞掉“资源不存在”错误处理。

## 实现与边界

- `Files` 继续持有目录、批处理及移动流程；单行回调显式传该行。
- `SpaceDirectoryRow` 持有权限、标签和版本弹窗，挂在菜单外，避免 Radix 菜单关闭时卸载弹窗。范围、空间、文件夹、文件、版本标记和功能开关改变后旧弹窗失效。
- `SpaceRowVersionMenu` 共用已有 `detail-actions` 查询 key 获取空间动作；相似提示和版本管理沿用原抽屉，`initialPanel` 只选择初次展示面板。版本历史的既有服务端端点及写入授权不变。
- `KnowledgeTagSelect` 增加可选受控开关；原有触发器调用保留兼容。
- `knowledgeScopeLanding` 只处理 `/filelib` 路由边界，保留经过白名单校验的单一 view 参数；不会误处理 `/filelib-extra` 或其他模块。
