此前用用户提供的普通账号在 116 正常登录并访问 `/dataset`：所属子租户 60、`is_child_admin=false`、有效菜单含 `dataset`。列表请求 HTTP 200、业务码 19801，文案为共享模型只读；页面没有模型调用。正式 tag `v3.0.0`（`5bffc2ed`）同样在整个 finetune 父路由和数据集端点使用 `get_tenant_admin_user`，前端则按菜单显示入口，故为原有权限冲突，不是模型故障。

## 实现与兼容边界

入口统一调用 `get_dataset_user`，复用当前有效菜单断言；没有新增角色、权限模型、错误码或数据库结构。模型端点自身管理员依赖保留。创建业务下移到 Service；QA 内容通过既有 permission application `require_business_action`，菜单不作为资源动作的兜底许可。

全局超管和当前租户管理员保留与既有导航一致的固有数据集能力，不强制另补角色菜单；管理员资格通过已认证身份和统一 permission identity 协议确认。普通用户仍逐请求经过有效菜单断言，管理员能力也不扩大跨租户数据范围。

下载先按 URL 在严格当前租户查找数据集，再签名该行的 URL。个人微调上传没有数据集记录，使用独立租户/本人分区证明；不认可无归属的任意旧键。正式数据集对象使用另一分区，删除后不能走个人暂存兼容分支重新下载。

本地导入使用新的 `/api/v1/finetune/job/file/preset/upload`，返回 `file_path`；创建字段 `name/files/qa_list` 不变。临时桶对象绑定当前租户/本人，创建只用 SDK 读取该已验证键，不再下载任意请求 URL 或服务器本地路径。存量数据库数据集仍可凭同租户记录下载；旧通用暂存或无归属个人微调文件需重新上传。前后端应配套升级，不迁移或补写旧数据。

路由审计 JSON 由实际应用生成器刷新，增加数据集上传的 TENANT 声明，同时补齐基线已有的审批候选人路由清单遗漏；未修改审批业务。浏览器运行时的作用域处理不依赖该审计 JSON。数据集页的身份 key 使用真实 `leaf_tenant_id`（旧 `tenant_id` 可能为 null），管理租户仍随既有事件刷新。
