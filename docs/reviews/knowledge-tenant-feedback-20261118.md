## 冲突场景与继续操作方式

| 已知状态或冲突 | 提示中的业务含义 | 继续操作 |
| --- | --- | --- |
| 文件WAITING / PROCESSING | 文件正在排队 / 解析，不能重复处理 | 等待原任务，查看任务记录 |
| file_reprocess / file_resplit | 正在重新解析 / 重新切分 | 在处理任务查看进度，结束后再试 |
| embedding_rebuild / 空间REBUILDING / model_transition | 空间正在重建向量索引 | 查看任务记录，失败时重试原任务 |
| metadata_schema_change | 正在同步元数据字段 | 等任务结束，失败项单独重试 |
| move_index | 文件正在移动 | 查看移动任务，失败时先重试该任务 |
| space_copy / 空间COPYING | 正在复制文件，相关输入还不能被修改或清理 | 查看复制任务，等待输入复制完成 |
| copy_permission_not_ready / copy_vector_collection_not_ready | 副本权限或索引初始化未完成 | 查看并重试复制任务 |
| source_space_move_input_required / space_transfer_input_required | 移动或复制仍依赖源数据 | 先处理目标任务，不能靠删除源空间解除保护 |
| move_pending_source_input / move_source_input_required | 移动尚未转移数据或完成源数据清理 | 在移动任务重试原任务 |
| model_provider_operation_active | 相关向量模型仍被任务占用 | 等该任务完成后修改模型 |
| reference_target_deleting | 资源正在删除 | 等待删除完成 |
| processing_scope_not_empty | 有历史文件或分段，不能直接换模型 | 从模型与索引发起重建 |
| 文件、版本或恢复记录不完整 | 当前状态不支持操作，不应误称为“正在解析” | 刷新文件/任务；仍异常时联系管理员核查版本或任务记录 |

后端只返回状态或任务类型枚举，不新增任务内容、其他文件名或原始异常文本。显示逻辑只允许注册过的本地翻译，未知原因、原型键及技术参数不会直接展示。

## similar-pending：测量与优化方案

### 116只读结果

空间3810共有51个逻辑文档、57个物理文件；25个文件处于待处理相似状态，其中1个已经属于多版本文档，当前接口跳过后仍需处理24个独立文档。

调用链是`KnowledgeVersionService.list_pending_similar_files`逐文件调用`get_similar_candidates_for_file`，再进入`KnowledgeVersionReadService.similar_candidates`。每个文件都重新读取配置、解析源锚点，并重新分页扫描同一空间的候选文档、构建权限目标和检查可见性。

使用116容器内真实Repository和数据库连接，设置会话事务只读，计数候选扫描SQL：

| 子阶段 | 候选数量 | SQL次数 | 实测耗时 |
| --- | --- | --- | --- |
| 一次候选Repository扫描 | 51 | 6 | 52.60ms |
| 连续重复24次候选Repository扫描 | 每次51 | 144 | 合计515.39ms |

第二行连接和数据库缓存已热，不能用两行时间简单线性推算。以上计时不包括配置读取、身份解析、源锚点、权限快照/可见性检查、完整HTTP调度和序列化。截图中的18.85秒是完整请求耗时；数据库候选扫描的约0.515秒不足以解释其余部分。没有获得对应请求完整trace，剩余耗时仍需分阶段定位，不能宣称已锁定某个FGA或数据库慢调用。

### 建议实施顺序

1. **先增加阶段耗时和调用次数指标**：pending读取、源版本/版本链、配置与actor、候选扫描、权限快照、可见性判断、SimHash比较、总耗时。只记录计数与耗时，不记录文件内容或凭据。
2. **一次请求复用候选扫描**：当前空间候选只分页扫描一次；验证有效主版本后，构建本次请求的候选事实集合。对24个源文件复用该集合，减少23次相同扫描。以本样本计算，候选读取SQL应从144降至6；这只是该子阶段的目标，不能当作完整请求时延承诺。
3. **批量解析源文档与版本链**：一次读取pending对应的版本锚点、版本计数与主版本，避免逐文件两次查询。配置、actor和请求身份只解析一次。
4. **权限计算按资源批量复用**：仅在本次请求、同一actor与租户范围内复用已验证目标和可见性结果。先裁剪不可见候选，再计算相似度；保留源文件校验、主版本校验和输出权限边界。不得使用跨用户全局缓存或超级管理员捷径跳过源校验。
5. **数据量继续增长时分页/按需读取**：pending列表分页；可考虑只为当前选中文档加载推荐，避免打开弹窗时为全部待处理文件计算。该交互改动需要单独确认，不能仅靠截断结果伪装提速。

验收应覆盖24/100/1000待处理文件、候选跨页、非管理员仅可见部分文件、主版本变化、源文件失效、管理租户切换。比较总耗时P50/P95与各阶段调用次数；确保推荐排序、阈值、最多3个推荐及权限结果保持一致。本次未实现或部署此性能重构，因此没有优化后端到端耗时。
