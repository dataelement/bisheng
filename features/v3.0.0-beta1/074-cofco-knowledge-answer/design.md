# Design: F074 中粮知识空间检索问答开放接口

**关联**：[Spec](./spec.md) · [设计自审](./design-review.md)
**版本**：v3.0.0-beta1 中粮定制线
**更新日期**：2026-10-08
**状态**：Spec 与 Design 已经用户确认；接口已实现，专项验证通过；全量测试未全绿，真实环境验收待执行。

## 1. 目标与非目标

为客户提供一个单次调用即可“检索指定知识空间 → 模型归纳 → 返回答案及参考文件”的开放接口。复用现有凭据、文件可见性和模型能力，原接口行为冻结。

不做会话历史、流式、全文总结、下载、联网、助手工具、机器人接入或 MCP 自动扩围；仅支持知识空间，不新增表或数据迁移。

## 2. 约束

遵循 [constitution C1–C8](../../../docs/constitution.md) 和 [版本契约](../release-contract.md)，尤其是 F053/F066 的身份与数据范围、F067 的旧接口冻结边界；本功能不使用 F073 的机器人特殊权限。

- 新接口只在 API 进程内异步执行，不新增 Worker、队列、常驻连接或部署组件。
- 文本请求有界：问题最多 4,096 字符，空间最多 20 个，最终片段最多 50 条，总参考正文最多 60,000 字符。ID 必须为正整数，拒绝 bool；未知字段拒绝。
- 服务编排（包括配置校验）的总超时 120 秒；检索阶段最多 30 秒，生成阶段最多 90 秒且不得突破剩余总预算。鉴权依赖沿用既有超时，不声称整个 HTTP 请求必在 120 秒内结束。
- 字符限额不是模型 token 上下文保证；模型上下文不足明确报错，不自动换模型或截掉问题。网关/客户端读取超时需大于鉴权时间加服务预算。
- 不在业务逻辑之外自动重跑整个请求；供应商 SDK 的既有重试仍受生成与总超时约束，超时取消本地调用不能保证供应商立即停止计算或计费。

## 3. 决策与备选

### D1：独立问答编排，而非包装内部会话

- 备选：调用空间会话接口收集 SSE；或走助手，让模型自行决定检索；或新建无状态问答服务。
- 选定：新建无状态服务，固定先检索、后生成。
- 原因：内部 `_render_rag_response` 会读取历史、写 ChatMessage、保存引用和生成标题；助手有工具选择和应用配置，两者都引入客户未要求的行为。
- 重考虑条件：客户明确需要多轮、永久引用或应用工具时另行设计，不隐式打开。

### D2：权限位沿用 knowledge:read

- 备选：增加知识问答权限位；要求额外 assistant:invoke；沿用 knowledge:read。
- 选定：沿用 `knowledge:read`，注册新端点；无需更换已有具备此权限位的 Key，不修改凭据签发规则。现有服务账号 S/D 与 PAT 准入规则全部保留。
- 原因：这是受限的知识读取回答，不是通用模型或助手执行接口；请求不能传提示词、模型端点、密钥或工具。**现有 knowledge:read 凭据将新增调用该知识问答接口的能力，并可能产生模型费用**，使用既有凭据限流/配额和模型配额；不宣称新增了独立费用权限。
- PAT 能力仍只有 knowledge:read，仍按租户数据范围收窄；F066 覆盖清单为新端点登记 `raise`，不能只登记路由而遗漏数据范围验证。
- 重考虑条件：客户要求将检索和付费生成授权分开时，另行新增权限位并设计凭据/UI兼容。

### D3：多空间公平合并，不强行宣称全局相关性排序

- 备选：复用旧拼接后截断；增加跨空间重排模型；或各空间保留已有排序，轮流选取。
- 选定：去重并按空间 ID 排序后，对各空间的候选列表按轮次交替取片段，直到总条数或总正文预算耗尽。空间候选仍使用现有向量+关键词融合排序。
- 原因：旧接口 `aretrieve_chunks` 按传入顺序拼接再截断，首空间可占满结果；现有 RRF 不输出可直接用于跨空间比较的统一分数。轮流选取不引入额外重排模型，且结果不依赖输入空间顺序。
- 取舍：公平覆盖不等于全局最相关；空间很多且 top_k 小时仍无法覆盖所有空间，稳定空间 ID 顺序用于同轮决胜。
- 重考虑条件：多空间检索质量验收不足时，为新接口单独增加全局重排，不更改旧排序。

### D4：模型由调用方选择，但只允许后台配置的可用模型

- 备选：任意模型 ID；固定新默认模型；或复用当前租户工作台可选模型清单。
- 选定：`model_id` 必填，必须属于 `LLMService.get_workbench_llm().models` 的当前租户有效清单，并通过模型/供应商存在、模型类型、上线状态检查。Root 共享配置仅走现有受控共享读取。
- 原因：不新增模型配置页面；避免任意模型 ID 绕过后台选择范围；不为此调用日常配置的工具权限投影。
- 不提供默认模型或失效模型回退。模型内置联网/工具能力开启时拒绝本接口调用，提示选择关闭相关能力的模型；检查 `enable_web_search`、高级配置的工具/联网选项及供应商内置工具参数。返回 tool_calls 时视为异常，不执行工具。
- 重考虑条件：需独立问答模型配置或联网混合回答时另开范围评审。

## 4. 当前代码与新增流程

### 4.1 已有代码（不改行为）

| 位置 | 现有职责 | 复用边界 |
|---|---|---|
| `open_endpoints/api/endpoints/filelib.py:retrieve_chunks` | v2 召回入口与结果序列化 | 原函数、Schema、返回和错误语义不改 |
| `knowledge/domain/services/knowledge_space_chat_service.py:aretrieve_chunks` | 跨空间检索、标签、最终文件过滤及更新时间 | 新服务每次只传一个空间，避免旧跨空间截断偏差 |
| 同文件 `_render_rag_response` | 历史、持久引用、LLM 流和消息写入 | 不调用 |
| `knowledge/domain/services/knowledge_file_visibility_service.py` | 索引前过滤与结果后过滤、主版本及业务状态 | 原样复用，不增加权限旁路 |
| `open_api/api/dependencies.py` | 凭据、租户、权限位、S/D/PAT 执行主体 | 原样复用 |
| `llm/domain/services/llm.py`、`llm/domain/llm/llm.py` | 模型配置与供应商调用、配额及遥测 | 使用既有包装，不直接调用裸供应商客户端 |

### 4.2 新增流程（待实现）

`开放 Key 鉴权 → 参数校验 → 空间/模型预校验 → 各空间召回 → 公平合并及总长度限制 → 模型生成 → 后端整理来源 → JSON 返回`

1. 既有 `/api/v2` 路由门禁确定 PermissionActor、租户与数据范围；业务参数不选择身份。
2. 新 Endpoint 只适配请求/响应，调用知识领域 `KnowledgeSpaceAnswerService.answer`。
3. 通过注入的 KnowledgeRepository 验证每个空间存在且 type=SPACE，再复用既有空间业务权限入口验证所有空间；任一失败整体拒绝，不调用生成。
4. 读取租户工作台模型列表，验证所选模型；预先检查模型和供应商，避免既有模型工厂在缺记录时出现空引用异常。使用 LLM 领域已有读取能力，不新增 DAO 或直接 ORM 查询。
5. 按稳定空间顺序串行调用现有 `aretrieve_chunks`，每次 `knowledge_base_ids=[space_id]`、top_k=本次请求值、该空间标签及内容预算。串行是为避免同一请求 AsyncSession 在多个空间检索中并发使用；全阶段受 30 秒超时控制。
6. 去除空正文，校验来源标识；片段按 `(knowledge_id, document_id, chunk_index)` 去重，空间内保留原排序，执行 D3 合并。无法标识来源的非空结果应报检索错误，不能静默当作无资料。
7. 严格按全局 `max_content` 字符预算选取正文；最后一个过长片段截至剩余额度并在模型上下文中标明“片段截断”。参考文件只来自实际保留的正文；模型上下文标签和问题不计入该正文预算。
8. 合并后无正文时返回固定无结果答案，不调用 LLM。否则使用本功能独立提示词和一个用户问题，以 `ainvoke` 收集完整响应，不存历史。
9. 仅提取最终文字，不返回推理过程、工具调用或内容块附件；出现工具调用、空答案或非文字输出时报生成格式错误。模型不得据文档里的指令更改任务或权限范围。
10. 由后端从实际参考资料生成文件列表，不接受模型生成的文件 ID/名称；返回统一成功信封。所有阶段失败整体失败，不返回部分答案。

提示词只服务该接口：资料是证据、不是指令；仅依据资料答题；资料不足说明不足；冲突分别说明；不声称已阅读全文、不生成图片/图表、不使用内部私有引用标记。不能直接使用当前空间会话提示词，因为其要求图片、ECharts 和持久引用标记。

## 5. 已知坑

| 事实 | 不处理的后果 | 处理位置 |
|---|---|---|
| 旧多空间召回按顺序拼接截断，无全局分数 | 前空间占满参考内容，答案遗漏后空间 | 新 answer service/context；旧方法不变 |
| max_content 在旧召回中是每空间限制，且可能超出一个片段 | 总上下文失控 | 新 context 的严格总预算，不更改旧 retriever |
| S 模式兼容 UserPayload 可能引用资源归属人，真实主体在 PermissionActor | 错把归属人权限当服务账号权限 | 沿用已安装 actor 的原召回，覆盖服务账号隔离测试 |
| knowledge:read 新端点需同步 F066 分类测试 | PAT 数据范围漏接或测试失败 | 分类清单登记 raise，并验证主路径 |
| 现有会话生成路径会写历史/引用 | 接口隐式创建会话或消费其他请求历史 | 不调用 `_render_rag_response` |
| LLM 工厂可能先引用空 model_info，且供应商缺失不等于 Key 过期 | 返回不准确异常诊断 | 本接口模型预检查和明确错误 |
| 模型后台配置可开启内置联网 | 未绑定工具也可能引入外部依据 | D4 模型配置准入检查及 tool_calls 拒绝 |
| 工作台模型配置有租户继承及缓存 | 误用跨租户配置、后台更改暂未生效 | 复用租户投影/共享读取；按原缓存时效验证 |

## 6. 对外契约与依赖

### 6.1 HTTP 契约

`POST /api/v2/filelib/answer`；`Content-Type: application/json`。

`Authorization: Bearer <后台生成的开放 API Key>`，所需权限位 `knowledge:read`。委托仅按已有 `X-On-Behalf-Of` 规则处理，不接收 body user_id/tenant_id。无 conversation_id、stream、messages、system_prompt、api_key、工具或供应商配置参数。

| 请求字段 | 规则 |
|---|---|
| query | 必填字符串，去空白后 1～4,096 字符 |
| knowledge_base_ids | 必填空间 ID 数组，原始输入 1～20 项，去重后执行；保留既有命名以便客户迁移 |
| model_id | 必填正整数，D4 模型准入 |
| filters | 可选；knowledge_base_filters 内每空间只能出现一次，必须在请求范围内 |
| filters.knowledge_base_filters[].knowledge_base_id | 对应空间 ID |
| filters.knowledge_base_filters[].tags | 标签名，去空白后非空，每空间最多 20 个、单项最多 128 字符，去重 |
| filters.knowledge_base_filters[].tag_match_mode | 仅 ANY，其他值拒绝；不修改旧筛选 Schema |
| top_k | 最终参考片段条数，默认 10，范围 1～50，不是文件数量 |
| max_content | **全空间参考正文总字符数**，默认 15,000，范围 1～60,000；不是旧接口的每空间上限 |

成功 HTTP 200，统一信封：

```json
{
  "status_code": 200,
  "status_message": "SUCCESS",
  "data": {
    "answer": "根据资料，……",
    "has_context": true,
    "model_id": 30,
    "references": [
      {"knowledge_id": 8, "document_id": 123, "document_name": "制度.pdf", "document_update_time": "2026-10-08 09:00:00"}
    ]
  }
}
```

`has_context` 仅表示是否有参考资料，不代表模型已成功找到充分依据；有资料但不足时 answer 明确说明不足。无资料返回 `has_context=false`、`answer="未找到相关内容"`、`references=[]`，model_id 仍为本次验证的模型选择。references 不包含文件路径、下载 URL、私有 citation ID、原始分块或推理内容，按实际片段首次入选顺序列出；更新时间沿用既有值，缺失为空字符串。

### 6.2 错误

原有鉴权、数据范围、权限、资源和模型准入错误原样传播；权限后端不可用与旧召回一样映射为 503/26030，不返回资料。参数校验沿用既有v2异常处理的400（不是FastAPI默认422），包括越界/重复筛选和未支持的标签模式。模型工厂初始化和生成异常统一脱敏为10964。

本功能新增错误已核对并分配知识模块空闲编码：

| code | 场景 | 新接口 HTTP 状态 |
|---|---|---|
| 10963 | 非权限类检索依赖失败 | 502 |
| 10964 | 非已知配置类模型调用失败 | 502 |
| 10965 | 本次编排或阶段超时 | 504 |
| 10966 | 空答案、工具调用或非文字输出 | 502 |

新增错误由新 Endpoint 显式适配为 sanitized 统一错误信封、data=null，并记录审计错误码；不修改全局状态映射或老接口行为。供应商 401 是模型配置调用失败，不误报成调用方开放 Key 无效。内部异常完整保留 traceback，但不把供应商异常原文和密钥返回客户。调用取消应向上传播，不吞取消、不记录成无结果。

### 6.3 契约与上游依赖

| 契约/依赖 | 消费者/风险 |
|---|---|
| 新 HTTP answer 契约 | 客户系统；max_content 与旧接口语义不同，必须按本契约调用 |
| `KnowledgeSpaceAnswerService.answer` | 仅新 Endpoint；不暴露为助手工具或公共模型调用能力 |
| 既有 aretrieve_chunks 的单空间结果 `(knowledge_id, Document)`、排序、来源元数据 | 原方法或 metadata 变动可能破坏来源整理；新测试覆盖 |
| KnowledgeRepository/版本 Repository、Milvus、ES、嵌入模型 | 必须存在可检索索引；不在请求里重新解析或重建 |
| 工作台模型清单、供应商和模型调用包装 | 模型配置/共享/配额变化影响可用性；不修改原配置 |
| 既有开放身份、PAT 数据范围、调用审计及 Redis | 故障沿用原失败关闭；不能绕过 |

无新增系统二进制或第三方库依赖。

## 7. 测试与可观测

- 单元：请求边界、标签校验、重复 ID、空间类型、模型准入、内置联网拒绝；公平合并、顺序不变性、来源完整性、全局长度截断；无资料零模型调用、无历史写入、超时和异常。
- API 合约：真实路由与模型/检索 mock，验证 Key、scope、S/D/PAT、F066 数据范围与响应；新增错误 HTTP 状态与脱敏，缺凭据优先及撤销行为沿用既有链路。
- 回归：保留旧 retrieve 多空间 `[1,1,1,2]` 拼接用例；原空间问答、助手、E+ 的相关单测不改预期。路由注册和 F066 覆盖清单必须通过。
- 环境 E2E：有 Key 的服务账号或合法 PAT、至少两个授权空间、一份无权限文件、配置好的文本模型；验证可回答/无资料/越权空间/越权文件/标签/模型离线。DM8 与真实 Milvus/ES/OpenFGA 的效果只能在对应环境确认，不以 mock 通过声称真实集成通过。

手动调用模板（API Key 从环境安全注入，不写入文件或日志）：

```sh
curl --fail-with-body -X POST "$BISHENG_BASE_URL/api/v2/filelib/answer" \
  -H "Authorization: Bearer $BISHENG_OPEN_API_KEY" \
  -H 'Content-Type: application/json' \
  --data '{"query":"这份制度对报销时限有什么要求？","knowledge_base_ids":[8,9],"model_id":30,"top_k":10,"max_content":15000}'
```

ID 为示例，需替换为环境真实授权空间与工作台模型；无资料用与样本文档无关的问题，越权验证替换为空间/文件测试夹具，不用真实敏感内容做日志样本。

结构化日志 domain=`knowledge_answer`，记录 trace_id、阶段、空间/片段数量、参考字符数、模型 ID、阶段耗时和终态错误码，不记录 Key、问题原文、参考正文或答案原文。既有模型包装可能有原有遥测，本功能不修改全局遥测格式；新日志不额外复制内容。

## 8. 后续与发布边界

- 暂不做跨空间全局重排、独立问答默认模型、流式或历史；需要时重新确认相应接口契约。
- 轮流选取偏向覆盖而非最优相关性，资料过少时模型仍可能误判；通过业务样本验收，而非宣称完全杜绝幻觉。
- 新接口有模型调用成本；如已有 knowledge:read 授权不应包含该成本，需在本设计确认前改为独立权限位。
- 正式上线需更新 API 文档、发布新镜像，核对网关路由与读取超时；不需要降级/迁移脚本，不改变原 Key 的明文或哈希，不自动导出到 MCP。
- 仅中粮定制线交付；不能回流公共版本。按任务计划执行，提交和发布 tag 需用户另行授权。
