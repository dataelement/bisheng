## 二、统一生效规则

建议把以下四层明确分开，并在页面分别表达来源与状态：

1. **配置继承**：Root 提供默认选择和参数。它不产生模型授权。
2. **提供商共享**：决定该子租户是否可使用 Root 提供商下的模型。保持当前提供商级共享粒度。
3. **租户内可见范围**：决定本租户哪些成员可在 Chat / Work 主动选择该模型。
4. **价格与积分**：模型价格由模型所属方管理；积分设置及额度属于调用租户。

普通用户可选模型应满足：本租户自有或实际获共享 + 模型上线且能力匹配 + 当前租户的成员可见规则。真正调用还需通过相关业务权限、额度、提供商限额与运行条件。

后台默认模型用于摘要、向量化、评测等系统能力时，按业务执行身份和实际执行租户验证。不要直接把“Chat / Work 可见范围”当作这些内部任务的授权，否则隐藏聊天候选可能误停文档解析。反过来，允许文档解析使用模型，也不应自动把它开放为用户聊天候选。

## 三、继承到未共享模型的处理

推荐采用“保留来源配置、标记失效、阻止实际使用”的规则：

- 管理页能看到继承的原模型及具体原因，例如“继承自 Root；提供商尚未共享给本租户”。这类模型仅作为配置修复信息，不进入可执行候选列表。
- 不因继承自动授予共享，不悄悄换成另一个模型，不把 Root 的其他未共享模型扩展成可选项。
- 由有权的 Root 管理员显式共享对应提供商，或由子租户管理员切换为本租户配置，选择已获授权模型。
- Root 保存默认配置时，给出启用继承的子租户影响预检；Root 自己可使用的未共享模型仍可用于 Root，不强制全集团共享。
- 提供商开启共享后，必须展示实际覆盖结果和未完成租户。新挂载/重新启用租户也应落实同一共享意图；失败有可恢复记录，不能仅以“存在一个共享 tuple”代表“已共享给全部子租户”。
- 原模型恢复共享后，原引用经复核可恢复使用，不需要用户重新选择；若处于相反命令的持久计划中，仍按原计划恢复规则处理，不能自动清锁。

建议统一状态：可用、未共享、模型下线、模型删除、类型不匹配、能力不足、可见范围不允许、权限服务暂不可用。价格缺失和基准无效另作计费/展示状态，不混为模型授权错误。

## 四、继承粒度和保存语义

推荐保持现有五类配置的**栏目级继承**，不引入字段自动拼接：

- 每个栏目显式显示“继承 Root”或“本租户配置”。子租户可以只自定义助手栏目，其余栏目继续继承。
- 修改继承栏目时，以显式动作“转为本租户配置”建立一份本地配置；保存前检查其中全部模型引用，不把未共享的 Root ID 顺带落入新配置。
- 提供“恢复继承”操作，展示差异并按原配置/引用服务变更，不直接删数据库记录。
- 本地显式为空、关闭可选能力，和“没有本地配置”分开。空值不悄悄重新开启 Root 的能力。
- 界面文案改成“本栏目未自定义时继承 Root”，避免当前“未配置项继承”让人误以为每个空字段分别继承。
- 继承徽标表示当前已生效配置的来源。编辑草稿不应立即让人误认为来源已改变。

模型可见范围、积分设置及逐模型能力开关应有独立的来源标签和保存反馈；不能因它们即时保存就把整个模型默认栏目固化成本地副本。

## 六、积分倍率、模型价格与能力开关

### 6.1 模型价格可随模型共享

Root 共享模型继续读取 Root 该模型的同一份价格，子租户只读，不显示可提交的“修改价格”入口；子租户自有模型由本租户定价。价格属于实际模型 ID，不按名称匹配，避免同名模型串价。

### 6.2 倍率是计算结果

倍率不作为独立授权或可手动保存的数值跨租户复制。当前按换算到同一币种后的价格计算：

`倍率 = (3 × 模型输入价 + 模型输出价) / (3 × 基准输入价 + 基准输出价)`

各租户可选择自己已获授权、上线且有正数输入/输出混合价格的基准模型。相同基准和计价条件会得到相同倍率；不同基准/汇率可能产生不同倍率。

基准只影响倍率展示，不改变实际扣费。积分单价影响扣多少积分，不直接出现在上述倍率公式里。不要把“积分倍率即时保存”用作页面说明，实际保存的是基准或价格。

### 6.3 积分设置保持租户独立

推荐本期保留币种、积分单价、汇率、基准模型和个人额度的租户隔离；缺省明确显示“系统默认”，不暗示继承 Root。Root 的基准 1143 不能因子租户继承工作台配置而自动成为子租户基准。

若产品要求 Root 统一这些积分设置，另设明确的“跟随 Root 积分设置”选项，并设计覆盖优先级、基准授权检查、变更影响预检和撤销规则；不要将其隐式绑定到“继承系统模型配置”，以免 Root 的积分单价调整无意改变所有子租户后续扣费。

基准不可用时展示具体原因及重新选择入口，倍率显示“—”；不影响其他已授权模型调用。模型价格缺失继续尊重当前“允许调用并按免费策略计费”的既有约定，页面区分“价格缺失”与“管理员明确设为免费”，不在本方案中擅自改为拒绝调用。

### 6.4 支持图片独立处理

当前开关是租户级 DSH 设置，缺省 false，并不会随工作台配置 JSON 自动继承。推荐：Root 定义并维护共享模型的基础能力；子租户继承基础能力，可在本租户关闭，不能把声明为不支持的模型强行开启。图像能力可用还需模型类型/接口适配支持，不等同于已经获得共享。

此项会改变现有租户独立 vision 设置的继承合同，应设计后实施；升级前盘点子租户显式开关，保留明确本地限制，不批量覆盖为 Root 值。

## 七、可见范围是否跨租户

**“全员可见”只表示当前配置租户的全员。Root 全员可见，不直接表示子租户全员可见。**

建议界面改为“Root 全员”“租户回归部门全员”，并提供范围说明。

为使新子租户开箱可用，推荐明确设定以下默认政策：提供商被显式共享后，对没有本地可见设置的接收租户，以独立、可审计的“共享默认：本租户全员”规则启用；已有本地范围完全保留。新租户和新共享模型也按同一规则初始化。

这是新增的接收侧默认政策，不是复制 Root everyone 或 Root 的用户/部门/角色 ID。Root 不同栏目的默认选择也不能冒充这一授权动作。若产品要求默认关闭，应改为明确“待子租户配置可见范围”，不能界面显示已就绪却让所有成员不可选。

当前有 DSH 时“无可见记录”默认隐藏，没有 DSH 时默认可见，存在模式差异。本方案建议接收侧明确落规则，两个模式沿同一业务语义解析，启停 DSH 不改变授权事实；历史无记录如何补齐须先审计、预览，再经确认执行，不能后台自动扩大历史访问。

## 八、其他容易遗漏的边界

1. **影响范围隔离**：本期目标是某个可选槽位失效不阻断无关功能；当前默认模型运行准入按整份来源校验，这一点不能只在前端过滤解决。需要在 F118 来源完整性/槽位使用准入中明确设计，保留原数据和引用登记，不绕过鉴权。
2. **共享意图与实际覆盖**：Root 开关、全部接收租户、停用租户和新租户都要有明确合同。新挂载遗漏、单租户失败、批量部分成功应可查询和重试；禁止用日志一笔带过。
3. **撤销/删除/下线**：预检列出受影响栏目、子租户、已保存应用及任务；保留原有引用保护和显式强制流程。撤销后新调用不得被缓存放行；历史结果与计费记录保留。
4. **已有业务配置**：系统默认的更新不应自动重建知识空间、不覆盖已保存的助手/工作流节点，也不改变正在运行的任务冻结配置；新任务按新配置准入。
5. **默认模型的个人可见范围**：某用户看不到默认模型时，必须有明确策略。建议仅对“尚未选择模型的新会话”按稳定顺序选一个已授权候选并显示实际模型；用户已明确选择或历史会话原模型失效时，不静默替换。所有候选均不可用时明确提示联系管理员。
6. **额度分层**：个人积分和用量归调用租户；提供商每日调用上限当前按提供商 ID 聚合，Root 与子租户共享同一提供商总上限。页面需要说明共享总限额，达到时提示具体限额原因，不能记成“模型未授权”。
7. **缓存与切换**：查询必须随用户、真实租户、当前管理租户和配置版本隔离。切租户关闭旧弹窗、废弃迟到响应，避免 Root 结果写入子租户表单；共享、价格、视觉及可见范围变更应使相关列表及时失效。
8. **界面请求**：统一读取本页合法模型和诊断结果，视觉/价格等元数据按页批量读取，避免每行自动请求报错。已知未共享展示状态；瞬时接口失败统一反馈且可重试，不返回伪空列表。权限服务异常与确实未授权分别展示。
9. **安全和管理范围**：超管切换子租户后的编辑结果必须写向该子租户；不能因超管本人有权就显示普通子租户成员可用。服务密钥、端点凭据继续仅归提供商 owner，子租户接收可调用能力而不接收秘密。直接 API 请求也执行相同校验。
10. **DSH/Chat/Work/工作流一致性**：管理列表、普通用户候选、实际调用使用同一租户可用模型事实；按各自业务附加能力、可见或额度限制。允许展示失效配置用于修复，但不可把修复清单当执行清单。

## 九、实施顺序与验收

### 阶段 1：明确合同、补诊断

确认本方案的三项推荐：未共享模型不因继承获权；共享接收方无本地可见规则时采用独立全员默认；积分设置本期继续租户独立。同步 F022 系统默认、F016 计价及 F118 来源准入相关文档。该变更跨共享、配置与运行准入，走 Full SDD，不将其包装成单点 UI 热修复。

### 阶段 2：统一读取与管理页面

在已有 owner/application 边界内统一有效模型及逐槽位诊断，不让前端拼授权。提供配置来源、权限状态、计费状态及可编辑范围；修复视觉逐行报错、未授权候选、共享模型价格编辑入口、继承文案和租户切换。

### 阶段 3：共享生命周期及运行消费面

落实新租户、新模型、共享变更的接收侧策略，复用权限投影和可恢复计划；补普通用户、后台任务、同步节点及异步 Worker 的真实执行租户校验。设计独立槽位准入，保留已保存引用和历史数据。

### 阶段 4：116 存量恢复（单独授权）

先部署已经推送的 condition:null 兼容修复，再盘点每个提供商的活动计划；特别是 358 存在关闭意图的 PREPARING 计划，不能直接执行开启来补共享。核对 Root 实际共享意图、接收范围和本地可见策略，产出差异清单后再执行。禁止删账本、重签摘要或直接改任务状态绕过保护。

目标验收必须使用租户 69 的普通用户（例如此前反馈的 wangxinlei3），并分别验证管理员视图、候选列表和真实调用；超管管理页面出现模型不算普通用户验收通过。
