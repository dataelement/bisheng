### 模型空值的具体原因

- `subject_id`：全部为 app_self 调用，没有自然人执行主体。原始 NULL 保留，不能填资源 owner。
- `ttft_ms`：30 行的 `is_stream=0`；非流式调用没有流式首 Token 耗时。
- `prompt_tokens / completion_tokens / total_tokens`：22 条 `upstream_failed` 没有返回 usage，保持 NULL；8 条成功记录有实际用量。
- `error_code`：8 条成功调用未发生错误，空值正常。
- `http_status`：现有写入者在错误时记录状态；这 8 条成功记录未写该列。导出保留原值，不反推或回填 200。

能力写入链：`CapabilityBusService._audit` → `capability_audit.record_retrieval`。
有结果对象才记录 `result.total`；没有结果对象则为 None。现行 `csv_bytes` 对 None 输出空单元格，
对数值 0 输出 `0`，不能把两者合并成同一种情况。

- 在 116 只读查询 `model_call_record`、`app_capability_call_record`、`app_access_log`、导出任务和凭据展示元数据；未读取密钥明文、token hash、对话正文或检索正文。
- 调用 116 现行 `csv_bytes` 对白名单原始字段序列化并逐字段比较：模型 30 行、能力 17 行，所检查 nullable/数值字段均为 **0 个不一致**。
- 截图对应导出任务的 final_count 分别为模型 30、能力 7；状态均为 expired，gc_completed_at 有值，读取原 manifest 返回 `NoSuchKey`。因此不能再直接打开用户当时下载的原文件验证全部字节。
- 不创建新导出、不修改任务状态、不补写历史身份、count、Token 或时间，不更新 116 服务。

## 3. 实现边界

### 后端

`RuntimeAuditRepository.with_display_labels` 只增强列表及自然人候选：

- 通过事实中有类型的 subject ID 左连接用户，只读当前 user_name；全局唯一 user_id 的读取范围严格来自已授权审计事实，不新增人员目录入口。
- 同一自然人/服务账号同时作为 caller 与 subject 时，优先使用该行 actor_name 快照；数字相同但类型不同不能互相冒充。
- 能力密钥按 credential ID 和源记录 tenant 同时匹配，只取 prefix/last4 合成掩码；不返回凭据私密名称或散列。
- 缺失或删除资料只导致显示投影为空，不丢原始行，不扩展租户或应用范围。
- 导出继续使用原始 `FIELDS` 和原单一源 SELECT，不增加展示列，也不依赖实时名称表。

### 前端

- 将名称和重复数字列合并，原标识放入现有共享 Tooltip；不修改表格组件样式。
- 执行身份明确区分应用自身、自然人和服务账号；缺少名称时显示带类型的标识说明。
- NULL 显示“未记录”，拒绝且无检索结果显示“未产生结果”，真实 0 保持 0。
- 模型/能力导出弹窗增加空值原因说明；中、英、日三语同时提供。
- 页面说明记录名称与当前账号名称的区别，显示投影不冒充历史身份快照。
