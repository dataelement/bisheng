# Markdown 文档交付约定

## 适用产物

| 文档 | 默认文件名 | 内容规则 |
|---|---|---|
| 需求／PRD | requirements.md | 使用[PRD 写作与完成标准](../../sdd-requirement-validation/references/prd-writing-standard.md) |
| 技术设计 | design.md | 使用[设计文档写作与完成标准](../../sdd-design/references/design-writing-standard.md) 与 [Markdown 模板](../../sdd-design/assets/design-template.md)，保留分层解释、精确契约、追溯和验证安排 |
| 测试用例 | test-cases.md | 使用[测试用例写作与完成标准](../../sdd-test-cases/references/case-writing-standard.md)，包含覆盖矩阵、九列用例表、异常边界清单及自动化标注；不同岗位的用例归各自工程 |

正式交付保存为 UTF-8 编码的实际 `.md` 文件，不能只有聊天摘要、代码片段或把 HTML 改扩展名。需求确认稿也使用 Markdown；未解决事项清晰标注，文档齐全不表示内容已闭环。计划、状态、提测索引及文字执行报告同样使用 `.md`；测试脚本、日志、图像及机器可读配套数据保留各自原生格式。简单 Bug 不因此增加全套文档。

实际位置由[产物存放与维护约定](artifact-storage.md) 统一解析。表中名称是默认名称，用户指定、项目约定及有效登记确定本次位置；各阶段引用同一来源，不因目录分类复制正文。研发用例与独立验收用例分别归各自工程。

## 结构与排版

- 尽量沿用现有 HTML 模板的章节顺序、阅读层次、摘要、表格字段及追溯关系。设计使用配套 Markdown 模板，原 [HTML 模板](../../sdd-design/assets/design-template.html) 保留为结构参考，不要求同步维护两份正式稿。
- 用标题层级和目录替代侧栏导航，用引用块及加粗表达提示／状态，技术细节以子标题直接展开。不要求复刻 CSS、卡片、脚本、折叠按钮、滚动和打印效果；复杂排版可合理调整，保留必要内容及关联关系。
- 表格使用 Markdown 表格，单元格中的竖线转义。长段落、编号步骤、代码和复杂字段移到表外分级小节，在表中以稳定 ID 或链接关联。用例清单保留九列，详细内容可链接到对应用例小节。
- 图解优先用 Mermaid 围栏，配标题、图例及文字解读；已有 SVG／PNG 等通过相对路径引用并随文交付。阅读器不支持 Mermaid 时，正文与表格仍应讲清关键规则。不依赖 CDN 或在线字体，不为复刻 HTML 布局强制引入工具。
- 保留文档标题、版本／日期、当前状态、来源及适用范围。稳定 REQ／AC／INV／决策／用例 ID 保留在正文或标题中，目录及跨文档链接使用实际可定位的标题锚点；标题改动后核对链接。
- 相关术语与技术映射引用同一来源、修订及确认状态，摘录不独立定义另一套业务规则。用户决定、事实、建议和未知分别记录；待确认、已确认、用例就绪和执行通过保持区分。

## 已有材料与迁移

已有 HTML、Word、PDF 等继续作为有效输入，不因新格式要求批量改写历史材料或破坏已有引用。本轮新建或修订的正式稿保存为 `.md`；替代旧稿时保留来源／版本关系，同步登记、交接及链接，旧稿标明被替代或指向当前稿。每种正式文档维护一个有效来源。

纯格式转换不使原确认或有效测试失效，也不产生新的确认／通过事实；实质内容变化时按影响范围重新确认和更新下游。共享词典等已有权威载体仍按其维护约定沿用。

## 交付前检查

检查实际文件存在、中文编码正确、标题层级合理、表格及代码围栏完整、图与正文一致、标识唯一、链接及配套资源能定位。能使用本地 Markdown 预览时检查宽表、图解和长文本；未预览或未渲染的部分如实说明，不宣称已验证显示效果。

内容自检以各专业 skill 为准；格式检查不能证明需求闭环、设计获确认或测试已执行，不为文档检查启动业务系统或执行产品 UI／真实 E2E。交付实际文件位置与真实状态，跨岗位使用可访问的版本化来源。
