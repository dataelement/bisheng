# Feature: NVDB 漏洞修复（F072）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How 一律不写在这里。** How 的唯一真相在 [design.md](./design.md)。

**关联来源**: NVDB（工信部网络安全威胁和漏洞信息共享平台）2026-09-02 批次 7 份漏洞报告（去重后 5 个独立漏洞）
**优先级**: P0（安全发版）
**所属版本**: v3.0.0-beta2（目录沿 F067 先例挂在 `features/v3.0.0-beta1/`）
**依赖**: 无本版本未交付 Feature 前置

> **范围边界**
> - **本次纳入**：
>   - V1 JWT 签名密钥硬编码，可伪造任意用户（含超管）。
>   - V2 知识空间目录 / 搜索接口的排序参数拼接进 SQL，可时间盲注。
>   - V3 知识库上传 HTML 时，`file://` 与相对路径引用可把服务器任意文件复制进对象存储。
>   - V4 微调「预置训练文件」接口接受任意本地路径，可读服务器任意文件。
>   - V5 前端隐藏「新建应用」入口但后端创建接口不校验，普通用户可绕过直接建应用（工作流代码节点 RCE 链的第一跳）。
> - **本次明确排除**（已与用户确认，另立 Feature）：
>   - 工作流代码节点的执行沙箱与权限策略（RCE 根因）。V5 只封第一跳，不改变代码节点本身的执行方式。
>   - HTML 解析时对 `http/https` 外部资源的 SSRF 限制（内网地址、元数据服务）——与本批报告无关的独立问题。
>   - 单节点试运行（`run_once`）接口对非 code 节点的进一步权限收紧。
>   - 向 2.x 旧版本线回移（是否 backport 由发版决策另定）。

## 1. 用户故事

作为 **平台运维**，
我希望 **升级后不改任何配置，登录态就不再能被公开密钥伪造**，
以便 **不用逐个客户排查 config.yaml 有没有改过密钥**。

作为 **平台管理员**，
我希望 **关掉普通用户的「新建应用」入口后，后端接口同样拒绝**，
以便 **菜单权限是真的权限，而不是只藏一个按钮**。

作为 **普通用户**，
我希望 **上传知识库文件、浏览知识空间的正常操作不受影响**，
以便 **安全修复对我是透明的**。

## 2. 验收标准

> AC-ID 在本特性内唯一。字段名 / 表结构 / 接口路径等实现细节见 design.md。

### 2.1 V1 JWT 密钥

- **AC-01** — THE SYSTEM SHALL 不在代码中携带任何可用的 JWT 签名密钥默认值。
- **AC-02** — WHERE `config.yaml` 配置了 `jwt_secret` 且其值不是历史版本曾内置的默认值, THE SYSTEM SHALL 使用该值签发与校验登录态。
- **AC-03** — WHERE `config.yaml` 未配置 `jwt_secret`、为空或其值等于历史内置默认值, THE SYSTEM SHALL 在首次需要时生成一个随机密钥并持久化，之后同一部署的所有进程使用同一密钥。
- **AC-04** — WHEN 部署从携带内置默认值的旧版本升级且未配置 `jwt_secret`, THE SYSTEM SHALL 使旧密钥签发的登录态全部失效（用户需重新登录）；个人访问令牌与开放 API 凭据不受影响。
- **AC-05** — WHEN 运维修改 `config.yaml` 的 `jwt_secret` 或删除已持久化的生成密钥并重启, THE SYSTEM SHALL 以新密钥工作（轮换手段）。

### 2.2 V2 排序参数 SQL 注入

- **AC-06** — THE SYSTEM SHALL 只接受固定集合内的排序字段（文件类型、文件名、文件大小、更新时间、创建时间）与排序方向（升序 / 降序）；集合外的取值在接口层以参数校验失败拒绝，不进入 SQL。
- **AC-07** — IF 任何调用方把集合外的排序字段或方向传到数据访问层, THEN THE SYSTEM SHALL 抛出错误而不是拼接执行。
- **AC-08** — THE SYSTEM SHALL 保持现有前端使用的全部排序取值继续可用。

### 2.3 V3 HTML 任意文件读取

- **AC-09** — WHEN 解析用户上传的 HTML 且其中引用了以 `file://` 或相对路径指向本地文件的媒体, THE SYSTEM SHALL 仅在该文件位于该 HTML 自身所在目录（含子目录，符号链接按真实路径判定）内时复制，否则跳过并记录日志。
- **AC-10** — THE SYSTEM SHALL 保持 `data:` 内嵌媒体与 `http/https` 远程媒体的既有处理不变。

### 2.4 V4 本地路径任意文件读取

- **AC-11** — WHEN 文件下载工具收到一个指向本地已存在文件的路径, THE SYSTEM SHALL 仅在该文件位于本进程的下载缓存目录或系统临时目录内（按真实路径判定）时返回，否则拒绝。
- **AC-12** — THE SYSTEM SHALL 保持对象存储分享链接、带签名的对象存储相对路径、`http/https` 链接的既有下载行为不变。

### 2.5 V5 建应用权限绕过

- **AC-13** — WHEN 非超级管理员用户调用创建工作流或创建助手的接口且其生效菜单权限不含「新建应用」, THE SYSTEM SHALL 拒绝（403）。
- **AC-14** — THE SYSTEM SHALL 对超级管理员与生效菜单含「新建应用」的用户保持创建行为不变；判定口径与前端「新建应用」入口的显示条件一致。

## 4. 发版说明要点（写入 Release Notes）

- 升级后所有用户需重新登录一次（V1）。
- 若运维曾把老版本代码里的默认 `jwt_secret` 抄进 `config.yaml`，该值会被忽略，行为等同未配置。
- 关闭了普通用户「新建应用」菜单的租户，普通用户直接调接口建应用会开始返回 403（V5）；这是修复而非回归。
