# Feature: 任务模式按模型上下文长度控制上下文

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答做什么、验收标准、不做什么。实现方案见 [design.md](./design.md)，执行流水见 [tasks.md](./tasks.md)。
> 问题背景、现状盘点和采访决策记录见 [plan.md](./plan.md)。

**关联 PRD**: 无独立 PRD；需求来自 2026-10-21 某客户现场问题，Spec Discovery 结论见 [plan.md §7](./plan.md)
**优先级**: P0（第一批）/ P1（第二批）/ P2（第三批），各条 AC 标注所属批次
**所属版本**: v3.0.0
**依赖**: 任务模式 agent 框架（deepagents 0.6.x）；模型管理的服务商与模型配置

### 术语

| 术语 | 定义 |
|---|---|
| 上下文长度 | 模型单次请求能接受的 token 总数，输入加输出。vLLM 中即 `--max-model-len` |
| 可用输入 | 单次请求输入部分的上限。按以下规则确定：(1) 来源只给出输入上限时（例如 Anthropic 接口返回的 `max_input_tokens`），可用输入等于该值；(2) Ollama 模型的可用输入等于上下文长度，因为它的"上下文长度"字段与其他服务商的"最大输出"是同一个字段；(3) 其他情况下，可用输入等于上下文长度减去模型配置里的"最大输出 token 数"，没有配置最大输出时等于上下文长度 |
| 压缩 | 任务模式把较早的执行步骤替换成一段摘要，腾出上下文空间 |
| 转存 | 把过大的工具结果写进任务工作区的文件，上下文里只保留开头片段和文件路径 |
| 超窗 | 请求的 token 数超过上下文长度，服务商拒绝请求 |

> **范围边界**
> - **本次纳入**：
>   - 任务模式确定所用模型的上下文长度。来源依次为：高级配置中的手动值、Ollama 的上下文长度字段、服务商接口。
>   - 已知上下文长度时，任务模式按可用输入决定压缩时机和单条工具结果的转存阈值。
>   - 服务商返回超窗错误时，任务模式先压缩再重试；仍然超窗时，任务以明确的错误失败。
>   - 压缩时生成摘要失败的处理。
>   - token 计数在中文内容上不再明显少算。
>   - 删除任务模式配置中没有任何代码读取的配置项。
> - **本次明确排除**：
>   - 修改拿不到上下文长度时的默认行为（170K 压缩阈值、80000 字符转存阈值）。拿不到上下文长度的模型保持改动前的行为。
>   - 在模型配置页面新增"上下文长度"字段。手动配置只走高级配置。因此 Ollama 的"上下文长度"与其他服务商的"最大输出"共用一个字段的现状保持不变。
>   - 未配置最大输出时为输出单独预留空间。
>   - 华为昇腾 MindIE 的接口读取。现有证据不足，接口已被官方标为计划弃用。
>   - 日常模式、助手、工作流的上下文控制。本次只覆盖任务模式。
>   - 修改 deepagents 框架源码。
>   - 分别调整各工具自带的字符截断（代码执行 30000 字符、API 工具 10000 字符、网页读取的可配上限等）。这些截断保持不变；已知上下文长度时，超过可用输入 10% 的结果由 AC-19 统一转存。知识库检索的返回条数不单独限制，原因相同：一次检索的全部结果是一条工具结果，受 AC-19 约束。
>   - 限制图片张数和技能清单长度。图片不按文本计数，技能清单属于固定开销；两者另起需求评估。

## 1. 用户故事

作为 **使用本地部署模型的终端用户**，
我希望 **执行步骤较多的任务时不因"上下文超长"而失败**，
以便 **在上下文长度较小的本地模型上也能完成调研、写报告等长任务**。

作为 **平台管理员**，
我希望 **任务模式自动获知模型的上下文长度，必要时我也能手动指定**，
以便 **不需要理解框架内部阈值，也能让任务模式适配不同部署**。

作为 **现场运维人员**，
我希望 **任务因上下文超长失败时，界面和日志能明确说出原因、上下文长度及其来源**，
以便 **判断应该调大部署的上下文长度、改配置，还是让用户拆分任务**。

## 2. 验收标准

### 2.1 确定上下文长度（P0，百炼为 P1）

- **AC-01** — WHERE 模型的高级配置包含正整数 `context_window`, THE SYSTEM SHALL 在任务模式中以该值作为这个模型的上下文长度。
- **AC-02** — THE SYSTEM SHALL 不把高级配置中的 `context_window` 作为请求参数发给服务商。
- **AC-03** — WHERE 模型的服务商类型是 Ollama、高级配置不含 `context_window`、并且模型配置的"上下文长度"字段有值, THE SYSTEM SHALL 以该字段的值作为上下文长度。
- **AC-04** — WHEN 任务开始且以上手动来源都没有值, THE SYSTEM SHALL 通过服务商接口读取上下文长度。支持的服务商类型为：vllm、llamacpp、ollama、xinference、anthropic、deepseek、moonshot，以及配置了自定义地址的 openai 类型（后端为 vLLM、SGLang 等时可读到）。
- **AC-05** — WHEN 同一模型在上一次成功读取后 1 小时内再次开始任务, THE SYSTEM SHALL 不再请求服务商接口，并且所有节点使用同一个值。
- **AC-06** — WHEN 管理员保存了某个模型的配置, THE SYSTEM SHALL 在该模型的下一次任务中重新确定上下文长度。
- **AC-07** — IF 服务商接口读取失败, THEN THE SYSTEM SHALL 在之后 5 分钟内不再为该模型请求接口，并按"拿不到上下文长度"处理。
- **AC-08** — IF 所有来源都拿不到上下文长度, THEN THE SYSTEM SHALL 保持改动前的压缩时机和单条工具结果转存阈值。
- **AC-09** — WHEN 任务开始, THE SYSTEM SHALL 在日志中记录本次使用的上下文长度及其来源（手动配置 / Ollama 上下文长度字段 / 服务商接口返回的部署值 / 服务商接口返回的模型公布值 / 未知）。
- **AC-10** — （P1）WHEN 任务开始、服务商类型是 qwen（百炼）且没有手动来源, THE SYSTEM SHALL 通过百炼接口读取上下文长度；IF 无法确定该接口的地址, THEN THE SYSTEM SHALL 按"拿不到上下文长度"处理。

### 2.2 压缩时机（P0）

- **AC-11** — WHILE 上下文长度已知, THE SYSTEM SHALL 在按系统的 token 计数、请求的输入达到可用输入的 85% 时先压缩，再发出请求。主任务和子任务都满足此条。计数在中文内容上的准确性由 AC-21（P1）保证；P0 下以中文为主的任务允许先超窗、再按 AC-13 压缩重试，但不允许因此失败。
- **AC-12** — WHEN 在 `max_model_len=32768` 的 vLLM 模型上执行一个需要读取多份中文长文档（合计远超 32768 token）并写出报告的任务, THE SYSTEM SHALL 在超窗之前触发压缩，任务不因超窗失败。现场复验：在 `max_model_len=133120` 的环境重新执行引发本需求的任务（原话"使用 skill 把这家企业调债"），同样满足此条。
- **AC-24** — WHILE 上下文长度已知, WHEN 压缩发生, THE SYSTEM SHALL 原样保留最近的执行步骤，保留部分的总量不超过可用输入的 10%，其余较早的步骤替换为摘要。（P1 起，配合 AC-19：最近一次工具调用的结果总在保留部分中。）

### 2.3 超窗处理（P0）

- **AC-13** — IF 服务商返回超窗错误, THEN THE SYSTEM SHALL 先压缩，再重试这次请求，不直接让任务失败。至少能识别 vLLM、OpenAI 和 Anthropic 的超窗错误。
- **AC-14** — IF 压缩后重试仍然超窗, THEN THE SYSTEM SHALL 让任务以新增的"上下文超出模型长度"错误码失败，前端显示对应文案（简体中文 / 英文 / 日文，大意为"任务内容超出了模型一次能处理的长度，请拆分任务或换用上下文更长的模型"），并保留任务已生成的文件。
- **AC-15** — WHEN 任务因超窗失败, THE SYSTEM SHALL 在日志中记录上下文长度、其来源和服务商报告的输入 token 数。
- **AC-16** — IF 子任务在压缩后重试仍然超窗, THEN THE SYSTEM SHALL 结束该子任务，向主任务返回一段说明，写明这一步因超出模型上下文长度而未完成、应缩小范围后再做，并在日志中记录 AC-15 所列信息；主任务继续执行。IF 同一任务中子任务因超窗或其他原因被结束的次数超过任务模式现有的降级次数上限（配置项 `max_degrade`，默认 3）, THEN THE SYSTEM SHALL 让整个任务失败；最后一次结束的原因是超窗时，按 AC-14 的错误码失败。

### 2.4 摘要失败（P1）

- **AC-17** — IF 压缩时生成摘要失败, THEN THE SYSTEM SHALL 重试一次，重试时交给模型的内容不超过可用输入的一半。
- **AC-18** — IF 重试后生成摘要仍然失败, THEN THE SYSTEM SHALL 在日志中记录错误级别的信息，并让任务以新增的"上下文压缩失败"错误码失败，前端显示对应文案（简体中文 / 英文 / 日文，大意为"任务执行中整理历史步骤失败，请重试；多次失败请联系管理员检查模型服务"），保留任务已生成的文件；THE SYSTEM SHALL 不把失败信息当作摘要继续执行。

### 2.5 单条工具结果（P1）

- **AC-19** — WHILE 上下文长度已知, WHEN 一条工具结果超过可用输入的 10%, THE SYSTEM SHALL 转存该结果。上下文中只保留开头片段和文件路径，模型可以通过读取文件取回全文。主任务和子任务都满足此条。
- **AC-20** — WHILE 上下文长度已知, THE SYSTEM SHALL 让模型每次读取文件得到的内容不超过可用输入的 10%。

### 2.6 计数准确性（P1）

- **AC-21** — WHILE 上下文长度已知, THE SYSTEM SHALL 让以中文为主的任务在压缩触发前的每一次请求的实际输入 token 数（以服务商返回的用量为准）都不超过可用输入。

### 2.7 配置清理（P2）

- **AC-22** — THE SYSTEM SHALL 从任务模式配置中删除没有任何代码读取的配置项（`tool_buffer`、`file_content_length`、`max_file_num`、`max_knowledge_num`、`retry_temperature`、`max_file_content_num`）。
- **AC-23** — WHEN 已部署环境的系统配置（数据库中保存的配置，以及 `config.yaml`）中仍然包含 AC-22 所列的配置项, THE SYSTEM SHALL 正常启动，任务模式正常执行。

## 3. 边界情况

- 当高级配置中的 `context_window` 不是正整数（例如字符串、0、负数）时，系统应忽略它，在日志中记录警告，并按下一个来源继续确定上下文长度。
- 当高级配置不是合法的 JSON 时，系统的行为与改动前一致。
- 当服务商接口返回的值大于实际部署的上下文长度时（例如 Xinference 返回模型公布值，而部署时调小了长度），系统应按 AC-13 在超窗后压缩重试。
- 当最大输出 token 数大于或等于上下文长度时（Ollama 除外，见术语"可用输入"），系统应视为配置错误：日志记录警告，并按"拿不到上下文长度"处理。
- 当服务商接口返回多个模型条目时，系统应使用与模型配置中模型名称对应的条目；该条目本身不带上下文长度、但能确定其基础模型时（例如 vLLM 上加载的 LoRA 适配器），系统应使用基础模型的值。
- 当用户在任务中途"继续"、"重试"或回答提问后恢复执行时，系统应按本次恢复时确定的上下文长度执行 AC-11。
- 当可用输入很小、接近任务的固定开销（系统提示词与工具说明，约 1.2–1.6 万 token）时，系统对同一次请求最多压缩一次，不反复压缩；压缩后仍然超窗时按 AC-14 处理。
