# 风险驱动的代码审核检查

按改动选择适用检查。结论需要代码因果、实际入口或执行证据，避免把检查表中的所有项目都变成缺陷。

## 行为、异常与资源

检查关键输入边界、缺失值、空集合、异常分支、超时和取消。
核对资源申请与释放、锁和任务生命周期。检查部分成功后的状态、事务与外部动作是否一致。
相关时检查并发覆盖、幂等、重复投递和重试放大；资源已经释放不代表业务状态已经恢复。

## 需求、设计与实际接通

按共享产物约定核对标识、位置、文档来源、代码基线及适用状态。关注本次改变涉及的模块知识是否同步、交付后关联变更是否可追溯，检查索引／登记与实际文件的必要一致性。
对照确认范围、验收条件和关键设计，检查注册、路由、调用方、配置默认值和功能入口。
检查路径是否实际可达，区分仍在使用的机制和遗留代码。存在文件不能证明功能已经接通。
核对共享机制的使用方及兼容性，限制修改范围与根因相称。按[领域语言约定](../../sdd-workflow/references/domain-language.md) 核对当前术语基线、概念增量、职责和技术映射，检查图文与用例是否混淆不同对象；有依据的旧别名不因词面不同而打回。

## 测试与静态检查

复用项目真实的 lint、类型、构建与扫描设置，核对新增问题和已有基线。
检查断言和用例预期、失败与拒绝行为、状态及副作用，关注被 mock 掉的逻辑。
使用适当 mock／隔离单元、接口和功能测试检查修复，保留真实业务、路由及相关权限代码；覆盖率只帮助发现缺口，不代表断言正确。检查替身与当前契约一致，断言覆盖状态、副作用和错误处理，而非仅重复 mock 设置。
检查当前代码与执行报告对应；未执行、全跳过或仅 dry-run 的结论需准确标记。区分开发期需要的隔离业务验证与后置真实部署 E2E。昂贵真实依赖和按约定后置的 UI 用例保持待验收，不要求开发者在本机部署全栈；不能因此免除开发期必要接口／功能用例。

## 安全

从相关攻击路径核对输入到危险操作的处理、访问控制、资源归属、秘密配置与敏感信息。
包括适用的注入、文件路径／上传、外部请求、前端内容处理、越权及新增依赖风险。
核对普通用户允许与拒绝场景，不能只用管理员成功推断权限正确。
安全清单与 AI 自述不能替代必要的真实验证。

## 可观测性与运行风险

优先检查现有日志、指标和关联能力是否足以发现及定位故障，再补必要缺口。
核对失败类别、上下文关联、敏感信息、日志注入、采样与性能开销；避免高基数指标和无行动价值告警。
适用时检查查询数量、内存或队列增长、大数据量、环境差异、新旧版本和数据兼容。
发布与恢复安排应适配实际风险，不假设回滚代码可以恢复所有数据变化。

## 结论

发现写清代码位置、可达触发条件、影响及依据。无法证实的担忧标记待核实。
阻塞项需有实质影响或必要证据缺口；维护性建议与格式偏好依据项目规则处理。
原作者修复后按影响定向复核；独立性和环境限制保持可见。
