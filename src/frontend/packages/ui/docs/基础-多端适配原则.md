# 多端适配 Responsive

> 设计系统 · v1.5 · 2026-11-02
> 适用：响应式 Web，覆盖手机 / 平板 / 桌面三档，无原生 App。
> 本文只放通用原则；各组件的具体细则写在自己文档的「移动端适配」一节。

---

同一套界面，要同时照顾**手机、平板、桌面**三种尺寸。我们为多端准备了专门的适配方式——**用最小的成本，让每一端都有好的体验**。适配围绕两个真正的差别展开：手指比鼠标粗，屏幕有宽有窄。以下就是各种情况下的适配原则。

---

## 1. 布局和交互分开判断

- 跟**交互**有关的（悬停、点击范围）→ 按「是不是触屏设备」判断
- 跟**布局**有关的（排版、留白）→ 按屏幕窗口宽度判断

屏幕宽度用**两个断点切三档**：

| 档位 | 宽度 | 典型设备 |
|---|---|---|
| 手机 | < 576px | 竖屏手机 |
| 平板 | 576–768px | 平板、横屏手机、分屏窗口 |
| 桌面 | > 768px | 电脑 |

例：触屏笔记本屏幕很宽，但它需要触屏适配。

## 2. 触屏设备没有 hover 操作

hover 操作是鼠标悬停时的变色。手指没有「悬停」，点一下之后 hover 色会粘在按钮上不消失。

- 触屏：不显示 hover，按下时用 active（按下态）变色
- 桌面：只显示 hover，不叠 active，否则点击会闪一下

记住一句：**桌面只有 hover，触屏只有 active。**

## 3. 给手指留够点击范围

指尖按下约 44px 宽，比鼠标指针粗得多，小按钮容易点空。

- 触屏上，可点范围一律 ≥ 44×44px
- 做法：按钮外观不变，把可点范围透明地向外扩大
- 高度小于 28px 的小控件别扩（会和邻居打架），直接换大一号

44px 是 BISHENG 采用的点击范围目标，对应 WCAG 2.2 AAA 的增强要求；AA 的最小要求是 24px，并有间距等例外。点击范围与字号分别检查，不能把字号放大当成点击范围达标。

## 4. 不做手机版组件

所有适配写在同一个组件文件里，用 CSS 条件完成。不引入第二套移动端组件库，不做第二套组件。

原因：两套组件等于每个改动做两遍，很快就会各长各样。

## 布局惯例

| 场景 | 手机档 | 平板档 | 桌面档 |
|---|---|---|---|
| 弹窗底部按钮 | 等宽平铺占满一行 | 同桌面 | 右对齐，自适应宽 |
| 页面主操作 | block 占满整行 | 同桌面 | 正常宽度 |
| 弹窗位置 | 全屏（弹窗）／从底部上滑（抽屉），见各自组件文档 §7 | 居中 | 居中 |
| 容器圆角 | 全屏时四角直角、贴底时仅顶部留圆角 | 同桌面 | 按容器档取圆角 |

平板档默认走桌面布局，只在组件文档另有说明时单独处理。先例：C 套确认弹窗、AlertDialog 底座。新组件照抄，不自造。

## 给实现窗口（技术细节，设计师可跳过）

- 双判断写法：触屏 = `@media (hover: none) and (pointer: coarse)`；屏宽两断点 = **576px / 768px**（与 platform 端现有断点一致）。不自造断点。
- 断点现状与对齐（2026-07-14 盘点）：client 活跃断点约 6 个值——576（手写 10 处）、640（Tailwind `sm:` 329 处 + css）、767/768（hooks、字体重映射、`md:` 80 处）、1022–1024（`lg:` 110 处 + css）、1280（`xl:` 41 处）、1536（`2xl:` 1 处）。规范以 **576/768** 为准；>768 内部的 `lg:/xl:` 属桌面档内的细分排版，不算档位断点。Tailwind `screens` 改配置会整体挪动现有 `sm:` 行为（576–640 区间受影响），**随组件迁移逐步对齐，不一次性全局切**。原字号重映射仍保留 768 断点，但默认关闭；见下方暂停决策。
- hover 禁用**已全局落地**：`tailwind.config.cjs` 开启 `future.hoverOnlyWhenSupported`，所有 `hover:` 类自动只在可悬停设备生效，组件无需自行处理。必须写普通 `hover:` 类，禁止自造 hover 前缀（tailwind-merge 认不出冲突，业务页覆盖会失效，见 [组件-Button按钮.md](组件-Button按钮.md) §5.5）。
- active 深档包 `coarse-pointer` 媒体查询，与 hover 互为补集（呼应原则 2）。
- 热区扩展用透明伪元素/padding；窄屏判断可用现成 hooks:`useMediaQuery` / `usePrefersMobileLayout`。
- 依据存档：sticky hover 与 antd-mobile 仅 `:active` 的做法；WCAG 2.2 §2.5.8（AA 24px）/ §2.5.5（AAA 44px）、iOS HIG 44pt、Material 48dp；字体分类与字号见 [基础-字体规范.mdx](基础-字体规范.mdx) §2.2；此前字号适配决策现已暂停。

### 字体适配暂停（2026-11-02，当前决策）

- 设计师要求：当前尚未确定移动端字体方案，取消所有自动字号适配，避免同层级 14 / 16px 混用。各屏宽沿用基准字阶；原本为 16px 的 large 控件及标题层级不改成 14px。用户主动缩放、点击热区、布局断点与触屏交互继续保留。
- 单一入口：只有 `<html data-mobile-typography="enabled">` 才启用预留方案。默认不设置该属性，文档站、client、platform 均不设置；不开业务侧自动检测，不添加公开设置。
- 生效边界：`packages/ui/src/styles/tokens.css` 中阅读字阶重映射、字段窄屏 / 粗指针重映射、`.input-no-zoom` 输入下限，以及 `client/src/style.css` 中旧原生表单 16px 兜底，都由同一个属性控制。`design-token.cjs` 的 `mobile` 数组保留为草案数据；组件继续使用语义 token，后续无需逐个组件重接。
- 展示边界：字体规范、字体预览、Design Token 表不渲染移动字号列；Input、InputNumber、Select、Cascader、Button 的公开说明移除移动字号适配规则。不要在这些公开页面加入「已暂停」开关说明；当前状态与旧方案仅留在本文隐藏区。
- 已知取舍：关闭输入下限后，iOS 小字号输入框聚焦可能重新触发自动放大；本轮优先统一当前字号观感，未采用禁用用户缩放的替代方案。
- 下方调研、原方案与历史验证仅作存档，不代表当前生效行为；重新启用前需重新确认完整方案。
- 当前验证：Chrome 字体演示在 390 / 600 / 768 / 769 / 1024px 下，普通字段、搜索、选择器与多选值均为 14 / 22；实际 client 模型选择器在 390 / 600 / 1024px 下均为 14 / 22，手机面板搜索和候选项同为 14 / 22。另核对 large 输入仍为 16 / 24、阅读字阶变量保持基准值；8 个公开规范页均不显示移动字号规则或内部开关。CSS 解析检查确认 4 组响应式字体规则全部受入口保护；相关交互测试 16 项、前端与 UI 类型检查、UI / client lint、MDX 编译及架构守卫通过。全仓 lint 仍受未改动的 platform 两文件 6 处既有错误阻断；未做 iOS 真机聚焦验收。

### 历史方案与调研（2026-11-02，已暂停）

#### 原公开规则：按用途适配文字

**把阅读文字、表单字段和紧凑控件分开处理。**正文和标题跟随阅读字阶；填写、搜索、显示字段答案的文字使用字段字阶；按钮、候选项和紧凑工具栏入口使用各自的控件字阶。

字号数值、适配条件、可搜索选择器的处理和用户放大文字的要求，统一见 [基础-字体规范.mdx](基础-字体规范.mdx) §2.1、§2.2、§4。同一个字段的占位、已选值和输入文字保持一致，不因聚焦或展开而换字号。



- 用户确认：表单字段统一使用字段字阶，紧凑控件保留原字阶；允许同步修改相关组件代码。字体规范是数值与用途的唯一来源，本文只记录实现和调研依据。
- 单一源：`packages/ui/design-token.cjs` 新增 `CONTROL_TYPE_SCALE`，字段与控件 token 不加入 `TYPE_SCALE`，避免十档数值层编号变化。`src/styles/tokens.css` 承载 CSS 变量，`tailwind-preset.cjs` 映射类名，`src/utils/cn.ts` 将新类名注册为字号，防止被当成文字颜色吞掉。
- 组件接入：`Input/shared.ts` 的外壳使用字段字阶，Input、SearchInput、PasswordInput、Textarea、InputNumber 与描边选择器共同继承；`shared/SelectionTrigger.tsx` 为内联搜索切换整个文字区；`Select/SelectTags.tsx` 让可见值、测量副本及「+N」继承同一字阶。Button、`shared/menuSurface.ts`、Cascader 返回导航使用控件字阶。
- 输入下限：`.input-no-zoom` 在原有窄屏 / 触屏条件内使用 `max(1em, 1rem, 16px)` 与 1.5 倍行高，保护输入下限且保留更大字号；client 旧原生表单兜底的 `!important` 同步保留较大值，避免压回固定 16px。
- 调研口径：2026-11-02 查阅官方规范与官方仓库当前源码，仅比较字体角色、默认字阶和缩放原则，不把原生 pt 当作 Web px。Ant Design 桌面正文基准 14 / 22；Arco 的常规 Input、Select 与 Cascader 选项共用 14px；Ant Design Mobile 的 Input 默认 17px、SearchBar 与 Selector 默认 15px；Apple 强调文字样式、Dynamic Type 和大字下布局适配。业内没有「手机所有控件统一放大」的共同规则。
- 官方来源：[Ant Design 字体](https://ant.design/docs/spec/font/)、[Arco 字阶](https://github.com/arco-design/arco-design/blob/main/components/style/theme/global.less)、[Arco Input](https://github.com/arco-design/arco-design/blob/main/components/Input/style/token.less)、[Arco Select](https://github.com/arco-design/arco-design/blob/main/components/Select/style/token.less)、[Arco Cascader](https://github.com/arco-design/arco-design/blob/main/components/Cascader/style/token.less)、[Ant Design Mobile 字阶](https://github.com/ant-design/ant-design-mobile/blob/master/src/global/theme-default.less)、[Input](https://github.com/ant-design/ant-design-mobile/blob/master/src/components/input/input.less)、[SearchBar](https://github.com/ant-design/ant-design-mobile/blob/master/src/components/search-bar/search-bar.less)、[Selector](https://github.com/ant-design/ant-design-mobile/blob/master/src/components/selector/selector.less)、[Apple HIG 字体](https://developer.apple.com/design/human-interface-guidelines/typography)。
- 无障碍依据：[WCAG 文字缩放](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)、[目标尺寸 AA](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)、[目标尺寸 AAA](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)。本次不调整菜单行高、间距与热区，字号验收与触达范围验收分别进行。
- 历史验证口径（暂停前）：Chrome 文档演示在 390 / 768px 下，表单字段、内联搜索和多选值为 16px，紧凑入口与候选项为 14px；769 / 1024px 下回到桌面字阶。另核对手机 Cascader 的独立搜索、可搜索紧凑 Select、8 个字号 / 颜色合并用例及两份 token 载体一致性。相关交互测试 16 项通过，前端与 UI 包类型检查、UI / client lint、MDX 编译和架构守卫通过；全仓 lint 被未改动的 platform `controllers/API/linsight.ts` 与 `test/speechForm.test.tsx` 的 6 处既有错误阻断。本记录不代表完成 iOS 真机聚焦或 200% 文字缩放验收。
