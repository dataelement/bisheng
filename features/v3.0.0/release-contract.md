## 表 1：领域对象归属

每个领域对象只能有一个 Owner Feature，负责定义该对象的写入行为
（创建、更新、删除）。其他 Feature 只能"读取"或"引用"该对象。

| 领域对象 | Owner Feature | 说明 |
|---------|--------------|------|
| **ApiCredential**（平台自签发凭据底座：服务账号密钥 `bs-sak-` / 会话派生凭据；`bs-pat-` 形态待 PRD-1 DEV-01 口径确认后由 F050 追加） | **F049-openapi-auth-baseline** | 拥有凭据的生成、哈希存储、校验、权限位与过期、软撤销与批量撤销、最后使用时间写入。⚠️ 伴生 PRD 终版（`9bb8e89cc`）已**整条否决**开放 API 侧的个人访问令牌——密钥只签发给服务账号；PRD-1 DEV-01 的开发者个人 key 属另一个面，是否作为本对象的第二主体轨见 F049 spec §4 待澄清-4。F050 追加委托相关属性取值，不改底座语义；F055 的应用 token 按服务账号密钥形态由本底座签发 |
| **ServiceAccount**（不可登录的服务账号主体：`User` 上的主体类型标识 + 租户归属 + 登录守卫 + 列表可见性分叉） | **F049-openapi-auth-baseline** | 伴生 PRD R4。拥有服务账号的创建/启停/删除、租户关联行的声明式写入、对账豁免、用户列表默认排除规则；不拥有 `User` 表本身（自然人侧行为不变） |
| （候选）AppServiceAccountToken —— 应用 token 不是新对象，是 ApiCredential 的一种主体绑定 | F055（使用方） | GOV-08：应用即一个服务账号主体，其 token 由 F049 底座签发；F055 拥有「按能力声明重签/失效」的生命周期编排，不拥有凭据本身 |
| （候选）App / AppVersion / AppInstance（工场应用本体、不可变版本快照、运行实例） | F054-app-domain-runtime | RT-05 语义与既有 flow_version 可变指针语义不同，独立建模 |
| （候选）ResourceTier（资源档位） | F055-app-publish-pipeline | GOV-03 档位实体 + 发布选档/入快照/预检/终检；F056 只读（管理列表展示档位列） |

**规则**：
- 非 Owner Feature 的 AC 中不得出现其他对象的"创建/修改/删除"行为，只能"读取"或"调用" Owner 的 Service
- 新增领域对象时必须先更新本表

## 表 2：跨 Feature 不变量（INV-N）

全局业务约束，任何 spec 的 AC **不得与之矛盾**。
（INV-1~7 见 v2.6.0 release-contract；INV-8~26 见 origin/feat/3.0.0-beta1 分支的 v3.0.0-beta1 release-contract，生效前提见编号约定。）

| ID | 不变量描述 | 涉及领域对象 | 来源 spec |
|----|-----------|------------|---------|
| INV-27 | **开放 API 默认拒绝**：`/api/v2/**` 的任何调用必须先由平台签发的凭据确立主体，不得回落到任何固定/配置身份。存量兼容窗口是**显式、限时、每请求记告警**的例外，由部署开关控制且窗口结束即移除该路径——不得成为长期形态，也不得扩展到新端点 | ApiCredential | F049 |
| INV-28 | **平台自签发凭据统一底座**：一切平台自签发凭据（服务账号密钥、应用 token、会话派生凭据，以及 PRD-1 DEV-01 的开发者个人 key——若经待澄清-4 确认保留）必须密码学随机生成、服务端仅存单向哈希（不用可逆加密）、明文仅签发时一次性展示、此后一切界面只见掩码（前缀 + 末四位）、撤销为软撤销且保留审计记录、撤销生效上界 5 秒（主动清缓存，不依赖 TTL 自然过期）。有效性判据唯一 = 未撤销且未过期，不得引入可独立漂移的状态枚举列 | ApiCredential | F049 |
| INV-29 | **服务账号主体不可登录**：服务账号不得通过任何登录入口获得会话；其租户归属为声明式写入、不由部门树派生，任何以部门树为真相的对账都必须结构性跳过它；不计入租户用户数配额；在面向自然人的用户列表消费点默认不可见（失败方向必须是"看不到"而非"泄漏"），仅在资源授权选人处显式 opt-in 可见 | ServiceAccount | F049 |
| INV-30 | **开放面权限评估 fail-closed（INV-19 在开放 API 上的加强）**：权限引擎不可用、评估失败或结果不可判定时，开放 API 必须返回错误，**且绝不返回未过滤或部分过滤的结果集**；「配置为必须携带最终用户身份的端点未收到身份头」时只返回对所有人公开的资源，不得放行全量。本条不放宽 INV-19，只补充「部分过滤亦属失败」这一判据 | ApiCredential, PermissionGrant | F049 |

**规则**：
- 新增不变量：先在此表追加，再写 AC
- 修改不变量：必须列出 Impacted Specs 清单，逐一回写并重新评审
- 冲突检测：若 AC 与不变量矛盾，spec 评审不通过
