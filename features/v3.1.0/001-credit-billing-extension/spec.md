# Feature: 积分扣费扩展（工具调用 + 助手 / 工作流 / 托管应用 + 计费总开关）

**关联 PRD**：
- 《积分扣费扩展-需求文档与界面原型 v1.0》（2026-11-19 定稿）
- 《积分扣费扩展-技术实现与评审文档 v1.0》（2026-11-24 技术评审定稿，含评审会已拍板变更 #1、#2 及 4 项出入点最终结论）

**优先级**：P0  
**所属版本**：v3.1.0（F001-credit-billing-extension）  
**依赖**：`v3.1.0-beta1/016-credit-pricing`（F016）、F062 统一额度账本、F051 模型协议面、F054/F055 托管应用访问人令牌  
**流程**：Full SDD（状态：✅ 已确认）

> **范围边界**
> - **本次纳入**：
>   - **工具设价与按次扣费**：内置工具、API 工具、MCP 工具三类（含联网搜索、网页读取），全工具统一按二级工具配置「次数（默认 1 次）+ 价格（按金额或按积分）」，不区分引擎；调用开始执行即按次扣调用人积分，非任务模式下的收费工具执行前实时校验额度。
>   - **助手、工作流纳入计费**：工作台使用、构建页调试（扣搭建者）、免登录分享（扣本租户运行身份）中的模型与工具调用全部纳入扣费；应用内模型不受员工「用户可选模型」限制；工作流改为节点级实时扣费与实时额度拦截（取消原 PRD 整轮免拦截）；网页工作台在助手、工作流（含运行中途）、免登录访客页统一接入现有「本月积分已用完」提示卡片。
>   - **任务模式单周期豁免**：任务模式（深度研究）保持发起任务时校验一次额度，单次任务生命周期内（含中途等待用户输入恢复与所有模型/工具调用）实时入账且不做额度拦截。
>   - **托管应用计费与开放 API 免计费**：平台内托管应用调用模型网关按有效访问人令牌扣访问人（无令牌或审批预览试用扣应用负责人；携带过期/伪造令牌维持报错拒绝 26504；余额用完返回 HTTP 429 与错误码 26121）；其他所有外部开放 API（服务账号/代员工调助手、工作流、深度研究、模型网关）统一不算账（将开放 API 调深度研究由「扣」改为「不扣」）。
>   - **全局积分与计费总开关**：取消原企业客户端耦合开关，桌面端基础接入常驻可用；新增全局配置型「积分与计费总开关」（默认开启），关闭后停用全平台积分/计费与额度拦截并隐藏相关前后端入口，保留平台原有模型可见范围配置。
>   - **扣费记录与账本对账恢复**：记录完整工具扣费明细与模型调用来源；用户余额与账本故障恢复重算同时涵盖模型与工具扣费。
> - **本次明确排除**：
>   - 员工端展示工具价格。
>   - 新的用量统计报表界面（按场景、按应用、按工具维度的统计页）；现有「本月已用 / 剩余」自然包含本期新增扣费。
>   - 应用卡片上展示所用模型或预估积分。
>   - 开放 API 计费（本期明确全部不算账）。
>   - 向量、重排等非聊天模型计费、知识库入库计费、评测计费。
>   - 桌面客户端在员工本机运行的工具、插件、员工自带 Key 的调用（不经过服务端）。
>   - 联网搜索/网页读取按不同搜索引擎分别定价（2026-11-24 评审会已拍板取消引擎定价维度，所有引擎共用一份价格）。
>   - 在积分模块为子公司免登录跨租户默认操作员放行租户校验（2026-11-24 评审会已拍板拒绝跨租户放行，由免登录配置侧约束仅选本租户成员）。

## 1. 用户故事

- **A. 企业管理员（工具设价与成本控制）**  
  作为**企业管理员**，我希望给内置工具、API 工具和 MCP 工具的每个二级工具统一配置「次数 + 价格」（按金额或按积分），以便将外部付费工具的实际成本折算为积分计入员工月度额度，且各子公司可独立定价互不干扰。

- **B. 企业管理员（应用与托管应用成本收口）**  
  作为**企业管理员**，我希望员工在工作台、构建页调试、免登录链接中使用助手和工作流，以及使用平台内托管应用时，产生的模型与工具消耗均计入对应责任人的月度积分额度；同时外部系统通过开放 API 集成调用不消耗员工个人积分。

- **C. 企业运维 / 平台管理员（全局总开关）**  
  作为**平台管理员**，我希望通过独立的全局配置开关一键启停积分与计费功能，且关闭积分后不影响企业桌面客户端的基础登录与模型可见范围管理，以便不需要积分管控的部署环境零负担运行。

- **D. 员工 / 访客（可预期的额度提示）**  
  作为**员工或免登录访客**，我希望在助手、工作流或托管应用中因本月积分用完而被拦截时，能收到与日常对话一致的清晰提示（而非静默失败或模糊弹窗），且正在运行中的深度研究（任务模式）任务不会在中途被突然掐断。

## 2. 验收标准

> 本特性为 P0 跨模块能力，全部 AC 采用 EARS 句型编写；AC 编号 `AC-01` ~ `AC-32` 为本特性唯一追溯主键（括号内保留与原 PRD `AC-Txx` / `AC-Axx` 及评审变更的对应关系）。

### 2.1 工具设价与管理后台

- **AC-01**（对应 PRD AC-T01） — THE SYSTEM SHALL 使所有内置工具、API 工具、MCP 工具的二级工具默认价格为 0；当价格为 0 时，调用不扣积分、不写工具扣费记录、不做额度拦截。
- **AC-02**（对应评审变更 #4） — WHEN 管理员打开管理后台「构建 → 工具与技能」的「内置工具」「API 工具」「MCP 工具」任一页签并展开工具组, THE SYSTEM SHALL 在每个二级工具行（含联网搜索、网页读取）统一显示当前价格（价格为 0 显示「免费」，非 0 显示「价格 / 次数」及按当前积分设置折算的单次约扣积分），并向有设价权限的管理员显示「设置价格」按钮。
- **AC-03**（对应评审变更 #4） — WHEN 管理员点击任意二级工具（含联网搜索、网页读取）的「设置价格」按钮, THE SYSTEM SHALL 打开统一的「设置价格」弹框，支持选择计价方式（「按金额」或「按积分」，默认「按金额」）、配置「次数」（正整数，范围 `1 ~ 1,000,000`，默认 `1`）、币种（人民币 / 美元，默认取当前租户积分设置币种）和价格（`0 ~ 999999.999999`，最多 6 位小数，清空视为 0），并在输入下方实时显示单次约扣积分或约合费用；输入不合法时标红提示且「保存」不可点击。
- **AC-04**（对应评审变更 #4） — THE SYSTEM SHALL 使「联网搜索」「网页读取」的所有搜索引擎共用同一份工具价格配置，不随切换引擎改变价格，且不在「编辑内置工具」引擎配置弹框中嵌入价格表单。
- **AC-05**（对应 PRD AC-T11） — WHILE 当前用户既不是超级管理员也不是当前租户管理员, THE SYSTEM SHALL 在列表隐藏「设置价格」按钮，并在后端改价接口直接拒绝其保存请求。
- **AC-06**（对应 PRD AC-T12） — IF 两名管理员同时修改同一二级工具的价格, THEN THE SYSTEM SHALL 仅允许先提交的一方保存成功，对后提交的一方返回冲突错误（错误码 26130）并提示「价格已被他人修改，请刷新后重试」，不得覆盖前者修改。
- **AC-07**（对应 PRD AC-T10） — WHEN 管理员修改 API 工具定义或刷新 MCP 工具列表, THE SYSTEM SHALL 保留未删除二级工具的原价格，将新出现的二级工具价格置为 0，并同步删除被移除二级工具（或整个被删工具组）的价格配置。
- **AC-08**（对应 PRD AC-T13） — WHEN 新建子公司（或子公司首次初始化内置工具）从总公司复制内置工具, THE SYSTEM SHALL 将总公司对应内置二级工具当时的价格一并复制一次；复制完成后总公司与子公司各自改价互不同步；功能上线前已存在的子公司存量内置工具价格保持为 0。

### 2.2 工具换算、实时扣费与额度拦截

- **AC-09**（对应 PRD AC-T02） — WHEN 某二级工具按「按积分」配置为 `N` 次 `P` 积分（例：`1` 次 `2` 积分）且被调用一次, THE SYSTEM SHALL 扣除 `ceil(P / N)`（向上取整到 `0.000001` 积分，例：`2` 积分），且后续修改租户积分单价或汇率不影响其单次扣分。
- **AC-10**（对应 PRD AC-T03、AC-T04、AC-T08） — WHEN 某二级工具按「按金额」配置为 `N` 次 `P` 元或美元（例：`1000` 次 `5` 元，积分单价 `0.01` 元 → 扣 `0.5` 积分；`1000` 次 `8` 美元，汇率 `6.72`，积分单价 `0.01` 元 → 扣 `5.376` 积分）, THE SYSTEM SHALL 按调用开始时当前租户的计价币种、汇率与积分单价换算并向上取整到 `0.000001` 积分；租户修改积分单价或汇率后，后续调用按新设置换算。
- **AC-11**（对应 PRD AC-T09） — WHEN 管理员修改工具价格, THE SYSTEM SHALL 对修改前已开始执行的调用按开始时冻结的价格快照结算，对修改后开始执行的调用按新价格结算。
- **AC-12**（对应 PRD AC-T06） — WHEN 工具通过权限、启用状态与密钥等前置校验并真正开始执行, THE SYSTEM SHALL 无论该次执行最终成功、失败、超时还是中途取消，均按一次调用扣费并写入扣费记录；IF 工具在执行前因无权限、未启用或缺少/错误密钥配置被拦下, THEN THE SYSTEM SHALL 不扣费、不写扣费记录。
- **AC-13**（对应评审变更 #1） — WHERE 处于非任务模式（日常对话、知识空间、助手、工作流、工具试运行等）且二级工具价格大于 0, WHEN 调用前员工本月积分已用完（`used >= limit`）, THEN THE SYSTEM SHALL 在执行工具前直接拦截并返回错误码 `26121`，不执行工具且不扣费；WHILE 员工仍有剩余额度（`used < limit`）, THE SYSTEM SHALL 放行本次调用（允许本次扣费后轻微超额），并在扣费入账后由下一次模型或收费工具调用拦截。
- **AC-14**（对应 PRD AC-T14） — WHEN 子公司员工调用工具, THE SYSTEM SHALL 按该子公司自己的工具价格及该子公司的积分单价、汇率计算扣费。
- **AC-15**（对应 PRD AC-T15） — WHEN 工作流的工具节点或 Agent 节点调用已设价工具, THE SYSTEM SHALL 实时校验额度并按次扣除工作流发起人（或免登录运行身份）的积分。

### 2.3 任务模式单周期豁免

- **AC-16**（对应评审变更 #1） — WHEN 员工通过网页或桌面端发起一次任务模式（深度研究）新任务或追问新轮次, THE SYSTEM SHALL 在任务启动前检查一次本月额度，若已用完则拦截并返回错误码 `26121`；一旦通过启动检查，WHILE 该次任务处于其单次生命周期内（含中途等待用户输入 `ask_user` 后的恢复执行）, THE SYSTEM SHALL 对任务内产生的所有模型调用与工具调用实时写入账本扣分且不做额度拦截，不中断正在运行的任务。

### 2.4 助手、工作流与免登录计费

- **AC-17**（对应 PRD AC-A01、AC-A02） — WHEN 员工在工作台使用助手或运行工作流, THE SYSTEM SHALL 按 F016 真实单价公式对其中的聊天模型调用扣除该员工积分；即使应用配置的模型不在员工「用户可选模型」范围内，THE SYSTEM SHALL 照常运行并按该模型价格扣费，不得报「模型不可用」。
- **AC-18**（对应 PRD AC-A03） — IF 员工本月积分已用完且在工作台向助手发消息, THEN THE SYSTEM SHALL 拦截该次模型调用（错误码 `26121`），本次不回答，并在应用对话页渲染与日常对话一致的「本月积分已用完」卡片。
- **AC-19**（对应评审变更 #1） — WHEN 员工在工作台或后台运行工作流, THE SYSTEM SHALL 对工作流中每一个大模型节点与收费工具节点在执行前实时检查额度并实时扣分；IF 在启动时或运行中途任一节点触发积分用完（错误码 `26121`）, THEN THE SYSTEM SHALL 立即中止后续节点执行，并将工作流置为失败，在网页工作台工作流消息流中渲染「本月积分已用完」卡片（不止弹 toast）。
- **AC-20**（对应 PRD AC-A05） — WHEN 用户在管理后台「构建」页调试助手或工作流（含调试他人搭建的应用）, THE SYSTEM SHALL 按对应助手/工作流的实时规则扣除当前调试者的积分，并在调试者积分用完时拦截提示。
- **AC-21**（对应 PRD AC-A06 + 评审变更 #3） — WHEN 访客通过免登录分享链接使用助手或工作流, THE SYSTEM SHALL 扣除该应用所配置「运行身份」的积分（含模型与工具）；运行身份用完积分时拦截访客并在免登录页渲染「本月积分已用完」卡片；THE SYSTEM SHALL 严格要求运行身份为当前租户的有效成员，不在积分扣费路径放行跨租户成员校验。

### 2.5 开放 API 免计费与托管应用计费

- **AC-22**（对应 PRD AC-A07） — WHEN 外部系统通过开放 API（服务账号模式或代员工模式）调用助手、工作流、深度研究（任务模式）或模型网关, THE SYSTEM SHALL 全程不算账（不查额度、不扣模型与工具积分、不写积分账本），即使对应员工积分已用完也不受影响（含将开放 API 调深度研究由原先会扣改为不扣）。
- **AC-23**（对应 PRD AC-A08） — WHEN 平台内托管应用调用模型网关且携带有效的代访问人令牌, THE SYSTEM SHALL 按该实际访问人实时校验额度并扣除其积分（不受员工可选模型限制）；IF 访问人本月积分已用完, THEN THE SYSTEM SHALL 拒绝调用并返回 OpenAI 兼容 HTTP 429（`type="rate_limit_error"`、`code="credit_exhausted"`，对应平台错误码 `26121`）。
- **AC-24**（对应 PRD AC-A09 + 评审变更 #1 方案 A） — WHEN 平台内托管应用调用模型网关且未携带访问人令牌（如后台定时任务），或处于上线审批的「预览试用」场景, THE SYSTEM SHALL 按应用负责人校验额度并扣除其积分；IF 托管应用携带了过期或伪造的访问人令牌, THEN THE SYSTEM SHALL 维持报错拒绝（错误码 `26504`），不得降级扣应用负责人。

### 2.6 扣费记录、月度汇总与账本恢复

- **AC-25**（对应 PRD 第 6 节） — WHEN 发生一次收费工具调用扣费, THE SYSTEM SHALL 持久化一条完整的工具扣费明细记录，包含时间、租户、调用人、工具组、二级工具、价格快照（计价方式、价格、币种、次数及按金额时的积分单价与汇率）、本次扣减积分、调用结果（`success`/`failed`/`timeout`/`cancelled`）以及调用来源（日常对话、任务模式、桌面端、助手 ID、工作流 ID、调试、免登录等）；同时对所有计费模型调用明细补充记录调用来源类型与来源 ID。
- **AC-26**（对应评审变更 #2） — THE SYSTEM SHALL 使员工「本月已用 / 剩余」及后台「本月已用」实时包含本期新增的全部模型与工具扣费；当实时账本发生故障重建或对账恢复时，THE SYSTEM SHALL 合并模型与工具两类持久化记录重算「各模型已用 + 各工具已用 = 本月总已用」，保证恢复前后余额一致，且兼容历史无工具分项的月份数据。

### 2.7 全局「积分与计费总开关」与兼容性

- **AC-27**（对应评审变更 #2） — THE SYSTEM SHALL 取消原企业客户端耦合开关（`dsh.enabled`），使企业桌面客户端基础接入常驻可用，并提供独立的全局配置开关控制积分与计费功能（默认开启）。
- **AC-28**（对应评审变更 #2） — WHERE 全局「积分与计费总开关」关闭, THE SYSTEM SHALL 停用全平台（含网页端、桌面端、助手、工作流、托管应用、工具）的积分扣费与额度拦截，不再返回 `26121`，保留平台原有模型可见范围配置（未受限上线模型正常可用）；前端同步隐藏员工端积分余额与倍率提示，以及管理后台积分设置、积分规则、积分用量和工具价格列/「设置价格」入口（保留桌面端基础配置等非积分管理）。
- **AC-29**（对应评审变更 #2） — WHEN 全局「积分与计费总开关」由关闭切换为开启, THE SYSTEM SHALL 仅对开启后的新调用恢复扣费与额度拦截，不对关闭期间发生的调用追溯补扣，并继续沿用存量月度账本记录。
- **AC-30**（对应 PRD AC-A11） — WHEN 旧版本桌面客户端连接新版本服务端, THE SYSTEM SHALL 保持原有对话与工具功能不受影响。
- **AC-31** — THE SYSTEM SHALL 在 MySQL 与达梦（DM8）双数据库方言下均正常完成表结构迁移与读写运行，多租户数据严格隔离。
- **AC-32**（对应 PRD 5.3） — THE SYSTEM SHALL 同步更新托管应用开发文档，补充调用模型网关透传代访问人令牌说明，以及 HTTP 429 / `credit_exhausted`（26121）错误码与建议提示文案。

## 3. 边界情况

- **单次回答多次 / 并行调用工具**：一次对话、任务模式或 Agent 并行/连续调用同一或多个收费工具时，每次调用分别独立计费。
- **工作流节点重试**：工作流工具节点或模型节点配置了失败重试时，每次重试均视为一次独立调用，分别校验额度与扣费。
- **当次轻微透支**：员工剩余额度大于 0 但小于本次工具单价或本次模型实际消耗时（例如剩 `0.2` 积分调用 `2` 积分工具），本次放行并扣减至超额，下一次模型或收费工具调用触发 `26121` 拦截。
- **不限额账号**：月度额度为不限额的员工或免登录运行身份，照常按实际价格扣费并记录明细，不触发额度拦截。
- **工作流运行中途失败**：工作流在某节点因业务异常、超时或中途积分耗尽失败时，此前已发生的模型调用和工具调用照常扣费不回退。
- **模型未配置价格**：助手、工作流、托管应用使用了未配置价格的模型时，沿用 F016 规则按免费（0 积分）放行并记录。
- **存量托管应用未更新**：已上线但尚未改造携带访问人令牌的托管应用，其模型网关调用按「无令牌」计入应用负责人积分，不中断现有业务。
- **后台工具试运行**：管理员或用户在工具页试运行已设价工具时，按非任务模式统一规则校验并扣当前试运行人积分（不限额账号不受拦截）。
- **存量配置兼容**：已有部署的配置文件中若仍残留旧 `dsh.enabled` / `bs_client.enabled` 键，服务升级启动不得因未知字段而崩溃。
