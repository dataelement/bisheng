## Constitution Check

| 条款 | 判断及依据 |
| --- | --- |
| C1 分层 | 各域应用端口+所属Repository/UoW；department/role批量只调用user绑定端口，DSH/审批/audit各自拥有存储 |
| C2 双DB | §4.9新增表发现与既有表DDL分开，JsonType/兼容ID，集中MySQL/DM8验证必需；不以SQLite证明 |
| C3 租户隔离 | 已验证主体/T；定义O和绑定H分开；跨租户只读事实有限缩小；扫描系统先定位再严格T执行 |
| C4 权限 | 不改PDP/FGA模型；已有adapter及durable frozen投影；业务READY晚于投影，super前仍检查pending |
| C5 错误码 | 真实Code字面量核对12个候选无占用，发布契约设计预留；实现期再次核对及三语文案 |
| C6 安全 | 不保存原token/schema密钥，响应不暴露SQL/外部地址；后台原主体引用及当前资格 |
| C7 前端 | §6.1沿controllers/API，组件/query失效/i18n，不在store直接发HTTP |
| C8 多节点 | SQL持久操作/MinIO外部对象，Celery至少一次+租约/CAS；无本地文件权威状态 |
