# Workflow 同步调用昆联 Agent 一期方案

状态为待评审。本稿用于确认范围、接口和验收口径，停在项目 SDD 的 Spec Discovery 阶段。主要依据是 10 月 23 日《昆联 × 毕昇 Workflow Integration》总体设计的 S04／S05、K-01／03／04／06／10 及 A05–A07。11 月 2 日开发包已提供浏览器 OIDC 和用户同步契约，Agent 运行身份和接口仍待昆联确认。F118 提供登录、目录和本地身份映射基础，实际登录联调独立验收。[F118 规格](../../../features/v3.0.0/118-kunlian-sso-user-sync/spec.md)

## 一期范围

| 编号 | 业务结果 |
| --- | --- |
| REQ-01 | 编辑者在毕昇画布配置独立的「平台 Agent」节点，选择有权使用的昆联 Agent 及具体版本，根据版本 Schema 配置输入和输出变量。 |
| REQ-02 | 发布者通过毕昇工作流发布授权后，校验目标版本、Schema、昆联资源权限及跨资产依赖。通过后发布版本固定 AgentVersion 和映射。 |
| REQ-03 | 实际运行者通过毕昇工作流运行授权后，Worker 在节点执行时同步调用指定的昆联 Agent 版本。昆联以实际运行者和租户执行资源及数据授权。 |
| REQ-04 | 昆联返回结构化结果后，毕昇校验并交给下游节点。鉴权拒绝、超时、上游错误或输出不匹配时，节点明确失败，并可用关联标识定位。 |

一期按同步返回终态设计，Worker 在约定时限内等待结果。异步轮询、回调、远端取消、人工输入、反向工具调用、权限镜像和昆联后端代用户管理 Workflow 分别评审。现有毕昇运行入口承接本期场景。

## 双方接口与交付

总体设计中的昆联路径是相对路径。昆联需确认正式路径、测试 Base URL、凭据和 OpenAPI，并提供可用的样例 AgentVersion 及授权和拒绝数据。

| 编号 | 提供方 → 调用方 | 需要交付或确认 |
| --- | --- | --- |
| K-01 | 昆联 IAM 与毕昇 → 毕昇 API／Worker | 确定服务凭据获取方式和实际用户委托协议。明确外部用户与租户字段、签发方、受众、scope、有效期和校验责任。API 侧用于选择和发布的编辑者／发布者身份与 Worker 侧实际运行者身份分别绑定。 |
| K-03 | 昆联 → 毕昇 API | 授权目录 `GET /resources?types=agent&action=use` 及版本详情 `GET /resources/agent/{resource_id}/versions/{version_id}`。明确权限过滤、分页、可用状态、版本 ID、输入输出 Schema 的方言及版本稳定性。 |
| K-04 | 昆联 → 毕昇发布服务／Worker | 提供 `check` 或 `batch_check` 的 HTTP 契约。支持按实际操作者、租户、目标版本和动作返回允许／拒绝及原因。执行端 `invoke` 仍按实际运行人鉴权。 |
| K-06 | 昆联 Agent Runtime → 毕昇 Worker | `POST /agent-runtime/invoke` 同步模式。固化目标版本、结构化入参、可信身份承载、请求关联和幂等字段。响应至少明确实际版本、`agent_run_id`、成功输出或稳定失败原因。双方确认超时、大小限制、重复请求和结果未知的语义。 |
| K-10 | 昆联依赖服务 → 毕昇发布服务 | `POST /dependencies/cycles:check` 或等价契约。明确怎样提交候选版本的依赖清单、如何阻断环路，以及通过检查后的引用如何登记。双方确认发布与依赖登记失败的处理、并发约束和可观察状态。 |
| BS-01 | 毕昇 → Platform 编辑器 | 新增平台 Agent 授权目录和版本详情查询，由毕昇 API 代理昆联接口。前端走现有 API 层，使用毕昇登录身份。正式路由名在接口设计阶段定稿。 |
| BS-02 | 毕昇 → Platform 编辑器／现有运行调用方 | 扩展现有草稿、版本、发布、节点试运行及工作流运行入口。返回节点开始、成功、失败与关联标识。昆联通过 K-06 同步响应回传终态。 |

## 毕昇现有能力与改造点

| 环节 | 可复用的实现 | 一期新增或补齐 |
| --- | --- | --- |
| 编辑器与节点 | Platform 的 [Workflow 画布与节点配置](../../../src/frontend/platform/src/pages/BuildPage/flow/FlowNode/index.tsx)、[节点注册表](../../../src/backend/bisheng/workflow/nodes/node_manage.py)、[BaseNode 变量和回调](../../../src/backend/bisheng/workflow/nodes/base.py#L208)。 | 注册独立的 `platform_agent` 类型，接入授权目录和版本选择。将类型化的上下游映射存入工作流图。现有本地 Agent 节点继续服务原有工作流。 |
| 草稿和发布 | [Workflow v1 路由](../../../src/backend/bisheng/api/v1/workflow.py)、[发布服务](../../../src/backend/bisheng/api/services/workflow.py#L1219)已有版本归属校验、`publish` 权限和当前版本切换。 | 在切换前做昆联权限、Schema、依赖预检，并将通过校验的 AgentVersion、Schema 快照或可核验指纹及映射绑定到本次发布的图。校验与发布之间校对候选内容，防止并发编辑替换已校验的图。运行取已提交的图，固定版本失效时明确拒绝。 |
| 运行与身份 | [已发布工作流执行服务](../../../src/backend/bisheng/workflow/domain/services/published_workflow_service.py#L49)已有任务快照和 RedisCallback。[Worker](../../../src/backend/bisheng/worker/workflow/tasks.py#L59)分别传递实际运行人 `user_id`、Flow 租户和创建者 `flow_user_id`。 | 从可信运行上下文和有效外部映射取得实际用户及租户。Worker 以服务身份按约定获得授权，调用前校验执行主体和目标。所有能进入平台 Agent 节点的试运行和正式入口使用同一身份规则。缺映射、凭据或授权时终止节点。 |
| 结果与异常 | [BaseNode](../../../src/backend/bisheng/workflow/nodes/base.py#L208)负责执行、保存输出变量及发布节点事件，现有执行服务转发运行状态。 | 新节点先校验输入，调用专用昆联客户端，再校验返回版本和输出。成功才写入图变量。失败通过现有事件返回稳定原因，并用 Workflow 运行标识、节点执行标识、`agent_run_id` 和 Trace ID 关联。外部报文和秘密按字段脱敏。 |

拟以现有版本图承载节点配置，持久化和事务方案在详细设计阶段确认。服务凭据由服务侧注入。幂等标识以一次逻辑节点执行为边界，独立运行使用不同标识。同一次调用结果未知时，仅在昆联明确支持幂等重放或原结果查询后才允许按约定处理。试运行使用当前操作者，正式运行使用实际发起人。租户和用户通过可信上下文解析，图参数只承载业务输入。

## 验收

| 编号 | 关联需求 | 场景与可观察结果 | 验证方式 |
| --- | --- | --- | --- |
| AC-01 | REQ-01 | A 在画布只能选到可用且有权使用的版本。保存后重新打开，版本及映射一致。切换到不兼容 Schema 时须提示并阻止无效配置进入发布。 | 编辑器 E2E，配合目录与版本契约样例。 |
| AC-02 | REQ-02 | 有发布权限的 A 发布并固定 V1。昆联新增 V2 后，原发布图仍调用 V1。候选图被并发修改，或版本失效、预检拒绝、依赖成环时，发布失败且旧发布图仍可按其资格运行。 | 发布接口集成测试，加入并发编辑和依赖拒绝用例。 |
| AC-03 | REQ-03 | A 创建、B 获授权运行，昆联证据显示实际执行人为 B，返回结果符合 B 的数据范围。移除 B 的 Workflow 运行权或昆联 Agent 使用权，或用 C 跨租户尝试时，执行被拒绝。 | 真实双系统联调，检查双方脱敏审计。 |
| AC-04 | REQ-03、REQ-04 | 起始节点的结构化参数传入 V1，昆联返回结果，毕昇校验后下游节点读取该输出。画布／运行入口可见节点结果，双方可用关联 ID 找到同一次执行。 | 真实 Workflow 端到端，使用「起始 → 平台 Agent → 输出」最小图。 |
| AC-05 | REQ-04 | 输入不合法时没有发出昆联调用。超时、上游错误、返回版本错配和输出 Schema 不符时，节点失败且下游未收到成功输出。超时结果未知时，按已签订的幂等语义处理。 | 本地契约桩模拟失败和超时，真实联调复核一条明确拒绝路径。 |
| AC-06 | REQ-03、REQ-04 | 试运行与正式运行均从可信身份取得主体。伪造请求或节点里的用户、租户或凭据字段，无法改变调用身份。已运行的旧节点类型继续通过相关回归。 | API／Worker 集成测试与现有工作流回归。 |

本地联调用契约桩验证请求结构、图变量及失败处理。正式通过需有真实昆联测试环境、可用固定版本及 A／B／C 授权数据，留存版本、运行标识、脱敏的身份和输出证据。当前为评审稿，验收项待执行。

## 评审后推进顺序

1. 双方先确认一期同步范围、K-01 可信身份和 K-06 同步预算及幂等语义，并交付 K-03／04／10 契约及样例。依赖检查和登记未定稿时，平台 Agent 工作流发布的验收待闭合。
2. 确认 Discovery 后按项目流程编写正式规格，再评审详细设计及任务。实现按「授权选版本 → 发布固定版本 → Worker 运行 → 结果进下游」切分。
3. 先跑契约桩和本地集成，再使用昆联真实接口跑 AC-03／04，回填验收证据。
