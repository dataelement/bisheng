### 需求信息

| 项目 | 内容 |
| --- | --- |
| 模块 | 专家问答 |
| 变更性质 | 增量补齐现网 `qa_expert`（非重写） |
| 交付面 | Portal UI/BFF + BiSheng `qa_expert` 写模型 |

### 功能描述

专家问答用于承载一线业务问题提问、认证专家解答。用户可发布定向提问或公开提问，系统根据问题类型、问题状态、受邀关系，统一控制内容可见范围与回答资格。

本章按照用户完成业务任务的路径组织：先在首页进入提问；在提问过程中借助类似问题完善或终止重复提问；发布后在同一问题详情页完成查看、回答、互动、采纳、匿名展示及定向转公开；专家榜单与专家库共同构成专家发现和运营体系。通知、权限、数据与并发规则作为跨流程约束统一说明。

用户可见问题状态为三态（与现网 Portal 派生逻辑一致），**不是**仅「未解决 / 已解决」两态：

| 展示文案 | 条件 |
| --- | --- |
| 未回答 | 有效回答数 = 0 |
| 待采纳 | 有效回答数 ≥ 1，且采纳次数 = 0 |
| 已解决 | 至少成功采纳 1 次 |

- 「未解决」仅作筛选项语义：未回答 ∪ 待采纳。
- **不提供「已关闭」标签/主状态**；运营下架只走平台超管违规删除。
- 列表筛参现网 `status=3/4` 表示「我提问的 / 邀请我的」，**不是**业务态「待采纳」；禁止混用（见附录）。

### 规则

- 未登录用户不能进入专家问答页面。
- 定向提问仅提问者、受邀专家和**专家库管理员**可见；公开提问的问题对已登录用户可见。
- 问题中关联的知识库文档始终按访问者自身的知识库权限校验；问题公开不扩张文档权限；无权限时不挡问答正文，链接灰显/不可打开。
- 关联文档的**选择**与**打开**必须使用同一套可解析身份（门户详情能 resolve 的 `knowledgefile`/entry id，或等价的 `canonical_document_id`）。有权限时必须能打开并显示标题，**不得**显示「文档不存在」。
- 「文档不存在」仅用于文件已删除或知识库无有效 entry；无权限必须用「无权限 / 链接不可用」，禁止用「文档不存在」冒充。
- 专家仅指专家库中当前有效、未停用的认证专家。
- 专家不能邀请自己，也不能回答自己提出的问题。
- 问题类型以独立字段区分定向 / 公开（`directed` / `public`，命名实现自定）；**不得**用「有无邀请」推断类型。存量问题一律视为公开。
- 所有读/写接口服务端鉴权；前端隐藏不能替代接口鉴权。

### 名词与状态

| 术语 | 定义 |
| --- | --- |
| 有效回答 | 已成功提交且未删除的回答；已采纳回答始终为有效回答且不可删除。 |
| 受邀专家 | 问题发布或首次回答前由提问者确认的受邀专家集合；问题首次出现回答后邀请名单锁定。 |
| 采纳后可回答的人员 | 公开问题第一次采纳成功时，固化为「受邀专家 + 首次采纳前已提交有效回答的不同专家」（含采纳前已删未采纳回答的专家）。 |
| 匿名稳定别名 | 同一用户在同一问题内固定使用的「匿名同事A/B/…」别名；按题内首次出现匿名内容的时间序分配；跨问题不要求一致；删除不回收、不重排。 |
| 专家库管理员 | 门户 `isPortalAdmin`：角色 ∈ `{管理员, 系统管理员, admin}`（或账号 `admin`）。可维护专家库、查看全部定向问题、查看匿名真实身份。**不等于**平台超管。 |
| 平台超管 | BiSheng `is_global_super` / `require_platform_admin`。可违规删除内容（±积分 R* 扣分）；不自动获得回答、采纳或转公开发起资格。 |
| 专家资格停用 | 取消认证专家身份（调岗、移出专家库等）；账号仍可用；**不是**删问题/删回答。管理端原「删除」改为「停用」（软停用）。 |
| 账号停用 | 系统用户不可登录（如离职）；问答侧按 §3.2.6.7 处理。账号硬删/销户本需求不定义。 |

## 3.2.6.1 问题列表

### 需求信息

| 项目 | 内容 |
| --- | --- |
| 所属模块 | 专家问答 |
| 用例名称 | 问题列表 |
| 需求说明 | 展示专家问答首页、问题列表、统计数据、筛选排序和提问入口。 |

### 功能描述

页面顶部展示专家问答运营区、问题数、回答数、认证专家数、解决率及「我要提问」入口。

列表支持最新、最热、未回答等排序，以及业务域、状态、我提问的、邀请我的等筛选。问题卡片展示问题类型、状态、业务域、标题、摘要、提问人、日期、回答数、浏览数和受邀专家。

定向问题只出现在有权人员的列表、搜索和消息跳转中；公开问题面向全部已登录用户展示完整内容。

### 规则

- 最热排序以热度指标（包括浏览、回答数等行为）执行；未回答页签仅展示有效回答数为 0 的问题。
- 已回答但尚未采纳的问题，展示状态为**待采纳**（属未解决筛选项集合）。
- 匿名提问在列表卡片即执行脱敏；不得先返回真实身份再由前端隐藏。

## 3.2.6.2 提问发布

### 需求信息

| 项目 | 内容 |
| --- | --- |
| 所属模块 | 专家问答 |
| 用例名称 | 提问发布 |
| 需求说明 | 在同一提问流程内完成问题准备、类似问题判断、提问类型选择、专家邀请和正式发布。 |

### 功能描述

用户进入「我要提问」后，页面同时承担问题准备和发布决策。用户填写标题与描述时，右侧「提问小贴士」提示补充现象、已做检查、设备编号和现场资料；「类似问题」根据当前输入持续匹配用户有权查看的历史问题，帮助用户先判断是否已有可复用答案。

用户可打开类似问题查看历史详情，类似问题仅提供辅助，不阻断发布；当用户提问时，在同一页面选择定向或公开类型，填写标题、业务领域、问题描述，添加图片、普通附件或关联知识库文档，并完成专家邀请及身份公开选择。

定向提问要求一定要邀请专家，提问者在提问的时候，需要选择「后续转为公开问答后是否公开姓名」，这个选项决定了后续转为公开提问后，是否为匿名。在定向提问中，提问者和专家固定都是非匿名状态。

公开提问要求提问者在提问时选择是否匿名。

### 提问流程

| 阶段 | 用户行为 | 系统反馈 |
| --- | --- | --- |
| 问题准备 | 输入标题和问题描述 | 展示提问小贴士，并按输入更新类似问题 |
| 重复判断 | 查看有权访问的类似问题 | 打开历史详情；返回后保留当前未发布内容 |
| 完善发布信息 | 选择问题类型、业务域、附件、关联文档和受邀专家 | 按定向/公开类型切换邀请和身份公开要求 |
| 提交发布 | 确认并点击发布 | 校验必填项、邀请人数、本人邀请限制，成功后进入详情页 |
| 发布后锁定 | 有任意专家进行了首个有效回答提交 | 锁定问题正文、类型、邀请名单、身份公开选项和删除入口，提问者无法再编辑问题 |

### 提问类型差异

| 项目 | 定向提问 | 公开提问 |
| --- | --- | --- |
| 邀请专家 | 必选，1—3 位 | 可选，0—3 位 |
| 初始可见范围 | 提问者、原受邀专家、专家库管理员 | 当前租户内全部已登录用户 |
| 未解决时回答人 | 仅原受邀专家 | 全部有效专家；受邀专家额外收到提醒 |
| 提问者匿名选项 | 保存「转公开后是否公开姓名」；定向阶段始终实名 | 发布时直接选择是否匿名 |

### 规则

- 标题、业务领域和问题描述必填；图片最多上传 3 张，普通附件遵循平台上传限制，关联知识库文档仅保存引用关系。
- 定向提问必须邀请 1—3 位当前有效专家；公开提问可邀请 0—3 位专家。任何类型均不能邀请提问者本人。
- 定向提问保存「后续转为公开问答后是否公开姓名」，但定向参与者之间始终实名；公开提问发布时直接选择是否匿名。
- 相似问题召回必须先过滤问题可见范围；定向问题不得因相似度命中而泄露给无权用户，匿名问题在结果中继续匿名。
- 类似问题不阻断发布，也不替用户自动合并或关闭问题。
- 发布成功后展示状态为**未回答**。首个有效回答前，提问者可编辑、切换类型、调整邀请、修改身份公开选项或删除问题。首个有效回答提交后上述内容全部锁定（锁标记原子更新；并发允许多条首答成功）；之后即使全部未采纳回答被删除、有效回答数回到 0，**也不解除锁定**（文案可回到「未回答」）。

## 3.2.6.3 问题详情

### 需求信息

| 项目 | 内容 |
| --- | --- |
| 所属模块 | 专家问答 |
| 用例名称 | 问题详情 |
| 需求说明 | 在同一详情页完成内容查看、专家回答、互动追问、回答采纳、匿名展示和定向转公开。 |

### 功能描述

问题发布后，详情页成为问题从「未回答 / 待采纳」到「已解决」、以及定向问题后续转公开的统一协同工作台。页面根据问题类型、当前状态和访问者资格，展示问题正文、普通附件、关联知识库文档、受邀专家、回答、评论、追问、采纳状态及可执行操作；各阶段共享同一份问题和回答事实，避免不同页面产生权限或状态差异。

### 详情页生命周期

| 阶段 | 可见范围 | 回答与互动 | 关键动作 |
| --- | --- | --- | --- |
| 定向—未回答/待采纳 | 提问者、原受邀专家、专家库管理员 | 原受邀有效专家回答；提问者追问；已回答专家参与评论 | 提问者可采纳回答 |
| 定向—已解决 | 同上 | 原受邀有效专家仍可继续回答和互动 | 继续采纳至 3 次；符合条件者可发起转公开 |
| 定向—转公开审批中 | 同上 | 原受邀有效专家仍可回答；回答删除暂时锁定 | 审批人同意或拒绝；新增回答专家动态加入审批 |
| 定向已转公开 | 全部已登录用户 | 仍仅原受邀有效专家回答；公开用户按规则评论 | 身份按预存匿名选项展示；转换不可撤销 |
| 公开—首次采纳前 | 全部已登录用户 | 全部有效专家可回答（提问者除外） | 首次采纳时生成持续回答资格快照 |
| 公开—首次采纳后 | 同上 | 仅资格快照中的当前有效专家继续回答 | 继续采纳至 3 次；未采纳回答按规则删除 |

### 内容展示与访问边界

详情区展示问题类型、业务域、状态、标题、正文、普通附件、关联知识库文档、提问时间、浏览量、受邀专家和完整互动记录。定向阶段只向提问者、原受邀专家和专家库管理员返回完整详情；转换完成或问题本身为公开类型时，完整业务内容面向当前租户内已登录用户公开。

- 公开范围仅限当前租户内已登录用户，禁止未登录或跨租户访问。
- 问题、回答或评论配置匿名时仅隐藏身份字段，业务正文仍完整可见。
- 关联知识库文档在展示链接、打开预览、下载和接口取数时分别校验访问者权限。
- 回答、采纳、删除和转公开入口由服务端资格结果驱动；前端隐藏不能替代接口鉴权。

### 回答、采纳与问题解决

符合资格的专家可在详情页提交富文本回答，添加图片、普通附件或关联知识库文档；同一专家可多次回答，回答时可选择是否匿名，每条回答独立保存身份公开的选项。提问者可在同一详情页对有效回答进行采纳，首次采纳后问题立即进入已解决状态，详情页继续保留符合资格的专家的回答入口。

- 回答正文必填；提交时校验专家当前有效、不是提问者本人、拥有问题查看权限且符合回答资格。
- 回答一经提交，在任何问题状态下均不能编辑或修改。
- 定向问题在未解决（未回答/待采纳）、已解决及转公开后，始终只允许原受邀且当前有效的专家回答。
- 公开问题首次采纳前允许全部有效专家回答；首次采纳成功时进行记录，之后仅受邀专家和首次采纳前已提交有效回答的专家继续回答。
- 首次采纳前已回答专家即使后来删除未采纳回答，也保留持续回答资格；专家资格停用或账号停用后不再允许回答。
- 每题最多 3 条有效采纳记录，同一回答只能采纳一次；采纳后不能取消，已采纳回答不能编辑或删除。
- 同一专家的多条回答可分别被采纳并分别占用槽位；达到 3 次采纳后仍可回答，但提问者的采纳已达上限，无法再采纳。
- 采纳槽位并发：事务/条件更新保证第 4 次采纳失败并返回业务错误。

### 回答资格矩阵

| 问题类型/阶段 | 可继续回答的专家 | 不可回答情形 |
| --- | --- | --- |
| 定向—未回答/待采纳 | 原受邀且当前有效的专家 | 非受邀专家、提问者本人、已停用专家 |
| 定向—已解决 | 原受邀且当前有效的专家 | 同上；达到 3 次采纳不关闭回答入口 |
| 定向已转公开 | 仍仅原受邀且当前有效的专家 | 公开可见不重新开放回答资格 |
| 公开—首次采纳前 | 当前全部有效专家（提问者本人除外） | 提问者本人、已停用专家 |
| 公开—首次采纳后 | 资格快照中的当前有效专家 | 无资格专家；有资格专家删除未采纳回答后仍保留资格 |

### 采纳计数与积分边界

| 项目 | 规则 |
| --- | --- |
| 采纳槽位 | 每题最多 3 条有效采纳记录；每条回答最多占用 1 个槽位。 |
| 同一专家多回答 | 多条回答可分别被采纳并分别占用槽位。 |
| 问题状态 | 首次采纳成功即变为已解决；后续采纳不再改变状态。 |
| 积分系统（F070） | 采纳成功触发积分挂钩；本域不写积分账本、不自拟幂等键或分值。业务意图：同一专家在同一问题中多次被采纳只激励一次；细则与 `idempotency_key` 归 F070 / release-contract INV-11～14。 |
| 现有专家分 | 专家榜单仍按回答数 × 1 + 采纳数 × 5 + 获赞数 × 2 排序，不与积分系统合并；本需求不改投票/获赞语义。 |

### 评论、追问与回答删除

提问者围绕问题发起追问，其他用户围绕回答继续讨论。定向阶段，专家须先在本问题提交有效回答后，才能在回答下方进行评论；定向阶段产生的有效回答、评论和追问在问题转公开后随问题一并公开。转为公开后，已登录用户可参与评论。

- 回答的作者只能删除本人发布的且还未被采纳的回答；删除后该回答、普通附件及其全部评论从业务页面中删除。
- 存在有效转公开申请时，任何专家都不能删除自己的回答，只能等待申请通过、被拒绝、过期或因提问者账号停用结束。
- 转公开完成后，未采纳回答仍允许作者删除。
- 已采纳回答始终不可删除；评论所依附回答删除时，其全部评论同步删除。
- 评论和追问的可见范围跟随问题；其中关联的知识库文档链接仍需跟随权限系统进行鉴权。

### 互动身份继承

| 互动类型 | 匿名规则 |
| --- | --- |
| 提问者追问 | 继承问题的匿名状态 |
| 专家评论自己的回答 | 继承该回答的匿名状态 |
| 用户评论他人的回答 | 在定向和公开提问中评论时，单独选择是否匿名 |

### 匿名身份贯穿详情生命周期

公开提问时，提问者选择是否匿名，每条专家回答独立选择是否匿名。定向提问时，问题、每条回答、评论他人时各自保存「转为公开提问后是否公开姓名」；转公开时不再次询问，而是按原先保存的选择统一生成公开身份。定向阶段保持实名展示。追问继承问题；专家评论自己的回答继承该回答。

- 匿名时展示固定匿名头像和「匿名同事A、匿名同事B……」稳定别名，不展示真实姓名、部门、岗位、职务、简介等可识别信息。
- 同一用户在同一问题的全部匿名内容中保持同一别名；不同问题之间可重新分配。删除某条内容不得导致其余别名重新排序。
- 除**专家库管理员**外任何人均看不到匿名内容的真实身份；列表、详情、搜索、通知和接口字段必须由服务端统一脱敏。

### 匿名覆盖范围

| 位置 | 非专家库管理员展示 | 专家库管理员展示 |
| --- | --- | --- |
| 问题列表/详情 | 固定匿名头像、稳定别名；不显示岗位、部门等身份字段 | 可查看真实身份及匿名展示结果 |
| 回答/评论/追问 | 按内容继承或独立匿名规则展示稳定别名 | 可查看真实身份及匿名展示结果 |
| 搜索结果 | 不返回真实姓名、头像、部门、岗位等可识别字段 | 可按管理权限查看真实身份 |
| 通知消息 | 触发人匿名时使用稳定别名或不含真实身份的文案 | 可查看真实身份 |
| 接口字段 | 服务端直接脱敏，不向客户端下发真实身份字段 | 仅专家库管理员授权接口返回真实身份 |

### 已解决定向问题转公开

定向问题被采纳并进入已解决状态后，提问者或拥有有效回答的专家可直接从详情页发起转公开申请。申请把提问者和所有拥有有效回答的不同专家作为同一内容共同体进行审批；只有全体当前审批人同意，系统才将完整问题及其互动记录不可逆地转为公开。

- 数据落点：独立申请表 + 审批人明细表（禁止整段 JSON 塞问题表）。
- 同一问题同一时间最多一个有效申请；发起者选择 1 天、3 天或 7 天有效期，发起者自动记为同意且不能撤回。
- 同意或拒绝一经提交不可修改；任一审批人拒绝后申请立即结束，过期、拒绝的旧申请不能继续操作，但允许重新发起。
- 审批中新出现不同回答专家时，回答提交成功的一瞬间将其加入审批人并发送同一申请；同一专家新增回答不重复审批。
- 每新增一名不同审批专家，在当前到期时间上延后 1 天；同一专家不重复加入或延时，累计最多延长 3 天。
- 已删除未采纳回答且不再拥有其他有效回答的专家不再属于审批人；专家资格停用、从专家库移除、或账号停用的专家不再属于审批人，系统默认该专家为同意，并**立即重判**是否全体同意（默认同意可导致无人再点按钮即转公开，须写审计日志）。
- 提问者账号停用后不能发起转公开申请；正在进行的申请自动结束，问题保持定向。
- 转换完成后不可恢复为定向，也不重新开放回答资格，仍只有原受邀且当前有效的专家可继续回答。
- 过期判定：定时任务 + 读时惰性双保险；允许秒～分钟级延迟（建议容忍 ≤1 分钟）。

### 审批人与时限

| 项目 | 规则 |
| --- | --- |
| 发起条件 | 问题已解决；无其他有效申请；发起人为提问者或拥有有效回答的专家。 |
| 审批人 | 提问者 + 所有拥有有效回答的不同专家；发起者自动记为同意。评论者无需单独同意。 |
| 有效期 | 发起者选择 1 天、3 天或 7 天，按服务端时间生成到期时间。 |
| 新增专家 | 审批中新增不同回答专家时，加入审批人、立即通知，并在当前到期时间上延后 1 天；同一专家不重复加入或延时，累计最多延长 3 天。 |
| 移除/停用专家或账号停用 | 不再属于审批人，系统按默认同意处理并立即重判；其既有内容继续按原匿名选择展示。 |
| 提问者账号停用 | 不能新发起申请；审批中的申请自动结束，不执行公开转换。 |

### 申请状态

| 状态 | 进入条件 | 允许操作 | 结束结果 |
| --- | --- | --- | --- |
| 审批中 | 创建成功且未到期 | 审批人同意或拒绝；不能撤回；专家回答不可删除 | 全体同意、任一拒绝或到期 |
| 已通过 | 全体当前审批人在到期前同意（含系统默认同意凑齐） | 旧申请不可再操作 | 问题不可逆转为公开 |
| 已拒绝 | 任一审批人拒绝 | 旧申请不可再操作；允许重新发起 | 问题保持定向 |
| 已过期 | 服务端时间达到到期时间且未通过 | 旧申请不可再操作；允许重新发起 | 问题保持定向 |
| 已结束 | 提问者账号停用 | 旧申请不可再操作 | 问题保持定向 |

## 3.2.6.4 专家管理

### 需求信息

| 项目 | 内容 |
| --- | --- |
| 所属模块 | 专家问答 |
| 用例名称 | 专家管理 |
| 需求说明 | 统一支撑用户发现和邀请专家，以及专家库管理员维护专家身份、状态、专业信息和贡献数据。 |

### 功能描述

专家榜单和专家库使用同一套专家主数据与贡献统计。前台榜单面向提问用户，突出当前有效专家的专业信息和答题贡献，帮助用户识别、查看并在提问时邀请合适专家；后台专家库面向**专家库管理员**，负责专家身份、关联用户、专业标签、组织岗位、排序和有效/停用状态的维护。后台状态变化实时影响前台榜单、可邀请范围、回答资格及转公开审批人集合。

BiSheng 专家写接口（创建/更新/停用）必须服务端校验专家库管理员；不得仅依赖 Portal 前端隐藏按钮。

### 前后台协同

| 使用场景 | 展示/操作 | 数据与状态影响 |
| --- | --- | --- |
| 首页专家榜单 | 展示头像、姓名、认证标识、组织岗位、回答等贡献数据；进入完整专家列表 | 仅展示当前有效专家，默认按专家分排序 |
| 提问邀请专家 | 搜索并选择 1—3 位有效专家 | 来源于专家库有效数据，禁止邀请提问者本人 |
| 专家库管理 | 新增、编辑、排序、**停用或恢复**专家；维护简介、专业、职位族、职位类、职务和岗位 | 专家必须关联当前租户系统用户；姓名和部门可同步；管理端原「删除」改为「停用」（软停用） |
| 状态变更 | 专家库管理员停用或恢复专家 | 停用后停止新回答并退出新排行；既有内容保留；恢复不追溯加入历史申请 |
| 贡献统计 | 展示回答数、采纳数、获赞数和专家分 | 专家分用于现有榜单；积分系统独立计算 |

### 规则

- 榜单仅展示当前有效认证专家；匿名仅作用于具体问题中的身份展示，不要求在专家榜单中匿名。
- 专家分计算公式为：专家分 = 回答数 × 1 + 采纳数 × 5 + 获赞数 × 2，并用于榜单排序。
- 专家分与积分系统相互独立；同一专家同一问题多次被采纳时，积分侧业务意图为只激励一次（细则归 F070）。
- 仅专家库管理员可维护专家库；专家身份不自动扩大知识库文档权限。
- 专家资格停用后不能新回答，其既有内容继续按问题可见范围与匿名规则展示；账号仍可用时可继续提问/评论（非专家权限）。
- 专家在转公开审批中被停用时，从审批人集合移除并按系统默认同意处理；系统立即重新判断是否满足全体同意。
- 专家恢复启用不自动加入已经结束或已经完成的历史申请。
- 不提供业务硬删专家入口；硬删仅 DBA/超管修数场景，不进产品按钮。

## 3.2.6.5 消息通知

### 功能描述

通知包含问题标题、触发动作、处理状态和可访问的问题/回答/审批入口，并支持未读、已读状态。

通知覆盖邀请回答、问题被回答、回答被评论、回答被采纳，以及转公开申请、新增审批人、申请通过、拒绝、过期、因提问者停用结束和问题完成转换。

| 回答被采纳 | 回答作者 | 展示采纳结果，匿名身份继续脱敏。 |
| 转公开申请 | 当前审批人 | 展示发起人、到期时间和审批入口。 |
| 新增审批人 | 新增专家、原审批相关人 | 提示审批人和到期时间已更新。 |
| 申请通过/拒绝/过期/结束 | 发起人、审批人 | 展示最终状态和问题入口。 |
| 问题已转公开 | 提问者、回答专家 | 提示不可撤销，身份按匿名规则展示。 |

## 3.2.6.6 权限规则

### 需求信息

| 项目 | 内容 |
| --- | --- |
| 所属模块 | 专家问答 |
| 用例名称 | 权限规则 |
| 需求说明 | 统一限定问题可见、提问、邀请、回答、采纳、删除、审批和专家库管理范围。 |

### 功能描述

权限由租户身份、登录状态、提问者身份、专家有效状态、原受邀关系、问题类型、问题状态、首次采纳资格快照、回答归属、专家库管理员及平台超管权限共同决定。

前端根据服务端返回的可操作项展示入口；所有写接口和内容读取接口仍需在服务端重新鉴权。

专家库管理员 ≠ 平台超管；不得把中文角色「管理员」自动升格为 `is_global_super`（避免撞击分 INV-12/14）。

### 规则

- 未登录用户不能查看或操作专家问答。
- 专家库管理员可查看定向问题和匿名真实身份，但不自动获得回答、采纳或转公开发起资格。

- 问题、回答、评论、通知和搜索必须使用相同的可见范围与匿名策略。
- 停用账号不允许发起新的业务操作；提问者账号停用时按转公开申请规则结束正在进行的申请。

| 发布问题 | 可 | 可 | 可 | 可 | 可（若账号未停用） |
| 邀请专家 | 仅本人问题首次回答前 | 可，最多 3 位且不能邀请自己 | 仅作为提问者时 | 可管理专家库，须遵守业务锁定 | 同左（不因超管额外放宽） |
| 回答问题 | 不可 | 不可回答本人问题 | 按问题类型、状态和资格快照判断 | 仅同时具备有效专家资格时 | 仅同时具备有效专家资格时 |
| 采纳回答 | 不可 | 仅本人问题，最多 3 次 | 不可 | 不代替提问者采纳 | 不代替提问者采纳 |

| 发起转公开 | 不可 | 满足条件时可 | 有有效回答且满足条件时可 | 不因管理员身份自动具备 | 不因超管身份自动具备 |
| 维护专家库 | 不可 | 不可 | 不可 | 可（服务端强制校验） | 不可（除非兼专家库管理员） |
| 查看匿名真实身份 | 不可 | 不可 | 不可 | 可 | 不可（除非兼专家库管理员） |
| 违规删除内容 | 不可 | 不可 | 不可 | 不可 | 可 |

## 3.2.6.7 专家资格停用与账号停用

### 专家资格停用（账号仍可用）

- 含义：取消认证专家（调岗、移出专家库等），不是删问题、不是删回答。
- 落库：`qa_expert` 有效/停用状态；管理端「停用」为软停用。
- 效果：不可被邀请、不可新回答、退出有效榜单；既有内容按问题可见性保留；转公开审批中移出审批人并默认同意后立即重判。
- 恢复启用：不追溯加入已结束/已完成的历史转公开申请。
- 用户仍可登录提问/评论（非专家权限）。

### 账号停用

| 身份 | 行为 |
| --- | --- |
| 提问者 | 进行中转公开申请结束；不可新发起；其问题只读保留 |
| 回答专家（兼审批人） | 与专家资格停用相同：不可新答；审批默认同意并重判 |
| 仅评论者 | 历史评论保留；展示名可按账号体系惯例 |

### 账号删除 / 销户

- 本需求不定义硬删/匿名化销户；依赖账号域提供停用。
- 有问答产物的账号删除策略另文。

| 积分 F070 | 采纳成功调用挂钩；本域不写账本；同题同专家只激励一次为业务意图；幂等键与分值归 F070；不得覆盖 release-contract INV-11～14 |
