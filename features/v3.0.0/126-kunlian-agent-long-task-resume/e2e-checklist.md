# Agent 长任务挂起与恢复联调清单

使用隔离测试租户、临时会话数据库和回环地址的 Redis 队列。API 与 Worker 在测试装配中同时启用 `enable_long_tasks` 和 `enable_long_task_resume`，注册普通长任务恢复及补偿扫描任务。Agent 使用可控时间的 Mock。准备发布者、运行者和无权读取原会话的账号。

| 检查项 | 操作 | 通过标准 |
| --- | --- | --- |
| 固定版本发布 | 在 Platform 打开[示例工作流](./mock-workflow.example.json)，确认平台 Agent 节点选择 `mock:echo / v1`、异步执行且关闭人工输入，然后发布。 | Workflow 和 Agent 均绑定固定版本。 |
| 等待和刷新 | 用运行者打开 Client 的 `/workspace/app/<conversationId>/<workflowId>/10`。保持远端未完成并刷新。 | 等待时无人工表单或下游输出。刷新前后的执行、Agent Run 和截止一致。 |
| 完成和结果回读 | 让原 Mock Run 成功，等待输出后再次刷新。 | 下游只保存一条消息，回读使用同一个消息 ID，浏览器只显示一次。 |
| 停止和重跑 | 用新会话发起第二次执行。在等待时点击停止，先观察取消受理，再推进 Mock 时间观察确认。刷新后点「重新运行」。 | 停止时无下游输出。刷新仍展示原停止终态，显式重跑才创建新的执行与 Agent Run。 |
| 权限 | 以无权限账号请求上述原会话状态和输出。用定向测试复核会话历史、按会话取消息和无授权主体的通用读取。 | 无权时不能收到原执行状态或正文。允许访问的历史响应移除内部关联标记。 |

同时复核单执行槽和跨 Worker 两项队列验收。运行命令、实际结果和环境限制见[验证记录](./verification.md)。
