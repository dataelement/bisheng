# DSH 14 天设备闲置会话 — 服务端增量规格

2026-11-06。用户已确认 [最终方案](../refresh-reliability-plan.md)，并明确授权基于 feat/bisheng-work-130 实施服务端，客户端暂不实施。沿用 F110，不新增特性编号。

## 目标与范围

持续业务使用自动延长该设备登录，默认连续闲置 14 天过期。保持多设备独立和已发布 1.2.0 登录协议，保留 refresh 轮换与恢复。客户端 1.3.0 优化、浏览器回调重设计及生产部署不在此次实施范围。

## 验收标准

| ID | 标准 |
| --- | --- |
| AC-IDLE-01 | 新登录默认 14 天，持续活动跨越原 30/60 天仍可刷新；保持原 session_id 和 created_at，无强制绝对上限 |
| AC-IDLE-02 | refresh、恢复返回、cookie 换发/校验、模型目录、状态及工作流状态轮询不续期；now>=expires_at 拒绝，不能复活 |
| AC-IDLE-03 | 业务通过验证和准入后、供应商或工具执行前续期；上游失败仍计活动；活动保存失败不执行上游，释放已取得的资源 |
| AC-IDLE-04 | 会话与 ACTIVE refresh 有效期一致；旧 USED 截止时间不提前阻断滑动恢复；后继已消费仍撤销 |
| AC-IDLE-05 | 活跃、过期、退出、重放只影响对应设备；精确租户和人员隔离；账号停用影响其凭据 |
| AC-IDLE-06 | 历史行不伪造活跃；按显式开关在下一次有效业务活动转换；后台操作不转换，失效行不恢复 |
| AC-IDLE-07 | 1.2.0 回调/粘贴及 PKCE 请求、标准/兼容路径、响应字段不变；旧解析器接受新截止时间；cookie 业务绑定准确设备 |
| AC-IDLE-08 | 兼容 MySQL/DM8 的 DDL，重复执行安全、单 head；期限固化到会话，配置改变不重解释已有行；长期链撤销不遍历历史 |

## 确认与边界

默认 idle=1209600 秒，默认存量转换开关关闭，以便按发布顺序开启。没有客户端活动心跳或可信前台标记的新增要求。只认服务端业务准入，不声称能证明请求来自真人。实际 1.2.0 安装包跨期恢复和 MySQL/DM8 并发必须作为发布验收，不能由本地 mock/SQLite 代替。
