# 制作网页报告

## 0. 开工纪律

**这一轮只读文档，不要在同一轮里并行调用别的工具。** 读完本文件，按需再读 references 和底座，
下一轮才开始动手。

本技能**不需要代码执行工具**：页面用文件工具（write_file / edit_file）写成，用 check_html 检查。
本次如果有代码执行工具，可以用它画图表（见 §3.4），没有也能完成。

## 1. 交付约束（硬性，违反就是交付失败）

用户会在两个地方打开这个文件：界面里的预览框（沙箱 iframe，没有网络、没有基础路径），
以及下载到本地后直接双击（单个文件，旁边没有任何资源）。所以：

| 项 | 要求 |
|---|---|
| 文件 | 一个 `output/<name>.html`，完整的 `<!DOCTYPE html>` 文档 |
| 样式 | 全部写在 `<style>` 里 |
| 脚本 | 全部写在 `<script>` 里；不用任何框架和库；不读写 localStorage |
| 图片 | 只能用 `data:` URI 或内联 `<svg>` |
| 禁止 | 任何 `http(s)://`、`//` 开头的资源地址（CDN、Google Fonts、图床），以及 `output/x.png` 这类相对路径——都加载不到 |
| 字体 | 只用系统字体栈（底座里已写好），不引用网络字体 |
| 超链接 | `<a href="https://…">` 是跳转，不是资源，可以用 |
| 中间产物 | 写 `scratch/`，不进交付 |

## 2. 先做设计计划（写代码之前）

在思考里写 6～10 行设计计划，**不写进文件**：

1. **报告类型、读者、主要任务**：例如「审核报告；读者是评审会；任务是让人 30 秒看到要改什么」。
   这三项决定版块取舍，答不上来就回头看用户的问题。
2. **信息结构**：结论放在哪、问题按什么排序、哪些明细收进折叠。参照
   `/skills/html-report/references/patterns-zh.md` 选版块。
3. **颜色 token**：底座的 `:root` 已有一套克制的配色。只在有理由时改 `--accent`
   （例如客户材料里有明确的主色）；状态色（ok / warn / risk）保持语义，不要拿来装饰。
4. **版式线框**：用两三行 ASCII 画出页面从上到下的版块顺序。

然后对照 `/skills/html-report/references/design-zh.md` §4 的「生成式默认审美清单」复查一遍：
计划里任何一项是「换个题目也会这么做」的默认选择，就改掉它，并说明改了什么。

## 3. 组装页面

### 3.1 读底座

```
read_file("/skills/html-report/assets/report-base.html", limit=1000)
```

**必须传 limit=1000**（默认只读 100 行，会漏掉样式和脚本）。返回内容每行带行号前缀，写文件时去掉。

### 3.2 写骨架

用 write_file 写 `output/<name>.html`：

- 保留底座的 `<style>` 和末尾的 `<script>`；删掉本页用不到的版块对应的样式，也删掉 CSS 注释。
- `<main>` 里只放计划中要用的版块，示例文字全部换成真实内容；用不到的版块整段删除，不留空壳。
- 页面较长（预计超过 6 个版块，或对照表超过 30 行）时，先写骨架：标题区、结论区和各节标题，
  每节正文先放一句占位，再用 edit_file **逐节**替换成正文。一次 write_file 写太长容易被截断。

### 3.3 写内容

- **结论先行**：结论区的第一句就是总判断，后面不超过 4 条要点。读者只看这一块也能做决定。
- **问题按严重程度排序**：每条发现写清现象、依据（出处、页码、条款）、建议。
- **对照表只标差异**：一致的行不加标记；有差异的行用 `diff`，相互矛盾的行用 `conflict`。
- **数字**：金额、比例右对齐（`td.n`），单位写在表头；同一列保留相同小数位。
- **文案**：写给业务读者，用业务词，不用内部字段名；按钮和标签用短动词或名词。
  细则见 design-zh.md §5。

### 3.4 图表

先问自己：这个数字用一句话或一张表能不能说清？能就不画图。

- 简单比例、排名：用底座的 `.bars` 条形图（纯 CSS，`--v` 填 0-100）。
- 需要折线、散点等复杂图形，且本次有代码执行工具：用
  `skills/html-report/scripts/svg_chart.py` 生成 SVG 文本（用法见脚本头部说明），
  把输出的 `<svg>…</svg>` 原样嵌进页面。
- 没有代码执行工具又必须画复杂图：手写简单的内联 `<svg>`（坐标轴加折线即可），不要引用任何图表库。

## 4. 检查

写完调用：

```
check_html(path="output/<name>.html")
```

- 报告里有 **ERROR**：逐条用 edit_file 修复，再调用一次 check_html。**最多修 2 轮。**
- **WARN** 不阻止交付，修起来简单就修（例如补 viewport），代价大就跳过。
- 报告里有截图路径、并且你能看图时，read_file 看一次截图，按「出门前摘掉一件配饰」自评：
  有没有哪个装饰不服务于内容（多余的图标、色块、分隔线），删掉它。
- 2 轮后仍有 ERROR：在收尾里如实说明还剩什么问题，不要声称页面没有问题。

## 5. 收尾

用 1～2 句话概括报告的核心结论。不要复述文件名、路径或「已完成」之类的状态字样。
