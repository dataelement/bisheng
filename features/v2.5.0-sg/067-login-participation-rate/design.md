# 设计

## 查询策略

在用户统计的参与占比和实际登录人数上使用专用查询策略。读取现有 ES participation 登录事实，完整分页到统计截止日；业务筛选保持，时间筛选提取为期间边界，历史读取去掉下界。流式维护每组每用户首次登录日以及每个展示期间的去重用户集合，分母按首次登录日不晚于各期间结束日累计。查询用一致性快照，分页失败、超时或部分分片失败报错，避免输出残缺比例。

支持时间和自然日，以及现有人员/部门维度；同一嵌套对象的维度保持配对。含时间的 OR/NOT 等不能唯一确定累计截止点的筛选显式拒绝。按日事实不支持小时粒度。无时间筛选截止今天；图表中的时间范围裁剪只作用分子和展示区间。日期按北京时间自然日，周一开始一周。

保留 participation_rate 和 logged_in_employee_count 字段标识，通过 calculation 路由新算法；默认百分比格式。两个已有用户数据集的初始化配置同时更新，正常应用启动刷新配置。实际登录人数和参与率共用去重事实；导出沿用原明细扫描，通过指标的 cardinality 配置按用户去重。

## 边界

人员组织仍按历史登录事实上的维度字段，沿用现有筛选含义，不新增权限/租户政策、不改变账号名单、不新增登录采集。缺失的历史事实不能凭当前名单补成登录事件。历史读取的成本与筛选后累计登录人天数相关；本轮不引入额外索引、迁移或缓存。

## 回退与部署

仅本地代码修改；回退本次代码并正常重启以恢复旧指标配置。部署后核对索引覆盖时间和样本；不自动补历史或执行生产变更。导出展示的是期间登录人员（分子），不把累计分母人员混入明细。
