## 本轮实际修改

### 普通迁移移除物理存储盘点

- CLI 不再构造或导入普通迁移的 ES/Milvus 客户端。
- M2 不读取普通索引的存在性、mapping/schema/count，也不对正常文件逐个 MinIO stat；正常资源仍冻结 SQL 中的原索引绑定，由原业务摘要/转换计划校验。
- 新 baseline/plan 均写 `physical_inventory_policy=bindings_only`，不造空数量、空结构或未验证的物理事实。两根策略必须一致，新策略拒绝任何 physical 页，包括空叶页。
- 原冻结图无该字段时，仍采用原完整物理证据与旧索引保留证明校验；原文件标识、绑定及相关SQL范围保护不改，不重写旧基线。
- 历史准备中已授权的孤儿文件精确备份/删除仍保留。只有选中集合非空才访问相关物理端口；未知绑定、有效下游或无法精确定位时仍阻断。
- MinIO 的正式迁移证据、备份/schema材料和冻结对象读取继续保留。

### 新 Run 真正执行完整只读预检

`Inventory.arun(..., freeze=False)` 复用正式 M2 的结构、历史准备、资源、权限、六类来源及引用盘点和完整分页图校验；成功不调用 `afreeze_all`，不写 SQL/FGA 或持久 MinIO 对象。

临时分页使用一次性0700本地目录及0600文件，沿用原 canonical envelope、SHA256和单页大小校验，不将全量内容堆入内存。成功、异常及取消退出后清理；它们不进入SQL指针，也不作为备份或续跑来源。

| 分支 | 输出和语义 |
| --- | --- |
| 新 Run 预览 | `validation_scope=current_inventory`、`preflight_complete=true`、`frozen=false`、`ready=false`；不输出临时 baseline/plan 描述符 |
| 原冻结 Run 预览 | `validation_scope=frozen_run`、`preflight_complete=false`；复核原计划，不宣称重新扫描当前数据 |
| 新 Run apply | 重新扫描当次事实、保存正式对象、冻结原子Run，再进入原M3/M4；不复用预览临时页 |

备份/schema材料仍须符合当次 Run、环境、writer与实际租户集合。原30租户材料不能冒充31租户的新材料。旧 Run 的租户集合约束未被放宽；已完成后新增租户的独立历史复核能力不在本轮伪造实现。

独立审查发现两处边界并修复：新预览初查之后同名 Run 被并发冻结时，扫描入口明确拒绝 `migration_inventory_preview_requires_new_run`；physical 页检查放在 section 层，避免空页绕过逐记录验证。

### 历史恢复测试纠正

恢复生产逻辑的原操作ID、版本及当前 pin 围栏已在前轮实现。本轮修正旧系统资源测试：无约束 mock 不再把非原bootstrap状态假装成可恢复；同时覆盖合法同操作恢复，以及调用方 tenant 为None/99、成功/失败时的完整上下文恢复。没有为适配旧测试放宽生产校验。
