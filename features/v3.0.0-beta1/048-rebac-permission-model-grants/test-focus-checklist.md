# F048 业务功能测试重点清单

> 适用版本：v3.0.0-beta1
> Feature：F048 ReBAC Permission Model Grants
> 目标：从最终用户和权限管理员的实际操作出发，验证“看得到、做得了、管得住、撤得净”。
> 升级脚本、门禁和性能取证的详细步骤见 [E2E 手工与运维验证清单](./e2e-checklist.md)。

## 1. 测试角色与数据准备

### 1.1 账号与组织

- [ ] 平台超管、租户管理员、资源创建者、拥有权限管理能力的普通用户、普通成员、无权限用户。
- [ ] 同租户用户 A/B/C 和另一租户用户 X。
- [ ] 父部门 D1、子部门 D2、D2 成员、非部门成员，以及用户组 G1。
- [ ] 一个用户同时通过“直接用户、部门、包含子部门、用户组”获得同一资源的不同权限。

### 1.2 权限模型

- [ ] 四个标准模型：查看者、编辑者、管理者、所有者。
- [ ] 自定义模型 A：有业务动作但没有“权限管理”。
- [ ] 自定义模型 B：有“权限管理”，禁止授予同级。
- [ ] 自定义模型 C：有“权限管理”，允许授予同级。
- [ ] 已被多个资源使用的自定义模型，以及停用状态的自定义模型。

### 1.3 业务资源

- [ ] knowledge_space、knowledge_library、folder、knowledge_file、workflow、assistant、tool、
  channel、dashboard 每类至少准备两个资源。
- [ ] 多级目录：知识空间 → 文件夹 A → 文件夹 B → 文件。
- [ ] 分别准备继承权限和自定义权限的文件夹、文件，以及可移动、可复制的资源。
- [ ] 普通用户创建资源、多个 owner 资源、系统预置工具等系统资源。

## 2. P0 核心业务场景

### 场景 01：平台管理员配置动作等级

- [ ] 打开动作等级配置，能够看到“未分配、1 级、2 级、3 级、4 级”五个区域，一个动作只能
  出现在一个区域。
- [ ] 新增动作默认进入“未分配”；未分级或已停用的动作不能出现在可用模型中，也不能产生业务权限。
- [ ] 将动作从低等级调整到高等级并发布后，四个标准模型按累计等级重新计算：查看者包含 1 级，
  编辑者包含 1～2 级，管理者包含 1～3 级，所有者包含 1～4 级。
- [ ] 动作等级、启用状态或适用资源发生变化后，所有自定义模型的显示等级和有效动作同步重算，
  不能只更新当前编辑的模型。
- [ ] 标准模型名称、等级和动作不可编辑或删除；只有模型实际包含“权限管理”时才能配置是否允许
  授予同级。

### 场景 02：创建和维护自定义权限模型

- [ ] 新建自定义模型时选择动作，模型等级自动取最高动作等级；前端不能自行指定等级。
- [ ] 空动作、未分级动作或不适用于目标资源类型的动作无法保存。
- [ ] 修改一个已被多个资源使用的模型，确认页准确展示受影响资源、授权组和主体数量；取消确认时
  线上权限不发生变化。
- [ ] 确认模型变更后，所有引用该模型的资源同时获得或失去对应动作，不需要逐个资源重新授权。
- [ ] 停用模型后不能再选择该模型新增成员，已有成员立即失去该模型带来的资源可见性和具体动作；
  重新启用后按原授权恢复。
- [ ] 被资源使用的模型不能直接删除；必须先停用或解除全部引用。

### 场景 03：资源所有者添加成员

- [ ] 创建者或拥有“权限管理”的成员可以从原有权限弹窗添加用户、部门和用户组。
- [ ] 添加父部门并勾选“包含子部门”后，当前及后续加入子部门的成员都能获得权限；取消勾选时
  子部门成员不再自动获得权限。
- [ ] 给同一资源、同一模型、同一主体重复授权，不产生重复成员行或重复权限。
- [ ] 授权成功后，被授权人刷新列表即可看到资源，并能执行模型包含的动作。
- [ ] 撤销授权后，被授权人立即失去该来源带来的可见性和动作，直接访问资源地址也不能绕过。
- [ ] 两个管理员同时修改成员时，后提交的过期页面被明确提示数据已变化，不能覆盖先提交的结果。

### 场景 04：权限管理员只能授予自己有权授予的模型

- [ ] 高等级模型如果不包含“权限管理”，用户仍不能查看完整成员列表或添加、修改、删除成员。
- [ ] 模型包含“权限管理”且禁止授予同级时，只能选择比自己等级低的模型。
- [ ] 模型包含“权限管理”且允许授予同级时，可以选择同级及以下模型，不能选择更高等级。
- [ ] 用户同时拥有“高等级但无权限管理”和“低等级且有权限管理”两个模型时，最多按低等级模型
  的范围授权，不能把两者能力拼接后越级授权。
- [ ] 无“权限管理”的普通成员打开权限入口时，只能看到自己的权限摘要，不能看到其他用户、部门
  或用户组信息。

### 场景 05：同一用户的多来源权限取并集且可独立撤销

- [ ] 给用户 A 直接授予“编辑”，同时通过部门授予“下载”；用户 A 同时可以编辑和下载。
- [ ] 撤销用户 A 的直接授权后，编辑能力消失，但部门来源的下载能力继续有效。
- [ ] 用户 A 退出部门后，仅失去部门来源；其他直接授权或用户组授权继续有效。
- [ ] 同一用户通过两个同等级但动作不同的自定义模型获得权限时，动作取并集，不能只保留一个
  所谓“最高模型”。
- [ ] 权限弹窗分别展示直接授权、部门授权、用户组授权及继承来源，能够解释当前权限从哪里获得。

### 场景 06：资源可见不等于拥有具体操作权限

- [ ] 仅有有效成员关系、但模型不包含目标动作时，用户可以看到资源和基础信息，但编辑、下载、
  删除、分享、使用、发布或权限管理分别被拒绝。
- [ ] 列表按钮的显示状态、详情页按钮状态和实际接口执行结果一致；隐藏按钮不能代替后端鉴权。
- [ ] 用户没有任何有效成员关系时，资源不出现在列表、搜索和选择器中，直接访问详情也不能进入。
- [ ] 停用模型、撤销成员或切换继承来源后，列表、详情和实际操作在同一次变更后保持一致。

### 场景 07：文件夹和文件默认继承上级权限

- [ ] 新建 knowledge_space 和 knowledge_library 后权限模式固定为“自定义”，且不能切换为继承。
- [ ] 在合法父级下新建文件夹或文件，默认使用“继承权限”；继承成员只读，不能在当前资源修改或删除。
- [ ] 多级链“知识空间（自定义）→ 文件夹 A（继承）→ 文件夹 B（继承）”中，文件夹 B 继承
  最近的自定义祖先知识空间，不把中间继承文件夹的创建者误当成普通权限来源。
- [ ] 将文件夹 A 切为自定义后，文件夹 B 改为继承 A；成员展示、列表可见和具体操作同步变化。
- [ ] 没有合法上级的资源不能切换为继承；workflow、assistant、tool、channel、dashboard 不展示
  继承模式切换入口。

### 场景 08：继承与自定义模式切换

- [ ] 文件夹或文件从“继承”切到“自定义”前，界面展示将复制的成员及影响；确认后当前有效普通
  成员变成本级成员，之后上级成员变化不再影响该资源。
- [ ] 从“自定义”切回“继承”前，界面展示将删除的本级普通成员；确认后重新跟随上级权限。
- [ ] 任一模式切换选择取消时，模式、成员和实际权限全部保持不变。
- [ ] 模式切换过程中发生失败时，用户看到明确失败结果，不能出现界面显示已切换但实际权限仍为
  旧状态的情况。
- [ ] 创建者受保护所有者在两种模式下都保留，但不能因此破坏普通成员的继承规则。

### 场景 09：移动和复制资源后的权限

- [ ] 继承权限的文件夹或文件移动到新父级后，立即停止使用旧父级权限并继承新父级权限。
- [ ] 自定义权限的文件夹或文件移动后保留原本级成员，不自动加入新父级普通成员。
- [ ] 复制继承资源时，副本仍为继承模式，并按副本所在的新父级计算权限。
- [ ] 复制自定义资源时，副本保留普通成员和模型，但创建者受保护所有者按新资源重新生成，不能
  照搬原资源的受保护行。
- [ ] 删除、移动或重挂父级失败时，不能留下仍可访问或继续授权的悬空子资源。

### 场景 10：创建者和多个所有者

- [ ] 用户创建资源后自动成为受保护所有者，能够正常管理该资源。
- [ ] 受保护创建者不能在普通成员管理中被删除、降级或替换。
- [ ] 同一资源可以额外增加多个普通所有者；删除其中一个普通所有者不影响创建者和其他所有者。
- [ ] 前端和接口均不提供“所有权转让”；本期只支持普通 owner 独立增删，不支持转让创建者身份。
- [ ] 系统预置资源按原有系统身份规则访问，不显示伪造的普通用户所有者。

### 场景 11：知识空间、知识库、文件夹和文件

- [ ] knowledge_space：分别验证查看、编辑设置、新建文件夹、上传文件、分享、删除和成员管理。
- [ ] knowledge_library：分别验证查看、编辑、使用、删除和成员管理；权限模式固定为自定义。
- [ ] folder：分别验证查看、重命名、新建下级文件夹、上传文件、移动、打包下载、删除和成员管理。
- [ ] knowledge_file：分别验证查看、重命名、移动、下载、分享、删除和成员管理。
- [ ] 给用户仅授予资源可见性但不给 download：文件仍可按既有产品规则预览，但原件下载和文件夹
  打包下载必须被拒绝；授予 download 后才允许下载。
- [ ] 用户曾经预览过文件、持有分享入口或知道下载地址，都不能绕过 download 权限。

### 场景 12：Workflow、Assistant、Tool 和 Channel

- [ ] workflow、assistant：分别验证查看、编辑、使用、发布、下线、分享、删除和成员管理；每个
  操作只由对应动作控制。
- [ ] 只有 use 没有 edit 的用户可以运行但不能修改；只有 edit 没有 publish 的用户不能发布。
- [ ] tool：分别验证查看、编辑、使用、删除和成员管理；系统预置工具与普通用户工具都要覆盖。
- [ ] channel：分别验证查看、编辑、删除和成员管理；频道独立授权入口与通用权限弹窗结果一致。
- [ ] 后台任务或异步执行涉及受限资源时，与用户从页面直接执行得到相同权限结论。

### 场景 13：Dashboard 权限

- [ ] 有资源可见性时才能出现在 Dashboard 列表，并能进入详情、读取组件数据、作为复制源、设为
  个人默认；没有可见性时以上入口全部不可用。
- [ ] 分享链接不能绕过资源可见性；无权限用户通过分享链接仍不能读取 Dashboard 或组件数据。
- [ ] 修改标题、状态、布局和组件都要求 edit；只有可见性但没有 edit 时只能查看。
- [ ] 发布/取消发布状态变更按 edit 校验，删除按 delete 校验，成员管理按 manage_permission 校验。
- [ ] 新建 Dashboard 继续使用既有菜单能力；不能因为拥有某个 Dashboard 的成员权限就获得全局
  新建能力。

### 场景 14：租户隔离和系统管理员

- [ ] 另一租户用户 X 即使知道资源 ID，也不能在列表、详情、搜索、分享链接或成员接口中访问本租户资源。
- [ ] 不能把另一租户的用户、部门或用户组添加为成员；失败后原成员列表不发生变化。
- [ ] 平台超管、租户管理员按既有明确身份策略访问资源，不在普通成员列表中伪装成 owner。
- [ ] 权限服务异常时，普通用户不能因历史角色、创建者字段或旧权限数据被临时放行；页面应展示
  明确失败，而不是错误地提示“无数据”。

### 场景 15：Platform 与 Client 两端权限界面一致

- [ ] Platform 和 Client 均保留原有新增成员操作布局，用户、部门、用户组选择和“包含子部门”行为一致。
- [ ] 成员行展示主体名称、模型、等级、本级/继承、直接/部门/用户组、受保护状态和继承来源。
- [ ] 只有文件夹、文件等具有上级的资源展示权限模式切换；顶级资源不出现无效入口。
- [ ] 同一授权在任一端新增、修改或撤销后，另一端刷新可看到相同结果。
- [ ] 快速重复点击提交不会产生重复成员；页面过期时提示刷新，不能静默覆盖新数据。

## 3. P1 业务回归场景

### 场景 16：列表、分页和搜索

- [ ] 九类资源的列表、搜索、最近使用和选择器只返回当前用户可见的资源。
- [ ] 混合准备直接、部门、用户组和继承权限数据，翻页后不漏数据、不重复，列表总数与实际可见资源一致。
- [ ] 授权、撤销、模型停用或模式切换后，重新查询列表立即反映最新结果。
- [ ] 具有大量可见资源的用户打开列表、翻页和搜索时响应时间可接受，不出现持续加载或超时。

### 场景 17：模型变更对存量资源的影响

- [ ] 一个自定义模型同时用于多类、多资源、多主体时，新增动作后所有适用资源同步生效，不适用
  该动作的资源类型不获得权限。
- [ ] 移除动作后所有引用资源立即失去该动作，但模型中其他动作和其他来源权限不受影响。
- [ ] 动作等级变化导致模型升降级后，可授予模型列表同步变化；旧页面提交时被版本校验拒绝。
- [ ] 模型停用再启用期间，成员关系不丢失，也不产生重复成员。

### 场景 18：升级后历史权限保持业务语义

- [ ] 升级前拥有查看、编辑、管理、所有者权限的用户，升级后对各类资源的可见性和合法操作符合
  新模型映射，不出现批量丢权或扩权。
- [ ] 旧自定义模型只包含“查看”时，升级后用户仍能看到资源，但不能凭此下载、使用、编辑、删除、
  分享或管理成员。
- [ ] 历史直接用户、部门、包含子部门、用户组和多个 owner 均能在权限界面正确展示来源。
- [ ] 已经撤销、找不到有效授权依据的历史绑定不能在升级后重新让用户获得权限。
- [ ] 升级后新建、授权、撤销、模式切换、移动、复制和模型维护全部使用新逻辑；不存在旧版权限
  页面或所有权转让入口。

### 场景 19：异常与重试体验

- [ ] 授权、撤销、模型发布、模式切换操作超时或失败时，页面明确提示结果未知或失败，不能直接
  展示成功。
- [ ] 用户刷新后看到的成员和权限必须与最终实际状态一致；重试同一请求不产生重复数据。
- [ ] 业务资源不存在、已删除、状态不允许操作或父级不合法时，由对应业务功能返回准确提示，
  不能被统一包装成“无权限”。
- [ ] 操作失败不会误删原有成员、创建者所有者或其他来源权限。

## 4. 建议执行顺序

1. **权限配置**：动作等级 → 标准模型 → 自定义模型 → 模型停用与恢复。
2. **成员管理**：直接用户 → 部门/子部门 → 用户组 → 多来源撤销 → 越级授权拦截。
3. **继承链路**：新建默认模式 → 多级继承 → 模式切换 → 移动 → 复制。
4. **资源操作**：知识资源 → Workflow/Assistant/Tool/Channel → Dashboard → 文件预览与下载。
5. **安全回归**：受保护所有者 → 多 owner → 跨租户 → 无权限直链 → 异常关闭。
6. **升级回归**：历史成员和模型映射 → 列表/分页 → 两端 UI → 并发和失败重试。

## 5. 业务发布通过条件

- [ ] 全部 P0 场景通过，无跨租户、越级授权、创建者被删除、可见性冒充具体动作等问题。
- [ ] 九类资源至少完成一次“允许操作”和一次“拒绝操作”的真实业务验证。
- [ ] 直接、部门、用户组、继承四类来源均完成授权和独立撤销验证。
- [ ] 文件预览/下载、Dashboard 分享链接、模式切换、移动/复制和多 owner 场景全部通过。
- [ ] Platform 与 Client 权限界面结果一致，列表、详情、按钮和实际操作结果一致。
- [ ] 升级后的历史可见性和具体动作没有非预期丢失或扩大，遗留异常有明确处置结论。
