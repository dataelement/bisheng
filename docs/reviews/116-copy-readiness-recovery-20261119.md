## 额外发现与补齐

运行时发现 coroutine never awaited。原 `_initialize` 将异步 `es._store._create_index_if_not_exists` 交给 `asyncio.to_thread`，实际只返回协程；只读检查证实两个空间的 ES 索引都不存在，但 Milvus 已 Loaded。这使“空间已开放”不能代表 ES 就绪。

源码改为直接 `await` 异步 ES 初始化，继续 finally 关闭 client，失败会传播到原就绪事务；测试将替身同步为 AsyncMock，并新增“ES 失败必须被等待、向上传播、关闭连接”的回归。

现场仅在独立进程内加载该修正后的初始化函数，再次验证原任务身份、当前源动作及完整原投影回执，在原 source→target 锁和引用 session 下补齐两个空 ES 索引；该步骤对所有 SQL DML 设置拒绝保护。未覆盖容器业务文件或更改权限策略。

最终另一次只读验证：4399、4408 均 state=1；ES exists=true、mapping=true；Milvus exists=true、load_state=Loaded。文件任务仍各 10 项失败，step=copy_input_ready，原文件与处理检查点保留。初始化成功不代表这些文件已检索入库，用户之后可独立重试。
