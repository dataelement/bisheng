# Feature: 灵思任务模式引用溯源可靠性（短句柄 + 审计）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
> spec 只回答 **做什么 / 验收标准 / 不做什么**；所有 How 在 [design.md](./design.md)。

**关联 PRD**: [`docs/PRD/3.0 灵思任务模式引用溯源优化方案/灵思任务模式引用溯源优化方案.md`]（2026-09-20 评审通过，决策 D1～D8）
**优先级**: P1
**所属版本**: v3.0.0-beta1（发版线 `feat/3.0.0-beta2`）
**依赖**: F047（灵思任务模式引用溯源，已上线 release）· F054（统一角标入口：resolve 分态、导出剥标契约 AC-07 / AC-12）· F029（`view_file` 过滤，INV-7）

> **范围边界**
> - **本次纳入**：
>   - **P0 度量与诚实呈现**：任务完成时审计「检索到多少来源、报告引用了多少」，结果随任务结果持久化，零引用时后端告警、前端如实提示；引用规则搬到系统提示词末尾，交付步骤明确要求引用。
>   - **P1 短句柄契约**：检索结果给模型的来源标识改为后端分配的短编号（`[S3]` 形态），会话级去重；写盘与最终回复边界把编号确定性转回既有私有区溯源标记，下游（预览、解析、持久化、导出剥标）零改动；每轮重注入来源表；零引用时一次纠偏提醒；可一键回退到旧契约。
>   - **P2 导出烘焙**：Word / PDF / 打包 md / 单文件转换 / 前端「另存为 md」把溯源标记烘成可见编号 `[n]` 与文末参考资料；html 交付物把编号转为上标与附录。
> - **本次明确排除**：
>   - **任何形式的自动补引用**：不按文本重叠给句子挂来源、不把模型自编的脚注或编号映射成引用、不做二次模型调用的事后归因写回（PRD D2、D4）。原因：会把「模型没标」伪装成「已溯源」。
>   - **拒写重发**：写文件缺引用时不返回工具错误强迫重写（PRD D3）。原因：会撞既有截断守卫与连续失败计数，软着陆阶段可能零交付。
>   - **结果区 Badge / 新组件**（PRD D6）：零引用提示只是一行文字。
>   - **日常模式、知识空间、频道、工作流、助手入口的任何改动**：它们与本 Feature 共用下游契约，本 Feature 只改灵思的上游契约。
>   - **本任务上传附件作为可引用来源**：另立 Feature（F062 临时知识库路线）。
>   - **部分引用或归因错误的检测**：审计只判「零引用」与「有引用」，不判每条引用是否支持该句。
>   - **下游契约的任何改动**（共享的引用规则文本、检索结果呈现模板、角标解析接口、溯源持久化结构、两端前端的标记解析）：保持不变，本 Feature 只改灵思的上游契约。
>   - **前端复制文本时剥离未识别编号**：磁盘文件里没有已识别编号，未识别编号留在预览与复制文本里正是「不掩盖」，不视为缺陷。
>   - **子代理结构化 findings、离线归因诊断**：只在 P1 的 A/B 数据出来后再议（P3 条件触发）。

## 1. 用户故事

作为 **使用灵思任务模式的业务用户**，
我希望 **任务产出的报告尽可能带有可点击角标，并且当模型确实没有标注来源时能明确知道这一点，而不是把「没有角标」误当成「没有引用资料」**，
以便 **信任报告结论、回看原始出处**。

作为 **需要把报告带出平台的用户**，
我希望 **下载的 Word / PDF / Markdown 里有可见的编号引用和参考资料列表**，
以便 **在平台之外也能核对出处**。

作为 **运维与产品**，
我希望 **每次任务的引用情况有结构化记录与告警**，
以便 **按模型统计引用达标率，并在新契约表现不佳时一键回退**。

## 2. 验收标准

> P1、跨模块，采用 EARS 句型。AC-ID 在本特性内唯一。

### 2.1 审计与可见性（P0）

- **AC-01** — WHEN 任务在任一完成路径（正常完成、部分结果、直接作答）结束, THE SYSTEM SHALL 在任务结果中记录本次运行检索到的来源数、报告与最终回复实际引用的来源数、未识别的编号数、裸编号（`[n]`）数、无定义脚注（`[^n]`）数，以及一个三值状态（无来源 / 已引用 / 有来源未引用）。
- **AC-02** — THE SYSTEM SHALL 把子代理（researcher）在其独立上下文中检索到的来源计入 AC-01 的「检索到的来源数」，与主流程检索到的来源同等对待。
- **AC-03** — WHEN AC-01 状态为「有来源未引用」, THE SYSTEM SHALL 输出一条可按会话检索的 WARNING 级日志，包含模型名与各计数。
- **AC-04** — WHEN AC-01 状态为「有来源未引用」, THE SYSTEM SHALL 在结果区摘要下方向用户显示一行提示，说明检索到的来源数与「报告未标注来源」的事实；实时完成、历史回看与分享页三种查看方式下一致显示；提示文案具备 zh-Hans / en / ja 三语，且不写入报告文件与最终回复文本。
- **AC-05** — WHERE 检索到了来源但唯一交付物不是 markdown（如仅 html、pptx）, THE SYSTEM SHALL 判定为「有来源未引用」而非「无来源」。
- **AC-06** — WHEN 任务开启了知识库或联网检索, THE SYSTEM SHALL 使一段引用要求位于系统提示词中语言要求之前、且其后不再有任何框架内置提示（即引用要求与语言要求共同构成系统提示词的结尾），并在交付物撰写步骤中明确要求引用；未开启任一检索能力时两处均不出现引用要求。

### 2.2 短句柄契约（P1）

- **AC-07** — WHERE 短句柄契约开启, WHEN 知识库或联网检索返回结果, THE SYSTEM SHALL 为每条结果呈现一个形如 `S<n>` 的短编号，同一会话内同一来源（同一文档片段 / 同一网页）多次检索得到同一编号，模型不再看到内部引用键。
- **AC-08** — WHERE 短句柄契约开启, THE SYSTEM SHALL 在每一轮模型调用时提供本轮可用来源编号表（编号、来源类型、标题、定位），该表不进入持久化的对话状态。
- **AC-09** — WHERE 短句柄契约开启, WHEN 子代理（researcher）完成检索并回传, THE SYSTEM SHALL 要求编号以 `[S<n>]` 形态原样出现在其最后一条消息的对应句末，供主流程写入报告；主流程与子代理共用同一会话编号表。
- **AC-10** — WHEN 模型在写入 `output/` 下的 markdown 文件或最终回复中写出 `[S<n>]`、`[S<n>][S<m>]` 或 `[S<n>, S<m>]` 形态的编号, THE SYSTEM SHALL 在写盘与最终回复边界把它们确定性转换为既有私有区溯源标记，使预览、解析、持久化与导出剥标沿用 F047 / F054 的现有链路无改动。
- **AC-11** — THE SYSTEM SHALL 只转换 AC-10 所列形态；`[n]`、`[^n]`、markdown 链接 `[S<n>](url)`、代码块内文本、`[S<n>]: ` 定义行一律原样保留并只计数，不转换、不映射。
- **AC-12** — WHERE 交付物为 html, THE SYSTEM SHALL 在 P1 阶段原样保留正文中的 `[S<n>]` 文本，不转换、不删除（P2 按 AC-23 处理）。
- **AC-13** — IF 模型写出的编号不在本会话来源表中, THEN THE SYSTEM SHALL 原样保留该编号文本、计入 AC-01 的未识别编号数，不猜测、不删除。
- **AC-14** — WHEN 模型对已含溯源标记的文件执行编辑, THE SYSTEM SHALL 使编辑定位不因「模型记忆中是编号、磁盘上是标记」而失败。
- **AC-15** — WHERE 短句柄契约开启, WHEN 主流程模型已成功写入 `output/` 下的 markdown 文件、正文无任何编号且来源表非空, THE SYSTEM SHALL 在下一轮向模型提出一次补编号的提醒（要求以编辑方式补充而非重写），同一文件至多提醒一次；任务已进入既有的「软着陆」收尾状态（模型调用次数接近上限、只允许交付类工具）时不提醒；子代理不提醒；提醒不以工具错误形式出现。
- **AC-16** — WHEN 任务为追问轮（同一会话新版本）或从中断处恢复, THE SYSTEM SHALL 沿用该会话已分配的编号表，不重新编号。
- **AC-17** — IF 编号表所依赖的运行时存储不可用, THEN THE SYSTEM SHALL 回退为向模型呈现原有内部引用键，任务继续，不中断检索。
- **AC-18** — THE SYSTEM SHALL 提供一个系统级开关，默认开启；关闭时检索结果呈现、引用规则、写盘转换与每轮来源表同时回到 F047 的逐字复制契约；AC-01 至 AC-05 的审计与提示在开关关闭时照常生效；历史任务的预览与解析不受开关状态影响。
- **AC-19** — WHEN 用户导出、下载或转换含未识别编号的报告, THE SYSTEM SHALL 剥离未识别编号文本（P1 与 P2 均如此；已识别标记在 P1 按 F054 AC-07 剥离、在 P2 按 AC-20 烘焙）。

### 2.3 导出烘焙（P2）

- **AC-20** — WHEN 用户把任务报告导出为 Word / PDF、打包下载、单文件转换或在前端「另存为 md」, THE SYSTEM SHALL 把正文溯源标记按首次出现顺序烘焙为可见编号 `[n]`，并在文末追加「参考资料」列表（知识库来源显示文档名与定位，网页来源显示标题与 URL）；内部引用键与协议标记不出现在导出件中。
- **AC-21** — WHERE 导出者对某知识库来源无 `view_file` 权限（含分享页查看者与权限已变更的用户）, THE SYSTEM SHALL 对该来源退回剥离：既不分配可见编号，也不在参考资料列表中出现其文档名或任何来源信息（守 v2.6.0 INV-7，与角标解析同一过滤口径）。
- **AC-22** — IF 烘焙所需的来源信息已过期或缺失, THEN THE SYSTEM SHALL 回退为剥离标记（AC-19 口径）并记录日志，导出不失败。
- **AC-23** — WHERE 交付物为 html, THE SYSTEM SHALL 把编号渲染为上标并在页尾追加参考资料附录。
- **AC-24** — WHEN 任务模式报告经 AC-20 烘焙导出, THE SYSTEM SHALL 在导出件中只出现可见编号与参考资料段的可读来源信息，任何用户可见状态下仍不出现内部引用键、片段标识与协议标记（F054 AC-12 的口径不变；F054 AC-07 对任务模式报告的「不出现编号与参考资料段」措辞由本 AC 取代，日常模式会话导出不受影响）。

### 2.4 健壮性与非侵入

- **AC-25** — IF 编号分配、来源记录或写盘转换过程发生任何异常, THEN THE SYSTEM SHALL 回退为不转换的原文并继续任务，绝不使工具报错或任务中断（承接 F047 AC-13）。
- **AC-26** — THE SYSTEM SHALL 保持既有任务执行流的对外事件协议与执行记录结构不变，不新增流式事件类型。
- **AC-27** — THE SYSTEM SHALL 使转换幂等：已转换的文本再次经过写盘边界不产生变化。

## 3. 边界情况

- **模型把编号写成脚注 `[^3]` 或裸编号 `[3]`** → 不转换、不映射，报告落成零引用并按 AC-04 提示（PRD D2 有意为之，不是缺陷）。
- **模型在句中而非句末写编号** → 照常转换，位置不作校验。
- **同一句连续多组编号 `[S3][S7]`** → 合并为一组标记，前端渲染为相邻角标。
- **模型用自然语言写「据知识库《X》」而不写编号** → 零引用，按 AC-04 提示。
- **来源表超过展示上限** → 只展示最近的一批，并告知模型其余见检索结果；已分配的编号不受影响。
- **上下文压缩后模型看不到早期检索结果** → 依赖每轮来源表（AC-08）。
- **流式阶段最终回复短暂显示 `[S12]`** → 完成后被持久化版本替换，接受。
- **技能或代码解释器读取含溯源标记的 md 再生成其它产物** → 产物可能带私有区字符，本期不处理。
- **同一文档同时作为知识库来源与本任务上传附件** → 上传附件不可引用，可能误报「有来源未引用」，本期接受。
- **开关关闭后重新打开** → 新任务按新契约执行，进行中的任务沿用创建时的契约。
