# 中粮机器人问答调试客户端

用途：在我们自己的环境复现机器人知识问答，观察原助手的模型、执行模式、工具调用、模型实际收到的结果和检索来源。它不是 E+ 通信模拟器，也不修正模型答案。

## 入口与边界

助手编辑 →「E+ 机器人」配置区 →「机器人调试」。请先保存配置并上线助手；编辑页未保存的改动不参与测试。

第一版只测试文字和机器人知识工具；其他工具不执行，页面列出差异。只允许当前租户的授权管理员，并校验助手编辑权限和测试用户活动成员资格。用户只能输入测试用户 ID，不能自定义空间、模型或系统提示词。

知识检索仍只认机器人绑定空间，绑定部门空间走原检索逻辑；不按测试用户的个人空间权限扩大范围。每轮重读绑定，本轮用快照完成，历史不按空间版本过滤，与本次已确认的正式机器人规则一致。

不启动正式 Worker、不建客户连接、不发客户消息、不申请机器人单活租约、不写正式会话/消息/轮次。测试历史只在页面内存，刷新、清空或切换用户会清除；只将成功完整回答带入下一轮，最多20轮/64000字。模型及数据库、索引共用，仍产生正常费用、配额、既有调用审计/遥测和资源竞争。

## 启用

需要包含 F075 代码的前后端，不能只启动旧镜像。没有新增表或迁移；不需要降级数据库，也不要复制生产密钥到本地文件。

1. 在专门的调试前端构建中设置 `VITE_EPLUS_DEBUG_ENABLED=true`。默认关闭，不出现入口。该变量是**构建时**开关，改容器运行环境不能改变已构建页面。
2. 使用既有环境的 backend 配置启动独立服务，不替换正式 API/Worker，不使用 `bisheng.main:app`：

   ```bash
   EPLUS_DEBUG_ENABLED=true uv run uvicorn bisheng.eplus.debug_app:create_app --factory --host 127.0.0.1 --port 7871 --workers 1 --no-access-log
   ```

   沿用部署的 `config` 配置路径及安全凭证注入。必须 unset `BISHENG_RECORD_HISTORY`，否则拒绝启动。权限目录必须已由正式部署准备完成；调试服务不播种目录、不执行迁移或默认业务数据回填。
3. 在**已登录前端的同源入口**增加代理；只代理 API，页面仍由 Platform SPA 提供。示例适用于无路径前缀的 Nginx（容器独立服务需改为可达的内部服务地址，不能把容器 localhost 当宿主机）：

   ```nginx
   location /robot-debug/api/ {
       proxy_pass http://127.0.0.1:7871;
       proxy_http_version 1.1;
       proxy_set_header Host $http_host;
       proxy_set_header X-Forwarded-Proto $scheme;
       proxy_set_header Authorization $http_authorization;
       proxy_set_header Cookie $http_cookie;
       proxy_buffering off;
       proxy_cache off;
       proxy_read_timeout 240s;
   }
   ```

   保留真实登录身份与租户，不设置固定管理员，不绕过商业网关认证。若前端有部署路径前缀，代理应剥离该前缀后转到 `/robot-debug/api/`。仅信任内部代理的 forwarded headers，确保 HTTP/HTTPS origin 一致。不要把7871暴露公网；未能安全转发认证时不启用入口。
4. 管理员访问 `/robot-debug/api/status` 应返回成功信封、`data.enabled=true`；匿名/普通用户应拒绝。该检查证明准入可用，不代表模型或全部检索资源已就绪。
5. 保存上线的助手配置后，在机器人配置区打开调试页。默认当前管理员为测试用户，可输入同租户有效用户 ID 切换。无外部 ID 的测试用户可测试后端问答，但不代表客户 IAM 入站已验证。

## 怎样定位来源问题

- 本轮调用次数为0：模型没有用知识工具；不要把它的空间/文件描述当检索结果。
- 「实际交给模型的工具结果」：原包装器返回的完整文本，包含哪些来源字段就显示哪些，没有则不补。
- 「检索原始元数据」：格式化前命中 Document 的空间 ID、文件 ID、文件名等安全字段；不代表这些字段都已传给模型。
- 两个空间同名文件：按实际空间 ID、文件 ID 对照原始结果，不能只比较文件名。
- 工具错误和最终回复分开：旧 ReAct 会把工具错误转成观察结果后继续回答，所以“有回复”不代表检索成功。ReAct 整段返回，不伪造逐字流。

## 运行限制和退出

全环境同时只允许一轮调试，专用 Redis 键 `eplus:debug:active-run`（210秒TTL，按所有者 token 释放）。180秒总超时覆盖准备与推理；忙碌、失败或超时通过 `failed` 事件结束，错误只显示类型。请求512KiB、问题4096字、答案16000字、整轮追踪2MiB上限；越界明确失败，不截断后宣称完整。

每轮按 `run_id/seq` 顺序展示，不自动重发请求。停止、关闭、清空会取消本地执行并释放名额；供应商已经开始的计算和计费不能保证撤销。临时来源文本包含业务数据，仅授权管理员可看；不要随意对外分享截图。服务只记录脱敏错误类型及堆栈位置，不把详细正文写入日志文件。

测试结束：停止独立调试进程、移除调试代理即可回收后端；后续前端构建关闭开关。无需回滚业务表；正式机器人按原方式运行。

## 验证状态

本地后端单元/链路验证使用确定性测试模型和检索替身，验证真实助手执行器、真实格式化器、事件顺序、准入、取消，不等于真实模型验收。前端测试/构建按用户约定留给镜像阶段；真实模型、部门空间、跨进程 Redis 与网关认证需部署后按 [验收清单](../features/v3.0.0-beta1/075-cofco-robot-debug-client/e2e-checklist.md) 验证。
