## 实现与业务结果

1. 普通角色按用户所有仍存在的原绑定读取、去重。不再因绑定tenant_id与当前主属不同，或角色为Root私有、部门范围不属于当前主属而丢弃这份已有授予。定义/绑定编号、类型、所有者及时间不转换；缺失定义等不可判定数据仍明确失败，不静默补角色。
2. 原角色的WEB_MENU按角色编号读取；登录、本人信息、同步/异步、Quota、审批动态角色标签和DSH角色读取共用相同结果。真实主属、活动状态及主部门一致性继续核验，不把角色定义所属当作资源执行租户。
3. 角色定义保存沿v3.0.0不自动清理人员绑定。明确保存菜单时，按同角色+WEB_MENU替换所有旧存储副本，避免已经撤销的菜单因遗留副本继续生效；写入仍归定义所有者，不删除资源类型行。
4. 保留已有授权不重新迁绑或重复插入；新授予仍验证当前目标资格。显式撤销/重置删除该用户该角色的全部存储租户副本；本租户管理员可以撤销本租户成员的原绑定，但不能凭此给未获授权者新增外租户私有角色。同步回调的前后角色集合与读取相同。
5. 挂载、本地登录、Beat/手工主属补同步保留原绑定、不重发默认。相同SSO组织快照及同成员事实的旧账号接管也不清理原角色；仅实际组织变更采用既有成员维护。真实新增成员默认规则保持原入口，升级/挂载本身不作为发默认的依据。后续明确撤销后，重复SSO快照不恢复角色。
6. F048、业务资源DAO及主属/执行目标边界未改变。恢复原角色菜单不等于恢复旧role_access资源授权；未共享Root/外租户资源仍拒绝，同租户资源也需要独立授权。角色额度仍受当前租户预算和责任人约束。
