# Feature: 知识空间文件菜单权限预取（空间级判定 + 例外清单）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> 所有 How（决策、数据流、字段、API、Service、前端、文件清单）一律在 [design.md](./design.md) 与 [tasks.md](./tasks.md)。

**关联 PRD**: 客户反馈（2026-08-13）：文件列表「⋯」菜单打开后下载等按钮延迟出现,体验差
**优先级**: P1
**所属版本**: v2.6.0（cofco 分支）
**依赖**: F040（本 feature 替换其定下的「菜单打开时逐文件懒查」策略,需知会该设计口径）、F029/F033（「非 owner 的文件/文件夹授权必有 binding 记录」不变量,例外清单的数据来源）

> **范围边界**
> - **本次纳入**：
>   - client 知识空间文件列表的动作权限（下载 / 改名 / 删除 / 管理）改为**进入空间/文件夹时一次性预取**：当前用户的空间级动作判定 + 本范围内有细粒度授权的例外文件清单
>   - 「⋯」菜单打开即完整展示,不再逐文件发权限请求（例外文件除外）
>   - 流式滚动分页零权限请求（判定与例外清单均不随分页走）
>   - 例外清单上限保护,超限退化为现行逐文件懒查
> - **本次明确排除**：
>   - 不改权限模型、不新增权限关系或角色
>   - 不动下载/改名/删除接口自身的服务端强制鉴权（显示层判定只管 UI）
>   - platform 端文件列表不动（客户反馈仅 client）
>   - 不做权限变更的实时推送——变更后靠重新进入/刷新生效

---

## 1. 用户故事

A. 作为**空间普通成员**,我希望点开文件「⋯」菜单时操作项立即完整出现,以便不被"按钮后蹦"的延迟打断操作。

B. 作为**在大空间里滚动浏览的成员**,我希望持续下滑加载文件时不产生额外的权限请求,以便列表始终流畅。

C. 作为**被单独授权了某些文件的成员**,我希望这些文件的菜单仍按我的实际权限展示,以便细粒度授权不因优化失真。

---

## 2. 验收标准

- **AC-01** — WHEN 用户进入知识空间或切换文件夹, THE SYSTEM SHALL 以**一次**聚合请求返回:当前用户在该空间的动作判定(下载/改名/删除/管理)+ 该范围内存在文件/文件夹级细粒度授权的例外条目清单。
- **AC-02** — WHEN 用户打开非例外文件的「⋯」菜单, THE SYSTEM SHALL 不发出任何权限请求,且菜单项按预取判定一次性完整渲染。
- **AC-03** — WHILE 列表流式滚动加载后续页, THE SYSTEM SHALL 不因新文件进入视图而发出权限请求。
- **AC-04** — WHERE 文件/文件夹在例外清单中, THE SYSTEM SHALL 按该条目的实际细粒度权限展示菜单项（允许逐条或批量解析,解析期间该条目菜单按现行懒查行为渐进出现）。
- **AC-05** — IF 例外清单规模超过上限, THEN THE SYSTEM SHALL 对该空间整体退化为现行逐文件懒查行为,列表加载与浏览不受影响。
- **AC-06** — THE SYSTEM SHALL 保持服务端对下载/改名/删除/管理操作的强制鉴权不变;显示层判定与实际鉴权不一致时,以服务端结果为准并按既有错误提示。
- **AC-07** — WHEN 用户权限发生变更, THE SYSTEM SHALL 在其重新进入空间/文件夹或刷新后反映新判定（预取结果的生命周期不跨越该边界）。
- **AC-08** — THE SYSTEM SHALL 保留 admin / 空间 owner 的本地短路判定（不发请求）,行为与现状一致。

---

## 3. 边界情况

1. **上传中/新建中的临时条目**（isCreating）——沿用现状:不参与权限解析。
2. **预取请求失败** —— 回退为现行逐文件懒查,不阻塞列表(fail-open 到旧行为,fail-closed 到菜单项)。
3. **文件夹与文件动作名不同**（download_folder/download_file 等）——空间级判定需分别覆盖两类动作。
4. **同一空间内跨文件夹移动/新上传的文件** —— 新条目默认适用空间级判定;若其携带细粒度授权,以服务端例外清单口径为准(见 design 的清单范围决策)。
5. **例外清单的范围口径**（按空间还是按文件夹拉取）与上限数值 —— 实现细节,定在 design.md §3;对外行为只承诺 AC-04/05。
