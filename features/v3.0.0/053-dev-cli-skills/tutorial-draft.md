## 写在前面：参考飞书 CLI 又降了一档门槛

你给的飞书 CLI 落地页，杀招是一句话：**「仅需一行指令，在任意 Agent 操作飞书」**——
不让用户自己敲 `curl`/`pip`，而是给一段**提示词**，复制给 AI 助手（Claude Code / Codex / Cursor / Trae…），
**AI 自己把命令跑完**。用户只做一个动作：复制、粘贴、回车。

套到我们的部署流程上，威力比飞书更大——因为**安装、登录、部署**三件都能交给 AI：

- **v1 草稿**：用户自己 `curl -OJ … && pip install …`、自己 `bisheng login`、自己 `bisheng deploy`。门槛 = 会用终端。
- **v2（本版）**：用户**把提示词粘给 AI 助手**，AI 替他装、替他登、替他部署。门槛 = **会把一段话丢给 AI**。

于是开发者的全部工作收敛成 **「对 AI 说三句话 + 在界面点两下」**：

| 动作 | 谁做 | 怎么做 |
|---|---|---|
| 装好 + 登录 | 你 → AI | 复制**安装提示词**给 AI，粘上你的密钥，回车。AI 装好命令行、登录、接好平台规矩 |
| 做出应用 | 你 → AI | 一句话描述你要什么。AI 写代码、在本地跑给你看，改到满意 |
| 部署 | 你 → AI | 一句「帮我部署到平台」。AI 跑部署，出审批单 |
| 审批 | 管理员 | 审批中心点「通过」，自动上线 |
| 授权 | 你 | 「构建→应用」里把「查看者」授权给部门 |
| 使用 | 同事 | 应用中心点开 |

**这需要一处很小的后端新增**：一个 `install-guide` 端点（几十行，和现有 `cli/download`、`skills/{pack}` 同一套匿名分发机制），
把「怎么装 + 怎么登录」写成一份 AI 能读的指引；提示词只用指向它，就能保持一行、且能处理各系统的 pip 小坑。
飞书就是这么做的（它指向 `…/feishu-cli-installation-guide.md`）。**手动 `curl`/`pip` 仍保留为「手动安装」备选**（飞书也留了这个 tab）。

### 请你拍板的 5 个点（我已按建议列写好草稿）

| # | 决策点 | 我的建议 | 说明 / 备选 |
|---|---|---|---|
| **A** | 主路径 | **「复制提示词给 AI」为主**，手动 curl/pip 为备选 tab（仿飞书两 tab） | 或维持 v1 的手动命令为主 |
| **B** | install-guide 端点 | **加**（让提示词保持一行、指引可演进、处理 pip 坑） | 不加：把 curl/pip 直接写进提示词里让 AI 跑（零后端，但提示词更长、处理不了系统差异） |
| **C** | 密钥进提示词 | **让用户把 `bs-sak-…` 粘进自己本地 AI 会话**（信任边界=本机终端，可接受）；教程配一句安全提醒「只粘进你自己本机的 AI 助手，别贴到任何共享/公开处」 | 或让 AI 反问用户要密钥（多一轮） |
| **D** | AI 工具支持面 | 像飞书那样列一排 **Claude Code / Codex / Cursor / Trae / Copilot / Windsurf**；**如实标注**：安装-任意 Agent 都行；平台规矩自动接线目前最顺的是 **Claude Code / Codex**，其它工具靠 `deploy` 写的 `AGENTS.md` 兜底 | 只列自动接线的两个（更保守，但支持面显得窄） |
| **E** | 本地预览 | **保留**（让 AI 本地跑给你看再部署） | 去掉，直接部署 |

**A 是主轴**——它一变整篇口吻都变，最想先跟你对齐这个。下面正文按「A=提示词优先 / B=加端点 / C=密钥进提示词+安全提醒 / D=列全但如实标 / E=保留预览」写的。

# 把你的想法，交给 AI，变成全公司能用的应用

你有一个小想法——一张报销单、一个满意度问卷、一块数据看板、一个查询小工具。
这份教程带你把它做出来、发布到公司应用平台，让被授权的同事在**应用广场**里点开就能用。

**你要会什么？** 只要会用一个 **AI 助手**（Claude Code、Codex、Cursor、Trae……任选其一）。
**代码、命令，全交给它**——你只负责复制提示词、描述想法、在界面点两下。

**大概多久？** 顺的话十几分钟，剩下的时间在等管理员点一下审批。

---

## 谁做什么（先看这张图）

| 角色 | 做的事 |
|---|---|
| **你** | 把 3 段提示词交给 AI（装+登 / 做应用 / 部署）→ 通过后在界面把应用授权给部门 |
| **管理员** | 发你一把服务账号密钥 → 在审批中心点「通过」，应用才真正上线 |
| **同事** | 在应用中心点开你的应用，用起来 |

平台负责最重的活儿——打包、构建镜像、拉起容器、路由、身份注入，全自动。你一条终端命令都不用碰。

---

## 出发前：只用找管理员要一样东西

**一把服务账号密钥**，形如 `bs-sak-…`。**只有管理员能发放，只显示一次**——找管理员领一把，存好。
你做的应用会归在管理员指定的「资源归属人」名下，这是正常的，你不用管。

> 命令行不用你自己装——下一步交给 AI。

---

## 第 1 句 ·〔你 → AI〕装好命令行，并登录

打开你的 AI 助手，把下面这段**复制**给它，**把 `bs-sak-…` 换成管理员给你的密钥**，回车：

```text
帮我安装并登录 bisheng 命令行。安装与登录指引见：
http://你的毕昇地址/api/v1/dev-toolkit/install-guide.md
登录地址就用同一个 http://你的毕昇地址，我的密钥是 bs-sak-把这里换成你的密钥
装好后请确认 bisheng --help 能正常运行，并告诉我接入了哪些 AI 工具。
```

AI 会照指引把命令行装上、用你的密钥登录一次（凭据存你本机，以后不用再输），
**并顺手把《部署纳管》技能接到你的 AI 助手上**——AI 靠它才知道平台的规矩（不然就是「盲写」，本地跑得好、平台上起不来）。

> **⚠️ 密钥只粘进你自己本机的 AI 助手，别贴到任何共享文档、聊天群或公开页面。**
>
> 装完后**重启一下 AI 助手**，让它读到刚接上的技能。AI 会告诉你接入了哪些工具；
> 若显示 **"未接入任何 AI 编程工具"**，见文末「卡住了怎么办」。

### 更喜欢自己动手？（手动安装）

在终端里：

```bash
# -OJ 让 curl 用平台给的正确文件名（pip 只认这个名字）
curl -OJ http://你的毕昇地址/api/v1/dev-toolkit/cli/download
pip install ./bisheng_cli-*.whl
bisheng login http://你的毕昇地址 --api-key bs-sak-…
```

---

## 第 2 句 ·〔你 → AI〕让 AI 做出你的应用

**新开一个 AI 会话**（重启后的新会话才读得到技能），然后**用大白话说你要什么**。举两个例子：

> "帮我做一个**部门费用报销小工具**：填写人、金额、事由、日期，提交后存下来，我能看到一张汇总表。"
>
> "做一个**满意度问卷**：5 道单选题，提交后按选项统计比例，给我一个结果页。"

AI 会照平台规矩，把两样东西一起写好：**应用代码** + 一个叫 `bisheng-app.yaml` 的小配置（你不用懂，AI 懂就够了）。

**让 AI 先在本地跑给你看。** 让它把应用启动起来，你在浏览器里点一点，确认样子和逻辑是你要的。
不满意就继续说「提交按钮改成蓝色」「再加一列备注」，改到满意为止——**这一步不花平台任何资源，尽管改**。

---

## 第 3 句 ·〔你 → AI〕让 AI 部署

满意了，对 AI 说一句：

> "帮我把这个应用部署到毕昇平台。"

AI 会跑 `bisheng deploy`，平台自动**打包 → 密钥扫描 → 构建镜像 → 启动探活 → 生成发布审批单**，
然后把结果告诉你：应用标识、发布单号、入口地址。

> 部署成功**不等于上线**——要等管理员审批。想在上传前先看会打包哪些文件，让 AI 加 `--dry-run` 跑一次。

---

## 第 4 步 ·〔管理员做〕等审批通过

发布要过一道人工审批（**可能跨天**，属正常）。管理员在**审批中心 → 待我审批**点「通过」，
你的应用就会**自动上线**。你不用守着——AI 跑的部署会跟踪审批状态并告诉你结果；
也可以回平台「构建 → 应用」，卡片显示 **「已上线」** 就成了。

> 万一被驳回，会给出驳回理由；改完让 AI 再部署一版即可。
> （小团队里若你自己就是管理员，且你是唯一的审批人，平台允许你自审自批，会记审计。）

---

## 第 5 步 ·〔你做〕把应用授权给部门

**上线 ≠ 公开。** 刚上线时只有你自己能进。到「构建 → 应用」找到它，点卡片上的齿轮 →
**管理权限 → 添加权限**，把「查看者」授权给需要的人：选**部门 / 用户组**，想全员就勾顶层部门并「包含子部门」。

> 授权就在这个界面点几下完成，一步到位——不用找后台、不用改配置。

---

## 第 6 步 ·〔同事做〕大家用起来

被授权的同事打开**应用中心**，在「探索更多应用」里就能看到你的应用，点**「进入应用」**在新标签打开。
用过一次，它会自动出现在每个人的「最近使用」里。

以后要改？让 AI 改完再部署一版，走同样的审批就更新了——**应用里的数据不会丢**（存在平台的持久盘上）。

---

## 支持你手上的 AI 工具

**安装**这一步，任意能跑命令的 AI 助手都行：**Claude Code · Codex · Cursor · Trae · GitHub Copilot · Windsurf …**

平台规矩的**自动接线**目前对 **Claude Code、Codex** 最顺（登录时直接接好）；
用其它工具的，首次部署会在你项目里写一个 `AGENTS.md` 指明技能位置，AI 读它就行（这个文件建议提交到代码仓库）。

---

## 卡住了怎么办？

**本地跑得好、平台上起不来** —— 几乎都是没照平台规矩来。这些规矩和常见错误**都写在《部署纳管》技能里**，
你不用自己读懂：**把报错原样贴给你的 AI，让它「对照技能排查」**，通常一两轮就好。

**登录说「未接入任何 AI 编程工具」** —— 本机没检测到 Claude Code / Codex。
用这两个的：确认装过、让 AI 再跑一次 `bisheng skills sync`。
用 Cursor / Trae / 通义灵码等的：首次部署会写 `AGENTS.md` 指明技能位置，让 AI 读它即可。

**平台升级后想更新规矩** —— 让 AI 跑一次 `bisheng skills sync` 重新同步并接入，最后一行会写明接进了哪些。
