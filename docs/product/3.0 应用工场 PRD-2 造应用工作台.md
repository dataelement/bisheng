## 1. 综述

**一句话定位：让不会编程的业务人员在 BiSheng 平台内对话式从 0 到 1 造应用——浏览器内「对话 + 实时预览 + 一键发布」，接入企业的知识/模型/身份，发布进应用广场、同事即点即用；常驻应用管家负责造与改，发布后迭代 = 继续对话。应用运行时、发布审批管线与治理面是两册共享的地基，见《PRD-1 专业开发者通道与应用运行时》。**

三大能力（对应功能需求域的归属）：

| 能力 | 一句话 | 承载域 |
|------|--------|--------|
| 造 | 浏览器内「对话 + 实时预览 + 一键发布」的造应用工作台，从空白 / 模板（推荐）/ 导入本地项目三路径起步 | §3.1 工作台（WB） |
| 活 | 管家会话随应用终身存续：发布后迭代 = 继续对话，审批/权限/配额/审计全程自动生效 | §3.2 管家（GJ） |
| 接与跑 | 应用托管运行、发布审批与治理的地基 | PRD-1（本册 §3.3 承载工作台专属的 RT-06 / GOV-06） |

本册交付边界一览：

| 维度 | 本版做 | 本版明确不做（详见 §5） |
|------|--------|------------------------|
| 造 | 从空白 / 模板（首发 6 类，推荐）/ 导入本地项目三路径新建；选项式澄清；修错回流；代码版本管理（每轮自动版本/回滚/差异查看） | 点选局改；代码在线编辑 |
| 数据与资源 | 「资源」tab（数据/知识库/模型/密钥四子页，数据为默认子页）：数据网格查改/导入 Excel·CSV/附件字段/导出回溯；知识库可浏览可接入、模型只读展示；密钥 masked（掩码不回显）管理 | SQL 查询面；对象存储独立管理面；数据自助恢复 |
| 代码 | 只读玻璃盒 + 只读运行日志子页 + 导出工程 | 交互式终端；云端通用 IDE |
| 发布 | 发布 tab 承载能力声明完整白话清单 / 审批状态与撤回 / 版本与回滚 / 资源档位选择 / 入口链接 + 二维码 / 运营动作（停运/重新启用）/ 显式删除 / 改码权归属 / 元信息修改（审批管线与治理规则见 PRD-1） | 公网域名/公开可见性（PRD-1 §5.1） |
| 管家 | 造/改会话终身存续 | 上线应用持续看护（v3.1 重新立项，见 §5.2） |

## 2. 用户与旅程

### 2.1 用户

| 用户 | 要什么 | 主要触达面 |
|------|--------|-----------|
| 业务人员（主用户，非程序员） | 把脑子里的表单/看板/小工具变成同事能用的应用，不学编程、不等排期 | 造应用工作台（§3.1） |
| 普通业务用户 | 在应用广场找到并直接使用同事造的工具 | 统一入口与应用广场（PRD-1 §3.2） |
| 租户管理员 / 平台超管 | 造应用引擎与凭据可控可管、业务人员零感知 | 管理面（GOV-06） |

### 2.2 主旅程：业务人员 造 → 发布 → 迭代

1. **新建**：进入工作台，从空白或模板新建（模板推荐起步；导入本地项目走 PRD-1 §2.2 主旅程），一句话描述需求（WB-01）。
2. **澄清**：管家以选项式提问一轮问完，用户点选即可（WB-02）。
3. **生成**：管家列出任务清单并着手执行（管家内核行为方式，见 §3.2）；需要知识库时，管家以候选选项卡供点选接入（WB-10）；右侧预览逐步成形（WB-04）。
4. **备数与自测**：对话里传 Excel 或在数据面导入存量台账（WB-07）；在预览中完整试用自测（WB-04）。
5. **发布**：管家选项式询问预览自测数据去留（默认清空，RT-06）；选择资源档位（默认推荐，WB-14）；首次发布提交审批（RT-03）。
6. **使用**：审批通过后，owner 在发布面设置可见范围（GOV-01，首发默认仅 owner），同事方可经应用广场 / 入口链接 / 扫二维码免二次登录使用，各自只看到权限内数据（RT-01 / RT-02）。
7. **迭代**：回到同一个对话说「导出加个 Excel 格式」，管家在草稿里改好、预览确认、点更新上线提交迭代审批，通过后生效（GJ-02 / RT-04）。

## 3. 功能需求

### 3.1 造应用工作台（WB）

**本域交付：业务人员造应用的唯一主界面——左栏与管家的持久对话 + 任务清单，右栏预览/资源/代码/发布四个核心 tab（「资源」tab 含数据/知识库/模型/密钥四个子页，默认停在数据）；草稿全程仅 owner 可见。**

以下（a）~（d）为域级约定，供本域各条目统一引用，不新增条目编号（手法同 PRD-1 §3.2 应用状态机域级约定）：

**（a）工作台框架与布局**

| 区域 | 构成 | 承载条目 |
|------|------|---------|
| 顶栏 | 返回「我的应用列表」入口（定义见 c）＋ 应用名（可编辑；元信息语义同 RT-02——修改不触发审批、计审计，与发布面元信息区（WB-14）为同一动作的两个入口）＋ 应用态徽标（枚举引用 PRD-1 §3.2 应用状态机；存在在途审批单时以附加标识呈现，审批单态同引该处四值枚举）＋ 代码版本入口「版本 vN」（打开代码版本面板，WB-15） | RT-02 / WB-15 |
| 左栏（管家持久对话） | 上 = 任务清单区（可折叠，条目带待办/进行中/完成态；任务清单为对话体验呈现、不作为独立需求条目约束，§3.2）；中 = 对话流（结构化卡片类型见 b）；底 = 输入框（文本 ＋ 附件上传按钮，支持 Excel/CSV/图片截图，承接 WB-07 导入路径① 与 WB-03 截图反馈） | §3.2 / WB-02 / WB-03 / WB-07 |
| 右栏 | 四核心 tab：预览（默认，WB-04）/ 资源（数据默认/知识库/模型/密钥四子页，WB-05~11）/ 代码（WB-12/13）/ 发布（WB-14） | WB-04 ~ WB-14 |

各条目「界面与交互」小节只写本条增量，不重复本表布局。

**（b）对话流结构化卡片类型清单**

| 卡片类型 | 出现时机 | 可点动作 | 回链 |
|---------|---------|---------|------|

| 引擎降级 / 错误系统提示卡 | 造应用引擎凭据异常时 | 仅提示、无操作（文案不暴露引擎与凭据细节） | GOV-06 |

**（c）「我的应用列表」定义**（承接 WB-01 验收 3、WB-16 验收 2 与 PRD-1 GOV-07 对应用列表的引用，落点即此）

| 要素 | 定义 |
|------|------|
| 语义位置 | 平台主导航「应用工场」入口页；灰度关闭时隐藏「新建应用」按钮、保留既有应用入口（GOV-07） |
| 内容范围 | 本人为 owner 的全部应用（含草稿与已停运），他人不可见 |
| 与应用广场的关系 | 应用广场（RT-02）仅呈现已发布且在访问者可见范围内的应用；本列表是 owner 视角的全量造应用入口，两者互不替代 |
| 卡片字段 | 应用名、图标、一句话描述、应用态徽标（枚举引用 PRD-1 §3.2）＋ 在途审批标识、最近编辑时间、来源标识（平台内造 / CLI 导入） |
| 卡片动作 | 进入工作台（恒有）；打开应用（仅已上线态展示） |
| 空态 | 引导文案 ＋「新建应用」按钮 ＋ 模板推荐（WB-01） |
| 排序与搜索 | 默认按最近编辑时间倒序；支持按应用名搜索 |

**（d）导入应用的工作台呈现（按改码权归属，承接 DEV-06）**

CLI 导入的应用进入工作台后，各界面行为按改码权归属（DEV-06）呈现差异；交接与收回在发布面改码权归属区完成（WB-14）：

| 界面 | 改码权在本地 | 改码权在管家 |
|------|-------------|-------------|

| 预览 tab | 无草稿沙箱：呈引导态「该应用改码权在本地，暂无草稿预览」＋「打开线上应用」链接（仅已上线态展示） | 正常草稿预览 |

#### 入口与新建

**WB-01 新建三路径：空白 / 模板 / 导入本地项目**
- 需求描述：新建应用提供空白、模板（推荐起步）、导入本地项目三条路径；模板首发 6 类，每个模板 = 「一张表 + 一条流 + 一个看板」的微应用。
- 三路径：

| 路径 | 说明 | 起步方式 |
|------|------|---------|
| ① 从空白 | 一句话描述需求直接生成 | 新建界面顶部输入框提交，即创建应用并进入工作台首轮对话（后续澄清见 WB-02） |
| ② 从模板（推荐起步） | 首发 6 类模板（清单见下），含预接线的数据表与页面 | 模板卡片区点选，确认后按模板初始化并进入工作台 |
| ③ 导入本地项目 | 已在本地（vscode / cursor 等）开发的存量项目导入平台纳管发布；新建入口仅提供该路径的指引，导入本身经开发者通道的统一发布管线完成（bisheng deploy，PRD-1 §3.1） | 「导入本地项目」入口卡打开指引 |

- 模板清单（每个 = 「一张表 + 一条流 + 一个看板」的微应用，含预接线的数据表与页面）：
  1. 信息收集上报
  2. 业务台账
  3. 检查整改闭环
  4. 数据看板＋AI 解读
  5. 知识问答页
  6. 轻审批·督办跟踪
- 界面与交互：

| 界面/入口 | 位置 | 构成 |
|-----------|------|------|
| 新建界面 | 「我的应用列表」的「新建应用」按钮（§3.1 域引言 c；按钮受 GOV-07 灰度控制） | 顶部一句话需求输入框（空白路径）＋ 模板卡片区（6 张卡）＋「导入本地项目」入口卡 |
| 模板卡片 | 新建界面模板卡片区 | 模板名、适用场景一句话、构成标注（一张表＋一条流＋一个看板）、缩略示意；点选确认后按模板初始化并进入工作台 |
| 导入指引 | 「导入本地项目」入口卡打开的指引页/弹窗 | 三步指引：CLI 安装 → bisheng login（个人 API key 由租户管理员签发，DEV-01）→ bisheng deploy，附开发者文档链接；页面本身不承载导入动作 |

- 规则与边界：
  - 空白路径允许从空白直接生成，不强制先选模板。
  - 模板初始化失败时回流左栏对话，由管家说明原因并可重试（回流形态承接 WB-03）。
  - 经开发者通道导入的应用出现在 owner 的「我的应用列表」（§3.1 域引言 c），其工作台呈现见 §3.1 域引言 d。
- 验收要点：
  1. 从空白路径可用：一句话描述需求即可直接生成应用（后续澄清见 WB-02）。
  2. 新建流程中 6 类模板全部可选，选中后基于模板生成初始应用（含预接线的数据表与页面）。
  3. 新建入口存在「导入本地项目」路径指引；经开发者通道导入的应用出现在 owner 的「我的应用列表」（§3.1 域引言 c；导入与发布管线见 PRD-1 §3.1）。
  4. 空白路径一句话提交后进入工作台并开始首轮对话。
  5. 模板卡片区 6 张卡均可见适用场景一句话与构成标注；模板初始化失败时回流对话并可重试。

#### 左栏对话

**WB-02 一句话起步与选项式澄清**
- 需求描述：用户一句话描述需求后，管家先「梳理需求 → 确认要点 → 匹配平台资源（知识库；选择交互见 WB-10）」再动手；澄清以选项式为主，用户点选即可，尽量不要求打字描述技术细节。
- 界面与交互（澄清卡，出现在左栏对话流，§3.1 域引言 b）：

| 要素 | 说明 |
|------|------|
| 题目构成 | 每题 = 问题文案 ＋ 候选选项（标注单选/多选）＋「其他（自由输入）」兜底项 |
| 整卡快捷动作 | 「都按推荐，直接开始」：跳过逐题作答，按管家推荐项开始生成 |
| 已答呈现与改选 | 已答题呈现所选项；生成开始前可改选，开始后改需求走对话 |

- 流程：
  1. 用户一句话描述需求。
  2. 管家梳理需求、判断要点是否齐备；「要点齐备 →」不澄清，直接给出任务清单并开始执行。
  3. 管家给出一轮选项式澄清（≤5 题），用户点选作答；候选不合适时经「其他（自由输入）」兜底。
  4. 管家给出需求确认摘要，随后给出任务清单并开始执行（任务清单为对话体验呈现，§3.2）。
- 规则与边界：
  - 澄清问题数不超过 5 个。
  - 一轮问完，不出现多轮连环追问。
  - 选项式优先：问题连同候选答案一起给出，尽量不要求打字描述技术细节。
- 验收要点：
  1. 首轮需求存在待澄清要点时，管家先给出澄清问题（≤5 个）而非直接生成；要点齐备时直接进入任务清单。
  2. 澄清问题以「问题 + 候选选项」形式呈现，可全程点选完成；候选不合适时可经「其他（自由输入）」兜底作答。
  3. 验收用例集内澄清均在一轮内完成并进入任务清单，不出现第二轮追问卡。

**WB-03 报错一键回流与修错**
- 需求描述：运行报错、用户截图反馈、以及构建/依赖安装失败，均可一键回流给管家；管家用业务人员能懂的话解释原因并自动修复，改到好为止。
- 界面与交互（场景 × 入口）：

| 场景 | 回流入口 | 构成 |
|------|---------|------|
| ① 预览内运行报错 | 预览区内联回流条（WB-04） | 业务语言错误摘要一句 ＋「帮我修」按钮 |
| ② 构建/依赖安装失败 | 预览 tab 整面失败态（替代空白预览，WB-04 状态表） | 失败说明 ＋「帮我修」按钮 |
| ③ 用户截图反馈 | 左栏输入框图片上传（§3.1 域引言 a） | 上传截图（可附文字说明），管家识别后进入修复流程 |

- 规则与边界：
  - 管家的原因说明与修复说明用业务语言，不出现堆栈/错误码原文。
  - 修复进度落左栏任务清单区（§3.1 域引言 a）。
  - 修复完成后回流条消失、预览自动刷新。
- 验收要点：
  1. 预览出错与构建失败场景均出现「帮我修」一键回流入口，点击后管家自动开始修复。
  2. 回流后管家说明报错原因与修复内容，说明中不出现堆栈/错误码原文；修复完成后预览恢复可用。
  3. 构建失败场景下预览 tab 呈整面失败态且「帮我修」可用。

#### 预览面

**WB-04 预览 tab（桌面/移动两态）**
- 需求描述：右栏默认停在预览 tab，应用未发布也可在预览中完整试用；提供桌面/移动两态切换（上报/检查类应用常被移动端打开）。
- 界面与交互：

| 要素 | 位置 | 说明 |
|------|------|------|
| 桌面/移动切换控件 | 预览 tab 顶部 | 两态切换，移动态以移动端视口呈现 |
| 手动刷新按钮 | 预览 tab 顶部工具区 | 手动重载预览 |
| 全屏切换 | 预览 tab 顶部工具区 | 预览区全屏展开/退出 |
| 预览视口 | tab 主体 | 应用实时预览，可完成完整业务操作 |
| 内联回流条 | 预览区内、报错处内联出现 | 业务语言错误摘要 ＋「帮我修」（承接 WB-03） |

- 状态：

| 状态 | 呈现 | 去向 |
|------|------|------|
| 空态 | 尚未生成内容：引导语「开始对话后应用会在这里逐步成形」 | 生成开始 → 构建中 |
| 构建中 | 生成中提示 | 完成 → 正常（自动刷新）；失败 → 失败态 |
| 正常 | 应用可完整试用；运行报错时于报错处出现内联回流条 | 报错回流修复不改变整体状态 |
| 失败态 | 整面失败态：失败说明 ＋「帮我修」（WB-03） | 修复完成 → 正常 |

- 规则与边界：
  - 预览试用产生的数据一律落草稿库，在预览内应用自带数据页可见。
  - 已发布应用迭代期间同理：迭代期草稿数据仍在预览内应用数据页查看——此时工作台数据面呈生产库，草稿库属管家工作区内部事务（WB-06）。
  - 应用无自带数据页时，迭代期草稿数据本版不提供额外查看入口，发布时仍经 RT-06 去留提问处置。
  - 预览出错在预览内联回流（WB-03），不做独立终端。
- 验收要点：
  1. 未发布的草稿应用可在预览中完成完整业务操作（提交表单、查看列表等）。
  2. 桌面/移动两态切换生效，移动态以移动端视口呈现。
  3. 预览内应用报错时出现内联「报错 → 帮我修」回流条。
  4. 空态与构建中态按状态表正确呈现，构建完成后自动刷新为正常态。
  5. 迭代期间预览试用数据落草稿库并在预览内应用数据页可见，工作台数据面仍呈生产库（WB-06）。

#### 资源面（「资源」tab：数据 / 知识库 / 模型 / 密钥）

**WB-05 「资源」tab 结构**
- 需求描述：右栏四个核心 tab 为预览 / 资源 / 代码 / 发布；「资源」tab 是使用视角的四子页结构，打开默认停在「数据」。密钥子页管理本应用自有的第三方凭证（如 webhook token），全程只见引用名与掩码。
- 界面与交互（子页结构）：

| 子页 | 定位 | 构成与关键字段 | 回链条目 |
|------|------|---------------|---------|
| 数据（默认子页） | 应用自有数据的一等面 | 网格查改、导入、附件、导出与表结构演进 | WB-06 ~ WB-09 |
| 知识库 | owner 可见的知识库，可浏览、可接入 | 库卡片列表 + 搜索 | WB-10 |
| 模型 | 租户管理员经能力总线配置的可用模型，只读展示 | 模型列表 + 搜索 | WB-11 / GOV-05 |
| 密钥 | 本应用要用的第三方凭证（如 webhook token） | 密钥列表 + masked 录入，见下 | 本条 / NFR-2 |

- 界面与交互（密钥子页）：

| 界面/入口 | 位置 | 构成 |
|-----------|------|------|
| 密钥列表 | 资源 tab · 密钥子页 | 列：引用名、掩码、用途备注、状态（启用/已吊销）、创建/更新时间、最近使用时间、操作 |
| 新增弹窗 | 密钥子页「录入密钥」按钮 | 引用名（唯一性校验，代码内即以此名引用）、值（masked 输入，提交即写平台加密存储、不回显）、备注 |
| 行动作 | 密钥列表行上 | 覆盖更新（重输新值、不显旧值）；吊销（二次确认，明示「引用该密钥的功能将报明确错误态直至重新录入」） |

  - 空态：「本应用暂无密钥」+ 录入引导 + 「请勿在对话中粘贴密钥」提示。
  - 失效呈现：已吊销行状态标红；发布面/资源面的失效提示与能力收回（GOV-05）同语义。
- 流程（密钥生命周期）：
  1. owner 在密钥子页以 masked 控件录入 → 值直写平台加密存储。
  2. 代码以引用名引用该密钥（代码中不出现值）。
  3. 覆盖更新 → 新值即时生效，旧值即刻失效且不可见。
  4. 吊销 → 运行中应用对该引用的调用得到明确错误态（不回退旧值）→ 重新录入后恢复。
- 状态（密钥）：

| 状态 | 含义 | 应用侧表现 |
|------|------|-----------|
| 未录入 | 代码或能力声明引用了尚未在密钥子页录入的引用名 | 引用该密钥的功能报明确错误态，应用整体可用 |
| 生效 | 已录入且未吊销 | 功能正常调用 |
| 已吊销 | 值已吊销、引用名保留 | 引用该密钥的功能报明确错误态（不回退旧值），重新录入后恢复 |

- 规则与边界：
  - 密钥值不经对话、不写日志、不回显；任何界面（含对话历史、日志、代码玻璃盒）只见引用名与掩码（NFR-2）。
  - 代码中仅出现引用名，不出现值。
  - 不提供「在对话里粘贴密钥」的路径；管家在对话中收到疑似密钥明文时，引导用户改用密钥子页。
  - 密钥录入/覆盖/吊销仅 owner 操作；租户管理员的应急手段 = 停运（RT-07）。上述事件计审计（GOV-04）。
  - 资源 tab 是使用视角：平台共享能力的账号/端点配置只在管理面（GOV-05），密钥子页管理的仅是本应用自有凭证。
  - 知识库/模型子页带搜索，只放「需要用户挑选的实例」；应用能做什么，由 6 类模板承担示例职责（WB-01）。
  - 后续版本可以扩展子页。
- 验收要点：
  1. 右栏四核心 tab 为预览/资源/代码/发布；「资源」tab 含数据/知识库/模型/密钥四个子页且默认停在数据。
  2. 资源 tab 内不存在任何账号/端点配置项。
  3. 密钥录入后任何界面（含对话历史、日志、代码玻璃盒）均不出现明文值，仅见引用名与掩码、无「查看明文」入口；应用代码中仅存在引用名。
  4. 吊销密钥后，应用引用该密钥的功能报明确错误但应用整体可用；重新录入后恢复。
  5. 覆盖更新后新值生效、旧值即刻失效且不可见，事件计审计（GOV-04）。
  6. 管家在对话中收到疑似密钥明文时给出改用密钥子页的引导，且不留存明文。

**WB-06 数据子页：网格查改与导出回溯**
- 需求描述：「数据」子页为资源 tab 默认子页（WB-05）、应用数据的一等面：应用存的数据在此可查、可改、可导出、可回溯——业务人员看数据就是看真数据。数据面无草稿/生产切换器，随应用状态自动跟随。
- 界面与交互：

| 界面/入口 | 位置 | 构成 |
|-----------|------|------|
| 数据面布局 | 资源 tab · 数据子页 | 左侧表清单（多表切换）+ 右侧可编辑网格（查、改、增行、删行） |
| 工具栏 | 网格上方 | 搜索、按列筛选、增行、删行、导入入口（WB-07）、导出 |
| 库标识徽标 | 网格顶部 | 非交互徽标「草稿数据 / 生产数据」，只标识、不可切换 |
| 二次确认弹窗 | 编辑/删除生产库中的行时 | 明示影响行数 + 「该操作计入审计」提示 |

  - 空态：应用尚无数据表时，引导「到对话里建表或导入」（WB-07）。
  - 导出：点导出时选择范围（当前筛选结果 / 全表，默认当前筛选结果）与格式（xlsx / csv）。
- 状态：

| 应用状态 | 数据面呈现 | 预览自测数据去向 |
|---------|-----------|----------------|
| 未发布 | 草稿库 | 落草稿库（草稿库承接导入与预览自测数据）；提交发布时经去留提问处置（RT-06） |
| 已发布 | 生产库 | 预览试用数据仍落草稿库、不入生产库（WB-04） |
| 已发布、迭代期间 | 仍呈生产库 | 迭代草稿数据在预览内应用数据页查看（WB-04），草稿库属管家工作区内部事务；更新上线时经去留提问处置（RT-06） |

- 规则与边界：
  - 数据面不存在草稿/生产手动切换控件，库随应用状态自动跟随。
  - 编辑与删除生产库中的行均需二次确认，且计入审计（回链 GOV-04）。
  - 数据子页仅 owner 可达（含生产库视图）；不向租户管理员提供生产数据查看/编辑入口，其处置手段 = 停运（RT-07）。
  - 导出格式为 xlsx / csv；导出范围 = 当前筛选结果或全表。
  - 附件列导出为文件名（回链 WB-08）。
- 验收要点：
  1. 数据面以可编辑网格呈现应用数据表，支持查、改、增行、删行、导出。
  2. 数据面不存在草稿/生产手动切换控件；发布前后打开数据面分别呈现草稿库/生产库数据。
  3. 编辑或删除生产行时弹出二次确认；确认后该操作在审计记录中可查（操作人/时间/变更内容）。
  4. 多表应用可经左侧表清单切换查看各表。
  5. 库标识徽标随应用状态正确呈现「草稿数据/生产数据」，且不可点击切换。

**WB-07 数据子页：导入双路径**
- 需求描述：存量数据导入提供两条路径且都必须可用；导入前做列匹配与类型校验预检，失败行处置以失败行报告驱动闭环。
- 双路径：

| 路径 | 入口 | 适用场景 |
|------|------|---------|
| ① 对话上传 | 左栏输入框上传 Excel/CSV，管家建表灌数 | 尚无数据表，建新表并灌入 |
| ② 数据面显式导入 | 数据面工具栏「导入 Excel/CSV」入口 | 向已有表导入数据 |

- 流程：
  1. 选择 Excel/CSV 文件（对话路径：左栏输入框上传；数据面路径：工具栏导入入口并选定目标表）。文件无法解析 → 导入中止并提示原因。
  2. 列匹配与类型校验预检：数据面路径呈映射界面供确认与调整；对话路径由管家自动完成列建模并在对话流给出确认摘要。
  3. 逐行校验落库。部分行失败 → 失败行跳过、成功行落库、出具失败行报告（可修正后重导）；全部行失败 → 导入中止 + 原因摘要提示。
- 界面与交互：

| 界面/入口 | 位置 | 构成 |
|-----------|------|------|
| 导入映射界面 | 数据面路径：点工具栏导入入口后 | 源列→目标列映射表、类型校验结果、可调整映射 |
| 失败行报告 | 两路径同一报告结构：数据面路径为导入结果弹窗/结果区；对话路径为管家在对话流呈现的同格式报告卡（摘要 + 下载入口） | 结果摘要（成功行数 / 失败行数 / 失败原因归类）+ 失败行明细（行号、原始值、失败原因列）+ 「下载失败行文件」（保留原列结构 + 追加失败原因列）+ 「修正后重新导入失败行文件」指引 |

- 规则与边界：
  - 重导语义 = 报告驱动的失败行闭环：下载失败行文件、修正后仅重导该文件；不承诺全文件级去重。
- 验收要点：
  1. 在左栏对话上传 Excel/CSV 后，管家能创建对应数据表并完成数据灌入。
  2. 数据面存在显式导入入口，可将 Excel/CSV 导入指定数据表。
  3. 两条路径导入的数据均在数据网格中可见、可编辑。
  4. 列不匹配/类型不符时给出失败行报告，成功行正常落库。
  5. 全部行失败时导入中止并提示原因。
  6. 失败行文件可下载；修正后重导成功，且不产生成功行重复入库。

**WB-08 数据子页：附件字段与行内预览下载**
- 需求描述：附件字段为本版基线能力：上报/整改类应用支持拍照/上传附件，数据面附件列支持行内预览与下载。
- 界面与交互：
  - 附件单元格形态：图片 = 缩略图、点开大图预览；文档 = 文件名 + 下载图标；多附件时带数量角标。
  - 上传交互：超限或类型不符即时提示，文案含上限值与允许类型；移动端上传失败保留重试按钮。
- 规则与边界：
  - 单文件大小上限与允许类型为部署配置项（默认单文件 ≤ 20MB、文档/图片常用类型白名单）。
  - 超限或类型不符的上传即时拒绝并提示；移动端上传失败可重试。
  - 网格导出时附件列导出为文件名（WB-06）。
  - 独立的对象存储管理面不在本版（§5）。
- 验收要点：
  1. 含附件字段的模板应用中，终端用户可上传附件（含移动端拍照上传）。
  2. 数据面中附件列可行内预览（图片类）与下载（通用类）。
  3. 超过单文件上限或类型不在白名单的上传被拒绝并有明确提示。
  4. 移动端上传失败后可重试成功。

**WB-09 数据子页：表结构演进与确认闸口**
- 需求描述：表结构演进由管家以业务语言引导；本条是工作台路径结构变更确认的唯一闸口。
- 变更类型：

| 变更类型 | 是否需确认 | 变更前快照 |
|---------|-----------|-----------|
| 加列 | 无需确认，安全直接做 | 不留 |
| 改/删列 | 需用户确认 | 变更前自动留数据快照 |

- 规则与边界：
  - 本条是工作台路径结构变更确认的唯一闸口；CLI 路径的确认闸口见 DEV-04 / RT-05 结构演进表。
  - 草稿期已确认的结构变更，发布时不再二次确认（见 RT-05）。
  - 快照为系统级保障，本版不提供用户自助查看与恢复入口（数据自助恢复与结构变更管理面顺延 §5.2）；需要恢复时由管家给出「联系租户管理员」指引。
  - 确认执行后，管家在对话流留结构变更确认卡（含变更内容与快照留存标识）。
  - 结构变更确认记录以草稿库当前实际结构为准；代码版本回滚不自动撤销已执行的库结构变更（WB-15 联动）。
  - 提交发布时以「草稿库实际结构 vs 生产库结构」差集生成变更摘要（RT-04）。
- 验收要点：
  1. 请求删列/改列时管家要求确认；确认后执行，且对话流中出现含快照留存标识的结构变更确认卡；加列不要求确认。
  2. 草稿期已确认的结构变更在迭代发布时不再触发二次确认（RT-05 验收 4）。

**WB-10 知识库子页：浏览与接入**
- 需求描述：知识库子页列出 owner 可见的库供浏览与接入本应用；三条接入路径殊途同归、均在对话流留痕。工作台内不新建知识库。
- 界面与交互：

| 界面/入口 | 位置 | 构成 |
|-----------|------|------|
| 库卡片列表 | 资源 tab · 知识库子页（带搜索，WB-05） | 字段：知识库名称（即平台知识库模块中的名称，无独立别名）、一句话描述、文档量、更新时间、「已接入」角标 |
| 卡片按钮 | 库卡片上 | 「接入本应用」；已接入态替换为「解除接入」（二次确认，明示应用相关问答功能将不再引用该库） |
| 库详情 | 点卡片打开右侧抽屉 | 简介、文档量、更新时间、内容样例（若干篇文档标题或片段） |
| 空态 | owner 无任何可见库时 | 指引去向：到知识库模块建库、或联系知识库管理者/租户管理员授权（知识库管理者为平台知识库模块既有角色；走既有授权，本册不新增授权面） |

- 接入路径（三条路径，殊途同归）：

| 路径 | 触发 | 交互形态 | 结果 |
|------|------|---------|------|
| ① 页内点按钮 | 知识库子页卡片「接入本应用」（WB-05） | 点按钮即接入 | 接入动作与结果在对话流留痕 |
| ② 管家推荐 | 澄清或造/改过程中管家判断需要知识库 | 选项式候选卡：库名 + 一句话描述 + 「先不接」，支持多选 | 点选完成接入，对话流留痕 |
| ③ 用户点名 | 对话中说「接入 XX 知识库」 | 名称近似的多个库以选项式挑 | 接入完成，对话流留痕 |

- 规则与边界：
  - 权限边界：子页、候选与点名的范围恒 ⊆ owner 自身知识库权限——无权限的库不出现、点名应答「未找到」。
  - 管家推荐是尽力而为的便利入口、不作硬保证（候选带试检索命中预览为 v3.1 增强，§5.2）。
  - 找不到时：owner 可见范围内无匹配时，管家明确告知并指引去向（到知识库模块建库、或联系知识库管理者/租户管理员授权），不静默跳过。
  - 解除接入：对话中说「不要再用 XX 库」为页内「解除接入」按钮的等价路径；动作与结果在对话流留痕，并计入能力声明变更（RT-04）。
  - 工作台内不新建知识库。
- 验收要点：
  1. 知识库子页列出且仅列出 owner 有权限的库；「接入本应用」完成接入。
  2. 需求涉及知识问答/口径类内容时，管家给出候选知识库选项（库名、一句话描述、「先不接」），点选完成接入；点名「接入 XX 知识库」可完成接入。
  3. 无匹配时管家明确告知并给出去向指引，不静默跳过。
  4. owner 无权限的库不出现在子页与推荐候选中，点名时应答为「未找到」。
  5. 任一路径接入后，对话流中留有接线记录。
  6. 解除接入后应用不再引用该库；对话流留痕；迭代审批单变更摘要含该项（RT-04）。

  7. 驳回理由全文在发布面可见。

#### 版本与草稿边界

**WB-15 代码版本管理（每轮自动版本、回滚与差异查看）**
- 需求描述：每轮改动自动生成一个代码版本（无需手动保存），版本列表随应用保留，支持回到任一版本与查看版本差异。代码版本是「造的过程记录」，与发布版本（RT-05，上线记录）是两个概念，入口分立、互不混排。
- 界面与交互：

| 界面/入口 | 位置 | 构成 |
|-----------|------|------|
| 代码版本面板 | 工作台顶栏「版本 vN」入口（§7 Demo「存档 v3」按钮即此示意） | 版本列表：版本号、生成时间、该轮改动一句话摘要、当前版本标识；行动作 = 查看差异、回到此版本 |
| 差异查看 | 版本行「查看差异」 | 相对上一版本的文件变更清单（新增/修改/删除）+ 行级差异，均为只读视图 |
| 回滚确认弹窗 | 版本行「回到此版本」 | 明示「对话历史保留、草稿数据不随版本回滚」；确认后代码与管家工作上下文恢复到该版本，对话流插入回滚事件卡 |
| 空态 | 应用刚创建、仅有初始版本时 | 列表仅含初始版本一条；无上一版本，不提供差异查看 |

- 两概念对照（代码版本 vs 发布版本）：

| 维度 | 代码版本（本条） | 发布版本（RT-05） |
|------|-----------------|------------------|
| 生成时机 | 每轮对话改动自动生成 | 提交发布时生成 |
| 回滚是否审批 | 免审批、即时生效 | 生成回滚审批单（RT-05） |
| 是否影响生产 | 仅作用于草稿工作区 | 作用于生产 |
| 数据与对话是否回退 | 均不回退 | 生产数据不回退（回滚处置见 RT-05 处置表） |
| 入口位置 | 顶栏代码版本面板 | 发布面版本列表区（WB-14 ④） |

- 规则与边界：
  - 每轮改动自动生成版本，无需手动保存。
  - 回滚仅 owner 可发起，仅作用于草稿工作区，不构成发布、不触发审批。
  - 对话历史只追加、永远完整保留（GJ-01）；草稿数据不随版本回滚。
  - 已执行的库结构变更不随代码回滚自动撤销（WB-09）；回滚目标版本与草稿库当前表结构不一致（回滚跨越已执行的结构变更）时，管家在回滚事件卡中明确提示结构不一致及其影响，并给出处置选项：由管家生成反向结构修正，或放弃本次回滚（恢复到回滚前版本）。
  - CLI 导入应用：改码权交接前版本列表 = 每次 deploy 的版本快照（即发布版本，RT-05）；代码版本时间线自交接给管家后的首轮对话起生成（DEV-06，§3.1 域引言）。
- 验收要点：
  1. 每轮改动后版本列表自动新增一条版本记录，无需用户手动保存。
  2. 可查看任一版本的文件变更清单与行级差异，均为只读。
  3. 回滚到任一版本后，代码与管家工作上下文恢复到该版本状态；对话历史与草稿数据不受影响，对话流中出现回滚事件卡。
  4. 代码版本面板（顶栏）与发布面版本列表（WB-14）分立呈现，代码版本回滚不产生审批单。
  5. 回滚跨越已执行结构变更时，回滚事件卡含结构不一致提示与处置选项。

**WB-16 草稿 owner-only**
- 需求描述：草稿全程仅 owner 可见可试，想给同事用就发布。
- 规则与边界：
  - owner-only 的范围 = 草稿工作区：对话、预览、数据均只对 owner 开放。
  - 唯一例外：审批期间，审批人可经审读视图（RT-03）查看待上线版本快照、并经草稿沙箱预览试用（审批例外、计审计，NFR-1.2）。
  - 草稿对话无例外：始终仅 owner 可见，审批人亦不可见。
  - 不提供授权试用、共建草稿能力（本版明确不做，§5.1）。
- 验收要点：
  1. 任何非 owner 用户（包括租户管理员与平台超管在内）访问草稿的对话/预览/数据均被拒绝；审批人仅经审读视图查看与预览（RT-03），无工作台草稿入口。
  2. 草稿应用不出现在任何他人的「我的应用列表」（§3.1 域引言）与应用广场（RT-02）中，也不出现在管理后台应用管理列表（GOV-09 仅列已发布应用）。
  3. 工作台内不存在「邀请协作」「授权试用」类入口。

### 3.2 应用管家（GJ）

**本域交付：每个应用绑定一个常驻管家，造它、改它是同一个 agent、同一段会话。管家基于成熟 coding agent 内核，天然具备「讨论只回答、改动先列任务清单再执行」的行为方式——任务清单作为对话体验呈现，不作为独立产品需求条目约束。左栏界面构成与对话流卡片清单见 §3.1 域引言。**

**GJ-01 管家会话随应用终身存续**
- 需求描述：管家的对话历史与工作上下文和应用绑定存储，不随发布、运行实例回收或时间流逝而丢失；应用创建数月后回来提一句需求，管家仍带着全部上下文（数据模型/口径/历史决策）接得住，上下文零移交。
- 规则与边界：
  - 重进工作台时对话历史完整可滚动回溯、任务清单一并恢复（验收 1 的界面落点；左栏构成见 §3.1 域引言）。
  - 导入应用冷启动约定：CLI 导入应用交接改码权（DEV-06）时，以最新已发布版本快照初始化草稿沙箱与管家工作上下文；管家首轮回复包含对应用结构（页面/数据表/能力声明）的摘要确认；交接前的 deploy 历史经发布面的发布版本列表（WB-14）可查、不进入对话流。
- 验收要点：
  1. 关闭浏览器/长时间离开后重新打开应用工作台，完整对话历史与任务清单可见。
  2. 运行实例被回收后再次进入，管家能在回复中正确引用会话内既有事实（应用数据表与字段名、历史决策记录），并给出不与历史决策冲突的修改方案。
  3. 会话历史的生命周期与应用一致，仅随应用显式删除而删除（回链 RT-07）。
  4. CLI 导入应用交接改码权后的首轮对话中，管家给出对应用结构（页面/数据表/能力声明）的摘要确认。

**GJ-02 发布后迭代 = 继续对话**
- 需求描述：发布后的修改不需要「打开工程」：用户在同一对话里提需求，管家只在草稿中修改，用户预览确认后点「更新上线」提交迭代发布审批（RT-04），审批通过后生效。管家永不直接改动生产实例。
- 流程：
  1. 用户在原对话中提出修改需求，管家仅在草稿中修改；生产应用不发生任何变化。
  2. 用户在预览 tab 确认修改效果（WB-04）。
  3. 点「更新上线」，双入口等价：管家在预览确认后于对话流给出「更新上线」操作卡；发布面主操作区提供同款按钮（WB-14），两处为同一动作。
  4. 发布流程编排：自测数据去留提问（草稿库有自测数据时，RT-06）→ 资源档位确认（默认沿用原档位，WB-14）→ 生成迭代审批单（RT-04），对话流插入「已提交审批」事件卡。
  5. 审批终态回流对话：通过 → 对话流追加「审批通过、新版本已生效」事件卡；「驳回 →」对话流追加驳回事件卡（含理由全文），owner 修改后重新提交生成新审批单；审批终态同步经平台站内信通知 owner。
- 规则与边界：
  - 提交前 owner 可在发布面查看本次四类变更摘要（能力声明 / 可见范围 / 表结构 / 资源档位，与 RT-04 审批单同源）。
  - 管家永不直接改动生产实例；迭代期间同事访问线上应用不受影响。
- 验收要点：
  1. 已发布应用的修改请求全程在原对话中完成，生产应用在迭代审批通过前不发生任何变化。
  2. 迭代过程中同事访问线上应用不受影响。
  3. 提交时生成的版本记录在迭代审批通过后标注为已上线并生效（回链 RT-05）。
  4. 「已提交审批」、「审批通过」与驳回三类事件卡在对话流中可见，驳回事件卡含理由全文。

### 3.3 工作台专属的运行时与治理条目（RT-06 / GOV-06）

其余 RT / GOV 条目见 PRD-1 §3.2 / §3.3；以下两条与工作台流程强绑定，随本册交付与评审：

**RT-06 预览自测数据发布去留**
- 需求描述：任何发布（首发与迭代）时，若草稿库存在 owner 预览自测产生的数据，管家以选项式提问由用户点选去留，默认选项为「清空」；用户显式选择保留时这些数据随发布进入生产库。
- 界面与交互：

| 界面/入口 | 位置 | 构成 |
|-----------|------|------|
| 自测数据去留选项卡 | 工作台左栏对话流——owner 点「提交发布 / 更新上线」后由管家发出（对话流卡片类型清单见 §3.1 域引言） | 提示文案 + 自测数据行数摘要 + 选项「清空［默认］/ 保留」；点选后发布流程继续，未点选前发布流程停在该步 |
| 保留冲突报告卡 | 工作台左栏对话流——迭代发布选「保留」且存在冲突行时出现 | 复用 WB-07 失败行报告形态：成功并入行数 + 冲突跳过行数 + 冲突行明细 |

- 流程：
  1. owner 点「提交发布 / 更新上线」（发布面主操作区，或对话流「更新上线」操作卡，WB-14 / GJ-02）。
  2. 判定草稿库是否存在预览自测产生的数据；「无自测数据 →」不出现提问，直接进入步骤 5。
  3. 管家在左栏对话流发出去留选项卡（默认「清空」）；「未点选 →」发布流程停在该步、不生成审批单。
  4. 点「清空」→ 自测数据不随发布进入生产库；点「保留」→ 自测数据随发布进入生产库；迭代发布时保留行以追加方式并入生产库，「冲突行（主键/唯一约束）→」跳过并出保留冲突报告卡。
  5. 发布动线继续：资源档位确认（首发默认推荐轻量档、迭代默认沿用原档位，WB-14 / GOV-03）→ 生成审批单（RT-03/04）；可见范围于审批通过后设置（WB-14 / §2.2）。
- 规则与边界：
  - 提问与「清空」仅针对 owner 预览自测产生的数据；经 WB-07 双路径导入的存量数据一律随发布进入生产库、不在提问范围。
  - 自测/导入数据的判定依据 = 导入按批次留痕，仅用于发布去留判定，不构成 §5.2 顺延的行级归属能力。
  - 「保留」范围冻结为提交发布时刻的草稿库快照；审批期间审批人新增的试用数据一律不带入生产（RT-03）。
  - 迭代草稿库初始内容约定：迭代开始时草稿库不含生产数据副本，仅承接迭代期的自测与导入数据。
  - 首发与迭代提问行为一致；草稿库无自测数据时不出现该提问。
  - 本条为工作台发布路径专属；CLI deploy 路径无此提问，首发生产库默认空库初始化（回链 RT-03）。
- 验收要点：
  1. 草稿库含预览自测数据的应用发布时（首发与迭代一致），管家给出「清空 / 保留」选项式提问，默认为清空。
  2. 选清空后生产库无自测数据行；选保留后这些行在生产库可见。
  3. 草稿库无自测数据时不出现该提问。
  4. 含导入数据的应用选「清空」后，导入行完整进入生产库、仅自测行被清空。
  5. 审批期间审批人新增的试用数据不出现在生产库。
  6. 未点选去留前发布流程停在该步、不生成审批单。

**GOV-06 引擎与凭据档案配置（管理面，业务人员零感知）**
- 需求描述：造应用引擎的选择、模型接入路径与凭据档案全部是管理面决策；业务人员在工作台永远只是「开始造应用」，对引擎及其模型/凭据零感知，最多收到一条友好降级提示。应用自身 AI 功能所用模型为平台默认配置（WB-11），与引擎配置无关。
- 角色分工：

| 角色 | 职责 |
|------|------|
| 平台超管 | 维护平台默认档案（平台托管模型类） |
| 租户管理员 | 创建/分配本租户档案（客户订阅账号授权 / 客户自有模型 API key），分配粒度 = 全租户 / 用户组 / 指定用户；设并发上限；吊销；预配降级策略（订阅额度用尽自动降级到平台托管模型） |

- 档案类型：

| 档案类型 | 凭据形态 | 适用场景 |
|---------|---------|---------|
| 平台托管模型 | 平台内置引擎模型服务凭据，随部署提供、平台超管维护 | 开箱即用的默认路径；亦为降级策略的目标档案 |
| 客户订阅账号授权 | 企业既有引擎服务订阅账号的授权凭据 | 复用企业已订阅的引擎服务额度 |
| 客户自有模型 API key | 企业自备模型服务的 API key | 以企业自有模型承载造应用引擎 |

- 界面与交互（位置：管理后台-造应用引擎配置页，与能力总线 GOV-05 分置；逐区标注操作角色）：

| 界面/入口 | 位置 | 构成 |
|-----------|------|------|
| 凭据档案列表 | 造应用引擎配置页主区（租户管理员见本租户档案；平台超管见平台默认档案） | 列：档案名、类型、分配范围摘要、并发上限、当前并发数、状态（启用/已吊销）、创建时间；同一用户命中多档案时按解析链标注生效档案；空态 =「尚未配置凭据档案」+ 新建引导 |
| 创建/编辑弹窗 | 列表「新建档案」按钮 / 行上编辑 | 字段：档案名、类型（三类档案单选）、凭据录入（masked 控件，NFR-2 同口径）、分配范围选择器（全租户 / 用户组 / 指定用户）、并发上限、降级策略开关（订阅额度用尽 → 平台托管档案） |
| 吊销确认弹窗 | 档案行上「吊销」按钮 | 二次确认，明示对进行中会话的影响：自下一次请求起失效 |

- 引擎凭据异常 × 会话侧表现：

| 异常场景 | 会话侧表现 | 会话与历史 |
|---------|-----------|-----------|
| 订阅额度用尽、已预配降级策略 | 自动降级到平台托管模型档案；工作台左栏对话流出现一条友好降级系统提示卡（文案不暴露引擎与凭据细节） | 会话继续、不中断 |
| 订阅额度用尽且未配降级 / 凭据被吊销 / 无可用档案 | 对话流出现明确错误卡（「造应用服务暂不可用，请联系租户管理员」类文案） | 会话与对话历史完整保留，凭据恢复后原地续聊 |
| 同一档案并发会话数达上限 | 新消息被拒绝并提示「当前使用人数较多，请稍后再试」，不排队 | 会话与历史保留，稍后重试 |

- 规则与边界：
  - 生效档案解析链 = 指定用户 > 用户组 > 租户默认 > 平台默认；未配置任何租户档案时按解析链落到平台默认档案，不影响使用。
  - 降级为租户管理员预配策略：未预配时订阅额度用尽按上表错误卡处理，不自动降级。
  - 档案吊销自下一次请求起失效。
  - 同一档案并发会话数不超过其设定的并发上限；超限拒绝、不排队。
  - 业务人员零感知：引擎及其模型/凭据的一切配置项不出现在工作台，业务人员仅可能感知上表的降级提示或错误提示。
  - 应用自身 AI 功能所用模型为平台默认配置（WB-11 只读展示），与引擎配置无关。
  - 档案创建/分配/吊销与自动降级触发事件均计审计（GOV-04）。
- 验收要点：
  1. 引擎与凭据的全部配置项只出现在管理面，工作台无造应用引擎相关的选择入口（WB-11 的应用模型子页为只读展示，不属引擎配置）。
  2. 凭据档案只对其分配范围内的用户会话生效；吊销后自下一次请求起失效。
  3. 订阅额度用尽时（配置了降级策略）用户会话不中断，仅收到降级提示。
  4. 同一档案并发会话数不超过其设定的并发上限。
  5. 凭据档案的创建/分配/吊销在管理面可完成且计审计。
  6. 同时命中指定用户与用户组档案时，按解析链取指定用户档案。
  7. 无可用档案时对话侧出现明确错误卡、会话历史保留，凭据恢复后可原地续聊。
  8. 并发超限时新消息得到明确提示而非静默失败。

## 5. 范围外与顺延

### 5.1 本版明确不做

| 项 | 说明 |
|----|------|
| 交互式终端 / SQL 查询面 | 排障走只读运行日志（WB-13），数据出口走导出（WB-06） |
| 模拟用户视角切换 / 样本数据播种 | 不做视角切换入口与样本数据播种；想体验其他用户视角，用真实账号登录访问已发布应用即可 |
| 复制同事应用为自己的草稿 | 不做；新建走空白 / 模板 / 导入本地项目三路径（WB-01） |
| 草稿授权试用 / 共建 | 草稿 owner-only（WB-16），想给同事用就发布 |
| 组织级规范资产注入 | 不在本版范围（组织统一 UI/代码规范等资产自动注入生成过程） |
| 云端通用 IDE | 改码走对话，玻璃盒只读（WB-12） |
| 已定顺延 v3.1 的项 | 只在 §5.2 维护（点选局改、代码在线编辑、数据自助恢复等），本表不重复 |

### 5.2 v3.1 顺延清单

- 管家持续看护上线应用（定时/事件触发巡检、增量比对节流、合并简报推送，及其依赖的平台级触发/调度子系统）——本版不做，v3.1 重新立项。
- 点选局改；代码在线编辑（玻璃盒本版只读，WB-12）；模板库深化。
- 知识库推荐候选的试检索命中预览（候选卡上展示「为什么推荐它」的检索证据，WB-10 增强）。
- 应用模型的选择/更换交互（本期应用模型用平台默认配置，WB-11 只读展示）。
- 生产日志对指定用户单独授权（本版生产日志仅 owner 与租户管理员可见，WB-13）。
- 应用数据行级归属（系统 owner 字段 / 来源字段）与「仅本人 / 全部」按表数据模式。
- 应用数据备份与自助恢复（用户显式发起、可审计，不动摇「生产数据默认不回滚」）。
- 应用所有者使用情况视图（调用量/活跃用户/趋势，仅 owner 可见）——与 PRD-1 §5.2「owner 应用侧审计与访问记录自查视图」同域，v3.1 立项时合并评估，避免两处分别维护。
