## 一、结论

**在开放 API 已有的会话能力上点亮任务模式：调用方一次提交任务描述、附件、技能与模型，平台异步执行；调用方凭任务标识查询状态、取回结果、下载产物。**

三条支撑：

1. **契约不另起。** 同一能力、同一权限位 `chat:invoke`、同一套身份模式；只在「运行模式 × 传输方式」中新开「任务 × 异步」一格。
2. **可无人值守。** 调用方可先查询执行身份可用的模型、技能、工具与知识，查询与提交按同一口径判定；任务执行中不向用户提问；提交时一次校验全部入参，不可用项明确报错，不静默丢弃。
3. **结果可交付、可追溯。** 状态可重复查询；产物经鉴权下载；归属、分区与审计沿用父 PRD 规则。

本期不做：实时事件流、中途提问、续接会话、托管应用接入、在途任务数上限（§三）。

## 二、背景与场景

### 2.1 背景

- **情境**：任务模式能处理多文件、多步骤的复杂任务，但使用者要自己写长提示词、手动选技能。
- **冲突**：客户项目要把一类固定任务交给一线员工，员工只上传文件、点一次确认；平台目前只能在工作台里人工操作，开放 API 调用任务模式返回 `26017`。
- **疑问**：能否让客户应用内置提示词和技能，代用户发起任务并取回结果？
- **解答**：开放任务模式 API，由客户应用持有预置内容并调用（§一）。

### 2.2 典型场景：表单式客户应用

员工在客户应用里上传文件、点确认，等待完成后下载结果。应用后端持服务账号密钥调用本 API，任务描述与技能写在应用里。

| 执行身份 | 特点 | 前提 |
|---|---|---|
| 代表当前员工（代表他人） | 结果归员工本人，员工可回工作台查看；按员工本人的知识库与工具权限执行 | 应用接入客户统一登录，并能映射到平台用户 ID；密钥持有 `delegate` 且员工在委托范围内 |
| 服务账号自身身份 | 部门共用、不区分个人权限；按授权给服务账号的资源执行 | 应用按外部用户传 `X-End-User` 分区 |

平台内的 workflow 代码节点也可以作为调用方，与外部应用同等对待：持服务账号密钥调用本 API，两种执行身份均可使用，本 API 不为其另设规则。代码节点所在执行环境的网络连通与执行时长，由交付按部署配置调整，不在本文范围。

### 2.3 与父 PRD 的关系

父 PRD §4.6.3 第六小节要求点亮任务模式前完成四项前置，并考虑两项平台语义。本文处理如下：

| 父 PRD 前置 | 本期处理 | 见 |
|---|---|---|
| ① 异步作业语义 | 提交即返回任务标识；状态可查、结果可取 | §4.4、§4.7 |
| ② 可重放事件流 | 不对外开放事件流，以可重复的状态查询替代 | DT-3 |
| ③ 后端统一编排 | 一次提交完成建会话与入队，调用方不需要二次触发 | §4.4 |
| ④ 并发准入与限流 | **改判**：只排队、不设上限，状态报告排队位置；限流仍归 P2 | DT-5 |
| 「等待人工输入」状态 | 本期任务不提问，该状态不出现；契约为它留位 | DT-4 |
| 产物下载入口 | 经鉴权按「任务 + 文件」下载 | §4.8 |

父 PRD 的「未开放能力明确报错」「附件只走上传端点」「业务上下文指令只叠加」「归属不匹配返回 404」「契约形态归 design（D9）」全部沿用。

## 三、范围

**做**：查询可用配置 · 提交任务 · 查询状态 · 取回结果 · 下载产物 · 终止任务 · 附件沿用会话附件上传 · 对外文档新增「任务模式」章节。

**不做**：

| 不做 | 原因 |
|---|---|
| 实时事件流、执行步骤明细 | 表单场景只需状态；见 DT-3 |
| 中途提问（等待人工输入） | 见 DT-4；契约留位 |
| 在已有会话上续接或追问 | 见 DT-7 |
| 任务模式同步（流式）执行 | 见 DT-2 |
| 日常模式异步执行 | 无需求，维持 `26015` |
| 托管应用经能力总线接入 | 见 DT-8，另行立项 |
| 在途任务数上限、限流、配额 | 见 DT-5；限流归父 PRD P2 |
| 幂等键、Webhook 回调 | 父 PRD 已列为 P2 / 非目标 |
| 引用溯源对外开放 | 本期答复正文去除引用标记（§4.8） |
| 个人访问令牌调用 | 父 PRD 本期个人令牌只开 `knowledge:read` |
| 任务总时长上限 | 沿用任务模式现有的执行轮次上限 |
| 平台侧保存预置提示词与技能（任务模板） | 预置内容由客户应用持有 |
| 附件目录层级 | 本期附件按平铺文件处理 |
| workflow 代码节点执行环境的配置调整（网络连通、执行时长） | 由交付按部署调整 |
| 资源归属人凭会话标识直接读取服务账号会话的消息 | 日常模式既有问题，另行处理；本期任务模式与日常模式保持一致 |

## 四、规则

> 本章只定业务规则。字段名、端点路径、请求与返回形态归 design（沿用父 PRD D9）。
> **执行身份**：自身身份下为服务账号，代表他人时为被代表用户。下文所有权限判定均以执行身份为准。

### 4.1 调用全景

```
① 查询可用配置 → 模型、技能、平台工具、知识库与知识空间（可选；可在应用启动时查询并缓存）
② 上传附件 → 得到附件引用
③ 提交任务 → 得到任务标识，状态「排队中」
④ 轮询状态 → 排队中 / 执行中 / 已完成 / 失败 / 已终止
⑤ 终态后取回结果 → 答复正文、产物清单、附件处理结果
⑥ 下载产物
（③ 之后任一非终态均可终止任务）
```

### 4.2 开通与权限

| 规则 | 依据 |
|---|---|
| 调用需持权限位 `chat:invoke`，缺失返回 `26003` | DT-1 |
| 自身身份、代表他人两种模式均支持；代表他人沿用父 PRD 五道准入 | 父 PRD §4.4.4 |
| 代表他人时，被代表用户须具备任务模式使用权限，否则拒绝 | 代表他人即以其平台权限执行，工作台里不能用的，API 也不能用 |
| 自身身份下不判定任务模式使用权限 | 服务账号不登录工作台，无此权限项 |
| 个人访问令牌不可调用 | 父 PRD §4.10.3 权限位白名单 |

### 4.3 可用配置查询

调用方写进应用的模型、技能、工具与知识，须能事先从平台查到，而不是从管理后台抄名字。

| 规则 | 依据 |
|---|---|
| 扩展日常模式已开放的配置查询，按运行模式区分；运行模式为「任务」时返回：可用模型（标出任务模式默认模型）、平台工具、已启用技能、知识库与知识空间 | DT-9 |
| 权限、身份模式与个人令牌限制同 §4.2；代表他人且被代表用户不具备任务模式使用权限时，返回与提交相同的 403 | 查询与提交同一准入 |
| 返回内容按执行身份过滤，与 §4.4 的提交校验同一口径：查询中列出的项，提交时不会因「不存在」或「无权限」被拒 | 避免查到能用、提交被拒 |
| 每项返回提交时使用的标识与显示名称；技能另返回说明，提交时按技能名选择 | 显示名称可重复、可修改，不能作标识 |
| 知识库、知识空间只返回执行身份可读的，支持按名称搜索与分页 | 数量可能很多；表单场景需让员工挑选 |
| 查询结果是时点快照，提交时仍按 §4.4 重新校验 | 管理员可随时停用技能、下线模型 |
| 运行模式为「日常」或未指定时，返回内容与现有契约一致 | 父 PRD 演进要求：不推翻已开放的日常模式契约 |

### 4.4 提交

| 入参 | 必填 | 规则 | 不合法时 |
|---|---|---|---|
| 运行模式 | 是 | 取「任务」；未指定时按日常模式处理 | 枚举外取值返回 `26017` |
| 传输方式 | 是 | 任务模式只接受「异步」 | 拒绝，与 `26015`、`26017` 可区分 |
| 任务描述 | 是 | 非空，有长度上限；客户应用的预置提示词放在这里 | 拒绝 |
| 业务上下文指令 | 否 | 叠加在平台提示词之上，不替换、不关闭 | 拒绝 |
| 模型 | 是 | 从执行身份在工作台可用的模型中按名选择，且须在线 | 拒绝 |
| 技能 | 否 | 按技能名选择，须为本租户已启用；不传则不加载任何技能 | 任一不可用即拒绝，响应列出不可用的技能名 |
| 知识库 / 知识空间 | 否 | 执行身份须有读权限 | 拒绝并指明出错项 |
| 平台工具（含代码执行、联网搜索） | 否 | 执行身份须有使用权限 | 拒绝并指明出错项 |
| 附件引用 | 否 | 只接受会话附件上传得到的引用，且须属于同一调用主体；不接受内联文件数据与外链地址 | 拒绝 |
| 会话标识 | 不接受 | 每次提交新建会话 | 拒绝 |

| 通用规则 | 依据 |
|---|---|
| 任一入参不合法则整次提交被拒，不创建任务 | 父 PRD §4.6.3 硬边界 2「不静默降级」 |
| 提交成功即已入队，不依赖调用方的任何后续请求 | 父 PRD 前置 ③ |
| 启用内容安全策略的部署中，检查任务描述与业务上下文指令；命中则拒绝提交，并返回处置文案 | 与工作台一致 |
| 提交后、执行前，所选技能被停用或模型下线：任务以「失败」结束，并说明原因；不得缺少该项继续执行 | 不静默降级 |

### 4.5 附件

| 规则 | 依据 |
|---|---|
| 类型与单个文件大小上限与工作台一致 | 同一执行内核 |
| 附件在执行阶段解析；单个附件不可用不导致任务失败 | 与工作台一致 |
| 结果中逐个列出不可用的附件及原因：类型不支持 / 解析失败 / 已过期 | 如实呈现，调用方可据此提示用户 |
| 附件引用有有效期，须在有效期内提交；有效期写入对外文档 | 附件上传沿用会话附件的临时存储 |

### 4.6 执行

| 规则 | 依据 |
|---|---|
| 执行中不向用户提问；信息不足时按合理的默认假设推进，并在答复中写明所做假设 | DT-4 |
| 全部任务（含工作台发起的任务）共用一个队列，先到先执行；不设在途任务数上限 | DT-5 |
| 沿用任务模式的执行轮次上限；超限时能整理出结果的记为「部分完成」，否则记为「失败」 | 与工作台一致 |
| 排队中、执行中的任务可终止；终止后不可恢复，不产出结果 | — |
| 已结束的任务不可终止，明确报错 | 不静默成功 |

### 4.7 状态

| 状态 | 含义 | 终态 | 附带信息 |
|---|---|---|---|
| 排队中 | 已受理，尚未开始 | 否 | 排队位置 |
| 执行中 | 已开始，含附件解析阶段 | 否 | 待办进度（已完成数 / 总数，尚未生成待办时为空） |
| 已完成 | 执行结束并产出结果 | 是 | 是否部分完成 |
| 失败 | 执行未成功 | 是 | 失败类别与说明 |
| 已终止 | 被调用方终止 | 是 | — |

| 规则 | 依据 |
|---|---|
| 本期不出现「等待输入」状态；契约须能在日后加入该状态，且不需要调用方改已有代码 | DT-4；父 PRD 演进要求 |
| 状态以平台持久记录为准，可重复查询；查询本身不消耗任何数据，终态后每次结果一致，也不影响工作台对同一任务的实时展示 | DT-3 |
| 查询状态与取回结果可以是同一次调用，形态归 design | 父 PRD D9 |
| 失败类别沿用平台现有分类（内容审核拦截、模型额度用尽、模型鉴权失败、模型限流、服务不可用、网络超时、任务中止、其他），对外文档逐类给出处置建议 | 调用方需区分「重试有用」与「须联系管理员」 |
| 查询、取回结果、下载、终止均校验归属；不匹配一律返回 404 | 父 PRD §4.6.3 第四小节 |

### 4.8 结果与产物

| 内容 | 规则 |
|---|---|
| 答复正文 | 去除内部引用标记 |
| 产物清单 | 每项含文件名、类型、大小、是否主交付物；不含存储路径或服务器本地路径 |
| 未生成的交付物 | 模型声称生成、实际不存在的交付物单独列出，不混入产物清单 |
| 附件处理结果 | 见 §4.5 |
| 产物下载 | 调用方凭密钥按「任务 + 文件」下载，校验归属；不返回长期有效的直链 |
| 保留期 | 与工作台任务一致 |

### 4.9 归属、可见性与审计

| 维度 | 代表他人 | 自身身份 |
|---|---|---|
| 执行权限 | 被代表用户 | 服务账号 |
| 任务归属 | 被代表用户；出现在其工作台会话记录中，可查看执行过程与产物 | 服务账号；不出现在任何自然人的工作台会话记录中，包括该服务账号的资源归属人。处理方式与日常模式一致 |
| 外部分区 | 由被代表用户天然分区 | 按 `X-End-User` 分区；未传时沿用父 PRD §4.3.4（记录告警、不阻断） |

| 规则 | 依据 |
|---|---|
| 审计沿用父 PRD §4.8.1 逐调用记录与双归属，可同时查到调用密钥与执行身份 | 父 PRD |
| 模型用量计入执行身份 | 与工作台一致 |
| 任务模式使用统计可区分「来源：开放 API」 | 运营需区分工作台与集成调用 |

### 4.10 错误

| 场景 | HTTP | 错误码 |
|---|---|---|
| 缺少 `chat:invoke` | 403 | `26003`（沿用） |
| 运行模式为枚举外取值（提交与配置查询） | 400 | `26017`（沿用，含义收窄，见 §7.2） |
| 日常模式要求异步执行 | 400 | `26015`（沿用） |
| 任务模式要求同步执行 | 400 | 新增 |
| 传入会话标识 | 400 | 新增 |
| 技能不存在或未启用（响应列出技能名） | 400 | 新增 |
| 被代表用户不具备任务模式使用权限 | 403 | 新增 |
| 终止已结束的任务 | 409 | 新增 |
| 内容安全拦截（响应附处置文案） | 400 | 新增 |
| 模型不存在、不可用或未上线 | 400 | 新增；日常模式同一场景目前只有 HTTP 400、无平台错误码，一并补上 |
| 知识库、知识空间、平台工具无权限或不存在 | — | 沿用各业务模块原有错误码 |
| 附件引用无效、不属于调用主体 | — | 沿用会话附件上传原有错误码 |
| 查询、取回、下载、终止时归属不匹配 | 404 | — |

新增错误码的编号，按 release-contract 的 260 段规则在 design 阶段分配；不得占用父 PRD 附录 C 的预留段。执行期失败（§4.7 失败类别）不是 HTTP 错误，体现在任务状态里。

## 五、验收标准

### 5.1 验收条目

**开通与权限**
- **AC-T1**　持 `chat:invoke` 的服务账号密钥可发起任务模式；缺该权限位返回 403（`26003`），不创建任务。
- **AC-T2**　代表他人时沿用五道准入；被代表用户不具备任务模式使用权限时返回 403（新码），不创建任务。
- **AC-T3**　个人访问令牌调用任务模式被拒，不创建任务。

**可用配置查询**
- **AC-T29**　以「任务」运行模式查询可用配置，返回可用模型（标出任务模式默认模型）、平台工具、已启用技能（含技能名、显示名称、说明）、执行身份可读的知识库与知识空间；以日常模式或不指定运行模式查询，返回与现有契约一致。
- **AC-T30**　用查询结果中的任意一组模型、技能、工具、知识库、知识空间提交，不因「不存在」或「无权限」被拒；代表不同员工、自身身份分别查询，结果各按执行身份过滤。
- **AC-T31**　停用的技能、未上线的模型、执行身份无权限的工具与知识不出现在查询结果中；查询后停用某技能再提交，按 §4.4 被拒。
- **AC-T32**　知识库、知识空间支持按名称搜索与分页；代表他人且被代表用户不具备任务模式使用权限时，查询返回 403，与提交一致。

**提交**
- **AC-T4**　任务模式 + 异步提交返回任务标识，状态为「排队中」；调用方不再发送任何请求，任务仍会执行至终态。
- **AC-T5**　任务模式 + 同步返回 400（新码）；日常模式 + 异步仍返回 `26015`；枚举外运行模式仍返回 `26017`；三者响应可区分。未指定运行模式时按日常模式执行。
- **AC-T6**　所选技能中任一不存在或未启用时，提交被拒，响应列出不可用的技能名，不创建任务。
- **AC-T7**　模型不在执行身份的工作台可用列表中或未上线时，提交被拒并返回平台错误码，不创建任务。
- **AC-T8**　知识库、知识空间、平台工具中任一项执行身份无权限或不存在时，提交被拒并指明出错项。以自身身份提交时，只能使用授权给该服务账号的资源。
- **AC-T9**　附件引用属于其他调用主体、为内联文件数据或外链地址时，提交被拒。
- **AC-T10**　传入会话标识时返回 400（新码），不创建任务、不续接任何会话。
- **AC-T11**　启用内容安全策略的部署中，任务描述或业务上下文指令命中时提交被拒，返回处置文案，不创建任务。
- **AC-T12**　提交后、执行前停用所选技能（或下线所选模型），任务以「失败」结束，失败说明指明该技能（或模型）；任务不以缺少该项的方式继续执行。

**附件**
- **AC-T13**　同时提交一个类型不支持的附件和一个正常附件：任务正常执行至终态，结果中列出前者及原因「类型不支持」。

**执行与状态**
- **AC-T14**　API 发起的任务全程不出现「等待输入」状态；任务描述信息不足时仍产出结果，答复中写明所做假设。
- **AC-T15**　排队中、执行中的任务可终止，状态变为「已终止」且不产出结果；终止已结束的任务返回 409（新码）。
- **AC-T16**　执行中连续查询多次，进度只增不丢；终态后连续查询多次，结果完全一致；期间被代表用户在工作台打开该任务，实时展示不缺失。
- **AC-T17**　排队中的任务返回排队位置；执行中的任务返回待办进度，尚未生成待办时为空。
- **AC-T18**　失败的任务返回失败类别与说明；部分完成的任务带「部分完成」标记。
- **AC-T19**　换一个调用主体（另一服务账号、另一被代表用户，或自身身份下另一 `X-End-User`）查询、取回结果、下载、终止同一任务，一律返回 404。

**结果与产物**
- **AC-T20**　答复正文不含内部引用标记；产物清单不含任何存储路径或服务器本地路径。
- **AC-T21**　模型声称生成但实际不存在的交付物单独列出，不出现在产物清单中。
- **AC-T22**　产物须凭密钥下载并通过归属校验，内容与工作台下载的文件一致；返回中不含长期有效的直链。

**归属与审计**
- **AC-T23**　代表他人发起的任务出现在被代表用户的工作台会话记录中，可查看执行过程与产物。
- **AC-T24**　自身身份发起的任务不出现在任何自然人的工作台会话记录中，包括该服务账号的资源归属人。
- **AC-T25**　审计记录可同时查到调用密钥与执行身份；任务模式使用统计可区分来源为开放 API。

**交付**
- **AC-T26**　端到端：按最小表单流程（查询可用配置 → 上传 2 个附件 → 以预置任务描述和 1 个技能提交 → 轮询至完成 → 下载主交付物），代表他人、自身身份各走通一遍。
- **AC-T27**　对外文档新增「任务模式」章节，逐项列出可用配置查询、入参、状态、结果内容、错误码及处置、完整调用示例，以及本期不支持的能力和对应报错。
- **AC-T28**　对外文档的升级说明写明：持 `chat:invoke` 的存量密钥升级后即可发起任务模式。
