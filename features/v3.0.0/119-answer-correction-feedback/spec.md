# F119 应用回答纠错反馈

状态：已确认
需求来源：本次需求描述和两轮需求发现确认。

工作台用户发现应用回答有误时，可以指出具体原句，提交更正说明和依据。应用负责人选择应用关联的一个知识库，将反馈分派给该库的一名维护人员。维护人员记录处理结果，应用负责人向原反馈用户回复。

首期覆盖当前租户自有、且关联了至少一个知识库的应用回答。跨租户共享应用的回答不开放纠错。自动修改知识内容、重写历史回答和批量分派留在首期范围之外。

| ID | 当满足条件时，系统应提供的行为 | 失败情形 |
|---|---|---|
| AC-01 | 当用户针对自己有权查看的适用回答提交原句、更正说明和依据时，系统应记录反馈并显示提交成功。原句没有引用也可以提交。 | 缺少任一必填项或原句不属于该回答时，应拒绝提交。 |
| AC-02 | 当反馈提交成功时，应用负责人应能看到待分派反馈及其原句、更正说明和依据。 | 无该应用负责权限的人不能从负责人入口读取反馈。 |
| AC-03 | 当应用负责人选定应用关联的一个知识库和该库的一名维护人员时，系统应将反馈置为待处理，并让受派人看到反馈内容。 | 知识库与应用无关联或受派人无该库维护权限时，应拒绝分派并保留待分派状态。 |
| AC-04 | 当受派维护人员提交非空处理结果时，系统应保存结果并将反馈置为待回复，应用负责人可查看结果。 | 未受派的维护人员提交结果时，应拒绝并保留原状态。 |
| AC-05 | 当应用负责人对待回复反馈发送非空回复时，系统应将反馈置为已回复，并让原反馈用户看到回复。 | 尚无处理结果时，应拒绝发送。 |
| AC-06 | 当用户查看自己提交的反馈时，系统应显示对应原句、处理进度和已发送的回复。 | 其他用户通过反馈用户入口访问时，应拒绝，包括跨租户访问。 |
| AC-07 | 当用户查看未关联知识库或由其他租户共享的应用回答时，系统应隐藏逐句纠错入口。 | 应用已无关联知识库或属于其他租户时，从旧页面提交也应被拒绝。 |

## 已确认的产品口径

- 依据支持文字和其中的链接。负责人通过待处理列表收到反馈，用户通过自己的反馈记录查看回复。独立消息提醒、文件附件和重新分派留待后续。
- 处理结果可以记录已修正，也可以说明无需修正或无法修正的原因。
