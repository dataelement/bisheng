# 可选 Gateway 与旧版兼容修订（2026-11-16）

用户本轮明确要求兼容旧 Gateway、尽量不让 Gateway 感知租户，且 Gateway 是可选组件。此前已明确：普通用户按真实主属；超管创建业务资源归管理目标；已有聊天消息/会话按持久归属回写；没有消息/会话的首次拦截按用户真实主属创建。本轮仅调整旧协议兼容及交付依赖；旧Gateway配置页面范围与旧直连接口授权缺口分别记录，不把前面的可行性讨论当成用户已接受安全风险。该确认修订此前必须联合升级 Java 的交付边界。

## 范围与设计

1. 毕昇的认证、租户选择、资源权限与数据过滤独立运行，不依赖安装、调用或升级 Java。普通租户/个人业务继续保留严格目标头，不全局放宽准入。既有本人信息/本人主部门/独立凭据协议保持。
2. 旧 Gateway 两个聊天回写端点（POST /api/v1/chat/message、PUT /api/v1/chat/message/{message_id}）声明为身份准入，认证仍必需，不要求读取管理选择或携带管理目标头。目标由聊天领域的记录归属决定，不能按客户端 user_id、flow_id 的所有者或当前 Redis 选择兜底。此例外仅覆盖这两个端点，DELETE 和其他聊天接口不变。
3. 用消息/会话唯一编号执行窄范围的持久身份定位；定位期间允许读取必要归属元数据，校验本人、消息与会话租户/资源一致、未删除和非独立API会话后才进入固定租户上下文写入。普通用户仅可操作其主属；超管仍须为消息/会话本人，不能改写他人记录；独立 Web 会话凭据不得超出其固定租户。归属缺失、停用、冲突或对象不存在拒绝，不改历史数据。
4. POST 有会话时按会话租户；没有会话时按经后端认证的真实主属（独立凭据仍按原固定范围），验证应用存在及原 use 权限，然后先创建有效会话再保存消息，防止先留下无归属消息；既有DAO仍为分步提交，不新增事务/幂等引擎，消息保存失败时可能保留空会话，重试沿用原会话归属。会话创建和资源使用仍保留既有审计/快照/遥测。后续回写不改变已持久的归属。
5. Gateway 仍按资源编号＋类型、部门编号和既有组合存储/执行配置；不新增租户字段或目录同步。旧 Gateway 自有配置接口本批不宣称后端租户授权已完善：页面只提供当前租户资源和部门，直接构造旧接口请求的授权加强另列，不能把前端限制当成安全校验。不新增 Python 代理层，不修改网络入口或 Java 代码。
6. Gateway 不部署时，毕昇核心资源创建/查询、登录与范围自举继续工作；Gateway专属敏感词/限流功能仍需启用该组件；启用旧 Gateway 时正常代理透传，旧回写只依赖原 Cookie、路径和正文。新 Gateway 的独立修复分支保留待合并，不作为毕昇本批运行前提。DSH 独立凭据/内容安全协议不改变；旧 Java 对错误的通用提示差异不承诺消除。

## 历史影响及验证

零新增表、列、迁移，不批量迁移聊天记录、业务资源或创建人。超管主属 Root、管理甲租户的首次拦截记录将归 Root；原来已属于甲的会话继续归甲。普通用户不因兼属部门改变主属。Root共享应用的记录归使用方，不能按资源所有者归 Root。

回归覆盖无 Gateway、模拟旧 Gateway 原请求、超管管理切换后延迟回写、普通用户/他人消息/凭据越界、首次拦截、孤儿与冲突记录、上下文恢复及既有资源创建归属。真实旧 Java 进程、浏览器和MySQL/DM8验收与本地应用测试分开报告。开发基线为缓存发布线089e152db0；本轮远端fetch连接失败，合入前须重新核验远端。

## 方案取舍与重新考虑条件

选择后端按持久归属兼容，而不做全局缺头回退、伪造用户主属、Gateway专用信任白名单或新代理层。这样不引入额外租户选择权威，也不影响可选组件部署。已知首次拦截记录按主属，不能按管理目标筛选看到它；若未来要求同一共享资源的分租户规则、租户独立Gateway总配额、旧直连接口完整授权或匿名拦截落库，须另行明确契约并改造相应入口。此批不移除既有鉴权，也不宣称旧Java全部客户分支均已兼容。

## 影响评估待闭环项（2026-11-16）

首次拦截按主属创建会话后，同chat_id正常继续的工作流/助手写入未纳入原21项测试。正常执行按管理目标查询会话时可能看不到主属行，产生重复主键及消息/会话混合归属。存储机制已在隔离SQL确认，真实时序未验证，具体衔接修复待定；不得默认搬迁历史或改变用户确认的首次归属。详见[影响评估](../../../docs/reviews/tenant-context-optional-gateway-impact-test-focus-20261116.md)。

## 首次拦截后继续的修复设计（用户2026-11-16明确授权）

在毕昇聊天领域提供窄的会话持久化适配器，通过公共协议注入浏览器助手/工作流客户端；工作流受信任务仅在platform路径使用同一适配器。按当前会话编号、真实用户和应用编号核验持久会话，存储消息时沿会话租户，资源执行上下文始终保持原目标；无会话时沿既有正常执行目标，首次Gateway拦截仍按前述主属规则。禁止把整个模型/工作流执行重绑到主属。

浏览器跨执行/存储范围仅支持当前超管本人主属会话，且应用仍须属于已验证管理目标；普通用户和独立凭据不可借此跨范围。任务侧仅依据已准入任务身份、同一资源与持久会话恢复存储范围，不使用最新选择。消息和可选新会话在同一SQL提交中保存，重用已有会话，编号冲突不得先留下消息。已有记录不搬迁；归属矛盾拒绝。

同会话的历史读取、重连、输入消息更新和消息引用持久化同步使用该窄范围；列表不扩大，公开/服务凭据既有独立会话规则不变。修复不改Gateway、表/列、任务消息协议或历史数据；验证首次拦截后正常继续、同连接/重连、普通用户及独立凭据拒绝、异常恢复和原资源执行目标保持。

## 首次拦截衔接最终实现

当前修复及验证以[本轮交付](continuation-fix-delivery-20261116.md)为准；前文“待闭环”是缺陷发现时点，不代表当前仍未实现。按受控持久化协议分离存储范围与资源执行，消息和新父会话同事务保存，平台输入提示提前与父一起持久化；重连/已知详情仅恢复合法本人会话。历史孤儿和混合归属仍拒绝、不补父，不新增Gateway契约。可选组件条件和旧直连接口授权缺口不变。
