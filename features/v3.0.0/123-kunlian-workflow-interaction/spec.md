# Feature 昆联反向调用 Workflow 人工输入与恢复

- **Feature ID**: F123（拟用，合入前复核）
- **Status**: CONFIRMED，用户确认进入设计
- **Mode**: SPEC_ONLY，Mock 优先
- **Version**: v3.0.0
- **关联**: [开发规划 4A](../../../docs/architecture/proposals/kunlian-workflow-development-plan.md#下一批需求发现--人工输入长任务与取消)、[F122 固定版本反向调用](../122-kunlian-workflow-invocation/spec.md)、[F121 发布与登记](../121-kunlian-workflow-management/spec.md)。沿用 F118 的可信用户和租户语义及 F048 的 Workflow 使用权校验。

## 1. 目标与范围

昆联调用毕昇已登记的固定 Workflow 版本。工作流到达原生输入节点时进入等待，昆联通过轮询取得当前表单。原实际用户提交答案后，另一 Worker 从等待点继续同一次运行，昆联再通过轮询取得结果。

首轮覆盖一处毕昇原生文本表单、查询等待状态、提交答案、跨 Worker 恢复及终态查询。Mock 验收使用「开始 → 文本输入 → 输出 → 结束」的线性工作流，样例使用一个必填文本字段。调用方显式选择交互运行，F122 既有预置输入和无交互调用继续按原合同执行。

范围限于单次人工等待。远端 Agent 异步运行和取消归 4B，远端 Agent 人工交互归 4C。文件上传、多轮表单、审批、转交、主动取消、回调、事件订阅与断线续取按后续工作包处理。

## 2. 用户故事

- 作为昆联调用方，我希望用原会话查询当前是否等待输入，提交后仍用该会话查询结果。
- 作为实际运行用户，我希望过一段时间再回答，重复点击也只提交一次。只有我在原接入方及租户中仍有该工作流的使用权限时，才能查看或完成该交互。
- 作为毕昇发布者，我希望编辑、发布新版本或下线旧版本时，已受理的会话仍按原版本和表单继续。

## 3. 业务需求

| ID | 需求 |
| --- | --- |
| REQ-01 | 在 F122 的固定版本调用基础上支持显式选择交互运行。首次受理返回同一套会话和版本标识，重复发起按 F122 的规则去重。选定版本不支持首轮表单时，拒绝启动交互运行。 |
| REQ-02 | Workflow 到达输入节点时公开可轮询的等待状态，返回当前交互标识、冻结版本对应的文本字段约束及等待截止时间。初始请求结束后仍可查询，等待期间释放原 Worker 的执行任务。成功或失败仍通过原会话查询。 |
| REQ-03 | 交互提交必须匹配原会话和当前交互。输入按该次表单校验，校验失败不消耗交互。相同提交标识与相同答案的重试返回原受理结果，即使已经恢复或结束也不会再次启动。相同标识改答案须报冲突，同一交互已经接受答案后，用新标识也不能再次消费。 |
| REQ-04 | 受理答案后，另一 Worker 能从原输入节点的等待点继续，沿用暂停前的工作流上下文、原会话、发布版本和实际用户。恢复不得重新执行暂停前已完成的节点。修改草稿、发布替换或下线不改变已受理会话。 |
| REQ-05 | 发起、轮询、提交、重试和恢复前均按 F122 的边界核验可信接入方、租户、原实际用户和当前 Workflow `use`。其他主体或撤权、停用的用户不得获得表单或结果。已接受答案但 Worker 启动前权限失效时，不继续执行。权限服务暂不可用时，查询和提交应给出安全的可重试结果。 |
| REQ-06 | 等待截止时间内可接受一次有效答案。已到期且未接受答案的交互进入可查询的等待超时终态，迟到答案不能恢复运行。答案在等待截止前已受理的，进入恢复阶段并按其独立时限处理。等待超时、交互提交受理、恢复失败及成功终态应可区分，迟到任务或输出不能覆盖终态。 |
| REQ-07 | Mock 阶段用隔离的昆联身份和请求模拟首轮闭环。跨 Worker 验收须在第一个 Worker 已退出后，由另一个独立执行实例恢复，验证实际 Workflow 节点执行。真实协议替换点留 `TODO`，受控环境和双方联调记录为待执行（`NOT_RUN`）。 |

## 4. 行为口径

| 运行阶段 | 昆联可观察到的行为 |
| --- | --- |
| 已受理／运行中 | 用同一 `session_id` 轮询。处于该阶段时尚无最终结果。 |
| 等待输入 | 查询返回待填表单及交互标识。相同会话的重复查询返回同一待办，不延长等待时间。 |
| 已接受答案／恢复中 | 提交响应表示答案已被接受。查询可继续跟踪原会话，表单不再可提交。 |
| 成功／失败 | 在保留期内轮询可重复读取结果或安全的失败分类。等待超时和恢复失败可区分，响应不得包含原始异常、凭据或内部检查点。 |

## 5. 验收标准

V-01 为隔离 Mock HTTP 与实际 Workflow 的跨 Worker 闭环，V-02 为权限、并发和超时集成验证，V-03 为受控环境及双方真实联调。当前阶段为规格编写，V-01、V-02 等待实施，V-03 标记为 `NOT_RUN`。

| ID | Requirements | 可观察验收结果 | Verification |
| --- | --- | --- | --- |
| AC-01 | REQ-01、REQ-02 | 有权用户选择交互运行并提交 V1 后，取得会话和版本标识。原请求结束后用新请求轮询，仍可获得同一交互标识、文本表单和截止时间。重复轮询不创建新的待办。 | V-01、V-03 |
| AC-02 | REQ-04、REQ-07 | Worker A 到达等待点并退出。用户补交有效文本后，Worker B 使用相同会话和 V1 恢复。结果同时包含能证明暂停前上下文被保留的信息和提交的答案。核对暂停前节点只执行一次。 | V-01、V-03 |
| AC-03 | REQ-01、REQ-04 | 等待期间修改草稿、用 V2 替换 V1 或下线 V1 后，已受理会话仍按 V1 表单接受输入并返回 V1 结果。新调用按 F122 规则拒绝已不可用的 V1。 | V-02 |
| AC-04 | REQ-03、REQ-04 | 同一答案并发提交或响应丢失后重试，只接受一次并恢复一次。同一标识修改答案返回冲突。换新标识提交已消费的交互被拒。提交无效文本后，仍可提交修正后的合法答案。 | V-02、V-03 |
| AC-05 | REQ-05 | 其他用户、租户或接入方无法查看表单或提交答案。原用户撤权或停用后，轮询、提交和重试被拒。若答案已受理后才撤权，Worker 不执行恢复后的节点。 | V-02、V-03 |
| AC-06 | REQ-06 | 未提交答案就到达截止时间时，查询得到等待超时终态，迟到提交无法恢复。截止前已接受的答案按恢复时限处理。恢复失败可独立查询，迟到执行结果不能覆盖失败终态。 | V-02 |
| AC-07 | REQ-01、REQ-07 | F122 预置文本输入和无交互用例继续按原合同返回结果。选择交互运行时，无首轮支持的表单则拒绝启动，不产生等待会话。 | V-01、V-02 |
