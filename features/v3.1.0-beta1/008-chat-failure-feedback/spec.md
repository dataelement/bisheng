# 日常与任务模式错误反馈迁移

用户于2026-11-10要求把当前已实现的错误提示逻辑适配到最新 feat/3.1.0-beta1。以本会话已确认的五类分类与原错误恢复行为为依据，不重新设计产品。

- AC-01: 已知依赖故障显示数据库、网络、模型服务、单点登录、对象存储之一及对应维护提示，附服务、时间、故障编号。
- AC-02: 真实调用来源跨包装、SSE/WS、保存和历史读取保持一致；供应方内部数据库故障仍属模型服务。
- AC-03: 权限、平台额度、输入和资源业务结果保留原文案；主线 credit_exhausted、context_overflow、context_compress_failed、自动压缩、用户停止保持原处理。
- AC-04: 部分答案、工具成功结果和附件保留；公开提示不带凭据、内部地址、原始堆栈。
- AC-05: 旧数据缺少可靠来源时使用原通用反馈；无数据库升级，无数据回填。
- AC-06: 迁移已落地的通用错误反馈，不迁入中粮知识步骤名称、授权、客户配置或其他定制功能。之前审计的独立OCR/SSO与附件批处理等尚未完成能力不宣称本次已实现。

## 修订（2026-11-12）

用户于 2026-11-12 在 116 测试环境看到深度研究失败卡只显示「灵思Bisheng LLM相关错误」，没有可排查的信息，并要求「查看详情」仍展示 detail。本修订调整 AC-04 的口径，并新增 AC-07、AC-08。

- AC-04（修订）：公开 detail 只含异常类型和消息（外层异常及根因），URL、IP、host:port、凭据值脱敏，长度不超过 500 字符；不含原始堆栈。错误卡把 detail 放在「查看详情」后面。
- AC-07：没有依赖 failure_id 的失败返回 reference_id（优先用当前日志 trace id），错误卡显示为故障标识；有业务错误码的失败不返回 reference_id。
- AC-08：任务模式中未识别（unknown）且异常链不来自模型服务的失败，错误码为 11091（任务执行出现内部错误），不再报 11090；错误卡对 11090/11091 显示按类型的说明，不显示错误码文案。
