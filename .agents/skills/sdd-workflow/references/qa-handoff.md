# 岗位协作与提测规则

## 两个入口

- sdd-workflow：研发交付。需求、设计、开发用例、实施、mock／隔离验证、代码审核、提测交接，随后结束。
- sdd-acceptance：测试工程师的独立验收。可以提前准备验收用例和脚本；研发交付且验收条件具备后，由测试岗位显式组织执行。

全生命周期仍覆盖研发与验收。两岗位分别承担完成责任，不要求同一轮本地 agent 一直运行到验收结束。

## 代码与依据

交接沿用[产物存放与维护约定](artifact-storage.md) 中的稳定特性标识及来源登记。研发产物包的位置不决定 QA 工程的位置，跨工程引用说明仓库／版本／路径或可访问制品。

| 内容 | 位置与维护者 |
|---|---|
| 后端单元、接口、业务功能开发测试 | 对应后端项目/test/，研发维护 |
| 前端非 UI 开发测试 | 对应前端子项目/test/，研发维护 |
| UI、真实集成和 E2E 验收代码 | 测试工程师指定的独立验收工程，测试岗位维护 |
| 需求、业务规则、验收条件和契约 | 共用有效来源，跨工程通过标识和版本关联；正式需求与设计为 HTML |
| 开发与独立验收用例文档 | HTML，按各岗位范围归档并关联同一需求／验收标识；脚本仍使用实际测试语言 |
| 各次执行结果 | 分别保存开发与验收的代码／构建对应关系、环境和证据 |

独立验收工程优先考虑单独仓库，具体地址和技术框架由团队或测试岗位选择；本规则不自动创建仓库，也不固定某台机器的目录。
写验收脚本前确认实际目标工程，遵循该工程配置。未指定工程时，先整理用例和执行准备，不把脚本落到应用 test/ 中。
研发可以提供业务数据规范、契约和场景建议。验收不用开发 mock 去代替需要真实验证的机制，也不默认导入研发私有测试助手；需要复用的版本化协议客户端等应说明版本与边界。
页面验收针对确定构建或部署。若组件 UI 测试需要应用组件，明确所用的版本化产物或源码快照及引用方式，避免依赖某个开发者正在变化的工作区；不为此强制拆出新的组件库。

## 提测材料

优先复用已有产物，以链接和摘要交接，不重新复制一套需求。必要内容包括：

1. 已确认需求、设计、范围和验收条件，以及本次修改与排除项。
2. 能对应到实际内容的提交、补丁、源代码快照或构建标识；未发布的工作区不能仅用旧 HEAD 冒充待测版本。
3. 相关接口／页面入口、契约与必要配置、数据／迁移变化和启用条件。
4. 开发单元、接口及功能测试结果，真实／mock 边界、失败／跳过与对应代码。
5. 需要测试岗位补足的 UI、真实依赖与 E2E 场景、已知风险及最小验收前提。

区分目标版本、实际交付和文档修订。未交付任务延期可沿用标识并更新位置；已交付包保留基线，后续变更／补丁用关联记录说明各版本的代码、差异和证据。提测摘要引用登记中的元数据，不独立维护第二份状态。

配置交代键名和凭据获取方式，不把秘密写进材料。可部署构建、依赖说明和可测试性由研发协作提供；验收脚本与测试数据由测试岗位维护；共享环境的具体提供者按团队实际分工确定，不能假定测试工程师凭空补齐所有环境能力。
跨机器交接使用可访问的需求／代码／构建引用及对应版本，不能只给另一岗位无法访问的个人绝对路径。未授权发布时可先准备源代码快照或补丁，说明实际交付与环境缺口，不把本地材料存在当作对方已经收到。
目标项目已有交接格式时复用；否则可用研发任务产物中的 handoff.md 做简短索引。简单 Bug 的材料可以很短。

交接同时定位相关术语基线、本次已确认概念增量和技术名称映射；测试岗位按待测构建消费这些依据，不使用更新版本定义覆盖历史预期。
交付说明用最小必要的文字或图表达具体变化、前后执行证据、受影响使用方及可逆性。数据、消息等副作用的恢复条件需具体说明；用户授权创建 PR 时复用项目模板与这些来源，不固定为小改动画图，也不把提测材料自动变成 PR 或发布动作。

## 岗位完成条件

研发完成：约定范围实现，所需开发测试通过，代码审核阻塞已处理，提测内容与实际版本对应，待验收项和前提明确。输出后结束研发入口，不自动运行 UI／E2E 或等待 QA。
独立验收完成：测试岗位针对确定版本完成必要场景，真实证据满足范围要求，剩余问题与风险明确，由该岗位负责确认结论。AI 运行报告不是人为签字记录。
材料或环境不足时，分别标记交接缺口、待验收或验收未验证；不混为研发代码必然失败，也不宣称产品已通过验收。

## 缺陷回流

测试岗位报告用例／需求标识、待测版本、环境、复现步骤、预期与实际、必要证据和影响。
研发在自身项目修复，并在对应项目/test/ 补充或复用回归验证；重大需求或设计变化按既定规则重新对齐。
研发交付新的确定版本及修复证据；测试岗位在独立工程定向复测并核对必要回归。环境问题、契约分歧与代码缺陷分别归因。
对外提单、发消息、推送或部署依用户实际授权处理，本规则本身不自动向其他人发送材料。
