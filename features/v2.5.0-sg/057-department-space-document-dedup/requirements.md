# F057 部门知识空间重复文档清理脚本：需求规格

> **状态**：已确认（2026-07-19）  
> **所属版本**：v2.5.0-sg  
> **Feature ID**：F057-department-space-document-dedup  
> **优先级**：P0  
> **Owner**：Knowledge 模块；本特性不新增领域对象所有权

## 1. 背景与目标

公共知识空间与部门知识空间中存在内容完全重复的文档。为减少重复存储、重复索引和维护成本，需要提供一个运维脚本：以公共知识空间的当前有效文档为基准，识别部门知识空间中 MD5 完全相同的当前有效文档，并在显式执行模式下删除部门侧整个逻辑文档及其全部物理版本。

脚本必须把安全预览、执行前重校验、跨存储清理、审计报告和失败重试作为第一等能力。默认运行不得修改任何业务数据。

## 2. 术语与判定口径

| 术语 | 定义 |
|------|------|
| 公共空间 | `knowledge_space_scope.level = 'public'` 的知识空间；是否发布不参与分类 |
| 部门空间 | `knowledge_space_scope.level = 'department'` 的知识空间 |
| 公共见证文档 | 公共空间内满足候选条件、可证明某个 MD5 已存在的当前物理文件 |
| 部门目标文档 | 部门空间内满足候选条件且 MD5 命中至少一个公共见证文档的当前物理文件所代表的删除单元 |
| 当前物理文件 | 已纳入版本模型时，必须是逻辑文档唯一且关系一致的主版本；未纳入版本模型时，指没有任何 `knowledge_document_version` 记录的兼容旧文件 |
| 版本化删除单元 | 一个 `knowledge_document` 及其全部 `knowledge_document_version` 和对应 `knowledge_file` |
| 旧数据删除单元 | 没有版本关系的单个 `knowledge_file` |

候选文件还必须同时满足：

- `file_type = FILE`；文件夹不参与匹配。
- `status = SUCCESS`。
- `md5 IS NOT NULL` 且去除首尾空白后不为空。
- MD5 按数据库保存值精确比较，不转小写、不做模糊匹配、不使用 SimHash。

## 3. 范围

### 3.1 IN

- 扫描当前单租户系统中全部公共空间和全部部门空间。
- 支持通过部门空间 ID、当前文件 ID 和最大处理数量缩小扫描/执行范围。
- 识别公共当前文件与部门当前文件之间的非空 MD5 精确重复。
- 默认 dry-run，只生成确定性的候选与影响报告。
- 显式 `--apply` 后，删除部门侧完整逻辑文档或兼容旧文件。
- 清理目标物理文件拥有的 MySQL 关系、Milvus、Elasticsearch、MinIO 和 OpenFGA 数据。
- 输出机器可读 JSON 报告，记录见证、目标、计划、跳过、完成、失败和待处理项目。
- 支持失败后幂等重跑。

### 3.2 OUT

- 不删除、修改或重新索引公共空间中的任何文件。
- 不删除部门空间中的空文件夹，也不调整文件夹层级。
- 不处理 `team`、`personal` 或缺少有效 scope 的空间。
- 不以文件名、路径、大小、SimHash 或文本相似度作为判重依据。
- 不把历史版本作为公共见证，也不单独删除部门文档的某个历史版本。
- 不提供在线 API、管理页面、定时任务或自动生产执行能力。
- 不新增数据库表、字段、迁移、配置项或第三方依赖。
- 不删除审批、审计等不可变历史记录。
- 不级联删除用户创建的收藏引用副本；这些引用按现有产品语义变为失效引用，并在报告中统计。

## 4. 功能需求

### REQ-001：单租户安全前置检查

脚本必须在访问业务数据前初始化现有应用配置和数据库上下文。若检测到多租户能力已启用，必须拒绝继续并以非零状态退出；不得跨租户扫描。单租户模式下使用项目既有租户上下文机制，不在业务查询中手写租户过滤条件。

### REQ-002：空间集合识别

脚本必须仅依据 `knowledge_space_scope.level` 构建公共空间集合与部门空间集合。`Knowledge.is_released` 或等价发布字段不得影响空间分类。

### REQ-003：当前文件识别

版本化文件只有在以下关系一致时才可作为候选：

- `knowledge_document.primary_version_id` 指向当前版本记录；
- 该版本记录 `is_primary = true`；
- 同一逻辑文档不存在第二个主版本；
- 版本记录指向的物理文件属于该逻辑文档所在知识空间。

没有任何版本记录的物理文件按兼容旧文件处理。存在版本记录但关系损坏、主版本缺失或空间混杂的数据必须跳过并报告，禁止推测后删除。

### REQ-004：重复判定

公共当前文件与部门当前文件仅在非空 MD5 数据库值完全相等时判定为重复。一个部门删除单元即使命中多个公共文件也只能进入计划一次，并保留全部公共见证 ID 供审计。

### REQ-005：dry-run 默认行为

未传入 `--apply` 时，脚本必须：

- 完成扫描、校验、去重和影响分析；
- 输出 JSON 报告及控制台摘要；
- 不初始化或调用任何删除写入器；
- 不修改数据库、缓存、搜索索引、向量库、对象存储或权限系统。

### REQ-006：范围限制

脚本应支持以下可选范围参数：

- `--department-space-id`：可重复指定，仅处理选中的部门空间；
- `--file-id`：可重复指定，仅处理选中的部门当前文件；
- `--limit`：按稳定排序截取最多 N 个删除单元；
- `--report-dir`：指定报告目录；默认 `migration_reports/knowledge_file_dedup`。
- `--resume-report`：与 `--apply` 配合，只恢复既有 apply 报告中已记录的失败/待处理步骤。

范围参数只能收窄部门目标集合，不能改变公共见证集合，也不能允许处理公共文件。

### REQ-007：执行前漂移校验

`--apply` 模式必须在每个删除单元开始前从数据库重新读取并校验：

- 公共见证仍存在且仍满足候选条件；
- 目标空间仍为部门空间；
- 目标当前文件仍为成功文件且 MD5 未变化；
- 逻辑文档、主版本和全版本图与计划一致；
- 目标物理文件均属于同一部门空间。

任一条件不一致时，该单元必须以明确原因跳过，不得沿用过期 dry-run 结果。

### REQ-008：部门版本链删除

版本化部门目标必须删除整个逻辑文档，包括所有历史物理版本；旧数据目标仅删除目标物理文件。历史版本自身不需要与公共文件重复。公共见证和公共版本链不得进入删除集合。

### REQ-009：外部存储清理

每个目标物理文件必须清理：

- Milvus 中以文件/文档 ID 标识的向量数据；
- Elasticsearch 中以文件/文档 ID 标识的索引数据；
- MinIO 中该物理文件拥有的原始文件、转换文件、预览、bbox 和其他既有派生对象；
- OpenFGA 中以 `knowledge_file` 为资源的权限元组。

删除必须使用目标文件自身保存的对象标识，禁止根据公共见证推导或删除公共对象。

### REQ-010：关系数据清理与保留

数据库事务必须删除目标拥有的活动关系：

- 普通标签关联与审核标签关联；
- 文件级分享链接；
- 相似度候选表中目标作为 source 或 candidate 的记录；
- 门户推荐文件投影；
- 文档版本记录、逻辑文档和物理文件记录。

收藏引用、审批历史、审计历史等非目标所有的用户/历史记录不得级联删除。报告必须给出已识别的受影响收藏引用数量。

### REQ-011：执行顺序与失败语义

每个删除单元必须独立处理。脚本应先完成快照和重校验，再清理外部资源，最后在数据库事务中删除关系和主记录。任一步失败时：

- 当前单元标记为失败；
- 不再启动后续删除单元；
- 已完成单元不回滚；
- 未开始单元标记为 pending；
- 进程返回非零状态；
- 报告保存足以支持同参数重试的信息。

### REQ-012：幂等性

重复运行不得误删公共数据或其他部门文档。已完整删除的单元应自然不再进入候选；外部对象已不存在应视为幂等成功。部分失败重跑时，应根据仍存在的数据库快照继续完成剩余清理。

若数据库主记录已提交删除，仅允许通过 `--resume-report` 重试报告明确记录的提交后缓存失效和验证步骤。恢复模式不得把报告当作新增删除授权，不得仅凭报告 ID 删除数据库或外部资源；报告格式、模式、状态和目标边界不合法时必须拒绝恢复。

### REQ-013：报告

每次运行必须生成唯一报告，至少包括：

- 格式版本、运行 ID、开始/结束时间、运行模式和参数；
- 单租户前置检查结果和空间统计；
- 公共候选、部门候选、空 MD5 跳过和异常版本图统计；
- 每个删除单元的空间、当前文件、逻辑文档、全部版本/物理文件、MD5 和公共见证 ID；
- 各类关系与外部资源影响计数；
- 每个执行步骤的状态、错误类型和可重试性；
- completed、failed、skipped、pending 总数；
- 运行后公共见证完整性和目标残留校验结果。

报告不得包含文件正文、对象存储凭证、访问令牌或其他秘密。

### REQ-014：退出码和可观测性

- `0`：dry-run 成功，或 apply 全部计划单元成功/安全跳过；
- `2`：参数或安全前置检查失败；
- `3`：扫描或计划生成失败；
- `4`：apply 中至少一个删除单元失败；
- `5`：报告初始化/持久化失败，因而未安全进入或完成执行。

日志必须带运行 ID、删除单元 ID、空间 ID 和文件 ID，不记录文件内容或秘密。

### REQ-015：执行后验证

apply 成功的每个单元必须验证：

- 目标逻辑文档、版本行、物理文件和规定的活动关系已不存在；
- Milvus、Elasticsearch 和 MinIO 不再存在目标资源；
- 公共见证仍存在且候选属性未被修改；
- 验证失败按 apply 失败处理并返回非零状态。

## 5. 验收标准

| ID | 操作 | 预期结果 | 关联需求 |
|----|------|----------|----------|
| AC-01 | 在无参数模式运行脚本 | 只生成 dry-run 报告，所有写入后端调用次数为 0 | REQ-005, REQ-013 |
| AC-02 | 公共空间发布状态为任意值但 scope 为 public | 其中符合条件的当前文件均可作为见证 | REQ-002 |
| AC-03 | 部门当前成功文件的非空 MD5 与公共当前文件完全相同 | 部门文档进入删除计划并记录全部公共见证 | REQ-003, REQ-004 |
| AC-04 | MD5 为空、仅空白、大小写不同或只有 SimHash 相似 | 不判重；空值单独计入跳过统计 | REQ-004, REQ-013 |
| AC-05 | 公共历史版本与部门当前版本 MD5 相同，但公共当前版本不同 | 部门文档不进入计划 | REQ-003, REQ-004 |
| AC-06 | 部门当前版本命中公共见证且本逻辑文档有多个历史版本 | apply 删除整个部门版本链及全部物理资源 | REQ-008, REQ-009, REQ-010 |
| AC-07 | 文件没有任何版本记录且命中公共见证 | 按兼容旧文件单元预览或删除 | REQ-003, REQ-008 |
| AC-08 | 版本图主版本不一致、缺失或跨空间 | 安全跳过并报告，不删除任何关联数据 | REQ-003, REQ-007 |
| AC-09 | 一个部门文档命中多个公共见证 | 删除计划只有一个单元，报告保留所有见证 | REQ-004 |
| AC-10 | 通过范围参数执行 | 仅收窄部门目标；公共见证集合仍完整，公共数据不受影响 | REQ-006 |
| AC-11 | dry-run 后目标状态、MD5、scope 或版本链发生变化 | apply 重校验后跳过该单元 | REQ-007 |
| AC-12 | apply 成功 | 目标 MySQL 关系、Milvus、ES、MinIO、OpenFGA 数据清理完成，公共文件仍存在 | REQ-009, REQ-010, REQ-015 |
| AC-13 | 目标存在分享链接、推荐投影和相似度候选 | 这些活动关系被删除 | REQ-010 |
| AC-14 | 目标存在收藏引用或审计历史 | 记录被保留，收藏影响数量进入报告 | REQ-010, REQ-013 |
| AC-15 | 中途外部系统删除失败 | 当前单元失败、后续单元 pending、退出码为 4，报告可用于重试 | REQ-011, REQ-014 |
| AC-16 | 外部对象已不存在后重跑，或提交后步骤通过原 apply 报告恢复 | 已存在数据库元数据时幂等完成清理；已提交删除时只重试受限的提交后步骤 | REQ-012 |
| AC-17 | 检测到多租户启用 | 不扫描、不删除，退出码为 2 | REQ-001, REQ-014 |
| AC-18 | apply 后目标仍有规定资源残留 | 验证失败并返回非零状态 | REQ-015 |

## 6. 非功能要求

- **安全**：默认 dry-run；公共资源加入不可删除断言；apply 前重校验；秘密不进入报告。
- **确定性**：按部门空间 ID、逻辑文档/文件 ID 稳定排序；相同数据库快照和参数产生相同计划顺序。
- **性能**：公共 MD5 构建索引后，部门候选按批读取；不得为每个候选重复全表扫描。
- **兼容性**：查询与删除应兼容 MySQL 和 DM8；不使用数据库方言专有 JSON 查询。
- **可维护性**：使用 `argparse`、类型标注、模块说明文档；从 `src/backend/` 可直接运行。
- **可测试性**：扫描/计划层与执行写入层分离；dry-run 测试可证明未构造写入器。

## 7. 约束与假设

- 真实 apply 应安排在维护窗口，避免上传、换版和移动文档并发发生。
- MD5 精确相等是业务确认的重复判据；本特性不附加内容二次校验。
- 跨系统删除不具备全局原子性，失败恢复依赖数据库快照、执行报告和幂等重跑。
- `features/` 当前被 Git 忽略；后续如需纳入提交，必须显式确认并使用精确路径暂存。
