# Feature: F052 工作流会话打开时自动重新运行

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> 本文只定义业务范围与验收标准；实现方案、配置字段、接口与文件清单在设计确认后记录于
> [design.md](./design.md)。

**关联 PRD**: 用户需求（2026-08-27）
**优先级**: P1
**所属版本**: v3.0.0-beta1
**依赖**: 既有工作流独立会话与手动重新运行能力

> **范围边界**
> - **本次纳入**：
>   - 系统级统一开关，控制所有工作流独立会话的自动重新运行行为。
>   - 免登录与需登录页面的首次进入，以及两类页面的历史会话切换。
>   - 打开目标会话时的一次性状态判断与至多一次自动重新运行。
> - **本次明确排除**：
>   - 不提供工作流级、用户级或会话级开关。
>   - 不在会话打开后持续监听、自动重试或恢复后续中断。
>   - 不改变手动“重新运行”功能。
>   - 不作用于助手会话、应用中心会话、工作流编排调试页或 API 调用。

---

## 1. 用户故事

作为 **工作流独立会话的访问者**，
我希望 **打开一个已经结束的会话时，系统能按统一配置自动重新运行一次**，
以便 **无需额外点击即可重新获得该工作流的最新执行结果**。

作为 **系统管理员或运维人员**，
我希望 **通过一个系统级开关统一启停此行为**，
以便 **对全系统工作流采用一致策略并保持存量行为可控**。

---

## 2. 验收标准

| ID | 角色 | 操作 | 预期结果 |
|----|------|------|---------|
| AC-01 | 管理员/运维人员 | 未配置或关闭统一开关 | 所有工作流会话保持现有行为，不发生自动重新运行 |
| AC-02 | 管理员/运维人员 | 开启统一开关 | 系统内所有工作流独立会话统一启用本功能，无需逐工作流配置 |
| AC-03 | 免登录访问者 | 首次进入免登录工作流页面，目标会话已结束 | 系统在该次打开过程中自动重新运行一次 |
| AC-04 | 登录访问者 | 首次进入需登录工作流页面，目标会话已结束 | 系统在该次打开过程中自动重新运行一次 |
| AC-05 | 免登录访问者 | 从本地历史会话列表切换到一个已结束的会话 | 系统在该次打开过程中自动重新运行一次 |
| AC-06 | 登录访问者 | 从服务端历史会话列表切换到一个已结束的会话 | 系统在该次打开过程中自动重新运行一次 |
| AC-07 | 任一访问者 | 打开仍在运行或等待用户输入的工作流会话 | 系统恢复现有会话状态，不重新运行 |
| AC-08 | 任一访问者 | 会话因正常完成、执行失败、用户手动终止、断网或其他原因在打开后结束或中断 | 系统不在当前打开过程中再次自动重新运行 |
| AC-09 | 任一访问者 | 同一次会话打开过程中收到重复状态事件或界面重复渲染 | 自动重新运行至多触发一次 |
| AC-10 | 任一访问者 | 离开后再次进入该会话，或切走后再次切回该会话 | 视为新的打开行为；若此时会话已结束，则可再次自动重新运行一次 |
| AC-11 | 任一访问者 | 打开没有历史执行的新会话 | 沿用现有首次运行行为，不额外重复触发重新运行 |
| AC-12 | 任一访问者 | 自动重新运行条件满足 | 自动行为与现有手动“重新运行”具有相同的会话目标和用户可见结果 |
| AC-13 | 助手、应用中心或编排调试页用户 | 进入或切换会话 | 本功能不改变这些页面的运行行为 |

---

## 3. 边界情况

- 系统配置缺失、无效或无法识别时，按关闭处理，避免存量环境意外自动执行。
- 会话状态尚未判定时不得提前重新运行；只有确认打开时已经结束才允许触发。
- 自动重新运行正在触发时，重复状态通知、重复渲染或连接重建不得产生第二次运行。
- 用户切换到另一个会话后，前一会话迟到的状态结果不得触发当前会话或前一会话的自动重新运行。
- 自动重新运行失败后不得自动重试；用户仍可使用既有手动操作处理。
