SDD 修复：审计、可信身份与异常恢复

本轮复用 8 张表和 26 个 HTTP 接口。客户端 0.4.0 的 7 个接口保持冻结；内部身份 DTO、平台管理 policy 保存和 operations 查询有补充，两仓按 Design 同步实现。

共享模型：模型业务认可的租户自有或合法 Root 共享范围，与用户 DSH 授权取交集；取消共享后新调用拒绝。Spec AC-18/21/30 已统一。

策略审计：UPDATE_POLICY 以 operation_id 串行编排，策略和前后值/版本/actor 同事务提交；committed_at 与 effective_at 区分提交和生效。查询 operations 返回 phase、before/after 和结果；故障恢复同一操作，不覆盖历史。

身份显示：redeem/check 共用 DshIdentitySnapshot；首次换证与每次刷新返回当前可信 user/tenant。display_name 空时回退 username，租户名称空时回退 Tenant <tenant.id>；无有效账号或身份服务失败不签发成功凭据。

UNKNOWN：拟建 DshReconciliationService 和 python -m bisheng.dsh.cli.reconcile 受控命令。真实管理员鉴权后，以逐请求证据、expected_event_version 和 operation_id 登记 RECONCILE_USAGE，复用 Lua/Stream/SQL 投影幂等结算；证据存受控 MinIO，命令不直改账本。

未知用量只记录 USAGE_UNKNOWN 明细，token字段为NULL；不冻结用户或模型。补记为可选审计操作，策略变更和账本故障保护独立保留。

完整字段、CLI 输入、幂等和故障恢复步骤见 Design §4.5.5、§4.7.4、§6.1；复核结果见 设计评审报告。生产恢复入口和故障验收见 配额运维与恢复报告；外部环境门禁仍需关闭。

请求示例与响应约定

config 在关闭时仅返回 enabled=false，不公开内部地址或 Secret；Token 使用共享 HMAC 派生的 HS256；JWKS 仅保留空 keys 兼容响应，不发布密钥。License 保留旧配置项、加密外层和 trial/pro 字段；DSH 以可选签名扩展接入，扩展缺失或失效不改变旧商业能力，旧 pro 不代表 DSH 无限席位。旧商业期满与 DSH 到期独立判定；旧 trial 期满但外层可解析且 DSH 授权有效时，DSH 可独立验权，旧 SSO 不延期。外层无法解析则 DSH 拒绝；四种有效期组合见 Design §4.5.4。

PKCE 固定 S256；内部兑换须比对 client_id、redirect_uri、code_challenge 与票据绑定记录，再原子消费。管理聚合失败标记 unavailable，不显示成 0 席。

票据换证 · POST /api/dsh/token

{
  "grant_type": "identity_ticket",
  "auth_id": "<本次授权事务>",
  "identity_ticket": "<一次性票据>",
  "code_verifier": "<本机生成的 PKCE verifier>"
}

刷新时 grant_type=refresh_token，提交 refresh_token；成功后两个凭证均由 Gateway 返回，刷新凭证每次轮换。同会话串行刷新，回包丢失不重放旧凭证。7 个客户端接口使用裸 JSON（logout 为 204）；浏览器 authorize 与管理接口沿用统一响应。

完成入账用户总量与模型分量原子累加实际 usage达到或超过阈值后拒绝新请求；在途继续完成，超额如实记录
批量 SQL最多 500 事件或 5 秒一批，按 request_id 合并，每月行每批一次更新event_version 完整快照去重；明细/汇总同事务，提交后 XACK
策略变更冻结准入 → SQL PENDING → Redis 安装 → SQL READY → 解冻成功后立即生效；失败保持冻结，不靠最终一致广播
写入成本减少事务、往返和热点汇总行更新审计明细仍随请求增长，不承诺 MySQL 零写入或未经压测的吞吐

并发示例：限额 1000，已用 900

A / B 准入均看到 900 < 1000，全部放行，不预扣
A 完成 +300已用 1200 → 拒绝此后的新请求
B 完成 +300在途继续，最终如实记录 1500

取消输入上界估算和额度归还；不按剩余额度限制模型输出，不因达限中断已准入的 SSE。超额取决于在途数量与实际用量，不承诺固定上界，也不新增并发限流。

异常时不拿旧余额继续放行

异常处理
usage 缺失 / 断流无法计量token字段=NULL、USAGE_UNKNOWN，保留调用明细及缺失原因；不冻结用户或模型。成功回答正常返回，缺usage的SSE仍发送DONE；实际断流保留上游错误。可靠补记可选，不是继续调用的前提。
SQL/消费者中断Stream 保留 pending，恢复后幂等重放；积压超过 30 秒或容量阈值停止新准入并预留在途结算空间，不丢未确认事件。
Redis key 丢失 / 断连 / OOM失败关闭；不能从旧 SQL 取零或剩余额度放行。Lua 运行错误也不自动回滚，脚本先校验，异常冻结排查。
重启 / 主从切换门禁绑定批准的主节点/恢复代次，先阻断并隔离旧主，再核对 AOF/Stream + SQL + 在途请求；证明完整、提高 epoch 后才能开放。
丢失已确认事件无法证明完整则冻结受影响月份/分片、人工核账，不承诺无损自动恢复。AOF、副本和 WAIT 不等于任意故障下的强一致。

额度区独立 noeviction、持久化，不使用普通缓存 TTL；同槽脚本同时登记事件，不用 Pub/Sub 或进程内异步任务。/usage 读 live，SQL 降级展示标 persisted + as_of。

待验证：5 万席位、50/100 条分页与执行计划；1000 请求/秒下原子计数、批次大小、SQL 事务量、投影延迟；跨模型并发、丢尾/主切换、重复乱序事件及策略冻结恢复。此处不是压测结论。

参考：Redis 复制一致性边界。若要求故障后无损且持续可用，需要另评审同步持久化日志或数据库逐请求准入。

配额维护：默认内存预算 512 MiB、结算余量 64 MiB；10,000 条或 30 秒积压停止新准入。RUNNING 索引与实时 usage 门禁一致；投影每批 500 条，单用户 10 批或 1 秒后让出。只清理 SQL 精确确认、全部消费组 ACK 且保留 30 天的可靠终态。恢复顺序为 FROZEN 回执 → SQL epoch CAS → owner/digest/epoch/version CAS READY。详见 Design §4.7；生产容量待压测。

部署 dsh.enabled 默认关闭，决定管理界面可见性；管理界面的业务开关默认关闭，决定整个 DSH 功能能否使用。两者均开启才能登录和调用模型。

业务关闭后隐藏模型开放范围和 DSH 用户入口，服务端拒绝新授权、身份换证校验与模型转发。保留席位、令牌、额度与历史用量，在途结算和后台投影继续。
