# Feature: 托管应用入口理顺与桌面专用通道下线

**关联 PRD**: 《云端工作台改版 —— 需求文档：入口理顺 + 发布流程收成一条》v1.0（2026-11-20，产品方向已与需求方逐项确认）；发布流程以平台自带的《托管应用部署教程》为准；背景见 [docs/PRD/3.0-release/3.0 应用工场 PRD-1 专业开发者通道与应用运行时.md](../../../docs/PRD/3.0-release/3.0%20应用工场%20PRD-1%20专业开发者通道与应用运行时.md)

**所属版本**: v3.1.0-alpha1
**依赖**: v3.0.0 F054（托管应用领域与运行时）、F055（发布管线）、F056（应用广场）；撤销 v3.0.0 F130（云端工作台）中的桌面专用部分

> **范围边界**
> - **本次纳入**：
>   - 员工端「应用」（最近使用）和「发现广场」：托管应用、助手、工作流按类型区分展示，并能按类型分类
>   - 去掉员工端单独的「云端工作台」页面及其入口链接，旧地址可达
>   - 管理后台：去掉构建页跳员工端的「云端工作台」链接；「应用模板」页的托管应用卡片改为先看说明
>   - 下线桌面专用的发布、源码下载、一次性访问票据通道，以及面向 Agent 的「云端工作台」规范与协作样例
>   - 继续给桌面客户端提供托管应用列表；已发版的旧客户端走到已下线能力时得到明确提示
> - **本次明确排除**：
>   - 托管应用平台本身：运行环境、发布管线、审批、构建页详情页、命令行与技能包、平台教程页——不改
>   - 改名：网页、管理后台、教程里的「托管应用」名称都不改；代码里的类型名、表名、接口名不改
>   - 员工自助申请平台密钥——不做，仍由管理员签发
>   - 发布后的授权方式——不改，仍在构建页卡片的「管理权限」里授权
>   - 桌面客户端本身的界面和逻辑（「制作我的工作台」、「云端工作台」标签、在客户端内打开）——在 bisheng-desktop 配套交付，本仓库只提供它依赖的服务端行为
>   - SDK 0.1.2 已发布的协作模块——不删，只是不再在规范里推荐

## 1. 用户故事

- **A. 员工（用应用的人）**：作为员工，我希望在「应用」和「发现广场」里一眼分清哪个是托管应用、哪个是助手和工作流，并能只看某一类，以便快速找到要用的应用。
- **B. 发布者（会用 AI 编程工具的员工）**：作为发布者，我希望只有一条清楚的发布路（拿平台密钥、用命令行部署、等审批、授权给同事），并在新建应用时能先看懂托管应用是什么、要准备什么，以便不走弯路。
- **C. 管理员**：作为管理员，我希望管理后台只放管理用的入口，不出现跳到员工端的链接，以便后台和员工端分工清楚。
- **D. 桌面客户端（配套，bisheng-desktop）**：作为桌面客户端，我需要继续拿到员工能用的托管应用列表，并能用员工在客户端里已登录的网页身份打开托管应用，以便不再依赖单独的桌面票据和会话。

## 2. 验收标准

### 2.1 员工端「应用」与「发现广场」

- **AC-01** — THE SYSTEM SHALL 在「应用」（最近使用）和「发现广场」两个页面里，用同一种卡片展示托管应用、助手、工作流，并在每张卡片右上角显示类型标签「托管应用」「助手」「工作流」之一；类型标签不遮挡卡片上已有的置顶、更多按钮。
- **AC-02** — THE SYSTEM SHALL 在「应用」和「发现广场」两个页面提供类型分类，选项依次为「全部类型」「托管应用」「助手」「工作流」，默认「全部类型」。
- **AC-03** — WHEN 员工在「发现广场」同时选择了标签分类、类型分类并输入了搜索词, THE SYSTEM SHALL 只展示同时满足这三个条件的应用。
- **AC-04** — WHERE 当前环境没有启用托管应用运行环境, THE SYSTEM SHALL 在两个页面的类型分类里都不出现「托管应用」这一项。
- **AC-05** — IF 所选类型下没有应用, THEN THE SYSTEM SHALL 显示空列表样式并提示「这个类型下还没有应用」。
- **AC-06** — THE SYSTEM SHALL 不再在「应用」页提供「云端工作台」链接，也不再提供单独的云端工作台页面。
- **AC-07** — WHEN 员工访问原来云端工作台页面的地址, THE SYSTEM SHALL 跳转到「应用」页，不出现 404。
- **AC-08** — WHEN 员工在浏览器里点击托管应用卡片, THE SYSTEM SHALL 在新标签页打开该应用，并把它记入「应用」（最近使用）。（沿用现有行为）
- **AC-09** — WHEN 员工在桌面客户端内嵌的网页里点击托管应用卡片, THE SYSTEM SHALL 在客户端内打开该应用、不交给系统浏览器，并能返回原来的列表。
- **AC-10** — THE SYSTEM SHALL 在桌面客户端内嵌的「应用」「发现广场」里，提供与浏览器中一致的类型标签和类型分类。

### 2.2 管理后台

- **AC-11** — THE SYSTEM SHALL 不再在「构建 → 应用」列表里提供跳转到员工端「云端工作台」的链接；托管应用的管理（列表、筛选、详情页）不变。
- **AC-12** — WHEN 管理员在「应用模板」页点击「托管应用」卡片, THE SYSTEM SHALL 把该卡片置为选中，并在右侧显示托管应用说明，不直接打开新标签页。说明包含：托管应用是什么；和工作流、助手的区别；需要准备的东西（一个 AI 编程工具、管理员签发的平台密钥）；五个步骤（安装并登录命令行、描述应用并在本机运行、部署、等管理员审批后自动上线、在「构建 → 应用」里授权给同事）；「看部署教程」按钮。
- **AC-13** — WHILE「应用模板」页选中的是托管应用, THE SYSTEM SHALL 把模板搜索框置为不可用。
- **AC-14** — WHEN 管理员点击说明里的「看部署教程」, THE SYSTEM SHALL 在新标签页打开平台自带的部署教程页。
- **AC-15** — WHERE 当前环境没有启用托管应用运行环境, THE SYSTEM SHALL 在托管应用说明顶部显示现有的「运行环境未启用」提示；托管应用卡片和「看部署教程」仍然可用。
- **AC-16** — THE SYSTEM SHALL 把「应用模板」页托管应用卡片的说明改为「本地写代码，部署到平台，同事登录就能用」、链接文字改为「了解怎么做」；卡片标题「托管应用」以及后台其余位置的「托管应用」名称不变。

### 2.3 发布与桌面专用通道

- **AC-17** — THE SYSTEM SHALL 只通过既有发布管线接收托管应用的发布（平台密钥 + 命令行部署，或构建页应用详情页）；不再提供桌面客户端专用的发布、发布进度查询和源码下载能力。
- **AC-18** — THE SYSTEM SHALL 不再签发桌面专用的一次性访问票据，也不再维护对应的桌面访问会话。
- **AC-19** — IF 已发版的旧客户端（1.3.0）请求打开托管应用、发布或下载源码等已下线的能力, THEN THE SYSTEM SHALL 返回明确的错误，提示把客户端升级到 1.3.1 或以上。
- **AC-20** — THE SYSTEM SHALL 继续向桌面客户端（含 1.3.0）提供员工可用的托管应用列表，返回内容与原来一致，并额外告知当前环境是否启用了托管应用运行环境。
- **AC-21** — WHEN 用户携带已登录的网页身份访问托管应用入口, THE SYSTEM SHALL 按该用户对该应用的使用权限放行或拒绝（沿用现有网页登录复用）。桌面客户端用内嵌网页的登录身份打开托管应用时，适用同一规则。
- **AC-22** — THE SYSTEM SHALL 让员工在网页发现广场、「应用」页和桌面客户端列表中看到的托管应用来自同一范围：同租户、本人可见；网页两个页面里已下线的托管应用显示「已下线」且不能打开，桌面列表只列已上线的；草稿和已删除的都不出现（release-contract INV-2）。
- **AC-23** — THE SYSTEM SHALL 不再对外提供面向 Agent 的「云端工作台」在线规范和协作样例；平台部署教程页、命令行和技能包照常提供。
- **AC-24** — THE SYSTEM SHALL 继续提供 SDK 0.1.1 和 0.1.2 的下载与校验，已经引用 SDK 协作模块的应用照常构建。
- **AC-25** — THE SYSTEM SHALL 保持已上线托管应用的访问、数据、版本和权限不受本次改动影响，不论它们当初经由哪条路径发布。

## 3. 边界情况

- 当员工收藏了旧的云端工作台页面地址时，访问后应落在「应用」页（AC-07）。
- 当已发版的 1.3.0 客户端仍在使用时：列表照常显示（AC-20），点打开、发布、下载源码时得到「请升级客户端」的明确错误（AC-19），其余功能不受影响。
- 当托管应用已下线时：网页卡片照常显示「已下线」，点击不打开（沿用现有行为）；桌面列表不列出（AC-22）。
- 当员工没有登录、或登录已过期时访问托管应用入口：沿用现有的登录引导和兜底页（AC-21）。
- 当环境没有启用托管应用运行环境时：员工端类型分类不出现「托管应用」（AC-04），管理后台说明页给出提示（AC-15），桌面客户端从列表结果得知未启用（AC-20）。
- 当某个托管应用当初是经由已下线的桌面通道发布的：它和其他托管应用一样照常使用（AC-25）。
