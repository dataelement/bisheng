## 下一批 · Workflow 对外运行控制

覆盖原设计的运行状态与事件、取消运行两项接口。现有反向运行已保存固定版本、原实际用户、接入方、状态和结果。原生文本表单已保存等待点及答复回执。可沿用现有运行记录、授权入口和 Worker 领取流程，在同一 `session_id` 上扩展行为。普通 Agent 长任务的停止与迟到结果隔离已有本地证据，可复用其裁决语义。反向调用与浏览器运行使用各自的执行记录。[运行控制规格](../../../features/v3.0.0/127-kunlian-workflow-run-control/spec.md) · [运行控制设计](../../../features/v3.0.0/127-kunlian-workflow-run-control/design.md) · [反向运行规格](../../../features/v3.0.0/122-kunlian-workflow-invocation/spec.md) · [原生交互规格](../../../features/v3.0.0/123-kunlian-workflow-interaction/spec.md) · [反向运行服务](../../../src/backend/bisheng/workflow/application/kunlian_workflow_invocation.py) · [反向运行 Worker](../../../src/backend/bisheng/worker/workflow/kunlian_workflow_run.py)

**首批范围。** 用固定版本的纯文本 Workflow 与单次原生文本输入 Workflow 做 Mock。先验证排队、运行、等待输入和待恢复阶段的取消。用可控节点模拟执行中断点，验证取消后不会启动下一节点或提交迟到输出。已发生的外部动作与远端取消终态单独处理，首批样例避免外部写操作。远端 Agent 取消复用已有语义，实际绑定接线待双向嵌套范围和正式合同确认。

## 已验证的 4D 规格范围

以「开始 → 平台 Agent（异步、固定 V1）→ 输出 → 结束」为首轮范围。检查点的持久化方式、领取机制及运行入口见[长任务恢复设计](../../../features/v3.0.0/126-kunlian-agent-long-task-resume/design.md)。

1. **挂起并释放执行槽。** Worker A 启动 Mock Agent，保存原 Workflow 执行、节点上下文、Agent Run、固定版本及截止时间。Agent 保持运行中时，验证同一执行队列只有一个执行槽的 Worker 仍能处理另一条任务。
2. **换 Worker 恢复。** 结束 Worker A，由 Worker B 从持久状态领取，查询原 Run，校验结果并从原节点继续。核对远端只启动一次、前序节点不重跑、下游只输出一次。重复派发、领取者失效和漏投补偿用隔离进程验证。
3. **停止与超时。** 等待期间停止或到期，停止意图可补投，取消受理与最终取消状态分别记录。迟到结果不能触发下游。回归 F119 同步调用、F123 原生输入及 F125 单文本表单恢复。

4D 首轮使用固定 Mock Agent、真实的本地队列与独立 Worker 证明释放和接管。正式运行接口继续待昆联确认。通用图恢复、多轮表单、SSE／回调及对外 Session 取消分别保留在后续批次。

### 批次 4 · 人工输入、长任务与取消

批次 4 拆成三个可以独立验收的工作包。4A 和 4B 已提供 4C 所需的交互语义和远端运行关联。正式字段、权限映射、等待时限和页面行为待双方确认。

| 顺序 | 工作包 | 开发和验收出口 | 对接条件 |
| --- | --- | --- | --- |
| 4A | **毕昇 Workflow 人工输入与恢复** | 首轮一处文本表单。昆联提交固定版本运行，轮询得到等待状态、交互标识及表单。原实际用户稍后补交输入，毕昇在原会话和版本继续执行，昆联轮询取得结果。 | 本地先用 Mock。正式联调确认昆联如何展示表单、传递实际用户，以及表单协议、等待和重试窗口。 |
| 4B | **昆联 Agent 异步运行与取消** | 毕昇启动固定 Agent 版本并保留 Agent Run ID。按运行标识查状态、进度摘要及结果，区分取消已受理和已取消。覆盖结果未知、重复启动、重复取消、迟到结果和已经终态的取消。 | 待确认昆联异步启动、状态查询、取消和幂等契约，需提供 Mock 样例和真实接口材料。 |
| 4C | **昆联 Agent 等待人工输入** | 远端 Agent 等待时，由毕昇转交表单和交互标识。用户提交后继续原 Agent Run 和原 Workflow 会话，并把最终结果交给下游节点。 | 基于 4B 的远端运行事实，复用 4A 已验证的交互语义。待确认远端表单、交互提交、重复提交与状态收敛规则。 |

**4A 的验收边界**

1. **等待与查询**。走「开始 → 文本输入 → 输出 → 结束」。首次调用返回 `session_id`，查询能识别当前等待项和表单。原请求断开后，后续查询仍能找到等待项。
2. **提交与去重**。提交必须匹配当前交互。同一提交重试只恢复一次，改答案重试、提交过期交互或输入不符时给出明确结果。首次提交、查询、交互提交和 Worker 恢复都沿用 F122 的实际用户、接入方、租户和 Workflow 使用权边界。
3. **固定版本恢复**。等待期间发布 V2 或下线 V1，已受理会话仍按 V1 恢复。设计阶段先验证另一 Worker 能否从保存的等待点继续。Mock 验收要更换执行实例，核对等待状态和节点上下文都能恢复。恢复失败或等待超时应有可查询的终态。
4. **兼容回归**。保留 F122 的预置输入和无交互结果查询路径。首轮采用轮询，远端 Agent、取消、事件订阅及多轮交互排入后续工作包。

4A 在 F122 固定版本执行的基础上，保存了原生输入节点的等待点，并在隔离环境验证了跨 Worker 恢复。正式契约与真实环境验收继续按 F123 的任务记录推进。[4A 验证记录](../../../features/v3.0.0/123-kunlian-workflow-interaction/verification.md)

### 下一批需求发现 · 4C 昆联 Agent 等待人工输入

首轮拟在毕昇有会话的运行页走一条线性流程「开始 → 平台 Agent → 输出 → 结束」。使用固定版本的 Mock Agent，在同一次运行中暂停一次，只展示一个必填文本字段。用户断线后可回到原会话查看表单。提交后继续轮询原 Agent Run，取得结果后从同一节点恢复原 Workflow，下游只消费一次输出。

| 开发批次 | 拟开发内容 | Mock 验收 |
| --- | --- | --- |
| 1. 等待与重连 | 复用 4B 的固定版本、Run 关联和轮询。识别显式启用交互的 Agent 返回的 `WAITING_INPUT`，保存可信交互标识、表单及等待期限，接入现有会话状态入口与文本表单组件。 | 刷新或断线重连后显示同一表单，保留原 Workflow 执行 ID、Agent Run ID 和交互 ID。等待期间下游保持暂停。 |
| 2. 提交与续跑 | 沿用 4A 的表单校验、归属检查与幂等规则，把答案提交给原远端交互。首轮验证原 Worker 退出后，另一 Worker 能从 Agent 节点等待点继续。 | 只有原运行用户且当前仍有权时才能提交。同一答案重试收敛为同一次有效提交，改答案重试、旧交互或其他用户被拒绝。恢复时启动、暂停前节点和下游输出各只执行一次。 |
| 3. 停止与失败收敛 | 复用 4B 停止和取消。区分交互等待截止、提交回执未知和提交后的结果等待；在有界窗口内按原关联查回。 | 覆盖停止与提交竞争、过期表单、撤权和提交响应丢失。停止或超时后，迟到的结果只能用于核对，不能恢复下游。保留同步 Agent、普通异步 Agent 和 4A 原生交互回归。 |

### 原首批平台 Agent 的范围

1. 毕昇后端接入昆联资源查询，返回当前编辑者有权使用的 Agent 和可用版本；前端支持选择和重新打开配置。
2. 新增平台 Agent 节点，依据输入输出 Schema 配置常量和上游变量，向下游暴露结构化输出。
3. 保存和试运行时校验参数，发布时复核版本、权限和映射，并固定 Agent 版本及 Schema。并发编辑时确保发布内容与校验内容一致。
4. Worker 以实际运行用户和可信租户调用 invoke。优先确认能否复用现有 SSO Access Token，同时处理排队后 Token 过期的情况。
5. 校验响应版本及输出结构，接入既有节点事件和运行日志，关联 Workflow Session、节点执行与 Agent Run。
6. 明确鉴权拒绝、版本停用、输入错误、上游失败和超时的结果。按双方确认的幂等规则处理重复请求及结果未知。
7. 提供本地契约样例、最小示例流程和定向测试；取得昆联环境后执行真实双系统验收。

平台 Agent 节点采用独立类型。项目入口的节点展示及历史 Agent 配置处理方式另行确认后进入规格。首批验收至少覆盖成功输出、A 发布／B 运行、无权或跨租户拒绝、版本固定及超时结果未知。
