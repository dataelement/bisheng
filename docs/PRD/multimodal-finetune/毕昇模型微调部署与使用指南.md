# 毕昇模型微调安装与使用指南

版本 V2.1（3.1 beta1 开发分支）

日期 2026年11月17日

本指南帮助第一次使用模型微调的企业用户，完成训练服务安装、模型准备、平台接入、训练任务创建和结果验证。支持文本、图文及视频画面输入，训练方法为 LoRA。

服务器管理员先完成第1至4章；平台使用者从第5章开始。当前版本的模型微调操作需要使用平台超级管理员或当前租户管理员账号。已经接入服务后，使用者不需要安装 Docker、下载模型或登录服务器。

本指南对应随文档交付的毕昇前后端与 bisheng-ft 多模态功能版本。使用旧版毕昇或旧版 FT 时，页面与接口可能不同，应先由交付人员安装配套版本。本分支包含本地、FTP/FTPS 和 S3 数据导入及数据集版本选择入口；连接器测试已完成，完整登录网页端到端验收仍待完成。模型在线发布不属于本期多模态流程。

## 1 安装前准备

### 1.1 了解各部分的作用

毕昇平台提供网页、账号、训练数据保存和任务管理。FT 服务安装在带 GPU 的服务器上，负责加载模型、执行训练和测试训练结果。两者可以在不同服务器上，业务用户只使用毕昇网页。

LoRA 训练得到的是 adapter，即一份较小的模型适配权重。使用它时仍需要对应的基础模型，因此训练后应同时保留基础模型和任务输出目录。

### 1.2 管理员需要准备的材料

- 已能正常登录的毕昇平台，以及配套功能版本的毕昇与 bisheng-ft 源码或镜像。
- 一台 Linux NVIDIA GPU 服务器，已安装驱动、Docker Engine、Docker Compose 和 NVIDIA Container Toolkit。
- 服务器登录账号、可写的数据目录、用于下载模型与镜像的网络或离线文件。
- 平台后端能访问的 FT 服务地址，以及 FT 能访问的平台文件存储地址。

本指南以单卡安装和小规模样例训练入门。首批模型在24 GB显存的 NVIDIA GPU 上完成过小规模验证；更大的模型、图片、视频或批大小需要另行评估资源。

在训练服务器终端执行：

```bash
nvidia-smi
docker version
docker compose version
```

应能看到显卡、Docker 服务端和 Compose 的版本。如果命令不存在或显卡查询失败，先完成对应软件安装，再继续。Docker 安装说明：https://docs.docker.com/engine/install/ubuntu/ 。GPU 容器运行时安装说明：https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/install-guide.html 。这些是服务器的一次性准备工作。

### 1.3 记录客户自己的地址

请记录训练服务器的内网 IP 和服务端口。下文将 `192.0.2.10` 作为文档示例地址，执行前全部替换为客户实际服务器地址；端口示例为 `8000`。

平台填写的是 FT 的 HTTP 地址，例如 `http://192.0.2.10:8000`。SSH 登录地址、模型推理接口和 LlamaFactory WebUI 不是此处的 FT 地址。

## 2 在服务器安装 FT 服务

### 2.1 放置配套源码

将本版本 bisheng-ft 源码解压到训练服务器，例如 `/opt/bisheng-ft`。以下命令都在训练服务器执行，路径按实际解压位置调整：

```bash
cd /opt/bisheng-ft/deploy/multimodal
cp .env.example .env
mkdir -p data/models data/jobs
```

该目录内应有 `Dockerfile`、`compose.yaml`、`constraints.txt` 和 `.env.example`。不要使用仓库中旧版本的启动脚本替代这里的 Compose 配置。

### 2.2 配置服务

用文本编辑器打开 `.env`，修改以下配置：

```dotenv
GPU_ID=0
FT_PORT=8000
FT_BIND_IP=192.0.2.10
MODEL_DIR=./data/models
OUTPUT_DIR=./data/jobs
FT_MODELS=Qwen3-0.6B,Qwen2.5-VL-3B-Instruct
HF_ENDPOINT=https://huggingface.co
CAPABILITIES_FILE=../../src/sft_server/model_capabilities.json
```

`GPU_ID` 是分配给本服务的显卡编号，在 `nvidia-smi` 中查看；单卡服务器通常填0。`FT_BIND_IP` 填训练服务器实际内网 IP，不能保留示例地址。默认文件中的 `127.0.0.1` 只允许本机访问，平台在另一台服务器时须改为可达内网地址。

`MODEL_DIR` 保存下载的基础模型，`OUTPUT_DIR` 保存训练任务及产物。相对路径从当前部署目录计算。`FT_MODELS` 决定此服务向平台开放哪些已经登记的模型；多个名称用英文逗号隔开。

服务面向受控内网，网络策略只允许毕昇后端和管理员访问。客户访问网页使用毕昇账号，不能把无独立账号认证的 FT 端口直接作为公网入口。

### 2.3 构建训练镜像

```bash
docker compose build ft
```

首次构建会下载训练环境，耗时取决于网络。镜像固定训练框架与依赖版本，完成后再执行下一步；出现下载或安装错误时先处理该错误，不要跳过构建继续启动。

确认容器能访问所选显卡：

```bash
docker compose run --rm --no-deps ft nvidia-smi
```

应看到分配给该服务的 GPU。若宿主机能查到 GPU 而容器报错，应检查 NVIDIA Container Toolkit 配置。

### 2.4 下载基础模型

```bash
docker compose --profile tools run --rm download
```

此命令下载文本模型 Qwen3-0.6B，以及图文和视频模型 Qwen2.5-VL-3B-Instruct，并校验权重文件。模型保存在前面配置的 `MODEL_DIR` 中。只需试文本时，可以先下载一个模型：

```bash
docker compose --profile tools run --rm download --model Qwen3-0.6B
```

没有外网的服务器可由管理员在联网机器执行同一下载命令，再将完整模型目录和下载校验记录复制到 `MODEL_DIR`。不要只复制一个权重文件；配置、分词器与视觉处理器也属于模型所需文件。

### 2.5 启动并检查服务

```bash
docker compose up -d ft
docker compose ps
curl --fail http://192.0.2.10:8000/health
curl --fail http://192.0.2.10:8000/v2.1/sft/capabilities
```

将命令中的 IP 替换为实际地址。容器应处于运行或 healthy 状态，健康接口应成功返回；能力接口应包含已经下载并可用的模型。健康接口成功只说明服务可访问，首次安装仍需按后文完成一条训练任务。

启动失败时查看日志：

```bash
docker compose logs --tail 100 ft
```

## 3 将配套功能部署到毕昇

本章由毕昇平台管理员执行。如果交付人员已经部署对应版本，可直接进入第4章。安装新的 FT 服务不会自动改变旧毕昇页面，前端和后端必须同时使用配套版本。

采用源码构建部署时，在毕昇服务器将本版本源码放到 `/opt/bisheng`，保留客户现有配置和数据卷。先备份现有数据库、文件存储和配置，再在测试环境执行：

```bash
cd /opt/bisheng/docker
docker compose -f docker-compose.yml -f compose.multimodal.yml build backend frontend
docker compose -f docker-compose.yml -f compose.multimodal.yml up -d backend backend_worker frontend
docker compose -f docker-compose.yml -f compose.multimodal.yml logs --tail 100 backend
```

`compose.multimodal.yml` 用当前源码构建前后端，后台任务进程使用同一后端镜像。平台启动会执行数据库迁移及模型表初始化；若日志出现迁移失败，先修复版本或数据库问题，不要继续交给业务用户操作。使用企业镜像发布流程的部署，由交付人员将同版本镜像替换到对应服务。

数据库、Redis、对象存储及平台其他依赖沿用毕昇标准部署。本指南安装的是既有毕昇平台的微调功能；若客户尚未安装毕昇，应先完成平台基础安装和登录验证。

平台上传的训练文件由 FT 下载，因此 FT 必须能够访问平台生成的文件下载地址。只在毕昇后端 Docker 网络内有效的 `minio` 主机名，另一台训练服务器通常无法解析。管理员应配置训练服务器可达的文件存储地址或内部域名，并确认文件下载通路可用。

使用配套 Compose 时，编辑 `docker-compose.yml` 中 `backend` 和 `backend_worker` 的 `BS_MINIO_SHAREPOINT`，填写文件存储的实际主机名及端口，例如 `storage.company.internal:9000`，不带 `http://`。该值对应 `object_storage.minio.sharepoint`；`BS_MINIO_ENDPOINT` 仍用于平台内部连接，可保留原值。修改后重新创建后端服务，并从训练服务器确认该域名可解析和访问。下载链接的主机参与签名，不能在链接生成后手工替换。

## 4 在毕昇接入训练服务

1. 使用平台超级管理员或当前租户管理员账号登录毕昇，进入“模型”中的“模型微调”。仅拥有模型菜单查看权限的普通账号不能执行微调操作。
2. 点击“训练服务管理”，新增一条服务记录。
3. 名称填写易于识别的业务名称，例如“企业训练服务器”。FT 地址填写实际 HTTP 地址，例如 `http://192.0.2.10:8000`。
4. 保存后点击“检测并同步模型”。等待连接检测和模型信息同步完成。
5. 创建任务时选择这条服务，确认能够看到服务器已准备好的模型。

检测失败时，先在毕昇后端所在的运行环境验证能否访问 FT 健康接口。管理员自己的电脑能打开该地址，不代表平台后端也能访问。

两个训练服务提供不同模型时，分别修改各自 `.env` 中的 `FT_MODELS`，重建服务后在平台重新检测同步。例如，文本服务只填写 `Qwen3-0.6B`，图文视频服务只填写 `Qwen2.5-VL-3B-Instruct`。同一服务器运行多份部署时，要分别设置服务端口、任务输出目录、Compose 项目名和管理员分配的 GPU。

### 4.1 增加新的模型

管理员先区分两种情况：已经登记的模型，只需下载完整权重并加入 `FT_MODELS`；配置文件里没有的新模型，则需要增加能力记录和完成适配验证。

能力登记文件由 `.env` 中的 `CAPABILITIES_FILE` 指定，默认是源码里的 `src/sft_server/model_capabilities.json`。可复制一份由本服务独立维护。记录中的 `model_name` 必须与 `MODEL_DIR` 下的模型文件夹一致，`input_types` 分别使用 `text`、`image_text`、`video_text`，并填写正确的 `template`、训练方法和参数范围。

新模型先标记为 `unverified`，由算法或交付人员验证训练和产物重载后才开放。不能只修改验证状态就认为新模型可用。业务使用者无需编辑该文件。

完成配置且确认没有运行任务后，在 FT 部署目录执行：

```bash
docker compose up -d --force-recreate ft
```

随后回到毕昇点击“检测并同步模型”。如果新增模型需要当前镜像没有的框架或处理器支持，还需要先构建经过验证的新训练镜像。

## 5 准备第一次训练的数据

### 5.1 先使用页面提供的示例包

进入“创建训练任务”，选择文本、图文或视频类型，下载该类型的示例数据包，再上传到训练数据区。每次任务使用一个数据包，重新上传会替换已选包。第一次使用建议先运行文本样例，熟悉流程后再试图文和视频。

示例只用于熟悉文件格式和验证功能，不能代表企业业务效果。开始业务训练前，应替换为企业的问题与标准答案，并留出一部分未参加训练的样本用于测试。

### 5.2 文本数据

文本 JSON 文件的内容是一个样本数组。`user` 填问题，`assistant` 填期望答案。例如保存为 `train.json`：

```json
[
  {
    "messages": [
      {"role": "user", "content": "打印机无法连接，应交给哪个部门？"},
      {"role": "assistant", "content": "IT"}
    ]
  }
]
```

可以在数组中加入更多样本。文本也可使用 JSONL，每行一个样本，不能把整段数组按任意位置换行后当作 JSONL。

### 5.3 图文数据

图片需要与问答一起打包。ZIP 解压后的根目录直接包含 `train.json` 和图片文件夹，不要再套一层同名文件夹：

```text
receipt-training.zip
  train.json
  images/
    receipt-001.png
```

`train.json` 示例：

```json
[
  {
    "messages": [
      {"role": "user", "content": "<image>票据上的金额是多少？"},
      {"role": "assistant", "content": "128.00元"}
    ],
    "images": ["images/receipt-001.png"]
  }
]
```

`<image>` 表示问题中引用一张图片，`images` 填写 ZIP 内的相对路径。路径和文件名必须完全一致。标准答案由企业准备，系统不会从任意图片自动生成训练答案。

### 5.4 视频数据

视频同样使用 ZIP，根目录放 `train.json`，视频放 `videos` 文件夹。入门样例使用短 MP4，问题中写 `<video>`，媒体字段写 `videos`：

```json
[
  {
    "messages": [
      {"role": "user", "content": "<video>方块向哪个方向移动？"},
      {"role": "assistant", "content": "向左移动"}
    ],
    "videos": ["videos/clip-001.mp4"]
  }
]
```

本版本处理视频画面，不读取音轨；单段视频不超过10秒，分辨率不超过1080p。首次使用优先采用随页面提供的短视频样例。视频越长、分辨率越大，对解码、存储和显存的要求越高；应按服务配置控制数据规模。

### 5.5 从 FTP/FTPS 或 S3 导入并复用数据

在创建任务的数据区打开导入弹窗，选择本地、FTP 或 S3。远程来源填写数据集名称和服务器连接信息，再选择清单来源：上传本地清单，或填写服务器上的清单路径；媒体根目录用于解析清单中的相对路径。例如清单写 `images/receipt-001.png`，媒体根目录写 `training`，服务会读取该根目录下对应图片。无需为每个样本填写一套服务器地址。

FTP 地址只填写协议、主机及端口，例如 `ftp://files.example.com:21`，用户名和密码放在独立字段；使用 TLS 时选择 FTPS/TLS，当前不支持 SFTP。S3 填兼容端点、bucket、访问凭据及必要的 region。地址中不要夹带密码、文件路径或查询参数。网络及账号应能读取清单和引用素材。

导入会把远程文件拉取、校验后保存为平台数据集版本，后续任务复用的是已保存版本，不会在每次训练时重新读取远程地址。修订数据需要重新导入。连接凭据仅用于本次导入，不保存在数据集版本、任务配置或浏览器持久存储中。

在“已有数据集”中选择版本并预览样本，再提交训练；刷新页面后可重新选择已保存版本。本分支的真实连接器读取已验证，仍需交付人员在客户环境完成网页导入、数据库/对象存储持久化、复用和跨租户权限的整体验收。FTPS 证书握手尚待专项验收。

## 6 创建并运行训练任务

1. 打开“模型微调”，点击“创建训练任务”。
2. 选择数据类型：文本、图文或视频。名称例如 `support-model-v1`，须以字母开头，仅使用字母、数字、下划线和连字符，长度不超过50个字符。
3. 选择管理员接入的训练服务，再选择匹配的基础模型。文本示例用 Qwen3-0.6B，图文或视频示例用 Qwen2.5-VL-3B-Instruct。
4. 上传训练文件或 ZIP，单文件不超过20 MB。等待检查完成，核对样本数量和媒体数量，并展开前3条样本确认问答和媒体对应；有错误先修正再上传。视频上传先做结构检查，FT 执行时再做解码检查。
5. 本版本训练方法固定为 LoRA。首次体验采用下表的小规模参数，熟悉流程后再由算法人员设置业务训练参数。
6. 点击“预检并创建”。检查通过后进入任务详情；失败时按页面原因修正并重新检查。

| 参数 | 首次体验值 | 含义 |
| --- | --- | --- |
| 最大训练步数 | 8 | 进行8次参数更新后停止 |
| 学习率 | 0.0001 | 控制每次参数调整的幅度 |
| 批大小 | 1 | 每次处理一个样本 |
| 梯度累积 | 1 | 每批执行一次更新 |
| 序列长度 | 1024 | 输入输出的长度预算 |
| LoRA rank | 8 | 适配参数的规模设置 |

最大训练步数为正数时优先于训练轮数，8步不等于把全部数据训练8遍；需要按训练轮数运行时，最大训练步数填 `-1`。以上参数用于检查流程，不是企业效果优化方案。

提交成功后记下任务名称或编号。加载模型时可能暂时没有训练指标，应查看实际日志等待，避免连续点击创建。资源忙时使用其他可用服务，或等当前任务结束后再提交。

## 7 查看结果并测试新样本

### 7.1 查看训练状态

在任务列表选择对应任务，查看详情中的运行状态、日志、实际训练配置和产物。训练失败时保留错误日志，先处理数据、模型或资源问题。

关闭或刷新网页不会主动停止服务器训练。需要停止时，在任务详情点击“停止”并确认，等待服务确认；已经完成的任务不能再当作运行中任务取消。

### 7.2 检查产物

训练结束后确认任务成功且产物检查通过。LoRA 权重通常显示为 `adapter_model.safetensors`，并带有配置和文件信息。只有训练进度结束而产物不完整时，不能继续把该结果当作可用模型。

### 7.3 测试微调后的模型

1. 在任务详情打开“新样本验证”。
2. 文本任务填写新的问题；图文任务上传一张新图片并填写问题；视频任务上传一段新视频并填写问题。
3. 需要对比时勾选“同时用基础模型对比”，使用同一输入查看训练前后的输出。
4. 点击“重新加载并推理”，等待服务器加载基础模型和本次训练的 adapter。
5. 阅读实际回答，并与预先准备的正确答案比较。测试成功只表示能够执行推理，回答内容仍可能有误。

新样本应与训练数据分开。先检查是否能完成调用，再用企业认可的测试集评估内容正确性和输出格式。当前版本的此流程到任务内推理验证为止；在线业务调用需要另外部署兼容的推理服务。

## 8 常见问题和日常维护

| 现象 | 优先检查 | 处理方法 |
| --- | --- | --- |
| 服务检测连接失败 | FT地址 端口和网络 | 从毕昇后端验证健康接口 检查容器日志 |
| 服务可访问但没有模型 | 模型是否下载完整及FT_MODELS | 完成下载后重新检测同步 |
| 上传报缺少图片或视频 | 清单路径与ZIP内容 | 保持相对路径一致 后重新打包 |
| 创建后下载数据失败 | FT能否访问文件存储 | 修正存储对外地址 DNS或网络策略 |
| 显存不足 | 模型大小 输入长度和批大小 | 减小配置或使用资源足够的服务器 |
| 训练成功但推理失败 | 基础模型和adapter是否还在 | 保留完整目录并查看推理错误 |
| 回答不符合预期 | 数据答案 训练设置及测试集 | 做独立效果评估 调整数据后重新训练 |

管理员在 FT 部署目录查看日志和停止服务：

```bash
docker compose logs --tail 100 ft
docker compose stop ft
```

停止服务会中断该服务正在执行的训练或推理，应先确认没有运行任务。日常备份 `.env`、模型登记配置和 `OUTPUT_DIR`，同时保留对应基础模型版本；平台数据库和对象存储按企业原有备份流程保护。

升级前记录当前镜像版本，备份任务输出，在测试环境完成一次训练与推理后再替换。不要删除历史任务仍依赖的基础模型，也不要清理正在运行任务的输出目录。
