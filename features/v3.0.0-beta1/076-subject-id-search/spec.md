## 1. 范围与用户故事

作为管理者，我希望使用已知的名称或完整、部分业务 ID 找到授权对象及其他入口的目标用户，核对其身份后继续原操作，避免同名误选和逐层查找。

### 本次纳入

- 新增授权中的用户、部门、用户组检索，以及资源创建时已有的授权候选选择入口。
- 系统管理：用户列表搜索、用户组成员选择。
- 组织管理：添加成员、新建部门与部门设置中的管理员选择。
- 租户管理：初始管理员选择、租户用户列表。
- 审批配置：指定审批人、异常处理中的审批人选择。
- 标注任务：已有任务成员选择。
- 应用使用日志：用户候选检索。
- 当前分支中服务账号功能已有的用户检索组件；入口存在性在设计阶段逐项核对，不凭 PRD 的版本名称推定已有实现。

### 本次不包含

- PRD §2 的文件存入知识空间误跳转修复、频道文章查询性能优化。
- 已授权列表新增展示或操作；知识库、工具、角色名称检索。
- 名称自动转拼音；ID 中段或后缀包含匹配；新增身份字段、修改历史 ID、批量回填历史空值。
- 将授权对象范围扩大到其他租户、受限部门之外或隐藏/失效对象。
- 提前实现当前分支尚不存在的业务页面或服务账号能力。

## 2. 业务 ID 口径

用户已明确确认：用户与部门均以各自的 `external_id` 为检索 ID。本节字段名只用于固定已确认的产品身份口径，不定义接口或存储改造。

- 用户：使用人员 ID，保留已有原值；不以内部数字用户 ID 替代。
- 部门：使用外部部门 ID，保留已有原值；不额外把系统部门编码作为新增匹配字段。当前本地新建部门的两个值可能相同，不能由此推定所有部门相同。
- 用户组：使用现有数字用户组 ID 的文本形式；目前没有独立外部 ID，用户已确认此口径。
- 勾选去重、授权提交、日志筛选继续引用原稳定对象 ID；展示检索 ID 不改变身份关联。

## 3. 验收标准

### 3.1 覆盖与匹配

- **AC-01** — WHEN 管理者使用上述已有入口查询对象，THE SYSTEM SHALL 在该入口原允许范围内支持名称及本规格声明的业务 ID 检索，并保留原名称匹配规则、搜索触发方式、单选/多选和提交动作。原为名称前缀匹配的入口继续使用前缀匹配。
- **AC-02** — WHEN 输入一个非空关键词，THE SYSTEM SHALL 返回名称按原规则匹配或业务 ID 以前缀匹配的对象；匹配覆盖整个允许候选集合，不限于已加载页。用户于本轮明确接受完整 ID＋前缀，优先保留性能优化。
- **AC-03** — WHEN 业务 ID 为 `jia0100`，THE SYSTEM SHALL 允许 `jia`、`jia0100` 通过 ID 命中，不允许 `0100` 仅凭 ID 中段命中；WHEN 另一对象 ID 为 `jia0100-02`，THE SYSTEM SHALL 允许 `jia0100` 同时命中两者，并在平铺结果中将完整 ID 相等的对象排前。
- **AC-04** — THE SYSTEM SHALL 将 ID 作为文本比较，保留前导零、字母大小写和分隔符；名称沿用各入口既有大小写规则；特殊字符按字面值匹配，不作为通配符或表达式。
- **AC-05** — WHEN 多个平铺结果命中，THE SYSTEM SHALL 优先展示完整 ID 相等的对象，其余沿用原排序，原排序相同时按稳定 ID 的文本升序排列；先去重、排序再分页。已有已选分组保持原分组，各组内执行相同排序。
- **AC-06** — WHEN 检索使用部门树或用户组织树展示结果，THE SYSTEM SHALL 保留路径上下文与同级排序，自动展开命中路径；完整部门 ID 命中时定位目标节点，祖先仅作为路径上下文，不自动成为匹配或选择对象。

### 3.2 展示与选择

- **AC-07** — WHEN 展示新增授权候选或已选对象，THE SYSTEM SHALL 展示名称及对应 ID 的字段名和值；用户保留部门信息，部门补充所属路径，用户组保留既有辅助信息；完整 ID 可查看并选中复制。
- **AC-08** — WHEN 搜索、翻页、删空关键词或切换对象类型，THE SYSTEM SHALL 保留已选对象，以对象类型与稳定 ID 去重，候选及已选区域双向同步，已授权和已选对象保持既有可选状态与提示。
- **AC-09** — WHEN 切换对象类型，THE SYSTEM SHALL 清空搜索词并加载该类型默认首屏；WHEN 关闭并重新打开弹窗，THE SYSTEM SHALL 恢复默认搜索状态，其他授权草稿字段遵守原保存规则。
- **AC-10** — WHEN 空关键词或删空输入，THE SYSTEM SHALL 恢复该入口的原默认候选、排序与首屏；WHEN 非空关键词改变，THE SYSTEM SHALL 从首屏重新查询。

### 3.3 输入、加载与错误

- **AC-11** — THE SYSTEM SHALL 接受中文、字母、数字、空格及特殊字符，查询前去除首尾空白、保留内部空格，将粘贴换行替换为空格，并将整次输入作为一个关键词；中文输入法组词完成后更新查询。
- **AC-12** — IF 按 AC-11 规范化后的输入超过 255 个字符（按 Unicode code point 计），THEN THE SYSTEM SHALL 保留输入、暂停查询，并提示“搜索内容超过长度限制，请缩短后重试”；修改到 255 个字符以内后恢复查询。
- **AC-13** — WHILE 查询进行中，THE SYSTEM SHALL 显示加载状态并暂停选择旧结果；WHEN 响应乱序返回，THE SYSTEM SHALL 只展示最新查询的结果。
- **AC-14** — WHEN 新增授权查询成功但无结果，THE SYSTEM SHALL 显示“未找到可授权对象，请核对名称或 ID”；IF 查询失败或超时，THEN THE SYSTEM SHALL 显示“搜索失败，请重试”及重试操作，保留关键词和已选对象，重试同一条件。WHEN 关联用户入口（系统、组织、租户、审批、标注、日志、服务账号）查询成功但无结果，THE SYSTEM SHALL 显示“未找到匹配的用户，请核对名称或 ID”；失败与重试同上。
- **AC-15** — THE SYSTEM SHALL 按当前对象类型显示“搜索用户名称或 ID”“搜索部门名称或 ID”“搜索用户组名称或 ID”，新增文案同时支持中文、英文、日文。

### 3.4 权限、提交与兼容

- **AC-16** — THE SYSTEM SHALL 对名称和 ID 使用相同的租户、部门子树、对象类型、隐藏/失效状态及可授权/可管理范围，每次查询校验既有操作者权限；部门挂载租户保持其指定部门子树限制。
- **AC-17** — WHEN 对象不存在、失效或超出当前允许范围，THE SYSTEM SHALL 使用相同的无结果行为，不通过 ID 查询泄露对象存在性。
- **AC-18** — WHEN 管理者选择并提交授权，THE SYSTEM SHALL 按原稳定对象 ID 写入授权，提交时由服务端重新校验操作者权限、对象有效性及租户归属；查询和选择本身不产生授权。部门子树与隐藏状态沿用既有写入合同，不在写入时新增强制校验；本期不新增校验接口或修改授权写入规则。
- **AC-19** — IF 原提交接口报告失败，THEN THE SYSTEM SHALL 保留本次选择及原有错误处理，允许用户调整后重试；批量事务、重复提交与审计沿用既有合同。本期只扩展搜索，不新增逐项失效定位、候选复检接口或部分成功语义。
- **AC-20** — WHEN 在日志用户候选中使用业务 ID 查到并选中用户，THE SYSTEM SHALL 继续以该用户原稳定 ID 筛选日志，不能将业务 ID 当作日志关联键。
- **AC-21** — WHEN 前后端作为同一版本更新，THE SYSTEM SHALL 直接在现有检索入口提供 ID 搜索，保留原参数名、响应结构和稳定提交身份，不要求新查询模式。
- **AC-22** — THE SYSTEM SHALL 不为混合前后端版本增加能力探测、版本响应标记、兼容分支或升级提示；本期部署合同为前后端同版更新。
- **AC-23** — THE SYSTEM SHALL 保留存量 ID、租户归属、部门关系、所有者、授权对象、权限等级、生效状态及原有查看/编辑/管理结果；本期不因新增搜索能力修改业务数据。
- **AC-24** — IF 需要回滚本次更新，THEN THE SYSTEM SHALL 按现有发布流程同时回滚前后端版本，保留既有和升级期间新增的有效授权；不新增搜索能力开关。

### 3.5 性能

- **AC-25** — WHEN 在不少于 15 万用户、3 万部门的组织中，以最宽可见范围（系统超管、根租户）使用名称或 ID 检索，THE SYSTEM SHALL 使每个入口的单次检索服务端耗时 P95 不超过 500 ms，MySQL 与达梦均满足；IF 某入口未达标，THEN THE SYSTEM SHALL 在发布前修正查询方案并重新验收，不通过增加运行时能力开关掩盖性能问题。原有名称检索应对照同环境、同数据、同负载的改动前基线复测。

## 4. 边界情况

- 业务 ID 为空的历史对象仍可按名称查找，不生成替代 ID，不将空值显示成 `null` 或 `undefined`。
- 同名、相同业务 ID 的不同稳定对象不错误合并；可辨认信息与原权限范围共同决定候选，选择仍以稳定 ID 为准。
- 同一个对象同时命中名称与 ID 时只出现一次；相同内部数字在不同对象类型下不是同一个对象。
- 树结果中的祖先不扩大可授权范围；无主属部门用户维持该入口已有的候选边界，不借本期隐式改变组织模型。
- 已有候选上限、分页与截断提示需在设计中逐项核对；不能把加载第一页后本地过滤当作全候选检索。
- 当前源码没有统一搜索长度限制；此次将涉及的交互搜索输入明确为 AC-12 的 255 code point 上限，不改登录、同步等非搜索请求。
- 无业务数据迁移；为保护 ID 前缀查询性能，允许在现有索引不足时仅补必要的查询索引，记录双库部署/回滚方案，不改变字段值或既有唯一性。
