读库前先看

  • 这是配置库里记录的是"配给了谁"。某人最终能看到、能操作什么，还要叠加部门成员（含下级部门）、用户组成员、文件夹继承、知识空间加入方式和管理员身份，单靠读表得不出这个结果。
  • 只取生效行授权表只取 state = 'ACTIVE' 的行。INACTIVE 是已撤销的历史记录。
  • 只读，不写直接改表不会同步到权限引擎，界面上不生效，还会让两边数据不一致。请使用只读账号。
  • 按版本核对表结构随版本变化。本字典按 3.0.0-beta1 核对，平台升级后请重新核对。

资源授权

知识空间、知识库、文件、工作流、助手、工具、频道、看板的授权都存在这两张表。permission_grant 每行是"某资源上的某个权限模型"，被授予的人、部门、用户组挂在 permission_grant_assignee 下面。

flowchart LR
  G["permission_grant<br/>资源 × 权限模型"] -->|"grant_id"| A["permission_grant_assignee<br/>授给谁"]
  G -->|"resource_type + resource_id"| R["业务表<br/>knowledge / knowledgefile / flow …"]
  G -->|"model_key"| M["permission_model<br/>当前目录版本"]
  M --> PA["permission_model_action<br/>→ permission_action"]
  A -->|"subject_type + subject_id"| S["user / department<br/>group / service_account"]

permission_grant资源上的一个权限模型

同一资源上每个权限模型只有一行（唯一键：tenant_id, resource_type, resource_id, model_key）。

字段含义
idBIGINT主键，被 permission_grant_assignee.grant_id 引用
tenant_idBIGINT租户 ID。单租户部署恒为 1
resource_typeVARCHAR(64)资源类型，取值见下方「资源类型」
resource_idVARCHAR(64)资源 ID，按资源类型对应到业务表。数字 ID 也以字符串保存
model_keyVARCHAR(64)权限模型编码，对应 permission_model.model_key
stateVARCHAR(64)状态，取值见下方「状态」
projection_stateVARCHAR(64)同步到权限引擎的进度：CURRENT 已同步，PENDING / PROJECTING 同步中，FAILED_CLOSED 同步失败
versionBIGINT并发控制用的版本号
create_time · update_timeDATETIME创建、最后修改时间

permission_grant_assignee这个权限模型授给了谁

字段含义
idBIGINT主键
tenant_idBIGINT租户 ID
grant_idBIGINT所属授权，外键指向 permission_grant.id
subject_typeVARCHAR(64)授权对象类型，取值见下方「授权对象」
subject_idVARCHAR(64)授权对象 ID，按对象类型对应到用户、部门、用户组或服务账号表
include_childrenBOOLEAN1 = 连同下级部门一起授权。只有部门会用到
userset_relationVARCHAR(64)部门：member 仅本部门，subtree_member 含下级部门；用户组：member 全体成员，admin 仅组管理员；用户和服务账号为空
source_typeVARCHAR(64)这条授权是怎么来的，取值见下方「授权来源」
protectedBOOLEAN1 = 受保护授权（创建人的所有者身份），界面上不能移除
stateVARCHAR(64)状态，与 permission_grant.state 取值相同。两张表都要取 ACTIVE
projected_subjectVARCHAR(256)写入权限引擎的对象串，例如 department:4#subtree_member
source_ref · source_locator · source_fingerprintVARCHAR / CHAR(64)来源定位和去重键，系统内部使用，读数时可忽略
version · create_time · update_timeBIGINT / DATETIME版本号、创建与修改时间

ACTIVE生效

PENDING正在写入

权限模型

权限模型是一组操作的集合，例如「编辑者」包含上传、重命名、编辑等。管理员调整模型时会生成新的目录版本，模型表按版本存多份，读取时必须只取当前版本，否则同一模型会重复出现。

permission_catalog_release目录版本

字段含义
idBIGINT主键，被模型表和操作表的 catalog_release_id 引用
versionBIGINT版本序号
statusVARCHAR(64)CURRENT 为当前生效版本（只有一行）；DRAFT 草稿，RETIRED 已退役，COMMITTED / PROJECTING 发布中，FAILED_CLOSED 发布失败

permission_model权限模型

字段含义
catalog_release_idBIGINT所属目录版本
model_keyVARCHAR(64)模型编码。内置 viewer editor manager owner；管理员自建的是随机 ID；平台升级迁移生成的形如 legacy-custom-…
nameVARCHAR(255)界面显示名，如「查看者」
kindVARCHAR(64)STANDARD 内置，CUSTOM 自定义
derived_levelINT权限等级 1–4：查看者 1、编辑者 2、管理者 3、所有者 4；自定义模型按所含操作推算
activeBOOLEAN是否启用

继承与自定义

resource_permission_mode资源的权限模式

字段含义
resource_type · resource_idVARCHAR(64)资源，含义同授权表
modeVARCHAR(64)INHERIT 继承：除自身授权外，上级的授权也对它生效；CUSTOM 自定义：只按自身授权
parent_type · parent_idVARCHAR(64)上级资源（知识空间、知识库或文件夹）。顶层资源没有上级，恒为 CUSTOM
projection_state · version · update_time—同步进度、版本号、修改时间

从继承改为自定义时，系统把当时上级的授权复制一份到自身，这些授权的来源记为 SNAPSHOT_FROM_PARENT。

知识空间加入方式

知识空间（knowledge.type = 3）的 auth_type 决定其他人能否申请加入。库里存的是大写值。

取值含义
PUBLIC公开，申请后直接加入
APPROVAL需要空间管理员审批
PRIVATE私有，不接受申请

加入后的成员会以 SPACE_MEMBERSHIP 来源出现在资源授权表里，所以统计空间成员直接读授权表即可。

管理员身份

管理员不受资源授权限制，授权表里没有他们的记录也能操作。其中两类只记录在 OpenFGA（平台的权限引擎）自己的库里。

身份记录在说明
超级管理员userrole.role_id = 1，以及 OpenFGA 库中 system:global 的 super_admin 关系两处任一即为超级管理员，建议合并去重
子租户管理员仅 OpenFGA 库：tenant:<租户 ID> 的 admin 关系只在多租户部署中存在
部门管理员department_admin_grantgrant_source：manual 手工设置，sso 单点登录同步
用户组管理员usergroup.is_group_admin = 1

tupleOpenFGA 库中的关系表

字段含义
object_type · object_idVARCHAR对象，如 system / global、tenant / 3
relationVARCHAR(50)关系，如 super_admin、admin
_userVARCHAR(256)主体，形如 user:1，冒号后是 user.user_id
store · inserted_atCHAR(26) / TIMESTAMP存储 ID（一套部署通常只有一个）、写入时间

位置：Docker Compose 默认部署时，是业务库所在 MySQL 实例上的 openfga 库；达梦部署时，是 OpenFGA 服务配置 OPENFGA_DATASTORE_URI 指定的模式。只读这张表，不要修改。

常用查询

数据库
关键字 user、group、mode、protected 用反引号
Q1资源授权明细：哪个资源、什么权限、授给了谁
SELECT
  g.tenant_id,
  g.resource_type,
  g.resource_id,
  COALESCE(k.name, f.file_name, w.name, s.name, t.name, c.name, b.title, sk.name) AS resource_name,
  CASE WHEN k.id IS NULL AND f.id IS NULL AND w.id IS NULL AND s.id IS NULL
            AND t.id IS NULL AND c.id IS NULL AND b.id IS NULL AND sk.id IS NULL
       THEN 0 ELSE 1 END AS resource_exists,
  g.model_key,
  pm.name AS model_name,
  a.subject_type,
  a.subject_id,
  CASE a.subject_type
    WHEN 'user' THEN u.user_name
    WHEN 'department' THEN d.name
    WHEN 'user_group' THEN ug.group_name
    WHEN 'service_account' THEN sa.name
  END AS subject_name,
  a.include_children,
  a.source_type,
  a.`protected`,
  a.create_time,
  a.update_time
FROM permission_grant g
JOIN permission_grant_assignee a
  ON a.grant_id = g.id AND a.state = 'ACTIVE'
LEFT JOIN permission_catalog_release r
  ON r.status = 'CURRENT'
LEFT JOIN permission_model pm
  ON pm.catalog_release_id = r.id AND pm.model_key = g.model_key
LEFT JOIN knowledge k
  ON g.resource_type IN ('knowledge_space', 'knowledge_library') AND CONCAT('', k.id) = g.resource_id
LEFT JOIN knowledgefile f
  ON g.resource_type IN ('folder', 'knowledge_file') AND CONCAT('', f.id) = g.resource_id
LEFT JOIN flow w
  ON g.resource_type = 'workflow' AND w.id = g.resource_id
LEFT JOIN assistant s
  ON g.resource_type = 'assistant' AND s.id = g.resource_id AND s.is_delete = 0
LEFT JOIN t_gpts_tools_type t
  ON g.resource_type = 'tool' AND CONCAT('', t.id) = g.resource_id AND t.is_delete = 0
LEFT JOIN channel c
  ON g.resource_type = 'channel' AND c.id = g.resource_id
LEFT JOIN dashboard b
  ON g.resource_type = 'dashboard' AND CONCAT('', b.id) = g.resource_id
LEFT JOIN linsight_skill sk
  ON g.resource_type = 'linsight_skill' AND CONCAT('', sk.id) = g.resource_id
LEFT JOIN `user` u
  ON a.subject_type = 'user' AND CONCAT('', u.user_id) = a.subject_id
LEFT JOIN department d
  ON a.subject_type = 'department' AND CONCAT('', d.id) = a.subject_id
LEFT JOIN `group` ug
  ON a.subject_type = 'user_group' AND CONCAT('', ug.id) = a.subject_id
LEFT JOIN service_account sa
  ON a.subject_type = 'service_account' AND CONCAT('', sa.id) = a.subject_id
WHERE g.state = 'ACTIVE'
ORDER BY g.tenant_id, g.resource_type, g.resource_id, pm.derived_level, a.subject_type, a.subject_id;
Q2当前生效的权限模型及其操作
SELECT pm.model_key, pm.name AS model_name, pm.kind, pm.derived_level, pm.active,
       pa.code AS action_code
FROM permission_catalog_release r
JOIN permission_model pm ON pm.catalog_release_id = r.id
LEFT JOIN permission_model_action pma ON pma.model_id = pm.id
LEFT JOIN permission_action pa ON pa.id = pma.action_id
WHERE r.status = 'CURRENT'
ORDER BY pm.derived_level, pm.model_key, pa.sort_order;
Q3文件夹、文件的继承 / 自定义模式
SELECT m.tenant_id, m.resource_type, m.resource_id, m.`mode`, m.parent_type, m.parent_id, m.update_time
FROM resource_permission_mode m
ORDER BY m.tenant_id, m.resource_type, m.resource_id;
Q4知识空间加入方式
SELECT k.tenant_id, k.id AS space_id, k.name, k.auth_type
FROM knowledge k
WHERE k.type = 3
ORDER BY k.tenant_id, k.id;
Q5用户所属部门、用户组两条语句
SELECT ud.user_id, u.user_name, ud.department_id, d.name AS department_name, d.path, ud.is_primary
FROM user_department ud
JOIN `user` u ON u.user_id = ud.user_id
JOIN department d ON d.id = ud.department_id
ORDER BY ud.user_id, ud.is_primary DESC;

SELECT x.user_id, u.user_name, x.group_id, g.group_name, x.is_group_admin
FROM usergroup x
JOIN `user` u ON u.user_id = x.user_id
JOIN `group` g ON g.id = x.group_id
ORDER BY x.group_id, x.user_id;
Q6用户角色、角色菜单、审批获得的菜单三条语句
SELECT ur.user_id, u.user_name, ur.role_id, r.role_name, r.department_id AS role_department_id
FROM userrole ur
JOIN `user` u ON u.user_id = ur.user_id
JOIN role r ON r.id = ur.role_id
ORDER BY ur.user_id, ur.role_id;

SELECT ra.role_id, r.role_name, ra.third_id AS menu_key
FROM roleaccess ra
JOIN role r ON r.id = ra.role_id
WHERE ra.type = 99
ORDER BY ra.role_id, ra.third_id;

SELECT uma.user_id, u.user_name, uma.menu_key, uma.menu_name, uma.grant_source, uma.create_time
FROM user_menu_access uma
JOIN `user` u ON u.user_id = uma.user_id
WHERE uma.status = 'active'
ORDER BY uma.user_id, uma.menu_key;
Q7部门管理员、超级管理员三条语句，最后一条读 OpenFGA 库
SELECT dag.user_id, u.user_name, dag.department_id, d.name AS department_name, dag.grant_source
FROM department_admin_grant dag
JOIN `user` u ON u.user_id = dag.user_id
JOIN department d ON d.id = dag.department_id
ORDER BY dag.department_id, dag.user_id;

SELECT ur.user_id, u.user_name
FROM userrole ur
JOIN `user` u ON u.user_id = ur.user_id
WHERE ur.role_id = 1;

SELECT object_type, object_id, relation, _user AS subject, inserted_at
FROM openfga.tuple
WHERE (object_type = 'system' AND relation = 'super_admin')
   OR (object_type = 'tenant' AND relation = 'admin')
ORDER BY object_type, object_id;

读库注意事项

  • 资源删除后授权可能残留Q1 输出的 resource_exists = 0 表示业务表里已找不到该资源，统计时请过滤掉。
  • ID 以字符串关联resource_id、subject_id 是字符串，业务表的数字主键要先转成字符串再比较。示例用 CONCAT('', id)，MySQL 和达梦都适用。
  • 多租户部署各表都有 tenant_id，跨表关联时请同时带上租户条件。单租户部署恒为 1。
  • 数据量接入组织同步的部署，user、user_department、userrole 可能有十万行以上，建议加条件查询，不要整表导出。
