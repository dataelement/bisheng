# 会话标题模型非关键流程修复

日期：2026-11-27。基线：发版线 `feat/3.1.0-beta2`，`ef789f8c9883286964d9200613f1aac29e26c1f2`。按缺陷修复流程处理，不新增接口或配置字段。

交付目标按用户指定为 `feat/3.1.0-alpha1`：将原始修复 `c4502ffc92` 应用到 `67c2806432b50133c15b342df24b5362790010cd`，没有冲突；在 alpha1 上重新执行相同的 138 项回归和 Ruff 检查，全部通过。

## 业务行为

- 配置的标题模型可用时，继续使用它起标题，并保留既有关闭思考、清理思考标签和调用失败时取问题文本的处理。
- 未配置或无法加载标题模型时，工作台沿用当前对话模型起标题；知识空间、助手和工作流跳过自动起标题。
- 标题配置读取或模型初始化异常记录服务端日志，不向正常对话主流程抛出。
- 标题模型下线时，工作台候选配置和客户端能力配置均排除这个可选槽位，不影响其余可用配置。管理端保存的原始模型引用保持可见，便于管理员修复。
- 实际对话模型的租户、权限、在线状态和类型校验不变；没有调用已下线标题模型或绕过模型准入。

## 根因与修复位置

`LLMService.aget_available_default`、同步工作台候选读取及 `project_workbench_runtime_capabilities` 原来只处理无效引用，没有处理标题模型的 `model_default_models_unavailable`，导致可选标题模型下线时配置读取整体失败。本次只对标题槽位处理这种不可用状态，其余模型的严格校验保留。

知识空间、助手及工作流原来在可选模型配置读取与初始化完成后才进入已有的标题调用容错。新增 `LLMService.get_optional_chat_title_llm` 及同步版本，将这段可选准备过程也纳入失败隔离；工作台已有回退逻辑保持原样。
