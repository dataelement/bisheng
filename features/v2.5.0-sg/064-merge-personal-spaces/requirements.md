# 重复默认个人知识库合并

Status: `confirmed`

用户要求独立合并脚本, 并已确认同目录同名时按来源库 ID 升序合并, 后迁入覆盖前面的及目标原有文档和完整版本链。该确认授权本地实现和验证, 不包含真实业务环境执行。

- REQ-001 / AC-01: 按租户及个人库 owner 分组, 仅同用户多个同名默认库, 排除收藏及非个人库; 保留 ID 最小者。预览列出来源/目标, 支持指定用户或全部用户。规划测试验证。
- REQ-002 / AC-02: 合并整个来源库, 包括根目录文件、目录树和空目录; 保留版本号/主版本, 不按上传人重新分配目标。规划与执行测试验证。
- REQ-003 / AC-03: 来源库 ID、文件 ID 升序执行, 仅同路径同名覆盖; 删除旧目标完整版本链, 不按 MD5 扩大覆盖。复用迁移底座并验证 root 权限及顺序覆盖。
- REQ-004 / AC-04: 不安全版本图、审批/分享/发布引用、非成功文件、目录冲突、模型或来源 ES/Milvus 数量持续不一致时跳过并保留来源库。按 2026-09-10 用户最新要求, 默认普通单元失败在来源保全且补偿完成后继续; 审计失败、补偿不完整、覆盖中断等不可安全继续的错误仍停止。支持 --stop-on-error。失败结果不得标为成功, 覆盖后的唯一新副本不得清理。失败注入验证。
- REQ-005 / AC-05: 仅来源全部单元完成, 且无剩余文件/文档/未迁目录或外部同步绑定时删除旧库; 删除前重校验, 通过现有业务清理并核验。不能证明安全时保留, 不直接 SQL 删库。空库、保留及删除失败测试验证。
- REQ-006 / AC-06: 默认 dry-run, 不初始化写入基础设施; apply 使用 JSON + fsync JSONL 记录目标、覆盖及删库步骤, 可中断/重跑。实际 MySQL/DM8/对象/索引/权限验证单列限制。

边界: 不合并收藏库或任意自定义名称个人库, 不更改在线权限协议、数据库结构、依赖或配置。删除旧库及被覆盖内容不可用 JSONL 一键恢复。原链接/收藏引用需按现有保护拒绝或单独核查, 不承诺所有历史链接重定向。

- REQ-007 / AC-07: 用户确认修复性能。保持单文件和现有覆盖/保护语义; 发现重复用户前不读取文件及版本, 分用户加载重复库, 单元复查限定来源/目标路径和版本链, 外部引用与跨库共用存储需单独查询保留。规划使用索引避免逐候选全表遍历, 汇总报告分批写盘但删除日志仍及时持久化。查询范围与复杂度回归验证。


## 原记录迁移策略变更

REQ-008 / AC-08: 2026-09-10 用户明确变更为优先完成合库。Milvus 不可读时读取 ES, 可读内容尽量迁移; 无内容或索引/附属资源异常时仍迁移原记录并设解析失败。保留文件/文档/版本 ID 与原文件地址; 同名覆盖数据库旧版本链。解析失败/超时与模型不一致不再跳过。数据库、版本图、活动任务及业务引用保护不豁免。REQ-004/005 中旧索引计数门禁及仅业务删库要求由本项取代: 空库在外部清理异常时可重新验证后事务移除记录, 留待清理审计。
