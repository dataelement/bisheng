# 按需要推敲接口与方案

用于职责不清、调用者负担大、修改牵连广或重要设计未知；普通局部改动沿用现有机制，不固定生成三套方案。

检查调用者必须理解的参数、不变量、调用顺序、错误、配置与性能约束；复杂逻辑应在合理职责内集中，避免重复扩散到调用方。以使用收益、可测试入口与变更局部性评估接口，不用内部代码行数衡量“深度”，也不机械合并项目要求的架构层。
备选方案针对真实约束，例如简化常用调用、保留扩展能力或隔离远程依赖。先把问题和判断依据写清，再比较做法、收益、代价与推荐；协作只有实际获准且收益明确时采用，不默认并发多代理设计。
纸面难判断的重要状态或逻辑问题，可以用范围明确、内存状态的单文件 HTML 原型回答一个具体问题；明显标注原型和未验证边界。记录问题、结论及相关来源，将有效决定写回正式设计。原型不替代业务契约、产品测试或验收，不据此创建新分支。
替换测试或模块前检查原有保护的行为、边界与风险是否仍覆盖；仅因新接口已有测试，不能无依据删除旧安全、分支或性能保护。图解按既有选图方法处理；全部产品 UI 测试及真实 E2E 仍归独立验收。
