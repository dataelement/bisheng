# 客户端模型调用审计 PRD

版本：0.19　日期：2026-10-14　状态：本轮用户要求按当前规格、设计生成任务并交付客户端并行开发，采用为开发基线；D-09 数值评估延至开发完成后的测试环境；实现与真实联调未完成

本需求让管理员能够追溯经毕昇转发的客户端模型调用；对成功留存的请求，按聊天对话浏览简洁的模型请求时间线，并按需查看每次请求实际使用的完整上下文、模型返回、调用状态和用量事实。时间线不是客户端聊天记录的逐条气泡复刻；同一段历史在多次请求中重复出现时，每次请求仍保留自己的完整原件，但默认不重复铺开。审计留存失败时，按独立证据呈现可识别的缺口；若记录和独立证据同时丢失，不承诺逐条发现，不以“没有审计记录”推断“没有模型调用”。

**一期只建设审计能力。敏感词、安全围栏、内容检查、风险判定和输入输出阻断不在本期范围，后续另行确认需求与实现方案。** 本期审计只观察并记录实际调用，不改写请求或响应，不基于内容改变模型调用结果。

本文件是需求口径与验收依据。[技术设计](./design.md) 0.8、[客户端接口契约](./client-api-audit-extension.md) 0.3 和 [任务清单](./tasks.md)已按本版同步，客户端可先按能力协商与两字段契约并行开发。评审页仍为旧版阅读材料，不作为本版依据。文档暂存于 F062 目录，服务端开发分支为 feat/3.0.0-dsh-audit；不代表已发布 beta2 包含本功能或当前部署已实现。目标发布版本及独立 Feature 编号另行登记，不阻塞本轮任务拆解。本次不覆盖 F062 已有 spec/design；主客户端接口仅增加可选扩展文档入口，既有线协议不变。

## 1 已确认边界与待确认事项

### 1.1 已确认边界

| 编号 | 边界 | 来源 |
|---|---|---|
| C-01 | 一期只做客户端模型调用审计，不做敏感词、安全围栏或内容检查 | 本轮需求确认 |
| C-02 | 审计对象是客户端经毕昇转发的模型调用，不扩展普通工作台、工作流和知识文件解析 | 本轮范围收敛 |
| C-03 | 客户端存在多个聊天对话，同一对话内有多次模型请求；一期只按客户端上报的会话 ID 归组，服务端不验证该 ID 是否对应客户端真实会话 | 本轮需求确认 |
| C-04 | 客户端会压缩上下文；审计以每次实际发送的输入为准，不要求在一期追溯摘要替换了哪些历史消息；重复正文存储按 D-08 控制 | 本轮范围收敛 |
| C-05 | 老客户端不能提供完整关联信息时，仍保留请求级审计 | 兼容性要求 |
| C-06 | 不因本需求重做席位、License、模型授权、月额度、登录和退出语义 | 既有功能边界 |
| C-07 | 审计只记录事实，不自动冻结用户、撤销席位、替换模型、重试请求或改变模型输出 | 本轮范围收敛 |
| C-08 | 采集边界是毕昇 DSH 统一模型调用接口的有效业务入参与统一出参，不追踪底层供应商 SDK 的最终请求/响应报文；未进入统一模型调用的客户端本地数据不审计 | 本轮需求确认 |
| C-09 | 不对审计正文另设截断阈值；工具结果是否缩短由客户端在调用模型前决定 | 本轮需求确认 |
| C-10 | 进入毕昇统一模型调用接口只证明本服务发起该次调用；超时、取消和失败按该接口已观察到的事实记录，不推断底层供应商实际收到或处理的内容 | D-03 统一接口口径的可检验性要求 |
| C-11 | 一期暂不实现审计数据的到期自动删除或过期状态展示；期限、删除与备份处置另行确定 | 本轮需求确认 |

| D-08（已确认） | 正文去重范围 | 只在同租户、同用户、相同有效客户端会话 ID 内复用相同正文；无有效会话 ID 时仅在单次请求内复用。不同用户或不同有效会话 ID 不共享正文副本，但各次请求及内容出现事实始终独立 | 去重作用域以客户端声明的 ID 为准，不意味着服务端已核实真实对话边界；相同文本不等于同一次调用 |
| D-09（开发后评估） | 异步可见性、性能与覆盖率数值 | 开发前暂不冻结数值目标，也不以 PoC 作为进入开发的门槛。开发完成后在测试环境按 §4.7 测量元数据/正文可见时效、PENDING 与候选缺口窗口、覆盖率、告警和模型调用性能，并与固定来源的现有 DSH Token 用量展示作参考对照；据实决定调参及后续验收数值 | 有界资源、写入失败不阻断模型、状态真实及权限隔离仍是一期功能要求；未评估前不宣称实时、零丢失或无性能影响 |

## 2 产品目标与范围

### 2.1 产品目标

1. 对完整留存的调用，审计员能查清某个用户在什么时间、哪个对话中调用了哪个模型，实际提交了什么、模型返回了什么、调用最终处于什么状态；对有独立证据的缺失调用识别已知或待核实缺口，不补造内容，也不承诺在证据全部丢失时逐条识别。
2. 在多轮历史反复提交、压缩、重试、分支和并行任务场景下，仍能还原每次模型请求实际使用的有序上下文；有格式合法的客户端会话 ID 时按请求形成易浏览的会话时间线，不将重复历史误当成新的聊天气泡。
3. 正文只保存必要副本，同时保留每次出现、每次请求和每次用量的独立事实。
4. 审计记录明确区分待写入、完整、部分、未采集和未关联，不用摘要或推断补造事实。
5. 正文仅由全局超管和租户管理员在各自租户范围内查看并逐次留痕，租户和用户之间不能因正文去重或相同编号发生数据串联。

### 2.2 一期纳入

- 请求级元数据：用户、登录会话、模型、时间、耗时、统一模型接口结果、本服务响应结果、用量结算状态、用量和请求编号。
- 内容审计：毕昇统一模型调用接口的有效业务入参及统一业务出参，包括有序消息、角色、工具定义/调用/结果、多模态载荷及流式增量；按该接口形态留存，不追底层 SDK 报文，不额外生成摘要或解析文件。
- 以客户端上报且格式合法的会话 ID 聚合请求级记录，按稳定的请求时间与服务端请求编号排序；调用种类在客户端可稳定上报且服务端已公布时作为可选展示信息，轮次/步骤不在本期契约。并行子调用及重试各自保留独立请求事实，不要求重建任务树或重试归组。
- 每次请求的完整上下文快照；会话时间线默认展示简洁请求卡片，完整输入历史和模型返回按需展开，不在时间线中逐条重放重复历史。
- 同租户、同用户、相同有效客户端会话 ID 作用域内的正文去重、加密保存和完整性标记。
- 常用筛选仅显示用户、时间和模型名称；用户从当前所选租户的现有用户中下拉选择，支持搜索和分页，不要求手填用户编号或用户名。排查条件默认收起，并展示最近成功写入进度与已知缺口状态。
- 元数据详情、正文按需查看、正文查看日志和越权拒绝。
- 当前审计模式与最近成功写入进度的可见展示，避免将 OFF 或留存故障误认为“没有模型调用”。
- 老客户端请求级兼容和新客户端增强关联。

一期只覆盖经毕昇 DSH 客户端专用 Chat Completions 入口实际进入模型接口的请求，不按官方客户端版本或 User-Agent 筛选；同一任务内经该入口的子调用和客户端发起的重试均按独立请求计入。客户端直接使用第三方模型服务或其他不经该入口的模型请求，毕昇本功能不审计，不得在覆盖率或页面文案中宣称已覆盖。

### 2.3 本期明确不做

- 敏感词词库、规则匹配、安全围栏、内容风险分类、仅记录/阻断策略。
- 因内容触发的输入拒绝、流式输出截断、自动脱敏、自动改写、模型替换或自动重试。
- 为后续安全围栏预设 Gateway/Python 归属、策略数据模型、检查接口、流式算法或闭源交付方式。
- 客户端本地工具执行、文件访问、屏幕操作和网络访问的全量行为审计。
- 图片 OCR、图像语义理解、音视频解析和任意附件全文解析；但已经作为模型接口输入/输出传输的原始内容仍属于审计范围。
- 审计全文检索、批量原文导出、自定义报表和跨用户正文共享去重。
- 客户端聊天气泡的精确复刻、从请求正文推断跨请求消息身份，以及源消息 ID、消息修订/分支、任务父子、重试归组、压缩来源关系的采集或展示；不要求模型响应后客户端补报。每次实际进入模型接口的请求仍须独立审计。
- 改造既有非客户端敏感词功能，或将已有知识空间、频道检查能力迁入本需求。
- 自动冻结用户、撤销席位、修改额度或根据审计内容执行处置。
- 审计正文、元数据及正文查看日志的到期自动删除和过期状态展示；期限、删除及备份处置作为后续需求确定。

安全围栏如需建设，必须作为独立需求重新确认目标、风险模型、误判处理、执行位置、可用性语义和验收标准，不能把本期审计存储直接当作已具备的执行能力。

## 3 用户角色与术语

| 术语 | 产品含义 |
|---|---|
| 登录会话 | 某台设备的登录授权，同一登录会话可能包含多个聊天对话 |
| 聊天对话 | 客户端一个持续的聊天主题；重新登录或压缩上下文不会自动新建对话 |
| 模型请求 | 一次实际模型调用；重试产生新的请求事实 |
| 会话请求时间线 | 同一认证租户、用户及客户端声明的有效会话 ID 下独立模型请求的分页列表；按请求开始时间与服务端请求编号稳定排序。会话归组是客户端声明，不等于服务端已核实的真实聊天记录、客户端气泡或任务因果链 |
| 模型接口观察点 | 毕昇 DSH 完成请求校验与适配后、实际调用统一模型接口时的有效消息、工具和参数，以及接口返回的统一结果或有序增量；不以底层供应商 SDK/网络报文为审计原件，也不推断供应商是否实际收到 |
| 上下文快照 | 某次模型请求实际提交的有序内容，不等于对话里曾出现过的全部内容 |
| 压缩型模型请求 | 通过本功能覆盖的模型入口实际发起的压缩调用；其有效输入和返回按普通模型请求审计。压缩后被提交的新摘要也是后续请求输入的一部分，但不据此推断被替换的源消息 |
| 内容完整性 | 本次统一接口有效入参、已返回的统一出参及可核验的终止事实是否完整留存，取待写入、完整、部分或未采集；与模型调用成功、失败或取消独立，METADATA 模式的正文固定为未采集。“待写入”只用于已建立但尚未完成异步留存的审计行，不要求模型调用前同步插入 |
| 对话关联状态 | 请求是否具备客户端上报且通过非空字符串与长度校验的会话 ID；服务端不验证它是否对应真实会话。无 ID、ID 不合法或客户端未获能力声明时保留独立请求，不推断所属对话。可选调用种类缺失不影响请求审计或归组 |
| 逐条缺口证据 | 可关联到同一请求编号且能证明本服务的统一模型接口实际开始了该次调用的独立事实；调用前产生的业务明细或系统级汇总指标不能单独证明某次请求已进入统一接口，更不能证明供应商已接收 |
| 请求生效模式 | 某次请求开始时实际生效的 OFF、METADATA 或 CONTENT；模式读取失败时本次按 OFF 降级，但租户配置值仍未知。后续租户模式切换不得追溯改变该请求应留存的范围 |

审计日志入口位于客户端管理。全局超管可按所选租户查看对应用户的审计元数据与原文，租户管理员可查看本租户用户的审计元数据与原文；不按被审计用户逐人授权。普通客户端用户继续使用原有聊天能力，不新增内容审查提示。仅有菜单权限或其他管理员身份不等于有审计查看权限。

## 4 业务需求

### 4.1 审计记录与查询

进入审计页面时，全局超管默认选中系统默认租户（编号 1），不跟随其个人归属租户或列表顺序，仍可切换其他现有租户；租户管理员直接加载当前管理范围对应租户的审计，不展示全局租户切换入口。超管的默认选择须经过租户目录确认；目录未加载、加载失败或默认租户不在目录中时，不擅自改选其他租户或发起无租户范围的查询。

审计默认按时间倒序展示。页面常用筛选仅保留用户、时间范围和模型名称；下拉选择当前开放模型按 ID 精确查询，手填完整历史名称精确查询，不支持模糊匹配；用户通过下拉框选择当前所选租户下的现有用户，可搜索和分页加载，默认全部用户，不再提供手填用户编号或用户名的筛选框。请求编号、对话编号、模型提供方、统一接口结果、本服务响应结果、用量结算状态、内容完整性和对话关联状态放入默认收起的高级筛选；收起不清除已生效条件，入口标明生效的高级条件数量，并提供重置筛选。切换租户清空已选用户、筛选、分页与原文并取消旧请求。查询必须分页，不能一次加载全部正文。页面应展示最近成功写入时间、异步积压与已知缺口状态；写入进度只表示已处理事件，不证明此前所有模型调用均已留存。任何空结果都不能仅凭审计列表解释为“没有调用”。

列表展示用户、模型、时间、耗时、用量、统一接口结果、本服务响应结果、用量结算状态、内容完整性和关联状态；窄屏可将独立状态放入详情，但不得合并成一个“成功/失败”。模型名称展示“提供方 / 模型名”，不以内部编号代替可读名称。用量未知、审计待写入、正文未采集、正文部分留存和对话未关联必须分别标记。按请求编号查询时，若已有业务调用明细而审计记录尚不可查，应展示“有业务调用记录、审计待写入或缺失”，并明确该业务明细不能单独证明统一接口已被调用或供应商已收到请求；不得返回单纯的“未调用”。

逐条缺口必须以该请求开始时实际生效的模式为前提：配置 OFF 或可证实的读取失败降级 OFF 下没有本功能审计记录、METADATA 下没有正文均属预期，不得报审计缺口；METADATA 缺元数据、CONTENT 缺应留存的元数据或正文，才按对应证据判断缺口。读取失败降级属于系统异常，须与租户显式配置 OFF 区分，尽力告警；不能事后用当前租户配置倒推该请求原本应留存什么。超过当前配置的观察窗口后（数值在开发后测试环境校准），已知生效模式为 METADATA 或 CONTENT 且有同一请求的模型接口进入证据时，才可将缺失的应留存事实报告为已知缺口；已知模式已开启但仅有业务调用明细时，只能报告待核实的候选缺口。若请求生效模式及降级原因均无法证实，应显示“审计模式未知，适用性待核实”，不能断言已知或候选缺口，也不得无限期显示为待写入。系统级指标只能说明整体异常，不能据此把某个请求标为已知缺口。

请求详情提供“本次输入”“模型返回”“对话关联”“调用信息”。同一输入包含多个角色时保留角色、顺序和工具关系。正文默认不随列表或元数据详情返回，必须通过独立正文访问操作获取。会话时间线每次请求只显示一张可折叠卡片，默认仅展示时间、模型、调用种类（若客户端上报且字段合法）、入参消息数量或正文大小等非正文统计，以及彼此独立的接口/响应/用量/留存状态；不得在默认卡片中显示输出原文预览。管理员明确展开某张卡片的正文后，才对该请求单独授权、留痕并读取完整输入与返回，可在已授权的展开区显示输出片段；长历史默认收起，仍能继续展开查看完整原件。长对话按请求分页或分段加载，不一次渲染全部请求正文。

服务端传输层的认证 Token、Cookie、供应商凭证和内部服务密钥不是模型输入，不得进入审计正文、列表或错误信息。用户或工具主动放入模型入参的疑似凭证文本则属于 D-03 已确认的完整输入：不得在原始审计记录中静默删除、改写或截断，但只能由 D-06 规定的角色在对应租户范围内通过单独正文读取操作查看，不能出现在列表、普通日志或错误中。规格不承诺识别它是否真凭证。审计记录不得改变现有模型调用状态、错误类型或额度结算结果。

### 4.2 对话关联与请求时间线

服务端按“认证结果中的租户、用户 + 客户端上报且有效的 `conversation_id`”划分会话请求时间线：相同三元组归为一组，不同三元组分开；缺少或不合法的 ID 标为“未关联”，仍留独立请求。服务端只校验字段是否已公布、是否为非空字符串以及是否满足通用长度上限，不限定 UUID、前缀或字符集合，也不核实该 ID 是否对应客户端真实会话；不得通过消息正文、登录会话或时间推断归属。客户端若为不同真实会话复用同一 ID，这些请求在同一用户范围内会被归为一组；客户端若为同一真实会话更换 ID，则形成两组。会话归组仅是客户端声明的审计上下文，不改变每次模型请求原件及其租户、用户归属。

会话 ID 按客户端上报的原值精确比较，不转换大小写或归一化；不同值形成不同组。未关联请求的服务端请求编号即使与另一请求的客户端会话 ID 字符串相同，也不得让两者跨请求复用正文。

同一对话跨设备或跨登录续接时，只有客户端继续上报同一 ID 才能进入同一组；本期不要求服务端恢复、校正或证明这一关系。每次请求均有服务端请求编号，按请求开始时间、再按该编号确定稳定顺序；并发请求只表示时间上的排列，不推断父子、依赖或客户端实际显示顺序。重试也保留独立请求，不与原请求合并。

| 信息 | 来源与一期用途 | 缺失时 |
|---|---|---|
| 租户、用户 | DSH 凭证认证结果；确定记录归属和授权边界，不接受客户端覆盖 | 不进入合法模型调用审计 |
| 服务端请求编号、开始时间 | 服务端产生；标识独立调用并稳定排列时间线 | 属于请求级审计必需事实，不靠文本或客户端编号补造 |
| `conversation_id` | 新客户端按能力协商上报；服务端仅按格式合法的值在已认证租户、用户范围内归组，不验证真实会话归属 | 请求仍留存，显示“未关联”，不能按登录会话或相似文本合并 |
| `request_kind` | 可选；区分普通对话、压缩、标题等调用，避免把辅助调用误读为客户端回复 | 显示“调用种类未知”，仍展示模型请求，不从内容猜测 |

轮次/步骤、源消息 ID、响应后补报、任务父子、压缩来源和重试归组不属于一期字段。即使提供会话 ID 与可选调用种类，管理员看到的也是请求时间线，而非经过消息身份校准的客户端聊天气泡。

旧客户端未上报审计关联信息时仍保存独立请求记录并标记“未关联”；无法据此还原它属于哪个聊天会话。跨用户协作对话不在一期支持范围内。

新客户端先依[客户端接口契约 0.3](./client-api-audit-extension.md)读取服务端能力声明，只发送已公布且文档定义的 `audit_context` 字段；能力缺失或字段集合无法识别时省略，不为探测支持情况自动重试模型。若模型请求本身合法且处于通用安全限制内，关联字段不满足类型或长度要求时只忽略对应字段，保留其他有效字段及请求级审计；扩展整体非对象或超限则忽略整个扩展。缺少有效会话 ID 标记未关联，附加字段异常可另记非正文诊断，不因 request_kind 无效使有效 conversation_id 失效。非法 JSON、原有通用请求大小限制或模型业务参数错误仍按原接口拒绝。

一期唯一影响聚合的客户端字段是 `conversation_id`；租户和用户始终取认证结果。`request_kind` 的一期已知值为 chat、compaction、session-title，用于区分普通、压缩和标题调用；未知种类不从正文猜测，也不影响 ID 归组。两字段相互独立，能力、基本类型、长度与降级规则已在接口契约 0.3 固定；轮次/步骤不实施，不要求单独扩展版本或特定 ID 格式。缺少可选字段仍按实际生效模式采集，不能将 OFF 描述为已审计。

客户端局部 PoC 已找到会话 ID 和辅助调用种类的生成位置，但尚未验证跨重启、跨登录、能力协商与服务端实际接收端到端成立；目标接口契约须经联调确认。这些未验证场景不改变一期服务端“按收到的有效 ID 归组，否则未关联”的处理规则。源消息与最终请求项不一定一对一，且一期展示的是模型请求明细，因此不要求上报源消息 ID，不要求响应完成后的补报。Fork 若上报新的会话 ID，则以新 ID 呈现独立时间线，一期不展示父子来源。

### 4.3 重复历史与压缩后的展示

每次请求保存自己实际提交的有序上下文；压缩前已留存的请求原件不被覆盖。CONTENT 模式下，压缩型调用若经过审计入口，其输入和返回照常留存；压缩后摘要只有实际进入后续模型请求的有效输入时才作为该次输入留存。METADATA 模式不留摘要文本。无论哪种模式，一期均不建立摘要与被替换历史消息的来源边。

例如请求 R1 的输入是「用户：你好」，模型返回「助手：你好」；R2 的输入是「用户：你好、助手：你好、用户：你会什么」，模型返回新回答。时间线只显示 R1、R2 两张请求卡片；展开 R2 可看到它实际发送的三段输入，不把前两段再作为时间线上的新气泡。即使某段文本与 R1 完全相同，也不凭文本相等断定它们是同一条客户端消息。重复、编辑、重试或分支产生的请求均独立计数和计量。

有序输入或输出留存不完整时，仅按实际留存范围展示并标记部分；不能根据后续摘要、相似文本或客户端界面推断缺失的原文，也不生成“新增消息”“修订消息”等未经验证的标签。正文存储去重只影响物理副本，不改变请求事实、消息出现次数和计费次数。

例如，同一租户、用户且相同有效会话 ID 的两次请求中都提交“你好”，可复用一份允许作用域内的正文，但两次请求分别保留内容出现、顺序和用量；不同用户或同一用户的不同有效会话 ID 也提交“你好”时，不跨用户或 ID 复用正文。服务端不核实客户端 ID 是否真的代表同一个聊天对话。这是已确认的 D-08 去重作用域，不是按文本内容合并聊天记录。

### 4.4 内容留存与流式结果

三种模式的留存边界如下；缺口判断使用请求开始时实际生效的模式，模式切换只影响新开始的请求：

| 模式 | 本次请求的审计范围 | 正文状态 |
|---|---|---|
| OFF | 租户配置 OFF 或本次模式读取失败降级 OFF 时，模型请求不产生新的本功能审计记录、模型接口进入证据或审计活动标记；读取失败不改变租户配置，仅尽力记录最小系统故障诊断并告警，不改变既有业务调用明细与用量；模式配置变更仍按 AC-29 留痕 | 不适用 |
| METADATA | 保存请求级身份、模型、时间、状态、耗时、用量关联，以及有效客户端会话 ID 与可选调用种类；不保存轮次/步骤、消息或摘要文本、工具内容、流式响应片段及多模态载荷 | 未采集，不可回放 |
| CONTENT | 保存 METADATA 范围及毕昇统一接口本次有效入参、实际返回的统一出参；实际进入统一入参的压缩摘要属于正文 | 依实际留存结果标记待写入、完整、部分或未采集 |

CONTENT 模式不能只保存文本而把统一接口有效入参中的图片、附件载荷或结构化字段降格成类型统计。外部引用仅在统一接口有效入参是引用时按引用留存，不能声称已经保存引用目标的字节。审计不得自行截断大正文；客户端在调用模型前的压缩或截断已经体现在有效入参中，不应额外审计未发送的版本。

CONTENT 模式的流式输出按统一接口实际返回顺序采集文本及其他响应增量。只有统一接口有效入参、截至可核验终止点实际返回的全部统一出参及终止事实均持久化成功，才可标记“完整”；接口失败或客户端取消不自动意味着审计“部分”，若上述事实完整留存，应分别展示接口结果、本服务响应结果、用量结算状态和审计“完整”。若审计写入失败、响应片段缺失，或服务进程退出等原因使实际终止边界无法核验，则仅展示已确认留存的范围并标记“部分”或“未采集”。若记录完全丢失，仅能依据仍可取得的同一请求生效模式与独立证据尽力报告已知或候选缺口，模式或证据也丢失时无法逐条断定。不得补造后续内容，也不得把部分记录展示成完整成功。

按已确认的 D-05，审计留存不得使模型请求或流式响应等待远程存储确认，审计失败不让本次模型调用算失败，也不自动重试模型调用。审计积压或写入失败时，资源占用必须有上界，不能无限占用内存，也不能静默截断后仍标记完整。有记录但正文失败时标记“部分/未采集”；记录完全不可写时，通过仍可取得的独立证据、指标、告警及与既有业务调用明细的事后对账尽力发现盲区。独立指标只能提示系统级异常；只有同一请求的统一模型接口进入证据才能把该请求标为已知缺口。不能补造原文或声称逐条缺口都实时可见。D-09 开发后评估前，不得声称对主流程“无性能影响”。

### 4.5 用量与调用状态

审计引用既有模型调用明细和真实用量，不建立第二套额度账本。没有拿到用量时保留“用量未知”，不能按文本长度估算，也不能填成零。

须分别呈现四条事实轴：统一模型接口结果（进行中、正常返回、失败、取消或未知）、本服务响应结果（完整响应、错误、部分输出后中断或未知；不宣称客户端一定收到）、既有用量结算状态（已结算、用量未知或结算未确认）和审计内容完整性（待写入、完整、部分或未采集）。模型接口正常返回后仍可能因用量结算失败而使本服务返回错误；不能把接口成功写成整个业务成功，也不能把既有 `USAGE_UNKNOWN` 直接当成模型接口失败。各轴的状态来源及时间应保留，无法核验时标未知。

同一次 DSH 请求在成功响应、非流式错误响应、SSE、既有用量和审计中使用同一服务端请求编号，不因发生错误另生成关联编号。调用前拒绝仍可返回该次请求编号，但不得据此生成模型已调用审计；调用已进入且审计成功留存时，管理员应能按失败响应中的编号定位该次审计。

客户端重试产生新的请求记录；接口失败、取消、上游异常和正常完成分别保存。完整留存失败或取消调用的统一入参、已返回出参及终止事实时，审计仍可为“完整”；模型接口或本服务响应成功但正文丢失时，审计只能为“部分”或“未采集”。

### 4.6 查看权限与留痕

审计日志入口放在客户端管理中。每条记录的租户归属由该次模型调用的 DSH 凭证认证结果确定，客户端传入的关联字段不能改变归属。正文查看按管理员角色和记录租户归属授权，不做“查看人—被审计用户”逐人授权，也不另设正文授权管理；每次正文读取仍记录查看人、时间、目标记录和结果。正文访问日志写入失败时拒绝正文读取；普通列表、浏览器错误和服务日志不输出原文。进入菜单本身不产生查看或配置权限。已确认权限矩阵如下：

| 角色或权限 | 当前租户元数据 | 当前租户正文 | 切换审计模式 |
|---|---|---|---|
| 全局超管 | 按所选租户查看 | 按所选租户查看并留痕 | 可切换所选租户 |
| 租户管理员 | 仅本租户 | 仅本租户查看并留痕 | 不可切换 |
| 普通客户端用户、其他管理员、仅有菜单权限者 | 不可查看 | 不可查看 | 不可切换 |

全局超管与租户管理员查看各自租户范围内其他用户的元数据和正文，不属于越权；跨租户读取及仅凭菜单权限读取仍属越权。模式变更应留下操作者、租户、变更时间、变更前后模式，且只影响新开始的请求。两类管理员均可查看其范围内当前模式，但只有超管可切换。

一期不实现正文、元数据及正文查看日志的到期自动删除，也不提供“正文已过期”状态；保留期限、删除及备份处置留待后续需求确定。由于一期可能持续保存敏感原文，启用 CONTENT 前需由数据/安全责任方确认风险、容量与运营责任。第一期不开放批量原文导出。

### 4.7 异步可见性、性能与覆盖率（D-09 开发后在测试环境评估）

审计日志不要求实时可查。开发前不预设与现有 DSH Token 用量“同量级”的硬性数值 SLA，不因缺少 PoC 阻止开发；开发完成后在测试环境固定所对照的 Token 用量展示与查询路径，在相同请求、负载和统计起点下测量两者，作为评估和调参依据，不能将实时额度读数与异步用量投影混作同一基线。失败、取消及无用量请求单独测量，不假设一定存在可对照的 Token 用量。以下口径用于开发后评估，不是开发前已批准的数值验收门槛。审计 PENDING 只表示已建立的 SQL 审计行仍在异步留存，流式开始前不要求同步写这条行；尚未落库时可以暂时无审计行，完全写入失败也可能始终无行。开发时可设置可调整的观察窗口供状态回收与缺口查询使用，测试环境再校准其数值；功能正确性仍须验证。

| 指标 | 起止与统计口径 | 开发后评估产出 |
|---|---|---|
| 元数据可见时效 | METADATA 或 CONTENT 请求从模型调用终态到元数据可查询；正常完成请求与同一测试条件下所选 Token 用量展示对照，失败/取消单独统计；按租户分别统计 P95/P99 | 记录实测分布与异常样本，必要时调参；暂不设预先数值门槛 |
| 正文终态可见时效 | CONTENT 请求从统一接口返回终态、失败或取消，到完整、部分或未采集状态可查询；正常完成请求与所选 Token 用量展示对照，失败/取消单独统计，不能把部分留存计作完整 | 记录实测分布与积压成因，必要时调参 |
| PENDING 超时 | 有模型调用终态时从终态起算；无终态但有确认事件时从最后确认事件起算，须结合请求仍活动的证据判断，等待首字或暂时无输出也可能正常活动；活动可确认的请求不得仅因总时长长而判为缺口；无终态且活动无法确认、超过观察窗口的已落库记录应按实际范围标部分/未采集，无法核验的接口/响应状态标未知 | 评估并调整可配置观察窗口，不把初始默认值当成最终 SLA |
| 无终态候选缺口观察窗口 | 已知请求生效模式为 METADATA 或 CONTENT、仅有业务调用明细、无法确认统一接口是否进入且无审计事件时，从业务调用明细的开始时间起算；超过窗口且没有仍在运行的活动证据，标为“待核实候选缺口／调用状态未知”；模式未知时仅标记适用性待核实 | 评估误报、漏报并调整可配置观察窗口 |
| 常态审计覆盖率 | 受控测试用独立记录实际进入统一接口的请求清单作为分母，按请求生效模式分别核对元数据成功留存率、CONTENT 请求完整留存率；正常结束、失败和取消分别统计，正常运行与故障注入分组报告 | 报告实测覆盖与缺口来源；后续再决定是否设正式数值目标 |
| 模型调用性能回归 | 同一受控上游、同一请求与并发条件下，对比 OFF、METADATA、CONTENT 的首字及总耗时 P95/P99，并测大正文、长流和积压满载 | 报告增量和资源占用，必要时调参；不能宣称零开销 |
| 模式读取失败降级 | 在原配置分别为 METADATA、CONTENT 的租户注入读取超时或故障，核对本次请求按 OFF、模型继续调用、无本功能审计记录、告警及可取得的降级诊断；单列降级次数和读取等待开销 | 核对降级语义与可观测性，评估读取时间上限；不把降级请求并入正常配置 OFF 样本 |

覆盖率验收不能只用成功写入的审计行作为分母，也不能把配置 OFF、可证实的读取失败降级 OFF 请求或 METADATA 请求未保存正文算作本功能审计缺口；受控测试应单列模式读取失败降级次数，不能混入正常配置 OFF 数量。线上没有与 D-05 同时成立的逐条完整分母保证：进程崩溃可能同时丢失内存事件和指标，既有业务调用明细也可能早于模型接口进入，请求生效模式或降级原因也可能无法证实。线上仅报告可观测覆盖率估计、已知缺口、待核实候选缺口、可证实的读取失败降级及模式未知的请求，并说明统计来源与局限；不得把估算写成精确全量覆盖率。存储故障注入时 D-05 的模型主流程优先仍适用；故障场景应验收缺口表达和告警，不要求审计可见时效仍满足正常运行阈值。

## 5 典型用户流程

| 场景 | 操作与结果 |
|---|---|
| 查询调用 | 审计员按用户、模型和时间过滤，分别查看统一接口结果、本服务响应结果、用量结算状态、耗时、用量和审计完整性 |
| 查看正文 | 全局超管或租户管理员在各自租户范围内按需读取输入输出；系统记录本次查看行为 |
| 查看对话 | 审计员进入按客户端声明的会话 ID 归组的请求时间线，每次请求默认只显示一张简洁卡片；需要核对原件时单独展开该次输入和返回，长对话分页加载，不把重复历史当作新的聊天气泡 |
| 老客户端 | 审计员看到未关联对话的请求，仍可查看本次已留存的输入输出 |
| 调用中断 | 分别保留统一接口、服务响应和用量结算事实；有效入参、已返回出参及终止事实均完整留存时审计标记完整，存在缺失或终止边界无法核验时才标记部分 |
| 仅元数据模式 | 审计员能查看已留存的调用与关联标识，但正文标为未采集、不可回放 |

## 6 验收标准

以下 AC 采用 EARS 形式。涉及已留存内容的查询、关联、还原和展示，以对应模式已开启且所需事实已持久化为前提；采集与写入本身不得以“已经持久化成功”为验收前提，正常受控条件下必须通过 AC-35 的直接成功路径。留存延迟或失败按 AC-17、AC-24、AC-25 处理，不把模型业务成功等同于审计成功。D-01、D-02、D-03、D-05、D-06、D-07、D-08 及一期不做过期删除已确认；D-09 数值评估延至开发完成后的测试环境，D-04 的期限/删除留待后续需求。

| ID | 验收条件 |
|---|---|
| AC-01 | 当同一认证租户和用户的两次请求携带不同且格式合法的客户端会话 ID 时，系统应将它们分到不同时间线，不能按登录会话合并；任一次未携带 ID 或 ID 格式不合法时，该次请求只展示为未关联的独立记录，不推断归属 |
| AC-02 | 当同一认证租户和用户的多次请求（包括重新登录后）携带相同且格式合法的客户端会话 ID 时，系统应归入同一时间线并保留各请求独立身份；客户端更换 ID 时应展示为不同组，缺少 ID 时应标未关联。服务端不验收这些 ID 是否对应客户端真实聊天会话 |
| AC-03 | 当审计模式开启、客户端未提供聊天关联信息且该次审计持久化成功时，系统应保存请求级记录并标记未关联；缺失关联信息不得拒绝原有合法调用 |
| AC-04 | 当不同租户或用户提供相同会话编号时，系统应保持各自时间线和正文存储作用域独立，不得因编号相同而合并、复用正文或绕过查看权限；管理员查看范围仍按 AC-18、AC-19 执行 |
| AC-05 | 当同一有效客户端会话 ID 下发生并行 Agent 子调用或重试，且调用实际经过审计入口并成功留存时，系统应将每次物理模型请求各显示一次、保留独立编号和时间；按开始时间及服务端请求编号稳定排列，不从完成顺序推断任务依赖，也不要求父任务或重试归组标识 |
| AC-06 | 当 CONTENT 模式下同租户、同用户、相同有效客户端会话 ID 的请求中，相同正文随历史多次提交且成功留存时，系统应减少允许作用域内的正文重复存储，同时保留每次出现、顺序和调用次数；跨用户、跨不同有效会话 ID 及无有效会话 ID 时不得跨请求复用正文；未关联请求编号与另一请求的会话 ID 字符串相同，也不得造成跨请求复用 |
| AC-07 | 当 CONTENT 模式下压缩后的摘要实际进入模型输入且正文持久化成功时，系统应作为该次请求输入留存摘要，不覆盖已留存的历史请求原件；经过审计入口的压缩型模型请求也按独立请求留存。METADATA 模式不保存摘要文本；两种模式均不要求采集或展示压缩来源关系 |
| AC-08 | 当发生多次压缩、消息编辑、重新生成或 Fork，且 CONTENT 模式下各次请求正文成功留存时，系统应分别还原每次实际发送的有序上下文；无论是否有客户端会话 ID，都不补造跨请求的修订、分支或压缩来源关系。Fork 上报新的有效会话 ID 时展示为独立时间线 |
| AC-09 | 当某请求的历史输入未被采集或仅部分留存时，系统应按实际范围标记未采集或部分，不从后续摘要、相似文本或其他请求反推出缺失内容；不显示未经验证的“新增消息”或“同一客户端消息”关系 |
| AC-10 | 当内容审计开启且该次审计持久化完整时，系统应按毕昇统一模型接口的有效入参、统一出参形态、角色和顺序还原全部内容，不因正文大小或内容类型自行截断；不要求与底层供应商 SDK 报文逐字段一致 |
| AC-11 | 当 METADATA 对受控请求实际生效、统一接口已进入，且模式读取、存储正常、资源预算充足、异步写入处理完成时，系统应产生该请求独立的元数据记录，记录用户、模型、时间、统一接口结果、本服务响应结果、用量结算状态、耗时和用量关联，并明确正文未采集；元数据写入失败按 AC-17 处理 |
| AC-12 | 当 CONTENT 模式下流式输出正常结束且统一接口有效入参、全部统一增量与终止事实均持久化成功时，系统应按统一接口返回顺序保存输出并标记完整，不丢字、不重字、不乱序；模型正常结束但审计事实缺失时不得标记完整，METADATA 模式不得留存输出片段且正文标为未采集 |
| AC-13 | 当 CONTENT 模式下流式连接中断、上游失败或客户端取消时，若统一接口有效入参、截至可核验终止点已返回的全部统一增量和终止事实均已持久化，系统应分别展示模型接口结果、本服务响应结果和用量结算状态，并将审计内容标记完整；若有片段缺失或进程退出等原因使终止边界无法核验，则仅展示已确认留存范围并标记部分，不伪造正常完成；完全无审计记录时应按 AC-17、AC-24 依据请求生效模式及仍可取得的独立证据尽力区分已知缺口、待核实候选缺口与模式未知，证据也丢失时不得声称能够逐条展示 |
| AC-14 | 当 CONTENT 模式下毕昇统一接口入参包含图片、附件或其他非文本内容且正文持久化成功时，系统应留存该接口形态的载荷或引用形式；METADATA 模式不得留存相关载荷或引用正文，未进入统一接口的客户端本地内容不应进入审计 |
| AC-15 | 当统一模型接口失败、取消或由客户端重试且审计记录成功持久化时，系统应分别保存接口结果、本服务响应结果、用量结算状态与审计完整性；模型接口成功但结算失败或响应中断时不得显示为整体成功。重试形成独立请求事实，不得因审计失败自动重试模型调用 |
| AC-16 | 当模型返回真实用量且审计记录成功持久化时，系统应关联既有用量事实并单独标示结算状态；没有用量时应标记未知，不填零、不估算，不因审计缺失改写既有额度账本 |
| AC-17 | 当审计留存失败、积压超限或记录完全丢失时，系统不应仅因审计故障使模型调用失败、中止或自动重试；审计资源占用应有上界并尽力告警，已有不完整记录不得标记完整，完全无记录时不得声称可查询或保证逐条实时告警 |
| AC-18 | 当普通客户端用户、其他管理员或仅有菜单权限者请求审计列表、详情、正文或模式配置时，系统应拒绝访问；租户管理员跨租户读取或尝试切换审计模式时也应拒绝；任何列表、元数据详情、搜索结果、错误或服务日志均不得返回模型输入输出原文 |
| AC-19 | 当全局超管按所选租户或租户管理员在本租户查看其他用户的原文时，系统应逐次记录查看人、时间、目标记录和结果；正文访问日志写入失败、角色不符或超出租户范围时应拒绝读取 |
| AC-20 | 当多个请求复用同一份正文时，系统应保留各请求独立的内容出现事实与查看能力，不得因存储复用造成任一请求正文丢失；一期不执行到期自动删除，也不展示“正文已过期”状态 |
| AC-21 | 进入页面时，超管默认选中目录中已确认的系统默认租户（编号 1）并可切换，租户管理员直接加载当前管理范围的租户，不查询全局租户目录；身份信息延迟返回后也应自动加载正确租户，不发起无范围查询。默认仅显示当前租户用户下拉选择、时间和模型名称筛选，不提供手填用户编号/用户名入口；下拉候选来自当前租户现有开放模型目录，显示名称并按模型 ID 精确过滤；手填完整历史名称（提供方 / 模型名，最多 2048 字符）按原始 UTF-8 值精确匹配，不裁剪空白、不忽略大小写，不依赖模型配置仍存在。两种条件互斥，修改手填名称清除已选模型 ID；审计大表不执行名称 LIKE、候选 DISTINCT/GROUP BY 或全量计数。模型 ID 与名称摘要分别有租户内联合索引，时间使用范围过滤及游标分页；不新增历史模型目录表。高级排查条件默认收起，生效时显示数量且可重置。用户列表按需搜索和分页，切租户清空用户、模型和旧查询；候选列表与审计查询均遵守同一管理员租户范围。组合常用与高级条件过滤，或按客户端声明的有效会话 ID 进入时间线时，应在当前授权范围内稳定分页返回；时间线以请求开始时间和服务端请求编号确定稳定顺序 |
| AC-22 | 当租户配置 OFF 或本次因模式读取失败按 OFF 降级时，合法模型调用、席位、额度、登录和退出行为应保持一致，不产生本功能的模型请求审计记录、逐请求模型接口进入证据或审计活动标记；读取失败仅尽力记录系统降级诊断并告警，不能启动模型审计；当模式为 METADATA 或 CONTENT，但服务端未公布 `audit_context` 能力、客户端未提供关联字段，或仅关联字段不合法且模型请求本身合法并未触发通用安全限制时，模型调用仍应继续，服务端按实际留存结果保留请求级审计，忽略无效字段及依赖关系并如实标记关联状态；新客户端只能发送接口文档定义且服务端已公布的字段，不得因未知字段错误自动重试模型 |
| AC-23 | 当请求在身份、模型权限、参数或额度校验阶段被拒绝且未进入毕昇统一模型调用接口时，系统不应生成已调用模型的输入输出审计记录；客户端本地工具结果只有被纳入统一接口的有效入参时才应留存 |
| AC-24 | 当 METADATA 或 CONTENT 对某请求实际生效且统一模型调用先于异步审计写入完成时，已落库的 CONTENT 审计行在正文或终止事实尚未核验完成时应显示待写入，不得标记完整；METADATA 已落库行的正文固定为未采集。流式开始前不要求同步创建审计行，尚未落库时不得伪造 PENDING。查询结果应显示最近成功写入进度、异步积压及已知缺口，并注明进度不证明审计覆盖完整；按请求编号查到业务调用明细但没有审计记录时不得回答“未调用”。超过当前配置的观察窗口后（数值在开发后测试环境校准），只有该请求生效模式可证实为 METADATA 或 CONTENT、且有可关联同一请求并证明统一接口实际开始调用的独立证据，才应将缺失的应留存事实显示为已知缺口；模式可证实为已开启但仅有可能在模型调用前生成的业务明细时，即使该明细已有业务终态也只能显示待核实候选缺口；请求生效模式无法证实时应显示“审计模式未知，适用性待核实”，OFF 无审计记录及 METADATA 无正文均不得算作缺口。汇总指标与系统级告警不得用来指认某次请求已进入统一接口；已知模式开启、无业务终态且无审计事件时须在缺少运行活动证据后显示“待核实候选缺口／调用状态未知”并尽力告警，正常输出中的长流不应仅因总时长触发缺口；统一接口进入证据不等于供应商已接收 |
| AC-25 | 当毕昇统一模型接口已开始调用而底层供应商网络超时、客户端取消或服务进程退出时，系统应只记录本服务在统一接口观察到的入参、已返回出参及可核验终止事实，不凭调用前排队事件断言已进入接口，也不推断供应商实际接收内容；在受控统一接口测试中，完整审计应与该接口的有效入参和统一出参逐项核对 |
| AC-26 | 当用户或工具把疑似凭证文本放入实际模型输入时，CONTENT 模式成功留存的原始审计内容应保持完整，仅正文授权者可查看；服务端传输层凭证不得进入正文、列表、日志或错误信息 |
| AC-27 | 当开启 METADATA 或 CONTENT，出现大正文、并发长流或审计积压时，模型响应和用量语义应与 OFF 一致；积压满载不得无限占用内存或因审计故障阻断模型调用。开发完成后在测试环境以相同受控上游、请求及并发对比 OFF/METADATA/CONTENT 的首字与总耗时 P95/P99，记录性能增量并据实调参；本期开发前不设数值回归上限 |
| AC-28 | 当某请求开始时实际生效的模式为 METADATA 或 CONTENT，且该请求经毕昇 DSH 客户端专用 Chat Completions 入口以流式、非流式、Agent 子调用或客户端重试方式实际进入统一模型接口时，系统应按每次请求分别采集审计事实，不因客户端版本或 User-Agent 不同而漏采；留存失败按 AC-17 处理，生效模式为 OFF 的请求、直连供应商及其他毕昇入口不应被误报为本功能已覆盖 |
| AC-29 | 当新建租户或存量租户升级且未由超管显式开启审计时，默认模式应为 OFF；仅全局超管可切换所选租户的 OFF、METADATA、CONTENT 模式，系统应记录操作者、租户、变更时间及前后模式，向该超管和本租户管理员显示当前模式；切换只影响新开始的请求，各请求按开始时实际生效的模式确定应留存范围，不改变在途请求模式或历史审计记录，租户管理员及其他角色不得切换 |
| AC-30 | 当开发完成后在测试环境执行受控评估且审计模式开启、统一模型接口已进入时，系统应以独立请求清单为分母，按请求生效模式分别报告元数据成功留存率，以及 CONTENT 请求在正常结束、失败、取消时入参、出参和终止事实的完整留存率；确有缺失时还应核对部分或未采集状态，并单列模式读取失败降级 OFF 请求。暂不设开发前覆盖率数值门槛，评估结果用于调参和后续目标确认。线上仅报告有来源说明的可观测覆盖率估计、已知与候选缺口、可证实的读取失败降级及模式未知情况，不得把配置 OFF、读取失败降级 OFF 请求或 METADATA 未留正文算作本功能审计缺口，不得用成功写入的审计行作为唯一分母或宣称精确全量覆盖、零丢失 |
| AC-31 | 当本次请求的租户审计模式读取失败或超时，且模型业务请求本身合法时，系统应在有上限的等待后让模型调用继续，并将本次审计采集按 OFF 处理：不留存本功能的模型请求元数据或正文，不把历史缓存值当作 CONTENT，也不改写租户配置；须尽力记录读取失败并告警。若可关联同一请求的降级证据仍可取得，查询与统计应把它与租户配置 OFF 区分，不报本功能审计缺口；若降级证据也丢失，不得凭当前租户配置补造该请求的模式或断言其为已知缺口 |
| AC-32 | 当相同有效客户端会话 ID 下的第二次请求重复提交第一次的历史消息且两次均成功留存时，会话时间线应仅展示两张请求卡片，不把第二次输入里的重复历史再显示成新的聊天气泡；展开任一请求并通过正文授权与留痕后，应能按该次实际顺序查看完整输入和返回。文本相同不应成为跨请求消息身份或先后关系的证据 |
| AC-33 | 当相同有效客户端会话 ID 下包含大量请求或长历史时，时间线应按请求分页或分段加载，默认卡片只返回非正文统计与独立状态，不返回输入输出原文或输出预览；管理员明确展开某请求且逐次正文授权及查看日志写入成功后，才可读取该请求完整正文。展开一张卡片不应预取其他请求正文，收起或翻页不应改变已持久化的原件 |
| AC-34 | 当旧客户端、新客户端未获能力声明，或新客户端缺少可选调用种类、轮次/步骤及源消息 ID 时，只要合法请求实际经过审计入口并成功留存，系统就应保留请求级审计；有格式合法的客户端会话 ID 才归入会话时间线。客户端不需要响应后补报，系统不得仅凭请求正文推断普通回复、压缩、标题调用或源消息对应关系 |
| AC-35 | 当受控小请求的 METADATA 或 CONTENT 模式读取成功、统一模型接口正常返回、存储正常、资源预算充足且异步写入处理完成时，系统应直接产生且可查询该次独立审计记录；分别覆盖流式、非流式及缺少客户端会话 ID 的请求。METADATA 应留元数据且不留正文；CONTENT 应能逐项核对完整输入、实际输出及终止事实，内容标记完整。该 AC 不以写入已成功作为前提，不新增生产零丢失或可见时效数值承诺 |
| AC-36 | 当同一次 DSH 请求返回成功、非流式业务错误或 SSE 错误时，响应中的服务端请求编号应与该次实际产生的用量及审计编号一致；模型已进入且审计成功留存时，应可按失败响应编号定位对应审计。调用前拒绝保持该次请求编号，但不得生成模型已调用审计；不能因审计或结算失败重放模型调用 |
| AC-37 | 当请求等待首字、暂时无输出或持续长流，但仍有可核验的请求活动证据时，系统不应仅因总时长将其判为审计缺口或模型失败。当已落库请求缺少终止事实、活动无法确认且超过当前观察窗口时，应只将无法确认的模型/响应状态标为未知，正文按已留存范围标部分或未采集，不无限显示待写入，也不补造失败或取消；后续可核验事实到达后应按事实更新，不能覆盖已有已确认终态 |
| AC-38 | 当 CONTENT 请求有已留存记录，但任一预期输入/输出片段缺失（包括最后一片丢失而终止事实到达），或终止边界无法核验时，系统不得将内容标为完整；超过观察窗口后按实际留存范围标部分或未采集。只有后续事实补齐并通过完整性核验，且不存在已确认的采集丢失或原件冲突时，才可更新为完整 |
| AC-39 | 当处理配置请求的服务实例缺少合法的活动审计加密密钥时，新的 CONTENT 模式变更应返回明确业务错误且不修改模式、版本或变更历史；关闭和 METADATA 仍可配置。管理读取应同时返回已配置模式与当前实例密钥可用性，页面禁用不可用的正文采集选项并提示联系运维；已配置 CONTENT 后密钥失效，打开或刷新页面应显示原文采集异常而不暗改模式，模型调用继续且按实际留存标不完整、不回退明文。保存时重新校验而不信任页面先前结果；已提交操作的相同幂等重放仍返回既有结果和当前可用性，不新增变更。密钥状态只证明当前实例配置可解析且活动版本对应 32 字节密钥，不证明全实例、存储或历史密钥均可用，也不返回密钥材料 |

## 7 验证样本与评审出口

QA 样本必须包含：同一用户多对话、跨登录续接、并行子任务、两次压缩、编辑分支、跨租户同名编号、同用户不同对话重复正文、重复上报、旧版与新版客户端及不同 User-Agent、旧客户端仅能形成未关联的请求级审计、第三方模型直连不纳入而经毕昇专用入口的请求纳入、能力声明缺失/不识别及仅发送已公布关联字段、非法但未触发通用安全限制的审计关联字段被忽略且模型继续调用、未经能力协商的新字段、客户端重试、SSE 半包与合包、发送与未发送给统一模型接口的工具结果、调用前校验失败、统一接口入参/出参与审计原件对照而不比对 SDK 私有报文、供应商超时和接收状态未知、模型接口成功但结算失败或响应中断、客户端取消、上游异常、失败/取消且统一入参出参及终止事实完整留存、服务进程退出且终止边界无法核验、数据库与正文存储故障、审计积压达到资源上限、大正文增量编码中途预算耗尽且标部分、长时间正常流式输出、首字早于异步 SQL PENDING 行出现、完全无行时不伪造 PENDING、无模型终态且无审计事件的停滞请求、逐条统一接口进入证据与仅有汇总指标的对照、独立请求清单与线上估计口径、存量与新建租户默认 OFF、模式切换前后在途请求、请求生效模式未知、OFF 无记录及 METADATA 无正文均不算缺口、超管跨租户选择与配置、租户管理员本租户查看原文但不得配置或跨租户查看、正文读取留痕失败拒绝、开发后测试环境与现有 DSH Token 用量可见时效对照、模型完成但审计尚不可查、OFF/METADATA/CONTENT 的正文边界、跨请求正文引用、提示词中含疑似凭证和越权读取。

其中同一用户多对话、跨登录续接只验证服务端按收到的有效会话 ID 归组、无效或缺失时标未关联，不验证 ID 与客户端真实会话的一致性；并行子任务、两次压缩、编辑分支与客户端重试只验证各次请求原件独立留存、按上报 ID 归组及不伪造跨请求关系，不验收任务树、来源边或重试归组。另须覆盖同一用户不同真实会话复用相同 ID、同一真实会话更换 ID、同一历史在多轮输入中重复、相同文本来自不同消息、长会话分页与默认折叠、仅展开单次请求时正文逐次授权留痕、辅助调用种类缺失或无效、没有源消息 ID 或响应后补报时仍可审计。默认列表和卡片不得出现任何原文预览。

另须注入租户模式读取超时、存储故障及降级诊断丢失：验证本次请求按 OFF 而非历史 CONTENT 模式采集、模型仍可调用、租户配置不被修改；有诊断时将降级 OFF 与配置 OFF 分开，无诊断时不凭事后配置补造逐条审计缺口。

本轮补充样本须覆盖：正常存储、预算充足且异步写入处理完成的流式/非流式成功留存（AC-35）；非流式上游失败及结算失败的响应编号与审计定位一致、调用前拒绝无模型审计（AC-36）；等待首字、暂时无输出、进程退出、活动证据丢失和迟到终态（AC-37）；最后一片丢失但终止事实成功留存、终止事实丢失及缺片恢复（AC-38）。另验证显式 OFF 不产生进入证据或活动标记、降级 OFF 仅有最小系统诊断、会话 ID 与未关联请求编号同值碰撞、大小写不同 ID 的精确隔离，以及管理员合法查看同租户其他用户原文。

产品已确认 D-01、D-02 的 OFF/METADATA/CONTENT 三档、默认 OFF 及模式读取失败时本次按 OFF 降级、D-03、D-05、D-06、D-07 的新客户端能力协商与无效关联字段降级处理、D-08，以及一期不做过期删除；本轮确认按模型请求明细建立简洁会话时间线，不以聊天气泡精确复刻为验收目标。D-07 已在接口契约 0.3 固定 conversation_id/request_kind 两字段、能力协商、限制及软降级，可交付客户端开发；现行 0.5.0 尚未声明该扩展，兼容的可选字段不要求仅为本扩展升级 `contract_version`，真实双端联调仍待实现后完成。D-09 的数值目标暂不作为开发前门槛，开发完成后在测试环境评估并据实调参或提出后续数值目标，不应提前宣称与 Token 用量展示同量级。D-04 的期限、删除及备份处置留待后续需求，但启用 CONTENT 前仍需数据/安全责任方确认一期持续留存原文的风险与运营责任。本轮按用户推进要求生成任务及客户端契约，不把文档审查、旧评审页或局部 PoC 当作实施验收通过。安全围栏不在本轮交付范围。
