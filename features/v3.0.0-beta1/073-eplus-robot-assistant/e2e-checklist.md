## 3. 客户测试环境必验

### 3.1 数据、部署与连接

- [ ] 备份数据库；启动当前版本 API 后确认 5 张 E+ 表在客户实际 MySQL/DM8 中存在，字段与唯一键生效。
- [ ] 并发插入同一 `(tenant_id, bot_id, msgid)` 时只有一条成功。
- [ ] API 与 E+ Worker 以独立进程/容器运行；Worker 数量至少 2 个。
- [ ] 同一机器人只有一个 Worker 建立连接；杀掉租约持有者后，另一实例在租约到期后接管。
- [ ] 入站图片由 Worker 写入 MinIO，后续排队执行或接管实例可以读取，不依赖容器本地目录。
- [ ] 助手离线保存配置时不连接；助手上线且配置启用后连接；下线、关闭或删除配置后断开。
- [ ] 断网、连续心跳丢失、普通重连、凭据轮换和外部客户端抢占均符合状态与退避策略。

### 3.2 P0：身份与知识范围

- [ ] 已同步用户可以使用；库中不存在、停用、删除或不属于当前租户的用户固定回复「无权限使用」，且不调用助手、工具或知识检索。
- [ ] 同一群内可用和不可用用户逐条按实际发送者判断。
- [ ] 两个机器人分别绑定互斥空间 A/B；机器人 A 不得检索或引用 B。
- [ ] 提问人即使个人拥有未绑定空间权限，也不能扩大机器人范围。
- [ ] 管理员没有空间个人权限，但有助手管理权限时，可绑定同租户有效空间；跨租户、已删除或不存在空间必须拒绝。
- [ ] 机器人零绑定时知识检索为空，不回退到助手原知识库/知识空间。
- [ ] 绑定空间内有 CUSTOM 文件权限时仍可检索；本期不做空间内文件级过滤。
- [ ] 执行中修改绑定：本轮继续用启动快照，下一轮使用新绑定，历史仍完整保留。
- [ ] 会读取毕昇知识的工作流/API/MCP 不能绕过机器人空间上限。

### 3.3 P0：既有助手回归

- [ ] 内部助手文字、知识库、知识空间和图片对话保持原行为。
- [ ] 开放 API、分享页、助手上线、自动优化和评测主路径保持可用。
- [ ] 日常对话的视觉模型、非视觉文字提取、文档和视频附件路径不受影响。

### 3.4 P1：消息、图片与回复

- [ ] 单聊文字、纯图片、图文混排及群聊 @机器人图文混排均能收到回复；群聊纯图片不作为协议保证项。
- [ ] 同一条消息的文字与多张图片保持原顺序；群聊 `@机器人` 前缀不进入模型和历史。
- [ ] 视觉模型能理解一般图片；仅 OCR 时只验图片文字；无能力时明确告知看不了，不得编造。
- [ ] 图片 URL 格式错误、超时、下载/解密失败或图片过大时返回明确失败，日志不泄密；空历史白名单不阻断正常 E+ 图片。
- [ ] 图片下载响应带 `Content-Encoding: gzip` 时先解压再解密；纯文本模型走已配置的 Paddle OCR，机器人能回答图片中的文字，不再出现解密或配置属性错误。
- [ ] 重投同一 `msgid` 不重复执行、不重复业务回复。
- [ ] 同一会话连续发送 3 条，后两条排队并自动续跑；第 4 条回复「消息处理中，请稍后再试」。
- [ ] 排队消息真正开始执行时才发送首帧并启动其回复窗口；前一轮完成后能看到完整历史。
- [ ] 模型片段按约 1–2 秒合并，不按字或 token 逐帧；每帧为累计全文。
- [ ] 回执超时或 `errcode≠0` 后停止该轮；占位帧失败时不启动助手。
- [ ] 超过 20,480 UTF-8 字节时安全截断并发送结束帧；始终为终态预留额度。

### 3.5 管理页与安全

- [ ] E+ 设置区可配置机器人、连接、可选 CA、多个空间和启用状态；不再展示媒体域名白名单。
- [ ] Secret 保存后不回显，轮换后新连接生效；连接状态准确。
- [ ] 中、英、日文案完整，无控制台错误。
- [ ] 日志不包含消息原文、Secret、AES key、完整临时 URL 或图片字节。

## 4. 测试环境从 923 分支恢复到当前版本

923 是从 beta1 拉出的下一版本分支，含当前版本不存在的后续数据库迁移。测试环境若已运行 923，不能只替换后端镜像：

1. 备份数据库并停止 API、异步 Worker 和 E+ Worker。
2. 使用原 923 后端镜像和同一份数据库配置执行 Alembic 降级到 `f061_merge_cofco_909_f066_heads`；后续迁移文件只存在于 923 镜像中。
3. 执行 `alembic current`，确认当前 revision 为 `f061_merge_cofco_909_f066_heads`。
4. 替换为当前版本镜像和编排配置，先启动 API 完成当前版本初始化，再启动其他 Worker。
5. 检查 5 张 E+ 表、健康状态和日志，然后执行本清单。

该过程不需要额外编写降级脚本，但数据库降级必须由旧 923 镜像执行。若 923 环境已有业务数据，先评估后续字段的数据损失风险。

## 5. 发布判定

以下条件全部满足才能从 PARTIAL 改为 PASS：

- 第 2 节所有阻断项已确认；
- 第 3 节 P0 项全部通过，其余项目无阻断缺陷；
- 双数据库、双 Worker、跨进程 MinIO 和真实 E+ 链路留下可追溯日志；
- 923 环境如有降级，已确认 revision 和业务数据；
- 生产机器人没有其他长连接客户端，回滚镜像和数据库备份可用。
