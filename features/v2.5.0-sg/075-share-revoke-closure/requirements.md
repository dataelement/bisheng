# 需求与验收

## 当前错误行为与证据边界

- `_normalize_share_source()` 使用 `find_entry_in_space_for_update()`；该查询包含 `deleting`，撤回后的旧引用会造成“目标知识库已存在该文档入口”。
- 清理失败耗尽重试后，旧引用仍在；重复撤回返回幂等成功但不重开清理，持续阻塞再次分享。
- `remove_share_entry()` 没有保存分享撤回审批履历；审批中心只对菜单和部门文件查看授权展示撤回标记。
- 用户报告撤回后待办记录消失。本地撤回及最终清理未发现删除 `ApprovalInstance/ApprovalTask` 的路径。必须验证已办及我的申请视图，不将“缺少标记/视图筛选”认定为已证实的物理删除；线上部署和历史数据尚未核对。

## Clarifications

- 2026-10-14 用户选择“直接覆盖”：旧引用尚在清理时允许新申请；新审批通过后启用新的分享引用，不等待旧引用删除。
- 有效入口以及真正待处理的新申请仍进行重复拦截。
- 已完成分享的撤回与审批中申请的撤销是不同状态，不混用审批 `withdrawn` 状态。

## 范围

Includes：部门文件库间分享、撤回、接收方删除分享引用、重新申请、审批历史与必要的投影并发保护。

Excludes：线上清理/补数据、重建丢失审批数据、新建分享外链、发布能力调整、改变审批人或授权范围、积分规则、无关投影重构、新表和 Schema 迁移。

## REQ-1 再次分享覆盖已撤回引用

只允许忽略目标库内 `share + deleting` 的旧引用；不得忽略有效入口、准备中的新入口、发布删除或其他资源冲突。每轮分享保留独立审批与引用身份。

- AC-1：分享 → 撤回 → 旧清理尚未结束 → 再次提交及审批生效，不再报旧引用冲突；同目标有效入口和重复待处理申请仍拦截。验证：后端本地集成，参数化正常清理中/旧清理失败。
- AC-2：新分享使用新的目标目录和下载策略；重复审批回调不产生第二个有效入口。验证：同一集成行为批次。

## REQ-2 旧清理不得影响新分享

旧任务只能删除旧入口 ID 的权限、全文记录和引用；共享索引归属必须基于剩余有效入口生成，沿用文档级任务领取互斥和入口租约/代次保护。引用停用立即阻断新访问。

- AC-3：暂停旧任务、创建新分享、恢复旧任务；新引用访问能力及目标库 ES/Milvus 归属保留，其他库及源文件不变。验证：投影批量本地集成与存储 fake，不用真实线上存储。
- AC-4：新任务不继承旧失败计数；旧清理失败可查，复用现有显式恢复工具，不后台无限重置失败预算。验证：失败路径与恢复工具回归。

## REQ-3 审批历史永久保留撤回标记

撤回时持久记录关联原审批实例、旧分享 ID、文档/目标库、操作人和时间；记录与停用操作保持一致。后台删除分享引用不删除审批实例、审批任务、操作日志或消息记录。

- AC-5：清理前、清理后、再次分享后，原审批在待办窗口的已办列表及我的申请历史中均保留，列表和详情显示“已撤回”；新审批不继承旧标记。验证：审批中心查询及前端行为测试。
- AC-6：已撤回审批回调重新投递时，不复活旧分享，也不覆盖新分享。验证：旧审批回放的集成失败/幂等路径。
- AC-7：权限不足、跨文档或跨租户请求拒绝；日志写入失败不留下“已停用但无履历”的新状态；重复撤回不重复追加撤回事件。验证：后端拒绝及事务回归。

## REQ-4 界面准确展示清理进度

分享弹窗区分有效分享与已撤回待清理/清理失败记录。保持可提交新分享，不把旧记录展示成有效分享。待办已处理记录不增加待处理数量。

- AC-8：弹窗与待办列表/详情显示正确标记；撤回后刷新两个知识库和审批中心，再次分享使用新的申请。验证：前端定向测试与本地浏览器模拟闭环。
