# 统计批处理与有界恢复

Status: locally-verified

用户授权：2026-09-22 要求优化前述统计任务，减少查询/写入、批量处理、重试有上限，并形成可验证闭环。

- REQ-1：人员名单按批复用于历史日期；名单和登录结果先合并再写入。按用户后续确认，人员当天对账调整为每小时 0、30 分，问答补漏为 15、45 分，内容全量对账为每天 01:10；历史补算仍为每天 00:40、回补两天，租约恢复仍每分钟执行。统计口径不变。
- REQ-2：人员、问答和文件增量按批读取目标 ES，仅写业务差异；保留事件时组织快照和实时登录字段，使用版本条件避免并发覆盖。
- REQ-3：同一失败链首次执行加最多 5 次自动重试；持久状态跨 Celery task ID、Beat 和租约回收生效。退避 30 秒起，最多 15 分钟。终止后保留失败原因和待处理数据，人工显式重放。
- REQ-4：租约恢复独立运行；批量成功必须逐项确认。读取/部分写入失败不得触发清理或误报成功，旧 owner 不得确认新 owner 的工作。
- REQ-5：日志记录扫描/未变/写入/失败/尝试次数；提供只读检查和显式 apply 恢复工具。

验收：AC-1 多日人员扫描只做一轮且每个目标 ID 一次组装；AC-2 未变零写入、批量失败重跑只补失败；AC-3 并发登录与组织快照不丢失；AC-4 6 次失败后 Beat/重投/租约回收不再执行业务；AC-5 过期领取、手动重放和部分失败可恢复；AC-6 保留相关既有回归。

边界：不部署、不运行线上任务、不修改统计定义或依赖；每日不同类型事件任务暂不合并，它们读取不同事件，合并收益未证实。
