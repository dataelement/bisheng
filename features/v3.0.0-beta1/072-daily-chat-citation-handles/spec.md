# Feature: 工作台日常模式引用改用短句柄

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
> spec 只回答 **做什么 / 验收标准 / 不做什么**；所有 How 在 [design.md](./design.md)。
>
> **前置步骤**：Spec Discovery 已完成（2026-09-30）。三项需要拍板的决策已由用户确认：存量提示词里的旧引用规则在运行时替换；零引用时一条来源都不落库；未识别编号保留在正文，复制与导出时剥掉。

**关联 PRD**: 无独立 PRD。沿用 [`docs/PRD/3.0-beta2/3.0 灵思任务模式引用溯源优化方案.md`] 的短句柄契约，本 Feature 把它推广到日常模式。
**优先级**: P1
**所属版本**: v3.0.0-beta1（发版线 `feat/3.0.0-beta2`）
**依赖**: F069（短句柄契约与会话级编号表，已上 release）· F047 / F054（私有区标记、`message_citation` 持久化、resolve 分态、会话导出剥标 AC-07 / AC-12）· F029（`view_file` 过滤，INV-7，**不改**）

> **范围边界**
> - **本次纳入**：
>   - 日常模式中知识库检索与联网检索的结果，改为给模型呈现短编号 `S<n>`，不再呈现内部引用键；编号与任务模式共用同一会话级编号表。
>   - 日常模式专用的引用规则：教模型写 `[S<n>]`。存量租户已保存的旧引用规则段落，在运行时替换成新规则；三语默认模板同步改写。
>   - 流式输出、正常完成、中途停止三条路径上，把 `[S<n>]` 确定性地转回既有私有区标记。前端的角标渲染、解析与持久化结构保持不变。
>   - 多轮对话：回放给模型的历史回答改用编号呈现；本轮引用上一轮的来源时，角标照常成立。
>   - 零引用时一条来源都不落库。这条取代 F054 为日常模式保留的"无标记则全部落库"。
>   - 未识别编号保留在正文，前端复制与会话导出时剥掉。
>   - 每轮一条结构化日志，记录检索来源数、实际引用数与未识别编号数，用于按模型统计效果。
>   - 独立于任务模式的系统开关；关闭后日常模式整体回到逐字复制内部键的旧契约。
> - **修订的既有契约**：
>   - **F054 AC-18**（"日常模式等四类入口溯源行为不变"）对日常模式不再成立，由本 Feature 的 AC-01 至 AC-19 取代；工作流、助手、知识空间三类入口仍受 F054 AC-18 约束（见本 Feature AC-20）。
>   - **F069 的会话级编号表**由任务模式独占写入改为两种模式共同写入；编号表的写入语义仍归 F069，本 Feature 只作为第二个调用方。两处都要在 release-contract 表 1 / 表 4 登记。
> - **本次明确排除**：
>   - **知识空间、频道、工作流、助手入口的任何改动**。它们与日常模式共用引用规则文本、检索结果模板和落库辅助函数，这些共享部分本 Feature 一律不改；"零引用一条不存"也只作用于日常模式。
>   - **日常模式会话导出烘焙 `[n]` 与参考资料**。F054 AC-07 规定会话导出维持剥标，本 Feature 不改。
>   - **每轮向模型注入来源表、零引用纠偏提醒**（对应 F069 AC-08、AC-15）。日常模式一轮之内，检索结果就在上下文里，也没有交付文件，这两项的前提都不成立。
>   - **零引用时在前端给用户提示**（对应 F069 AC-04）。本期只记日志，看过数据再决定。
>   - **任何形式的自动补引用**，包括按文本重叠给句子挂来源、把模型自编的编号映射成引用。原因同 F069：这会把"模型没标"伪装成"已溯源"。
>   - **临时知识库 `tempsearch_` 来源**。日常模式上传的文件以文本内联，不是可引用来源。

## 1. 用户故事

作为 **在工作台日常对话里开启了知识库或联网检索的业务用户**，
我希望 **回答里的角标尽量完整、准确，模型写错编号时我能看出来，而不是看到一个指错来源的角标**，
以便 **核对回答的出处**。

作为 **运维与产品**，
我希望 **每轮对话的引用情况有结构化日志，新契约可以单独开关**，
以便 **按模型比较迁移前后的引用质量，效果不佳时一键回退**。

## 2. 验收标准

> P1、跨前后端，采用 EARS 句型。AC-ID 在本特性内唯一。

### 2.1 呈现与规则

- **AC-01** — WHERE 日常模式短句柄开启, WHEN 知识库或联网检索返回结果, THE SYSTEM SHALL 为每条结果呈现一个形如 `S<n>` 的短编号，模型不再看到内部引用键；同一会话内同一来源（同一文档片段或同一网页）多次检索得到同一编号，包括跨轮检索，以及同一会话里任务模式已经分配过的编号。
- **AC-02** — WHERE 日常模式短句柄开启, THE SYSTEM SHALL 在系统提示词中提供日常模式专用的引用规则，教模型在句末写 `[S<n>]`，多个来源写成 `[S<n>][S<m>]` 或 `[S<n>, S<m>]`；规则中不出现内部引用键格式与私有区字符。
- **AC-03** — WHERE 日常模式短句柄开启, IF 生效的系统提示词里含有旧版引用规则段落（包括存量租户保存的默认提示词）, THEN THE SYSTEM SHALL 在本轮调用中把该段替换为 AC-02 的规则，不写回数据库，提示词其余内容保持不变；若提示词里没有任何引用规则，则追加 AC-02 的规则。
- **AC-04** — THE SYSTEM SHALL 把三语（zh-Hans / en / ja）默认提示词模板里的引用规则段落改为 AC-02 的内容。

### 2.2 转换

- **AC-05** — WHILE 回答正在流式生成, THE SYSTEM SHALL 把已完整出现的 `[S<n>]` 形态编号转为既有私有区标记后再下发，使角标像今天一样实时出现；用户在任何时刻都看不到已识别编号的字面文本 `[S<n>]`。
- **AC-06** — WHEN 回答正常完成或被用户中途停止, THE SYSTEM SHALL 对回答正文和执行记录中的每个文本段都完成 AC-05 的转换后再落库并下发完成事件，确保刷新前后看到的内容一致。
- **AC-07** — THE SYSTEM SHALL 只转换 `[S<n>]`、`[S<n>][S<m>]`、`[S<n>, S<m>]` 三种形态；`[n]`、`[^n]`、markdown 链接 `[S<n>](url)`、代码块内文本、`[S<n>]: ` 定义行一律原样保留。
- **AC-08** — IF 模型写出的编号不在本会话编号表中, THEN THE SYSTEM SHALL 在正文中原样保留该编号文本，计入 AC-13 的未识别编号数，不猜测、不删除、不映射。
- **AC-09** — THE SYSTEM SHALL 使转换幂等：已转换的文本再次经过转换不产生变化。
- **AC-10** — WHILE 过渡期模型仍输出旧版私有区标记, THE SYSTEM SHALL 按今天的规则识别和清理这些标记，与 `[S<n>]` 同一回答并存时两者都生效。

### 2.3 多轮与持久化

- **AC-11** — WHEN 历史回答作为上下文回放给模型, THE SYSTEM SHALL 把其中的私有区标记呈现为该来源在编号表中的 `[S<n>]`；无法映射的标记从回放文本中去掉，模型不会同时看到两种引用格式。
- **AC-12** — WHEN 本轮回答引用了本会话之前轮次检索到的来源, THE SYSTEM SHALL 保留该角标，并把该来源绑定到本轮回答；来源的运行时信息已过期时按 F054 的"已失效"分态呈现，不删除角标。
- **AC-13** — WHEN 一轮对话结束（正常完成或中途停止）, THE SYSTEM SHALL 输出一条可按会话检索的日志，包含模型名、本轮检索到的来源数、回答实际引用的来源数、未识别编号数、旧版标记数。
- **AC-14** — WHEN 回答中没有任何有效引用, THE SYSTEM SHALL 不为该回答持久化任何来源；只持久化回答实际引用到的来源。

### 2.4 复制与导出

- **AC-15** — WHEN 用户复制日常模式回答或导出会话, THE SYSTEM SHALL 在剥离私有区标记（F054 AC-07 口径不变）的同时剥离未识别的 `[S<n>]` 编号文本；AC-07 列出的其它形态保留。

### 2.5 开关与健壮性

- **AC-16** — THE SYSTEM SHALL 提供一个独立于任务模式的系统级开关控制日常模式短句柄，默认开启；关闭时 AC-01 至 AC-06、AC-11 回到逐字复制内部键的旧契约，AC-13、AC-14、AC-15 照常生效；历史消息的渲染与解析不受开关状态影响。
- **AC-17** — IF 编号表依赖的运行时存储不可用，或编号分配、转换过程出现任何异常, THEN THE SYSTEM SHALL 回退为向模型呈现内部引用键、按旧契约继续本轮，不使工具报错、不中断回答。
- **AC-18** — THE SYSTEM SHALL 保持日常模式对外的流式事件协议与消息结构不变，不新增事件类型，前端角标渲染组件无需区分新旧契约。
- **AC-19** — WHEN 回答走识图路径（图片问题）, THE SYSTEM SHALL 对 `[S<n>]` 编号与旧版标记做同样处理，不因路径不同而出现字面编号或错误角标。
- **AC-20** — THE SYSTEM SHALL 使知识空间、频道、工作流、助手四个入口的检索结果呈现、引用规则、落库规则与复制导出行为保持不变。

## 3. 边界情况

- **模型把编号写成 `[3]` 或脚注 `[^3]`** → 不转换、不映射，按零引用处理（AC-14），日志可见。
- **同一句连续多组编号 `[S3][S7]`** → 合并为一组标记，前端渲染为相邻角标。
- **流式分片把 `[S1` 和 `2]` 切在两个片段里** → 不能提前下发半截文本；具体做法见 design.md。
- **同一会话先跑任务模式再回到日常模式** → 两边共用编号空间，同一来源编号相同（AC-01）。
- **管理员自定义的提示词里改写过引用规则、识别不到旧段落** → 视为没有引用规则，按 AC-03 追加新规则；两段规则并存时以新规则为准的措辞写在新规则里。
- **多标签页同时在一个会话里提问** → 编号不重复；同一来源两边拿到同一编号。
- **开关在一轮进行中被切换** → 本轮沿用开始时的契约。
