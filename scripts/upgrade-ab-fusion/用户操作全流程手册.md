# 毕昇 B→A 升级融合：用户操作全流程手册

在 **B 源机** 操作。本地 MySQL 是 B，A 只通过 SSH 写入。  
P2 升级逐步命令仍以 [`复制即跑.md`](./复制即跑.md) 为准；**数据融合从本文第 3 节复制即跑**。

包路径：仓库 `scripts/upgrade-ab-fusion/`。现场把整个 2.5 仓拷到 B 再进该目录。

---

## 0. 铁律（违反即停）

- 最终环境是 **A**。不 `UPDATE` / `DELETE` A 的 `knowledge.type=3`。
- 默认 `MIGRATE_B_SPACES=0`：不迁 B 的知识空间（type=3）。
- 只迁传统库 type=0/1、工作流、助手、会话消息、审计 `auditlog`。积分/遥测不迁。
- 默认 `APPLY=0` 只生成 SQL / 预览。确认后再 `APPLY=1`。
- 会话里 `export APPLY=1` 必须能压过 `env.sh`（脚本已用 `APPLY="${APPLY:-0}"`）。
- 密码、`SSHPASS`、MinIO/ES 密钥 **不要写入 `env.sh`、不要进 git**。
- B 独有模型 / 自定义工具：人在 A 配好再填 `p4/model-map.csv` / `tool-map.csv`。禁止拷密钥。工作流 JSON 里用到的模型/工具未映射时，`p5/30-apply.sh` 生成 SQL 会失败。
- 不兼容向量库只进 `logs/p5/vector-exceptions.tsv`，**不自动重解析**。
- 本阶段验收：数据完整、引用能对上、迁入工作流在 A 能跑、A 原 type=3 与原会话未被改。不含网关切流量、备份恢复。切流量见 `p6/cutover-runbook.md`。

涉及表（无业务 DDL）：控制表仅 A 的 `fusion_batch` `fusion_map` `fusion_exception` `fusion_a_baseline`；业务读写见 [`README.md`](./README.md)「涉及数据表」。


```bash

```

B 上要有 `sshpass`（密码登录 A 时）。缺则脚本会尝试安装。


## 5. MinIO

```bash
APPLY=0 bash p5/20-copy-minio.sh
# 应打印 jobs=N, N 与文件映射条数相当 (含预览/bbox 等, 可多于 knowledgefile 行)
APPLY=1 bash p5/20-copy-minio.sh
```

- 只写 **新对象键**（按 A 新 file id 改名）。不覆盖 A 已有键。
- A 若拉不到 Docker Hub 的 `mc` 镜像，脚本会从 B `docker save` 导过去。
- B 上已删的对象会记 missing，不中断整批。核对 `copied` / `missing`。
- 现场容器名不是自动发现结果时：`export B_MINIO_CONTAINER=... A_MINIO_CONTAINER=...`

## 6. Milvus / ES

```bash
APPLY=0 bash p5/22-copy-vectors.sh
# jobs=copy|convert|skip ; exceptions=need_reparse 不自动解析
# pending 必须为 0 才能 APPLY=1
APPLY=1 BATCH_NO=fusion-YYYYMMDD bash p5/22-copy-vectors.sh
```

- 写入名 `b{B知识库id}_...`，禁止撞 A 原空间 Collection/Index。
- 目标已在 A（续跑）→ `skip`，不覆盖。
- B Collection 不存在 → 进 `logs/p5/vector-exceptions.tsv`，元数据仍在 MySQL，检索须批准后重解析。
- A ES 若开了 basic_auth，脚本读 backend 容器的 `BS_ELASTICSEARCH_SSL_VERIFY`，不要只拷 URL。
- B mapping 里的 `custom_bm25` 在 A 没有该插件时会降为默认 BM25（正文仍迁入）。

## 7. OpenFGA

```bash
APPLY=0 bash p5/35-apply-openfga.sh
APPLY=1 bash p5/35-apply-openfga.sh
```

只写本批迁入资源的 owner / 组 manager / 角色与部门授权。不改 A 原空间 Tuple。  
`A_OPENFGA_URL` 是 **A 机上的** `http://127.0.0.1:8080`（经 SSH 在 A 执行 curl）。续跑对已存在 tuple 视为成功。

部门授权还依赖 B OpenFGA 导出（挂在 `10-export` 末尾）。B OpenFGA 不可达时只迁 `roleaccess` 角色授权。

## 8. 验收（必须跑到绿灯）

```bash
BATCH_NO=fusion-YYYYMMDD bash p5/40-verify.sh
# APPLY=1 且 MinIO/向量已拷完后:
BATCH_NO=fusion-YYYYMMDD VERIFY_STORAGE=1 bash p5/40-verify.sh
```

`40-verify` 硬门：

- A 原 type=3 行数不降，空间元数据/原文件 id/原 chat_id 仍在
- 五表 + 会话/消息 map 条数与 dump 一致（消息按 dump 里有会话的 chat 计）
- 本批悬挂 FK = 0
- `VERIFY_STORAGE=1`：MinIO 抽查新键存在；检索金标 overlap@5 ≥ `GOLD_MIN_HIT`（默认 0.8）

人还要在 **A UI** 抽几条迁入工作流跑通。脚本不代替这一步。

发布（改 status）另走，且默认不下：

```bash

# CONFIRM_PUBLISH_FLOWS=1 APPLY=1 bash p5/36-publish-flows.sh
```

## 12. 排障要点（演练踩过，脚本已收）

| 现象 | 处理 |
|---|---|
| `APPLY=1` 仍按 0 跑 | `env.sh` 不要写死 `APPLY=0`；用 `APPLY="${APPLY:-0}"`，会话 `export APPLY=1` |
| MinIO 只拷了 1 个对象 | `ssh`/`docker` 吃掉了 `while read` 的 stdin；作业循环走 fd 3，远程 stdin `/dev/null` |
| A 拉不了 `minio/mc` | 从 B `docker save` 导入 A |
| ES 401 | 带上容器 `BS_ELASTICSEARCH_SSL_VERIFY`（basic_auth） |
| ES `custom_bm25` 400 | 导入时去掉该 similarity |
| QA 向量 `file_id` 未映射 | type=1 占位 id 写成 0，不丢向量 |
| 续跑把已写入 Collection 当成例外 | 本批 `b{src}_` 已存在 → skip，并保留 knowledge_id 过滤表达式 |
| OpenFGA curl `host: application` | Header 必须放进远程 `bash -s` 脚本，不能当 ssh argv |
| 金标 top1 对不齐 | convert 会重建 HNSW；硬门是 overlap@5，不是 top1 |
| `t_variable_value` / `share_link` / `chatmessage` PK | 生成器已补列与 ID 间隙；不要用过期包 |

某步 `FAIL` 就停，不要跳。日志在 `logs/`，总账 `logs/ledger.tsv`。
