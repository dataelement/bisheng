## 表 1：领域对象归属

每个领域对象只能有一个 Owner Feature，负责定义该对象的写入行为（创建、更新、删除）。其他 Feature 只能「读取」或「调用」Owner 的 Service。

| 领域对象 | Owner Feature | 说明 |
|---------|--------------|------|
| 工具价格配置（按租户 + 二级工具） | F001-credit-billing-extension | 创建、更新（带乐观锁）、删除、子公司初始化复制、API/MCP 工具刷新联动清理 |
| 工具调用扣费明细 | F001-credit-billing-extension | 按次写入、异步投影落库、故障恢复重算 |
| 月度用量汇总（扩展类型维度） | F001-credit-billing-extension（继承自 F062 / F016） | 在既有月度用量汇总上扩展 `MODEL` / `TOOL` 类型维度并维护统一重建一致性 |
| 积分与计费全局总开关 | F001-credit-billing-extension | 取代原 `dsh.enabled` 对积分/计费的耦合门控；桌面端基础接入常驻可用，总开关仅控制积分、计费与额度拦截 |
| 模型调用扣费来源标记（应用/工作流/托管应用/调试/免登录） | F001-credit-billing-extension（继承自 F062 / F016） | 扩展模型调用明细来源标注及助手/工作流/托管应用计费准入与开放 API 免计费分流 |
| 免登录「运行身份」成员配置 | 原免登录配置模块（非 F001） | F001 仅读取运行身份并按本租户成员计费，不在积分底座绕过租户成员校验 |

**规则**：
- 非 Owner Feature 的 AC 中不得出现其他对象的「创建/修改/删除」行为，只能「读取」或「调用」Owner 的 Service。
- 新增领域对象时必须先更新本表。

## 表 2：跨 Feature 不变量（INV-N）

全局业务约束，任何 spec 的 AC **不得与之矛盾**。

| ID | 不变量描述 | 涉及领域对象 | 来源 spec |
|----|-----------|------------|---------|
| INV-1 | **单周期例外唯一性**：全平台所有计费场景中，仅「任务模式（深度研究）」在单次任务生命周期内（发起时校验一次额度，含中途 `ask_user` 恢复）实时入账且不做额度拦截；其余所有计费场景（日常对话、知识空间、助手、工作流、托管应用、工具试运行等）的模型调用与收费工具调用均须实时校验额度（`used < limit`）并实时扣费。 | 统一积分账本、模型调用、工具调用 | F001 |
| INV-2 | **开放 API 与托管应用严格身份分流**：外部开放 API（服务账号 / 代员工，调用助手、工作流、深度研究、模型网关）一律不算账、不查额度、不写账本；仅平台内托管应用调用模型网关纳入扣费，且携带过期/伪造访问人令牌时维持报错拒绝（26504），不得降级转嫁给应用负责人。 | 开放 API、托管应用、模型网关 | F001 |
| INV-3 | **账本守恒不变量**：同一用户单月实时账本始终满足「各模型已用 + 各工具已用 = 本月总已用」，故障恢复重建前后余额严格一致；历史无工具分项月份按 0 兼容。 | 统一积分账本、月度用量汇总 | F001 |
| INV-4 | **多租户成员隔离不可绕过**：计费主体必须为当前租户的有效成员；积分模块不得为免登录跨租户默认操作员放行租户成员校验。 | 积分准入、月度投影、免登录配置 | F001 |
| INV-5 | **工具设价与多租户独立性**：所有工具（内置/API/MCP，含联网搜索、网页读取）统一按「租户 + 二级工具」存储「次数（默认 1）+ 价格」，不区分引擎；新建子公司复制内置工具时复制一次总公司价格，之后总/子租户完全独立不同步；仅超级管理员与本租户管理员可改价。 | 工具价格配置 | F001 |
| INV-6 | **桌面端接入与积分总开关解耦**：取消 `dsh.enabled` 配置后，企业客户端（桌面端）基础接入常驻可用；全局「积分与计费总开关」（默认开启）关闭时，仅停用积分计费与额度拦截并隐藏前后端积分/价格入口，保留平台原有模型可见范围配置；关闭期间调用不追溯补扣。 | 积分与计费全局总开关、模型可见范围、桌面端接入 | F001 |
