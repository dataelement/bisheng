# Feature: 模型状态手动验证

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
> spec 只回答 **做什么 / 验收标准 / 不做什么**；所有 How 一律在 [design.md](./design.md) 与 [tasks.md](./tasks.md)。

**关联 PRD**: [3.0.0-beta1 需求文档 §模型状态增加手动验证功能](https://dataelem.feishu.cn/wiki/Ifj6wOgSmiyClfkMQySc7ZmvnNb)
**优先级**: P1
**所属版本**: v3.0.0-beta1
**依赖**: 无

> **范围边界**
> - **本次纳入**：
>   - 模型管理列表：鼠标悬停模型行时，状态右侧显示「更新状态」按钮；点击对该模型发起一次真实验证请求，按结果把状态更新为「正常」或「异常」
>   - 状态列右侧新增「状态更新时间」列；验证完成后同步刷新，顶部 Toast「状态已更新」
>   - 记录状态更新时间（新增持久化字段，随每次状态检测/验证写入）
> - **本次明确排除**：
>   - **定时自动检测**（Celery beat 轮询模型健康）——本期只做手动触发，避免无谓的模型调用成本
>   - **批量验证**（一键验证全部模型）——本期逐个手动
>   - **运行时调用失败自动回写状态**——业务调用链路失败不影响状态字段，状态仅由「配置时检测 + 手动验证」两个入口写入（维持现状语义）

---

## 1. 用户故事

作为 **平台管理员**，
我希望 **在模型管理页直接点一下就能验证某个模型当前是否真的可用，并看到上次验证时间**，
以便 **不必跑到其他页面手动发起测试对话来确认模型状态**。

---

## 2. 验收标准

> AC-ID 在本特性内唯一。

| ID | 角色 | 操作 | 预期结果 |
|----|------|------|---------|
| AC-01 | 管理员 | 鼠标悬停在模型所在行 | 状态右侧出现「更新状态」按钮；移出后隐藏 |
| AC-02 | 管理员 | 点击「更新状态」 | 按钮进入 loading 且不可重复点击；系统对该模型发起一次真实验证请求 |
| AC-03 | 管理员 | 验证的模型正常响应 | 状态更新为「正常」（包括此前为「异常」的模型）；状态更新时间刷新；顶部 Toast「状态已更新」 |
| AC-04 | 管理员 | 验证的模型响应失败/超时 | 状态更新为「异常」，悬浮可查看异常原因；状态更新时间刷新；顶部 Toast「状态已更新」 |
| AC-05 | 管理员 | 查看模型列表 | 状态列右侧展示「状态更新时间」列，显示该模型最近一次状态检测（配置时检测或手动验证）的时间；从未检测过的显示占位（如「—」） |
| AC-06 | 管理员 | 对已下线（online=关）的模型点击「更新状态」 | 同样可验证并更新状态（验证不受上下线开关影响） |

---

## 3. 边界情况

- 验证请求超时（上限见 design.md §2，约 30s）时按「异常」处理，异常原因注明超时。
- 同一模型的验证进行中，该行按钮禁用；不同模型可各自独立验证。
- 新增/编辑模型配置时的既有自动检测行为保持不变，且同样写入状态更新时间。
- 页面权限沿用模型管理页现有管控，不新增权限点。
