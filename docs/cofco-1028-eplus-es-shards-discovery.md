## 2. 已核实的当前行为

### E+ 机器人

- `bisheng/eplus/infrastructure/connection_client.py`：一个机器人客户端持有到 E+ 服务端的 WebSocket，认证后接收消息；连接可以服务多个用户。连接数不能替代使用人数。
- `bisheng/eplus/infrastructure/connection_supervisor.py`：按租户与机器人配置取得 Redis 租约，维持单活连接，包含连接、认证、重试、被接管与退出路径。
- `bisheng/eplus/worker.py`：连接状态写回 `eplus_bot_config`，认证时更新 `last_connected_at`。该历史状态没有持续存活时间证明，不能直接将 AUTHENTICATED 行数当作实时在线数。
- `bisheng/eplus/domain/models/eplus.py`：持久化接收消息、会话与问答轮次，包含外部用户标识、时间、准入轮次和回复状态。
- `bisheng/eplus/domain/services/message_service.py`：先持久化去重消息，再校验身份和准入。收到消息不等于通过准入，重复回调不应重复计入问答量。
- `docs/observability/metric-log-contract.md`：已有 BS_METRIC 契约；`eplus_notify` 统计通知发送，并不代表机器人问答的使用人数或长连接数。
- 前端已有机器人配置与连接状态展示；用户已确认本次仅提供指标日志。

### 频道文章 ES

- `bisheng/channel/domain/es/article_index.py`：业务索引名固定为 `channel_articles`，同步和异步创建函数共用 ARTICLE_SETTINGS，当前没有显式指定 `number_of_shards`。
- `bisheng/channel/domain/services/article_es_service.py` 与 `channel_service.py`：频道文章写入和查询使用上述索引名。
- `bisheng/core/context/manager.py` 与 ES manager：频道文章走默认 `get_es_connection`；正常初始化注册的是 `settings.get_search_conf()`，缺少上下文时的懒加载兜底却读取 `get_telemetry_conf()`。此条已在 Design 阶段沿 main/worker 初始化调用核实并纠正；迁移必须完整初始化，取得与正常服务相同的默认 ES 连接，不能依赖兜底。
- `bisheng/common/services/config_service.py`：配置通过共享 settings 加载，新 YAML 顶层键需要在 Settings 注册。
- 尚未连接任何部署环境核实实际索引类型、模板、副本数、数据量或集群容量。上述结论为当前分支代码证据。

## 3. 已确认的 E+ 范围

用户已确认：仅沿用结构化指标日志，供现有监控采集；后端只记录事件，不新增 Redis 聚合，不新增统计查询接口或管理页面。

| 后端记录的事件 | 监控侧可计算的指标 |
| --- | --- |
| 自包含请求终态：是否准入、最终结果、原因、结果发生时间、接收到结束的耗时及统计识别信息 | 已结束请求/问答量、成功率、失败/拒绝量、重复回调处理量 |
| 终态中的稳定脱敏用户及消息/会话识别信息 | 窗口内有已准入问答结束的使用人数、完成回答人数、会话数 |
| 连接尝试、认证、断开、重连、被接管 | 连接过程及错误分类 |
| 有效连接的周期存活事件 | 按连接去重并结合过期规则计算的存活连接数 |

- 用户在本轮要求按评审建议修改，并提出仅消费结束日志；本版将新增问答指标收敛到自包含终态日志，免去监控侧关联接收/排队/开始事件。消息去重及跨请求的用户去重仍然需要。
- 人数和成功率统一按业务结果发生时间归属窗口；使用人数是窗口内有已准入问答结束的去重用户，暂不包括未结束请求，不能解释为实时在线人数或窗口内新发请求人数。
- 回答成功率 = 已准入成功问答数 /（已准入成功问答数 + 已准入失败问答数）；准入前拒绝、重复回调、未结束请求不进分母，零样本时无成功率。
- 统计窗口完全由监控侧选择；后端不设置近 5 分钟、近 24 小时人数窗口，也不执行人数聚合或周期扫描。
- 同一租户内跨节点、机器人与会话的用户识别一致；不同租户隔离。租户整体人数不能相加机器人分别去重的人数。
- 成功须问答正常完成且最终回复获 E+ 成功确认，不表示用户已读。拒绝与重复回调单独分类。
- 连接不等于使用者；只凭问答终态无法判断当前连接数，连接仍记录生命周期与存活事件，进程崩溃后由监控按超时失效。
- 仅记录稳定脱敏标识，不输出消息内容、Secret、原始用户标识或完整媒体临时 URL。
- 沿用现有尽力日志语义；不建立可靠投递、全局统计缓存或历史统计回填。正式入口与机器人调试调用区分。

## 4. 频道文章分片与迁移范围

- 增加专属频道文章索引配置，例如 `channel_article_index.number_of_shards`，默认值为 3，校验为正整数。
- 同步和异步创建索引读取同一配置。旧 YAML 缺少配置时默认采用 3；已有索引不在应用启动时自动重建。具体配置键、复制与切换实现留待 Design 确认。
- 配置只调整频道文章索引的主分片数，不同时调整知识库、遥测索引或现有副本策略。
- 运维迁移脚本从与服务一致的 `config` 和共享 settings 读取目标分片数，不另设一套默认值。
- 默认 dry-run：显示实际索引、当前分片、配置目标、迁移计划、数据量与前置条件，不写入数据。显式 apply 才执行。
- 分片数已符合配置时幂等跳过；源不存在、目标冲突、配置非法、集群异常时给出清晰的退出结果。
- 任意目标主分片数采用预建目标索引再 reindex 的方式；保留源索引实际 mappings、分析器、相关 settings、文档 ID、routing 与数据内容。
- 已确认采用维护窗口：暂停并排空频道文章所有写入方，在源索引建立写保护后迁移，避免复制期间的新增、更新、删除遗漏；这意味着文章写入短暂停止，不承诺在线无损双写。
- 已接受的评审建议：完整性基准覆盖停写完成前所有已确认写入，包括尚未检索可见的新增、更新和删除；目标不得漏新增、保留旧内容或恢复已删文章。以此基准校验身份、数量、内容及目标分片数，不能仅核对两侧旧可见视图。具体刷新顺序在 Design 落地。
- 脚本需支持源名已经是 alias 与仍为具体索引两种情况；首次将同名具体索引转换为 alias 存在删除原索引的步骤，必须先有可验证恢复的备份，切换方案在 design 阶段明确。
- 切换前失败保持源数据可用；切换后回滚必须明确处理新写入，不声称只换回 alias 就能保留全部数据。
- 输出可续查的任务与目标索引信息；保留备份和失败目标供人工检查，不静默清理。
- 交付脚本与 README、dry-run/apply 示例；本任务当前不执行生产迁移。
