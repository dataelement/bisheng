> 与 [组件-Input输入框.md](组件-Input输入框.md) 配套：尺寸、外壳、状态、聚焦全部引用输入框，本文只写数字输入的差异。颜色见 [基础-色彩规范.mdx](基础-色彩规范.mdx)、图标见 [基础-图标规范.mdx](基础-图标规范.mdx)、移动端通则见 [基础-多端适配原则.md](基础-多端适配原则.md)。
> 调研 antd InputNumber（controls / handleVisible: auto / changeOnBlur 回正）、Arco InputNumber（embed 右侧叠放 / button 两侧加减 / onChange reason outOfRange）、Semi InputNumber（innerButtons 悬停显示 / shiftStep 10 / 长按连发）、Semrush Intergalactic（失焦回正到边界、不报错）、Carbon Number input（越界报错、到边界禁用按钮、键盘上下键）后制定。设计师 2026-10-21 拍板四项：独立成组件不并入 Input；步进按钮右侧上下叠放；悬停才显示；越界报错（业内多数是失焦自动回正，此处取 Carbon 路线）。

## 1. 什么时候用

数字输入框用来录入**一个需要拿来计算的数**——数量、比例、时长、阈值。

- 值是能加减的数，且常常只需小幅调整，用数字输入框。
- 范围很大、不需要精确值（音量、温度），用滑块；既要拖又要精确，滑块旁并排一个数字输入框，见 [组件-Slider滑块.md](组件-Slider滑块.md)。
- 手机号、验证码、证件号这类「由数字组成的文本」不能加减，用基础输入框，见 [组件-Input输入框.md](组件-Input输入框.md)。

## 2. 结构

数字输入框 = 输入框外壳 + 右侧一列步进按钮。

| 部分 | 规则 |
|---|---|
| 外壳 | 与输入框完全一致：尺寸、圆角、描边、聚焦环见 [组件-Input输入框.md](组件-Input输入框.md) §3、§5 |
| 数值 | 左对齐，与输入框里的文字同一位置 |
| 单位 | 放后缀文字（%、秒、条），排在步进按钮右侧、收住外壳右端；**不写进数值本身** |
| 步进按钮 | 数值右侧的一列，上「加」下「减」各占一半高；没有单位时贴外壳右侧，有单位时排在单位左边 |

### 2.1 步进按钮

- **只在鼠标悬停到输入框上时出现**，平时隐藏，让一列数字输入框看起来和普通表单一样安静。
- **位置常驻预留**：没出现时右侧也空着那一列宽，出现时只是显形——不压住数值、不让文字跳动。
- 列宽 20px，各档一致；与数值区之间、上下两个按钮之间各一条 1px 分隔线（border-base）。
- 图标用 Up / Down 箭头，固定 12px，不随档放大；常态 hint 文字色，悬停该按钮时加浅灰底（fill-subtle）、图标转次要文字色。
- **到了边界，那一侧的按钮转禁用**（图标转禁用色、「禁止」光标）：值等于最大值时「加」不可点，等于最小值时「减」不可点。
- 按住按钮连续加减；键盘 ↑ / ↓ 加减一个步长，Shift + ↑ / ↓ 加减 10 个步长。
- **鼠标滚轮不改值**——滚动页面时指针扫过输入框就把数改了，用户往往察觉不到。

| ✅ 推荐 | ❌ 不推荐 | 原因 |
|---|---|---|
| 步进按钮悬停才显形，位置常驻预留 | 悬停时按钮盖在数值末尾上 | 盖住的正是用户在看的那几位数，显隐一次文字还跳一下 |
| 有单位时步进按钮排在单位左边：「30 ⇅ 秒」 | 单位后面再接步进列：「30 秒 ⇅」 | 步进列平时隐藏，单位右边就空出一大块，单位看起来飘在框中间 |
| 单位写在后缀：「30」+「秒」 | 数值框里填「30 秒」 | 单位进了数值就不能加减、也不能计算，还得靠解析把它剥掉 |
| 滚轮只滚页面 | 滚轮经过输入框就加减 | 滚动是在找东西，不是在改数；被误改的值用户很难发现 |

## 3. 尺寸

跟输入框三档走（24 / 32 / 40px，medium 默认），见 [组件-Input输入框.md](组件-Input输入框.md) §3；步进列各档都是 20px 宽、两个按钮均分高度。

- **宽度按最大值的位数给**：最大值 3 位数就别撑满一行，框的长短本身在提示能填多大的数。
- 独占一行的表单字段例外，照输入框「同级字段等宽」走。
- **与滑块并排时用 small 档**，见 [组件-Slider滑块.md](组件-Slider滑块.md) §5.1。

## 4. 数值规则

### 4.1 范围、步长与精度

- **有边界就设最小值、最大值**，并在 placeholder 或说明文字里写出来（如「1～100」）——用户在输入前就该知道范围，而不是错了才知道。
- 步长默认 1；小数步长（0.1、0.5）同时决定默认精度。
- 精度按业务需要定，显示时按精度补齐（精度 2 时 1 显示为 1.00）。

### 4.2 不替用户改值

**组件不自动修改用户输入的值**：越界不回正、小数位超出精度不四舍五入，统一报错（见 §5.2），由用户自己改。悄悄改掉的数，用户往往在提交后才发现不对。

- 非数字字符输不进框（字母、空格、第二个小数点）；只有最小值小于 0 时才允许输负号。
- 粘贴「1,000」这类带千分位的数，去掉逗号后照常识别。
- **清空就是空**，不自动填回 0 或默认值；字段是否必填交给表单校验。

| ✅ 推荐 | ❌ 不推荐 | 原因 |
|---|---|---|
| 输入 150（最大 100），失焦后报错「请输入 1～100 之间的数」 | 输入 150，失焦后悄悄变成 100 | 用户以为提交的是 150，回头才发现被改成 100，比报错更难排查 |
| 清空后保持空，必填交给表单校验 | 清空后自动填回 0 | 「没填」和「填了 0」是两回事，自动补 0 会把空值伪装成一个有效值 |

## 5. 状态

### 5.1 通用状态

常态、悬停、聚焦、只读、禁用、错误、警告七态，外壳样式全部见 [组件-Input输入框.md](组件-Input输入框.md) §5.2。数字输入框的差异只有：

- **只读、禁用时步进按钮不出现**，悬停也不出。
- 错误、警告态下步进按钮照常可用，用户可以直接点着改回范围内。

### 5.2 越界与精度报错

- **失焦时校验**：值超出范围、或小数位超出精度，外壳转错误态，下方用危险色文字说明怎么改——「请输入 1～100 之间的数」「最多保留 2 位小数」。
- **改对立刻消红**：报错之后用户边打字边校验，值一回到合法范围就恢复常态，不必再失焦一次。
- **越界时点步进按钮，先回到最近的边界值**：150（最大 100）点「减」变成 100，越过的那一侧按钮禁用。这是用户主动的操作，不算替他改值。
- 越界值阻断提交，与输入框「错误阻断提交」同一规则。

| ✅ 推荐 | ❌ 不推荐 | 原因 |
|---|---|---|
| 失焦后才报错，改对立刻消红 | 每敲一个字就校验报错 | 想输 50，敲下「5」还没打完就红了——提前报错是在打断用户 |
| 报错写「请输入 1～100 之间的数」 | 报错写「数值无效」 | 只说错了不说范围，用户还得猜边界在哪 |

## 6. 移动端适配

跨组件通则见 [基础-多端适配原则.md](基础-多端适配原则.md)；外壳的触屏规则（16px 字号防缩放、热区、small 升 medium）同输入框 §6。

| 项 | 触屏 / 窄屏规则 |
|---|---|
| 步进按钮 | **不显示**：触屏没有悬停，而半高按钮远小于 44px 触达底线，点不准；改为直接输入 |
| 键盘 | 弹出数字键盘（允许小数时带小数点） |
| 越界报错 | 与桌面一致 |

## 7. 深浅色

所有颜色（外壳、分隔线、按钮悬停底、图标、报错色）都走语义 token，深色模式由 token 自动翻转，无单独取值。

## 落地（给实现窗口）

1. 组件放 `packages/ui/src/components/InputNumber/`，**复用 Input 外壳**（`Input/shared.ts` 的外壳 cva、三档取值、`status`、`borderless`、`.input-no-zoom` / `.input-touch-hit`），步进列作为外壳内的右侧插槽；单位走 `suffix` 插槽，排在步进列**右侧**（步进列两侧各一条分隔线），单位右边只留外壳的常规内边距。由 `@bisheng/ui` 导出。
2. `<input type="text" inputMode="decimal">`（整数场景 `inputMode="numeric"`），**不用 `type="number"`**：原生 number 会带浏览器自带微调箭头、响应滚轮、接受 `e` 科学计数法。无障碍：`role="spinbutton"` + `aria-valuemin` / `aria-valuemax` / `aria-valuenow` 落在 `<input>` 本身（spinbutton 必须是拿焦点的那个元素），报错显示时置 `aria-invalid`；两个按钮 `aria-label` 走 `increaseLabel` / `decreaseLabel` prop（组件库不带文案，「增加」「减少」的 i18n key 由接入方三语同 PR 加），`tabIndex={-1}`（键盘走 ↑↓，不进 Tab 序）。
3. 步进列：宽 20px（`w-5`），`border-l border-border-base`，两按钮中间 `border-t border-border-base`；按钮透明底，`hover:bg-fill-1`，图标 `Outlined.Up` / `Outlined.Down`（bisheng-icons 0.2.36 已有）12px 内联样式钉死（同清除图标的教训：行容器 `[&_svg]:size-*` 会压过图标 class），`text-text-3`，按钮 hover `text-text-2`，禁用 `text-text-4 cursor-not-allowed`；触屏按下 `fill-2` 走 `coarse-pointer:active:`，同按钮口径。
4. 显隐：外壳 `group`，步进列 `opacity-0 group-hover:opacity-100`，`readOnly` / `disabled` 时整列不渲染；**输入区 `padding-right` 恒预留 20px**，显隐不改布局。`hoverOnlyWhenSupported` 已全局开启，触屏下 `group-hover` 不生效，再以 `@media (hover: none) and (pointer: coarse)` 把整列 `display:none` 兜底（§6）。
5. 交互数值：长按 300ms 后开始连发、每 100ms 一步；Shift + ↑↓ = 10 × step；**不监听 wheel**。步进结果按 `precision` 用十进制字符串运算（避免 0.1 + 0.2 浮点误差），结果 clamp 到 `[min, max]`；当前值越界时点按钮 = 先落到最近边界（§5.2）。
6. 校验：输入过滤只拦「非数字、多余小数点、min ≥ 0 时的负号」；粘贴去千分位逗号。范围 / 精度校验在 `blur` 触发首次报错，之后 `onChange` 实时重算、合法即清（「迟报早清」）。**组件不 clamp、不 round 用户输入**；`onChange` 回传解析后的 number 与校验结果（越界 / 超精度 / 合法），空值回传 `null`。错误文案由调用方通过 `errorMessage(error)` 按 `min` / `max` / `precision` 拼句（组件库契约：所有文案走 prop，不内置默认句）；`onErrorChange` 在「显示出来的错误」变化时触发。
7. 现状（2026-10-21 扫描，口径：`client/src` 的 *.tsx，grep `<InputNumber`）：旧 `client/src/components/ui/InputNumber.tsx` 基于 `rc-input-number`，22 处 / 8 文件，全在设置面板（`Endpoints/Settings/*` 4 个、`SidePanel/Parameters/DynamicSlider`、`Nav/SettingsTabs/Speech/*` 3 个），多为「滑块 + 数字框」并排。旧壳样式 `max-h-5 border-gray-300`、无聚焦态、`displayName` 误写为 `'Input'`。**`rc-input-number` 默认失焦回正越界值，与本文 §4.2 冲突**：迁移不能直接包 rc 了事，要么自建（推荐，第 1 条），要么关掉其回正并改走报错。迁移批次照总纲节奏，设计师点名后再动。

## 待决策清单

- 键盘聚焦但鼠标未悬停时，步进按钮是否显示：现按设计师「悬停才显示」只认悬停，键盘用户靠 ↑↓ 加减；若有反馈再议。
- 移动端需要频繁加减的场景（如购买数量）：v1 触屏隐藏步进按钮，若出现此类场景，再定「左右两侧 −/+ 大按钮」的移动端形态。
- 千分位显示：金额、数量类大数是否显示千分位、聚焦编辑时是否去掉，等真有金额场景再定。
- 范围输入（两个数字框组成「从～到」）未建档，等有场景再定。
