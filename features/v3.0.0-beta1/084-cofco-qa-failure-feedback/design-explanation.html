图上的边界，用这几条核对

D 分类看真实调用对象

模型连接/认证/限流/余额及供应方内部数据库错误 → 模型服务；DM/MySQL、池等待、Redis、ES、Milvus调用错误 → 数据库；MinIO访问/签名 → 对象存储。锁占用、空队列、NoSuchKey正常缺失、Python/协议错误分别判断。

D 网络、认证与业务不混用

确认设备/入口链路失败才归网络；确认企业会话认证失败才归单点登录，沿用登录入口。平台权限、用量、许可证、文件格式和资源删除保持业务提示。OpenFGA/工具/沙箱自身错误来源不足时通用反馈，权限规则不改。

K 名称先核验，再附在步骤上

已选名单只是候选；业务适配器经现有权限入口批量核验。知识对象ID与空间ID不混用。模型编造的名字不采信。每轮一次映射、每步内存读取；核验失败不阻断原检索，不改提示词/白名单。

E / H 开始、补充、结束都不能丢

参数未完整先中文兜底，可靠参数到齐后同一call_id只补一次；结束帧和历史保留同一快照。开始/结束乱序、恢复旧调用没有可靠快照时不猜名。前端两个缓存关口比较可见字段值，避免名称不刷新或每token重绘。

G / H 名称快照与显示限制

改名不回改本人既有历史，旧记录无可靠来源就兜底、不逐条查库补名。个人库通用称呼；分享/他人只读无法证明名称可见则省略。名称纯文本渲染，最长两行，展开看全名，手机不依赖Tooltip。

H 标题和次数保持含义

内部工具名仍为search_knowledge_base，只换展示。相同空间重复8次仍是8条调用；同名不同ID不合并。标题用“检索”，end不等于成功。失败提示与名称并列，只读视图无执行按钮。

D → F → G 安全与一致性

只带已有可见名称，不为补名称再查依赖。包装保留原异常链，跨队列/存储显式序列化；不能只靠进程内变量。统一脱敏detail/exception和只读响应，不发凭据、内部URL、SQL或堆栈；原原因在受控日志。

两项上线与范围

仅日常和任务，不改工作流、独立问答页、platform、SSO开户、开放API或api/request.ts全局拦截。后端先更新，前端后更新；旧端忽略新键，新端对非法/未知版本回退。旧失败仅有可靠来源时读取映射、不回写；只有Connection error则通用反馈。三语同步、复用现有组件/状态库，视觉变化另行确认。

为什么这样选、什么时候重新评估
  • D保留来源而不按错误文字猜：11090和Connection error不能可靠区分对象；SDK或边界改变、出现误分类样本时修适配器并补回归。
  • C恢复与H分类分开：替换原error_type会影响恢复行为；恢复机制真要变时另行设计。
  • G复用字段：本次不需要独立错误生命周期；将来做跨会话检索、工单或独立统计时再评估专表。
  • K另附名称而不改工具名：避免破坏模型调用、图标及步骤归类；工具接口本身变更时再迁移。
  • K批量查名而不每行查：避免额外查询及授权放大；候选将来只含ID时仍统一批量解析。旧历史全面补名若另有明确要求再设计。
  • 遵循constitution C1—C8及本版本release-contract；公共层不导入领域，权限只走已有统一入口，共享数据不以本地文件为真相；MySQL/DM8均复用现有兼容字段。正式契约、实现任务和运行门禁仍待确认后推进。
  • 不在本期建设全局错误治理、SDK异常全集、外部网关改造、联系人通讯录、自动通知、根因定责或统一错误工单。
