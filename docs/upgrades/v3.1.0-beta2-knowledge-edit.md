# beta2 文件、文件夹 edit 动作补齐

## 原因与行为

版本修改已经检查物理文件 `edit`，但历史 Catalog 的 `edit.resource_types`
缺少 `folder`、`knowledge_file`，导致文件夹编辑者继承到文件后仍没有处理相似文档入口，
直接检查动作返回 25001。只更新镜像无法修改已经持久化的 CURRENT Catalog。

本修复同时补齐首次安装的动作定义和存量升级。标准 editor/manager 按原动作等级获得
文件夹与文件 edit；viewer 不获得 edit。自定义模型只有显式选择 edit 才获得此动作，
不从 rename 推断；保留动作的 active/level、模型选择、同级授权策略和可见性来源。
文件 CUSTOM 边界继续阻断父级继承，跨租户仍拒绝。

版本关联要求来源和目标主版本均有文件 edit；合并要求当前和来源文件 edit；设主版本、
忽略相似要求实际文件 edit。读取仍用 visible，历史删除仍要求 edit + delete。

## 存量升级

先部署包含本修复的代码，并在维护期间暂停 Catalog 配置发布。使用后端容器的同一份
`config`、数据库、Redis、OpenFGA 配置运行。普通资源授权关系不需要重建。
以下 ID 是执行人的真实用户 ID，用于审计，不是账号名，也不代替登录认证。

```bash
cd /path/to/src/backend
export config=/path/to/live-config.yaml
python scripts/upgrade_knowledge_edit_scopes.py plan
python scripts/upgrade_knowledge_edit_scopes.py apply --plan-digest PLAN_DIGEST --operator-id USER_ID --idempotency-key knowledge-edit-20261125
python scripts/upgrade_knowledge_edit_scopes.py verify
```

默认命令是只读 plan；检查 `missing_scopes`、`impact` 后使用返回的 `plan_digest`。
apply 前会再次计算影响，基线或授权来源变化时拒绝，重新 plan 后使用新操作 key。
输出 `verified` 且 SQL/FGA Catalog 指针一致才算完成。返回的 edit_active/level 保留原值；
原先禁用 edit 的环境不会因升级被启用。已升级环境重复执行不会创建新发布或扫描成员表。
首次安装无需运行升级，但可运行 verify。

升级复用原 Catalog 台账、写入 fence、tuple 暂存、模型测试、原子 active 指针切换和
SQL 完成确认；不改资源 Grant、assignee、继承模式或业务文件，不写新 OpenFGA schema。
脚本核对 ACTIVE 授权模型与当前代码和远端模型的 checksum；不匹配时先完成原授权模型升级。
未完成 F048 或缺少完整 Catalog 的旧环境不能跳过前置迁移。

## 中断恢复

保留日志中的 `draft_id`、原 operator ID、原幂等 key：

```bash
python scripts/upgrade_knowledge_edit_scopes.py resume --draft-id DRAFT_ID --operator-id USER_ID --idempotency-key knowledge-edit-20261125
```

只有本工具原操作的草稿允许恢复。预约后尚未构建完整草稿，重跑原 apply；未到期 DRAFT/
PROJECTING 会重新暂存并完整验证，不能把部分 tuple 当成成功发布。FGA 已切换但 SQL
确认丢失时，沿原 reconcile 完成同一条发布，不创建第二个 release。过期或 FAILED_CLOSED、
指针异常、前驱已变更时保持拒绝状态，按既有 Catalog 故障恢复流程处理；不可手工取消 fence、
改 CURRENT、删草稿或直接补权限 tuple。不要把旧 Catalog 切回作为回滚。

影响摘要改为 `catalog-impact-v2` 的增量摘要，并修复仅改动作适用范围时遗漏标准模型的统计。
部署前尚未发布的普通 Catalog 草稿必须重新规划，旧摘要不能跨代码版本继续确认。

## 成本与验证范围

Grant 与成员均按 200 行游标分页，影响摘要增量计算；内存不累积成员或资源集合，
不穷举用户 × 资源。完整 plan/apply 对关系扫描五次：外部预览、执行时重新预览、冻结草稿、
暂存前和提交前校验，分别用于防止预览后变更及暂存期间变更。verify 只验证 Catalog 和
实际指针/模型；无变更路径不扫描 Grant/成员。运维窗口仍需按现场规模评估。

本地真实 SQL Catalog、原发布器和模型语义测试覆盖新装、存量、继承、独立授权、普通用户、
自定义模型、停用动作、关联/合并/设主版本接口、幂等、中断、过期、提交确认丢失、CLI 原生
连接池释放。OpenFGA 传输由内存模型语义执行器替代；本地验证不代表现场 MySQL/DM8 与
OpenFGA 服务验收。现场使用普通账号刷新有效动作后检查相似入口，并验证直接接口拒绝边界。
