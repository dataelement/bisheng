# 一、结论

## 1.1 一句话

**把 dsh desktop 当作《鉴权 PRD》「场景四 · 员工自己选的工具」的又一个消费者接入：登录复用平台登录、凭据用个人访问令牌、模型走平台的 OpenAI 兼容模型面、开放范围与额度在同一份授权面配置、用量与审计落在既有的逐条调用记录上。**

不引入任何新概念。新增的是四处扩展：个人访问令牌放开「模型调用」权限位并支持一人多把；模型协议面接受自然人主体；模型升格为可授权资源；额度与用量视图（原顺延到 v3.1 的两项提前）。

## 1.2 三层机制

| 层 | 回答的问题 | 做法 | 依据 |
|---|---|---|---|
| **登录** | 谁在用 | 桌面端把员工带到平台登录页（含企业 SSO），登录后平台签发一把**个人访问令牌**自动带回桌面端；员工不填任何密钥 | 《鉴权 PRD》§4.10 个人访问令牌：主体是自然人、权限动态继承本人、随人事级联失效 |
| **模型** | 能用什么 | 员工手里只有这把个人令牌；厂商密钥只在平台模型管理页；桌面端经平台的 OpenAI 兼容模型面调用，只看得到**被授权给本人**的模型 | PRD-1 DEV-02 模型协议面；F051 spec |
| **治理** | 能用多少、用了多少 | **授权**答「能不能」（按人 / 部门 / 用户组开放模型），**额度**答「能用多少」（RPM / TPM / 月预算），**逐条记录**答「谁、什么时候、用哪个模型、多少 token」；三者在管理面同处配置与查看 | 《鉴权 PRD》§4.10.7 三道闸门；PRD-1 GOV-04 |

## 1.3 复用、规划中、新增

| 件 | 状态 | 本需求要做的 |
|---|---|---|
| 平台自签发凭据底座（哈希存储、明文只显示一次、5 秒撤销、租户隔离） | **已实现** | 直接复用 |
| 个人访问令牌 `bs-pat-` | PRD 已定，**未实现** | 本需求是它的第二个消费者：放开 `model:invoke` 权限位；一人多把、按接入端签发 |
| OpenAI 兼容模型协议面（F051） | spec 已定，**未实现** | 凭据主体扩展到自然人；可用范围 = 租户已启用 ∩ 授权给本人 |
| 模型的按人 / 部门授权 | **新增** | 模型升格为可授权资源，复用既有权限弹窗 |
| 额度：RPM / TPM / 月预算 | **新增**（PRD-1 §5.2 顺延项提前） | 平台没有限流基础设施，从零建 |
| 逐条模型调用记录 | F051 已定 | 加「持有人」「接入端」维度 |
| 用量聚合视图 | **二期**（2026-09-03 裁定本期不做） | 管理面按人 / 部门 / 模型 / 时间的汇总与导出移二期；本期只有逐条记录（F051 既有）与员工本月用量自查（额度计数顺带得到） |
| 桌面端登录（两个入口）与「账号与企业」 | **新增**（dsh 企业扩展包 + 桌面壳三处小改） | 入口 A 桌面端发起；入口 B 固定链接（管理员分发，或工作台头像菜单「DSH Desktop」）自动拉起桌面端（§4.1）；整套功能由「DSH Desktop 接入」开关控制、默认关 |
| 授权密钥与席位 | **新增** | 桌面端接入全功能开源；不配密钥免费 10 个席位，密钥抬高席位上限或不限（§8.5） |

## 1.4 分期

- **一期（跑通闭环）**：桌面端登录（两个入口）+ 个人访问令牌 + 模型协议面 + 模型开放范围 + 逐条记录 + 月预算硬闸 + 授权密钥与席位上限。员工登录一次即可在 dsh 里用企业模型，管理员能开放模型、设月预算、查到每一次调用。
- **二期**：RPM / TPM、用量看板、金额预算、部门共享池。
- 工作量粗估与锚点见 §六。

# 二、需求

## 2.1 谁在用

| 角色 | 要什么 |
|---|---|
| 员工 | 在 dsh desktop 里用企业身份登录一次，之后直接用企业模型；不找模型地址、不管密钥 |
| 租户管理员 | 决定哪些模型开放给谁、每人能用多少；看得到谁用了多少；能随时收回 |
| 安全与合规 | 员工离职即失效；每次调用可追溯到人；厂商密钥不出平台 |

## 2.2 与《鉴权 PRD》场景四的关系

场景四的判据是「**谁来配这把密钥**」：前三类场景由管理员配，场景四由员工自配。dsh desktop 正是员工自己选的工具，属场景四。三处相同、三处不同：

| 维度 | 场景四（技能包接通用 Agent） | dsh desktop |
|---|---|---|
| 密钥由谁配 | 员工本人 | 员工本人（但由桌面端自动完成） |
| 权限来源 | 持有人本人的既有权限 | 相同 |
| 离职 / 停用 | 令牌级联失效 | 相同 |
| **拿密钥的方式** | 到平台复制一串明文粘给 Agent | **登录即拿到**，员工不接触密钥明文 |
| **开放的能力** | 知识检索（数据流出组织） | **模型调用**（提示词流入平台，数据不流出） |
| **治理关注点** | 泄密 | **成本与滥用**，因此需要额度 |

后两处差异决定了本方案比场景四多出两块：登录流程与额度控制。

## 2.3 需求归纳

1. 员工在桌面端**登录一次即用**，登录方式与平台一致（账号密码或企业 SSO）
2. 员工**不持有任何厂商密钥**，也不需要知道模型服务地址
3. 员工在 dsh 里**只看到被授权给自己的模型**，多一个是越权、少一个是功能不可信
4. 超出额度时**得到明确提示**，而不是莫名报错
5. 管理员能看到**谁在用、用了多少**，并能按人 / 部门 / 模型收回或调额
6. 员工离职、被停用后，桌面端**立即失效**，不依赖任何人记得去吊销；换租户不打断，令牌随人走

## 2.4 dsh 侧的接入形态（取证事实）

dsh 的「设置 → 模型」支持**添加自定义 provider**：填 Provider ID、Base URL、API 协议、凭据、模型 ID 列表即可，凭据存本地凭据文件、**环境变量优先**。这意味着平台只要提供一个 OpenAI 兼容地址 + 一把令牌 + 一份模型清单，dsh 不需要任何改造就能用；桌面端要做的只是把这三样自动填进去。

自定义 provider 的协议只有三种：`openai-completions`、`openai-responses`、`anthropic-messages`，F051 的对话补全面对应第一种；对经代理转发的 DeepSeek 推理内容，dsh 有 `compat.thinkingFormat` 兼容项可声明。dsh 还提供程序化的扩展点（profile 扩展包、动态注册 provider、写凭据接口、设置页插槽），§4.6 的桌面侧实现即建立在这些扩展点上。

# 四、方案分述

## 4.1 统一登录：桌面端登录，浏览器完成、自动返回

> 交互演示：[S1 登录页与确认页](https://claude.ai/code/artifact/8ab14900-e95b-42dd-8a5c-3f2750e046b0#s1) · [S2 工作台头像菜单弹窗](https://claude.ai/code/artifact/8ab14900-e95b-42dd-8a5c-3f2750e046b0#s2:open) · [S8 深链确认](https://claude.ai/code/artifact/8ab14900-e95b-42dd-8a5c-3f2750e046b0#s8) · [完整剧本](https://claude.ai/code/artifact/8ab14900-e95b-42dd-8a5c-3f2750e046b0#script)

### 两个入口，一套签发

| 入口 | 谁发起 | 员工怎么开始 | 登录结果怎么回到桌面端 |
|---|---|---|---|
| A · 桌面端发起 | 员工 | 在桌面端「设置 → 账号与企业」填平台地址、点「登录企业账号」 | 平台页面回传到桌面端在本机监听的地址 |
| B · 固定链接 | 管理员或员工 | 打开管理员分发的**固定链接**（如 `https://<平台地址>/desktop-login`），或在工作台头像菜单点「DSH Desktop」→「打开 DSH Desktop」；在网页里登录 | 平台页面用自定义协议 `dsh-desktop://…` 拉起本地桌面端 |

两个入口共用同一张「桌面端登录」页、同一次确认、同一套令牌签发，只差登录结果回到桌面端的方式。入口 B 的链接**人人相同、不过期、不含任何身份或凭据**，可写进入职手册或做成二维码。**不设「授权码」这一产品概念**：浏览器与桌面端之间的交接凭证是实现细节，一次性、短时、不向员工展示，也不提供复制粘贴。

### 入口 A 流程

| # | 谁 | 做什么 | 看到什么 |
|---|---|---|---|
| 1 | 员工 | 在「设置 → 账号与企业」填一次平台地址，点「登录企业账号」 | 系统浏览器被打开 |
| 2 | 平台 | 打开「桌面端登录」页。已登录平台的直接进第 3 步；未登录的走平台既有登录（账号密码 / 企业 SSO），登录后回到本页 | 平台登录页 |
| 3 | 员工 | 确认页：「允许 DSH Desktop 使用你的身份调用企业模型」，显示设备名、用途、有效期至；点「允许」。席位已满时此处改为提示「本实例桌面端席位已用完，请联系管理员」，不签发 | 确认页 |
| 4 | 平台 | 签发一把个人访问令牌（接入端 = `dsh-desktop@设备名`），把登录结果回传到桌面端在本机监听的地址 | 浏览器页面提示「可以回到桌面端了」 |
| 5 | 桌面端 | 收到后自动写入 dsh 的自定义 provider：平台模型面地址 + 令牌 + 可用模型清单 | 「账号与企业」显示已登录、姓名与租户、有效期至、本月用量 |
| 6 | 员工 | 在 dsh 里选企业模型开始用 | 模型下拉只列被授权给自己的模型 |

**兜底**：桌面端本机监听地址不可用（端口被占、安全软件拦截）时，页面提示「回到桌面端点『重试』」，桌面端换端口重新发起；不提供授权码复制粘贴。

**退出登录**：桌面端调平台接口吊销这把令牌并清本地配置。换一台设备登录 = 新签一把，互不影响。

### 入口 B 流程

| # | 谁 | 做什么 | 看到什么 |
|---|---|---|---|
| 1 | 管理员 / 员工 | 管理员把固定链接发给员工（企微 / 邮件 / 入职手册 / 二维码）；或员工在工作台头像菜单点「DSH Desktop」→「打开 DSH Desktop」 | — |
| 2 | 员工 | 打开链接；未登录的走平台既有登录（账号密码 / 企业 SSO） | 平台登录页 |
| 3 | 员工 | 同入口 A 的确认页：「允许 DSH Desktop 使用你的身份调用企业模型」，点「允许」（含席位检查） | 确认页 |
| 4 | 平台 | 页面自动尝试打开 `dsh-desktop://login?server=…`（带一次性交接凭证），同时常驻「打开 DSH Desktop」按钮 | 浏览器询问「要打开 DSH Desktop 吗」 |
| 5 | 桌面端 | 被系统拉起（未运行则启动），弹确认「连接到 <平台地址>，身份 <姓名>？」，确认后向平台换取令牌，其余同入口 A 第 5 步 | 桌面端前置，「账号与企业」显示已登录 |
| 6 | 员工 | 在 dsh 里选企业模型开始用 | 模型下拉只列被授权给自己的模型 |

**兜底**：未安装桌面端时页面给「下载 DSH Desktop」；浏览器不允许自动跳转或拦截了协议时，点常驻的「打开 DSH Desktop」按钮。不提供授权码复制粘贴。

### 深链安全规则

| 规则 | 说明 |
|---|---|
| 链接里只有一次性交接凭证 | 交接凭证 5 分钟内用一次即作废，绑定生成它的平台地址，不向员工展示；令牌本身永不出现在任何 URL |
| 桌面端兑换前必须确认 | 自定义协议可被任意网页触发，桌面端收到深链先展示平台地址与姓名，员工确认后才向该地址兑换 |
| 只对确认过的平台地址发起 | 防止恶意页面把桌面端引到别的服务器 |
| 浏览器行为如实告知 | 浏览器会先询问「要打开 DSH Desktop 吗」；部分浏览器不允许无点击的自动跳转，因此按钮常驻 |

### 令牌规则

| 项 | 规则 | 依据 |
|---|---|---|
| 主体 | 登录的员工本人 | 《鉴权 PRD》§4.10.2 |
| 权限位 | 本期只有 `model:invoke`（模型调用与模型清单） | 开放判据 = 「出现只需要它的真实消费者」（《鉴权 PRD》§4.10.3），dsh desktop 即是 |
| 可访问范围 | 权限位 ∩ 持有人本人的模型授权（§4.3），每次调用现判、不做快照 | 与 §4.10.3 两层判定同构 |
| 接入端标签 | `dsh-desktop@设备名`，签发时由桌面端上报 | 个人中心与台账据此区分技能包令牌与桌面端令牌 |
| 有效期 | 租户配置的默认时长（默认 1 年），员工不可选；到期桌面端回到未登录态并提示重新登录 | §4.10.5 |
| 级联失效 | 持有人被停用 / 删除时立即失效，桌面端下次调用即被拒并提示；**换租户不失效**——令牌随人迁移到新租户（不重签，审计记一条「令牌随持有人迁移」），可用模型按当前租户与当前授权现判 | §4.10.5；「换租户」一项为本方案改判（D-21） |
| 管理员短路 | 管理员登录桌面端照常享受短路，但不跨租户 | §4.10.4（D17） |
| 一人多把 | 每个接入端一把；个人中心「授权管理」列表可逐个吊销 | §七 D-1 |
| 席位 | 签发前检查实例席位：持有效桌面端令牌的自然人数 ≤ 上限（免费 10，密钥可抬高或不限）；已占席者换设备不占新席；超限不签发并提示 | §8.5 |

### 与「OAuth 授权服务器」的边界

《鉴权 PRD》§六明确不做完整 OAuth 2.0 授权服务器，D18 取消了面向第三方平台的授权服务器。本方案不与之冲突：这是**第一方桌面端**的登录流程——客户端固定（只有 dsh desktop）、只允许回传到本机监听地址、无刷新令牌、无第三方注册、无权限协商。§六措辞需补一句限定（见 §七连带修订）。

### 工作台入口与治理

- **工作台头像菜单「DSH Desktop」**：与「审批中心」「消息提醒」同形态——菜单项拉起弹窗，位置在「消息提醒」之后。弹窗四件事：「打开 DSH Desktop」（即入口 B，员工已登录，直接进确认与拉起）、「下载 DSH Desktop」（下载地址由管理员在系统配置里设置）、「**授权管理**」（只列本人 DSH Desktop 的登录授权：接入端、创建时间、最后使用、有效期至、状态，逐个吊销）、本月用量与剩余额度。技能包等其它工具的个人令牌不在此处，仍走《鉴权 PRD》§4.10.6 的个人中心。
- **管理员台账**（闸门二）：本租户全部个人令牌，新增「接入端」与「占席」列；可按人批量强制吊销。
- **「DSH Desktop 接入」开关**（闸门一）：一个开关同时管**展示**与**放行**。开 = 工作台菜单入口、桌面端登录页、模型「开放范围」入口、系统配置席位与授权区、台账接入端列全部出现，桌面端令牌可签发可调用；关 = 以上全部不出现，桌面端登录页显示「本平台未启用 DSH Desktop 接入」，已签发令牌**停用不撤销**，重开即恢复。**默认关，管理员一键开**。层级沿用《鉴权 PRD》两层：部署级（运维配置）+ 租户级（租户管理员界面即时生效）；租户级原「允许个人令牌用于模型调用」勾选升格改名为本开关，技能包的「允许用于知识检索」勾选保留。单租户只显示租户级一个，部署级未开时置灰说明原因。依据：升级不应静默打开新能力；两种用途数据流向相反，各自独立开关。

## 4.2 企业模型服务：员工只持令牌，模型走平台

- **承载面**：F051 模型协议面（OpenAI 兼容子集：对话补全含流式 + 模型列表）。dsh 侧以「自定义 provider」接入，桌面端登录后自动写入、每次启动刷新模型清单，员工零配置。
- **「员工不持厂商密钥」如何成立**：厂商密钥只存在于平台模型管理页；桌面端只有个人令牌；令牌泄漏的爆炸半径 = 本人被授权模型的使用权 + 本人的额度，5 秒内可吊销。
- **相对 F051 spec 的两处扩展**：

| 项 | F051 spec 现定 | 本需求扩展 |
|---|---|---|
| 凭据主体 | 服务账号密钥、托管应用运行期凭据 | 加**自然人**（个人访问令牌），仍是「自身身份模式」，请求流程不变 |
| 可用模型范围 | 服务账号 = 租户已启用（租户级） | 自然人 = 租户已启用 **∩ 授权给本人**（§4.3） |
| 调用记录归属 | actor = 密钥、subject = 服务账号自身 | actor = 令牌、**subject = 持有人**（闸门三：区分本人在平台用与桌面端拉取） |

其余规则原样沿用：模型名 = 模型管理页原名、跨服务商同名拒绝裸名并给限定名、模型下线 60 秒内对新调用生效、裸协议透传不建会话不留正文、错误对客户端可读。

- **风险与前置动作**：dsh 带 DeepSeek 协议扩展（推理内容、工具调用的流式形态）。模型面是裸透传、理论上不受影响，但**必须在一期早期用 dsh 真机跑一遍 PoC**，确认工具调用与流式在平台面上完整可用。只讲 Anthropic 协议的路径本版不承诺（F051 决议-1）。

## 4.4 额度控制：授权答「能不能」，额度答「能用多少」

> 交互演示：[S3 额度列与取最大](https://claude.ai/code/artifact/8ab14900-e95b-42dd-8a5c-3f2750e046b0#s3:open) · [S9 员工超额与失效提示](https://claude.ai/code/artifact/8ab14900-e95b-42dd-8a5c-3f2750e046b0#s9)

### 先回答产品经理的问题

**额度不由 RBAC 管，也不由 ReBAC 管；它跟着授权走，但存在授权旁边、由另一套机制执行。**

| | 授权（ReBAC） | 额度 |
|---|---|---|
| 回答 | 这个人能不能用这个模型 | 能用多少 |
| 存哪 | 权限引擎（只回答是 / 否，不存数字） | 授权账本旁的**额度策略表**，一条授权可附带一条额度 |
| 在哪配 | 模型「开放范围」弹窗 | **同一个弹窗**，每行授权后面多一列「额度」（可留空 = 用上级默认） |
| 谁执行 | 模型面入口第 ② 步 | 模型面入口第 ③ 步，Redis 计数 |

结论：**从交互上放在一起（管理员配一次），从机制上分开（引擎只管是否，计数器管多少）。** 不需要给角色配额度：角色是权限载体不是组织维度，且模型额度需要按模型设，落在授权行上最自然。

### 策略维度

| 维度 | 取值 | 说明 |
|---|---|---|
| 主体 | 租户默认 / 部门·用户组 / 用户 | **按人与按部门可同时配，所有命中的明确额度行取最大值**（与授权「并集」语义一致）；一条都没有才用租户默认。代价：无法把某人压到低于其部门 / 用户组的额度，需要个别收紧时二期加「个人上限」标记（D-13） |
| 模型 | 全部模型 / 指定模型 | 指定模型优先于全部 |
| 指标 | RPM（每分钟请求数）/ TPM（每分钟 token 数）/ 月 token 预算 | 三项各自可空 |
| 部门行的语义 | **组内每人各自一份** | §七 D-5；部门共享池二期 |
| 计数口径 | 只计经模型协议面的调用 | 与 §4.3 作用范围一致；平台内使用不计入个人桌面额度 |

### 执行语义

| 指标 | 超限行为 | 员工看到 | 依据 |
|---|---|---|---|
| RPM / TPM | 拒绝本次，返回 OpenAI 429 语义与 `Retry-After`；滑动窗口。TPM 按已消耗 token 判定，允许最后一次越界 | dsh 原生显示限流并按提示重试 | 讲 OpenAI 协议的客户端本就处理 429 |
| 月预算 | **走完当前回合再拦**：在途响应完成，之后的新调用被拒；自然月 1 日重置 | 「本月企业模型额度已用完，如需继续请联系管理员」 | PRD-1 §5.2「预算触顶走完当前回合再拦截 → 转管理员」 |
| 触顶通知 | 站内信通知持有人与租户管理员；审计记一条「额度触顶」；台账与用量视图高亮 | — | 闸门二、三 |

### 与既有机制的关系

- 服务商级「每日调用上限」（模型管理页既有）继续作为**租户总量兜底**，不与个人额度混用。
- 平台已有「每月模型 token」配额键但从未接线执行，可作为**租户级月预算**的落点，避免第二套账。
- 预算按 **token** 计。金额预算需要先建模型单价表，列二期。

**成本红线**：平台今天没有任何 HTTP 层限流基础设施，最接近的可复用原语在 Redis 故障时放行而非拒绝，不能直接用于鉴权场景。额度这块的估算**不可按「接个现成库」计**。

# 八、付费化与落点：全功能开源、免费 10 席位，授权密钥抬高上限

## 8.1 结论

1. **桌面端企业接入的全部功能进开源版，免费 10 个席位。** 登录（两个入口）、模型转接、模型开放范围、额度、用量看板、令牌台账全部开源可用；不配置密钥时最多 10 名员工可接入桌面端。凭据底座、个人访问令牌、模型协议面、模型授权、逐条记录本就在 v3.0 发版契约里。
2. **付费买的是席位。** 超过 10 人联系 dataelement 获取授权密钥，密钥只做一件事：抬高席位上限（数字或不限）。付费代码与开源同仓、不单独部署、网关零改动。
3. **不放进 bisheng-gateway。** 这条链路需要的东西网关一样都没有：模型路由真相、租户上下文、权限引擎、令牌校验、token 计量；它又不在开源部署里、按客户分叉、自身鉴权与密钥管理薄弱。放进去等于在 Java 里复制一份平台核心，正是《产品方案》§3.4 已否决的「两层漂移」。
4. 许可靠合同与密钥约束，与平台既有付费能力同一现实，不做技术防破解。

## 8.2 免费档与付费的边界

| 件 | 免费档（不配密钥） | 付费（配密钥） |
|---|---|---|
| 桌面端登录（两个入口）、「账号与企业」卡片 | 可用 | 可用 |
| 模型转接、模型开放范围授权 | 可用 | 可用 |
| 额度 RPM / TPM / 月预算、员工自查（用量看板二期） | 可用 | 可用 |
| 令牌台账、审计 | 可用 | 可用 |
| **席位数**（持有效桌面端令牌的自然人） | **10** | **密钥写的上限，或不限** |
| 到期 | — | 回落免费档，存量不硬断 |

依据：功能不分档、只数人头，规则最简单；小团队零门槛试用；与 D-11「不靠削开源功能」一致。凭据底座、个人访问令牌、模型协议面、模型授权、逐条记录本就是开源交付项（release-contract、PRD-1 GOV-10）。

## 8.4 为什么不放网关

**不适合，五条：**

| # | 网关现状 | 后果 |
|---|---|---|
| 1 | 模型转发所需的一切都在 Python：对 19 家服务商的参数翻译、厂商凭据（平台库）、模型名解析、租户上下文、权限引擎判定；网关零 LLM 代码、无权限引擎客户端、无租户概念（根租户 ID 硬编码） | 放网关 = 在 Java 里重写一份平台核心，即《产品方案》§3.4 已否决的「两层漂移」；记账也会变成两套 |
| 2 | 网关不认 `Authorization: Bearer`，代理的 HTTP 请求不做任何鉴权，含 `api/v2/` 的 WebSocket 一律跳过身份 | 令牌校验仍要落平台，网关只能是一跳透传 |
| 3 | 网关限流是进程内令牌桶，不跨实例、不落 Redis，按部门 / 资源、无用户与 token 维度 | RPM 勉强，TPM 与月预算做不了——它们需要响应里的 token 数，只有模型面知道 |
| 4 | License 只有 trial / pro 与到期日，无席位或模块字段；且只在启动与每小时校验、不拦单个请求 | 当不了席位门控，要用得先改 License 模型 |
| 5 | 网关不在开源部署里、独立部署、按客户分叉；自身管理端点无鉴权、密钥硬编码在仓内 | 放核心链路进去 = 只有装网关的客户才有模型面（与「开放能力层可独立部署」冲突），且把凭据签发与模型代理放在防护最弱的一层 |

**适合的三件窄事：**

| 事 | 说明 |
|---|---|
| SSO 前门 | 既有能力零改动：桌面端登录页在浏览器里打开，网关的 SSO 回调照常写 cookie，登录页即可识别身份 |
| 路由放行 | 新路径放 `/api/v1/**` 或 `/api/v2/**` 下即自动代理（模型面 base URL 建议落在此范围）；否则加 route 与 nginx location |
| 与授权密钥的关系 | 平台自验授权密钥，不依赖网关；装了网关的客户两套授权并存、互不影响 |

## 8.5 门控机制：免费 10 席位 + 授权密钥

| 项 | 规则 | 依据 / 先例 |
|---|---|---|
| 席位定义 | 持有**至少一把有效桌面端令牌**（接入端为 dsh-desktop、未过期未吊销）的自然人；一人多设备只占一席；技能包个人令牌不占席 | 数人不数设备，员工换电脑不吃席位 |
| 计数范围 | 按部署实例计，多租户合并计数，不按租户分配 | 授权密钥是实例级；2026-09-03 拍板 |
| 免费档 | 未配置密钥 = 10 席，功能完整；前提是管理员打开「DSH Desktop 接入」开关（默认关） | 2026-09-03 拍板 |
| 密钥是什么 | dataelement 签发的签名串：客户名、席位上限（数字或不限）、到期日、**实例指纹（必绑）** | 公钥内置开源代码、私钥留在 dataelement——比网关 License 把公私钥都打进 jar 更稳；网关有 `finger.sh` 生成指纹但从不校验，本方案校验 |
| 在哪配 | 管理后台「系统配置 → 授权」：显示**本实例指纹**（管理员复制发给 dataelement 签发）、席位已用 / 上限、到期日，粘贴密钥保存即验签，指纹不匹配即拒收；自动化部署可改用配置文件 / 环境变量 | 落点 = 平台配置里从未使用的 `license_str` 字段 |
| 检查时机 | 桌面端登录签发令牌前（入口 A / B 同一处）；已占席的人重新登录、换设备不占新席 | 只在签发处判定一次 |
| 超限表现 | 第 11 人（或超出密钥上限）登录：确认页显示「本实例桌面端席位已用完（10 / 10），请联系管理员」，不签发令牌；管理员在授权区看到用量与「联系我们获取授权密钥」 | 员工与管理员各看各的提示 |
| 释放席位 | 管理员吊销该人全部桌面端令牌，或其令牌全部到期 / 级联失效 → 席位释放；**不按不活跃自动释放** | 与令牌生命周期同源，不另建状态；2026-09-03 拍板 |
| 到期 / 降档 | 不再签发超出上限的新席位；已登录设备用到令牌到期或被吊销为止；提前 30 天顶部横幅提醒超管；台账高亮超出上限的席位 | 2026-09-03 拍板：回落免费档、存量不硬断；横幅复用 LicenseBanner 形态 |
| 与网关 | 平台自验，不依赖网关；装了网关的客户两套授权并存、互不影响 | 网关 License 无席位字段（§8.4） |

三条规则：① 密钥只管席位数，不管功能。② 密钥绑定实例指纹，迁移主机须重新签发。③ 授权密钥与商业版整体（`BISHENG_PRO`）、看板 PRO（`BISHENG_DASHBOARD_PRO`）相互独立，各自售卖、各自配置，互不并入。

**如实写代价**：付费代码公开可见，校验可被改掉，保护靠合同与密钥——与看板 PRO、网关 License 同一现实。
