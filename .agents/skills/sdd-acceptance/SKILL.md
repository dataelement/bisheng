# Sdd Acceptance

先读 [阶段交接规则](../sdd-workflow/references/stage-contract.md) 和[岗位协作与提测规则](../sdd-workflow/references/qa-handoff.md)。

## 入口与工程归属

本入口服务测试岗位，由测试工程师或用户明确要求以该岗位开展验收时使用。研发入口交付待验收后已经结束，不因为本 skill 存在就自动调用、触发远端 CI 或等待验收结果。
从用户说明、当前已明确的验收工程或团队配置核实目标位置和任务范围。UI、真实集成及 E2E 脚本、配置与结果保存在该工程，不写入研发前后端项目的 test/。无法确定工程时先分析材料和准备场景，开始写脚本前取得目标位置。
按[产物存放与维护约定](../sdd-workflow/references/artifact-storage.md) 关联研发稳定特性标识、需求版本和确定构建；验收用例与每次运行结果沿用本验收工程的目录登记。跨工程引用包含仓库／版本／路径或可访问制品，避免将应用特性包默认当作 QA 产物根目录。
AI 辅助测试岗位工作，不能将自身执行报告写成测试工程师已经确认或签字。

## 接收与准备

核对研发交付的需求／设计依据、范围、代码或构建、开发验证证据、接口与配置变化、待验收项和环境前提。对版本不一致、交接缺失或环境缺口明确记录。沿用待测构建对应的词典修订、已确认概念增量和技术映射，不能拿最新词典替换旧构建预期；发现分歧回报对应需求／设计来源，不自行改定义。
测试工程师可在需求闭环后提前使用 [sdd-test-cases](../sdd-test-cases/SKILL.md) 的独立验收用途设计场景，在已指定验收工程准备脚本；UI 和真实环境执行仍等待研发交付及当前验收条件具备。
正式验收用例按 [HTML 交付约定](../sdd-workflow/references/html-delivery.md) 和 [测试用例写作与完成标准](../sdd-test-cases/references/case-writing-standard.md) 交付 HTML，关联有效需求与设计版本；测试脚本和执行证据的原生格式不因此改变。
实现自动化时遵循验收工程的现有框架和入口，按需求验证用户可观察行为与必要数据状态。共享需求和契约，独立维护脚本与数据，不把开发 mock 直接用于证明真实链路。
若当前请求只要求生成用例或脚本，完成指定准备后交付结果，不擅自扩大为真实环境执行。

## 选择验收范围

真实依赖集成、真实部署 E2E 和全部 UI 测试由测试岗位在研发交付后组织。若研发尚未交付，本岗位可以继续准备验收用例、脚本和条件，不自动代替研发运行开发测试，也不提前执行 UI 或真实环境验收。
优先复用 CI 或共享验收环境，不要求开发者在个人电脑部署线上整套系统；核对关键依赖版本、配置、权限、协议及相关拓扑，记录差异。性能容量另按目标验证，不把小规模功能通过解释为线上容量通过。

读取有效需求与验收条件、相关用例、实际修改和审核结果。简单 Bug 从原问题、正确预期和直接影响进入。
逐条关联需要验收的行为与可信验证方式，复用仍适用的已有用例。
优先使用能验证目标的最低成本层：单元、组件、接口、集成、浏览器或实际运行检查，按风险选择。
并发、重试、真实性能和外部依赖需要相应可信环境；mock 验证只能支撑被保留的真实逻辑。
复用开发期已有且仍有效的 mock／隔离证据，优先补足真实依赖兼容性缺口，再跑关键业务旅程和必要失败路径。接口契约一致、实际业务正确和真实 E2E 通过分别核对；不为了验收重复所有开发用例。
界面可见行为在必要时采用组件或浏览器验证；一般静态检查不能证明用户看到的结果正确。

## 执行与核对

实际运行必要检查，记录代码对应关系、环境、命令或操作、结果、断言和必要输出。
核对业务返回、数据或状态变化、外部副作用，以及失败／拒绝后的行为；不能只断言成功状态码。
为相关重要失败路径进行适度故障模拟；不要把依赖或被验证逻辑全部模拟掉。
测试数据与清理限定在本次创建的资源，使用适当测试环境，避免破坏无关数据。

汇总实际用例数、失败、跳过及重要覆盖缺口。空套件、全跳过、dry-run 和旧代码报告均不构成当前通过证据。
发现产品缺陷时按需求／用例、版本、环境、步骤、实际与预期及证据回报研发，不自动修改应用代码或把验收脚本放回应用 test/。研发完成修复与自身回归并交付新版本后，本岗位定向复测；两个岗位不自动串回一次本地研发等待。
运行后版本发生相关变化时，重跑受影响验收。用例自身有误时核对需求与契约，不为了通过擅改预期。

## 结果与完成标准

逐项使用“通过／不通过／未验证／不适用”，区分测试执行结果与逐条需求验收。
缺环境、权限、工具或外部服务时标记实际未验证范围、影响及最小补验动作；继续独立可做的检查。
范围内必要验收均有可信通过证据，阻塞问题已处理，才可给出该范围的验收执行结论；岗位确认由测试工程师负责，未经确认不能宣称人工签字完成。
部分完成按实际范围报告；人工接受某项风险仍应保留其未验证或未解决事实。

输出交付范围、需求映射、执行摘要、真实性边界、未解决事项及剩余风险。
发布相关修改在适用时核对兼容、监测和恢复安排；代码回滚不能自动恢复已改变数据。
提交、合并、部署或外部通知按用户的具体授权执行。
