## 1. 需求来源与确认边界

用户要求 Bisheng 后端向外提供 MCP 工具，接受首期使用 `X-Developer-Token`，随后要求实施。
首期规划为一个 `/mcp` 入口和一个 `search_knowledge` 工具，复用现有检索服务、绑定用户身份和资源权限。

需求发现与规格阶段已确认。用户于 2026-10-08 回复“开始实施”，授权在本规格范围内完成任务、实现及验证。
客户端需要能够为远程 HTTP MCP 请求配置自定义请求头。标准 OAuth 接入不属于本期。

## 2. 概述与用户故事

作为外部智能体接入方，我希望用管理员签发的开发者 Token，通过 MCP 获取有权访问的知识片段和文档来源，
以便使用自己的模型回答问题，并沿用 Bisheng 的权限和数据范围。

首期不调用 LLM 生成答案，不创建新的业务资源，不进行文件或知识数据修改。

## 4. 验收标准

| ID | 角色 | 操作 | 预期结果 |
|----|------|------|---------|
| AC-01 | 运维人员 | 未配置服务或显式关闭后访问 `/mcp` | 未配置时入口默认启用并要求 Token；显式关闭返回 HTTP 404；现有 REST 可继续使用。 |
| AC-02 | 接入方 | 开启服务，携带获准 Token 初始化并调用 `tools/list` | 握手成功；只返回 `search_knowledge`，输入输出 Schema 与 §6 一致。 |
| AC-03 | 接入方 | 请求缺失、无效、禁用或绑定已失效的 Token | HTTP 401；返回已有鉴权业务码，不执行工具、不创建业务数据库会话。 |
| AC-04 | 接入方 | 使用空白名单、未覆盖 `/mcp`、不允许当前 HTTP 方法或 IP 不匹配的 Token | HTTP 403；资源业务未执行；不改变旧 REST 对空白名单的处理。 |
| AC-05 | 接入方 | 触发 Token 限流或限流基础设施不可用 | 分别返回 HTTP 429、503；不执行工具。 |
| AC-06 | 接入方 | 查询有权知识资源，或有效查询无结果 | 返回 MCP 结构化结果及兼容的文本结果；片段包含既有来源字段；空结果为 `chunks=[]`、`total=0`。 |
| AC-07 | 接入方 | 指定无权资源、混合有权/无权知识库或触发权限系统异常 | 保持既有严格授权及失败关闭规则；响应不包含无权正文、名称、ID 或链接。 |
| AC-08 | 接入方 | 传入未知工具、非法参数、超出上限参数或任意身份参数 | 按 MCP 约定明确拒绝；不进入检索，不切换执行身份。 |
| AC-09 | 接入方 | 检索超时或下游异常 | 已进入工具执行的失败返回 `isError=true`，不返回空成功或 traceback、内部连接信息。 |
| AC-10 | 多个接入方 | 两个绑定不同用户/租户的 Token 并发检索，含失败与取消 | 各自使用自身身份和租户；结束后上下文复位、会话关闭；后续请求不受影响。 |
| AC-11 | REST 使用方 | 复跑已有检索、外部用户与来源链接场景 | 既有成功和错误响应、用户选择与超时行为不变。 |
| AC-12 | 运维人员 | 正常启动关闭、异常启动、显式关闭后重启；使用不同 Host/Origin 调用 | 生命周期资源无泄漏；显式关闭后入口不可用；任意 Host/Origin 均可进入 Token 鉴权和协议处理。 |
| AC-13 | 审查人员 | 检查改动、日志及 SDK 真实 HTTP 联调证据 | 不引入数据库迁移或依赖升级；日志无 Token 明文、检索原文或来源签名；协议端到端验证有实际证据。 |
| AC-14 | 跨域接入方 | 从任意 Origin 对 `/mcp`、`/mcp/` 发送预检及正常/错误请求，检查其他 REST 路径 | MCP 预检允许请求头和 POST；成功及鉴权失败响应有 `Access-Control-Allow-Origin: *`，不启用跨域 Cookie 凭证；其他路径继续原 CORS 策略。 |

## 5. 架构决策

| ID | 决策 | 结论 | 理由 |
|----|------|------|------|
| AD-01 | 协议实现 | 复用已安装、已锁定的官方 `mcp 1.27.1` 和 `FastMCP` | 当前依赖具备服务端能力，无需新库或升级。 |
| AD-02 | 部署 | 挂载现有 FastAPI，使用无状态传输 | 共用业务基础设施，不引入新的服务部署和会话存储。 |
| AD-03 | 业务复用 | 从 REST endpoint 提取共享检索 Service，两种入口调用同一业务编排 | 保留权限、超时与来源行为，避免复制检索逻辑。 |
| AD-04 | 鉴权 | 复用开发者 Token 服务，为 MCP 增加显式入口授权 | 避免空白名单旧 Token 自动扩大能力；不修改旧 REST 默认语义。 |
| AD-05 | 工具授权 | 首期静态注册唯一工具；只有通过入口鉴权的调用方可列出与调用 | 一个工具无需新增权限实体；未来多工具授权另做规格。 |
| AD-06 | 身份 | 仅 Token 绑定身份，参数禁止切换用户 | 明确最小权限边界，避免复用 REST 外部身份代理能力造成范围扩大。 |
| AD-07 | 配置 | 在既有 `mcp` 配置中新增 `server` 子块，启动时加载 | 保留 `mcp.enable_stdio`；缺少 server 子块或 enabled 时默认开启，显式 enabled=false 仍关闭；不再读取 Host/Origin 白名单。 |
| AD-08 | 协议包装 | `/mcp` 使用 MCP JSON-RPC；既有 REST 继续使用统一业务响应 | MCP 有独立协议契约，不能使用 `resp_200/resp_500` 替代协议结果。 |

## 6. API 与工具契约

### 6.1 HTTP 入口

| Method | Path | 描述 | 认证 |
|--------|------|------|------|
| POST | `/mcp` | 初始化、协议通知、工具列表和工具调用 | `X-Developer-Token` |
| GET / DELETE | `/mcp` | 首期不提供独立 SSE 流或会话删除，入口完成鉴权后明确返回 405 | 鉴权及显式路由规则仍适用 |

规范地址为 `/mcp`；不得产生 `/mcp/mcp`。`/mcp/` 可以直接等价处理，但不依赖携带凭证的跨地址重定向；
路由授权统一使用 `/mcp`，白名单示例为 `METHOD_PATH + POST + /mcp`。
有效 Token 下不支持的方法不执行工具。CORS 预检允许走现有 CORS，不能返回工具或数据。
SDK 支持的协议版本按 `initialize` 协商，不能宣称支持未通过锁定 SDK 验证的版本。

### 6.2 工具输入

工具名：`search_knowledge`；只读、无外部写入；不提供模型答案。

| 字段 | 类型 | 必填 | 默认值 | 边界 |
|------|------|------|--------|------|
| `query` | string | 是 | 无 | 去除首尾空白后长度 1～2000。 |
| `knowledge_base_ids` | integer[] | 是 | 无 | 1～20 个正整数；接入方配置，无自动扫描。 |
| `top_k` | integer | 否 | 5 | 1～50；最终结果数量上限。 |
| `max_content` | integer | 否 | 15000 | 1～15000；保持现有按知识库合并内容的限制语义。 |
| `filters` | RetrieveFilters / null | 否 | null | 复用现有结构；支持 `ANY`，`ALL` 按既有行为拒绝。 |

拒绝未声明字段，不接收身份切换参数。MCP 的上限只影响 MCP，不收紧旧 REST 参数契约。

请求示例：

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "search_knowledge",
    "arguments": {
      "query": "安全管理要求",
      "knowledge_base_ids": [118],
      "top_k": 5
    }
  }
}
```

### 6.3 工具输出

成功返回 `CallToolResult`，`isError=false`；`structuredContent` 对应现有 `RetrieveResp`，
并提供相同数据的 JSON 文本 `content`，兼容不读取结构化结果的客户端。

```json
{
  "chunks": [
    {
      "content": "示例片段",
      "knowledge_id": 118,
      "document_id": 1001,
      "document_name": "示例文档",
      "chunk_index": 0,
      "source_url": "",
      "source_full_url": ""
    }
  ],
  "total": 1
}
```

来源签发仍在资源授权之后，保持现有有效期和缺失对象处理，不新增下载审批或改变来源链接契约。
输入、数量和按知识库内容上限共同约束输出；不另行增加截断算法或修改片段排序。

### 6.4 错误契约

| HTTP Status | 业务码 / 协议错误 | 场景 | 关联 AC |
|-------------|------------------|------|---------|
| 404 | 服务关闭 | 运维显式关闭 | AC-01, AC-12 |
| 401 | 19801 / 19802 / 19803 | 缺失、无效/绑定失效、禁用 Token | AC-03 |
| 403 | 19804 / 19812 | IP、路由或缺少显式 MCP 授权 | AC-04 |
| 429 | 19805 | Token 限流 | AC-05 |
| 503 | 19806 | Token 限流基础设施不可用 | AC-05 |
| SDK 状态 | MCP JSON-RPC 错误 | 协议方法、未知工具或参数错误 | AC-08 |
| 200 | `CallToolResult.isError=true` | 已执行工具的权限拒绝、超时与下游失败 | AC-07, AC-09 |
| 200（预检） | CORS 响应 | 任意 Origin 可完成 MCP 预检，其他接口 CORS 不变 | AC-14 |

不新增业务错误模块编码。鉴权 HTTP 响应复用既有业务码但保留真实 HTTP 状态，
协议层不依赖主 FastAPI 对普通异常的 HTTP 200 包装；工具内部未知异常返回固定错误说明，详细信息只记服务端日志。

## 7. 数据与领域边界

无新表、新字段或迁移。DeveloperToken 的创建、更新、删除、密钥和绑定归属现有模块；本期只调用其服务。
Knowledge/KnowledgeFile/KnowledgeDocument/KnowledgeDocumentVersion、权限元组、ES/Milvus 和 MinIO 的所有权不变。
MCP 不创建 OpenFGA 资源类型，不读写 `role_access`，不引入手工租户查询。

## 8. 发布与风险

默认开启，无需额外服务配置；接入方仍需 Token 的 `/mcp` 白名单及知识资源权限。
公网通过 HTTPS；第一版 JSON 响应不要求长期 SSE 连接，代理仍须保留 MCP 协议和 Token 请求头。
关闭 `mcp.server.enabled` 并重启可停止入口；REST 保持可用。配置读取遵守现有 Redis 缓存，变更生效时间不能只按重启推断。

风险集中在共享检索提取的兼容性、SDK 任务上下文传递、鉴权错误包装和挂载路径。
必须用现有回归及真实 SDK HTTP 调用验证；真实数据库、Milvus/ES/MinIO、DM8 与线上代理未验证时必须单独列明，不能声称部署完成。

当前工作区积分模块的两个未提交文件属于用户已有改动，不纳入本特性。

## 10. 2026-10-09 已确认调整

用户要求默认开启、所有跨域来源允许，并确认取消 SDK Host/Origin 白名单及 DNS 重绑定防护。
