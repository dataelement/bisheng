# 测试用例写作与完成标准

相关对象、状态、数据和预期使用需求／契约对应的术语基线与概念增量；技术别名有映射，不把任务与一次执行等不同生命周期对象混写。关键断言按[独立预期方法](assertion-quality.md) 核对，未解决的规则分歧保留待补，不生成自洽但无来源的预期。

适用于研发验证和独立验收两种用途。正式文档按 [HTML 交付约定](../../sdd-workflow/references/html-delivery.md) 输出；岗位、工程与执行阶段仍按 [测试环境与证据策略](test-strategy.md)。本标准约束用例定义，不授权执行测试或替测试工程师确认结论。

## 用例粒度与独立性

每条用例只验证一个明确意图。标题概括“条件／动作／预期行为”，按模块分组，ID 稳定且不因排序变化重编。一个业务意图可以需要返回、状态和相关副作用等多个断言；不把互不相关的校验、成功、拒绝、并发场景堆成一例。重复提交等场景可以有多次动作，仍需共同服务于同一个意图。
每个编号步骤只表达一个可执行动作；预期与数据单列，不混在操作里。前提包含角色、初始状态、依赖、配置和必要资源；每例能自行创建或取得确定状态，不能写“先执行 TC-xxx 并使用其结果”。公共前置抽成有稳定编号和版本的公共准备步骤，在 HTML 中可定位，并说明所需参数、完成状态与本例数据隔离。执行顺序不能成为隐藏前提。
清理只影响本例创建的资源。允许复用 fixture／数据定义，不共享上一用例遗留的可变结果。长业务旅程的中间动作可保留为步骤；要单独判断的多个业务结果拆为独立意图，用公共准备重建前提。

## 必备要素与取值

用例清单固定九列，复杂内容可在相应单元格用编号列表和可定位引用呈现，不能只有空标题或不可访问的附件：

| 列 | 写作要求 |
|---|---|
| ID | 稳定且唯一，推荐含模块标识；参数化数据行另有数据 ID，能定位失败的是哪一行 |
| 标题 | 唯一明确的验证意图，避免“综合测试”“验证功能正常” |
| 优先级 | P0／P1／P2；依据业务关键性、失败影响与风险评定，说明分级口径。沿用项目定义，不机械复制需求优先级，也不把优先级当执行顺序 |
| 类型 | 主类型为功能／异常／边界／性能／安全／兼容之一；并发、重复提交、权限等可作为附加标签；类型与测试层级分开 |
| 关联需求 | 完整 REQ／AC 标识及来源版本；缺陷回归关联原需求／既有契约和缺陷证据。不从代码现状凭空发明需求编号或正确行为 |
| 前置条件 | 自包含状态或明确公共准备编号、参数与状态；所需环境、权限及依赖可查，不依赖其他用例结果 |
| 步骤 | 从 1 编号，每步一个动作，入口／操作对象清楚；引用公共步骤时能直接查看实际内容 |
| 测试数据 | 引用独立数据项，给出具体输入、身份／资源关系、初始值及边界数据；与步骤分离以供参数化 |
| 预期结果 | 与动作对应的唯一可观察判据，含适用状态和副作用；能够据此判定通过／不通过，禁止“正常、友好、合理、尽量”等模糊规范性用语 |

本套件已有的来源／风险、负责岗位、目标工程、清理、执行阶段、环境模式、真实／替身边界及证据限制继续保留：共用内容可放文档元信息或公共准备，各例差异必须明确。文档标明模块／用例版本、有效需求与契约版本、当前用途和定义／评审状态；执行结果另行记录。

## 数据与唯一预期

边界值取自已确认需求或契约，写出确定数字、单位和具体数据；不能只写“最大值+1”“超长字符串”或随机数据。比如已确认上限 20 个字符，应定义实际 19、20、21 字符数据及其准确内容或确定的数据文件；明确字符／字节、去空格和归一化等适用口径。不知道上限时列缺口，不自定 255 或其他数值。
输入与预期按数据 ID 关联。参数化的一组数据只验证同一意图，各行有确定输入和结果；独立规则或不同业务意图拆例。时间、随机和并发数据需要可重复的时钟／种子／调度条件；测试用业务值具体化，环境地址、凭据及环境生成 ID 用有明确获取／创建方式的绑定，不能硬编码真实秘密或依赖他人数据。
一个用例可以有多个共同判定条件，全部满足才通过；不能写“成功或失败均可”。并发等允许合法不确定顺序的场景应给出唯一不变量，例如“两个冲突请求恰好一个成功、一个按契约拒绝，最终仅一条关联”，不凭空指定哪个请求获胜。
异步观察明确契约允许的完成窗口、事件标识、数量和终态；性能场景明确负载、观察周期、指标口径及阈值。缺少这些依据时回到需求／设计补齐，不用任意等待或臆造 SLA 掩盖未知。

## 异常、边界与副作用

正常流之外必须覆盖本范围适用的异常和边界；每项逐一说明“适用及用例／待补及影响／不适用及理由”。用户未指定数值配比，不自行设定正常／异常／边界的固定百分比，也不靠重复用例凑覆盖率。

| 专项 | 至少核对 |
|---|---|
| 空值 | 缺字段、null、空字符串／空集合的相关区别，必填条件和拒绝后状态 |
| 超长与其他边界 | 已确认的上下限、临界点及边界两侧，明确单位与合法结果 |
| 特殊字符 | 与字段／协议有关的 Unicode、空白、转义及注入风险，不无差别穷举字符集 |
| 重复提交 | 同一业务动作重复后的结果、状态和副作用次数；不默认所有动作都必须幂等 |
| 并发 | 竞争对象、参与者、数量和受控重叠条件，核对终态；顺序执行两次不能证明并发 |
| 超时 | 注入点、阈值／时钟、是否可能已生效、结果查询与恢复规则 |
| 弱网 | 相关的延迟、丢包、断连／恢复条件、操作期间状态和结果；工具参数需有确定依据 |
| 权限与越权 | 允许／拒绝配对、他人／跨租户等相关范围、信息披露及拒绝无副作用 |
| 数据不存在 | 缺失／已删除对象与查询空结果，按契约区别允许和拒绝，不推断错误文案 |
| 状态非法流转 | 初始状态、禁止动作、返回与保持的状态，失败不能产生意外副作用 |

性能、安全和兼容用例按对应非功能需求及风险设计，不为填满类型而制造需求。未知不是不适用；真实环境条件未具备仍是待验证，不能删去已识别场景。

预期逐项评估下列副作用。适用项给出可观察断言或引用公共副作用规则；不适用有依据，不能要求每例都凭空新增消息／埋点／日志：

| 副作用 | 判据与证据边界 |
|---|---|
| 数据库落库 | 目标记录、关键字段、数量、归属，以及失败后无意外写入。内存 fake 状态／仓库调用只证明隔离链路行为，不能称真实落库 |
| 状态机流转 | 前态、合法后态／保持不变及相关转换次数 |
| 消息／通知 | 收件对象、事件／载荷、次数和重复／失败规则；模拟发布调用不能证明真实送达 |
| 埋点上报 | 事件、触发、关键属性、数量／去重及隐私规则；spy 只能证明本地发出意图，不能证明平台已接收 |
| 下游系统接收 | 目标系统及关联标识、收到的内容、次数与响应／后续状态；开发 mock 调用与真实接收分别表述 |
| 日志记录 | 必要事件、级别／关联标识、允许字段及脱敏；不把任意调试输出当作需求，也不使用真实敏感数据 |

保留真实被测机制，在适当隔离环境观察业务状态、调用和事件；真实存储、投递、接收等不足以证明的部分交接独立验收。所有 UI 执行（含 mock UI）和真实部署 E2E 仍在验收，文档标准不要求研发提前部署或运行它们。

## HTML 输出结构

元信息与目录之后，按以下四部分输出；公共前置和数据字典可放在用例清单部分并提供锚点：

1. **用例覆盖概览**：功能点／REQ／AC × 正常／异常／边界矩阵。各格关联具体用例或明确待补／不适用理由，标明岗位和适用范围；这是定义覆盖，不是执行通过率。
2. **用例清单表**：严格保留上述九列，按模块分组。编号步骤、独立数据和预期在各自列中可读；配套公共准备与测试数据可定位。元信息／行内附注承载阶段、环境及证据边界，避免超宽表丢失核心信息。
3. **异常与边界专项清单**：逐项列出专项、关联需求、适用性、具体数据／触发条件、用例 ID、剩余缺口；适用副作用的断言也可在此以稳定编号共用。
4. **自动化可行性标注**：逐例标注“可自动化／需人工／需工具”，说明理由、候选层级、必要工具及数据／环境前提。需工具不等于不能自动化，可写“可自动化，需工具 X”或“需工具，自动化待确认”；未核实框架／工具时给候选和缺口，不宣称已可运行。实际执行阶段与负责岗位必须可查。

JSON／CSV 等可以从同一份结构化定义产生配套文件，避免和 HTML 各自更新。自动化标注与脚本已实现、测试已执行分别记录，不因此安装工具或触发验收。

## 完成标准

本岗位范围内，必要 REQ／AC 均有覆盖，适用异常／边界及重要副作用均有明确断言；每例单一意图、可独立执行、九列完整、数据确定、预期可二值判定、公共准备可展开、追溯和版本有效；HTML 四部分齐全，实际所用复核方式及其限制明确。必要规则／契约仍不明时可交付草稿和缺口，相关范围不能标记“用例就绪”；另一岗位尚未准备的用例单独记录。
可判定通过／不通过指预期具备明确判据，不要求把缺环境、未执行或证据不足硬填成失败。定义、评审与每次运行状态分开，实际结果仍按“通过／不通过／未验证／不适用”及真实执行记录报告。
