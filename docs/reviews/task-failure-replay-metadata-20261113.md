# 任务错误实时提示与刷新结果不一致

日期：2026-11-13。目标分支：`feat/3.1.0-beta1`。现场：116。

## 证据与原因

指定会话的数据库结果与 Redis 原错误事件都记录了 `content_filter`，并附有完整 `failure_info.category=model_service`。该模型为 `mock-content-filter`，返回的是模型侧内容过滤失败，独立于平台敏感词开关。

116 已部署的 WebSocket 终态补发分支只复制 `error`、`error_code`、`error_type`。任务先保存失败状态，再完成任务行收尾及推送错误，连接在这个间隙轮询到失败结果时会走补发并关闭，丢失模型服务来源；页面于是按 `content_filter` 显示旧文案。刷新使用完整的持久化结果，恢复模型服务异常提示。前端实际部署的错误处理仍走统一元数据解析，丢失点在后端补发。

## 修复与边界

终态补发与 Worker 异常收尾补发复用同一个公开错误投影，保留有效服务来源、故障标识与既有恢复字段；错误详情经过统一脱敏。只复制公开错误字段，不把任务答案或其他内部输出一并发送。保持错误分类、敏感词策略、执行状态和权限检查的原语义。
