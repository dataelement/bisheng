# 毕昇文本与多模态模型微调改版需求

版本 V2.1（3.1 beta1 开发分支）

日期 2026年11月17日

适用对象 业务负责人 产品研发负责人 交付负责人

本次改版服务于企业在毕昇平台训练专属模型的需求。将现有以早期文本模型为主的微调模块，扩展为支持文本、图文和视频理解的训练流程，并统一服务接入、数据校验、任务创建、训练监控和结果验证。首批采用 LoRA 监督微调，音频与视频音轨不在本期范围。

需求评审需要确认功能范围、各模块的交付责任和验收标准。文本、图文、视频已通过小规模真实训练及产物重载验证，具备继续产品化的技术依据；模型效果、正式平台部署和企业权限验收应分别完成，不能用技术验证代替交付验收。

## 1 背景与业务问题

企业在毕昇中建设业务应用后，需要模型遵循企业的术语、判断规则和输出格式。例如，将客服工单分到指定类别，从票据或现场照片提取信息，或根据短视频回答操作过程中的问题。企业希望通过统一页面使用自己的数据训练模型，减少自行编写训练脚本和排查环境的工作。

现有 FT 服务及训练框架封装基于较早的模型体系，模型映射、数据准备和推理流程主要面向文本。增加模型名称或升级一个依赖，无法同时解决图片与视频的读取、模板适配、训练参数传递、产物加载和页面交互问题。因此，本次需要联动改造毕昇前端、毕昇后端、bisheng-ft 和训练环境。

企业提供的问题、标准答案与媒体构成训练样本。只有图片或视频文件还不足以直接进行本期监督训练；自动标注、生成训练问答不属于默认交付。

## 2 目标与范围

### 2.1 业务目标

1. 企业用户在毕昇内完成数据上传、模型选择、训练和新样本验证，普通使用者无需登录 GPU 服务器执行训练命令。
2. 管理员可以为不同训练服务配置不同模型。平台读取服务的真实能力，新增适配模型无需再次修改前端模型名单。
3. 任务保留数据、模型、参数、日志和产物信息，能够追溯一次训练的实际执行过程。
4. 在保留历史文本任务的基础上扩展多模态能力，失败和不支持的组合必须明确提示。

### 2.2 输入输出和训练方法

| 类型 | 训练输入 | 预期输出 |
| --- | --- | --- |
| 文本 | 问题或多轮文本对话及标准答案 | 分类标签 结构化数据或自然语言文本 |
| 图文 | 图片 问题及标准答案 | 图片理解结果或结构化文本 |
| 视频 | 视频画面 问题及标准答案 | 内容描述 时序判断或结构化文本 |

首批训练方法为 LoRA，即训练较小的适配参数，继续依赖原基础模型。视频按模型处理规则抽帧，不处理音轨。本期不包含音频训练、图像生成、语音合成、视频生成、自动标注、多机自动调度，以及未经单独验证的全量或量化微调。

首批验证模型为 Qwen3-0.6B 和 Qwen2.5-VL-3B-Instruct，分别覆盖文本与图文、视频输入。这是首批适配记录，不代表平台只支持这两个模型，也不代表同系列其他规模和版本自动可用。

### 2.3 交付范围的管理

本地数据包到真实训练、产物重载是核心路径。本分支现有数据集管理与任务内可复用版本是两条分离的链路。2026-11-25 用户确认本轮统一四类数据集管理、旧格式转换和任务选数，任务内本地上传改为仅本次使用；这些为本轮待实现需求，不代表已经交付。当前仍需在 3.1 beta1 部署环境完成登录网页端到端和权限验收。目标推理服务发布另行设计、适配及验收，不将任务内推理验证视为已发布。

## 3 使用角色和完整流程

管理员负责在训练服务器安装 FT 服务、准备模型，并在毕昇登记服务。业务或算法使用者提供训练样本，配置任务并检查输出。交付人员负责确认平台、FT 与模型版本一致，并完成安装和功能验收。

使用顺序为：准备服务器和模型 → 在毕昇接入训练服务 → 上传并检查训练数据 → 选择模型与训练参数 → 提交前检查 → 执行训练 → 检查产物 → 用新样本验证 → 按目标推理服务的适配情况发布。

以票据识别为例，使用者准备含图片、问题和标准答案的数据包，选择图文模型训练；训练结束后使用另一张未参与训练的票据进行测试。产物能加载说明技术链路可用，字段是否识别正确仍需按业务标准判断。

## 4 功能需求与页面对应

### 4.1 训练服务接入和模型发现

管理员填写服务名称和 FT API 地址，平台从后端检测该服务是否可访问，并读取模型清单及资源信息。页面分别呈现连接失败、模型未准备、能力未验证和资源不足的原因。

同一服务可以提供多个模型，不同服务可以提供不同模型。模型记录包含精确标识、版本、支持输入类型、训练方法、模板及验证状态。页面按当前服务和数据类型筛选模型，不使用静态白名单推测能力。模型更换后重新检查数据和参数的兼容性。

服务停用应阻止新任务，历史任务继续保留。服务器地址由管理员维护，业务用户无需理解容器目录或物理显卡编号。

### 4.2 数据上传和检查

文本支持约定的文本清单格式；图文和视频使用包含清单及媒体文件的 ZIP。页面提供对应模板与示例，说明如何填写问题、标准答案和媒体引用。

上传后检查字段、角色顺序、空答案、占位符、媒体数量、相对路径、缺失文件及解码失败。错误需要定位到样本或文件，不能丢弃错误样本后报告全部通过。检测通过的数据保存内容标识和报告，任务引用提交时的数据，不随原始文件的变化被覆盖。

图文预览展示图片、问题与答案；视频预览展示视频及对应问答。再次上传修正数据时形成新的记录，已有任务仍能追溯旧内容。

### 4.3 创建训练任务

创建保持单页，包含任务名称、数据类型、训练服务、基础模型、训练数据、训练方式和参数。基础参数提供训练轮数或最大步数、学习率；高级参数包含序列长度、批大小、梯度累积和 LoRA rank。页面解释最大步数与轮数的优先关系。

选择模型后采用该模型的默认值和可配置范围。页面填写的参数必须进入实际训练配置，不允许展示可编辑项却在服务端静默忽略。提交前执行数据、模型、运行环境、方法和资源检查；失败时保留表单并定位原因。

### 4.4 训练任务列表与详情

任务列表展示名称、类型、模型、服务、状态和创建时间。详情展示实际阶段、运行日志、已获得的训练指标、数据摘要与生效参数。没有日志或指标时显示等待采集，不生成示意曲线。

刷新页面后继续查询同一服务器任务。服务断开时保留最后观测状态并提示重查，不将通信错误直接视为训练失败或成功。取消任务须由服务确认终止后显示已取消；重复提交和重试不得产生重复训练进程。

### 4.5 产物和新样本验证

训练正常结束后检查 LoRA 权重、配置及基础模型加载依赖，记录文件大小与内容哈希。训练成功、产物完整和推理验证分别展示，缺失产物不能显示为可用模型。

任务详情支持新文本输入、新图片上传和新视频上传，重新加载基础模型及本次 adapter 后执行推理。显示实际输出；可用时支持相同输入下基础模型与微调模型的对比。推理完成仅表示执行成功，不自动表示答案正确。

### 4.6 数据来源扩展和发布

数据集管理支持本地文件、FTP/显式 FTPS、SFTP、S3/MinIO。远程导入只需一次填写连接与媒体根目录，无需逐条输入远程地址；沿用已确认的训练服务直接读取远程媒体和不长期保存凭据的约定。通过数据集管理导入并校验成功后可长期复用，任务内临时本地上传不自动保存为数据集。

模型发布需验证目标推理服务是否支持该基础模型、LoRA 和输入类型。发布成功必须有实际调用结果；未适配的组合保留产物和验证结果，不呈现虚假的发布成功。

### 4.7 页面与功能清单

| 入口 | 用户主要操作 | 对应需求 |
| --- | --- | --- |
| 模型微调任务列表 | 新建 查看 取消及追溯任务 | 训练管理 |
| 单页创建任务 | 选择服务 模型 数据及参数并预检 | 训练提交 |
| 任务详情 | 查看日志 配置 产物并测试新样本 | 训练监控与验证 |
| 训练服务管理 | 登记地址 检测连接和模型能力 | 环境接入 |
| 数据集管理 | 四类标识 导入 转换 复用及来源管理 | 本轮数据集迭代 |

### 4.8 数据集迭代补充（2026-11-25 用户确认）

1. 数据集增加旧格式、文本、图文、视频四类标识；类型与来源分开呈现，并支持分类筛选。
2. 旧格式及原数据保留，显式转换另生成新版文本数据集；转换不得丢失问题、补充输入、答案或已有会话内容，失败需定位到样本。
3. 创建微调任务时，已有数据下拉列表来自数据集管理，只展示当前租户可用、已校验且分类匹配的数据；旧格式先转换。
4. 用户可以在任务内临时上传一份本地数据并预览、校验和使用；成功、失败或取消都不会将其加入可复用数据集或版本列表，成功任务保留自身的数据引用与校验快照。
5. 原有加入数据集和 QA 知识库转数据集业务继续支持，新产生的数据直接使用新版文本格式并归入文本分类；沿用已有租户和权限约束。

本轮详细验收口径见 [F025 spec §2.9](../../../features/v3.1.0-beta1/025-multimodal-finetune/spec.md)。

## 5 各层需要修改什么

### 5.1 毕昇前端和后端

前端增加文本、图文、视频选择，动态模型列表、数据检查反馈、任务详情和真实验证入口。页面复用毕昇现有组件、国际化与权限入口。

后端负责权限、任务及数据持久化、模型能力快照、FT 调用、状态同步和结果保存。新增字段兼容历史记录；数据库迁移需覆盖项目支持的数据库。数据通过平台对象存储提供给训练节点，不能依赖用户电脑或单台后端的临时文件。

### 5.2 bisheng-ft 服务

FT 底层代码需要更新。它负责将平台请求转换为训练任务，因此要同时改造模型登记、数据下载与校验、多模态字段映射、真实参数传递、训练进程管理、日志、取消、产物检查和推理重载。

新增服务提供版本化接口，保留旧任务兼容路径。训练任务独立保存配置与输出；服务对训练和推理资源执行互斥，重启后核对遗留任务状态。训练和推理不得拼接用户输入执行任意 shell 命令。

### 5.3 LlamaFactory 和模型依赖

需要固定一套已验证的 LlamaFactory 与 PyTorch、Transformers、PEFT、媒体解码依赖，提供可复现的 Docker 构建文件。新框架安装位置必须与旧内置代码隔离，避免运行时仍加载旧版本。

模型适配验证覆盖加载、模板、处理器、数据预处理、反向训练、保存和重载。存在模板或权重文件不能直接视为支持；后续新增模型要通过同样流程后登记开放。

### 5.4 安装和交付材料

交付包含毕昇功能分支、FT 功能分支、数据库迁移、容器部署文件、模型配置样例、训练数据样例及客户使用指南。客户指南按服务器管理员与平台使用者的操作顺序编写，不包含内部测试机器地址、实验任务编号和项目交接记录。

## 6 验收标准

| 编号 | 验收项 | 通过条件 |
| --- | --- | --- |
| AC01 | 服务与模型 | 两个服务可返回不同模型清单 页面按当前服务选择 |
| AC02 | 文本训练 | 从毕昇提交文本 LoRA 保存产物并用新文本推理 |
| AC03 | 图文训练 | 从毕昇提交真实图片数据 保存产物并用新图片推理 |
| AC04 | 视频训练 | 从毕昇提交真实视频数据 保存产物并用新视频推理 |
| AC05 | 数据错误 | 缺失媒体 损坏文件 非法路径或错误样本能被阻断定位 |
| AC06 | 参数生效 | 页面参数与训练服务保存的生效配置一致 |
| AC07 | 状态与取消 | 刷新后可查同一任务 取消须实际终止且不标记成功 |
| AC08 | 产物真实性 | 缺少权重或配置时不能通过产物检查 |
| AC09 | 验证真实性 | 真实加载本次 adapter 显示实际输出 失败保留原因 |
| AC10 | 权限与历史 | 非管理员及跨租户访问符合原权限 旧文本任务可查询 |
| AC11 | 客户安装 | 新环境按指南部署并完成一次数据上传到推理验证 |
| AC12 | 远程数据与发布 | 对应连接器及推理服务完成真实调用后才能开放 |
| AC13 | 数据集分类与来源 | 统一显示四类标识，支持既有本地及远程来源，类型不符不入可用列表 |
| AC14 | 旧格式转换 | 原数据保留，另生成新版文本；失败可定位且不覆盖原数据 |
| AC15 | 任务选数 | 下拉列表仅展示数据集管理中分类匹配、当前用户可用的数据 |
| AC16 | 临时本地上传 | 仅本次任务使用，所有提交结果均不新增可复用数据集或版本记录 |
| AC17 | 既有业务入口 | 加入数据集与 QA 知识库转入继续可用，新产出均为新版文本 |

技术验收使用小数据量验证功能，业务验收使用客户认可的独立测试集和指标。准确率、输出格式、时延及资源目标按业务与模型确定，不由通用微调平台承诺统一数值。

## 7 推进顺序与交付判断

先固定模型和训练环境，完成正式 FT 服务、平台接口和页面接入；再完成真实训练、取消、异常恢复及新样本验证；最后结合客户环境验收权限、数据来源和目标推理服务。每项交付以实现代码与测试结果为准，保留版本、未完成项及回退方式。
