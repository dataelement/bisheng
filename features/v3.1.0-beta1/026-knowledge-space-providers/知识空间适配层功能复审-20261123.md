## 2. 主要发现

| 编号 | 优先级 | 缺口 | 直接受影响功能 |
|---|---|---|---|
| F01 | P1 | 任务工具独立直连Milvus且缺少执行身份契约 | 任务新建、继续、恢复、researcher检索 |
| F02 | P1 | 单文件问答独立直连本地索引；回答模型与处理模型未拆开 | 文件问答、空间聊天模型选择 |
| F03 | P1 | 标签及高级检索条件没有完整Provider转换协议 | 日常/目录标签筛选、工作流metadata/重排 |
| F04 | P1 | 结果ID映射未覆盖完整引用及原文定位链 | 引用注册、历史来源、预览下载、PDF等定位 |
| F05 | P1 | 上传前文件解析预览、编辑、冻结提交未纳入闭环 | 先预览再入库、用户编辑分块 |
| F06 | P1 | 元数据schema变更与值迁移没有明确端口/能力边界 | 字段管理、元数据筛选、移动复制 |
| F07 | P1 | 远端存储与毕昇配额计量之间缺少账本 | 用户/租户存储限制、上传及迁移计量 |
| F08 | P1 | 删除引用预检仍基于本地子树，不能仅替换执行manifest | 目录递归删除、引用阻断、预检确认 |
| F09 | P1 | 方案主证据与选定发版基线不一致 | 所有能力声明和实施门槛 |
| F10 | P2 | 已讨论性能要求尚未形成执行/验收契约 | 多空间、任务子Agent、工作流并发 |

### F01. 任务模式不能只通过Engine/Facade改造覆盖

**方案缺口：**原§10.2及代码落点列了客户端、MCP、SDK、工作流，未显式纳入Linsight独立工具及其装配。

**证据：**[SearchKnowledgeBase.search_knowledge](../../../src/backend/bisheng/tool/domain/langchain/linsight_knowledge.py#L147)要求本地model，执行int转换、查询本地模型并以user_id=0创建Milvus，未通过统一检索或文件资格链。[工具装配](../../../src/backend/bisheng/tool/domain/services/tool.py#L768)只传allowed_knowledge_ids；[任务范围](../../../src/backend/bisheng/linsight/domain/task_exec.py#L1666)来自用户选择，范围不是每篇文件的实时授权。

**失败示例：**WeKnora空间model为空/远端UUID时失败；填一个本地模型只会继续查本地索引。若只把召回换HTTP而不注入可信执行身份，白名单内空间也不能证明每篇文件当前可读。

**修订：**工具保留search_knowledge_base及现有citation scope，但注入不可由模型覆盖的用户、租户和本次选择范围，统一走授权retrieval应用服务。新任务、继续、恢复及researcher共享同一范围规则；每次检索重验，不回退user_id=0/管理员。用户上传到任务的临时文件保持现有独立路径，不混成外部空间。

### F02. 单文件问答和回答LLM必须独立列入兼容范围

**证据：**[chat_single_file](../../../src/backend/bisheng/knowledge/domain/services/knowledge_space_chat_service.py#L154)在188/192行直接初始化Milvus和ES，再由space_rag构造检索器，绕过RetrievalEngine。[get_space_llm_config](../../../src/backend/bisheng/knowledge/domain/services/knowledge_space_chat_service.py#L626)则使用本地整数model_id构造回答LLM。

**失败示例：**整空间检索已适配，文件列表点击问答仍访问空本地索引；把WeKnora摘要模型ID填进回答模型选择也会类型/归属错误。

**修订：**将单文件、目录、整空间、日常工具四类入口分别验收，单文件请求固定已授权file/version候选。模型命名区分：知识处理模型（WeKnora摘要/Wiki/标签/Embedding/VLM）与调用场景回答模型（毕昇会话/任务/工作流现有配置）。如果未来要用WeKnora目录中的模型直接回答，单独设计模型执行端口，不在本次靠字符串兼容整数ID。

### F03. 标签、metadata、权重、阈值与重排都要有执行语义

**证据：**[标签解析](../../../src/backend/bisheng/knowledge/domain/services/retrieval_engine.py#L199)查本地TagDao；[日常固定标签](../../../src/backend/bisheng/workstation/domain/services/workstation_service.py#L1367)也调用本地标签过滤，目录聊天有独立TagDao路径。[工作流条件构建](../../../src/backend/bisheng/workflow/common/knowledge.py#L168)查本地metadata后生成Milvus/ES表达式；[工作流空间召回](../../../src/backend/bisheng/knowledge/domain/services/space_flow_retrieval.py#L118)直接消费表达式、RRF权重和Python rerank对象。

v0.9.0 [SearchParams](../../../dist/WeKnora/internal/types/search.go#L258)有knowledge_ids/tag_ids/scope_tag_ids、阈值、两路开关和rerank，但无通用metadata AST。[远端RerankOptions](../../../dist/WeKnora/internal/types/rerank.go#L8)使用实例内字符串模型ID，不接受毕昇Python对象；省略rerank对象不会自动保留本地重排。

**失败示例：**远端标签可显示但筛选查不到本地关联；高级条件被丢弃导致扩大范围；本地模型ID被错误传远端，或本地/远端重复重排。

**修订：**RetrievalRequest增加逻辑目录/文件/标签条件、metadata AST、TopK/预算和可选重排策略。Provider按能力解析远端标签，任何空候选都短路；与权限候选求交。逐项声明可下推/公共执行/不支持，无法保持条件时在预检拒绝。相似度阈值与融合排名不混用，本地rerank只在权限复核后执行，远端rerank必须使用匹配实例的模型身份。

### F04. 引用注册、解析与多格式定位是独立闭环

**证据：**[RagCitationPayload](../../../src/backend/bisheng/citation/domain/schemas/citation_schema.py#L53)使用本地整数knowledgeId/documentId；[registry构建](../../../src/backend/bisheng/citation/domain/services/citation_registry_service.py#L246)还消费名称、文件类型和chunk定位。[resolve](../../../src/backend/bisheng/citation/domain/services/citation_resolve_service.py#L172)继续查本地文件并调用[get_file_share_url/get_file_bbox](../../../src/backend/bisheng/knowledge/domain/services/knowledge_service.py#L2938)，二者依赖MinIO。前端[citationUtils](../../../src/frontend/client/src/components/Chat/Messages/Content/citationUtils.ts#L26)已经重新调用空间preview/download接口，适合保留，不必另造预览器；但后端resolve本身仍可能先走空对象路径。

v0.9.0 [SearchResult](../../../dist/WeKnora/internal/types/search.go#L159)的knowledge_id是远端文档ID，knowledge_base_id才是库；[SourceLocator](../../../dist/WeKnora/internal/types/source_locator.go#L9)的页/行/段等序号是1-based，bbox是归一化坐标。它们不能原样当毕昇现有page/bbox格式。

**修订：**集中实现SearchResult→统一Hit→各入口Document/DTO转换，保留本地space/file/version、远端chunk、名称/类型、定位、access_scope。引用证据绑定generation与源修订，迁移后不得把旧chunk自动指到新版本。resolve改为provider-aware并返回受控入口；原文预览与下载分别判权。保留匿名拒绝知识引用、shared引用可见但原文仍按查看者判权的现有层次，不将WeKnora服务Key权限当用户权限。不能可靠转换定位时明确回退片段/文件级定位，不伪造页码或高亮。

### F05. 上传前预览不能用只读文本chunker接口替代

**证据：**[UploadPreviewService.start/parse](../../../src/backend/bisheng/knowledge/domain/services/upload_preview_service.py#L110)会解析真实暂存文件；[edit/freeze](../../../src/backend/bisheng/knowledge/domain/services/upload_preview_service.py#L176)要求upload_id、preview_id、expected_revision、rule_digest，正式入库使用冻结编辑结果。v0.9.0 [PreviewChunkingRequest](../../../dist/WeKnora/internal/handler/chunker_debug.go#L45)只接text与切分参数；[PreviewChunking](../../../dist/WeKnora/internal/handler/chunker_debug.go#L105)不写库/不Embedding且最多64K文本，不能构成文件解析、编辑及正式提交收据。

**修订：**ProcessingPort细分file_preview_session/read/edit/commit/abort与text_chunker_preview。完整兼容需要WeKnora拥有临时文件、解析产物及冻结提交会话，在提交前排除索引/Wiki/标签发布；毕昇只存句柄和修订。否则明确关闭该可选能力，不把上传后编辑当作上传前预览。该能力是否首期必须开放需明确决策。

### F06. 自定义元数据存储不等于schema变更任务

**证据：**毕昇[metadata_schema接口](../../../src/backend/bisheng/knowledge/api/endpoints/processing.py#L68)及[MetadataProcessingService](../../../src/backend/bisheng/knowledge/domain/services/metadata_processing_service.py#L135)已有字段新增/改名/删除、值迁移、revision预检。v0.9.0并非完全不支持自定义元数据：[Knowledge.CustomMetadata](../../../dist/WeKnora/internal/types/knowledge.go#L224)已经存在；但[KnowledgeBase](../../../dist/WeKnora/internal/types/knowledgebase.go#L59)、SearchParams及已读路由未提供与毕昇相同的schema修订/字段迁移契约。

**修订：**增加MetadataPort与独立能力，区分值读写、schema管理、值迁移和过滤。若兼容现有schema操作，字段定义/值以内容后端为权威，毕昇保留控制修订和计划；跨空间移动/复制预检schema映射。若首期不支持则显式能力拒绝，不能让ProcessingPort笼统承诺全部处理设置。

### F07. 配额不能只复用校验函数而不保留计量事实

**证据：**[QuotaRepository](../../../src/backend/bisheng/role/domain/repositories/quota_repository.py#L56)对storage_gb/knowledge_space_file按本地KnowledgeFile.file_size及file_source求和。[上传用户/租户检查](../../../src/backend/bisheng/knowledge/domain/services/knowledge_space_service.py#L4159)同时考虑当前用户与目标租户链。方案§4.2将文件大小原则远端读取，无法支撑并发上传预留及本地额度报表；WeKnora租户自身配额不是毕昇用户和父租户的额度。

**修订：**将byte_count、accounting_subject、reservation/committed/released状态、operation_key加入控制计量白名单，不是原文副本。并发流上传前预留、按实际接收校验并提交；ACK未知保留预留并对账，删除/迁移按定义释放或转移且只执行一次。决定是否计历史版本、预览临时文件、远端直接新增、索引占用；未明确前不能声称“原生配额无改动复用”。内容处理模型费用与毕昇回答费用分开，不把远端使用量虚报为本地模型日志。

### F08. 删除预检与业务引用闭包不能只靠远端delete解决

**证据：**[knowledge_delete_precheck](../../../src/backend/bisheng/knowledge/application/knowledge_delete_precheck.py#L76)先做引用检查，再冻结scope/inbound/root/coverage并在确认前重验；[本地scope展开](../../../src/backend/bisheng/knowledge/domain/repositories/knowledge_space_delete_repository.py#L182)依赖file_level_path、逻辑文档和版本行。它发生在删除执行manifest之前，远端树已变化但本地关系未刷新时会漏目标或改变受引用范围。

**修订：**Provider提供带内容/树修订的scope读取，映射为稳定本地资源，合并毕昇应用/工作流等引用事实；保留预检→确认→引用阻断/允许force→异步执行。计划冻结本地引用coverage和远端目标修订，确认不一致拒绝并重新预检。仅管理端远端对象不能因未注册到本地而自动进入删除范围；文件/历史版本/目录/清空/整空间分别验收。

### F09. 发版证据与能力声明需分离

**事实：**旧报告固定main cf5306，当前选定v0.9.0为f17ee8；方案的“已核验”表仍大范围引用旧报告。本轮实读v0.9.0的检索参数、重排、引用定位、chunker预览和模型结构，但未逐条重跑旧报告14项全量链。

**修订：**方案同时标记“历史main证据”“当前release已重验”“待release重验/扩展”，保留旧报告不可变基线。实例能力必须绑定release/commit及契约测试结果。不能仅因路由同名就宣告旧main全部结论适用于release，更不能把版本未核验误当不支持。

### F10. 性能治理需进入契约和验收

**证据：**[工作区空间检索](../../../src/backend/bisheng/knowledge/domain/services/knowledge_space_chat_service.py#L695)及[工作流空间检索](../../../src/backend/bisheng/knowledge/domain/services/space_flow_retrieval.py#L213)逐空间执行；[任务子Agent](../../../src/backend/bisheng/linsight/domain/services/agent_factory.py#L1258)又会放大检索并发。原生串行代码直接替换HTTP可能增加尾延迟，解除串行但无预算又可能击穿远端。

**修订：**按Provider实例及Embedding兼容分组、有界并行；权限事实批量加载；任务/租户/实例共享预算及分布式限流；请求去重、统一超时重试预算、只在一个位置重排。缓存只在身份/范围/权限修订/代次一致时复用，不建立跨用户持久正文缓存。压测授权耗时、远端耗时、队列等待、结果体积、首字延迟、P95/错误率，覆盖多空间、少量可读大库、子Agent及批量工作流，实际目标由部署验证确定，不给未测量的固定SLO承诺。

## 3. 功能验收矩阵

| 功能链 | 必须覆盖的入口/行为 | 首期门槛 |
|---|---|---|
| 日常会话 | 选择范围、固定标签、混合空间、失败提示、引用点击 | 全链路 |
| 任务模式 | 新建/继续/恢复、主Agent/researcher、逐次身份/文件复核、报告引用 | 全链路 |
| 工作流/助手 | RAG/检索/Agent、运行用户或作者共享策略、metadata/重排映射 | 全链路；不支持参数明确拒绝 |
| 空间内问答 | 单文件、目录、整空间、模型角色、历史消息 | 分别验收，不以整空间代替 |
| 引用 | 注册/短句柄/持久历史、原文预览与下载、定位、匿名/shared | 全链路 |
| 上传 | 直接接收与失败重试 | 全链路 |
| 上传前编辑预览 | 远端暂存、解析、编辑、冻结提交/取消 | 明确首期是否必须；否则能力关闭 |
| 元数据schema | 读写值/字段变更/迁移/过滤及跨库转换 | 明确支持级别 |
| 配额 | 用户/角色/目标租户链、并发预留、未知结果、删除/迁移计量 | 定义口径后验收 |
| 删除 | 引用预检与确认、远端scope修订、软墓碑、旧任务恢复 | 全链路 |
| 性能 | 端到端分阶段测量、预算与限流、失败隔离 | 压测门槛后确定容量 |

## 4. 处置与剩余决策

本轮已将三类检索入口、引用、参数语义、上传预览、元数据、计量、引用预检、性能要求及版本边界补入两份方案。尚需明确：上传前编辑预览是否首期必须；远端元数据schema管理范围；额度计量口径；工作流作者共享策略是否沿用；完整版本及目录等上游扩展的交付范围。

这些是具体功能与技术范围决策，不是通过适配器命名即可消除的问题。建议先完成“日常/任务/单文件/工作流各一次检索并点击引用”的纵向闭环，再并行推进生命周期功能。未经上述决策与真实验证，当前方案仍不应标为完整兼容设计已通过。
