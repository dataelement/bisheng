# Feature: 审计功能优化（动作补齐、组织归属与数据范围、使用类型）

**关联 PRD**：《审计功能优化》（`/Users/binfeng/Downloads/审计功能优化.docx`）§2.1–§2.4；技术方案草稿 [`docs/审计功能优化方案.md`](../../../docs/审计功能优化方案.md)
**优先级**：P0
**所属版本**：v3.1.0-beta1
**状态**：Spec Discovery 已确认（2026-11-03）：菜单角色只看本人主部门一级；部门管理员可看所管路径上已归档部门的历史记录；用户组身份不再授予审计数据访问。2026-11-09 产品改口：租户管理员也按本租户部门树裁剪；2026-11-13 补充：租户管理员另可看本租户「无所属部门」「不适用」记录，「未记录」仍不可见（AC-13、AC-23）。
**依赖**：发版线既有审计页三个页签（应用使用、系统操作、应用运行记录）、部门树与主部门、用户组、菜单授权、F019 管理租户切换、F056 结构化审计动作与托管应用筛选。

## 范围边界

本次纳入：

- 系统操作可按模块筛出 51 类动作：34 类既有动作（补齐其中 5 类的筛选与文案）和 17 类关键敏感动作（复用已写入的记录）。
- 三个页签按「记录发生时的操作者主部门」展示组织列、按组织树筛选，导出同步。
- 按身份确定的租户及部门数据范围，作用于列表、组织候选、用户候选、会话详情和导出。
- 应用使用页的四类使用类型筛选与列。
- 知识空间问答、频道文章问答进入应用使用列表并归入日常对话。

本次明确排除：

- 新增动作类型；把成功、失败、批量、不同入口拆成新动作；生命周期阶段事件（受理、排队、开始、结束）。
- 统一相关对象、对象 ID / 版本补齐、结构化变更详情、批量影响明细、关联时间线。
- 历史记录的组织回填，以及按当前组织改写已有记录。
- 逐消息或逐任务轮次的组织归属与权限。
- 任务执行明细、全文采集、会话详情加载上限调整、导出正文机制调整。
- 导出确认页、导出任务中心、传输进度跟踪、审计自身事件、审计补记或恢复流程。
- 应用运行记录的日志类型扩展、正文采集范围、启用条件和专业模型审计入口的变化。

## 1. 用户故事

- 作为**租户管理员**，我希望在审计页看到每条记录发生时所属的组织，并按组织树、使用类型和关键动作筛选与导出，以便完整核查租户内的应用使用和敏感操作。
- 作为**有审计菜单的部门管理员**，我希望只看到我所管部门及下级的审计记录，且查询重置后范围依旧有效，以便在不越权的前提下审计本部门。
- 作为**有审计菜单的普通角色用户**，我希望只看到本部门的审计内容，以便完成本部门的审计工作而不接触其他部门数据。
- 作为**全局超管**，我希望在未进入指定租户时跨租户查询，进入指定租户后只限该租户，以便按现有授权管理多租户。

## 2. 验收标准

### 2.1 动作补齐与模块归类

- **AC-01** — THE SYSTEM SHALL 在系统操作的「操作行为」筛选中提供修改沙箱配置、关联文件版本、设置文件主版本、删除历史文件版本、忽略相似文件建议 5 类动作，选中后列表只返回该动作的已有记录；列表单元格、筛选项和导出在中、英、日三语下均显示动作文案，不显示原始枚举值。
- **AC-02** — THE SYSTEM SHALL 将 17 类关键敏感动作按清单归入现有系统模块：租户管理 3 类（部门挂载租户、解除部门租户挂载、调整租户状态）、模型管理 3 类（创建、修改、删除模型服务）、审批管理 2 类（同意、拒绝审批）、开放 API 2 类（签发、撤销 API Key）、应用工场 7 类（发布、停止、删除托管应用，导出、恢复应用数据，修改应用可见范围，设置应用密钥）；模块名称同时用于筛选、列表和导出，不新增模块项。
- **AC-03** — WHEN 用户选择某个系统模块, THE SYSTEM SHALL 只提供该模块对应的现有动作作为操作行为候选；修改沙箱配置和工具相关动作归入「系统」，四个文件版本类动作归入「知识库」，知识空间动作不出现在「知识库」下。
- **AC-04** — WHEN 用户切换系统模块, THE SYSTEM SHALL 清空已选操作行为；WHEN 用户点击重置, THE SYSTEM SHALL 清空模块与操作行为，保留当前权限范围。
- **AC-05** — THE SYSTEM SHALL 对 51 类动作中已经写入的同一业务操作只展示原有那一条记录，不为本期改动新增重复日志。
- **AC-06** — WHERE 单租户部署, THE SYSTEM SHALL 隐藏租户选择、租户列，以及「租户管理」模块和对应的操作行为候选；其余既有动作按现状可查。

### 2.2 组织归属记录

- **AC-07** — WHEN 本期上线后新产生一条应用使用会话、系统操作或应用运行记录, THE SYSTEM SHALL 保存该会话发起人或操作者在发生时的主部门及其完整组织路径；资源所属部门和用户组不作为组织归属。
- **AC-08** — THE SYSTEM SHALL 以整条会话为应用使用的组织归属单位：会话后续消息沿用会话发起时的归属，不按消息或任务轮次另行记录。
- **AC-09** — WHEN 人员调动、部门改名或部门归档, THE SYSTEM SHALL 保持已有记录的组织归属和路径不变。
- **AC-10** — THE SYSTEM SHALL 在列表和导出中按以下口径显示组织列：本期上线前或组织无法确认的记录显示「未记录」；发生时确认没有主部门的显示「无所属部门」；无自然人归属的系统触发或服务账号记录显示「不适用」；其余显示发生时的组织路径。
- **AC-11** — IF 记录组织归属时查询失败, THEN THE SYSTEM SHALL 让原业务操作照常成功，该记录的组织显示「未记录」。

### 2.3 数据范围

- **AC-12** — WHILE 全局超管未进入指定管理租户, THE SYSTEM SHALL 返回其现有授权内的跨租户记录，并允许用租户条件缩小；WHILE 全局超管已进入指定管理租户, THE SYSTEM SHALL 只返回该租户记录，IF 改参请求其他租户, THEN THE SYSTEM SHALL 拒绝请求。
- **AC-13** — WHEN 租户管理员查询, THE SYSTEM SHALL 返回当前租户内、组织归属在本租户部门树（含挂载到父租户部门树上的子租户部门、路径上的已归档部门）内的记录，以及本租户内组织为「无所属部门」「不适用」的记录；不返回组织为「未记录」的记录，也不返回操作者部门在本租户部门树外的记录。
- **AC-14** — WHEN 有审计菜单的部门管理员查询, THE SYSTEM SHALL 只返回当前有效租户内、其所管部门及其下级（包括仍处于所管路径上的已归档部门）的记录；管理多个部门时取并集。
- **AC-15** — WHEN 有审计菜单但不是部门管理员的用户查询, THE SYSTEM SHALL 只返回组织归属为其本人主部门这一级的记录，不含下级部门。
- **AC-16** — WHILE 用户按部门范围查询（AC-14、AC-15）, THE SYSTEM SHALL 不返回组织为「未记录」「无所属部门」「不适用」的记录，也不向其提供这两个历史选项；IF 其自行传入这些条件, THEN THE SYSTEM SHALL 忽略之。
- **AC-17** — IF 用户既不是全局超管、租户管理员，也没有审计菜单, THEN THE SYSTEM SHALL 拒绝其访问审计数据；用户组成员或用户组管理员身份不授予审计数据访问。
- **AC-18** — THE SYSTEM SHALL 对列表、总数、组织候选、用户候选、会话详情和导出使用同一租户及部门范围；组织、用户组和其他筛选只缩小这一范围，重置筛选不取消范围。
- **AC-19** — IF 用户通过改参请求其范围外的部门、租户或会话, THEN THE SYSTEM SHALL 返回空结果或拒绝，不泄露范围外记录。
- **AC-20** — WHERE 应用运行记录已启用, THE SYSTEM SHALL 对直接调用其列表、候选和导出接口的部门范围用户同样施加 AC-14、AC-15 的部门范围。

### 2.4 组织筛选

- **AC-21** — THE SYSTEM SHALL 在应用使用、系统操作及已启用的应用运行记录中提供组织树筛选：支持按部门名称或编号搜索、多选，默认勾选「包含下级部门」；候选只含用户数据范围内的部门。
- **AC-22** — WHEN 「包含下级部门」勾选, THE SYSTEM SHALL 让选中的有效部门匹配其自身及当前有效下级部门的记录；WHEN 取消勾选, THE SYSTEM SHALL 只匹配选中部门本身的记录。
- **AC-23** — THE SYSTEM SHALL 在组织面板中单独列出范围内的已归档部门（标注「已归档」），可多选，选中后匹配归属于该部门的历史记录；全局超管另可选择「无所属部门」「未记录」，租户管理员另可选择「无所属部门」；IF 租户管理员自行传入「未记录」条件, THEN THE SYSTEM SHALL 忽略之。
- **AC-24** — THE SYSTEM SHALL 以记录上保存的组织归属进行匹配，不以操作者当前所在部门匹配。
- **AC-25** — WHEN 用户在同一维度多选（组织、用户组）, THE SYSTEM SHALL 取并集；父子部门同时选中时每条记录只计一次；WHEN 多个维度同时选择, THE SYSTEM SHALL 取交集。
- **AC-26** — THE SYSTEM SHALL 在用户点击「查询」后才使组织条件生效，不自动清空应用、用户、用户组、时间等其他筛选；「重置」清除已生效的组织条件但保留权限范围。
- **AC-27** — WHILE 全局超管未进入指定管理租户, THE SYSTEM SHALL 在组织候选中提供其所选租户的部门；未选租户时按租户分组提供各租户的部门。
- **AC-28** — THE SYSTEM SHALL 保持用户组为独立的平铺筛选，成员可来自多个组织；用户组不作为组织层级，组织与用户组组合取交集且不产生额外权限。

### 2.5 应用使用

- **AC-29** — THE SYSTEM SHALL 在应用使用列表保留应用名称、用户、用户组、创建时间、反馈、审核结果和详情入口，并在用户列之后新增组织列；保留现有应用名称、用户、用户组、时间、反馈及适用的敏感词审核筛选。
- **AC-30** — THE SYSTEM SHALL 提供单选的使用类型筛选，固定四项：日常对话、助手会话、工作流会话、任务模式；默认不限定，清除或重置后恢复全部；点击查询后生效，与组织、应用名称、用户、用户组、时间等条件取交集，且不自动清空其他筛选。
- **AC-31** — THE SYSTEM SHALL 按以下规则把每条会话只归入一个类型：助手应用会话为助手会话；工作流应用会话为工作流会话；日常会话（含知识空间问答、频道文章问答）存在已保存任务记录时为任务模式，否则为日常对话。
- **AC-32** — WHEN 一条日常会话同时含普通问答和已保存任务记录, THE SYSTEM SHALL 将整条会话归为任务模式并在列表、总数和导出中只出现一次；仅切换任务按钮而未产生任务记录的会话仍为日常对话；任务执行成败不影响归类。
- **AC-33** — THE SYSTEM SHALL 让知识空间问答和频道文章问答进入应用使用列表并显示其原有名称，不为它们增加独立的使用类型、应用名称筛选项或详情入口；应用名称筛选仍只含原有实际应用。
- **AC-34** — THE SYSTEM SHALL 在分页前按使用类型、组织和其他条件筛选并计算总数；导出使用相同条件和权限范围。
- **AC-35** — WHEN 用户导出应用使用记录, THE SYSTEM SHALL 在现有列基础上增加组织列和使用类型列，并应用已生效的组织和类型筛选；用户组、组织、使用类型分别输出；沿用现有导出入口、文件格式、时间规则和数量限制。

### 2.6 会话详情

- **AC-36** — WHEN 用户从应用使用列表点开详情, THE SYSTEM SHALL 让日常对话和任务模式（含知识空间、频道问答）进入现有日常会话详情，助手和工作流会话进入现有应用会话详情；保留返回、消息显示、来源查看和原有加载行为；任务模式只展示该会话已有消息；不新增组织元信息、任务轮次、步骤或产物面板。
- **AC-37** — WHEN 审计用户读取一条会话的消息, THE SYSTEM SHALL 在读取整条会话前按该会话的租户和组织归属做与列表一致的范围校验；IF 会话在其范围外, THEN THE SYSTEM SHALL 拒绝返回消息。
- **AC-38** — WHEN 会话发起人本人在原有业务页面查看自己的会话历史, THE SYSTEM SHALL 保持现有行为，不因审计范围校验而被拒绝。

### 2.7 系统操作

- **AC-39** — THE SYSTEM SHALL 保留系统模块、操作行为、操作者、用户组、时间和已有的专用应用筛选，以及表格、分页、备注和 CSV 导出；新增组织树筛选与组织列；操作者候选只含权限范围内的人员。
- **AC-40** — THE SYSTEM SHALL 按原字段继续显示已有操作对象类型、名称、备注、原因和真实结果，空值保持为空，不补成成功；审批同意不表述为业务已执行成功；密钥类动作不显示明文值。
- **AC-41** — WHEN 用户导出系统操作记录, THE SYSTEM SHALL 只新增组织列，并应用已生效的组织筛选；沿用现有导出条数上限。

### 2.8 应用运行记录

- **AC-42** — WHERE 应用运行记录已启用, THE SYSTEM SHALL 在模型调用、能力调用、应用访问三个子页新增组织列和组织筛选，导出包含组织列并应用已生效的组织筛选；原有字段、详情、启用条件和异步导出不变。

## 3. 边界情况

- 开放接口、服务账号或系统触发的记录即使附带兼容用的用户编号，也按「不适用」显示，不记成某个自然人的部门；系统写入时操作者编号为 0 或负数（如 -1）的记录同样按「不适用」显示。
- 部门管理员所管部门后来被归档：归档前写下的记录仍在其范围内；已移出其所管路径的归档部门不在其范围和候选内，对应记录只对租户管理员和全局超管可见。
- 选中的部门全部落在用户范围外时，返回空列表而不是报错。
- 选中父部门且勾选「包含下级」时，不自动带上路径上的已归档部门，除非该归档部门被单独勾选。
- 同一会话存在多个任务版本时，仍只计一条会话。
- 历史会话没有可确认的任务记录时按日常对话归类，不补造任务记录。
- 已写入但不在本期 17 类内的结构化动作保持可查，不删除、不改名。
