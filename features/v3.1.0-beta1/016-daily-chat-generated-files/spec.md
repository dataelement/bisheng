# Feature: 日常会话代码执行生成文件的附件交付

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。How 的唯一真相在 [design.md](./design.md)。

**状态**: 规格已确认（2026-11-13；用户确认单轮上限 50、审计只放开模型生成文件、管理员下载本期不另记审计日志）
**关联问题**: 116 环境报障 — 日常会话 `1bf1895760984458a9f58a9a757edc5a` 中模型生成的 Word 文档，会话页与审计页点击「下载」均返回 404；同一会话中有时给出可下载的 MinIO 地址，有时给出 `output/北京今日天气_20261113.docx` 这类相对路径
**优先级**: P1
**所属版本**: v3.1.0-beta1
**依赖**: 发版线既有日常会话（agent 模式）、代码执行器（本地 / 容器沙箱）、会话附件转正与按需签名、F003 审计会话详情范围校验

> **范围边界**
> - **本次纳入**：
>   - 日常会话中，代码执行器在 `output/` 下生成的文件，自动作为该轮回答的附件保存，并以文件卡片展示
>   - 这些附件随会话长期保留、按需重新签名下载，不受临时桶 7 天有效期限制
>   - 回答正文里指向 `output/` / `scratch/` 的相对链接：能对应到本条回答附件的，点击即下载该附件；对应不到的，不再渲染成会 404 的可点击链接
>   - 审计页会话详情展示同样的文件卡片，审计范围内的管理员可下载
>   - 仅在日常会话中告知模型「文件会自动作为附件交付，不要在回答里写下载链接或路径」
>   - 修正代码执行器上传对象名多一个点（`<uuid>..docx`）的问题
>   - **E2B 执行器**（实现期追加，2026-11-13 用户确认）：日常会话下 E2B 运行成功后，把 `output/` 下新增或改动的文件复制出沙箱并上传，与本地 / 容器执行器一样挂到回答上；同一轮回答内的多次调用共用一个 E2B 沙箱，回答结束时关闭
> - **本次明确排除**：
>   - **历史消息回填**：本功能上线前的回答不补附件；正文中的 `output/` 链接按 AC-13 变为不可点击文字
>   - **深度研究（任务模式）**：交付物已有工作区产物面板，行为不变
>   - **工作流代码节点、助手等其他使用代码执行器的入口**：行为不变（仅受对象名修正影响）
>   - **审计页展示用户自己上传的附件**：现状审计页不展示任何附件，本期只补模型生成文件
>   - **匿名分享页的下载**：分享页可以看到文件卡片，下载能力沿用用户上传附件在分享页的现状，本期不新增匿名签名
>   - **工具调用卡片里的原始返回**（含 MinIO 直连地址）：不改
>   - **会话导出（docx）中包含附件**：不做
>   - **管理员下载行为另记审计日志**：不做（见 design §8）

---

## 1. 用户故事

- **A. 日常会话用户**：作为使用代码执行器的用户，我希望模型生成的文件直接以附件形式出现在回答下方，并且隔多久回来都能下载，以便不用依赖模型写出的链接是否正确。
- **B. 审计管理员**：作为审计范围内的管理员，我希望在审计详情里看到并能下载模型当时交付给用户的文件，以便核查会话产出。

---

## 2. 验收标准

### 2.1 生成与展示

- **AC-01** — WHEN 日常会话中代码执行器（本地、容器沙箱或 E2B）成功运行并在 `output/` 下新建或修改了文件, THE SYSTEM SHALL 在该轮回答下方为每个文件展示一张文件卡片，卡片显示原文件名（如 `北京今日天气_20261113.docx`）与文件类型。
- **AC-02** — THE SYSTEM SHALL 只为交付物展示卡片：`scratch/` 下的中间文件、用户上传的源文件、知识库暂存图片不展示；脚本写在工作目录根的文件按既有规则移入 `output/` 后展示。
- **AC-03** — WHEN 同一轮回答中同一 `output/` 路径被多次写入, THE SYSTEM SHALL 只展示一张卡片，下载得到最后一次写入的内容。
- **AC-04** — WHEN 一轮回答结束, THE SYSTEM SHALL 在不刷新页面的情况下展示卡片；刷新或重新打开会话后卡片仍在且一致。
- **AC-05** — IF 代码执行失败（非 0 退出）或该轮没有产生交付物, THEN THE SYSTEM SHALL 不展示任何文件卡片。
- **AC-06** — IF 某个文件保存失败, THEN THE SYSTEM SHALL 照常展示其余文件和回答正文，本轮回答不因此报错。
- **AC-07** — IF 单轮交付物超过 50 个, THEN THE SYSTEM SHALL 只保存并展示按生成顺序最后写入的 50 个。

### 2.2 下载与保留

- **AC-08** — WHEN 会话本人点击文件卡片, THE SYSTEM SHALL 下载该文件（可预览的类型先打开预览，预览中可下载），下载文件名为原文件名。
- **AC-09** — WHILE 会话未被删除, THE SYSTEM SHALL 保持附件可下载，生成超过 7 天后仍可下载。
- **AC-10** — WHEN 会话被删除, THE SYSTEM SHALL 一并删除这些附件文件（与用户上传附件的现有规则一致）。
- **AC-11** — IF 既不是会话本人、也不在该会话审计范围内的用户请求附件下载地址, THEN THE SYSTEM SHALL 拒绝，返回与现有会话附件相同的「不存在」结果。
- **AC-12** — THE SYSTEM SHALL 通过平台访问地址提供下载（浏览器无需直连 MinIO 端口）。

### 2.3 正文中的文件链接

- **AC-13** — WHEN 回答正文中的相对链接（`output/<路径>`，可带 `./` 或前导 `/`，可为 URL 编码）与本条回答某个附件的路径一致, THE SYSTEM SHALL 在点击时下载该附件，与点击卡片效果相同。
- **AC-14** — IF 回答正文中指向 `output/` 或 `scratch/` 的相对链接对应不到本条回答的任何附件, THEN THE SYSTEM SHALL 将其显示为不可点击的文字，点击不发生跳转。
- **AC-15** — THE SYSTEM SHALL 对绝对地址（`http(s)://…`）及站内其他链接保持现有渲染行为不变。
- **AC-16** — WHERE 日常会话启用了代码执行器, THE SYSTEM SHALL 在交给模型的工具说明中写明「`output/` 下的文件会自动作为附件交付给用户，回答中不要写下载链接、URL 或 `output/` 路径，只用文件名提及」；深度研究的工具说明保持不变。

### 2.4 审计

- **AC-17** — WHEN 审计范围内的管理员在审计页打开日常会话详情, THE SYSTEM SHALL 在对应回答下展示与会话页相同的文件卡片，点击可下载。
- **AC-18** — IF 管理员不在该会话审计范围内, THEN THE SYSTEM SHALL 拒绝附件下载，结果与拒绝查看详情一致。
- **AC-19** — THE SYSTEM SHALL 在审计页对回答正文中的 `output/` / `scratch/` 相对链接执行与 AC-13、AC-14 相同的规则。

### 2.5 兼容

- **AC-20** — IF 回答被内容安全替换为自动回复, THEN THE SYSTEM SHALL 不展示、也不保留该轮的生成文件附件。
- **AC-21** — WHEN 用户在回答流式过程中点击停止，且该轮回答被保存, THE SYSTEM SHALL 为停止前已完成的代码执行产生的交付物展示卡片。
- **AC-22** — THE SYSTEM SHALL 保持深度研究交付物、工作流代码节点及助手中代码执行器的返回结构和行为不变。
- **AC-23** — THE SYSTEM SHALL 使代码执行器上传到对象存储的文件名形如 `<uuid>.docx`，不再出现连续两个点。

---

## 3. 边界情况

- 文件名含中文、空格、括号时，卡片和下载文件名保持原样。
- 同名文件位于 `output/` 不同子目录（如 `output/a/x.png` 与 `output/b/x.png`）时，展示两张卡片，正文链接按完整路径对应。
- 一轮中多次调用代码执行器、分别生成不同文件时，全部汇总到这一轮回答下。
- 对象存储暂时不可用时，回答正常保存；未能转为长期保存的文件仍按临时地址展示，最长 7 天后不可下载（design §5）。
- 下载地址每次点击时重新获取；链接过期不影响再次下载。
- 会话的工作区文件面板会汇总本会话全部附件，生成文件也出现在其中，打开时同样满足 AC-08、AC-09。
