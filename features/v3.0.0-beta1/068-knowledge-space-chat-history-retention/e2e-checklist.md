## 2. Client 页面主流程

以下每个场景都以用户 A 登录 Client `/workspace`，使用 `e2e-f068-` 前缀创建数据；资源操作完成后允许等待定向任务的默认短延时并刷新源空间。

### AC-01/10/11/12/13：单文件删除

- [ ] 在源空间文件夹内上传一个文件，从单文件入口发起至少两轮问答，记录标题、消息顺序、引用、反馈状态和时间。
- [ ] 删除该文件；确认删除接口成功时不等待会话回收完成。
- [ ] 任务完成前允许根目录暂时不可见；任务完成后刷新源空间根目录，会话出现且只出现一次。
- [ ] 打开会话，核对原消息、标题、引用、反馈、创建时间与消息时间不变。
- [ ] 从该会话继续提问，答案检索范围为源空间当前全部可见文件，不依赖已删除文件。
- [ ] 执行会话切换、重命名和删除，行为与原生根目录会话一致。

### AC-02/03/15：多层文件夹与批量删除

- [ ] 创建父文件夹、子文件夹、兄弟文件夹，并分别建立文件夹/单文件会话。
- [ ] 批量选择父文件夹、其子文件夹、子文件和一个独立文件，验证父子重复输入只删除一次。
- [ ] 任务完成后，父子树及独立文件的活动会话均在根目录；未受影响兄弟目录的会话仍在原入口。
- [ ] 重复投递相同 flow chunk，确认没有重复 session、消息或入口。

### AC-04A/22：清空内容与完整删除空间

- [ ] 在一个空间的根、文件夹和文件入口分别建立会话，执行“清空空间内容”（保留空间）。
- [ ] 清空提交后空间仍存在且可进入；任务完成后文件夹/文件会话在根目录，原生根会话保持单份。
- [ ] 对空空间再次清空，确认 no-op 且没有额外会话变化。
- [ ] 另建空间并建立会话，执行完整删除空间；确认不出现任何可访问历史入口。
- [ ] 数据库只读核对可允许旧 session 或排队任务留下失效 entry，但所有 API 均因空间不存在而拒绝。

### AC-05～09/14：移动、重命名和 sticky 归属

- [ ] 把单文件和多层文件夹分别跨空间移动；任务完成后仅源空间根目录出现历史，目标空间不出现。
- [ ] 核对直接 move rows 内的当前文件/后代被回收；额外版本 sibling 不作为本期在线保证失败项。
- [ ] 在同一空间内移动文件/文件夹，确认会话仍归原资源入口，不回收到根。
- [ ] 仅重命名资源，确认会话归属不变。
- [ ] 把跨空间移出的资源移回源空间，确认旧 recovered 会话仍留在根目录；从文件入口问答时创建或选择新的有效会话，不回绑旧会话。

## 3. 权限与负向入口校验

准备用户 A（会话所有者）、用户 B（同空间有访问权）和用户 C（无源空间访问权）。

- [ ] AC-16：用户 B 在源空间根目录看不到用户 A 的 recovered 会话。
- [ ] AC-17：撤销用户 A 的源空间访问权后，A 无法列表、打开或继续 recovered 会话；恢复合法权限后可再次访问。
- [ ] 把普通旧文件夹/文件会话的 `chat_id` 传给根目录 history/chat API，确认在读取历史、构造 retriever和写消息前拒绝。
- [ ] 把 recovered `chat_id` 传给旧文件夹/文件入口，确认拒绝且不重新绑定。
- [ ] 使用其他空间、其他用户、已软删或非知识空间会话的 `chat_id` 请求，确认拒绝且消息数不变。
- [ ] AC-18：目标空间用户不会因资源移入获得源空间会话或内容权限。

## 4. best-effort、并发与运维恢复

- [ ] AC-19：暂停 broker 或模拟 publish 失败后删除资源，确认资源操作仍成功，日志含 `stage=dispatch`、source space、reason 和精确 flow chunk。
- [ ] 恢复 broker，人工重投相同 chunk 或运行迁移脚本，确认会话最终恢复且幂等。
- [ ] 模拟 worker 前两次失败、后续成功，确认有界 retry、`acks_late` 和 retry count 日志；终态失败不回滚资源操作。
- [ ] AC-20：在删除/移动期间创建会话；任务扫描前已提交的会话被回收，扫描后才提交的极低概率残余按已接受边界记录，不要求创建链路阻塞。
- [ ] AC-21：先执行 dry-run，核对数据库身份、分类、掩码样例、`unparseable=0`、`cross_tenant_conflict=0` 和 manifest SHA。
- [ ] 用 reviewed SHA 执行 apply，模拟中断后用 checkpoint 续跑；终态 `recoverable_orphan_remaining=0`，第二次 apply `updated_count=0`。
- [ ] 核对迁移前后 session 原 `flow_id/create_time`、消息、引用和消息时间不变；只有被恢复 session 的 `entry_flow_id/update_time` 可变化。
