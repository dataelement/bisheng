# Design 昆联 Agent 反向调用毕昇 Workflow

- **Feature ID**: F122（当前分支拟用）
- **Status**: CONFIRMED，用户确认继续拆分任务
- **Version**: v3.0.0
- **关联**: [spec.md](./spec.md)、[F121 发布登记设计](../121-kunlian-workflow-management/design.md)、[版本契约](../release-contract.md)、[架构约束](../../../docs/constitution.md)。

## 1. 目标与范围

昆联调用已登记的固定发布版本，获得会话后独立轮询状态和结果。Mock 替代昆联身份和网络协议，毕昇侧使用真实发布资料、图引擎和业务输入输出。最小图为「开始 → 可选文本表单 → 文本输出 → 结束」，V1、V2 使用可区分的输出模板。

首轮候选接入只在隔离测试应用装配。运行图限定为上述节点和线性路径，单次提交提供全部业务输入。人工交互、取消、事件续取、回调、外部资源节点和跨平台嵌套沿用规格中的后续范围。

## 2. 现状与复用

| 现有能力 | 复用及接线边界 |
| --- | --- |
| F121 登记仓储 `RegistrationRepository` | 复用 Flow、FlowVersion、连接范围、登记资料和发布写入的锁顺序。`version()` 返回同步侧资料，调用准入需要在同一事务中重新校验发布状态并写入会话。见[登记仓储](../../../src/backend/bisheng/workflow/domain/repositories/kunlian_registration.py)。 |
| 现有 OpenAPI `invoke_workflow` | 已有业务 `use` 鉴权、用户执行上下文和 Worker 接线。`prepare_invocation()` 读当前 `Flow.data`，事件消费后清理临时状态。F122 单独提供提交和查询入口，复用其身份、权限底座。见[运行入口](../../../src/backend/bisheng/open_endpoints/api/endpoints/workflow.py)、[已发布运行服务](../../../src/backend/bisheng/workflow/domain/services/published_workflow_service.py)。 |
| Workflow 图引擎 | 复用 `Workflow.run()`、图节点、输入处理和回调协议。现有 `run(input_data)` 表示续跑，必须先启动图，到表单等待点后才能提供输入。见[Workflow](../../../src/backend/bisheng/workflow/graph/workflow.py)、[GraphEngine](../../../src/backend/bisheng/workflow/graph/graph_engine.py)、[BaseCallback](../../../src/backend/bisheng/workflow/callback/base_callback.py)。 |

## 3. 关键设计决策

| 决策 | 拟采用 | 比较与依据 |
| --- | --- | --- |
| D-01 固定版本与受理顺序 | 新受理与发布、下线串行，事务内读取登记事实和确切的 `FlowVersion.data`，把图与 Schema 冻结到会话。 | 在 Worker 启动时再读当前图会让请求受版本替换影响。只存版本 ID 仍依赖原对象持续存在及所有写入口长期保持不可变。快照只在运行阶段需要，终态提交后即可清理。 |
| D-02 用户权限 | 凭据适配器建立可信的接入方、租户和实际用户，统一走 F048 Workflow `use`。状态查询还匹配会话归属。 | F121 登记主体只负责目录同步。沿用发布者或服务身份执行会扩大访问范围。 |
| D-03 幂等和运行事实 | Workflow 领域新增一张运行记录表，同时作为幂等记录、待投递记录和状态结果来源。 | Redis 事件会被消费清理，也无法与 F121 发布状态一起提交。独立消息表会增加首轮事务和清理成本，单条记录足以表示一次提交和一次运行。 |
| D-04 调度和图执行 | 复用 Celery 和 Workflow 图引擎，使用专用任务入口与轻量回调适配。请求提交和 Worker 领取分离。 | 直接复用旧调用会进入事件流及会话续跑协议。专用入口保留旧调用合同，轻量回调可把文本输出直接落到 F122 结果记录。 |

## 4. 流程与数据设计

### 4.1 身份与受理

1. 入口从可信适配器取得 `connection_id`、毕昇租户和实际用户。Mock 由隔离应用注入具名的调用方、用户和当前资格。身份只从依赖装配取得，请求体禁止覆盖用户、租户、会话和图参数。正式适配位置保留 `TODO [F122][EXT-01]`，默认拒绝。
2. 在可信租户上下文加载工作流并确认归属，通过 F048 核验实际用户当前具备 `use`。权限查询在 SQL 事务外完成。受理事务内复核工作流仍存在、目标和连接范围匹配。授权不可用时拒绝受理。发布串行化只涉及版本状态，权限在请求和 Worker 启动两道边界各自重新检查。
3. 先查该主体的已有幂等记录。相同业务请求回原会话，更改目标或输入返回冲突。此路径只检查现有会话和当前权限，可恢复已经下线的版本对应的运行。若并发写入唯一键冲突，回滚后重读已提交记录，按同样规则响应。
4. 对初查无记录的请求，锁定 Flow 后再次查同一幂等记录，再判断版本可用性。这样即使同键请求刚受理且版本随后下线，重试也能找回原会话。仍无记录时，沿 F121 的 Flow → FlowVersion 锁顺序，在同一事务读取对应连接下的登记记录，核验 Flow 在线、版本当前且未删除、登记状态 `AVAILABLE`、描述与目标版本一致。确认图符合首轮能力和输入符合该版本 Schema，持久化快照及 `QUEUED` 会话。发布、下线与准入共用 Flow 行作为顺序边界。提交成功后才返回会话并尝试投递。

F048 检查期间隔离上游请求遗留的开放接口、权限主体和访客上下文，以本次核验的实际用户重新做授权决策。幂等、登记和补偿读取命中记录后核对接入方标识是否完全一致，防止数据库排序规则把不同接入方视为相同。

### 4.2 记录与幂等

| 数据 | 用途 |
| --- | --- |
| 会话与归属 | 随机 `session_id`，可信租户、接入方、实际用户和工作流／版本 ID。唯一键覆盖租户、接入方、实际用户与幂等键摘要。 |
| 请求摘要 | 对工作流 ID、版本 ID 和规范化业务输入生成稳定摘要。缺省输入按 `{}` 处理，对象键顺序无关，字符串内容原样保留。幂等键和请求摘要分别计算，比较请求摘要判断冲突。 |
| 执行材料 | 冻结的图、输入输出 Schema、已验证的输入、表单和文本输出定位、内部主体引用。只保存可重新验证的身份引用，凭据原文不进数据库或消息。 |
| 运行及结果 | 状态、领取标识、受理／启动／终态时间、投递和执行截止时间、关联标识、经校验的最终输出或安全失败分类。 |

Mock 使用可控时钟验证窗口。活动会话保留幂等记录，终态后在约定的查询和重试窗口内保留结果与键。终态后清除图、原输入及临时运行材料。Mock 窗口届满后停止查询并分批清除输出，保留摘要记录来拒绝旧键。正式保留期、旧键过期语义、大小限制和清理策略保留 `TODO [F122][EXT-03]`，由双方确定后开放正式入口。

### 4.3 调度与终态

| 阶段 | 处理 |
| --- | --- |
| `QUEUED` | 提交后尽力投递只含会话引用的任务，可信租户通过 Celery 消息头传递。隔离测试接入可扫描同范围内仍待领取的记录并补投，覆盖提交后进程中断、消息发送失败或投递结果未知。超出排队截止时间仍未领取则记为 `FAILED`。正式补投频率与范围需在启用前确认。 |
| `RUNNING` | Worker 在可信租户范围重新读取记录，用原实际用户复核连接、用户状态和 Workflow `use`。使用条件更新把 `QUEUED` 改成 `RUNNING` 并取得领取标识，只有成功领取者能启动图。重复投递及延迟任务不能再次领取。受理后版本替换或下线不重新判定当前版本，始终执行已保存的图。 |
| 图执行 | 以实际用户和可信租户创建 `Workflow`。若该图有文本表单且首次运行停在该输入节点，把已校验的值按 `node_id → 字段值` 映射立即续跑，属于同一个任务。回调收集指定输出节点的文本，按 F121 的 `result` Schema 校验。意外等待、缺输出或输出形态不符归为失败。 |
| `SUCCEEDED`／`FAILED` | 通过领取标识提交终态和结果，并清理运行材料。Worker 丢失或超过执行截止时间，由补偿流程把未结束的领取标为失败，保留同一会话。对已领取任务不自动重跑。迟到的结果不能覆盖终态。超时终态表示结果不可用，Worker 的执行时限也需单独配置，超时状态本身不代表物理取消。 |

### 4.4 查询及安全错误

查询按会话 ID 和可信归属查找，在返回状态或结果前复核当前 Workflow `use`。版本下线时仍可查询已有会话。工作流已删除、租户或主体失效、权限已撤销、对象和会话不属于当前调用方时，按安全口径拒绝访问。未授权与不存在的会话采用统一响应，避免枚举。可用性查询失败返回可重试错误，已记录的运行终态保持原值。

查询在权限复核完成后再检查保留截止时间。F122 启用图引擎异常脱敏，运行日志记录异常类型，失败原因仍按候选接口的安全分类返回。

## 5. 候选接口与替换点

| Mock 候选接口 | 请求与返回 |
| --- | --- |
| `POST /api/v2/kunlian/workflow-runs` | `Idempotency-Key` 加 `workflow_id`、`workflow_version_id` 和 `input`。版本 ID 接受 F121 目录提供的十进制字符串或正整数，返回十进制字符串。新受理返回 `202`，包含 `session_id`、`workflow_version_id`、`status`。同一请求重放返回 `200` 和原会话的当前摘要，输入、目标或版本冲突返回 `409`。 |
| `GET /api/v2/kunlian/workflow-runs/{session_id}` | 返回会话、工作流及版本标识和当前 `status`。`SUCCEEDED` 带 `output`，`FAILED` 带安全 `error`。待执行和运行中只返回状态摘要。 |

候选错误语义区分未认证 `401`、无权提交 `403`、会话不可见 `404`、有权访问但版本不可调用或幂等冲突 `409`、输入不合约 `422` 和暂不可用 `503`。两类 `409` 用不同错误分类，正式业务错误码按 C5 登记。成功与失败使用既有 OpenAPI 封装约定，查询响应禁止共享缓存。日志关联请求和会话，可定位版本、重放、领取和终态，业务输入输出、凭据、原始异常不进入外部错误详情。

## 6. 拟改文件与架构约束

| 计划落点 | 职责 |
| --- | --- |
| `src/backend/bisheng/open_endpoints/api/endpoints/kunlian_workflow_runs.py` | 候选接口、可信身份依赖及 HTTP 映射。Mock 由测试应用装配，正式装配和 scope 待确认。 |
| `src/backend/bisheng/workflow/application/kunlian_workflow_invocation.py`、`workflow/domain/schemas/kunlian_workflow_invocation.py` | 受理、权限、查询和 Worker 协调，输入输出与状态合同。 |
| `src/backend/bisheng/workflow/domain/repositories/kunlian_registration.py` | 提供准入事务内读取并锁定发布事实的入口，和 F122 仓储共享受理事务。 |
| `src/backend/bisheng/workflow/domain/models/kunlian_workflow_run.py`、`workflow/domain/repositories/kunlian_workflow_run.py` | 独立运行表、幂等约束、条件领取、终态和清理。隔离测试先用夹具建表，实际环境迁移另列待办。 |
| `src/backend/bisheng/worker/workflow/kunlian_workflow_run.py`、`src/backend/test/workflow/` | Celery 适配、图执行与结果收集、补投入口及验收用例。 |

架构自检覆盖 C1 分层、C2 MySQL／DM8 通用列和事务语义、C3 可信租户上下文及新增表租户过滤、C4 统一 `use` 授权、C5 错误码、C6 凭据安全和 C8 共享状态。C7 在本期无前端改动的范围内不适用。建议在设计确认后登记运行事实归属及拟新增表，实际环境迁移须独立确认。

正式启用前确认入口、连接配置、存储和补投均就绪。回退时先关闭新受理，保留已受理任务处理和授权查询到窗口结束，再下线入口和补投任务。异常需立即关闭外部访问时，已受理记录保留供核对，关闭入口本身不代表取消运行。
