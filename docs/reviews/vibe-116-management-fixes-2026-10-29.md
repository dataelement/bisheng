## 统一视角实现边界

- `HeaderTenantScope` 复用现有 Select、F019 Redis scope API。明确区分 null 全平台与 id=1 的 Root 租户，加载全部租户选项并过滤非法 ID。
- 切换清理 query cache 并重载页面，覆盖 useEffect 管理的页面及旧表单；模型、工作台和服务账号页的重复选择器移除。
- scope 中间件采用真实路由前缀和路径边界；包括知识库、模型、应用管理、构建的元数据操作、审批管理、审计、权限/角色/用户组等管理请求。聊天执行、工作流 run_once/WS、v2 RPC、个人审批不受管理视角影响。
- 全平台是 SELECT 级受信范围，不等于全局 bypass；INSERT 仍绑定明确租户，业务鉴权和已有显式过滤保留。后台 `tenant_execution_scope` 清除全平台及管理标记，防止扩大 worker 读范围。
- 服务账号仍要求明确租户和原 X-Service-Account-Tenant 范围确认，不能在全平台直接创建/修改。
- 本次对实际报告问题入口及公用过滤器做配对验证；不以通用过滤器测试宣称每个历史模块的定制查询和写权限均已端到端验收。
