# V2 密钥鉴权错误契约 Review

日期：2026-09-14。

依据：工作区当前《3.0 开放 API 鉴权与身份传递 PRD》附录 C、§4.3.1、§4.4.1、§4.4.4、§4.6.1、§4.6.3，以及 AC-1/4/6–10/13/18/20/35/38/41/50。

范围：实际注册的 42 个 HTTP 接口与 2 个 WebSocket 接口；逐项检查响应体 `status_code`、HTTP 状态、异常捕获和校验顺序。修复已有契约的偏差，不新增产品能力。PRD 中已有的工作区修改未作改动。

## 已修复的问题

| 场景 | 原行为 | 校准后的行为 | 依据 |
|---|---|---|---|
| V2 请求带有过期/停用账号的登录 Cookie 或 JWT | 登录中间件可能先返回 `19103/19104/20001/20004`，覆盖密钥鉴权结果 | V2 登录中间件跳过 Cookie/JWT；密钥校验独立决定身份与错误 | 无回落路径；PRD §4.3.1、AC-1 |
| 无密钥且请求 JSON 非法 | FastAPI 在运行鉴权依赖前解析失败，返回参数错误 | 全部 V2 HTTP 路由先鉴权，返回 `401/26001`；不会执行业务 | AC-1、附录 C |
| `.http_exception()` 抛出 `10962` 等业务错误 | 五位业务码被直接用作 HTTP 状态，形成非法 HTTP 响应 | 保留错误类型并统一映射；例如 `HTTP 400 + status_code=10962`；权限类与鉴权类保留各自状态 | §4.4.1：保留业务模块既有错误码 |
| 助手调用的权限拒绝、资源不存在、权限服务不可用 | 被 `except Exception` 转成 HTTP 500 和纯字符串，丢失错误码 | 分别返回 403/404/503，响应保留原业务码；流式与非流式调用均适用 | §4.4.1、AC-13 |
| 日常对话初始化时报鉴权、权限等业务异常 | 提前打开 HTTP 200 的 SSE，在流中返回错误 | V2 在开始 SSE 前抛出，由统一处理器返回对应 HTTP 状态与业务码；V1 保留原 SSE 行为 | §4.4.1、附录 C |
| 非日常对话接口恰好带 `task_mode/run_mode/execution` 且校验失败 | 全局校验处理器把它错误归为 `26017/26015` | 这些语义只由日常对话请求模型处理；任务模式 `400/26017`，异步 `400/26015`，其它接口保留自身错误 | §4.6.3、AC-35/50 |
| 委托能力未授权，同时目标格式非法 | 先解析目标，返回 `26005` | 按五道准入先检查委托能力，返回 `403/26004`；身份头冲突仍为 `400/26010` | §4.4.4 |
| 委托目标为超长数字或超出 User INTEGER 范围 | Python 转换/数据库绑定异常，可能返回 500 或 `503/26030` | 在访问目标仓储前拒绝，返回统一的 `403/26005` | 附录 C、AC-8/41 |
| 主体停用/删除，或因此级联撤销密钥 | 统一返回 `401/26002`，无法区分主体失效与密钥错误 | PAT 返回 `401/26043`；服务账号使用现有扩展码 `401/26027`；普通撤销/过期仍为 `401/26002` | 附录 C 关于主体失效单独成码的说明 |
| 停止其他主体的工作流会话 | 与读取会话共用 404 | 停止返回 403，不触发停止操作；读取/续接仍为 404，不存在的会话仍为 404 | AC-20、§4.6.3 |

## PRD 错误码核对表

下表 HTTP 状态与响应体中的业务码是两个独立字段。HTTP 路径上直接抛业务异常和旧 `.http_exception()` 两种方式均有回归覆盖。

| status_code | 预期 HTTP | 场景 | V2 核对结果 |
|---|---|---|---|
| 26001 | 401 | 缺少/格式非法密钥、误用登录 JWT | 全部已注册 HTTP 接口验证通过 |
| 26002 | 401 | 无效、普通撤销、过期密钥 | 已核对；主体级联失效单独处理 |
| 26003 | 403 | 缺少接口所需 scope | 已核对；`data.required` 标识缺少的权限位 |
| 26004 | 403 | 未授予 delegate 或目标不在范围内 | 已核对；先查委托能力，再解释目标 |
| 26005 | 403 | 委托目标无效、停用、不存在、跨租户 | 同一错误响应；格式与数值范围非法也返回此码 |
| 26006 | 403 | 端点不支持代表模式 | 已核对，仍为第五道准入 |
| 26007 | 403 | 委托目标为超级/租户管理员 | 已核对 |
| 26010 | 400 | 两个身份头冲突 | 已核对 |
| 26015 | 400 | 日常对话要求尚未开放的异步执行 | 已核对，与任务模式独立 |
| 26016 | 400 | delegate 密钥未传 X-On-Behalf-Of | 已核对，不回落至服务账号模式 |
| 26017 | 400 | 要求任务模式，或非法运行模式枚举 | 已核对；同时要求任务与异步时优先报告任务模式未开放 |
| 26040 | 403 | PAT 部署或租户开关未启用 | 两层开关均覆盖 |
| 26041 | 400 | PAT 签发权限位不在白名单 | 错误类映射正确；实际签发入口在 V1，不是 V2 调用入口 |
| 26042 | 400 | PAT 指定有效期超上限 | 错误类映射正确；实际签发入口在 V1，不是 V2 调用入口 |
| 26043 | 401 | PAT 持有人失效 | 包括持有人解析失败及停用/删除引起的级联撤销 |

补充边界：

- `26008/26009/26011` 是 P2 预留，`26013/26014` 已废止，没有启用这些场景。
- `26012` 是平台登录场景，不属于 V2 密钥调用端点。现有 F053 将服务账号与 User 分表，不新增 V2 登录入口或复用该编号。
- `26018/26019/26027/26030/26031/26044` 是已经落地的扩展错误；本次没有占用新编号。PRD 未逐项指定编号的原因沿用已落地设计，不把资源权限错误改成 `26003`。
- WebSocket 按 PRD §4.6.1/AC-18 在握手阶段拒绝。沿用 F053 的关闭码 `1008` 与原因中的 `260xx`；尚未升级为连接，不发送业务数据。WebSocket 关闭码不作为 HTTP 状态码使用。
- 已经开始发送的 SSE 无法修改已发送的 HTTP 响应头；本次修复鉴权和初始化校验提前返回的问题，运行中的错误仍通过流协议报告。

## 验证结果

- **409 项通过**：完整 `test/open_api/`、`test/public_endpoints/`，以及登录 token-version、管理员范围中间件、统一对话入口和文件解析错误的相关测试。
- 新增 `test/open_api/test_prd_error_contract.py`：使用真实生产路由及中间件验证全端点鉴权优先级、码值/状态组合、会话隔离和前置流式错误。
- `.http_exception()` 与直接抛异常均验证 V2 正确状态；V1 对照验证维持 HTTP 200 的既有业务错误信封。
- 修改的 Python 文件通过 Ruff 格式与检查，以及架构守卫；涉及的跨模块 API 导入改为复用领域层凭据监测和身份访问函数。
- 测试采用本地 ASGI 请求、内存 SQLite 和外部依赖替身；本次未执行真实 MySQL/DM8、Redis、OpenFGA 或网关部署环境的集成回归。运行中仅有两项既有依赖弃用警告。
