## 1. 纳入依据与不再捆绑的工作

纳入六项直接租户错位、同一判断链上的合法角色/菜单/Quota、跨租户兼属写前拒绝、基本绑定终止与必要资源pending。不会只修前端候选而漏最终写，也不会修保存后放任菜单/配额继续读另一套scope。

暂不交付跨系统全效果原子收敛、全员持久预留/后台编排、复制全程重启恢复/逐项幂等、外部attempt隔离、DSH全模型门禁发布或全站审计恰好一次。本批并未证明这些需求可以不留持久事实实现；完整复制恢复日后可能仍需要任务/明细表。

## 3. 最小数据变动为何仍有四列

- 工具和Flow SQL已提交、权限尚未确认的窗口真实存在。若无业务pending，super可越过PDP使半成品可用；is_delete和发布status已有其他含义，不能借用。
- 复制源只存COPYING无法区分“是哪一次、哪个目标占用”。update_time不是唯一操作标识。精确源/目标指针用于失败定位和防止旧worker解除后一次占用。
- 不额外加政策generation、parent_ref、批次游标、lease、operation payload或任意恢复调度字段；不存在把七表机械折叠到JSON的替代方案。
