# Feature: 企业插件与企业工作台按用户 / 部门 / 用户组授权

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。How 的唯一真相在 [design.md](./design.md) 与 [tasks.md](./tasks.md)。
>
> **前置步骤**：Spec Discovery 已于 2026-11-16 与需求方（Callum）对齐，结论见 §5。

**关联 PRD**: 「工具、技能、插件体系」需求 ——「企业工作台和插件增加权限管理 - 用户/部门/用户组，涉及 bs 和 bs desktop」（需求方口述，2026-11-16）
**优先级**: P1
**所属版本**: v3.1.0-beta2
**依赖**: F048 统一资源权限（含 F118「全平台权限移除 use 动作，只保留可见」口径）；企业插件市场；v3.1.0-beta1 F019 企业工作台市场

> **范围边界**
> - **本次纳入**：
>   - 企业插件、企业工作台（企业管理员上传到本企业市场的插件和工作台包）按用户、部门、用户组授权，授权后员工「可见即可用」。
>   - 管理后台为每个企业插件、企业工作台提供权限设置入口。
>   - 新上传的和升级前已有的企业插件、企业工作台默认对全企业可见。
>   - 员工侧（BISHENG 桌面客户端）只能看到、安装、下载自己有权限的项；权限被收回后，已安装的自动停用（保留安装和用户数据），恢复授权后可再次启用。
>   - 已部署环境升级到本版本时，使本特性生效的升级步骤。
> - **收窄的既有规格**（本特性生效后以本文为准）：
>   - [F055](../../v3.0.0-beta1/055-enterprise-plugin-market/spec.md)「员工在 Desktop 安装本租户可用插件」→ 只能安装有可见权限的企业插件（AC-07）。
>   - F055 **AC-WB-04**「已登录 Desktop 可查询本租户当前工作台列表、详情，并下载当前版本」→ 只对有可见权限的员工成立（AC-08）。
>   - [F019](../../v3.1.0-beta1/019-dsh-market-workbench/spec.md) **AC-05**「删除后保留记录，主动重导入可恢复」→ 恢复时沿用删除前的授权（AC-18）。
> - **本次明确排除**：
>   - **云端工作台（企业托管应用）**：已有按人授权（发布时设置可见范围），本特性不改。
>   - **公开市场的第三方插件 / 工作台，以及「允许安装第三方插件 / 工作台」开关**：开关只控制员工能否从公开市场安装第三方内容，与企业自己上传的插件、工作台无关，行为保持不变。
>   - **多级权限**（如「看得到但不能安装」、按项委派管理权）：只有一级，可见即可用。
>   - **收回权限后自动卸载或删除数据**：只停用。
>   - **离线时强制收回企业工作台**：客户端联系不上企业服务时，不因此停用已安装的企业工作台（见 AC-14）。

## 1. 用户故事

**A. 企业管理员**
作为 **企业管理员**，
我希望 **把某个企业插件或企业工作台只开放给指定的用户、部门或用户组**，
以便 **只在特定岗位使用的业务能力、涉及敏感数据的工具，不被无关人员看到和使用**。

**B. 员工**
作为 **员工**，
我希望 **在客户端只看到自己能用的企业插件和企业工作台；权限被收回时清楚知道原因，恢复后能继续使用原来的数据**，
以便 **不被无关的东西干扰，也不会因为权限变化丢失工作成果**。

**C. 运维人员**
作为 **负责升级部署的运维人员**，
我希望 **把已有环境升级到本版本时，按升级说明执行一次可预览、可回滚的步骤即可生效**，
以便 **升级过程可控，出问题能退回**。

## 2. 验收标准

### 2.1 管理员授权

- **AC-01** — WHERE 管理员有某个企业插件的权限管理资格, THE SYSTEM SHALL 在管理后台的企业插件列表为该插件提供权限设置入口，支持按用户、部门、用户组授予或收回可见权限，并支持设为全企业可见或取消全企业可见。
- **AC-02** — WHERE 管理员有某个企业工作台的权限管理资格, THE SYSTEM SHALL 在管理后台的企业工作台列表为该工作台提供与 AC-01 相同的权限设置能力。
- **AC-03** — WHEN 管理员上传一个新的企业插件或企业工作台, THE SYSTEM SHALL 默认授予全企业可见。
- **AC-04** — WHEN 已部署环境完成本版本升级, THE SYSTEM SHALL 让升级前已存在的企业插件和企业工作台对全企业可见，员工看到的企业插件、企业工作台与升级前一致。
- **AC-05** — THE SYSTEM SHALL 对企业插件、企业工作台采用与技能相同的授权口径：对同一组用户、部门、用户组授权设置，员工对企业插件、企业工作台的可见结果与对技能的可见结果相同（包括部门授权是否覆盖下级部门、用户组成员的认定、命中多条授权时取并集）。
- **AC-06** — THE SYSTEM SHALL 在管理后台的企业插件、企业工作台列表中，向有管理资格的管理员显示全部企业插件、企业工作台，不按管理员本人的可见权限过滤。

### 2.2 员工侧可见与下载

- **AC-07** — WHILE 员工对某个企业插件没有可见权限, THE SYSTEM SHALL 不在该员工的企业插件列表中显示该插件；该员工按标识下载该插件时拒绝请求，不返回其文件、名称或描述，客户端提示该插件不可用。
- **AC-08** — WHILE 员工对某个企业工作台没有可见权限, THE SYSTEM SHALL 不在该员工的企业工作台列表中显示该工作台；该员工按标识查看详情或下载该工作台时拒绝请求，不返回其文件、名称或描述，客户端提示该工作台不可用。
- **AC-09** — WHEN 员工新获得某个企业插件或企业工作台的可见权限, THE SYSTEM SHALL 在员工下一次刷新企业市场时显示该项，无需重启客户端。
- **AC-10** — IF 员工在已打开的市场页面中安装一个其已失去可见权限的企业插件或企业工作台, THEN THE SYSTEM SHALL 安装失败并提示该项不可用，不留下部分安装的内容。

### 2.3 收回与恢复

- **AC-11** — WHEN 员工失去某个已安装企业插件的可见权限，且客户端在线并完成下一次与企业服务的同步, THE SYSTEM SHALL 停用该插件、保留其安装，并在插件页面提示「管理员已收回使用权限」，与普通「已停用」区分。
- **AC-12** — WHEN 员工失去某个已安装企业工作台的可见权限，且客户端在线并完成下一次与企业服务的同步, THE SYSTEM SHALL 停用该工作台（入口不可再打开），保留其安装以及已有会话、项目文件和工作台笔记，并提示「管理员已收回使用权限」。
- **AC-13** — WHEN 员工重新获得已停用的企业插件或企业工作台的可见权限, THE SYSTEM SHALL 允许员工再次启用，启用后原有配置和数据可继续使用。
- **AC-14** — IF 客户端联系不上企业服务, THEN THE SYSTEM SHALL 让已安装的企业工作台保持上一次确认的启用状态；企业插件保持现有离线行为不变。

### 2.4 不受影响的部分

- **AC-15** — THE SYSTEM SHALL 保持「允许安装第三方插件 / 工作台」开关以及公开市场插件、工作台的现有行为不变。
- **AC-16** — THE SYSTEM SHALL 保持云端工作台的现有授权与可见范围不变。
- **AC-17** — WHEN 管理员删除一个企业插件或企业工作台, THE SYSTEM SHALL 不再在任何员工的列表中显示它，员工按标识也无法查看或下载。
- **AC-18** — WHEN 管理员重新导入以恢复一个已删除的企业插件或企业工作台（F019 AC-05 / F055 的恢复语义）, THE SYSTEM SHALL 沿用其删除前的授权，不重置为全企业可见。

### 2.5 部署与升级

- **AC-19** — WHERE 全新安装, THE SYSTEM SHALL 无需额外操作即可使用本特性。
- **AC-20** — WHERE 已部署环境升级到本版本, THE SYSTEM SHALL 提供与现有授权模型升级一致的升级步骤：执行前可预览且预览不改数据、执行后可校验、可回滚；升级说明须写明执行后需要重启的服务。
- **AC-21** — THE SYSTEM SHALL 在 MySQL 与达梦部署上行为一致。

## 3. 边界情况

- 员工同时属于多个被授权的部门或用户组，只要命中任一授权即可见（AC-05）。
- 管理员取消「全企业可见」后没有授权给任何人：员工端无人可见，管理员在后台仍可看到并继续设置（AC-06）。
- 企业插件被管理员停用、但员工有可见权限：仍按现有的「停用」处理，权限不会让停用的插件重新可用。
- 同一员工在多台设备上安装：每台设备在线并完成同步后分别生效。
- 权限在员工使用企业工作台的过程中被收回：在下一次同步时生效，不要求打断正在进行的单次操作。
- 被授权的用户、部门或用户组被删除或变动后的可见结果，与技能在同样情况下的结果一致（AC-05）。
- 已部署环境只更新了程序、没有执行升级步骤：升级说明须明确这是不允许的状态及其后果，部署流程须包含升级步骤（AC-20；具体后果和防护见 design.md §5）。

## 5. Spec Discovery 结论（2026-11-16，需求方确认）

1. 只有一级权限：可见即可用（看得到就能安装、启用、使用）。
2. 权限收回后：停用，不卸载、不删用户数据；恢复授权后可再启用。
3. 新上传的默认全企业可见；升级前已有的也补成全企业可见。
4. 与「允许安装第三方插件 / 工作台」开关互不影响（开关只管公开市场的第三方内容）。
5. 服务端、管理后台、桌面客户端由本特性一并实现。
6. 云端工作台已有授权，不在范围内。
7. 删除后重新导入恢复时，沿用删除前的授权（2026-11-16 Spec 评审时确认，选项 A）。
