# 型号批次与采购会话合同 v0.3

HTTP mock先补齐分页，再按型号拆为最多3份单型号批次；真实客户API未接通。每份原始批次不可变，会话保存筛选、排序、页码、指纹、上一展示引用与本次甲方。HTTP合同见mock-api.md。

Chat的唯一分析入口现为procurement.run(request)，由采购专用执行器固定调用并直接呈现终态answer；模型不操作下述底层CLI路径。入口内部保存固定registry，仅新批次首次load，续问恢复状态执行单动作。具体结构见platform-runtime.md，本文保留下层批次及引擎合同。

## 批次

- schema_version为1，model为明确型号，所有CJ型号须与其格式归一后相等。
- complete为布尔true，total_records等于rows及source_rows的长度；完整空批次可为0。不完整批次先补齐，不给全量统计。
- columns是原Excel表头数组，保留重复名称和列位置；rows为等宽标量数组，不执行公式。
- source_rows保留真实原Excel行号且唯一；后续API适配器提供稳定批次行引用。
- provenance存原文件、工作表、原SHA256和覆盖范围，不含凭据。批次SHA256由同一份文件字节计算，独立于来源哈希。
- “完整”仅针对本批声明范围，不等于生产全部历史。模拟源仅为用户Excel样例。
- 本地预算25MiB、10万行、200万单元格，超限明确停止。

字段按位置和精确表头一起检查：A/B订单身份；F/G供应商；H/I制造商；J币种、L整单总价；O/P贸易条款及地点；Y确认时间；AD/AE客户；BZ明细ID、CA外键、CB订单号、CC行号；CG/CH编码、CI名称、CJ型号、CK牌号、CL技术规范；CP单位、CQ数量、CR单价、CS行金额。其他列保留于原始批次，不全部送入模型。

主外键、主明细订单号须一致；明细ID和订单＋行号须唯一，不按型号去重。数字用Decimal，缺失不当0，非有限/异常数字不参与价格证据。单型号不能代表整单，因此不以明细合计判断订单总价正确性。

## 动作与状态

固定参数为--batch、--session及--request-file（或结构化stdin），批次与会话路径不得相同；由执行器绑定各用户对话文件，不能从单元格选路径。

| action | 合同 |
|---|---|
| load | model必需，与批次一致；加载或显式刷新时保留既有明确筛选，清空展示并回第一页 |
| show | 展示当前筛选，可改sort、page、page_size；改排序/每页数默认回第一页 |
| filter | set设置/替换指定条件，unset移除指定条件，两者不得重叠；其他条件保留，回第一页 |
| reset | 清空筛选、恢复time_desc、回第一页，不改原批次 |
| compare | positions（上一展示1起序号）或line_ids二选一，2—10条且不重复；不能同时排序/翻页 |
| suppliers | 沿用当前型号及筛选展示历史供应商，purchaser可选并独立保存；按空客QPL/商飞QSL/其他跳过附名录证据；清除旧价格行位置 |

筛选为supplier、customer、date_from、date_to、currency、unit、incoterms、incoterms_place。对象可用精确标识或名称；日期YYYY-MM-DD、含首尾、按确认时间；所有条件AND生效。未知参数、非法日期、空筛选不忽略。sort为time_desc/price_asc/price_desc/none，page_size默认20、范围1—50。

ok/no_records才提交状态；空结果保留条件、清空展示，取消条件从原始批次恢复。非法动作、过期或越界选择不覆盖有效会话。批次指纹变化必须显式load后重选；不能继续解释旧行号。

## 输出

返回source、query、active_filters、原始条数、命中/展示数/has_more。明细保留line_id、订单号及source_row；展示序号不等于源行号。

summary在当前完整筛选结果上统计订单数、供应商数，逐条件组给记录数、有效价格数、观测最小/最大单价及依据、同一最近确认时间的全部记录。分页不改变统计范围。current_quote为空，不自动生成本次报价。

comparison给所选明细、可计算时的最大最小价差、differing_fields。basis_complete仅指币种＋单位＋贸易条款＋地点与数值完整，不证明原厂/税费/技术规格等业务可比；causal_explanation为空。

固定入口向用户呈现的有符号差额另按选择顺序明确映射：第1条为基准，比较条单价减基准单价；比值为比较条单价除基准单价，四位小数、基准0不算比值。不能把下层最大最小价差错标成有方向的两条记录差额。全部当前页业务行只在终态answer出现一次，完整下层结果内部保留。

报价/询价/成交时间、合同号、是否成交未建立映射，列为未提供，不用确认时间、订单号或确认状态替代。

## 异常

- no_records：本批及当前条件无结果，不推断全历史或市场无货。
- needs_clarification：缺型号、选择或未加载；needs_new_batch：请求型号不属于当前批次。
- incomplete_batch：声明不完整或条数不符；model_mismatch：混入其他型号。
- schema_error/data_integrity_error：结构、身份或公式问题，停止。
- stale_source/invalid_selection/page_out_of_range/invalid_request/session_error/file_or_state_error：按具体问题解释，不当0记录，不自动改数据。

旧query_orders.py保留history/suppliers/compare回归入口。suppliers提供有历史依据的候选及条件组内排序，名录lookup提供所给版本证据，均不自动下准入结论。运输、报关、实际交付排序、预测与下单不在本版范围。

## 2026-11-12 白名单与供应商视图修订 v0.5.4

## 2026-11-12 手动采购流程修订 v0.6.0

用户已明确本阶段手动输入、按型号文本识别；不要求询价单自动事件或唯一物料主键。精确未命中先在对话核对：修正后用新的精确查询；确认不修正直接以原主号字面正则召回最多3个近似型号。主号为首个空格前片段；无空格则移除最后一个连字符后缀，至少4个字母/数字；无有限主号先补主号，不允许.*全量试探。近似无结果结束，筛选导致空结果不进入型号修正链。

resolve显式绑定待核对状态及新API文件；choose只接受当前候选序号/名称，选择后沿用该型号，比价不跨型号。用户无需再次批准近似搜索，不使用平台选择表单阻断恢复。

2026-11-13 v0.6.10：choose允许候选序号与完整型号同时出现，前提是两者精确指向当前同一候选；冗余一致的信息不视为冲突。序号与型号矛盾、缺少选择、越界或非当前候选均拒绝且不改变选择/筛选状态；不默认选第一个，不放宽API字段和跨型号边界。该逻辑兼容多种自然说法，不要求使用固定选择句。

同日v0.6.11完整演示补充：history续问可携带合法set/unset，与公开工具合同和已有“先原子筛选、再显示历史”的执行路径一致。撤销某一条件仅移除指定字段，保留其他条件；非法字段、同字段同时设置撤销、非法值仍在改状态前拒绝。filter仍是优先动作，不为模型选择了history而拒绝语义等价的历史筛选/撤销请求。

手动多型号batch最多20项，每项自己的API文件、隔离注册表/筛选/甲方/选中状态。一个失败或待核对不阻断已取数其他项；batch_summary保留所有输入与当前状态，失败不计完成，相同输入型号仍保留两个输入项。item_index是输入项序号，candidate_position是相近型号序号，positions是历史价格记录序号。普通新型号查询退出批次默认焦点，旧汇总仍可查看。本版没有自动询价单解析或附件逐行读取。平台API工具原有HTTP失败终止策略尚不能证明多请求网络失败后的续取能力，需单独联调，不用本地逐项导入测试冒充覆盖。

confirm仅记录当前已展示、按当前甲方可推荐的历史供应商作为询价对象；确认前重算候选，保存当时数据来源/查询/筛选/价格与名单证据。记录位于当前Chat隔离工作区，时间由代码生成，不接受模型指定确认人/时间；未单独验证业务人员身份。相同有效依据重复确认不重复保存，最多100条，confirmations查看、unconfirm追加撤销事件，不删除原依据。本记录不写客户业务系统，不代表下单或跨会话台账。不同型号/甲方不自动改写旧记录。

交付表现仍缺数据：explain_limits topic=delivery只说明缺口，不输出虚构交付排名。无历史型号的供应商推荐已由v0.7.0取代原“只说明缺口”约定，见文末。正式中台API、发票关联和交付口径继续等待客户。

## 2026-11-15 供应商推荐 v0.7.0

用户确认（2026-11-15）：没有历史记录也要推荐供应商；推荐结果给出排序和首选。本节取代旧“suppliers只列有历史依据的候选”“无历史反向寻源只说明缺口”“不推断综合最优”的约定。

推荐由scripts/recommendation.py固定代码完成，模型不参与排名。候选分四层，层间固定先后：①历史供货——本型号历史采购的供应商，且通过本次甲方名录（空客QPL/商飞QSL；其他甲方或未指定不过滤）；层内按采购记录数降序、最近确认日期降序，全部候选同一币种和单位时再按历史最低单价升序，否则不比价并提示。②规范命中——型号/物料文本中的AMS规范号与QSL standard_code相同的QSL供应商。③类别匹配——由物料描述关键字（液体、涂料、密封胶、铝、钛、钢、成品、壁板、非金属等）或波音BMS规范系列（3/5/10→化工耗材，8→非金属/复合，7→钢；系列级推断，待业务确认）识别类别；规范号在QSL登记的材料类别也用于确定类别。金属类别取QSL同material_category供应商及QPL AFM-002-1/AFM-002-2；化工耗材取QPL GP-1-73D（主组）、AFM-002-1；非金属取QPL AFM-002-1/AFM-002-2；结构件取QPL AFM-001-2（主组）、AFM-001-1、AFM-002-3。④通用渠道——类别无法识别时取QPL材料分销组AFM-002-1、AFM-001-4、SAT-1-1。名录候选层内按命中规范条目数（QSL）或命中映射产品组数、是否命中主组、获批产品组总数（QPL）降序，再按名称。排名第1即首选，展示前10家并给出总数。

甲方约束保留：空客只推荐QPL内、商飞只推荐QSL内供应商（QSL只收录金属，非金属类别对商飞明确提示无可推荐）；历史供应商未列入名录仍排除并单列。推荐只用于确定询价对象，不是报价、准入结论或下单；名录候选的主体、场所与产品适用范围须复核。

入口：suppliers视图（含choose/resolve/batch的suppliers意图）在历史供应商明细前附“供应商推荐”；精确0条且意图为suppliers时在型号核对提示后附推荐；近似也无结果且意图为suppliers时附推荐；explain_limits topic=sourcing对当前型号出推荐（有已选或唯一精确型号时走suppliers视图）。工作区uploads/procurement-runtime/recommendations.json按型号保存最近一次推荐表；confirm可用supplier_name确认表中无历史的名录候选，证据保存推荐层级、排名、理由、名录来源和物料识别依据，并提示无本型号历史采购记录。历史供应商的confirm规则不变。

已知限制：样例历史数据只有物料名称（液体、成品材料、复合壁板等），缺技术规范和制造商；QSL只覆盖金属材料（AMS规范），QPL只有企业×产品组、没有物料规范，因此BMS波音规范、185A等件号在两份名录中都没有规范级命中，只能做类别级或渠道级推荐。BMS系列与类别的对应、关键字到QPL产品组的映射需业务确认。用户在对话中补充的物料描述目前无法传入执行器（公开工具合同的explain_limits/suppliers不接受物料字段），类别只能从型号和历史物料名称识别。


## 2026-11-26 历史查询与显式供应商意图边界

history及历史视图的show/filter/reset只返回历史明细、价格、比较条件与来源，不执行供应商查询、名录核验或生成候选；compare也不附推荐。精确无历史和近似无历史在history意图下只走型号核对及结束流程；仅明确suppliers或explain_limits topic=sourcing才生成供应商/名录结果。历史后明确要供应商沿用当前完整批次，无需重新取API。已有候选遇到型号查询、甲方或筛选范围变化及筛选空结果仍按原规则失效，不因暂时转历史视图或撤销筛选恢复旧编号；同范围历史展示不生成或重编号候选。近似选择、批量隔离、确认和撤销规则保持。
