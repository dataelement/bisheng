# 知识空间文档统计升级

看板与 `export_portal_category_usage.py` 共用文档身份：优先 `reference_document_id`，其次版本表 `document_id`，无文档关系时使用独立 `file_id`。文件 ID 与文档 ID 使用不同前缀。同一知识的发布、分享引用合并计 1，独立上传不按名字或 MD5 合并。

## 指标口径

| 指标 | 计算规则 |
| --- | --- |
| 总文件数 | 当前有效库存，在筛选范围内按文档去重 |
| 新增文件数 | 当前筛选范围内文档首次有效入口的创建时间落入选定期间；后续分享不重复新增 |
| 被系统化调用知识数 | 入选知识任一非个人入口曾有预览或下载日统计大于 0，计 1 |
| 调用比例 | 被系统化调用知识数 / 总文件数，分母为 0 时返回 0 |
| 知识贡献占比 | 当前分组去重知识数 / 全部筛选结果去重知识数 |
| 预览次数、下载次数、收藏次数 | 保持操作次数口径 |

个人库选项保留；与脚本对账时选择公共库、部门库、团队库、科室库，排除个人库。
调用范围固定为同租户全部非个人空间，不随库存的上传人组织筛选缩小。个人库文档若没有非个人入口调用，调用数为 0。
组织归属为上传人当前主组织；按组织及子组织对账时，选择对应上传人层级维度，不能用“所属库组织”或“原始上传库组织”代替。名称重名时看板的名称维度会合并，脚本的 `--department-id` 不会；这种情况下须用上传人 ID 集合等价筛选再对账，不能直接比较同名组织标签。

总数和调用数按时间桶结束时间累计，新增数按桶内首次出现时间计算；日、周、月、年使用北京时间。调用记录来自日统计，不能提供小时精度的调用数，选择小时粒度会明确报错；查询历史调用的截止时间须为完整自然日末（23:59:59），不支持日内历史截止点。
同一知识可属于多个分组；行、列、组织小计及总计均重新去重，因此不一定等于子项相加。比例合计重新计算分子分母，不对比例求和。展示条数上限不改变服务端合计。
明细导出一文档一行，关联入口、空间、组织合并展示；调用比例明细列出分子即已调用知识。整图导出按筛选结束时的文档集合，点击时间桶导出对应桶的集合。超过导出上限会报错，不截断成功输出。

**历史边界：** 库存是当前有效库存投影，不能还原已经删除的历史库存。历史入口在数据库中仍保留时可关联调用；已物理删除且没有文档关系的历史记录不能猜测归属，迁移保留原记录并输出无法关联诊断。重新导入索引不能恢复源系统已丢失的行为记录。历史操作次数仍使用事件发生时的维度快照，新文档调用数按当前库存归属，所以组织调动后不能用组织内预览次数直接反推调用知识数。

## 正式执行

以下命令从 `src/backend/` 运行，配置读取与导出脚本一致的业务 ES。索引名称须唯一且不存在；工具不会覆盖已有目标或备份。迁移支持源名称为实体索引或指向单一实体的别名。

1. 在测试环境运行只读预检，检查库存、历史记录、无法关联数量，确认 ES 有新索引和备份所需磁盘空间及克隆、别名权限。对真实数据量做查询耗时与内存验证。
2. 安排维护窗口，暂停知识业务写入、遥测消费、统计 worker 和 beat；等待在途任务完成。保留原配置、原应用版本。仅停止定时任务不足以阻止请求路径写入日统计。
3. 使用新版本代码运行迁移；此时新版 API 暂不对外提供统计查询。新版数据集未迁移时会明确返回“统计尚未就绪”。

```bash
.venv/bin/python scripts/migrate_knowledge_document_statistics.py \
  --config config.yaml \
  --target-index mid_knowledge_space_content_stat-doc-v1-20260921 \
  --backup-index mid_knowledge_space_content_stat-backup-20260921 \
  --apply --writers-paused --confirm-index mid_knowledge_space_content_stat \
  > knowledge-document-migration-report.json
```

4. 检查退出码为 0 且报告 `switched=true`。核对各记录类型数量、预览/下载/收藏次数、内容摘要。实体源索引会在原子切换中移除，但已校验的完整克隆备份保留；别名源的原实体也保留。脚本不修改业务库。
5. 部署同版本 API、worker 和前端。启动 API 会更新已保存数据集的指标定义，原图表字段 ID 保留；需要手动在图表配置选择新增两个指标。
6. 恢复统计消费和同步，等待待处理队列及库存同步完成。用同租户、同组织、同非个人空间范围比较脚本四列；同时检查跨组织分享只计 1、调用比例、导出行数及总计。全部通过后恢复正常写入。

维护期间的检查和代码更新须使用实际部署方式，不应直接照抄未核实的容器名或服务名。真实 ES 环境未验证前，不将本地测试视为发布通过。

## 失败与回退

切换前失败会保留原指向并恢复源写入设置，新目标和备份保留供诊断。切换应答不确定时，先查询 ES 别名确认实际状态，不能盲目重跑。任何重试均使用新的目标和备份名称。

如果切换成功但尚未恢复写入，可使用同一目标和备份运行回退预检：

```bash
.venv/bin/python scripts/migrate_knowledge_document_statistics.py \
  --config config.yaml \
  --target-index mid_knowledge_space_content_stat-doc-v1-20260921 \
  --backup-index mid_knowledge_space_content_stat-backup-20260921 \
  --rollback
```

确认仍暂停写入后，加 `--apply --writers-paused --confirm-index mid_knowledge_space_content_stat` 执行回切，并恢复原 API、worker、前端及原数据集定义。备份为旧结构，新版精确查询不会接受它。工具保留新索引，便于复核。
如果迁移后已有新写入，回退校验会拒绝切换；必须先对账并处理新增数据，避免用旧备份覆盖新行为。回退过程中若检测到并发写入，目标保留只读，需要人工核查后处理。

## 验收记录

部署后保存迁移报告、脚本的 `统计口径.json`/CSV、相同筛选条件的看板导出、同步结束时间和应用版本。先比较知识总数，再比较被调用知识集合；数据源残缺、同步未完成、筛选组织重名及日期边界应单独列出，不能统一当作 0。
