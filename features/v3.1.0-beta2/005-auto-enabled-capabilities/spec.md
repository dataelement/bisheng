# Feature: 工作台工具与技能「自动启用」

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答做什么、验收标准、不做什么。How 的唯一真相在 [design.md](./design.md) 与 [tasks.md](./tasks.md)。

**关联 PRD**: 无（2026-11-20 用户口头需求 + Spec Discovery 对齐，见本文 §0）
**优先级**: P1
**所属版本**: v3.1.0-beta2
**依赖**: F004-unified-agent-runtime（本特性基于 F004 的统一发送入口与直接回答挂载技能能力开发，F004 合入 beta2 后本特性再合入）

> **范围边界**
> - **本次纳入**：
>   - 工作台配置的「已选工具」：每个工具可设为「自动启用」。
>   - 技能管理里的企业技能（含内置技能和管理员上传的技能）：每个技能可设为「自动启用」。
>   - 用户端（网页用户端，以及嵌入网页用户端的桌面端 Chat）的工作台对话：直接回答与深度研究两种方式。
> - **本次明确排除**：
>   - 开放 API（日常对话 API、F073 任务模式 API）不自动补入：调用方显式传什么就用什么。原因：已有集成的运行结果不应因管理员改配置而变化。
>   - 助手、工作流里的工具选择不受影响：它们由应用的构建者配置，不经过工作台配置。
>   - 个人技能不能设为自动启用：个人技能归用户自己管理，管理员看不到。
>   - 不隐藏执行过程：自动启用的工具调用、技能加载步骤在对话的执行过程里照常显示。「不展示」只作用于选择入口。
>   - 不按用户或部门区分使用方式：同一租户内一个工具或技能只有一种使用方式。谁能用仍由既有的使用/可见权限决定。
>   - 不改变默认值：新装和升级后，没有任何工具或技能是自动启用；由管理员手动设置。

---

## 0. 术语

- **自动启用**：管理员给工具或技能设置的一种使用方式。设为自动启用后，该工具或技能不出现在用户端的任何选择入口里；用户每次在工作台发送消息时，系统自动让 agent 能使用它，用户不能关掉它。
- **使用方式**：管理员给工作台工具设置的三选一属性：
  - **用户自选**：出现在用户端工具菜单里，默认不勾选。
  - **默认勾选**：出现在用户端工具菜单里，新会话预先勾选，用户可以取消。
  - **自动启用**：见上。
  技能只有两种使用方式：**用户自选**与**自动启用**（技能的「默认勾选」已于 2026-11-11 决定不恢复）。
- **选择入口**：用户端让用户挑选工具或技能的界面，包括输入框的工具菜单、输入框里已选工具和技能的标签、技能选择器、技能中心的企业技能列表、能力中心（侧边栏「工具与技能」）的工具和技能列表。

## 0.1 Spec Discovery 结论（2026-11-20 用户确认）

- 基于 F004 分支开发。
- 直接回答也要挂载自动启用的技能（接受直接回答准备时间变长，交付前实测）。
- 默认值：全部保持「展示」；新装时代码执行器与联网搜索仍为默认勾选。
- 开放 API 不自动补入。

## 1. 用户故事

作为 **租户管理员**，
我希望 **把代码执行器、内置的 Word / PPT / Excel 技能这类基础能力设为自动启用**，
以便 **用户不用学习和理解这些能力，也不会因为没勾选而用不上**。

作为 **普通用户**，
我希望 **输入框里只出现我需要自己判断要不要用的工具和技能**，
以便 **少一些看不懂的选项，提问时不用先想该勾什么**。

## 2. 验收标准

### 2.1 管理端：工具

- **AC-01** — THE SYSTEM SHALL 让工作台配置「已选工具」里的每个工具，在「用户自选 / 默认勾选 / 自动启用」三种使用方式中有且只有一种。
- **AC-02** — WHEN 管理员把某个已选工具设为自动启用并保存, THE SYSTEM SHALL 保存该设置；管理员重新打开配置页时，该工具仍显示为自动启用。
- **AC-03** — WHEN 一个环境从没有本特性的版本升级上来, THE SYSTEM SHALL 让每个已选工具保持升级前的行为：升级前默认勾选的显示为「默认勾选」，其余显示为「用户自选」，没有工具变成自动启用。
- **AC-04** — WHERE 环境里还没有保存过工作台配置（新装）, THE SYSTEM SHALL 让预置的联网搜索与代码执行器显示为「默认勾选」。
- **AC-05** — THE SYSTEM SHALL 让设为自动启用的工具仍计入已选工具的数量上限。

### 2.2 管理端：技能

- **AC-06** — WHEN 管理员在技能管理里把某个企业技能设为自动启用, THE SYSTEM SHALL 保存该设置，技能列表里显示该技能的使用方式为自动启用。
- **AC-07** — WHILE 技能处于停用状态, THE SYSTEM SHALL 不允许修改它的使用方式，并且该技能对用户不生效（停用优先于自动启用）。
- **AC-08** — WHEN 系统启动时重新同步内置技能, THE SYSTEM SHALL 保留管理员给内置技能设置的使用方式；设置使用方式也不改变该内置技能后续接收内核更新的资格。
- **AC-09** — WHEN 一个环境升级到本特性, THE SYSTEM SHALL 让所有已有技能的使用方式为「用户自选」。

### 2.3 用户端：不展示

- **AC-10** — WHILE 某工具为自动启用, THE SYSTEM SHALL 不在用户端输入框的工具菜单、已选工具标签和能力中心的工具列表里展示它。
- **AC-11** — WHILE 某技能为自动启用, THE SYSTEM SHALL 不在技能选择器（直接回答与深度研究）、技能中心的企业技能列表和能力中心的技能列表里展示它。
- **AC-12** — WHEN 用户此前保存的工具选择里包含一个现已自动启用的工具, THE SYSTEM SHALL 不再把它显示为已选标签，并且该工具在一次运行里只挂载一次。
- **AC-13** — WHEN 管理员把工具或技能从自动启用改回其他使用方式, THE SYSTEM SHALL 在用户下次加载页面后让它重新出现在对应的选择入口里。

### 2.4 用户端：自动生效

- **AC-14** — WHEN 用户在工作台发送消息（直接回答或深度研究）, THE SYSTEM SHALL 让 agent 能调用所有自动启用、且该用户有使用权限的工具，与用户勾选了哪些工具无关。
- **AC-15** — WHEN 用户在工作台发送消息（直接回答或深度研究）, THE SYSTEM SHALL 让 agent 能使用所有自动启用、且该用户有可见权限的技能，即使用户一个技能都没选。
- **AC-16** — THE SYSTEM SHALL 不把自动启用的技能当作用户这一轮选中的技能：agent 收到的「用户选中了哪些技能」只包含用户自己选的。
- **AC-17** — IF 用户对某个自动启用的工具没有使用权限, 或对某个自动启用的技能没有可见权限, THEN THE SYSTEM SHALL 不对该用户生效，也不报错。
- **AC-18** — IF 用户此前在能力中心停用过某个企业技能, 而管理员随后把它设为自动启用, THEN THE SYSTEM SHALL 对该用户生效。
- **AC-23** — IF 用户此前在能力中心停用过某个工具, 而管理员随后把它设为自动启用, THEN THE SYSTEM SHALL 对该用户生效。
- **AC-19** — WHEN 用户在一次运行进行中发送的消息被排队，随后由接力运行处理, THE SYSTEM SHALL 让接力运行同样带上自动启用的工具和技能。
- **AC-20** — THE SYSTEM SHALL 在对话的执行过程里照常显示自动启用的工具调用和技能加载步骤。

### 2.5 开放 API

- **AC-21** — WHEN 调用方通过开放 API 发起对话或任务, THE SYSTEM SHALL 只使用调用方传入的工具和技能，不补入自动启用项。
- **AC-22** — THE SYSTEM SHALL 在开放 API 返回的日常配置里照常列出自动启用的工具（调用方仍可以显式传入它们）。

---

## 3. 边界情况

- 多租户：子租户继承根租户的工作台配置时，工具的使用方式随配置一起继承；技能的使用方式按租户各自设置。
- 自动启用的工具在租户里被删除或下线：不再对用户生效，配置页的已选工具里也不再出现（与今天已选工具被删除时一致）。
- 管理员修改使用方式后，正在进行的运行不受影响；新的发送按新设置生效。
- 直接回答挂载自动启用的技能会增加每次运行的准备时间。增加量在交付前实测并记录（见 design.md），不设验收阈值。
