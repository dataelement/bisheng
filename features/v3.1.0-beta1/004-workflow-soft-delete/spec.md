# 工作流逻辑删除

**版本**：v3.1.0-beta1。**优先级**：P1。**状态**：2026-11-04 用户已确认。

**关联需求**：本会话已确认的单标记、低复杂度方案；评审材料见 [工作流逻辑删除技术方案](../../../docs/reviews/workflow-soft-delete-technical-proposal-2026-11-03.md) 和 [合并评审 HTML 的功能一](../../../docs/reviews/workflow-delete-and-error-messages-review-v2-2026-11-03.html#deletion)。技术材料中的实现选择不作为本文需求来源扩项。

## 1 目标与范围

作为工作流管理者，我希望删除工作流后正常使用入口关闭，原有定义、版本及历史仍能保留，便于追溯。

本期只实现工作流逻辑删除。错误提示分类另行开发；不增加回收站、恢复、定时物理清理、删除进度管理、额外业务版本体系或在途实例协调。

## 2 验收标准

- **AC-01** — WHEN 有删除权限的用户成功删除工作流，THE SYSTEM SHALL 保留主记录、定义和版本内容，并将该工作流及其版本视为已删除，不再物理移除主记录。
- **AC-02** — WHEN 普通列表、搜索、推荐或应用数量查询执行，THE SYSTEM SHALL 排除已删除工作流，分页数据与总数口径一致。
- **AC-03** — WHEN 用户通过旧详情地址、构建预览、分享链接、网页或开放接口发起新的工作流操作，THE SYSTEM SHALL 拒绝对已删除工作流的编辑、发布、调试、复制、定义导出、版本修改、分享及新调用；管理员同样遵守资源删除状态。
- **AC-04** — WHEN 有权读取历史的用户查看原会话、消息、文件或审计，THE SYSTEM SHALL 保留其既有访问能力；删除工作流不删除这些历史数据，也不扩大历史访问权限。
- **AC-05** — WHEN 工作流删除完成，THE SYSTEM SHALL 沿用原有删除配套行为：撤销使用授权、移除用户组使用入口、为历史会话保留展示信息、使访客分享链接失效，并保留删除审计。
- **AC-06** — WHEN 删除后用户创建同名工作流，THE SYSTEM SHALL 不因已删除记录拒绝创建，并为新工作流生成独立身份；已删除记录不占用工作流业务配额。已保存模板和复制件保持独立，已删除工作流不能再作为新模板的来源。
- **AC-07** — IF 旧页面保存与删除并发，THEN THE SYSTEM SHALL 不允许保存将已删除工作流恢复为可用或重新插入，也不允许在删除后留下可用的新版本。
- **AC-08** — WHERE 多租户启用，THE SYSTEM SHALL 保持现有租户隔离和资源动作权限，普通用户不可删除无权限工作流，也不可借历史读取访问其他租户的数据。
- **AC-09** — WHEN 删除权限校验或权限撤销失败，THE SYSTEM SHALL 不报告删除成功、不提交业务删除状态；数据库标记提交失败或原有后置清理失败时沿用现有异常反馈，不伪造成功。
- **AC-10** — WHEN 数据库升级，THE SYSTEM SHALL 将存量未删除工作流保持为可用的原状态，兼容 MySQL 和 DM8，并保持其他应用类型的删除语义及工作流上线/下线含义。
- **AC-11** — WHEN 重复请求删除已删除工作流，THE SYSTEM SHALL 沿用现有资源不存在的反馈，不重新创建资源或恢复授权。

## 3 明确接受的边界

- 已在途、已入队、运行中和等待输入的实例沿用现有机制；可能继续，也可能因既有检查而失败。不要求主动终止，也不保证最终完成，不新增运行快照或跨 Worker 协调。
- 权限撤销、业务数据更新和既有后置清理仍存在跨系统失败窗口；本期保留现有权限账本和运维处理方式，不增加自动补偿系统，不保证再次点击即可恢复所有失败。
- 已有历史读取权限不赋予完整工作流定义的普通下载、编辑或调用能力。
- 此前已物理删除的主记录不能自动补回。保留数据持续占用存储，保留期限另议。
- 发布需迁移数据库并清退忽略删除状态的旧版本；回滚须保留删除过滤和禁止物理删除的兼容行为，或暂停相关入口。
