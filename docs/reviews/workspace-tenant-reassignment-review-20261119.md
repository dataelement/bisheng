# 迁租后资源访问边界：第二轮审查

**范围**：用户从 Root 变成 Child、两个 Child 之间变动或返回 Root 后，利用相同创建者、历史授权、旧资源 ID、混合 ID 批次和已建立的浏览器连接查询或操作原租户资源。

**分支**：`codex/3.1.0-beta1/workspace-bugfixes-20261118`，继续使用原独立 worktree。对照提交为第一轮修复 `2036cb1449`；整个分支仍基于 beta1 的 `c91e614052315ef704223cc1ce4c53defd0ab0db`。

**结果**：本轮发现的高优先级问题均已修复，复审未发现本轮范围内新的待修复问题。没有部署、推送、迁移资源或修改 116 数据。全仓基线检查并非全绿。

## 已修复发现

| 优先级 | 触发及影响 | 修复 |
| --- | --- | --- |
| P1 | `/chat/message/{id}` 删除只以用户 ID 与消息 ID 为条件。用户迁租后仍能删除自己在旧租户的消息；其他消息、会话和知识文件的既有批量写入也缺少 SQL 租户条件 | 新增 `apply_strict_tenant_filter`，为消息/会话/知识文件/QA 批量 UPDATE、DELETE 添加当前租户条件，标签复用同一入口。更宽的发现可见集合不会扩大写范围；同步、异步、无上下文拒绝和显式维护 bypass 均有回归 |
| P1 | QA 批量删除先读取过滤后的部分条目，再以请求原始 IDs 删除；旧文件删除的非 SPACE 兼容路径也可能只验证可见子集。追加问题或删除还只确认首个 QA 的父库 | QA 要求 IDs 全部命中，批次同属一个已授权知识库；向量及 SQL 删除使用确认后的去重 ID。旧文件删除也在任何权限投影、向量、调度和审计副作用前检查完整批次；空批次、缺失 ID、外租户及其他父库都拒绝 |
| P1 | QA 创建接受客户端 `tenant_id`，可能向旧租户插入数据后才因刷新过滤报错；更新可以把有权限的知识库与另一个 QA ID 组合 | `add_qa` 由已授权父库确定租户，并在写入及向量操作前确认已有 QA 的租户、父库与授权目标一致。原接口和响应形状不变 |
| P1 | 浏览器助手/工作流 WS 只在建连时确认身份，后续权限检查继续使用冻结身份。历史授权保留时，用户迁租后可沿旧连接继续发送操作 | 两个原生浏览器入口在既有消息准入回调中重读当前成员归属及 token version；停用、归属不唯一、迁租及凭据失效均拒绝。超管额外重新确认身份。失败在资源权限检查及消息处理前终止，使用原有错误帧及策略关闭路径 |
| P2 | QA 状态切换读取外租户 ID 后对空对象访问属性，返回内部错误 | 不存在或不可见时返回现有 404 错误 |

读路径复审包括空间详情、目录、文件预览/下载、会话历史及详情；写路径包括空间修改/删除、文件改名/删除、会话重命名/删除、审核回写、QA 追加/创建/更新/删除及底层批量写。业务目标必须先在当前租户解析，创建者相同及旧授权不能恢复目标可见性。

普通会话删除、单条消息删除沿用幂等响应：不可见目标可以是成功的空操作，不会确认目标存在或修改它。资源保留原租户归属，不自动迁移。
